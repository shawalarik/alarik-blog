## 第三篇：响应式原理 ⭐

> **"深入理解数据的响应式原理，学习常见的响应式对象 API、计算属性以及侦听器的实现原理。"**

### 第 9 章：响应式对象 reactive()

#### 9.1 Proxy 基础

`reactive` 是 Vue 3 响应式的入口，它通过 `Proxy` 创建对象的代理：

```ts
// @vue/reactivity/src/reactive.ts（简化）

const reactiveMap = new WeakMap<object, any>();

export function reactive<T extends object>(target: T): UnwrapNestedRefs<T> {
  return createReactiveObject(target, false, mutableHandlers, reactiveMap);
}

function createReactiveObject(
  target: object,
  isReadonly: boolean,
  baseHandlers: ProxyHandler<any>,
  proxyMap: WeakMap<object, any>
) {
  if (!isObject(target)) return target;

  const existingProxy = proxyMap.get(target);
  if (existingProxy) return existingProxy; // 缓存命中

  const proxy = new Proxy(target, baseHandlers);
  proxyMap.set(target, proxy);
  return proxy;
}
```

**关键设计决策**：

| 策略 | 原因 |
|------|------|
| `WeakMap` 缓存 | 避免重复代理，不阻碍 GC |
| 代理不可变原则 | 同一对象始终返回同一 Proxy 引用 |

#### 9.2 get 拦截 —— track 依赖收集

```ts
// @vue/reactivity/src/baseHandlers.ts（简化）

const get = createGetter();

function createGetter(isReadonly = false, shallow = false) {
  return function get(target: object, key: string | symbol, receiver: object) {
    const res = Reflect.get(target, key, receiver);

    if (!isReadonly && !isInternalKey(key)) {
      track(target, TrackOpTypes.GET, key); // ★ 核心：收集依赖
    }

    if (shallow) return res;

    // 深度响应：嵌套对象继续代理
    if (isObject(res)) {
      return isReadonly ? readonly(res) : reactive(res);
    }
    return res;
  };
}
```

**`track` 的数据结构**（三维映射）：

```
targetMap (WeakMap)
  └── target_1 (object) → depsMap (Map)
        ├── 'name'      → Set([effect_A, effect_B])
        └── 'age'       → Set([effect_A])
  └── target_2 (object) → depsMap (Map)
        └── 'count'     → Set([effect_C])
```

#### 9.3 set 拦截 —— trigger 触发更新

```ts
// @vue/reactivity/src/baseHandlers.ts（简化）

const set = createSetter();

function createSetter(shallow = false) {
  return function set(target, key, value, receiver): boolean {
    let oldValue = (target as any)[key];
    const result = Reflect.set(target, key, value, receiver);

    if (target === toRaw(receiver)) {
      if (hasChanged(value, oldValue)) {
        trigger(target, TriggerOpTypes.SET, key, value, oldValue);
      }
    }
    return result;
  };
}
```

`trigger` 会执行三个步骤：
1. **精确触发** — key 对应的依赖
2. **迭代触发** — 数组 length 变化
3. **调度执行** — 通过 scheduler 或直接 run effect

### 第 10 章：ref 与 shallowRef 等

#### 10.1 ref — 值类型的响应式包装

`reactive` 只能处理对象，基本类型无法被 Proxy 代理。`ref` 用 **getter/setter 拦截** 解决：

```ts
// @vue/reactivity/src/ref.ts（简化）

class RefImpl<T> {
  private _value: T;
  private _rawValue: T;       // 原始值，用于比较
  public dep: Dep = new Set(); // 依赖集合
  public readonly __v_isRef = true;

  constructor(value: T, public readonly __v_isShallow: boolean) {
    this._rawValue = __v_isShallow ? value : toRaw(value);
    this._value = __v_isShallow ? value : toReactive(value);
  }

  get value() {
    trackRefValue(this);  // 读取时 track
    return this._value;
  }

  set value(newVal) {
    newVal = this.__v_isShallow ? newVal : toRaw(newVal);
    if (hasChanged(newVal, this._rawValue)) {
      this._rawValue = newVal;
      this._value = toReactive(newVal);
      triggerRefValue(this);  // 写入时 trigger
    }
  }
}
```

#### 10.2 ref vs reactive 选择策略

| 场景 | 推荐 | 原因 |
|------|------|------|
| 基本类型（string/number/boolean） | `ref` | 无法用 Proxy |
| 对象，需要整体替换 | `ref` | `.value` 赋值可触发 |
| 对象，深层属性修改 | `reactive` | 无需 `.value`，更自然 |
| 解构后仍需响应式 | `ref` | 解构丢失 reactive 的 Proxy |

#### 10.3 其他响应式 API

| API | 用途 | 特点 |
|-----|------|------|
| `shallowReactive` | 浅层响应式 | 只代理第一层属性 |
| `readonly` / `shallowReadonly` | 只读代理 | set 操作会报警告 |
| `toRaw` | 获取原始值 | 脱去 Proxy 包装 |
| `isReactive` / `isRef` / `isReadonly` / `isProxy` | 类型判断 | 辅助函数 |

### 第 11 章：计算属性与侦听器

#### 11.1 computed — 惰性求值的派生状态

`computed` 本质是一个带缓存的 `effect`，使用 **dirty 标记机制** 实现懒更新：

```ts
class ComputedRefImpl<T> {
  private _dirty = true;             // 脏标记
  private _value: T;

  get value() {
    trackRefValue(this);            // 外部 effect 订阅此 computed
    if (this._dirty) {               // 只有脏了才重算
      this._dirty = false;
      this._value = this.effect.run(); // 同时建立内部依赖
    }
    return this._value;
  }

  constructor(getter: () => T) {
    this.effect = new ReactiveEffect(getter, () => {
      if (!this._dirty) {
        this._dirty = true;           // scheduler 仅设 dirty
        triggerRefValue(this);         // 通知外部 effect
      }
    });
  }
}
```

**computed 完整链路**：

```
computed(() => state.a + state.b)
    │
    ▼ .value 被读取：
    ├── trackRefValue(self)     ← 外部 effect 订阅此 computed
    ├── _dirty? → effect.run()
    │   ├── 读 state.a → track(a)
    │   └── 读 state.b → track(b)
    └── _dirty = false, 缓存结果

state.a 变化时：
    ├── trigger(a) → computed.scheduler()
    ├── _dirty = true
    └── triggerRefValue(self) → 通知外部
```

#### 11.2 watch / watchEffect — 副作用侦听

```ts
// watchEffect 默认使用微任务队列批处理
watchEffect(() => {
  console.log(state.count);
});
state.count++;
state.count++;  // 微任务合并，最终只打印一次 2
```

**调度器对比**：

| 方式 | 行为 | 使用场景 |
|------|------|---------|
| 同步 `effect()` | 立即执行 | 少见 |
| `watchEffect()` | 微任务队列（nextTick） | 组件内副作用 |
| `watch()` | 可配置 flush: 'pre'/'post' | 需要获取新旧值 |
| `watchSync()` | 同步刷新 | 在 `flushPostFlush` 钩子中 |

#### 11.3 cleanup 机制

当 effect 重新执行时，必须先清理旧依赖，避免泄漏：

```ts
function cleanupEffect(effect: ReactiveEffect) {
  const { deps } = effect;
  for (let i = 0; i < deps.length; i++) {
    deps[i].delete(effect);  // 从每个 dep 中移除自身
  }
  deps.length = 0;
}
```

**嵌套 effect 处理** — 使用全局栈 `effectStack` 保证每次 track 都能正确记录"谁在读"。

## 第四篇：编译优化

### 第 13~14 章：编译过程与优化策略

> **"了解编译过程以及背后的优化思想。"**

#### 13.1 编译器三大阶段

```
模板字符串 (.vue SFC)
    │
    ▼ parse (解析器)
    │   将模板解析为 AST（抽象语法树）
    │
    ▼ transform (转换器)
    │   AST → 优化后的 AST
    │   ├── 静态提升（hoist）
    │   ├── 缓存处理器（PatchFlag）
    │   └── v-on/v-bind 合并
    │
    ▼ generate (代码生成)
    │   AST → render 函数字符串
    │
    ▼ 最终输出
渲染函数 (JavaScript)
```

#### 13.2 关键优化策略

| 优化 | 原理 | 效果 |
|------|------|------|
| **静态提升 (hoist)** | 静态节点提升到外层循环外 | 减少重复创建 VNode |
| **PatchFlag** | 给动态节点标记变更类型 | diff 时只比对标记的部分 |
| **缓存处理器** | 缓存事件监听器函数引用 | 避免不必要的 removeEventListener/addEventListener |
| **Block Tree** | 将连续静态节点打包为单个 VNode | 减少 VNode 数量，加速 diff |
| **Tree flatten** | 扁平化条件分支中的稳定结构 | 减少运行时的创建成本 |

#### 14.1 PatchFlag 详解

PatchFlag 通过位运算标记节点的变化特征：

```ts
// @vue/shared/src/patchFlags.ts

enum PatchFlags {
  TEXT = 1,                  // 动态文本
  CLASS = 1 << 1,             // 动态 class
  STYLE = 1 << 2,             // 动态 style
  PROPS = 1 << 3,             // 动态 props
  FULL_PROPS = 1 << 4,         // 有动态 key 的 props
  HYDRATION_EVENTS = 1 << 5, // 事件监听器
  STABLE_FRAGMENT = 1 << 6,    // 稳定片段
  KEYED_FRAGMENT = 1 << 7,     // 带有 key 的 v-for
  UNKEYED_FRAGMENT = 1 << 8,   // 无 key 的 v-for
  NEED_PATCH = 1 << 9,          // 需要完整 patch
  COMPONENT = 1 << 10,          // 组件
  VNODE_HOOK = 1 << 11,         // 自定义指令钩子
  DYNAMIC_SLOTS = 1 << 12,      // 动态 slot
  DEV_ROOT_FRAGMENT = 1 << 13,   // 开发模式根节点
  ...                        // 更多...
}
```

## 小结

| 模块 | 核心职责 | 关键机制 |
|------|---------|---------|
| `reactive` | 对象的响应式代理 | `Proxy` + `Reflect`，WeakMap 缓存 |
| `ref` | 值类型的响应式包装 | `class RefImpl`，getter/setter 拦截 |
| `effect` | 副作用注册与执行 | `activeEffect` 全局变量 + effectStack |
| `computed` | 惰性求值的派生状态 | `_dirty` 脏标记 + scheduler |
| `dep` | 依赖收集容器 | 三维 `target → key → Set<effect>` 结构 |
| `scheduler` | 异步批处理 | 微任务队列 `queueJob` |
| `compiler` | 模板编译 | Parse → Transform → Generate |
| **PatchFlag** | Diff 性能优化 | 位运算标记变更类型 |
