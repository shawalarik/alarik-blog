Vue 3 的响应式系统是基于 ES2015 `Proxy` 构建的。本文从源码层面逐层拆解其实现原理，理解 `reactive`、`ref`、`computed`、`effect` 的内在机制。

## 整体架构

Vue 3 响应式系统的核心模块位于 `@vue/reactivity` 包，结构如下：

```
@vue/reactivity
├── reactive.ts        // reactive() 入口，Proxy 代理创建
├── ref.ts             // ref() 入口，值类型响应式包装
├── effect.ts          // effect / watchEffect 核心调度
├── computed.ts        // computed() 计算属性
├── baseHandlers.ts    // Proxy handler（get/set/deleteProperty/has）
├── collectionHandlers.ts  // Set/Map/WeakSet/WeakMap 的代理
├── dep.ts             // Dep 依赖收集容器（用 Set 实现）
└── system.ts          // 全局调度器与工具函数
```

数据流向：

```
reactive(obj)
    │
    ▼
new Proxy(obj, baseHandlers)   ← 拦截所有读写操作
    │
    ├── get → track()           ← 收集依赖：谁在读？
    │         └── activeEffect → dep.add(effect)
    │
    └── set → trigger()         ← 触发更新：通知所有依赖
              └── dep.forEach(effect => scheduler.run(effect))
```

## reactive：基于 Proxy 的深度代理

### 入口函数

```ts
// @vue/reactivity/src/reactive.ts（简化）

// 缓存：同一对象只代理一次（代理不可变）
const reactiveMap = new WeakMap<object, any>();

export function reactive<T extends object>(target: T): UnwrapNestedRefs<T> {
  return createReactiveObject(target, false, mutableHandlers, reactiveMap);
}

function createReactiveObject(
  target: object,
  isReadonly: boolean,
  baseHandlers: ProxyHandler<any>,
  proxyMap: WeakMap<object, any>
) {
  // 1. 只能代理对象
  if (!isObject(target)) {
    return target;
  }

  // 2. 已代理则直接返回（缓存命中）
  const existingProxy = proxyMap.get(target);
  if (existingProxy) {
    return existingProxy;
  }

  // 3. 创建 Proxy
  const proxy = new Proxy(target, baseHandlers);

  // 4. 缓存映射
  proxyMap.set(target, proxy);

  return proxy;
}
```

关键设计点：

| 策略 | 原因 |
|------|------|
| `WeakMap` 缓存 | 避免对同一对象重复代理，且不阻碍 GC |
| `new Proxy()` | 比 Vue 2 的 `Object.defineProperty` 更彻底——能拦截新增属性、数组索引、`in` 操作符等 |
| 代理不可变原则 | 对已返回的 Proxy 再次调用 `reactive()` 返回同一引用 |

### get 拦截器 —— track 收集依赖

```ts
// @vue/reactivity/src/baseHandlers.ts（简化）

const get = createGetter();

function createGetter(isReadonly = false, shallow = false) {
  return function get(target: object, key: string | symbol, receiver: object) {
    const res = Reflect.get(target, key, receiver);

    // 非只读 + 非内部 Symbol → 收集依赖
    if (!isReadonly && !isInternalKey(key)) {
      track(target, TrackOpTypes.GET, key);  // ★ 核心调用
    }

    // 浅响应直接返回
    if (shallow) {
      return res;
    }

    // 深度响应：嵌套对象继续代理
    if (isObject(res)) {
      return isReadonly ? readonly(res) : reactive(res);
    }

    return res;
  };
}
```

**`track` 的实现**：

```ts
// @vue/reactivity/src/effect.ts（简化）

let activeEffect: ReactiveEffect | undefined;  // 当前正在执行的副作用

export function track(target: object, type: string, key: unknown) {
  // 没有 activeEffect 说明不在 effect 内部读取，无需收集
  if (!activeEffect) return;

  // target → key → dep 的三维结构
  let depsMap = targetMap.get(target);       // Map<target, Map<key, Set<effect>>>
  if (!depsMap) {
    targetMap.set(target, (depsMap = new Map()));
  }

  let dep = depsMap.get(key);
  if (!dep) {
    depsMap.set(key, (dep = new Set()));
  }

  // 收集当前副作用到该 key 的依赖集合中
  trackEffects(dep);
}

export function trackEffects(dep: Dep) {
  // 去重：同一个 effect 不重复收集
  if (!dep.has(activeEffect!)) {
    dep.add(activeEffect!);

    // 同时维护 effect → deps 的反向映射（用于 cleanup）
    activeEffect!.deps.push(dep);
  }
}
```

核心数据结构：

```
targetMap (WeakMap)
  └── target_1 (object) → depsMap (Map)
        ├── 'name'      → Set([effect_A, effect_B])
        └── 'age'       → Set([effect_A])
  └── target_2 (object) → depsMap (Map)
        └── 'count'     → Set([effect_C])
```

### set 拦截器 —— trigger 触发更新

```ts
// @vue/reactivity/src/baseHandlers.ts（简化）

const set = createSetter();

function createSetter(shallow = false) {
  return function set(
    target: object,
    key: string | symbol,
    value: unknown,
    receiver: object
  ): boolean {
    // 获取旧值（用于触发判断）
    let oldValue = (target as any)[key];

    const result = Reflect.set(target, key, value, receiver);

    // 触发更新（判断条件避免无效触发）
    if (target === toRaw(receiver)) {
      if (hasChanged(value, oldValue)) {
        trigger(target, TriggerOpTypes.SET, key, value, oldValue);
      }
    }

    return result;
  };
}
```

**`trigger` 的实现**：

```ts
// @vue/reactivity/src/effect.ts（简化）

export function trigger(
  target: object,
  type: string,
  key?: unknown,
  newValue?: unknown,
  oldValue?: unknown
) {
  const depsMap = targetMap.get(target);
  if (!depsMap) return;  // 没有依赖，什么都不做

  const effectsToRun = new Set<ReactiveEffect>();

  // 1. 精确触发：key 对应的依赖
  const dep = depsMap.get(key);
  if (dep) {
    add/effectsToRun(dep);
  }

  // 2. 迭代相关触发（数组长度的变化）
  if (type === TriggerOpTypes.ADD) {
    const iterKey = isArray(target) ? 'length' : ITERATE_KEY;
    add(effectsToRun, depsMap.get(iterKey)!);
  }

  // 3. 执行所有收集到的副作用
  effectsToRun.forEach((effect) => {
    // 避免 effect 内部修改自己触发的死循环
    if (effect !== activeEffect) {
      if (effect.scheduler) {
        effect.scheduler();     // 有调度器走调度器（如 nextTick）
      } else {
        effect.run();          // 否则同步执行
      }
    }
  });
}
```

## ref：值类型的响应式包装

`reactive` 只能处理对象，基本类型（`number`、`string`、`boolean`）无法被 Proxy 代理。`ref` 用 **getter/setter 拦截** 解决这个问题：

```ts
// @vue/reactivity/src/ref.ts（简化）

class RefImpl<T> {
  private _value: T;
  private _rawValue: T;       // 原始值，用于比较
  public dep: Dep = new Set(); // 依赖集合
  public readonly __v_isRef = true;

  constructor(value: T, public readonly __v_isShallow: boolean) {
    this._rawValue = __v_isShallow ? value : toRaw(value);
    this._value = __v_isShallow ? value : toReactive(value); // 对象值自动转 reactive
  }

  get value() {
    trackRefValue(this);  // ★ 读取时 track
    return this._value;
  }

  set value(newVal) {
    // 使用原始值做比较，避免响应式对象误判
    newVal = this.__v_isShallow ? newVal : toRaw(newVal);
    if (hasChanged(newVal, this._rawValue)) {
      this._rawValue = newVal;
      this._value = toReactive(newVal);
      triggerRefValue(this);  // ★ 写入时 trigger
    }
  }
}

export function ref<T>(value: T): Ref<T> {
  return new RefImpl(value, false);
}
```

`ref` vs `reactive` 的选择策略：

| 场景 | 推荐 | 原因 |
|------|------|------|
| 基本类型（string/number/boolean） | `ref` | 无法用 Proxy |
| 对象，需要整体替换 | `ref` | `.value` 赋值可触发 |
| 对象，深层属性修改 | `reactive` | 无需 `.value`，更自然 |
| 解构后仍需响应式 | `ref` | 解构丢失 reactive 的 Proxy |

## effect：副作用的注册与调度

### ReactiveEffect 类

```ts
// @vue/reactivity/src/effect.ts（简化）

export class ReactiveEffect<T = any> {
  public active = true;
  public deps: Dep[] = [];            // 反向依赖列表（用于 cleanup）
  public scheduler?: () => void;      // 自定义调度器

  constructor(
    public fn: () => T,               // 用户传入的副作用函数
    public scheduler?: () => void     // 可选调度器
  ) {}

  run() {
    if (!this.active) return this.fn();

    // 避免 effect 内部重复入栈（cleanup 时需要）
    if (effectStack.includes(this)) {
      return this.fn();
    }

    try {
      // 1. 将当前 effect 设为 activeEffect
      effectStack.push((activeEffect = this));

      // 2. 清理旧依赖（Vue 3 的关键优化）
      cleanupEffect(this);

      // 3. 执行用户函数（执行过程中会触发 getter → track）
      return this.fn();
    } finally {
      // 4. 弈栈恢复上一个 effect
      effectStack.pop();
      activeEffect = effectStack[effectStack.length - 1];
    }
  }

  stop() {
    if (this.active) {
      cleanupEffect(this);  // 从所有 dep 中移除自身
      this.active = false;
    }
  }
}

function cleanupEffect(effect: ReactiveEffect) {
  const { deps } = effect;
  if (deps.length > 0) {
    for (let i = 0; i < deps.length; i++) {
      deps[i].delete(effect);
    }
    deps.length = 0;
  }
}
```

### effect 函数栈与嵌套

Vue 3 用一个全局栈 `effectStack` 处理嵌套 effect：

```js
// 嵌套场景示例
const state = reactive({ a: 1, b: 2 });

effect(() => {
  console.log('外层 effect 运行');
  console.log('a =', state.a);       // 外层追踪 a

  effect(() => {
    console.log('内层 effect 运行');
    console.log('b =', state.b);     // 内层追踪 b
    console.log('a =', state.a);     // 内层也追踪 a
  });
});

state.a = 99;
// 修改 a 时：
// 1. 外层 effect 先执行（activeEffect 指向外层）
// 2. 执行过程中遇到内层 effect → activeEffect 切换为内层
// 3. 内层执行完毕 → activeEffect 恢复为外层
// 保证每次 track 都能正确记录"谁在读"
```

## computed：惰性求值的派生状态

`computed` 本质是一个带缓存的 `effect`：

```ts
// @vue/reactivity/src/computed.ts（简化）

class ComputedRefImpl<T> {
  private _value: T;
  private _dirty = true;             // 脏标记：是否需要重新计算
  public effect: ReactiveEffect<T>;
  public dep: Dep = new Set();       // computed 自身的依赖集合
  public __v_isRef = true;

  constructor(getter: () => T) {
    // 创建一个懒执行的 effect（scheduler 仅设 dirty 标记，不立即重算）
    this.effect = new ReactiveEffect(getter, () => {
      if (!this._dirty) {
        this._dirty = true;
        // 通知依赖此 computed 的外部 effect
        triggerRefValue(this);
      }
    });

    this.effect.computed = this as any;
  }

  get value() {
    // 收集依赖：谁在访问这个 computed？
    trackRefValue(this);

    // 只有脏了才重算
    if (this._dirty) {
      this._dirty = false;
      this._value = this.effect.run();  // 执行 getter，同时建立内部依赖
    }
    return this._value;
  }
}

export function computed<T>(getter: () => T): ComputedRef<T> {
  return new ComputedRefImpl(getter);
}
```

计算属性的完整链路：

```
computed(() => state.a + state.b)
    │
    ▼
ComputedRefImpl
    ├── .value 被读取时：
    │   ├── trackRefValue(self)     ← 外部 effect 订阅此 computed
    │   ├── _dirty? → effect.run()
    │   │   ├── 执行 getter
    │   │   ├── 读 state.a → track(a)   ← 内部订阅 state.a
    │   │   └── 读 state.b → track(b)   ← 内部订阅 state.b
    │   └── _dirty = false, 缓存结果
    │
    └── state.a 或 state.b 变化时：
        ├── trigger(a/b) → computed.scheduler()
        ├── _dirty = true
        └── triggerRefValue(self) → 通知外部 effect 重算
```

## 调度系统：从同步到异步批处理

### 默认调度 vs watchEffect 调度

```ts
// 同步 effect：每次变化立即执行
effect(() => {
  console.log(state.count);
});
state.count++;  // 立即打印 1
state.count++;  // 立即打印 2

// watchEffect：默认微任务队列（queueJob）
watchEffect(() => {
  console.log(state.count);
});
state.count++;
state.count++;  // 微任务队列中合并，最终只打印一次 2
```

Vue 3 的调度器使用 `Promise.resolve().then()` 实现微任务批处理（`nextTick`）：

```ts
// @vue/runtime-core/src/scheduler.ts（简化）

const queue: Function[] = [];
let isFlushPending = false;

export function queueJob(job: Function) {
  if (!queue.includes(job)) {
    queue.push(job);
  }

  queueFlush();
}

function queueFlush() {
  if (!isFlushPending) {
    isFlushPending = true;
    // 微任务批处理
    Promise.resolve().then(flushJobs);
  }
}

function flushJobs() {
  isFlushPending = false;

  for (let i = 0; i < queue.length; i++) {
    queue[i]();
  }

  queue.length = 0;
}
```

## 与 Vue 2 的对比

| 特性 | Vue 2 (`Object.defineProperty`) | Vue 3 (`Proxy`) |
|------|--------------------------------|------------------|
| 属性拦截 | 必须预定义属性才能响应式 | 动态属性自动响应 |
| 数组监听 | 重写 7 个变异方法 | 原生拦截索引和 length |
| 深层响应 | 递归 `defineReactive` | 懒递归（按需） |
| 性能开销 | 初始化全量递归 | 按需代理，内存更优 |
| Map/Set 等 | 不支持 | 完整支持 |
| `delete` / `in` | 需要 `$delete` / `$set` | 原生支持 |

## 小结

| 模块 | 核心职责 | 关键机制 |
|------|---------|---------|
| `reactive` | 对象的响应式代理 | `Proxy` + `Reflect`，WeakMap 缓存 |
| `ref` | 值类型的响应式包装 | `class RefImpl`，getter/setter 拦截 |
| `effect` | 副作用注册与执行 | `activeEffect` 全局变量 + effectStack 嵌套栈 |
| `computed` | 惰性求值的派生状态 | `_dirty` 脏标记 + scheduler 懒更新 |
| `dep` | 依赖收集容器 | 三维结构 `target → key → Set<effect>` |
| `scheduler` | 异步批处理 | 微任务队列 `queueJob` + `flushJobs` |

理解这套机制后，阅读任何基于响应式的代码都能快速定位问题根源。
