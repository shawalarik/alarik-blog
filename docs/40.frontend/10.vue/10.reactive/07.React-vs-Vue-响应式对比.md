这一模块从机制与哲学两个维度比较 React 和 Vue，建立跨框架响应式认知坐标。

## 核心哲学差异

### 两种响应式世界观

```
Vue 的世界观：                    React 的世界观：
"我帮你盯着数据变化，             "你告诉我数据变了，
 自动更新视图"                     我来重绘视图"
                                 
 数据可变                          数据不可变
 Proxy 劫持                       setState / useState
 细粒度依赖追踪                   组件级重新渲染
 框架驱动更新                      开发者触发更新
```

### 同一个需求的两种实现

**需求：用户名变化时，显示欢迎信息并记录日志**

```vue
<!-- Vue 响应式方式 -->
<template>
  <div>
    {{ greeting }}
  </div>
</template>

<script setup>
import { ref, computed, watch } from 'vue';

const username = ref('');
const greeting = computed(() => `Hello, ${username.value || 'Guest'}`);

watch(username, (newVal) => {
  console.log(`用户名变为: ${newVal}`);
}, { immediate: true });
</script>
```

```jsx
// React 方式
function Welcome() {
  const [username, setUsername] = useState('');
  const greeting = `Hello, ${username || 'Guest'}`;

  useEffect(() => {
    console.log(`用户名变为: ${username}`);
  }, [username]);  // 明确声明依赖

  return (
    <div>{greeting}</div>
  );
}
```

关键区别：

| 维度 | Vue | React |
|------|-----|-------|
| **谁决定更新？** | 框架自动检测到 `username` 变化 → 触发 `computed` 和 `watch` 重算 | 开发者调用 `setUsername` → 触发组件 re-render → 执行 `useEffect` |
| **依赖如何收集？** | 运行时自动追踪（Proxy get 时 track） | 开发者手动声明（useEffect 的 deps 数组） |
| **心智模型** | "改了就自动生效" | "改了要告诉 React，还要说明依赖什么" |

## 数据劫持 vs 不可变数据

### Vue：数据劫持（Mutable + Interception）

```js
// Vue —— 数据本身是可变的
const state = reactive({
  user: { name: 'Alice', age: 25 },
});

// 直接修改对象属性即可
state.user.name = 'Bob';     // ✅ 触发更新
state.user.age += 1;          // ✅ 触发更新

// 嵌套修改也完全正常
state.user.profile.avatar = 'new.jpg';  // ✅ 自动深层追踪

// 新增/删除也正常
state.user.email = 'bob@test.com';      // ✅
delete state.user.age;                  // ✅
```

**优点**：
- 代码自然，符合 JavaScript 惯用写法
- 无需学习不可变数据模式
- 深层嵌套操作无需特殊处理

**缺点**：
- 需要注意响应式丢失（解构、传递给外部库）
- 调试时难以追溯变更历史（不知道谁改了什么）

### React：不可变数据（Immutable）

```jsx
// React —— 每次创建新状态
const [user, setUser] = useState({ name: 'Alice', age: 25 });

// ❌ 直接修改无效！
user.name = 'Bob';        // 不触发重渲染
user.age += 1;            // 不触发重渲染

// ✅ 必须创建新对象
setUser(prev => ({
  ...prev,
  name: 'Bob',
}));

// 深层嵌套需要展开每一层
setUser(prev => ({
  ...prev,
  user: {
    ...prev.user,
    profile: {
      ...prev.user.profile,
      avatar: 'new.jpg',
    },
  },
}));

// 数组操作也需要不可变方式
const [items, setItems] = useState([1, 2, 3]);

setItems(prev => [...prev, 4]);           // push
setItems(prev => prev.filter(i => i > 1)); // filter
setItems(prev => prev.map((i, idx) => idx === 0 ? 99 : i)); // 修改某项
```

**优点**：
- 状态变更历史清晰可追溯（时间旅行调试）
- 容易做状态比对（引用相等性检查）
- 天然支持撤销/重做功能
- 并发模式下无撕裂风险

**缺点**：
- 展开运算符在深层嵌套时冗长且易错
- 需要额外的 Immer 等库来简化
- 内存开销更大（频繁创建中间对象）

### 用 Immer 弥合差异

```jsx
// Immer 让 React 也拥有类似 Vue 的"直接修改"体验
import { produce } from 'immer';
import { useImmer } from 'use-immer';

// 方式一：useImmer hook
function Profile() {
  const [user, updateUser] = useImmer({ name: 'Alice', profile: {} });

  function handleRename(newName) {
    // 可以像 Vue 一样直接修改！
    updateUser(draft => {
      draft.name = newName;       // Immer 内部处理不可变性
      draft.profile.updatedAt = Date.now();
    });
  }
}

// 方式二：配合 setState
setState(produce(draft => {
  draft.items[0].count++;
  draft.items.push({ id: 4 }));
}));
```

## 自动细粒度更新 vs 组件级重新渲染

### Vue：细粒度依赖追踪

```vue
<!-- Vue 只重新渲染真正变化的 DOM -->
<template>
  <div class="profile">
    <!-- A：只在 name 变化时更新 -->
    <h1>{{ user.name }}</h1>

    <!-- B：只在 age 变化时更新 -->
    <span>{{ user.age }} years old</span>

    <!-- C：完全不相关的部分不会受影响 -->
    <FooterComponent />
  </div>
</template>
```

Vue 在编译阶段就知道每个模板表达式依赖了哪些变量。当只有 `name` 变化时：

```
虚拟 DOM 层面：
  VNode diff 发现只有 <h1> 的 text 变了 → 只 patch 这一个节点

依赖层面：
  effect 收集的依赖是 { user.name }
  user.age 变化 → 不触发此 effect
```

### React：组件级重新渲染

```jsx
// 当 state 变化时，整个组件函数重新执行
function Profile() {
  const [user, setUser] = useState({ name: 'Alice', age: 25 });

  // 每次 user 变化，以下所有代码都重新执行：
  console.log('整个组件函数执行');         // 重新执行
  const greeting = `Hi, ${user.name}`;      // 重新计算
  const isAdult = user.age >= 18;            // 重新计算

  return (
    <div>
      <h1>{greeting}</h1>                  {/* 重新创建 */}
      <span>{isAdult ? 'Adult' : 'Minor'}</span> {/* 重新创建 */}
      <Footer />                            {/* 重新创建（但可能被 memo 保护） */}
    </div>
  );
}
```

React 默认行为：**任何一个 state/prop 变化都会导致整个组件函数重新执行**。

### React 的优化手段

```jsx
// 1. memo —— 避免子组件不必要的重渲染
const Footer = memo(function Footer() {
  return <footer>Static Content</footer>;
});

// 2. useMemo —— 缓存昂贵计算
const sortedItems = useMemo(() => {
  return [...items].sort((a, b) => a.rank - b.rank);
}, [items]);  // 只有 items 变化时才重新排序

// 3. useCallback —— 缓存回调函数
const handleClick = useCallback(() => {
  doSomething(id);
}, [id]);  // id 不变则返回同一个函数引用

// 4. 自定义 hook 封装细粒度更新
function useSelect(store, selector) {
  const [selected, setSelected] = useState(selector(store));

  useEffect(() => {
    const unsubscribe = store.subscribe(() => {
      setSelected(selector(store.getState()));
    });
    return unsubscribe;
  }, [store, selector]);

  return selected;
}

// 使用：只订阅 store 中需要的切片
const userName = useSelect(authStore, s => s.user.name);
// authStore 中其他字段变化不会导致此组件重渲染
```

### 性能影响对比

| 场景 | Vue | React (未优化) | React (优化后) |
|------|-----|---------------|---------------|
| 大型列表中一项变化 | 仅更新对应 DOM 节点 | 整个列表组件 re-render | 通过 key/virtual list 缓解 |
| 深层嵌套对象的叶子变化 | 精确到叶子属性的 effect | 整个组件树 re-render | useMemo + memo 分层保护 |
| 无关 prop 频繁变化 | 自动忽略无关依赖 | 子组件可能不必要 re-render | memo 浅比较过滤 |
| 初始渲染性能 | 编译优化 + 细粒度 | 较慢（全量执行） | 差距缩小 |

## Proxy vs setState 设计哲学

### 设计哲学溯源

```
Vue 的哲学（源自 AngularJS/Meteor）：
┌──────────────────────────────────────────────┐
│  "让框架处理复杂性，开发者专注业务逻辑"         │
│                                              │
│  数据 → [框架拦截] → 自动更新视图              │
│  开发者只需关心：数据的结构和含义              │
│  框架负责：何时更新、更新多少、怎么更新         │
└──────────────────────────────────────────────┘


React 的哲学（源自函数式编程）：
┌──────────────────────────────────────────────┐
│  "显式优于隐式，可控性优先于便捷性"            │
│                                              │
│  数据 → [开发者创建新版本] → setState → 重绘   │
│  开发者负责：何时更新、更新的内容              │
│  框架负责：高效的 Diff 和 DOM 操作             │
└──────────────────────────────────────────────┘
```

### 各自的优势场景

**Vue 更适合的场景：**
- 快速原型开发——减少样板代码
- 复杂表单交互——双向绑定天然适配
- 团队水平参差——隐式约定降低出错率
- 数据结构嵌套深且频繁局部修改

**React 更适合的场景：**
- 大型应用的状态管理——不可变性带来可预测性
- 需要复杂的状态回滚/时间旅行调试
- 高度动态的 UI（大量条件渲染）
- 与非 React 生态集成——纯 JS 数据流更通用

### 实际工程中的选择

很多团队的选择并非基于技术优劣，而是基于**团队能力与项目约束**：

```
选 Vue 如果：
✅ 团队偏向前端基础较弱或新人多
✅ 项目追求快速交付
✅ UI 交互复杂但数据流相对简单
✅ 已有 Vue 技术栈积累

选 React 如果：
✅ 团队有强 FP 背景或偏好显式控制
✅ 应用规模大、需要严格的状态管理
✅ 需要与 RN/Web/其他平台共享逻辑
✅ 对性能有极致要求且有优化能力
```

## 小结

| 维度 | Vue 响应式 | React 不可变 |
|------|-----------|-------------|
| **数据模型** | 可变 + 劫持 | 不可变 + 替换 |
| **更新触发** | 框架自动检测 | 开发者主动通知 |
| **更新粒度** | 属性级细粒度 | 组件级 + 手动优化 |
| **学习成本** | 低（直觉式） | 高（需理解闭包/依赖/memo） |
| **调试体验** | 变更来源较难追踪 | 时间旅行、变更栈清晰 |
| **并发安全** | 单线程同步模型 | Fiber 可中断 + 双缓冲 |
| **生态互补** | Immer 可补充不可变需求 | VueUse 可补充更多组合 API |

两者没有绝对的优劣之分，而是在**开发效率和运行时可预测性**之间的不同权衡。理解各自的设计哲学有助于在不同项目中做出合理的技术选型。
