这一模块讨论编译时响应式路线，理解其与运行时响应式在成本结构和能力边界上的差异。

## 编译时 vs 运行时响应式

### 三种响应式范式的成本结构对比

```
┌─────────────────────────────────────────────────────────────┐
│                     响应式成本分布                           │
│                                                             │
│  Vue / React (运行时)                                       │
│  ─────────────────────                                      │
│  构建期:    ██████░░░░░░░  较轻                             │
│  运行时:    ████████████████  重（Virtual DOM + Diff）       │
│  包体积:    ~40KB+ (Vue) / ~45KB+ (React DOM)               │
│                                                             │
│  Svelte (编译时)                                             │
│  ─────────────────                                          │
│  构建期:    ████████████████████  重（编译分析）              │
│  运行时:    ███░░░░░░░░░░░░░  极轻（原生 DOM 操作）          │
│  包体积:    ~1KB (无 Virtual DOM runtime)                    │
│                                                             │
│  Solid (混合型)                                              │
│  ────────────────                                           │
│  构建期:    ████████████░░░ 中等（编译优化）                 │
│  运行时:    ██████████░░░░░  中等（细粒度 Signal，无 VDOM）  │
│  包体积:    ~7KB                                            │
└─────────────────────────────────────────────────────────────┘
```

| 维度 | Vue/React (运行时) | Svelte (编译时) | Solid (混合) |
|------|-------------------|-----------------|-------------|
| **何时确定依赖关系？** | 运行时追踪 (Proxy/getter) | 编译器静态分析 | 编译器注入 Signal |
| **更新粒度** | 组件级 (React) / VNode 级 (Vue) | 精确到赋值语句 | 精确到 Signal 订阅 |
| **Virtual DOM** | 有 | **无** | **无** |
| **运行时核心** | 调度器 + Diff 算法 | 极简赋值 + DOM API | 响应式系统 |
| **包大小** | 大 | 极小 | 小 |

## Svelte 编译时响应式原理

### 核心理念：没有 Virtual DOM

Svelte 的革命性理念：**框架不是运行时，而是编译步骤**。

```svelte
<!-- App.svelte —— Svelte 组件 -->
<script>
  let count = 0;

  function increment() {
    count += 1;
  }
</script>

<button on:click={increment}>
  点击次数: {count}
</button>

<style>
  button { padding: 8px 16px; }
</style>
```

这段代码经过 Svelte 编译后，输出的是**纯 JavaScript**：

```js
// 编译输出（大幅简化）
import { create_ssr_component, svg_attributes, spread } from 'svelte/internal';

function create_fragment(ctx) {
  let button;

  return {
    c() {  // create —— 创建 DOM
      button = element('button');
      t0 = text('点击次数: ');
      t1 = text(ctx[0]);  // ctx[0] 就是 count
    },

    m(target, anchor) {  // mount —— 挂载 DOM
      insert(target, button, anchor);
      append(button, t0);
      append(button, t1);
    },

    p(ctx, [dirty]) {  // update —— 按需更新！
      if (dirty & /*count*/ 1) set_data(t1, ctx[0]);
    },

    d(detaching) {
      if (detaching) detach(button);
    },
  };
}

function instance($$self, $$props, $$invalidate) {
  let count = 0;

  function increment() {
    $$invalidate(0, count += 1);  // 关键：标记 dirty 并触发更新
  }

  return [count, increment];
}

export default class App extends SvelteComponent {
  constructor(options) {
    super();
    init(this, options, instance, create_fragment, safe_not_equal, {});
  }
}
```

### `$$invalidate` —— Svelte 响应式的魔法

`$$invalidate` 是编译器为每个响应式变量生成的函数调用：

```js
// Svelte 内部简化实现
const component = {
  // 每个 component 实例的上下文
  $$: {  // 副作用（$: 语句）
    dirty: new Set(),   // 脏标记集合
    callbacks: [],      // 更新回调
    bound: {},          // 双向绑定
    ctx: {},            // 当前上下文值
    update_dirty: new Set(),
  },

  $set(newProps) {
    this.$$ctx = assign(assign({}, this.$$props), newProps);
    this.$$.dirty.forEach(key => {
      if (!(key in newProps)) this.$$.dirty.delete(key);
    });
    this.$$schedule_update();
  },

  $$.update() {
    // 只重新计算脏了的部分
    if (this.$$.dirty & /*count*/ 1) {
      // 重新执行依赖 count 的派生语句 ($:)
    }

    // 调用 fragment.p() 进行最小化 DOM 更新
  },
};
```

### 响应式声明（$:）

```svelte
<script>
  let count = 0;
  let doubled;     // 派生状态

  // $: 相当于 computed，由编译器自动建立依赖图
  $: doubled = count * 2;

  $: console.log(`count is ${count}`);  // watchEffect

  // 条件性响应式语句
  $: if (count > 10) {
    alert('太多了！');
  }
</script>

<p>{count} × 2 = {doubled}</p>

<button on:click={() => count++}>+</button>
```

编译器会分析 `$:` 语句之间的数据依赖关系，生成正确的更新拓扑：

```js
// 编译后的效果（概念上）：
// count 变化 → 重新计算 doubled → 重新执行 console.log → 检查 if 条件
```

### Svelte 的响应式限制

```svelte
<script>
  // ✅ 顶层变量自动响应式
  let a = 1;
  let b = a * 2;  // ❌ 这不会自动更新！

  // 需要用 $: 声明
  $: b = a * 2;   // ✅ 现在 b 会跟随 a 变化

  // ❌ 数组方法不会触发更新（除非替换引用）
  let items = [1, 2, 3];
  items.push(4);   // 不触发 UI 更新！

  // 必须用赋值触发
  items = [...items, 4];  // ✅ 触发更新
  items.length = 0;       // ❌ 不触发
  items = [];             // ✅ 触发更新

  // ❌ 对象属性修改不触发更新（除非是顶层变量赋值）
  let obj = { name: 'Alice' };
  obj.name = 'Bob';  // ❌ 不触发！
  obj = { ...obj, name: 'Bob' };  // ✅ 触发更新
</script>
```

> 注意：Svelte 5 引入了 Runes 系统，彻底解决了这些限制。详见后续章节。

## Solid 细粒度响应式（基于 Signal）

Solid 的设计哲学：**像 React 的语法，但拥有比 Vue 更细粒度的响应式**。

### 核心 API：createSignal

```jsx
import { createSignal, createEffect } from 'solid-js';

function Counter() {
  const [count, setCount] = createSignal(0);

  // createEffect 类似于 Vue 的 watchEffect 或 React 的 useEffect
  createEffect(() => {
    console.log(`count changed to: ${count()}`);  // 用函数调用来读取
  });

  return (
    <button onClick={() => setCount(c => c + 1)}>
      {/* 在 JSX 中直接使用 signal 函数 */}
      Count: {count()}
    </button>
  );
}
```

关键特点：

1. **Signal 是 getter/setter 对**——类似 Vue 的 ref，但通过函数调用访问
2. **没有 Virtual DOM**——JSX 编译后直接操作真实 DOM
3. **精确更新**——只有实际读取了 signal 的 DOM 节点才会被更新

### 编译过程揭秘

```jsx
// 源码
function NameDisplay() {
  const [name, setName] = createSignal('Alice');

  return (
    <div>
      <p>Hello, {name()}</p>
      <input value={name()} onInput={e => setName(e.target.value)} />
    </div>
  );
}

// 编译后的伪代码（无 VDOM！）：
function NameDisplay() {
  const [name,setName] = createSignal('Alice');

  // 创建真实的 DOM 元素
  const div = document.createElement('div');
  const p = document.createElement('p');
  const input = document.createElement('input');

  // 创建响应式绑定 —— 只有这里会随 name 变化而更新
  insert(div, p);
  append(p, () => `Hello, ${name()}`);  // 文本节点绑定到 signal
  input.value = name();
  input.addEventListener('input', e => setName(e.target.value));
  // input.value 也需要绑定...

  return div;  // 返回真实 DOM 元素！
}
```

### createMemo 和 createDerived

```jsx
import { createSignal, createMemo, createComputed } from 'solid-js';

const [firstName, setFirstName] = createSignal('Alice');
const [lastName, setLastName] = createSignal('Smith');

// createMemo —— 懒求值的 computed（只在被读取且脏时重算）
const fullName = createMemo(() => `${firstName()} ${lastName()}`);

// createComputed —— 急切执行的 effect（立即开始追踪）
createComputed(() => {
  console.log(`Full name is: ${fullName()}`);
});

// createMemo vs createComputed：
// createMemo: 按需求值（类似 Vue computed），有缓存
// createComputed: 自动执行（类似 Vue watchEffect），无缓存返回值
```

### createSignal 的内部实现

```js
// Solid 的 Signal 极简实现（~50 行核心代码）
function createSignal(value, options) {
  const observers = new Set();  // 订阅此 signal 的 effects

  // getter —— 读取时注册依赖
  const read = () => {
    // 如果当前有正在执行的 effect，将自身加入其依赖列表
    if (listener !== null) {
      if (!observers.has(listener)) {
        observers.add(listener);
        listener.dependencies.push(observers);
      }
    }
    return value;
  };

  // setter —— 写入时通知所有订阅者
  const write = (nextValue) => {
    value = nextValue;
    for (const observer of [...observers]) {
      observer.execute();  // 执行依赖此 signal 的 effect
    }
  };

  return [read, write];
}
```

### Solid 的响应式规则

```
Solid 的黄金三法则：

1. 响应式数据必须以"函数形式"读取
   ✅ const x = signal();    // 在追踪上下文中
   ❌ const x = signal;      // 只是拿到了函数引用

2. 数据变化只通知真正使用了它的地方
   // 即使组件内有 100 个元素，
   // 只有实际包含 signal() 的元素会被更新

3. 同步执行，无批处理队列
   // setSignal(A)
   // → 所有依赖 A 的 effect 立即同步执行
   // → 无 nextTick、无 setState batch
```

## 与运行时响应式的本质差异

### 性能模型对比

```
用户点击按钮 → count++

┌─ React ──────────────────────────────────────────────────┐
│ 1. setState(count + 1)                                    │
│ 2. 标记组件为 dirty                                       │
│ 3. 调度 re-render                                         │
│ 4. 执行整个组件函数                                        │
│ 5. 生成新的虚拟 DOM 树                                     │
│ 6. Diff 新旧两棵树                                         │
│ 7. 计算 minimal changeset                                  │
│ 8. Patch 真实 DOM                                         │
│                                                            │
│ 成本：O(组件大小) + O(VDOM diff)                          │
└──────────────────────────────────────────────────────────┘

┌─ Vue ───────────────────────────────────────────────────┐
│ 1. count++ (Proxy set 触发)                               │
│ 2. trigger(dep)                                           │
│ 3. 收集所有依赖此属性的 effects                            │
│ 4. 通过 scheduler 排队 (nextTick/Promise)                 │
│ 5. 执行 effects → 组件 render 函数                        │
│ 6. 生成新的 VNode 树                                      │
│ 7. Diff 新旧 VNode (基于模板静态优化，diff 范围缩小)       │
│ 8. Patch 真实 DOM                                         │
│                                                            │
│ 成本：O(依赖数) + O(VDOM diff，但范围更小)                │
└──────────────────────────────────────────────────────────┘

┌─ Svelte ─────────────────────────────────────────────────┐
│ 1. count += 1                                             │
│ 2. $$invalidate(0, count)  // 标记第 0 个变量为 dirty     │
│ 3. scheduleUpdate()                                      │
│ 4. 执行 component.$$.update()                            │
│ 5. 重新计算所有 $: 派生变量                                │
│ 6. 执行 fragment.p(dirty)                                 │
│ 7. 直接操作 DOM（如 set_data(textNode, newValue)）         │
│                                                            │
│ 成本：O(脏标记相关联的 DOM 操作) ≈ O(1)                   │
└──────────────────────────────────────────────────────────┘

┌─ Solid ─────────────────────────────────────────────────┐
│ 1. setCount(c => c + 1)                                   │
│ 2. value = newValue                                       │
│ 3. 遍历 observers Set，逐个 execute()                      │
│ 4. 每个 effect 内部：                                      │
│    - 重新执行 JSX 表达式                                   │
│    - 直接对绑定的 DOM 节点进行 textContent / attribute 更新│
│                                                            │
│ 成本：O(活跃订阅者数量) × O(单个 DOM 操作) ≈ O(k)        │
└──────────────────────────────────────────────────────────┘
```

### 内存与包体积

```
包体积比较（gzip 后）：

React + ReactDOM:  ~42 KB
Vue (runtime):      ~34 KB
Svelte (runtime):   ~1.5 KB  （几乎无运行时！）
Solid JS:           ~7 KB


内存占用（中等复杂度应用）：

React:  高（VNode 树 + Fiber 节点 + 闭包）
Vue:    中（VNode + Dep + Watcher + Proxy）
Svelte: 低（仅组件实例 + DOM 引用）
Solid:  低（Signal + Effect + DOM 引用）
```

### 开发体验对比

| 维度 | Vue/React | Svelte | Solid |
|------|----------|--------|-------|
| **调试工具** | 成熟 DevTools | 较好但生态较小 | 正在发展 |
| **TypeScript** | 原生支持好 | 支持 | 优秀 |
| **SSR 支持** | 完善 | SvelteKit | SolidStart |
| **学习曲线** | 中等 | 低 | 中等（需理解 Signal 语义） |
| **社区规模** | 非常大 | 快速增长 | 小众但活跃 |
| **生态系统** | 极丰富 | 增长中 | 精品少 |

## 小结

| 框架 | 响应式策略 | 核心优势 | 核心取舍 |
|------|-----------|---------|---------|
| **Vue** | 运行时 Proxy 劫持 | 平衡性能与开发体验 | VDOM 开销 + Proxy 兼容性 |
| **React** | 不可变状态 + 调度渲染 | 生态最大、并发模式领先 | 手动优化负担重 |
| **Svelte** | 编译时分析 + 赋值拦截 | 极小体积、极快运行 | 编译器复杂度高、动态特性受限 |
| **Solid** | 编译注入 Signal | 细粒度更新的极致性能 | 函数式取值语义需习惯 |

编译时响应式代表了前端框架的一个重要演进方向——**把更多工作从运行时转移到构建时**。Svelte 和 Solid 分别从"无运行时"和"精细 Signal"两个角度验证了这条路的可行性。
