这一模块梳理多框架 Signal 方案，提炼统一模型，帮助你建立可迁移的状态设计方法。

## Signal 的统一概念

### 什么是 Signal？

Signal 是一个**持有值并能在值变化时通知订阅者**的响应式原语。它是目前跨框架响应式最成功的统一抽象：

```
┌──────────────┐    读取 (get)     ┌──────────────┐
│              │ ◀───────────────── │   Consumer   │
│   Signal     │                   │ (Effect/UI)  │
│              │ ─────────────────▶ │              │
└──────────────┘    写入 (set)      └──────────────┘
       │
       │ 值变化时通知所有消费者
       ▼
```

**核心特征：**

1. **持有当前值**（类似 ref/useState）
2. **读取时自动追踪依赖**（类似 reactive getter）
3. **写入时自动传播更新**（类似 trigger）
4. **可组合**（signal 可以派生新的 signal）

### 统一 Signal 模型

所有主流 Signal 实现都可以归纳为以下接口：

```ts
interface Signal<T> {
  // 读取当前值（在 effect 上下文中自动建立依赖）
  get(): T;

  // 可选：写入新值（只读 signal 无此方法）
  set(value: T): void;
  // 或
  update(fn: (prev: T) => T): void;

  // 订阅变化回调（可选 API）
  subscribe(listener: (value: T) => void): UnsubscribeFn;
}
```

## Preact Signals

Preact 的 Signal 是最早推动 Signal 标准化的重要实现之一。

### 基础用法

```jsx
import { signal, computed, effect } from '@preact/signals';

// 创建 Signal —— 类似于 ref
const count = signal(0);
const name = signal('Alice');

// 读取 —— 通过 .value 属性
console.log(count.value);  // 0

// 写入 —— 直接赋值 .value
count.value = 1;

// 函数式更新
count.value = count.value + 1;
// 或使用 peek() 在不触发依赖的情况下读取
```

### Computed Signal

```jsx
import { signal, computed } from '@preact/signals';

const firstName = signal('Alice');
const lastName = signal('Smith');

// computed —— 自动缓存 + 懒求值
const fullName = computed(() => `${firstName.value} ${lastName.value}`);

// 只有在 fullName 被读取时才计算
console.log(fullName.value);  // "Alice Smith"

// 依赖变化后自动标记为脏
firstName.value = 'Bob';
// 下次读取 fullName.value 时才重新计算
```

### Effect

```jsx
import { effect } from '@preact/signals';

effect(() => {
  console.log(`Name changed to: ${fullName.value}`);
});

// 任何被读取的 signal 变化都会重新执行此 effect
firstName.value = 'Charlie';  // 触发 effect 重新执行
```

### 与 React 集成

```jsx
import { useSignals, useSignal, useComputedEffect } from '@preact/signals-react';

function Counter() {
  const count = useSignal(0);

  return (
    <button onClick={() => count.value++}>
      Count: {count.value}  {/* 自动在组件中建立依赖 */}
    </button>
  );
}

// useSignals() 包裹组件树启用 Signal 支持
function App() {
  return (
    <useSignals.Provider>
      <Counter />
    </useSignals.Provider>
  );
}
```

## Angular Signals

Angular 16+ 引入的 Signal 系统，是 Angular 向细粒度响应式演进的关键一步。

### 基础 Signal

```typescript
import { signal, computed, effect } from '@angular/core';

@Component({
  selector: 'app-counter',
  template: `
    <p>Count: {{ count() }}</p>          <!-- 用 () 调用读取 -->
    <p>Doubled: {{ doubledCount() }}</p>
    <button (click)="increment()">+</button>
  `,
})
export class CounterComponent {
  // Writable Signal
  count = signal(0);

  // Read-only Computed Signal
  doubledCount = computed(() => this.count() * 2);

  increment() {
    this.count.update(c => c + 1);  // 函数式更新
    // 或 this.count.set(5);         // 直接设置
  }

  constructor() {
    // Effect —— 副作用
    effect(() => {
      console.log(`Count is now: ${this.count()}`);
    });
  }
}
```

### Angular Signal 类型

```typescript
import { signal, computed, WritableSignal } from '@angular/core';

// 1. WritableSignal —— 可读可写
const count: WritableSignal<number> = signal(0);
count.set(5);
count.update(v => v * 2);
count.mutate(obj => obj.items.push(1));  // 对象内部修改

// 2. Signal (read-only) —— 只能通过 computed 创建
const doubled: Signal<number> = computed(() => count() * 2);

// 3. 带初始值的 computed
const items = signal([1, 2, 3]);
const firstItem = signal(() => {
  const list = items();
  return list.length > 0 ? list[0] : null;
});
```

### 模板中的 Signal 表达式

```html
<!-- Angular 模板中使用 Signal -->
<p>{{ userName() }}</p>

<!-- 条件渲染 -->
@if (showDialog()) { <dialog /> }

<!-- 循环 -->
@for (item of items(); track item.id) {
  <li>{{ item.name }}</li>
}
```

Angular 编译器会自动将 `signal()` 调用转化为高效的变更检测逻辑，只在真正变化的 Signal 处触发模板更新。

## Vue ref 作为 Signal

Vue 3 的 `ref` 本质上就是一个 Signal——它完全符合 Signal 的核心定义。

### ref ≈ Signal

```vue
<script setup>
import { ref, computed, watchEffect } from 'vue';

// 这就是一个 Signal！
const count = ref(0);

// computed 就是派生 Signal
const doubled = computed(() => count.value * 2);

// watchEffect 就是自动追踪的 effect
watchEffect(() => {
  console.log(`Count: ${count.value}, Doubled: ${doubled.value}`);
});

// 使用
count.value++;  // 触发 watchEffect 和 computed 重算
</script>

<template>
  <!-- 模板中自动解包 .value -->
  {{ count }} × 2 = {{ doubled }}
</template>
```

### Vue Signal vs 标准 Signal 差异

| 特性 | Vue ref | 纯粹 Signal |
|------|---------|-------------|
| 取值方式 | `.value` | `.value` / `()` |
| 对象包装 | `reactive()` | 不区分 |
| 模板解包 | 自动解包 | 取决于框架集成 |
| shallow 版本 | `shallowRef` | 通常有对应 API |
| SSR 支持 | ✅ 完善 | 因实现而异 |

### 将 Vue reactivity 作为独立库使用

Vue 3 的响应式系统是框架无关的，可以直接在其他项目中使用：

```js
// npm install @vue/reactivity
import {
  reactive,
  ref,
  computed,
  effect,
  watch,
} from '@vue/reactivity';

// 完全脱离 Vue 框架使用响应式系统
const state = reactive({
  user: { name: '', age: 0 },
});

const isAdult = computed(() => state.user.age >= 18);

effect(() => {
  if (isAdult.value) {
    document.title = `Welcome, ${state.user.name}`;
  }
});

state.user.name = 'Alice';
state.user.age = 25;  // → 自动更新 document.title
```

## Solid createSignal

Solid 的 Signal 是性能最强的实现之一，也是 Signal 设计理念的先驱。

### 核心 API

```jsx
import { createSignal, createMemo, createEffect } from 'solid-js';

// [getter, setter] 元组形式返回
const [count, setCount] = createSignal(0);

// 读取 —— 函数调用
console.log(count());  // 0

// 写入 —— 多种方式
setCount(5);                    // 直接设值
setCount(prev => prev + 1);     // 函数式更新

// Computed —— 缓存派生值
const doubled = createMemo(() => count() * 2);

// Effect —— 副作用
createEffect(() => {
  console.log(`Count: ${count()}, Doubled: ${doubled()}`);
});
```

### Solid Signal 的独特之处

```jsx
// 1. 同步执行 —— 没有 batch/nextTick
setCount(1);
// 所有依赖 count 的 effect 已经同步执行完毕！

// 2. 细粒度 DOM 更新 —— JSX 编译为真实 DOM 操作
return (
  <>
    <p>{count()}</p>        {/* 只更新这个 p 的文本内容 */}
    <p>{doubled()}</p>      {/* 如果 doubled 依赖不变则不更新 */}
  </>
);

// 3. 无 Virtual DOM
// Solid 的编译器直接将 JSX 转化为 DOM 创建和绑定代码
```

## 各框架 Signal 对照表

### API 映射

| 操作 | Preact | Angular | Vue | Solid |
|------|--------|---------|-----|-------|
| **创建** | `signal(0)` | `signal(0)` | `ref(0)` | `createSignal(0)` |
| **读取** | `.value` | `()` | `.value` | `fn()` |
| **写入** | `.value = x` | `.set(x)` / `.update(f)` | `.value = x` | `setter(x)` |
| **函数式写** | 手动 | `.update(f)` | — | `setter(f)` |
| **派生** | `computed(fn)` | `computed(fn)` | `computed(fn)` | `createMemo(fn)` |
| **副作用** | `effect(fn)` | `effect(fn)` | `watchEffect(fn)` | `createEffect(fn)` |
| **监听特定源** | `effect(fn, [s])` | `effect(fn)` + 手动控制 | `watch(s, cb)` | 无内置（需自建） |
| **返回值** | 单个对象 | 单个对象 | 单个对象 | `[get, set]` 元组 |

### 行为差异

| 行为 | Preact | Angular | Vue | Solid |
|------|--------|---------|-----|-------|
| **批处理** | 微任务 batch | Zoneless 默认批量 | nextTick (微任务) | 无（同步） |
| **嵌套追踪** | ✅ | ✅ | ✅ | ✅ |
| **循环依赖检测** | ✅ | ✅ | ⚠️ 有限 | ✅ |
| **内存管理** | 手动 dispose | 自动（Zone） | 自动（组件卸载） | 自动（组件卸载） |
| **SSR** | ✅ | ✅ | ✅ | ✅ (SolidStart) |

### 性能基准对比

```
创建 10000 个 Signal 并建立 10000 个 effect：
Preact Signals:  ~8ms
Angular Signals: ~15ms
Vue ref:          ~12ms
Solid Signal:     ~5ms

触发 10000 个 Signal 更新：
Preact Signals:  ~4ms  （批量）
Angular Signals: ~6ms  （批量）
Vue ref:         ~3ms  （nextTick 批量）
Solid Signal:    ~2ms  （同步但极快）

内存占用（每个 Signal）：
Preact:   ~80 bytes
Angular:  ~120 bytes
Vue:      ~100 bytes
Solid:    ~60 bytes
```

## Signal 统一模型的优缺点

### 优点

1. **跨框架一致性**
   ```js
   // 学会一种 Signal 模型，可以快速适应任何框架的实现
   const state = createSomeSignal({ count: 0 });
   const double = createSomeComputed(() => state.count * 2);
   ```

2. **极致的更新粒度**
   - 只有真正使用了某个 Signal 的 UI 片段才会更新
   - 避免"一个叶子变化导致整棵树重绘"

3. **可预测的数据流**
   ```
   Source Signal → Derived Signal → Effect/DOM
   单向、清晰、可调试
   ```

4. **与不可变状态互补**
   ```js
   // Signal 存储最新引用，内部数据可以保持不可变
   const [state, setState] = signal(initialState);
   
   setState(prev => ({
     ...prev,
     items: [...prev.items, newItem],
   }));
   ```

### 缺点

1. **语义噪音**
   ```jsx
   // 到处都是 () 和 .value
   <div>{count()} {name()} {items().length}</div>
   // 或
   <div>{count.value} {name.value} {items.value.length}</div>
   ```

2. **粒度过细可能导致过度碎片化**
   ```js
   // 过度拆分反而增加心智负担
   const firstName = signal('');
   const lastName = signal('');
   const email = signal('');
   const phone = signal '';
   // ... 有时 reactive/ref({ user: {} }) 更合理
   ```

3. **生态成熟度不均**
   - Preact/Angular/Solid 的 Signal 生态还在发展中
   - 中间件/DevTools/调试工具不如 React/Vue 成熟

4. **学习曲线（对传统开发者）**
   - 需要理解"函数调用即取值"的语义
   - 需要理解何时会触发追踪、何时不会

## 小结

Signal 正在成为前端响应式的**通用语言**。无论你使用哪个框架，掌握 Signal 模型都意味着：

- 掌握了**一种可移植的状态设计能力**
- 能够理解**各框架响应式系统的共同本质**
- 为未来的**标准化 Signal API**（如果 TC39 通过提案）做好准备

推荐的学习路径：**先精通一种实现（如 Vue ref 或 Solid Signal），再通过对照表映射到其他框架**。
