这一模块对比主流状态管理方案，关注可维护性、性能和团队协作成本之间的平衡。

## 状态管理的演进脉络

```
第一代：全局变量 / 事件总线
  └→ 简单但不可扩展

第二代：Flux / Redux（2014+）
  └→ 单向数据流，可预测，但样板代码多

第三代：MobX / Vuex（2016+）
  └→ 响应式状态，开发体验好，但魔法较多

第四代：原子化状态（2020+）
  ├→ Jotai / Recoil（React）
  ├→ Zustand（React，简化版 Redux）
  └→ Valtio（Proxy-based，跨框架友好）

第五代：Signal + Store（2022+）
  ├→ Pinia（Vue 3 官方）
  ├→ Angular Signals + injectable services
  └→ Nanostores（框架无关 Signal store）
```

## MobX（可观察对象与装饰器）

### 核心理念：一切皆可观察

```js
import { makeAutoObservable, action, computed, observable } from 'mobx';

class TodoStore {
  // Observable State
  todos = [];
  filter = 'all';

  constructor() {
    // 自动推断：数组 → observable, 函数 → action, getter → computed
    makeAutoObservable(this);
  }

  // Computed
  get filteredTodos() {
    switch (this.filter) {
      case 'active':   return this.todos.filter(t => !t.done);
      case 'completed': return this.todos.filter(t => t.done);
      default:         return this.todos;
    }
  }

  // Action
  addTodo(text) {
    this.todos.push({
      id: Date.now(),
      text,
      done: false,
    });
  }

  toggleTodo(id) {
    const todo = this.todos.find(t => t.id === id);
    if (todo) todo.done = !todo.done;
  }

  setFilter(filter) {
    this.filter = filter;
  }
}

// 创建实例
const store = new TodoStore();

// 任意地方使用 —— 自动追踪依赖
autorun(() => {
  console.log(`${store.filteredTodos.length} tasks remaining`);
});
```

### MobX 的响应式机制

```
MobX 基于装饰器/Proxy 实现响应式：

Observable Value (observable)
  ↓ 读取时
Reaction (autorun / reaction / component)
  ↓ 写入时
自动触发依赖它的 Reaction 重跑

关键规则：
1. Action 内修改状态（可选但推荐）
2. Computed 派生值（带缓存）
3. Reaction 连接到 UI
```

**优点：**
- 极少的样板代码
- 自动的细粒度依赖追踪
- 天然的 TypeScript 支持
- 支持复杂图结构（循环引用等）

**缺点：**
- 隐式依赖可能让数据流难以追踪
- 调试困难（"是谁改了这个值？"）
- 与 React StrictMode 兼容性需注意

## Redux（单向数据流与不可变）

### 三大原则

```
1. Single Source of Truth（单一数据源）
   └→ 整个应用的 state 存在一个 object tree 里
   
2. State is Read-Only（状态只读）
   └→ 只能通过 dispatch(action) 来改变
   
3. Changes are Made with Pure Functions（纯函数修改）
   └→ Reducer 必须是纯函数：(state, action) => newState
```

### 现代 Redux Toolkit (RTK)

```tsx
import { createSlice, configureStore } from '@reduxjs/toolkit';
import { Provider, useDispatch, useSelector } from 'react-redux';

// ===== Slice：自动生成 Action Creator 和 Reducer =====
const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    incremented: (state) => {
      // Immer 允许直接"修改"！内部处理不可变性
      state.value += 1;
    },
    decremented: (state) => {
      state.value -= 1;
    },
    incrementedByAmount: (state, action) => {
      state.value += action.payload;
    },
  },
});

// 自动生成的 actions:
// { type: 'counter/incremented' }
// { type: 'counter/decremented' }
// { type: 'counter/incrementedByAmount', payload: 5 }

// ===== Store 配置 =====
export const store = configureStore({
  reducer: {
    counter: counterSlice.reducer,
  },
});

// ===== 组件中使用 =====
function Counter() {
  const dispatch = useDispatch();
  const count = useSelector(state => state.counter.value);

  return (
    <div>
      <span>{count}</span>
      <button onClick={() => dispatch(counterSlice.actions.incremented())}>+</button>
    </div>
  );
}

function App() {
  return (
    <Provider store={store}>
      <Counter />
    </Provider>
  );
}
```

### Redux 中间件模式

```tsx
// 异步操作：Redux Thunk / RTK Query
const userSlice = createSlice({
  name: 'user',
  initialState: { data: null, loading: false, error: null },
  reducers: {},
  extraReducers: (builder) => {
    builder
      .addCase(fetchUser.pending, (state) => { state.loading = true; })
      .addCase(fetchUser.fulfilled, (state, action) => {
        state.data = action.payload;
        state.loading = false;
      })
      .addCase(fetchUser.rejected, (state, action) => {
        state.error = action.error.message;
        state.loading = false;
      });
  },
});

// RTK Query —— 数据获取的一等公民
const api = createApi({
  baseQuery: fetchBaseQuery({ baseUrl: '/api' }),
  endpoints: (builder) => ({
    getUser: builder.query<{ name: string }, number>({
      query: (id) => `/users/${id}`,
    }),
  }),
});
```

## Zustand / Jotai（原子化）

### Zustand —— 最小化的 Redux 替代品

```tsx
import { create } from 'zustand';
import { devtools, persist } from 'zustand/middleware';

// ===== 基础用法 =====
const useStore = create((set) => ({
  bears: 0,
  increasePopulation: () => set((state) => ({ bears: state.bears + 1 })),
  removeAllBears: () => set({ bears: 0 }),
}));

function BearCounter() {
  const bears = useStore(state => state.bears);
  return <>There are {bears} bears around here...</>;
}

function Controls() {
  const increasePopulation = useStore((state) => state.increasePopulation);
  return <button onClick={increasePopulation}>one up</button>;
}

// ===== 中间件链 =====
const usePersistedStore = create(
  persist(
    devtools(
      (set) => ({
        user: null,
        login: (userData) => set({ user: userData }),
        logout: () => set({ user: null }),
      }),
      { name: 'app-store' }
    ),
    { name: 'app-storage', partialize: (s) => ({ user: s.user }) }
  )
);

// ===== 切片模式 =====
const createBearSlice = (set) => ({
  bears: 0,
  increase: () => set((s) => ({ bears: s.bears + 1 })),
});

const createFishSlice = (set) => ({
  fishes: 0,
  addOne: () => set((s) => ({ fishes: s.fisheses + 1 })),
});

const useCombinedStore = create((...args) => ({
  ...createBearSlice(...args),
  ...createFishSlice(...args),
}));
```

### Jotai —— 原子化状态管理

```tsx
import { atom, useAtom, useAtomValue, useSetAtom } from 'jotai';
import { atomWithStorage, atomWithQuery } from 'jotai/utils';
import { atomWithImmer } from 'jotai/immer';

// ===== 原子（Atom）：最小的状态单元 =====
const countAtom = atom(0);           // 原始 Atom
const textAtom = atom('hello');       // 字符串 Atom

// ===== 派生原子（Derived Atom）：自动追踪依赖 =====
const doubledAtom = atom((get) => get(countAtom) * 2);
const greetingAtom = atom((get) => `Hello, ${get(textAtom)}!`);

// ===== 异步原子 =====
const userAtom = atom(async (get) => {
  // 依赖其他原子
  const userId = get(userIdAtom);
  const res = await fetch(`/api/users/${userId}`);
  return res.json();
});

// ===== 使用 =====
function Counter() {
  const [count, setCount] = useAtom(countAtom);  // 读写
  const doubled = useAtomValue(doubledAtom);      // 只读
  const setOnly = useSetAtom(countAtom);          // 只写

  return (
    <>
      <span>{count} × 2 = {doubled}</span>
      <button onClick={() => setCount(c => c + 1)}>+</button>
    </>
  );
}

// ===== 特殊原子 =====
const storageAtom = atomWithStorage('theme', 'dark');  // 持久化到 localStorage
const queryAtom = atomWithQuery(getData);               // 与 TanStack Query 集成
const immerAtom = atomWithImmer({ items: [] });          // Immer 集成
```

**Zustand vs Jotai：**

| 维度 | Zustand | Jotai |
|------|---------|-------|
| **模型** | 单一 Store + Selector | 原子（Atom）网络 |
| **粒度** | 组件级选择器优化 | 原子级精确重渲染 |
| **适用场景** | 全局状态为主 | 大量局部/共享状态混合 |
| **学习成本** | 低 | 中（需要理解原子组合） |
| **DevTools** | 完善（devtools middleware） | 较好（Jotai Devtools） |

## Valtio（基于 Proxy）

Valtio 利用 Proxy 提供了类似 Vue 的响应式体验，且支持 React 和 Vanilla JS。

```tsx
import { proxy, useSnapshot } from 'valtio';

// ===== 定义代理状态 =====
const state = proxy({
  count: 0,
  text: 'hello',
  nested: {
    items: [] as string[],
  },
});

// ===== 修改 —— 直接改就行 =====
state.count++;
state.nested.items.push('new item');

// ===== React 组件中使用 =====
function Counter() {
  // useSnapshot 返回代理对象的快照（只读）
  const snap = useSnapshot(state);

  return (
    <div>
      {/* snap.count 变化时组件才重渲染 */}
      <p>Count: {snap.count}</p>
      <button onClick={() => state.count++}>+</button>
    </div>
  );
}

// ===== 订阅特定属性（非 React 环境） =====
subscribe(state.nested.items, () => {
  console.log('Items changed:', [...state.nested.items]);
});

// ===== 派生状态 =====
import { proxyWithComputed } from 'valtio/utils';

const state = proxyWithComputed(
  {
    firstName: 'Alice',
    lastName: 'Smith',
  },
  {
    // Computed 属性（只读）
    fullName: (get) => `${get.firstName} ${get.lastName}`,
  }
);

// state.fullName 是自动更新的
console.log(state.fullName);  // "Alice Smith"
state.firstName = 'Bob';
console.log(state.fullName);  // "Bob Smith"
```

**Valtio 特点：**
- 语法最接近 Vue/MobX（直接修改对象即可）
- 基于 Proxy，天然支持深层嵌套
- `useSnapshot` 提供 React 集成的细粒度更新
- 支持非 React 场景（Vanilla JS / Node.js）

## Pinia（Vue 官方）

Pinia 是 Vue 3 的官方状态管理库，设计上结合了 Vuex 的简洁性和 Composition API 的灵活性。

### Store 定义

```ts
// stores/counter.ts
import { defineStore } from 'pinia';

// Options API 风格
export const useCounterStore = defineStore('counter', {
  state: () => ({
    count: 0,
    user: null as User | null,
  }),

  getters: {
    // 类似 computed
    doubled: (state) => state.count * 2,

    // 可以访问其他 getter
    summary: (state): string =>
      `${state.user?.name ?? 'Guest'}: ${state.count}`,

    // 返回函数以接受参数
    getCountMultiplier: (state) => {
      return (multiplier: number) => state.count * multiplier;
    },
  },

  actions: {
    // 可以是异步的！
    increment() {
      this.count++;
    },

    async fetchUser(id: number) {
      this.user = await api.getUser(id);
    },

    $reset() {
      // 自动生成的重置方法
      this.$reset();
    },
  },
});
```

### Composition API 风格（Setup Store）

```ts
// stores/cart.ts —— 推荐
import { defineStore } from 'pinia';
import { ref, computed } from 'vue';
import { useAuthStore } from './auth';  // 跨 Store 组合

export const useCartStore = defineStore('cart', () => {
  // State —— 相当于 ref / reactive
  const items = ref<CartItem[]>([]);
  const couponCode = ref<string | null>(null);

  // Getters —— 相当于 computed
  const itemCount = computed(() => items.value.reduce((sum, i) => sum + i.qty, 0));
  const subtotal = computed(() => items.value.reduce((sum, i) => sum + i.price * i.qty, 0));

  const discount = computed(() => {
    if (!couponCode.value) return 0;
    return applyCoupon(subtotal.value, couponCode.value);
  });

  const total = computed(() => subtotal.value - discount.value);

  // Actions —— 普通函数
  function addItem(item: CartItem) {
    const existing = items.value.find(i => i.id === item.id);
    if (existing) {
      existing.qty += item.qty;
    } else {
      items.value.push(item);
    }
  }

  async function checkout() {
    const auth = useAuthStore();
    if (!auth.isLoggedIn) throw new Error('Not authenticated');

    await api.createOrder({
      userId: auth.user!.id,
      items: items.value,
      total: total.value,
    });

    items.value = [];  // 清空购物车
  }

  // $onAction 用于拦截/日志
  function $onAction(context) {
    console.log(`Action "${context.name}" started`);
  }

  // 返回的所有内容都公开可用
  return {
    items,
    couponCode,
    itemCount,
    subtotal,
    discount,
    total,
    addItem,
    checkout,
  };
});
```

### 在组件中使用

```vue
<script setup>
import { useCartStore } from '@/stores/cart';
import { storeToRefs } from 'pinia';

const cart = useCartStore();

// storeToRefs 保持响应性解构
const { itemCount, total } = storeToRefs(cart);

// Actions 直接解构即可（不需要保持响应性）
const { addItem, checkout } = cart;
</script>

<template>
  <div>
    <p>{{ itemCount }} items — Total: ¥{{ total }}</p>
    <button @click="addItem({ id: 1, name: 'Widget', price: 99, qty: 1 })">
      Add Widget
    </button>
  </div>
</template>
```

## 选型决策指南

```
你的项目需求是什么？

├── 团队规模小 / 项目简单
│   └→ props + emit + 少量 provide/inject 就够了
│
├── 中等规模，需要全局共享状态
│   ├── Vue 项目 → **Pinia**（官方、TypeScript 友好）
│   ├── React 项目，偏好简单 → **Zustand**（最小化、灵活）
│   └── React 项目，偏好细粒度 → **Jotai**（原子化）
│
├── 大型企业应用
│   ├── 需要 DevTools / 时间旅行 → **Redux (RTK)** 或 **MobX + mobx-state-tree**
│   ├── 需要服务端状态管理 → **RTK Query** / **TanStack Query**
│   └── 跨框架共享状态 → **Valtio** 或 **Nanostores**（基于 Signal）
│
└── 需要极致性能
    ├── 细粒度更新 → **Jotai** / **Solid Store**
    └── 零开销 → **Svelte Stores** / **Angualr Signals**
```

## 小结

| 库 | 核心范式 | 响应式策略 | 最佳场景 |
|----|---------|-----------|---------|
| **MobX** | OOP + 装饰器 | Observable + Auto-run | 复杂状态关系图 |
| **Redux (RTK)** | 函数式 + 不可变 | Dispatch + Reducer | 企业级大型应用 |
| **Zustand** | 极简 Hook API | Selector 订阅 | 快速开发的 React 项目 |
| **Jotai** | 原子化 | 原子依赖图 | 大量局部/共享状态混合 |
| **Valtio** | Proxy 代理 | Proxy 劫持 | 跨框架 / 类 Vue 体验 |
| **Pinia** | Composition API | Vue reactive | Vue 3 项目的标准答案 |
