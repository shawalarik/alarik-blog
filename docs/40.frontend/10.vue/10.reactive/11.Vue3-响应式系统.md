这一模块分析 Vue 3 的响应式升级路径，重点理解 API 设计与运行时机制的协同关系。

## 整体架构演进

Vue 3 响应式系统的核心变化：

```
Vue 2                              Vue 3
─────────                          ─────────
Object.defineProperty                Proxy + Reflect
Dep (每个属性一个)                   Dep (每个属性一个，重构为 Map)
Watcher（统一）                     ReactiveEffect（统一）+ track/trigger
nextTick (callbacks + timerFunc)    nextTick (Promise.resolve().then())
手动 $set/$delete                   Proxy 原生支持
数组变异方法 hack                    Proxy 原生支持所有操作
```

## Proxy + Reflect

### 基本拦截

```js
// @vue/reactivity/src/reactive.ts — 简化版

const mutableHandlers = {
  get(target, key, receiver) {
    // 内置 Symbol 和特殊 key 不做响应式
    if (key === ReactiveFlags.IS_REACTIVE) return true;
    if (key === ReactiveFlags.RAW) return target;

    // 依赖收集
    track(target, TrackOpTypes.GET, key);

    // Reflect.get 保持 receiver 链
    const res = Reflect.get(target, key, receiver);

    // 如果是对象，懒代理（shallowReactive 除外）
    if (isObject(res)) {
      return reactive(res);  // 惰性代理，按需创建
    }

    return res;
  },

  set(target, key, value, receiver) {
    // 先获取旧值
    const oldValue = target[key];

    const result = Reflect.set(target, key, value, receiver);

    // 判断是否真的发生了变化
    // 处理 NaN !== NaN 的特殊情况
    const hadKey = isArray(target)
      ? Number(key) < target.length
      : hasOwn(target, key);

    if (
      (hadKey || !(key in target)) &&
      value !== oldValue &&
      (value === value || oldValue === oldValue)  // NaN check
    ) {
      // 区分 ADD 还是 SET（对数组 length 变化有不同处理）
      trigger(
        target,
        hadKey ? TriggerOpTypes.SET : TriggerOpTypes.ADD,
        key,
        value,
      );
    }

    return result;
  },

  has(target, key) {
    track(target, TrackOpTypes.HAS, key);
    return Reflect.has(target, key);
  },

  deleteProperty(target, key) {
    const hadKey = hasOwn(target, key);
    const result = Reflect.deleteProperty(target, key);

    if (result && hadKey) {
      trigger(target, TriggerOpTypes.DELETE, key, undefined);
    }

    return result;
  },

  ownKeys(target) {
    track(target, TrackOpTypes.ITERATE, ITERATE_KEY);
    return Reflect.ownKeys(target);
  },
};
```

### Proxy vs defineProperty 的能力对比

| 操作 | Vue 2 (defineProperty) | Vue 3 (Proxy) |
|------|-----------------------|---------------|
| 属性读取 | ✅ | ✅ |
| 属性写入 | ✅ | ✅ |
| 新增属性 | ❌ 需要 `$set` | ✅ 原生支持 |
| 删除属性 | ❌ 需要 `$delete` | ✅ 原生支持 |
| `in` 操作符 | ❌ | ✅ |
| `for...in` / `Object.keys` | ⚠️ 有限支持 | ✅ |
| 数组索引修改 | ❌ | ✅ |
| 数组 `length` 修改 | ❌ | ✅ |
| `Map` / `Set` | ❌ | ✅ (`reactive(new Map())`) |
| 初始化性能 | 差（需递归遍历） | 好（惰性代理） |

## reactive / ref

### reactive — 对象响应式

```js
import { reactive } from 'vue';

const state = reactive({
  count: 0,
  user: { name: 'Alice', age: 25 },
  tags: ['vue', 'ts'],
});

// 所有操作都是响应式的
state.count++;              // ✅
state.user.name = 'Bob';    // ✅
state.tags.push('react');   // ✅
state.newField = 'hello';   // ✅ 新增属性！
delete state.count;         // ✅ 删除属性！
```

### ref — 基础类型响应式

为什么需要 `ref`？因为 **Proxy 只能代理对象**，无法代理基本类型（number、string、boolean）。

```js
import { ref } from 'vue';

const count = ref(0);       // number
const message = ref('hello'); // string
const visible = ref(true);   // boolean

// 访问需要 .value
console.log(count.value);    // 0
count.value++;

// 在模板中不需要 .value（模板自动解包）
// <template>{{ count }}</template>  ✅ 不需要 .value
```

### ref 的实现原理

```js
// @vue/reactivity/src/ref.ts — 简化版
class RefImpl {
  private _value;
  public readonly __v_isRef = true;
  public dep = new Dep();

  constructor(value, public readonly __v_isShallow) {
    this._value = __v_isShallow ? value : toReactive(value);
  }

  get value() {
    trackRefValue(this);  // 依赖收集
    return this._value;
  }

  set value(newVal) {
    const useDirectValue = this.__v_isShallow || isShallow(newVal) || newVal.isReadonly;
    newVal = useDirectValue ? newVal : toReactive(newVal);

    if (hasChanged(newVal, this._value)) {
      this._value = newVal;
      triggerRefValue(this);  // 触发更新
    }
  }
}

function ref(value) {
  return createRef(value, false);
}

function createRef(rawValue, shallow) {
  if (isRef(rawValue)) {
    return rawValue;  // 已经是 ref 就返回自身
  }
  return new RefImpl(rawValue, shallow);
}
```

### reactive vs ref 选择指南

| 场景 | 推荐 API | 原因 |
|------|---------|------|
| 对象/数组 | `reactive` | 无需 `.value`，语义自然 |
| 基本类型（number/string/boolean） | `ref` | 唯一选择 |
| 需要整体替换的对象 | `ref` | `reactive` 替换后失去响应性 |
| 解构后仍保持响应式 | `ref` | `toRefs` 配合使用 |
| 模板中频繁访问 | `ref` | 模板自动解包 `.value` |

```js
// reactive 替换陷阱
let state = reactive({ count: 0 });
state = reactive({ count: 1 });  // ❌ 失去响应性！原绑定的是旧对象

// ref 替换无此问题
let state = ref({ count: 0 });
state.value = { count: 1 };  // ✅ 正常工作
```

## computed / watch / watchEffect

### computed — 派生状态的缓存

```js
import { ref, computed } from 'vue';

const firstName = ref('Alice');
const lastName = ref('Smith');

const fullName = computed(() => `${firstName.value} ${lastName.value}`);

console.log(fullName.value);  // "Alice Smith"

firstName.value = 'Bob';
console.log(fullName.value);  // "Bob Smith" — 自动更新
```

#### 可写的 computed

```js
const count = ref(1);

const double = computed({
  get() {
    return count.value * 2;
  },
  set(newValue) {
    count.value = newValue / 2;  // 反向写入
  },
});

double.value = 10;  // count 自动变为 5
```

#### computed 内部实现要点

```js
// @vue/reactivity/src/computed.ts
class ComputedRefImpl extends RefImpl {
  #dirty = true;     // 脏标记
  #value;
  #effect;

  constructor(getter) {
    super();

    // 用 scheduler 实现惰性求值
    this.#effect = new ReactiveEffect(getter, () => {
      if (!this.#dirty) {
        this.#dirty = true;  // 依赖变了只标记脏，不立即算
        triggerRefValue(this);
      }
    });

    this.#effect.computed = this;
  }

  get value() {
    // 读取时如果脏了才重新计算
    if (this.#dirty) {
      this.#dirty = false;
      this.#value = this.#effect.run();  // 此时才真正执行 getter
    }
    trackRefValue(this);
    return this.#value;
  }
}
```

### watchEffect — 自动追踪依赖

```js
import { ref, watchEffect } from 'vue';

const count = ref(0);

watchEffect(() => {
  console.log(`count is: ${count.value}`);  // 自动追踪 count
  // 任何这里用到的响应式变量都会被自动追踪
});
// → "count is: 0"

count.value++;
// → "count is: 1"

watchEffect 的特点：
// 1. 自动收集依赖，无需显式声明源
// 2. 立即执行一次
// 3. 返回停止函数

const stop = watchEffect(() => { /* ... */ });
stop();  // 停止监听
```

### watch — 显式监听特定源

```js
import { ref, watch } from 'vue';

const count = ref(0);
const state = reactive({ name: 'Alice' });

// 监听单个 ref
watch(count, (newVal, oldVal) => {
  console.log(`count: ${oldVal} -> ${newVal}`);
});

// 监听 getter 函数
watch(
  () => state.name,
  (newVal, oldVal) => {
    console.log(`name: ${oldVal} -> ${newVal}`);
  }
);

// 监听多个源
watch(
  [count, () => state.name],
  ([newCount, newName], [oldCount, oldName]) => {
    console.log(`${oldCount},${oldName} → ${newCount},${newName}`);
  }
);

// 深度监听
watch(state, (newVal) => {
  console.log('deep change:', newVal);
}, { deep: true });  // 注意：不要对 getter 使用 deep

// watch vs watchEffect 的区别
// watch:
//   - 不会立即执行（除非 immediate: true）
//   - 明确知道什么触发了回调（能拿到旧值）
//   - 适合：需要在变化时做额外逻辑的场景
//
// watchEffect:
//   - 立即执行一次
//   - 不知道是什么变化导致的
//   -适合：副作用（打日志、DOM操作等）
```

## effect 副作用

### ReactiveEffect 类

```js
// @vue/reactivity/src/effect.ts
let activeEffect: ReactiveEffect | undefined;
const effectStack: ReactiveEffect[] = [];

class ReactiveEffect {
  // 公开字段
  active = true;
  deps: Dep[] = [];
  parent: ReactiveEffect | undefined = undefined;

  constructor(
    public fn: () => T,
    public scheduler?: EffectScheduler,
  ) {}

  run() {
    if (!this.active) return this.fn();

    // 避免 effect 嵌套时重复触发
    if (!effectStack.includes(this)) {
      try {
        this.parent = activeEffect;
        activeEffect = this;
        effectStack.push(this);

        // 清理旧依赖（优化：避免内存泄漏）
        cleanupEffect(this);

        return this.fn();  // 执行过程中会触发 track
      } finally {
        effectStack.pop();
        activeEffect = this.parent;
        this.parent = undefined;
      }
    }
  }

  stop() {
    if (this.active) {
      cleanupEffect(this);
      this.active = false;
    }
  }
}
```

### track 与 trigger

```js
// @vue/reactivity/src/effect.ts

// 依赖收集
function track(target, type, key) {
  if (!activeEffect || activeEffect.shouldTrack === false) return;

  let depsMap = targetMap.get(target);
  if (!depsMap) {
    targetMap.set(target, (depsMap = new Map()));
  }

  let dep = depsMap.get(key);
  if (!dep) {
    depsMap.set(key, (dep = new Set()));
  }

  if (!dep.has(activeEffect)) {
    dep.add(activeEffect);
    activeEffect.deps.push(dep);  // 双向关联
  }
}

// 触发更新
function trigger(target, type, key, newValue) {
  const depsMap = targetMap.get(target);
  if (!depsMap) return;

  const effectsToAdd = new Set<ReactiveEffect>();

  // 1. 触发具体 key 的 effects
  if (key !== void 0) {
    const dep = depsMap.get(key);
    dep && dep.forEach(effect => effectsToAdd.add(effect));
  }

  // 2. 触发迭代相关的 effects（数组长度变化、对象属性增删）
  if (type === TriggerOpTypes.ADD) {
    // 数组新增元素可能影响 length 相关的迭代
    if (isArray(target)) {
      const lengthEffects = depsMap.get('length');
      lengthEffects && lengthEffects.forEach(e => effectsToAdd.add(e));
    }
  }

  // 3. 触发 ITERATE_KEY（for...in、keys() 等）
  const iterateEffects = depsMap.get(ITERATE_KEY);
  iterateEffects && iterateEffects.forEach(e => effectsToAdd.add(e));

  // 4. 依次触发 effects
  effectsToAdd.forEach(effect => {
    if (effect.scheduler) {
      effect.scheduler(effect);  // 有调度器就走调度器
    } else {
      effect.run();             // 否则同步执行
    }
  });
}
```

### 依赖清理（Cleanup）

这是 Vue 3 响应式系统的一个重要优化——**分支切换时清理无用依赖**：

```js
const state = reactive({ flag: true, a: 1, b: 2 });

watchEffect(() => {
  if (state.flag) {
    console.log('a =', state.a);  // 分支 A：依赖 a
  } else {
    console.log('b =', state.b);  // 分支 B：依赖 b
  }
});

// 初始：flag=true → 收集依赖 [flag, a]
state.a = 99;   // ✅ 触发更新
state.b = 99;   // ❌ 不触发（不在依赖集中）

// 切换分支：
state.flag = false;
// → 清理旧依赖 [flag, a]，建立新依赖 [flag, b]

state.a = 99;   // ❌ 不再触发（依赖已清理）
state.b = 99;   // ✅ 触发更新
```

## 响应式 API 设计哲学

### 组合优于继承

Vue 3 的 Composition API 围绕响应式构建，而非 Options API 的黑盒：

```js
// Options API：响应式藏在 data/computed/watch 里
export default {
  data() {
    return { count: 0 };
  },
  computed: {
    doubled() { return this.count * 2; }
  },
  watch: {
    count(val) { console.log(val) }
  }
};

// Composition API：响应式是一等公民
function useCounter() {
  const count = ref(0);
  const doubled = computed(() => count.value * 2);
  watch(count, (v) => console.log(v));

  const increment = () => count.value++;

  return { count, doubled, increment };  // 显式暴露
}
```

### 惰性与按需

- **reactive**：只在属性被访问时才深层代理（惰性代理）
- **computed**：只有被读取且依赖变化后才重新计算（脏标记 + 按需求值）
- **watchEffect**：只在依赖变化后才重新执行

### 类型安全

```ts
import { ref, Ref, reactive, ComputedRef } from 'vue'

const count: Ref<number> = ref(0)
const user: User = reactive<User>({ name: '', age: 0 })
const double: ComputedRef<number> = computed(() => count.value * 2)

// TypeScript 能推断出正确的类型
count.value.toFixed(2)  // ✅ 编译正确
count.value.toUpperCase() // ❌ 类型错误
```

## 小结

| API | 用途 | 核心机制 |
|-----|------|---------|
| **reactive** | 对象/数组的深度响应式 | Proxy 拦截 + 惰性代理 |
| **ref** | 任意值的响应式包装 | getter/setter + Dep |
| **computed** | 缓存派生值 | dirty 标记 + scheduler 懒求值 |
| **watch** | 显式监听特定源 | 依赖预收集 + immediate/deep 选项 |
| **watchEffect** | 自动追踪依赖的副作用 | 自动依赖收集 + 立即执行 |
| **effect** | 底层副作用原语 | track/trigger + 依赖清理 |

Vue 3 的响应式系统相比 Vue 2 的改进不仅是底层技术升级（defineProperty → Proxy），更是 API 设计理念的进步——**将响应式作为一等公民暴露给开发者，而非隐藏在框架内部**。
