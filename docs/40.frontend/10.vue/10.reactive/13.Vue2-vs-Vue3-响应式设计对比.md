这一模块以对比视角梳理两代 Vue 响应式系统，帮助你在维护与迁移时更快做技术决策。

## 底层实现差异

### 数据劫持方式

```js
// ===== Vue 2: Object.defineProperty =====
// 对每个属性逐一定义 getter/setter
function defineReactive(obj, key, val) {
  const dep = new Dep();

  Object.defineProperty(obj, key, {
    get() {
      dep.depend();  // 收集依赖
      return val;
    },
    set(newVal) {
      if (val !== newVal) {
        val = newVal;
        dep.notify();  // 触发更新
      }
    },
  });

  // 递归处理嵌套对象（初始化时全部遍历）
  if (isObject(val)) {
    observe(val);
  }
}

// ===== Vue 3: Proxy + Reflect =====
// 代理整个对象，拦截所有操作
const handler = {
  get(target, key, receiver) {
    track(target, key);              // 收集依赖
    return Reflect.get(target, key, receiver);
  },
  set(target, key, value, receiver) {
    const result = Reflect.set(target, key, value, receiver);
    trigger(target, key, 'SET');     // 触发更新
    return result;
  },
};
```

| 能力 | Vue 2 (defineProperty) | Vue 3 (Proxy) |
|------|-----------------------|---------------|
| 属性读取/写入 | ✅ | ✅ |
| 新增属性检测 | ❌ 需要 `Vue.set()` | ✅ 原生支持 |
| 删除属性检测 | ❌ 需要 `Vue.delete()` | ✅ 原生支持 |
| 数组索引修改 | ❌ | ✅ |
| `in` 操作符 | ❌ | ✅ |
| `for...in` / `Object.keys` | ⚠️ 需手动触发 | ✅ |
| `Map` / `Set` | ❌ | ✅ |
| 初始化性能 | 差（递归遍历） | 好（惰性代理） |
| IE 兼容性 | ✅ (IE9+) | ❌ (IE 不支持) |

### 依赖收集机制

```js
// ===== Vue 2 =====
// 使用全局变量 + 手动栈管理
Dep.target = null;          // 全局变量存储当前 Watcher

function pushTarget(watcher) {
  targetStack.push(Dep.target);
  Dep.target = watcher;
}

function popTarget() {
  Dep.target = targetStack.pop();
}
```

```js
// ===== Vue 3 =====
// 同样是全局变量但重构了数据结构
let activeEffect: ReactiveEffect;
const effectStack: ReactiveEffect[] = [];

function run(effect) {
  try {
    effect.parent = activeEffect;
    activeEffect = effect;
    effectStack.push(effect);

    cleanupEffect(effect);   // 清理旧依赖
    effect.fn();             // 执行副作用（收集新依赖）
  } finally {
    effectStack.pop();
    activeEffect = effect.parent;
  }
}
```

Vue 3 的关键改进：**每次 effect 执行前先清理旧依赖再收集新依赖**，解决了 Vue 2 中分支切换时遗留无效依赖的问题。

## 性能对比

### 初始化性能

```js
// Vue 2：深度递归 defineProperty
const data = {
  user: { name: '', profile: { avatar: '' } },
  items: Array(1000).fill(0).map((_, i) => ({ id: i })),
};

observe(data);  // 遍历所有嵌套属性，逐个 defineProperty
// 大约 O(n) 个 defineProperty 调用，n 为所有属性总数
```

```js
// Vue 3：惰性 Proxy
const state = reactive(data);
// 只创建一层 Proxy，内部对象在被访问时才按需代理
// 初始化复杂度 O(1)
```

**实测对比（近似值）：**

| 场景 | Vue 2 | Vue 3 | 提升幅度 |
|------|-------|-------|---------|
| 创建 10K 属性的响应式对象 | ~50ms | ~0.5ms | **~100x** |
| 首次访问深层属性 | 即时 | ~0.01ms（创建子 Proxy） | - |
| 整体组件挂载（中等复杂度） | 基准 | **~2x 快** | **~2x** |
| 更新触发后重新渲染 | 基准 | **~1.5x 快** | **~1.5x** |

### 内存占用

```js
// Vue 2：每个属性需要
// - 一个闭包（getter/setter 的 val）
// - 一个 Dep 实例（subs 数组）
// 总计：每个属性 ~200 bytes（估算）

// Vue 3：每个属性只需要
// - targetMap 中的一个 Map entry（key → Set）
// 惰性创建：只有被追踪过的属性才分配内存
// 总计：被追踪的属性 ~80 bytes（估算）
```

### 更新效率

```js
// Vue 2：修改深层嵌套属性
this.user.profile.avatar = 'new.jpg';
// → 触发 profile 的 set
// → 触发 user 的 dep.notify()
// → Watcher.update() → queueWatcher → nextTick → re-render
// 但如果 profile 有很多其他属性，它们也可能被误追踪

// Vue 3：精确到属性的依赖追踪
state.user.profile.avatar = 'new.jpg';
// → trigger(state.user, 'profile') → trigger(profile, 'avatar')
// → 只有真正依赖 avatar 的 effect 被通知
```

## 限制突破

### 1. 属性增删

```vue
<!-- Vue 2：必须使用 $set -->
<template>
  <div>{{ obj.newProp }}</div>
</template>

<script>
export default {
  data() { return { obj: {} }; },
  mounted() {
    this.$set(this.obj, 'newProp', 'hello');  // 必须！直接赋值不生效
  },
};
</script>
```

```vue
<!-- Vue 3：直接赋值即可 -->
<template>
  <div>{{ obj.newProp }}</div>
</template>

<script setup>
const obj = reactive({});
onMounted(() => {
  obj.newProp = 'hello';  // 直接赋值即可！
});
</script>
```

### 2. 数组操作

```vue
<!-- Vue 2：限制较多 -->
<script>
export default {
  data() { return { list: [1, 2, 3] }; },
  methods: {
    addItem() {
      // ✅ 有效方式
      this.$set(this.list, 3, 4);
      this.list.push(4);
      this.list.splice(0, 1, 99);

      // ❌ 无效方式
      this.list[0] = 99;       // 无效
      this.list.length = 0;     // 无效
    },
  },
};
</script>
```

```vue
<!-- Vue 3：全部有效 -->
<script setup>
const list = reactive([1, 2, 3]);

function addItem() {
  // 所有方式都有效！
  list[0] = 99;        // ✅
  list.length = 0;     // ✅
  list.push(4);        // ✅
  list.splice(0, 1);   // ✅
}
</script>
```

### 3. Map / Set 支持

```js
// Vue 2：Map 和 Set 不是响应式的
const vm = new Vue({ data: { map: new Map() } });
vm.map.set('key', 'value');  // ❌ 不触发更新

// Vue 3：原生支持！
const state = reactive({ map: new Map(), set: new Set() });
state.map.set('key', 'value');  // ✅ 响应式
state.set.add('item');           // ✅ 响应式
state.map.delete('key');         // ✅ 响应式
state.set.clear();               // ✅ 响应式
```

### 4. reactive 对象整体替换

```js
// Vue 2
data() {
  return { form: { name: '', email: '' } };
},
methods: {
  resetForm() {
    // ⚠️ 这种写法在 Vue 2 中会导致响应丢失
    this.form = { name: '', email: '' };

    // 安全做法：
    Object.assign(this.form, { name: '', email: '' });
  }
}

// Vue 3
const form = reactive({ name: '', email: '' });
function resetForm() {
  // ❌ 这样做会失去响应性（reactive 返回的是原始对象的 Proxy）
  // form = reactive({ name: '', email: '' });

  // ✅ 推荐用 ref 包裹对象
  const formRef = ref({ name: '', email: '' });
  function resetForm() {
    formRef.value = { name: '', email: '' };  // 替换 .value 是安全的
  }

  // 或者清空现有对象
  Object.keys(form).forEach(key => delete form[key]);
}
```

## API 映射对照表

| Vue 2 | Vue 3 | 说明 |
|-------|-------|------|
| `data()` | `reactive()` / `ref()` | 响应式数据声明 |
| `computed: {}` | `computed(fn)` | 计算属性 |
| `watch: {}` | `watch(source, cb)` | 监听器 |
| （无） | `watchEffect(fn)` | 自动依赖追踪监听 |
| `Vue.set()` / `this.$set()` | **不需要** | Proxy 原生支持 |
| `Vue.delete()` / `this.$delete()` | **不需要** | Proxy 原生支持 |
| `props` | `defineProps()` | 组件属性 |
| `$emit` | `defineEmits()` | 事件发射 |
| `this.$nextTick(cb)` | `nextTick(cb)` | 异步 DOM 更新 |
| （无） | `shallowReactive()` | 浅层响应式 |
| （无） | `shallowRef()` | 浅层 ref |
| （无） | `toRaw()` | 获取原始非代理对象 |
| （无） | `markRaw()` | 标记对象不被代理 |
| （无） | `effectScope()` | 作用域内的自动清理 |

## 迁移注意事项

### 常见迁移陷阱

#### 1. `this` 语义变化

```js
// Vue 2：Options API 中 this 指向组件实例
export default {
  methods: {
    handleClick() {
      console.log(this.count);  // this.data.count
      this.$emit('click');
    },
  },
};

// Vue 3：Composition API 没有 this
import { ref, getCurrentInstance } from 'vue';

const count = ref(0);

function handleClick() {
  // 没有 this！所有数据都是显式导入的变量
  console.log(count.value);

  // 如果真的需要 this（不推荐）:
  const instance = getCurrentInstance();
  instance?.proxy?.$emit('click');
}
```

#### 2. 响应式解构丢失

```js
// Vue 2：解构不会破坏响应式（因为通过 this.xxx 访问）
computed: {
  formattedUser() {
    const { name, age } = this.user;  // 解构后仍能正常工作
    return `${name} (${age})`;
  }
}

// Vue 3：reactive 对象解构会丢失响应式！
const state = reactive({ name: 'Alice', age: 25 });

// ❌ 失去响应式
const { name, age } = state;
name = 'Bob';  // 不会触发更新！

// ✅ 正确做法一：保持引用
function format() { return `${state.name} (${state.age})`; }

// ✅ 正确做法二：toRefs
import { toRefs } from 'vue';

const { name, age } = toRefs(state);
name.value = 'Bob';  // ✅ 保持响应式
```

#### 3. watch 与 watchEffect 选择

```js
// Vue 2：watch 自动追踪表达式中的响应式属性
watch: {
  // 简写形式 — 相当于 watchEffect
  count(val) {
    console.log('count changed:', val);
  },

  // 完整形式 — 类似 Vue 3 的 watch
  deepObj: {
    handler(val, oldVal) { /* ... */ },
    deep: true,
    immediate: true,
  },
}

// Vue 3：明确区分 watch 和 watchEffect
watch(
  () => state.count,   // 明确指定源
  (newVal, oldVal) => { /* ... */ },  // 能拿到旧值
);

watchEffect(() => {
  console.log(state.count);  // 自动追踪，无旧值
});
```

#### 4. 生命周期钩子映射

| Vue 2 | Vue 3 (setup 内) | 变化 |
|-------|-------------------|------|
| `beforeCreate` | 不需要 | setup 本身在此阶段执行 |
| `created` | 不需要 | 同上 |
| `beforeMount` | `onBeforeMount` | - |
| `mounted` | `onMounted` | - |
| `beforeUpdate` | `onBeforeUpdate` | - |
| `updated` | `onUpdated` | - |
| `beforeDestroy` | **`onBeforeUnmount`** | 名称变更 |
| `destroyed` | **`onUnmounted`** | 名称变更 |
| errorCaptured | `onErrorCaptured` | - |
| - | **`onRenderTracked`** | 🆕 调试钩子 |
| - | **`onRenderTriggered`** | 🆕 调试钩子 |
| - | **`onServerPrefetch`** | 🆕 SSR 钩子 |

### 渐进式迁移策略

对于大型项目，建议采用渐进式迁移：

```
阶段 1：升级 Vue 2.7
├── 获得 Composition API 支持
├── 可以在 Options API 和 Composition API 之间过渡
└── 代码库无需大改

阶段 2：混合模式运行
├── 新页面/组件用 Composition API 编写
├── 旧组件逐步改造
└── 共享状态用 provide/inject 或 composable

阶段 3：完全迁移至 Vue 3
├── 升级构建工具（Vite）
├── 移除 $set/$delete 调用
├── 替换废弃的过滤器/事件总线等
└── 利用 Vue 3 新特性全面优化
```

## 小结

| 维度 | Vue 2 | Vue 3 |
|------|-------|-------|
| **核心劫持** | Object.defineProperty | Proxy + Reflect |
| **能力边界** | 属性增删需辅助 API、数组有限支持 | 全量操作原生响应式 |
| **初始性能** | 深度递归，O(n) | 惰性代理，O(1) |
| **更新精度** | 组件级粒度（配合 VNode diff） | 属性级细粒度依赖追踪 |
| **API 设计** | 黑盒（隐藏在 Options API 中） | 白盒（一等公民暴露） |
| **TypeScript** | 需要额外装饰器/类组件 | 原生完美支持 |
| **包体积** | 较小（功能集固定） | 可摇树优化（按需引入） |

从 Vue 2 到 Vue 3 的迁移不只是语法层面的改变，更是**思维模式的升级**——从"框架替你管理响应式"转变为"你显式地掌控响应式"。这种转变让代码更可预测、更易测试、更利于复用。
