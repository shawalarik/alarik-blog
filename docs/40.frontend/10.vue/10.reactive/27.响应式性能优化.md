这一模块聚焦性能瓶颈与优化策略，目标是减少无效追踪、缩小更新范围并降低重算成本。

## 性能瓶颈诊断

### 常见性能问题

| 问题类型 | 症状 | 根因 |
|----------|------|------|
| **过度渲染** | 一个小改动导致整页重新渲染 | 组件粒度过大、缺少 memoization |
| **依赖泄漏** | 无关数据变化触发不必要的 effect | 闭包捕获过多依赖、深层 reactive 全量追踪 |
| **频繁重算** | computed/expensive 函数反复执行 | 缓存失效、依赖链不稳定 |
| **内存增长** | 页面越用越卡 | 未取消的订阅、未清理的 observer |
| **初始化缓慢** | 白屏时间长 | 大型对象深度响应化、大量组件同时挂载 |

## 细粒度订阅

### 问题：大对象的粗粒度依赖

```js
const state = reactive({
  user: {
    name: 'Alice',
    age: 25,
    profile: {
      avatar: '',
      bio: '',
      settings: { /* 大量设置 */ }
    }
  },
  theme: 'dark',
  locale: 'zh-CN',
  notifications: [/* 很多通知 */],
});

// ❌ 问题：读取了整个 user 对象，任何子属性变化都触发此 effect
watchEffect(() => {
  console.log(`Hello, ${state.user.name}`);  // 只用了 name
  // 但 Vue 会追踪整个 state.user 的访问路径
  // 如果 user.profile.settings 变化，这个 effect 也会被触发！
});
```

### 解决方案一：精确到具体属性

```js
// ✅ 方案一：只访问需要的属性
watchEffect(() => {
  console.log(`Hello, ${state.user.name}`);  // 只追踪 name
  // 只有 state.user.name 变化才触发
});
```

```js
// ✅ 方案二：使用 computed 派生出需要的切片
const userName = computed(() => state.user.name);

watchEffect(() => {
  console.log(`Hello, ${userName.value}`);
  // 依赖于 computed，而 computed 只依赖 name
});
```

### 解决方案二：使用 toRefs 解构

```vue
<!-- ❌ 解构会丢失响应性 -->
<script setup>
const props = defineProps<{ user: User }>();
const { name, age } = props.user;  // 不是响应式的！
</script>

<!-- ✅ 使用 toRefs -->
<script setup>
import { toRefs, toRef } from 'vue';

const props = defineProps<{ user: User }>();

// 方式 A：解构整个对象的所有顶层属性
const { name, age } = toRefs(props.user);

// 方式 B：只解构需要的单个属性（更高效）
const name = toRef(props.user, 'name');
</script>
```

## shallowRef / shallowReactive

### shallowRef —— 跳过深层响应式转换

```vue
<script setup>
import { shallowRef, triggerRef, watchEffect } from 'vue';

// shallowRef 只对 .value 的赋值做响应式
// 内部对象不会变成 Proxy
const list = shallowRef([
  { id: 1, text: 'Learn Vue' },
  { id: 2, text: 'Build App' },
]);

watchEffect(() => {
  console.log(list.value.length);  // 只追踪 list.value 的引用
});

// ❌ 这不会触发更新！内部不是响应式的
list.value[0].text = 'Learn deeply';  // 静默修改，不触发

// ✅ 触发更新的正确方式
list.value = [...list.value];  // 替换引用 → 触发更新

// 或手动通知
triggerRef(list);              // 强制触发依赖它的 effect
</script>
```

**适用场景：**
- 大型不可变数据（替换整个引用比追踪每个属性更高效）
- 需要配合外部库（如 Three.js 对象、Monaco Editor 实例）
- 渲染大型列表（每项是复杂的对象树）

### shallowReactive —— 仅浅层响应式

```js
import { shallowReactive } from 'vue';

// 只有顶层属性是响应式的
const state = shallowReactive({
  counts: [1, 2, 3],        // 数组的 push/pop 等操作能被检测到
  nested: { a: 1 },         // 但 nested.a 不是响应式的
});

state.counts.push(4);       // ✅ 能检测到（数组方法被代理）
state.nested.a = 99;        // ❌ 检测不到！

// 配合 markRaw 标记不应被代理的对象
const rawObj = markRaw(new SomeExternalClass());
state.external = rawObj;     // rawObj 不会被转换为 Proxy
```

## Immer 优化不可变更新

### React 中的 Immer

```tsx
import { produce } from 'immer';
import { useState, useMemo } from 'react';

// ❌ 没有 Immer：深层嵌套的手动展开
function updateNested(state, path, value) {
  setState(prev => ({
    ...prev,
    users: prev.users.map(u =>
      u.id === path.userId ? {
        ...u,
        profile: {
          ...u.profile,
          settings: {
            ...u.profile.settings,
            theme: value,  // 展开每一层...
          }
        }
      } : u
    ),
  }));
}

// ✅ 使用 Immer：像修改一样写，但实际是不可变更新
function updateNestedImmer(path, value) {
  setState(produce(draft => {
    const user = draft.users.find(u => u.id === path.userId);
    if (user) {
      user.profile.settings.theme = value;  // "直接"修改！
    }
  }));
}

// 配合 Zustand 使用
import { create } from 'zustand';
import { devtools, persist } from 'zustand/middleware';
import { immer } from 'zustand/middleware/immer';

const useStore = create<
  State,
  [['zustand/devtools', never], ['zustand/persist', unknown], ['zustand/immer', never]]
>(
  devtools(
    persist(
      immer((set) => ({
        users: [] as User[],
        updateUserTheme: (userId, theme) =>
          set((state) => {
            const user = state.users.find(u => u.id === userId);
            if (user) user.profile.theme = theme;
          }),
      })),
      { name: 'app-store' }
    )
  )
);
```

### Immer 性能特性

```js
// 1. Structural Sharing（结构共享）
// 相同的部分复用引用，只有变化的路径创建新对象

// 2. Auto-freeze（自动冻结）
const nextState = produce(currentState, draft => {
  draft.items.push(newItem);
}, {
  // 开发模式下冻结状态防止意外修改
  freeze: process.env.NODE_ENV === 'development'
});

// 3. Patches —— 可以记录每次修改的增量
import { produceWithPatches, enablePatches } from 'immer';
enablePatches();

const [nextState, patches, inversePatches] = produceWithPatches(baseState, draft => {
  draft.items.push({ id: 4, text: 'New' });
});

console.log(patches);
// [{ op: 'replace', path: ['items', 3], value: { id: 4, text: 'New' } }]
// 可用于协作编辑、撤销/重做等功能
```

## React useMemo / useCallback

### useMemo —— 缓存昂贵计算

```tsx
function ProductList({ products, filter, sort }) {
  // ❌ 每次渲染都重新计算
  const filtered = products
    .filter(p => matchesFilter(p, filter))
    .sort(sortFn(sort));

  // ✅ 只在依赖变化时重算
  const filtered = useMemo(() =>
    products
      .filter(p => matchesFilter(p, filter))
      .sort(sortFn(sort)),
    [products, filter, sort]  // 依赖数组
  );

  return <ul>{filtered.map(p => <ProductItem key={p.id} product={p} />)}</ul>;
}
```

### useCallback —— 缓存回调函数

```tsx
function TodoList({ todos }) {
  // ❌ 每次渲染都创建新的函数引用
  // 导致接收此 prop 的子组件即使有 memo 也可能重渲染
  const handleToggle = (id: number) => {
    dispatch({ type: 'TOGGLE', payload: id });
  };

  // ✅ 函数引用稳定
  const handleToggle = useCallback((id: number) => {
    dispatch({ type: 'TOGGLE', payload: id });
  }, [dispatch]);  // dispatch 通常稳定不变

  return (
    <ul>
      {todos.map(todo =>
        <MemoTodoItem key={todo.id} todo={todo} onToggle={handleToggle} />
      )}
    </ul>
  );
}
```

### memo —— 避免不必要的子组件重渲染

```tsx
import { memo, useMemo } from 'react';

// 纯展示组件用 memo 包裹
const ListItem = memo(function ListItem({ item }: { item: Item }) {
  return (
    <li className={item.active ? 'active' : ''}>
      {item.name}
    </li>
  );
});

// 自定义比较函数（默认是浅比较）
const HeavyComponent = memo(function HeavyComponent({ data }) {
  return <ExpensiveVisualization data={data} />;
}, (prevProps, nextProps) => {
  // 只在特定条件时返回 false（允许重渲染）
  return prevProps.data.version === nextProps.data.version;
});
```

## 虚拟滚动中的响应式优化

### 问题：大量 DOM 节点

渲染 10000 条数据的列表会导致严重的性能问题——无论哪个框架。

```jsx
// ❌ 直接渲染全部数据 —— 可能导致页面卡死
<ul>
  {items.map(item => <li key={item.id}>{item.text}</li>)}
</ul>
```

### 虚拟滚动原理

```
可视区域（Viewport）
┌──────────────────────────┐
│ Item 45                  │  ← scrollTop = 4500 (每项高 100px)
│ Item 46                  │
│ Item 47                  │
│ Item 48                  │  可见约 10 个项目
│ Item 49                  │
│ Item 50                  │
│ Item 51                  │
│ Item 52                  │
│ Item 53                  │
│ Item 54                  │
└──────────────────────────┘

DOM 中只存在 10 个 li 元素（而非 10000 个），
随着滚动动态替换内容。
```

### Vue 实现 (@vueuse/virtual)

```vue
<template>
  <div ref="containerRef" class="viewport" @scroll="onScroll">
    <div class="spacer" :style="{ height: `${totalHeight}px` }" />
    <div class="content" :style="{ transform: `translateY(${offsetY}px)` }">
      <div
        v-for="item in visibleItems"
        :key="item.id"
        :style="{ height: `${itemHeight}px` }"
      >
        {{ item.text }}
      </div>
    </div>
  </div>
</template>

<script setup lang="ts">
import { ref, computed, onMounted } from 'vue';
import { useVirtualList } from '@vueuse/core';

const props = defineProps<{
  items: Array<{ id: number; text: string }>();
  itemHeight?: number;
}>();

const containerRef = ref<HTMLDivElement>();

const { list: visibleItems, containerProps, wrapperProps } = useVirtualList(
  () => props.items,
  {
    itemHeight: props.itemHeight ?? 50,
    overscan: 5,  // 上下额外渲染 5 个项目（缓冲区）
  }
);
</script>
```

### React 实现 (@tanstack/react-virtual)

```tsx
import { useVirtualizer } from '@tanstack/react-virtual';

function VirtualList({ items }: { items: Item[] }) {
  const parentRef = useRef<HTMLDivElement>(null);

  const virtualizer = useVirtualizer({
    count: items.length,
    getScrollElement: () => parentRef.current,
    estimateSize: () => 50,  // 预估每项高度
    overscan: 5,
  });

  return (
    <div ref={parentRef} style={{ height: '400px', overflow: 'auto' }}>
      <div style={{ height: virtualizer.getTotalSize(), position: 'relative' }}>
        {virtualizer.getVirtualItems().map(virtualItem => (
          <div
            key={virtualItem.key}
            style={{
              position: 'absolute',
              top: 0,
              left: 0,
              width: '100%',
              transform: `translateY(${virtualItem.start}px)`,
            }}
          >
            {items[virtualItem.index].text}
          </div>
        ))}
      </div>
    </div>
  );
}
```

```js

const [data, setData] = useState(initialData);

// 3. 结合响应式状态做筛选
const filteredItems = useMemo(
```

## 小结

| 优化策略 | 适用框架 | 效果 |
|----------|---------|------|
| **细粒度订阅 / toRefs** | Vue | 减少 effect/computed 的无效触发 |
| **shallowRef / shallowReactive** | Vue | 跳过深层 Proxy 转换，降低初始化开销 |
| **markRaw** | Vue | 标记不需要响应式的数据（第三方库实例） |
| **Immer** | React | 简化不可变更新代码，结构共享降低内存 |
| **useMemo** | React | 缓存计算结果，避免每次渲染重算 |
| **useCallback** | React | 稳定函数引用，避免子组件不必要的重渲染 |
| **memo** | React | 子组件级的渲染拦截 |
| **虚拟滚动** | 所有框架 | 将 O(n) DOM 降为 O(viewport)，适用于长列表 |

性能优化的核心原则：**先测量再优化**。大多数情况下，过早优化是万恶之源。只在确实遇到性能问题时，针对瓶颈精准施策。
