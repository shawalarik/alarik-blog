这一模块通过高频问题反推最佳实践，帮助你避免常见事故并建立稳定的排错方法。

## 响应式丢失

### 场景一：解构丢失响应性

```vue
<!-- ❌ 常见错误 -->
<script setup>
import { reactive, toRefs } from 'vue';

const state = reactive({
  user: { name: 'Alice', age: 25 },
  items: [1, 2, 3],
});

// 解构后失去响应性
const { user, items } = state;   // user 和 items 是普通值！

user.name = 'Bob';  // 不会触发更新！
items.push(4);      // 不会触发更新！
</script>

<!-- ✅ 正确做法：toRefs -->
<script setup>
const { user, items } = toRefs(state);
// 现在 user 和 items 都是 ref

user.value.name = 'Bob';  // ✅ 触发更新
</script>
```

### 场景二：传递给外部库后再取回

```js
// ❌ 外部库可能剥离响应式包装
const state = reactive({ list: [] });

externalLibrary.process(state.list);  // 库内部可能复制了一份
const processed = externalLibrary.getResult();  // 拿回的不是 Proxy

// ✅ 保持引用或重新包装
const processed = reactive(externalLibrary.getResult());
```

### 场景三：ES6 解构参数

```vue
<!-- ❌ props 解构丢失响应式 -->
<script setup>
const props = defineProps<{ items: Item[]; filter: string }>();

// 这样解构后 filter 不再是响应式的
const { items, filter } = props;

watch(filter, () => { /* 不会触发！*/ });
</script>

<!-- ✅ 使用 toRefs 或 toRef -->
<script setup>
const items = toRefs(props).items;
const filter = toRef(props, 'filter');

watch(filter, () => { /* ✅ 正常工作 */ });

// 或者直接在 watch 中使用 getter
watch(() => props.filter, () => { /* 也正常 */ });
</script>
```

## 无限循环更新

### 典型模式：watch 中修改自己监听的值

```vue
<script setup>
import { ref, watch } from 'vue';

const count = ref(0);

// ❌ 无限循环！
watch(count, (newVal) => {
  count.value++;  // 触发 count 变化 → 再次触发 watch → ...
});

// ❌ computed 中间接修改自身依赖
const doubled = computed(() => {
  // 如果这里有副作用导致 count 变化
  someGlobalFunctionThatModifiesCount();
  return count.value * 2;  // 可能无限循环
});
</script>
```

### 常见的隐式循环场景

```vue
<script setup>
// 1. watchEffect 中的副作用触发了它自己的依赖
const state = reactive({ input: '', normalized: '' });

watchEffect(() => {
  // input 变化 → 更新 normalized → 如果某处监听 normalized 又影响 input...
  state.normalized = state.input.toLowerCase().trim();
});

// 2. template 中的双向绑定形成环
// 父组件传 prop，子组件 emit 回来，父组件又更新 prop
// （这通常是设计问题，应改为单向数据流）

// 3. 异步操作中的竞态
let lastId = 0;
watch(sourceId, async (id) => {
  const currentId = ++lastId;
  const result = await fetchData(id);
  
  // 如果 sourceId 在等待期间又变了，
  // 这里更新可能会触发新一轮 watch
  if (currentId === lastId) {
    output.value = result;
  }
});
</script>
```

### 预防措施

```js
// 1. watch 中使用 flush: 'pre' 或 'post' 避免同步循环
watch(source, callback, { flush: 'post' });  // DOM 更新后才执行

// 2. 使用 guard 标志位防止重入
let updating = false;
watch(data, async (val) => {
  if (updating) return;
  updating = true;
  await processData(val);
  updating = false;
});

// 3. 使用 watch 替代 watchEffect（显式声明依赖更安全）
watch(
  () => state.input,  // 明确依赖
  (input) => { state.normalized = input.toLowerCase() }
);
```

## 内存泄漏（未取消订阅）

### 场景：组件销毁后 effect 仍在运行

```vue
<script setup>
// ❌ 定时器/事件监听器未清理
import { onMounted, onUnmounted } from 'vue';
import { io } from 'socket.io-client';

let socket;

onMounted(() => {
  socket = io('/chat');
  socket.on('message', (msg) => {
    messages.value.push(msg);  // 组件卸载后仍在推送
  });

  // setInterval 未清理
  setInterval(() => {
    checkHealth();
  }, 5000);
});

// ❌ 忘记 onUnmounted 清理！
</script>
```

```vue
<!-- ✅ 正确清理 -->
<script setup>
import { onMounted, onUnmounted } from 'vue';
import { io } from 'socket.io-client';

const socket = ref<Socket | null>(null);
let healthTimer: ReturnType<typeof setInterval>;

onMounted(() => {
  socket.value = io('/chat');
  socket.value.on('message', handleMessage);

  healthTimer = setInterval(checkHealth, 5000);
});

onUnmounted(() => {
  // 清理所有副作用
  socket.value?.off('message', handleMessage);
  socket.value?.disconnect();
  socket.value = null;

  clearInterval(healthTimer);
});

// 更优雅的方式：watchEffect 自动清理
import { watchEffect } from 'vue';

watchEffect(onCleanup => {
  const socket = io('/chat');
  socket.on('message', handler);
  
  // onCleanup 会在 effect 重新执行或组件卸载时自动调用
  onCleanup(() => {
    socket.off('message', handler);
    socket.disconnect();
  });
});
</script>
```

### 场景：全局事件总线未注销

```js
// ❌ 全局事件总线泄漏
import mitt from 'mitt';

const emitter = mitt();

export function useGlobalEvents() {
  emitter.on('theme-change', handleThemeChange);
  // 组件卸载时不会自动移除！
}

// ✅ 自动清理
export function useGlobalEvents() {
  const cleanup = () => emitter.off('theme-change', handleThemeChange);
  emitter.on('theme-change', handleThemeChange);

  onUnmounted(cleanup);
  // 或者在 watchEffect 中使用 onCleanup
}
```

### 场景：Store 中的持久订阅

```ts
// ❌ Pinia store 中的订阅未清理
export const useUserStore = defineStore('user', () => {
  const token = ref('');

  // 这个 subscription 永远不会被清理
  someExternalService.onTokenRefresh((newToken) => {
    token.value = newToken;
  });

  return { token };
});

// ✅ 使用 $onAction / $subscribe 的返回值清理
export const useUserStore = defineStore('user', () => {
  const token = ref('');
  let unsub: (() => void) | null = null;

  function initSubscription() {
    unsub = someExternalService.onTokenRefresh((newToken) => {
      token.value = newToken;
    });
  }

  function $dispose() {
    unsub?.();  // store 销毁时清理
  }

  initSubscription();

  return { token };
});
```

## 跨组件状态污染

### 问题：共享可变状态的意外修改

```ts
// ❌ 默认参数的引用陷阱
export function useTable(options: TableOptions = {
  pageSize: 20,
  sortable: true,
  filters: {},
}) {
  // options 是同一个对象引用！多个组件实例共享同一份
  // 一个组件修改 options.filters 会影响其他组件
  const state = reactive({ ...options });
  return state;
}

// ✅ 每次调用创建新的默认值
export function useTable(options?: Partial<TableOptions>) {
  const merged = reactive({
    pageSize: 20,
    sortable: true,
    filters: {},       // 每个实例独立的对象
    ...options,
  });
  return merged;
}
```

```vue
<!-- ❌ provide/inject 的可变共享 -->
<!-- Parent.vue -->
<script setup>
import { provide, reactive } from 'vue';

// 提供了一个可变的 reactive 对象
provide('config', reactive({ theme: 'dark' }));
</script>

<!-- ChildA.vue -->
<script setup>
import { inject } from 'vue';
const config = inject('config');
config.theme = 'light';  // 直接修改了共享状态！ChildB 也会受影响
</script>

<!-- ✅ 提供只读版本或明确约定 -->
<script setup>
import { provide, reactive, readonly } from 'vue';

const config = reactive({ theme: 'dark' });
provide('config', readonly(config));  // 子组件只能读取
// 或者提供 setter 方法
provide('setTheme', (t: string) => { config.theme = t; });
</script>
```

## 生命周期与响应式的协调

### 问题：在错误的时机访问响应式数据

```vue
<script setup>
// ❌ 在 setup 顶层进行 DOM 操作
const el = ref<HTMLElement | null>(null);

// 此时 el 还没挂载！el.value 是 null
console.log(el.value?.clientWidth);  // undefined

// ✅ 使用 onMounted
onMounted(() => {
  console.log(el.value?.clientWidth);  // 正确获取尺寸
});
</script>

<template>
  <div ref="el">...</div>
</template>
```

```vue
<script setup>
// ❌ watchEffect 在 setup 时执行，此时某些数据可能还没准备好
const route = useRoute();

watchEffect(() => {
  // 首次执行时 route.params.id 可能还是旧值或 undefined
  fetchData(route.params.id);
});

// ✅ 使用 immediate: false + watch，或使用 nextTick
watch(
  () => route.params.id,
  (id) => {
    if (id) fetchData(id);
  },
  { immediate: true }
);
</script>
```

### 异步操作与生命周期竞态

```vue
<script setup>
// ❌ 异步操作完成后组件可能已经卸载
const data = ref(null);

onMounted(async () => {
  const res = await fetch('/api/data');
  // 如果用户在此期间离开了页面，组件已卸载
  // 这里写入已卸载的组件的 ref —— 至少是无意义的
  data.value = await res.json();
});

// ✅ 使用标志位或 AbortController
const isMounted = ref(true);
let abortController: AbortController;

onMounted(async () => {
  abortController = new AbortController();
  try {
    const res = await fetch('/api/data', { signal: abortController.signal });
    if (isMounted.value) {
      data.value = await res.json();
    }
  } catch (e) {
    if (e.name !== 'AbortError') throw e;
  }
});

onUnmounted(() => {
  isMounted.value = false;
  abortController?.abort();
});
</script>
```

## 排错方法论

### Vue 响应式调试工具

```js
// 1. Vue DevTools —— 最直接的调试方式
// 打开浏览器 DevTools → Vue 面板
// 可以查看组件的响应式数据、事件、路由信息

// 2. devtools plugin —— 编程式调试
import { watchEffect } from 'vue';
import { vueDevtools } from '@vue/devtools-api';

// 3. onTrack / onTrigger —— 精确追踪依赖收集和触发
app.config.performance = true;

const state = reactive({ count: 0 });

watchEffect(() => {
  console.log(`count is: ${state.count}`);
}, {
  onTrack(e) => {
    // 当依赖被收集时触发
    console.log('tracking:', e.target, e.key, e.type);
  },
  onTrigger(e) => {
    // 当依赖触发更新时触发
    console.log('triggering:', e.target, e.key, e.type);
  },
});

// 4. console 日志增强
// Vue 3.2+ 支持在 template 中使用 $watch
```

### React 调试工具

```tsx
// 1. React DevTools Profiler
// 录制 → 分析哪些组件 re-render 了 → 为什么

// 2. why-did-you-render（开发环境）
// import whyDidYouRender from 'why-did-you-render';
// 在开发环境中提示不必要的重渲染原因

// 3. 自定义日志 HOC
function withDebugInfo<P extends object>(WrappedComponent: ComponentType<P>) {
  return function DebuggedComponent(props: P) {
    const renderedCount = useRef(0);
    renderedCount.current++;

    if (process.env.NODE_ENV === 'development') {
      console.log(
        `[${WrappedComponent.name}] Render #${renderedCount.current}`,
        props
      );
    }

    return <WrappedComponent {...props} />;
  };
}
```

### 通用排错检查清单

```
□ 数据变了但视图没更新？
  → 是否丢失了响应性？（解构 / 传递给外部库 / markRaw）
  → 是否使用了 shallowXXX 却修改了内部？
  → watch/watchEffect 的 flush 时机是否正确？

□ 视图更新了但数据不对？
  → 是否存在闭包陷阱？（旧值被 capture）
  → 是否有竞态条件？（异步操作的顺序）
  → 是否有内存泄漏？（旧的数据源仍在发送值）

□ 性能突然变差？
  → 是否有不必要的深度 reactive？（改用 shallowRef）
  → 是否有无限循环更新？（检查 watch 中的写入）
  → 是否有过多的 effect？（合并相关 effect）
  → 是否有大列表？→ 虚拟滚动

□ 组件卸载后报错？
  → 定时器/事件监听/WebSocket 是否清理？
  → 异步操作是否有 abort/cancel 机制？
  → 全局 store 订阅是否清理？
```

## 小结

| 陷阱类型 | 典型症状 | 解决方案 |
|----------|---------|---------|
| **响应式丢失** | 数据变了 UI 不更新 | `toRefs()` / `shallowRef` + `triggerRef` / 检查解构 |
| **无限循环** | CPU 100% 或栈溢出 | 显式 `watch` 替代 `watchEffect` / guard 标志位 |
| **内存泄漏** | 页面越来越卡 | `onCleanup` / `onUnmounted` 清理所有订阅和定时器 |
| **状态污染** | 一个组件影响另一个 | 默认参数用工厂函数 / `readonly()` 保护 / `provide` 只读版本 |
| **生命周期竞态** | 卸载报错 / 数据残留 | `AbortController` / `isMounted` 标志位 / `flush: 'post'` |

最好的防御是**理解原理**。当你知道 `reactive` 如何追踪依赖、`effect` 何时执行、`cleanup` 何时触发，就能自然地写出无陷阱的代码。
