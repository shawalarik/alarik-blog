## 细粒度响应式成为行业共识

### 为什么大家都在转向 Signal？

```
2018年之前：Virtual DOM 是主流
  - React: VDOM diff
  - Vue 2: VDOM diff + Options API
  - Preact: VDOM diff

2020-2022：Signal 开始崛起
  - Solid: 证明了无 VDOM 可以更快
  - Vue 3: ref/reactive 底层已经是 Signal
  - Preact X: 引入 @preact/signals

2023-2024：全面 Signal 化
  - Angular 16: 官方引入 Signals
  - Svelte 5: Runes（本质是编译期 Signal）
  - React: 实验性 useSignal（React Forget 编译器方案）
  - Vue 3.4+: defineModel 等 Signal-like API 增强

核心驱动因素：
┌─────────────────────────────────────────────┐
│ 1. 性能：细粒度 > 组件级重渲染               │
│ 2. 开发体验：更少的 memo/useMemo/useCallback  │
│ 3. 包体积：无 VDOM runtime ≈ 更小的 bundle    │
│ 4. SSR/Streaming：Signal 天然支持序列化       │
│ 5. 并发模式：Signal 比 VDOM 更容易做一致性保证  │
└─────────────────────────────────────────────┘
```

## Signals 提案进入 TC39？

### 当前的标准化努力

目前还没有正式的 Signal 提案进入 TC39 Stage 1，但社区有多份相关提案和讨论：

#### 1. Signals 作为 polyfill/库先行

```js
// 社区的共识接口（各库正在靠拢）
const signal = initial => {
  let value = initial;
  const subscribers = new Set();

  return Object.freeze({
    get() {
      if (currentEffect) subscribers.add(currentEffect);
      return value;
    },
    set(newValue) {
      if (Object.is(value, newValue)) return;
      value = newValue;
      for (const sub of [...subscribers]) sub();
    },
  });
};
```

## 编译时与运行时融合

### Svelte 5 Runes —— 编译时响应式的成熟形态

Svelte 5 的 Runes 系统代表了编译时和运行时响应式的融合：

```svelte
<script>
  // $state —— 响应式变量（编译器注入追踪代码）
  let count = $state(0);

  // $derived —— 派生值（编译器生成缓存逻辑）
  let doubled = $derived(count * 2);

  // $effect —— 副作用（编译器管理生命周期）
  $effect(() => {
    console.log(`count is now: ${count}`);
  });

  // $props —— 组件属性（类型安全）
  let { name } = $props();

  // $bind —— 双向绑定语法糖
  let value = $bind(this, 'inputValue');
</script>

<input bind:value={value} />
<p>{count} × 2 = {doubled}</p>
<button onclick={() => count++}>+</button>
```

**Runes 的编译输出（概念性）：**

```js
// 上面的 Svelte 代码大致编译为：
function instance($$props, $$invalidate) {
  let count = $.source(0);  // 自定义 Signal 原语
  let doubled = $.derive(() => $.get(count) * 2);

  $.effect(() => {
    console.log(`count is now: ${$.get(count)}`);
  });

  // 返回属性和更新函数
  return {
    props: { value: $.proxy(count), doubled: $.proxy(doubled) },
    update: (newProps) => { /* ... */ }
  };
}
```

### React Forget —— React 的编译时之路

React Forget 编译器尝试将 React 代码自动优化为等效的细粒度更新：

```tsx
// 输入：普通 React 代码
function NameDisplay({ user }: { user: User }) {
  return (
    <div>
      <h1>Hello, {user.name}</h1>         {/* 只依赖 user.name */}
      <p>{user.email}</p>                   {/* 只依赖 user.email */}
      <Footer />                               {/* 不依赖 user */}
    </div>
  );
}

// Forget 编译后的效果（概念性）：
function NameDisplay({ user }: { user: User }) {
  // 编译器自动分析依赖关系
  const $name = useComputed(() => user.name);
  const $email = useComputed(() => user.email);

  return (
    <div>
      <h1>{$name()}</h1>      {/* 只在 user.name 变化时重新执行 */}
      <p>{$email()}</p>       {/* 只在 user.email 变化时重新执行 */}
      <Footer />               {/* 从不因 user 变化而重渲染 */}
    </div>
  );
}
```

### Qwik —— 可恢复的响应式

Qwick 提出了一个全新的思路：**将响应式状态序列化到 HTML 中，在需要时才"唤醒"（Resumable）**：

```tsx
// Qwik 组件
export const Counter = component$(() => {
  // $ —— Qwik 的信号标记（告诉编译器这是可序列化的）
  const count = useSignal(0);

  // $ —— 事件处理器是懒加载的（点击时才下载 JS）
  return (
    <button onClick$={() => count.value++}>
      Count: {count.value}
    </button>
  );
});

// HTML 输出（初始）：
// <button q:id="0">Count: 0</button>
// <script>window.qwik['0']=(e)=>{...}</script>
//
// 点击按钮时：
// 1. 只下载该事件处理器的小 chunk（而非整个应用 bundle）
// 2. 恢复 Signal 状态
// 3. 执行更新
```

### 融合趋势总结

```
2020: 运行时 vs 编译时 二选一
  "你要 Virtual DOM 还是零运行时？"

2023: 发现两者各有优劣
  "能不能结合两者的优势？"

2025+: 编译-运行融合成为主流方向
  ├── Svelte 5: 编译器注入 Signal 原语
  ├── React Forget: 编译器自动优化组件粒度
  ├── Qwik: 编译器实现可恢复的懒执行
  ├── Angular: 编译时模板 + 运行时 Signal
  └── Vue: 编译时模板优化 + 运行时 reactive 核心

共识：
  "用编译器消除样板代码，
   用运行时处理动态行为"
```

### 实际案例：AI 生成的 Composable

人类提示词：
> "创建一个 Vue composable，用于管理分页表格的数据获取。支持搜索、排序、分页参数，自动防抖，错误重试。使用 @vue/reactivity 和 fetch API。"

AI 输出：

```ts
// ai-generated: usePaginatedTable.ts
import { ref, computed, watchEffect } from '@vue/reactivity';

interface UsePaginatedTableOptions<T> {
  fetchData: (params: FetchParams) => Promise<{ data: T[]; total: number }>;
  pageSize?: number;
  debounceMs?: number;
  maxRetries?: number;
}

interface FetchParams {
  page: number;
  pageSize: number;
  search?: string;
  sortField?: string;
  sortOrder?: 'asc' | 'desc';
}

function usePaginatedTable<T extends { id: string | number }>(
  options: UsePagetableOptions<T>
) {
  const { fetchData, pageSize = 20, debounceMs = 300, maxRetries = 3 } = options;

  // 响应式参数
  const currentPage = ref(1);
  const searchQuery = ref('');
  const sortField = ref<string>();
  const sortOrder = ref<'asc' | 'desc'>();

  // 内部状态
  const items = ref<T[]>([]);
  const total = ref(0);
  const loading = ref(false);
  const error = ref<string | null>(null);
  const retryCount = ref(0);

  // 防抖后的搜索
  const debouncedSearch = ref('');
  let debounceTimer: ReturnType<typeof setTimeout>;

  // 监听搜索输入 → 防抖
  watchEffect(() => {
    clearTimeout(debounceTimer);
    debounceTimer = setTimeout(() => {
      debouncedSearch.value = searchQuery.value;
      currentPage.value = 1;  // 重置到第一页
    }, debounceMs);
  });

  // 派生值
  const totalPages = computed(() => Math.ceil(total.value / pageSize));
  const hasMore = computed(() => currentPage.value < totalPages.value);
  const isEmpty = computed(() => !loading.value && items.value.length === 0);

  // 获取数据
  async function load() {
    loading.value = error.value = null;
    
    try {
      const result = await fetchData({
        page: currentPage.value,
        pageSize,
        search: debouncedSearch.value || undefined,
        sortField: sortField.value,
        sortOrder: sortOrder.value,
      });

      items.value = result.data;
      total.value = result.total;
      retryCount.value = 0;  // 成功后重置
    } catch (e) {
      if (retryCount.value < maxRetries) {
        retryCount.value++;
        setTimeout(load, 1000 * retryCount.value);  // 指数退避
      } else {
        error.value = e instanceof Error ? e.message : 'Unknown error';
      }
    } finally {
      loading.value = false;
    }
  }

  // 参数变化时自动重新加载
  watchEffect(load);

  // 清理定时器
  function dispose() {
    clearTimeout(debounceTimer);
  }

  return {
    // 状态
    items: readonly(items),
    total: readonly(total),
    loading: readonly(loading),
    error: readonly(error),

    // 参数（可外部控制）
    currentPage,
    searchQuery,
    sortField,
    sortOrder,

    // 派生值
    totalPages,
    hasMore,
    isEmpty,

    // 方法
    nextPage: () => { if (hasMore.value) currentPage.value++; },
    prevPage: () => { if (currentPage.value > 1) currentPage.value--; },
    goToPage: (page: number) => { currentPage.value = Math.max(1, page); },
    setSort: (field: string, order: 'asc' | 'desc') => {
      sortField.value = field;
      sortOrder.value = order;
    },
    retry: () => { retryCount.value = 0; load(); },
    reset: () => {
      currentPage.value = 1;
      searchQuery.value = '';
      sortField.value = undefined;
      sortOrder.value = undefined;
    },
    dispose,
  };
}
```

## 小结

| 趋势方向 | 关键进展 | 影响 |
|----------|---------|------|
| **Signal 标准化** | 多框架靠拢统一接口 | 降低跨框架迁移成本 |
| **编译-运行融合** | Svelte 5 / React Forget / Qwik | 最佳的性能与开发体验平衡点 |
| **AI 辅助** | 代码生成 / 错误检测 / 迁移 | 大幅降低响应式系统的使用门槛 |
| **全栈统一** | 服务端组件 + 客户端 Signal | 同一份状态逻辑贯穿前后端 |

响应式的未来不是某个框架独占的创新，而是**整个行业向细粒度、低开销、高表达力的方向收敛**。作为开发者，掌握 Signal 模型的本质原理，就能在任何具体实现面前游刃有余。
