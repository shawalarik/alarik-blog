Vue 1.0 是框架的第一个稳定版，奠定了 Vue 核心的设计方向。虽然如今已进入 Vue 3 时代，但理解 Vue 1.x 的设计决策对于认识框架的演进脉络至关重要。

## 版本时间线

```
2014.02  首次 commit（项目启动）
   │
2014.06  v0.6 — 公开发布（GitHub）
   │
2014.10  v0.8 — 过滤器系统完善
   │
2014.12  v0.10 — 社区快速增长
   │
2015.01  v0.11 — 性能优化
   │
2015.05  v0.12 — 最后的预发布版
   │
2015.10  ★ v1.0.0 — 第一个正式稳定版 ★
   │
2016.04  v1.0.26 — 1.x 最终版本（进入维护模式）
```

## 核心架构

### 流式 API 设计（Stream-based API）

Vue 1.x 采用了独特的**流式（Stream-based）**架构，这是它与后续版本最大的区别：

```javascript
// Vue 1.x 的典型用法
new Vue({
  el: '#app',
  data: {
    message: 'Hello World'
  },
  // 阶段一：数据变化前的处理
  beforeCompile: function() {},
  // 阶段二：编译完成
  compiled: function() {},
  // 阶段三：数据绑定就绪
  ready: function() {},
  // 阶段四：销毁前清理
  beforeDestroy: function() {}
})
```

**生命周期钩子**（当时叫"阶段"）反映了流式处理的本质：数据流入 → 编译模板 → 绑定完成 → 就绪可用 → 销毁释放。

### 双向数据绑定（v-model）

`v-model` 是 Vue 1.x 最具标志性的功能之一，它让表单元素的双向绑定变得极其简洁：

```html
<!-- Vue 1.x -->
<input type="text" v-model="username">
<p>{{ username }}</p>
```

底层实现基于 **脏检查（Dirty Checking）** + **发布-订阅模式**的结合：

```
用户输入 input
      ↓
v-model 监听 input 事件
      ↓
更新 data.username
      ↓
Object.defineProperty setter 触发
      ↓
通知所有订阅该属性的 Watcher
      ↓
Watcher 更新对应 DOM 节点的文本内容
```

### 指令系统

Vue 1.x 的指令系统已经相当丰富：

| 指令 | 用途 | 说明 |
|------|------|------|
| `v-if` | 条件渲染 | 移除/插入 DOM 元素 |
| `v-show` | 切换显示 | 通过 CSS `display` 控制 |
| `v-for` | 列表渲染 | 支持 `(value, index) in list` 语法 |
| `v-bind` | 动态属性 | 缩写 `:` |
| `v-on` | 事件监听 | 缩写 `@` |
| `v-model` | 双向绑定 | 表单专属 |
| `v-text` / `v-html` | 内容插入 | 安全的文本/HTML 输出 |
| `v-ref` | 子组件引用 | 已被 Vue 2/3 的 refs 替代 |
| `v-el` | DOM 元素引用 | 已废弃 |

### 过滤器（Filters）

过滤器是 Vue 1.x 的一大特色功能：

```javascript
// 全局注册
Vue.filter('capitalize', function(value) {
  if (!value) return '';
  value = value.toString();
  return value.charAt(0).toUpperCase() + value.slice(1);
})

// 模板中使用
<span>{{ message | capitalize }}</span>
```

支持**链式调用**和**带参数**：

```html
<p>{{ price | currency('¥', 2) }}</p>
```

> **注意**：Vue 2.x 移除了内置过滤器，Vue 3.x 则完全移除了过滤器功能。推荐使用**方法调用**或 **计算属性** 替代。

### 组件化的雏形

Vue 1.x 的组件系统已经具备了现代组件的基本形态：

```javascript
// 定义组件
var MyComponent = Vue.extend({
  template: '<div class="my-component">Hello</div>',
  props: ['msg'],
  data: function() {
    return { localData: 'local' }
  },
  methods: {
    greet: function() {
      alert('Hello from component!')
    }
  }
})

// 注册全局组件
Vue.component('my-component', MyComponent)

// 使用
<my-component msg="hello"></my-component>
```

**父子通信机制**：

```javascript
// 父 → 子：props
<child-component :message="parentMsg"></child-component>

// 子 → 父：$dispatch（向上派发事件）
this.$dispatch('child-event', payload)

// 广播：$broadcast（向下广播事件）
this.$broadcast('update-all', data)
```

> **重要变迁**：Vue 2.x 废弃了 `$dispatch` 和 `$broadcast`，改用 **props down, events up** 的单向数据流模式。

## Vue 1.x vs 后续版本对比

| 特性 | Vue 1.x | Vue 2.x | Vue 3.x |
|------|---------|---------|---------|
| 响应式原理 | `Object.defineProperty` | `Object.defineProperty` | `Proxy` |
| 渲染方式 | 流式编译 | 虚拟 DOM | 虚拟 DOM + 编译优化 |
| 组件通信 | `$dispatch/$broadcast` | `props down / $emit up` | `provide/inject` + `emit` |
| 过滤器 | 内置管道过滤器 | 内置过滤器（2.7移除） | 完全移除 |
| 构建工具 | Browserify / webpack 1 | webpack 2+ | Vite / webpack 5 |
| TypeScript | 不支持 | .d.ts 类型定义 | 完整 TS 重写 |
| 包大小 | ~27KB (min+gzip) | ~23KB (min+gzip) | ~33KB (含 runtime-compiler) |

## Vue 1.x 的局限性

### 1. 无虚拟 DOM

Vue 1.x **没有使用虚拟 DOM**，而是通过**细粒度的依赖追踪**直接操作真实 DOM。这在小型应用中性能极佳，但在大型列表场景下存在瓶颈：

```javascript
// Vue 1.x: 每个 text node 都有独立的 watcher
// 1000 个列表项 = 3000+ 个 watcher（每个项有多个绑定）
```

### 2. $dispatch / $broadcast 的性能问题

事件冒泡/捕获机制在深层嵌套组件树中会产生大量中间节点的遍历：

```
GrandChild.$dispatch('event')
  → Parent 处理？否 → 继续
  → GrandParent 处理？否 → 继续
  → Root 处理！停止
```

当组件层级超过 5~7 层时，性能下降明显。

### 3. 缺乏官方路由和状态管理

- **Vue Router 0.7.x** 功能简陋
- **Vuux**（非官方）是主流状态管理方案
- 生态尚未标准化

## 里程碑意义

尽管 Vue 1.x 有诸多局限，但它的历史意义不可磨灭：

1. **证明了渐进式框架的可行性**
2. **建立了清晰的 API 风格**（模板 + 指令 + 响应式数据）
3. **积累了早期社区反馈**，直接指导了 Vue 2.0 的设计
4. **培养了第一批核心贡献者**

## 迁移建议

如果你仍在维护 Vue 1.x 项目，强烈建议尽快迁移：

- Vue 1.x 已于 **2017 年 4 月**结束官方支持
- 存在未修复的安全漏洞
- 无法享受现代工具链（Vite、TypeScript 等）
- 社区插件几乎全部停止对 1.x 的兼容
