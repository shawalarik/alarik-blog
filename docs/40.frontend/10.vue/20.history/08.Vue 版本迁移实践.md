从 Vue 2 到 Vue 3 的迁移是一项系统工程。本文总结了实战中的迁移策略、常见坑点和最佳实践。

## 迁移决策

### 是否应该迁移？

| 场景 | 建议 |
|------|------|
| 新项目 | **直接使用 Vue 3** |
| 小型 Vue 2 项目（< 10 个页面） | **推荐迁移**，工作量小 |
| 中型 Vue 2 项目（10~50 页面） | **评估后决定**，ROI 通常为正 |
| 大型 Vue 2 项目（50+ 页面） | **渐进式迁移**，分阶段进行 |
| Vue 2 项目已稳定运行多年 | **保持 Vue 2**，除非有明确需求 |

### Vue 3 的优势是否值得迁移？

- ✅ **更好的 TypeScript 支持**
- ✅ **Composition API 提升大型项目可维护性**
- ✅ **性能提升（尤其是 SSR 场景）**
- ✅ **更小的打包体积**（Tree-shaking）
- ✅ **Vite 开发体验飞跃**

⚠️ **迁移成本**：
- 第三方依赖可能不兼容
- 团队学习成本（Composition API）
- 测试回归风险

## 第一步：准备阶段

### 1. 升级构建工具

```bash
# 如果使用 Vue CLI → 迁移到 Vite
npm install -g create-vite

# 或保留 webpack 但升级版本
npm install webpack@5 webpack-cli@4 --save-dev
npm install vue-loader@17  # Vue 3 兼容的 loader
```

### 2. 安装兼容性构建

```bash
# 安装 Vue 3 Migration Build（提供 Vue 2 兼容 API）
npm install vue@^3.1.0

# 或者使用 @vue/compat（官方兼容层）
npm install vue@^3.1.0 @vue/compat
```

### 3. 升级核心依赖

```json
{
  "dependencies": {
    "vue": "^3.4.0",
    "vue-router": "^4.3.0",
    "pinia": "^2.1.0"
  },
  "devDependencies": {
    "@vitejs/plugin-vue": "^5.0.0",
    "vite": "^5.0.0",
    "typescript": "^5.3.0",
    "@vue/tsconfig": "^0.5.0"
  }
}
```

## 第二步：自动化辅助

### 使用 migration-build 模式

Vue 3 提供了**兼容构建**（compat build），可以在 Vue 3 中运行 Vue 2 代码并给出警告：

```javascript
// vite.config.ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [
    vue({
      template: {
        compilerOptions: {
          compatConfig: {
            MODE: 2  // Vue 2 兼容模式（会输出警告）
          }
        }
      }
    })
  ]
})
```

这样你可以：
1. **先用 Vue 3 运行现有代码**
2. **根据警告逐个修复问题**
3. **最终移除 compat 模式**

### 使用 @vue/cli-plugin-vue-next（如果还在用 Vue CLI）

```bash
vue add migration
```

这会：
- 升级 `vue` 到 `@vue/compat`
- 升级 `vue-router` 和 `vuex`
- 添加编译器兼容选项
- 给出迁移建议报告

## 第三步：逐项迁移

### 1. 模板语法变更

```html
<!-- ❌ Vue 2: filters -->
<span>{{ date | format('YYYY-MM-DD') }}</span>
<!-- ✅ Vue 3: 方法或计算属性 -->
<span>{{ formatDate(date, 'YYYY-MM-DD') }}</span>


<!-- ❌ Vue 2: $listeners 独立 -->
<ChildComponent v-on="$listeners" />
<!-- ✅ Vue 3: $listeners 合并到 $attrs -->
<ChildComponent v-bind="$attrs" />


<!-- ❌ Vue 2: .sync 修饰符 -->
<Dialog :visible.sync="showDialog" />
<!-- ✅ Vue 3: v-model:paramName -->
<Dialog v-model:visible="showDialog" />


<!-- ❌ Vue 2: inline-template -->
<my-component inline-template>
  <div><p>内容</p></div>
</my-component>
<!-- ✅ Vue 3: 使用 SFC 或 render 函数 -->
```

### 2. JavaScript API 变更

```javascript
// ════════════════════════════════════
// 全局 API
// ════════════════════════════════════

// ❌ Vue 2: new Vue()
new Vue({
  router,
  store,
  render: h => h(App)
}).$mount('#app')

// ✅ Vue 3: createApp()
const app = createApp(App)
app.use(router)
app.use(store)
app.mount('#app')


// ════════════════════════════════════
// 生命周期名称
// ════════════════════════════════════

// ❌ Vue 2
{
  beforeDestroy() {},
  destroyed() {}
}

// ✅ Vue 3
{
  beforeUnmount() {},  // renamed
  unmounted() {}       // renamed
}


// ════════════════════════════════════
// v-model 变更
// ════════════════════════════════════

// ❌ Vue 2 子组件接收 v-model
export default {
  model: {
    prop: 'checked',
    event: 'change'
  },
  props: ['checked']
}

// ✅ Vue 3 子组件接收 v-model
export default {
  props: ['modelValue'],  // 默认 prop 名
  emits: ['update:modelValue']  // 对应的事件名
}

// 或使用 defineModel (Vue 3.4+)
const modelValue = defineModel()


// ════════════════════════════════════
// 事件总线
// ════════════════════════════════════

// ❌ Vue 2: 使用 Vue 实例作为 EventBus
const bus = new Vue()
bus.$on('event', handler)
bus.emit('event', payload)  // Vue 3 中是 $emit
bus.$off('event', handler)

// ✅ Vue 3: 使用 mitt 或自实现
import mitt from 'mitt'
const emitter = mitt()

emitter.on('event', handler)
emitter.emit('event', payload)
emitter.off('event', handler)


// ════════════════════════════════════
// $children / $listeners 移除
// ════════════════════════════════════

// ❌ Vue 2
console.log(this.$children)
this.$listeners.click

// ✅ Vue 3: 使用 $refs 或 provide/inject
// $listeners 已合并到 $attrs
```

### 3. 功能函数迁移

```javascript
// ════════════════════════════════════
// Vue.set / Vue.delete → 直接赋值
// ════════════════════════════════════

// ❌ Vue 2
Vue.set(this.obj, 'newKey', value)
Vue.delete(this.obj, 'key')
this.$set(this.arr, 0, newValue)

// ✅ Vue 3 (Proxy 自动处理)
this.obj.newKey = value
delete this.obj.key
this.arr[0] = newValue


// ════════════════════════════════════
// Vue.filter → 方法/计算属性
// ════════════════════════════════════

// ❌ Vue 2
Vue.filter('capitalize', str => 
  str.charAt(0).toUpperCase() + str.slice(1)
)

// ✅ Vue 3: 定义为工具函数或 composable
// utils/filters.ts
export const capitalize = (str: string): string =>
  str.charAt(0).toUpperCase() + str.slice(1)

// 在模板中使用
{{ capitalize(message) }}


// ════════════════════════════════════
// Vue.extend → defineComponent
// ════════════════════════════════════

// ❌ Vue 2
const Component = Vue.extend({
  props: [...],
  data() { return {...} }
})

// ✅ Vue 3
import { defineComponent } from 'vue'

const Component = defineComponent({
  props: {...},
  setup(props) {
    // ...
  }
})


// ════════════════════════════════════
// Functional Components 变更
// ════════════════════════════════════

// ❌ Vue 2
Vue.component('functional-comp', {
  functional: true,
  render(h, context) {
    return h('div', context.data, context.children)
  }
})

// ✅ Vue 3: 普通函数
function FunctionalComp(props, { slots, emit, attrs }) {
  return () => h('div', attrs, slots.default ? slots.default() : null)
}

FunctionalComp.props = { ... }
FunctionalComp.displayName = 'FunctionalComp'


// ══════════════════════════════════
// 自定义指令
// ══════════════════════════════════

// ❌ Vue 2
Vue.directive('focus', {
  bind(el, binding, vnode) {},
  inserted(el, binding, vnode) {},
  update(el, binding, vnode, oldVnode) {},
  componentUpdated(el, binding, vnode, oldVnode) {},
  unbind(el, binding, vnode) {}
})

// ✅ Vue 3: 简化为 beforeMount + updated + unmounted
app.directive('focus', {
  beforeMount(el, binding) {},
  mounted(el, binding) {},
  updated(el, binding) {},
  unmounted(el, binding) {}
})

// 或简化写法（仅 mounted + updated）
app.directive('color', (el, binding) => {
  el.style.color = binding.value
})
```

### 4. Vuex → Pinia 迁移

```typescript
// ════════════════════════════════════
// Vuex Store
// ════════════════════════════════════
// stores/user.js (Vue 2/Vuex 3)
export default new Vuex.Store({
  modules: {
    user: {
      namespaced: true,
      state: { user: null },
      getters: {
        isLoggedIn: state => !!state.user
      },
      mutations: {
        SET_USER(state, user) { state.user = user }
      },
      actions: {
        async fetchUser({ commit }) { /* ... */ }
      }
    }
  }
})

// 使用: mapState(['user']), mapActions(['fetchUser'])

// ════════════════════════════════════
// Pinia Store (Vue 3)
// ════════════════════════════════════
// stores/user.ts
export const useUserStore = defineStore('user', () => {
  const user = ref<User | null>(null)
  const isLoggedIn = computed(() => !!user.value)
  
  async function fetchUser(id: string) {
    const res = await api.getUser(id)
    user.value = res.data
  }
  
  function clearUser() { user.value = null }
  
  return { user, isLoggedIn, fetchUser, clearUser }
})

// 使用: const userStore = useUserStore(), const { isLoggedIn } = storeToRefs(userStore)
```

## 第四步：常见陷阱与解决方案

### 陷阱 1：Emits 声明遗漏

```vue
<!-- Vue 2 不需要声明 emits -->
<!-- Vue 3 未声明的 emits 会触发警告且出现在 $attrs 中 -->

<script setup>
// ❌ 缺少 emit 声明
// ✅ 正确做法
const emit = defineEmits<{
  (e: 'update:value', value: number): void
  (e: 'close'): void
}>()
</script>
```

### 陷阱 2：异步组件写法

```javascript
// ❌ Vue 2
const AsyncComp = () => import('./AsyncComp.vue')

// ✅ Vue 3
import { defineAsyncComponent } from 'vue'
const AsyncComp = defineAsyncComponent(() => import('./AsyncComp.vue'))

// 带加载状态的异步组件
const CompWithLoading = defineAsyncComponent({
  loader: () => import('./HeavyComp.vue'),
  loadingComponent: LoadingSpinner,
  delay: 200,  // 延迟显示 loading
  errorComponent: ErrorComponent,
  timeout: 10000,  // 超时时间
})
```

### 陷阱 3：Teleport 目标挂载

```vue
<!-- Teleport 的目标必须在挂载时已存在 -->
<Teleport to="#modal-container">
  <!-- 如果 #modal-container 还不存在，会静默失败 -->
  <ModalDialog />
</Teleport>

<!-- 解决方案：条件渲染确保目标存在 -->
<Teleport v-if="containerReady" to="#modal-container">
  <ModalDialog />
</Teleport>
```

### 陷阱 4：Transition 类名变更

```css
/* Vue 2 Transition 类名 */
.v-enter, .v-leave-to { opacity: 0; }
.v-enter-active, .v-leave-active { transition: opacity 0.3s; }

/* Vue 3: -to 改为 -from */
.v-enter-from, .v-leave-to { opacity: 0; }  /* enter → enter-from */
.v-enter-active, .v-leave-active { transition: opacity 0.3s; }
```

## 第五步：迁移后的验证清单

- [ ] 所有页面正常渲染，无白屏
- [ ] 路由跳转正常工作（包括动态路由）
- [ ] 表单双向绑定正常（v-model）
- [ ] 父子组件通信正常（props/emit/provide-inject）
- [ ] Vuex/Pinia 状态管理正常
- [ ] 第三方组件库正确渲染
- [ ] CSS Scoped 样式无泄漏
- [ ] Transition 动画流畅
- [ ] SSR（如有）首屏正常
- [ ] 生产构建成功，无 warning
- [ ] Lighthouse 性能评分无明显下降
- [ ] 单元测试全部通过
- [ ] E2E 测试覆盖主要流程

## 渐进式迁移策略（大型项目）

对于无法一次性迁移的大型项目，可采用以下策略：

```
阶段 1: 基础设施准备
├── 升级构建工具到 Vite/Webpack 5
├── 安装 @vue/compat 兼容层
├── 配置 TypeScript
└── 建立 CI/CD 回归测试

阶段 2: 逐模块迁移
├── 从叶子组件开始迁移
├── 每个 PR 迁移一个模块
├── 使用 compat 模式平滑过渡
└── 每个模块完成后移除 compat flag

阶段 3: 核心重构
├── 迁移 Vuex → Pinia
├── 重构共享逻辑为 Composables
├── Options API → Composition API（可选）
└── 移除 @vue/compat

阶段 4: 收尾
├── 清理遗留的 Vue 2 代码
├── 更新文档
└── 团队培训和知识转移
```
