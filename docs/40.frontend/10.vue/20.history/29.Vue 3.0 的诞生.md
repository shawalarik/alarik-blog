## 为什么要重写？

### Vue 2.x 的四个根本限制

#### 1. `Object.defineProperty` 的硬伤

```javascript
// Vue 2 响应式系统的致命缺陷

// 缺陷一：无法检测对象属性的添加/删除
const vm = new Vue({ data: { a: 1 } })
vm.b = 2          // b 不是响应式的！需要用 Vue.set()

// 缺陷二：无法检测数组索引的直接赋值
vm.items[0] = 'new'  // 不是响应式的！

// 缺陷三：无法检测数组长度修改
vm.items.length = 0  // 不是响应式的！

// 缺陷四：不支持 Map/Set/WeakMap/WeakSet/Proxy 等
const mapData = new Map()
// 完全无法响应式化
```

#### 2. TypeScript 支持不理想

```typescript
// Vue 2 的 TypeScript 体验（Options API）

import Vue from 'vue'

// 需要手动声明 this 的类型
export default Vue.extend({
  data() {
    return {
      count: 0 as number
    }
  },
  methods: {
    increment(): void {
      this.count++  // this 类型推导困难
    }
  },
  computed: {
    double(): number {
      return this.count * 2  // 隐式 any 风险
    }
  }
})

// 问题：
// 1. this 的类型需要手动声明
// 2. data/computed/methods 之间没有类型关联
// 3. props 验证与 TypeScript 类型重复
```

#### 3. Tree-shaking 困难

```
Vue 2.x 完整打包大小（runtime + compiler）:
  ├── Vue.prototype.* (全局 API)
  ├── 内置组件 (Transition/KeepAlive/TransitionGroup)
  ├── 内置指令 (v-show/v-model/v-if/v-for)
  └── 各种工具方法

即使只用了 10% 的功能，也要加载全部代码
```

#### 4. 代码复用模式混乱

```javascript
// Vue 2 的 mixin 深渊

const paginationMixin = {
  data() {
    return { page: 1, pageSize: 10, total: 0 }
  },
  methods: {
    fetchPage() { /* ... */ },
    nextPage() { this.page++ }
  },
  computed: {
    totalPages() { return Math.ceil(this.total / this.pageSize) }
  }
}

const searchMixin = {
  data() {
    return { keyword: '', results: [] }
  },
  methods: {
    doSearch() { /* ... */ }
  },
  watch: {
    keyword(val) { this.doSearch(val) }
  }
}

// 使用时的问题：
export default {
  mixins: [paginationMixin, searchMixin],
  // 问题 1：来源不明 — page 是哪个 mixin 的？
  // 问题 2：命名冲突 — 如果两个 mixin 都定义了 reset？
  // 问题 3：隐式依赖 — mixins 之间可能有耦合
}
```

## Vue 3 核心突破

### 1. Proxy 响应式系统

```javascript
// Vue 3 的 reactive — 基于 ES6 Proxy
import { reactive, effect } from 'vue'

const state = reactive({
  user: { name: 'Alice', age: 25 },
  items: [],
  map: new Map(),    // ✅ Map/Set 支持！
})

// 所有操作都是响应式的：
state.user.address = 'Beijing'  // ✅ 新增属性自动响应
state.items.push({ id: 1 })      // ✅ 数组操作完全支持
state.map.set('key', 'value')    // ✅ Map 操作支持
delete state.user.age            // ✅ 属性删除支持
```

**Proxy 的优势总结**：

| 能力 | `Object.defineProperty` | `Proxy` |
|------|------------------------|---------|
| 属性动态添加 | ❌ | ✅ |
| 属性删除检测 | ❌ | ✅ |
| 数组索引修改 | ⚠️ hack | ✅ 原生支持 |
| Map/Set/WeakMap | ❌ | ✅ |
| 性能（初始化） | 惰性（按需定义） | 代理整个对象 |
| 性能（访问） | 直接读取 | 有 Proxy 陷阱开销 |
| IE 兼容 | ✅ IE9+ | ❌ 需要 polyfill |

### 2. Composition API

**Vue 3 最具争议也最具影响力的创新**：

```javascript
// Vue 2 Options API — 横切关注点分散
export default {
  data() {
    return { 
      user: null,
      loading: false,
      error: null
    }
  },
  created() { this.fetchUser() },
  watch: { '$route.params.id': 'fetchUser' },
  methods: {
    async fetchUser() {
      this.loading = true
      try {
        const res = await api.getUser(this.$route.params.id)
        this.user = res.data
      } catch(e) {
        this.error = e.message
      } finally {
        this.loading = false
      }
    }
  }
}

// Vue 3 Composition API — 关注点内聚
import { ref, watch, onMounted } from 'vue'
import { useRoute } from 'vue-router'

export function useUserFetch() {
  const route = useRoute()
  const user = ref(null)
  const loading = ref(false)
  const error = ref(null)

  async function fetchUser() {
    loading.value = true
    try {
      const res = await api.getUser(route.params.id)
      user.value = res.data
    } catch(e) {
      error.value = e.message
    } finally {
      loading.value = false
    }
  }

  onMounted(fetchUser)
  watch(() => route.params.id, fetchUser)

  return { user, loading, error, fetchUser }
}

// 在组件中使用
export default {
  setup() {
    const { user, loading, error } = useUserFetch()
    return { user, loading, error }
  }
}
```

**核心 API 一览**：

| API | 用途 | 类比 |
|-----|------|------|
| `reactive()` | 深度响应式对象 | Vue 2 的 `data()` |
| `ref()` | 响应式基本类型 | 包装值 `.value` |
| `computed()` | 计算属性 | 同 Vue 2 |
| `watch()` / `watchEffect()` | 监听器 | 同/增强 Vue 2 |
| `onMounted()` 等 | 生命周期钩子 | Vue 2 的 `mounted` |
| `toRefs()` | 解构保持响应性 | 新增 |
| `provide()` / `inject()` | 依赖注入 | Vue 2 已有 |

### 3. Monorepo 架构

Vue 3 采用 Monorepo 管理，包拆分更精细：

```
packages/
├── vue/              # 主入口（整合导出）
├── vue-compat/       # Vue 2 兼容构建
├── @vue/runtime-dom # 浏览器 DOM 运行时
├── @vue/runtime-core # 平台无关的核心运行时
├── @vue/reactivity  # 响应式系统（独立包！）
├── @vue/compiler-core    # 编译器核心
├── @vue/compiler-dom     # 浏览器编译器
├── @vue/compiler-sfc     # SFC 编译器
├── @vue/server-renderer  # SSR 渲染器
└── @vue/shared           # 内部共享工具
```

**好处**：
- **Tree-shaking 友好**：按需引入，不用不打包
- **独立使用**：`@vue/reactivity` 可以脱离 Vue 单独使用
- **解耦开发**：各包可以独立发版

### 4. 编译优化

Vue 3 引入了革命性的**编译时优化**：

```html
<!-- Vue 2: 动态绑定，diff 时不确定 -->
<div :class="dynamicClass" :id="dynamicId">
  {{ message }}
</div>

<!-- Vue 3: PatchFlag 标记 -->
<!-- 编译后标记哪些属性会变 -->
<div _hoisted_1 _ctx>
  {{ message }}
  <!-- patch flag: CLASS | PROPS | TEXT -->
</div>
```

**Patch Flag 机制**：

| Flag | 含义 | 跳过检查 |
|------|------|----------|
| `TEXT` | 只有文本变化 | class/style/props/dynamicChildren |
| `CLASS` | 只有 class 变化 | style/props/dynamicChildren |
| `STYLE` | 只有 style 变化 | props/dynamicChildren |
| `PROPS` | 有 props 变化 | dynamicChildren |
| `FULL_PROPS` | props key 可能变化 | dynamicChildren |
| `HYDRATE_EVENTS` | 有事件监听 | — |
| `STABLE_FRAGMENT` | 子节点顺序不变 | children 顺序 diff |
| `KEYED_FRAGMENT` | 带 key 的 fragment | — |
| `UNKEYED_FRAGMENT` | 无 key 的 fragment | — |

### 5. `<script setup>` 语法糖（3.2+）

```vue
<script setup>
// 导入的 API 自动暴露给模板
import { ref, computed, onMounted } from 'vue'
import { useRoute } from 'vue-router'
import ChildComponent from './ChildComponent.vue'

// 声明的变量自动暴露
const count = ref(0)
const doubled = computed(() => count.value * 2)

// 声明的函数自动暴露
function increment() {
  count.value++
}

// 组件自动注册，无需 components 选项
// props / emits 使用编译器宏
const props = defineProps({
  msg: String
})

const emit = defineEmits(['update'])

onMounted(() => {
  console.log('Mounted!')
})
</script>

<template>
  <div class="setup-demo">
    <h1>{{ msg || 'Hello Setup!' }}</h1>
    <p>Count: {{ count }}, Doubled: {{ doubled }}</p>
    <button @click="increment">+1</button>
    <ChildComponent :count="count" @update="handleUpdate" />
  </div>
</template>
```

**优势**：
- 代码量减少 **30%~50%**
- 更好的 TypeScript 推断
- 运行时性能更好（无需 setup 函数返回对象）

## 性能提升数据

| 指标 | Vue 2 | Vue 3 | 提升 |
|------|-------|-------|------|
| 初始渲染（SSR） | 基准 | 快 **2~3x** | 显著 |
| 更新性能 | 基准 | 快 **1.3~2x** | 明显 |
| 包体积 (gzip) | 23KB | ~31KB (含 compiler) / **10.5KB** (runtime-only) | 按需更小 |
| Tree-shaking | 不支持 | **完整支持** | — |
| TypeScript 支持 | .d.ts | **原生 TS** | 质的飞跃 |
| Source Map | 部分 | **精确** | — |

## 小结

Vue 3.0 的诞生标志着 Vue 进入**成熟框架的新纪元**：

- **响应式**：Proxy 彻底解决了 Vue 2 的硬伤
- **组合式**：Composition API 解决了大型项目的代码组织难题
- **工程化**：TypeScript + Monorepo + Tree-shaking 全面现代化
- **性能**：PatchFlag 等编译优化使运行时更快

正如 Evan You 在 Vue 3 发布演讲中所说：

> *"We didn't just rewrite Vue for the sake of rewriting it. We rewrote it because we had a vision of where the web platform is going, and we wanted to make sure Vue is ready for that future."*
