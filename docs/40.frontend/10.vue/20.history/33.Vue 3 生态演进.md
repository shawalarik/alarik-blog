## 一、Pinia — Vuex 的继任者

### 为什么是 Pinia？

Vuex 4.x 虽然兼容 Vue 3，但存在以下问题：

| Vuex 的问题 | Pinia 的解决方案 |
|-------------|-----------------|
| 需要手动 `mapState/mapActions` | **解构即用**，自动推导类型 |
| mutations/actions 区分繁琐 | **只有 actions**（同步/异步统一） |
| 单一 Store 的模块嵌套复杂 | **扁平 Store**，每个 Store 独立 |
| TypeScript 支持差 | **原生 TS**，完整类型推断 |
| DevTools 集成有限 | **增强版 DevTools** |

### Pinia 核心用法

```typescript
// stores/user.ts
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'
import type { User } from '@/types'

// Option Store 风格（类似 Vuex）
export const useUserStore = defineStore('user', {
  state: () => ({
    user: null as User | null,
    loading: false
  }),
  
  getters: {
    isLoggedIn: (state) => !!state.user,
    userName: (state) => state.user?.name ?? 'Guest',
    
    // 可以访问其他 getters
    userProfile: (state) => ({
      name: state.user?.name,
      email: state.user?.email,
      avatar: state.user?.avatar
    })
  },
  
  actions: {
    // 同步和异步都可以写在 actions 中
    setUser(user: User) {
      this.user = user
    },
    
    async fetchUser(userId: string) {
      this.loading = true
      try {
        const res = await api.get<User>(`/users/${userId}`)
        this.setUser(res.data)
      } finally {
        this.loading = false
      }
    },
    
    logout() {
      this.user = null
      router.push('/login')
    }
  }
})
```

```typescript
// stores/todo.ts — Setup Store 风格（更灵活）
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'

export const useTodoStore = defineStore('todos', () => {
  // state（类似组件中的 ref/reactive）
  const todos = ref<Todo[]>([])
  const filter = ref<'all' | 'active' | 'completed'>('all')
  
  // getters（类似 computed）
  const filteredTodos = computed(() => {
    switch (filter.value) {
      case 'active': return todos.value.filter(t => !t.completed)
      case 'completed': return todos.value.filter(t => t.completed)
      default: return todos.value
    }
  })
  
  const stats = computed(() => ({
    total: todos.value.length,
    active: todos.value.filter(t => !t.completed).length,
    completed: todos.value.filter(t => t.completed).length
  }))
  
  // actions（普通函数）
  function addTodo(text: string) {
    todos.value.push({ id: crypto.randomUUID(), text, completed: false })
  }
  
  function toggleTodo(id: string) {
    const todo = todos.value.find(t => t.id === id)
    if (todo) todo.completed = !todo.completed
  }
  
  function removeTodo(id: string) {
    todos.value = todos.value.filter(t => t.id !== id)
  }
  
  // 返回所有需要在模板/外部使用的状态和方法
  return { todos, filter, filteredTodos, stats, addTodo, toggleTodo, removeTodo }
})
```

### 在组件中使用 Pinia

```vue
<script setup lang="ts">
import { useUserStore } from '@/stores/user'
import { useTodoStore } from '@/stores/todo'

const userStore = useUserStore()
const todoStore = useTodoStore()

// 直接解构（Pinia 的 store 是 reactive 的，但解构后失去响应性）
const { isLoggedIn, userName } = storeToRefs(userStore)  // ✅ 保持响应性

// 方法可以直接解构（不需要 storeToRefs）
const { addTodo, toggleTodo, removeTodo } = todoStore  // ✅ 方法可以直接解构
</script>

<template>
  <div v-if="userStore.isLoggedIn">
    <p>Welcome, {{ userStore.userName }}!</p>
  </div>
  
  <ul>
    <li v-for="todo in todoStore.filteredTodos" :key="todo.id">
      <input type="checkbox" :checked="todo.completed" 
             @change="todoStore.toggleTodo(todo.id)" />
      <span>{{ todo.text }}</span>
      <button @click="todoStore.removeTodo(todo.id)">✕</button>
    </li>
  </ul>
  
  <p>Stats: Active={{ todoStore.stats.active }}, Done={{ todoStore.stats.completed }}</p>
</template>
```

## 二、Vue Router 4.x

### 主要变化

| 特性 | Vue Router 3 (Vue 2) | Vue Router 4 (Vue 3) |
|------|---------------------|---------------------|
| 创建方式 | `new VueRouter({...})` | `createRouter({...})` |
| History 模式 | `mode: 'history'` | `createWebHistory()` |
| Hash 模式 | `mode: 'hash'` | `createWebHashHistory()` |
| 动态路由 | `router.addRoutes([])` | `router.addRoute()` (单条) |
| 导航守卫 | `next()` 必须 | `return` / `false` / 抛出异常 |
| TypeScript | .d.ts 类型 | **原生 TS** |
| Composition API | 不支持 | `useRoute()` / `useRouter()` |

### Vue Router 4 配置示例

```typescript
// router/index.ts
import { createRouter, createWebHistory, type RouteRecordRaw } from 'vue-router'
import Home from '@/views/Home.vue'

const routes: RouteRecordRaw[] = [
  {
    path: '/',
    name: 'home',
    component: () => import('@/views/Home.vue'),  // 懒加载
    meta: { requiresAuth: false }
  },
  {
    path: '/about',
    component: () => import('@/views/About.vue'),
    // 路由独享守卫
    beforeEnter: (to) => {
      // 返回 false 取消导航
      // 返回路径字符串重定向
      // 不返回或返回 undefined 允许导航
      if (!to.query.token) return '/login?redirect=' + to.fullPath
    }
  },
  {
    path: '/user/:id',
    name: 'user',
    component: () => import('@/views/UserDetail.vue'),
    props: true,  // 将 route.params 作为 props 传入
    children: [
      {
        path: 'profile',
        component: () => import('@/views/UserProfile.vue')
      },
      {
        path: 'posts',
        component: () => import('@/views/UserPosts.vue')
      }
    ]
  }
]

const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes,
  scrollBehavior(to, from, savedPosition) {
    if (savedPosition) return savedPosition
    if (to.hash) return { el: to.hash, behavior: 'smooth' }
    return { top: 0 }
  }
})

// 全局前置守卫（新版写法）
router.beforeEach(async (to, from) => {
  const authStore = useAuthStore()
  
  if (to.meta.requiresAuth && !authStore.isLoggedIn) {
    return { name: 'login', query: { redirect: to.fullPath } }
  }
  
  // 权限验证
  if (to.meta.roles && !authStore.hasAnyRole(to.meta.roles)) {
    return { name: 'forbidden' }
  }
  
  // 允许导航（不返回任何值或返回 true）
})

export default router
```

### Composition API 用法

```vue
<script setup lang="ts">
import { useRouter, useRoute, onBeforeRouteLeave } from 'vue-router'

const router = useRouter()
const route = useRoute()

// 编程式导航
function goHome() { router.push('/') }
function goBack() { router.back() }
function replaceCurrent() { router.replace('/new-path') }

// 访问当前路由信息
console.log(route.params.id)       // 动态参数
console.log(route.query.search)    // 查询参数
console.log(route.hash)            // hash 片段
console.log(route.meta.requiresAuth) // 自定义 meta

// 组件内守卫
onBeforeRouteLeave((to) => {
  if (hasUnsavedChanges) {
    const answer = window.confirm('确定离开？未保存的修改将丢失')
    if (!answer) return false  // 取消导航
  }
})
</script>
```

## 三、Vite — 革命性的构建工具

### 为什么不是 Webpack？

```
Webpack 开发模式:
保存文件 → 打整个项目 → 生成 bundle → HMR 更新 → 浏览器刷新
耗时: 3~10秒（取决于项目大小）❌

Vite 开发模式:
保存文件 → ESM 直接加载浏览器 → HMR 模块替换
耗时: 50~200ms（无论项目多大） ✅
```

### Vite 配置示例

```typescript
// vite.config.ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { resolve } from 'path'

export default defineConfig({
  plugins: [
    vue(),
    // 其他插件...
  ],
  
  resolve: {
    alias: {
      '@': resolve(__dirname, 'src'),
      '@components': resolve(__dirname, 'src/components'),
      '@utils': resolve(__dirname, 'src/utils')
    }
  },

  server: {
    port: 3000,
    open: true,
    proxy: {
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true,
        rewrite: (path) => path.replace(/^\/api/, '')
      },
      '/upload': {
        target: 'http://cdn.example.com',
        changeOrigin: true
      }
    },
    cors: true
  },

  build: {
    outDir: 'dist',
    sourcemap: process.env.NODE_ENV === 'development',
    rollupOptions: {
      output: {
        manualChunks: {
          'vendor': ['vue', 'vue-router', 'pinia'],
          'ui': ['element-plus'],
          'utils': ['lodash-es', 'dayjs']
        }
      }
    },
    chunkSizeWarningLimit: 500,
    cssCodeSplit: true
  },

  css: {
    preprocessorOptions: {
      scss: {
        additionalData: `@use "@/styles/variables" as *;`
      }
    }
  },

  // 环境变量
  envPrefix: 'VITE_',

  // SSR 相关配置
  ssr: {
    noExternal: ['element-plus']
  }
})
```

### Vite 与 Vue CLI 对比

| 能力 | Vue CLI (webpack) | Vite |
|------|-------------------|------|
| 启动速度 | 10~30s（冷启动慢） | **< 1s**（即时启动） |
| HMR 速度 | 1~3s | **50~200ms** |
| 生产构建 | 成熟稳定 | Rollup 打包，同样优秀 |
| 配置方式 | `vue.config.js` | `vite.config.ts` |
| 插件生态 | webpack 插件 | Vite/Rollup 插件 |
| 兼容性 | IE11+ | 现代浏览器（需 polyfill 时考虑） |
| SSR 支持 | 通过 vue-server-renderer | 内置 SSR 支持 |

import { ref, reactive } from 'vue'

## 六、Nuxt 3

Nuxt 3 是基于 Vue 3 的全新全栈框架，相比 Nuxt 2 有质的飞跃：

| 特性 | Nuxt 2 (Vue 2) | Nuxt 3 (Vue 3) |
|------|-----------------|-----------------|
| 核心引擎 | 基于 Vue 2 + webpack | 基于 Vue 3 + **Nitro** 引擎 |
| 构建工具 | webpack | **Vite**（开发体验飞跃） |
| TypeScript | 部分 | **原生支持** |
| Auto-imports | 手动配置 | **自动导入**（API、组件、composables） |
| Server API | express 兼容 | **Nitro**（跨平台部署） |
| 数据获取 | `asyncData` + `fetch` | `useFetch` + `useAsyncData` |
| 混合渲染 | SPA / Universal | **Route Rules**（按路由配置） |
| 文件路由 | pages/ 目录 | pages/ 目录（增强） |
| Nitro | 不支持 | **Server-only code** |

```vue
<!-- Nuxt 3 页面示例 -->
<script setup lang="ts">
// 这些都是自动导入的，无需显式 import

const { data: post, pending, error, refresh } = await useFetch(

  <p v-else-if="error">加载失败: {{ error.message }}</p>

```

## 七、DevTools 与开发者体验

### Volar 替代 Vetur

```
Vetur (Vue 2 时期):
  - 基于 TypeScript Language Service
  - 模板类型推断弱
  - 对大型项目性能差

Volar (Vue 3):
  - 完全重写的语言服务器
  - Takeover Mode（接管 TS 支持）
  - 精确的模板类型检查
  - 更好的性能
```

### Vue DevTools v7+

- **Timeline** 面板：组件渲染/更新时间线
- **Inspector** 面板：实时查看/编辑组件数据
- **Router** 面板：可视化路由历史
- **Pinia 面板：** 时间旅行调试、状态快照导出
- **Performance** 面板：组件渲染性能分析
- **Custom Inspector**：第三方库集成点

## 小结

Vue 3 生态已经全面成熟，关键特点：

1. **Pinia** 成为状态管理的事实标准（TypeScript 友好）
2. **Vite** 彻底改变了前端开发体验（即时启动、极速 HMR）
3. **VueUse** 提供了丰富的组合式函数库
4. **UI 组件库** 全面完成 Vue 3 迁移
5. **Nuxt 3** 为全栈应用提供了强大方案

这套生态体系使 Vue 3 成为当今最具生产力的前端框架之一。
