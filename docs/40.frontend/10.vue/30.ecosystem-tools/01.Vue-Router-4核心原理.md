Vue Router 是 Vue.js 官方的路由管理器，与 Vue.js 核心深度集成。本文深入 Vue Router 4 的底层实现机制。

## 架构概览

## 一、路由模式的实现差异

### Hash 模式

Hash 模式利用 URL 中 `#` 号后面的部分（称为 hash fragment）来模拟路由变化：

```
URL 结构:  http://example.com/#/user/123
                          ↑
                       hash 部分
                       (不会发送到服务器)
```

**核心原理**：

```javascript
// Hash 模式的关键：监听 hashchange 事件
class HashHistory {
  constructor(router) {
    this.router = router
    
    // 确保初始 hash 存在
    ensureSlash()
    
    // 监听 hash 变化
    window.addEventListener('hashchange', () => {
      this.onHashChange()
    })
  }
  
  push(location) {
    // 通过改变 location.hash 触发导航
    window.location.hash = location.path
  }
  
  replace(location) {
    // 替换当前记录（不产生新历史条目）
    window.location.replace(
      getUrl(this.base + location.fullPath)
    )
  }
  
  getCurrentLocation() {
    // 返回 # 后面的部分，去掉开头的 #
    return getHash().replace(/^#/, '')
  }
  
  onHashChange() {
    // hashchange 触发时通知路由更新
    const current = this.getCurrentLocation()
    this.transitionTo(current)
  }
}
```

**特点**：

| 优点 | 缺点 |
|------|------|
| 兼容所有浏览器（包括 IE9） | URL 不美观（带 `#`） |
| 无需服务器配置 | SEO 不友好（搜索引擎忽略 hash） |
| 部署简单（静态服务器即可） | 第三方服务可能截断 hash |

**内部实现细节** — `setupListeners` 方法：

```javascript
// 简化版 setupListeners
function setupListeners() {
  // 兼容性处理：某些浏览器在用户点击后退/前进时
  // 不会立即触发 hashchange，需要用 popstate 辅助
  const handleRoutingEvent = () => {
    const current = getHash().slice(1)  // 去掉 '#'
    if (current === this.current) return  // 避免重复处理
    this.transitionTo(current)
  }
  
  window.addEventListener('hashchange', handleRoutingEvent)
  window.addEventListener('popstate', handleRoutingEvent)
}
```

### History 模式

History 模式利用 HTML5 History API (`pushState` / `replaceState`) 来管理导航：

```
URL 结构:  http://example.com/user/123
                          ↑
                     无 # 号，看起来像正常路径
```

**核心原理**：

```javascript
class HTML5History {
  constructor(router, base) {
    this.router = router
    this.base = normalizeBase(base)
    
    // 监听 popstate（浏览器后退/前进按钮）
    window.addEventListener('popstate', e => {
      // 注意：popstate event 的 state 可能是 null
      // 需要从当前 URL 解析路径
      const current = this.getCurrentLocation()
      this.transitionTo(current)
    })
  }
  
  push(location, onComplete) {
    const { current } = this
    
    this.transitionTo(location, () => {
      // 导航成功后调用 pushState 更改 URL
      pushState(cleanPath(this.base + location.fullPath))
      
      // 处理 scroll 行为
      handleScroll(this.router, current, true)
      
      onComplete && onComplete()
    })
  }
  
  replace(location, onComplete) {
    const { current } = this
    
    this.transitionTo(location, () => {
      // replaceState 不产生新的历史记录
      replaceState(cleanPath(this.base + location.fullPath))
      
      handleScroll(this.router, current, false)
      
      onComplete && onComplete()
    })
  }
  
  getCurrentLocation() {
    // 从当前 URL 提取 path
    return getLocation(this.base)
  }
}

// 底层 API 封装
function pushState(url) {
  // 保存滚动位置到 state 对象
  saveScrollPosition()
  
  // 支持 scrollRestoration 的浏览器可以跳过手动保存
  if (supportsPushState()) {
    window.history.pushState({ key: setKey() }, '', url)
  } else {
    // 降级为 location.replace（不推荐）
    window.location.replace(url)
  }
}
```

**关键问题 — 404 处理**：

History 模式下，直接访问 `/user/123` 或刷新页面会向服务器发送请求。如果服务器没有对应资源，返回 **404**。

**解决方案 — 服务器 Fallback 配置**：

```nginx
# Nginx 配置
location / {
  try_files $uri $uri/ /index.html;  # 所有未匹配的路径回退到 index.html
}
```

```javascript
// Node.js Express 配置
const history = require('connect-history-api-fallback')()

app.use(history)
app.use(express.static('dist'))
```

```apache
# Apache (.htaccess)
<IfModule mod_rewrite.c>
  RewriteEngine On
  RewriteBase /
  RewriteRule ^index\.html$ - [L]
  RewriteCond %{REQUEST_FILENAME} !-f
  RewriteCond %{REQUEST_FILENAME} !-d
  RewriteRule . /index.html [L]
</IfModule>
```

### Memory 模式

Vue Router 4 新增的模式，用于非浏览器环境（SSR、测试、移动端原生应用）：

```javascript
import { createMemoryHistory } from 'vue-router'

// 不操作浏览器 URL，完全内存中管理
createRouter({
  history: createMemoryHistory(),
  routes
})
```

```typescript
// 内部实现极简
class MemoryHistory extends History {
  private stack: HistoryState[] = []
  private index = -1
  
  push(location: string) {
    this.stack = this.stack.slice(0, this.index + 1)
    this.stack.push(createState(location))
    this.index++
  }
  
  replace(location: string) {
    if (this.stack.length > 0) {
      this.stack[this.index] = createState(location)
    } else {
      this.push(location)
    }
  }
  
  getCurrentLocation(): string {
    const entry = this.stack[this.index]
    return entry ? entry.location : '/'
  }
}
```

### 三种模式对比

| 特性 | Hash | History | Memory |
|------|------|---------|--------|
| URL 格式 | `/path#/route` | `/route` | N/A |
| 服务器要求 | 无 | **必须配置 fallback** | 无 |
| 浏览器支持 | 所有浏览器 | HTML5 History API | 任意环境 |
| SEO | ❌ 弱 | ✅ 好 | N/A |
| 刷新行为 | 正常 | **需要服务端配合** | N/A |
| 适用场景 | 简单部署 | 生产环境首选 | SSR/测试/原生应用 |

## 二、路由匹配（Matcher）

### 路径解析与参数提取

路由匹配的核心任务是将 **URL 路径** 匹配到对应的 **路由记录** 并提取动态参数：

```typescript
interface RouteRecord {
  path: string          // 路由路径模板
  name?: string         // 命名路由名称
  components?: Record<string, Component>
  component?: Component
  redirect?: RouteLocation
  alias?: string | string[]
  children?: RouteRecord[]
  meta?: Record<string, any>
  props?: boolean | Record<string, any> | Function
  beforeEnter?: NavigationGuard
}

interface MatchedRouteRecord {
  path: string
  regex: RegExp          // 编译后的正则表达式
  components: Record<string, Component>
  instances: Record<string, any>
  name?: string
  parent?: MatchedRouteRecord
  redirect?: Record<string, any>
  meta: any
  props: any
}

// 路径编译：将字符串路径转为正则表达式
function compilePath(path: string): { regexp: RegExp; keys: PathParamKey[] } {
  const keys: PathParamKey[] = []
  
  // 将 :id → ([^/]+)，将 * → (.*)
  const regexp = path
    .replace(/\/:([^/]+)/g, (_, key) => {
      keys.push({ name: key, optional: false })
      return '/([^/]+)'
    })
    .replace(/\/\*/g, '(/.*)')
    .replace(/\/$/, '')
  
  return {
    regexp: new RegExp(`^${regexp}$`),
    keys
  }
}

// 示例
const result = compilePath('/users/:id/posts/:postId')
// result.regexp: /^\/users\/([^/]+)\/posts\/([^/]+)$/
// result.keys: [{name:'id'}, {name:'postId'}]
```

### 匹配过程详解

```typescript
function matchRoute(
  record: RouteRecordRaw,
  location: NormalizedLocation,
  matchedFrom: MatchedRouteRecord[]
): MatchedRouteRecord[] | void {
  // 1. 检查重定向
  if (record.redirect) {
    return pushWithRedirect(record, location)
  }
  
  // 2. 匹配路径并提取参数
  const { params, path } = extractParams(record, location)
  
  if (!params) return undefined  // 不匹配
  
  // 3. 构建匹配结果
  const matched: MatchedRouteRecord = {
    ...record,
    path,
    params,
    // 合并父级参数
    params: Object.assign({}, matchedFrom[matchedFrom.length - 1]?.params, params),
    matchedFrom
  }
  
  // 4. 如果有子路由，递归匹配剩余路径
  if (record.children && record.children.length > 0) {
    const remainingPath = location.path.slice(path.length)
    
    for (const child of record.children) {
      const childMatched = matchRoute(child, remainingPath, [...matchedFrom, matched])
      if (childMatched) return childMatched
    }
    
    // 子路由都不匹配但有默认子路由
    const defaultChild = record.children.find(c => c.path === '' || c.path === undefined)
    if (defaultChild) {
      return matchRoute(defaultChild, '', [...matchedFrom, matched])
    }
  } else if (location.path !== path && !record.path.includes('*')) {
    // 有剩余路径但无子路由可匹配
    return undefined
  }
  
  return [...matchedFrom, matched]
}
```

### 动态路由匹配示例

```
路由配置:
/user/:id              → 匹配 /user/123, 参数 id=123
/user/:id/post/:pid   → 匹配 /user/456/post/78, id=456, pid=78
/files/*               → 匹配 /files/a/b/c, 通配符捕获 "a/b/c"

实际匹配过程:

输入 URL: /user/42/post/99

Step 1: 根路由 '/' 匹配成功
Step 2: 尝试匹配子路由 'user/:id'
  → 正则 /^\/user\/([^/]+)$/ 匹配 "/user/42"
  → params = { id: '42' }
Step 3: 剩余路径 = "/post/99"，继续匹配 user 的子路由
  → 'post/:pid' 的正则匹配成功
  → params 合并 = { id: '42', pid: '99' }
  
最终结果: matched = [
  { path: '/', component: App },
  { path: '/user/:id', component: User },
  { path: '/post/:pid', component: Post }
]
params = { id: '42', pid: '99' }
```

## 三、嵌套路由的视图渲染

### `<router-view>` 的渲染逻辑

`<router-view>` 是一个函数式组件，负责根据当前路由匹配结果渲染对应组件：

```typescript
// <router-view> 组件定义（简化）
export const RouterView = defineComponent({
  name: 'RouterView',
  props: {
    name: { type: String, default: 'default' },  // 支持命名视图
    route: { type: undefined as any, default: undefined }
  },
  
  setup(props, { attrs, slots }) {
    // 注入路由上下文
    const injectedRoute = inject(routeLocationKey)!
    const depth = inject(matchDepthKey, 0)  // 嵌套层级
    
    // 计算要渲染的路由记录
    const matchedRouteRef = computed(() => {
      return props.route || injectedRoute.value
    })
    
    // 根据 depth 和 view name 找到对应的组件
    const viewRef = computed(() => {
      const route = matchedRouteRef.value
      return route.matched[depth]?.components[props.name] || null
    })
    
    // 渲染组件时传入 props 和插槽
    return () => {
      const route = matchedRouteRef.value
      const ViewComponent = viewRef.value
      
      if (!ViewComponent) return h(slots.default?.({ Component: ViewComponent }))
      
      // 将路由信息作为 props 传入
      const routeProps: Record<string, any> = {}
      
      // 处理 props 选项
      if (typeof route.matched[depth]?.props === 'object') {
        Object.assign(routeProps, route.matched[depth].props as object)
      } else if (route.matched[depth]?.props === true) {
        // props: true 时将所有 params 作为 props 传入
        Object.assign(routeProps, route.params || {})
      }
      
      return h(ViewComponent, mergeOptions(attrs, routeProps), slots.default ? 
        { default: () => slots.default({ Component: ViewComponent }) } : undefined)
    }
  }
})
```

### 嵌套路由的数据传递链路

```
URL: /parent/child/grandchild

路由配置:
/parent (ParentComponent)
  /child (ChildComponent)
    /grandchild (GrandchildComponent)

渲染结构:
<App>
  <!-- depth=0, name='default' → ParentComponent -->
  <RouterView>
    <ParentComponent :key="...">
      <!-- depth=1, name='default' → ChildComponent -->
      <RouterView>
        <ChildComponent :key="...">
          <!-- depth=2, name='default' → GrandchildComponent -->
          <RouterView>
            <GrandchildComponent />
          </RouterView>
        </ChildComponent>
      </RouterView>
    </ParentComponent>
  </RouterView>
</App>

数据流:
matched 数组 = [ParentRecord, ChildRecord, GrandchildRecord]

每个 RouterView 根据 depth 索引取 matched[depth]:
- 第一个 RouterView (depth=0): 取 matched[0] = ParentRecord → 渲染 ParentComponent
- 第二个 RouterView (depth=1): 取 matched[1] = ChildRecord → 渲染 ChildComponent
- 第三个 RouterView (depth=2): 取 matched[2] = GrandchildRecord → 渲染 GrandchildComponent
```

### Props 传递的三种模式

```javascript
// 1. props: false（默认）— 只传 $route 属性
{ path: '/user/:id', component: User }

// 2. props: true — 将路由参数作为 props 传入
{ path: '/user/:id', component: User, props: true }
// 等价于: <User :id="$route.params.id" />

// 3. props: Object — 静态 props
{ path: '/hello', component: Hello, props: { greeting: 'world' }}
// 等价于: <Hello greeting="world" />

// 4. props: Function — 动态 props
{
  path: '/search/:keyword',
  component: SearchResults,
  props: route => ({ query: route.query.q, keyword: route.params.keyword })
}
```

## 四、路由守卫的执行顺序

### 守卫类型总览

```
完整的导航解析流程:

导航触发 (push/replace/<nuxt-link>/编程式)

  ↓
① beforeEach (全局前置守卫)
   ↓ 返回 false 则取消
   ↓ 返回路径则重定向
   ↓ 否则继续

  ↓
② beforeRouteUpdate (复用组件内守卫)
   ↓ 仅当组件被复用时触发
   ↓ (如 /user/1 → /user/2)

  ↓
③ beforeEnter (路由独享守卫)
   ↓ 在路由配置中定义

  ↓
④ 解析异步路由组件
   ↓ import() 加载完成

  ↓
⑤ beforeRouteEnter (目标组件内守卫)
   ↓ 注意：此时组件实例尚未创建！
   ↓ 无法通过 this 访问组件

  ↓
⑥ 导航确认 (确认最终路由)

  ↓
⑦ afterEach (全局后置守卫)
   ↓ 导航已完成，无法取消

  ↓
⑧ DOM 更新触发
   ↓ 组件 mounted
```

### 守卫的参数与返回值

```typescript
// 守卫函数签名
type NavigationGuard = (
  to: RouteLocationNormalized,      // 目标位置
  from: RouteLocationNormalized,    // 当前位置
  next?: NavigationGuardNext        // Vue Router 3 兼容（可选）
) => RouteLocationRaw | boolean | Error | void

// 返回值含义：
// - false / undefined  → 取消导航
// - 字符串路径对象     → 重定向到该路径
// - (无返回或 true)    → 确认导航
// - Error 实例        → 导航中断，可被 router.onError 捕获
```

### 异步守卫

```javascript
// 返回 Promise 的异步守卫
router.beforeEach(async (to) => {
  // 检查是否已认证
  const authStore = useAuthStore()
  
  if (!authStore.isLoggedIn) {
    // 未登录且不是去登录页 → 重定向
    if (to.name !== 'login') {
      return { name: 'login', query: { redirect: to.fullPath } }
    }
    return  // 允许前往登录页
  }
  
  // 已登录但需要检查权限
  if (to.meta.roles) {
    await authStore.ensureRolesLoaded()
    if (!authStore.hasAnyRole(to.meta.roles)) {
      throw createError({ statusCode: 403, message: '无权限' })
    }
  }
})

// async/await 写法等价于：
// router.beforeEach((to) => {
//   return someAsyncCheck(to).then(result => {
//     if (!result.allowed) return '/login'
//   })
// })
```

### 组件内守卫

```vue
<script setup>
import { onBeforeRouteLeave, onBeforeRouteUpdate } from 'vue-router'

// 组件离开前（可用于防误操作提示）
onBeforeRouteLeave((to) => {
  if (hasUnsavedChanges) {
    const answer = window.confirm('确定离开？修改将丢失')
    if (!answer) return false  // 取消导航
  }
})

// 复用时触发（同组件不同参数）
// 例如从 /user/1 切换到 /user/2
onBeforeRouteUpdate(async (to) => {
  // 使用新参数重新获取数据
  userData.value = await fetchUser(to.params.id)
})
</script>
```

## 五、路由懒加载与代码分割

### Webpack 代码分割

```javascript
import { createRouter, createWebHistory } from 'vue-router'

const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [
    {
      path: '/',
      name: 'home',
      component: () => import('@/views/Home.vue')
      // ↑ webpack 会为这个 import() 创建单独的 chunk
    },
    {
      path: '/about',
      name: 'about',
      component: () => import(/* webpackChunkName: "about" */ '@/views/About.vue')
      // ↑ 魔法注释指定 chunk 名称
    },
    {
      path: '/admin',
      component: () => import('@/layouts/AdminLayout.vue'),
      children: [
        {
          path: '',
          name: 'admin-dashboard',
          // 嵌套路由也可以懒加载
          component: () => import('@/views/admin/Dashboard.vue')
        },
        {
          path: 'settings',
          name: 'admin-settings',
          component: () => import('@/views/admin/Settings.vue')
        }
      ]
    }
  ],
  
  // 预加载策略（Vue Router 4 新增）
  scrollBehavior(to, from, savedPosition) {
    if (savedPosition) return savedPosition
    if (to.hash) return { el: to.hash, behavior: 'smooth' }
    return { top: 0 }
  }
})
```
