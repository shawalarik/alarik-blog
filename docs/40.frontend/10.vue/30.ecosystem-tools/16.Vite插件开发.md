Vite 拥有丰富的插件生态，理解插件开发机制对于定制化构建流程至关重要。本文从零开始讲解 Vite 插件的完整开发生命周期。

## Vite 插件是什么？

Vite 插件是一个函数，接收 Vite 配置对象并返回增强后的配置：

```typescript
// 最简单的 Vite 插件
interface Plugin {
  name: string                    // 必须唯一
  enforce?: 'pre' | 'post'       // 可选：执行顺序
  
  // 以下钩子按执行时机排列
  config(config, env) { ... }      // 修改 vite.config
  configResolved(config) { ... }   // 配置已解析完成
  configureServer(server) { ... }   // 开发服务器配置
  transformIndexHtml(html) { ... } // index.html 转换
  resolveId(source, importer) { ... }
  load(id) { ... }                 // 加载模块内容
  transform(code, id) { ... }      // 转换模块代码
  buildStart(options) { ... }      // 构建开始
  closeBundle() { ... }            // 构建结束（生成文件）
}
```

## 钩子生命周期详解

### 完整执行时序

```
Vite 启动/构建 流程:

1. config()              ← 解析 vite.config.ts
2. configResolved()      ← 配置完成（不可再修改）
3. configureServer()     ← 开发服务器创建时（仅 dev）
4. transformIndexHtml() ← 处理 index.html
5. resolveId()           ← 解析每个 import 的模块 ID
6. load()                ← 读取模块原始内容
7. transform()           ← 转换代码（TypeScript → JS 等）
8. buildStart()          ← Rollup 构建开始（仅 build）
9. [每个 chunk 的] renderChunk()
10. [每个 chunk 的] generateBundle()
11. closeBundle()        ← 构建结束
12. writeBundle()        ← 文件写入磁盘
13. closeBundle()        ← 关闭 bundle
```

### 各钩子详解

#### `config` — 修改配置

```typescript
export default function myPlugin(): Plugin {
  return {
    name: 'my-plugin',
    
    // 接收用户配置和当前环境
    config(config, { command, mode }) {
      // command: 'serve' | 'build'
      // mode: 'development' | 'production'
      
      if (command === 'serve') {
        // 开发模式特定配置
        return {
          server: {
            proxy: {
              '/api': 'http://localhost:8080'
            }
          }
        }
      }
      
      // 返回的对象会与用户配置深度合并
      return {
        define: {
          __APP_VERSION__: JSON.stringify('1.0.0')
        },
        resolve: {
          alias: {
            '@utils': path.resolve(__dirname, './src/utils')
          }
        }
      }
    }
  }
}
```

#### `resolveId` — 自定义模块解析

```typescript
export default function virtualModulePlugin(): Plugin {
  return {
    name: 'virtual-module',
    
    resolveId(id) {
      // 将虚拟路径映射为真实 ID
      if (id.startsWith('virtual:')) {
        return '\0' + id  // \0 前缀标记为虚拟模块
      }
      
      // 将 .svg?url 映射为特殊 ID
      if (id.endsWith('.svg?url')) {
        return id.replace('?url', '?__VITE_ASSET__')
      }
      
      return null  // 不处理则交给下一个插件
    }
  }
}
```

#### `load` — 自定义模块加载

```typescript
export default function virtualModulePlugin(): Plugin {
  const virtualModules = {
    'virtual:config': JSON.stringify({
      apiUrl: process.env.API_URL,
      appName: 'My App'
    }),
    
    'virtual:env': `
export const ENVIRONMENT = '${import.meta.env.MODE}'
export const BUILD_TIME = '${new Date().toISOString()}'
`
  }
  
  return {
    name: 'virtual-modules',
    
    resolveId(id) {
      if (id in virtualModules) return '\0' + id
      return null
    },
    
    load(id) {
      if (id.startsWith('\0virtual:')) {
        const realId = id.slice(1)
        return virtualModules[realId]
      }
      return null
    }
  }
}

// 使用方式
// import config from 'virtual:config'
// import { BUILD_TIME } from 'virtual:env'
```

#### `transform` — 代码转换

```typescript
export default function customDirectiveTransform(): Plugin {
  return {
    name: 'custom-directive-transform',
    
    enforce: 'pre',  // 在 vue 插件之前执行
    
    transform(code, id) {
      // 只处理 .vue 文件
      if (!id.endsWith('.vue')) return
      
      // 示例：将 v-permission 指令转换为运行时代码
      if (code.includes('v-permission')) {
        code = code.replace(
          /v-permission="([^"]+)"/g,
          (_, permission) => 
            `v-if="hasPermission('${permission}')"`
        )
        
        // 注入 hasPermission 函数导入
        code += '\nimport { hasPermission } from "@/composables/usePermission"'
      }
      
      return { code, map: null }
    }
  }
}
```

#### `configureServer` — 开发服务器钩子

```typescript
export default function devServerPlugin(): Plugin {
  return {
    name: 'dev-server-enhance',
    
    configureServer(server) {
      // server 是 ViteDevServer 实例
      
      // 添加自定义中间件
      server.middlewares.use((req, res, next) => {
        if (req.url === '/api/health') {
          res.end(JSON.stringify({ status: 'ok', timestamp: Date.now() }))
          return
        }
        next()
      })
      
      // WebSocket 连接
      server.ws.on('connection', (ws) => {
        ws.onmessage = (event) => {
          console.log('Client message:', event.data)
        }
      })
    }
  }
}
```

#### `transformIndexHtml` — HTML 转换

```typescript
export default function htmlTransformPlugin(): Plugin {
  return {
    name: 'html-transform',
    
    transformIndexHtml(html, ctx) {
      // ctx.path — 当前 HTML 路径
      // ctx.server — 开发服务器实例
      // ctx.bundle — 构建时的入口 chunk
      
      return {
        html,
        tags: [
          // 在 </head> 前注入
          {
            tag: 'script',
            attrs: { src: 'https://analytics.example.com/tracker.js' },
            injectTo: 'head'
          },
          // 在 <body> 后注入（用于全局 CSS/JS）
          {
            tag: 'link',
            attrs: { rel: 'stylesheet', href: '/global-styles.css' },
            injectTo: 'body'
          }
        ]
      }
    }
  }
}
```

## 完整实战：从零编写一个实用插件

### 场景：SVG 内联优化插件

目标：自动将小体积 SVG 文件内联到代码中（避免额外的 HTTP 请求）：

```typescript
// plugins/vite-svg-inline.ts
import type { Plugin, ResolvedConfig } from 'vite'
import { readFileSync, statSync } from 'fs'
import { extname, join } from 'path'

interface Options {
  /** 小于此阈值的 SVG 会内联（bytes），默认 10KB */
  inlineThreshold?: number
  /** 排除的文件 glob 模式 */
  exclude?: RegExp
  /** 是否移除 fill/stroke 等属性以支持 CSS 着色 */
  stripStyleAttrs?: boolean
}

export default function svgInlinePlugin(options: Options = {}): Plugin {
  const {
    inlineThreshold = 10240,
    exclude = /node_modules/,
    stripStyleAttrs = false
  } = options

  return {
    name: 'vite-svg-inline',

    async transform(code, id) {
      // 1. 只处理 .svg 文件的 import
      if (extname(id) !== '.svg') return null

      // 2. 排除匹配的文件
      if (exclude.test(id)) return null

      // 3. 读取文件大小
      try {
        const stats = statSync(id)
        if (stats.size > inlineThreshold) {
          // 大文件保持原样（由其他插件如 vite-plugin-svg 处理）
          return null
        }

        // 4. 读取并内联 SVG 内容
        let svgContent = readFileSync(id, 'utf-8')

        // 5. 可选：移除样式属性以便通过 CSS 控制
        if (stripStyleAttrs) {
          svgContent = svgContent
            .replace(/\sfill="[^"]*"/gi, '')
            .replace(/\sstroke="[^"]*"/gi, '')
            .replace(/\sstroke-width="[^"]*"/gi, '')
        }

        // 6. 导出为 URL 字符串
        const encoded = encodeURIComponent(svgContent)
          .replace(/'/g, "%27")
          .replace(/"/g, "%22")

        const dataUrl = `data:image/svg+xml,${encoded}`

        return {
          code: `export default ${JSON.stringify(dataUrl)}`,
          map: null,
        }
      } catch (e) {
        this.warn(`Failed to inline SVG ${id}:`, e.message)
        return null
      }
    },

    // 开发者提示
    apply: 'build' as const,  // 同时在 dev 和 build 生效
  }
}
```

### 使用这个插件

```javascript
// vite.config.ts
import svgInline from './plugins/vite-svg-inline'

export default defineConfig({
  plugins: [
    vue(),
    svgInline({
      inlineThreshold: 8192,      // 8KB 以内内联
      exclude: /src\/icons\/large/,  // 排除大图标目录
      stripStyleAttrs: true         // 移除颜色属性
    })
  ]
})
```

```vue
<!-- 组件中使用 -->
<template>
  <img :src="logoIcon" alt="Logo" />
</template>

<script setup lang="ts">
// 小 SVG 会被内联为 data URL（无 HTTP 请求！）
import logoIcon from '@/assets/logo.svg'
</script>
```

## 兼容 Rollup 插件

Vite 使用 Rollup 作为生产构建引擎。Rollup 插件可以通过适配层在 Vite 中使用：

```typescript
// 如果已有 Rollup 插件想兼容 Vite：
import type { Plugin } from 'vite'

function rollupCompatiblePlugin(rollupPlugin): Plugin {
  const name = rollupPlugin.name || 'rollup-compat-wrapper'
  
  return {
    name,
    
    // Vite 的 transform 对应 Rollup 的 transform
    // Vite 的 buildStart/closeBundle 直接透传
    
    // 核心转换逻辑
    transform(code, id) {
      // Rollup 插件的 transform 签名是 (code, id)
      const result = rollupPlugin.transform?.(code, id)
      if (result) {
        return typeof result === 'string' ? { code: result } : result
      }
      return null
    }
  }
}
```

**注意**：
- Vite 的 `transform` 钩子签名与 Rollup 不同（多了 sourceMap 参数）
- Vite 的 `load` 钩子在 Rollup 中没有直接对应
- Rollup 的 `options` / `outputOptions` 钩子对应 Vite 的 `config`
- 建议优先使用原生 Vite 插件 API，需要 Rollup 功能时可参考 `@rollup/plugin-commonjs` 等

## HMR（热更新）处理

```typescript
export default function hmrAwarePlugin(): Plugin {
  return {
    name: 'hmr-demo',
    
    handleHotUpdate({ file, modules, server }) {
      // file: 变更的文件路径
      // modules: 受影响的模块列表
      // server: ViteDevServer 实例
      
      console.log(`[HMR] File changed: ${file}`)
      console.log(`[HMR] Affected modules: ${modules.length}`)
      
      // 可以返回自定义 HMR 更新
      // 返回 undefined 则使用默认行为
      return
    }
  }
}
```

## 插件推荐顺序（enforce）

```typescript
export default function myPrePlugin(): Plugin ({
  name: 'my-pre-plugin',
  enforce: 'pre',  // 在核心插件之前执行（如 vue 插件之前）
})

export default function myPostPlugin(): Plugin({
  name: 'my-post-plugin',
  enforce: 'post', // 在核心插件之后执行（如构建压缩之前）
})

// 默认不设置 enforce → 中间位置
```

| enforce | 适用场景 |
|---------|----------|
| `'pre'` | 别名解析、虚拟模块、环境变量注入 |
| （默认） | 代码转换、CSS 处理、资源处理 |
| `'post'` | 压缩、打包分析、最终产物修改 |
