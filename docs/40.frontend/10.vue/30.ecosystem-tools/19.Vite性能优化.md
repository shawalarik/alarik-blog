Vite 本身已经很快了，但在大型项目中仍需关注性能调优。本文覆盖从开发环境到生产构建的全链路优化策略。

## 一、依赖预构建（Deps Optimization）

### 工作原理

```
首次启动 (npx vite):
  
  node_modules/
  ├── vue/dist/vue.runtime.esm-bundler.js  ← ESM 入口
  ├── lodash-es/lodash.js                  ← ESM 入口
  └── ... 更多依赖

  Vite 扫描源码中所有 import
  ↓ 找出所有 bare imports (非相对路径、非绝对路径)
  ↓ 用 esbuild 将这些依赖预构建为单个 ESM 文件
  ↓ 输出到 node_modules/.vite/deps/

  结果:
  node_modules/.vite/deps/
  ├── vue.js          ← 预构建后（合并 + 压缩）
  ├── lodash-es.js   ← 预构建后
  └── chunk-XXX.js    ← 其他依赖
```

### 优化配置

```javascript
// vite.config.ts
import { defineConfig } from 'vite'

export default defineConfig({
  optimizeDeps: {
    // 1. 强制预构建某些包（即使没被扫描到）
    include: [
      'axios',           // 常用库
      'lodash-es',       // ESM 版本的 lodash
      'dayjs/esm',       // dayjs 的 ESM 入口
    ],
    
    // 2. 排除不需要预构建的包
    exclude: ['@vueuse/core'],  // 已经是 ESM 且无 CJS 依赖
    
    // 3. esbuild 选项
    esbuildOptions: {
      target: 'es2020',     // 目标浏览器版本
      // 自定义 esbuild 插件
      plugins: []
    },
    
    // 4. 禁用预构建（不推荐，仅调试时使用）
    // enabled: false
  }
})
```

### 常见问题与解决

```javascript
// 问题 1: 新增依赖后需要重启 dev server？
// 解决: 设置 noDiscovery: true 后手动指定 include
optimizeDeps: {
  include: ['my-new-package']
},

// 问题 2: 子依赖没有被预构建？
// 解决: 使用 allowNodeBuiltins 或手动 include
optimizeDeps: {
  esbuildOptions: {
    // 让 esbuild 能解析 Node 内置模块
    banner: {
      js: 'import { createRequire } from "module"; const require = createRequire(import.meta.url);'
    }
  }
}
```

## 二、开发环境优化

### 冷启动加速

```javascript
// vite.config.ts
export default defineConfig({
  server: {
    host: '0.0.0.0',       // 允许局域网访问（不影响性能但方便调试）
    port: 3000,
    open: false,           // 自动打开浏览器可关闭以节省时间
    cors: true
  },
  
  // 减少 DNS 解析等开销
  dns: {
    // 可选：配置 hosts 映射
  }
})
```

### HMR 优化

```vue
<!-- 避免 HMR 全量更新：拆分大组件 -->
<template>
  <!-- ✅ 好：稳定部分独立组件 -->
  <LayoutHeader />
  <LayoutSidebar />
  
  <!-- ✅ 好：频繁变化的内容区域 -->
  <MainContent />
</template>

<!-- ❌ 差：整个页面是一个巨型 SFC，任何改动都触发全量 HMR -->
<template>
  <div class="app">
    <header>...</header><nav>...</nav>...
    <main>{{ hugeData }}</main>
    <footer>...</footer>
  </div>
</template>
```

```css
/* CSS 也影响 HMR 范围 */

/* ✅ 好：局部作用域样式 */
<style scoped>
.component-a { color: red; }
</style>

/* ⚠️ 注意：全局 CSS 变更可能触发大量组件 HMR */
/* 尽量减少对全局样式的频繁修改 */
```

## 三、生产构建优化

### 构建配置清单

```javascript
// vite.config.ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  
  build: {
    // ========== 输出目录 ==========
    outDir: 'dist',
    assetsDir: 'assets',        // 静态资源输出子目录
    
    // ========== Source Map ==========
    sourcemap: false,             // 生产环境通常关闭（减小产物）
    // sourcemap: 'hidden',       // 仅错误信息包含 source map
    // sourcemap: true,          // 完整 source map
    
    // ========== 代码压缩 ==========
    minify: 'esbuild',           // 'esbuild'(快速) | 'terser'(更多选项)
    cssCodeSplit: true,           // CSS 分割（默认开启）
    
    // ========== Chunk 分割策略 ==========
    rollupOptions: {
      output: {
        manualChunks: {
          // 1. Vue 核心（变化少，长期缓存）
          'vendor-vue': ['vue', 'vue-router', 'pinia'],
          
          // 2. UI 库（较大，单独分包）
          'vendor-ui': ['element-plus'],
          
          // 3. 工具库
          'vendor-utils': ['lodash-es', 'dayjs'],
        },
        
        // Chunk 文件命名（便于长期缓存）
        entryFileNames: 'assets/[name].[hash].js',
        chunkFileNames: 'assets/[name].[hash].js',
        assetFileNames: 'assets/[name].[hash].[ext]',
      }
    },
    
    // ========== 打包阈值 ==========
    chunkSizeWarningLimit: 500,  // 单个 chunk 超过 500KB 时警告
    
    // ========== CSS 策略 ==========
    cssTarget: 'chrome87',       // CSS 兼容目标
    
    // ========== 其他 ==========
    reportCompressedSize: true,  // 构建完成后打印 gzip 后的大小
    emptyOutDir: true,           // 构建前清空输出目录
  }
})
```

### 构建产物分析

```bash
# 方式 1：Vite 内置可视化报告
npx vite build --mode production

# 方式 2：使用 rollup-plugin-visualizer
npm install -D rollup-plugin-visualizer

# vite.config.ts
import { visualizer } from 'rollup-plugin-visualizer'

export default defineConfig({
  plugins: [vue(), visualizer()]
})

# 构建后会自动打开依赖关系图的可视化页面
```

### 典型构建产物结构

```
dist/
├── index.html                          # 入口 HTML
├── assets/
│   ├── vendor-vue.[hash].js            # ~140 KB (gzip: ~45 KB)
│   ├── vendor-ui.[hash].js             # ~200 KB (gzip: ~60 KB)
│   ├── vendor-utils.[hash].js         # ~50 KB (gzip: ~15 KB)
│   ├── index.[hash].js                # 主应用代码 (gzip: ~20 KB)
│   ├── index-[other].[hash].js        # 动态 import 的 chunk
│   ├── style.[hash].css               # 合并后的 CSS
│   └── logo.[hash].svg                # 静态资源
└── ...
```

## 四、大型 Monorepo 项目优化

```javascript
// vite.config.ts (Monorepo 项目)
import { defineConfig } from 'vite'

export default defineConfig({
  // 1. 减少文件搜索范围
  resolve: {
    // 明确指定别名，避免深度递归搜索
    alias: {
      '@': resolve(__dirname, 'packages/app/src'),
      '@shared': resolve(__dirname, 'packages/shared/src'),
      '@ui': resolve(__dirname, 'packages/ui/src')
    }
  },
  
  // 2. 缓存策略
  cacheDir: 'node_modules/.vite-cache',
  
  // 3. 环境变量
  envPrefix: 'APP_',
  
  // 4. esbuild 配置
  esbuild: {
    jsxFactory: 'h',       // JSX 工厂函数
    jsxFragment: 'Fragment'
  },
  
  // 5. SSR 相关
  ssr: {
    noExternal: ['element-plus']  // SSR 时这些包不 externalize
  },
  
  // 6. 开发性能
  server: {
    fs: {
      // 允许访问的文件范围（安全限制）
      strict: false
    },
    watch: {
      // 忽略不必要的文件监听
      ignored: ['**/node_modules/**', '**/.git/**', '**/dist/**']
    },
    // HMR 去抖（避免频繁刷新）
    hmr: {
      overlay: true  // 错误覆盖层
    }
  },
  
  // 7. 构建优化
  build: {
    target: 'es2020',
    outDir: 'dist',
    rollupOptions: {
      output: {
        manualChunks(id) {
          // 更细粒度的分包策略
          if (id.includes('node_modules')) {
            // 第三方包分组
            if (id.includes('@element-plus')) return 'element-plus'
            if (id.includes('vue')) return 'vue-vendor'
            if (id.includes('lodash')) return 'lodash'
            return 'vendor'  // 其余第三方
          }
        }
      }
    }
  }
})
```

## 五、运行时性能检查清单

```
构建后应验证的项目:

Lighthouse 评分:
□ Performance > 90 (绿)
□ Accessibility > 90
□ Best Practices > 90
□ SEO > 80 (如适用)

网络层面:
□ 启用 Gzip/Brotli 压缩
□ 静态资源 CDN 加速
□ HTTP/2 或 HTTP/3
□ Cache-Control 头部正确配置
□ 图片使用 WebP/AVIF 格式 + lazy loading

JS/CSS 层面:
□ Tree-shaking 无效代码被移除
□ CSS 已提取并压缩
□ 未使用的 CSS 被 purged (purgecss)
□ Polyfills 仅针对需要的浏览器
□ 第三方库按需引入 (unplugin-vue-components)

运行时层面:
□ 首屏渲染时间 (FCP) < 1.5s
□ 最大内容绘制 (LCP) < 2.5s
□ 累积布局偏移 (CLS) < 0.1
□ 首次输入延迟 (FID) < 100ms
□ 总阻塞时间 (TBT) < 300ms
```

## 六、常用性能优化插件推荐

| 插件 | 用途 | 效果 |
|------|------|------|
| [`vite-plugin-compression`](https://github.com/vitejs/vite-plugin-compression) | Gzip/Brotli 压缩 | 传输体积减 60~80% |
| [`vite-plugin-imagemin`](https://github.com/anncodejs/vite-plugin-imagemin) | 图片无损压缩 | 图片体积减 5~15% |
| [`rollup-plugin-visualizer`](https://github.com/btd/rollup-plugin-visualizer) | 构建产物可视化 | 分析依赖关系 |
| [`vite-bundle-visualizer`](https://github.com/vitenjs/vite-bundle-visualizer) | Bundle 分析器 | 找出过大 chunk |
| [`vite-plugin-pwa`](https://github.com/vite-pwa/svelte-kit-pwa) | PWA 支持 | 离线可用 |
