Web Components 是浏览器原生的组件标准（Custom Elements + Shadow DOM + Templates）。本文探讨 Vue 与 Web Components 双向互操作的各种方式。

## 技术背景

### Web Components 三大支柱

```
1. Custom Elements (自定义元素)
   └── 允许开发者定义新的 HTML 标签：<my-component />
   
2. Shadow DOM (影子 DOM)
   └── 创建隔离的 DOM 子树，外部样式不影响内部
   
3. HTML Templates (HTML 模板)
   └── 声明式的模板声明机制（<template> 标签）

组合效果:
  <my-counter value="5"></my-counter>
  ↑ 这是一个真正的 DOM 元素！
  内部实现被 Shadow DOM 封装，样式完全隔离
```

### 为什么需要互操作？

```
场景:

1. 微前端架构中混用框架
   ├── 主应用: Vue 3
   ├── 子应用 A: React (已发布为 Web Component)
   └── 子应用 B: Svelte (已发布为 Web Component)

2. 发布跨框架可复用的 UI 库
   ├── Button.vue → 定义为 <ui-button> Web Component
   └── React/Angular/Vanilla JS 项目都能直接用

3. 利用成熟的 Web Component 生态
   ├── Google Charts (<google-chart>)
   ├── Video Player (<video-player>)
   └── Payment Form (<payment-request-button>)
   这些都是原生或第三方的 Web Components！

4. 团队技术栈迁移过渡期
   └── 新功能用 WC 发布，老项目直接引用，无需同步改造
```

## 方向一：Vue 组件 → Web Component

### defineCustomElement

Vue 3 提供了 `defineCustomElement` API，可以将 SFC 转换为 Custom Element：

```vue
<!-- src/components/FancyCounter.vue -->
<script setup lang="ts">
import { ref, onMounted } from 'vue'

const props = defineProps<{
  initialValue?: number
}>()

const count = ref(props.initialValue ?? 0)
const doubled = computed(() => count.value * 2)

function increment() { count.value++ }
function decrement() { count.value-- }

defineExpose({ increment, decrement, doubled })

// 暴露给外部的方法（WC 中通过 .method() 调用）
onMounted(() => {
  if (window.customElements) {
    console.log('[FancyCounter] mounted as Custom Element')
  }
})
</script>

<template>
  <div class="fancy-counter" part="root">
    <button class="fancy-counter__btn" @click="decrement">−</button>
    <span class="fancy-counter__value">{{ count }}</span>
    <span class="fancy-counter__doubled">(×2 = {{ doubled }})</span>
    <button class="fancy-counter__btn" @click="increment">+</button>
  </div>
</template>

<style>
:host {
  display: inline-block;
  font-family: system-ui;
}

.fancy-counter {
  display: inline-flex;
  align-items: center;
  gap: 8px;
  padding: 8px 16px;
  border-radius: 9999px;
  background: linear-gradient(135deg, #667eea 0%, #764ba2 100%);
  color: white;
  font-weight: bold;
  font-size: 18px;
  box-shadow: 0 4px 15px rgba(102, 126, 234, 0.4);
}

.fancy-counter__btn {
  width: 32px;
  height: 32px;
  border: none;
  border-radius: 50%;
  background: rgba(255,255,255,0.2);
  color: white;
  cursor: pointer;
  font-size: 18px;
  line-height: 1;
}
</style>
```

```typescript
// 注册为 Web Component
import FancyCounter from './components/FancyCounter.vue'
import { defineCustomElement } from 'vue'

defineCustomElement('fancy-counter', FancyCounter, {
  // Shadow DOM 选项
  shadowRoot: false,          // 是否创建 Shadow DOM
  // props 映射（可选）
  props: {
    // 将 HTML attribute 映射到 Vue props
    'initial-value': {
      type: Number,
      default: 0
    }
  },
  // 事件映射（可选）
  // events: ['count-changed'],
})
```

### 在非 Vue 项目中使用

```html
<!-- 纯 HTML 页面！ -->
<!DOCTYPE html>
<html>
<head>
  <script src="https://unpkg.com/vue@3/dist/vue.global.prod.js"></script>
  <script type="module">
    import { defineCustomElement } from 'https://unpkg.com/vue@3/dist/vue.esm-browser.js'
    import MyComponent from './MyComponent.js'  // 编译后的组件
    
    defineCustomElement('my-component', MyComponent)
  </script>
</head>
<body>
  <!-- 直接作为自定义元素使用 -->
  <my-component initial-value="10"></my-component>
  
  <script>
    // 访问暴露的方法
    const el = document.querySelector('my-component')
    console.log(el.doubled)  // 20
    
    // 监听事件
    el.addEventListener('count-changed', (e) => {
      console.log('Count:', e.detail)
    })
  </script>
</body>
</html>
```

## 方向二：在 Vue 中使用 Web Components

### 直接使用 Custom Elements

```vue
<script setup lang="ts">
import { ref, onMounted, onUnmounted } from 'vue'

// 第三方 Web Component（如 Google Charts）
const chartData = ref([['Year', 'Sales', 'Expenses'], ['2021', 1040, 400], ['2022', 1300, 500]])
</script>

<template>
  <div class="dashboard">
    <!-- 直接在模板中使用 Web Component -->
    <google-chart
      type="column"
      :options="{ title: 'Company Performance', height: 400 }"
      :data="chartData"
    ></google-chart>
    
    <!-- 另一个 WC 示例 -->
    <payment-request-button 
      id="pay-btn"
      button-label="Pay $9.99"
      price="9.99"
      currency="USD"
    ></payment-request-button>
  </div>
</template>
```

### 属性传递与事件桥接

```vue
<script setup lang="ts">
// 问题 1: Vue 的 v-bind 对 WC attributes 的处理有限制
// 解决: 使用 ref 直接操作 DOM 属性

const wcRef = ref<HTMLElement>()

function setWcProp(key: string, value: any) {
  wcRef.value?.setAttribute(`data-${kebabize(key)}`, JSON.stringify(value))
}

function getWcProp<T>(key: string): T | null {
  const attr = wcRef.value?.getAttribute(`data-${kebabize(key)}`)
  return attr ? JSON.parse(attr) : null
}
</script>

<template>
  <!-- 使用 ref 获取 WC 元素引用 -->
  <some-web-component ref="wcRef" data-custom-prop='{"foo":"bar"}' />
  
  <button @click="setWcProp('newKey', { a: 1 })">Set Prop</button>
</template>
```

### 更优雅的桥接方案：vue-wc-bridge

对于频繁使用 Web Components 的项目，可以创建一个 Composable：

```typescript
// composables/useWebComponent.ts
/**
 * Web Component 互操作的 Composable
 * 解决 Vue 与 WC 之间的属性/事件通信问题
 */
export function useWebComponent<T extends HTMLElement>(selector: string) {
  const el = shallowRef<T | null>(null)
  
  onMounted(() => {
    el.value = document.querySelector(selector) as T
  })
  
  // 设置 WC 属性
  function setAttr(name: string, value: string | null) {
    el.value?.setAttribute(name, value ?? '')
  }
  
  // 获取 WC 属性
  function getAttr(name: string): string | null {
    return el.value?.getAttribute(name)
  }
  
  // 监听 WC 自定义事件
  function onCustomEvent(event: string, handler: EventListener) {
    el.value?.addEventListener(event, handler)
    onUnmounted(() => el.value?.removeEventListener(event, handler))
  }
  
  return { el, setAttr, getAttr, onCustomEvent }
}
```

## Shadow DOM 的挑战

### 样式穿透问题

```vue
<!-- 场景：Web Component 使用了 Shadow DOM -->

<template>
  <!-- 这个 WC 有自己的 Shadow DOM -->
  <third-party-wc theme="dark">
    <!-- 我们的 Vue 内容会被渲染到 Shadow DOM 内部吗？ -->
    <!-- 这取决于 WC 的 slot 设计 -->
  </third-party-wc>
</template>
```

```css
/* 问题：Vue 的全局样式无法穿透 Shadow DOM */

/* 全局 CSS */
.btn { background: blue; }

/* 如果 .btn 在 Shadow DOM 内部，这个规则无效！ */

/* 解决方案：::part() 选择器 */
:host(.dark) ::part(btn) {
  /* 可以影响 Shadow DOM 中标记了 part="btn" 的元素 */
  background: red;
}
```

```vue
<style>
/* Vue 组件内定义的样式对 Shadow DOM 无效 */
/* 需要通过以下方式之一解决：

1. 使用 CSS 变量（WC 暴露）
   :root { --wc-btn-bg: blue; }

2. 通过 ::part() 伪类（WC 必须暴露 part）
   ::part(root) { padding: 16px; }

3. 使用 constructable stylesheets（实验性 API）
*/
</style>
```

### Slot 桥接

```
Vue Slot ↔ Web Component Slot 的映射关系:

Vue Template              →  Web Component
────────────────────         ──────────────────
<slot name="header">     ←→  <slot name="header">
  <h1>Title</h1>                  │   <h1>Slotted Title</h1>
</slot>                         │ </slot>
                               │
<slot />                 ←→  <slot> (默认插槽)
Default content                │   Default content
</slot>                          │
                               │
<slot name="footer">     ←→  <slot name="footer">
  <p>Footer</p>                   │   <p>Footer content</p>
</slot>                          │ </slot>
```

## Lit / Stencil 组件在 Vue 中复用

### 使用 Stencil 编写的 WC

Stencil 是 Ionic 出品的 WC 构建工具，输出标准 Web Components：

```html
<!-- my-lib/package/my-card.wc (Stencil 组件) -->
<component>
  <div class="card">
    <slot name="image" />
    <div class="card-body">
      <slot name="title" />
      <slot />
      <slot name="actions" />
    </div>
  </div>
</component>
```

```typescript
// 编译输出: my-card.js (标准的 Web Component)
class MyCard extends HTMLElement {
  static get observedAttributes() {
    return ['heading-level']
  }

  connectedCallback() {
    this.attachShadow({ mode: 'open' })
    this.render()
  }
  
  render() {
    const heading = this.getAttribute('heading-level') || 'h3'
    this.shadowRoot!.innerHTML = `
      <div class="card">
        <slot name="image"></slot>
        <div class="card-body">
          <${heading}><slot name="title"></slot></${heading}>
          <slot></slot>
          <slot name="actions"></slot>
        </div>
      </div>
    `
  }
}

customElements.define('my-card', MyCard)
```

```vue
<!-- 在 Vue 中使用 Stencil 组件 -->
<script setup lang="ts">
// 直接 import 并使用
import '@mylib/my-card'
</script>

<template>
  <main>
    <my-card heading-level="h2">
      <img slot="image" src="/logo.png" alt="Logo" slot="image" />
      <h2 slot="title">Hello World</h2>
      <p>This is body content.</p>
      <button slot="actions">Action!</button>
    </my-card>
  </main>
</template>
```

## 微前端架构中的角色

```
微前端架构示例:

┌─────────────────────────────────────┐
│           Shell App (Vue 3)            │
│                                       │
│  ┌─────────────────────────────────┐   │
│  │  Header (Vue SFC)               │   │
│  │  <nav>                             │   │
│  │    <micro-fea-nav></nav>       │   │ ← Web Component!
│  │  └───────────────────────────────┘   │
│  │                                     │
│  ├─ Main Content Area               │
│  │  ┌─────────────────────────────┐  │
│  │  │  <micro-fea-dashboard />   │  │ ← WC (React)
│  │  └───────────────────────────────┘  │
│  │                                     │
│  └─────────────────────────────────┘   │
└─────────────────────────────────────┘

优势:
1. Shell 和子应用可以使用不同框架
2. WC 作为标准化接口解耦
3. 各团队独立开发、独立部署
4. 通信通过 Custom Events 实现
```

## 性能考虑

| 方面 | 建议 |
|------|------|
| **何时将 Vue 组件转为 WC** | 需要在非 Vue 项目中复用时；或发布公共 UI 库时 |
| **Shadow DOM 开销** | 仅在确实需要样式隔离时开启；否则保持 `shadowRoot: false` |
| **性能** | WC 的渲染不在 Vue 的虚拟 DOM 中，DevTools 可能无法检测其内部状态 |
| **调试** | Chrome DevTools Elements 面板可以看到 Shadow DOM 边界，但 Vue DevTools 无法看到 WC 内部结构 |
