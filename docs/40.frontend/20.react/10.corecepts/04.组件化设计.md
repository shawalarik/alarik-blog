# 组件化设计

## 1. 组件的本质

React 应用由**组件（Component）**构成——组件是 UI 的独立、可复用的构建块，接收输入（props），输出描述 UI 的 React Element。

```js
// 最简组件
function Welcome(props) {
  return <h1>Hello, {props.name}</h1>;
}
```

### 组件的核心契约

```
Props (输入) → Component (纯函数) → ReactElement (输出)
```

| 要素 | 说明 |
|------|------|
| **输入** | `props` —— 不可变的（immutable）数据 |
| **输出** | `ReactElement`（或 `null`） |
| **副作用** | 应尽量少；副作用放在事件处理器 / useEffect 中 |
| **原则** | 单一职责、高内聚低耦合 |

## 2. 函数组件 vs 类组件

### 2.1 定义方式对比

```jsx
// ========== 函数组件（推荐）==========
function Greeting({ name }) {
  return <h1>Hello, {name}!</h1>;
}

// 箭头函数写法
const Greeting = ({ name }) => <h1>Hello, {name}!</h1>;

// ========== 类组件（遗留代码）==========
class Greeting extends React.Component {
  render() {
    return <h1>Hello, {this.props.name}!</h1>;
  }
}
```

### 2.2 全面对比

| 维度 | 函数组件 (Function) | 类组件 (Class) |
|------|-------------------|----------------|
| 定义 | 普通函数 / 箭头函数 | extends React.Component |
| 状态管理 | Hooks（useState 等） | this.state / setState |
| 生命周期 | useEffect/useLayoutEffect | componentDidMount 等 |
| This 绑定 | 无 this 问题 | 需要绑定或箭头函数 |
| 内部方法 | 普通函数即可 | 方法需 bind 或用箭头属性 |
| 代码体积 | Tree-shaking 友好 | 较大（prototype chain） |
| HOC 支持 | 直接包裹 | 需处理 static 方法 |
| 性能 | React 内部优化空间更大 | 无法优化实例化开销 |
| 推荐度 | ✅ **首选** | ⚠️ 仅维护旧代码 |

### 2.3 为什么推荐函数组件

```jsx
// 类组件的常见痛点
class Counter extends React.Component {
  constructor(props) {
    super(props);
    this.state = { count: 0 };
    // 痛点1: 手动 bind
    this.increment = this.increment.bind(this);
  }

  // 痛点2: 方法中的 this
  increment() {
    this.setState({ count: this.state.count + 1 });
  }

  // 痛点3: 生命周期分散
  componentDidMount() {
    document.title = `Count: ${this.state.count}`;
  }
  componentDidUpdate() {
    document.title = `Count: ${this.state.count}`;
  }

  render() {
    return (
      <button onClick={this.increment}>
        Count: {this.state.count}
      </button>
    );
  }
}

// 函数组件：清晰、简洁
function Counter() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    document.title = `Count: ${count}`;
  }, [count]);  // 关注点集中！

  return (
    <button onClick={() => setCount(c => c + 1)}>
      Count: {count}
    </button>
  );
}
```

## 3. Props — 单向数据流

### 3.1 Props 是只读的

```jsx
function Profile({ name, age }) {
  // ❌ 错误：不能修改 props
  name = "Modified";  // 可能报错（严格模式下）

  // ✅ 如果需要修改，应该提升状态到父组件
  return <div>{name}, {age} years old</div>;
}
```

**所有 React 组件都必须像纯函数一样对待 props。**

### 3.2 Props 解构与默认值

```tsx
interface ButtonProps {
  variant?: 'primary' | 'secondary';
  size?: 'sm' | 'md' | 'lg';
  disabled?: boolean;
  children: React.ReactNode;
  onClick?: () => void;
}

// 解构 + 默认值
function Button({
  variant = 'primary',
  size = 'md',
  disabled = false,
  children,
  onClick
}: ButtonProps) {
  return (
    <button
      className={`btn btn-${variant} btn-${size}`}
      disabled={disabled}
      onClick={onClick}
    >
      {children}
    </button>
  );
}
```

### 3.3 Props 传递模式

#### 父 → 子（最常用）

```jsx
function Parent() {
  const [user] = useState({ name: 'Alarik', role: 'admin' });
  
  return (
    <Card 
      title="User Info"
      userName={user.name}
      isAdmin={user.role === 'admin'}
    />
  );
}

function Card({ title, userName, isAdmin }) {
  return (
    <div>
      <h2>{title}</h2>
      <p>{userName} {isAdmin ? '(Admin)' : ''}</p>
    </div>
  );
}
```

#### 子 → 父（通过回调）

```jsx
function SearchBox({ onSearch }) {
  const [query, setQuery] = useState('');

  function handleSubmit(e) {
    e.preventDefault();
    onSearch(query);  // 子组件调用父组件传递的回调
  }

  return (
    <form onSubmit={handleSubmit}>
      <input value={query} onChange={e => setQuery(e.target.value)} />
      <button type="submit">Search</button>
    </form>
  );
}

// 使用
<SearchBox onSearch={(q) => console.log('搜索:', q)} />
```

#### 跨层级（Context / 组合）

```jsx
// 方案一：组合模式（children prop）—— 推荐
function Card({ header, footer, children }) {
  return (
    <div className="card">
      {header && <div className="card-header">{header}</div>}
      <div className="card-body">{children}</div>
      {footer && <div className="card-footer">{footer}</footer>}
    </div>
  );
}

// 使用
<Card
  header={<h3>Title</h3>}
  footer={<button>Action</button>}
>
  <p>This is the body content.</p>
</Card>

// 方案二：Render Props
<DataFetcher url="/api/users">
  {(data, loading) => loading ? <Spinner /> : <UserList users={data} />}
</DataFetcher>
```

### 3.4 Children 特殊 Prop

```jsx
function FancyBox({ label, children }) {
  return (
    <fieldset>
      <legend>{label}</legend>
      {children}
    </fieldset>
  );
}

// children 可以是任意内容
<FancyBox label="Settings">
  {/* 文本 */}
  Some content here
  
  {/* 多个元素 */}
  <p>Paragraph</p>
  <button>Button</button>
  
  {/* 甚至可以是函数 */}
  {(visible) => visible ? <span>Visible!</span> : null}
</FancyBox>
```

## 4. 组合 vs 继承

### 4.1 React 推崇组合，而非继承

```
继承（Inheritance）:
  BaseComponent
    ├── ChildA extends BaseComponent
    ├── ChildB extends BaseComponent
    └── ChildC extends BaseComponent
    → 耦合紧密，难以复用

组合（Composition）:
  Component = (props) => <UI />
    ├── A uses B's output as its input
    ├── C wraps D via children
    └── E delegates rendering to F via render prop
    → 松耦合，灵活组装
```

### 4.2 包含关系（Containment）

```jsx
// 通用容器：通过 children 组合任意内容
function Sidebar({ position = 'left', children }) {
  return (
    <aside className={`sidebar sidebar-${position}`}>
      {children}
    </aside>
  );
}

<Sidebar position="right">
  <NavLinks />       {/* 任何组件都可以放进来 */}
  <AdBanner />
  <UserProfile />
</Sidebar>
```

### 4.3 特殊实例（Specialization）

```jsx
// 通用对话框
function Dialog({ title, message, confirmText, cancelText, onConfirm, onCancel }) {
  return (
    <div className="dialog-overlay">
      <div className="dialog">
        <h3>{title}</h3>
        <p>{message}</p>
        <div className="actions">
          <button onClick={onCancel}>{cancelText || 'Cancel'}</button>
          <button onClick={onConfirm} className="primary">
            {confirmText || 'OK'}
          </button>
        </div>
      </div>
    </div>
  );
}

// 特殊化的确认删除对话框
function ConfirmDeleteDialog({ itemName, onDelete, onCancel }) {
  return (
    <Dialog
      title="Confirm Deletion"
      message={`Are you sure you want to delete "${itemName}"? This action cannot be undone.`}
      confirmText="Delete"
      cancelText="Cancel"
      onConfirm={onDelete}
      onCancel={onCancel}
    />
  );
}
```

## 5. 组件设计原则

### 5.1 单一职责原则（SRP）

每个组件只做一件事并做好它：

```jsx
// ❌ 反例：一个组件做了太多事情
function UserDashboard() {
  // 用户信息获取
  // 权限校验
  // 数据统计图表
  // 表格渲染
  // 分页逻辑
  // 导出功能
}

// ✅ 拆分为专注的小组件
function UserDashboard() {
  return (
    <Layout>
      <UserInfo />
      <StatsCharts />
      <DataTable />
      <Pagination />
      <ExportButton />
    </Layout>
  );
}
```

### 5.2 状态归属（Lifting State Up）

当多个组件需要共享同一个状态时，将该状态**提升到它们最近的共同祖先组件**：

```jsx
// ❌ 错误：各自维护独立的状态
function BoilingVerdict({ celsius }) {
  return <p>The water would {celsius >= 100 ? '' : 'not'} boil.</p>;
}

function Calculator() {
  const [celsius, setCelsius] = useState('');
  const [fahrenheit, setFahrenheit] = useState('');
  // 两个状态可能不一致！
}

// ✅ 正确：状态提升到父组件
function Calculator() {
  const [temperature, setTemperature] = useState('');
  const [scale, setScale] = useState('c');

  const celsius = scale === 'f' ? tryConvert(temperature, toCelsius) : temperature;
  const fahrenheit = scale === 'c' ? tryConvert(temperature, toFahrenheit) : temperature;

  return (
    <div>
      <TemperatureInput
        scale="c"
        temperature={celsius}
        onTemperatureChange={(t) => { setTemperature(t); setScale('c'); }}
      />
      <TemperatureInput
        scale="f"
        temperature={fahrenheit}
        onTemperatureChange={(t) => { setTemperature(t); setScale('f'); }}
      />
      <BoilingVerdict celsius={parseFloat(celsius)} />
    </div>
  );
}
```

### 5.3 受控 vs 非受控组件选择

| 场景 | 选择 | 原因 |
|------|------|------|
| 表单数据需要验证/转换 | **受控组件** | 完全控制输入值 |
| 需要即时反馈（如字符计数） | **受控组件** | state 驱动 UI |
| 与外部状态同步 | **受控组件** | 单一数据源 |
| 一次性表单提交 | **非受控组件** | ref 取值更简单 |
| 文件上传 | **非受控组件** | input 只读 |
| 第三方 UI 库集成 | 视情况而定 | 遵循库的设计约定 |

## 6. 组件通信全景图

```
                    ┌─────────────────┐
                    │   父组件 (Parent) │
                    │  拥有 state      │
                    └────────┬────────┘
                             │
           ┌─────────────────┼─────────────────┐
           ▼                 ▼                 ▼
    ┌──────────┐      ┌──────────┐      ┌──────────┐
    │ 子组件 A  │      │ 子组件 B  │      │ 子组件 C  │
    │ 接收props│◄─────│ 接收props│      │ 接收props│
    │ 回调传回 │──────►│ 回调传回 │      │ 回调传回 │
    └──────────┘      └──────────┘      └──────────┘
    
    跨层级通信方案:
    ┌─────────────────────────────────────────┐
    │  Context API (轻量级全局状态)             │
    │  状态管理库 (Redux/Zustand/Pinia)        │
    │  自定义事件总线 (极少数场景)              │
    └─────────────────────────────────────────┘
```

## 7. 高阶组件（HOC）— 了解即可

HOC 是一个函数，接收组件并返回新组件：

```jsx
// Hoc 模式（遗留但仍有参考价值）
function withLoading(WrappedComponent) {
  return function WithLoadingComponent({ isLoading, ...props }) {
    if (isLoading) return <Spinner />;
    return <WrappedComponent {...props} />;
  };
}

// 使用
const UserProfileWithLoading = withLoading(UserProfile);
<UserProfileWithLoading isLoading={loading} user={userData} />
```

> 在 Hooks 时代，大多数 HOC 场景已被自定义 Hook 替代。HOC 主要用于第三方库内部实现（如 React Router 的 `withRouter`、Redux 的 `connect`）。
