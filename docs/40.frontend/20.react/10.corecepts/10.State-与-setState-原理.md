# State 与 setState 原理

## 1. State 是什么

State 是组件内部的**私有可变数据**，类似于组件的"记忆"。与 props 不同：

| 特性 | State | Props |
|------|-------|-------|
| 所有权 | 组件内部私有 | 由父组件传入 |
| 可变性 | 可变（通过 setState） | 只读（不可变） |
| 作用范围 | 当前组件 | 从父组件传入 |
| 更新方式 | `setState` / `useState` setter | 父组件重新传入 |

## 2. 类组件中的 setState

### 2.1 基本用法

```jsx
class Counter extends React.Component {
  constructor(props) {
    super(props);
    this.state = {
      count: 0,
      name: 'Alarik',
      items: []
    };
  }

  increment = () => {
    this.setState({ count: this.state.count + 1 });
  };

  render() {
    return (
      <div>
        <p>Count: {this.state.count}</p>
        <button onClick={this.increment}>+</button>
      </div>
    );
  }
}
```

### 2.2 setState 是异步的

```jsx
class AsyncExample extends React.Component {
  state = { count: 0 };

  handleClick = () => {
    this.setState({ count: this.state.count + 1 });
    
    // ⚠️ 此时 this.state.count 可能还是旧值！
    console.log(this.state.count);  // 可能打印 0 而不是 1
    
    // 如果需要在 state 更新后执行操作，使用回调
    this.setState({ count: this.state.count + 1 }, () => {
      console.log(this.state.count);  // 此时保证是新值
    });
  };
}
```

### 2.3 setState 的合并机制（浅合并）

```jsx
class MergeExample extends React.Component {
  state = {
    name: 'Alarik',
    age: 25,
    address: { city: 'Beijing' }
  };

  update = () => {
    // ✅ 浅合并：只会合并顶层属性
    this.setState({ name: 'NewName' });
    // 结果: { name: 'NewName', age: 25, address: { city: 'Beijing' } }

    // ❌ 不会深度合并！
    this.setState({ address: { city: 'Shanghai' } });
    // 结果: address 整体被替换，不是合并 city 字段
    
    // ✅ 正确的深层更新方式
    this.setState(prev => ({
      address: { ...prev.address, city: 'Shanghai' }
    }));
  };
}
```

**合并规则总结**：

```js
// setState 做的是 Object.assign({}, prevState, partialState)
// 即浅合并（shallow merge），只合并没有 undefined 的顶层键
```

### 2.4 批量更新（Batching）

React 会将多次 setState 调用**批量为一次更新**：

```jsx
class BatchingExample extends React.Component {
  state = { count: 0 };

  handleBatch = () => {
    // React 18+：无论在哪里都会批量处理
    this.setState({ count: this.state.count + 1 });  // count: 0 → ?
    this.setState({ count: this.state.count + 1 });  // count: ? → ?
    this.setState({ count: this.state.count + 1 });  // count: ? → final
    
    // 最终结果取决于读取方式！
  };
}
```

**关键陷阱**：上面三次 `this.state.count` 都读到的是**同一个初始值**（因为异步批量），所以最终 `count` 只增加了 **1**，而不是 3。

**正确做法 —— 函数式更新**：

```jsx
handleCorrect = () => {
  // ✅ 使用函数式 setState，确保基于最新状态计算
  this.setState(prev => ({ count: prev.count + 1 }));  // 0 → 1
  this.setState(prev => ({ count: prev.count + 1 }));  // 1 → 2
  this.setState(prev => ({ count: prev.count + 1 }));  // 2 → 3
  // 最终: count = 3 ✓
};

// 函数式签名：
// setState((prevState, props) => newState, [callback])
```

### 2.5 React 18 的 Automatic Batching

| 版本 | 批量更新范围 |
|------|------------|
| React 16/17 | 仅在**事件处理函数**和**生命周期**中批量 |
| React 18+ | **所有地方**都自动批量（包括 Promise、setTimeout、原生事件） |

```jsx
// React 18+: 以下全部自动批量处理
function handleClick() {
  setCount(c => c + 1);   // 批量
  setFlag(f => !f);       // 批量
}

function asyncUpdate() {
  fetch('/api').then(() => {
    setCount(c => c + 1); // React 18: 也批量！
    setFlag(f => !f);     // React 17: 不批量，各触发一次重渲染
  });
}

// 如果确实需要退出批量更新（极少情况）
import { flushSync } from 'react-dom';

flushSync(() => {
  setCount(c => c + 1);  // 立即触发重渲染
});
setFlag(f => !f);        // 再次触发重渲染
```

## 3. 函数组件中的 useState

### 3.1 基本用法

```jsx
function Counter() {
  // useState 返回 [当前值, 设置函数]
  const [count, setCount] = useState(0);       // 数字
  const [name, setName] = useState('Alarik');  // 字符串
  const [items, setItems] = useState([]);      // 数组
  const [user, setUser] = useState(null);      // 对象/null
  
  return (
    <div>
      <p>{name}: {count}</p>
      <button onClick={() => setCount(count + 1)}>+</button>
    </div>
  );
}
```

### 3.2 惰性初始值

对于初始值计算昂贵的场景，传入函数避免每次渲染都重新计算：

```jsx
// ❌ 每次渲染都会执行 computeExpensiveValue()
const [data, setData] = useState(computeExpensiveValue(initialProp));

// ✅ 只在首次渲染时执行一次
const [data, setData] = useState(() => computeExpensiveValue(initialProp));

// 典型案例：从 localStorage 读取
const [theme, setTheme] = useState(() => {
  const saved = localStorage.getItem('theme');
  return saved ?? 'light';  // nullish coalescing
});

// 典型案例：复杂对象的初始化
const [matrix, setMatrix] = useState(() => {
  const m = Array(100).fill(null).map(() => Array(100).fill(0));
  return m;
});
```

### 3.3 函数式更新（解决闭包陷阱）

```jsx
function DelayedCounter() {
  const [count, setCount] = useState(0);

  function alertLater() {
    setTimeout(() => {
      // ⚠️ 闭包陷阱：这里的 count 是定时器创建时的快照
      alert(`Current count: ${count}`);  // 可能是过期值！
      
      // ✅ 使用函数式更新
      setCount(prevCount => prevCount + 1);  // 总是基于最新值
    }, 3000);
  }

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>+</button>
      <button onClick={alertLater}>Alert Later</button>
    </div>
  );
}
```

### 3.4 状态不可变性（Immutability）

**永远不要直接修改 State**：

```jsx
// ❌ 错误：直接修改（Mutation）
const [items, setItems] = useState([1, 2, 3]);
items.push(4);           // 直接修改原数组
items[0] = 99;           // 直接修改
setItems(items);         // React 检测不到变化（同一引用）

// ✅ 正确：创建新对象（Immutable update）
setItems([...items, 4]);                              // 追加
setItems(items.filter(i => i !== 2));                  // 删除
setItems(items.map(i => i === 1 ? 99 : i));            // 修改
setItems(items.sort((a,b) => b-a));                    // 排序也要新建

// 对象同理
const [user, setUser] = useState({ name: 'A', age: 25 });
setUser({ ...user, name: 'B' });                       // 更新属性
setUser(prev => ({ ...prev, name: newName }));         // 函数式
```

### 3.5 状态拆分与合并策略

```jsx
// ✅ 推荐：相关状态分组为一个 state
const [position, setPosition] = useState({ x: 0, y: 0 });

// ✅ 推荐：无关状态分开管理
const [isLoading, setIsLoading] = useState(true);
const [error, setError] = useState(null);
const [data, setData] = useState([]);

// ❌ 不推荐：把所有状态塞进一个巨大对象
const [all, setAll] = useState({
  isLoading: true,
  error: null,
  data: [],
  page: 1,
  filters: {},
  sort: 'desc',
  // ... 太多字段，每次更新都要 spread
});
```

**决策指南**：

| 场景 | 建议 |
|------|------|
| 状态经常一起变化 | 合并为一个对象/数组 |
| 状态彼此独立 | 分开为多个 useState |
| 状态更新逻辑复杂 | 考虑 useReducer |
| 状态被多处使用 | 提升（lift up）或使用 Context |

## 4. useState 内部原理（简化模型）

```
┌─────────────────────────────────────────────────────┐
│               useState 工作机制                      │
│                                                     │
│  function useState(initialState) {                  │
│    1. 获取当前 fiber（正在渲染的组件）                │
│    2. 检查是否是首次渲染                             │
│       - 首次：存储 initialState 到 hooks 链表中     │
│       - 后续：从链表中取出上次的 state               │
│    3. 返回 [currentState, dispatchSetter]          │
│                                                     │
│    dispatchSetter(action) {                         │
│      将更新加入该 hook 的更新队列                     │
│      标记组件为需要 re-render                        │
│      （React 18: 自动 batch，调度更新）              │
│    }                                                │
│  }                                                  │
└─────────────────────────────────────────────────────┘
```

**为什么 Hooks 必须在顶层调用？**

React 依赖**调用顺序一致性**来正确关联 state：

```jsx
function Form() {
  // 第一次渲染：hooks 按顺序注册
  const [name, setName] = useState('');     // hook #0
  const [email, setEmail] = useState('');   // hook #1
  const [age, setAge] = useState(0);        // hook #2

  // 第二次渲染：必须保持相同顺序！
  // React 通过顺序匹配来找到对应的 state
}
```

如果在条件语句中使用 Hooks，顺序就会被打乱，导致状态错乱。

## 5. 常见陷阱与解决方案

### 5.1 闭包陈旧值（Stale Closure）

```jsx
// 问题：effect 中的 state 是旧的
function Timer() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      // 这里的 count 永远是 effect 创建时的值！
      setCount(count + 1);  // 永远是 0 + 1 = 1
    }, 1000);
    return () => clearInterval(id);
  }, []);  // 空依赖意味着只在 mount 时创建一次

  // ✅ 解决方案1：函数式更新
  useEffect(() => {
    const id = setInterval(() => {
      setCount(c => c + 1);  // 总是取最新值
    }, 1000);
    return () => clearInterval(id);
  }, []);

  // ✅ 解决方案2：将变化的值放入依赖数组
  useEffect(() => {
    const id = setInterval(() => {
      setCount(count + 1);
    }, 1000);
    return () => clearInterval(id);
  }, [count]);  // 每次 count 变化重建 interval
}
```

### 5.2 状态更新但不重渲染

```jsx
// 问题：直接修改嵌套对象
const [user, setUser] = useState({ profile: { name: 'A' } });
user.profile.name = 'B';  // 直接修改
setUser(user);             // 同一引用，React 跳过更新

// ✅ 解决：深拷贝或使用 Immer
setUser({
  ...user,
  profile: { ...user.profile, name: 'B' }
});
// 或者使用 immer produce
import { produce } from 'immer';
setUser(draft => { draft.profile.name = 'B'; });
```

## 6. 总结

```
┌──────────────────────────────────────────────────┐
│           State 核心要点                           │
├──────────────────────────────────────────────────┤
│ setState 是异步的（React 18 全自动批量更新）       │
│ setState 做浅合并（Object.assign 语义）            │
│ 用函数式 setState(prev => ...) 避免读取过期值      │
│ 永远不要直接修改 State（不可变性原则）              │
│ useState 惰性初始化用函数形式                      │
│ 相关状态分组，无关状态分离                          │
│ Hooks 必须在组件顶层调用                           │
│ 闭包陷阱用函数式更新或依赖数组解决                  │
└──────────────────────────────────────────────────┘
```
