# React 事件系统

## 1. 概述

React 实现了一套**合成事件系统（SyntheticEvent）**，统一了不同浏览器间的事件差异。开发者编写的 `onClick`、`onChange` 等事件处理器并非直接绑定到 DOM 元素上，而是经过 React 事件系统的代理和分发。

## 2. 合成事件（SyntheticEvent）

### 2.1 基本用法

```jsx
function Button() {
  const handleClick = (event) => {
    // event 是 SyntheticEvent，不是原生 Event
    event.preventDefault();   // 阻止默认行为
    event.stopPropagation();  // 阻止冒泡
    console.log(event.type);  // 'click'
    console.log(event.target);      // 触发事件的 DOM 元素
    console.log(event.currentTarget); // 绑定事件的 DOM 元素
  };

  return <button onClick={handleClick}>Click me</button>;
}
```

### 2.2 SyntheticEvent 与原生 Event 的对比

| 特性 | SyntheticEvent | 原生 DOM Event |
|------|---------------|----------------|
| 跨浏览器兼容 | ✅ 统一接口 | ❌ 各浏览器差异大 |
| 事件委托 | ✅ 自动根节点委托 | 需手动管理 |
| 事件池（v17 前） | ✅ 复用对象 | 每次新建 |
| `stopPropagation` | ✅ | ✅ |
| `preventDefault` | ✅ | ✅ |
| `nativeEvent` 属性 | ✅ 可访问原生事件 | N/A |

## 3. 事件委托机制

### 3.1 React 16 及之前的委托方式

```
┌─────────────────────────────────────────────┐
│  React 16: 所有事件委托给 document           │
│                                             │
│  <div id="root">                            │
│    <button onClick={fn}>                    │  ← 不直接绑定
│    <input onChange={fn}>                    │  ← 不直接绑定
│                                             │
│  document                                   │  ← 所有事件冒泡到这里
│    ↓ addEventListener('click', handler)     │
│    ↓ addEventListener('change', handler)    │
└─────────────────────────────────────────────┘
```

**工作流程**：

```
用户点击 <button>
  → 原生 click 事件冒泡到 document
  → React 的 document 级别监听器捕获
  → 根据 target 查找对应组件的 handler
  → 构建 SyntheticEvent
  → 调用用户的事件处理函数
```

### 3.2 React 17 及之后的委托方式

React 17 将事件委托从 `document` 改到了**挂载容器的根节点**：

```
┌─────────────────────────────────────────────┐
│  React 17+: 事件委托给 root 容器             │
│                                             │
│  document                                   │
│  <div id="root">  ← 事件委托在这里          │
│    ↓ addEventListener('click', handler)     │
│    <button onClick={fn}>                    │
│    <input onChange={fn}>                    │
└─────────────────────────────────────────────┘
```

**为什么要改变？**

| 问题 | React 16 (document) | React 17 (root) |
|------|--------------------|-----------------|
| 多个 React 应用共存 | 冲突（抢 document） | 各自隔离 |
| 与其他框架混用 | 可能干扰 | 互不影响 |
| 微前端架构 | 困难 | 天然支持 |

## 4. 事件池（Event Pooling）

### 4.1 React 16 的事件池行为

```jsx
function handleClick(e) {
  console.log(e.type);        // ✅ 同步访问 OK
  
  setTimeout(() => {
    console.log(e.type);      // ⚠️ 已被清空！所有属性变为 null
  }, 1000);
  
  // 如果需要异步访问，先保存值：
  const eventType = e.type;   // ✅
}
```

### 4.2 React 17 移除了事件池

```jsx
// React 17+：不需要担心事件池问题
function handleClick(e) {
  console.log(e.type);        // ✅ 同步访问 OK
  
  setTimeout(() => {
    console.log(e.type);      // ✅ 异步访问也 OK！
  }, 5000);
}
```

| 版本 | 事件池 | `persist()` |
|------|--------|------------|
| React ≤16 | 合成事件复用，回调后清空 | 防止回收 |
| React ≥17 | **不再使用事件池** | 空操作 (no-op) |

## 5. 支持的事件类型

```jsx
// === 剪贴板 ===
onCopy onCut onPaste

// === 键盘 ===
onKeyDown onKeyPress onKeyUp
// event.key, event.code, event.ctrlKey, event.metaKey

// === 焦点 ===
onFocus onBlur
// 注意：React 的 focus 事件使用冒泡（原生不冒泡）

// === 表单 ===
onChange onInput onInvalid onSubmit onReset

// === 鼠标 ===
onClick onContextMenu onDoubleClick
onDrag* onMouseDown onMouseEnter onMouseLeave onMouseMove onMouseUp

// === 指针 ===
onPointerDown/Move/Up/Enter/Leave/Over/Out

// === 触摸 ===
onTouchCancel onTouchEnd onTouchMove onTouchStart

// === UI ===
onScroll onLoad onError onAbort

// === 滚轮 ===
onWheel

// === 动画/过渡 ===
onAnimationStart/End/Iteration
onTransitionEnd/Run/Start/Cancel
```

## 6. 事件命名规范

```jsx
// camelCase（小驼峰），处理器是函数引用
<button onClick={handleClick}>OK</button>       // ✅
<input onChange={handleChange} />               // ✅
<div onMouseEnter={handleHover} />              // ✅
<button onclick="handleClick()">OK</button>     // ❌ 字符串无效
```

## 7. 事件处理器中的 this 绑定（类组件）

```jsx
class MyButton extends React.Component {
  // 方案1：构造器中 bind
  constructor(props) {
    super(props);
    this.handleClick = this.handleClick.bind(this);
  }

  // 方案2：类属性 + 箭头函数（推荐）
  handleClick2 = () => {
    console.log(this);  // ✅ 正确指向组件实例
  };

  render() {
    return (
      <div>
        <button onClick={this.handleClick1}>Bind</button>
        <button onClick={this.handleClick2}>Arrow</button>
        {/* 方案3：render 中箭头 —— 每次渲染创建新函数 */}
        <button onClick={() => this.handleClick()}>Inline Arrow</button>
      </div>
    );
  }
}
```

> **函数组件无此问题**：天然简洁，无需处理 this。

## 8. 向事件处理器传参

```jsx
function ItemList({ items, onRemove }) {
  return (
    <ul>
      {items.map(item => (
        <li key={item.id}>
          {item.name}
          {/* 方案1：箭头函数 */}
          <button onClick={() => onRemove(item.id)}>Remove</button>
          {/* 方案2：.bind */}
          <button onClick={onRemove.bind(null, item.id)}>Remove</button>
        </li>
      ))}
    </ul>
  );
}
```

| 方案 | 优点 | 缺点 |
|------|------|------|
| `() => fn(arg)` | 语义清晰，可传多参 | 每次渲染创建新函数 |
| `fn.bind(null, arg)` | 不创建新函数 | `this` 为 null，不够直观 |

> 大多数场景箭头函数的性能影响可以忽略。仅在高性能列表（数千项）时需考虑优化。

## 9. 合成事件与原生事件混用

```jsx
class MixedEvents extends React.Component {
  componentDidMount() {
    this.el.addEventListener('click', this.handleNativeClick);
  }
  componentWillUnmount() {
    this.el.removeEventListener('click', this.handleNativeClick);
  }
  
  handleNativeClick = (e) => { /* ... */ };
  handleReactClick = (e) => { /* ... */ };

  render() {
    return (
      <div ref={el => this.el = el} onClick={this.handleReactClick}>
        Click me
      </div>
    );
  }
}
```

**执行顺序（React 17 冒泡阶段）**：

```
1. 原生 DOM listener 触发
2. React onClick 处理器触发
3. 原生事件继续冒泡
4. React 合成事件继续冒泡

⚠️ stopPropagation():
  - 原生 e.stopPropagation(): 同时阻止两者
  - 合成 e.stopPropagation(): 只阻止合成事件
  - 需完全阻止时两者都调用
```

## 10. 总结

```
┌──────────────────────────────────────────────────┐
│           React 事件系统要点                       │
├──────────────────────────────────────────────────┤
│ 事件名: camelCase (onClick, onChange)             │
│ 处理器: 函数引用，不是字符串                       │
│ 合成事件: 跨浏览器统一的 SyntheticEvent            │
│ 事件委托: v16→document, v17→root容器             │
│ 事件池: v16存在(v17移除)，注意异步访问             │
│ this 绑定: 函数组件无此问题                        │
│ 传参: 箭头函数或 .bind                             │
│ 混用: 注意 stopPropagation 差异                   │
└──────────────────────────────────────────────────┘
```
