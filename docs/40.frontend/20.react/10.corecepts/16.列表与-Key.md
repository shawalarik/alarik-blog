# 列表渲染与 Key

## 1. 列表渲染基础

在 React 中使用 JavaScript 的 `map()` 方法来渲染列表：

```jsx
function NumberList({ numbers }) {
  return (
    <ul>
      {numbers.map((number) => (
        <li key={number.toString()}>{number}</li>
      ))}
    </ul>
  );
}

<NumberList numbers={[1, 2, 3, 4, 5]} />;
```

### 渲染多组件列表

```jsx
function ListItem({ value }) {
  return <li>{value}</li>;
}

function List({ items }) {
  return (
    <ul>
      {items.map((item) => (
        <ListItem key={item.id} value={item.value} />
      ))}
    </ul>
  );
}
```

> **规则**：`key` 放在 map 内最外层的 JSX 元素上，而不是子组件内部。

## 2. Key 的作用

Key 是 React 用于识别哪些元素**改变了、添加了或删除了**的特殊字符串属性。

### 没有 Key 会怎样？

```jsx
// ⚠️ 没有 key（或用 index 作为 key 且列表会变化）
{items.map(item => <Item name={item.name} />)}
// React 的警告：Each child in a list should have a unique "key" prop.
```

**没有 Key 时，React 的 Diffing 行为**：

```
旧列表: [A, B, C]           新列表: [D, A, B, C]
         ↓                              ↓
  [A→A, B→B, C→C]  (按位置复用)    [A→D, B→A, C→B, ?→C]
  
结果: 所有组件都被"错误复用"，导致不必要的更新和状态错乱
```

### 有正确 Key 时

```
旧列表: [A(id=1), B(id=2), C(id=3)]
新列表: [D(id=4), A(id=1), B(id=2), C(id=3)]

React 通过 key 匹配：
  id=1(A): 位置变化但组件保留 ✓
  id=2(B): 位置变化但组件保留 ✓
  id=3(C): 位置变化但组件保留 ✓
  id=4(D): 新增组件 ✓

结果: 最小化 DOM 操作，状态正确保持
```

## 3. Key 的选择策略

### 3.1 最佳选择：稳定的唯一 ID

```jsx
// ✅ 最佳：数据自带唯一标识
{users.map(user => (
  <li key={user.id}>{user.name}</li>
))}

// ✅ 后端生成的 ID
{posts.map(post => (
  <Article key={post._id} {...post} />
))}
```

### 3.2 可接受的选择：组合唯一值

```jsx
// 当没有唯一 ID 时，组合多个字段
{items.map(item => (
  <li key={`${item.category}-${item.name}`}>
    {item.name}
  </li>
))}
```

### 3.3 应避免的选择：数组索引

```jsx
// ⚠️ 可以工作但有隐患
{items.map((item, index) => (
  <li key={index}>{item.name}</li>
))}

// 何时可以用 index？
// 1. 列表是静态的（不会重新排序）
// 2. 列表没有过滤/排序功能
// 3. 列表不会在头部/中间插入/删除项目
```

**为什么 index 作为 key 有问题？**

```jsx
function TodoList({ todos }) {
  return (
    <ul>
      {todos.map((todo, index) => (
        <TodoItem 
          key={index}  // ⚠️ 用 index 作 key
          text={todo.text} 
          completed={todo.completed}
        />
      ))}
    </ul>
  );
}

// 场景：在列表头部插入新项目
// 初始: ['Buy milk', 'Read book']  →  keys: [0, 1]
// 插入后: ['New task', 'Buy milk', 'Read book'] → keys: [0, 1, 2]

// React 的 diff 结果（基于 index）：
//   key=0: 'Buy milk' → 'New task'     (认为内容变了 → 更新)
//   key=1: 'Read book' → 'Buy milk'   (认为内容变了 → 更新)
//   key=2: (新增) → 'Read book'        (新增)

// 实际期望：
//   'New task' 应该是新增
//   'Buy milk' 和 'Read book' 应该保持原样

// 后果：
// 1. 不必要的 DOM 更新（影响性能）
// 2. 如果 TodoItem 有内部状态（如输入框焦点、滚动位置），会被错乱
```

## 4. Key 与组件状态的关系

```jsx
function TextInput({ label }) {
  const [value, setValue] = useState('');
  return (
    <div>
      <label>{label}</label>
      <input value={value} onChange={e => setValue(e.target.value)} />
    </div>
  );
}

// 使用
const items = [
  { id: 'a', label: 'Name' },
  { id: 'b', label: 'Email' },
  { id: 'c', label: 'Phone' }
];

// 正确的 key → 状态与正确的 label 关联
{items.map(item => <TextInput key={item.id} label={item.label} />)}

// 错误的 key(index) → 用户在 Name 输入的内容可能跑到 Email 上去
{items.map((item, idx) => <TextInput key={idx} label={item.label} />)}

// 在 items 排序/插入/删除时尤其明显！
```

## 5. Key 必须在同层级兄弟间唯一

```jsx
// ✅ Key 只需要在同一父元素的直接子元素之间唯一
function BlogPosts({ posts }) {
  return (
    <div>
      {posts.map(post => (
        // 这些 key 在兄弟之间唯一即可
        <article key={post.id}>
          <h2>{post.title}</h2>
          
          {/* 不同层级的 key 可以重复 */}
          {post.comments.map(comment => (
            <Comment key={comment.id} {...comment} />
          ))}
          
          {post.tags.map(tag => (
            <span key={tag}>{tag}</span>
          ))}
        </article>
      ))}
    </div>
  );
}

// ⚠️ 但不要用随机数或时间戳作为 key
{items.map(item => <Item key={Math.random()} />)}  // 每次渲染都不同 → 全部重建
{items.map(item => <Item key={Date.now()} />)}     // 同上
```

## 6. Key 强制重置组件

利用 **key 变化会导致组件卸载再重挂载**的特性，可以强制重置组件状态：

```jsx
// 场景1：重置表单
function UserEditor({ userId }) {
  return <UserForm key={userId} userId={userId} />;
  // 当 userId 变化时，整个 UserForm 卸载并重新挂载
  // 所有内部状态（表单字段、验证状态等）全部清空
}

// 场景2：切换时重置状态
function TabContent({ activeTab }) {
  const tabs = [
    { id: 'profile', component: ProfileForm },
    { id: 'settings', component: SettingsForm }
  ];
  
  const CurrentComponent = tabs.find(t => t.id === activeTab)?.component;
  
  // key={activeTab} → 切换 tab 时组件重新挂载
  return <CurrentComponent key={activeTab} />;
}

// 场景3：动画过渡时的强制重绘
{show && <Modal key="modal-open" />}
{!show && <div key="modal-closed" />}
// 两个不同的 key 让 React 执行卸载+挂载而非就地更新，
// 可配合 CSS transition 实现进入/退出动画
```

## 7. 列表渲染常见模式

### 7.1 条件渲染 + 列表

```jsx
function FilteredList({ items, filter }) {
  const filteredItems = items.filter(item =>
    item.name.toLowerCase().includes(filter.toLowerCase())
  );

  if (filteredItems.length === 0) {
    return <EmptyState message="No results found" />;
  }

  return (
    <ul>
      {filteredItems.map(item => (
        <ListItem key={item.id} item={item} />
      ))}
    </ul>
  );
}
```

### 7.2 分组列表

```jsx
function GroupedContacts({ contacts }) {
  const grouped = contacts.reduce((acc, contact) => {
    const firstLetter = contact.name[0].toUpperCase();
    (acc[firstLetter] ||= []).push(contact);
    return acc;
  }, {});

  return (
    <div>
      {Object.entries(grouped).sort().map(([letter, group]) => (
        <div key={letter}>
          <h3>{letter}</h3>
          <ul>
            {group.map(contact => (
              <ContactCard key={contact.id} contact={contact} />
            ))}
          </ul>
        </div>
      ))}
    </div>
  );
}
```

### 7.3 虚拟长列表（Virtual List）

当渲染数千行时，只渲染可视区域内的项目：

```jsx
import { FixedSizeList as List } from 'react-window';

function VirtualizedList({ items }) {
  const Row = ({ index, style }) => (
    <div style={style}>
      <Item data={items[index]} />
    </div>
  );

  return (
    <List
      height={400}           // 可视区域高度
      itemCount={items.length}
      itemSize={50}          // 每行高度
      width="100%"
    >
      {Row}
    </List>
  );
}

// 替代库：@tanstack/virtual, react-virtuoso
```

## 8. 总结

```
┌──────────────────────────────────────────────────┐
│           Key 要点速查                             │
├──────────────────────────────────────────────────┤
│ 目的: 帮助 React 识别元素身份，最小化 DOM 操作      │
│ 最佳: 数据的唯一 ID (id, _id, uuid 等)            │
│ 避免: Math.random(), Date.now() (每次都变)        │
│ 谨慎: 数组 index (仅在静态列表中使用)              │
│ 范围: 只需在同层级兄弟之间唯一                     │
│ 技巧: key 变化可强制重置组件状态                    │
│ 性能: 正确的 key 能显著减少不必要的重渲染          │
└──────────────────────────────────────────────────┘
```
