# useState 深入解析

## 1. 基础回顾

```jsx
const [state, setState] = useState(initialValue);
//       ↑          ↑              ↑
//    当前值    设置新值的函数     初始值
```

`useState` 是最基础的 State Hook，返回一个状态值和更新该状态的函数。

## 2. 惰性初始化

当初始值计算开销较大时，传入**函数**形式，避免每次重复计算：

```jsx
// ❌ 每次 render 都会执行 computeExpensive()
const [data, setData] = useState(computeExpensive(props.input));

// ✅ 仅首次 render 时执行一次
const [data, setData] = useState(() => computeExpensive(props.input));
```

**适用场景**：

| 场景 | 示例 |
|------|------|
| 复杂对象初始化 | `useState(() => new ComplexClass(options))` |
| 从 localStorage 读取 | `useState(() => JSON.parse(localStorage.getItem('key')))` |
| 大数组生成 | `useState(() => Array(n).fill(0).map((_, i) => compute(i)))` |
| 依赖 props 计算 | `useState(() => deriveFromProps(props))` |

## 3. 函数式更新 —— 最重要也最容易被忽视的特性

### 3.1 问题：闭包陈旧值（Stale Closure）

```jsx
function Counter() {
  const [count, setCount] = useState(0);

  function handleAlertClick() {
    setTimeout(() => {
      alert(`You clicked ${count} times`);
      // ⚠️ 这里的 count 是点击按钮时的快照值！
      // 如果之后又点了几次增加按钮，alert 显示的还是旧值
    }, 3000);
  }

  return (
    <>
      <p>You clicked {count} times</p>
      <button onClick={() => setCount(count + 1)}>Click me</button>
      <button onClick={handleAlertClick}>Show alert (after 3s)</button>
    </>
  );
}
```

**时间线演示**：

```
T=0s:   点击 "Show alert"
  → setTimeout 注册，捕获 count=0

T=1s:   点击 "Click me" 5次
  → count 变为 5

T=3s:   setTimeout 触发
  → alert("You clicked 0 times")  ← 陈旧的闭包值！
```

### 3.2 解决方案：函数式更新

```jsx
function Counter() {
  const [count, setCount] = useState(0);

  function handleAlertClick() {
    setTimeout(() => {
      // ✅ 用函数式更新：React 保证传入的是最新 state
      setCount(latestCount => {
        alert(`You clicked ${latestCount} times`);
        return latestCount;  // 返回当前最新值
      });
    }, 3000);
  }

  return (
    <>
      <p>You clicked {count} times</p>
      <button onClick={() => setCount(c => c + 1)}>Click me</button>
      <button onClick={handleAlertClick}>Show alert</button>
    </>
  );
}
```

### 3.3 函数式更新签名

```ts
setState((prevState) => newState);
// prevState: 由 React 保证的最新状态值
// 返回值: 新的状态值
```

**何时必须使用函数式更新？**

| 场景 | 是否需要 |
|------|---------|
| 新状态依赖于旧状态 | **✅ 必须用** |
| 在异步操作中更新（setTimeout/fetch/Promise） | **✅ 推荐使用** |
| 多次快速连续更新同一 state | **✅ 必须用** |
| 新状态与旧状态无关 | ❌ 可直接传值 |

### 3.4 批量更新中的函数式更新

```jsx
// 场景：基于旧值多次更新
function BatchUpdates() {
  const [count, setCount] = useState(0);

  function updateThreeTimes() {
    // ❌ 直接传值：三次都读到同一个初始 count（因为批量处理）
    setCount(count + 1);  // 0 + 1 = 1
    setCount(count + 1);  // 还是 0 + 1 = 1（state 还没变）
    setCount(count + 1);  // 同上
    // 最终结果：count = 1（而不是 3）

    // ✅ 函数式更新：每次都拿到上次的更新结果
    setCount(c => c + 1);  // 0 → 1
    setCount(c => c + 1);  // 1 → 2
    setCount(c => c + 1);  // 2 → 3
    // 最终结果：count = 3 ✓
  }

  return <button onClick={updateThreeTimes}>+3</button>;
}
```

> **核心原理**：React 的批量处理会将多次 `setState` 调用合并。直接传值时所有调用读到的是同一个闭包中的旧值；函数式更新则由 React 内部依次将前一次的结果作为参数传入下一次。

## 4. 状态拆分与合并策略

### 4.1 什么时候该拆分？什么时候该合并？

```jsx
// ✅ 合理拆分：独立变化的状态
const [isLoading, setIsLoading] = useState(true);
const [data, setData] = useState(null);
const [error, setError] = useState(null);
// 这三个通常不会同时变化

// ✅ 相关字段保持在一起
const [position, setPosition] = useState({ x: 0, y: 0 });
// x 和 y 总是同时表示一个坐标

// ❌ 过度拆分：频繁同时变化的字段
const [firstName, setFirstName] = useState('');
const [lastName, setLastName] = useState('');
const [email, setEmail] = useState('');
const [phone, setPhone] = useState('');
// → 应该用一个 formState 对象或 useReducer

// ❌ 过度聚合：无关字段塞进一个大对象
const [allState, setAllState] = useState({
  theme: 'dark',
  user: { name: '', email: '' },
  isLoading: false,
  modalOpen: false,
  notifications: [],
});
// → 任何字段变化都导致整个 object 重建，可能触发不必要的子组件重渲染
```

### 4.2 决策指南

```
这些状态是否总是同时变化？
  ├── 是 → 考虑合并为一个对象或使用 useReducer
  └── 否 → 保持为独立的 useState

这个状态的更新是否影响其他状态？
  ├── 是 → 考虑合并或使用 useReducer
  └── 否 → 保持独立

状态结构是否会随时间动态变化？
  ├── 是（字段增减）→ 考虑 useReducer 或分开管理多个 useState
  └── 否（固定结构）→ useState 对象即可
```

## 5. 不可变性原则（Immutability）

### 5.1 为什么需要不可变性？

```jsx
// React 用 Object.is 比较 state 来决定是否需要重渲染
const [items, setItems] = useState([1, 2, 3]);

// ❌ 直接修改原数组/对象
items.push(4);
setItems(items);  // 引用相同 → Object.is(old, new) === true → React 认为没变 → 跳过渲染！

// ✅ 创建新的引用
setItems([...items, 4]);  // 新引用 → React 检测到变化 → 触发重渲染 ✓
```

### 5.2 常见不可变操作速查表

**数组操作**：

```jsx
const [arr, setArr] = useState([1, 2, 3]);

// 追加（尾部）
setArr(prev => [...prev, newItem]);

// 插入（头部/指定位置）
setArr(prev => [newItem, ...prev]);
setArr(prev => [...prev.slice(0, index), newItem, ...prev.slice(index)]);

// 删除（按索引/按条件）
setArr(prev => prev.filter((_, i) => i !== index));
setArr(prev => prev.filter(item => item.id !== targetId));

// 修改某一项
setArr(prev => prev.map(item =>
  item.id === targetId ? { ...item, updated: true } : item
));

// 排序（注意：sort 会修改原数组！）
setArr(prev => [...prev].sort((a, b) => a.value - b.value));
```

**对象操作**：

```jsx
const [obj, setObj] = useState({ a: 1, b: 2, nested: { c: 3 } });

// 修改顶层属性
setObj(prev => ({ ...prev, a: 100 }));

// 添加属性
setObj(prev => ({ ...prev, newProp: 'value' }));

// 删除属性
setObj(prev => { const { removed, ...rest } = prev; return rest; });

// 深层嵌套修改
setObj(prev => ({
  ...prev,
  nested: { ...prev.nested, c: 999 }
}));
```

### 5.3 使用 Immer 简化深层不可变更新

```jsx
import { produce } from 'immer';

const [state, setState] = useState({
  users: [
    { id: 1, name: 'Alice', posts: [{ id: 10, title: 'Hello' }] },
  ]
});

// 不用 Immer：痛苦的多层展开
setState(prev => ({
  ...prev,
  users: prev.users.map(u =>
    u.id === 1
      ? { ...u, posts: u.posts.map(p => p.id === 10 ? { ...p, title: 'Updated' } : p) }
      : u
  )
}));

// 用 Immer：像直接修改一样简单（实际上生成了新对象）
setState(produce(draft => {
  const user = draft.users.find(u => u.id === 1);
  if (user) {
    const post = user.posts.find(p => p.id === 10);
    if (post) post.title = 'Updated';
  }
}));
```

## 6. useState 与 useRef 的选择

| 特性 | `useState` | `useRef` |
|------|-----------|----------|
| 存储值的变化 | **触发组件重新渲染** | **不触发**重新渲染 |
| 返回值 | `[currentValue, setter]` | `{ current: value }` |
| 适用场景 | UI 相关的状态 | 非渲染用的可变值 |
| 典型用途 | 表单输入、开关、列表数据 | DOM ref、定时器 ID、前次值存储 |

```jsx
function Timer() {
  const [count, setCount] = useState(0);     // 渲染用
  const countRef = useRef(0);                 // 不渲染用

  useEffect(() => {
    const id = setInterval(() => {
      countRef.current += 1;     // ref 变化不触发重渲染
      
      // 如果需要显示在 UI 上：
      setCount(c => c + 1);     // state 变化触发重渲染
    }, 1000);
    return () => clearInterval(id);
  }, []);

  return <p>Rendered: {count}, Internal: {countRef.current}</p>;
}
```

## 7. 高级模式

### 7.1 与 useReducer 配合管理复杂状态

当单个组件有多个关联状态字段时，考虑升级到 `useReducer`：

```jsx
// 多个 useState → 合并为 useReducer
// 之前：
const [items, setItems] = useState([]);
const [filter, setFilter] = useState('all');
const [sortOrder, setSortOrder] = useState('asc');

// 之后：
const initialState = { items: [], filter: 'all', sortOrder: 'asc' };

function reducer(state, action) {
  switch (action.type) {
    case 'ADD_ITEM':
      return { ...state, items: [...state.items, action.payload] };
    case 'SET_FILTER':
      return { ...state, filter: action.payload };
    case 'TOGGLE_SORT':
      return { ...state, sortOrder: state.sortOrder === 'asc' ? 'desc' : 'asc' };
    default:
      return state;
  }
}

const [state, dispatch] = useReducer(reducer, initialState);
```

### 7.2 同步状态到 URL 参数

```jsx
import { useState, useEffect } from 'react';
import { useSearchParams } from 'react-router-dom';

function useQueryState(key, defaultValue) {
  const [searchParams, setSearchParams] = useSearchParams();
  const value = searchParams.get(key) ?? defaultValue;

  const setValue = (newValue) => {
    setSearchParams(prev => {
      if (newValue === defaultValue || newValue === undefined || newValue === '') {
        prev.delete(key);
      } else {
        prev.set(key, String(newValue));
      }
      return prev;
    });
  };

  return [value, setValue];
}

// 使用：自动同步到 URL query string
function ProductList() {
  const [page, setPage] = useQueryState('page', '1');
  const [sort, setSort] = useQueryState('sort', 'popular');
  
  // URL 自动变为: /products?page=2&sort=newest
}
```

### 7.3 带验证的 useState

```jsx
function useStateWithValidation(validator, initialValue) {
  const [state, setState] = useState(initialValue);
  const [isValid, setIsValid] = useState(() => validator(initialValue));

  const setValue = (newVal) => {
    const validated = typeof newVal === 'function' ? newVal(state) : newVal;
    setState(validated);
    setIsValid(validator(validated));
  };

  return [state, setValue, isValid];
}

// 使用
function EmailInput() {
  const [email, setEmail, isValidEmail] = useStateWithValidation(
    val => /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(val),
    ''
  );

  return (
    <div>
      <input 
        value={email} 
        onChange={(e) => setEmail(e.target.value)}
        style={{ borderColor: email && !isValidEmail ? 'red' : '#ccc' }}
      />
      {!isValidEmail && email && <span style={{ color: 'red' }}>Invalid email</span>}
    </div>
  );
}
```

## 8. 常见陷阱清单

| # | 陷阱 | 症状 | 解决方案 |
|---|------|------|---------|
| 1 | 直接修改 state 对象/数组 | UI 不更新 | 使用展开运算符或 Immer 创建新对象 |
| 2 | 在异步回调中读取 state | 读到陈旧闭包值 | 使用函数式更新 `setState(prev => ...)` |
| 3 | useEffect 依赖了 state 但未加入依赖数组 | effect 中用过期数据 | 将 state 加入 deps 或用 ref 存储 |
| 4 | 初始值为函数但未用惰性初始化形式 | 函数本身被当作初始值 | `useState(() => fn())` |
| 5 | 在条件语句/循环/嵌套函数中使用 useState | 报错 "Hooks can be called inside the body of a function component" | 移到组件函数的最顶层 |
| 6 | setState 后立即读取新值 | 读到的仍是旧值（异步） | 使用 useEffect 监听变化或在回调中读取 |

## 9. useState 内部原理（简化模型）

```
┌─────────────────────────────────────────────────────┐
│               useState 工作机制                       │
│                                                     │
│  function useState(initialState) {                   │
│    1. 获取当前正在渲染的 Fiber（组件实例）            │
│    2. 检查当前 Hook 在链表中是否有对应的 memoized     │
│       state                                          │
│       - 首次渲染: 存储 initialState                  │
│       - 后续渲染: 返回已保存的 state                 │
│    3. 返回 [currentState, dispatchSetter]            │
│                                                     │
│    dispatchSetter(action) {                         │
│      将更新加入对应 hook 的 update queue             │
│      标记该组件为需要 re-render                      │
│      （React 18: 自动 batch，调度更新）              │
│    }                                                │
│  }                                                  │
└─────────────────────────────────────────────────────┘

关键：React 通过 Hooks 的**调用顺序**来匹配 state 和 setter。
这就是为什么 Hooks 不能在条件/循环中被调用的原因——
顺序必须保持稳定。
```

## 10. 总结

```
┌──────────────────────────────────────────────────┐
│         useState 要点速查                          │
├──────────────────────────────────────────────────┤
│ 惰性初始化: useState(() => expensiveInit())      │
│ 函数式更新: setState(prev => prev + 1)           │
│   → 解决闭包陈旧值、批量更新的正确累加问题          │
│ 不可变性: 永远创建新对象，不要直接 mutate          │
│   → 数组用 [...], filter, map                    │
│   → 对象用 {...obj} 或 immer produce             │
│ 拆分策略: 相关字段合并不相关字段分                 │
│ vs useRef: 需要渲染用 useState，不需要用 useRef    │
│ 升级路径: 复杂多字段状态考虑迁移到 useReducer      │
│ 顶层调用: 不要在条件/循环/嵌套函数中使用           │
└──────────────────────────────────────────────────┘
```
