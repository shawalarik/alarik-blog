# useReducer 与状态逻辑封装

## 1. 什么是 useReducer

`useReducer` 是 `useState` 的替代方案，适用于**状态逻辑较复杂**或**下一状态依赖前一状态**的场景。它的灵感来自 Redux 的 reducer 模式。

```jsx
const [state, dispatch] = useReducer(reducer, initialArg, init?);
//  state:    当前状态
//  dispatch: 触发状态更新的函数（接收 action 对象）
//  reducer:  (prevState, action) => nextState
//  initialArg: 初始状态或传给 init 函数的参数
//  init:     惰性初始化函数（可选）
```

## 2. 基本用法

### 2.1 计数器示例

```jsx
// 定义 reducer 函数：纯函数，根据 action 类型返回新状态
function counterReducer(state, action) {
  switch (action.type) {
    case 'increment':
      return { count: state.count + 1 };
    case 'decrement':
      return { count: state.count - 1 };
    case 'reset':
      return { count: 0 };
    case 'set':
      return { count: action.payload };
    default:
      throw new Error(`Unknown action: ${action.type}`);
  }
}

function Counter() {
  const [state, dispatch] = useReducer(counterReducer, { count: 0 });

  return (
    <div>
      Count: {state.count}
      <button onClick={() => dispatch({ type: 'increment' })}>+</button>
      <button onClick={() => dispatch({ type: 'decrement' })}>-</button>
      <button onClick={() => dispatch({ type: 'reset' })}>Reset</button>
      <button onClick={() => dispatch({ type: 'set', payload: 42 })}>Set 42</button>
    </div>
  );
}
```

### 2.2 Action 的约定

```jsx
// FSA (Flux Standard Action) 格式
{
  type: 'ACTION_TYPE',     // 必填：字符串，描述动作类型
  payload?: any,           // 可选：负载数据
  error?: boolean,         // 可选：标记是否为错误
  meta?: object            // 可选：元信息
}

// 示例
{ type: 'todos/add', payload: { text: 'Buy milk' } }
{ type: 'todos/fetch/error', payload: err, error: true, meta: { timestamp: Date.now() } }
```

## 3. useReducer vs useState

### 3.1 对比表

| 维度 | `useState` | `useReducer` |
|------|-----------|-------------|
| 状态复杂度 | 简单（布尔、字符串、单对象） | 复杂（多字段、多转换逻辑） |
| 更新方式 | 直接设值 `setState(newValue)` | 通过 dispatch 发送 action |
| 更新逻辑 | 分散在各 setter 调用处 |集中在 reducer 函数中 |
| 可预测性 | 取决于写法 | **强**（纯函数，易测试） |
| 调试 | 需追踪多处 setState | 只看 reducer 即可了解所有状态变化 |
| 适合场景 | 表单输入、开关、简单计数 | 复杂状态机、表单验证、购物车 |

### 3.2 选择指南

```
你的状态更新逻辑？
  ├── 简单赋值（toggle, set value）
  │   → useState
  │
  ├── 下一状态依赖前一状态，且有多条路径
  │   → useReducer
  │
  ├── 状态有多个子字段，彼此关联
  │   → useReducer
  │
  ├── 需要测试状态转换逻辑
  │   → useReducer（reducer 是纯函数，极易单元测试）
  │
  └── 状态接近有限状态机
      → useReducer + useMachine (xstate)
```

## 4. 实战案例

### 4.1 待办事项列表

```jsx
const initialTodos = [
  { id: 1, text: 'Learn React', completed: false },
  { id: 2, text: 'Build app', completed: false },
];

function todosReducer(state, action) {
  switch (action.type) {
    case 'add':
      return [
        ...state,
        { id: Date.now(), text: action.payload, completed: false },
      ];

    case 'toggle':
      return state.map(todo =>
        todo.id === action.payload
          ? { ...todo, completed: !todo.completed }
          : todo
      );

    case 'delete':
      return state.filter(todo => todo.id !== action.payload);

    case 'edit':
      return state.map(todo =>
        todo.id === action.payload.id
          ? { ...todo, text: action.payload.text }
          : todo
      );

    case 'toggleAll':
      return state.map(todo => ({ ...todo, completed: action.payload }));

    case 'clearCompleted':
      return state.filter(todo => !todo.completed);

    default:
      return state;
  }
}

function TodoApp() {
  const [todos, dispatch] = useReducer(todosReducer, initialTodos);
  const [text, setText] = useState('');

  function handleSubmit(e) {
    e.preventDefault();
    if (!text.trim()) return;
    dispatch({ type: 'add', payload: text });
    setText('');
  }

  const completedCount = todos.filter(t => t.completed).length;
  const allCompleted = todos.length > 0 && completedCount === todos.length;

  return (
    <div>
      <form onSubmit={handleSubmit}>
        <input value={text} onChange={e => setText(e.target.value)} />
        <button type="submit">Add</button>
      </form>

      <ul>
        {todos.map(todo => (
          <li key={todo.id}>
            <input
              type="checkbox"
              checked={todo.completed}
              onChange={() => dispatch({ type: 'toggle', payload: todo.id })}
            />
            <span style={{ textDecoration: todo.completed ? 'line-through' : 'none' }}>
              {todo.text}
            </span>
            <button onClick={() => dispatch({ type: 'delete', payload: todo.id })}>
              ×
            </button>
          </li>
        ))}
      </ul>

      <div>
        <span>{completedCount}/{todos.length} completed</span>
        <button onClick={() => dispatch({ type: 'toggleAll', payload: !allCompleted })}>
          Toggle All
        </button>
        <button onClick={() => dispatch({ type: 'clearCompleted' })}>
          Clear Completed
        </button>
      </div>
    </div>
  );
}
```

### 4.2 表单验证状态机

```jsx
const formStates = {
  IDLE: 'idle',
  SUBMITTING: 'submitting',
  SUCCESS: 'success',
  ERROR: 'error',
};

function formReducer(state, action) {
  switch (action.type) {
    case 'FIELD_CHANGE':
      return {
        ...state,
        values: { ...state.values, [action.field]: action.value },
        errors: { ...state.errors, [action.field]: undefined },
        status: state.status === formStates.ERROR ? formStates.IDLE : state.status,
      };

    case 'VALIDATE_FIELD':
      const error = validate(action.field, state.values[action.field]);
      return error
        ? { ...state, errors: { ...state.errors, [action.field]: error } }
        : state;

    case 'SUBMIT':
      const hasErrors = Object.values(state.errors).some(Boolean);
      if (hasErrors) return { ...state, status: formStates.ERROR };
      return { ...state, status: formStates.SUBMITTING };

    case 'SUCCESS':
      return { ...initialFormState, status: formStates.SUCCESS };

    case 'ERROR':
      return { ...state, status: formStates.ERROR, serverError: action.payload };

    case 'RESET':
      return initialFormState;

    default:
      return state;
  }
}

// 状态流转图:
//   IDLE --submit--> SUBMITTING
//   SUBMITTING --success--> SUCCESS
//   SUBMITTING --fail--> ERROR
//   SUCCESS --edit--> IDLE
//   ERROR --edit--> IDLE
//   IDLE/ERROR --validate fail--> ERROR
```

## 5. useReducer + Context = 轻量级 Redux

这是 React 应用中最常见的全局状态管理模式之一：

```jsx
// ====== store.js ======
import { createContext, useContext, useReducer } from 'react';

// State 类型
interface AppState {
  user: User | null;
  theme: 'light' | 'dark';
  notifications: Notification[];
}

// Action 类型
type AppAction =
  | { type: 'USER_LOGIN'; payload: User }
  | { type: 'USER_LOGOUT' }
  | { type: 'THEME_TOGGLE' }
  | { type: 'NOTIFICATION_ADD'; payload: Notification }
  | { type: 'NOTIFICATION_DISMISS'; payload: number };

// Initial state
const initialState: AppState = {
  user: null,
  theme: 'dark',
  notifications: [],
};

// Reducer
function appReducer(state: AppState, action: AppAction): AppState {
  switch (action.type) {
    case 'USER_LOGIN':
      return { ...state, user: action.payload };
    case 'USER_LOGOUT':
      return { ...state, user: null };
    case 'THEME_TOGGLE':
      return { ...state, theme: state.theme === 'dark' ? 'light' : 'deep' };
    case 'NOTIFICATION_ADD':
      return { ...state, notifications: [...state.notifications, action.payload] };
    case 'NOTIFICATION_DISMISS':
      return {
        ...state,
        notifications: state.notifications.filter(n => n.id !== action.payload),
      };
    default:
      return state;
  }
}

// Context
const AppContext = createContext<{
  state: AppState;
  dispatch: React.Dispatch<AppAction>;
} | null>(null);

// Provider
export function AppProvider({ children }: { children: React.ReactNode }) {
  const [state, dispatch] = useReducer(appReducer, initialState);

  return (
    <AppContext.Provider value={{ state, dispatch }}>
      {children}
    </AppContext.Provider>
  );
}

// Custom Hook
export function useAppState() {
  const ctx = useContext(AppContext);
  if (!ctx) throw new Error('useAppState must be used within AppProvider');
  return ctx;
}

// ====== 使用 ======
function Header() {
  const { state, dispatch } = useAppState();
  
  return (
    <header className={state.theme}>
      <span>Hello, {state.user?.name || 'Guest'}</span>
      <button onClick={() => dispatch({ type: 'THEME_TOGGLE' })}>
        Switch to {state.theme === 'dark' ? 'Light' : 'Dark'}
      </button>
      
      {state.notifications.map(notif => (
        <Notification key={notif.id} onDismiss={() => 
          dispatch({ type: 'NOTIFICATION_DISMISS', payload: notif.id })
        }>
          {notif.message}
        </Notification>
      ))}
    </header>
  );
}
```

## 7. useReducer 与 TypeScript

```tsx
type State = {
  count: number;
  history: number[];
};

type Action =
  | { type: 'INCREMENT'; by?: number }
  | { type: 'DECREMENT'; by?: number }
  | { type: 'RESET' }
  | { type: 'UNDO' };

function reducer(state: State, action: Action): State {
  switch (action.type) {
    case 'INCREMENT':
      const by = action.by ?? 1;
      return {
        count: state.count + by,
        history: [...state.history, state.count],
      };
    case 'DECREMENT':
      return { count: state.count - (action.by ?? 1), history: state.history };
    case 'RESET':
      return { count: 0, history: [] };
    case 'UNDO':
      const last = state.history[state.history.length - 1];
      return last !== undefined
        ? { count: last, history: state.history.slice(0, -1) }
        : state;
    default:
      // TypeScript 确保 exhaustiveness
      const _exhaustive: never = action;
      return state;
  }
}

function Counter() {
  const [state, dispatch] = useReducer<State, React.Dispatch<Action>>(reducer, {
    count: 0,
    history: [],
  });
  
  // dispatch 的参数会被 TypeScript 检查类型！
  dispatch({ type: 'INCREMENT', by: 5 });  // ✅
  dispatch({ type: 'UNKNOWN' });           // ❌ TS Error
}
```

## 9. 总结

```
┌──────────────────────────────────────────────────┐
│         useReducer 要点速查                       │
├──────────────────────────────────────────────────┤
│ 本质: useState 的复杂版，Flux/Redux 模式的简化实现  │
│ 签名: useReducer(reducer, initialArg, init?)     │
│ Reducer: 纯函数 (state, action) => newState      │
│ Dispatch: 发送 action 对象触发状态更新             │
│ 优势: 状态转换集中、可测试、可预测                 │
│ 适用: 复杂状态机、多字段联动、表单验证             │
│ 进阶: + Context = 轻量级 Redux                    │
│ 初始化: init 函数支持惰性计算                     │
└──────────────────────────────────────────────────┘
```
