# useCallback / useMemo 与性能优化

## 1. 概述

`useCallback` 和 `useMemo` 都是 React 提供的**性能优化 Hooks**，它们的本质相同——**记忆化（Memoization）**：

| Hook | 记忆化的内容 | 返回值 | 主要用途 |
|------|------------|-------|---------|
| `useCallback(fn, deps)` | **函数**本身 | 记忆化的函数引用 | 避免子组件因回调引用变化而重渲染 |
| `useMemo(factory, deps)` | **计算结果** | 记忆化的值 | 避免昂贵的重复计算 |

两者底层原理一致：**依赖项不变时，返回缓存的结果**。

## 2. useMemo — 值的记忆化

### 2.1 基本用法

```jsx
import { useMemo, useState } from 'react';

function ExpensiveList({ items, filterText }) {
  // ❌ 每次渲染都重新过滤
  const filtered = items.filter(item => item.name.includes(filterText));

  // ✅ 只有 items 或 filterText 变化时才重新计算
  const filteredMemoized = useMemo(() => {
    console.log('Running expensive filter...');
    return items.filter(item => item.name.includes(filterText));
  }, [items, filterText]);  // 依赖数组

  return <ul>{filteredMemoized.map(/* ... */)}</ul>;
}
```

### 2.2 典型使用场景

```jsx
// 1. 昂贵计算
const sortedProducts = useMemo(
  () => [...products].sort((a, b) => compareFn(a, b, sortBy, order)),
  [products, sortBy, order]
);

// 2. 派生状态
const totalPrice = useMemo(
  () => cart.items.reduce((sum, item) => sum + item.price * item.quantity, 0),
  [cart.items]
);

// 3. 避免对象/数组重建（配合 React.memo 使用）
const style = useMemo(() => ({
  color: isActive ? 'red' : 'gray',
  fontWeight: isActive ? 'bold' : 'normal',
}), [isActive]);

const columns = useMemo(() => [
  { key: 'id', label: 'ID', width: 80 },
  { key: 'name', label: 'Name', width: 200 },
], []);

// 4. 复杂的条件判断
const permissions = useMemo(() => {
  if (!user) return {};
  const roles = computeRoles(user.roles);
  return generatePermissions(roles, featureFlags);
}, [user, featureFlags]);
```

### 2.3 什么不该 memoize

```jsx
// ❌ 不值得：原始值的基本运算
const doubled = useMemo(() => count * 2, [count]);
// 直接 const doubled = count * 2 更简洁

// ❌ 不值得：简单的对象字面量
const options = useMemo(() => ({ method: 'POST', headers }), []);
// 直接内联即可，除非传给了 memo 化的子组件

// ❌ 反模式：依赖太多，几乎每次都重算
const result = useMemo(() => complexCalc(a, b, c, d, e, f, g), [a, b, c, d, e, f, g]);
// 如果依赖这么多，memoize 意义不大
```

## 3. useCallback — 函数的记忆化

### 3.1 基本语法

```jsx
// 等价于 useMemo(() => fn, deps)
const memoizedCallback = useCallback(
  () => {
    doSomething(a, b);
  },
  [a, b]
);
```

### 3.2 为什么需要记忆化函数？

```jsx
function Parent() {
  const [count, setCount] = useState(0);

  // ❌ 每次渲染都创建新的函数引用
  const handleClick = () => {
    console.log('Clicked!', count);
  };

  // ✅ 只有 count 变化时才创建新函数
  const handleClickMemoized = useCallback(() => {
    console.log('Clicked!', count);
  }, [count]);

  return (
    <div>
      <button onClick={() => setCount(c => c + 1)}>+1</button>
      {/* 如果 Child 是 React.memo 包装的 */}
      <Child onClick={handleClickMemoized} />  
      {/* 只有 handleClickMemoized 引用不变时，Child 才跳过重渲染 */}
    </div>
  );
}
```

### 3.3 常见模式

```jsx
// 1. 事件处理器
const handleSubmit = useCallback((formData) => {
  api.submit(formData).then(handleSuccess);
}, [handleSuccess]);

// 2. 传给子组件的回调
const removeItem = useCallback((id) => {
  setItems(items => items.filter(item => item.id !== id));
}, []);  // 不依赖外部变量

// 3. 带参数的事件处理器工厂
const getItemHandler = useCallback((itemId) => {
  return () => selectItem(itemId);
}, [selectItem]);

// 使用
{items.map(item => (
  <Item key={item.id} onSelect={getItemHandler(item.id)} />
))}
```

## 4. React.memo 的配合使用

`useCallback` / `useMemo` 单独使用意义有限，它们通常与 `React.memo` **配合**才能发挥真正作用：

```jsx
// 子组件用 React.memo 包装
const ChildComponent = React.memo(function ChildComponent({ onClick, data }) {
  console.log('Child re-rendered');
  return <button onClick={onClick}>{data.label}</button>;
});

function Parent() {
  const [count, setCount] = useState(0);
  const data = { label: 'Click me' };

  // ✅ 稳定的回调 + 稳定的 data → Child 不会因 Parent 重渲染而重渲染
  const handleClick = useCallback(() => {
    console.log('clicked');
  }, []);

  const memoizedData = useMemo(() => ({ label: 'Click me' }), []);

  return (
    <div>
      <p>Parent count: {count}</p>
      <button onClick={() => setCount(c => c + 1)}>Re-render Parent</button>
      <ChildComponent onClick={handleClick} data={memoizedData} />
    </div>
  );
}

// 点击 "Re-render Parent" 时，ChildComponent 不会重渲染 ✓
```

### 4.1 React.memo 的工作原理

```jsx
// React.memo 是一个高阶组件，默认做浅比较（shallow comparison）
const MemoizedComponent = React.memo(MyComponent);

// 等价于：
function areEqual(prevProps, nextProps) {
  // 浅比较每个 prop：
  return (
    prevProps.onClick === nextProps.onClick &&
    prevProps.data === nextProps.data &&
    // ... 其他 props
  );
}
```

**浅比较的限制**：

```jsx
// ⚠️ 浅比较的问题
const data = { name: 'Test' };
<MemoizedChild data={data} />  // 每次渲染都是新的对象引用 → 浅比较失败

// 解决：useMemo 保持引用稳定
const memoizedData = useMemo(() => ({ name: 'Test' }), []);
<MemoizedChild data={memoizedData} />  // ✓ 引用稳定
```

### 4.2 自定义比较函数

```jsx
const HeavyChart = React.memo(
  function Chart({ dataPoints, width, height }) {
    // 渲染复杂图表...
    return <svg>...</svg>;
  },
  (prevProps, nextProps) => {
    // 自定义比较逻辑：只关心数据点是否真的变了
    // 即使 width/height 变了一点点像素也不重绘
    return (
      prevProps.dataPoints.length === nextProps.dataPoints.length &&
      prevProps.dataPoints.every((pt, i) => pt.value === nextProps.dataPoints[i].value) &&
      Math.abs(prevProps.width - nextProps.width) < 5  // 小于 5px 差异忽略
    );
  }
);
```

## 5. 性能优化的真实成本

### 5.1 不要过早优化

```jsx
// ❌ 过度优化的反例
function OverOptimized() {
  const [val, setVal] = useState('');

  // 每个函数都 memoize 了
  const handleChange = useCallback((e: ChangeEvent<HTMLInputElement>) => {
    setVal(e.target.value);
  }, []);  // 没有意义：这个组件很简单，没有 memo 化的子组件

  const handleSubmit = useCallback(() => {
    submit(val);
  }, [val]);  // val 每次打字都在变 → useCallback 形同虚设

  const displayValue = useMemo(() => {
    return val.toUpperCase();  // 这种计算微不足道
  }, [val]);

  return (
    <div>
      <input value={val} onChange={handleChange} />
      <button onClick={handleSubmit}>Submit</button>
      <span>{displayValue}</span>
    </div>
  );
}
```

**优化的实际成本**：

| 成本 | 说明 |
|------|------|
| 内存 | 缓存占用内存空间 |
| 代码量 | 增加 wrapper 和依赖数组 |
| 复杂性 | 需要正确维护 deps，否则产生 bug |
| 可读性 | 过多的 memoize 降低代码清晰度 |

### 5.2 何时该优化？

```
先让它工作 → 发现性能问题 → 用 Profiler 定位瓶颈 → 再优化

具体信号：
  ├── React DevTools 的 Flame Chart 显示组件不必要的重渲染
  ├── 大列表（>100 项）出现卡顿
  ├── 昂贵计算在渲染过程中反复执行
  └── 子组件做了大量 DOM 操作
```

## 6. 常见误区

### 6.1 误区：useCallback 能让函数"跑得更快"

```jsx
// ❌ 误解：以为 useCallback 让函数执行更快
const slowFn = useCallback(() => {
  // 这个函数本身还是很慢
  heavyComputation();  // useCallback 不加速这个！
}, []);

// ✅ 理解：useCallback 只是缓存函数引用
// 它不改变函数内部的执行效率
// 真正要优化的是 heavyComputation 本身 → 用 useMemo
const result = useMemo(() => heavyComputation(), [dependency]);
```

### 6.2 误区：useMemo 一定提升性能

```jsx
// ❌ 如果计算本身很轻量，useMemo 的开销反而更大
const double = useMemo(() => count * 2, [count]);
// useMemo 本身有：依赖比较 + 缓存查找 + 内存分配
// 对于 count * 2 来说，直接算更快

// ✅ useMemo 的价值在于：
// 1. 计算确实昂贵（O(n^2)、递归、大数组遍历）
// 2. 结果被传给 memo 化的子组件（需要引用稳定性）
```

### 6.3 依赖数组遗漏

```jsx
// ⚠️ 依赖数组不完整
const memoizedFn = useCallback(() => {
  console.log(count);  // 用到了 count 但没加入依赖
}, []);  // count 永远是初始值！

// ✅ 正确：包含所有响应式依赖
const memoizedFn = useCallback(() => {
  console.log(count);
}, [count]);

// 或者在不需要最新值时，用 ref
const countRef = useRef(count);
countRef.current = count;  // 保持 ref 最新

const stableFn = useCallback(() => {
  console.log(countRef.current);  // 总是最新的
}, []);  // 依赖为空 → 函数引用永远稳定
```

## 7. React 18 的变化

React 18 的 automatic batching 改变了一些优化场景：

```jsx
// React 17: 以下情况不在批处理中
function OldBehavior() {
  const [a, setA] = useState(0);
  const [b, setB] = useState(0);

  function handleClick() {
    fetch('/api').then(() => {
      setA(1);  // 触发一次重渲染
      setB(1);  // 再触发一次重渲染（React 17）
    });
  }
  // React 17 中 useCallback 依赖 [a, b] 可能更有意义
}

// React 18: 自动批处理
function NewBehavior() {
  // setA 和 setB 会被批量为一次重渲染
  // 一些之前的优化场景不再必要
}
```

## 8. 总结

```
┌──────────────────────────────────────────────────┐
│      useCallback / useMemo 要点速查               │
├──────────────────────────────────────────────────┤
│ useMemo: 缓存计算结果，避免昂贵重复计算            │
│ useCallback: 缓存函数引用，避免子组件不必要的重渲染 │
│ 配合: 通常与 React.memo 一起使用才有效果          │
│ 代价: 内存占用 + 代码复杂度                       │
│ 原则: 先测量，后优化；不要过早优化                 │
│ 依赖: 必须完整列出所有响应式依赖                  │
│ 不适用: 轻量计算、没有 memo 子组件的场景           │
│ Ref trick: 需要稳定引用+最新值时用 useRef          │
└──────────────────────────────────────────────────┘
```
