# MobX 与响应式状态管理

## 1. 核心理念

MobX 的哲学与 Redux 截然不同：

| 维度 | Redux | MobX |
|------|-------|------|
| 核心思想 | 单向数据流、显式 action | **响应式**：自动追踪依赖、自动更新 |
| 状态变更方式 | dispatch(action) → reducer 返回新 state | 直接**修改**可观察对象 |
| 更新范围 | 需手动 selector 控制重渲染粒度 | 自动精确到使用了变化属性的组件 |
| 学习曲线 | 较陡（概念多） | 平缓（直觉式） |
| 包体积 | Redux + React-Redux (~7KB+7KB) | MobX + mobx-react-lite (~16KB) |

> **MobX 的口号**："Anything that can be derived from the application state, should be derived. **Automatically.**"

## 2. 核心概念

```
┌─────────────────────────────────────────────┐
│              MobX 三大核心                    │
│                                             │
│  ┌──────────┐                              │
│  │ Observable│ ← 可观察的状态（数据源）      │
│  │ (State)   │    state 可以是任何数据结构     │
│  └─────┬────┘                              │
│        │ 变化自动触发                        │
│        ▼                                    │
│  ┌──────────┐                              │
│  │ Computed  │ ← 派生值（自动缓存）          │
│  │ (Derived) │    类似 Vue 的 computed       │
│  └─────┬────┘                              │
│        │ 被消费时触发副作用                   │
│        ▼                                    │
│  ┌──────────┐                              │
│  │ Reaction │ ← 副作用（自动执行）           │
│  │ (Effect)  │    UI 渲染 / 日志 / 网络请求   │
│  └──────────┘                              │
└─────────────────────────────────────────────┘
```

### 2.1 Observable（可观察对象）

```ts
import { makeAutoObservable, observable, action, computed } from 'mobx';

// 方式一：makeAutoObservable（推荐，自动推断）
class TodoStore {
  todos = [] as Todo[];
  filter = 'all' as 'all' | 'active' | 'completed';

  constructor() {
    makeAutoObservable(this);  // 自动将所有属性/方法标记为对应类型
  }

  // getter → 自动变为 computed
  get filteredTodos() {
    switch (this.filter) {
      case 'active': return this.todos.filter(t => !t.completed);
      case 'completed': return this.todos.filter(t => t.completed);
      default: return this.todos;
    }
  }

  // 方法 → 自动变为 action（除非以 get/handle/set 开头的异步方法）
  addTodo(text: string) {
    this.todos.push({ id: crypto.randomUUID(), text, completed: false });
  }

  toggleTodo(id: string) {
    const todo = this.todos.find(t => t.id === id);
    if (todo) todo.completed = !todo.completed;
  }

  removeTodo(id: string) {
    this.todos = this.todos.filter(t => t.id !== id);
  }

  setFilter(filter: typeof this.filter) {
    this.filter = filter;
  }
}

// 方式二：makeObservable（手动标注，更精细控制）
class ManualStore {
  name = '';
  
  constructor() {
    makeObservable(this, {
      name: observable,
      upperName: computed,
      setName: action,
    });
  }

  get upperName() { return this.name.toUpperCase(); }
  setName(v: string) { this.name = v; }
}
```

### 2.2 Computed（计算值）

```ts
class OrderStore {
  items = observable<OrderItem>([]);

  constructor() { makeAutoObservable(this); }

  // ✅ Computed: 自动缓存，仅在依赖项变化时重新计算
  get subtotal() {
    return this.items.reduce((sum, item) => sum + item.price * item.quantity, 0);
  }

  get tax() { return this.subtotal * 0.1; }

  get total() { return this.subtotal + this.tax; }

  get itemCount() { return this.items.length; }
}
```

### 2.3 Action（动作）

Action 是**唯一允许修改 Observable 的地方**：

```ts
class CounterStore {
  count = 0;

  constructor() { makeAutoObservable(this); }

  increment() { this.count++; }         // 自动标记为 action
  decrement() { this.count--; }
  
  reset() {
    this.count = 0;
    this.history.clear();
  }

  // 异步方法默认也是 action
  async fetchData() {
    const res = await fetch('/api/data');
    this.data = await res.json();  // 允许在 async action 中修改
  }
}
```

> 在严格模式 (`useStrict(true)`) 下，在 action 外部修改 observable 会抛出错误。推荐始终开启。

## 3. 与 React 集成

### 3.1 Observer 组件

```tsx
import { observer } from 'mobx-react-lite';
import { useContext } from 'react';

const StoreContext = createContext<TodoStore | null>(null);

function TodoProvider({ children }: { children: React.ReactNode }) {
  const store = useMemo(() => new TodoStore(), []);
  return <StoreContext.Provider value={store}>{children}</StoreContext.Provider>;
}

function useTodoStore(): TodoStore {
  const store = useContext(StoreContext);
  if (!store) throw new Error('Missing Provider');
  return store;
}

// 用 observer 包装组件 → 只在使用的 observable 变化时重渲染
export const TodoList = observer(function TodoList() {
  const store = useTodoStore();

  return (
    <div>
      <select value={store.filter} onChange={(e) => store.setFilter(e.target.value as any)}>
        <option value="all">All</option>
        <option value="active">Active</option>
        <option value="completed">Completed</option>
      </select>

      <ul>
        {store.filteredTodos.map(todo => (
          <li key={todo.id}>
            <input
              type="checkbox"
              checked={todo.completed}
              onChange={() => store.toggleTodo(todo.id)}
            />
            {todo.text}
            <button onClick={() => store.removeTodo(todo.id)}>×</button>
          </li>
        ))}
      </ul>

      <p>{store.filteredTodos.length} items shown</p>
    </div>
  );
});
```

### 3.2 observer 的性能优势

```tsx
// 即使父组件重渲染，子组件也只在相关数据变化时更新：
const Parent = observer(() => {
  const store = useTodoStore();
  return (
    <>
      {/* 只依赖 store.todos */}
      <TodoList />
      
      {/* 只依赖 store.user */}
      <UserInfo />
      
      {/* 只依赖 store.notifications */}
      <NotificationPanel />
    </>
  );
});

// 当 store.todos 变化时:
//   → TodoList 重渲染 ✓ (它用了 todos)
//   → UserInfo 不渲染 ✗ (没用 todos)
//   → NotificationPanel 不渲染 ✗ (没用 todos)
```

## 4. 高级用法

### 4.1 异步操作

```ts
class UserStore {
  user = null as User | null;
  status = 'idle' as 'idle' | 'loading' | 'error' | 'success';
  error = null as string | null;

  constructor() { makeAutoObservable(this); }

  fetchUser = flow(function* (this: UserStore, userId: string) {
    this.status = 'loading';
    this.error = null;

    try {
      const response = yield fetch(`/api/users/${userId}`);
      if (!response.ok) throw new Error(`HTTP ${response.status}`);
      this.user = yield response.json();
      this.status = 'success';
    } catch (err) {
      this.status = 'error';
      this.error = err instanceof Error ? err.message : String(err);
    }
  });

  // 或者用 runInAction
  async loadUser(userId: string) {
    this.status = 'loading';
    try {
      const res = await fetch(`/api/users/${userId}`);
      runInAction(() => {
        this.user = await res.json();
        this.status = 'success';
      });
    } catch (err) {
      runInAction(() => {
        this.status = 'error';
        this.error = String(err);
      });
    }
  }
}
```

### 4.2 多 Store 组织

```ts
// stores/index.ts
import { createContext, useContext } from 'react';
import { TodoStore } from './TodoStore';
import { UIStore } from './UIStore';
import { AuthStore } from './AuthStore';

class RootStore {
  todoStore: TodoStore;
  uiStore: UIStore;
  authStore: AuthStore;

  constructor() {
    this.todoStore = new TodoStore(this);  // 传入 rootStore 以便跨 store 访问
    this.uiStore = new UIStore(this);
    this.authStore = new AuthStore(this);
  }
}

const rootStoreContext = createContext<RootStore | null>(null);

export function RootStoreProvider({ children }: { children: React.ReactNode }) {
  const store = useMemo(() => new RootStore(), []);
  return <rootStoreContext.Provider value={store}>{children}</rootStoreContext.Provider>;
}

export function useStores() {
  const stores = useContext(rootStoreContext);
  if (!stores) throw new Error('Missing RootStoreProvider');
  return stores;
}

// 使用时解构所需 store
function SomeComponent() {
  const { todoStore, uiStore } = useStores();
  // ...
}
```

### 4.3 Local Observable（组件内局部响应式）

```tsx
// 对于仅在一个组件内部使用的简单状态，不需要创建 class
import { observer, useLocalObservable } from 'mobx-react-lite';

const SearchInput = observer(() => {
  const state = useLocalObservable(() => ({
    query: '',
    results: [] as SearchResult[],
    
    get isSearching() { return this.query.length >= 2; },
    
    setQuery(q: string) {
      this.query = q;
      if (q.length >= 2) this.search(q);
    },
    
    async search(q: string) {
      this.results = await searchAPI(q);
    },
  }));

  return (
    <div>
      <input 
        value={state.query} 
        onChange={e => state.setQuery(e.target.value)} 
        placeholder="Type to search..."
      />
      {state.isSearching && <Spinner />}
      <ResultsList items={state.results} />
    </div>
  );
});
```

## 5. MobX vs 其他方案对比

| 特性 | MobX | Zustand | Jotai |
|------|------|---------|-------|
| 编程范式 | OOP（Class） | FP（Function） | FP（Atom） |
| 状态变更 | 直接修改 | `set()` 函数 | Atom setter |
| 响应性 | 自动追踪（细粒度） | 手动订阅或全量通知 | 自动追踪（原子粒度） |
| DevTools | mobx-devtools | zustand-middleware-devtools | jotai-devtools |
| TypeScript | 良好（需 makeAutoObservable） | 优秀 | 优秀 |
| 适用场景 | 复杂领域模型、OOP 团队偏好 | 通用轻量全局状态 | 细粒度原子状态 |
| 包大小 | ~16KB (core + react-lite) | ~1.5KB | ~5KB |

## 6. 总结

```
┌──────────────────────────────────────────────────┐
│         MobX 要点速查                               │
├──────────────────────────────────────────────────┤
│ 核心: Observable → Computed → Reaction            │
│ 创建: makeAutoObservable (自动推断)               │
│ 或: makeObservable (手动标注)                     │
│ Action: 唯一可以修改 observable 的地方             │
│ React集成: observer() HOC                         │
│ 性能: 自动精确追踪依赖，只更新需要的组件           │
│ 异步: flow* generator / runInAction              │
│ 组织: 多 Store 通过 RootStore 组合                │
│ 局部状态: useLocalObservable 无需 Class          │
│ 推荐: 适合 OOP 偏好、复杂业务模型的项目           │
└──────────────────────────────────────────────────┘
```
