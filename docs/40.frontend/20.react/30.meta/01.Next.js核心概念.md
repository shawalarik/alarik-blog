# Next.js 核心概念

## 1. 什么是 Next.js？

Next.js 是基于 React 的**全栈 Web 框架**（Meta Framework），由 Vercel 团队开发和维护。它解决了纯 React 应用在以下方面的工程化痛点：

```
纯 Create-React-App 的局限:
├── ❌ 没有 SEO 支持（CSR 只有空壳 HTML）
├── ❌ 没有路由系统（需手动配置 react-router）
├── ❌ 没有代码分割（首屏加载全量 JS）
├── ❌ 没有数据获取方案
├── ❌ 没有优化策略（图片/字体/打包）
└── ❌ API 部署需要单独的服务器

Next.js 开箱即用:
├── ✅ 文件系统路由 (File-based Routing)
├── ✅ SSR / SSG / ISR 多种渲染模式
├── ✅ 自动代码分割与按需加载
├── ✅ 内置图片/字体/脚本优化
├── ✅ API Routes (API 路由)
├── ✅ 中间件 (Middleware)
├── ✅ TypeScript 零配置支持
└── ✅ Vercel 一键部署 + 边缘网络
```

## 2. 项目结构

```

├── app/                          # App Router (Next.js 13+ 推荐)
```

## 3. 页面路由（Pages）

### 3.1 App Router（推荐，v13+）

```tsx
// app/page.tsx → /
export default function HomePage() {
  return <h1>Welcome to Next.js!</h1>;
}

// app/about/page.tsx → /about
export default function AboutPage() {
  return <div>About us</div>;
}

// app/blog/[slug]/page.tsx → /blog/hello-world
interface BlogPostParams {
  params: { slug: string };
}
export default function BlogPost({ params }: BlogPostParams) {
  return <h1>Post: {params.slug}</h1>;
}
```

### 3.2 动态路由参数

```tsx
// app/users/[id]/page.tsx
// 匹配: /users/1, /users/abc, /users/42-xyz
export default function UserProfile({ params }: { params: { id: string } }) {
  const user = await fetchUser(params.id);
  return <div>{user.name}</div>;
}

// Catch-all 路由: app/[...slug]/page.tsx
// 匹配: /a/b/c, /x/y/z 等
```

### 3.3 布局系统（Layouts）

```tsx
// app/layout.tsx — 根布局（必需）
import './globals.css';

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="en">
      <body>
        <nav>Global Navigation</nav>
        <main>{children}</main>
        <footer>© 2026</footer>
      </body>
    </html>
  );
}
```

**布局嵌套**：

```tsx
// app/dashboard/layout.tsx — Dashboard 区域的布局
export default function DashboardLayout({ children }: { children: React.ReactNode }) {
  return (
    <div className="dashboard">
      <aside>Sidebar</aside>
      <section>{children}</section>
    </div>
  );
}

// app/dashboard/settings/page.tsx
// 自动继承 dashboard layout + root layout
export default function SettingsPage() {
  return <h1>Settings</h1>;
}

// 最终渲染: <html><body><nav>...<div class="dashboard"><aside>...<section><h1>Settings</h1></section></div></body></html>
```

### 3.4 Loading 与 Error 状态

```tsx
// app/dashboard/loading.tsx — 该路由加载中显示
export default function DashboardLoading() {
  return (
    <div className="animate-pulse">
      <Skeleton height={40} count={5} />
    </div>
  );
}

// app/dashboard/error.tsx — 该路由出错时显示
'use client';
export default function DashboardError({
  error,
  reset,
}: {
  error: Error & { digest?: string };
  reset: () => reset();
}) {
  return (
    <div role="alert">
      <h2>Something went wrong!</h2>
      <p>{error.message}</p>
      <button onClick={() => reset()}>Try again</button>
    </div>
  );
}

// app/not-found.tsx — 404 页面
export default function NotFound() {
  return <div>Page not found</div>;
}

// app/error.tsx — 全局错误边界
```

## 4. 客户端导航

Next.js 使用 **Link 组件** 进行客户端导航，无需整页刷新：

```tsx
import Link from 'next/link';

function Navigation() {
  return (
    <nav>
      <Link href="/">Home</Link>
      <Link href="/about?ref=navbar">About</Link>
      
      {/* 动态路由 */}
      <Link href={`/blog/${postSlug}`}>
        Read post
      </Link>

      {/* 编程式导航 */}
      <button onClick={() => router.push('/dashboard')}>
        Go to Dashboard
      </button>
    </nav>
  );
}
```

**Link vs `<a>` 对比**：

| | `<a>` 标签 | `<Link>` 组件 |
|--|----------|-------------|
| 行为 | 整页刷新 | 客户端路由切换 |
| 性能 | 重新请求所有资源 | 仅获取新页面数据 |
| 状态保留 | 丢失组件状态 | **保持** React 状态 |
| Prefetching | 无 | 可预取（`prefetch` prop） |

```tsx
<Link href="/dashboard" prefetch>
  Dashboard {/* 鼠标悬停或进入视口时预取 */}
</Link>
```

## 5. API Routes

Next.js 允许你在同一项目中创建 **API 端点**作为 React Pages 的兄弟节点：

```ts
// app/api/users/route.ts
import { NextResponse } from 'next/server';

// GET /api/users
export async function GET() {
  const users = await db.users.findMany();
  // 返回 JSON Response 对象
  return NextResponse.json(users);
}

// POST /api/users
export async function POST(request: Request) {
  const body = await request.json();
  const user = await db.users.create({ data: body });
  return NextResponse.json(user, { status: 201 });
}

// 动态路由: app/api/users/[id]/route.ts
// GET /api/users/42, DELETE /api/users/42
```

**Route Handler 函数签名**：

```ts
export async function GET(
  request: Request,
  { params }: { params: Record<string, string | string[]> }
): Promise<NextResponse> { ... }

export async function POST(
  request: Request
): Promise<NextResponse> { ... }

// 也支持 PUT, PATCH, DELETE, HEAD, OPTIONS
```

**API Route 的特点**：

| 特性 | 说明 |
|------|------|
| 运行位置 | **服务端**（Node.js） |
| 访问方式 | fetch('/api/...') 或表单提交 |
| CORS | 同源无跨域问题；跨域需配置 |
| Body 解析 | `request.json()` / `request.formData()` / `request.text()` |
| Cookie/Headers | 通过 request 访问 |
| 数据库连接 | 可直接连接数据库（安全，不暴露给客户端） |

## 6. 数据获取方法

### 6.1 Server Components（默认，推荐）

```tsx
// 默认导出的 page 组件是 Server Component（RSC）
// 它在服务端渲染，可以直接使用 async/await
async function Page({ params }: { params: { id: string } }) {
  const post = await fetch(`https://api.example.com/posts/${id}`);
  
  if (!post.ok) notFound();
  
  return <article>
    <h1>{post.title}</h1>
    <p>{post.content}</p>
  </article>;
}
```

### 6.2 Client Components（需要标记）

```tsx
'use client';  // ← 必须在文件顶部添加此指令

import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(c => c + 1)}>Count: {count}</button>;
}
```

**Server vs Client Components**:

| | Server Component | Client Component |
|--|-----------------|-----------------|
| 声明 | 默认 | `'use client'` 指令 |
| 渲染位置 | 服务端 | 客户端 |
| 可用 API | Node.js 全量 API | 浏览器/Web API |
| Hooks | ❌ 不能使用 useState/useEffect | ✅ 可以 |
| 用途 | 数据获取、SEO 内容、隐私逻辑 | 交互、动画、浏览器 API |
| 大小 | 发送给客户端的是 HTML | 发送的是 JS bundle 引用 |

### 6.3 数据缓存（Cache）

```tsx
// Next.js 会自动缓存 fetch 请求的结果！
async function PostList() {
  // 这个 fetch 在构建时和导航时会执行
  // 但相同 URL 的重复请求会被去重（dedup）
  const res = await fetch('https://api.example.com/posts');
  const posts = await res.json();

  return (
    <ul>
      {posts.map(p => <li key={p.id}>{p.title}</li>)}
    </ul>
  );

  // 第二次访问该页面：
  // → 如果缓存有效，直接返回缓存的 HTML（不发请求）
  // → 缓存验证：revalidatePath/revalidateTag 控制
}
```

## 7. 环境变量

```bash
# .env.local (本地开发，不提交到 Git)
DATABASE_URL="postgresql://..."
NEXT_PUBLIC_API_KEY="pk_live_xxx"

# .env.production (生产环境)
DATABASE_URL="postgres://prod-db"
```

```tsx
// 服务端可访问所有环境变量
const dbUrl = process.env.DATABASE_URL;

// 客户端只能访问 NEXT_PUBLIC_ 前缀的变量
const apiKey = process.env.NEXT_PUBLIC_API_KEY;  // ✅ 可用
const secret = process.env.DB_SECRET;              // ❌ undefined
```

## 8. 总结

```
┌──────────────────────────────────────────────────┐
│         Next.js 核心要点速查                      │
├──────────────────────────────────────────────────┤
│ 路由: app/ 目录下的文件自动成为路由             │
│ 布局: layout.tsx 嵌套，根布局必须存在            │
│ RSC: 默认服务端渲染，'use client' 标记客户端        │
│ 导航: Link 组件替代 <a>，保持状态               │
│ API: app/api/ 下创建服务端接口                   │
│ Loading/Error: loading.tsx error.tsx 自动处理     │
│ 数据获取: Server Component 中直接 async/await    │
│ 环境: .env 文件 + NEXT_PUBLIC_ 前缀区分          │
│ 部署: Vercel 一键部署或自托管                    │
└──────────────────────────────────────────────────┘
```
