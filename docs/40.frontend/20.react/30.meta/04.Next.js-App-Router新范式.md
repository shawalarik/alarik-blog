# Next.js App Router 新范式

## 1. 从 Pages Router 到 App Router

Next.js 13 (2023年5月) 发布了全新的 **App Router**，代表了 React 服务端渲染架构的一次重大演进：

```
Pages Router (Legacy):
├── pages/index.jsx          → /
├── pages/blog/[slug].jsx    → /blog/:slug
├── pages/api/user.ts         → /api/user
└── getServerSideProps()       ← 手动声明数据获取函数

App Router (New):
├── app/page.tsx              → /
├── app/blog/[slug]/page.tsx  → /blog/:slug
├── app/api/user/route.ts     → /api/user
└── async function Page() {}    ← 组件本身就是数据获取函数
```

### 1.1 为什么需要 App Router?

| 问题 | Pages Router | App Router |
|------|--------------|------------|
| Layout 嵌套 | `_app.js` 不直观 | `layout.tsx` 自然嵌套 |
| 错误处理 | 自定义 `_error.js` | `error.tsx` 更规范 |
| 加载状态 | 需手动挂载 suspense | `loading.tsx` 自动集成 |
| 并行路由 | 难实现 | `Parallel Routes` 原生支持 |
| 拦截路由 | _middleware | `middleware.ts` + `route.ts` |
| Server Actions | 不支持 | 表单直接调用服务器函数 |
| RSC 支持 | 部分 | **完整原生支持** |
| Streaming | 需手写 | **自动 Suspense Streaming** |

## 2. React Server Components (RSC)

App Router 是围绕 **React Server Components** 设计的第一个框架。理解 RSC 是掌握 App Router 的关键。

### 2.1 什么是 RSC？

```
传统 CSR (Client-Side Rendering):

  Server → 发送空白 HTML + JS bundle
  Client → 执行 JS → hydrate → 显示 UI
  → 用户看到内容前有一段白屏时间


SSR (Server-Side Rendering) — Pages Router:

  Server → 执行 React 组件 → 生成完整 HTML → 发送
  Client → 接收 HTML → hydrate → 可交互
  → 用户立即看到内容，但 hydration 有成本


RSC (React Server Components) — App Router:

  Server → 执行 Server Components → 生成部分 HTML
         → Client Components 以引用形式发送
  Client → 渲染 HTML + 执行 Client Components
  → 无需 hydration！Server 和 Client 天然融合
```

### 2.2 RSC 的工作流程

```tsx
// Server Component（默认）
async function BlogPost({ params }: { params: { slug: string } }) {
  const post = await db.post.findUnique({ where: { slug: params.slug } });

  return (
    <article>
      {/* 这些 HTML 在服务端生成 */}
      <h1>{post.title}</h1>
      <time>{new Date(post.createdAt).toLocaleDateString()}</time>
      
      {/* Client Component —— 以特殊引用形式发送给客户端 */}
      <CommentSection postId={post.id} />
      <ShareButtons url={`/blog/${params.slug}`} />
      
      <RelatedPosts categoryId={post.categoryId} />
    </article>
  );
}

// Client Component
'use client';
function CommentSection({ postId }: { postId: string }) {
  const [comments, setComments] = useState([]);
  // useState、useEffect、事件处理器 —— 只在客户端运行
  
  useEffect(() => { fetchComments(postId).then(setComments); }, [postId]);
  
  return <CommentList comments={comments} />;
}
```

**RSC 的输出**（简化）：

```html
<!-- 服务端发送给客户端的内容 -->
<article>
  <h1>Hello World</h1>
  <time>March 15, 2026</time>
  
  <!-- Client Component 的占位符 -->
  <!-- 客户端收到后执行 CommentSection 组件 -->
  <template data-react-component-id="CommentSection" 
            data-react-props='{"postId":"123"}'>
  </template>
  <template data-react-component-id="ShareButtons" 
            data-react-props='{"url":"/blog/hello"}'>
  </template>
</article>
```

### 2.3 Server Components 的优势

| 优势 | 说明 |
|------|------|
| **零 Hydration** | 不需要客户端"接管"整个页面，减少 JS 执行 |
| **渐进式增强** | 关键内容即时显示，交互功能逐步加载 |
| **更小的 JS Bundle** | Server 部分不发送 JS，只发送 Client Component 引用 |
| **流式传输** | Server Component 可以流式发送 HTML，用户更快看到内容 |
| **边界清晰** | 明确划分哪些代码在服务端运行、哪些在客户端 |

## 3. Server Actions — 革向表单的革命性特性

Server Actions 是 App Router 最具创新性的功能之一：

### 3.1 传统方式 vs Server Action

```tsx
// ❌ 传统方式：手动管理 loading/error state + fetch
function NewTodoForm() {
  const [title, setTitle] = useState('');
  const [isSubmitting, setIsSubmitting] = useState(false);
  const [error, setError] = useState(null);

  async function handleSubmit(e: FormDataEvent) {
    e.preventDefault();
    setIsSubmitting(true);
    
    try {
      const res = await fetch('/api/todos', {
        method: 'POST',
        body: JSON.stringify({ title }),
        headers: { 'Content-Type': 'application/json' },
      });
      if (!res.ok) throw new Error('Failed to create');
      setTitle('');
    } catch (err) {
      setError(err.message);
    } finally {
      setIsSubmitting(false);
    }
  }

  return (
    <form action={handleSubmit}>
      <input value={title} onChange={(e) => setTitle(e.target.value)} />
      <button disabled={isSubmitting}>
        {isSubmitting ? 'Creating...' : 'Create Todo'}
      </button>
      {error && <span className="text-red">{error}</span>}
    </form>
  );
}

// ✅ Server Action 方式：极简！
import { createAction } from '@/lib/actions';

function NewTodoForm() {
  const createTodo = useFormState(createTodo, { initialState: '' });

  return (
    <form action={createTodo}>  {/* 直接指向 server function! */}
      <input name="title" defaultValue="" />  {/* name 属性对应 formData.get('title') */}
      <FormSubmit>
        <Submit>Create</Submit>
      </FormSubmit>
      <SubmitError>Failed to create todo.</SubmitError>
    </form>
  );
}
```

### 3.2 定义 Server Action

```ts
// actions/todo.ts — 在 Server 上执行的函数
'use server';

import { revalidatePath } from 'next/cache';
import { redirect } from 'next/navigation';
import { z } from 'zod';  // 推荐用 zod 做 schema 验证

const createTodoSchema = z.object({
  title: z.string().min(1).max(100),
});

export async function createTodo(prevState: unknown, formData: FormData) {
  // prevState: 上一次调用的返回值（用于乐观更新场景）
  // formData: 表单数据（自动从 <form action={fn}> 收集）
  
  const validated = createTodoSchema.safeParse(Object.fromEntries(formData));
  if (!validated.success) {
    return { error: 'Invalid input' };  // 错误会触发 SubmitError
  }

  const { title } = validated.data;
  
  await db.todo.create({ data: { title, completed: false }});
  
  // 使相关缓存失效
  revalidatePath('/');
  redirect('/todos');
  
  return { message: 'Todo created successfully!' };
}
```

### 3.3 useActionStatus — 获取状态反馈

```tsx
'use client';
import { useOptimistic, useActionStatus } from 'react-dom';
import { createTodo } from '@/actions/todo';

export function NewTodoForm() {
  const createTodo = useFormState(createTodo);
  const { pending, success, error, result } = useActionStatus(createTodo);
  const optimisticData = useOptimistic(createTodo, {
    currentState: '',
    // 乐观更新：假设成功后的状态
    fn: (prev, newTitle) => [...prev, { title: newTitle }],
  });

  return (
    <form action={createTodo}>
      <input name="title" defaultValue={optimisticData.currentValue} />
      <SubmitButton disabled={pending}>{pending ? 'Creating...' : 'Create'}</SubmitButton>
      {success && <SuccessMessage message={result!.message} />}
      {error && <ErrorMessage error={error.message} />}
    </form>
  );
}
```

## 4. Parallel Routes（并行路由）

并行路由允许在同一 URL 下**同时渲染多个独立页面**：

```tsx
// app/(shop)/@modal/login/layout.tsx
// @modal 是一个 Route Group（不影响 URL）
export default function ModalLayout({ children }: { children: React.ReactNode }) {
  return <dialog>{children}</dialog>;
}

// app/(shop)/@modal/login/page.tsx
export default function LoginModal() {
  return <LoginForm />;
}

// app/(shop)/page.tsx — 主页面
// 同时渲染主页面 + 登录弹窗（如果 URL 包含 ?modal=login）
export default function ShopPage() {
  return <main>Shop content here...</main>;
}

// 使用示例
function Shop() {
  return (
    <>
      <ShopPage />
      <LoginModal />  {/* 条件渲染模态框 */}
    </>
  );
}
```

**应用场景**：
- 模态框/侧边栏（URL 参数控制显隐）
- 分屏布局（左侧列表 + 右侧详情）
- A/B 测试变体（同一 URL 不同呈现）
- 后台仪表盘（多个面板同时展示）

## 5. Intercepting Routes（拦截路由）

```tsx
// app/(marketing)/about/page.tsx
import { redirect } from 'next/navigation';

// 拦截：未登录的用户重定向到登录页
export default async function AboutPage() {
  const session = await getAuthSession();
  
  if (!session?.user) {
    redirect('/login?callback=/about');
  }
  
  return <AboutContent />;
}

// 或者使用专门的拦截文件
// app/(marketing)/about/middleware.ts
import { NextResponse } from 'next/server';

export function middleware(request: NextRequest) {
  const isAuthenticated = checkAuth(request.cookies);
  
  if (!isAuthenticated && request.nextUrl.pathname.startsWith('/about')) {
    return NextResponse.redirect(new URL('/login', request.url));
  }
  
  return NextResponse.next();
}
```

## 6. Route Handlers (app/*)

App Router 中的 API 路由更加简洁和强大：

```ts
// app/items/[id]/route.ts
import { NextResponse } from 'next/server';
import { revalidateTag } from 'next/cache';

// GET
export async function GET(
  request: Request,
  { params }: { params: { id: string } },
) {
  const item = await db.item.findUnique({ where: { id: Number(params.id) } });
  
  if (!item) return NextResponse.json({ error: 'Not found' }, { status: 404 });
  
  return NextResponse.json(item, {
    headers: {
      'Cache-Control': 'public, s-maxage=60, stale-while-revalidate=3600',
    },
  });
}

// PUT
export async function PUT(
  request: Request,
  { params }: { params: { id: string } },
) {
  const body = await request.json();
  const updated = await db.item.update({
    where: { id: Number(params.id) },
    data: body,
  });
  
  revalidateTag('items');  // 使相关缓存失效
  
  return NextResponse.json(updated);
}

// DELETE
export async function DELETE(
  _req: Request,
  { params }: { params: { id: string } },
) {
  await db.item.delete({ where: { id: Number(params.id) } });
  revalidateTag('items');
  return new Response(null, { status: 204 });
}
```

## 7. App Router vs Pages Router 对比

| 功能 | Pages Router | App Router |
|------|-------------|-----------|
| 路由定义 | `pages/` 目录 | `app/` 目录 |
| 布局 | `_app.js` 单一入口 | `layout.tsx` 嵌套式 |
| 加载状态 | `loading.tsx` | `loading.tsx` (Suspense 集成) |
| 错误处理 | `_error.js` | `error.tsx` (更精细控制) |
| 404 | `404.js` | `not-found.tsx` |
| 数据获取 | `getServerSideProps` | 组件内 `async/await` |
| API | `pages/api/*.ts` | `app/api/*/route.ts` |
| Server Actions | ❌ | ✅ 原生支持 |
| RSC | 部分支持 | ✅ 完整支持 |
| Parallel Routes | ❌ | ✅ 原生支持 |
| Interception | Middleware | Middleware + Route Handlers |
| 文件约定 | 较灵活 | 更严格规范 |
| 推荐 | 维护旧项目 | **新项目首选** |

## 8. 迁移指南

```bash
# 安装迁移工具
npx @next/codemod-mod
```

主要变更点：

```
1. pages/ → app/
   pages/index.tsx → app/page.tsx
   pages/blog/[slug].tsx → app/blog/[slug]/page.tsx

2. _app.js → app/layout.tsx
3. _document.tsx → app/layout.tsx (合并)

4. getServerSideProps → 组件内 async function
5. api/*.ts → api/*/route.ts
6. _error.tsx → error.tsx (不再需要 use-error-boundary)

7. 移除 next/dynamic
8. link → next/link (基本不变)
```

## 9. 总结

```
┌──────────────────────────────────────────────────┐
│      App Router 要点速查                          │
├──────────────────────────────────────────────────┤
│ RSC: Server Components + Client Components 天然融合   │
│ Server Actions: 表单直连服务器，告别手动 fetch     │
│ Layouts: layout.tsx 嵌套，直观清晰              │
│ Parallel Routes: 同一 URL 多个页面并行渲染         │
│ Interception: middleware + route handler 双重保护     │
│ Data Fetching: async component 替代 getServerSideProps │
│ 推荐: 新项目首选 App Router                       │
│ 注意: 需要学习 RSC 概念才能充分利用其优势          │
└──────────────────────────────────────────────────┘
```
