# Next.js 渲染模式详解

## 1. 渲染模式全景图

```
┌─────────────────────────────────────────────────────┐
│                 Next.js 渲染模式                        │
│                                                     │
│  CSR (Client-Side Rendering)                       │
│  ├─ 客户端执行 JS → 生成 DOM                    │
│  ├─ 首屏空白（白屏）                              │
│  ├─ SEO 不友好（初始 HTML 为空壳）                 │
│  └─ 适用: 高交互后台 / SPA 应用                   │
│                                                     │
│  SSR (Server-Side Rendering)                       │
│  ├─ 服务端执行 React → 生成完整 HTML               │
│  ├─ 客户端接收 HTML → hydrate → 可交互               │
│  ├─ 首屏即有内容                                  │
│  ├─ SEO 友好                                      │
│  ├─ TTFB 可能较高（服务端计算耗时）               │
│  └─ 适用: 内容网站 / SEO 重要页面                 │
│                                                     │
│  SSG (Static Site Generation)                     │
│  ├─ 构建时生成静态 HTML 文件                      │
│  ├─ CDN 直接分发，响应最快                        │
│  ├─ 完美的 SEO                                    │
│  ├─ 无法动态生成                                   │
│  └─ 适用: 博客 / 文档 / 营销页                   │
│                                                     │
│  ISR (Incremental Static Regeneration)              │
│  ├─ 结合 SSG + 按需更新                             │
│  ├─ 首次访问返回静态版本                            │
│  ├─ 过期后后台重新生成                               │
│  ├─ 用户看到的是旧数据 → 后台刷新 → 新数据替换       │
│  └─ 适用: 新闻 / 商品 / 内容频繁变化的页面         │
│                                                     │
│  ISR + SWR (Stale While Revalidate)                │
│  ├─ ISR 的优化版                                  │
│  ├─ 先返回缓存（即使过期）→ 后台静默刷新            │
│  ├─ 刷新完成后下次请求返回新数据                  │
│  └─ 用户体验：始终快速，数据可能短暂过期             │
│                                                     │
│  CSR (in-viewport)                                 │
│  ├─ 视口内区域使用 CSR                              │
│  ├─ 其余区域保持 SSG/ISR                           │
│  └─ 适用: 评论 / 广告 / 低优先级交互区域          │
└─────────────────────────────────────────────────────┘
```

## 2. 各模式详细说明

### 2.1 CSR（客户端渲染）

```tsx
// app/page.tsx — 默认是 Server Component，需要标记为客户端
'use client';

export default function HomePage() {
  const [data, setData] = useState(null);
  useEffect(() => { fetch('/api/data').then(r => r.json()).then(setData); }, []);

  if (!data) return <LoadingSpinner />;
  return <div>{JSON.stringify(data)}</div>;
}
```

**何时使用 CSR？**

| 场景 | 推荐 |
|------|------|
| 纯后台管理界面（无需 SEO） | ★★★★★ |
| 需要大量客户端交互（拖拽/画布/游戏） | ★★★★☆ |
| 内容完全依赖用户输入/操作后才显示 | ★★★★☆ |
| 用户已认证的个性化面板 | ★★★★☆ |

### 2.2 SSR（服务端渲染）

```tsx
// app/page.tsx — 默认就是 Server Component
export default async function HomePage() {
  const res = await fetch('https://api.example.com/posts');
  const posts = await res.json();
  
  return (
    <main>
      <h1>Latest Posts</h1>
      <ul>
        {posts.map(post => <li key={post.id}>{post.title}</li>)}
      </ul>
    </main>
  );
}
```

**SSR 的生命周期**：

```
1. Client 请求 /page
2. Server 接收请求
3. Server 执行 HomePage()
4. fetch('/api/posts') 发起网络请求
5. Server 构建 React Virtual DOM
6. Server 将 Virtual DOM 序列化为 HTML 字符串
7. Server 将 HTML + JS bundle 返回 Client
8. Client 接收并渲染 HTML（FCP 快速显示）
9. Client hydrate：执行 JS，绑定事件监听器
10. 页面变为可交互状态
```

**何时使用 SSR？**

| 场景 | 推荐 |
|------|------|
| 首次加载性能重要（TTFB 优先） | ★★★★★ |
| SEO 要求高（搜索引擎爬虫） | ★★★★★ |
| 内容动态变化但不频繁 | ★★★★☆ |
| 社交媒体分享（Open Graph meta） | ★★★★★ |

### 2.3 SSG（静态站点生成）

```tsx
// app/blog/[slug]/page.tsx
// generateStaticParams 声态生成的路径列表
export async function generateStaticParams() {
  const posts = await fetchBlogPosts();
  return posts.map(post => ({ slug: post.slug }));
}

// 或者 generateStaticParams 返回 [] 表示完全动态
```

**SSG 的构建时行为**：

```
next build 时:
  1. 调用 generateStaticParams() → ['hello', 'world', 'foo']
  2. 对每个 params 执行 page() → 生成 HTML
  3. 写入 public/ 目录:
     /blog/hello/index.html
     /blog/world/index.html
     /blog/foo/index.html
  ...

部署后:
  User → CDN → 直接返回 HTML（毫秒级响应）
```

**何时使用 SSG？**

| 场景 | 推荐 |
|------|------|
| 博客 / 文档 / 营销页 | ★★★★★ |
| 内容相对固定 | ★★★★★ |
| 全球 CDN 分发需求 | ★★★★★ |
| 构建时已知所有路径 | ★★★★☆ |

### 2.4 ISR（增量静态再生）

```tsx
// app/products/[id]/page.tsx
import { unstable_cache } from 'next/cache';

// ISR: revalidate 指定重新生成的间隔
export const revalidate = 3600; // 每 1 小时重新生成

export default async function ProductDetail({ params }: { params: { id: string } }) {
  const product = await fetchProduct(params.id);
  
  return (
    <article>
      <h1>{product.name}</h1>
      <p>Price: ${product.price}</p>
      <p>Last updated: {new Date().toLocaleString()}</p>
    </article>
  );
}
```

**ISR 的工作流程**：

```
首次访问 /products/42:
  → 无缓存 → Server 渲染 → 返回 HTML + 存入缓存
  → 用户看到最新数据 (TTFB: ~300ms)

30 分钟后再次访问:
  → 缓存命中 → 返回旧的 HTML (TTFB: ~50ms)
  → 但后台检查发现缓存已超过 3600s
  → 触发后台重新生成
  → 缓存更新为新的 HTML

再下一次访问:
  → 返回新生成的 HTML (TTFB: ~50ms)
```

### 2.5 SWR (Stale-While-Revalidate)

```tsx
// SWR: 先返回旧数据，后台静默刷新
import { unstable_no-store as noStore } from 'next/cache';

export const revalidate = 60; // 每 60 秒重新验证

export default function RealtimePrice() {
  const price = await fetchCryptoPrice('ETH');
  return (
    <span>${price.usd.toLocaleString()}</span>
  );
}

// SWR 配合使用
<RealtimePrice />
```

**SWR 的优势**：

```
传统 ISR:
  请求 → 缓存过期 → 等待服务端重新生成 → 返回新数据
  → 用户等待期间看到 spinner 或空白

SWR:
 请求 → 缓存过期 → ⚡️ 立即返回旧数据（带 stale 头信息）
  → 后台静默重新生成
  → 下次请求时返回新数据（用户几乎无感）
  → 最佳用户体验！
```

## 3. 混合渲染策略

一个真实应用通常**混合使用多种渲染模式**：

```tsx
// app/layout.tsx — 整站布局（SSR）
export default async function RootLayout({ children }) {
  return (
    <html>
      <head>
        <title>My App</title>
      </head>
      <body>
        <Header />  {/* SSG: 导航栏几乎不变 */}
        <main>{children}</main>  {/* 各页面自行决定渲染方式 */}
        <Footer />  {/* SSG: 页脚不变 */}
      </body>
    </html>
  );
}

// app/page.tsx — 首页 (SSR + SWR)
export const revalidate = 60;
export default async function Home() {
  const [featured, latest] = await Promise.all([
    fetchFeaturedPosts(),
    fetchLatestPosts(),
  ]);
  return <Home featured={featured} latest={latest} />;
}

// app/blog/page.tsx — 博客列表 (SSG)
export async function generateStaticParams() { /* ... */ }

// app/dashboard/page.tsx — 仪表板 (CSR)
'use client';
export default function Dashboard() { /* ... */ };

// app/admin/settings/page.tsx — 设置 (ISR)
export const revalidate = 86400;
export default async function Settings() { /* ... */ };
```

## 4. 渲染模式选型决策树

```
你的页面需要？
  ├── SEO 很重要吗？（搜索引擎需要抓取内容）
  │   ├── 否 → CSR 或 SSG
  │   └── 是 → SSR 或 ISR/SWR
  │
  ├── 内容是否在构建时就确定？
  │   ├── 是且路径可知 → SSG（博客/文档/落地页）
  │   └── 否 → SSR / ISR / CSR
  │
  ├── 内容多久变化一次？
  │   ├── 几乎不变 → SSG
  │   ├── 每小时/每天 → ISR / SWR
  │   ├── 每分钟 → SSR
  │   └── 实时/用户驱动 → CSR
  │
  └── 首屏速度要求多快？
      → TTFB < 200ms → SSG/ISR+SWR
      → TTFB < 800ms → SSR
      → TTFC > 1s → CSR 可接受
```

## 5. 性能对比

| 模式 | 首屏 TTFB | SEO | 交互延迟 | 数据新鲜度 | 服务器负载 | 适用复杂度 |
|------|-----------|-----|---------|---------|-----------|----------|
| CSR | ~2~3s | ❌ | 即刻 | 实时 | 无 | 低 |
| SSR | ~200~800ms | ✅ | 需 hydrate | 实时 | 高 | 中 |
| SSG | ~50~150ms | ✅✅ | 即时 | 构建时 | 构建时 | 低 |
| ISR | ~50ms~1.5s | ✅ | 需 hydrate | 按需 | 中 | 中~高 |
| SWR | ~50~150ms | ✅ | 需 hydrate | 近实时 | 中 | 高 |

## 6. 总结

```
┌──────────────────────────────────────────────────┐
│         Next.js 渲染模式速查                      │
├──────────────────────────────────────────────────┤
│ CSR: 纯客户端渲染，SPA 应用                     │
│ SSR: 服务端渲染，每次请求服务端执行            │
│ SSG: 构建时静态生成，CDN 分发                  │
│ ISR: 按需重新生成（revalidate）                  │
│ SWR: 先返回旧数据，后台静默刷新（最佳体验）      │
│ 混合: 不同页面使用不同模式                     │
│ 选择依据: SEO需求 + 数据变化频率 + 性能要求      │
│ 推荐: 首页/详情用 SSR+SWR，文档用 SSG，后台用 CSR │
└──────────────────────────────────────────────────┘
```
