# Next.js 优化与实践

## 1. 图片优化

Next.js 内置的 Image 组件提供了开箱即用的图片优化能力：

### 1.1 基础用法

```tsx
import Image from 'next/image';

export default function Gallery() {
  return (
    <div className="grid grid-cols-3 gap-4">
      <Image
        src="/images/photo.jpg"
        alt="A beautiful photo"
        width={600}
        height={400}
        priority  // 首屏图片优先加载
        placeholder="blur"
        sizes="(max-width: 768px) 100vw, (max-width: 1200px) 50vw"
      />
      <Image
        src="/images/hero.png"
        alt="Hero banner"
        width={1200}
        height={400}
        quality={85}  // 降低质量减小体积
      />
    </div>
  );
}
```

### 1.2 Image 组件做了什么

| 优化手段 | 说明 |
|--------|------|
| **自动 WebP/AVIF 转换** | 根据浏览器能力选择最优格式 |
| **响应式 srcset** | `sizes` + `srcset` 实现艺术方向响应式 |
| **懒加载 (Lazy Loading)** | 进入视口才加载，默认启用 |
| **模糊占位 (Placeholder)** | `placeholder="blur"` 显示模糊预览图 |
| **优先级加载** | `priority` 让首屏图片跳过队列 |
| **优化 (Quality)** | `quality` (1-100) 平衡质量和体积 |
| **尺寸属性** | `width`/`height` 避免 CLS (Cumulative Layout Shift) |
| **远程图片** | 支持外部 URL（需配置 `remotePatterns`） |

### 1.3 next.config 图片配置

```ts
// next.config.ts
const nextConfig = {
  images: {
    formats: ['image/avif', 'image/webp'],
    deviceSizes: [640, 750, 828, 1080, 1200, 1920, 2048, 3840],
    imageSizes: [16, 32, 48, 64, 96, 128, 256, 384],
    remotePatterns: [
      {
        protocol: 'https',
        hostname: 'cdn.example.com',
      },
      {
        pathname: '/images/**',
      },
    ],
  },
};
```

### 1.4 CLS 优化（防止布局偏移）

```tsx
// ✅ 正确：设置 width/height 避免 CLS
<Image src="/hero.jpg" width={1200} height={400} />

// ❌ 未设置尺寸 → 图片加载时页面抖动
<Image src="/hero.jpg" />  // CLS 警告！

// 动态尺寸（未知图片）
// 方案A: 使用 aspect-ratio
<div style={{ position: 'relative', paddingBottom: '56.25%' }}>
  <Image src="/photo.jpg" fill sizes="(max-width: 800px) 100vw" alt="" />
</div>

// 方案B: 运行时获取尺寸
import { getImageProps } from 'next/dist/shared/lib/image-external';
// ...
```

## 2. 字体优化

### 2.1 Next/font（推荐）

Next.js 13+ 提供了优化的字体加载方案：

```tsx
// app/layout.tsx
import { Geist_Mono } from '@next/font/google/geist-mono';
import { Inter } from '@next/font/google/inter';

const geistMono = Geist_Mono({
  subsets: ['latin'],
  variable: '--font-geist-mono',  // CSS 变量
  display: 'swap',  // FOUT swap 策略
});

const inter = Inter({
  subsets: ['latin'],
  variable: '--font-inter',
  display: 'swap',
});

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="zh-CN" className={`${geistMono.variable} ${inter.variable}`}>
      <body className={inter.className}>
        {children}
      </body>
    </html>
  );
}
```

**font-optimize 的优势**：

| | 传统方式 | next/font |
|--|---------|-----------|
| FOIT | Flash Of Unstyled Text（字体闪烁） | ✅ FOUT swap（平滑过渡） |
| Self-hosted | 需自托管 font 文件 | ✅ Vercel CDN 自动托管 |
| Subset | 需手动 subset（易遗漏字符） | ✅ 自动分析页面使用的字符 |
| Preload | 需手动 `<link rel="preload">` | ✅ 自动 preload |
| Performance | 阻塞渲染 | ✅ 异步加载，不阻塞 |
| Size | 通常 200KB+ (含中文) | ✅ 只加载实际使用的字符集 |

### 2.2 本地字体文件

```tsx
import localFont from 'next/font/local';

const customFont = localFont({
  src: [
    { path: '../fonts/custom-font.woff2', style: 'Variable', weight: '100..900' },
    { path: '../fonts/custom-font.woff', style: 'Normal', weight: 400 },
  ],
  display: 'swap',
  variable: '--custom-font',
});

// CSS 中使用
.text { font-family: var(--custom-font); }
```

## 3. Script 加载策略

### 3.1 Script Component

```tsx
import Script from 'next/script';

export default function Page() {
  return (
    <>
      <Script
        src="https://analytics.google.com/gtag/js?id=G-XXXXXXX"
        strategy="afterInteractive"  // 交互后加载（推荐第三方脚本）
        onLoad={() => { window.dataLayer.push(...); }}
      />
      
      <Script
        src="https://cdnjs.cloudflare.com/ajax/libs/lodash/4.17.21/lodash.min.js"
        strategy="lazyOnload"  // 空闲时加载
      />
      
      {/* 关键脚本：内联或提前加载 */}
      <Script
        src="https://cdn.example.com/critical-lib.min.js"
        strategy="beforeInteractive"  // 阻塞渲染直到加载完成
      />
    </>
  );
}
```

**Script 策略选项**：

| Strategy | 行为 | 适用场景 |
|----------|------|---------|
| `beforeInteractive` | **阻塞渲染** | 必须在首屏前加载的关键脚本 |
| `afterInteractive` | 互交后异步加载 | 分析、聊天、非必要脚本 |
| `lazyOnload` | 空闲时加载 | 非关键库、广告、统计 |
| `worker` | Web Worker | 重计算、加密库 |
| `afterDynamic` | 动态导入后 | 特定条件才需要的脚本 |

### 3.2 第三方脚本最佳实践

```tsx
// 推荐的模式：封装常用第三方脚本
// lib/third-party-scripts.tsx
export function ThirdPartyScripts() {
  return (
    <>
      {/* Google Analytics — afterInteractive */}
      <Script
        src="https://www.googletagmanager.com/gtag/js?id=G-XXX"
        strategy="afterInteractive"
      />
      
      {/* Crisp Chat — lazyOnLoad */}
      <Script
        src="https://sp.tcrpt.chat/widget/LxXXX.js"
        strategy="lazyOnload"
        data-widget-id="LxXXX"
      />
      
      {/* Sentry — beforeInteractive (错误监控) */}
      <Script
        src="https://browser.sentry-cdn.com/XXX/tracing.bundle.min.js"
        strategy="beforeInteractive"
      />
    </>
  );
}
```

## 4. Bundle 分析与优化

### 4.1 分析工具

```bash
# 构建时分析
npm run build

# 生产分析
ANALYZE=true npm run build
```

### 4.2 动态导入（Code Splitting）

```tsx
import dynamic from 'next/dynamic';

// 动态导入：只在需要时加载
const HeavyChart = dynamic(() => import('../components/HeavyChart'), {
  { ssr: false,  // 仅在客户端加载
    loading: () => <Skeleton />,
  // 加载中占位
});

const ModalEditor = dynamic(() => import('../components/ModalEditor'), {
  { ssr: false },
  loading: null,
});
```

**Splitting 策略**：

| 策略 | 说明 | 适用场景 |
|------|------|---------|
| `ssr: false` | 客户端专用 | 图表编辑器、富文本编辑器 |
| `loading: () => <Skeleton />` | 加载中占位 | 模态框、下拉菜单 |
| `loading: null` | 无占位 | 折叠面板、可选功能 |
| 默认 (ssr: true) | SSR + 流式传输 | 首屏关键组件 |

### 4.3 Bundle 分析结果解读

```bash
○ (Shared by all routes)  80 kB
  ├─ main-app ........................... 76 kB (95%)
  └─ frameworks ........................  4 kB (5%)

○ (Initial JavaScript) 243 kB (Gzipped: 72 kB)
  ├─ 238 kB  First Load JS
  │   ├─ 199 kB  [frameworks] (83%)
  │   ├─ 29 kB  [main-app] (12%)
  │   └─ 14 kB  [other] (6%)
  └─ 5 kB  Runtime

○ Route (/)  / ........................ 180 kB (Gzipped: 54 kB)
  ├─ 177 kB  First Load JS
  │   ├─ 168 kB  [frameworks] (94%)  ← 太大了!
  │   └─ 9 kB   [page] (5%)
  └─ 3 kB   [runtime]
```

**优化目标**：

| 指标 | 目标值 | 优化手段 |
|------|-------|---------|
| Total JS (< 200KB) | ✅ 减少 shared framework | `output: 'standalone'`, `modularizeImports` |
| Route JS (< 100KB) | ✅ 按路由拆分 | `dynamic()` + `React.lazy()` |
| First Paint < 1.5s | ✅ 关键路径优化 | `loading.tsx`, `priority` image |
| LCP < 2s | ✅ 核心 web vitals | `next/font`, `preconnect`, DNS prefetch |

### 5.2 中间件（Middleware）

```ts
// middleware.ts — 运行在每个匹配的请求之前
import { NextResponse } from 'next/server';
import { NextRequest } from 'next/server';
import { verifyToken } from '@/lib/auth';

export async function middleware(req: NextRequest) {
  // 1. 静态资源跳过中间件
  if (
    req.nextUrl.pathname.startsWith('/_next') ||
    req.nextUrl.pathname.startsWith('/favicon.ico')
  ) {
    return NextResponse.next();
  }

  // 2. CORS 头部处理
  const response = new NextResponse();
  response.headers.set('x-request-id', crypto.randomUUID());
  response.headers.set('x-request-time', Date.now().toString());

  // 3. 认证检查（特定路由）
  if (req.nextUrl.pathname.startsWith('/admin')) {
    const token = req.headers.get('authorization');
    if (!token || !verifyToken(token)) {
      return NextResponse.json({ error: 'Unauthorized' }, { status: 401 });
    }
  }

  // 4. 地理位置检测
  const country = req.geo?.country || 'US';
  response.headers.set('x-detected-country', country);

  return response;
}
```

**中间件匹配规则**：

```
middleware.ts (项目根目录) → 匹配所有请求
  app/middleware.ts → 只匹配 /app/* 路由
  app/dashboard/middleware.ts → 只匹配 /dashboard/*
  
  执行顺序: middleware.ts → app/middleware.ts → app/dashboard/middleware.ts → route handler
```

## 6. 性能监控指标

###  Core Web Vitals

| 指标 | 含义 | 目标值 | 优化手段 |
|------|------|--------|---------|
| **FP (First Paint)** | 首次绘制任何像素 | < 1.5s | SSR/SSG, 关键资源优先 |
| **FCP (First Contentful Paint)** | 首次绘制有意义内容 | < 1.8s | SSR, stream, 优化 DB 查询 |
| **LCP (Largest Contentful Paint)** | 最大内容块绘制完毕 | < 2.5s | 代码分割, 延迟非关键 JS |
| **TBTB (Time to Byte)** | 可交互时间 | < 3s | hydration 优化, streaming |
| **CLS (Cumulative Shift)** | 累积布局偏移 | < 0.1 | 固定图片尺寸 |
| **INP (Input Delay)** | 输入可交互时间 | < 100ms | 事件委托优化 |
| **TTFB (Total Blocking Time)** | 主线程阻塞总时间 | < 200ms | 代码拆分, worker |
