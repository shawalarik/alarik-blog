# Next.js 部署指南

## 概述

Next.js 支持多种部署方式，从一键上线的 **Vercel 平台** 到完全自主的 **Docker 容器化部署**。选择合适的方案取决于你的团队规模、预算和对基础设施的控制需求。

```
┌─────────────────────────────────────────────────────┐
│                   部署方式选择矩阵                     │
├─────────────────────────────────────────────────────┤
│                                                     │
│  快速上线    ──► Vercel（零配置）                      │
│  成本敏感    ──► VPS + Docker / Node.js              │
│  企业私有    ──► Kubernetes / AWS ECS                 │
│  边缘计算    ──► Edge Runtime（Vercel Edge / Cloudflare Workers）│
│  静态导出    ──► CDN / S3 / Cloudflare Pages         │
│                                                     │
└─────────────────────────────────────────────────────┘
```

## 一、Vercel 部署（推荐入门）

### 1.1 为什么首选 Vercel

Vercel 是 Next.js 的官方托管平台，提供：

| 特性 | 说明 |
|------|------|
| **零配置部署** | Git Push 即自动构建部署 |
| **全球边缘网络** | 50+ POP 点自动分发 |
| **Serverless Functions** | 每个 API Route 自动变为函数 |
| **ISR 自动支持** | 页面缓存按需重新验证 |
| **预览部署** | 每次 PR 自动生成独立预览链接 |
| **DDoS 防护** | 内置流量清洗 |

### 1.2 部署步骤

```bash
# 1. 安装 Vercel CLI
npm i -g vercel

# 2. 登录
vercel login

# 3. 部署
vercel

# 4. 生产环境部署
vercel --prod
```

或通过 **GitHub/GitLab 集成**：
1. 访问 [vercel.com/import](https://vercel.com/import)
2. 导入你的仓库
3. Vercel 自动检测 Next.js 项目
4. 点击 **Deploy**

```json
{
  "$schema": "https://openapi.vercel.sh/vercel.json",

    {
      "source": "/old-path/:slug*",
      "destination": "/new-path/:slug*"
    }
  ]
}
```

## 二、Node.js 自托管部署

### 2.1 构建产物导出

```bash
# 构建
npm run build

# 生成的 .next 目录即为部署目标
# 包含：
#   .next/server/     ← SSR/SSG 渲染结果
#   .next/static/     ← 静态资源
#   public/           ← 公共静态文件
#   next.config.*.mjs ← 运行时配置
```

### 2.2 PM2 进程管理

```bash
# 安装 PM2
npm i -g pm2

# 启动应用
pm2 start npm --name "my-app" -- start

# 生产环境推荐 ecosystem.config.js 配置
```

```javascript
// ecosystem.config.js
module.exports = {
  apps: [{
    name: 'next-app',
    script: 'npm',
    args: 'start',
    cwd: './',
    instances: 'max',            // 根据 CPU 核心数自动扩展
    exec_mode: 'cluster',        // 集群模式
    autorestart: true,
    watch: false,
    max_memory_restart: '512M',  // 内存超限时重启
    env: {
      NODE_ENV: 'production',
      PORT: 3000,
    },
  }],
}
```

```bash
pm2 start ecosystem.config.js
pm2 save                          # 保存进程列表
pm2 startup                       # 设置开机自启
```

### 2.3 Nginx 反向代理

```nginx
# /etc/nginx/sites-available/my-app
upstream next_app {
    server 127.0.0.1:3000;
    keepalive 64;               # 保持长连接
}

server {
    listen 80;
    listen [::]:80;
    server_name example.com;

    # 重定向 HTTP 到 HTTPS
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name example.com;

    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

    # Gzip 压缩
    gzip on;
    gzip_types text/plain application/json text/css application/javascript image/svg+xml;
    gzip_min_length 1000;

    location / {
        proxy_pass http://next_app;
        proxy_http_version 1.1;
        
        # 关键头部设置
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket 支持
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # 超时设置
        proxy_read_timeout 120s;
        proxy_send_timeout 120s;
    }

    # 静态资源缓存
    location /_next/static {
        proxy_pass http://next_app;
        expires 365d;
        add_header Cache-Control "public, immutable";
    }
}
```

## 三、Docker 容器化部署

### 3.1 多阶段 Dockerfile

```dockerfile
# ============================
# 阶段一：依赖安装
# ============================
FROM node:20-alpine AS deps
RUN apk add --no-cache libc6-compat
WORKDIR /app

COPY package.json package-lock.json* ./
COPY prisma ./prisma/

# 仅安装 production 依赖（减少镜像体积）
RUN npm ci --ignore-scripts && \
    npx prisma generate

# ============================
# 阶段二：构建
# ============================
FROM node:20-alpine AS builder
WORKDIR /app

COPY --from=deps /app/node_modules ./node_modules
COPY . .

# 分析包体积（可选）
ENV ANALYZE=true
ENV NEXT_ANALYZE_OUTPUT=static

RUN npm run build

# ============================
# 阶段三：运行
# ============================
FROM node:20-alpine AS runner
WORKDIR /app

ENV NODE_ENV=production

# 创建非 root 用户
RUN addgroup --system --gid 1001 nodejs
RUN adduser --system --uid 1001 nextjs

# 复制必要文件
COPY --from=builder /app/public ./public
COPY --from=builder --chown=nextjs:nodejs /app/.next/standalone ./
COPY --from=builder --chown=nextjs:nodejs /app/.next/static ./.next/static

USER nextjs

EXPOSE 3000
ENV PORT=3000
ENV HOSTNAME="0.0.0.0"

CMD ["node", "server.js"]
```

> **注意**：使用 `standalone` 输出模式可大幅减小最终镜像体积。

```javascript
// next.config.ts
/** @type {import('next').NextConfig} */
const nextConfig = {
  output: "standalone",
}

module.exports = nextConfig
```

### 3.2 Docker Compose 编排

```yaml
# docker-compose.yml
version: "3.9"

services:
  app:
    build:
      context: .
      dockerfile: Dockerfile
    restart: always
    ports:
      - "3000:3000"
    environment:
      - DATABASE_URL=postgresql://postgres:password@db:5432/myapp
      - REDIS_URL=redis://redis:6379
      - NEXTAUTH_SECRET=${NEXTAUTH_SECRET}
      - NEXTAUTH_URL=https://example.com
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_started
    networks:
      - app-network

  db:
    image: postgres:16-alpine
    restart: always
    volumes:
      - postgres_data:/var/lib/postgresql/data
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: password
      POSTGRES_DB: myapp
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      timeout: 5s
      retries: 5
    networks:
      - app-network

  redis:
    image: redis:7-alpine
    restart: always
    volumes:
      - redis_data:/data
    networks:
      - app-network

volumes:
  postgres_data:
  redis_data:

networks:
  app-network:
    driver: bridge
```

```bash
# 一键启动整套服务
docker compose up -d --build

# 查看日志
docker compose logs -f app

# 更新部署
docker compose pull && docker compose up -d --build
```

## 四、静态导出（SSG-only）

如果你的页面全是 SSG（无 API Routes / 无 Server Components），可以导出纯静态站点：

```javascript
// next.config.ts
/** @type {import('next').NextConfig} */
const nextConfig = {
  output: "export",  // 静态导出模式
  images: {
    unoptimized: true,  // 静态导出不支持 Image Optimization API
  },
}

module.exports = nextConfig
```

```bash
npm run build
# 产出目录: out/
```

**适用场景**：
- 博客、文档站、落地页
- 部署到 GitHub Pages / Cloudflare Pages / S3
- 无法运行 Node.js 的环境

**限制**：

| 不支持的功能 | 替代方案 |
|--------------|----------|
| `getServerSideProps` | 改为 `generateStaticParams` + ISR |
| API Routes | 迁移到独立后端服务 |
| Middleware | 使用反向代理层处理 |
| `next/image` optimization | 使用 `<img>` 或外部图片服务 |

## 五、CI/CD 自动化部署

### 5.1 GitHub Actions

```yaml
# .github/workflows/deploy.yml
name: Deploy to Production

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: "npm"

      - run: npm ci
      - run: npm run lint
      - run: npm run build
      
      - name: Deploy to Vercel
        uses: amondnet/vercel-action@v25
        with:
          vercel-token: ${{ secrets.VERCEL_TOKEN }}
          vercel-org-id: ${{ secrets.ORG_ID }}
          vercel-project-id: ${{ secrets.PROJECT_ID }}
          vercel-args: "--prod"
```

### 5.2 Docker + SSH 部署

```yaml
# .github/workflows/docker-deploy.yml
name: Build and Deploy Docker

on:
  push:
    tags: ["v*"]

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Login to Registry
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Build and Push
        uses: docker/build-push-action@v5
        with:
          push: true
          tags: |
            ghcr.io/${{ github.repository }}:${{ github.ref_name }}
            ghcr.io/${{ github.repository }}:latest

      - name: Deploy via SSH
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.HOST }}
          username: ${{ secrets.USER }}
          key: ${{ secrets.SSH_KEY }}
          script: |
            cd /opt/my-app
            docker compose pull
            docker compose up -d
            docker image prune -f
```

## 六、性能优化清单

| 优化项 | 效果 | 实现难度 |
|--------|------|----------|
| **启用 ISR** | 减少服务端渲染压力 | 低 |
| **CDN 缓存静态资源** | 降低源站带宽 | 低 |
| **启用 Gzip/Brotli** | 传输量减少 70%+ | 低 |
| **图片格式转换 WebP/AVIF** | 体积减少 50%+ | 低 |
| **代码分割（Dynamic Import）** | 减少 JS Bundle 大小 | 中 |
| **Edge Runtime** | 全球低延迟响应 | 中 |
| **数据库连接池** | 减少连接开销 | 中 |
| **Redis 缓存层** | 减少重复查询 | 高 |
