# Gatsby 静态站点生成实战

## 概述

Gatsby 是基于 React 的静态站点生成（SSG）框架，以 **GraphQL 数据层** 和 **插件生态** 为核心特色。适合内容驱动型网站：博客、文档站、营销页、电商产品展示等。

```
┌──────────────────────────────────────────────────────┐
│                 Gatsby 架构                           │
│                                                      │
│  数据源（Sources）                                   │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐      │
│  │ CMS  │ │ MDX  │ │ REST │ │ GraphQL│ │ DB   │      │
│  └──┬───┘ └──┬───┘ └──┬───┘ └──┬───┘ └──┬───┘      │

│              ▼                                  │
│  ┌──────────────────────┐                        │
│  │  GraphQL 数据层       │  ← gatsby-source-*     │

│                                                      │
│  部署目标：CDN / S3 / Netlify / Cloudflare Pages     │
└──────────────────────────────────────────────────────┘
```

## 一、核心概念

### 1.1 关键术语

| 概念 | 说明 | 类比 |
|------|------|------|
| **Source Plugin** | 从外部系统拉取数据的插件 | 数据搬运工 |
| **Transformer Plugin** | 转换/标准化原始数据插件 | 数据加工厂 |
| **GraphQL Schema** | 构建时生成的统一数据模型 | 数据字典 |
| **Query** | 用 GraphQL 获取所需数据 | 数据订单 |
| **Page** | 由路径 + 组件 + 数据组成的页面 | 成品 |
| **Node** | GraphQL 中的数据单元 | 一条记录 |
| **Static Query** | 组件级数据查询（不可传参） | 固定订单 |
| **Page Query** | 页面级数据查询（可通过 context 传参） | 动态订单 |
| **Slice** | 页面片段懒加载 | 按需组装 |

### 1.2 Gatsby vs 其他 SSG 框架

| 特性 | Gatsby | Next.js (static) | VitePress | Astro |
|------|--------|-------------------|-----------|-------|
| **数据层** | GraphQL（内置） | fetch/API | Markdown frontmatter | Content Collections |
| **插件生态** | ~4000+ 插件 | 中等 | 少 | 增长快 |
| **构建速度** | 慢（大项目） | 快 | 很快 | 很快 |
| **图片优化** | `gatsby-image` 内置 | `next/image` | 手动 | `astro:assets` |
| **学习曲线** | 中高（GraphQL） | 低 | 低 | 低 |
| **适用场景** | 内容密集型网站 | 全栈应用 | 文档站 | 内容站 |
| **运行时** | React 必须 | React 必须 | Vue/可选 | 任意框架/零 JS |

### 3.2 在 gatsby-node.ts 创建动态页面

```typescript
// gatsby-node.ts
import type { GatsbyNode } from "gatsby"
import { createFilePath } from "gatsby-source-filesystem"

// 为每个 Markdown 文件创建 slug 字段
export const onCreateNode: GatsbyNode["onCreateNode"] = ({
  node,
  getNode,
  actions: { createNodeField },
}) => {
  if (node.internal.type === "MarkdownRemark") {
    const slug = createFilePath({ node, getNode })
    createNodeField({
      node,
      name: "slug",
      value: `/blog${slug}`,
    })
  }
}

// 为每篇博文创建页面
export const createPages: GatsbyNode["createPages"] = async ({
  graphql,
  actions: { createPage },
}) => {
  const result = await graphql(`
    query {
      allMarkdownRemark(filter: { fields: { slug: { ne: null } } }) {
        nodes {
          fields {
            slug
          }
          frontmatter {
            tags
          }
        }
      }
    }
  `)

  const posts = result.data?.allMarkdownRemark.nodes ?? []

  // 创建博客详情页
  posts.forEach((post) => {
    createPage({
      path: post.fields.slug,
      component: resolve("./src/templates/blog-post.tsx"),
      context: {
        slug: post.fields.slug,
      },
    })
  })

  // 创建标签聚合页
  const allTags = [...new Set(posts.flatMap(p => p.frontmatter.tags ?? []))]
  allTags.forEach(tag => {
    createPage({
      path: `/tags/${tag}`,
      component: resolve("./src/templates/tag-page.tsx"),
      context: { tag },
    })
  })
}
```

### 3.3 外部数据源（CMS / API）

```typescript
// gatsby-config.ts — 接入 headless CMS
{

// 或者自定义 Source Plugin
// gatsby-source-custom-api.js
exports.sourceNodes = async ({
  actions: { createNode },
  createContentDigest,
  createNodeId,
}) => {
  const res = await fetch("https://api.example.com/posts")
  const posts = await res.json()

  posts.forEach(post => {
    const node = {
      ...post,
      id: createNodeId(`Post-${post.id}`),
      internal: {
        type: "ApiPost",
        contentDigest: createContentDigest(post),
      },
    }
    createNode(node)
  })
}
```

## 四、页面开发

### 4.1 静态页面 + StaticQuery

```tsx
// src/pages/about.tsx
import { graphql, type HeadFC, type PageProps } from "gatsby"
import { StaticImage } from "gatsby-plugin-image"
import Layout from "../components/layout"

export default function AboutPage({ data }: PageProps<Queries.AboutQuery>) {
  return (
    <Layout>
      <h1>About Me</h1>
      <StaticImage
        src="../images/profile.jpg"
        alt="Profile photo"
        width={300}
        height={300
      />
      <p>{data.site?.siteMetadata?.description}</p>
    </Layout>
  )
}

// StaticQuery —— 组件内部查询，不可接受变量
export const query = graphql`
  query AboutQuery {
    site {
      siteMetadata {
        title
        description
      }
    }
  }
`

export const Head: HeadFC<Queries.AboutQuery> = ({ data }) => (
  <>
    <title>About | {data.site?.siteMetadata?.title}</title>
    <meta name="description" content={data.site?.siteMetadata?.description} />
  </>
)
```

### 4.2 动态页面模板 + PageQuery

```tsx
// src/templates/blog-post.tsx
import { graphql, type HeadFC, type PageProps } from "gatsby"
import { GatsbyImage, getImage } from "gatsby-plugin-image"
import Layout from "../components/layout"

export default function BlogPostTemplate({
  data,
  children,
}: PageProps<Queries.BlogPostBySlugQuery>) {
  const post = data.markdownRemark!
  const { title, date, featuredImg, tags } = post.frontmatter!

  return (
    <Layout>
      <article className="blog-post">
        <header>
          <h1>{title}</h1>
          <time dateTime={date}>{new Date(date!).toLocaleDateString()}</time>
          {featuredImg && (
            <GatsbyImage
              image={getImage(featuredImg.childImageSharp!.gatsbyImageData!)!}
              alt={title!}
            />
          )}
        </header>
        {/* Markdown → HTML */}
        <section dangerouslySetInnerHTML={{ __html: post.html! }} />
        {tags && (
          <footer className="tags">
            {tags.map(tag => (
              <span key={tag} className="tag">{tag}</span>
            ))}
          </footer>
        )}
      </article>
    </Layout>
  )
}

// PageQuery —— 可以接受 variables（通过 context 传入）
export const query = graphql`
  query BlogPostBySlug($slug: String!) {
    markdownRemark(fields: { slug: { eq: $slug } }) {
      html
      frontmatter {
        title
        date
        description
        tags
        featuredImg {
          childImageSharp {
            gatsbyImageData(width: 800, layout: CONSTRAINED)
          }
        }
      }
    }
  }
`

export const Head: HeadFC<Queries.BlogPostBySlugQuery> = ({ data }) => {
  const { title, description } = data.markdownRemark?.frontmatter!
  return (
    <>
      <title>{title}</title>
      <meta name="description" content={description} />
      <meta property="og:type" content="article" />
      <meta property="og:title" content={title} />
    </>
  )
}
```

### 4.3 列表页面

```tsx
// src/pages/blog/index.tsx
import { graphql, Link, type PageProps } from "gatsby"
import Layout from "../../components/layout"

export default function BlogIndex({
  data,
}: PageProps<Queries.BlogIndexQuery>) {
  const posts = data.allMarkdownRemark.nodes

  return (
    <Layout>
      <h1>Blog</h1>
      <ol className="post-list">
        {map((post) => {
          const { slug } = post.fields!
          const { title, date, description } = post.frontmatter!

          return (
            <li key={slug!}>
              <Link to={slug!} itemProp="url">
                <article itemScope itemType="http://schema.org/Article">
                  <h2 itemProp="headline">{title}</h2>
                  <small>{new Date(date!).toLocaleDateString()}</small>
                  {description && <p itemProp="description">{description}</p>}
                </article>
              </Link>
            </li>
          )
        })}
      </ol>
    </Layout>
  )
}

export const query = graphql`
  query BlogIndex {
    allMarkdownRemark(
      sort: { frontmatter: { date: DESC } }
      filter: { fileAbsolutePath: { regex: "/blog/" } }
    ) {
      nodes {
        excerpt
        fields { slug }
        frontmatter { title, date, description }
      }
    }
  }
```

## 六、SEO 优化

### 6.1 SEO 组件封装

```tsx
// components/seo.tsx
import { useStaticQuery, graphql } from "gatsby"

interface SEOProps {
  title: string
  description?: string
  image?: string
  article?: boolean
}

export default function SEO({ title, description, image, article }: SEOProps) {
  const { site } = useStaticQuery(graphql`
    query {
      site {
        siteMetadata {
          title
          description
          siteUrl
        }
      }
    }
  `)

  const seo = {
    title: `${title} | ${site.siteMetadata!.title}`,
    description: description || site.siteMetadata!.description,
    image: image ? `${site.siteMetadata!.siteUrl}${image}` : undefined,
    url: typeof window !== "undefined" ? window.location.href : "",
  }

  return (
    <>
      <title>{seo.title}</title>
      <meta name="description" content={seo.description} />
      {seo.image && <meta name="image" content={seo.image} />}
      {article && <meta property="og:type" content="article" />}
      <meta property="og:title" content={seo.title} />
      <meta property="og:description" content={seo.description} />
      {seo.image && <meta property="og:image" content={seo.image} />}
      <meta name="twitter:card" content="summary_large_image" />
    </>
  )
}
```

## 八、Gatsby 的优缺点

### 优点

| 优点 | 说明 |
|------|------|
| **丰富的插件生态** | ~4000+ 插件覆盖各种场景 |
| **GraphQL 统一数据层** | 无论数据来源，统一用 GraphQL 查询 |
| **内置性能优化** | 图片优化、代码分割、预加载、资源提示 |
| **TypeScript 一等公民** | 完善的类型推导 |
| **PWA 支持** | Manifest / Offline / Service Worker |

### 缺点

| 缺点 | 影响 | 应对策略 |
|------|------|----------|
| **构建速度慢** | 大项目构建可达 10-30 分钟 | 增量构建 / DSR (Deferred Static Generation) |
| **GraphQL 学习成本** | 需要了解 GraphQL 查询语法 | 使用 `gatsby-plugin-typegen` |
| **升级困难** | 主版本升级常有 breaking changes | 锁定版本 / 关注 changelog |
| **内存占用高** | 构建过程需要大量内存 | 增大 Node.js 内存限制 `--max-old-space-size` |
| **Runtime 较大** | 即使简单页面也包含 React runtime | 考虑 Astro（零 JS 默认） |

## 九、Gatsby 还适用吗？（2026 年视角）

```
场景评估矩阵：

博客 / 文档站
  ├── 内容稳定 → ✅ Gatsby（成熟稳定）
  └── 频繁更新 → 🤔 考虑 Astro / Next.js ISR

营销页 / 产品展示
  ├── SEO 重要 → ✅ Gatsby（完善的 SEO 工具链）
  └── 需要交互 → ✅ Gatsby（React 生态丰富）

电商展示
  ├── 纯展示 → ✅ Gatsby + headless CMS
  └── 有购物车 → ❌ 建议 Next.js（SSR 需求）

大型内容平台
  ├── 文章 > 500 → ⚠️ 构建速度成为瓶颈
  └── 推荐 → Next.js ISR / DSG 或 Astro
```
