# Webpack 核心原理深度解析

## 概述

Webpack 是一个**静态模块打包器**（static module bundler）。它递归地构建一个依赖图（dependency graph），其中包含应用需要的每个模块，然后将这些模块打包成一个或多个 bundle。

```
┌─────────────────────────────────────────────────────────┐
│                   Webpack 构建流程                        │
│                                                         │
│  Entry (入口)                                           │
│    │                                                    │
│    ▼                                                    │
│  ┌─────────────┐                                       │
│  │  解析入口文件  │                                       │
│  │  (entry)     │                                       │
│  └──────┬──────┘                                       │
│         ▼                                               │
│  ┌──────────────────────────────────────────┐           │
│  │           Module Resolution               │           │
│  │  (import / require → 找到对应文件)         │           │
│  │                                          │           │
│  │  resolve.modules → resolve.extensions     │           │
│  │  → resolve.alias → mainFields → ...       │           │
│  └──────────────────┬───────────────────────┘           │
│                     ▼                                   │
│  ┌──────────────────────────────────────────┐           │
│  │           Loader Chain                    │           │
│  │                                          │           │
│  │  raw-loader → babel-loader               │           │
│  │  → sass-loader → css-loader             │           │
│  │  → style-loader / mini-css-extract-plugin│          │
│  └──────────────────┬───────────────────────┘           │
│                     ▼                                   │
│  ┌──────────────────────────────────────────┐           │
│  │           Dependency Graph               │           │
│  │  (所有模块及其依赖关系的有向图)             │           │
│  └──────────────────┬───────────────────────┘           │
│                     ▼                                   │
│  ┌──────────────────────────────────────────┐           │
│  │           Plugins                        │           │
│  │                                          │           │
│  │  HtmlWebpackPlugin                     │           │
│  │  MiniCssExtractPlugin                   │           │
│  │  DefinePlugin / SplitChunksPlugin        │           │
│  └──────────────────┬───────────────────────┘           │
│                     ▼                                   │
│  Output (出口)                                          │
│    bundle.js / bundle.[contenthash].js                   │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 一、核心概念

### 1.1 五大核心概念

| 概念 | 说明 | 示例 |
|------|------|------|
| **Entry（入口）** | 构建起始点，Webpack 从这里开始构建依赖图 | `entry: './src/index.js'` |
| **Output（出口）** | 输出文件的路径和命名规则 | `output: { path, filename }` |
| **Loader（加载器）** | 让 Webpack 处理非 JS 文件 | `babel-loader`, `sass-loader` |
| **Plugin（插件）** | 扩展 Webpack 功能，作用于整个构建过程 | `HtmlWebpackPlugin` |
| **Mode（模式）** | 内置环境优化 | `development` / `production` / `none` |

### 1.2 Entry 配置方式

```javascript
// webpack.config.js
module.exports = {
  // 方式一：单入口（字符串）
  entry: "./src/main.js",
  
  // 方式二：多入口（对象）— 多页应用常用
  entry: {
    main: "./src/main.js",
    admin: "./src/admin.js",
    vendor: ["react", "react-dom"], // 分离第三方库
  },
  
  // 方式三：动态入口（函数）
  entry: () => ({
    main: "./src/main.js",
    // 根据条件动态决定入口
    ...(process.env.ADMIN ? { admin: "./src/admin.js" } : {}),
  }),
}
```

### 1.3 Output 配置

```javascript
const path = require("path")

module.exports = {
  output: {
    path: path.resolve(__dirname, "dist"),
    
    // 文件名模板
    filename: "[name].[contenthash:8].js",  // 内容 hash，缓存友好
    
    // 动态导入的 chunk 命名
    chunkFilename: "[id].[contenthash:8].chunk.js",
    
    // 静态资源公共路径（CDN）
    publicPath: process.env.CDN_URL || "/",
    
    // 清理上次构建
    clean: true,
    
    // 输出 library（库模式）
    library: "MyLibrary",
    libraryTarget: "umd",
  },
}
```

## 二、Loader 机制

### 2.1 Loader 的本质

Loader 是一个**导出为函数的 Node.js 模块**，接收源文件内容作为输入，返回转换后的内容。它像管道一样**从右到左**执行（最后一个 loader 最先执行）。

```
原始文件内容
  │
  ▼
┌──────────┐   ┌──────────┐   ┌──────────┐
│ css-loader│ → │ postcss-  │ → │ style-   │
│          │   │ loader   │   │ loader   │
│ (第3个)  │   │ (第2个)  │   │ (第1个)  │
└──────────┘   └──────────┘   └──────────┘
  │             │             │
  ▼             ▼             ▼
解析@import     添加前缀      注入<style>
转成JS字符串    压缩CSS       到DOM中
  
执行顺序：style-loader → postcss-loader → css-loader
配置顺序：css-loader, postcss-loader, style-loader（从后往前）
```

### 2.2 自定义 Loader

```javascript
// loaders/markdown-loader.js — 将 Markdown 转 HTML
const marked = require("marked")

module.exports = function markdownLoader(source) {
  // this 是 loader context，提供丰富的 API
  const html = marked.parse(source)
  
  // 返回可执行的 JS 字符串
  return `
    export default ${JSON.stringify(html)};
    
    /* 或者使用 this.callback 支持异步 */
  `
}

// 异步 loader
module.exports = function asyncMarkdownLoader(source) {
  const callback = this.async() // 声明异步
  
  setTimeout(() => {
    callback(null, `export default ${JSON.stringify(source.toUpperCase())}`)
  }, 100)
}
```

### 2.3 常用 Loader 组合

```javascript
module.exports = {
  module: {
    rules: [
      // JavaScript/TypeScript
      {
        test: /\.(tsx?|jsx?)$/,
        exclude: /node_modules/,
        use: [
          {
            loader: "babel-loader",
            options: {
              cacheDirectory: true, // 缓存编译结果
              presets: [
                "@babel/preset-env",
                "@babel/preset-react",
                "@babel/preset-typescript",
              ],
            },
          },
        ],
      },

      // CSS / SCSS
      {
        test: /\.scss$/,
        use: [
          // 开发环境注入 <style>；生产环境提取为独立文件
          isDev ? "style-loader" : MiniCssExtractPlugin.loader,
          {
            loader: "css-loader",
            options: {
              modules: {
                localIdentName: "[local]--[hash:base64:5]",
              },
            },
          },
          {
            loader: "postcss-loader",
            options: { postcssOptions: { plugins: ["autoprefixer"] } },
          },
          "sass-loader",
        ],
      },

      // 图片资源
      {
        test: /\.(png|jpe?g|gif|svg|webp)$/i,
        type: "asset",  // Webpack 5 内置资源模块
        parser: {
          dataUrlCondition: {
            maxSize: 8 * 1024, // <8KB 转 base64 inline
          },
        },
        generator: {
          filename: "images/[name].[hash:8][ext]",
        },
      },

      // 字体
      {
        test: /\.(woff2?|eot|ttf|otf)$/,
        type: "asset/resource",
        generator: {
          filename: "fonts/[name].[hash:8][ext]",
        },
      },
    ],
  },
}
```

## 三、Module Resolution（模块解析）

### 3.1 解析规则

当 Webpack 遇到 `import "./Button"` 或 `require("lodash")` 时，按以下顺序解析：

```
resolve.import (相对路径)
  │
  ├─ 以 ./ 或 ../ 开头？
  │   └→ 相对路径解析
  │
  └─ 否则（裸模块名）
      │
      ▼
  resolve.modules (默认: ["node_modules"])
      │
      ├─ 逐个目录查找
      │   └→ 找到 package.json?
      │       ├─ resolve.mainFields (["browser", "module", "main"])
      │       └─ 找到入口文件
      │
      ├─ 都没找到？
      │   └→ resolve.fallback (Node.js polyfill)
      │
      └─ 还没找到？→ 报错 MODULE_NOT_FOUND
```

### 3.2 常用 Resolve 配置

```javascript
module.exports = {
  resolve: {
    // 导入时省略扩展名
    extensions: [".ts", ".tsx", ".js", ".jsx", ".json"],
    
    // 路径别名
    alias: {
      "@": path.resolve(__dirname, "src"),
      "@components": path.resolve(__dirname, "src/components"),
      "@utils": path.resolve(__dirname, "src/utils"),
      
      // 修复某些包的路径问题
      "react-dom$": "react-dom/client",
    },
    
    // 查找范围
    modules: ["node_modules"],
    
    // 主字段优先级（ESM 优先）
    mainFields: ["browser", "module", "main"],
  },
}
```

## 四、插件（Plugins）

### 4.1 Plugin 与 Loader 的区别

| 维度 | Loader | Plugin |
|------|--------|--------|
| **作用位置** | 模块级别（文件转换） | 构建级别（整体流程） |
| **时机** | 模块被加载时 | 整个构建生命周期的钩子 |
| **功能** | "翻译"文件内容 | 打包优化、资源管理、环境注入等 |
| **使用方式** | `rules[].use[]` | `plugins.push()` |
| **执行次数** | 每匹配到一个文件执行一次 | 通常在特定阶段执行一次 |

### 4.2 必备插件清单

```javascript
const HtmlWebpackPlugin = require("html-webpack-plugin")
const MiniCssExtractPlugin = require("mini-css-extract-plugin")
const { DefinePlugin } = require("webpack")
const CssMinimizerPlugin = require("css-minimizer-webpack-plugin")
const TerserPlugin = require("terser-webpack-plugin")
const ForkTsCheckerWebpackPlugin = require("fork-ts-checker-webpack-plugin")
const BundleAnalyzerPlugin = require("webpack-bundle-analyzer")

module.exports = {
  plugins: [
    new HtmlWebpackPlugin({
      template: "./public/index.html",
      inject: true,
      minify: isProd && {
        removeComments: true,
        collapseWhitespace: true,
        removeRedundantAttributes: true,
      },
    }),

    // CSS 提取
    new MiniCssExtractPlugin({
      filename: "css/[name].[contenthash:8].css",
      chunkFilename: "css/[id].[contenthash:8].chunk.css",
    }),

    // 环境变量注入
    new DefinePlugin({
      "process.env.NODE_ENV": JSON.stringify(process.env.NODE_ENV),
      "process.env.API_URL": JSON.stringify(process.env.API_URL),
      "__VERSION__": JSON.stringify(require("./package.json").version),
    }),

    // TypeScript 类型检查（独立进程，不阻塞构建）
    new ForkTsCheckerWebpackPlugin({
      typescript: {
        configFile: path.resolve(__dirname, "tsconfig.json"),
      },
    }),
    
    // Bundle 分析（可选）
    ...(process.env.ANALYZE ? [new BundleAnalyzerPlugin()] : []),
  ],

  optimization: {
    minimizer: [
      new TerserPlugin({ // JS 压缩
        parallel: true, // 多线程压缩
        terserOptions: {
          compress: { drop_console: isProd, drop_debugger: isProd },
        },
      }),
      new CssMinimizerPlugin(), // CSS 压缩
    ],
  },
}
```

## 五、代码分割（Code Splitting）

### 5.1 SplitChunks 策略

```javascript
module.exports = {
  optimization: {
    splitChunks: {
      chunks: "all", // 同步+异步 chunk 都参与分割
      
      // 分组策略
      cacheGroups: {
        // 第三方库
        vendor: {
          test: /[\\/]node_modules[\\/]/,
          name: "vendor",
          priority: 10,
          chunks: "all",
        },
        
        // React 生态单独分组
        react: {
          test: /[\\/]node_modules[\\/](react|react-dom)[\\/]/,
          name: "react-vendor",
          priority: 20,
          chunks: "all",
        },
        
        // 公共业务代码
        common: {
          name: "common",
          minChunks: 2, // 至少被 2 个 chunk 引用
          priority: 5,
          reuseExistingChunk: true,
          chunks: "all",
        },
        
        // CSS 单独分组
        styles: {
          type: "css/mini-extract",
          name: "styles",
          priority: 30,
          enforce: true,
        },
      },
    },
  },
}
```

### 5.2 动态导入（Lazy Loading）

```typescript
// 方式一：语法层面（推荐）
const Dashboard = lazy(() => import("./Dashboard"))
const AdminPanel = lazy(() => import(/* webpackChunkName: "admin" */ "./Admin"))

// 方式二：带魔法注释
const HeavyComponent = lazy(() => import(
  /* webpackChunkName: "heavy-component" */
  /* webpackPrefetch: true */  // 预取（空闲时加载）
  /* webpackPreload: true */   // 预加载（与父 chunk 并行）
  "./HeavyComponent"
))

// 使用
function App() {
  return (
    <Suspense fallback={<Skeleton />}>
      <Dashboard />
    </Suspense>
  )
}
```

## 六、HMR（热模块替换）

### 6.1 HMR 原理

```
文件变更
  │
  ▼
Webpack Dev Server (watch)
  │
  ├─ 重新编译变更的模块
  │
  ├─ 通过 WebSocket 推送更新通知给浏览器
  │   { type: "hmr", updates: [{ accepted: true, chain: [...] }] }
  │
  └─ 浏览器接收
      │
      ├─ 如果模块接受 HMR → 替换模块，保持状态
      │
      └─ 如果不接受 → 触发整页刷新
```

### 6.2 HMR Accept 写法

```typescript
// Counter.module.ts — 支持 HMR 的模块
let count = 0

// 告诉 Webpack 此模块可以热替换
if (module.hot) {
  module.hot.accept()
  // 当此模块变化时：
  // 1. 执行新模块代码
  // 2. 不刷新页面
  // 3. 但注意：count 会重置为 0！
}

export function increment() { return ++count }
export function getCount() { return count }

// 更好的做法：将状态与 UI 分离
// counter-state.ts — 状态在外部
let state = { count: 0 }

export const getState = () => state
export const setState = (partial: Partial<typeof state>) => {
  state = { ...state, ...partial }
}

// counter-ui.tsx — UI 接受 HMR
if (module.hot) {
  module.hot.accept()
  // UI 更新时，state 保持不变 ✅
}
```

## 七、构建性能优化

| 优化项 | 方法 | 效果 |
|--------|------|------|
| **持久化缓存** | `cache: { type: "filesystem" }` | 二次构建加速 90% |
| **多线程** | `thread-loader` / `TerserPlugin.parallel` | CPU 密集任务提速 |
| **排除不必要扫描** | `exclude: /node_modules/` | 减少 loader 执行 |
| **减少解析范围** | `resolve.plugins` + `alias` | 加速模块查找 |
| **DllPlugin** | 预编译第三方库（v5 中较少需要） | 减少重复编译 |
| **Source Map 选择** | 生产环境 `hidden-source-map` | 减少构建开销 |
