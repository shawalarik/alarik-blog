# Webpack 插件开发实战

## 概述

Webpack 的插件机制是其**最强大的扩展能力**。通过 Tapable 事件流架构，开发者可以在构建生命周期的任意节点插入自定义逻辑。

```
┌──────────────────────────────────────────────────────────┐
│              Webpack 插件生命周期                          │
│                                                          │
│  environment (初始化)                                     │
│    └─ afterEnvironment                                   │
│                                                          │
│  entry (入口配置)                                         │
│    └─ afterPlugins                                       │
│                                                          │
│  compiler (编译器实例创建完成)                             │
│    ├─ entryOption                                        │
│    ├─ afterPlugins                                       │
│    ├─ beforeRun                                          │
│    ├─ run                                               │
│    ├─ watchRun (dev server 模式)                         │
│    └─ normalModuleFactory / contextModuleFactory         │
│                                                          │
│  compilation (每次编译)                                   │
│    ├─ thisCompilation                                    │
│    ├─ compilation                                       │
│    ├─ make (构建依赖图)                                  │
│    │   ├─ addEntry                                      │
│    │   ├─ seal                                          │
│    │   └─ optimize                                      │
│    ├─ afterCompile                                     │
│    └─ emit (输出产物到文件系统)                           │
│                                                          │
│  done (编译完成)                                          │
│    └─ afterDone                                         │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

## 一、插件基础结构

### 1.1 插件的骨架

```javascript
// MyWebpackPlugin.js
class MyWebpackPlugin {
  constructor(options = {}) {
    this.options = options
  }

  /**
   * Webpack 在注册插件时会调用 apply 方法，
   * 传入 compiler 实例
   */
  apply(compiler) {
    const pluginName = MyWebpackPlugin.name

    // 注册同步钩子
    compiler.hooks.run.tap(pluginName, (compiler) => {
      console.log("🚀 Webpack 开始构建！")
    })

    // 注册异步钩子
    compiler.hooks.emit.tapAsync(
      pluginName,
      (compilation, callback) => {
        console.log("📦 即将输出产物...")
        callback()
      }
    )
  }
}

module.exports = MyWebpackPlugin
```

### 1.2 Tapable Hook 类型

| Hook 类型 | 同步方法 | 说明 |
|-----------|---------|------|
| **SyncHook** | `.tap(name, fn)` | 同步、无返回值 |
| **SyncBailHook** | `.tap(name, fn)` | 同步、可中断（返回非 undefined 则终止） |
| **SyncWaterfallHook** | `.tap(name, fn)` | 同步、瀑布流（每个函数接收上一个的返回值） |
| **AsyncSeriesHook** | `.tapAsync(name, fn)` / `.tapPromise(name, fn)` | 异步串行 |
| **AsyncParallelHook** | `.tapAsync(name, fn)` / `.tapPromise(name, fn)` | 异步并行 |
| **AsyncSeriesBailHook** | `.tapAsync` / `.tapPromise` | 异步串行 + 可中断 |
| **AsyncParallelBailHook** | `.tapAsync` / `.tapPromise` | 异步并行 + 可中断 |
| **AsyncSeriesWaterfallHook** | `.tapAsync` / `.tapPromise` | 异步串行 + 瀑布流 |

## 二、Compiler vs Compilation

这是理解插件开发的**最关键区别**：

```
┌─────────────────────────────────────────────┐
│              Compiler (全局唯一)              │
│                                             │
│  生命周期: 整个 Webpack 运行期间               │
│  用途: 全局配置、监听 run/done 等事件         │
│  访问方式: compiler.options                  │
│                                             │
│  ┌─────────────┐  ┌─────────────┐           │
│  │Compilation 1│  │Compilation 2│  ...      │
│  │ (首次构建)   │  │ (HMR 重建)  │           │
│  └─────────────┘  └─────────────┘           │
│                                             │
└─────────────────────────────────────────────┘

┌─────────────┐
│ Compilation │ ← 每次构建创建新实例
└─────────────┘
  生命周期: 一次构建过程
  用途: 模块、chunk、assets 的操作
  访问方式: compilation.assets / compilation.modules
```

## 三、实战案例

### 3.1 案例 1：生成文件列表

```javascript
// plugins/FileListPlugin.js
const fs = require("fs").promises
const path = require("path")

class FileListPlugin {
  constructor(options = {}) {
    this.filename = options.filename || "file-list.md"
  }

  apply(compiler) {
    compiler.hooks.emit.tapAsync("FileListPlugin", async (compilation, callback) => {
      const assets = []
      
      for (const filename in compilation.assets) {
        const source = compilation.assets[filename].source()
        assets.push({
          name: filename,
          size: `${(source.length / 1024).toFixed(2)} KB`,
        })
      }

      const content = [
        "# Build Assets\n",
        "| File Name | Size |",
        "|-----------|------|",
        ...assets.map(a => `| ${a.name} | ${a.size} |`),
      ].join("\n")

      // 向产物中添加新文件
      compilation.assets[this.filename] = {
        source: () => content,
        size: () => Buffer.byteLength(content),
      }

      callback()
    })
  }
}

module.exports = FileListPlugin

// 使用
// webpack.config.js
// const FileListPlugin = require("./plugins/FileListPlugin")
// module.exports = { plugins: [new FileListPlugin()] }
```

### 3.2 案例 2：自动压缩图片

```javascript
// plugins/ImageOptimizePlugin.js
const imagemin = require("imagemin")
const imageminWebp = require("imagemin-webp")
const path = require("path")

class ImageOptimizePlugin {
  constructor(options = {}) {
    this.quality = options.quality ?? 80
    this.test = options.test ?? /\.(png|jpe?g)$/
  }

  apply(compiler) {
    compiler.hooks.emit.tapAsync("ImageOptimizePlugin", async (compilation, callback) => {
      const imageAssets = Object.keys(compilation.assets).filter(name =>
        this.test.test(name)
      )

      if (imageAssets.length === 0) {
        callback()
        return
      }

      for (const filename of imageAssets) {
        try {
          const source = compilation.assets[filename].source()
          const buffer = Buffer.isBuffer(source) 
            ? source 
            : Buffer.from(source)

          // 压缩并转为 WebP
          const result = await imagemin.buffer(buffer, {
            plugins: [imageminWebp({ quality: this.quality })],
          })

          const webpName = filename.replace(/\.\w+$/, ".webp")
          
          compilation.assets[webpName] = {
            source: () => result,
            size: () => result.length,
          }
        } catch (err) {
          compilation.warnings.push(new Error(`图片优化失败 ${filename}: ${err.message}`))
        }
      }

      callback()
    })
  }
}

module.exports = ImageOptimizePlugin
```

### 3.3 案例 3：构建耗时统计

```javascript
// plugins/BuildTimeAnalyzer.js
class BuildTimeAnalyzer {
  apply(compiler) {
    let startTime
    const phaseTimings = {}

    // 开始计时
    compiler.hooks.run.tap("BuildTimeAnalyzer", () => {
      startTime = Date.now()
      console.log("\n⏱️  开始构建...")
    })

    compiler.hooks.watchRun.tap("BuildTimeAnalyzer", (compiler) => {
      startTime = Date.now()
      const changedFiles = Array.from(compiler.modifiedFiles || [])
      if (changedFiles.length > 0) {
        console.log(`\n🔄 文件变更: ${changedFiles.join(", ")}`)
      }
    })

    // 各阶段计时
    compiler.hooks.compile.tap("BuildTimeAnalyzer", () => {
      phaseTimings.compile = Date.now()
    })

    compiler.hooks.make.tap("BuildTimeAnalyzer", () => {
      phaseTimings.make = Date.now()
    })

    compiler.hooks.emit.tap("BuildTimeAnalyzer", () => {
      phaseTimings.emit = Date.now()
    })

    // 输出报告
    compiler.hooks.done.tap("BuildTimeAnalyzer", (stats) => {
      const totalTime = Date.now() - startTime
      
      console.log("\n⏱️  构建时间分析:")
      console.log(`  总计: ${totalTime}ms`)
      console.log(`  compile: ${phaseTimings.make - phaseTimings.compile}ms`)
      console.log(`  make: ${phaseTimings.emit - phaseTimings.make}ms`)
      console.log(`  emit: ${Date.now() - phaseTimings.emit}ms`)
      
      if (stats.hasErrors()) {
        console.error(`  ❌ ${stats.errorsCount} 个错误`)
      }
      if (stats.hasWarnings()) {
        console.warn(`  ⚠️  ${stats.warningsCount} 个警告`)
      }
    })
  }
}

module.exports = BuildTimeAnalyzer
```

### 3.4 案例 4：自定义 Loader + Plugin 组合

```javascript
// plugins/i18n-markdown-plugin.js — 国际化 Markdown 处理
const marked = require("marked")

class I18nMarkdownPlugin {
  constructor(options = {}) {
    this.locales = options.locales ?? ["zh", "en"]
    this.defaultLocale = options.defaultLocale ?? "zh"
  }

  apply(compiler) {
    compiler.hooks.compilation.tap("I18nMarkdownPlugin", (compilation) => {
      // 注册自定义资源类型
      compilation.hooks.processAssets.tap(
        { name: "I18nMarkdownPlugin", stage: compiler.PROCESS_ASSETS_STAGE_ADDITIONS },
        (assets) => {
          // 遍历所有 md 文件
          Object.keys(assets)
            .filter(name => name.endsWith(".md"))
            .forEach(filename => {
              const source = assets[filename].source()
              
              // 为每种语言生成分离的 JSON
              this.locales.forEach(locale => {
                const i18nData = this.extractI18n(source, locale)
                const outName = filename.replace(".md", `.${locale}.json`)
                
                assets[outName] = {
                  source: () => JSON.stringify(i18nData, null, 2),
                  size: () => 0, // 会在调用时计算
                }
              })
            })
        }
      )
    })
  }

  extractI18n(markdownContent, locale) {
    // 解析 frontmatter 和正文，按 locale 提取
    const frontmatterMatch = markdownContent.match(/^---\n([\s\S]*?)\n---/)
    const frontmatter = frontmatterMatch 
      ? Object.fromEntries(frontmatterMatch[1].split("\n").map(l => l.split(": ").map(s => s.trim())))
      : {}

    return {
      title: frontmatter[`title_${locale}`] ?? frontmatter.title ?? "",
      content: marked.parse(markdownContent.replace(/^---[\s\S]*?---\n/, "")),
      locale,
    }
  }
}

module.exports = I18nMarkdownPlugin
```

### 4.2 使用 `debug` 模块

```javascript
const debug = require("debug")("webpack:my-plugin")

class DebuggablePlugin {
  apply(compiler) {
    debug("plugin registered with options: %O", this.options)

    compiler.hooks.thisCompilation.tap("DebuggablePlugin", (compilation) => {
      debug("new compilation created: %s", compilation.name)
      
      // 打印所有模块信息
      compilation.hooks.finishModules.tap("DebuggablePlugin", (modules) => {
        debug("total modules: %d", modules.size)
      })
    })
  }
}
```

## 五、最佳实践

| 原则 | 说明 |
|------|------|
| **命名规范** | 插件名称大驼峰，hooks 使用一致的前缀 |
| **错误处理** | 使用 `compilation.errors` / `compilation.warnings` 收集错误而非 throw |
| **异步兼容** | 尽量使用 tapAsync/tapPromise，避免阻塞主线程 |
| **幂等性** | 插件多次执行结果应相同 |
| **选项校验** | 构造函数中校验参数合法性 |
| **版本兼容** | 明确标注支持的 Webpack 版本范围 |
| **性能注意** | emit 阶段的操作影响构建速度，避免重操作 |
