# Vite 核心原理深度解析

## 概述

Vite（法语意为"快速"）由尤雨溪于 2020 年创建，其核心理念是利用**原生 ESM (ECMAScript Modules)** 在开发环境中实现极速启动，同时使用 **Rollup** 进行生产构建。

```
┌─────────────────────────────────────────────────────────┐
│                   Vite 架构双模                          │
│                                                         │
│  ┌──────────────────┐    ┌──────────────────────────┐   │
│  │   Development     │    │     Production            │   │
│  │                   │    │                           │   │
│  │  基于 Native ESM  │    │     基于 Rollup 打包      │   │
│  │                   │    │                           │   │
│  │  ┌─────────────┐  │    │  ┌─────────────────────┐  │   │
│  │  │ Dev Server  │  │    │  │ Rollup Bundler      │  │   │
│  │  │ (esbuild)   │  │    │  │                     │  │   │
│  │  │             │  │    │  │  • 代码分割          │  │   │
│  │  │ • 按需编译   │  │    │  │  • Tree Shaking     │  │   │
│  │  │ • HMR 快速  │  │    │  │  • 压缩优化          │  │   │
│  │  │ • 请求转发   │  │    │  │  • 产物哈希          │  │   │
│  │  └─────────────┘  │    │  │  • CSS 提取          │  │   │
│  │                   │    │  └─────────────────────┘  │   │
│  │  启动: < 100ms    │    │                           │   │
│  │  HMR:   ~ 20ms    │    │  产物: 优化的 static files │   │
│  └──────────────────┘    └──────────────────────────┘   │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 一、为什么 Vite 这么快？

### 1.1 传统构建工具的问题

```
传统工具 (Webpack/Parcel):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
│  启动流程:
│
│  1. 扫描所有文件
│  2. 构建完整依赖图
│  3. 对每个模块执行 Loader
│  4. 生成 bundle
│  5. 启动 dev server
│
│  问题: 即使只修改一个文件，也要重新走完整流程
│  时间: 大型项目 30s ~ 5min+
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━


Vite:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
│  启动流程:
│
│  1. 启动 dev server (瞬间)
│  2. 浏览器请求入口 HTML
│  3. 浏览器解析 import → 请求各模块
│  4. Vite 按需转换并返回 (esbuild)
│
│  核心: 不预打包！按需编译！
│  时间: < 100ms (任何规模项目)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 1.2 性能对比数据

| 操作 | Webpack 5 | Vite 6 | 提升 |
|------|-----------|--------|------|
| **冷启动 (1000 模块)** | ~14s | ~0.3s | **~47x** |
| **热更新 (单文件)** | ~800ms | ~20ms | **~40x** |
| **生产构建 (1000 模块)** | ~25s | ~8s | **~3x** |
| **内存占用** | ~500MB | ~200MB | **2.5x** |

> 注：数据基于实际基准测试，具体因项目而异

## 二、开发服务器原理

### 2.1 请求处理流程

```
浏览器请求 /src/main.tsx
  │
  ▼
Vite Dev Server (Connect 中间件)
  │
  ├─ ① 是否是静态资源 (public/)？
  │   └→ 直接返回文件
  │
  ├─ ② 是否是依赖 (node_modules)？
  │   └→ 返回预构建后的 ESM 模块 (.vite/deps/)
  │
  ├─ ③ 是否是源码 (src/)？
  │   └→ 走插件 transform 流程
  │       ├─ .vue → @vitejs/plugin-vue
  │       ├─ .tsx → esbuild transform
  │       ├─ .scss → sass + PostCSS
  │       └─ .css → CSS Modules / 注入
  │
  └─ ④ 返回转换后的 ESM 代码
      │
      ▼
浏览器收到 ES Module 代码
  → 解析 import → 发起下一个请求
  → 循环直到依赖图完全加载
```

### 2.2 依赖预构建（Deps Optimization）

为什么 node_modules 也需要处理？

```
问题: node_modules 中的包存在以下情况:
  • CommonJS 格式（浏览器不支持 require）
  • 不是纯 ESM（如包含 require()）
  • 一个包拆分成多个文件（大量 HTTP 请求）

解决方案: Vite 在首次启动时用 esbuild 预构建
  ┌─────────────────────────────┐
  │  lodash (CommonJS, 700+ 文件) │
  │         ↓ esbuild 预构建       │
  │  node_modules/.vite/deps/    │
  │  _vite/lodash.js (单一ESM)    │
  └─────────────────────────────┘

  结果: 
  • CJS → ESM 转换 ✓
  • Tree Shaking ✓
  • 单次请求即可加载 ✓
  • 缓存到 node_modules/.vite（下次启动秒开）✓
```

```typescript
// vite.config.ts
import { defineConfig } from "vite"

export default defineConfig({
  optimizeDeps: {
    // 强制预构建某些包
    include: ["lodash", "axios", "react-dom/client"],
    
    // 排除不需要预构建的包
    exclude: ["@your-local-package"],
    
    // 自定义 esbuild 选项
    esbuildOptions: {
      target: "es2020",
    },
  },
})
```

## 三、HMR（热模块替换）机制

### 3.1 Vite HMR 原理

```
文件变更
  │
  ▼
Vite Dev Server (chokidar watch)
  │
  ├─ 判断变更类型
  │   ├─ 创建/删除文件 → 页面刷新
  │   └─ 修改文件 → HMR 更新
  │
  ├─ 执行插件 transform（仅变更的文件）
  │
  ├─ 通过 WebSocket 推送
  │   ws.send(JSON.stringify({
  │     type: "update",
  │     updates: [{
  │       type: "js-update",  // 或 "css-update"/"full-reload"
  │       timestamp: Date.now(),
  │       path: "/src/App.tsx",
  │       acceptedPath: "/src/App.tsx",
  │     }]
  │   }))
  │
  ▼
客户端 vite/dist/client.mjs
  ├─ 收到 update 消息
  ├─ fetch 新模块代码
  ├─ 替换模块执行上下文
  └─ 触发 accept 回调（如有）
```

### 3.2 手动 HMR Accept

```typescript
// src/counter.ts — 状态管理
let count = 0

export function getCount() { return count }
export function increment() { return ++count }

// 声明接受自身热替换
if (import.meta.hot) {
  import.meta.hot.accept(() => {
    // 模块重新执行后回调
    // 注意: count 会被重置为 0!
    console.log("counter module reloaded")
  })
}

// src/App.tsx
if (import.meta.hot) {
  // 接受依赖模块的热更新
  import.meta.hot.accept("/src/counter.ts", (newModule) => {
    console.log("新的计数:", newModule.getCount())
  })
  
  // 接受整个模块树的热更新
  import.meta.hot.accept((newModule) => {
    // React 组件通常直接整树替换
    ReactDOM.createRoot(root).render(<newModule.default />)
  })
}
```

## 四、生产构建（Rollup）

### 4.1 为什么生产环境用 Rollup？

| 维度 | 开发 (esbuild) | 生产 (Rollup) |
|------|---------------|--------------|
| **速度** | 极快（Go 语言编写） | 较慢但够用 |
| **Tree Shaking** | 基础 | **更完善**（ESM 原生分析） |
| **CSS 处理** | 基础 | **更强大**（提取、压缩、代码分割） |
| **生态兼容** | 部分 | **全面** |
| **SSR 支持** | 一般 | **优秀** |
| **产物稳定性** | 一般 | **经过验证** |

### 4.2 构建配置详解

```typescript
// vite.config.ts
import { defineConfig } from "vite"
import react from "@vitejs/plugin-react-swc"
import { visualizer } from "rollup-plugin-visualizer"

export default defineConfig(({ mode, command }) => ({
  plugins: [react()],
  
  build: {
    // 产物目录
    outDir: "dist",
    
    // 资源内联阈值
    assetsInlineLimit: 4096, // <4KB 转 base64
    
    // CSS 代码分割
    cssCodeSplit: true,
    
    // Source Map
    sourcemap: mode === "development",
    
    // Chunk 大小警告阈值
    chunkSizeWarningLimit: 500,
    
    // Rollup 配置
    rollupOptions: {
      input: {
        main: "index.html",
        admin: "admin.html",
      },
      output: {
        // 手动 chunk 分割
        manualChunks(id) {
          // 第三方库分离
          if (id.includes("node_modules")) {
            if (id.includes("@chakra-ui")) return "vendor-chakra"
            if (id.includes("@tanstack")) return "vendor-table"
            if (id.includes("react") || id.includes("react-dom")) return "vendor-react"
            return "vendor"
          }
        },
        // 文件名模板
        chunkFileNames: "assets/js/[name]-[hash].js",
        entryFileNames: "assets/js/[name]-[hash].js",
        assetFileNames: (assetInfo) => {
          const info = assetInfo.name.split(".")
          const ext = info[info.length - 1]
          if (/png|jpe?g|svg|gif|tiff|bmp|ico/i.test(ext)) {
            return `assets/images/[name]-[hash].[ext]`
          }
          if (/woff2?|eot|ttf|otf/i.test(ext)) {
            return `assets/fonts/[name]-[hash].[ext]`
          }
          if (/css/i.test(ext)) {
            return `assets/css/[name]-[hash].[ext]`
          }
          return `assets/[name]-[hash].[ext]`
        },
      },
    },
    
    // 压缩选项 (Vite 6 默认用 esbuild)
    minify: "esbuild",
    // terserOptions: { ... } // 如需用 Terser
    
    // 目标浏览器
    target: "es2020",
  },

  // 插件仅在 build 时生效
  plugins: command === "build" 
    ? [visualizer({ open: true, gzipSize: true })]
    : [],
}))
```

## 五、插件系统详解

### 5.1 插件钩子（通用 Rollup Hooks）

| 阶段 | 钩子 | 说明 | 参数 |
|------|------|------|------|
| **通用** | `options` | 修改配置 | RollupOptions |
| **通用** | `buildStart` | 构建开始 | - |
| **解析** | `resolveId` | 解析模块 ID | id, importer |
| **解析** | `load` | 加载模块 | id |
| **转换** | `transform` | 转换模块代码 | code, id |
| **构建** | `moduleParsed` | 模块解析完成 | ModuleInfo |
| **构建** | `resolveDynamicImport` | 动态 import 解析 | specifier, importer |
| **输出生成** | `renderChunk` | 渲染 chunk | code, chunk |
| **输出生成** | `generateBundle` | 生成产物 | options, bundle |
| **写入** | `writeBundle` | 写入磁盘 | options, bundle |
| **关闭** | `closeBundle` | 构建结束 | - |

### 5.2 Vite 独有钩子

| 钩子 | 说明 |
|------|------|
| `config` | 修改 Vite 配置（在解析前） |
| `configResolved` | 配置已解析完毕 |
| `configureServer` | 配置 dev server（添加中间件等） |
| `transformIndexHtml` | 转换 index.html |
| `handleHotUpdate` | 自定义 HMR 更新逻辑 |

## 六、Vite 与 Webpack 对比

| 维度 | Vite | Webpack 5 |
|------|------|-----------|
| **内核语言** | Go (esbuild) + Node.js (Rollup) | JavaScript |
| **Dev Server** | 原生 ESM 按需编译 | 完整打包到内存 |
| **HMR 速度** | 极快（增量编译） | 较快（但需重新打包 chunk） |
| **大型项目** | 优势明显 | 可能变慢 |
| **生态兼容** | 部分插件需适配 | 成熟稳定 |
| **学习曲线** | 低 | 中高 |
| **配置复杂度** | 通常较简单 | 复杂场景配置较多 |
| **生产构建质量** | 优秀（基于Rollup） | 优秀（多年打磨） |
| **非标准特性** | 需要额外处理 | 处理得更全面 |
| **Monorepo** | 天然支持 | 需要额外配置 |

## 七、常见问题排查

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| `Cannot find module` | 依赖未正确预构建 | 清除 `node_modules/.vite` |
| HMR 不生效 | `import.meta.hot.accept` 未正确设置 | 检查 accept 路径 |
| 环境变量未生效 | `VITE_` 前缀缺失 | 确保以 `VITE_` 开头 |
| 构建产物过大 | 未做代码分割 | 配置 `manualChunks` |
| SSR 构建失败 | 使用了浏览器 API | 用 `define` 或 `ssr.noExternal` |
