# npm 包管理与发布完整指南

## 概述

npm 是 JavaScript 世界最大的包注册表。理解 npm 的包管理机制、版本规范和发布流程是每个前端工程师的必备技能。

```
┌─────────────────────────────────────────────────────────┐
│                 npm 生态系统                             │
│                                                         │
│  开发者                                                │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐          │
│  │  编写代码  │ →  │ 打包发布  │ →  │ 版本管理  │          │
│  └──────────┘    └──────────┘    └──────────┘          │
│                      │                                 │
│                      ▼                                 │
│              ┌───────────────┐                         │
│              │ npm Registry  │                         │
│              │ (registry.npm) │                         │
│              └───────┬───────┘                         │
│                      │                                 │
│                      ▼                                 │
│  消费者                                                │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐          │
│  │ 安装依赖  │ →  │ 版本解析  │ →  │ 项目使用  │          │
│  └──────────┘    └──────────┘    └──────────┘          │
│                                                         │
│  辅助工具: pnpm / yarn / lerna / changesets             │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 一、package.json 核心字段

### 1.1 必知字段详解

```json
{
  "name": "@scope/my-awesome-lib",
  "version": "1.2.3-beta.4+build.5",
  "description": "A really awesome library",
  "private": false,

  "type": "module",

  "main": "./dist/index.cjs",
  "module": "./dist/index.mjs",
  "types": "./dist/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.mjs",
      "require": "./dist/index.cjs",
      "default": "./dist/index.cjs"
    },
    "./package.json": "./package.json"
  },
  "files": ["dist", "README.md", "LICENSE"],
  "bin": {
    "my-tool": "./dist/cli.js"
  },

  "scripts": {
    "build": "tsup src/index.ts --format cjs,esm --dts",
    "dev": "tsup --watch",
    "test": "vitest run",
    "lint": "eslint src/",
    "release": "changeset publish"
  },

  "dependencies": {
    "lodash": "^4.17.21"
  },
  "peerDependencies": {
    "react": ">=18.0.0"
  },
  "devDependencies": {
    "typescript": "^5.4.0",
    "tsup": "^8.0.0",
    "vitest": "^2.0.0"
  },
  "optionalDependencies": {
    "fsevents": "^2.3.3"
  },
  "peerDependenciesMeta": {
    "react": { "optional": true }
  },

  "engines": {
    "node": ">=18.0.0",
    "npm": ">=9.0.0"
  },

  "publishConfig": {
    "access": "public",
    "registry": "https://registry.npmjs.org/"
  },

  "repository": {
    "type": "git",
    "url": "https://github.com/user/my-repo.git"
  },
  "homepage": "https://github.com/user/my-repo#readme",
  "bugs": "url": "https://github.com/user/my-repo/issues",
  "keywords": ["utility", "react", "hooks"],
  "author": "Alarik",
  "license": "MIT",
  "sideEffects": ["*.css"]
}
```

### 1.2 关键字段说明

| 字段 | 说明 | 必填 |
|------|------|------|
| `name` | 包名，作用域包以 `@scope/` 开头 | ✅ |
| `version` | SemVer 版本号 | ✅ |
| `main` | CommonJS 入口 | 推荐 |
| `module` | ESM 入口（Tree Shaking 友好） | 推荐 |
| `types` / `typings` | TypeScript 类型声明入口 | 推荐 |
| `exports` | 现代条件导出定义（**强烈推荐**） | 推荐 |
| `files` | 发布时包含的文件白名单 | 推荐 |
| `sideEffects` | 是否有副作用（影响 Tree Shaking） | 推荐 |
| `engines` | 运行环境要求 | 推荐 |
| `publishConfig` | 发布配置（如 access: public） | 作用域包必填 |

## 二、依赖类型详解

### 2.1 四种依赖对比

```
                    安装位置           影响范围           典型用途
                    ────────           ────────           ────────
dependencies         生产+开发         消费者安装          运行时必需
devDependencies      仅开发环境         仅开发者安装        构建/测试工具
peerDependencies     不自动安装        声明兼容的主依赖      React/Vue 等
optionalDependencies 可选安装           缺失不报错          平台特定库
```

### 2.2 版本范围语法

```json
{
  "dependencies": {
    "exact": "1.2.3",           // 精确版本
    
    "tilde": "~1.2.3",          // >=1.2.3 <1.3.0 (补丁级别可变)
    
    "caret": "^1.2.3",          // >=1.2.3 <2.0.0 (次要级别可变) ⭐ 最常用
    
    "gte": ">=1.0.0",           // 大于等于
    
    "range": ">=1.0.0 <2.0.0",  // 范围
    
    "or": "1.x || 2.x",         // 或
    
    "latest": "*",               // 任意版本（不推荐）
    
    "tag": "latest",            // 使用 dist-tag
    
    "github": "github:user/repo", // Git 仓库
    
    "local": "file:../local-pkg", // 本地路径
    
    "workspace": "workspace:*"  // Monorepo workspace 协议
  }
}
```

## 三、SemVer（语义化版本）

### 3.1 版本号结构

```
MAJOR.MINOR.PATCH[-prerelease][+build]

  MAJOR: 不兼容的 API 变更    → ^2.0.0 (需要升级代码)
  MINOR: 向后兼容的功能新增    → ^1.5.0 (可直接升级)
  PATCH: 向后兼容的问题修复    → ^1.4.2 (安全升级)

  示例:
    1.0.0        正式版
    2.0.0-beta.1 预发布版
    1.0.0+20260101 元数据（不影响版本优先级）
```

### 3.2 升级决策树

```
我的变更是：
│
├─ 修复了 Bug？
│   └→ PATCH: 1.0.0 → 1.0.1
│
├─ 新增了功能？
│   ├─ 是否破坏了现有 API？
│   │   └→ MAJOR: 1.0.0 → 2.0.0
│   └─ 否 → MINOR: 1.0.0 → 1.1.0
│
├─ 删除了 API 或改变行为？
│   └→ MAJOR: 1.0.0 → 2.0.0
│
└─ 内部重构，外部行为不变？
    └→ PATCH: 1.0.0 → 1.0.1
```

## 四、exports 字段（现代模块定义）

### 4.1 为什么需要 exports？

```
没有 exports 的问题:
  • 用户可以 import 内部文件: require("my-lib/dist/utils/internal")
  • 无法为不同环境提供不同产物
  • 无法限制访问

exports 的好处:
  ✓ 定义公开的模块边界
  ✓ 支持 CJS / ESM 双模
  ✓ 支持条件导出 (browser/node/import/require)
  ✓ Tree Shaking 友好
```

### 4.2 exports 最佳实践配置

```json
{
  "name": "my-lib",
  "type": "module",
  "main": "./dist/index.cjs",
  "module": "./dist/index.mjs",
  "types": "./dist/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.mjs",
      "require": "./dist/index.cjs",
      "default": "./dist/index.cjs"
    },
    "./utils": {
      "types": "./dist/utils.d.ts",
      "import": "./dist/utils.mjs",
      "require": "./dist/utils.cjs"
    },
    "./styles.css": "./dist/styles.css",
    "./package.json": "./package.json"
  },
  "files": ["dist", "README.md", "LICENSE", "CHANGELOG.md"]
}
```

## 五、Monorepo 包管理

### 5.1 workspace 配置

```json
// package.json (根目录)
{
  "name": "my-monorepo",
  "private": true,
  "workspaces": [
    "packages/*",
    "apps/*",
    "tools/*"
  ]
}
```

```bash
# pnpm workspace
pnpm add lodash -w --filter @scope/my-app
pnpm add @scope/shared-utils -F @scope/web-app
pnpm --filter @scope/web-app run build
pnpm -r run test        # 所有包并行执行 test
pnpm -r run build --stream # 串行并输出日志
```

## 六、发布流程

### 6.1 手动发布

```bash
# 1. 更新版本号
npm version patch  # 或 minor / major / prerelease

# 2. 构建生产产物
npm run build

# 3. 登录 npm（首次）
npm login

# 4. 发布
npm publish --access public

# 5. 打 tag 推送
git push origin main --tags
```

### 6.2 Changesets 自动发布

```bash
npm install @changesets/cli -D
npx changeset init
```

```yaml
# .changeset/config.json
{
  "$schema": "https://unpkg.com/@changesets/config@3.0.0/schema.json",
  "changelog": ["@changesets/cli/changelog"],
  "commit": false,
  "fixed": [],
  "linked": [[ "@scope/ui", "@scope/theme" ]],
  "access": "public",
  "baseBranch": "main",
  "updateInternalDependencies": "patch",
  "ignore": []
}
```

```bash
# 工作流:
# 1. npx changeset          # 创建变更记录
# 2. npx changeset version  # 版本升级 + changelog 生成
# 3. git commit && git push
# 4. npm publish            # 或 GitHub Actions 自动触发
```

## 七、常见问题

| 问题 | 解决方案 |
|------|----------|
| `403 Forbidden` | 作用域包需设置 `"access": "public"` |
| `404 Not Found` | 包名已存在或未正确 login |
| E403 | 未验证邮箱或 token 过期 |
| `EPUBLISHCONFLICT` | 版本号冲突，先 `npm version` |
| 依赖安装慢 | 换用 pnpm 或设置镜像源 |
