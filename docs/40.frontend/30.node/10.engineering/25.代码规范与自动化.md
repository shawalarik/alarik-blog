# 代码规范与自动化工作流

## 概述

统一的代码规范和自动化检查是团队协作的基础。通过 **ESLint + Prettier + Husky + lint-staged + Commitlint** 的组合拳，可以在代码提交的每个环节自动保证质量。

```
┌─────────────────────────────────────────────────────────┐
│              代码质量保障流水线                            │
│                                                         │
│  编辑器实时反馈                                          │
│    ├── ESLint:  代码质量问题（潜在 bug、最佳实践）         │
│    └── Prettier: 格式问题（空格、换行、引号等）            │
│                                                         │
│  Git 提交前（pre-commit hook）                           │
│    ├── lint-staged: 仅对暂存区文件执行检查                │
│    │   ├── eslint --fix (自动修复可修复的问题)           │
│    │   ├── prettier --write (自动格式化)                 │
│    │   └── tsc --noEmit (类型检查)                      │
│    └── 如果失败 → 阻止 commit                            │
│                                                         │
│  Commit Message 规范（commit-msg hook）                  │
│    └── Commitlint: 强制约定式提交格式                     │
│        feat: add user authentication                    │
│        fix: resolve login redirect issue                │
│        docs: update README installation steps           │
│                                                         │
│  CI/CD 流水线                                            │
│    ├── 全量 Lint 检查                                    │
│    ├── 类型检查                                         │
│    ├── 单元测试                                         │
│    └── 构建验证                                         │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 一、ESLint 配置

### 1.1 现代配置（Flat Config）

```javascript
// eslint.config.js (ESLint 9+ Flat Config)
import js from "@eslint/js"
import globals from "globals"
import reactHooks from "eslint-plugin-react-hooks"
import reactRefresh from "eslint-plugin-react-refresh"
import tseslint from "typescript-eslint"

export default tseslint.config(
  { ignores: ["dist", "node_modules", "*.config.*"] },
  
  // JS 基础规则
  js.configs.recommended,
  
  // TS 规则
  ...tseslint.configs.recommended,
  
  {
    files: ["**/*.{ts,tsx}"],
    languageOptions: {
      ecmaVersion: 2022,
      sourceType: "module",
      globals: {
        ...globals.browser,
        ...globals.node,
      },
      parserOptions: {
        project: "./tsconfig.json",
      },
    },
    plugins: {
      "react-hooks": reactHooks,
      "react-refresh": reactRefresh,
    },
    rules: {
      // React Hooks 规则
      ...reactHooks.configs.recommended.rules,
      "react-refresh/only-export-components": ["warn", { allowConstantExport: true }],
      
      // TypeScript 规则调整
      "@typescript-eslint/no-unused-vars": ["error", { argsIgnorePattern: "^_" }],
      "@typescript-eslint/no-explicit-any": "warn",
      "@typescript-eslint/explicit-function-return-type": "off",
      "@typescript-eslint/no-non-null-assertion": "off",
      
      // 通用规则
      "no-console": process.env.NODE_ENV === "production" ? "error" : "off",
      "prefer-const": "error",
      eqeqeq: ["error", "always"],
      curly: ["error", "all"],
    },
  },
)
```

### 1.2 常用规则速查

| 类别 | 规则 | 说明 |
|------|------|------|
| **Bug 预防** | `no-console` (prod error) | 生产禁止 console |
| | `no-eval` (error) | 禁止 eval |
| | `no-implied-eval` | 禁止隐式 eval |
| | `no-prototype-builtins` | 避免原型污染 |
| **代码质量** | `prefer-const` | 能 const 就 const |
| | `eqeqeq: ["error", "always"]` | 必须 === |
| | `curly: ["error", "all"]` | 必须用花括号 |
| | `no-shadow` | 禁止变量遮蔽 |
| **React** | `react-hooks/rules-of-hooks` | Hooks 调用顺序规则 |
| | `react-hooks/exhaustive-deps` | useEffect 依赖完整性 |
| **TS** | `@typescript-eslint/no-explicit-any` | any 报 warning |
| | `strict-boolean-expressions` | 严格布尔表达式 |

## 二、Prettier 配置

### 2.1 基础配置

```javascript
// .prettierrc
/** @type {import('prettier').Config} */
export default {
  semi: true,
  singleQuote: true,
  trailingComma: "es5",
  printWidth: 100,
  tabWidth: 2,
  useTabs: false,
  endOfLine: "lf",
  bracketSpacing: true,
  arrowParens: "always",
  singleAttributePerLine: true,
  plugins: [],  // 如需要 prettier-plugin-tailwindcss
}
```

### 2.2 ESLint + Prettier 协作

```bash
npm install -D eslint-config-prettier eslint-plugin-prettier
```

```javascript
// eslint.config.js — 添加 Prettier 集成
import prettierPlugin from "eslint-plugin-prettier"
import prettierConfig from "eslint-config-prettier"

export default [
  ...baseConfigs,
  prettierConfig,           // 禁止所有与 Prettier 冲突的规则
  {
    plugins: { prettier: prettierPlugin },
    rules: {
      "prettier/prettier": "error",  // Prettier 格式问题视为 ESLint error
    },
  },
]
```

## 三、Husky + lint-staged

### 3.1 安装与初始化

```bash
# Husky v10+ (推荐方式)
npx husky init
npm pkg set scripts.prepare="husky"

# lint-staged
npm install -D lint-staged
```

### 3.2 Hook 配置

```bash
# .husky/pre-commit
npx lint-staged

# .husky/commit-msg
npx --no -- commitlint --edit $1
```

### 3.3 lint-staged 配置

```javascript
// lintstaged.config.js
export default {
  "*.{js,jsx,ts,tsx}": [
    // 1. 先修复能修的问题
    "eslint --fix",
    // 2. 再格式化
    "prettier --write",
    // 3. 最后类型检查
    () => "tsc --noEmit --pretty",
  ],

  "*.{json,md,yml,yaml}": [
    "prettier --write",
  ],

  "*.{css,scss,less}": [
    "prettier --write",
    "stylelint --fix",
  ],

  "*.{vue,svelte}": [
    "eslint --fix",
    "prettier --write",
  ],
}
```

## 四、Commitlint（提交信息规范）

### 4.1 Conventional Commits

```
<type>(<scope>): <subject>

<body>

<footer>
```

### 4.2 Type 列表

| Type | 说明 | 适用场景 |
|------|------|----------|
| `feat` | 新功能 | 新增功能、特性 |
| `fix` | Bug 修复 | 修复缺陷 |
| `docs` | 文档变更 | README、注释、文档 |
| `style` | 代码格式（非样式文件） | 分号、缩进、格式化 |
| `refactor` | 重构（非新功能、非修复） | 代码结构调整 |
| `perf` | 性能优化 | 加速、减少内存 |
| `test` | 测试相关 | 新增测试、修改测试 |
| `build` | 构建系统 | webpack/vite/npm config |
| `ci` | CI 配置 | GitHub Actions、GitLab CI |
| `chore` | 杂务 | 依赖更新、工具配置 |
| `revert` | 回滚 | revert previous commit |

### 4.3 配置

```javascript
// commitlint.config.js
export default {
  extends: ["@commitlint/config-conventional"],
  rules: {
    "type-enum": [2, "always", [
      "feat", "fix", "docs", "style", "refactor", 
      "perf", "test", "build", "ci", "chore", "revert"
    ]],
    "subject-max-length": [2, "always", 72],  // 标题不超过 72 字符
    "body-max-line-length": [2, "always", 100],
    "scope-case": [2, "always", "lower-case"],  // scope 小写
  },
}
```

### 4.4 实际例子

```
✅ 合规范的提交:

feat(auth): add OAuth2.0 Google login support

Implement Google OAuth2 flow using Passport.js strategy.
Includes token refresh handling and account linking.

Closes #123

❌ 不合规范的提交:

fix bug
update
done
feat: it's a very long subject line that exceeds seventy-two characters limit
```

## 六、完整 workflow 图示

```
开发者修改代码
  │
  ├─ VSCode 保存时
  │   ├─ Prettier: auto format ✅
  │   └─ ESLint: show warnings/errors ✅
  │
  ├─ git add + git commit
  │   ├─ pre-commit hook 触发
  │   │   ├─ lint-staged: 对暂存文件运行
  │   │   │   ├─ eslint --fix → 修复并重新暂存
  │   │   │   ├─ prettier --write → 格式化并重新暂存
  │   │   │   └─ tsc --noEmit → 类型检查
  │   │   └─ ❌ 有错误 → commit 被阻止
  │   │
  │   └─ commit-msg hook 触发
  │       └─ commitlint → 检查 message 格式
  │           └─ ❌ 格式不对 → commit 被阻止
  │
  └─ git push
      ├─ GitHub Actions CI 触发
      │   ├─ npm ci (安装依赖)
      │   ├─ npm run lint (全量检查)
      │   ├─ npm run type-check
      │   ├─ npm run test
      │   └─ npm run build
      │
      └─ ✅ 全部通过 → PR 可合并
```
