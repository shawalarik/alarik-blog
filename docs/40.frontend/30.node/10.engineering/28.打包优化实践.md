# 前端打包优化完全指南

## 概述

打包优化的核心目标是：**让页面加载更快、用户体验更好、带宽成本更低**。从代码分割、压缩策略到缓存利用、CDN 部署，每一步都有优化空间。

```
┌──────────────────────────────────────────────────────────┐
│                   打包优化维度                             │
│                                                          │
│  速度优化                                                 │
│  ├── 减少请求数（合并/内联/预加载）                        │
│  ├── 减少传输体积（压缩/Tree Shaking）                     │
│  └── 减少渲染阻塞（异步加载/Critical CSS）                  │
│                                                          │
│  缓存优化                                                 │
│  ├── Content Hash（长期缓存）                              │
│  ├── Service Worker（离线能力）                            │
│  └── CDN 边缘缓存                                         │
│                                                          │
│  体验优化                                                 │
│  ├── Skeleton Screen（骨架屏）                             │
│  ├── Progressive Loading（渐进式加载）                     │
│  └── Error Boundary（优雅降级）                             │
│                                                          │
│  监控度量                                                 │
│  ├── Core Web Vitals                                      │
│  ├── Bundle Analyzer                                      │
│  └── Lighthouse Audit                                     │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

## 一、代码压缩

### 1.1 JavaScript 压缩

```javascript
// webpack.config.js
const TerserPlugin = require("terser-webpack-plugin")

module.exports = {
  optimization: {
    minimize: true,
    minimizer: [
      new TerserPlugin({
        parallel: true, // 多线程压缩
        terserOptions: {
          compress: {
            drop_console: true,        // 移除 console.*
            drop_debugger: true,       // 移除 debugger
            pure_funcs: [             // 移除无副作用的函数调用
              "console.log",
              "console.warn",
              "console.debug",
            ],
            passes: 2,                // 压缩遍历次数
          },
          mangle: {
            safari10: true,           // Safari 10 兼容
          },
          output: {
            comments: false,          // 移除注释
            ascii_only: true,         // 仅 ASCII（减小体积）
          },
        },
        extractComments: false,      // 不提取注释到独立文件
      }),
    ],
  },
}
```

```typescript
// vite.config.ts — esbuild 压缩（默认，更快）
export default defineConfig({
  build: {
    minify: "esbuild", // 或 'terser'（更精细控制但较慢）
    target: "es2020",
  },
})
```

## 二、代码分割（Code Splitting）

### 2.1 策略总览

```
原始 Bundle (500KB)
  │
  ├─ 路由级别分割 (Route-level)
  │   ├── Home (80KB)     → 动态导入
  │   ├── Dashboard (120KB) → 动态导入
  │   └── Settings (60KB)  → 动态导入
  │
  ├─ 第三方库分割 (Vendor)
  │   ├── React (45KB)
  │   ├── Lodash (70KB)
  │   └── Ant Design (200KB)
  │
  ├─ 公共业务代码分割 (Common)
  │   └── utils, components (30KB)
  │
  └─ 结果: 初始 bundle 从 500KB → 80KB (仅首页必要代码)
```

### 2.2 Webpack SplitChunks 配置

```javascript
module.exports = {
  optimization: {
    splitChunks: {
      chunks: "all",
      maxInitialRequests: 15,  // 入口最大请求数
      maxAsyncRequests: 10,    // 并行最大请求数
      minSize: 20000,          // 最小 20KB 才分割
      
      cacheGroups: {
        // React 核心（单独 chunk，变动频率低）
        react: {
          test: /[\\/]node_modules[\\/](react|react-dom|scheduler)[\\/]/,
          name: "react-vendor",
          chunks: "all",
          priority: 20,
        },
        
        // UI 库（单独 chunk）
        ui: {
          test: /[\\/]node_modules[\\/](@ant|antd|@mui|@chakra)[\\/]/,
          name: "ui-vendor",
          chunks: "all",
          priority: 15,
        },
        
        // 其他第三方库
        vendor: {
          test: /[\\/]node_modules[\\/]/,
          name: "vendor",
          chunks: "all",
          priority: 10,
          reuseExistingChunk: true,  // 复用已有 chunk
        },
        
        // 公共业务代码
        commons: {
          minChunks: 2,  // 被 2 个以上 chunk 引用才提取
          name: "commons",
          chunks: "all",
          priority: 5,
          reuseExistingChunk: true,
        },
      },
    },
  },
}
```

### 2.3 Vite 代码分割

```typescript
// vite.config.ts
export default defineConfig({
  build: {
    rollupOptions: {
      output: {
        manualChunks(id) {
          // 第三方库分组
          if (id.includes("node_modules")) {
            if (id.includes("@ant-design")) return "ant-design"
            if (id.includes("echarts")) return "echarts"
            if (id.includes("react") || id.includes("react-dom")) return "react"
            if (id.includes("lodash")) return "lodash"
            
            // 其余归入 vendor
            return "vendor"
          }
          
          // 业务代码：admin 和 frontend 分离
          if (id.includes("/src/admin/")) return "admin"
          if (id.includes("/src/pages/")) return "pages"
        },
        
        // chunk 文件命名
        chunkFileNames: "assets/[name]-[hash].js",
        entryFileNames: "assets/[name]-[hash].js",
        assetFileNames: "assets/[name]-[hash].[ext]",
      },
    },
  },
})
```

## 三、资源优化

### 3.1 图片优化

```javascript
// webpack.config.js
module.exports = {
  module: {
    rules: [
      {
        test: /\.(png|jpe?g|gif|webp|avif)$/i,
        type: "asset",
        parser: {
          dataUrlCondition: {
            maxSize: 10 * 1024, // <10KB 转 base64 inline
          },
        },
        generator: {
          filename: "images/[name].[contenthash:8][ext]",
        },
      },
      // 图片压缩 loader
      {
        test: /\.(png|jpe?g)$/i,
        use: [
          {
            loader: "image-webpack-loader",
            options: {
              mozjpeg: { progressive: true, quality: 75 },
              optipng: { enabled: false },
              svgo: { plugins: [{ name: "removeViewBox", active: false }] },
              webp: { quality: 75 },
            },
          },
        ],
        enforce: "pre",  // 在 url-loader 之前执行
      },
    ],
  },
}
```

## 四、缓存策略

### 4.1 Content Hash 缓存

```javascript
output: {
  filename: "js/[name].[contenthash:8].js",
  chunkFilename: "js/[name].[contenthash:8].chunk.js",
  assetFilename: "[name].[contenthash:8][ext]",
}

// Nginx 配置
location /assets/ {
  expires 365d;
  add_header Cache-Control "public, immutable";
  # contenthash 保证文件名唯一，可永久缓存
}

location /index.html {
  # HTML 不能缓存（引用了带 hash 的文件名）
  add_header Cache-Control "no-store, no-cache, must-revalidate";
}
```

### 4.2 缓存策略矩阵

| 资源类型 | 缓存时间 | 策略 | 原因 |
|---------|---------|------|------|
| **HTML** | 不缓存 | `no-cache` | 入口文件，随时可能更新 |
| **带 hash 的 JS/CSS** | 1 年 | `immutable` | hash 变则文件变，安全长期缓存 |
| **图片/字体/图标** | 1 年 | `max-age=31536000` | 通常不变 |
| **API 数据** | 0 | `no-store` | 动态数据 |
| **Google Fonts** | 1 年 | `max-age=31536000` | 第三方稳定资源 |

## 五、Bundle 分析

### 5.1 Webpack Bundle Analyzer

```bash
npm install -D webpack-bundle-analyzer
```

```javascript
const BundleAnalyzerPlugin = require("webpack-bundle-analyzer").BundleAnalyzerPlugin

module.exports = {
  plugins: [
    ...(process.env.ANALYZE 
      ? [new BundleAnalyzerPlugin({ analyzerMode: "static", openAnalyzer: true })] 
      : []
    ),
  ]
}
```

### 5.2 分析关注点

| 检查项 | 目标值 | 优化方向 |
|--------|--------|----------|
| **初始 bundle 大小** | < 200KB (gzipped) | 代码分割、动态导入 |
| **单个 chunk** | < 250KB | 拆分大型库 |
| **重复依赖** | 0 | dedupe / alias 统一 |
| **未使用的代码** | 0 | Tree Shaking / purge |
| **gzip 后大小** | 基准值的 25-30% | 压缩配置是否生效 |
