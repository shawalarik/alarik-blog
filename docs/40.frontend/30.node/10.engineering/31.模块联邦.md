# 模块联邦（Module Federation）深度解析

## 概述

模块联邦是 Webpack 5 引入的革命性架构——它允许多个独立的构建（应用/库）在**运行时**共享代码，无需统一构建或发布协调。这是目前最优雅的微前端技术方案之一。

```
┌──────────────────────────────────────────────────────────┐
│                模块联邦架构                               │
│                                                          │
│   Host Application (宿主)                                │
│   ┌─────────────────────────────────────────────────┐   │
│   │  import Button from "remote/Button"             │   │
│   │  import Dashboard from "remote/Dashboard"       │   │
│   │                                                 │   │
│   │  ┌──────────────┐  ┌──────────────┐             │   │
│   │  │ Local Module  │  │ Remote Module │             │   │
│   │  │ (本地代码)    │  │ (运行时加载)   │             │   │
│   │  └──────────────┘  └──────┬───────┘             │   │
│   └─────────────────────────────┼────────────────────┘   │
│                                 │                        │
│                    ┌────────────▼────────────┐          │
│                    │   Container (容器)      │          │
│                    │   remoteEntry.js        │          │
│                    └────────────┬────────────┘          │
│                                 │                        │
│   Remote Applications (远程)    │                        │
│   ┌──────────────┐ ┌──────────▼──────────┐             │
│   │ App A (React)│ │ App B (Vue)         │             │
│   │ exposes:     │ │ exposes:            │             │
│   │  - Button    │ │  - Dashboard        │             │
│   │  - Card      │ │  - Chart            │             │
│   └──────────────┘ └─────────────────────┘             │
│                                                          │
│   共享依赖 (Shared Dependencies)                         │
│   ├── react, react-dom (singleton)                      │
│   ├── lodash (singleton, strict version)                 │
│   └── dayjs (eager: true)                               │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

## 一、核心概念

### 1.1 术语表

| 术语 | 说明 | 类比 |
|------|------|------|
| **Host（宿主）** | 消费其他应用模块的应用 | 主应用 |
| **Remote（远程）** | 暴露模块给其他应用使用的应用 | 微应用 |
| **Container** | 远程应用的入口文件 (`remoteEntry.js`) | 目录索引 |
| **exposes** | 远程应用暴露给外部的模块清单 | 导出接口 |
| **remotes** | 宿主声明要消费的远程应用列表 | 导入来源 |
| **shared** | 多应用间共享的依赖配置 | 共享库 |
| **eager** | 共享依赖是否在初始加载时立即获取 | 预加载 |

### 1.2 传统方案 vs 模块联邦

```
传统微前端方案:
━━━━━━━━━━━━━━━━━
  Host App
    │
    ├─ iframe 嵌套 → ❌ 隔离严重、通信困难
    ├─ runtime integration → ❌ 构建耦合、发布依赖
    └─ Web Components → ⚠️ 样式隔离难

模块联邦方案:
━━━━━━━━━━━━━━━━━
  Host App
    │
    └─ import { Button } from "app1/Button"  → ✅ 天然共享
       import { Chart } from "app2/Chart"     → ✅ 独立部署
       
  各应用独立开发、独立构建、独立部署
  运行时动态加载，无需知道对方的存在
```

## 二、Host 配置

### 2.1 Webpack 5 ModuleFederationPlugin

```javascript
// host/webpack.config.js
const { ModuleFederationPlugin } = require("webpack/container/ModuleFederationPlugin")

module.exports = {
  entry: "./src/main.ts",
  
  plugins: [
    new ModuleFederationPlugin({
      // 应用名称（全局唯一标识）
      name: "host",
      
      // 声明要消费的远程应用
      remotes: {
        // 方式一：静态地址
        app1: "app1@http://localhost:3001/remoteEntry.js",
        app2: "app2@http://localhost:3002/remoteEntry.js",
        
        // 方式二：支持多环境
        dashboard: `dashboard@${process.env.DASHBOARD_URL}/remoteEntry.js`,
        
        // 方式三：Promise 异步加载（推荐用于生产）
        store: Promise.resolve().then(() => ({
          get: () => window.store, // 外部注入
        })),
      },
      
      // 共享依赖
      shared: {
        react: { singleton: true, requiredVersion: "^18.0.0" },
        "react-dom": { singleton: true, requiredVersion: "^18.0.0" },
        "react-router-dom": { singleton: false },  // 不强制单例
        lodash: { singleton: true, strictVersion: true },
        
        // 高阶共享配置
        "zustand": {
          singleton: true,
          eager: false,  // 延迟加载
          requiredVersion: "^5.0.0",
        },
      },
    }),
  ],
}
```

### 2.2 在 React Host 中使用远程组件

```tsx
// host/src/App.tsx
import React, { lazy, Suspense, useEffect } from "react"
import { BrowserRouter, Routes, Route, Link } from "react-router-dom"

// 异步加载远程组件
const RemoteButton = lazy(() => import("app1/Button"))
const RemoteDashboard = lazy(() => import("app2/Dashboard"))
const RemoteChart = lazy(() => import("app2/Chart"))

// Bootstrap 远程应用（关键步骤）
// 必须在 import 之前调用，确保 remoteEntry.js 已加载
function loadRemotes() {
  // 方式一：script 标签注入（简单）
  const scripts = [
    { src: "http://localhost:3001/remoteEntry.js" },
    { src: "http://localhost:3002/remoteEntry.js" },
  ]
  
  return Promise.all(
    scripts.map(({ src }) => {
      return new Promise((resolve, reject) => {
        const element = document.createElement("script")
        element.src = src
        element.type = "text/javascript"
        element.async = true
        element.onload = resolve
        element.onerror = reject
        document.head.appendChild(element)
      })
    })
  )
}

export default function App() {
  useEffect(() => {
    loadRemotes().catch(console.error)
  }, [])

  return (
    <BrowserRouter>
      <nav>
        <Link to="/">Home</Link>
        <Link to="/dashboard">Dashboard (Remote)</Link>
        <Link to="/chart">Chart (Remote)</Link>
      </nav>

      <Suspense fallback={<div>Loading remote module...</div>}>
        <Routes>
          <Route path="/" element={<Home />} />
          <Route path="/dashboard" element={<RemoteDashboard />} />
          <Route path="/chart" element={<RemoteChart />} />
        </Routes>
      </Suspense>

      <div style={{ marginTop: 20 }}>
        <Suspense fallback={<p>Loading button...</p>}>
          <RemoteButton label="I'm a remote button!" />
        </Suspense>
      </div>
    </BrowserRouter>
  )
}
```

## 三、Remote 配置

### 3.1 远程应用 Webpack 配置

```javascript
// remote-app-1/webpack.config.js
const HtmlWebpackPlugin = require("html-webpack-plugin")
const { ModuleFederationPlugin } = require("webpack/container/ModuleFederationPlugin")

module.exports = {
  entry: "./src/bootstrap.tsx",  // 注意：不是 index.tsx！

  // 注意：这里不需要 output.library 等配置，
  // ModuleFederationPlugin 会自动处理

  plugins: [
    new ModuleFederationPlugin({
      name: "app1",  // 必须与 host 中 remote 名称一致

      // 暴露给外部的模块
      exposes: {
        "./Button": "./src/components/Button",
        "./Card": "./src/components/Card",
        "./utils": "./src/utils/index",
      },

      // 远程应用也可以消费其他远程模块
      remotes: {
        // 可以形成链式依赖
        // app2: "app2@http://localhost:3002/remoteEntry.js",
      },

      // 共享依赖（必须与 host 保持一致）
      shared: {
        react: { singleton: true, requiredVersion: "^18.0.0" },
        "react-dom": { singleton: true, requiredVersion: "^18.0.0" },
        lodash: { singleton: true, strictVersion: true },
      },
    }),

    new HtmlWebpackPlugin({
      template: "./public/index.html",
    }),
  ],
}
```

### 3.2 Bootstrap 入口（关键！）

```tsx
// remote-app-1/src/bootstrap.tsx — 异步引导
import React from "react"
import ReactDOM from "react-dom/client"
import App from "./App"

// 导入 bootstrap 的原因：
// ModuleFederation 需要先检查共享依赖是否可用
// 如果直接 import ReactDOM 可能会报错
ReactDOM.createRoot(document.getElementById("root")!).render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
)
```

```javascript
// remote-app-1/src/index.ts — 真正入口
// 这个文件的作用是确保共享依赖就绪后再渲染
import("./bootstrap")
```

## 四、高级用法

### 4.1 动态 Remote（生产环境推荐）

```typescript
// host/src/dynamic-remotes.ts
/**
 * 动态加载远程模块
 * 适用于远程地址不确定或需要在运行时决定的场景
 */
export async function loadDynamicRemote(
  remoteName: string,
  remoteUrl: string,
  exposedModule: string,
) {
  // 1. 确保 remoteEntry 已加载
  await ensureRemoteLoaded(remoteName, remoteUrl)

  // 2. 获取远程容器
  const container = (window as any)[remoteName]

  // 3. 初始化共享作用域（共享依赖版本协商）
  await container.init(__webpack_share_scopes__.default)

  // 4. 加载暴露的模块
  const factory = await container.get(exposedModule)
  const Module = factory()

  return Module
}

async function ensureRemoteLoaded(name: string, url: string) {
  if ((window as any)[name]) return // 已加载

  return new Promise<void>((resolve, reject) => {
    const element = document.createElement("script")
    element.src = url
    element.type = "text/javascript"
    element.async = true
    element.onload = () => resolve()
    element.onerror = () => reject(new Error(`Failed to load remote: ${url}`))
    document.head.appendChild(element)
  })
}

// 使用
const { default: DynamicComponent } = await loadDynamicRemote(
  "marketing-site",
  "https://cdn.example.com/marketing/remoteEntry.js",
  "./Banner"
)
```

### 4.2 错误边界包裹

```tsx
// host/src/components/RemoteWrapper.tsx
import React, { Component, type ErrorInfo, type ReactNode } from "react"
import { Spin } from "antd"

interface Props {
  fallback?: ReactNode
  children: ReactNode
  onError?: (error: Error) => void
}

interface State {
  hasError: boolean
  error: Error | null
}

export class RemoteBoundary extends Component<Props, State> {
  state: State = { hasError: false, error: null }

  static getDerivedStateFromError(error: Error) {
    return { hasError: true, error }
  }

  componentDidCatch(error: Error, info: ErrorInfo) {
    console.error("[RemoteBoundary] Remote component crashed:", error, info)
    this.props.onError?.(error)
  }

  render() {
    if (this.state.hasError) {
      return this.props.fallback ?? (
        <div style={{ padding: 20, textAlign: "center" }}>
          <p style={{ color: "#999" }}>远程模块加载失败</p>
          <button onClick={() => this.setState({ hasError: false, error: null })}>
            重试
          </button>
        </div>
      )
    }

    return this.props.children
  }
}

// 使用
<RemoteBoundary fallback={<div>Fallback UI</div>}>
  <Suspense fallback={<Spin />}>
    <RemoteComponent />
  </Suspense>
</RemoteBoundary>
```

### 4.3 共享状态跨应用

```typescript
// shared/store.ts — 跨应用的 Zustand store
import { create } from "zustand"

// 通过 shared: { singleton: true, eager: true } 共享
// 所有应用使用同一个实例
interface AuthStore {
  user: { name: string; role: string } | null
  setUser: (user: AuthStore["user"]) => void
  logout: () => void
}

export const useAuthStore = create<AuthStore>((set) => ({
  user: null,
  setUser: (user) => set({ user }),
  logout: () => set({ user: null }),
}))
```

## 五、与其他微前端方案对比

| 维度 | Module Federation | qiankun | single-spa | Micro App |
|------|-------------------|---------|------------|-----------|
| **技术栈** | Webpack 5 必需 | 无关 | 无关 | 无关 |
| **样式隔离** | 需自行处理 | ✅ Shadow DOM | 需处理 | ✅ 内置 |
| **JS 隔离** | Sandbox 沙箱 | ✅ | 需处理 | ✅ 内置 |
| **独立部署** | ✅ | ✅ | ✅ | ✅ |
| **通信难度** | 低（天然 JS 共享） | 中 | 中 | 低 |
| **学习曲线** | 中 | 中 | 较高 | 低 |
| **社区活跃度** | ★★★★☆ | ★★★☆☆ | ★★★☆☆ | ★★★★☆ |
| **适用场景** | 同技术栈微前端 | 异构微前端 | 需精细控制 | 快速接入 |

## 六、注意事项与陷阱

| 问题 | 解决方案 |
|------|----------|
| **共享依赖版本不一致** | 使用 `requiredVersion` + `singleton` 严格约束 |
| **远程加载超时** | 设置合理的 timeout + 降级 UI |
| **CSS 冲突** | CSS Modules / BEM / scoped styles |
| **路由冲突** | 统一路由前缀 `/app1/`, `/app2/` |
| **TypeScript 类型丢失** | 为远程模块声明 `.d.ts` 类型 |
| **开发体验差** | 使用 `@module-federation/sdk` 增强 DX |
| **SSR 兼容** | 需要 `@module-federation/node` |
