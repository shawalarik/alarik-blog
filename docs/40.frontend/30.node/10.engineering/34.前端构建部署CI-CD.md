# 前端构建部署 CI/CD 实战

## 概述

CI/CD（持续集成/持续交付）是现代前端工程的最后一公里——将代码从仓库自动转化为线上可访问的产品。

## 一、GitHub Actions

### 1.1 基础工作流

```yaml
# .github/workflows/ci.yml
name: CI/CD Pipeline

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]
  # 定时任务（每晚构建检查）
  schedule:
    - cron: "0 2 * * *"

# 并发控制：同一分支只保留最新一次运行
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

env:
  NODE_VERSION: "20"
  PNPM_VERSION: "9"

jobs:
  # ════════════════════════════
  # Job 1: Lint & Test
  # ════════════════════════════
  quality:
    name: Quality Checks
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup pnpm
        uses: pnpm/action-setup@v4
        with:
          version: ${{ env.PNPM_VERSION }}

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: "pnpm"

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Run ESLint
        run: pnpm lint

      - name: Run Type Check
        run: pnpm type-check

      - name: Run Unit Tests
        run: pnpm test:coverage
      # 上传覆盖率报告
      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: coverage-report
          path: coverage/
          retention-days: 7

  # ════════════════════════════
  # Job 2: Build
  # ════════════════════════════
  build:
    name: Build Project
    runs-on: ubuntu-latest
    needs: quality  # 依赖 quality job 通过
    steps:
      - uses: actions/checkout@v4

      - name: Setup pnpm
        uses: pnpm/action-setup@v4
        with:
          version: ${{ env.PNPM_VERSION }}

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: "pnpm"

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Build project
        run: pnpm build
        env:
          NODE_ENV: production
          API_URL: ${{ vars.API_URL }}

      # 上传构建产物供 deploy job 使用
      - uses: actions/upload-artifact@v4
        with:
          name: dist
          path: dist/
          retention-days: 1

  # ════════════════════════════
  # Job 3: Deploy
  # ════════════════════════════
  deploy:
    name: Deploy
    runs-on: ubuntu-latest
    needs: build
    # 仅在 main 分支 push 时部署
    if: github.event_name == 'push' && github.ref == 'refs/heads/main'
    environment:
      name: production
      url: ${{ steps.deploy.outputs.url }}

    permissions:
      contents: read
      pages: write  # 如部署到 GitHub Pages
      id-token: write  # OIDC（如部署到 AWS/Azure）

    steps:
      - name: Download artifact
        uses: actions/download-artifact@v4
        with:
          name: dist
          path: dist/

      # ====== 部署方式选择 ======
      
      # 方式 A: GitHub Pages (静态站点)
      - name: Deploy to GitHub Pages
        if: github.ref == 'refs/heads/main'
        uses: peaceiris/actions-gh-pages@v4
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./dist
          cname: example.com

      # 方式 B: AWS S3 + CloudFront
      # - name: Configure AWS Credentials
      #   uses: aws-actions/configure-aws-credentials@v4
      #   with:
      #     aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
      #     aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
      #     aws-region: us-east-1
      #
      # - name: Deploy to S3
      #   run: |
      #     aws s3 sync dist/ s3://my-bucket \
      #       --delete \
      #       --cache-control "public, max-age=31536000, immutable"
      #
      # - name: Invalidate CloudFront Cache
      #   run: |
      #     aws cloudfront create-invalidation \
      #       --distribution-id ${{ secrets.CLOUDFRONT_DIST_ID }} \
      #       --paths "/*"

      # 方式 C: Vercel (一键部署)
      # - name: Deploy to Vercel
      #   uses: amondnet/vercel-action@v25
      #   with:
      #     vercel-token: ${{ secrets.VERCEL_TOKEN }}
      #     vercel-org-id: ${{ secrets.ORG_ID }}
      #     vercel-project-id: ${{ secrets.PROJECT_ID }}
      #     vercel-args: "--prod"
```

### 1.2 PR Preview 环境

```yaml
# .github/workflows/pr-preview.yml
name: PR Preview

on:
  pull_request:
    types: [opened, synchronize, reopened]

jobs:
  preview:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup pnpm & Node
        uses: pnpm/action-setup@v4
        with:
          version: 9
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: "pnpm"

      - run: pnpm install --frozen-lockfile
      - run: pnpm build

      # 部署 PR 预览
      - name: Deploy Preview
        uses: amondnet/vercel-action@v25
        id: deploy
        with:
          vercel-token: ${{ secrets.VERCEL_TOKEN }}
          vercel-org-id: ${{ secrets.ORG_ID }}
          vercel-project-id: ${{ secrets.PROJECT_ID }}

      # 在 PR 中评论预览链接
      - name: Comment Preview URL
        uses: actions/github-script@v7
        with:
          script: |
            const previewUrl = '${{ steps.deploy.outputs.preview-url }}';
            github.rest.issues.createComment({
              owner: context.repo.owner,
              repo: context.repo.repo,
              issue_number: context.issue.number,
              body: `🚀 **Preview**: ${previewUrl}\n\n_Updated at ${new Date().toISOString()}_`
            });
```

## 二、GitLab CI

```yaml
# .gitlab-ci.yml
stages:
  - lint
  - test
  - build
  - deploy

variables:
  PNPM_HOME: "${CI_PROJECT_DIR}/.pnpm-store"
  NODE_VERSION: "20"

cache:
  key: "${CI_COMMIT_REF_SLUG}"
  paths:
    - node_modules/
    - .pnpm-store/

# ═══ Lint ═══
lint:
  stage: lint
  image: node:${NODE_VERSION}-alpine
  before_script:
    - corepack enable && corepack prepare pnpm@latest --activate
    - pnpm config set store-path ${PNPM_HOME}
  script:
    - pnpm install --frozen-lockfile
    - pnpm lint
    - pnpm type-check
  only:
    - merge_requests
    - main

# ═══ Test ═══
test:
  stage: test
  image: node:${NODE_VERSION}-alpine
  before_script:
    - corepack enable && corepack prepare pnpm@latest --activate
    - pnpm config set store-path ${PNPM_HOME}
  script:
    - pnpm install --frozen-lockfile
    - pnpm test:ci
  coverage: '/Coverage:\s*(\d+\.\d+%)/'  # 解析覆盖率
  artifacts:
    when: always
    reports:
      junit: reports/junit.xml
    paths:
      - coverage/

# ═══ Build ═══
build:
  stage: build
  image: node:${NODE_VERSION}-alpine
  before_script:
    - corepack enable && corepack prepare pnpm@latest --activate
    - pnpm config set store-path ${PNPM_HOME}
  script:
    - pnpm install --frozen-lockfile
    - pnpm build
  artifacts:
    paths:
      - dist/
    expire_in: 1 hour
  only:
    - main
    - tags

# ═══ Deploy Production ═══
deploy:prod:
  stage: deploy
  image: alpine:latest
  dependencies:
    - build
  before_script:
    - apk add --no-cache openssh-client rsync
    - mkdir -p ~/.ssh
    - echo "$SSH_PRIVATE_KEY" | tr -d '\r' > ~/.ssh/id_ed25519
    - chmod 600 ~/.ssh/id_ed25519
    - ssh-keyscan -H $DEPLOY_HOST >> ~/.ssh/known_hosts
  script:
    - rsync -avz --delete dist/ $DEPLOY_USER@$DEPLOY_HOST:$DEPLOY_PATH/
    - ssh $DEPLOY_USER@$DEPLOY_HOST "cd $DEPLOY_PATH && pm2 restart all || true"
  environment:
    name: production
    url: https://example.com
  only:
    - main
  when: manual  # 手动触发部署
```

## 三、Docker 化部署

### 3.1 Dockerfile（多阶段构建）

```dockerfile
# Stage 1: Dependencies
FROM node:20-alpine AS deps
RUN apk add --no-cache libc6-compat
WORKDIR /app
COPY package.json pnpm-lock.yaml* ./
RUN corepack enable && corepack prepare pnpm@latest --activate
RUN pnpm install --frozen-lockfile

# Stage 2: Build
FROM node:20-alpine AS builder
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN corepack enable && corepack prepare pnpm@latest --activate
ENV NEXT_TELEMETRY_DISABLED=1
RUN pnpm build

# Stage 3: Run
FROM node:20-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
RUN addgroup --system --gid 1001 nodejs
RUN adduser --system --uid 1001 nextjs
COPY --from=builder /app/public ./public
COPY --from=builder --chown=nextjs:nodejs /app/.next/standalone ./
COPY --from=builder --chown=nextjs:nodejs /app/.next/static ./.next/static
USER nextjs
EXPOSE 3000
ENV PORT=3000
CMD ["node", "server.js"]
```

### 3.2 Docker Compose + CI

```yaml
# docker-compose.ci.yml
version: "3.9"
services:
  app:
    build:
      context: .
      dockerfile: Dockerfile
      args:
        BUILD_ARG: ${CI_COMMIT_SHA:-local}
    ports:
      - "3000:3000"
    environment:
      - NODE_ENV=production
      - API_URL=${API_URL}
    restart: unless-stopped
    networks:
      - app-network
    healthcheck:
      test: ["CMD", "wget", "--no-verbose", "--tries=1", "--spider", "http://localhost:3000/api/health"]
      interval: 30s
      timeout: 10s
      retries: 3
networks:
  app-network:
    driver: bridge
```

## 五、最佳实践清单

| 实践 | 说明 |
|------|------|
| **并发控制** | 同一分支取消旧运行，节省资源 |
| **缓存依赖** | pnpm/yarn cache 加速安装 |
| **冻结锁文件** | `--frozen-lockfile` 确保一致性 |
| **环境分离** | staging / production 不同环境变量 |
| **手动部署门禁** | 生产环境 `when: manual` |
| **健康检查** | 部署后自动验证服务可用 |
| **回滚机制** | 保留最近 N 个版本的产物 |
| **密钥管理** | 使用 Secrets，绝不硬编码 |
| **产物保留** | 设置合理 retention days |
| **通知机制** | 部署成功/失败及时通知团队 |
