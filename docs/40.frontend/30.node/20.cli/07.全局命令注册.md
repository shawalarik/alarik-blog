## 概述

让 CLI 工具能够像 `npm`、`git`、`vue` 一样作为全局命令使用，需要正确的入口文件设置、shebang 声明、package.json 配置以及发布到 npm 的完整流程。

## 创建 bin 入口

### 目录结构

```
my-cli/
├── src/
│   ├── index.js          # 主逻辑
│   └── commands/
│       ├── create.js
│       └── build.js
├── bin/
│   └── my-cli.js         # bin 入口文件
├── package.json
└── README.md
```

### 编写 bin 入口

```js
#!/usr/bin/env node

'use strict';

// Shebang 声明告诉操作系统用 Node.js 执行此脚本
// Windows 会忽略 shebang，但 npm link 生成的 .cmd shim 会处理它

require('../src/index.js');
```

或者使用 ESM：

```js
#!/usr/bin/env node

import '../src/index.js';
```

### package.json 中声明 bin

```json
{
  "name": "@scope/my-cli",
  "version": "1.0.0",
  "bin": {
    "my-cli": "./bin/my-cli.js"
  },
  "files": [
    "bin/",
    "src/",
    "dist/"
  ]
}
```

**多命令注册：**

```json
{
  "bin": {
    "my-cli": "./bin/my-cli.js",
    "my-cli-dev": "./bin/dev.js",
    "my-cli-build": "./bin/build.js"
  }
}
```

**简写形式（命令名与包名相同时）：**

```json
{
  "name": "my-cli",
  "bin": "./bin/my-cli.js"
}
// 等价于 { "bin": { "my-cli": "./bin/my-cli.js" } }
```

## npm link 本地调试

### 基本用法

在 CLI 项目根目录执行：

```bash
cd my-cli
npm link
```

这会在全局 `node_modules` 中创建一个符号链接，指向你的本地项目，并将 bin 命令注册到全局 PATH。

之后可以在任意位置使用：

```bash
my-cli --version
my-cli init my-project
```

### 查看链接状态

```bash
# 查看全局链接的所有包
npm ls -g --depth=0 --link=true

# 查看具体包的链接目标
npm root -g
ls $(npm root -g)/my-cli
```

### 取消链接

```bash
npm unlink -g my-cli

# 或者回到项目目录执行
cd my-cli
npm unlink
```

### 链接依赖的其他包

如果你的 CLI 依赖另一个本地包（monorepo 场景）：

```bash
# 在依赖包目录中
cd packages/utils
npm link

# 在 CLI 项目目录中
cd packages/cli
npm link @scope/utils

# 这样 CLI 就会使用本地开发的 utils 包
```

### yarn / pnpm 对应命令

```bash
# Yarn
yarn link
yarn unlink

# pnpm
pnpm link -g
pnpm unlink -g
```

### 注意事项

1. **Windows 上权限问题**：可能需要管理员权限来创建全局符号链接
2. **ESM 模块**：如果使用 `"type": "module"`，确保 bin 入口也使用 ESM 导入方式
3. **TypeScript**：需要先编译再链接，或使用 `ts-node` / `tsx` 作为运行时

### TypeScript 项目的本地调试

对于 TypeScript 项目，推荐两种方案：

**方案一：使用 tsx**

```json
{
  "bin": {
    "my-cli": "./bin/my-cli.js"
  },
  "devDependencies": {
    "tsx": "^4.0.0"
  },
  "scripts": {
    "dev": "tsx src/index.ts"
  }
}
```

```js
// bin/my-cli.js
#!/usr/bin/env node
require('tsx')('../src/index.ts');
```

**方案二：先 build 再 link**

```json
{
  "scripts": {
    "build": "tsc",
    "prepublishOnly": "npm run build"
  }
}
```

```bash
npm run build
npm link
```

## 发布到 npm

### 发布前检查清单

- [ ] 版本号已更新 (`npm version patch/minor/major`)
- [ ] `files` 字段正确配置，避免发布不必要的文件
- [ ] `.npmignore` 或 `package.json` 的 `files` 字段排除测试、文档等
- [ ] 测试全部通过
- [ ] README.md 包含使用说明
- [ ] `license` 字段已填写

### package.json 关键配置

```json
{
  "name": "@scope/my-cli",
  "version": "1.0.0",
  "description": "A powerful CLI tool",
  "main": "./dist/index.js",
  "bin": {
    "my-cli": "./bin/my-cli.js"
  },
  "files": [
    "bin/",
    "dist/",
    "README.md",
    "LICENSE"
  ],
  "scripts": {
    "build": "tsc",
    "prepublishOnly": "npm run build",
    "test": "vitest",
    "lint": "eslint src/"
  },
  "keywords": [
    "cli",
    "scaffold",
    "generator"
  ],
  "license": "MIT",
  "engines": {
    "node": ">=18.0.0"
  },
  "repository": {
    "type": "git",
    "url": "https://github.com/user/my-cli.git"
  },
  "homepage": "https://github.com/user/my-cli#readme",
  "bugs": {
    "url": "https://github.com/user/my-cli/issues"
  },
  "publishConfig": {
    "access": "public"  // scoped 包必须显式声明 public
  }
}
```

### .npmignore 配置

```
src/
*.ts
*.map
test/
__tests__/
coverage/
.github/
.vscode/
.env
.eslintrc*
.prettierrc*
tsconfig*
vitest.config.*
TODO.md
```

> 如果同时存在 `.npmignore` 和 `package.json` 的 `files` 字段，两者都会生效（取交集）。推荐只使用 `files`。

### 发布流程

```bash
# 1. 登录 npm（首次）
npm login

# 2. 检查包名是否已被占用
npm view @scope/my-cli

# 3. 使用 npm version 更新版本号（自动打 tag）
npm version patch   # 1.0.0 → 1.0.1（修复 bug）
npm version minor   # 1.0.0 → 1.1.0（新增功能）
npm version major   # 1.0.0 → 2.0.0（破坏性变更）

# 4. dry-run 预览将要发布的文件
npm publish --dry-run

# 5. 正式发布
npm publish

# 6. 打 tag（可选，用于标记重要版本）
git tag -a v1.0.0 -m "Release v1.0.0"
git push origin --tags
```

### 使用者安装

```bash
# 全局安装（获得全局命令）
npm install -g @scope/my-cli

# 或使用 npx（无需安装，每次拉取最新版）
npx @scope/my-cli init my-project

# 项目内安装（作为开发依赖）
npm install -D @scope/my-cli
npx my-cli build
```

## Shebang 与环境变量

### Shebang 详解

Shebang（`#!`）是脚本文件的第一行，告诉操作系统用什么解释器执行该脚本。

```js
#!/usr/bin/env node
```

**为什么用 `env` 而不是绝对路径？**

```js
// ❌ 硬编码路径 — 不同系统 Node.js 安装位置不同
#!/usr/local/bin/node
#!/usr/bin/node

// ✅ 通过 env 查找 node — 自动适配各种安装方式
#!/usr/bin/env node
```

### 各平台行为

| 平台 | Shebang 处理 |
|------|-------------|
| Linux / macOS | 读取 shebang，用指定的解释器执行 |
| Windows (CMD/PowerShell) | **忽略** shebang，但 npm 会根据 bin 字段生成 `.cmd` shim |
| Windows (Git Bash / WSL) | 正确处理 shebang |

### npm 生成的 Windows shim

当用户执行 `npm install -g my-cli` 时，npm 除了创建符号链接外，还会在 Windows 上生成 `.cmd` 文件：

```bat
@ECHO off
GOTO start
:find_delimiter
:: npm 自动生成的 .cmd shim 内容
:start
SETLOCAL
"%~dp0\node_modules\my-cli\bin\my-cli.js" %*
```

这就是为什么 shebang 在 Windows 上也能工作的原理。

### 环境变量的使用

```js
#!/usr/bin/env node

'use strict';

// 从环境变量读取配置
process.env.MY_CLI_DEBUG === '1' && enableDebugMode();
process.env.MY_CLI_NO_COLOR === '1' && disableColors();
process.env.MY_CLI_CONFIG_PATH && setCustomConfig(process.env.MY_CLI_CONFIG_PATH);

// 设置环境变量传递给子进程
process.env.INIT_CWD = process.cwd();  // 许多 CLI 工具遵循此惯例
process.env.npm_config_root = getUserHomeDir();
```

### 常用的环境变量约定

| 变量名 | 含义 | 示例 |
|--------|------|------|
| `NO_COLOR` / `MY_CLI_NO_COLOR` | 禁用颜色输出 | `NO_COLOR=1 my-cli` |
| `DEBUG` / `MY_CLI_DEBUG` | 启用调试模式 | `DEBUG=* my-cli` |
| `FORCE_COLOR` | 强制启用颜色 | `FORCE_COLOR=1 my-cli \| cat` |
| `HOME` / `USERPROFILE` | 用户主目录 | 存放全局配置 |
| `INIT_CWD` | npm script 执行时的工作目录 | npm lifecycle 注入 |
| `npm_config_*` | npm 配置项 | `npm_config_registry` |

### 检测运行环境

```js
function detectEnvironment() {
  return {
    isTTY: !!process.stdout.isTTY,           // 是否为交互式终端
    isCI: !!process.CI,                       // 是否在 CI 环境
    platform: process.platform,               // win32/linux/darwin
    arch: process.arch,                        // x64/arm64
    nodeVersion: process.version,              // Node.js 版本
    shell: process.env.SHELL || process.env.COMSPEC, // 当前 shell
    term: process.env.TERM,                   // 终端类型
    colors: process.stdout.getColorDepth(),   // 颜色深度
  };
}
```

## 小结

| 步骤 | 命令/文件 | 要点 |
|------|-----------|------|
| 创建入口 | `bin/*.js` | 添加 `#!/usr/bin/env node` |
| 注册命令 | `package.json` 的 `bin` 字段 | 映射命令名到入口文件 |
| 本地调试 | `npm link` | 全局符号链接，快速迭代 |
| TypeScript | `tsx` 或先 `tsc` 再 link | 开发和生产分离 |
| 发布 | `npm publish` | 确保 `files`、`.npmignore`、`publishConfig` 正确 |
| 用户使用 | `npm i -g` / `npx` | 全局安装或零安装运行 |
