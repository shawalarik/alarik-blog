## 概述

CLI 工具的可维护性很大程度上取决于测试覆盖率。由于 CLI 涉及进程输入输出、文件系统操作、子进程调用等特殊场景，测试策略与普通的库或应用有所不同。本章介绍 CLI 测试的各种方法和最佳实践。

## 模拟命令行输入

### 模拟 process.argv

最基础的测试方法是直接构造 `process.argv` 来模拟命令行输入。

```js
// __tests__/cli.test.js
import { describe, it, expect, vi, beforeEach, afterEach } from 'vitest';

describe('CLI 基础测试', () => {
  beforeEach(() => {
    // 保存原始 argv
    this.originalArgv = process.argv;
  });

  afterEach(() => {
    // 恢复原始 argv
    process.argv = this.originalArgv;
    delete process.exitCode;
  });

  it('应该正确解析 --port 参数', async () => {
    // 模拟命令行参数
    process.argv = [
      'node',
      'my-cli',
      '--port',
      '8080',
      '--verbose',
    ];

    // 导入 CLI（此时会读取 process.argv）
    const { parseArgs } = await import('../src/args.js');
    const result = parseArgs();

    expect(result.port).toBe(8080);
    expect(result.verbose).toBe(true);
  });

  it('应该在缺少必需参数时报错', async () => {
    process.argv = ['node', 'my-cli'];

    const { parseArgs } = await import('../src/args.js');

    expect(() => parseArgs()).toThrow('必须指定端口号');
  });
});
```

### 模拟 stdin/stdout/stderr

使用 `mockery` 或手动 mock 来拦截标准流：

```js
import { describe, it, expect, vi, beforeEach, afterEach } from 'vitest';

describe('输出测试', () => {
  beforeEach(() => {
    // Mock stdout.write
    this.stdoutSpy = vi.spyOn(process.stdout, 'write').mockImplementation(() => true);
    this.stderrSpy = vi.spyOn(process.stderr, 'write').mockImplementation(() => true);
  });

  afterEach(() => {
    vi.restoreAllMocks();
  });

  it('应该输出欢迎信息', () => {
    const { showWelcome } = require('../src/output.js');
    showWelcome('MyCLI', '1.0.0');

    expect(this.stdoutSpy).toHaveBeenCalledWith(
      expect.stringContaining('MyCLI')
    );
  });

  it('错误信息应输出到 stderr', () => {
    const { showError } = require('../src/output.js');
    showError('配置文件不存在');

    expect(this.stderrSpy).toHaveBeenCalled();
    expect(this.stdoutSpy).not.toHaveBeenCalledWith(
      expect.stringContaining('错误')
    );
  });
});
```

## Jest / Vitest 测试 CLI 输出

### 使用 execa 测试完整 CLI

这是最接近真实使用场景的测试方式——启动一个真实的子进程运行 CLI。

```js
// __tests__/integration.test.js
import { describe, it, expect, beforeAll, afterAll } from 'vitest';
import execa from 'execa';
import { resolve, join } from 'path';
import { fileURLToPath } from 'url';

const __dirname = dirname(fileURLToPath(import.meta.url));
const CLI_PATH = resolve(__dirname, '../bin/my-cli.js');

describe('CLI 集成测试', () => {
  it('应该显示版本号', async () => {
    const { stdout } = await execa('node', [CLI_PATH, '--version']);
    expect(stdout).toContain('1.0.0');
  });

  it('应该显示帮助信息', async () => {
    const { stdout } = await execa('node', [CLI_PATH, '--help']);
    expect(stdout).toMatch(/Usage:/);
    expect(stdout).toMatch(/Options:/);
  });

  it('应该正确执行 create 命令', async () => {
    const tempDir = join(os.tmpdir(), `test-${Date.now()}`);

    const { stdout, exitCode } = await execa('node', [
      CLI_PATH, 'create', 'test-project',
      '--template', 'vue',
    ], {
      cwd: tempDir,
      timeout: 30_000,
    });

    expect(exitCode).toBe(0);
    expect(stdout).toContain('创建成功');

    // 清理
    fs.rmSync(join(tempDir, 'test-project'), { recursive: true });
  });

  it('无效参数应该返回非零退出码', async () => {
    try {
      await execa('node', [CLI_PATH, '--invalid-option']);
      expect.unreachable('应该抛出错误');
    } catch (error) {
      expect(error.exitCode).toBeGreaterThan(0);
      expect(error.stderr).toBeDefined();
    }
  });

  it('应该正确处理环境变量', async () => {
    const { stdout } = await execa('node', [CLI_PATH, 'config'], {
      env: {
        ...process.env,
        MY_CLI_DEBUG: 'true',
        MY_CLI_PORT: '9000',
      },
    });

    expect(stdout).toContain('9000');
  });
});
```

### 测试 TTY 相关行为

```js
it('非 TTY 环境不应输出颜色', async () => {
  const { stdout } = await execa('node', [CLI_PATH, 'status'], {
    env: {
      ...process.env,
      TERM: 'dumb',           // 非 TTY 终端
      NO_COLOR: '1',          // 禁用颜色
    },
  });

  // 不应包含 ANSI 转义码
  expect(stdout).not.toMatch(/\x1b\[/);
});

it('强制启用颜色', async () => {
  const { stdout } = await execa('node', [CLI_PATH, 'status'], {
    env: {
      ...process.env,
      FORCE_COLOR: '1',       // 强制颜色
    },
  });

  expect(stdout).toMatch(/\x1b\[/);  // 应包含 ANSI 码
});
```

## 快照测试

快照测试非常适合 CLI 工具，因为输出的格式变化频率较低，且任何意外的格式变动都可能是 bug。

### Vitest 快照

```js
import { describe, it, expect } from 'vitest';
import { formatTable, formatBanner, formatError } from '../src/format.js';

describe('格式化输出快照', () => {
  it('表格输出', () => {
    const table = formatTable([
      { name: 'vue', version: '^3.4.0', license: 'MIT' },
      { name: 'react', version: '^18.2.0', license: 'MIT' },
      { name: 'typescript', version: '^5.3.0', license: 'Apache' },
    ]);

    expect(table).toMatchSnapshot();
  });

  it('横幅输出', () => {
    const banner = formatBanner('MyCLI', '2.0.0');
    expect(banner).toMatchSnapshot();
  });

  it('错误输出', () => {
    const error = formatError('配置文件格式错误', {
      file: 'mycli.config.json',
      line: 42,
      column: 5,
    });
    expect(error).toMatchSnapshot();
  });

  it('不同参数下的输出变体', () => {
    expect(formatBanner('ToolA', '1.0.0')).toMatchSnapshot('short-name');
    expect(formatBanner('MyAwesomeTool', '3.2.1')).toMatchSnapshot('long-name');
  });
});
```

## 使用 execa 测试子进程

### 测试子进程执行

```js
import execa from 'execa';
import { describe, it, expect, vi, beforeEach } from 'vitest';

describe('子进程调用测试', () => {
  it('应该正确执行 git 命令', async () => {
    // 真实的 git 调用
    const { stdout } = await execa('git', ['--version']);
    expect(stdout).toMatch(/^git version/);
  });

  it('应该正确处理子进程超时', async () => {
    await expect(
      execa('node', ['-e', 'setInterval(()=>{}, 1000)'], {
        timeout: 500,
        reject: true,
      })
    ).rejects.toThrow('Timed out');
  });

  it('应该正确传递环境变量给子进程', async () => {
    const { stdout } = await execa('node', ['-e', 'console.log(process.env.TEST_KEY)'], {
      env: { ...process.env, TEST_KEY: 'hello-world' },
    });
    expect(stdout).toBe('hello-world');
  });
});
```

### Mock 子进程（单元测试）

```js
import { describe, it, expect, vi, beforeEach } from 'vitest';

vi.mock('execa', () => {
  const execaMock = vi.fn();
  return {
    default: execaMock,
    execaSync: vi.fn(),
  };
});

describe('GitHelper (mock)', () => {
  let execaMock;

  beforeEach(async () => {
    const { default: mockExeca } = await import('execa');
    execaMock = mockExeca;
  });

  it('getCurrentBranch 应调用 git 命令', async () => {
    const { GitHelper } = await import('../src/git.js');
    execaMock.mockResolvedValue({ stdout: 'main\n' });

    const git = new GitHelper('/fake/path');
    const branch = await git.getCurrentBranch();

    expect(execaMock).toHaveBeenCalledWith('git', ['branch', '--show-current'], {
      cwd: '/fake/path',
    });
    expect(branch).toBe('main');
  });

  it('push 应在无远程时使用当前分支', async () => {
    execaMock
      .mockResolvedValueOnce({ stdout: 'feature/test\n' })  // getCurrentBranch
      .mockResolvedValueOnce({ stdout: '' });                 // push

    const { GitHelper } = await import('../src/git.js');
    const git = new GitHelper('/fake/path');
    await git.push();

    expect(execaMock).toHaveBeenLastCalledWith(
      'git',
      ['push', 'origin', 'feature/test'],
      expect.any(Object)
    );
  });

  it('应该正确传播错误', async () => {
    execaMock.mockRejectedValue(new Error('Not a git repository'));

    const { GitHelper } = await import('../src/git.js');
    const git = new GitHelper('/not-git/repo');

    await expect(git.getStatus()).rejects.toThrow('Not a git repository');
  });
});
```

## 测试辅助工具集

### Fixture 管理

```js
// tests/helpers/fixtures.js
import { mkdtemp, writeFile, mkdir, rm } from 'fs/promises';
import { tmpdir, join } from 'os';
import { join } from 'path';

export class TempProject {
  #dir;

  constructor(dir) {
    this.#dir = dir;
  }

  get path() { return this.#dir; }

  static async create(structure = {}) {
    const dir = await mkdtemp(join(tmpdir(), 'cli-test-'));
    const project = new TempProject(dir);

    await project.writeStructure(structure);
    return project;
  }

  async writeStructure(structure, basePath = this.#dir) {
    for (const [name, content] of Object.entries(structure)) {
      const fullPath = join(basePath, name);

      if (typeof content === 'object' && content !== null) {
        await mkdir(fullPath, { recursive: true });
        await this.writeStructure(content, fullPath);
      } else {
        await writeFile(fullPath, typeof content === 'string' ? content : JSON.stringify(content, null, 2));
      }
    }
  }

  async writeFile(relativePath, content) {
    await writeFile(join(this.#dir, relativePath), content);
  }

  async cleanup() {
    await rm(this.#dir, { recursive: true, force: true });
  }
}

// 使用
import { TempProject } from '../helpers/fixtures.js';

it('应在项目中正确初始化', async () => {
  const project = await TempProject.create({
    'package.json': { name: 'test-proj', version: '1.0.0' },
    'src': {
      'index.js': 'console.log("hello")',
    },
  });

  const { exitCode } = await execa('node', [CLI_PATH, 'init'], {
    cwd: project.path,
  });

  expect(exitCode).toBe(0);
  expect(await exists(join(project.path, 'mycli.config.js'))).toBe(true);

  await project.cleanup();
});
```

### 断言辅助函数

```js
// tests/helpers/assertions.js
export function assertSuccess(result) {
  expect(result.exitCode).toBe(0);
  expect(result.failed).toBeFalsy();
  expect(result.isCancelled).toBeFalsy();
}

export function assertFailure(result, code) {
  expect(result.exitCode).toBeGreaterThan(0);
  if (code !== undefined) expect(result.exitCode).toBe(code);
}

export function assertOutputContains(output, ...strings) {
  for (const str of strings) {
    expect(output).toContain(str);
  }
}

export function assertNoColorCodes(output) {
  // ANSI 转义码匹配模式
  expect(output).not.toMatch(/\x1b\[[0-9;]*[a-zA-Z]/);
}

export function assertValidJson(jsonString) {
  const parsed = JSON.parse(jsonString);
  expect(parsed).toBeInstanceOf(Object);
  return parsed;
}
```

## 测试策略总结

| 测试层次 | 工具/方法 | 测试内容 | 速度 |
|----------|-----------|---------|------|
| **单元测试** | Mock + 直接调用 | 函数、工具类、配置解析 | 快 |
| **组件测试** | mock-stdin, mock inquirer | 交互式组件 | 中 |
| **集成测试** | execa 运行 bin 入口 | 完整命令执行流程 | 中慢 |
| **快照测试** | Vitest snapshot | 输出格式稳定性 | 快 |
| **端到端测试** | execa + 临时项目 | 完整工作流（init → build → deploy） | 慢 |

### 推荐的测试目录结构

```
tests/

```

## 小结

| 测试场景 | 推荐方案 | 核心要点 |
|----------|---------|---------|
| **参数解析** | 构造 process.argv + 直接调用 | 轻量快速 |
| **交互输入** | mock-stdin / mock inquirer | 异步时序控制 |
| **输出验证** | spy stdout/stderr | 区分 stdout 和 stderr |
| **完整命令** | execa 启动子进程 | 最贴近真实场景 |
| **输出格式** | 快照测试 | 检测意外格式变更 |
| **子进程调用** | mock execa | 隔离外部依赖 |

好的测试不仅能捕获回归 bug，还能作为工具行为的活文档，帮助新贡献者快速理解预期行为。
