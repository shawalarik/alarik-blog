## 概述

`package.json` 是 Node.js 生态中每个包的"身份证"，定义了包的元数据、依赖关系、入口点和行为配置。深入理解每个字段的作用与最佳实践，是构建高质量 npm 包的基础。

## name — 包的唯一标识符

### 命名规则

```jsonc
{
  // 必须是小写字母、数字、连字符（-）或下划线（_）
  "name": "@scope/my-package",   // 作用域包
  "name": "my-awesome-lib",       // 普通包
}
```

**命名约束**：
- 长度 ≤ 214 字符
- 不能以 `.` 或 `_` 开头
- 不含大写字母
- 不能使用 Node.js 内置模块名（`http`, `fs`, `path` 等）
- 不能包含特殊字符如 `~!@#$%^&*()`

### 作用域包（Scoped Packages）

```bash
# 公开作用域包（免费发布）
npm publish --access public @myorg/mylib

# 私有作用域包（需要付费账户或私有 registry）
npm publish --access private @mycompany/secret-lib
```

作用域的优势：
- **命名空间隔离**：不同组织可拥有同名包
- **权限控制**：天然支持私有包
- **清晰归属**：`@vue/reactivity` 一眼看出来源

### 最佳实践

```js
// ✅ 推荐
"name": "@babel/core"
"name": "lodash-es"
"name": "typescript"

// ❌ 避免
"name": "My-Package"           // 大写
"name": "package"              // 与内置冲突
"name": "jquery-plugin"        // 过度使用前缀
```

## version — 语义化版本号

遵循 [SemVer](https://semver.org/lang/zh-CN/) 规范：`MAJOR.MINOR.PATCH`

```jsonc
{
  "version": "2.1.3"
}
// MAJOR: 不兼容的 API 变更 (2.x → 3.x)
// MINOR: 向后兼容的功能新增 (2.1 → 2.2)
// PATCH: 向后兼容的问题修复 (2.1.3 → 2.1.4)
```

**版本预发布标签**：

| 格式 | 含义 |
|------|------|
| `1.0.0-alpha.1` | Alpha 测试版 |
| `1.0.0-beta.2` | Beta 测试版 |
| `1.0.0-rc.1` | 候选发布版 |

## type — 模块系统声明

Node.js 12+ 引入的关键字段，决定 `.js` 文件的模块解析方式：

```jsonc
{
  "type": "module",    // ESM 模式：.js 按 ES Module 解析
  // "type": "commonjs" // CJS 模式（默认，可省略）
}
```

### ESM vs CJS 行为差异

| 特性 | `"type": "module"` | 默认（CJS） |
|------|-------------------|-------------|
| `import/export` | ✅ 原生支持 | ❌ 需要转换 |
| `require()` | ❌ 不可用 | ✅ 可用 |
| `__dirname` | ❌ 未定义 | ✅ 全局可用 |
| `require.cache` | ❌ 未定义 | ✅ 可用 |
|顶层 `await` | ✅ 支持 | ❌ 报错 |

### ESM 中获取 `__dirname` 和 `__filename`

```js
import { fileURLToPath } from 'node:url';
import { dirname } from 'node:path';

const __filename = fileURLToPath(import.meta.url);
const __dirname = dirname(__filename);
```

### 混合使用场景

```jsonc
{
  "type": "module",
  // .cjs 文件仍按 CommonJS 处理
  // .mjs 文件始终按 ES Module 处理
}
```

项目结构：
```
pkg/
├── index.js      ← ESM（受 type: module 影响）
├── index.cjs     ← CommonJS 入口
├── utils.mjs     ← ESM（显式声明）
└── package.json
```

## main / module / types / exports — 入口点配置

这是最容易出错的区域。现代 npm 包应优先使用 **exports** 字段：

### main — 传统入口

```jsonc
{
  "main": "./dist/index.cjs",
  "main": "./src/index.js"
}
```
- 被 `require('your-pkg')` 使用
- 兼容旧版 Node.js 和打包工具

### module — 打包工具入口

```jsonc
{
  "module": "./dist/index.esm.js"
}
```
- Webpack/Rollup/Vite 等工具识别的 **非标准字段**
- 提供 Tree-shaking 友好的 ESM 版本
- 注意：Vite 已不再推荐使用此字段

### types — TypeScript 类型入口

```jsonc
{
  "types": "./dist/index.d.ts",
  "typings": "./dist/index.d.ts"  // 同义字段，types 优先
}
```

### exports — 现代条件导出（推荐）

```jsonc
{
  "name": "@example/my-pkg",
  "type": "module",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",        // TypeScript
      "import": "./dist/index.mjs",        // ESM (import)
      "require": "./dist/index.cjs",       // CJS (require)
      "default": "./dist/index.mjs"         // 兜底
    },
    "./utils": {
      "types": "./dist/utils.d.ts",
      "import": "./dist/utils.mjs",
      "default": "./dist/utils.mjs"
    },
    "./package.json": "./package.json"
  }
}
```

**exports 的优势**：
- 精确控制哪些文件可被外部访问（封装内部文件）
- 支持条件导出（根据运行环境返回不同版本）
- 防止用户误导入未暴露的模块

### exports 踩坑指南

```jsonc
{
  // ❌ 错误：一旦使用 exports，main/module/types 就被忽略
  "main": "./index.js",
  "exports": { ".": "./index.js" },

  // ⚠️ 注意：exports 会阻止子路径访问
  "exports": { ".": "./index.js" }
  // 用户无法 require('@pkg/dist/internal') —— 即使文件存在！

  // ✅ 正确：显式允许子路径
  "exports": {
    ".": "./index.js",
    "./internal/*": "./dist/internal/*.js"
  },

  // ✅ 完全开放所有子路径
  "exports": {
    ".": "./index.js",
    "./*": "./*.js"
  }
}
```

## bin — CLI 命令注册

将包注册为全局可执行的命令行工具：

```jsonc
{
  "bin": {
    "my-cli": "./bin/cli.js",
    "my-cli-build": "./bin/build.js"
  }
}
```

`bin` 对应的脚本必须包含 shebang：

```js
#!/usr/bin/env node
console.log('Hello from my-cli!');
```

安装后的效果：
```bash
npm install -g my-pkg    # 创建全局命令 my-cli, my-cli-build
npm install my-pkg        # 在 node_modules/.bin/ 创建软链接
npx my-cli                # 直接运行（无需安装）
```

### 单字符串简写

```jsonc
{ "bin": "./cli.js" }     // 命令名 = 包名
// 等价于 { "bin": { "my-pkg": "./cli.js" } }
```

## files — 发布白名单

控制 `npm publish` 时上传哪些文件到 registry：

```jsonc
{
  "files": [
    "dist/",
    "README.md",
    "LICENSE",
    "CHANGELOG.md",
    "types/"
  ]
}
```

**默认排除**（即使不设 files 也会忽略）：
- `node_modules/`
- `.git/`
- `*.log`
- `.env`
- `.DS_Store`
- `npm-debug.log*`

**推荐做法**：
```jsonc
{
  // ✅ 明确白名单——只上传必要文件
  "files": ["dist/", "README.md"],

  // ❌ 用 .npmignore 黑名单——容易遗漏
  // .npmignore:
  // src/
  // test/
  // *.ts
  // webpack.config.*
}
```

## scripts — 生命周期钩子与自定义命令

### 生命周期钩子执行顺序

```
preinstall → install → postinstall
prepublishOnly → prepack → prepare → postpack
publish → postpublish
preversion → version → postversion
pretest → test → posttest
prestart → start → poststart
stop → poststop
```

### 常用脚本最佳实践

```jsonc
{
  "scripts": {
    // 开发相关
    "dev": "vite",
    "build": "tsc && vite build",
    "preview": "vite preview",

    // 质量保障
    "lint": "eslint src tests --ext .ts,.tsx",
    "lint:fix": "eslint src tests --fix",
    "format": "prettier --write \"src/**/*.ts\"",
    "test": "vitest run",
    "test:watch": "vitest",
    "test:coverage": "vitest run --coverage",

    // 发布流程
    "prepare": "husky install",
    "prepublishOnly": "pnpm build && pnpm test",
    "version": "conventional-changelog -p angular -i CHANGELOG.md -s && git add CHANGELOG.md",
    "postversion": "git push && git push --tags && npm publish",

    // 清理
    "clean": "rimraf dist node_modules"
  }
}
```

### 脚本中的变量引用

```jsonc
{
  "scripts": {
    // 使用 npm 变量
    "echo:name": "echo $npm_package_name v$npm_package_version",
    
    // 交叉引用其他脚本
    "prebuild": "npm run lint && npm run test",
    "build": "webpack --mode production",
    "postbuild": "npm run size-check"
  }
}
```

## 其他重要字段

### engines — 运行环境要求

```jsonc
{
  "engines": {
    "node": ">=18.0.0",
    "npm": ">=9.0.0",
    "pnpm": ">=8.0.0"
  }
}
```

配合 `.npmrc` 的 `engine-strict=true` 可强制检查。

### sideEffects — Tree-shaking 标记

```jsonc
{
  "sideEffects": [
    "*.css",
    "*.scss",
    "./src/polyfill.ts",
    false              // 整个包无副作用
  ]
}
```
- `false`：告诉打包工具可以安全移除未被导入的代码
- 数组：列出有副作用的文件

### license — 开源协议

```jsonc
{
  "license": "MIT",
  "license": "Apache-2.0",
  "license": "GPL-3.0-or-later",
  "license": "SEE LICENSE IN LICENSE_FILE"  // 自定义
}
```

### repository / bugs / homepage — 项目信息

```jsonc
{
  "repository": {
    "type": "git",
    "url": "https://github.com/user/repo.git"
  },
  "bugs": {
    "url": "https://github.com/user/repo/issues"
  },
  "homepage": "https://github.com/user/repo#readme"
}
```

### private — 防止误发布

```jsonc
{ "private": true }   // npm publish 会拒绝发布
```

## 完整示例：生产级 package.json

```jsonc
{
  "name": "@example/my-library",
  "version": "1.2.0",
  "description": "A high-quality TypeScript utility library",
  "type": "module",
  "private": false,

  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.mjs",
      "require": "./dist/index.cjs"
    },
    "./utils": {
      "types": "./dist/utils.d.ts",
      "import": "./dist/utils.mjs"
    }
  },

  "main": "./dist/index.cjs",
  "module": "./dist/index.mjs",
  "types": "./dist/index.d.ts",

  "files": ["dist", "README.md", "LICENSE", "CHANGELOG.md"],
  
  "bin": {
    "my-tool": "./bin/cli.mjs"
  },

  "sideEffects": ["*.css", "**/*.global.ts"],

  "engines": { "node": ">=18.0.0" },
  "license": "MIT",
  "author": "Alarik <alarik@example.com>",

  "repository": {
    "type": "git",
    "url": "https://github.com/example/my-library"
  },

  "scripts": {
    "build": "tsup",
    "dev": "tsup --watch",
    "test": "vitest",
    "lint": "eslint src",
    "typecheck": "tsc --noEmit",
    "prepublishOnly": "pnpm build && pnpm test",
    "release": "bumpp"
  },

  "devDependencies": {
    "tsup": "^8.0.0",
    "vitest": "^1.0.0",
    "typescript": "^5.4.0"
  },

  "peerDependencies": {
    "react": ">=17.0.0"
  },

  "keywords": ["utility", "typescript", "library"]
}
```

## 小结

| 字段 | 作用 | 是否必需 |
|------|------|---------|
| `name` | 包标识符 | ✅ |
| `version` | 版本号 | ✅ |
| `type` | 模块系统声明 | 推荐 |
| `main` | CJS 入口 | 兼容性需要 |
| `exports` | 条件导出（现代标准） | ✅ 推荐 |
| `module` | 打包器 ESM 入口 | 渐进弃用 |
| `types` | TS 类型入口 | TS 项目必需 |
| `files` | 发布白名单 | ✅ 推荐 |
| `bin` | CLI 命令注册 | 工具类包 |
| `scripts` | 生命周期与自定义命令 | ✅ 推荐 |
