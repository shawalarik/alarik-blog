## 概述

将 npm 包发布到公共或私有 registry 是开源贡献和团队协作的重要环节。一个健壮的发布流程应包括：版本管理、构建验证、自动更新 CHANGELOG、打 tag 推送、以及发布到 registry。本文详解完整的发布流水线。

## 发布前准备

### 注册 npm 账户

```bash
# 注册（会发送验证邮件）
npm adduser

# 或登录已有账户
npm login

# 验证登录状态
npm whoami
# 输出: your-username

# 查看当前 registry
npm config get registry
# https://registry.npmjs.org/
```

### 两步验证（2FA）

```bash
# 开启两步验证（强烈推荐！）
npm profile enable 2fa auth-and-writes

# 发布时需要输入 OTP
npm publish
# Enter OTP: 123456
```

### package.json 发布前检查清单

```jsonc
{
  // ✅ 必填项
  "name": "@myorg/my-package",       // 合法的包名
  "version": "1.0.0",                // 有效版本号
  
  // ✅ 推荐项
  "description": "Brief description",
  "keywords": ["keyword1", "kw2"],
  "license": "MIT",
  "author": "Your Name",
  "repository": {
    "type": "git",
    "url": "https://github.com/user/repo.git"
  },
  "homepage": "https://github.com/user/repo#readme",
  "bugs": {
    "url": "https://github.com/user/repo/issues"
  },

  // ✅ 内容控制
  "files": ["dist/"],
  "main": "./dist/index.cjs",
  "module": "./dist/index.mjs",
  "types": "./dist/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.mjs",
      "require": "./dist/index.cjs"
    }
  },
  
  // ⚠️ 注意
  "private": false,                  // 必须！否则无法发布
  "engines": { "node": ">=18.0.0" }
}
```

## npm publish 完整流程

### 手动发布步骤

```bash
# 第一步：更新版本号
npm version patch    # 1.0.0 → 1.0.1
npm version minor    # 1.0.0 → 1.1.0
npm version major    # 1.0.0 → 2.0.0

# 第二步：构建
npm run build

# 第三步：测试（确保通过）
npm test

# 第四步：预览将要发布的内容
npm pack --dry-run
# 列出所有将被包含的文件及大小

# 第五步：实际发布
npm publish --access public

# 第六步：推送到 Git（npm version 已自动 commit + tag）
git push origin main
git push origin --tags
```

## 生命周期钩子（Scripts Hooks）

### 完整钩子时序图

```
npm version patch
  │
  ▼
preversion ──── version ──── postversion
  │                │            │
  │ npm run        │ package.json│ npm run
  │ preversion     │ version     │ postversion
  │ (测试检查)      │ 1.0.0→1.0.1 │ (推送 tag)

npm publish
  │
  ▼
prepublishOnly ──→ prepack ──→ prepare ──→ postpack
  │                  │           │            │
  │ npm run          │ npm run    │ npm run     │ npm run
  │ prepublishOnly   │ prepack    │ prepare     │ postpack
  │ (构建+测试)      │ (很少用)   │ (构建)      │ (很少用)
  │                                          │
  └──────────────────────────────────────────┘
                                             │
                              publish ──→ postpublish
                                │            │
                                │            │ npm run
                                │            │ postpublish
                                │            │ (通知)
```

### 常用钩子配置

```jsonc
{
  "scripts": {
    // --- 版本钩子 ---
    "preversion": "npm run test && npm run build",
    "version": "conventional-changelog -p angular -i CHANGELOG.md -s && git add CHANGELOG.md",
    "postversion": "git push && git push --tags",
    
    // --- 发布钩子 ---
    "prepublishOnly": "pnpm build && pnpm test",
    "prepack": "node scripts/clean-dist.js",
    "prepare": "husky install",
    "postpublish": "node scripts/notify-discord.js"
  }
}
```

### 各钩子详细说明

| 钩子 | 触发时机 | 典型用途 |
|------|---------|---------|
| `preversion` | `npm version` 执行前 | 运行测试、lint 检查 |
| `version` | 版本号写入后、commit 前 | 生成 CHANGELOG |
| `postversion` | 版本 commit + tag 后 | 推送 git、触发 CI |
| `prepublishOnly` | `npm publish` 时（**注意**：不是 npm install 时！） | 最终构建、测试 |
| `prepack` | 打包 tarball 前 | 清理临时文件 |
| `prepare` | npm install 后、publish 前 | 安装 husky 等 |
| `postpack` | tarball 打包后 | 校验产物大小 |
| `publish` | 发布到 registry 后 | 很少使用 |
| `postpublish` | 发布完成后 | 发送通知、触发下游部署 |

### ⚠️ prepublishOnly vs prepublish

```jsonc
{
  // ❌ 废弃写法：prepublish
  // npm install 时也会触发！（历史遗留行为）
  "scripts": {
    "prepublish": "npm run build"
  }

  // ✅ 正确写法：prepublishOnly  
  // 仅在 npm publish 时触发
  "scripts": {
    "prepublishOnly": "npm run build"
  }
}
```

## 作用域包（Scoped Packages）

### 公开 vs 私有

```bash
# 默认情况下，作用域包是私有的（发布会报错）
npm publish
# ERR! This package has been marked as private

# 方法一：命令行指定
npm publish --access public

# 方法二：package.json 中设置（推荐）
// "publishConfig": { "access": "public" }

# 方法三："access": "public" 写入 publishConfig
```

### publishConfig 配置

```jsonc
{
  "name": "@myorg/my-lib",
  "publishConfig": {
    "access": "public",           // 公开包
    "registry": "https://registry.npmjs.org/"  // 指定 registry
  },
  // 或针对私有包
  // "publishConfig": {
  //   "registry": "https://npm.mycompany.com/"
  // }
}
```

### 组织（Organization）管理

```bash
# 创建组织（免费，最多可创建大量公开包）
npm org create myorg

# 邀请成员
npm org set @myorg member user123 developer  // developer/admin 角色

# 查看成员列表
npm org ls @myorg

# 设置包的访问级别
npm access restrict @myorg/my-lib    // 设为私有
npm access public @myorg/my-lib      // 设为公开
npm access grant read-write:org_name @myorg/my-lib user123  // 单包权限
```

## 发布实践模板

### 标准 scripts 配置（可直接抄用）

```jsonc
{
  "name": "@myorg/awesome-pkg",
  "version": "0.1.0",
  "private": false,
  "type": "module",
  "publishConfig": {
    "access": "public"
  },
  "files": ["dist"],
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.mjs",
      "require": "./dist/index.cjs"
    }
  },
  "scripts": {
    "dev": "tsup --watch",
    "build": "tsup",
    "test": "vitest run",
    "test:watch": "vitest",
    "lint": "eslint src/ --ext .ts",
    "typecheck": "tsc --noEmit",
    
    // 发布流程
    "preversion": "npm run test && npm run lint && npm run typecheck",
    "version": "changeset version",
    "postversion": "git push && git push --tags",
    "prepublishOnly": "npm run build && npm run test",
    
    // 日常
    "clean": "rimraf dist"
  },
  "devDependencies": {
    "tsup": "^8.0.0",
    "vitest": "^1.0.0",
    "typescript": "^5.4.0",
    "@changesets/cli": "^2.27.0"
  }
}
```

### .npmignore vs files

```bash
# 优先级：package.json 的 files 字段 > .npmignore > 默认规则

# 如果使用了 files 白名单，.npmignore 基本不需要
# 但如果要排除 files 白名单内的特定文件：

# .npmignore 示例
src/
*.ts
!.d.ts
test/
*.map
vitest.config.ts
tsconfig.json
.github/
.vscode/
```

### .npmrc 发布配置

```ini
# .npmrc（项目根目录）
# 确保始终使用正确的 registry
registry=https://registry.npmjs.org/

# 发布时强制认证
//registry.npmjs.org/:_authToken=${NPM_TOKEN}

# Provenance（来源证明，npm 新功能）
provenance=true
```

## 常见发布问题

### 名称已被占用

```bash
# 检查包名是否可用
npm view package-name
# 返回 404 = 可用

# 替代方案
# 1. 使用作用域 @myorg/package-name
# 2. 取更有辨识度的名字
# 3. 联系原作者转让（罕见成功）
```

### 402 Payment Required

```bash
# 原因：尝试发布私有作用域包但没有付费计划
npm publish
# 402 Payment Required - You must sign up for private packages

# 解决：
npm publish --access public
# 或在 package.json 加 "publishConfig": { "access": "public" }
```

### 403 Forbidden

```bash
# 原因：包名与已有包冲突（大小写变体等）
# npm 包名是不区分大小写的，MyPackage == mypackage

# 检查
npm search your-package-name --long
```

### 409 Conflict / Version Conflict

```bash
# 原因：该版本已存在
npm publish
# 409 Conflict - Cannot publish over previously published version

# 解决：升级版本号再发布
npm version patch
npm publish
```

## 小结

| 步骤 | 命令 | 作用 |
|------|------|------|
| 检查 | `npm pack --dry-run` | 预览发布内容 |
| 版本 | `npm version patch/minor/major` | 升版本 + commit + tag |
| 构建 | `npm run build` | 编译产物 |
| 测试 | `npm test` | 质量门禁 |
| 发布 | `npm publish --access public` | 上传到 registry |
| 推送 | `git push --tags` | 同步 Git tag |
