## 概述

在企业级开发中，私有 npm 仓库是基础设施的核心组件之一。它用于托管内部组件库、商业闭源包、以及对第三方包进行代理缓存。本文对比四种主流方案并提供完整的搭建指南。

## 为什么需要私有仓库？

```
场景                          需要？
─────────────────────────────────────
内部 UI 组件库                    ✅ 必须私有
业务 SDK（含敏感逻辑）             ✅ 必须私有
加速 npm 依赖下载（代理缓存）        ✅ 企业刚需
安全合规（审查每个包的内容）         ✅ 金融/政府需求
离线环境（内网/隔离网络）           ✅ 必须
发布开源包                        ❌ 用公共 registry 即可
```

## 方案总览

| 方案 | 类型 | 难度 | 成本 | 适合场景 |
|------|------|------|------|---------|
| **Verdaccio** | 自建（Node.js） | ★☆☆ | 免费 | 小中型团队、快速起步 |
| **GitLab Package Registry** | 平台集成 | ★★☆ | 免费（自托管）/付费 | 已使用 GitLab |
| **GitHub Packages** | 平台集成 | ★★☆ | 免费（公开）/付费 | 已使用 GitHub |
| **Nexus Repository** | 企业级 | ★★★ | 免费（OSS）/付费 | 大型企业、多类型制品 |
| **Artifactory** | 商业产品 | ★★★ | 映贵 | 大型金融/合规行业 |

## 方案一：Verdaccio（推荐入门）

### 简介

Verdaccio（原名 sinopia）是一个轻量级的私有 npm proxy registry，零配置启动，Node.js 生态原生。

### 安装与启动

```bash
# 全局安装
npm install -g verdaccio

# 启动（默认端口 4873）
verdaccio

# 输出：
# info ----- http://localhost:4873/
# info ---- http://localhost:4873/-/web
# info --- no auth plugin is installed, using default
```

访问 `http://localhost:4873` 即可看到 Web UI。

### 配置文件 `~/.verdaccio/config.yaml`

```yaml
# storage: ./storage  # 包存储位置
# web:
#   title: My Private Registry

# 包访问控制
packages:
  '@myorg/*':
    # 认证才能发布，登录才能访问
    access: $authenticated
    publish: $authenticated

  '**':
    # 所有其他包：任何人可访问，认证才能发布
    access: $all
    publish: $authenticated

# 服务器配置
server:
  keepAliveTimeout: 60

# 上游 registry（代理缓存）
uplinks:
  npmjs:
    url: https://registry.npmjs.org/
    # cache 时间（毫秒）
    maxage: 30m
    # 失败重试
    max_fails: 3
    timeout: 30s

# 日志
log: { type: stdout, format: pretty, level: http }

# 认证
auth:
  htpasswd:
    file: ./htpasswd
    # 注册最大用户数
    max_users: -1  # -1 为无限
```

### 用户管理

```bash
# 注册新用户
npm addUser --registry http://localhost:4873
# Username: admin
# Password: ****

# 登录
npm login --registry http://localhost:4873

# 查看当前认证信息
npm whoami --registry http://localhost:4873
```

### 使用私有仓库

```bash
# 方法一：每次指定 registry
npm install @myorg/ui --registry http://localhost:4873
npm publish --registry http://localhost:4873

# 方法二：项目级 .npmrc
# .npmrc（项目根目录）
registry=http://localhost:4873/

# 方法三：用户级配置
npm config set registry http://localhost:4873

# 方法四：混合模式（推荐！）
# .npmrc
@myorg:registry=http://localhost:4873/
//localhost:4873/:_authToken=xxxxx
# 内部包走私有源，外部包走公共源
```

### Docker 部署（生产推荐）

```yaml
# docker-compose.yml
version: '3'

services:
  verdaccio:
    image: verdaccio/verdaccio:5
    container_name: verdaccio
    ports:
      - "4873:4873"
    volumes:
      - ./conf:/verdaccio/conf
      - ./storage:/verdaccio/storage
      - ./plugins:/verdaccio/plugins
    environment:
      - VERDACCIO_PORT=4873
    restart: unless-stopped

  # 可选：反向代理
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf
      - ./ssl:/etc/nginx/ssl
    depends_on:
      - verdaccio
```

### Nginx 反向代理配置

```nginx
# nginx.conf
server {
    listen 80;
    server_npm registry.mycompany.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_npm registry.mycompany.com;

    ssl_certificate     /etc/nginx/ssl/cert.pem;
    ssl_certificate_key /etc/nginx/ssl/key.pem;

    location / {
        proxy_pass http://verdaccio:4873;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        
        # 大文件上传（发布包）
        client_max_body_size 100M;
        
        # 长连接（下载依赖）
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}
```

## 方案二：GitLab Package Registry

### 配置与使用

```bash
# 项目级 .npmrc（GitLab 自动生成）
# https://gitlab.com/mygroup/myproject/-/-/infrastructure_registry
@scope:registry=https://gitlab.com/api/v4/projects/PROJECT_ID/packages/npm/
//gitlab.com/api/v4/projects/PROJECT_ID/packages/npm/:_authToken=${GITLAB_TOKEN}

# 发布
npm publish

# GitLab UI 查看
# 左侧菜单 → Deploy → Package Registry
```

### CI/CD 集成

```yaml
# .gitlab-ci.yml
publish:
  stage: deploy
  image: node:20-alpine
  script:
    - npm ci
    - npm run build
    - echo "//gitlab.com/api/v4/projects/${CI_PROJECT_ID}/packages/npm/:_authToken=${CI_JOB_TOKEN}" > .npmrc
    - npm publish
  only:
    - main
  variables:
    NPM_TOKEN: ${CI_JOB_TOKEN}
```

### 优缺点

| 优点 | 缺点 |
|------|------|
| 与 GitOps 深度整合 | 仅限 GitLab 项目 |
| CI/CD Token 无缝对接 | 性能不如专用 registry |
| 权限与 Git 项目关联 | 不支持外部包代理缓存 |
| 免费（自托管版） | 包搜索体验一般 |

## 方案三：GitHub Packages

### 配置与使用

```bash
# .npmrc（项目级）
@myorg:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_TOKEN

# 注意：GitHub Packages 要求 scope 与组织/用户名匹配
# 如果你的包名是 @myorg/pkg，则必须是 github.com/myorg 的成员
```

### GitHub Actions 自动发布

```yaml
# .github/workflows/publish.yml
name: Publish to GitHub Packages

on:
  release:
    types: [published]

permissions:
  contents: read
  packages: write

jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          registry-url: 'https://npm.pkg.github.com'
          
      - run: npm ci
      - run: npm run build
      - run: npm publish
        env:
          NODE_AUTH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

### 优缺点

| 优点 | 缺点 |
|------|------|
| 与 GitHub 生态无缝集成 | 下载需要认证（即使公开包） |
| Actions Token 免费使用 | 流量限制（免费额度有限） |
| 免费公开包存储 | npm cli 集成不够顺滑 |

## 权限管理最佳实践

### RBAC 模型设计

```
角色层级：
├── Admin（管理员）
│   ├── 管理用户/团队
│   ├── 删除包
│   └── 修改 registry 配置
├── Publisher（发布者）
│   ├── publish/unpublish
│   ├── deprecate 包
│   └── 查看下载统计
└── Consumer（消费者）
    ├── install 包
    └── 查看包信息（仅公开部分）
```

### Verdaccio 组权限

```yaml
# config.yaml
packages:
  '@core/*':
    access: $authenticated
    publish: $authenticated
    unpublish: core-team

  '@team-frontend/*':
    access: $all
    publish: frontend-team

  '**':
    access: $all
    publish: $authenticated

# groups:
#   core-team:
#     - alice
#     - bob
#   frontend-team:
#     - charlie
#     - dave
#     - eve
```

### Token 管理

```bash
# 生成细粒度 Token（npm v9+）
npm token create --read-only --cidr=192.168.1.0/24
# 输出: npm_xxxxxxxxxxxxx

# CI/CD 中使用环境变量
# .npmrc
//registry.mycompany.com/:_authToken=${NPM_REGISTRY_TOKEN}

# GitLab/GitHub CI 中设置为 Secret 变量
```

## 代理缓存策略

```yaml
# Verdaccio 上游配置优化
uplinks:
  npmjs:
    url: https://registry.npmjs.org/
    maxage: 60m           # 缓存 60 分钟
    max_fails: 5          # 失败重试 5 次
    timeout: 60s          # 超时 60 秒
    failfast: false       # 不立即失败

  taobao:
    url: https://registry.npmmirror.com/
    maxage: 120m          # 国内镜像缓存更久

# 包级别的缓存策略
packages:
  '@myorg/*':
    # 内部包不走上游
    access: $authenticated
  'react':
    # 热门包缓存更久
    allow_access: $all
```

**缓存命中效果**：
```
第一次: npm install react → 下载 300KB（约 3s）
第二次: npm install react → 缓存命中（约 50ms）← 快 60 倍！
```

## 选型决策树

```
你的情况                          推荐方案
─────────────────────────────────────────────
快速搭建、团队 < 20 人             Verdaccio（Docker 部署）
已重度使用 GitLab                  GitLab Package Registry
已重度使用 GitHub                  GitHub Packages（或换 Verdaccio）
大型企业、需要多类型制品（npm/maven/docker） Nexus Repository
金融/合规行业、需要审计追踪         JFrog Artifactory
国内团队、需要高速下载              Verdaccio + 淘宝镜像双上行
```
