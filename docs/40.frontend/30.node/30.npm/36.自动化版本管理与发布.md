## 概述

手动管理版本号既繁琐又容易出错。现代工具链提供了从 **Commit → Version → Changelog → Tag → Publish** 的全自动化能力。本文详解三种主流方案的配置与实践：standard-version（半自动）、release-it（交互式）、semantic-release（全自动）。

## 三种方案对比

| 维度 | standard-version | release-it | semantic-release |
|------|-----------------|------------|------------------|
| **自动化程度** | 半自动（需手动触发） | 半自动（交互式确认） | **全自动**（push 触发） |
| **版本策略** | 基于 Convention Commits | 灵活（多种策略插件） | 基于 Convention Commits |
| **Changelog** | ✅ conventional-changelog | ✅ 内置/插件 | ✅ 内置 |
| **Tag** | ✅ 自动 | ✅ 自动 | ✅ 自动 |
| **Publish** | ❌ 需手动 | ✅ 可选自动 | ✅ 自动 |
| **CI/CD 集成** | 简单 | 简单 | **深度集成** |
| **学习曲线** | 低 | 低 | 中等 |
| **适用场景** | 个人/小团队 | 中型团队 | **CI/CD 驱动的成熟团队** |

## 方案一：standard-version（轻量半自动）

### 安装与初始化

```bash
# 安装
pnpm add -Dw standard-version

# 或全局安装
npm install -g standard-version

# 首次运行（创建 CHANGELOG.md）
pnpm standard-version --first-release
```

### 基础配置

```jsonc
// package.json
{
  "scripts": {
    "release": "standard-version"
  },
  "standard-version": {
    "types": [
      { "type": "feat", "section": "Features" },
      { "type": "fix", "section": "Bug Fixes" },
      { "type": "perf", "section": "Performance" },
      { "type": "refactor", "section": "Refactor" },
      { "type": "docs", "section": "Documentation", "hidden": true },
      { "type": "style", "section": "", "hidden": true },
      { "type": "chore", "section": "", "hidden": true },
      { "type": "ci", "section": "", "hidden": true },
      { "type": "test", "section": "", "hidden": true }
    ],
    "bumpFiles": [
      { "filename": "package.json", "type": "json" }
    ]
  }
}
```

### .versionrc 配置文件

```js
// .versionrc.js
module.exports = {
  // 跳过的 tags（如 alpha/beta 不生成 changelog）
  skip: {
    tag: true,
  },
  // 自定义 header
  header: '# Changelog\n\nAll notable changes to this project will be documented in this file.\n\n',
  // Commit 消息中的 issue 引用格式
  issuePrefixes: ['#'],
};
```

### 完整发布流程

```bash
# 1. 编写符合规范的 commit messages
git add .
git commit -m "feat(button): add loading state prop"
git commit -m "fix(utils): handle null input in formatCurrency"
git commit -m "docs(readme): add installation guide"

# 2. 运行 release（自动完成以下所有步骤）
pnpm release
# ↓ 自动执行：
#   1. 读取 git log 分析 commits
#   2. 根据 commit 类型确定版本跳跃（feat→minor, fix→patch）
#   3. 更新 package.json 的 version 字段
#   4. 生成/追加 CHANGELOG.md
#   5. git commit（changelog + version bump）
#   6. git tag（v1.2.0）

# 3. 推送到远程
git push --follow-tags origin main

# 4. 手动发布到 npm
npm publish
```

### 生成的 CHANGELOG.md 示例

```markdown
# Changelog

## [1.2.0](../../compare/v1.1.0...v1.2.0) - 2026-04-08

### Features

- **button:** add loading state prop (abc1234)

### Bug Fixes

- **(utils):** handle null input in formatCurrency (def5678)

### Documentation

- *(readme)* add installation guide (ghi9012)

## [1.1.0](../../compare/v1.0.0...v1.1.0) - 2026-03-15

### Features

- initial release
```

## 方案二：release-it（灵活强大）

### 安装

```bash
pnpm add -Dw @release-it/conventional-changelog release-it
```

### .release-it.json 配置

```jsonc
{
  "hooks": {
    "before:init": ["pnpm test", "pnpm lint", "pnpm build"],
    "after:bump": ["pnpm run changelog", "git add CHANGELOG.md"],
    "after:release": ["echo 'Released! 🎉'"]
  },
  "git": {
    "commitMessage": "chore(release): v${version}",
    "tagName": "v${version}",
    "tagAnnotation": "Release v${version}",
    "pushRepo": "origin"
  },
  "npm": {
    "publish": true,
    "publishPath": "./dist",
    "access": "public"
  },
  "plugins": {
    "@release-it/conventional-changelog": {
      "preset": "angular",
      "infile": "CHANGELOG.md"
    }
  }
}
```

### 使用方式

```bash
# 交互式（推荐日常使用）
pnpm release
# ? Select increment (major, minor, patch): (Use arrow keys)
# ? The following will be released: (details)
# ? Are you sure? (y/n)

# 非交互式（CI/CD 中使用）
pnpm release --patch --no-increment --ci
pnmp release --minor --ci
pnpm release --major --ci

# 预演（不实际执行）
pnmp release --dry-run

# 只生成 changelog 不发布
pnpm release --release-version-only
```

### release-it 的优势

- **交互式确认**：发布前可以看到即将发布的所有变更
- **多种版本策略**：不仅限于 conventional commits
- **内置发布通道**：npm、GitHub、GitLab、Docker 等
- **Hook 系统**：可在任意生命周期节点插入自定义命令
- **插件生态**：支持 Lerna Changesets 等扩展

## 方案三：semantic-release（全自动 CI/CD）

### 核心理念

```
传统方式                              semantic-release
─────────                            ─────────────
手动决定版本号                        Commit 信息决定版本号
手动更新 changelog                   自动生成 changelog
手动打 tag                            自动打 tag
手动 npm publish                     自动 publish
人工协调发布节奏                      每次 push 到 main 分支自动触发
```

### 原理解析

```
Push to Main Branch
       │
       ▼
┌──────────────────────┐
│  Analyze Commits      │  ← 读取 git log
│  (conventional-commits-parser)
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│  Determine Version    │  ← 根据 commit 类型计算下一个版本
│  (release-commit-analyzer)
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│  Generate Changelog   │  ← 生成 markdown changelog
│  (generate-release-changelog)
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│  Update Files & Tag   │  ← 更新 package.json + git tag
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│  Publish to Registry  │  ← npm publish
│  Create GitHub Release│  ← GitHub Release Notes
└──────────────────────┘
```

### Commit → 版本映射规则

| Commit Type | 版本变化 | 示例 |
|-------------|---------|------|
| `fix` | PATCH (x.x.**X**) | 1.0.0 → 1.0.1 |
| `feat` | MINOR (x.**X**.0) | 1.0.0 → 1.1.0 |
| `feat!` / `fix!` (!表示 breaking) | MAJOR (**X**.0.0) | 1.0.0 → 2.0.0 |
| `BREAKING CHANGE:` footer | MAJOR (**X**.0.0) | 1.0.0 → 2.0.0 |
| 其他 (docs/chore/refactor/style) | 不变 | - |

### 安装与配置

```bash
pnpm add -Dw semantic-release \
  @semantic-release/commit-analyzer \
  @semantic-release/release-notes-generator \
  @semantic-release/changelog \
  @semantic-release/npm \
  @semantic-release/git \
  @semantic-release/github
```

### .releaserc.json 配置（完整版）

```jsonc
{
  "branches": [
    "+([0-9])?(.{x,x}).x",
    "main",
    "next",
    {
      "name": "beta",
      "prerelease": true
    },
    {
      "name": "alpha",
      "prerelease": true
    }
  ],
  "plugins": [
    [
      "@semantic-release/commit-analyzer",
      {
        "preset": "angular",
        "releaseRules": [
          { "type": "docs", "scope": "README", "release": "patch" },
          { "type": "refactor", "release": "patch" },
          { "type": "perf", "release": "minor" }
        ]
      }
    ],
    [
      "@semantic-release/release-notes-generator",
      {
        "preset": "angular",
        "writerConfig": {
          "commitsSort": ["scope", "subject"]
        }
      }
    ],
    [
      "@semantic-release/changelog",
      {
        "changelogFile": "CHANGELOG.md"
      }
    ],
    [
      "@semantic-release/npm",
      {
        "npmPublish": true,
        "tarballDir": ".release",
        "pkgRoot": "."
      }
    ],
    [
      "@semantic-release/git",
      {
        "assets": ["package.json", "CHANGELOG.md"],
        "message": "chore(release): ${nextRelease.version} [skip ci]\n\n${nextRelease.notes}"
      }
    ],
    [
      "@semantic-release/github",
      {
        "assets": [
          { "path": ".release/*.tgz", "label": "Distribution Tarball" }
        ]
      }
    ]
  ]
}
```

### GitHub Actions 完整配置

```yaml
# .github/workflows/release.yml
name: Release

on:
  push:
    branches: [main]

permissions:
  contents: write          # 用于 git push tag
  issues: read
  pull-requests: read
  id-token: write          # 用于 npm provenance

jobs:
  release:
    name: Release
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0    # 需要完整历史来分析 commits

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          registry-url: 'https://registry.npmjs.org'

      - name: Install dependencies
        run: pnpm install

      - name: Build
        run: pnpm build

      - name: Test
        run: pnpm test:run

      - name: Release
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
          NPM_PROVENANCE: true
        run: npx semantic-release
```

### Secrets 配置

```bash
# GitHub Settings → Secrets and variables → Actions → New repository secret

GITHUB_TOKEN:   # 自动生成（GITHUB_TOKEN 权限勾选 Contents: Write）
NPM_TOKEN:      # npm token（Settings → Access Tokens → Generate New Token → Automation）
```

### Pre-release 分支支持

```
main 分支 push     →  正式版 (1.2.0)     → 发布到 npm latest
next 分支 push     →  pre-release        → 发布到 npm next
beta 分支 push     →  pre-release        → 发布到 npm beta
alpha 分支 push    →  pre-release        → 发布到 npm alpha

用户安装：
npm install my-pkg          # → latest（来自 main）
npm install my-pkg@next     # → next（来自 next 分支）
npm install my-pkg@beta     # → beta
```

## Convention Commits 规范速查

```
<type>(<scope>): <subject>

<body>

<footer>
```

### type 列表

| Type | Description | 触发版本变化 |
|------|------------|-------------|
| `feat` | 新功能 | MINOR |
| `fix` | Bug 修复 | PATCH |
| `docs` | 文档变更 | - |
| `style` | 代码格式（不影响逻辑） | - |
| `refactor` | 重构（非 feat 非 fix） | - |
| `perf` | 性能优化 | MINOR（可配置） |
| `test` | 测试相关 | - |
| `build` | 构建系统/依赖变更 | - |
| `ci` | CI 配置变更 | - |
| `chore` | 杂务（不影响 src） | - |
| `revert` | 回退提交 | - |

### 示例

```bash
feat(button): add loading spinner component
fix(form): validate email field before submission
perf(table): virtualize large datasets for 10x render speed
docs(api): add authentication endpoint examples
refactor(auth): extract JWT logic into separate module
chore(deps): upgrade typescript to 5.4
```

## 选型建议

```
你的场景                          推荐方案
─────────────────────────────────────────────
个人项目 / 刚开始接触               standard-version（最简单）
需要人工确认发布内容                 release-it（交互式体验好）
成熟的 CI/CD 流水线团队              semantic-release（全自动）
Monorepo + 多包发布                 changesets + semantic-release
需要同时发布到 npm + Docker + GHCR   release-it（多渠道发布）
```

> **核心原则**：无论选择哪个工具，**Convention Commits 是一切自动化的基础**。建立团队的 commit 规范习惯是最重要的第一步。
