## 概述

Koa 由 Express 原班团队打造，其核心理念是更轻量、更具表现力、更健壮的中间件框架。Koa 抛弃了 Express 的回调和内置路由，采用 **async/await** 实现了优雅的**洋葱模型（Onion Model）**，让异步代码的编写和组合变得极其自然。

## Koa vs Express 核心对比

| 维度 | Express | Koa |
|------|---------|-----|
| **设计哲学** | "开箱即用"（ batteries-included ） | "最小内核"（ minimal ） |
| **中间件模型** | 线性串联（`next()` 传递） | 洋葱模型（async/await） |
| **回调风格** | 回调函数 | async/await（Promise） |
| **请求/响应** | `req` / `res` 独立对象 | 统一的 `ctx` 上下文 |
| **路由** | 内置 `app.get/post` 等 | 无内置（需 koa-router） |
| **视图渲染** | 内置 `res.render()` | 无内置 |
| **Body 解析** | `express.json()` | 无内置（需 koa-bodyparser） |
| **包体积** | 较大 | 极小（~780 行源码） |
| **学习曲线** | 低（文档丰富） | 中等 |

## ctx 上下文对象

Koa 将 Node.js 的 `request` 和 `response` 封装到统一的 `context` 对象中：

```js
const Koa = require('koa');
const app = new Koa();

// ctx = context，是每次请求的唯一上下文
app.use(async (ctx, next) => {
  // --- 请求相关 ---
  ctx.request;          // Koa Request 对象（增强版）
  ctx.req;              // Node.js 原生 req
  ctx.method;           // 请求方法（ctx.request.method 的简写）
  ctx.url;              // 请求 URL
  ctx.path;             // URL 路径
  ctx.query;            // 查询参数（已解析的对象）
  ctx.querystring;      // 原始查询字符串
  ctx.header;           // 请求头（别名：headers）
  ctx.get('Content-Type'); // 获取指定请求头
  
  // --- 响应相关 ---
  ctx.response;         // Koa Response 对象（增强版）
  ctx.res;              // Node.js 原生 res
  ctx.body;             // 响应体（设置后自动序列化）
  ctx.status;           // 状态码
  ctx.length;           // Content-Length
  ctx.type;             // Content-Type（自动识别）
  ctx.set('X-Custom', 'val');  // 设置响应头
  ctx.append('Set-Cookie', ['a=b', 'c=d']);
  ctx.redirect('/new-url');
  ctx.attachment('file.pdf');   // 触发下载
  
  // --- 状态 ---
  ctx.state;            // 中间件间传递数据的推荐位置
  ctx.app;              // 应用实例
  ctx.originalUrl;      // 原始 URL
  ctx.ip;               // 客户端 IP
  ctx.accepts;          // 内容协商
  
  await next();
});
```

### ctx.body 的智能处理

```js
// string → 自动设置 Content-Type: text/html
ctx.body = '<h1>Hello</h1>';

// buffer → 自动设置 Content-Type: application/octet-stream
ctx.body = Buffer.from('binary data');

// object / array → 自动 JSON 序列化
ctx.body = { name: 'Alice', items: [1, 2, 3] };

// stream → 流式传输
ctx.body = fs.createReadStream('./large-file.zip');

// null → 204 No Content
ctx.body = null;
```

## 洋葱模型（Onion Model）

### 执行原理图示

```
请求进入
    │
    ▼
 ┌────────────────────────────────────────┐
 │                                        │
 │  ┌──────── middleware1 ────────┐       │
 │  │                             │       │
 │  │  ┌──── middleware2 ───┐     │       │
 │  │  │                    │     │       │
 │  │  │  ┌─middleware3─┐  │     │       │
 │  │  │  │             │  │     │       │
 │  │  │  │   核心      │  │     │       │
 │  │  │  │  (handler)  │  │     │       │
 │  │  │  │             │  │     │       │
 │  │  │  └─────────────┘  │     │       │
 │  │  │                    │     │       │
 │  │  └────────────────────┘     │       │
 │  │                             │       │
 │  └─────────────────────────────┘       │
 │                                        │
 └────────────────────────────────────────┘
    │
    ▼
  响应返回
```

### 执行时序详解

```js
const Koa = require('koa');
const app = new Koa();

// 中间件 1：外层
app.use(async (ctx, next) => {
  console.log('① 外层 - 请求进入（before next）');
  const start = Date.now();
  
  await next();  // ← 暂停，进入内层
  
  console.log('⑥ 外层 - 响应返回（after next）');
  const duration = Date.now() - start;
  ctx.set('X-Response-Time', `${duration}ms`);
});

// 中间件 2：中层
app.use(async (ctx, next) => {
  console.log('② 中层 - before next');
  
  await next();  // ← 暂停，进入内层
  
  console.log('⑤ 中层 - after next');
});

// 中间件 3：内层（核心处理）
app.use(async (ctx, next) => {
  console.log('③ 内层 - 核心逻辑');
  
  ctx.body = { message: 'Hello Koa!' };  // 设置响应体
  
  console.log('④ 内层 - 响应体已设置');
});

app.listen(3000);

// 访问后的输出顺序：
// ① 外层 - 请求进入（before next）
// ② 中层 - before next
// ③ 内层 - 核心逻辑
// ④ 内层 - 响应体已设置
// ⑤ 中层 - after next
// ⑥ 外层 - 响应返回（after next）
```

### 与 Express 中间件的对比

```js
// ===== Express（线性模型）=====
app.use((req, res, next) => {
  console.log('A before');
  next();          // 一去不复返（除非手动在后面加逻辑）
  console.log('A after');  // 在 next() 之后也会执行！但语义不直观
});

app.use((req, res, next) => {
  console.log('B handler');
  res.end('done');
});


// ===== Koa（洋葱模型）=====
app.use(async (ctx, next) => {
  console.log('A before');
  await next();     // 明确等待内层完成
  console.log('A after');  // 内层完成后才执行这里
});

app.use(async (ctx, next) => {
  console.log('B handler');
  ctx.body = 'done';  // 这里结束后回到外层的 "A after"
});
```

**关键区别**：

| 特性 | Express | Koa |
|------|---------|-----|
| `next()` 之后的代码 | 可执行但不常用 | **核心模式**（after 逻辑） |
| 控制流清晰度 | 一般 | **非常清晰**（洋葱结构自然表达） |
| 异步错误传播 | 需要 `next(err)` | **自动冒泡**（async/await 天然支持） |
| 请求耗时统计 | 需额外包装 | **天然适合**（前后包夹） |

## 常用 Koa 中间件实战

### 日志中间件（洋葱模型的典型应用）

```js
// 利用洋葱模型实现精确计时
async function logger(ctx, next) {
  const start = Date.now();
  
  // 请求阶段
  console.log(`  --> ${ctx.method} ${ctx.url}`);
  
  await next();  // 等待所有下游完成
  
  // 响应阶段
  const ms = Date.now() - start;
  console.log(`  <-- ${ctx.status} ${ctx.method} ${ctx.url} ${ms}ms`);
}

app.use(logger);
```

### 错误处理中间件

```js
// Koa 的错误会自动沿洋葱向外冒泡
app.use(async (ctx, next) => {
  try {
    await next();
  } catch (err) {
    console.error('Error:', err.message);
    
    // 已知的 HTTP 错误
    if (err.status || err.statusCode) {
      ctx.status = err.status || err.statusCode;
      ctx.body = { error: err.message };
      return;
    }
    
    // 未知错误
    ctx.status = 500;
    
    if (process.env.NODE_ENV === 'development') {
      ctx.body = { error: err.message, stack: err.stack };
    } else {
      ctx.body = { error: 'Internal Server Error' };
    }
  }
});

// 也可以用 app.on('error') 作为全局兜底
app.on('error', (err, ctx) => {
  // 记录日志、发送告警等
  logError(err, ctx);
});
```

### 认证中间件

```js
async function auth(ctx, next) {
  // 公开接口跳过验证
  if (ctx.path.startsWith('/public/') || ctx.path === '/health') {
    return await next();
  }
  
  const token = ctx.headers.authorization?.replace('Bearer ', '');
  
  if (!token) {
    ctx.status = 401;
    ctx.body = { error: 'No token provided' };
    return;  // 不调用 next() → 截断请求
  }
  
  try {
    const user = await verifyToken(token);
    ctx.state.user = user;  // 通过 ctx.state 向下游传递用户信息
    await next();
  } catch {
    ctx.status = 401;
    ctx.body = { error: 'Invalid token' };
  }
}

app.use(auth);
```

### CORS 中间件

```js
const cors = require('@koa/cors');

app.use(cors({
  origin: (ctx) => {
    const allowedOrigins = [
      'https://myapp.com',
      'https://staging.myapp.com',

    const origin = ctx.get('Origin');
```

## 组合中间件的高级用法

### 中间件条件启用

```js
function conditional(conditionFn, ...middlewares) {
  return async (ctx, next) => {
    if (conditionFn(ctx)) {
      // 用 compose 组合并执行中间件链
      const composed = compose(middlewares);
      await composed(ctx, next);
    } else {
      await next();
    }
  };
}

// 仅对 /api 路径启用认证
app.use(conditional(
  ctx => ctx.path.startsWith('/api'),
  authMiddleware,
  rateLimitMiddleware,
));

// 仅在非生产环境启用调试工具
app.use(conditional(
  () => process.env.NODE_ENV !== 'production',
  debugMiddleware,
));
```

### 中间件限流

```js
async function rateLimit(options = {}) {
  const {
    windowMs = 60 * 1000,    // 时间窗口
    maxRequests = 100,       // 最大请求数
  } = options;
  
  const requests = new Map();

  return async (ctx, next) => {
    const key = ctx.ip;
    const now = Date.now();
    
    // 清理过期记录
    for (const [k, v] of requests.entries()) {
      if (now > v.expiry) requests.delete(k);
    }
    
    const record = requests.get(key) || { count: 0, expiry: now + windowMs };
    
    if (record.count >= maxRequests) {
      ctx.status = 429;
      ctx.set('Retry-After', Math.ceil((record.expiry - now) / 1000));
      ctx.body = { error: 'Too many requests' };
      return;
    }
    
    record.count++;
    record.expiry = now + windowMs;
    requests.set(key, record);
    
    await next();
  };
}

app.use(rateLimit({ windowMs: 60 * 1000, maxRequests: 60 }));
```
