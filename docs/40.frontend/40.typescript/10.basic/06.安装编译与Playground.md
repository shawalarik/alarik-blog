## 一、环境准备：Node.js

在安装 TypeScript 之前，你需要先确保系统上已经安装了 **Node.js**。TypeScript 的编译器（`tsc`）本身是用 JavaScript/TypeScript 写的，需要 Node.js 环境来运行。

### 1.1 检查 Node.js 是否已安装

打开终端（Terminal），输入以下命令：

```bash
node --version
npm --version
```

如果能看到版本号输出（如 `v20.11.0` 和 `10.2.4`），说明已安装成功。

> 💡 **推荐版本**：Node.js **18.x 或更高**版本。LTS（长期支持）版本是稳定之选。

### 1.2 安装 Node.js（如果尚未安装）

- **官网下载**：访问 [nodejs.org](https://nodejs.org/)，选择 LTS 版本下载安装
- **使用 nvm**（推荐，方便管理多版本）：详见 nvm 文档
- **使用 Homebrew**（macOS）：`brew install node`

### 🎯 生活类比

把 Node.js 想象成一台**咖啡机**——它是运行环境；而 TypeScript 是**咖啡豆和配方**——它需要这台机器来处理并产出最终的饮品（JavaScript）。

## 二、安装 TypeScript

有两种主流的安装方式，各有适用场景。

### 2.1 方式一：全局安装（适合学习和小项目）

```bash
npm install -g typescript
```

安装完成后验证：

```bash
tsc --version
# 输出类似：Version 5.4.5
```

**优点**：
- 任何目录下都能直接使用 `tsc` 命令
- 适合快速学习和实验

**缺点**：
- 全局固定一个版本，不同项目可能需要不同版本的 TS
- 团队协作时可能因版本不一致产生问题

### 2.2 方式二：局部安装（推荐，适合正式项目）

```bash
# 在你的项目目录下执行：
cd my-project
npm init -y                    # 初始化 package.json（如果没有）
npm install --save-dev typescript   # 作为开发依赖安装
```

安装后通过 `npx` 调用：

```bash
npx tsc --version
```

或者添加 npm script 到 `package.json`：

```json
{
  "scripts": {
    "build": "tsc",
    "build:watch": "tsc -w"
  }
}
```

之后就可以用 `npm run build` 来编译了。

**优点**：
- 每个项目可以锁定自己的 TS 版本
- 团队成员通过 `npm install` 即可获得一致的环境
- 版本管理清晰，不会互相干扰

**缺点**：
- 每个新项目都需要单独安装

> 🎯 **我的建议**：学习和写小 demo 用全局安装没问题，但任何正经项目都应该用局部安装 + `npx` 或 npm scripts。

## 三、第一个 TypeScript 程序

### 3.1 创建 hello.ts

新建文件 `hello.ts`，写入以下内容：

```typescript
// hello.ts —— 你的第一个 TypeScript 程序！

// 定义一个带类型的变量
const message: string = "Hello, TypeScript!";

// 定义一个带类型注解的函数
function greet(name: string): string {
  return `${message} Welcome, ${name}!`;
}

// 调用函数
console.log(greet("Alarik"));
```

### 3.2 编译为 JavaScript

在终端中执行：

```bash
tsc hello.ts
```

如果一切顺利，终端不会有任何输出（Unix 哲学："没有消息就是好消息"）。此时同目录下会生成一个 `hello.js` 文件：

```javascript
// hello.js —— 编译器自动生成的 JS 文件
var message = "Hello, TypeScript!";
function greet(name) {
    return message + " Welcome, " + name + "!";
}
console.log(greet("Alarik"));
```

注意观察：
- 类型注解（`: string`）被完全移除了
- 模板字符串 `` `...` `` 可能被转换为普通字符串拼接（取决于编译目标）
- 变量声明 `const` 可能变成 `var`（同样取决于编译选项）

### 3.3 运行编译后的 JS 文件

```bash
node hello.js
# 输出：Hello, TypeScript! Welcome, Alarik!
```

### 3.4 完整流程图解

```
┌──────────┐    tsc     ┌──────────┐    node    ┌──────────────┐
│ hello.ts │ ────────▶  │ hello.js │ ────────▶  │ 终端输出结果   │
│ (编写代码) │  (编译)    │ (运行代码) │  (执行)    │              │
└──────────┘            └──────────┘            └──────────────┘
```

## 四、tsc 编译命令详解

`tsc` 是 TypeScript Compiler 的缩写，是最核心的命令行工具。

### 4.1 基本用法

```bash
# 编译单个文件
tsc filename.ts

# 同时编译多个文件
tsc file1.ts file2.ts file3.ts

# 编译当前目录下所有 .ts 文件
tsc
```

### 4.2 常用参数一览

| 参数 | 说明 | 示例 |
|------|------|------|
| `--outDir` | 指定输出目录 | `tsc --outDir dist` |
| `--rootDir` | 指定源码根目录 | `tsc --rootDir src` |
| `--target` | 指定编译到的 JS 版本 | `tsc --target ES2020` |
| `--module` | 指定模块系统 | `tsc --module ESNext` |
| `--strict` | 启用所有严格模式检查 | `tsc --strict` |
| `--watch` / `-w` | 监听文件变化自动重新编译 | `tsc -w` |
| `--noEmit` | 只做类型检查不输出文件 | `tsc --noEmit` |
| `--declaration` | 生成 `.d.ts` 类型声明文件 | `tsc --declaration` |
| `--sourceMap` | 生成 SourceMap 文件便于调试 | `tsc --sourceMap` |

#### 示例：指定输出目录

```bash
# 将编译产物放到 dist 目录
tsc hello.ts --outDir dist
# 结果：dist/hello.js
```

#### 示例：只做类型检查（CI/CD 场景常用）

```bash
# 不生成 .js 文件，仅检查类型错误——非常适合持续集成
tsc --noEmit
```

### 4.3 不同 target 对编译结果的影响

```typescript
// 源码 hello.ts
const greet = (name: string): string => `Hello, ${name}`;
```

| target | 输出 |
|--------|------|
| ES3 (`--target ES3`) | `var greet = function (name) { return "Hello, " + name; };` |
| ES5 (`--target ES5`) | `var greet = function (name) { return "Hello, " + name; };` |
| ES2015 (`--target ES2015`) | `var greet = (name) => \`Hello, ${name}\`;` |
| ES2020 (`--target ES2020`) | `const greet = (name) => \`Hello, ${name}\`;` |

可以看到，**target 设置越低，编译出的 JS 兼容性越广，但代码也越冗长**。

## 五、tsconfig.json——项目配置文件

当项目逐渐变大后，每次都手动输入一堆编译参数会很麻烦。`tsconfig.json` 就是用来集中管理这些配置的。

### 5.1 初始化配置文件

```bash
tsc --init
```

执行后会在当前目录生成一个带有大量注释的 `tsconfig.json`，大约有几百行。以下是**精简版的核心配置**：

```json
{
  "compilerOptions": {
    /* 基础选项 */
    "target": "ES2020",              // 编译目标 JS 版本
    "module": "ESNext",              // 模块系统
    "lib": ["ES2020", "DOM"],        // 包含的类型库
    "outDir": "./dist",             // 输出目录
    "rootDir": "./src",             // 源码根目录

    /* 严格模式 */
    "strict": true,                  // 启用所有严格检查
    "noUnusedLocals": true,          // 检查未使用的局部变量
    "noUnusedParameters": true,      // 检查未使用的函数参数
    "noFallthroughCasesInSwitch": true,

    /* 模块解析 */
    "moduleResolution": "bundler",   // 模块解析策略
    "esModuleInterop": true,         // CommonJS 与 ES Module 互操作
    "resolveJsonModule": true,       // 支持 JSON import

    /* 其他 */
    "sourceMap": true,               // 生成 sourcemap
    "declaration": true,             // 生成 .d.ts 声明文件
    "skipLibCheck": true             // 跳过 .d.ts 的类型检查
  },
  "include": ["src/**/*"],          // 包含的文件
  "exclude": ["node_modules"]       // 排除的目录
}
```

### 5.2 核心配置项详解

#### target — 目标 ECMAScript 版本

决定编译输出的 JS 代码兼容到哪个标准。可选值包括：`ES3`, `ES5`, `ES2015`, `ES2016`, ..., `ES2022`, `ESNext`。

```json
{
  "compilerOptions": {
    "target": "ES2020"  // 推荐值：现代浏览器基本都支持
  }
}
```

#### module — 模块系统

指定编译后的模块格式。常用值：`CommonJS`, `ESNext`, `AMD`, `System`, `UMD`。

```json
{
  "compilerOptions": {
    // Node.js 项目用 CommonJS
    // "module": "CommonJS",

    // 打包工具项目（Vite/Webpack）用 ESNext
    "module": "ESNext"
  }
}
```

#### strict — 严格模式总开关

这是**最重要的一个选项**！启用后会同时开启以下所有严格检查：

| 子选项 | 作用 |
|--------|------|
| `strictNullChecks` | 严格区分 null 和 undefined |
| `strictFunctionTypes` | 严格的函数类型检查 |
| `strictBindCallApply` | 严格的 call/apply/bind 检查 |
| `strictPropertyInitialization` | 类属性必须初始化 |
| `noImplicitAny` | 隐式 any 报错 |
| `noImplicitThis` | this 类型隐式 any 报错 |
| `alwaysStrict` | 启用严格模式 `"use strict"` |

```json
{
  "compilerOptions": {
    "strict": true  // 🌟 新项目强烈建议开启！
  }
}
```

> 🎯 **个人经验**：新项目直接开 strict。老项目迁移可以先关掉，然后逐个子选项开启，逐步适应。

#### outDir 和 rootDir — 目录结构控制

```json
{
  "compilerOptions": {
    "rootDir": "./src",    // 源码入口目录
    "outDir": "./dist"     // 编译输出目录
  }
}
```

这会让 `src/hello.ts` 编译到 `dist/hello.js`，保持目录结构一致。

### 5.3 配置好 tsconfig 后的使用方式

一旦有了 `tsconfig.json`，很多操作就简化了：

```bash
# 直接 tsc（不需要加文件名了！）——它会读取 tsconfig.json 的配置
tsc

# watch 模式
tsc -w

# 只检查类型
tsc --noEmit
```

## 六、Watch 模式（tsc -w）

在开发过程中，反复手动敲 `tsc` 很繁琐。Watch 模式可以让编译器监听文件变化，**自动重新编译**：

```bash
tsc -w
```

或者配合 tsconfig 使用：

```bash
# 在有 tsconfig.json 的项目中
tsc -w
```

启动后你会看到类似这样的输出：

```
[16:23:45] Starting compilation in watch mode...

[16:23:46] Found 0 errors. Watching for file changes.

[16:24:10] File change detected. Starting incremental compilation...
hello.ts(1,14): error TS2322: Type 'number' is not assignable to type 'string'.

[16:24:10] Found 1 error. Watching for file changes.
```

只要保存文件（Ctrl+S），编译器就会自动检测变更并重新编译。

### 🎯 推荐的开发工作流

```
编辑器（VS Code）中写 .ts 代码
        ↓ Ctrl+S 保存
实时看到红色波浪线（TS 语言服务即时提示）
        ↓
tsc -w 后台自动编译
        ↓ 浏览器热更新（如果配了 dev server）
立即看到效果
```

## 七、Playground 在线体验

不想本地安装？可以直接在浏览器里体验 TypeScript！

👉 访问 [TypeScript Playground](https://www.typescriptlang.org/play)

### 7.1 Playground 功能介绍

Playground 是 TypeScript 官方提供的在线编辑器，主要功能：

| 功能 | 说明 |
|------|------|
| 左侧编辑区 | 编写 TypeScript 代码 |
| 右侧预览区 | 实时查看编译后的 JavaScript |
| 设置面板 | 调整编译选项 |
| 代码示例 | 大量官方示例供参考 |

### 7.2 Playground 实战体验

打开 Playground，在左侧输入：

```typescript
interface Person {
  name: string;
  age: number;
}

function introduce(person: Person): string {
  return `我是${person.name}，今年${person.age}岁`;
}

introduce({ name: "Alarik", age: 25 });  // ✅ OK
// introduce({ name: "Alarik", age: "25" });  // ❌ Error!
```

右侧会实时显示编译结果。你可以点击右上角的设置图标调整各种编译选项。

### 7.3 Playground 的隐藏技巧

- **快捷键**：`Ctrl + Enter` 运行代码
- **分享链接**：点击 "Share" 按钮可以生成可分享的链接
- **对比不同设置**：可以开启多个 tab 对比不同编译选项的结果

## 八、常见问题排查

### 问题 1：版本冲突

```bash
# 你可能遇到的情况
tsc --version
# Version 4.9.5  ← 这是全局安装的旧版本

npx tsc --version
# Version 5.4.5  ← 这是你项目里的新版本
```

**解决方案**：优先使用 `npx tsc` 或 `npm run build`，确保用的是项目本地的版本。

### 问题 2：权限问题（macOS/Linux）

```bash
npm install -g typescript
# 报错：EACCES: permission denied
```

**解决方案**：不要用 sudo！改用 nvm 管理 Node.js，或者使用 npm 的用户级别目录：

```bash
mkdir ~/.npm-global
npm config set prefix '~/.npm-global'
export PATH=~/.npm-global/bin:$PATH
npm install -g typescript
```

### 问题 3：中文路径问题

Windows 用户如果将项目放在包含中文或特殊字符的路径下，可能会遇到奇怪的问题：

```bash
# ⚠️ 可能有问题的路径
D:\文档\我的项目\my-app\src\hello.ts

# ✅ 推荐的纯英文路径
D:\projects\my-app\src\hello.ts
```

**建议**：尽量使用英文路径。这不是 TypeScript 的问题，而是很多 Node.js 工具链对非 ASCII 路径的支持不够完善。

### 问题 4：tsc 命令找不到

```bash
tsc --version
# 'tsc' 不是内部或外部命令
```

**原因和解决**：

```bash
# 如果是全局安装后仍找不到，检查 npm 全局 bin 目录是否在 PATH 中
npm config get prefix
# 将返回的路径/bin 加入系统 PATH 环境变量

# 或者直接用 npx
npx tsc --version
```

## 九、推荐的完整项目工作流

以下是我实际项目中常用的 TypeScript 开发流程：

### 步骤 1：项目初始化

```bash
mkdir my-ts-project && cd my-ts-project
npm init -y
npm install --save-dev typescript
npx tsc --init
```

### 步骤 2：配置 tsconfig.json

根据上一节的内容，修改生成的 `tsconfig.json`。

### 步骤 3：创建源码目录结构

```
my-ts-project/
├── src/
│   ├── index.ts          # 入口文件
│   ├── utils/
│   │   └── helpers.ts    # 工具函数
│   └── types/
│       └── index.ts      # 共享类型定义
├── dist/                 # 编译输出（自动生成）
├── tsconfig.json
└── package.json
```

### 步骤 4：添加便捷的 npm scripts

```json
{
  "scripts": {
    "build": "tsc",
    "build:watch": "tsc -w",
    "check": "tsc --noEmit",
    "clean": "rm -rf dist"
  }
}
```

### 步骤 5：开始编码

```bash
# 终端 1：启动 watch 模式
npm run build:watch

# 终端 2：在 VS Code 中愉快地写代码
# 保存即编译，飘红即时反馈
```

## 十、个人总结与心得

### 关于工具链的心得

1. **工欲善其事，必先利其器**。花半小时把开发环境搭建好（tsconfig.json、npm scripts、editor 配置），后面能节省无数时间。

2. **善用 VS Code 的 TypeScript 插件**。VS Code 对 TypeScript 有一等支持——你甚至感觉不到你在用一门不同的语言。确保安装了插件并开启了 `typescript.tsdk` 设置。

3. **Watch 模式是你的好朋友**。开发时一直开着 `tsc -w`，让类型错误无处遁形。配合 VS Code 的实时提示，基本能做到零延迟发现 bug。

4. **Playground 是最好的实验场**。遇到不确定的类型行为，扔进 Playground 试一下比翻文档更快。

5. **保持构建工具的一致性**。如果你用 Vite 或 Webpack，它们内置了对 TypeScript 的支持——你可能根本不需要直接调用 `tsc`，只需要 tsconfig.json 就够了。
