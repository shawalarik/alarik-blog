## 一、什么是原始类型（Primitive Types）？

在 TypeScript 中，数据类型分为两大类：

```
TypeScript 类型体系
├── 原始类型（Primitive Types）    ← 本文重点
│   ├── string
│   ├── number
│   ├── boolean
│   ├── null
│   ├── undefined
│   ├── symbol
│   └── bigint
└── 对象类型（Object Types）
    ├── Array
    ├── Object
    ├── Function
    ├── Class/Interface
    └── ... 其他
```

### 🎯 核心区别

| 特性 | 原始类型 | 对象类型 |
|------|---------|---------|
| 存储方式 | 按值存储（不可变） | 按引用存储 |
| 比较方式 | 值比较（`===`） | 引用比较 |
| 示例 | `"hello"`, `42`, `true` | `[]`, `{}`, `function(){}` |

```typescript
// 原始类型 —— 按值比较
let a = "hello";
let b = "hello";
console.log(a === b); // true —— 值相同就相等

// 对象类型 —— 引用比较
let arr1 = [1, 2, 3];
let arr2 = [1, 2, 3];
console.log(arr1 === arr2); // false —— 虽然内容一样，但不是同一个引用！
```

> 💡 **生活类比**：原始类型就像**钞票**——面值相同的两张 100 元就是等价的。对象类型就像**房子**——即使两栋房子长得一模一样，它们也不是同一栋房子。

## 二、string 类型

字符串是最常用的类型之一，用于表示文本数据。

### 2.1 三种写法

```typescript
// 单引号
let single: string = 'Hello';

// 双引号
let double: string = "World";

// 模板字符串（反引号）—— 支持插值和多行
let template: string = `Hello, ${single}!`;
```

三种写法在 **TypeScript 中完全等价**，没有语义差异。选择哪一种是代码风格问题，建议团队统一即可。

### 2.2 字符串的常用操作

```typescript
let name: string = "TypeScript";

// 获取长度
name.length;        // 10

// 大小写转换
name.toUpperCase();  // "TYPESCRIPT"
name.toLowerCase();  // "typescript"

// 截取子串
name.slice(0, 4);   // "Type"
name.substring(4);   // "Script"

// 查找和替换
name.includes("type");     // false（大小写敏感）
name.startsWith("Type");    // true
name.endsWith("Script");    // true
name.replace("Script", "JS"); // "TypeJS"

// 分割和拼接
"a-b-c".split("-");        // ["a", "b", "c"]
["a", "b", "c"].join("-"); // "a-b-c"

// 去除空白
"  hello  ".trim();       // "hello"
```

### 2.3 字符串是不可变的

```typescript
let str: string = "hello";
str[0] = "H";  // ❌ TypeScript 编译错误！字符串索引只能读取不能修改
// str = "Hello"; ✅ 但整体重新赋值是可以的
```

这是 JavaScript 的特性，TypeScript 继承了这一点：**原始类型的值本身不可变**，变量只是指向新值的指针。

## 三、number 类型

TypeScript 的 number 类型与 JavaScript 一致——**不区分整数和浮点数**，所有数字都是 IEEE 754 双精度浮点数。

### 3.1 各种数字形式

```typescript
// 十进制
let decimal: number = 42;
let pi: number = 3.14159;

// 二进制（0b 前缀）
let binary: number = 0b1010;  // 等于 10

// 八进制（0o 前缀）
let octal: number = 0o744;    // 等于 484

// 十六进制（0x 前缀）
let hex: number = 0xff00;      // 等于 65280

// 大数字分隔符（ES2021+）
let bigNumber: number = 1_000_000; // 1000000，下划线提高可读性
```

### 3.2 特殊数值

```typescript
// NaN (Not a Number) —— 非数字结果
let notANumber: number = NaN;
console.log(0 / 0);           // NaN
console.log(Number("abc"));   // NaN

// ⚠️ NaN 有个特殊性质：
console.log(NaN === NaN);     // false！NaN 不等于任何东西，包括它自己
// 正确的判断方式：
console.log(Number.isNaN(NaN)); // true

// Infinity —— 无穷大
let positiveInfinity: number = Infinity;
let negativeInfinity: number = -Infinity;
console.log(1 / 0);            // Infinity
console.log(-1 / 0);           // -Infinity

// ⚠️ 注意：JavaScript/TypeScript 中除以零不会报错，而是返回 Infinity！
```

### 3.3 🚨 重要陷阱：浮点精度问题

```typescript
console.log(0.1 + 0.2);         // 0.30000000000000004
console.log(0.1 + 0.2 === 0.3); // false！

// 这不是 bug，是 IEEE 754 浮点数标准的固有特性
// 解决方案：
console.log(Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON); // true
// 或使用整数运算后再缩小
console.log((1 + 2) / 10);       // 0.3 ✅
```

> 💡 **生活类比**：浮点精度问题就像用十进制无法精确表达 1/3（= 0.3333...）。计算机用二进制也无法精确表示某些十进制小数，如 0.1。

## 四、boolean 类型

布尔类型只有两个值：`true` 和 `false`，用于逻辑判断。

### 4.1 基本用法

```typescript
let isActive: boolean = true;
let isComplete: boolean = false;

// 条件判断
if (isActive) {
  console.log("系统运行中");
}
```

### 4.2 Truthy 和 Falsy

虽然 boolean 类型只有两个值，但 JavaScript 中其他类型在条件上下文中也有"真/假"的含义：

| Falsy 值 | 说明 |
|----------|------|
| `false` | 布尔假 |
| `0` | 数字零 |
| `-0` | 负零 |
| `0n` | BigInt 零 |
| `""` | 空字符串 |
| `null` | 空值 |
| `undefined` | 未定义 |
| `NaN` | 非数字 |

**除此之外的所有值都是 Truthy**，包括 `"0"`, `"false"`, `[]`, `{}` 等！

```typescript
// ⚠️ 这些都是 truthy（可能出乎意料）
if ("") { console.log("空字符串"); }          // 不输出（falsy）
if ("0") { console.log("字符串0"); }          // 输出！字符串非空即 truthy
if ([] ) { console.log("空数组"); }            // 输出！对象总是 truthy
if ({}) { console.log("空对象"); }             // 输出！对象总是 truthy

// TypeScript 在严格模式下会帮你避免一些坑
let value: string | undefined;
if (value) {
  // 这里 TS 能自动收窄类型为 string（因为排除了 undefined）
  console.log(value.length);
}
```

## 五、null 和 undefined

这两个类型经常被放在一起讨论，它们都代表"没有值"，但含义不同。

### 5.1 区别与使用场景

```typescript
// undefined —— 变量已声明但尚未赋值
let notAssigned;              // 值为 undefined
let explicitlyUndefined: undefined = undefined;

// null —— 明确地表示"无值"或"空"
let emptyValue: null = null;
```

| | undefined | null |
|--|-----------|------|
| 含义 | "缺失"、"未定义" | "有意设为空" |
| 自动出现 | 访问未赋值的变量、不存在的属性时 | 必须手动赋值 |
| typeof 结果 | `"undefined"` | `"object"`（历史遗留 bug！） |
| JSON 支持 | ❌ JSON.stringify 会忽略 undefined | ✅ 会被序列化为 `null` |

```typescript
// 典型的 undefined 出现场景
let obj = { name: "Alarik" };
console.log(obj.age);        // undefined —— 属性不存在

function foo(x) {
  console.log(x);            // undefined —— 参数未传入
}

// 典型的 null 使用场景
let searchResult = db.query("SELECT * FROM users WHERE id = 999");
// 如果没查到数据，返回 null 表示"确实不存在"
if (searchResult === null) {
  console.log("用户不存在");
}
```

> 💡 **类比**：undefined 像"**还没填**"的表格格子；null 像"**特意填了 '无'**"的表格格子。一个是"忘了填"，一个是"确认没有"。

### 5.2 strictNullChecks 的影响

TypeScript 的 `strictNullChecks` 选项对 `null` 和 `undefined` 的处理有很大影响：

#### 关闭 strictNullChecks（默认宽松模式）

```typescript
let name: string = "Alarik";
name = null;     // ✅ 宽松模式下允许！null 可以赋值给 string
name = undefined; // ✅ 同样允许
```

这和 JavaScript 行为一致——但失去了类型安全保护。

#### 开启 strictNullChecks（推荐）

```typescript
let name: string = "Alarik";
name = null;     // ❌ 不能将类型 null 分配给类型 string
name = undefined; // ❌ 不能将类型 undefined 分配给类型 string

// 正确做法：显式包含 null/undefined
let nullableName: string | null = "Alarik";
nullableName = null;     // ✅ 现在可以了
nullableName = undefined; // ❌ 还是不行，需要加上 undefined
let looseName: string | null | undefined = "test";
looseName = undefined;   // ✅ 全都加上了
```

> 🎯 **强烈建议开启 strictNullChecks**。虽然初期会觉得繁琐，但它能帮你避免大量因 null/undefined 导致的运行时报错——这类错误在生产环境中极为常见。

### 5.3 可选链与空值合并（现代 JS/TS 最佳实践）

```typescript
interface User {
  name: string;
  address?: {
    city?: string;
    street?: string;
  };
}

const user: User = { name: "Alarik" };

// 可选链操作符 ?.
// 安全地访问深层属性，中间任何一环为 null/undefined 就返回 undefined
let city = user.address?.city;       // undefined —— 不会报错！
let street = user.address?.street?.toUpperCase(); // undefined —— 链式安全

// 空值合并运算符 ??
// 只在值为 null 或 undefined 时使用默认值（不同于 ||，它不会被 0 或 "" 触发）
let userName = user.name ?? "匿名用户";  // "Alarik"
let userCity = user.address?.city ?? "未知城市"; // "未知城市"

// 与 || 的对比
let count = 0;
let result1 = count || 10;   // 10 —— 因为 0 是 falsy！
let result2 = count ?? 10;   // 0 —— ?? 只针对 null/undefined
```

## 六、symbol 类型

Symbol 是 ES2015（ES6）引入的新的原始类型，用于创建**唯一且不可变**的值。

### 6.1 基本用法

```typescript
// 创建 Symbol
const sym1: symbol = Symbol();
const sym2: symbol = Symbol("description"); // 可选描述字符串（仅用于调试）

// 每个 Symbol 都是唯一的
console.log(Symbol() === Symbol()); // false —— 即使描述相同也不相等！
console.log(Symbol("foo") === Symbol("foo")); // false
```

### 6.2 主要用途

#### 用途 1：作为对象属性的键（避免命名冲突）

```typescript
const idKey = Symbol("id");

const user = {
  name: "Alarik",
  [idKey]: 12345,  // 用 Symbol 作为属性键
};

console.log(user[idKey]); // 12345
console.log(Object.keys(user)); // ["name"] —— Symbol 属性不出现在常规枚举中！
```

这在设计库/框架时特别有用——可以用 Symbol 作为内部属性名，确保不会和用户的自定义属性冲突。

#### 用途 2：定义常量（替代字符串魔术值）

```typescript
// ❌ 传统方式：用字符串作为常量
if (order.status === "pending") { ... }
// 问题：拼写错误不会被捕获

// ✅ Symbol 方式
const ORDER_STATUS = {
  PENDING: Symbol("pending"),
  SHIPPED: Symbol("shipped"),
  DELIVERED: Symbol("delivered"),
} as const;

if (order.status === ORDER_STATUS.PENDING) { ... }
// Symbol 的唯一性保证了不会有误判
```

#### 用途 3：内置 Symbol（Well-known Symbols）

JavaScript 内置了一些 Symbol 常量，用于定制对象的内置行为：

```typescript
const iterableObj = {
  items: [1, 2, 3],
  [Symbol.iterator]() {  // 让对象可以被 for...of 遍历
    let index = 0;
    return {
      next: () => ({
        done: index >= this.items.length,
        value: this.items[index++],
      }),
    };
  },
};

for (const item of iterableObj) {
  console.log(item); // 1, 2, 3
}
```

## 七、bigint 类型

BigInt 是 ES2020 引入的类型，用于表示**任意精度的整数**。

### 7.1 为什么需要 bigint？

普通的 `number` 类型有一个最大安全整数限制：

```typescript
// number 的安全范围
console.log(Number.MAX_SAFE_INTEGER);  // 9007199254740991 (约 9 千万亿)
console.log(Number.MAX_SAFE_INTEGER + 1 === Number.MAX_SAFE_INTEGER + 2);
// true！！超出了安全范围后计算就不准了
```

当需要处理超大整数（如加密算法、数据库 ID、高精度时间戳等），就需要 `bigint`。

### 7.2 使用方法

```typescript
// 创建 BigInt —— 在整数末尾加 n 后缀
let big1: bigint = 9007199254740993n;
let big2: bigint = 9007199254740994n;

// 或者用构造函数
let big3: bigint = BigInt("9007199254740995");

// 基本运算
console.log(big1 + big2n);    // 18014398509481987n
console.log(big2 * big3);     // 结果保持精度
console.log(big1 > big2);     // true

// ⚠️ BigInt 不能和普通 number 直接混用
let num: number = 42;
// let result = big1 + num; // ❌ 编译错误！不能混合运算
let result = big1 + BigInt(num); // ✅ 先转换为 BigInt
```

### 7.3 实际应用场景

```typescript
// 场景 1：数据库中的大 ID（如 Twitter 的 Snowflake ID）
const tweetId: bigint = 1234567890123456789n;

// 场景 2：高精度时间戳（微秒级）
const microTimestamp: bigint = BigInt(Date.now()) * 1000n;

// 场景 3：金融计算中需要精确分的时候
const amountInCents: bigint = 199900n; // $1999.00，用分为单位避免浮点问题
```

> 💡 **注意**：BigInt 目前在序列化方面还有局限性——`JSON.stringify()` 默认不支持 BigInt，需要自行处理。

## 八、字面量类型（Literal Types）

这是一个非常重要的概念：除了通用类型（如 `string`、`number`），TypeScript 还支持更**具体**的字面量类型。

### 8.1 const vs let 的推断差异

```typescript
// let 声明 —— 推断为宽泛类型
let x = "hello";   // 推断为 string
x = "world";       // ✅ 可以改成任何字符串
x = 42;            // ❌ 但不能改成 number

// const 声明 —— 推断为字面量类型
const y = "hello"; // 推断为 "hello"（不是 string！）
// y = "world";    // ❌ 不能改，因为 y 的类型是字面量 "hello"
```

这就是为什么推荐**默认使用 const**的原因之一——它能提供更精确的类型信息。

### 8.2 显式声明字面量类型

```typescript
// 字符串字面量类型
let direction: "north" | "south" | "east" | "west";
direction = "north";  // ✅
direction = "up";     // ❌ "up" 不在允许的列表中

// 数字字面量类型
let diceRoll: 1 | 2 | 3 | 4 | 5 | 6;
diceRoll = 3;  // ✅
diceRoll = 7;  // ❌

// 布尔字面量类型
let isReady: true;
isReady = true;   // ✅
isReady = false;  // ❌
```

### 8.3 实际应用示例

```typescript
// HTTP 方法
type HttpMethod = "GET" | "POST" | "PUT" | "DELETE" | "PATCH";

function request(url: string, method: HttpMethod): void {
  console.log(`${method} ${url}`);
}

request("/api/users", "GET");    // ✅
request("/api/users", "get");    // ❌ 小写不行！
// request("/api/users", "OPTIONS"); // ❌ 不在联合类型中
```

字面量类型配合联合类型使用非常强大——它让你能在**编写时就限定取值范围**，从根本上杜绝非法输入。

## 九、类型标注语法总结

TypeScript 的基本类型标注语法如下：

```typescript
// 完整语法：let/const 变量名: 类型 = 值;
let myName: string = "Alarik";
let myAge: number = 25;
let isActive: boolean = true;
let nothing: null = null;
let notDefined: undefined = undefined;
let uniqueId: symbol = Symbol("id");
let hugeNumber: bigint = 100n;

// 函数参数和返回值的类型标注
function add(a: number, b: number): number {
  return a + b;
}

// 箭头函数
const multiply = (x: number, y: number): number => x * y;

// 变量声明但不赋值（此时必须有类型注解）
let score: number;
score = 100; // ✅
// score = "excellent"; // ❌
```

### 📌 类型标注的位置规则

```
变量: let variableName: Type = value
参数: function func(paramName: Type)
返回值: function func(): ReturnType
```

## 十、常见陷阱汇总

### 陷阱 1：number 不区分 int 和 float

```typescript
let integer: number = 42;
let float: number = 3.14;
// 它们都是同一个 number 类型！TypeScript 没有 int/float 的区分

// 如果你真的需要区分，可以用类型别名 + 约束来模拟（但通常没必要）
type Int = number & { __int__: never }; // 模拟技巧，不推荐日常使用
```

### 陷阱 2：typeof null === 'object'

```typescript
// 这是 JavaScript 的历史遗留 bug，从诞生第一天就有
console.log(typeof null);  // "object" —— 应该是 "null"！

// TypeScript 无法修复这个问题（为了兼容性）
let data: any = getDataFromAPI();
if (typeof data === "object" && data !== null) {
  // ⚠️ 必须额外检查 !== null！否则 null 会通过 object 检查
  console.log(data.property);
}
```

### 陷阱 3：隐式 any 警告

```typescript
let x;  // TS 报错：参数 "x" 隐式具有 "any" 类型
// 开启 noImplicitAny 后，必须显式标注类型或赋予初始值

// 解决方案 1：标注类型
let x: number;

// 解决方案 2：赋予初始值（TS 会自动推断）
let x = 10;
```

### 陷阱 4：as any 的滥用诱惑

```typescript
let data: any = getSomeData();
(data as any).doAnything(); // 绕过所有类型检查

// ⚠️ 这等于主动放弃了 TypeScript 的保护！
// 就像买了保险却每次都故意制造事故
```

### 陷阱 5：字符串和 String 不同

```typescript
let primitive: string = "hello";     // 原始类型 ✅ 推荐
let wrapper: String = new String("hello"); // 包装对象 ❌ 不推荐

// 始终使用原始类型 string，不要用包装类 String
console.log(typeof primitive); // "string"
console.log(typeof wrapper);   // "object"
```

## 十一、与 JavaScript 原始类型的对应关系

TypeScript 的原始类型与 JavaScript 完全对应：

| JavaScript | TypeScript | typeof 结果 |
|-----------|-----------|-------------|
| String | `string` | `"string"` |
| Number | `number` | `"number"` |
| Boolean | `boolean` | `"boolean"` |
| Null | `null` | `"object"` ⚠️ |
| Undefined | `undefined` | `"undefined"` |
| Symbol (ES6+) | `symbol` | `"symbol"` |
| BigInt (ES2020+) | `bigint` | `"bigint"` |

> **关键点**：TypeScript 的类型系统是对 JavaScript 运行时类型的**静态描述**，而不是创造了一套新的类型。理解这一点对于学习 TypeScript 至关重要。

## 十二、个人总结与心得

### 关于原始类型的几点体会

1. **类型标注是可选但推荐的**。TypeScript 强大的类型推断意味着很多时候你不需要手写类型。但在函数签名、公共 API、复杂逻辑处，显式标注能大幅提升可读性和 IDE 提示质量。

2. **字面量类型是被低估的特性**。很多初学者只停留在 `string` / `number` 层面，其实 `"GET" \| "POST"` 这样的联合字面量类型在日常开发中使用频率极高，能从源头防止大量 bug。

3. **null vs undefined 要有明确的使用策略**。我倾向于：未初始化/缺失用 `undefined`，主动清空用 `null`。配合 `strictNullChecks` + 可选链 `?.` + 空值合并 `??`，基本可以消灭所有空值相关报错。

4. **Symbol 和 bigint 是锦上添花**。日常业务开发中用到的不多，但在特定场景（库开发、加密、大数据量 ID）下不可或缺。

5. **基础决定上层建筑**。原始类型看起来简单，但它们是一切复杂类型的基石。花时间彻底搞清楚每个原始类型的特性和边界情况，后续学习接口、泛型等高级概念时会事半功倍。
