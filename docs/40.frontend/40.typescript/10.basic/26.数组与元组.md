# 数组与元组——固定长度与可变长度的类型表达

> 在 JavaScript 中，数组就是数组，什么都能往里塞。但到了 TypeScript，数组和元组是两种不同的概念：
>
> **数组 = 同类物品的容器（可变长度）**
> **元组 = 固定结构的有序集合（固定长度 + 每位有特定类型）**

这篇文章将彻底讲清楚两者的区别、用法和最佳实践。

## 一、数组类型的定义方式

### 1.1 两种等价写法

TypeScript 提供了两种声明数组类型的方式，它们完全等价：

**方式一：方括号语法（更简洁，推荐日常使用）**

在类型后面加一对方括号，表示"这是一个装着某类型元素的容器"。就像你在超市购物时，购物车旁边标注了"只能放水果"——`string[]` 就是"只能放字符串的容器"，`number[]` 就是"只能放数字的容器"。

- 写法：先写元素类型，再加 `[]`
- 示例含义：`let scores: number[]` 表示"scores 是一个数字数组"
- 直观程度：五颗星，看一眼就懂

**方式二：泛型 Array 写法（更正式，复杂场景更清晰）**

使用 JavaScript 内置的 `Array` 全局对象，通过尖括号指定元素类型。这就像是给 `Array` 这个通用容器贴了一张标签："这个容器里装的是某种类型的元素"。

- 写法：`Array` 后面用尖括号包住元素类型（如 Array 后面跟 string）
- 示例含义：`let names` 声明为 Array 格式的 string 类型，表示"names 是一个字符串数组"
- 优势：嵌套时比多个方括号连写更易读

> **生活类比**：想象你去租储物柜。
>
> - **方式一（方括号）**：你直接说"我要一个放鞋子的格子组"——简单直接
> - **方式二（Array 写法）**：你走到通用柜台说"我要一个储物柜，里面用来存放鞋子"——正式但啰嗦一点
>
> 两种方式最终拿到的柜子完全一样，只是说话的方式不同。

### 1.2 什么时候用 Array 写法更好？

当元素本身就是一个数组类型时，Array 写法的优势就显现出来了：

**嵌套数组的可读性对比**

想象一下，你需要表达"一个数字矩阵"（即二维数组）：

- **方括号写法**：`number[][]` —— 两个方括号挤在一起，再多一层变成三连方括号，眼睛开始花了
- **Array 写法**：Array 包裹 Array 再包裹 number —— 虽然更长，但每一层都清晰可见

> **生活类比**：就像俄罗斯套娃。
>
> - 方括号写法就像直接说"套娃里的套娃"——简洁但层数多了容易晕
> - Array 写法就像说"一个装着'装着数字的容器'的容器"——啰嗦但每层关系一目了然

**函数类型数组的特殊情况**

当数组元素本身就是函数类型时，方括号语法会变得很难读。比如一个"接收字符串、返回空"的函数组成的数组：

- 方括号写法：先写函数签名再加方括号 —— 括号套括号，容易搞不清谁跟谁配对
- Array 写法：函数类型被整齐地包在尖括号里 —— 结构清晰

> **经验法则**：简单场景用方括号（日常开发绝大多数情况），复杂/嵌套场景用 Array 写法（泛型、多维数组、函数类型数组）。

### 1.3 生活化类比

| 概念 | 现实类比 | TS 表示 |
|------|---------|---------|
| 数组 (`string[]`) | 一箱苹果，每个都是苹果 | 装着同类型元素的列表 |
| 多维数组 (`number[][]`) | 教室里的座位表，每行每列都是座位 | 数组的数组 |
| 元组 (`[string, number]`) | 一个身份证：(姓名, 号码)，顺序和类型都固定 | 有序的异构数据组合 |

## 二、多维数组

### 2.1 二维数组

```typescript
// 二维数字数组 —— 类似矩阵
let matrix: number[][] = [
  [1, 2, 3],
  [4, 5, 6],
  [7, 8, 9],
];

// 访问元素
console.log(matrix[0][1]); // → 2

// 遍历
for (const row of matrix) {
  for (const num of row) {
    console.log(num);
  }
}
```

### 2.2 不规则二维数组

TypeScript 允许"锯齿状"数组（各行长度不同）：

```typescript
// 每行长度可以不同
let jagged: number[][] = [
  [1, 2],        // 2 个元素
  [3, 4, 5],     // 3 个元素
  [6],           // 1 个元素
];

jagged[0].push(3);     // ✅ 可以动态添加
jagged[1].pop();       // ✅ 可以删除
```

### 2.3 三维及以上

虽然不常见，但 TS 支持任意维度：

```typescript
// 三维数组：类似立方体数据
let cube: number[][][] = [
  [[1, 2], [3, 4]],
  [[5, 6], [7, 8]],
];
```

实际项目中超过二维的情况很少见，如果遇到，通常建议用更结构化的方式组织数据。

## 三、数组方法的类型安全

这是 TypeScript 数组最强大的特性之一：**所有数组方法都有完整的类型约束**。

### 3.1 map —— 自动推断返回值类型

```typescript
const numbers = [1, 2, 3, 4, 5];

// map 回调的参数自动推断为 number
const doubled = numbers.map((n) => n * 2);
// doubled 的类型：number[]

// 返回不同类型也没问题
const strNumbers = numbers.map((n) => `num: ${n}`);
// strNumbers 的类型：string[]
```

**注意回调参数的类型**：

```typescript
const numbers = [1, 2, 3];

// ❌ 错误：map 回调的第二个参数是索引（number），不是数组元素
numbers.map((n, index) => {
  console.log(index.toUpperCase()); // index 是 number，没有 toUpperCase 方法
});

// ✅ 正确
numbers.map((n, index) => {
  console.log(`index ${index}: ${n}`); // n 才是 number 元素
});
```

### 3.2 filter —— 收窄类型

`filter` 最神奇的地方在于它能**收窄类型**：

```typescript
const mixed = [1, "two", 3, null, "five", undefined];

// 过滤掉 null 和 undefined
const filtered = mixed.filter(
  (item): item is string | number => item != null
);
// filtered: (string | number)[]
```

一个更实用的例子——过滤空值：

```typescript
function processItems(items: (string | null | undefined)[]) {
  // filter(Boolean) 会移除 falsy 值
  const validItems = items.filter((item): item is string => typeof item === "string");
  // validItems: string[] —— null 和 undefined 被排除了！
  return validItems.map(s => s.toUpperCase());
}
```

### 3.3 reduce —— 需要小心初始值

`reduce` 对初始值的类型推断非常敏感：

```typescript
const numbers = [1, 2, 3, 4, 5];

// ✅ 提供初始值 —— 推断正确
const sum = numbers.reduce((acc, n) => acc + n, 0);
// sum: number

// ⚠️ 没有初始值 —— 可能推断出包含 undefined
const sum2 = numbers.reduce((acc, n) => acc + n);
// sum2: number（因为数组非空时没问题）

// 但如果数组可能为空...
const maybeEmpty: number[] = [];
const result = maybeEmpty.reduce((acc, n) => acc + n); // 可能返回 undefined！
```

**最佳实践**：始终给 `reduce` 提供初始值。

### 3.4 forEach / find / some / every 等

```typescript
const users = [
  { id: 1, name: "Alice", active: true },
  { id: 2, name: "Bob", active: false },
  { id: 3, name: "Charlie", active: true },
];

// find —— 返回元素或 undefined
const activeUser = users.find((u) => u.active);
// activeUser: { id: number; name: string; active: boolean } | undefined

// some / every —— 返回 boolean
const hasActiveUser = users.some((u) => u.active); // boolean
const allActive = users.every((u) => u.active);    // boolean

// forEach —— 无返回值
users.forEach((u) => {
  console.log(u.name);
});
```

## 四、只读数组

在函数式编程和不可变数据流中，只读数组非常重要。TS 提供了多种声明只读数组的方式：

### 4.1 ReadonlyArray —— 只读数组

**概念**：ReadonlyArray 是一种特殊的数组类型（在 Array 前面加了 Readonly 前缀），它告诉你和 TypeScript："这个数组只能读，不能写"。

**为什么需要它？**

想象你把一本珍贵的书借给了朋友。你希望他只能**阅读**这本书，不能在上面涂画、撕页或加书签。ReadonlyArray 就是编程世界里的这种"只读约定"——你可以看里面的每个元素，但不能修改、添加或删除任何元素。

**实际效果（用文字描述代码行为）**：

声明一个只读数字数组的代码大致长这样：用 ReadonlyArray 关键字后面跟 number 类型来声明一个变量，然后赋值为 `[1, 2, 3]`。这等价于下一节要讲的 `readonly number[]` 写法。

**能做的操作（读取类）**：
- 通过索引读取元素：比如取下标 0 就能得到第一个元素的值
- 获取长度：通过 `.length` 属性拿到数组长度
- 遍历：for...of 循环、forEach 方法、map/filter/reduce 等不修改原数组的方法都能正常使用
- 拼接：concat 方法返回一个新数组，原数组不受影响

**不能做的操作（写入类）**：
- 通过索引赋值 —— 编译直接报错！因为它是只读属性
- push 方法 —— 报错！push 不存在于 ReadonlyArray 类型上
- pop / shift / splice —— 都不存在！这些方法会修改原数组内容
- 给 length 重新赋值 —— 报错！length 属性也是只读的

> **生活类比对比**：
>
> | 类型 | 类比 | 能否修改 |
> |------|------|---------|
> | **普通数组**（number 方括号） | 家里的收纳箱 | 随便拿进拿出 |
> | **ReadonlyArray** | 博物馆展柜 | 只能看，不能摸 |

**核心使用场景**：

1. **函数参数保护**：当你写一个函数只需要"读取"数组而不应该修改它时，把参数类型声明为 ReadonlyArray 格式。这样即使你或者你的队友不小心在函数里写了 `arr.push(x)`，TypeScript 会立刻报错拦住你。

2. **状态不可变性**：React、Vue 等现代框架推崇不可变数据。把组件的状态声明为只读数组，可以从类型层面确保状态不会被意外篡改。

3. **公开 API 设计**：如果你在写一个库，对外暴露的数据用 ReadonlyArray 包装，可以防止使用者直接修改内部数据——这是防御性编程的最佳实践。

### 4.2 readonly 修饰符（推荐）

更简洁的写法是在类型后面加 `readonly`：

```typescript
let arr: readonly number[] = [1, 2, 3];

arr.push(4);   // ❌
arr[0] = 10;   // ❌
```

### 4.3 as const —— 最强力的只读断言

```typescript
// 普通数组
let arr = [1, 2, 3];        // number[]

// as const 断言
let readonlyTuple = [1, 2, 3] as const;
// readonly [1, 2, 3] —— 不仅只读，还是字面量元组

// 对象 + 数组
let config = {
  ports: [80, 443],
  endpoints: ["/api", "/auth"],
} as const;
/*
config.ports: readonly [80, 443]
config.endpoints: readonly ["/api", "/auth"]
*/
```

### 4.4 只读 vs 可写的兼容性规则

这是一个重要的兼容性规则：

```typescript
// 可写数组可以赋值给只读数组（安全：你承诺不修改）
let writable: number[] = [1, 2, 3];
let readable: readonly number[] = writable; // ✅

// 但反过来不行！（不安全：只读的可能实际上不可写）
let writable2: number[] = readable; // ❌ 错误！

// 解决方案：创建一份副本
let writable2: number[] = [...readable]; // ✅ 创建新数组
```

**生活类比**：这就像"只读文件权限"。任何人都可以读取公开文件（可写数组→只读数组），但你不能把只读文档当成可编辑文档来用。

## 五、元组（Tuple）—— 固定结构的数据

### 5.1 什么是元组？

**元组（Tuple）是一种特殊的数组，它有两个特征：**
1. **长度固定** —— 不能多也不能少
2. **每位有特定的类型** —— 第几位是什么类型是确定的

```typescript
// 声明一个元组
let person: [string, number] = ["Alarik", 25];

// 访问元素
person[0]; // string 类型
person[1]; // number 类型

// ✅ 正确的使用
person[0] = "Bob";
person[1] = 30;

// ❌ 错误：类型不对
person[0] = 123;         // 不能将 number 赋值给 string
person[1] = "twenty-five"; // 不能将 string 赋值给 number

// ❌ 错误：越界访问
person[2];               // 元组长度为 2，没有索引 2
```

### 5.2 为什么需要元组？

当一组数据有固定的含义和顺序时，元组比对象更合适：

```typescript
// 场景一：坐标点
type Point = [number, number]; // [x, y]
const origin: Point = [0, 0];
const location: Point = [116.40, 39.90]; // 北京坐标

// 场景二：RGB 颜色值
type RGB = [number, number, number]; // [r, g, b]，范围 0-255
const red: RGB = [255, 0, 0];
const green: RGB = [0, 255, 0];
const blue: RGB = [0, 0, 255];

// 场景三：函数返回多个值
function getNameAndAge(): [string, number] {
  return ["Alarik", 25];
}

const [name, age] = getNameAndAge();
// name: string, age: number

// 场景四：数据库记录的某一行
type UserRow = [number, string, string, boolean]; // [id, username, email, isActive]
const row: UserRow = [1, "alarik", "test@example.com", true];
```

**对比对象版本**：

```typescript
// 对象版本 —— 冗长
interface PointObj { x: number; y: number }
const p: PointObj = { x: 0, y: 0 };

// 元组版本 —— 简洁
const p: [number, number] = [0, 0];
```

### 5.3 可选元素元组

元组的某些位置可以是可选的：

```typescript
// 最后一位可选
let optional: [string, number?] = ["hello"];
optional = ["hello", 42];  // ✅ 两个元素也可以

// 使用前要检查是否存在
if (optional[1] !== undefined) {
  console.log(optional[1]); // 此时 TS 知道它是 number
}

// 实际应用：HTTP 响应
type HttpResponse = [number, string?, object?];
// [statusCode, statusMessage?, body?]

const ok: HttpResponse = [200];
const notFound: HttpResponse = [404, "Not Found"];
const serverError: HttpResponse = [500, "Internal Error", { code: "E001" }];
```

**注意**：可选元素只能出现在**必需元素之后**，且通常只在末尾。

### 5.4 剩余元素元组（Rest Elements）

元组也可以像函数参数一样有"剩余元素"：

```typescript
// 前两位固定，后面可以有任意数量的 string
let flexible: [string, number, ...string[]];

flexible = ["hello", 42];                    // ✅
flexible = ["hello", 42, "a"];               // ✅
flexible = ["hello", 42, "a", "b", "c"];     // ✅

// 剩余元素在最前面
let leadingRest: [...string[], boolean];

leadingRest = [true];                         // ✅
leadingRest = ["a", "b", true];              // ✅

// 实际应用：标签化联合（Tagged Template Arguments）
function log(level: 'info' | 'warn' | 'error', ...messages: string[]) {
  console.log(`[${level.toUpperCase()}]`, ...messages);
}

log("info", "应用启动");
log("error", "连接失败", "请检查网络设置");
```

### 5.5 只读元组

元组也可以是只读的：

```typescript
let readonlyTuple: readonly [string, number] = ["hello", 42];

readonlyTuple[0] = "world";  // ❌ 只读
readonlyTuple.push("!");      // ❌ push 不存在
readonlyTuple.pop();          // ❌ pop 不存在

// 配合 as const
const config = ["production", 3000, true] as const;
// 类型：readonly ["production", 3000, true]
```

## 六、元组 vs 数组的选择标准

### 6.1 决策指南

```
你的数据是……？
│
├─ 同一种类型，数量不限
│   └── 👉 用数组：number[]、string[] 等
│
├─ 不同类型，但数量和类型都固定
│   └── 👉 用元组：[string, number, boolean]
│
├─ 大部分固定，但有可选部分
│   └── 👉 用带可选元素的元组：[string, number?]
│
├─ 开头/结尾固定，中间可变
│   └── 👉 用带剩余元素的元组：[string, ...number[]]
│
└─ 结构复杂，字段有名称语义
    └── 👉 用对象/ interface（比元组更清晰）
```

### 6.2 各自的优势与劣势

| 特性 | 数组 | 元组 |
|------|------|------|
| 长度 | 动态可变 | 固定 |
| 元素类型 | 统一类型（或联合类型） | 每位可有不同类型 |
| 适用场景 | 列表、集合、队列等 | 坐标、颜色、固定格式数据 |
| 可读性 | 高（意图明确） | 中（需记住每位含义） |
| IDE 支持 | 好 | 较好 |
| 解构体验 | 好 | 很好 |

### 6.3 我的个人偏好

在实际开发中，我的经验是：

- **优先使用对象/interface**：当数据有明确语义时（如 `{ x, y }` 比 `[x, y]` 更清晰）
- **使用元组**的场景主要是：
  1. 函数返回多个临时值
  2. 与外部 API/库对接时的固定格式数据
  3. 坐标、颜色值等数学/图形领域的数据
  4. 作为性能敏感场景中对象的轻量替代

## 七、常见陷阱：越界访问问题

### 7.1 数组的越界访问

```typescript
const arr = [1, 2, 3];
const item = arr[99]; // 不报错！类型是 number，运行时却是 undefined
```

这是一个已知的 TS 设计决策：为了保持灵活性，TS **默认允许**对数组进行越界索引，返回的类型可能是 `undefined`。

### 7.2 如何避免越界问题

**方法一：开启 noUncheckedIndexedAccess**

```json
{
  "compilerOptions": {
    "noUncheckedIndexedAccess": true
  }
}
```

开启后：

```typescript
const arr = [1, 2, 3];
const item = arr[99]; // 类型变成 number | undefined —— 强制你做检查
```

**方法二：使用 at() 方法（负索引友好）**

```typescript
const arr = [1, 2, 3];
const last = arr.at(-1); // number | undefined —— 天然安全的 API

const first = arr.at(0);  // number | undefined
```

**方法三：解构赋值**

```typescript
const arr = [1, 2, 3];
const [first, second] = arr;
// first: number, second: number
```

### 7.3 元组的越界保护

好消息是：**元组的越界保护比普通数组好得多**：

```typescript
const tuple: [string, number] = ["hello", 42];

tuple[0]; // ✅ string
tuple[1]; // ✅ number
tuple[2]; // ❌ 元组长度为 2，超出范围的索引不允许
```

这也是选择元组的另一个理由：**更好的类型安全保障**。

## 八、实际应用案例

### 案例 1：处理 CSV 数据

```typescript
// CSV 的每一行解析后可以用元组表示
type CSVRow = [string, string, number, Date]; // [姓名, 邮箱, 年龄, 注册时间]

function parseCSVRow(line: string): CSVRow {
  const parts = line.split(",");
  return [parts[0], parts[1], parseInt(parts[2]), new Date(parts[3])];
}

const rows: CSVRow[] = [
  ["Alice", "alice@example.com", 25, new Date("2024-01-15")],
  ["Bob", "bob@example.com", 30, new Date("2024-02-20")],
];

// 处理每一行
rows.forEach(([name, , age, registeredAt]) => {
  console.log(`${name} 今年 ${age} 岁，注册于 ${registeredAt.toDateString()}`);
});
```

### 案例 2：状态机管理

```typescript
// 使用元组表示状态的转换规则
type StateTransition =
  | ['idle', 'loading']
  | ['loading', 'success']
  | ['loading', 'error']
  | ['success', 'idle']
  | ['error', 'idle'];

function transition(currentState: StateTransition[0], action: StateTransition[1]): void {
  console.log(`状态从 ${currentState} 变为 ${action}`);
}

transition('idle', 'loading');     // ✅
transition('loading', 'success');  // ✅
transition('idle', 'success');     // ❌ 不是合法的转换！
```

### 案例 3：React 自定义 Hook 返回元组

```typescript
// 类似 useState 的模式
function useToggle(initialValue: boolean): [boolean, () => void] {
  const [value, setValue] = useState(initialValue);
  const toggle = () => setValue(v => !v);
  return [value, toggle];
}

// 使用
const [isOn, toggle] = useToggle(false);
// isOn: boolean
// toggle: () => void
```

这种模式在 React 生态圈非常流行（useState、useReducer、useSearchParams 都返回元组）。

## 九、个人总结与心得

### 9.1 核心要点回顾

| 概念 | 关键字 | 核心特点 |
|------|--------|----------|
| 普通数组 | `T[]` / `Array 写法` | 同类型、可变长度 |
| 只读数组 | `readonly T[]` / `ReadonlyArray 写法` | 不可修改 |
| 元组 | `[T1, T2, ...]` | 固定长度、各位独立类型 |
| 可选元组 | `[T1, T2?]` | 某些位置可以省略 |
| 剩余元组 | `[T1, ...Type[]]` | 部分固定 + 部分灵活 |
| const 断言 | `as const` | 深度只读 + 字面量类型 |

### 9.2 关于数组与元组的选用心得

在实际项目开发中，我逐渐形成了这样的直觉：

1. **大多数情况下用数组就对了** —— 列表渲染、数据集合、遍历操作，这些都是数组的天然场景
2. **当你发现自己在注释里写"第一个是 xx，第二个是 yy"的时候，考虑用元组或者改用对象**
3. **元组的最大价值不是日常使用，而是作为工具函数的契约** —— 让调用者清楚地知道返回数据的结构
4. **只读数组是好的实践** —— 尤其是传递给其他函数时，明确"我不会修改它"

### 9.3 推荐的 tsconfig 配置

```json
{
  "compilerOptions": {
    "noUncheckedIndexedAccess": true,
    "strictNullChecks": true
  }
}
```

这两个选项配合使用，能让数组相关的 bug 在编译阶段就被捕获。

> **一句话总结**：数组是"一群同类人的集合"，元组是"一张有固定格式的表格"。选对数据结构，类型系统才能真正发挥威力。
