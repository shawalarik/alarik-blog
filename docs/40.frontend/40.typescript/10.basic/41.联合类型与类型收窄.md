# 联合类型与类型收窄

> **一句话总结**：联合类型让你表达"这个值可能是 A，也可能是 B"；类型收窄则帮你从"可能是 A 或 B"精确到"确定就是 A"——就像侦探排除嫌疑人一样。

## 一、生活化类比：为什么需要"或"的概念？

想象你在餐厅点餐：

```typescript
// 你点的饮料：可乐 或者 雪碧 —— 二选一
type Drink = 'cola' | 'sprite';

// 你的支付方式：现金 或者 微信 或者 支付宝
type PaymentMethod = 'cash' | 'wechat' | 'alipay';
```

这就是联合类型的本质：**一个变量可以接受多种不同类型的值**。它解决的是现实世界中"多选一"的常见场景。

再比如一个函数参数既可以是字符串也可以是数字：

```typescript
// 格式化输出：传入数字就格式化数字，传入字符串就直接返回
function formatOutput(input: string | number): string {
  // 这里 input 既可能是 string 也可能是 number
}
```

## 二、联合类型（Union Type）基础

### 2.1 基本语法

使用 `|`（竖线）符号来声明联合类型：

```typescript
// 基础联合类型
let value: string | number;

value = 'hello';     // ✅ 合法
value = 42;          // ✅ 合法
value = true;        // ❌ 错误：不能将类型 boolean 分配给 string | number
```

**设计理念**：TypeScript 的联合类型遵循数学中"并集"的概念——`A | B` 表示属于 A **或者** 属于 B 的值的集合。

```typescript
// 更复杂的联合类型
let mixed: string | number | boolean | null;

mixed = 'text';
mixed = 100;
mixed = false;
mixed = null;
mixed = undefined;    // ❌ undefined 不在联合类型中
```

### 2.2 字面量联合类型

这是实际开发中最常用的形式之一：

```typescript
// 状态字段的典型用法
type Status = 'success' | 'error' | 'pending' | 'loading';

// 方向
type Direction = 'up' | 'down' | 'left' | 'right';

// CSS 尺寸单位
type CSSUnit = 'px' | 'rem' | 'em' | '%' | 'vw' | 'vh';

// HTTP 方法
type HttpMethod = 'GET' | 'POST' | 'PUT' | 'DELETE' | 'PATCH';
```

**好处**：
- 比用枚举更轻量，编译后不会产生额外代码
- 自动补全友好，IDE 会列出所有可能的选项
- 类型安全，拼写错误会立即报错

```typescript
function fetchData(method: HttpMethod, url: string) {
  console.log(`${method} ${url}`);
}

fetchData('GET', '/api/users');      // ✅
fetchData('POST', '/api/users');     // ✅
fetchData('Get', '/api/users');      // ❌ 大小写不匹配！
fetchData('OPTIONS', '/api/users');  // ❌ OPTIONS 不在联合类型中
```

### 2.3 联合类型的使用限制：只能访问共有成员

这是一个非常重要的规则！当变量的类型是 `A | B` 时，你只能访问 **A 和 B 共有的成员**。

```typescript
interface Bird {
  fly(): void;
  layEggs(): void;
}

interface Fish {
  swim(): void;
  layEggs(): void;
}

type Pet = Bird | Fish;

function careForPet(pet: Pet) {
  pet.layEggs();   // ✅ layEggs 是 Bird 和 Fish 共有的方法
  pet.fly();       // ❌ 错误：Fish 没有 fly 方法
  pet.swim();      // ❌ 错误：Bird 没有 swim 方法
}
```

**生活类比**：想象你有一个盒子，里面要么是一只鸟，要么是一条鱼。在打开盒子之前，你能确定的只有一件事：它们都能生蛋（`layEggs`）。但你不能确定它能飞还是能游——除非你先看看里面到底是什么。

**为什么会这样设计？**

这是 TypeScript 的**保守策略**：既然 `pet` 可能是 `Fish`，调用 `fish.fly()` 就会在运行时崩溃。TypeScript 宁可让你多写几行代码来"缩小范围"，也不让你写出可能出错代码。

## 三、类型收窄（Narrowing）——核心概念

### 3.1 什么是类型收窄？

**类型收窄（Type Narrowing）** 是指 TypeScript 通过代码逻辑分析，将一个较宽的联合类型"收缩"为较窄的特定类型的过程。

```typescript
// 收窄前：input 的类型是 string | number（宽）
// 收窄后：input 的类型确定为 string（窄）
function formatOutput(input: string | number): string {
  if (typeof input === 'string') {
    // 在这个分支里，TS 知道 input 一定是 string
    return input.toUpperCase();  // ✅ 可以调用 toUpperCase()
  } else {
    // 在这个分支里，TS 知道 input 一定是 number
    return input.toFixed(2);    // ✅ 可以调用 toFixed()
  }
}
```

### 3.2 类型收窄的原理

TypeScript 的**控制流分析（Control Flow Analysis）** 会在以下情况追踪变量的类型变化：

- 条件判断（`if/else`、三元运算符）
- 真值检查
- 类型判断操作符（`typeof`、`instanceof`）
- 相等性判断
- `in` 操作符
- 自定义类型守卫函数

**生活类比**：这就像是破案过程——一开始嫌疑人是"张三或李四"（联合类型），通过排查"案发时不在场的是谁"，最终锁定"就是张三"（收窄后的具体类型）。

## 四、各种类型收窄方式详解

### 4.1 typeof 收窄

最常用的收窄方式，适用于区分原始类型：

```typescript
function printId(id: string | number) {
  if (typeof id === 'string') {
    // 此处 id 的类型被收窄为 string
    console.log(id.toUpperCase());
    console.log(id.length);        // ✅ string 特有属性
  } else {
    // 此处 id 的类型被收窄为 number
    console.log(id.toFixed(2));    // ✅ number 特有方法
    console.log(id.toExponential()); // ✅
  }
}
```

**typeof 返回值对照表**：

| typeof 结果 | 对应的 TypeScript 类型 |
|------------|----------------------|
| `'string'` | `string` |
| `'number'` | `number` |
| `'bigint'` | `bigint` |
| `'boolean'` | `boolean` |
| `'symbol'` | `symbol` |
| `'undefined'` | `undefined` |
| `'object'` | `object`, `null`, 数组, 等 |
| `'function'` | `function` |

**⚠️ 注意事项**：`typeof null === 'object'` 是 JavaScript 的历史遗留 bug。如果联合类型包含 `null`，需要特别注意：

```typescript
function processValue(value: string | null) {
  if (typeof value === 'object') {
    // 这里 value 可能是 null，也可能真的是 object！
    // typeof null === 'object'，所以这个条件不够精确
    console.log(value!.length); // 需要非空断言，或者用 !== null 判断
  }

  // 推荐做法：直接判断 null
  if (value !== null) {
    console.log(value.length); // ✅ 此时 value 确定是 string
  }
}
```

### 4.2 真值收窄（Truthiness Narrowing）

JavaScript 中会被判定为"假"（falsy）的值：`false`、`0`、`''`、`null`、`undefined`、`BigInt(0)`、`NaN`。TypeScript 能利用这一点进行类型收窄：

```typescript
function printName(name: string | null | undefined) {
  // 真值检查会排除 null 和 undefined
  if (name) {
    // 此处 name 的类型收窄为 string（排除了 '' 也排除了 null/undefined）
    console.log(name.toUpperCase());
  } else {
    console.log('没有提供名字');
  }
}

// 处理可能为空的数组
function getFirstElement(arr: string[] | null) {
  if (arr && arr.length > 0) {
    return arr[0]; // ✅ arr 确定 string[] 且非空
  }
  return undefined;
}
```

**实际应用：DOM 操作中的典型用法**：

```typescript
function getElementText(selector: string): string {
  const element = document.querySelector(selector);
  
  // document.querySelector 返回 Element | null
  // 用真值检查排除 null
  if (!element) {
    return ''; // 元素不存在
  }
  
  // element 在这里确定为 Element
  return element.textContent ?? '';
}
```

### 4.3 相等性收窄（Equality Narrowing）

通过 `===`、`!==`、`==`、`!=` 进行比较时的收窄：

```typescript
function printStatus(status: 'success' | 'error' | 'pending') {
  if (status === 'success') {
    // status 收窄为字面量类型 'success'
    console.log('🎉 操作成功！');
  } else if (status === 'error') {
    // status 收窄为字面量类型 'error'
    console.log('❌ 发生错误');
  } else {
    // status 收窄为字面量类型 'pending'
    console.log('⏳ 处理中...');
  }
}

// 与已知字面量比较
function handleInput(x: string | number) {
  if (x === 'hello') {
    // x 收窄为字面量类型 'hello'（string 的子类型）
    console.log('收到问候！');
  } else if (x === 42) {
    // x 收窄为字面量类型 42
    console.log('答案是 42');
  } else {
    // x 的类型仍然是 string | number（但排除了 'hello' 和 42）
    console.log(`其他值: ${x}`);
  }
}
```

### 4.4 in 操作符收窄

用于检查对象是否拥有某个属性，常用于区分接口类型：

```typescript
interface Cat {
  name: string;
  meow(): void;
}

interface Dog {
  name: string;
  bark(): void;
}

type Pet = Cat | Dog;

function speak(pet: Pet) {
  // 使用 in 操作符检查属性是否存在
  if ('meow' in pet) {
    // pet 收窄为 Cat
    pet.meow();  // ✅
  } else {
    // pet 收窄为 Dog（因为只有 Dog 没有 meow 属性）
    pet.bark();  // ✅
  }
}

// 另一个例子：API 响应处理
type ApiResponse =
  | { success: true; data: User }
  | { success: false; error: { code: number; message: string } };

function handleResponse(response: ApiResponse) {
  if ('data' in response) {
    // response 收窄为成功响应
    console.log(response.data.name);
  } else {
    // response 收窄为错误响应
    console.error(`错误 ${response.error.code}: ${response.error.message}`);
  }
}
```

**⚠️ 注意**：`in` 操作符会沿着原型链查找，所以要确保属性名是足够独特的。

### 4.5 instanceof 收窄

用于区分类实例：

```typescript
function handleError(error: Error | Date) {
  if (error instanceof Error) {
    // error 收窄为 Error
    console.error(error.message);
    console.error(error.stack);     // ✅ Error 特有属性
  } else {
    // error 收窄为 Date
    console.log(error.getTime());    // ✅ Date 特有方法
    console.log(error.toISOString()); // ✅
  }
}

// 实际应用：异常处理
try {
  // 可能抛出各种错误的代码
} catch (err) {
  // err 默认类型是 unknown（在 TS 4.0+ 中推荐）
  if (err instanceof Error) {
    console.error(err.message);  // ✅
  } else if (typeof err === 'string') {
    console.error(err);           // ✅
  } else {
    throw err;                    // 无法处理的错误重新抛出
  }
}
```

**自定义类同样适用**：

```typescript
class HttpError extends Error {
  constructor(
    public statusCode: number,
    message: string
  ) {
    super(message);
    this.name = 'HttpError';
  }
}

class NetworkError extends Error {
  constructor(public originalError: unknown) {
    super('网络连接失败');
    this.name = 'NetworkError';
  }
}

function classifyError(error: HttpError | NetworkError | Error) {
  if (error instanceof HttpError) {
    return `HTTP 错误: ${error.statusCode}`;
  } else if (error instanceof NetworkError) {
    return `网络错误`;
  } else {
    return `未知错误: ${error.message}`;
  }
}
```

## 五、自定义类型守卫（Type Predicate）

当内置的收窄方式无法满足需求时，你可以创建自己的**类型守卫函数**：

### 5.1 is 关键字的魔法

```typescript
// 自定义类型守卫：参数名 is Type
function isString(value: unknown): value is string {
  return typeof value === 'string';
}

function isNumber(value: unknown): value is number {
  return typeof value === 'number' && !isNaN(value);
}

// 使用
function doubleOrUpper(value: string | number) {
  if (isString(value)) {
    // TS 知道这里是 string，因为 isString 的返回类型说明了这一点
    return value.toUpperCase();
  }
  if (isNumber(value)) {
    // TS 知道这里是 number
    return value * 2;
  }
  return value; // 兜底
}
```

**`value is T` 语法的工作机制**：当你调用 `isString(value)` 并返回 `true` 时，TypeScript 就会在后续代码中将 `value` 的类型收窄为 `T`。这不是运行时行为，而是编译时的类型信息传递。

### 5.2 复杂对象的类型守卫

```typescript
interface Square {
  kind: 'square';
  size: number;
}

interface Circle {
  kind: 'circle';
  radius: number;
}

interface Triangle {
  kind: 'triangle';
  base: number;
  height: number;
}

type Shape = Square | Circle | Triangle;

// 为每种形状编写类型守卫
function isSquare(shape: Shape): shape is Square {
  return shape.kind === 'square';
}

function isCircle(shape: Shape): shape is Circle {
  return shape.kind === 'circle';
}

function isTriangle(shape: Shape): shape is Triangle {
  return shape.kind === 'triangle';
}

// 使用类型守卫计算面积
function calculateArea(shape: Shape): number {
  if (isSquare(shape)) {
    return shape.size * size;  // ✅ shape 为 Square
  }
  if (isCircle(shape)) {
    return Math.PI * shape.radius ** 2;  // ✅ shape 为 Circle
  }
  // shape 必定是 Triangle
  return (shape.base * shape.height) / 2;  // ✅ shape 为 Triangle
}
```

### 5.3 更实用的类型守卫示例

```typescript
// 验证 API 响应是否包含有效数据
interface ApiSuccess<T> {
  ok: true;
  data: T;
}

interface ApiFail {
  ok: false;
  error: string;
  status: number;
}

type ApiResponse<T> = ApiSuccess<T> | ApiFail;

function isSuccess<T>(res: ApiResponse<T>): res is ApiSuccess<T> {
  return res.ok === true;
}

async function fetchUser(id: number): Promise<User> {
  const res = await fetch(`/api/users/${id}`);
  const json: ApiResponse<User> = await res.json();

  if (isSuccess(json)) {
    // json 被收窄为 ApiSuccess<User>
    return json.data;
  } else {
    // json 被收窄为 ApiFail
    throw new Error(`请求失败 (${json.status}): ${json.error}`);
  }
}

// 数组元素过滤的实用模式
const mixedArray: (string | number)[] = ['hello', 42, 'world', 100, 'foo'];

// 过滤后只保留字符串
const stringsOnly = mixedArray.filter((item): item is string => {
  return typeof item === 'string';
});
// stringsOnly 的类型是 string[]，而不是 (string | number)[]
console.log(stringsOnly.map(s => s.toUpperCase())); // ✅
```

**💡 个人心得**：类型守卫配合数组的 `filter` 方法使用特别强大。普通过滤后数组类型不变（仍是 `(A | B)[]`），但如果 filter 回调函数的类型守卫返回 `true` 时类型为 `T`，那么 TypeScript 会自动推断出过滤后的数组类型为 `T[]`。这在处理混合数据时非常有用！

## 六、可辨识联合（Discriminated Union）

这是 TypeScript 中最重要的模式之一，也被称为**标签联合（Tagged Union）**。

### 6.1 核心思想

给联合类型中的每个成员添加一个共同的**字面量属性**作为"标签"，然后通过 switch/if 判断该标签来实现类型收窄：

```typescript
// 每个接口都有 kind 属性，且值各不相同
interface LoadingState {
  state: 'loading';  // ← 这是"辨识标签"
}

interface SuccessState {
  state: 'success';  // ← 同样的属性，不同的值
  data: User[];
}

interface ErrorState {
  state: 'error';    // ← 同样的属性，不同的值
  code: number;
  message: string;
}

type RequestState = LoadingState | SuccessState | ErrorState;

function renderUI(state: RequestState) {
  // 通过判断 state 属性的值来收窄类型
  switch (state.state) {
    case 'loading':
      // state 被收窄为 LoadingState
      return <Spinner />;
    case 'success':
      // state 被收窄为 SuccessState
      return <UserList users={state.data} />;
    case 'error':
      // state 被收窄为 ErrorState
      return <ErrorMessage code={state.code} message={state.message} />;
  }
}
```

**生活类比**：想象快递包裹上的标签——每个包裹都有一个标签写着"文件"、"食品"、"易碎品"。分拣员只需要看标签就知道该怎么处理每种包裹。

### 6.2 完整实战：表单验证结果

```typescript
type ValidationResult<T> =
  | { valid: true; value: T }                          // 验证通过
  | { valid: false; field: string; reason: string };    // 验证失败

// 验证邮箱
function validateEmail(email: string): ValidationResult<string> {
  const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
  if (!email) {
    return { valid: false, field: 'email', reason: '邮箱不能为空' };
  }
  if (!emailRegex.test(email)) {
    return { valid: false, field: 'email', reason: '邮箱格式不正确' };
  }
  return { valid: true, value: email };
}

// 验证年龄
function validateAge(ageStr: string): ValidationResult<number> {
  const age = Number(ageStr);
  if (isNaN(age)) {
    return { valid: false, field: 'age', reason: '年龄必须是数字' };
  }
  if (age < 0 || age > 150) {
    return { valid: false, field: 'age', reason: '年龄必须在 0-150 之间' };
  }
  return { valid: true, value: age };
}

// 使用验证结果
function handleSubmit(formData: { email: string; age: string }) {
  const emailResult = validateEmail(formData.email);
  const ageResult = validateAge(formData.age);

  // 利用 valid 标签进行收窄
  if (!emailResult.valid) {
    showError(emailResult.field, emailResult.reason);
    return;
  }
  // emailResult 在这里被收窄为 { valid: true; value: string }
  console.log('邮箱:', emailResult.value);

  if (!ageResult.valid) {
    showError(ageResult.field, ageResult.reason);
    return;
  }
  // ageResult 在这里被收窄为 { valid: true; value: number }
  console.log('年龄:', ageResult.value);

  // 到这里两个验证都通过了
  submitToServer({ email: emailResult.value, age: ageResult.value });
}
```

### 6.3 never 类型的穷尽检查作用

`never` 类型表示"永远不会发生的类型"。利用它可以实现**穷尽性检查（Exhaustiveness Checking）**，确保你处理了所有可能的联合类型成员：

```typescript
type Status = 'success' | 'error' | 'pending' | 'loading';

function getStatusMessage(status: Status): string {
  switch (status) {
    case 'success':
      return '✅ 操作成功';
    case 'error':
      return '❌ 操作失败';
    case 'pending':
      return '⏳ 等待中';
    // 故意遗漏了 'loading' 的情况
    // 如果不加 default 分支，TS 可能不会报错（取决于 strictNullChecks）
  }
}

// 使用 never 进行穷尽检查
function assertNever(value: never): never {
  throw new Error(`未预期的值: ${value}`);
}

function getStatusMessageSafe(status: Status): string {
  switch (status) {
    case 'success':
      return '✅ 操作成功';
    case 'error':
      return '❌ 操作失败';
    case 'pending':
      return '⏳ 等待中';
    case 'loading':
      return '🔄 加载中';
    default:
      // 如果将来新增了 Status 的成员但忘记在这里处理，
      // TypeScript 会报错：不能将类型 "新类型" 分配给 never
      return assertNever(status);
  }
}
```

**为什么这很有用？**

假设三个月后你的团队在 `Status` 类型中新增了 `'retrying'` 这个状态：

```typescript
type Status = 'success' | 'error' | 'pending' | 'loading' | 'retrying'; // 新增
```

如果你使用了 `assertNever` 模式，TypeScript 会立即在所有 `switch` 语句的 `default` 分支报错，提醒你："嘿，你忘记处理 `retrying` 了！"这就是**类型安全的重构保障**。

## 七、可赋值性（Assignability）规则

### 7.1 子类型可以赋给父类型

TypeScript 的类型系统遵循**结构化子类型（Structural Subtyping）**原则：如果一个类型的结构包含了另一个类型所需的一切，那它就是这个类型的子类型，可以被赋值给它。

```typescript
// string 是 string | number 的子类型
let x: string | number;
x = 'hello';         // ✅ string 可以赋给 string | number
x = 42;              // ✅ number 可以赋给 string | number

// 字面量类型是其父类型的子类型
let status: 'success' | 'error' | 'pending';
status = 'success';  // ✅ 'success' 是 'success' | 'error' | 'pending' 的子类型
status = 'failed';   // ❌ 'failed' 不在联合类型中
```

### 7.2 函数参数的可赋值性

```typescript
// 接受 string | number 的函数
function acceptUnion(value: string | number) {}

acceptUnion('hello');   // ✅
acceptUnion(42);        // ✅
acceptUnion(true);      // ❌ boolean 不在联合类型中

// 反过来，更具体的类型可以传给要求更宽泛类型的参数
function acceptString(s: string) {}
function acceptStringOrNumber(sn: string | number) {}

const myVar: string = 'hello';
acceptString(myVar);          // ✅ string -> string
acceptStringOrNumber(myVar);  // ✅ string -> string | number （向上兼容）
```

### 7.3 实际意义

理解可赋值性规则对于编写通用工具函数非常重要：

```typescript
// 这个函数可以接受任何 "success" | "error" 子集
function handleStatus(
  status: 'success' | 'error',
  callback: () => void
) {
  // ...
}

handleStatus('success', () => {});  // ✅
handleStatus('error', () => {});    // ✅

// 更严格的类型可以传给更宽松的位置
type StrictStatus = 'success';
function doSomething(status: StrictStatus) {
  handleStatus(status, () => {});  // ✅ 'success' 可赋给 'success' | 'error'
}
```

## 八、综合实战应用

### 8.1 API 响应处理

```typescript
// 定义统一的 API 响应类型（可辨识联合）
type ApiResponse<T> =
  | { status: 'ok'; data: T; timestamp: number }
  | { status: 'not_found'; message: string }
  | { status: 'error'; code: number; message: string }
  | { status: 'unauthorized'; redirectUrl: string };

async function fetchUserProfile(userId: string) {
  const response = await fetch(`/api/users/${userId}`);
  const result: ApiResponse<UserProfile> = await response.json();

  switch (result.status) {
    case 'ok':
      // result 被收窄为 { status: 'ok'; data: UserProfile; timestamp: number }
      return {
        user: result.data,
        fetchedAt: new Date(result.timestamp),
      };

    case 'not_found':
      // result 被收窄为 { status: 'not_found'; message: string }
      throw new NotFoundError(result.message);

    case 'error':
      // result 被收窄为 { status: 'error'; code: number; message: string }
      throw new ApiError(result.code, result.message);

    case 'unauthorized':
      // result 被收窄为 { status: 'unauthorized'; redirectUrl: string }
      window.location.href = result.redirectUrl;
      return null;

    default:
      // 穷尽检查：如果有新的 status 未处理会报错
      return assertNever(result);
  }
}
```

### 8.2 表单字段验证系统

```typescript
type FieldValue = string | number | boolean | string[];

type FieldValidationRule = {
  required?: boolean;
  minLength?: number;
  maxLength?: number;
  min?: number;
  max?: number;
  pattern?: RegExp;
  custom?: (value: FieldValue) => string | null; // 返回 null 表示验证通过
};

type FieldValidationResult =
  | { valid: true; value: FieldValue }
  | { valid: false; errors: string[] };

function validateField(
  value: FieldValue,
  rules: FieldValidationRule
): FieldValidationResult {
  const errors: string[] = [];

  // 必填检查
  if (rules.required) {
    if (value === '' || value === null || value === undefined) {
      errors.push('此字段为必填项');
    }
  }

  // 字符串长度检查
  if (typeof value === 'string') {
    if (rules.minLength && value.length < rules.minLength) {
      errors.push(`最少需要 ${rules.minLength} 个字符`);
    }
    if (rules.maxLength && value.length > rules.maxLength) {
      errors.push(`最多允许 ${rules.maxLength} 个字符`);
    }
    if (rules.pattern && !rules.pattern.test(value)) {
      errors.push('格式不正确');
    }
  }

  // 数字范围检查
  if (typeof value === 'number') {
    if (rules.min !== undefined && value < rules.min) {
      errors.push(`不能小于 ${rules.min}`);
    }
    if (rules.max !== undefined && value > rules.max) {
      errors.push(`不能大于 ${rules.max}`);
    }
  }

  // 自定义验证
  if (rules.custom) {
    const customError = rules.custom(value);
    if (customError) {
      errors.push(customError);
    }
  }

  if (errors.length > 0) {
    return { valid: false, errors };
  }

  return { valid: true, value };
}

// 使用
const usernameResult = validateField('', {
  required: true,
  minLength: 3,
  maxLength: 20,
  pattern: /^[a-zA-Z0-9_]+$/,
});

if (!usernameResult.valid) {
  // usernameResult 被收窄为 { valid: false; errors: string[] }
  console.error(usernameResult.errors); // ['此字段为必填项']
}
```

### 8.3 Redux/状态管理中的 Action 处理

```typescript
// Redux-style action（可辨识联合）
type Action =
  | { type: 'SET_USER'; payload: User }
  | { type: 'CLEAR_USER' }
  | { type: 'SET_LOADING'; payload: boolean }
  | { type: 'SET_ERROR'; payload: string | null };

type State = {
  user: User | null;
  loading: boolean;
  error: string | null;
};

function reducer(state: State, action: Action): State {
  switch (action.type) {
    case 'SET_USER':
      // action 被收窄为 { type: 'SET_USER'; payload: User }
      return { ...state, user: action.payload, error: null };

    case 'CLEAR_USER':
      // action 被收窄为 { type: 'CLEAR_USER' }
      return { ...state, user: null };

    case 'SET_LOADING':
      // action 被收窄为 { type: 'SET_LOADING'; payload: boolean }
      return { ...state, loading: action.payload };

    case 'SET_ERROR':
      // action 被收窄为 { type: 'SET_ERROR'; payload: string | null }
      return { ...state, error: action.payload, loading: false };

    default:
      return assertNever(action); // 穷尽检查
  }
}
```

## 九、常见坑点和注意事项

### 9.1 赋值不会触发收窄

```typescript
function process(x: string | number) {
  if (typeof x === 'string') {
    // x 是 string
  } else {
    // x 是 number
  }

  // ⚠️ 如果把 x 赋值给另一个变量，新变量不会自动收窄
  let y = x; // y 的类型仍然是 string | number
}
```

### 9.2 闭包中的收窄失效

```typescript
function problem() {
  let x: string | number = 'hello';

  if (typeof x === 'string') {
    // x 是 string
    setTimeout(() => {
      // ⚠️ 这里 x 又变回 string | number 了！
      // 因为 setTimeout 回调可能在 x 被修改后才执行
      console.log(x.toUpperCase()); // ❌ 报错！
    }, 100);
  }

  // 解决方案：提前保存收窄后的值
  if (typeof x === 'string') {
    const strX = x; // strX 是 string
    setTimeout(() => {
      console.log(strX.toUpperCase()); // ✅
    }, 100);
  }
}
```

### 9.3 异步代码中的类型保护

```typescript
async function asyncNarrowing(x: string | number | null) {
  if (x != null) {
    // x 是 string | number
    
    const result = await someAsyncOperation(x);
    
    // ⚠️ await 之后，x 不一定保持收窄状态（取决于 TS 版本和配置）
    // 更安全的做法是在 await 前保存
    const savedX = x;
    await anotherAsyncOp();
    console.log(savedX); // 安全
  }
}
```

### 9.4 联合类型与数组

```typescript
// 联合类型的数组 ≠ 联合的数组
let arr1: (string | number)[];  // 每个元素可以是 string 或 number
let arr2: string[] | number[];  // 整个数组要么全是 string，要么全是 number

arr1 = ['hello', 42, 'world'];  // ✅
arr2 = ['hello', 42];           // ❌ 不能混在一起
arr2 = [1, 2, 3];               // ✅ 全是 number
arr2 = ['a', 'b'];              // ✅ 全是 string
```

## 十、个人总结与心得

学习联合类型和类型收窄后，我最大的感受是：**TypeScript 不是在限制你，而是在帮助你思考得更清楚**。

1. **先定义，后编码**：在使用联合类型前，先想清楚"这个东西到底可能有哪几种状态"。这种思维方式的转变比语法本身更重要。

2. **可辨识联合是神器**：一旦你掌握了 `{ kind: 'xxx' }` + `switch` 的模式，你会发现它在处理状态机、API 响应、表单验证等场景下几乎万能。这是我最常用的 TypeScript 模式之一。

3. **never 穷尽检查是保险丝**：在大型项目中，类型经常会被扩展。`assertNever` 模式虽然只多写两三行，但它能在你忘记处理新情况时第一时间告诉你。

4. **类型守卫让你的意图显式化**：与其到处散布 `typeof` 和 `instanceof`，不如把判断逻辑封装成命名良好的类型守卫函数如 `isUser()`、`isValidResponse()`，代码可读性和复用性都会大幅提升。

5. **收窄的本质是信息增益**：每一步收窄都是因为你获得了更多信息（通过条件判断），TypeScript 只是把这种信息增量体现在类型系统中而已。理解这一点，你对类型收窄的各种方式就不会觉得神奇，而是理所当然。
