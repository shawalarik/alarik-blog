# 类型别名——type 与 interface 的初步对比

> **一句话总结**：`type` 是给类型起"绰号"，`interface` 是给对象画"蓝图"。两者都能描述对象的形状，但 `type` 能力更广（能表达联合、交叉、原始类型的别名），而 `interface` 在面向对象场景下更自然、支持声明合并。

## 一、生活化类比：为什么需要给类型起名字？

想象一下：

```typescript
// 没有类型别名——每次都要写完整的类型表达式
function greet(name: string) {}
function formatName(name: string) {}
function validateName(name: string) {}

// 如果类型变复杂了...
function processUser(user: { id: number; name: string; email: string; age: number }) {}
function updateUser(user: { id: number; name: string; email: string; age: number }) {}
function deleteUser(user: { id: number; name: string; email: string; age: number }) {}
```

这就像每次介绍你的朋友都要说全名："这是**张三丰·武当派创始人·太极拳发明者·活了200多岁的传奇人物**"。累不累？起个外号（别名）就好了！

```typescript
// 用类型别名——一次定义，到处复用
type User = {
  id: number;
  name: string;
  email: string;
  age: number;
};

function processUser(user: User) {}
function updateUser(user: User) {}
function deleteUser(user: User) {}
```

**设计理念**：类型别名的核心价值是**可读性**和**复用性**。它让复杂的类型表达式变成有语义的名字，让代码像自然语言一样易读。

## 二、类型别名基础

### 2.1 定义语法

使用 `type` 关键字定义：

```typescript
// 基本语法：type 名字 = 类型表达式
type Name = string;
type Age = number;
type IsActive = boolean;
type ID = string | number;        // 联合类型的别名
type Callback = () => void;       // 函数类型的别名
type StringOrNumber = string | number;

// 使用
let userName: Name = 'Alarik';
let userAge: Age = 25;
let userId: ID = 'u-001';   // ✅ string 可以赋给 string | number
userId = 12345;              // ✅ number 也可以
```

### 2.2 type 可以表达的各种类型

`type` 的能力非常广泛，几乎可以为**任何类型表达式**创建别名：

#### 原始类型别名

```typescript
// 给原始类型起更有语义的名字
type UserId = string;
type PortNumber = number;
type JsonString = string;
type Timestamp = number;

const userId: UserId = 'user_12345';
const port: PortNumber = 3000;
```

> **💡 什么时候用？** 当一个普通的 `string` 在你的业务中有特殊含义时（如用户ID、订单号等），给它起个类型别名能让代码意图更清晰。这在大型团队协作中尤其有价值。

#### 对象类型别名

```typescript
// 最常见的用法——描述对象形状
type Point = {
  x: number;
  y: number;
};

type Rectangle = {
  position: Point;
  width: number;
  height: number;
};

type User = {
  id: string;
  name: string;
  email?: string;          // 可选属性
  readonly createdAt: Date; // 只读属性
  roles: ('admin' | 'editor' | 'viewer')[];
};

const user: User = {
  id: 'u-1',
  name: '张三',
  createdAt: new Date(),
  roles: ['admin'],
};
```

#### 联合类型别名

```typescript
// 把复杂的联合类型封装起来
type Status = 'loading' | 'success' | 'error' | 'empty';
type ThemeMode = 'light' | 'dark' | 'system';
type HttpMethod = 'GET' | 'POST' | 'PUT' | 'DELETE' | 'PATCH';
type CSSSizeUnit = 'px' | 'rem' | 'em' | '%' | 'vw' | 'vh';

// 组合使用
type ApiResponse<T> =
  | { status: 'ok'; data: T }
  | { status: 'error'; code: number; message: string };
```

#### 函数类型别名

```typescript
// 描述函数签名
type Greeter = (name: string) => string;
type Predicate<T> = (value: T) => boolean;
type EventHandler<E> = (event: E) => void;
type AsyncFetcher<T> = (url: string) => Promise<T>;

// 使用
const greeter: Greeter = (name) => `Hello, ${name}!`;

const isEven: Predicate<number> = (n) => n % 2 === 0;

const fetchUser: AsyncFetcher<User> = async (url) => {
  const res = await fetch(url);
  return res.json();
};
```

#### 数组/元组类型别名

```typescript
// 数组
type StringList = string[];
type NumberArray = Array<number>;
type KeyValuePair<K, V> = [K, V][];

// 元组——固定长度、固定类型
type Coordinate = [number, number];        // [x, y]
type RGB = [number, number, number];       // [r, g, b]
type NamedPoint = [string, number, number]; // [name, x, y]

const origin: Coordinate = [0, 0];
const red: RGB = [255, 0, 0];
const pointA: NamedPoint = ['原点', 0, 0];

// 解构元组时类型信息保留完好
const [name, x, y] = pointA;
console.log(name.toUpperCase()); // ✅ name 是 string
```

### 2.3 交叉类型（Intersection Type）

使用 `&` 符号将多个类型合并为一个：

```typescript
type A = {
  a: string;
};

type B = {
  b: number;
};

type C = A & B; // 交叉类型：同时拥有 a 和 b

const obj: C = {
  a: 'hello',
  b: 42,
};
console.log(obj.a); // ✅ string
console.log(obj.b); // ✅ number
```

**生活类比**：交叉类型就像一个人同时拥有多个身份。比如一个人既是"员工"又是"学生"——他就是这两个角色的"交集"，拥有两者的所有属性。

#### 实际应用示例

```typescript
// 基础用户
type BaseUser = {
  id: string;
  name: string;
  email: string;
};

// 带时间戳
type WithTimestamps = {
  createdAt: Date;
  updatedAt: Date;
};

// 带软删除
type WithSoftDelete = {
  deletedAt: Date | null;
};

// 通过交叉组合出完整模型
type FullUser = BaseUser & WithTimestamps & WithSoftDelete;

// 等价于：
// type FullUser = {
//   id: string;
//   name: string;
//   email: string;
//   createdAt: Date;
//   updatedAt: Date;
//   deletedAt: Date | null;
// };

const newUser: FullUser = {
  id: 'u-001',
  name: '张三',
  email: 'zhangsan@example.com',
  createdAt: new Date(),
  updatedAt: new Date(),
  deletedAt: null,
};
```

#### 交叉类型的冲突处理

```typescript
type X = {
  name: string;
  age: number;
};

type Y = {
  name: number;  // ⚠️ 和 X 的 name 类型冲突！
  score: number;
};

type Z = X & Y;

// Z.name 的类型是什么？
// 答案：never —— string & number = never（没有值既是 string 又是 number）
let z: Z = {
  name: ???,     // 这里无法赋值！因为不存在既是 string 又是 number 的值
  age: 25,
  score: 100,
};
```

**⚠️ 重要**：当交叉类型中的同名属性类型不一致时，结果会是这些类型的交叉（通常是 `never`）。所以使用交叉类型时要避免属性名冲突，或者确保同名属性的类型兼容。

## 三、工具类型（Utility Types）

TypeScript 内置了许多基于 `type` 定义的**工具类型**，它们利用映射类型等高级特性来转换其他类型：

### 3.1 Partial——所有属性变为可选

```typescript
interface Todo {
  title: string;
  description: string;
  completed: boolean;
  priority: 'high' | 'medium' | 'low';
}

// Partial<Todo> 等价于：
// {
//   title?: string;
//   description?: string;
//   completed?: boolean;
//   priority?: 'high' | 'medium' | 'low';
// }

function updateTodo(id: number, fields: Partial<Todo>): Todo {
  const existing = getTodoById(id);
  return { ...existing, ...fields };
}

// 使用：只需要传想更新的字段
updateTodo(1, { completed: true });                    // ✅ 只更新 completed
updateTodo(1, { priority: 'high', title: '新标题' });  // ✅ 更新多个
updateTodo(1, {});                                     // ✅ 空对象也可以（全部可选）
```

**实现原理（简化版）**：
```typescript
// 大致原理（简化）
type MyPartial<T> = {
  [P in keyof T]?: T[P];
};
```

### 3.2 Pick——挑选部分属性

```typescript
interface User {
  id: string;
  name: string;
  email: string;
  password: string;
  phone: string;
  address: string;
  createdAt: Date;
}

// 只取需要的属性
type PublicUserInfo = Pick<User, 'id' | 'name' | 'createdAt'>;
// 等价于：{ id: string; name: string; createdAt: Date; }

type ContactInfo = Pick<User, 'email' | 'phone'>;
// 等价于：{ email: string; phone: string; }

// 实际应用：API 返回时不暴露敏感字段
function getPublicProfile(userId: string): PublicUserInfo {
  const user = getUserFromDB(userId);
  return {
    id: user.id,
    name: user.name,
    createdAt: user.createdAt,
    // password、phone、address 等不会被返回
  };
}
```

### 3.3 Omit——排除某些属性

```typescript
// 和 Pick 相反——排除指定属性
type SafeUser = Omit<User, 'password' | 'phone' | 'address'>;
// 等价于：{ id: string; name: string; email: string; createdAt: Date }

// 实际上 Omit 就是用 Pick 实现的
// type Omit<T, K extends keyof any> = Pick<T, Exclude<keyof T, K>>;

// 创建表单数据类型（不含 id 和 createdAt）
type UserFormData = Omit<User, 'id' | 'createdAt'>;
function createUser(data: UserFormData): User {
  return {
    ...data,
    id: generateId(),
    createdAt: new Date(),
  };
}
```

### 3.4 Record——键值对映射

```typescript
// Record<K, V> 表示一个对象，其 key 为 K 类型，value 为 V 类型
type ScoreMap = Record<string, number>;
// 等价于：{ [key: string]: number }

const scores: ScoreMap = {
  math: 95,
  english: 88,
  science: 92,
};

// 更实用的例子：字典/映射表
type HttpStatusMessages = Record<number, string>;

const httpMessages: HttpStatusMessages = {
  200: 'OK',
  201: 'Created',
  400: 'Bad Request',
  401: 'Unauthorized',
  403: 'Forbidden',
  404: 'Not Found',
  500: 'Internal Server Error',
};

// 配合联合类型做更精确的约束
type RolePermissions = Record<'admin' | 'editor' | 'viewer', string[]>;

const permissions: RolePermissions = {
  admin:    ['read', 'write', 'delete', 'manage_users'],
  editor:   ['read', 'write'],
  viewer:   ['read'],
};
```

### 3.5 其他常用工具类型一览

```typescript
interface Product {
  id: number;
  name: string;
  price: number;
  description: string;
  tags: string[];
}

// Required——所有属性必填（与 Partial 相反）
type RequiredProduct = Required<Partial<Product>>;
// 所有 ? 都被去掉

// Readonly——所有属性只读
type ReadOnlyProduct = Readonly<Product>;
// 每个属性都加了 readonly

// Extract——从 T 中提取可赋给 U 的部分
type StringKeys = Extract<keyof Product, string>; // 所有 key 都是 string

// Exclude——从 T 中排除可赋给 U 的部分
type NonIdFields = Exclude<keyof Product, 'id'>; // 'name' | 'price' | 'description' | 'tags'
```

## 四、type vs interface 详细对比

这是 TypeScript 中最经典的问题之一。让我们全面对比。

### 4.1 核心差异表格

| 特性 | `type`（类型别名） | `interface`（接口） |
|------|-------------------|---------------------|
| **定义对象类型** | ✅ 支持 | ✅ 支持 |
| **表达原始类型别名** | ✅ `type ID = string` | ❌ 不支持 |
| **表达联合类型** | ✅ `type A = B \| C` | ❌ 不支持 |
| **表达交叉类型** | ✅ `type A = B & C` | ❌ 不支持 |
| **表达元组/函数类型** | ✅ 全部支持 | ❌ 不支持 |
| **声明合并（Declaration Merging）** | ❌ 不支持 | ✅ 支持 |
| **继承/扩展方式** | `&` （交叉类型） | `extends` 关键字 |
| **计算属性名** | ✅ 支持 | ✅ 支持 |
| **泛型支持** | ✅ 支持 | ✅ 支持 |
| **递归引用自身** | ✅ 有限制地支持 | ✅ 支持 |
| **性能/编译速度** | 通常稍快 | 可能稍慢（因合并检查） |
| **错误信息可读性** | 较好 | 通常更好 |

### 4.2 声明合并——interface 独有能力

这是 `interface` 最独特的功能：

```typescript
// interface 支持声明合并：同名 interface 会自动合并
interface User {
  name: string;
}

interface User {
  age: number;
}

// 合并后等价于：
interface User {
  name: string;
  age: number;
}

const user: User = {
  name: '张三',
  age: 25,
}; // ✅ 需要 name 和 age

// type 不支持——会报重复声明错误
// type User = { name: string };
// type User = { age: number }; // ❌ 标识符 "User" 重复
```

**实际应用场景——扩展第三方库的类型**：

```typescript
// 扩展全局 Window 接口（在 .d.ts 文件中）
interface Window {
  __APP_CONFIG__: AppConfig;
  myCustomMethod(): void;
}

// 现在可以直接使用了
window.__APP_CONFIG__ = { /* ... */ };
window.myCustomMethod();

// 另一个典型场景：为 Express 的 Request 对象添加自定义属性
declare namespace Express {
  interface Request {
    currentUser?: User;
    sessionId?: string;
  }
}
```

### 4.3 扩展方式的差异

```typescript
// ====== interface 使用 extends ======
interface Animal {
  name: string;
}

interface Bear extends Animal {
  honey: boolean;
}

// Bear 自动拥有 name 和 honey

// ====== type 使用 &（交叉类型）======
type Animal = {
  name: string;
};

type Bear = Animal & {
  honey: boolean;
};

// Bear 同样拥有 name 和 honey

// ====== interface 可以 extends type ======
type Animal = {
  name: string;
};

interface Bear extends Animal {
  honey: boolean;
} // ✅ 完全合法

// ====== type 也可以通过 implements 来"继承" interface ======
interface Animal {
  name: string;
}

type Bear = Animal & {
  honey: boolean;
} // ✅ 也完全合法
```

### 4.4 错误信息的差异

这是一个微妙但重要的区别：

```typescript
// interface 的错误信息通常更清晰
interface Person {
  firstName: string;
  lastName: string;
}

const bad: Person = {
  firstName: 'John'
  // 缺少 lastName
};
// 错误信息：类型 "{ firstName: string; }" 中缺少属性 "lastName"

// type 有时会显示更复杂的交叉类型名称
type Person = {
  firstName: string;
  lastName: string;
};

const bad: Person = {
  firstName: 'John'
  // 类似错误信息
};
```

**一般来说**：对于简单对象类型，两者错误信息差不多；但当涉及多层交叉类型时，`interface` 的错误信息往往更简洁易读。

## 五、官方建议的使用原则

### 5.1 TypeScript 官方推荐

来自 [TypeScript Handbook](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html#differences-between-type-aliases-and-interfaces) 的建议：

> **大多数情况下，你可以根据个人喜好自由选择。**
>
> 如果你需要使用 `interface` 无法表达的特性（如联合类型、交叉类型、条件类型等），必须使用 `type`。
>
> 如果你需要**声明合并**的能力（如扩展第三方库），或者你在定义**对象类型**且可能在未来被扩展，优先选择 `interface`。

### 5.2 社区常见策略

```typescript
// ========== 策略一：interface 优先 ==========
// 适用：纯面向对象编程风格的项目

interface UserService {
  getUser(id: string): Promise<User>;
  createUser(data: CreateUserDTO): Promise<User>;
  updateUser(id: string, data: UpdateUserDTO): Promise<User>;
}

// ========== 策略二：type 优先 ==========
// 适用：函数式编程、大量使用联合/交叉类型的项目

type Result<T> =
  | { success: true; data: T }
  | { success: false; error: AppError };

type EventHandler<T> = (event: T) => void | Promise<void>;

// ========== 策略三：混合使用（最常见）==========
// 对象形状 → interface
// 联合/交叉/工具类型 → type

// 对象形状用 interface
interface User {
  id: string;
  name: string;
}

// 联合类型用 type
type Status = 'active' | 'inactive' | 'banned';

// API 响应用 type（包含联合）
type ApiResult<T> =
  | { ok: true; data: T }
  | { ok: false; error: ErrorCode };

// 类的实现用 implements + interface
class UserServiceImpl implements UserService {
  // ...
}
```

## 六、高级用法入门

### 6.1 条件类型（Conditional Types）

条件类型让你可以根据条件来选择不同的类型，类似三元运算符：

```typescript
// 基本语法：T extends U ? X : Y
// 含义：如果 T 可以赋给 U，则类型为 X，否则为 Y

type IsString<T> = T extends string ? true : false;

type A = IsString<string>;   // true
type B = IsString<number>;   // false
type C = IsString<'hello'>;  // true（字面量类型也是 string）

// 实际应用：提取函数的返回类型
type ReturnType<T> = T extends (...args: any[]) => infer R ? R : never;

function getUser(): User {
  return { id: '1', name: 'Test' };
}

type GetUserReturn = ReturnType<typeof getUser>; // User

// 实际应用：提取数组元素类型
type ElementOf<T> = T extends (infer E)[] ? E : never;

type Numbers = ElementOf<number[]>; // number
```

### 6.2 映射类型（Mapped Types）

映射类型可以遍历已有类型的每个属性，生成新的类型：

```typescript
// 基本语法：[K in keyof T]: 新类型
type Readonly<T> = {
  readonly [K in keyof T]: T[K];
};

type Optional<T> = {
  [K in keyof T]?: T[K];
};

// 应用
interface Config {
  host: string;
  port: number;
  ssl: boolean;
}

type ReadonlyConfig = Readonly<Config>;
// 等价于：
// {
//   readonly host: string;
//   readonly port: number;
//   readonly ssl: boolean;
// }

type OptionalConfig = Optional<Config>;
// 等价于：
// {
//   host?: string;
//   port?: number;
//   ssl?: boolean;
// }

// 映射类型 + 条件类型 = 强大的组合
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

interface Person {
  name: string;
  age: number;
}

type PersonGetters = Getters<Person>;
// 等价于：
// {
//   getName: () => string;
//   getAge: () => number;
// }
```

### 6.3 模板字面量类型（Template Literal Types）

TypeScript 4.1+ 支持：

```typescript
type EventName = 'click' | 'focus' | 'blur';

// 生成 onXxx 处理器名字
type HandlerName = `on${Capitalize<EventName>}`;
// 类型为：'onClick' | 'onFocus' | 'onBlur'

// 实际应用：事件处理器映射
type EventHandlers = {
  [H in HandlerName]: (event: Event) => void;
};

// 等价于：
// {
//   onClick: (event: Event) => void;
//   onFocus: (event: Event) => void;
//   onBlur: (event: Event) => void;
// }
```

## 七、实际项目中的选择策略

### 7.1 决策流程图

```
需要定义一个类型？
  │
  ├─ 需要表达联合/交叉/原始类型/元组/函数类型？
  │   └─ 是 → 用 type
  │
  ├─ 需要声明合并能力（扩展第三方类型）？
  │   └─ 是 → 用 interface
  │
  ├─ 是纯粹的对象形状（类/接口规范）？
  │   └─ 是 → 用 interface（语义更明确）
  │
  └─ 不确定？
      └─ 用 interface（更容易后期改为声明合并）
```

### 7.2 典型项目结构示例

```typescript
// ============================================
// types/models.ts —— 数据模型（interface 为主）
// ============================================

export interface User {
  id: string;
  name: string;
  email: string;
  avatarUrl?: string;
  role: UserRole;
  createdAt: Date;
  updatedAt: Date;
}

export interface Post {
  id: string;
  authorId: string;
  title: string;
  content: string;
  status: PostStatus;
  tags: string[];
  publishedAt?: Date;
}

// ============================================
// types/common.ts —— 通用类型（type 为主）
// ============================================

// 字面量联合
export type UserRole = 'admin' | 'editor' | 'viewer';
export type PostStatus = 'draft' | 'published' | 'archived';

// 工具型联合
export type ID = string;
export type JsonPrimitive = string | number | boolean | null;
export type Json = JsonPrimitive | Json[] | { [key: string]: Json };

// API 结果包装
export type ApiSuccess<T> = { ok: true; data: T };
export type ApiError = { ok: false; error: string; code: number };
export type ApiResult<T> = ApiSuccess<T> | ApiError;

// 分页结果
export type PaginatedResult<T> = {
  items: T[];
  total: number;
  page: number;
  pageSize: number;
  hasMore: boolean;

  | { type: 'POST_CREATED'; payload: Post }
```

## 八、常见误区与陷阱

### 8.1 误区一："type 不能被实现（implements）"

**错误认知**：以为只有 `interface` 能被 class `implements`。

```typescript
type Drawable = {
  draw(): void;
};

// ✅ type 别名同样可以被 implements！
class Circle implements Drawable {
  constructor(public radius: number) {}
  
  draw() {
    console.log(`画一个半径为 ${this.radius} 的圆`);
  }
}
```

实际上，只要是一个**对象类型**（无论是 `type` 还是 `interface`），都可以被 `implements`。

### 8.2 误区二："type 和 interface 性能差距很大"

**事实**：在大多数项目中，两者编译后的 JavaScript 代码完全相同（它们都是类型层面的概念，编译后会被擦除）。只有在极端情况下（数万个类型声明），`interface` 的声明合并检查才可能带来微小的编译速度差异。**不要为了这个而纠结选择。**

```typescript
// 这两种写法编译后的 JS 完全相同：
interface Point { x: number; y: number; }
type Point = { x: number; y: number; };

// 编译后都变成了：
// var p = { x: 0, y: 0 }; // 没有任何类型信息
```

### 8.3 误区三："应该统一只用一种"

**最佳实践**：混合使用才是最自然的做法。每种形式都有自己最适合的场景：

```typescript
// ✅ 推荐：各司其职
interface UserService {           // 对象契约 → interface
  getUsers(): Promise<User[]>;
}

type UserID = string;             // 类型别名 → type
type Status = 'ok' | 'error';     // 联合 → type
type Response<T> =                // 复杂组合 → type
  | { status: 'ok'; data: T }
  | { status: 'error'; message: string };
```

### 8.4 坑点：递归类型限制

```typescript
// interface 天然支持递归
interface TreeNode {
  value: string;
  left?: TreeNode;   // ✅ 引用自身
  right?: TreeNode;  // ✅ 引用自身
}

// type 的递归需要间接实现
type TreeNode = {
  value: string;
  left?: TreeNode;    // TS 中也允许（TS 3.7+）
  right?: TreeNode;   // TS 中也允许（TS 3.7+）
};

// 但某些复杂递归在 type 中可能有问题
// type LinkedList = {         // ⚠️ 直接递归可能在旧版本中有问题
//   value: number;
//   next: LinkedList | null;
// };

// 解决方案：使用接口包装或延迟计算
interface ILinkedList {
  value: number;
  next: ILinkedList | null;
}
type LinkedList = ILinkedList;
```

## 九、个人总结与心得

学习 `type` 和 `interface` 之后，我总结了几条实用原则：

1. **先问自己在描述什么**：如果你在描述"这个东西长什么样"（一组属性和行为），用 `interface`；如果你在说"这个类型是某种东西的另一种叫法"或"几种类型的组合"，用 `type`。

2. **声明合并是 interface 的王牌**：当你需要给已有的类型添加属性而不修改原文件时，`interface` 是唯一的选择。这也是为什么很多库的 `.d.ts` 文件都用 `interface` 的原因。

3. **工具类型是 type 的主场**：`Partial`、`Pick`、`Omit`、`Record` 这些内置工具类型都是用 `type` 定义的。当你需要类似的类型变换能力时，`type` 配合映射类型和条件类型几乎无所不能。

4. **不要过早优化选择**：项目初期随便选一种就行，TypeScript 让两者之间的迁移非常容易。真正重要的是**保持一致性**——在一个文件或模块内统一风格。

5. **类型即文档**：好的类型别名命名可以让代码自我解释。`type UserID = string` 比 `/** @type {string} 用户ID */` 更安全、更可靠、IDE 支持更好。把类型当作一等公民来对待，你的代码质量会有质的飞跃。
