# 类的高级特性——抽象类、访问器（get/set）、this 类型

> **一句话总结**：TypeScript 类的高级特性让面向对象编程更加灵活和强大——抽象类提供"半成品"模板、get/set 访问器实现精细的数据控制、`this` 类型支持链式调用，这些特性组合起来能构建出既安全又优雅的代码架构。

## 一、抽象类深入

### 1.1 抽象类的核心规则

抽象类是 TypeScript 中一种特殊的类，它遵循三个核心规则：

1. **不能被实例化** —— 你永远无法 `new` 一个抽象类
2. **必须被继承** —— 它存在的意义就是作为其他类的基类
3. **抽象方法必须被子类实现** —— 子类必须给出具体实现

```typescript
// 抽象类声明：使用 abstract 关键字
abstract class Animal {
  // ✅ 可以有普通字段和方法
  name: string;
  
  constructor(name: string) {
    this.name = name;
  }

  // ✅ 普通方法——已有完整实现
  describe(): string {
    return `这是一只叫 ${this.name} 的动物`;
  }

  // ❌ 抽象方法——只有签名，没有方法体！
  // 子类必须实现这些方法
  abstract makeSound(): string;
  abstract move(): void;

  // ✅ 抽象字段也可以（TS 4.0+）
  abstract habitat: string;  // 栖息地——子类必须定义
}
```

**生活类比**：想象一个"汽车设计图纸"——它规定了车必须有轮子、引擎、方向盘，但没有规定轮子的大小或引擎的具体参数。不同的车型（轿车、卡车、跑车）会基于这份蓝图做出自己的实现。抽象类就是那张"设计图纸"。

### 1.2 为什么需要抽象类？

```typescript
// 场景：我们需要处理不同类型的支付方式

// ❌ 没用抽象类的问题代码
class Payment {
  pay(amount: number): void {
    throw new Error('子类必须重写此方法');
  }
  refund(amount: number): void {
    throw new Error('子类必须重写此方法');
  }
}

// 问题：
// 1. new Payment() 能成功创建——但调用 pay 会运行时报错！
// 2. 忘记重写方法不会在编译时被发现
const p = new Payment();       // 😱 竟然能创建！
p.pay(100);                     // 💥 运行时才报错！

// ✅ 使用抽象类——编译时就能发现错误
abstract class PaymentMethod {
  abstract pay(amount: number): void;
  abstract refund(amount: number): void;
  
  // 公共逻辑放在基类
  logTransaction(type: string, amount: number): void {
    console.log(`[${type}] 金额: ¥${amount}, 时间: ${new Date().toISOString()}`);
  }
}

// const pm = new PaymentMethod();  // ❌ 编译报错！无法创建抽象类实例

class Alipay extends PaymentMethod {
  pay(amount: number): void {
    this.logTransaction('支付宝支付', amount);
    console.log(`支付宝支付 ¥${amount}`);
  }

  refund(amount: number): void {
    this.logTransaction('支付宝退款', amount);
    console.log(`支付宝退款 ¥${amount}`);
  }
}

class WechatPay extends PaymentMethod {
  pay(amount: number): void {
    this.logTransaction('微信支付', amount);
    console.log(`微信支付 ¥${amount}`);
  }

  refund(amount: number): void {
    this.logTransaction('微信退款', amount);
    console.log(`微信退款 ¥${amount}`);
  }
}
```

**设计理念**：抽象类体现了 **Template Method（模板方法）模式**——基类定义算法骨架（哪些步骤），子类填充具体细节。这样既保证了一致性（所有子类都遵循相同流程），又保留了灵活性（每个子类有自己的实现）。

### 1.3 抽象类中的构造函数与成员初始化

```typescript
abstract class Shape {
  color: string;
  
  // 抽象类也可以有构造函数
  constructor(color: string) {
    this.color = color;
  }

  // 有实现的方法
  getColor(): string {
    return `颜色: ${this.color}`;
  }

  // 抽象方法
  abstract area(): number;
  abstract perimeter(): number;
}

// 子类必须通过 super() 调用父类构造函数
class Circle extends Shape {
  radius: number;

  constructor(color: string, radius: number) {
    super(color);   // ✅ 必须调用
    this.radius = radius;
  }

  area(): number {
    return Math.PI * this.radius ** 2;
  }

  perimeter(): number {
    return 2 * Math.PI * this.radius;
  }
}

// 参数属性 + 继承的组合
class Rectangle extends Shape {
  constructor(
    color: string,
    public width: number,     // 参数属性
    public height: number     // 参数属性
  ) {
    super(color);             // 调用抽象类构造函数
  }

  area(): number {
    return this.width * this.height;
  }

  perimeter(): number {
    return 2 * (this.width + this.height);
  }
}

const circle = new Circle('红色', 5);
console.log(circle.getColor());   // 颜色: 红色
console.log(circle.area());        // 78.54...
```

### 1.4 抽象类可以引用抽象类型

```typescript
abstract class Employee {
  name: string;
  baseSalary: number;

  constructor(name: string, baseSalary: number) {
    this.name = name;
    this.baseSalary = baseSalary;
  }

  // 抽象方法返回抽象类类型——多态的核心！
  abstract getManager(): Employee | null;
  abstract calculateSalary(): number;

  getInfo(): string {
    const manager = this.getManager();
    return `${this.name}: 月薪 ¥${this.calculateSalary()}, 上司: ${manager?.name ?? '无'}`;
  }
}

class Developer extends Employee {
  private managerRef: Employee | null = null;

  constructor(name: string, baseSalary: number) {
    super(name, baseSalary);
  }

  setManager(manager: Employee): void {
    this.managerRef = manager;
  }

  getManager(): Employee | null {
    return this.managerRef;
  }

  calculateSalary(): number {
    return this.baseSalary + 2000;  // 开发津贴
  }
}

class Manager extends Employee {
  private subordinates: Employee[] = [];

  constructor(name: string, baseSalary: number) {
    super(name, baseSalary);
  }

  addSubordinate(emp: Employee): void {
    this.subordinates.push(emp);
  }

  getManager(): Employee | null {
    return null;  // 经理没有上司（简化示例）
  }

  calculateSalary(): number {
    return this.baseSalary + 5000 + (this.subordinates.length * 500);  // 管理津贴 + 团队奖金
  }
}

const cto = new Manager('技术总监', 30000);
const dev = new Developer('小明', 15000);

dev.setManager(cto);
console.log(dev.getInfo());   // 小明: 月薪 ¥17000, 上司: 技术总监
```

## 二、抽象类 vs 接口——何时用哪个？

这是面试高频题，也是实际开发中经常需要做选择的场景。

### 2.1 核心对比

| 特征 | 抽象类 (`abstract class`) | 接口 (`interface`) |
|------|--------------------------|-------------------|
| **本质** | 是一种"半成品类"，既有结构也有行为 | 纯粹的类型契约/规范 |
| **能否包含实现代码** | ✅ 可以包含完整的方法实现 | ❌ 不能（纯类型描述） |
| **能否包含构造函数** | ✅ 可以 | ❌ 不能 |
| **能否实例化** | ❌ 不能直接 `new` | ❌ 不能（本身不是值） |
| **继承数量** | 只能 `extends` 一个 | 可以 `extends` 多个接口；类可以 `implements` 多个 |
| **访问修饰符** | 支持 `public/private/protected` | 默认都是 `public` |
| **字段** | 可以有各种类型的字段 | 只能描述形状（TS 中的接口字段） |
| **运行时存在** | ✅ 编译后仍是 JS 函数 | ❌ 编译后完全消失 |

### 2.2 选择指南

```typescript
// ========== 场景 1：只需要定义"契约/形状" → 用 interface ==========

// 定义数据形状
interface IUser {
  id: string;
  name: string;
  email: string;
}

// 定义行为契约
interface ILogger {
  info(message: string): void;
  error(message: string): void;
  warn(message: string): void;
}

interface ICache<T> {
  get(key: string): T | undefined;
  set(key: string, value: T): void;
  delete(key: string): boolean;
}


// ========== 场景 2：多个类共享实现代码 → 用 abstract class ==========

abstract class BaseRepository<T> {
  protected items: Map<string, T> = new Map();

  // ✅ 提供通用实现
  findAll(): T[] {
    return Array.from(this.items.values());
  }

  findById(id: string): T | undefined {
    return this.items.get(id);
  }

  delete(id: string): boolean {
    return this.items.delete(id);
  }

  // ❓ 子类决定如何保存
  abstract save(item: T): void;
  abstract update(id: string, data: Partial<T>): T;
}

// 子类只关注差异部分
class UserRepository extends BaseRepository<User> {
  save(item: User): void {
    this.items.set(item.id, item);
    // 还可以做用户特有的校验、日志等
  }

  update(id: string, data: Partial<User>): User {
    const existing = this.findById(id);
    if (!existing) throw new Error('User not found');
    const updated = { ...existing, ...data };
    this.items.set(id, updated);
    return updated;
  }
}
```

### 2.3 经典组合模式：接口 + 抽象类

实际开发中最佳实践往往是**两者结合使用**：

```typescript
// 第一步：接口定义公开契约（对外暴露）
interface IDataService<T> {
  findById(id: string): Promise<T | null>;
  findAll(): Promise<T[]>;
  create(data: Omit<T, 'id'>): Promise<T>;
  update(id: string, data: Partial<T>): Promise<T>;
  delete(id: string): Promise<boolean>;
}

// 第二步：抽象类提供通用实现（内部复用）
abstract class BaseService<T implements { id: string }> implements IDataService<T> {
  protected items: Map<string, T> = new Map();
  
  // 提供默认实现
  async findById(id: string): Promise<T | null> {
    return this.items.get(id) ?? null;
  }

  async findAll(): Promise<T[]> {
    return Array.from(this.items.values());
  }

  async delete(id: string): Promise<boolean> {
    return this.items.delete(id);
  }

  // 留给子类实现的抽象方法
  abstract create(data: Omit<T, 'id'>): Promise<T>;
  abstract update(id: string, data: Partial<T>): Promise<T>;

  // 额外的辅助方法（接口中没有，但子类可以用）
  protected validateId(id: string): void {
    if (!id || typeof id !== 'string') {
      throw new Error('Invalid ID format');
    }
  }
}

// 第三步：具体类完成最后拼图
class UserService extends BaseService<User> {
  async create(data: Omit<User, 'id'>): Promise<User> {
    const user: User = {
      id: crypto.randomUUID(),
      ...data,
      createdAt: new Date(),
    };
    this.items.set(user.id, user);
    return user;
  }

  async update(id: string, data: Partial<User>): Promise<User> {
    this.validateId(id);
    const existing = await this.findById(id);
    if (!existing) throw new Error(`User ${id} not found`);
    const updated = { ...existing, ...data, updatedAt: new Date() };
    this.items.set(id, updated);
    return updated;
  }
}

// 使用时依赖接口（不依赖具体实现）
async function processUsers(service: IDataService<User>) {
  const users = await service.findAll();
  console.log(`共 ${users.length} 个用户`);
}
```

**💡 设计心得**：这种"接口定义契约 → 抽象类提供骨架 → 具体类完成实现"的三层架构，是大型项目中管理复杂性的黄金法则。它让你既能享受类型安全的好处，又能避免重复代码。

## 三、访问器（Accessor）——get/set 深入

### 3.1 基本语法

TypeScript 的访问器允许你像操作普通属性一样读写值，但背后执行的是自定义的逻辑：

```typescript
class Person {
  private _name: string = '';
  private _age: number = 0;

  // getter —— 读取 person.name 时自动调用
  get name(): string {
    console.log('📖 正在读取 name');
    return this._name;
  }

  // setter —— 设置 person.name 时自动调用
  set name(value: string) {
    console.log('✏️ 正在设置 name');
    if (value.trim().length === 0) {
      throw new Error('名字不能为空！');
    }
    this._name = value.trim();
  }

  // 只有 getter 没有 setter → 只读属性
  get age(): number {
    return this._age;
  }
}

const person = new Person();
person.name = '  小明  ';  // ✏️ 正在设置 name（自动 trim）
console.log(person.name);   // 📖 正在读取 name → 小明

person.age = 18;            // ❌ 只有 getter，不能赋值！
```

**⚠️ 重要规则**：
- TypeScript 中如果要同时定义 get 和 set，两者的**可访问性必须一致**
- 如果只有 getter 没有 setter，该属性隐式为 `readonly`
- 访问器底层对应的是 `_` 前缀命名的私有字段（命名约定）

### 3.2 类型标注

getter 和 setter 都可以进行类型标注：

```typescript
class TemperatureTracker {
  private _celsius: number = 0;

  // getter 返回 number
  get celsius(): number {
    return this._celsius;
  }

  // setter 接收 number
  set celsius(value: number) {
    if (value < -273.15) {
      throw new Error('低于绝对零度！');
    }
    this._celsius = value;
  }

  // getter 可以返回不同类型（计算属性）
  get fahrenheit(): number {
    return this._celsius * 9 / 5 + 32;
  }

  // setter 接收的可以是不同类型
  set fahrenheit(value: number) {
    this.celsius = (value - 32) * 5 / 9;
  }

  // getter 返回字符串格式化结果
  get display(): string {
    return `${this._celsius.toFixed(1)}°C / ${this.fahrenheit.toFixed(1)}°F`;
  }
}

const temp = new TemperatureTracker();
temp.celsius = 25;
console.log(temp.display);          // 25.0°C / 77.0°F
temp.fahrenheit = 100;              // 通过华氏度设置
console.log(temp.celsius);          // 37.777...
```

### 3.3 实际应用一：计算属性

```typescript
class Circle {
  constructor(public radius: number) {}

  // 直径——计算属性
  get diameter(): number {
    return this.radius * 2;
  }

  set diameter(value: number) {
    this.radius = value / 2;
  }

  // 面积——只读计算属性
  get area(): number {
    return Math.PI * this.radius ** 2;
  }

  // 周长——只读计算属性
  get circumference(): number {
    return 2 * Math.PI * this.radius;
  }
}

const circle = new Circle(5);
console.log(circle.diameter);       // 10（自动计算）
console.log(circle.area);           // 78.54...

circle.diameter = 20;               // 通过设置直径来改变半径
console.log(circle.radius);         // 10（半径自动变化）
console.log(circle.area);           // 314.16...（面积也跟着变）
```

**生活类比**：就像你的手机屏幕上的"电池百分比"——你并没有直接存储这个数字，它是根据当前电压实时计算的。当你看到"电量 85%"时，背后是一系列传感器读数经过公式换算的结果。

### 3.4 实际应用二：数据校验

```typescript
class UserRegistration {
  private _username: string = '';
  private _email: string = '';
  private _password: string = '';
  private _age: number = 0;
  private errors: Map<string, string> = new Map();

  // 用户名校验
  get username(): string {
    return this._username;
  }

  set username(value: string) {
    if (value.length < 3) {
      this.errors.set('username', '用户名至少 3 个字符');
      return;
    }
    if (!/^[a-zA-Z0-9_]+$/.test(value)) {
      this.errors.set('username', '只能包含字母、数字和下划线');
      return;
    }
    this.errors.delete('username');
    this._username = value;
  }

  // 邮箱校验
  get email(): string {
    return this._email;
  }

  set email(value: string) {
    const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
    if (!emailRegex.test(value)) {
      this.errors.set('email', '邮箱格式不正确');
      return;
    }
    this.errors.delete('email');
    this._email = value.toLowerCase();  // 自动转小写
  }

  // 年龄校验
  get age(): number {
    return this._age;
  }

  set age(value: number) {
    if (!Number.isInteger(value)) {
      this.errors.set('age', '年龄必须是整数');
      return;
    }
    if (value < 0 || value > 150) {
      this.errors.set('age', '年龄必须在 0-150 之间');
      return;
    }
    this.errors.delete('age');
    this._age = value;
  }

  // 密码强度检测
  get password(): string {
    return '*'.repeat(this._password.length);  // 读取时隐藏
  }

  set password(value: string) {
    if (value.length < 8) {
      this.errors.set('password', '密码至少 8 位');
      return;
    }
    if (!/[A-Z]/.test(value)) {
      this.errors.set('password', '需包含大写字母');
      return;
    }
    if (!/[0-9]/.test(value)) {
      this.errors.set('password', '需包含数字');
      return;
    }
    this.errors.delete('password');
    this._password = value;
  }

  // 校验状态
  get isValid(): boolean {
    return this.errors.size === 0;
  }

  get validationErrors(): Record<string, string> {
    return Object.fromEntries(this.errors);
  }
}

// 使用
const form = new UserRegistration();
form.username = 'ab';              // 太短
form.email = 'invalid';            // 格式不对
form.age = 200;                    // 超出范围
form.password = 'weak';            // 不够强

console.log(form.isValid);         // false
console.log(form.validationErrors);
// { username: '用户名至少 3 个字符', email: '邮箱格式不正确', 
//   age: '年龄必须在 0-150 之间', password: '密码至少 8 位' }

form.username = 'alice123';
form.email = 'Alice@Test.COM';    // 会自动转为小写
form.age = 25;
form.password = 'StrongPass2024';

console.log(form.isValid);         // true
console.log(form.email);           // alice@test.com（已小写）
console.log(form.password);        // *********（隐藏显示）
```

### 3.5 实际应用三：延迟加载与缓存

```typescript
class ExpensiveResource {
  private _data: string | null = null;
  private _loaded: boolean = false;

  get data(): string {
    if (!this._loaded) {
      console.log('🔄 正在从数据库加载数据...');
      // 模拟昂贵的数据库查询
      this._data = JSON.stringify({
        id: 1,
        name: '重要资源',
        content: '大量数据...'.repeat(1000),
        timestamp: Date.now()
      });
      this._loaded = true;
      console.log('✅ 数据加载完毕并缓存');
    }
    return this._data!;
  }

  // 手动清除缓存
  invalidateCache(): void {
    this._loaded = false;
    this._data = null;
    console.log('🗑️ 缓存已清除');
  }
}

const resource = new ExpensiveResource();
console.log(resource.data.substring(0, 30));  // 🔄 加载... ✅ 缓存
console.log(resource.data.substring(0, 30));  // 直接返回缓存（不再打印日志）

resource.invalidateCache();
console.log(resource.data.substring(0, 30));  // 🔄 再次加载...
```

### 3.6 访问器的注意事项

```typescript
class PitfallDemo {
  private _value: number = 0;

  get value(): number {
    return this._value;
  }

  set value(value: number) {
    // ⚠️ 不要在 setter 里触发 getter！会导致无限递归

    // ✅ 直接操作底层字段

}

const demo = new PitfallDemo();
demo.value = 5;
console.log(demo.value);   // 10（被乘以了 2）

// ⚠️ 另一个坑：严格模式下 getter 和 setter 必须成对出现
class StrictModeExample {
  private _x: number = 0;

  get x(): number {        // 只有 getter
    return this._x;
  }

  // 如果尝试赋值：
  // strict.x = 10;  // ❌ 只有 getter，不能赋值（隐式 readonly）
}
```

## 四、`this` 类型

### 4.1 什么是 `this` 类型？

TypeScript 中的 `this` 类型是一种特殊的**多态类型**，表示"当前类的实例类型"。它在方法中返回 `this` 时特别有用：

```typescript
class StringBuilder {
  private parts: string[] = [];

  add(text: string): this {
    this.parts.push(text);
    return this;  // 返回 this → 支持链式调用
  }

  addLine(text: string): this {
    this.parts.push(text + '\n');
    return this;
  }

  clear(): this {
    this.parts = [];
    return this;
  }

  toString(): string {
    return this.parts.join('');
  }
}
```

```typescript
  }

    return this;
```

```typescript
class Validator<T> {
  private value: T;
  private errors: string[] = [];

  constructor(value: T) {
    this.value = value;
  }

  required(message?: string): this {
    if (this.value == null || this.value === '') {
      this.errors.push(message ?? '此字段为必填项');
    }
    return this;
  }

  min(length: number, message?: string): this {
    if (typeof this.value === 'string' && this.value.length < length) {
      this.errors.push(message ?? `最少需要 ${length} 个字符`);
    }
    return this;
  }

  max(length: number, message?: string): this {
    if (typeof this.value === 'string' && this.value.length > length) {
      this.errors.push(message ?? `最多允许 ${length} 个字符`);
    }
    return this;
  }

  email(message?: string): this {
    if (typeof this.value === 'string' && !/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(this.value)) {
      this.errors.push(message ?? '邮箱格式不正确');
    }
    return this;
  }

  pattern(regex: RegExp, message?: string): this {
    if (typeof this.value === 'string' && !regex.test(this.value)) {
      this.errors.push(message ?? '格式不匹配');
    }
    return this;
  }

  custom(validatorFn: (value: T) => boolean, message: string): this {
    if (!validatorFn(this.value)) {
      this.errors.push(message);
    }
    return this;
  }

  getResult(): { valid: boolean; errors: string[]; value: T } {
    return {
      valid: this.errors.length === 0,
      errors: this.errors,
      value: this.value,
    };
  }
}
```

## 六、类的可见性与封装设计

### 6.1 封装的层次设计

好的类设计应该精心规划每一层可见性：

```typescript
/**
 * 封装层次示例：银行账户系统
 */
class BankAccount {
  // ==================== 第一层：完全对外公开 ====================
  /** 账号 —— 对外可见且不可修改 */
  public readonly accountNumber: string;
  
  /** 账户类型 —— 对外可见 */
  public accountType: 'checking' | 'savings' | 'credit';
  
  constructor(accountNumber: string, accountType: 'checking' | 'savings' | 'credit') {
    this.accountNumber = accountNumber;
    this.accountType = accountType;
  }

  // ==================== 第二层：受控的公开接口 ====================
  /** 存款 —— 外部可调用，但有业务逻辑 */
  deposit(amount: number): TransactionResult {
    if (amount <= 0) {
      return { success: false, message: '存款金额必须大于 0' };
    }
    this.#balance += amount;
    this.#recordTransaction('deposit', amount);
    return { success: true, message: `存款 ¥${amount} 成功`, newBalance: this.#balance };
  }

  /** 取款 —— 外部可调用，但需要密码验证 */
  withdraw(amount: number, pin: string): TransactionResult {
    if (!this.#verifyPin(pin)) {
      return { success: false, message: '密码错误' };
    }
    if (amount > this.#balance) {
      return { success: false, message: '余额不足', currentBalance: this.#balance };
    }
    if (amount <= 0) {
      return { success: false, message: '取款金额必须大于 0' };
    }
    
    this.#balance -= amount;
    this.#recordTransaction('withdrawal', amount);
    
    // 单日取款超限检查
    if (this.#dailyWithdrawTotal > this.DAILY_LIMIT) {
      return { success: false, message: '超过每日取款限额 ¥' + this.DAILY_LIMIT };
    }
    
    return { success: true, message: `取款 ¥${amount} 成功`, newBalance: this.#balance };
  }

  /** 查询余额 —— 受保护的接口 */
  getBalance(pin: string): BalanceResult | null {
    if (!this.#verifyPin(pin)) return null;
    return {
      balance: this.#balance,
      available: this.#balance - this.#frozenAmount,
      frozen: this.#frozenAmount,
    };
  }

  // ==================== 第三层：protected —— 子类可用 ====================
  
  /** 单日取款限额 —— 子类可能需要覆盖 */
  protected DAILY_LIMIT: number = 20000;

  /** 内部计算利息的方法 —— 子类可覆写 */
  protected calculateInterest(rate: number): number {
    return this.#balance * rate * (this.#daysSinceLastInterest / 365);
  }

  // ==================== 第四层：private —— 完全私有 ====================
  
  /** 余额 —— ES2020 私有字段 */
  #balance: number = 0;
  
  /** 冻结金额 */
  #frozenAmount: number = 0;
  
  /** 密码哈希 */
  #pinHash: string;
  
  /** 交易记录 */
  #transactions: Transaction[] = [];
  
  /** 今日取款总额 */
  #dailyWithdrawTotal: number = 0;
  
  /** 上次计息天数 */
  #daysSinceLastInterest: number = 0;

  constructor(accountNumber: string, accountType: 'checking' | 'savings' | 'credit', pinHash: string) {
    this.accountNumber = accountNumber;
    this.accountType = accountType;
    this.#pinHash = pinHash;
  }

  /** 密码验证 —— 纯内部逻辑 */
  #verifyPin(pin: string): boolean {
    // 实际应该用安全的哈希比较
    return hashPin(pin) === this.#pinHash;
  }

  /** 记录交易 —— 纯内部逻辑 */
  #recordTransaction(type: 'deposit' | 'withdrawal', amount: number): void {
    this.#transactions.push({
      type,
      amount,
      timestamp: new Date(),
      balanceAfter: this.#balance,
    });
    if (type === 'withdrawal') {
      this.#dailyWithdrawTotal += amount;
    }
  }
}

// 辅助类型
interface TransactionResult {
  success: boolean;
  message: string;
  newBalance?: number;
  currentBalance?: number;
}

interface BalanceResult {
  balance: number;
  available: number;
  frozen: number;
}

interface Transaction {
  type: 'deposit' | 'withdrawal';
  amount: number;
  timestamp: Date;
  balanceAfter: number;
}

function hashPin(pin: string): string {
  return pin; // 示例简化
}
```

**封装设计的核心原则**：
- **public**：最小化的稳定接口——外部真正需要的
- **protected**：扩展点——子类可能需要的钩子
- **private**：实现细节——绝对不让外界触碰

## 九、混入模式（Mixin Pattern）

JavaScript/TypeScript 只支持单继承，但有时我们确实需要一个类具备多个来源的能力。**混入（Mixin）** 就是解决方案：

### 9.1 基本混入模式

```typescript
// ====== 定义混入（可复用的能力模块）======

// 能力 1：时间戳追踪
function Timestamped<TBase extends new (...args: any[]) => {}>(Base: TBase) {
  return class extends Base {
    createdAt = new Date();
    updatedAt = new Date();

    getAgeInSeconds(): number {
      return Math.floor((Date.now() - this.createdAt.getTime()) / 1000);
    }

    touch(): void {
      this.updatedAt = new Date();
    }
  };
}

// 能力 2：序列化
function Serializable<TBase extends new (...args: any[]) => {}>(Base: TBase) {
  return class extends Base {
    toJSON(): string {
      return JSON.stringify({ ...this });
    }

    static fromJSON<T>(json: string): T {
      return Object.assign(new (this as any)(), JSON.parse(json));
    }
  };
}

// 能力 3：可验证
function Validatable<TBase extends new (...args: any[]) => {}>(Base: TBase) {
  return class extends Base {
    errors: string[] = [];

    isValid(): boolean {
      this.errors = [];
      this.validate();
      return this.errors.length === 0;
    }

    protected validate(): void {
      // 子类覆写此方法添加具体校验逻辑
    }

    addError(message: string): void {
      this.errors.push(message);
    }
  };
}

// ====== 使用混入组装类 ======

// 先定义基础类
class BaseEntity {
  id: string = crypto.randomUUID();
}

// 逐层应用混入
const EnhancedEntity = Timestamped(Serializable(Validatable(BaseEntity)));

class TimestampedEntity extends Timestamped(BaseEntity) {}
class SerializableEntity extends Serializable(TimestampedEntity) {}
class ValidatedUser extends Validatable(SerializableEntity) {

  email: string = '';

    super();
    this.name = name;
    this.email = email;
  }

    if (!this.email.includes('@')) this.addError('邮箱无效');
```

### 9.2 更实用的混入案例

```typescript
// 能力：事件发射
function EventEmitter<Base extends new (...args: any[]) => {}>(Base: Base) {
  return class extends Base {
    private listeners = new Map<string, Set<Function>>();

    on(event: string, callback: Function): this {
      if (!this.listeners.has(event)) {
        this.listeners.set(event, new Set());
      }
      this.listeners.get(event)!.add(callback);
      return this;
    }

    off(event: string, callback: Function): this {
      this.listeners.get(event)?.delete(callback);
      return this;
    }

    emit(event: string, ...args: any[]): void {
      this.listeners.get(event)?.forEach(cb => cb(...args));
    }

    once(event: string, callback: Function): this {
      const wrapper = (...args: any[]) => {
        this.off(event, wrapper);
        callback(...args);
      };
      return this.on(event, wrapper);
    }
  };
}

// 能力：可撤销操作
function Revocable<Base extends new (...args: any[]) => {}>(Base: Base) {
  return class extends Base {
    private history: any[] = [];
    private future: any[] = [];

    saveState(state: any): void {
      this.history.push(JSON.parse(JSON.stringify(state)));
      this.future = [];  // 新操作清空重做栈
    }

    canUndo(): boolean { return this.history.length > 0; }
    canRedo(): boolean { return this.future.length > 0; }

    undo(): any | null {
      if (!this.canUndo()) return null;
      const current = this.history.pop();
      this.future.push(current);
      return this.history[this.history.length - 1] ?? null;
    }

    redo(): any | null {
      if (!this.canRedo()) return null;
      const state = this.future.pop();
      this.history.push(state);
      return state;
    }
  };
}

// 组装一个同时具备事件发射和撤销能力的编辑器模型
class BasicEditor {
  text: string = '';

  setText(text: string): void {
    this.text = text;
  }
}

const EditorClass = Revocable(EventEmitter(BasicEditor));

class TextEditor extends EditorClass {
  setText(text: string): void {
    this.saveState({ text: this.text });  // 修改前保存状态
    this.text = text;
    this.emit('change', this.text);       // 发出变更事件
  }
}

// 使用
const editor = new TextEditor();

editor.on('change', (newText: string) => {
  console.log(`📝 文本变为: "${newText}"`);
});

editor.setText('Hello');     // 📝 文本变为: "Hello"
editor.setText('Hello World'); // 📝 文本变为: "Hello World"
editor.setText('Hello TypeScript!'); // 📝 文本变为: "Hello TypeScript!"

console.log(editor.canUndo()); // true
editor.undo();                // 撤销
console.log(editor.text);      // Hello World
editor.redo();                // 重做
console.log(editor.text);      // Hello TypeScript!
```

**设计理念**：Mixins 实现了 **"组合优于继承"**（Composition over Inheritance）的原则。与其建立一个深层的、复杂的继承树，不如把能力拆成独立的模块，按需自由组合。

```typescript
// 更实用的例子：灵活的 CSS 类名管理器
class ClassNames {
  private classes: Set<string> = new Set();

  // 索引签名——布尔值控制类名的增删
  [className: string]: boolean | undefined;

  constructor(initial?: Record<string, boolean>) {
    if (initial) {
      Object.entries(initial).forEach(([name, active]) => {
        this[name] = active;
      });
    }
  }

  toString(): string {
    return Array.from(this.classes).join(' ');
  }
}

// 使用 Proxy 来真正实现索引签名的语义
class FlexibleCSSClasses {
  private classes: Map<string, boolean> = new Map();

  // 通过代理实现索引签名效果
  has(className: string): boolean {
    return !!this.classes.get(className);
  }

  add(className: string): this {
    this.classes.set(className, true);
    return this;
  }

  remove(className: string): this {
    this.classes.delete(className);
    return this;
  }

  toggle(className: string, force?: boolean): this {
    const shouldAdd = force !== undefined ? force : !this.classes.get(className);
    if (shouldAdd) {
      this.classes.set(className, true);
    } else {
      this.classes.delete(className);
    }
    return this;
  }

  toString(): string {
    return Array.from(this.classes.entries())
      .filter(([, active]) => active)
      .map(([name]) => name)
      .join(' ');
  }
}

const classNames = new FlexibleCSSClasses()
  .add('container')
  .add('flex')
  .toggle('active', true)
  .toggle('hidden');

console.log(classNames.toString()); // container flex active
classNames.toggle('hidden');       // 切换 hidden
console.log(classNames.toString()); // container flex active hidden
```

### 11.1 访问修饰符只在编译时生效

```typescript
class RuntimeVsCompileTime {
  public publicField: string = 'public';
  private privateField: string = 'private';
  protected protectedField: string = 'protected';

  publicMethod(): string {
    return this.privateField;  // ✅ 编译时 OK
  }
}

const instance = new RuntimeVsCompileTime();

// 编译时检查
instance.publicField;       // ✅ 编译通过
instance.privateField;      // ❌ 编译错误：私有属性
instance.protectedField;    // ❌ 编译错误：受保护属性

// 但编译后的 JavaScript：
const compiled = new RuntimeVsCompileTime();
console.log(compiled.publicField);    // 'public'
console.log(compiled.privateField);   // 'private' ← 运行时可以访问！
console.log(compiled.protectedField); // 'protected' ← 运行时可以访问！
```

**结论**：TypeScript 的 `private`/`protected` 只是**编译时的门卫**，不是运行时的保险柜。如果需要真正的运行时隐私性，使用 ES2020 的 `#` 私有字段：

```typescript
class TrulyPrivate {

  private privateValue = 'TS私有';
  #trulyPrivate = 'JS原生私有';

    return {
      public: this.publicValue,
      tsPrivate: this.privateValue,   // 内部可访问
      jsPrivate: this.#trulyPrivate,   // 内部可访问
    };
  }
}

const tp = new TrulyPrivate();
tp.publicValue;       // ✅ 运行时可访问
tp.privateValue;      // ❌ 仅编译时报错，但运行时可访问
// tp.#trulyPrivate;  // ❌❌❌ 编译和运行都会报错！
```

```typescript
// 观察者接口
interface Observer {
  update(data: any): void;
}

// 被观察的主题
class Subject {
  private observers: Observer[] = [];

  attach(observer: Observer): void {
    this.observers.push(observer);
  }

  detach(observer: Observer): void {
    const index = this.observers.indexOf(observer);
    if (index > -1) {
      this.observers.splice(index, 1);
    }
  }

  notify(data: any): void {
    for (const observer of this.observers) {
      observer.update(data);
    }
  }
}

// 具体应用：股票价格监控
class StockPrice extends Subject {
  private price: number;

  constructor(initialPrice: number) {
    super();
    this.price = initialPrice;
  }

  get currentPrice(): number {
    return this.price;
  }

  setPrice(newPrice: number): void {
    this.price = newPrice;
    this.notify({ symbol: 'AAPL', price: newPrice, timestamp: new Date() });
  }
}

// 具体观察者
class AlertSystem implements Observer {

}

}

class LogRecorder implements Observer {
```

## 十三、常见问题与坑点

### 13.1 抽象类构造函数的陷阱

```typescript
abstract class Parent {
  x: string;
  
  constructor() {
    this.init();  // ⚠️ 危险！此时子类字段尚未初始化
  }

  init(): void {
    this.x = 'parent';
  }
}

class Child extends Parent {
  y: string = 'child';  // 字段初始化在 super() 之后
  
  constructor() {
    super();  // 此时 y 还是 undefined！
    console.log(this.y);  // undefined 而非 'child'
  }

  override init(): void {
    super.init();
    console.log(this.y);  // undefined! 子类字段还没准备好
    this.y = 'modified in init';  // 之后才会被字段初始化覆盖回 'child'
  }
}

const child = new Child();
console.log(child.y);  // 最终是 'child'（字段初始化覆盖了 init 中的赋值）
```

**规则**：不要在构造函数（包括间接调用的方法）中依赖子类的字段初始值。如果需要类似功能，使用两阶段初始化或在子类构造函数的 `super()` 之后手动调用初始化方法。

### 13.2 getter/setter 性能考量

```typescript
class PerformanceTest {
  private _value: number = 0;

  // 直接属性访问
  directValue: number = 0;

  // 简单 getter/setter
  get value(): number { return this._value; }
  set value(v: number) { this._value = v; }

  // 复杂 getter（含计算）
  get computedValue(): number {
    let sum = 0;
    for (let i = 0; i < 1000; i++) sum += i;

}
```

### 13.3 `this` 类型与类型缩小的冲突

```typescript
class Processor {
  protected data: string | number = '';

  setData(value: string | number): this {
    this.data = value;
    return this;
  }

  // ⚠️ 这里 this 类型导致 data 的类型缩小失效
  processData(): string {
    if (typeof this.data === 'string') {
      // TypeScript 认为 this.data 仍然是 string | number
      // 因为 this 可能指向子类实例，而子类可能改变了 data 的类型
      return this.data.toUpperCase();  // ❌ data 可能是 number
    }
    return String(this.data);
  }
}

// 解决方案：显式类型保护或类型断言
class FixedProcessor {
  protected data: string | number = '';

  setData(value: string | number): this {
    this.data = value;
    return this;
  }

  processData(): string {
    const d = this.data;
    if (typeof d === 'string') {
      return d.toUpperCase();  // ✅ 局部变量的类型缩小正常工作
    }
    return String(d);
  }
}
```

## 十四、个人总结与心得

学完 TypeScript 类的高级特性，我整理了几点核心体会：

### 1. 抽象类是"有骨有肉的模板"

接口像是"骨架"——只定义形状，没有血肉。普通类则是"完整的人"。抽象类介于两者之间——它有公共的实现（肌肉和器官），但也留出了一些空缺（抽象方法）让子类去填补。在设计框架或 SDK 时，抽象类几乎是不可或缺的工具。

### 2. get/set 让"属性"变得智能

普通的属性就是数据的容器——你放什么进去，拿出来就是什么。但加了 getter/setter 后，属性变成了一种"主动的行为"。读取时可以计算、过滤、记录日志；写入时可以校验、转换、触发副作用。这让我们的 API 既保持了简洁的语法（`obj.prop = value`），又获得了方法的灵活性。

### 3. `this` 类型是链式调用的灵魂

没有 `this` 类型，链式调用只能在单个类内部工作。一旦涉及继承，返回类型就会"退化"为父类类型，丢失子类特有的方法。`this` 类型解决了这个问题，让 jQuery 式的 `.css().animate().show()` 流畅 API 得以在继承体系中也完美运作。

### 4. 混入模式打破了单继承的限制

JavaScript 的单继承有时确实不够用。混入模式让我们可以把"能力"拆分成独立的小模块，然后像搭积木一样自由组合。这比建立深层继承树更灵活，也更符合"组合优于继承"的现代软件工程理念。

### 5. 编译时 vs 运行时的鸿沟要牢记心中

TypeScript 的很多特性（private、abstract、类型注解）只在编译时生效。编译成 JavaScript 后这些都消失了。这意味着：
- 不要依赖 TypeScript 做安全边界（如权限控制）
- 与不受信任的数据交互时，要做运行时类型检查
- 团队协作时要靠 Code Review，不能只靠类型系统 catch bug

### 6. 设计模式不是教条，而是工具

工厂、观察者、策略……这些模式都很强大，但不要为了用而用。先写出能工作的代码，当发现重复、耦合或难以扩展时，再用合适的模式去重构。TypeScript 的类型系统能让这些模式的实现更加安全和优雅。
