## 什么是类型守卫（Type Guard）

JavaScript 是一门**动态类型语言**——变量的类型在运行时才能确定。而 TypeScript 的**静态类型检查**发生在编译时。这两个世界之间存在着一道鸿沟。

**类型守卫（Type Guard）就是跨越这道鸿沟的桥梁。**

它的定义很简单：**在运行时进行类型检查，同时让 TypeScript 编译器在对应的代码分支中自动收窄（narrow）变量的类型。**

**生活类比**：想象机场安检。你拿着一张机票（声明了你的目的地），但安检员需要验证你本人是否与证件一致（运行时检查）。一旦通过验证，你就被放行到了正确的登机口（类型自动收窄）。

```typescript
// 最简单的例子——typeof 类型守卫
function printLength(value: string | number): void {
  // 这里 value 的类型是 string | number（宽泛）
  
  if (typeof value === 'string') {
    // 进入这个分支后，value 自动变成 string 类型！
    console.log(value.length)    // ✅ string 有 length 属性
    console.log(value.toUpperCase())  // ✅
  } else {
    // 这个分支里 value 自动变成 number 类型！
    console.log(value.toFixed(2))  // ✅ number 有 toFixed 方法
  }
}
```

注意上面代码的神奇之处：`value` 在 `if` 内外是不同的类型，而且这个变化是 **TypeScript 自动完成的**——不需要你手动写任何断言。

这就是类型守卫的核心价值：
1. **运行时安全**：真的做了类型检查
2. **编译时智能**：TS 在对应分支自动知道精确类型

## typeof 类型守卫

`typeof` 是最基础也最常用的内置类型守卫。

### 支持的类型判断

`typeof` 返回以下字符串值——TypeScript 只认这些：

| typeof 结果 | 对应的 TypeScript 类型 | 示例 |
|-----------|---------------------|------|
| `'string'` | `string` | `'hello'`, `` `template` `` |
| `'number'` | `number` | `42`, `3.14`, `NaN`, `Infinity` |
| `'bigint'` | `bigint` | `100n` |
| `'boolean'` | `boolean` | `true`, `false` |
| `'symbol'` | `symbol` | `Symbol('id')` |
| `'undefined'` | `undefined` | `undefined` |
| `'function'` | `Function` | `function(){}`, `() => {}`, `class {}` |
| `'object'` | `object \| null` | `{}`, `[]`, `new Date()`, `null` ⚠️ |

### 典型用法

```typescript
function processInput(input: string | number | boolean): void {
  if (typeof input === 'string') {
    input.toUpperCase()     // string
  } else if (typeof input === 'number') {
    input.toFixed(2)        // number
  } else {
    input ? 'true' : 'false'  // boolean
  }
}
```

### typeof 的经典陷阱 —— null

这是 JavaScript 遗留的最著名的设计缺陷之一：

```typescript
const data = null

console.log(typeof null)
// → 'object'  😱 不是 'null'！

// 这意味着在类型守卫中：
function check(data: string | null): void {
  if (typeof data === 'object') {
    // ❌ 危险！这里可能是真正的 object，也可能是 null！
    console.log(data.length)  // 如果 data 是 null，崩溃！
  }
}
```

**为什么？** 这是 JavaScript 从第一天就存在的 bug，但为了兼容已有代码，永远无法修复。

**正确的处理方式**：

```typescript
function check(data: string | null): void {
  if (typeof data === 'object' && data !== null) {
    // ✅ 排除了 null
    console.log(data.length)
  }

  // 更简洁的方式：直接用相等性判断
  if (data !== null) {
    // TS 知道这里 data 是 string（排除了 null）
    console.log(data.length)
  }
}

// 或者用现代语法
function check(data: string | null): void {
  console.log(data?.length)  // 可选链，最安全
}
```

### 实际应用场景

```typescript
// 场景：深度合并配置对象
function deepMerge<T extends Record<string, any>>(
  target: T,
  source: Partial<T>
): T {
  const result = { ...target }

  for (const key in source) {
    const sourceValue = source[key]
    const targetValue = result[key]

    if (
      typeof sourceValue === 'object' &&
      sourceValue !== null &&
      !Array.isArray(sourceValue) &&
      typeof targetValue === 'object' &&
      targetValue !== null &&
      !Array.isArray(targetValue)
    ) {
      // 两边都是普通对象，递归合并
      result[key] = deepMerge(targetValue, sourceValue)
    } else {
      // 否则直接覆盖
      result[key] = sourceValue as T[Extract<keyof T, string>]
    }
  }

  return result
}
```

## instanceof 类型守卫

`instanceof` 用于检查一个对象是否是某个类的实例（基于原型链）。

### 基本用法

```typescript
class Dog {
  bark(): string { return '汪汪!' }
}

class Cat {
  meow(): string { return '喵~' }
}

function makeSound(animal: Dog | Cat): void {
  if (animal instanceof Dog) {
    animal.bark()   // ✅ TS 知道这里是 Dog
  } else {
    animal.meow()   // ✅ TS 知道这里是 Cat
  }
}
```

### instanceof 的工作原理

`instanceof` 通过**原型链**来检查继承关系：

```typescript
class Animal { /* ... */ }
class Dog extends Animal { bark(): string { return '汪!' } }
class GoldenRetriever extends Dog { fetch(): string { return '叼回来!' } }

const dog = new GoldenRetriever()

dog instanceof GoldenRetriever  // ✅ true — 直接匹配
dog instanceof Dog              // ✅ true — 父类
dog instanceof Animal           // ✅ true — 祖父类
dog instanceof Object           // ✅ true — 所有对象的祖先
dog instanceof Array            // ❌ false — 无关的类
```

**生活类比**：就像查家谱——如果你问"这个人是不是张家的后代？"，不仅看他的姓氏是不是张，还要往上追溯每一代。`instanceof` 就是这样沿着原型链一路向上查找的。

### 跨 window/iframe 的限制

这是 `instanceof` 一个不太明显的坑：

```typescript
// 主页面中定义了一个类
class MyError extends Error {}

// 将数据通过 postMessage 发送到 iframe
iframe.contentWindow?.postMessage({ error: new MyError('出错了') }, '*')

// iframe 中接收后...
iframeWindow.addEventListener('message', (event) => {
  const error = event.data.error
  
  // ❌ 可能返回 false！
  // iframe 有自己的全局环境，MyError 构造函数不是同一个引用
  console.log(error instanceof MyError)   // 可能是 false！
  console.log(error instanceof Error)     // 这个也可能有问题
  console.log(error instanceof Object)    // 但 Object 通常没问题
})
```

**原因**：每个 iframe/window 有自己的全局对象和原型链。`instanceof` 使用的是**构造函数的引用比较**，不同环境中的同一个"类"其实是不同的函数对象。

**解决方案**：

```typescript
// 方案 1：使用 .constructor.name
if (error?.constructor?.name === 'MyError') { }  // 不依赖引用

// 方案 2：使用 duck typing（特征检测）
function isMyError(error: unknown): error is MyError {
  return (
    typeof error === 'object' &&
    error !== null &&
    'message' in error &&
    'name' in error && (error as any).name === 'MyError'
  )
}

// 方案 3：添加特殊标记属性
class MyError extends Error {
  readonly __type = 'MyError'  // 特殊标记
}
function isMyError(e: unknown): e is MyError {
  return typeof e === 'object' && e !== null && '__type' in e && (e as MyError).__type === 'MyError'
}
```

### 与内置类型的配合

```typescript
function processData(data: Date | RegExp | Map<string, any> | string[]): void {
  if (data instanceof Date) {
    console.log(data.toISOString())       // Date 方法
    data.setFullYear(2025)                // Date 方法
  } else if (data instanceof RegExp) {
    console.log(data.source)              // RegExp 属性
    data.test('hello')                    // RegExp 方法
  } else if (data instanceof Map) {
    console.log(data.size)                // Map 属性
    data.forEach((v, k) => {})            // Map 方法
  } else if (Array.isArray(data)) {
    // 注意：Array.isArray() 也是类型守卫！
    console.log(data.length)              // 数组属性
    data.push('new item')                 // 数组方法
  }
}
```

> **注意**：`Array.isArray()` 虽然不是 `instanceof`，但它同样起到类型守卫的作用，能将类型收窄为 `any[]`。

## in 操作符类型守卫

`in` 操作符用于检查对象是否包含某个属性名，在区分不同形状的对象类型时特别有用。

### 基本用法

```typescript
interface Circle {
  kind: 'circle'
  radius: number
}

interface Rectangle {
  kind: 'rectangle'
  width: number
  height: number
}

type Shape = Circle | Rectangle

function getArea(shape: Shape): number {
  // 用 in 操作符区分两种类型
  if ('radius' in shape) {
    // ✅ TS 知道这里是 Circle
    return Math.PI * shape.radius ** 2
  } else {
    // ✅ TS 知道这里是 Rectangle
    return shape.width * shape.height
  }
}
```

### 为什么不用 kind 字段做判断？

上面的例子中，其实也可以用 `shape.kind === 'circle'` 来判断。那什么时候必须用 `in`？

**当类型没有可辨识的联合字段时：**

```typescript
// 两个接口没有共同的可辨识字段
interface HttpSuccessResponse {
  status: 200 | 201 | 204
  data: unknown
  headers: Record<string, string>
}

interface HttpErrorResponse {
  status: 400 | 404 | 500
  error: string
  message: string
  stackTrace?: string
}

type HttpResponse = HttpSuccessResponse | HttpErrorResponse

function handleResponse(response: HttpResponse): void {
  // 不能只靠 status 判断——200 和 400 都是数字，没有明确的分界线
  // 但可以用 in 来判断独有的属性
  
  if ('data' in response) {
    // ✅ HttpSuccessResponse
    console.log(response.data)
  } else if ('error' in response) {
    // ✅ HttpErrorResponse
    console.error(`${response.error}: ${response.message}`)
  }
}
```

**另一个典型场景——API 数据校验**：

```typescript
interface UserDTO {
  id: number
  name: string
  email: string
}

interface ErrorDTO {
  code: string
  message: string
}

async function fetchUser(id: number): Promise<UserDTO> {
  const res = await fetch(`/api/users/${id}`)
  const data = await res.json()

  // API 可能返回用户数据或错误信息
  if (!res.ok || !('id' in data)) {
    throw new Error((data as ErrorDTO).message ?? '请求失败')
  }

  // 到这里 TS 知道 data 一定有 id 属性
  return data as UserDTO
}
```

### in 操作符的注意事项

```typescript
// 1. 继承链上的属性也能检测到
class Parent { parentMethod() {} }
class Child extends Parent { childMethod() {} }

const obj: Parent | Child = new Child()
if ('childMethod' in obj) {
  // ✅ 收窄为 Child
  obj.childMethod()
}

// 2. 注意原型链上的属性
const arr: string[] | { length: custom } = ['a', 'b']
if ('length' in arr) {
  // ⚠️ 两个分支都满足！数组和对象都有 length
  // 这种情况下 in 无法有效区分
}

// 3. 更安全的做法：组合多个属性检查
interface Cat { name: string; meow(): void }
interface Dog { name: string; bark(): void }
type Pet = Cat | Dog

function petSound(pet: Pet): void {
  // 单个属性可能不够
  if ('meow' in pet) {
    pet.meow()  // ✅ Cat
  }
  // 或者用排除法
  if (!('meow' in pet)) {
    pet.bark()  // ✅ Dog
  }
}
```

## 自定义类型守卫（Type Predicate）—— is 关键字

当内置的 `typeof`、`instanceof`、`in` 无法满足需求时，你可以编写自己的类型守卫函数。关键在于返回类型中使用 **`value is Type`** 语法的**类型谓词（Type Predicate）**。

### 语法结构

```typescript
// 标准格式
function isTypeName(variableName): variableName is TargetType {
  // 返回 boolean
  // 如果返回 true，TS 会将 variableName 收窄为 TargetType
  // 如果返回 false，variableName 会被从 TargetType 中排除
}
```

### 基础示例

```typescript
// 判断值是否是 string 类型
function isString(value: unknown): value is string {
  return typeof value === 'string'
}

function process(value: string | number): void {
  if (isString(value)) {
    // ✅ value 被收窄为 string
    console.log(value.toUpperCase())
  } else {
    // ✅ value 被收窄为 number
    console.log(value.toFixed(2))
  }
}
```

### 为什么不能直接用普通布尔函数？

```typescript
// ❌ 普通 boolean 函数——不会触发类型收窄
function checkIsString(value: unknown): boolean {
  return typeof value === 'string'
}

const value: string | number = maybeString()
if (checkIsString(value)) {
  // value 还是 string | number！没有收窄！
  value.toUpperCase()  // ❌ Error
}

// ✅ 类型谓词函数——会触发类型收窄
function isString(value: unknown): value is string {
  return typeof value === 'string'
}

if (isString(value)) {
  // value 变成了 string！✅
  value.toUpperCase()  // ✅ OK
}
```

**区别在于返回值的类型**：
- `boolean` → TS 认为这只是一个普通的真值/假值
- `value is X` → TS 认为"如果返回 true，那么 value 就是类型 X"

`is` 关键字是告诉 TypeScript 编译器的特殊信号："这个函数不仅是返回布尔值，它还是一个**类型保证**"。

### 实战：复杂对象的类型守卫

```typescript
interface Article {
  type: 'article'
  title: string
  content: string
  publishedAt: Date
  tags: string[]
}

interface Video {
  type: 'video'
  title: string
  url: string
  duration: number  // 秒
  thumbnail: string
}

interface ImageGallery {
  type: 'gallery'
  title: string
  images: { src: string; alt: string; caption?: string }[]
}

type Content = Article | Video | ImageGallery

// 编写完整的类型守卫函数
function isArticle(content: Content): content is Article {
  return content.type === 'article'
    && 'content' in content
    && 'publishedAt' in content
    && Array.isArray(content.tags)
}

function isVideo(content: Content): content is Video {
  return content.type === 'video'
    && 'url' in content
    && typeof content.duration === 'number'
    && 'thumbnail' in content
}

function isGallery(content: Content): content is ImageGallery {
  return content.type === 'gallery'
    && Array.isArray(content.images)
}

// 使用
function renderContent(content: Content): string {
  if (isArticle(content)) {
    return `<article><h1>${content.title}</h1>${content.content}</article>`
  } else if (isVideo(content)) {
    return `<video controls poster="${content.thumbnail}"><source src="${content.url}"></video>`
  } else if (isGallery(content)) {
    return content.images.map(img =>
      `<figure><img src="${img.src}" alt="${img.alt}">${img.caption ? `<figcaption>${img.caption}</figcaption>` : ''}</figure>`
    ).join('')
  }

  // 如果所有守卫都不匹配，这里 content 的类型会被排除掉所有已知分支
  const _exhaustive: never = content
  return _exhaustive
}
```

### 编写健壮类型守卫的原则

#### 原则 1：检查要全面

```typescript
// ❌ 过于简单——只检查了一个字段
function isUser(obj: unknown): obj is User {
  return typeof (obj as any)?.name === 'string'
  // 如果传入了 { name: 'xxx', 没有 id 和 email } 也会返回 true
}

// ✅ 全面检查所有必要字段
function isUser(obj: unknown): obj is User {
  return (
    typeof obj === 'object' &&
    obj !== null &&
    'id' in obj && typeof (obj as User).id === 'number' &&
    'name' in obj && typeof (obj as User).name === 'string' &&
    'email' in obj && typeof (obj as User).email === 'string'
  )
}
```

#### 原则 2：防御非法输入

```typescript
// ❌ 可能抛出异常
function isSafe(obj: unknown): obj is Safe {
  return (obj as any).nested.value.isValid === true
  // 如果 nested 或 value 不存在，会抛 TypeError
}

// ✅ 安全的逐步访问
function isSafe(obj: unknown): obj is Safe {
  const candidate = obj as Record<string, any>
  return (
    typeof candidate?.nested?.value?.isValid === 'boolean' &&
    candidate.nested.value.isValid === true
  )
}
```

#### 原则 3：考虑边界情况

```typescript
// 处理各种可能的"假值"
function isNonEmptyString(value: unknown): value is string {
  return typeof value === 'string' && value.length > 0
}

function isDefined<T>(value: T | undefined | null): value is T {
  return value !== undefined && value !== null
}

function isPositiveNumber(value: unknown): value is number {
  return typeof value === 'number' && !isNaN(value) && isFinite(value) && value > 0
  // 排除了 NaN, Infinity, -Infinity, 0 和负数
}
```

## 常见守卫函数库模式

在实际项目中，通常会维护一组通用的类型守卫工具函数：

### 基础类型守卫集合

```typescript
// utils/type-guards.ts

/** 是否是 null 或 undefined */
export function isNil(value: unknown): value is null | undefined {
  return value == null  // 同时检查 null 和 undefined
}

/** 是否有定义（非 null 且非 undefined） */
export function isDefined<T>(value: T | null | undefined): value is T {
  return value != null
}

/** 是否是非空字符串 */
export function isNonEmptyString(value: unknown): value is string {
  return typeof value === 'string' && value.trim().length > 0
}

/** 是否是有效的数字（非 NaN、非 Infinity） */
export function isValidNumber(value: unknown): value is number {
  return typeof value === 'number' && !Number.isNaN(value) && Number.isFinite(value)
}

/** 是否是普通对象（非数组、非 null、非函数等） */
export function isPlainObject(value: unknown): value is Record<string, unknown> {
  return (
    typeof value === 'object' &&
    value !== null &&
    !Array.isArray(value) &&
    toString.call(value) === '[object Object]'
  )
}

/** 是否是数组 */
export function isArray<T = unknown>(value: unknown): value is T[] {
  return Array.isArray(value)
}

/** 是否是函数 */
export function isFunction(value: unknown): value is (...args: any[]) => any {
  return typeof value === 'function'
}

/** 是否是 Date 对象且日期有效 */
export function isValidDate(value: unknown): value is Date {
  return value instanceof Date && !Number.isNaN(value.getTime())
}

/** 是否是 Promise（thenable） */
export function isPromise<T = unknown>(value: unknown): value is Promise<T> {
  return (
    typeof value === 'object' &&
    value !== null &&
    'then' in value &&
    typeof (value as any).then === 'function'
  )
}

/** 是否是空的（无自身可枚举属性） */
export function isEmptyObject(value: unknown): value is Record<string, never> {
  return isPlainObject(value) && Object.keys(value).length === 0
}
```

### 断言式守卫（不满足则抛异常）

有时候你希望守卫不通过时直接抛出错误，而不是返回 false：

```typescript
/** 断言式守卫：条件不满足时抛出 TypeError */
export function assert(condition: unknown, message?: string): asserts condition {
  if (!condition) {
    throw new TypeError(message ?? 'Assertion failed')
  }
}

/** 断言指定类型 */
export function assertIsString(value: unknown): asserts value is string {
  if (typeof value !== 'string') {
    throw new TypeError(`Expected string, got ${typeof value}`)
  }
}

/** 断言非空 */
export function assertDefined<T>(
  value: T | null | undefined,
  message?: string
): asserts value is T {
  if (value == null) {
    throw new TypeError(message ?? `Value should not be null or undefined`)
  }
}

// 使用示例
function processConfig(raw: unknown): void {
  assert(isPlainObject(raw), 'Config must be an object')
  assertIsString(raw.url, 'Config.url must be a string')
  assertDefined(raw.port, 'Config.port is required')

  //到这里 raw.url 已经被确认为 string，raw.port 已确认存在
  connectToServer(raw.url, raw.port as number)
}
```

注意这里的 **`asserts condition`** 和 **`asserts value is Type`** 语法——这也是 TypeScript 的类型谓词形式，专门用于"通过即继续，不通过则中断执行流"的场景。

## 类型守卫的组合使用

实际开发中，经常需要组合多个守卫来精确地收窄类型。

### 用逻辑运算符组合

```typescript
// 组合守卫：既是数字又是整数
function isInteger(value: unknown): value is number {
  return isValidNumber(value) && Number.isInteger(value)
}

// 组合守卫：非空数组
function isNonEmptyArray<T>(value: unknown): value is [T, ...T[]] {
  return isArray(value) && value.length > 0
}

// 组合守卫：有特定属性的对象
function hasProperty<K extends string>(
  obj: unknown,
  prop: K
): obj is Record<K, unknown> {
  return isPlainObject(obj) && prop in obj
}
```

### 守卫链模式

```typescript
// 先粗筛再细筛
function parseUserInput(input: unknown): User {
  // 第一层：必须是对象
  if (!isPlainObject(input)) {
    throw new Error('Input must be an object')
  }

  // 第二层：必须有基本字段
  if (!('name' in input) || !isNonEmptyString(input.name)) {
    throw new Error('name is required and must be a non-empty string')
  }

  // 第三层：可选字段的精细校验
  if ('age' in input && !isValidNumber(input.age)) {
    throw new Error('age must be a valid number')
  }

  if ('email' in input && !(input.email as string).includes('@')) {
    throw new Error('email must be a valid email address')
  }

  // 所有检查通过，安全转换
  return input as User
}
```

### 用 filter + 守卫过滤数组

这是一个非常实用的模式：

```typescript
const mixedArray: (string | number | null | undefined)[] = ['hello', 42, null, 'world', undefined, 100]

// ❌ filter 后类型仍然是 (string | number | null | undefined)[]
const filtered = mixedArray.filter(item => item != null)
// filtered 的类型还是 (string | number | null | undefined)[]

// ✅ 用守卫函数作为 filter 回调——类型正确收缩！
const definedItems = mixedArray.filter(isDefined)
// definedItems 的类型变成了 (string | number)[]

// 进一步细分
const stringsOnly = mixedArray.filter(isString)
// stringsOnly 的类型是 string[]

const numbersOnly = mixedArray.filter(isValidNumber)
// numbersOnly 的类型是 number[]
```

**为什么这样行得效？** TypeScript 对 `Array.prototype.filter()` 有特殊的类型推断——如果回调函数是一个类型谓词（返回 `value is T`），它会将结果数组的元素类型收窄为 `T`。

### 实际案例：API 响应数据的完整校验流程

```typescript
interface ApiResponse<T> {
  success: boolean
  data: T
  error?: { code: string; message: string }
}

interface UserProfile {
  id: number
  username: string
  displayName: string
  avatarUrl?: string
  followers: number
  createdAt: string  // ISO 格式日期
}

async function fetchProfile(userId: number): Promise<UserProfile> {
  const response = await fetch(`/api/users/${userId}`)
  const raw = await response.json()

  // 第一步：校验响应包装结构
  assert(
    isPlainObject(raw) && raw.success === true && isPlainObject(raw.data),
    'Invalid API response structure'
  )

  const data = raw.data as Record<string, unknown>

  // 第二步：校验每个必需字段
  assert(typeof data.id === 'number', 'Missing id')
  assert(isNonEmptyString(data.username), 'Missing username')
  assert(isNonEmptyString(data.displayName), 'Missing displayName')
  assert(typeof data.followers === 'number', 'Missing followers')
  assert(isNonEmptyString(data.createdAt), 'Missing createdAt')

  // 第三步：校验可选字段
  if ('avatarUrl' in data && data.avatarUrl !== null) {
    assert(isNonEmptyString(data.avatarUrl), 'avatarUrl must be a non-empty string')
  }

  // 第四步：业务规则校验
  assert(data.followers >= 0, 'followers cannot be negative')
  assert(!isNaN(Date.parse(data.createdAt as string)), 'createdAt must be a valid date')

  // 全部通过，安全返回
  return data as UserProfile
}
```

## 类型守卫 vs 类型断言 —— 运行时安全性的本质差异

这是本章最重要的对比总结：

| 维度 | 类型守卫 | 类型断言 (`as`) / 非空断言 (`!`) |
|------|---------|-------------------------------|
| **运行时检查** | ✅ 真正做了类型校验 | ❌ 只是编译时的"承诺" |
| **安全性** | 高——运行时不匹配会走 else 分支 | 低——运行时可能崩溃 |
| **编译器行为** | 自动类型收窄（控制流分析） | 强制类型覆盖 |
| **适用场景** | 外部数据、不可信输入 | DOM 操作、确定存在的值 |
| **性能开销** | 有少量运行时开销 | 零运行时开销 |
| **推荐程度** | 默认选择 | 谨慎使用 |

```typescript
// 来自 API 的外部数据 —— 必须用类型守卫
const userData = await fetch('/api/user').then(r => r.json())
if (isValidUserProfile(userData)) {
  userData.displayName  // ✅ 安全
}

// 来自 API 的数据 —— 用断言很危险
const userData = (await fetch('/api/user').then(r => r.json())) as UserProfile
userData.displayName  // ⚠️ 如果 API 变更了字段名，这里运行时报错

// DOM 元素获取 —— 合理使用断言
const btn = document.getElementById('submit-btn') as HTMLButtonElement
btn.click()  // ✅ 我们确实知道这个按钮存在于 HTML 模板中

// DOM 元素获取 —— 也可以用守卫（更安全）
const el = document.getElementById('submit-btn')
if (el instanceof HTMLButtonElement) {
  el.click()  // ✅ 同样安全，且对动态内容更有保障
}
```

**核心原则**：
> **数据来自外部（API、用户输入、localStorage 等）→ 用类型守卫**
> **数据来自内部可控源（模板、硬编码、刚经过校验的数据）→ 可以谨慎使用断言**

## 常见的类型守卫陷阱

### 陷阱 1：修改原始变量导致守卫失效

```typescript
let value: string | number = 'hello'

if (typeof value === 'string') {
  // value 是 string ✅
  
  value = 123  // 重新赋值！
  
  // 现在 value 又变回了 string | number
  // 因为赋值会重置控制流分析的类型信息
  value.toFixed(2)  // ❌ Error!
}
```

### 陷阱 2：闭包中的类型守卫

```typescript
function setupValidator(input: string | number): () => void {
  if (typeof input === 'string') {
    // 这里 input 是 string
    
    // 返回闭包函数
    return () => {
      // ⚠️ 这里 input 不一定是 string 了！
      // TypeScript 不会把闭包内的类型也收窄
      console.log(input.length)  // 可能报错！
    }
  }
  
  return () => {}
}
```

**解决方案**：在守卫内创建一个新的局部变量：

```typescript
function setupValidator(input: string | number): () => void {
  if (typeof input === 'string') {
    const strInput = input  // 新变量捕获当前收窄后的类型
    return () => {
      console.log(strInput.length)  // ✅ strInput 永远是 string
    }
  }
  
  return () => {}
}
```

### 陷阱 3：守卫函数参数名不一致

```typescript
// ⚠️ 参数名叫 x
function isString(x: unknown): x is string {
  return typeof x === 'string'
}

// 使用时传入 value
const value: unknown = 'test'

// ✅ 这样是可以的（TS 能正确关联）
if (isString(value)) {
  value.toUpperCase()  // 正常工作
}

// 但是——如果谓词中的参数名和调用处的变量名不一致，
// 代码阅读者可能会困惑
```

**最佳实践**：让守卫函数的参数名具有语义，并在调用处保持一致的命名风格。

### 陷阱 4：守卫函数有副作用

```typescript
// ⚠️ 不好的实践：守卫函数做了额外操作
function validateAndLog(user: unknown): user is User {
  console.log('Validating:', user)        // 副作用：日志
  metrics.increment('validation.count')   // 副作用：计数
  return isPlainObject(user) && 'id' in user
}

// 在 filter 中使用时，副作用会对每个元素执行
users.filter(validateAndLog)  // 每个元素都会打日志+计数！
```

**原则**：守卫函数应该是**纯函数**——无副作用，只做类型检查并返回 boolean。

### 陷阱 5：忘记穷尽检查

```typescript
type Status = 'loading' | 'success' | 'error'

function renderStatus(status: Status): string {
  switch (status) {
    case 'loading':
      return '加载中...'
    case 'success':
      return '加载成功'
    // 忘记了 case 'error'！
    default:
      // 如果不加 never 检查，TS 不会警告你
      return status  // 这里 status 还是 Status 类型
  }
}

// ✅ 加上穷尽检查
function renderStatus(status: Status): string {
  switch (status) {
    case 'loading': return '加载中...'
    case 'success': return '加载成功'
    case 'error': return '出错了:('
    default:
      const _exhaustive: never = status  // 如果新加了状态没处理这里会报错
      return _exhaustive
  }
}
```

## 个人总结

类型守卫是 TypeScript 类型系统中最精妙的设计之一，它是连接**动态运行时**和**静态类型**的关键桥梁。

回顾我们学到的四类内置类型守卫：
- **`typeof`**：适合基础类型判断（string/number/boolean...），注意 `null` 的坑
- **`instanceof`**：适合类/构造函数的继承关系判断，注意跨 window/iframe 的限制
- **`in`**：适合区分不同形状的对象类型，特别是没有可辨识联合字段的情况
- **自定义类型谓词 (`is`)**：万能方案，适合复杂的类型校验逻辑

再加上 **`asserts`** 形式的断言守卫——用于"不通过就炸"的严格场景。

**我建议的开发习惯**：

1. **优先用内置守卫**：`typeof`、`instanceof`、`in`、`Array.isArray()` 能解决的就不要自己写
2. **建立团队共享的守卫函数库**：`isDefined`、`isPlainObject`、`isArray` 这些应该成为项目的标准工具
3. **对外部数据永远不要信任**：API 响应、localStorage、URL params 都要通过守卫校验
4. **善用 `filter` + 守卫**：这是清理混合类型数组的最优雅方式
5. **用 `never` 做穷尽检查**：switch 语句加上 `default: const _exhaustive: never = x` 能帮你捕获遗漏的分支
6. **守卫函数要保持纯**：不做副作用，只做判断

最后，记住这句话：**类型断言是你对编译器说的"相信我"，而类型守卫是你向运行时证明"我没说错"。** 在安全性至关重要的地方，证明总是比口头承诺更可靠。
