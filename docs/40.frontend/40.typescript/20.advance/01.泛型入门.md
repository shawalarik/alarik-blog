## 什么是泛型？

在编程语言理论中，**泛型（Generics）** 是一种参数化类型（Parameterized Type）的机制。它允许我们在定义函数、接口或类时，不预先指定具体的类型，而是使用**类型参数（Type Parameter）**作为占位符。当实际使用时，再传入具体的类型来替换这些占位符。

### 从一个生活化的类比开始

想象你是一家工厂的设计师，你需要设计一种"通用包装箱"：

```typescript
// 不使用泛型 —— 你需要为每种商品设计不同的箱子
function packageString(item: string): string {
  return `包装: ${item}`
}

function packageNumber(item: number): number {
  return item // 数字不需要额外包装
}

function packageBoolean(item: boolean): boolean {
  return item
}

// 问题来了：每新增一种商品类型，就要写一个新的包装函数！
```

这就像你为苹果设计了一个箱子、为橘子设计了另一个箱子、为西瓜又设计了一个——虽然原理完全相同，但你不得不重复劳动。

**泛型的思维方式是**：设计一个"通用模板"，让调用者告诉你要装什么：

```typescript
// 使用泛型 —— 一个箱子装所有
function packageItem<T>(item: T): T {
  console.log(`已包装`)
  return item
}

// 调用时指定（或让 TypeScript 自动推断）类型
const boxedString = packageItem<string>('Hello')   // T = string
const boxedNumber = packageItem<number>(42)        // T = number
const boxedBool   = packageItem<boolean>(true)     // T = boolean

// 大多数情况下，TypeScript 能自动推断，无需手动写 <string>
const autoInferred = packageItem('TypeScript 推断我是 string')
```

### 为什么叫"泛型"？

"泛"意为广泛、普遍；"型"即类型。合起来就是**"适用于多种类型的类型"**。

从类型论的角度看，泛型是一种**类型级函数（Type-level Function）**：

```typescript
// 普通函数：值 → 值
function add(a: number, b: number): number { return a + b }

// 泛型：类型 → 类型
// Array<T> 就像一个"类型构造器"，输入 T，输出 Array<T>
type StringArray = Array<string>   // 输入 string → 输出 string[]
type NumberArray = Array<number>   // 输入 number → 输出 number[]
type BoolArray   = Array<boolean>  // 输入 boolean → 输出 boolean[]
```

这种**"用代码操作类型"的能力**正是 TypeScript 类型系统强大的根源所在。

## 深入理解类型参数（占位符 T）

> **这是本章最核心的概念。如果你只能从这篇文章中记住一件事，那应该是：`<T>` 就是一个等待被填充的类型占位符——它在定义时是"空的"，在使用时被"填满"。**

### 1.1 什么是"占位符"？—— 从生活中的例子说起

在日常生活中，"占位符"无处不在。理解了它，你就理解了泛型的本质。

#### 例子一：邀请函上的空白处

想象你在制作一份活动邀请函模板：

```
┌─────────────────────────────────────┐
│                                     │
│   亲爱的 _____ ：                     │  ← 这里的横线就是"占位符"
│                                     │
│   我们诚挚地邀请您参加 _____ 活动！     │  ← 又一个占位符
│   时间：_____                        │  ← 还是一个
│   地点：_____                        │
│                                     │
│                                 组织者 │
└─────────────────────────────────────┘
```

当你把这份模板给不同的人时，你填入不同的内容：

```
// 填充实例 A
亲爱的 张三：
我们诚挚地邀请你参加 年会 活动！

// 填充实例 B  
亲爱的 李四：
我们诚挚地邀请你参加 技术分享会 活动！
```

**模板本身不关心填进去的是什么**——它只规定了"这里有一个空位需要填写"。泛型中的 `<T>` 就是这个"空白横线"，而调用函数时传入的具体类型（如 `string`、`number`）就是在横线上填写的内容。

#### 例子二：快递运单

快递公司每天处理成千上万个包裹。每个包裹的**内容物完全不同**——衣服、电子产品、食品、文件……但**运单的格式是一样的**：

```typescript
// 运单模板 —— 内容物的位置就是一个"占位符"
interface ShippingLabel<T> {
  trackingNumber: string      // 固定字段
  sender: Address             // 固定字段
  recipient: Address          // 固定字段
  weight: number              // 固定字段
  contents: T                 // ← 占位符！内容物可以是任何东西
  declaredValue: number       // 固定字段
}

// 同一张运单模板，装不同的东西
const clothesShipment: ShippingLabel<{ item: string; size: 'S' | 'M' | 'L'; color: string }> = {
  trackingNumber: 'SF1234567890',
  sender: { name: '卖家', address: '广州' },
  recipient: { name: '买家', address: '北京' },
  weight: 0.5,
  contents: { item: 'T恤', size: 'L', color: '黑色' },  // T 被填充为衣服信息
  declaredValue: 99,
}

const electronicsShipment: ShippingLabel<{ model: string; serialNumber: string; warranty: boolean }> = {
  trackingNumber: 'SF9876543210',
  sender: { name: '苹果仓库', address: '深圳' },
  recipient: { name: '用户', address: '上海' },
  weight: 1.2,
  contents: { model: 'iPhone 17', serialNumber: 'X123ABC', warranty: true },  // T 被填充为电子产品信息
  declaredValue: 8999,
}
```

**关键洞察**：运单的结构不变（都有追踪号、收发件人、重量等），但 `contents` 字段的**类型随包裹内容而变**。这就是 `<T>` 的本质——一个在定义时留空、使用时才确定的类型槽位。

#### 例子三：函数参数 vs 类型参数

你已经熟悉了**值层面的参数化**。类型参数不过是同样的思想搬到了**类型层面**：

```typescript
// ========== 值层面的参数（你已经熟悉的）==========

// 不参数化 —— 只能处理固定的值
function greetAlice() {
  return 'Hello, Alice!'    // 写死了，只能打招呼给 Alice
}

// 参数化 —— 可以处理任意名字
function greet(name: string) {     // ← name 是值的占位符
  return `Hello, ${name}!`         // 使用时填入具体值
}

greet('Alice')   // → "Hello, Alice!"
greet('Bob')     // → "Hello, Bob!"
greet('Charlie') // → "Hello, Charlie!"

// ========== 类型层面的参数（泛型的新概念）==========

// 不参数化 —— 只能处理固定类型
function getStringLength(s: string): number {
  return s.length               // 只能处理字符串的长度
}

function getArrayLength(arr: any[]): number {
  return arr.length              // 用 any[] 失去了类型安全
}

// 参数化 —— 可以处理任意类型，且保持类型安全
function getLength<T>(item: T): number {  // ← T 是类型的占位符
  // 这里不能写 item.length，因为 T 可能没有 length
  // 但 T 本身作为"类型的变量"，可以被传递和使用
  return JSON.stringify(item).length
}

getLength<string>('hello')        // T = string，传入字符串
getLength<number>(42)             // T = number，传入数字
getLength<boolean>(true)          // T = boolean，传入布尔值
```

| 对比维度 | 函数参数（值层面） | 泛型参数（类型层面） |
|---------|------------------|---------------------|
| **声明语法** | `(name: string)` | `<T>` |
| **占位的对象** | 一个具体的**值** | 一个具体的**类型** |
| **填充时机** | 函数**调用时**填入值 | 函数**调用时**（或显式指定时）填入类型 |
| **作用域** | 在**函数体内部**使用该值 | 在整个**类型标注区域**使用该类型 |
| **类比** | "你好 \_\_\_\_" 中填入名字 | "\_\_\_ 类型的数组" 中填入类型名 |

#### 例子四：数学函数的抽象

在数学中，我们经常写出这样的公式：

$$f(x) = x^2 + 2x + 1$$

这里的 $x$ 是什么？它是一个**变量/占位符**——你可以代入任何数字：

- $f(3) = 9 + 6 + 1 = 16$
- $f(5) = 25 + 10 + 1 = 36$
- $f(-1) = 1 - 2 + 1 = 0$

泛型中的 `T` 就是**类型世界的 $x$**：

$$f(T) = \text{返回 } T \text{ 类型的值}$$

- $f(\text{string})$ → 返回 string 类型的值
- $f(\text{number})$ → 返回 number 类型的值
- $f(\text{User})$ → 返回 User 类型的值

### 1.2 占位符 T 的完整生命周期

让我们用一个完整的流程图来展示 `<T>` 从"出生"到"消亡"的全过程：

```
═══════════════════════════════════════════════════════════════
                    T 的生命周期
═══════════════════════════════════════════════════════════════

阶段 ①：【声明】—— 占位符诞生
───────────────────────────────────────────────────────────────

  function identity<T>(arg: T): T { ... }
                  ^^
                  │
                  └── 在这里，T 被声明为一个类型占位符。
                      此时 T 是"未绑定的"——就像一个空盒子，
                      还不知道里面要装什么。

  理解要点：
  • <T> 是声明区 —— 相当于说 "我需要一个叫 T 的类型变量"
  • 此时 T 没有具体值，它代表 "某种未知的类型"
  • T 的作用域从 <T> 开始，到函数签名结束


阶段 ②：【使用于签名中】—— 占位符被引用
───────────────────────────────────────────────────────────────

  function identity<T>(arg: T): T
                       ^^^^^^  ^^^
                       │       │
                       │       └── 返回值也标记为 T
                       │           表示 "返回和输入相同类型的东西"
                       │
                       └── 参数 arg 的类型标记为 T
                           表示 "arg 的类型由 T 决定"

  理解要点：
  • T 在函数签名的多个位置出现 → 它们都是同一个 T
  • 这建立了约束关系："输入是什么类型，输出就必须是什么类型"
  • 就像方程式 y = x，x 和 y 是关联的


阶段 ③：【绑定/推断】—— 占位符被填充
───────────────────────────────────────────────────────────────

  调用者写下：
  
  identity<string>("hello")
                ^^^^^^^^
                │
                └── 显式指定 T = string
                    此时 T 这个占位符被"填充"为 string

  或者更常见的情况 —— 编译器自动推断：

  identity("hello")
            ^^^^^^^
            │
            └── 传入的是字符串字面量
                TypeScript 推断：T = string

  理解要点：
  • 绑定时，T 从 "未知类型" 变为 "已知的具体类型"
  • 一旦绑定，所有出现 T 的地方都同步替换为该具体类型
  • 每次函数调用都会创建一次新的绑定（不同调用可以有不同的 T）


阶段 ④：【类型检查】—— 填充后的类型生效
───────────────────────────────────────────────────────────────

  当 T = string 时，函数签名等效于：

  function identity(arg: string): string { ... }

  TypeScript 会像检查普通函数一样进行类型检查：

  const result = identity("hello")
  // result 的类型是 string ✓

  const bad = identity(42)
  // 如果之前 T 被绑定为 string，这里就会报错
  // 但实际上每次调用重新绑定，所以这里 T = number ✓


阶段 ⑤：【编译后消失】—— 占位符完成任务
───────────────────────────────────────────────────────────────

  泛型只存在于 TypeScript 的编译期。
  编译成 JavaScript 后，所有 T 都会被擦除（Type Erasure）：

  // TypeScript 编译前
  function identity<T>(arg: T): T { return arg }

  // JavaScript 编译后（T 被完全擦除）
  function identity(arg) { return arg }

  理解要点：
  • 泛型是"零运行时开销"的 —— JS 引擎根本不知道 T 的存在
  • 所有的类型安全检查都在编译时完成
  • 这是 TypeScript 泛型和 Java/C# 泛型的重要区别之一

═══════════════════════════════════════════════════════════════
```

### 1.3 占位符的视觉模型

为了建立直觉，我们可以用几种不同的可视化方式来理解 `T`：

#### 模型一：插槽（Slot）

```
┌──────────────────────────────────────┐
│  函数: identity<T>(arg: T): T        │
│                                      │
│  ┌─────────┐    ┌──────┐  ┌──────┐  │
│  │ 参数 arg │───→│ 插槽T │  │ 插槽T │──→ 返回值
│  └─────────┘    └──┬───┘  └──┬───┘  │
│                    │         │      │
│              ┌─────┴─────────┴──┐   │
│              │   共享同一个 T    │   │
│              └──────────────────┘   │
└──────────────────────────────────────┘

调用 identity<string>("hello") 后：

┌──────────────────────────────────────┐
│  函数: identity(arg: string): string  │  ← 所有 T 替换为 string
│                                      │
│  ┌─────────┐    ┌──────┐  ┌──────┐  │
│  │ "hello"  │───→│string │  │string │──→ "hello"
│  └─────────┘    └──────┘  └──────┘  │
└──────────────────────────────────────┘
```

两个插槽被**同一块类型牌**填充，这就是为什么输入 `string` 就输出 `string`——它们共享同一个 `T`。

#### 模型二：管道（Pipe）

```
定义时（空的管道）：

  输入 [ ? ] ──→ 处理逻辑 ──→ 输出 [ ? ]
           ↑                     ↑
           └── 都是同一个未知类型 T ──┘


调用时 identity<number>(42) 后（管道通了）：

  输入 [ 42:number ] ──→ 直接返回 ──→ 输出 [ 42:number ]


调用时 identity<UserProfile>(userObj) 后：

  输入 [ userObj:UserProfile ] ──→ 直接返回 ──→ 输出 [ userObj:UserProfile ]
```

#### 模型三：透镜（Lens）

把泛型函数想象成一个**透明玻璃管**，T 就像是透过管子看到的颜色：

```
定义时：管子是透明的，不知道会通过什么颜色的光
         ═══════════
    光 → (  T   ) → 出来的光

调用 identity<string> 时：红光通过
         ═══════════
  🔴 红 → ( string ) → 🔴 红

调用 identity<number> 时：蓝光通过
         ═══════════
  🔵 蓝 → ( number ) → 🔵 蓝

核心性质：进出的颜色一定相同！（因为是同一个 T）
```

### 1.4 为什么不直接用 `any`？

这是初学者最常问的问题，也是理解占位符价值的关键。

```typescript
// 方案一：用 any —— 放弃类型安全
function identityAny(arg: any): any {
  return arg
}

const a1 = identityAny('hello')
const a2 = identityAny(42)
// a1 和 a2 的类型都是 any
// 你对 a1 或 a2 做任何操作都不会得到类型提示或检查
a1.push('???')    // ❌ 不会报错！但运行时会崩溃（string 没有 push）
a2.toFixed()       // ✅ 正确，但即使写成 a2.push() 也不会报错


// 方案二：用联合类型 —— 需要穷举所有可能
function identityUnion(arg: string | number | boolean | object): string | number | boolean | object {
  return arg
}
// 问题：每增加一种支持类型就要改代码
// 而且 return 类型也是联合类型，丢失了"输入输出一致"的信息


// 方案三：用泛型 T —— 保持类型安全的灵活性
function identity<T>(arg: T): T {
  return arg
}

const t1 = identity('hello')   // t1 的类型是 string ✓
const t2 = identity(42)        // t2 的类型是 number ✓
const t3 = identity({ x: 1 })  // t3 的类型是 { x: number } ✓

t1.toUpperCase()     // ✅ 有自动补全！string 的方法都可用
t2.toExponential(2)  // ✅ 有自动补全！number 的方法都可用
t3.x                // ✅ 能访问到属性 x

t1.push('!')        // ❌ 编译错误！string 没有 push 方法
t2.push(1)         // ❌ 编译错误！number 没有 push 方法
```

**对比总结：**

```
┌─────────────┬──────────────┬──────────────┬──────────────┐
│              │     any      │  联合类型     │    泛型 T     │
├─────────────┼──────────────┼──────────────┼──────────────┤
│ 类型安全     │ ❌ 完全无     │ ⚠️ 部分有     │ ✅ 完全有      │
│ 自动补全     │ ❌ 无         │ ⚠️ 仅公共部分  │ ✅ 精确匹配    │
│ 输入输出关系  │ ❌ 丢失       │ ❌ 丢失       │ ✅ 保持一致     │
│ 可扩展性     │ N/A          │ ❌ 需改代码   │ ✅ 天然支持    │
│ 运行时开销   │ 无            │ 无            │ 无（编译时擦除） │
│ 适用场景     │ 快速原型      │ 少量固定类型  │ 通用工具库     │
└─────────────┴──────────────┴──────────────┴──────────────┘
```

**一句话概括差异**：`any` 说的是"我不在乎类型是什么"，而 `<T>` 说的是"我在乎类型是什么，但现在先不确定，等你告诉我"。前者是**放弃**，后者是**推迟决定**（Deferred Commitment）。

### 1.5 占位符的"身份同一性"

这是一个微妙但极其重要的点：**同一次声明中的多个 `T` 是同一个占位符**。

```typescript
/**
 * 关键：函数签名中出现多次的 T，指的是同一个类型！
 * 
 * 这不是三个独立的 T，而是三个指向同一个"插槽"的引用
 */
function makeTuple<T>(first: T, second: T): [T, T] {
  return [first, second]
}

// ✓ 两个参数类型相同
makeTuple(1, 2)          // [number, number] —— T 同时绑定两个参数
makeTuple('a', 'b')      // [string, string]

// ✗ 编译错误！两个参数类型不同
makeTuple('hello', 42)
//   ^^^^^^^  ^^
//   string   number
// 
// 错误信息：Argument of type 'number' is not assignable to parameter of type 'string'
// 
// 原因：第一个参数将 T 绑定为 string，
//       第二个参数也必须是 string，但实际传入了 number
```

这和下面这种情况形成鲜明对比：

```typescript
/**
 * 两个独立的占位符 T 和 U
 * 它们可以绑定不同的类型
 */
function makePair<T, U>(first: T, second: U): [T, U] {
  return [first, second]
}

// ✓ T 和 U 各自独立绑定
makePair('hello', 42)    // T=string, U=number → [string, number]
makePair(true, [1, 2])   // T=boolean, U=number[] → [boolean, number[]]
makePair({ a: 1 }, null) // T={a:number}, U=null → [{a:number}, null]
```

**规则总结**：

```
同一个字母（如 T）在同一尖括号 <T> 中声明后，
在该作用域内所有出现的 T 都是同一个东西。

不同字母（T, U, V）或不同声明位置的同类字母，
彼此独立，可以绑定不同的类型。
```

### 1.6 占位符的作用域规则

理解 `T` 的作用域边界非常重要：

```typescript
// ═══════════════════════════════════════════
// 场景 1：函数级作用域 —— 最常见
// ═══════════════════════════════════════════

function foo<T>(x: T): T {
  // ✅ T 在此范围内有效
  const local: T = x       // 可以用于局部变量
  function inner(y: T): T { // 可以用于内部函数
    return y
  }
  return inner(x)
}

// ❌ T 在函数外部无效
// let outside: T  // Error: Cannot find name 'T'


// ═══════════════════════════════════════════
// 场景 2：接口级作用域
// ═══════════════════════════════════════════

interface Box<T> {
  value: T              // ✅ 有效
  getValue(): T         // ✅ 有效
  transform<U>(fn: (v: T) => U): Box<U>  // ✅ T 仍有效，U 是新的
}

// ❌ 接口外部的 T 与接口内部的 T 无关
let unrelated: T        // Error


// ═══════════════════════════════════════════
// 场景 3：类级作用域
// ═══════════════════════════════════════════

class Container<T> {
  private data: T       // ✅ 实例成员可以使用 T
  
  constructor(initial: T) {
    this.data = initial
  }
  
  get(): T {            // ✅ 实例方法可以使用 T
    return this.data
  }
  
  set(value: T): void {  // ✅
    this.data = value
  }
  
  // ❌ 静态成员不能使用 T！
  // static default: T   // Error!
  // static create(): Container<T>  // Error!
}


// ═══════════════════════════════════════════
// 场景 4：类型别名级作用域
// ═══════════════════════════════════════════

type Result<T> =
  | { success: true; data: T }       // ✅ T 有效
  | { success: false; error: Error } // ✅ T 未在此分支中使用（合法）

// Result 内部到处都可以引用 T


// ═══════════════════════════════════════════
// 场景 5：嵌套作用域 —— 内层 T 会遮蔽（shadow）外层 T
// ═══════════════════════════════════════════

function outer<T>(x: T): T {
  // 这里的 T 是外层的 T
  
  function inner<T>(y: T): T {
    // ⚠️ 注意！这里的 T 是内层的 T，和外层的 T 无关！
    // 这是一个全新的类型参数，只是恰好也叫 T
    return y
  }
  
  inner(x)  // 可能报错！因为 inner 的 T 是全新的，不一定与 outer 的 T 兼容
  return x
}

// 最佳实践：避免同名遮蔽，使用不同的名称
function outerBetter<T>(x: T): T {
  function inner<U>(y: U): U {  // 用 U 避免与 T 冲突
    return y
  }
  inner(x)  // OK
  return x
}
```

### 1.7 占位符的"自由度"谱系

不是所有的占位符都是完全自由的。根据约束条件的不同，`T` 的自由程度也不同：

```
完全自由 ──────────────────────────────────── 完全受限
  │                                            │
  │  <T>          T extends SomeInterface     │
  │  可以是任何类型   必须满足特定形状           │
  │                                            │
  │  例如：          例如：                     │
  │  function id<T>  function len<T extends    │
  │   (x: T): T      {length: number}          │
  │   (x): x        (x: T): number             │
  │                                            │
  │  T = string ✓    T = string  ✓ (有 length) │
  │  T = number ✓    T = number  ✗ (无 length)  │
  │  T = Object ✓    T = [1,2,3]  ✓ (有 length)│
  │  T = anything ✓  T = true    ✗ (无 length)  │
```

**类比理解**：

- **无约束的 `<T>`** = 一张空白支票（金额不限）
- **`<T extends HasLength>`** = 一张有最低余额要求的支票
- **`<T extends string \| number>`** = 只能在两家银行兑现的支票

随着约束的增加，T 能代表的类型范围缩小，但在函数体内能做的操作却增加了（因为你能确定它具有某些属性）。这是一种**安全性与灵活性的权衡**。

### 1.8 多个占位符如何协作

当有多个类型参数时，它们之间的协作方式决定了函数的行为模式：

```typescript
// ═══════════════════════════════════════
// 模式 1：独立型 —— T 和 U 互不影响
// ═══════════════════════════════════════

function pair<T, U>(first: T, second: U): [T, U] {
  return [first, second]
}
// T 和 U 各自独立，想填什么就填什么
pair(1, 'one')        // [number, string]
pair('a', true)       // [string, boolean]


// ═══════════════════════════════════════
// 模式 2：依赖型 —— U 依赖于 T
// ═══════════════════════════════════════

// U 必须是 T 的数组
function wrapWithArray<T, U extends T[]>(value: T, arr: U): [T, U] {
  return [value, arr]
}

wrapWithArray(1, [1, 2, 3])           // ✓ T=number, U=number[]
wrapWithArray('a', ['a', 'b'])         // ✓ T=string, U=string[]
// wrapWithArray(1, ['a', 'b'])         // ✗ string[] 不能赋值给 number[]


// ═══════════════════════════════════════
// 模式 3：转换型 —— 输入 T，输出 U
// ═══════════════════════════════════════

function map<T, U>(arr: T[], fn: (item: T) => U): U[] {
  return arr.map(fn)
}

map([1, 2, 3], n => n.toString())   // T=number, U=string → ["1","2","3"]
map(['a','b'], s => s.length)      // T=string, U=number → [1,1]


// ═══════════════════════════════════════
// 模式 4：键值对应型 —— K 是 T 的键
// ═══════════════════════════════════════

function pluck<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key]
}

const user = { name: 'Alice', age: 30, active: true }
pluck(user, 'name')   // T=User, K='name' → string
pluck(user, 'age')    // T=User, K='age'  → number
pluck(user, 'active') // T=User, K='active' → boolean
```

### 1.9 占位符的实际效果：以 Array 为例

你可能每天都在用泛型而不自知。JavaScript 的内置 `Array` 就是一个泛型类：

```typescript
// Array 的简化声明（TypeScript 内置）
interface Array<T> {
  length: number
  pop(): T | undefined              // 弹出一个元素，类型是 T
  push(...items: T[]): number        // 推入元素，必须是 T 类型
  concat(...items: Array<T>[]): T[]  // 连接数组，保持 T 一致
  map<U>(callback: (item: T) => U): Array<U>  // 映射，可转换为新类型
  filter(callback: (item: T) => unknown): T[]  // 过滤，保持 T
  [index: number]: T               // 索引访问，返回 T
  // ... 更多方法
}
```

看看 `<T>` 如何影响你的日常编码体验：

```typescript
// 当你写 const numbers = [1, 2, 3] 时
// TypeScript 推断 numbers 的类型为 number[]
// 也就是 Array<number> —— T 被绑定为 number

const numbers = [1, 2, 3]       // Array<number>

numbers.push(4)                 // ✓ 4 是 number
numbers.push('five')            // ✗ 'five' 不是 number
const first = numbers[0]        // first 是 number（不是 any！）
const popped = numbers.pop()    // popped 是 number | undefined

// map 操作产生新类型
const doubled = numbers.map(n => n * 2)  // number[]
const strs = numbers.map(n => `#${n}`)   // string[] （T 从 number 变成了 string）


// 再看字符串数组
const names = ['Alice', 'Bob']   // Array<string> —— T 被绑定为 string

names.push('Charlie')            // ✓
names.push(42)                   // ✗ 42 不是 string
const upper = names.map(n => n.toUpperCase())  // string[]

// pop 返回 string | undefined
const removed = names.pop()
removed?.toLowerCase()           // ✅ TypeScript 知道它是 string（如果非 undefined）
```

**如果没有泛型 T**，`Array` 的方法签名大概是这样的：

```typescript
// 假想的、没有泛型的 Array
interface BadArray {
  pop(): any                    // 不知道弹出的是什么
  push(...items: any[]): number  // 什么都让进
  map(callback: (item: any) => any): any[]  // 丢失一切类型信息
  [index: number]: any           // 取出来就是个 any
}

const arr: BadArray = [1, 2, 3]
const x = arr[0]       // any —— 无法知道它是 number
arr.push('oops')       // 不会报错！混入了字符串
arr.map(item => item.toFixed(2))  // 不会报错！但 'oops'.toFixed() 运行时崩溃
```

这就是 `<T>` 存在的意义：**它让 `Array<string>` 的 `pop()` 返回 `string`，让 `Array<number>` 的 `pop()` 返回 `number`**。同一个 `Array` 定义，通过不同的 `T` 绑定，产生无数种类型安全的数据结构。

### 1.10 占位符的思维模型总结

经过以上全方位的分析，你可以用以下心智模型来理解 `<T>`：

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│    T = Type Variable（类型变量）= 类型层面的占位符            │
│                                                             │
│    核心特征：                                                │
│    ┌─────────────────────────────────────────────────────┐  │
│    │  ① 定义时空着：声明时不绑定任何具体类型               │  │
│    │  ② 使用时填充：调用时（或显式指定时）绑定具体类型     │  │
│    │  ③ 全局统一：同一作用域内的同名 T 指向同一个类型      │  │
│    │  ④ 编译期存在：运行时完全擦除，零性能开销             │  │
│    │  ⑤ 可受约束：通过 extends 限制 T 的可选范围           │  │
│    └─────────────────────────────────────────────────────┘  │
│                                                             │
│    记忆口诀：                                                │
│    "T 就是类型界的 x —— 一个待求解的未知数，                 │
│     方程写好时不关心 x 是多少，                              │
│     代入具体值后就能算出结果。"                              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 泛型函数（Generic Functions）

泛型函数是最常见的泛型形式。它在函数声明时引入类型参数，使函数能够处理不同类型的输入，同时保持类型安全。

### 基本语法

```typescript
/**
 * 泛型函数的语法结构：
 * 
 * function 函数名<类型参数列表>(参数列表): 返回值类型 { ... }
 *                    ^^^^^^^^^^^^^^^^
 *                    这里的 <T> 就是类型参数声明
 */

// 最经典的例子：恒等函数（Identity Function）
function identity<T>(arg: T): T {
  return arg
}
```

关键语法点：

| 语法元素 | 含义 | 示例 |
|---------|------|------|
| `<T>` | 声明类型参数 | `function fn<T>()` |
| `T` | 类型参数名（可以是任意合法标识符） | `T`, `U`, `K`, `V` |
| `T` 在参数中的使用 | 用类型参数标注参数/返回值的类型 | `(arg: T): T` |

### 类型参数命名约定

TypeScript 社区有一套广为接受的命名约定：

```typescript
// 单个类型参数 —— 通常使用 T（代表 Type）
function first<T>(arr: T[]): T | undefined {
  return arr[0]
}

// 两个类型参数 —— T 和 U
function pair<T, U>(first: T, second: U): [T, U] {
  return [first, second]
}

// 键值对场景 —— K（Key）和 V（Value）
function mapEntry<K extends string, V>(key: K, value: V): Record<K, V> {
  return { [key]: value } as Record<K, V>
}

// 元素类型 —— E（Element）
function createElement<E>(tag: string, props: Record<string, unknown>, children?: E[]): E {
  // 概念示例
  return document.createElement(tag) as unknown as E
}

// 更具描述性的名称 —— 当语义明确时优先使用
function fetchData<ResponseDataType>(url: string): Promise<ResponseDataType> {
  return fetch(url).then(res => res.json())
}
```

**核心原则**：单字母名称（T/U/K/V）用于简短、局部的作用域；多字母描述性名称用于跨多处使用的公共 API。

### 类型推断机制

TypeScript 的泛型推断是其最实用的特性之一——大多数时候你无需手动指定类型参数：

```typescript
/**
 * TypeScript 如何进行泛型推断：
 * 
 * 编译器会分析函数调用的实际参数，
 * 从参数的类型反推类型参数 T 的具体值。
 */

function wrap<T>(value: T): { value: T; timestamp: Date } {
  return { value, timestamp: new Date() }
}

// ===== 自动推断 =====

// 传入字符串字面量 → T 推断为 "hello"（字面量类型）
const result1 = wrap('hello')
// result1 的类型：{ value: "hello"; timestamp: Date }

// 传入变量 → T 推断为变量的宽类型
const myName = 'Alarik'  // 类型是 string（非字面量）
const result2 = wrap(myName)
// result2 的类型：{ value: string; timestamp: Date }

// 传入数字 → T 推断为 number
const result3 = wrap(42)
// result3 的类型：{ value: number; timestamp: Date }

// 传入对象 → T 推断为对象的结构化类型
const result4 = wrap({ name: 'Alice', age: 30 })
// result4 的类型：{ value: { name: string; age: number }; timestamp: Date }

// ===== 手动指定（覆盖推断） =====

// 有时需要更精确的控制
const result5 = wrap<string>('hello')
// 此时 T 固定为 string（而非 "hello" 字面量）

// 典型场景：空数组或空对象
const emptyArr = wrap([])           // T 推断为 never[]（可能不是你想要的）
const betterEmptyArr = wrap<string[]>([])  // 明确指定
```

### 多个类型参数

当函数涉及多种独立变化的类型时，可以声明多个类型参数：

```typescript
/**
 * 两元组的创建 —— 展示多个类型参数
 */
function makePair<T, U>(first: T, second: U): [T, U] {
  return [first, second]
}

// 使用示例
const pair1 = makePair(1, 'one')        // [number, string]
const pair2 = makePair('key', { val: 42 })  // [string, { val: number }]
const pair3 = makePair([1, 2, 3], { x: 1, y: 2 })  // [number[], { x: number; y: number }]

/**
 * 三元组 —— 类型参数数量与数据结构的维度对应
 */
function triple<T, U, V>(a: T, b: U, c: V): [T, U, V] {
  return [a, b, c]
}

const coords = triple('origin', 0, 0)  // [string, number, number]

/**
 * Map 工厂函数 —— 展示 K 和 V 约定
 */
function createMap<K extends string | number, V>(
  entries: Array<[K, V]>
): Map<K, V> {
  return new Map(entries)
}

const userMap = createMap([
  ['u1', { name: 'Alice', role: 'admin' }],
  ['u2', { name: 'Bob', role: 'user' }],
])
// Map<string, { name: string; role: string }>
```

### 泛型函数的实际应用场景

#### 场景一：API 响应处理

```typescript
/**
 * 通用的 fetch 封装 —— 泛型让响应数据有精确的类型
 * 
 * 这可能是前端开发中最常用的泛型模式之一
 */
async function apiRequest<T>(
  url: string,
  options?: RequestInit
): Promise<{
  data: T
  status: number
  ok: boolean
  headers: Headers
}> {
  const response = await fetch(url, {
    headers: { 'Content-Type': 'application/json', ...options?.headers },
    ...options,
  })

  const data = await response.json() as T

  return { data, status: response.status, ok: response.ok, headers: response.headers }
}

// 使用时指定期望的响应类型
interface UserProfile {
  id: string
  name: string
  email: string
  avatarUrl: string
}

interface Article {
  id: string
  title: string
  content: string
  authorId: string
  createdAt: string
}

// 同一个 apiRequest 函数处理不同的 API
async function loadUser(id: string) {
  const result = await apiRequest<UserProfile>(`/api/users/${id}`)
  // result.data 的类型是 UserProfile —— 完全类型安全的访问
  console.log(result.data.name)      // string ✓
  console.log(result.data.avatarUrl) // string ✓
  // console.log(result.data.nonExistent) // 编译错误！属性不存在
}

async function loadArticles() {
  const result = await apiRequest<Article[]>('/api/articles')
  // result.data 的类型是 Article[]
  result.data.forEach(article => {
    console.log(`${article.title} by ${article.authorId}`)
  })
}
```

#### 场景二：数组工具函数

```typescript
/**
 * 获取数组的第一个元素
 * 
 * 与内置的 arr[0] 不同的是：
 * - 返回 undefined 而非可能抛异常
 * - 保持元素的原始类型（而非 any）
 */
function head<T>(arr: T[]): T | undefined {
  return arr[0]
}

head([1, 2, 3])              // number | undefined
head(['a', 'b', 'c'])         // string | undefined
head([{ id: 1 }, { id: 2 }])  // { id: number } | undefined

/**
 * 获取数组的最后一个元素
 */
function last<T>(arr: T[]): T | undefined {
  return arr[arr.length - 1]
}

/**
 * 安全地获取数组中指定索引的元素
 * 超出范围返回 undefined 而非 undefined（避免运行时报错）
 */
function at<T>(arr: T[], index: number): T | undefined {
  if (index >= 0) return arr[index]
  // 支持负索引（类似 Python / JS 的 at 方法）
  return arr[arr.length + index]
}

/**
 * 数组去重 —— 基于 Set 的实现
 * 注意：这里要求 T 可以用作 Map/Set 的键（基本类型或对象引用）
 */
function unique<T>(arr: T[]): T[] {
  return [...new Set(arr)]
}

unique([1, 2, 2, 3, 3, 3, 4])           // [1, 2, 3, 4]
unique(['a', 'b', 'a', 'c'])             // ['a', 'b', 'c']
unique([{ id: 1 }, { id: 1 }, { id: 2 }]) // 对象按引用去重，两个 { id: 1 } 视为不同
```

#### 场景三：事件系统

```typescript
/**
 * 类型安全的事件发射器
 * 
 * 泞型参数 Map 表示事件名称到事件数据的映射
 * 这样每个事件的回调函数都能获得正确的参数类型
 */
class EventEmitter<EventMap extends Record<string, unknown>> {
  private listeners = new Map<keyof EventMap, Set<Function>>()

  on<E extends keyof EventMap>(
    event: E,
    callback: (data: EventMap[E]) => void
  ): () => void {
    if (!this.listeners.has(event)) {
      this.listeners.set(event, new Set())
    }
    this.listeners.get(event)!.add(callback)

    // 返回取消订阅函数
    return () => this.off(event, callback)
  }

  off<E extends keyof EventMap>(event: E, callback: Function): void {
    this.listeners.get(event)?.delete(callback)
  }

  emit<E extends keyof EventMap>(event: E, data: EventMap[E]): void {
    this.listeners.get(event)?.forEach(cb => cb(data))
  }
}

// 定义事件映射
interface AppEvents {
  'user:login': { userId: string; loginTime: Date }
  'user:logout': { userId: string; sessionDuration: number }
  'notification:show': { message: string; type: 'info' | 'warning' | 'error' }
  'route:change': { from: string; to: string }
}

// 创建实例
const emitter = new EventEmitter<AppEvents>()

// 订阅事件 —— 回调参数自动获得正确的类型！
emitter.on('user:login', (data) => {
  // data 的类型自动推导为 { userId: string; loginTime: Date }
  console.log(`User ${data.userId} logged in at ${data.loginTime.toLocaleTimeString()}`)
})

emitter.on('notification:show', (data) => {
  // data 的类型是 { message: string; type: 'info' | 'warning' | 'error' }
  if (data.type === 'error') {
    alert(`错误: ${data.message}`)
  }
})

// 触发事件 —— 参数类型受约束
emitter.emit('user:login', { userId: 'u123', loginTime: new Date() })
emitter.emit('notification:show', { message: '操作成功', type: 'info' })

// 类型错误！payload 结构不匹配
// emitter.emit('user:login', { userId: 'u123' })  // 缺少 loginTime
// emitter.emit('unknown:event', {})                // 事件名不存在于 AppEvents
```

#### 场景四：函数组合与管道

```typescript
/**
 * 函数管道 —— 将多个函数串联执行
 * 前一个函数的输出作为后一个函数的输入
 */
function pipe<A, B>(fn: (a: A) => B): (a: A) => B
function pipe<A, B, C>(fn1: (a: A) => B, fn2: (b: B) => C): (a: A) => C
function pipe<A, B, C, D>(
  fn1: (a: A) => B,
  fn2: (b: B) => C,
  fn3: (c: C) => D
): (a: A) => D
function pipe<A, B, C, D, E>(
  fn1: (a: A) => B,
  fn2: (b: B) => C,
  fn3: (c: C) => D,
  fn4: (d: D) => E
): (a: A) => E
function pipe(...fns: Array<(x: unknown) => unknown>): (x: unknown) => unknown {
  return (x) => fns.reduce((acc, fn) => fn(acc), x)
}

// 使用示例
const processUser = pipe(
  // 步骤 1：将 JSON 字符串解析为对象
  (raw: string) => JSON.parse(raw) as { name: string; age: string },
  
  // 步骤 2：转换字段类型
  (obj: { name: string; age: string }) => ({
    name: obj.name.trim(),
    age: parseInt(obj.age, 10),
  }),
  
  // 步骤 3：验证并格式化
  (user: { name: string; age: number }) => ({
    displayName: `${user.name} (${age}岁)`,
    isAdult: user.age >= 18,
  })
)

// 整体类型：(raw: string) => { displayName: string; isAdult: boolean }
const result = processUser('{"name": "  Alice  ", "age": "25"}')
// result.displayName === "Alice (25岁)"
// result.isAdult === true
```

## 泛型接口（Generic Interfaces）

泛型接口让你定义"类型的蓝图"——接口本身不绑定到特定类型，而是由使用者决定。

### 基本语法

```typescript
/**
 * 泛型接口的语法结构：
 * 
 * interface 接口名<类型参数列表> { ... }
 *                  ^^^^^^^^^^^^^^^^
 */

// 通用容器接口
interface Container<T> {
  value: T
  getValue(): T
  setValue(newValue: T): void
}

// 实现时指定具体类型
class StringContainer implements Container<string> {
  value: string = ''
  
  getValue(): string {
    return this.value
  }
  
  setValue(newValue: string): void {
    this.value = newValue.toUpperCase()
  }
}

class NumberContainer implements Container<number> {
```

### 泛型接口 vs 泛型类型别名

两者功能高度重叠，但有微妙的差异：

```typescript
// 方式一：泛型接口
interface BoxInterface<T> {
  contents: T
  open(): T
}

// 方式二：泛型类型别名
type BoxTypeAlias<T> = {
  contents: T
  open(): T
}

// 功能上几乎等价
const iface: BoxInterface<string> = { contents: 'hello', open: function() { return this.contents } }
const alias: BoxTypeAlias<number> = { contents: 42, open: function() { return this.contents } }

/**
 * 关键差异：
 * 
 * 1. 接口可以被 extend（继承/扩展），类型别名不能
 * 2. 接口支持 declaration merging（声明合并），类型别名不支持
 * 3. 类型别名可以表示联合类型、条件类型等复杂类型，接口不行
 */

// 差异 1：extends
interface LabeledBox<T> extends BoxInterface<T> {
  label: string
}

// 差异 2：declaration merging
interface Window {
  myCustomProperty: string
}

// 差异 3：复杂类型只能用 type
type Maybe<T> = T | undefined
type AsyncResult<T> = Promise<{ success: true; data: T } | { success: false; error: Error }>
```

## 泛型约束（Generic Constraints）

泛型的力量在于灵活性，但**过度的灵活性会导致类型信息的丢失**。泛型约束就是解决这个问题的工具——它在不牺牲太多灵活性的前提下，给类型参数加上必要的限制。

### 问题场景：为什么需要约束？

```typescript
/**
 * 问题演示：无约束的泛型无法访问特定属性
 */

// 我们想获取任意值的长度
function getLength<T>(arg: T): number {
  // ❌ 编译错误！
  // Property 'length' does not exist on type 'T'.
  return arg.length
}
```

编译器报错的原因很直观：**T 可以是任何类型**——包括 `number`、`boolean`、没有 `length` 属性的自定义对象。如果允许 `arg.length`，那么调用 `getLength(42)` 时就会在运行时出错。

TypeScript 的哲学是：**宁可编译期报错，也不要运行时崩溃**。

### extends 约束

使用 `extends` 关键字限定类型参数的范围：

```typescript
/**
 * 泛型约束的基本语法：
 * 
 * T extends ConstraintType
 * 
 * 意思是："T 必须是 ConstraintType 或其子类型"
 */

// 定义约束接口
interface HasLength {
  length: number
}

// 加上约束后，T 保证具有 length 属性
function getLength<T extends HasLength>(arg: T): number {
  return arg.length  // ✅ 安全！T 一定有 length
}

// 正确的使用
getLength('hello world')          // string 有 .length → 11
getLength([1, 2, 3, 4, 5])       // array 有 .length → 5
getLength({ length: 100, name: 'box' })  // 对象有 .length → 100

// 错误的使用
// getLength(42)       // number 没有 .length → 编译错误
// getLength(true)     // boolean 没有 .length → 编译错误
// getLength({})       // 空对象没有 .length → 编译错误
```

### 约束的本质：子类型关系

理解 `extends` 在泛型中的含义至关重要。它和类继承中的 `extends` 本质上是同一个概念——**子类型关系（Subtyping Relation）**：

```typescript
/**
 * extends 在泛型中表示子类型关系
 * 
 * T extends SomeType 意味着：
 * T 是 SomeType 的子类型（subtype）
 * 
 * 子类型满足：
 * - T 至少包含 SomeType 要求的所有成员
 * - T 可以有额外的成员（结构化子类型）
 */

// 基础约束
interface Named {
  name: string
}

// Person 是 Named 的子类型（有 name，还有额外的 age）
interface Person extends Named {
  age: number
}

// Product 也是 Named 的子类型
interface Product extends Named {
  price: number
  category: string
}

// 泛型函数接受任何 Named 的子类型
function greet<T extends Named>(entity: T): string {
  return `你好，${entity.name}！`
}

greet({ name: 'Alice', age: 30 })             // Person ✓
greet({ name: 'iPhone', price: 9999, category: '电子产品' }) // Product ✓
greet({ name: 'Simple' })                      // 纯 Named 对象 ✓
```

### keyof 约束

这是最常用也最实用的泛型约束之一——限制类型参数必须是某个对象的键：

```typescript
/**
 * keyof 约束 —— 确保只传入对象已有的键名
 */

function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key]
}

const user = {
  id: 'u001',
  name: '张三',
  age: 28,
  email: 'zhangsan@example.com',
  isActive: true,
}

// 正确 —— key 是 user 的真实属性名
getProperty(user, 'name')    // 返回 string 类型
getProperty(user, 'age')     // 返回 number 类型
getProperty(user, 'email')   // 返回 string 类型
getProperty(user, 'isActive') // 返回 boolean 类型

// 错误 —— 'phoneNumber' 不是 user 的键
// getProperty(user, ' phoneNumber')  // Argument of type '"phoneNumber"' is not assignable to parameter of type '"id" | "name" | "age" | "email" | "isActive"'
```

注意返回值 `T[K]` 的神奇之处——**它根据 key 的不同返回不同类型的值**。这就是**索引访问类型（Indexed Access Type）**，我们将在后续章节深入探讨。

### 多重约束

有时需要同时满足多个条件：

```typescript
/**
 * 多重约束：同时满足多个接口的要求
 */

interface CanIdentify {
  id: string | number
}

interface CanTimestamp {
  createdAt: Date
  updatedAt: Date
}

interface CanSerialize {
  toJSON(): string
  fromJSON(json: string): void
}

// T 必须同时满足三个接口的要求
function processEntity<T extends CanIdentify & CanTimestamp & CanSerialize>(
  entity: T
): { id: T['id']; age: number; serialized: string } {
  const now = new Date()
  const ageMs = now.getTime() - entity.createdAt.getTime()
  const ageDays = Math.floor(ageMs / (1000 * 60 * 60 * 24))

  return {
    id: entity.id,
    age: ageDays,
    serialized: entity.toJSON(),
  }
}

// 满足所有约束的实现
class Document implements CanIdentify, CanTimestamp, CanSerialize {
  constructor(public id: string, public createdAt: Date = new Date(), public updatedAt: Date = new Date()) {}

  toJSON(): string {
    return JSON.stringify({ id: this.id, createdAt: this.createdAt, updatedAt: this.updatedAt })
  }

  fromJSON(json: string): void {
    const parsed = JSON.parse(json)
    Object.assign(this, parsed)
  }
}

const doc = new Document('doc001', new Date('2026-01-01'))
processEntity(doc)  // ✓ 通过所有约束检查
```

### 约束中的条件逻辑

泛型约束还可以结合**条件类型（Conditional Types）**实现更精细的控制：

```typescript
/**
 * 根据类型的不同行为不同的函数
 */

// 如果 T 是数组，返回元素类型；否则返回 T 本身
type Flatten<T> = T extends Array<infer U> ? U : T

function flatten<T>(value: Flatten<T>): Flatten<T> {
  return value
}

// 数组被"展平"为元素类型
flatten([1, 2, 3])        // 参数类型是 number，返回 number
flatten(['a', 'b'])        // 参数类型是 string，返回 string

// 非数组保持原样
flatten(42)                // 参数类型是 number，返回 number
flatten('hello')           // 参数类型是 string，返回 string

/**
 * 更实际的例子：确保函数参数要么有默认值，要么必须提供
 */
type WithDefault<T, D> = [T] extends [undefined | null] ? D : T

function withDefault<T, D>(value: T, defaultValue: D): WithDefault<T, D> {
  return (value ?? defaultValue) as WithDefault<T, D>
}

withDefault(undefined, 'N/A')   // 返回 'N/A'（使用了默认值）
withDefault(null, 'N/A')        // 返回 'N/A'（使用了默认值）
withDefault('hello', 'N/A')     // 返回 'hello'（有实际值）
withDefault(0, 100)             // 返回 0（0 不是 undefined/null，不算"无值"）
```

### 实战案例：深度合并工具

```typescript
/**
 * 类型安全的深度合并（Deep Merge）
 * 
 * 利用泛型约束确保两个对象的键结构兼容
 */

// 递归地展平嵌套对象类型
type DeepPartial<T> = {
  [P in keyof T]?: T[P] extends object ? DeepPartial<T[P]> : T[P]
}

// 合并两个对象的结果类型
type DeepMerge<T, U> = {
  // 对于 T 和 U 都有的键，递归合并
  [K in keyof T & keyof U]: T[K] extends object && U[K] extends object
    ? DeepMerge<T[K], U[K]>
    : U[K]
} & Omit<U, keyof T> & Omit<T, keyof U>

/**
 * 深度合并函数
 * 当遇到同名对象属性时递归合并，否则后者覆盖前者
 */
function deepMerge<
  T extends Record<string, unknown>,
  U extends Record<string, unknown>
>(target: T, source: U): DeepMerge<T, U> {
  const result = { ...target } as any

  for (const key in source) {
    const sourceValue = source[key]
    const targetValue = target[key]

    if (
      typeof sourceValue === 'object' &&
      sourceValue !== null &&
      !Array.isArray(sourceValue) &&
      typeof targetValue === 'object' &&
      targetValue !== null &&
      !Array.isArray(targetValue)
    ) {
      // 都是普通对象 → 递归合并
      result[key] = deepMerge(
        targetValue as Record<string, unknown>,
        sourceValue as Record<string, unknown>
      )
    } else {
      // 否则直接覆盖
      result[key] = sourceValue
    }
  }

  return result
}

// ===== 使用示例 =====

const defaults = {

    retries: 3,
  },
  features: {
    darkMode: false,
    notifications: true,
    analytics: true,
  },
}

  theme: {
    colors: {
      primary: '#ff6b35',       // 覆盖主色

    fontSize: 16,                // 覆盖字体大小

    darkMode: true,              // 覆盖暗黑模式

}

/*
```

### 实战案例：类型安全的 EventBus

```typescript
/**
 * 类型安全的全局事件总线
 * 结合泛型约束 + 映射类型 + 函数重载
 */

// 事件处理器类型
type EventHandler<T = unknown> = (data: T) => void | Promise<void>

// 事件映射 —— 定义所有支持的事件及其数据类型
interface EventDefinitions {
  // 用户相关
  'auth:login': { userId: string; sessionId: string; loginMethod: 'password' | 'oauth' | 'sso' }
  'auth:logout': { userId: string; reason: 'manual' | 'timeout' | 'forced' }
  'auth:session-expired': { userId: string; redirectUrl: string }

  // 数据相关
  'data:fetched': { resource: string; data: unknown; cached: boolean }
  'data:error': { resource: string; error: Error; retryable: boolean }

  // UI 相关
  'ui:modal-open': { modalId: string; props: Record<string, unknown> }
  'ui:modal-close': { modalId: string; result?: unknown }
  'ui:notification': { message: string; variant: 'success' | 'info' | 'warning' | 'error'; duration?: number }

  // 导航相关
  'router:navigate': { path: string; query?: Record<string, string>; replace?: boolean }
  'router:back': {}
}

// EventBus 类
class TypedEventBus<Events extends Record<string, unknown>> {
  private listeners = new Map<keyof Events, Set<EventHandler>>()
  private onceListeners = new Map<keyof Events, Set<EventHandler>>()

  /**
   * 订阅事件
   */
  on<E extends keyof Events>(event: E, handler: EventHandler<Events[E]>): () => void {
    if (!this.listeners.has(event)) {
      this.listeners.set(event, new Set())
    }
    this.listeners.get(event)!.add(handler)

    // 返回取消订阅的函数
    return () => this.off(event, handler)
  }

  /**
   * 一次性订阅
   */
  once<E extends keyof Events>(event: E, handler: EventHandler<Events[E]>): () => void {
    if (!this.onceListeners.has(event)) {
      this.onceListeners.set(event, new Set())
    }
    
    const wrapper: EventHandler<Events[E]> = (data) => {
      handler(data)
      this.off(event, wrapper)
    }
    
    this.onceListeners.get(event)!.add(wrapper)
    return () => this.off(event, wrapper)
  }

  /**
   * 取消订阅
   */
  off<E extends keyof Events>(event: E, handler: EventHandler<Events[E]]): void {
    this.listeners.get(event)?.delete(handler)
    this.onceListeners.get(event)?.delete(handler)
  }

  /**
   * 触发事件
   */
  async emit<E extends keyof Events>(event: E, data: Events[E]): Promise<void> {
    const allHandlers = [
      ...(this.listeners.get(event) ?? []),
      ...(this.onceListeners.get(event) ?? []),
    ]

    await Promise.allSettled(
      allHandlers.map(handler => handler(data))
    )
  }

  /**
   * 移除某个事件的所有监听器
   */
  clear<E extends keyof Events>(event: E): void {
    this.listeners.delete(event)
    this.onceListeners.delete(event)
  }

  /**
   * 清除所有事件监听器
   */
  clearAll(): void {
    this.listeners.clear()
    this.onceListeners.clear()
  }
}

// ===== 全局实例 =====

export const eventBus = new TypedEventBus<EventDefinitions>()

// ===== 使用演示 =====

// 订阅登录事件
const unsubLogin = eventBus.on('auth:login', (data) => {
  // data 类型自动推导为 { userId: string; sessionId: string; loginMethod: 'password' | 'oauth' | 'sso' }
  console.log(`User ${data.userId} logged in via ${data.loginMethod}`)

  if (data.loginMethod === 'oauth') {
    trackEvent('oauth_login', { userId: data.userId })
  }
})

// 订阅一次性事件
eventBus.once('ui:modal-close', (data) => {
  // data 类型: { modalId: string; result?: unknown }
  if (data.result) {
    console.log(`Modal ${data.modalId} closed with result:`, data.result)
  }
})

// 触发事件 —— 数据类型受到严格检查
await eventBus.emit('auth:login', {
  userId: 'u123',
  sessionId: 'sess_abc',
  loginMethod: 'oauth',  // 只能是三个选项之一
})

// 类型错误示范：
// await eventBus.emit('auth:login', { userId: 'u123' })  // 缺少 sessionId 和 loginMethod
// await eventBus.emit('nonexistent:event', {})            // 事件不存在

// 取消订阅
unsubLogin()
```

## 常见陷阱与最佳实践

### 陷阱一：过度使用 any 放弃类型安全

```typescript
// ❌ 反面教材 —— 用 any 破坏了泛型的意义
function badProcess<T>(data: T): any {
  return JSON.parse(JSON.stringify(data))  // 失去了所有类型信息
}

// ✅ 正确做法 —— 保持类型链路完整
function goodProcess<T>(data: T): T {
  const cloned = JSON.parse(JSON.stringify(data))
  return cloned as T  // 在确信安全的情况下使用断言
}

// ✅ 更好的做法 —— 提供明确的类型转换
function safeClone<T>(data: T): T {
  if (typeof structuredClone === 'function') {
    return structuredClone(data)
  }
  return JSON.parse(JSON.stringify(data)) as T
}
```

### 陷阱二：不必要的泛型

```typescript
// ❌ 泛型 T 从未被有效利用 —— 这种情况下不需要泛型
function print<T>(value: T): void {
  console.log(value)  // 这里 T 没有任何约束或特殊用途
}

// ✅ 直接使用具体类型即可
function printBetter(value: unknown): void {
  console.log(value)
}

// 或者如果确实需要处理多种类型，考虑重载
function show(value: string): string
function show(value: number): string
function show(value: boolean): string
function show(value: unknown): string {
  return String(value)
}
```

### 陷阱三：约束过于严格导致可用性差

```typescript
// ❌ 约束太严 —— 很难找到满足条件的类型
function strictFunc<T extends { a: number; b: string; c: boolean; d: symbol }>(obj: T): T {
  return obj
}

// ✅ 合理约束 —— 只要求真正需要的属性
function relaxedFunc<T extends { id: string | number }>(entity: T): T {
  return entity
}
```

### 最佳实践总结

| 原则 | 说明 |
|------|------|
| **优先使用接口定义约束** | 让意图更清晰，也便于复用 |
| **合理命名类型参数** | 单字母（T/U/K/V）用于简单场景，描述性名称用于公开 API |
| **善用类型推断** | 不要到处写 `<T>` 显式指定，让编译器帮你推断 |
| **约束最小化原则** | 只加必要的约束，过度约束降低复用性 |
| **文档注释不可省略** | 泛型代码比普通代码更难阅读，好的注释必不可少 |
| **考虑提供非泛型重载** | 为常见用法提供便利的重载版本 |

## 总结

泛型入门的核心概念可以用四层递进来概括：

**第零层：占位符直觉**（本章新增的核心章节）——理解 `<T>` 本质上就是一个类型层面的"空白处"、"插槽"或"未知数"。它像邀请函上的横线、快递运单的内容栏、数学公式中的变量 $x$——定义时留空，使用时填入。通过邀请函、运单、函数参数 vs 类型参数、数学公式等生活化类比，建立对 T 的直觉认知；再通过生命周期（声明→引用→绑定→检查→擦除）、视觉模型（插槽/管道/透镜）、any 对比、身份同一性、作用域规则、自由度谱系、多占位符协作、Array 实例等全方位维度彻底吃透这个概念。

**第一层：语法认知**——学会 `<T>` 的声明和使用，理解类型参数在函数、接口中的作用域。这是最基础的门槛。

**第二层：约束思维**——认识到"无约束的泛型等于 any"的问题，掌握 `extends`、`keyof` 等约束手段，在灵活性和安全性之间取得平衡。

**第三层：建模能力**——将现实世界的关系映射为类型之间的关系。Repository 模式中的实体抽象、EventBus 中的事件映射、API 层的请求/响应对——这些都是泛型思维的工程实践。

泛型不仅是一个语法特性，更是一种编程范式。它教会我们从**"针对具体类型编写代码"**转向**"针对类型之间的关系编写代码"**。而这一切的起点，就是理解那个看似简单却蕴含深意的尖括号 —— **`<T>`，一个等待被填充的类型占位符**。

> **一句话带走**：T 就是类型世界的"填空题空格"。你写下一道带空格的题目（定义泛型），别人做题时把答案写进去（传入具体类型），然后所有人都能看到完整的解答（获得完整类型信息）。这种视角的转变，是从"能用 TypeScript"到"用好 TypeScript"的关键一步。
