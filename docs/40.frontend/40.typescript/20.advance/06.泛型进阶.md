## 从入门到进阶：泛型的深层能力

在《泛型入门》中，我们建立了对泛型的基础认知——泛型函数、泛型接口、泛型约束。这些工具已经能解决日常开发中大部分的类型参数化需求。

但 TypeScript 的类型系统远不止于此。本章将深入三个更高级的主题：

1. **默认泛型参数**——让泛型在不指定时也能有合理的默认行为
2. **泛型类**——将泛型能力融入面向对象的类设计
3. **keyof 与泛型结合**——实现类型安全的属性访问、对象映射等高级操作

这三个主题的共同点是：它们都涉及**"在类型层面进行计算"**的能力。理解了它们，你就能真正体会到 TypeScript 作为一门"类型编程语言"的魅力。

---

## 一、默认泛型参数（Default Generic Parameters）

### 动机：减少调用时的类型噪音

回顾一下我们之前写过的 API 请求函数：

```typescript
async function apiRequest<T>(
  url: string,
  options?: RequestInit
): Promise<{ data: T; status: number; ok: boolean }> { /* ... */ }

// 每次调用都必须显式指定 T
const result = await apiRequest<UserProfile>('/api/user')     // 必须写 <UserProfile>
const result2 = await apiRequest<Article[]>('/api/articles')   // 必须写 <Article[]>
```

当某个泛型函数的绝大多数调用都使用相同的类型时，反复写 `<SomeType>` 就成了**语法噪音（Syntax Noise）**。默认泛型参数就是解决这个问题的。

### 基本语法

```typescript
/**
 * 默认泛型参数的语法：
 * 
 * <T = DefaultType>
 *       ^^^^^^^^^^^
 *       当调用时不指定 T，自动使用 DefaultType
 */

// 简单例子：创建数组
function createArray<T = string>(length: number, value: T): T[] {
  return Array(length).fill(value)
}

// 不指定 T —— 默认为 string
const arr1 = createArray(3, 'hello')
// arr1 的类型是 string[]

// 显式指定 T —— 覆盖默认值
const arr2 = createArray<number>(4, 0)
// arr2 的类型是 number[]
```

### 默认值的推断规则

TypeScript 对默认泛型参数有一套完整的推断策略：

```typescript
/**
 * 规则 1：如果提供了实参且编译器能推断出类型，则使用推断结果
 */

function identity<T = string>(value: T): T {
  return value
}

identity(42)           // T 推断为 number（不是默认值 string）
identity('hello')      // T 推断为 string（恰好与默认值一致）
identity(true)         // T 推断为 boolean

/**
 * 规则 2：如果无法从参数推断（如无参调用），则使用默认值
 */
function create<T = number>(): T {
  return {} as T
}

const val1 = create()        // T 使用默认值 → number
const val2 = create<string>() // 显式指定 → string

/**
 * 规则 3：多个类型参数可以分别设置默认值
 */
function merge<
  T = { [key: string]: unknown },
  U = Partial<T>
>(base: T, override?: U): T & U {
  return { ...base, ...override } as T & U
}

const merged1 = merge({ a: 1 }, { b: 2 })
// T = { [key: string]: unknown } (默认)
// U = Partial<{ [key: string]: unknown }> (默认)
// 结果: { a: number; b?: number }

const merged2 = merge<{ x: number; y: number }, { z: number }>(
  { x: 1, y: 2 },
  { z: 3 }
)
// T = { x: number; y: number }
// U = { z: number }
```

### 实战案例：带默认类型的响应包装器

```typescript
/**
 * API 响应的标准包装结构
 * 大多数情况下 data 是 unknown 或具体业务类型，
 * 但 error 有一个合理的默认值
 */
interface ApiResponse<TData = unknown, TError = ApiError> {
  success: boolean
  data: TData
  error?: TError
  timestamp: number
  requestId: string
}

interface ApiError {
  code: string
  message: string
  details?: Record<string, string[]>
}

/**
 * 创建成功响应
 * 注意：只传入 data 时，error 自动使用默认值 ApiError
 */
function successResponse<T>(data: T): ApiResponse<T> {
  return {
    success: true,
    data,
    timestamp: Date.now(),
    requestId: crypto.randomUUID(),
  }
}

/**
 * 创建错误响应
 * error 参数使用默认类型
 */
function errorResponse<TError extends ApiError = ApiError>(
  error: TError
): ApiResponse<never, TError> {
  return {
    success: false,
    data: undefined as never,
    error,
    timestamp: Date.now(),
    requestId: crypto.randomUUID(),
  }
}

// ===== 使用示例 =====

// 成功响应 —— 只需关心数据类型
const userResp = successResponse({
  id: 'u001',
  name: 'Alice',
  email: 'alice@example.com',
})
// 类型: ApiResponse<{ id: string; name: string; email: string }, ApiError>

// 错误响应 —— 使用默认的错误类型
const errResp = errorResponse({
  code: 'NOT_FOUND',
  message: '用户不存在',
  details: { userId: ['该 ID 对应的用户记录不存在'] },
})
// 类型: ApiResponse<never, ApiError>

// 自定义错误类型
interface ValidationError {
  code: 'VALIDATION_ERROR'
  fieldErrors: Array<{ field: string; messages: string[] }>
}

const validationErr = errorResponse<ValidationError>({
  code: 'VALIDATION_ERROR',
  fieldErrors: [
    { field: 'email', messages: ['邮箱格式不正确'] },
    { field: 'age', messages: ['年龄必须大于0'] },
  ],
})
// 类型: ApiResponse<never, ValidationError>
```

### 实战案例：可配置的缓存系统

```typescript
/**
 * 通用缓存系统 —— 展示默认泛型参数的实际威力
 * 
 * 设计目标：
 * - 支持任意类型的键和值
 * - 提供合理的默认配置
 * - 支持过期时间和最大容量限制
 */

interface CacheOptions<TKey = string, TValue = unknown> {
  /** 最大条目数，0 表示不限 */
  maxSize?: number
  /** 默认 TTL（毫秒），0 表示永不过期 */
  defaultTTL?: number
  /** 键序列化函数 */
  keySerializer?: (key: TKey) => string
  /** 缓存未命中时的回退加载器 */
  loader?: (key: TKey) => Promise<TValue>
  /** 条目被淘汰时的回调 */
  onEvict?: (key: TKey, value: TValue) => void
}

interface CacheEntry<TValue> {
  value: TValue
  createdAt: number
  expiresAt: number | null // null 表示永不过期
  lastAccessedAt: number
  accessCount: number
}

/**
 * 泛型缓存类 —— TKey 和 TValue 都有默认值
 */
class Cache<TKey = string, TValue = unknown> {
  private store = new Map<string, CacheEntry<TValue>>()
  private readonly options: Required<CacheOptions<TKey, TValue>>

  constructor(options: CacheOptions<TKey, TValue> = {}) {
    this.options = {
      maxSize: options.maxSize ?? 1000,
      defaultTTL: options.defaultTTL ?? 0,
      keySerializer: options.keySerializer ?? ((k: TKey) => String(k)),
      loader: options.loader,
      onEvict: options.onEvict,
    }
  }

  /**
   * 获取缓存值
   * 如果存在 loader 且缓存未命中，自动加载并缓存
   */
  async get(key: TKey): Promise<TValue | undefined> {
    const serializedKey = this.options.keySerializer(key)
    const entry = this.store.get(serializedKey)

    if (entry) {
      // 检查是否过期
      if (entry.expiresAt !== null && Date.now() > entry.expiresAt) {
        this.delete(key)
        // 过期后如果存在 loader，重新加载
        return this.loadAndCache(key, serializedKey)
      }

      // 更新访问信息
      entry.lastAccessedAt = Date.now()
      entry.accessCount++
      
      return entry.value
    }

    // 缓存未命中，尝试通过 loader 加载
    return this.loadAndCache(key, serializedKey)
  }

  private async loadAndCache(key: TKey, serializedKey: string): Promise<TValue | undefined> {
    if (!this.options.loader) return undefined

    const value = await this.options.loader(key)
    this.set(key, value)
    return value
  }

  /**
   * 设置缓存值
   */
  set(key: TKey, value: TValue, ttl?: number): void {
    const serializedKey = this.options.keySerializer(key)

    // 检查容量限制
    if (this.options.maxSize > 0 && this.store.size >= this.options.maxSize && !this.store.has(serializedKey)) {
      this.evictLRU()
    }

    const effectiveTTL = ttl ?? this.options.defaultTTL
    const now = Date.now()

    this.store.set(serializedKey, {
      value,
      createdAt: now,
      expiresAt: effectiveTTL > 0 ? now + effectiveTTL : null,
      lastAccessedAt: now,
      accessCount: 1,
    })
  }

  /**
   * 删除缓存项
   */
  delete(key: TKey): boolean {
    const serializedKey = this.options.keySerializer(key)
    const entry = this.store.get(serializedKey)
    
    if (entry) {
      this.store.delete(serializedKey)
      this.options.onEvict?.(key, entry.value)
      return true
    }
    
    return false
  }

  /**
   * 淘汰最近最少使用的条目（LRU 策略）
   */
  private evictLRU(): void {
    let lruKey: string | null = null
    let lruTime = Infinity

    for (const [key, entry] of this.store.entries()) {
      if (entry.lastAccessedAt < lruTime) {
        lruTime = entry.lastAccessedAt
        lruKey = key
      }
    }

    if (lruKey !== null) {
      const entry = this.store.get(lruKey)!
      this.store.delete(lruKey)
      // 反序列化 key 回调给 onEvict（这里简化处理，实际可能需要维护反向映射）
      this.options.onEvict?.({} as TKey, entry.value)
    }
  }

  /** 清空所有缓存 */
  clear(): void {
    for (const [serializedKey, entry] of this.store.entries()) {
      this.options.onEvict?.({} as TKey, entry.value)
    }
    this.store.clear()
  }

  /** 获取当前缓存大小 */
  get size(): number {
    return this.store.size
  }

  /** 获取统计信息 */
  get stats(): { size: number; maxSize: number } {
    let totalAccessCount = 0
    for (const entry of this.store.values()) {
      totalAccessCount += entry.accessCount
    }
    return {
      size: this.store.size,
      maxSize: this.options.maxSize,
    }
  }
}

// ===== 使用示例 =====

// 场景一：使用全部默认值 —— 键是 string，值是 unknown
const basicCache = new Cache()
basicCache.set('user:001', { name: 'Alice' })
basicCache.get('user:001').then(val => console.log(val)) // { name: 'Alice' } | undefined

// 场景二：指定值类型，键使用默认 string
const userCache = newCache<string, UserProfile>({
  maxSize: 500,
  defaultTTL: 5 * 60 * 1000, // 5 分钟
  loader: async (id) => {
    const res = await fetch(`/api/users/${id}`)
    return res.json()
  },
})

// 场景三：完全自定义键和值类型
const queryCache = new Cache<QueryKey, QueryResult>({
  maxSize: 200,
  keySerializer: (key) => `${key.endpoint}?${new URLSearchParams(key.params as any)}`,
  onEvict: (key, value) => {
    console.log(`查询缓存被淘汰: ${key.endpoint}`)
  },
})

interface QueryKey {
  endpoint: string
  params: Record<string, string | number>
}

interface QueryResult {
  data: unknown
  fetchedAt: number
}
```

### 多个泛型参数的默认值依赖关系

```typescript
/**
 * 高级技巧：后面的参数可以引用前面的参数作为默认值的一部分
 * 
 * 这允许构建灵活的类型层级
 */

// 基础容器
interface Container<T> {
  value: T
  created: Date
}

// 包装器 —— 内部容器类型由外部决定
type Wrapper<
  InnerT = string,
  OuterT = Container<InnerT>
> = {
  inner: InnerT
  outer: OuterT
  meta: { version: number; description: string }
}

// 使用默认值
const w1: Wrapper = {
  inner: 'hello',
  outer: { value: 'hello', created: new Date() },
  meta: { version: 1, description: 'default wrapper' },
}
// InnerT = string, OuterT = Container<string>

// 指定 InnerT
const w2: Wrapper<number> = {
  inner: 42,
  outer: { value: 42, created: new Date() },
  meta: { version: 2, description: 'number wrapper' },
}
// InnerT = number, OuterT = Container<number>

// 完全自定义
const w3: Wrapper<boolean, Array<boolean>> = {
  inner: true,
  outer: [true, false, true],
  meta: { version: 3, description: 'custom wrapper' },
}
// InnerT = boolean, OuterT = boolean[]

/**
 * 实际应用：分页响应的默认类型
 */
interface PaginationMeta {
  page: number
  pageSize: number
  total: number
  totalPages: number
  hasNext: boolean
  hasPrev: boolean
}

type PaginatedResponse<
  T = unknown,
  MetaT = PaginationMeta
> = {
  data: T[]
  meta: MetaT
  links: {
    self: string
    first?: string
    prev?: string
    next?: string
    last?: string
  }
}

// 最简形式
type DefaultPaginated = PaginatedResponse
// 等价于 PaginatedResponse<unknown, PaginationMeta>

// 指定数据类型
type UserPaginated = PaginatedResponse<User>
// 等价于 PaginatedResponse<User, PaginationMeta>

// 完全自定义元数据
type CustomMeta = PaginationMeta & { elapsedTime: number; cacheHit: boolean }
type ArticlePaginated = PaginatedResponse<Article, CustomMeta>
```

## 二、泛型类（Generic Classes）

### 类中的泛型声明位置

泛型类的类型参数紧跟在类名之后，作用域覆盖整个类体（包括属性、方法、访问器等）：

```typescript
/**
 * 泛型类的语法：
 * 
 * class ClassName<TypeParams> { ... }
 *                  ^^^^^^^^^^
 *                  类型参数在此处声明
 */

class Box<T> {
  private _contents: T

  constructor(contents: T) {
    this._contents = contents
  }

  get contents(): T {
    return this._contents
  }

  set contents(value: T) {
    console.log(`内容已更新: ${JSON.stringify(value)}`)
    this._contents = value
  }

  // 方法也可以使用泛型参数 T
  transform<U>(fn: (value: T) => U): Box<U> {
    return new Box(fn(this._contents))
  }
}

// ===== 使用 =====

const strBox = new Box('Hello TypeScript')
console.log(strBox.contents)  // "Hello TypeScript"
strBox.contents = "Updated!"  // 触发 setter 日志

const numBox = new Box(42)
console.log(numBox.contents)  // 42

// transform 方法产生新的 Box，类型随之变化
const lengthBox = strBox.transform(s => s.length)
// lengthBox 是 Box<number>，contents 为 12
```

### 泛型约束在类中的应用

类级别的泛型同样支持 `extends` 约束：

```typescript
/**
 * 泛型约束类 —— 确保类型参数满足特定条件
 */

// 约束：必须有比较能力
interface Comparable<T> {
  compareTo(other: T): -1 | 0 | 1
}

/**
 * 泛型二叉搜索树（BST）
 * 要求元素类型必须是 Comparable 的子类型
 */
class BinarySearchTree<T extends Comparable<T>> {
  private root: BSTNode<T> | null = null
  private _size = 0

  get size(): number {
    return this._size
  }

  insert(value: T): void {
    this.root = this.insertNode(this.root, value)
    this._size++
  }

  private insertNode(node: BSTNode<T> | null, value: T): BSTNode<T> {
    if (node === null) {
      return new BSTNode(value)
    }

    const comparison = value.compareTo(node.value)

    if (comparison < 0) {
      node.left = this.insertNode(node.left, value)
    } else if (comparison > 0) {
      node.right = this.insertNode(node.right, value)
    }
    // comparison === 0 时，不插入重复值（可根据需求修改）

    return node
  }

  contains(value: T): boolean {
    return this.search(this.root, value) !== null
  }

  private search(node: BSTNode<T> | null, value: T): BSTNode<T> | null {
    if (node === null) return null

    const comparison = value.compareTo(node.value)

    if (comparison < 0) return this.search(node.left, value)
    if (comparison > 0) return this.search(node.right, value)
    return node // 找到了
  }

  // 中序遍历（返回排序后的数组）
  inOrderTraversal(): T[] {
    const result: T[] = []
    this.inOrder(this.root, result)
    return result
  }

  private inOrder(node: BSTNode<T> | null, result: T[]): void {
    if (node === null) return
    this.inOrder(node.left, result)
    result.push(node.value)
    this.inOrder(node.right, result)
  }

  // 删除操作（略复杂，此处省略完整实现）
  remove(value: T): boolean {
    // ... 实现
    return false
  }
}

class BSTNode<T> {
  constructor(
    public value: T,
    public left: BSTNode<T> | null = null,
    public right: BSTNode<T> | null = null
  ) {}
}

// ===== 实现 Comparable 接口的类型 =====

class Person implements Comparable<Person> {
  constructor(
    public name: string,
    public age: number
  ) {}

  compareTo(other: Person): -1 | 0 | 1 {
    if (this.age < other.age) return -1
    if (this.age > other.age) return 1
    // 年龄相同则按名字排序
    return this.name.localeCompare(other.name) as (-1 | 0 | 1)
  }
}

// 使用 BST
const personTree = new BinarySearchTree<Person>()
personTree.insert(new Person('Alice', 30))
personTree.insert(new Person('Bob', 25))
personTree.insert(new Person('Charlie', 35))

console.log(personTree.inOrderTraversal())
// 按年龄排序: [Bob(25), Alice(30), Charlie(35)]

console.log(personTree.contains(new Person('Bob', 25)))  // true
```

### 静态成员不能使用实例泛型参数

这是一个重要的限制，需要特别注意：

```typescript
class GenericClass<T> {
  // ✅ 实例属性可以使用 T
  instanceValue: T

  // ✅ 实例方法可以使用 T
  getInstance(): T {
    return this.instanceValue
  }

  // ❌ 静态属性不能使用 T！
  // static defaultValue: T  // 编译错误：静态成员不能引用类的类型参数

  // ❌ 静态方法不能使用 T！
  // static create(): GenericClass<T> { ... }  // 同样的错误

  // ✅ 如果静态成员需要泛型，需要单独声明
  static create<U>(defaultValue: U): GenericClass<U> {
    const instance = new GenericClass<U>(defaultValue)
    return instance
  }

  constructor(value: T) {
    this.instanceValue = value
  }
}

// 正确的使用方式
const instance = GenericClass.create(42)          // GenericClass<number>
const instance2 = GenericClass.create('hello')    // GenericClass<string>
```

**原因**：`T` 属于实例级别——每次 `new GenericClass<T>()` 时 `T` 可能不同。而静态成员属于类级别，不依赖于任何具体实例。因此静态成员无法知道 `T` 到底是什么。

### 继承中的泛型传递

```typescript
/**
 * 泛型继承的三种模式
 */

// 模式一：父类泛型，子类固定具体类型
abstract class BaseRepository<T extends Entity> {
  abstract findById(id: string): Promise<T | null>
  abstract findAll(): Promise<T[]>
  abstract save(entity: Omit<T, 'id' | 'createdAt' | 'updatedAt'>): Promise<T>
  abstract delete(id: string): Promise<boolean>
}

class UserRepository extends BaseRepository<User> {
  // 此处 T 被固定为 User
  async findById(id: string): Promise<User | null> {
    // 具体实现...
    return null
  }
  
  async findAll(): Promise<User[]> {
    return []
  }
  
  async save(data: Omit<User, 'id' | 'createdAt' | 'updatedAt'>): Promise<User> {
    return {} as User
  }
  
  async delete(id: string): Promise<boolean> {
    return false
  }
}

// 模式二：父子都是泛型，子类保留或扩展父类的类型参数
class CachedRepository<T extends Entity> extends BaseRepository<T> {
  private cache = new Map<string, T>()

  async findById(id: string): Promise<T | null> {
    const cached = this.cache.get(id)
    if (cached) return cached
    
    const entity = await super.findById(id)
    if (entity) this.cache.set(id, entity)
    return entity
  }

  // 其他方法必须实现...
  async findAll(): Promise<T[]> { return [] }
  async save(data: any): Promise<any> { return {} as T }
  async delete(id: string): Promise<boolean> { return false }
}

// 模式三：子类增加新的类型参数
class PaginatedRepository<T extends Entity, F = Partial<T>> extends BaseRepository<T> {
  findPage(
    filter?: F,
    page = 1,
    pageSize = 20
  ): Promise<{ items: T[]; total: number; page: number; pageSize: number }> {
    // 分页查询的实现
    return { items: [], total: 0, page, pageSize }
  }
}

// 使用
const userRepo = new UserRepository()
const cachedUserRepo = new CachedRepository<User>()
const paginatedPostRepo = new PaginatedRepository<Post, { isPublished?: boolean }>()
```

### 实战案例：类型安全的观察者模式

```typescript
/**
 * 泛型观察者（Observer）模式实现
 * 
 * 展示泛型类如何实现经典的设计模式
 * 同时保持完整的类型安全
 */

// 观察者接口
interface Observer<T> {
  onNext(value: T): void
  onError?(error: Error): void
  onComplete?(): void
}

// 取消订阅的句柄类型
type Unsubscribe = () => void

/**
 * 可观察对象（Observable）核心类
 * 
 * T 是通知数据的类型
 */
class Observable<T> {
  private observers = new Set<Observer<T>>()
  private isComplete = false
  private error: Error | null = null

  /**
   * 订阅 observable
   */
  subscribe(observer: Observer<T>): Unsubscribe {
    if (this.isComplete) {
      observer.onComplete?.()
      return () => {}
    }

    if (this.error) {
      observer.onError?.(this.error)
      return () => {}
    }

    this.observers.add(observer)

    // 返回取消订阅函数
    return () => {
      this.observers.delete(observer)
    }
  }

  /**
   * 便捷订阅 —— 直接传入回调
   */
  onNext(next: (value: T) => Unsubscribe {
    const observer: Observer<T> = { onNext: next }
    return this.subscribe(observer)
  }

  /**
   * 发送下一个值给所有观察者
   */
  next(value: T): void {
    if (this.isComplete || this.error) return

    for (const observer of this.observers) {
      try {
        observer.onNext(value)
      } catch (e) {
        console.error('Observer.onNext threw an error:', e)
      }
    }
  }

  /**
   * 通知错误
   */
  error(err: Error): void {
    if (this.isComplete || this.error) return
    
    this.error = err
    for (const observer of this.observers) {
      observer.onError?.(err)
    }
    this.observers.clear()
  }

  /**
   * 通知完成
   */
  complete(): void {
    if (this.isComplete || this.error) return

    this.isComplete = true
    for (const observer of this.observers) {
      observer.onComplete?.()
    }
    this.observers.clear()
  }

  /**
   * 操作符：map —— 转换数据类型
   */
  map<U>(transformer: (value: T) => U): Observable<U> {
    const output = new Observable<U>()

    this.subscribe({
      onNext: (value) => {
        try {
          output.next(transformer(value))
        } catch (e) {
          output.error(e instanceof Error ? e : new Error(String(e)))
        }
      },
      onError: (err) => output.error(err),
      onComplete: () => output.complete(),
    })

    return output
  }

  /**
   * 操作符：filter —— 过滤数据
   */
  filter(predicate: (value: T) => boolean): Observable<T> {
    const output = new Observable<T>()

    this.subscribe({
      onNext: (value) => {
        if (predicate(value)) {
          output.next(value)
        }
      },
      onError: (err) => output.error(err),
      onComplete: () => output.complete(),
    })

    return output
  }

  /**
   * 操作符：reduce —— 聚合数据
   */
  reduce<U>(accumulator: (acc: U, value: T) => U, initialValue: U): Observable<U> {
    const output = new Observable<U>()
    let acc = initialValue

    this.subscribe({
      onNext: (value) => {
        acc = accumulator(acc, value)
      },
      onError: (err) => output.error(err),
      onComplete: () => {
        output.next(acc)
        output.complete()
      },
    })

    return output
  }
}
```

### 实战案例：状态管理 Store

```typescript
/**
 * 轻量级状态管理 Store —— 类似 Vuex/Pinia 的简化版
 * 
 * 利用泛型类确保状态、getter、mutation、action 之间的类型一致性
 */

// Action 的类型定义
type ActionDefinition<TState, TPayload = void> = (
  state: TState,
  payload: TPayload
) => void | Promise<void>

// Getter 的类型定义
type GetterDefinition<TState, TReturn> = (state: TState) => TReturn

// 异步 Action 的类型定义
type AsyncActionDefinition<TState, TPayload = void, TResult = void> = (
  context: { state: TState; commit: <P>(mutation: string, payload?: P) => void },
  payload: TPayload
) => Promise<TResult>

/**
 * Store 定义的接口
 */
interface StoreDefinition<TState> {
  state: () => TState
  getters?: {
    [key: string]: GetterDefinition<TState, any>
  }
  mutations?: {
    [key: string]: ActionDefinition<TState, any>
  }
  actions?: {
    [key: string]: AsyncActionDefinition<TState, any, any>
  }
}

/**
 * Store 实例的类型
 */
interface StoreInstance<TState, TGetters = Record<string, any>> {
  state: Readonly<TState>
  getters: { [K in keyof TGetters]: TGetters[K] }
  commit<K extends keyof NonNullable<StoreDefinition<TState>['mutations']>>(
    mutation: K,
    payload?: Parameters<NonNullable<StoreDefinition<TState>['mutations']>[K]>[1]
  ): void
  dispatch<K extends keyof NonNullable<StoreDefinition<TState>['actions']>>(
    action: K,
    payload?: Parameters<NonNullable<StoreDefinition<TState>['actions']>[K]>[1]
  ): Promise<ReturnType<NonNullable<StoreDefinition<TState>['actions']>[K]>>
}

/**
 * Store 工厂类
 */
class StoreFactory<TState, TGetters = Record<string, never>> {
  private readonly definition: StoreDefinition<TState>
  private readonly reactiveState: TState
  private computedGetters: TGetters

  constructor(definition: StoreDefinition<TState>) {
    this.definition = definition
    this.reactiveState = definition.state()
    this.computedGetters = {} as TGetters

    // 计算 getters
    if (definition.getters) {
      for (const [key, getter] of Object.entries(definition.getters)) {
        Object.defineProperty(this.computedGetters, key, {
          get: () => getter(this.reactiveState),
          enumerable: true,
        })
      }
    }
  }

  get state(): Readonly<TState> {
    return this.reactiveState
  }

  get getters(): TGetters {
    return this.computedGetters
  }

  commit<K extends keyof NonNullable<typeof this.definition.mutations>>(
    mutation: K,
    payload?: Parameters<NonNullable<typeof this.definition.mutations>[K]>[1]
  ): void {
    const mutFn = this.definition.mutations?.[mutation]
    if (mutFn) {
      mutFn(this.reactiveState, payload as any)
    } else {
      console.warn(`Unknown mutation: ${String(mutation)}`)
    }
  }

  async dispatch<K extends keyof NonNullable<typeof this.definition.actions>>(
    action: K,
    payload?: Parameters<NonNullable<typeof this.definition.actions>[K]>[1]
  ): Promise<ReturnType<NonNullable<typeof this.definition.actions>[K]>> {
    const actionFn = this.definition.actions?.[action]
    if (actionFn) {
      const ctx = {
        state: this.reactiveState,
        commit: this.commit.bind(this),
      }
      return actionFn(ctx, payload as any)
    }
    
    console.warn(`Unknown action: ${String(action)}`)
    return undefined as any
  }
}

// ===== 完整使用示例 =====

interface TodoItem {
  id: string
  text: string
  completed: boolean
  priority: 'low' | 'medium' | 'high'
  createdAt: Date
}

interface TodoState {
  todos: TodoItem[]
  filter: 'all' | 'active' | 'completed'
  loading: boolean
}

// 定义 Todo Store
const todoStoreDef: StoreDefinition<TodoState> = {
  state: (): TodoState => ({
    todos: [],
    filter: 'all',
    loading: false,
  }),

  getters: {
    activeTodos: (state) =>
      state.todos.filter(t => !t.completed),

    completedTodos: (state) =>
      state.todos.filter(t => t.completed),

    todoCount: (state) => state.todos.length,

    activeCount: (state) =>
      state.todos.filter(t => !t.completed).length,

    completedRatio: (state) => {
      const total = state.todos.length
      if (total === 0) return 0
      return state.todos.filter(t => t.completed).length / total
    },

    highPriorityActive: (state) =>
      state.todos.filter(t => !t.completed && t.priority === 'high'),
  },

  mutations: {
    ADD_TODO(state, payload: { id: string; text: string; priority: TodoItem['priority'] }) {
      state.todos.push({
        id: payload.id,
        text: payload.text,
        completed: false,
        priority: payload.priority,
        createdAt: new Date(),
      })
    },

    TOGGLE_TODO(state, payload: { id: string }) {
      const todo = state.todos.find(t => t.id === payload.id)
      if (todo) {
        todo.completed = !todo.completed
      }
    },

    SET_FILTER(state, payload: TodoState['filter']) {
      state.filter = payload
    },

    SET_LOADING(state, payload: boolean) {
      state.loading = payload
    },

    REMOVE_TODO(state, payload: { id: string }) {
      state.todos = state.todos.filter(t => t.id !== payload.id)
    },

    CLEAR_COMPLETED(state) {
      state.todos = state.todos.filter(t => !t.completed)
    },
  },

  actions: {
    async fetchTodos(context) {
      context.commit('SET_LOADING', true)
      try {
        const res = await fetch('/api/todos')
        const todos: TodoItem[] = await res.json()

        for (const todo of todos) {
          context.commit('ADD_TODO', {
            id: todo.id,
            text: todo.text,
            priority: todo.priority ?? 'medium',
          })
        }
      } finally {
        context.commit('SET_LOADING', false)
      }
    },

    async toggleAndSave(context, payload: { id: string }) {
      context.commit('TOGGLE_TODO', payload)
      
      const todo = context.state.todos.find(t => t.id === payload.id)
      if (todo) {
        await fetch(`/api/todos/${payload.id}`, {
          method: 'PATCH',
          body: JSON.stringify({ completed: todo.completed }),
        })
      }
    },
  },
}

// 创建 Store 实例
const todoStore = new StoreFactory(todoStoreDef)

// ===== 使用 Store =====

// 访问状态（只读）
console.log(todoStore.state.loading)  // boolean
console.log(todoStore.state.filter)   // 'all' | 'active' | 'completed'

// 访问 getter（自动计算，类型安全）
todoStore.getters.activeTodos       // TodoItem[]
todoStore.getters.todoCount         // number
todoStore.getters.completedRatio    // number (0~1)
todoStore.getters.highPriorityActive // TodoItem[]

// 提交 mutation —— payload 类型受约束
todoStore.commit('ADD_TODO', {
  id: 'todo-1',
  text: '学习 TypeScript 泛型',
  priority: 'high',  // 只能是 'low' | 'medium' | 'high'
})

todoStore.commit('SET_FILTER', 'active')  // ✓
// todoStore.commit('SET_FILTER', 'invalid')  // ✗ 不是合法的 filter 值

// 分发 action —— 返回 Promise，payload 类型受约束
await todoStore.dispatch('fetchTodos')
await todoStore.dispatch('toggleAndSave', { id: 'todo-1' })
```

## 三、keyof 与泛型结合

### 核心概念回顾：keyof

在深入组合之前，先巩固 `keyof` 操作符的基本含义：

```typescript
/**
 * keyof 操作符：
 * 
 * 对于一个对象类型 T，keyof T 产生一个由 T 的所有公共属性名组成的联合类型
 * （string literal types 的联合）
 */

interface UserInfo {
  id: number
  username: string
  email: string
  age: number
  isActive: boolean
}

// UserInfoKeys 等价于:
// 'id' | 'username' | 'email' | 'age' | 'isActive'
type UserInfoKeys = keyof UserInfo

  apiUrl: 'https://api.example.com',
  timeout: 5000,
  retries: 3,
  debug: false,
}

type ConfigKeys = keyof typeof config
// 'apiUrl' | 'timeout' | 'retries' | 'debug'

// 只想要索引签名的话
type NumberKeys = keyof number[]
// 同上，因为数组本质上也是对象
```

### keyof 在泛型函数中的基本用法

```typescript
/**
 * 经典模式：安全地获取对象属性的值
 * 
 * 这是 keyof + 泛型最基础的用法
 * 也是实际开发中最高频使用的模式之一
 */
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
```

### Pick 和 omit 模式

```typescript
 * Pick —— 从 T 中选取指定的键组成新类型

// 手动实现 Pick
type MyPick<T, K extends keyof T> = {
```

### 实战案例：类型-safe 的 ORM 风格查询构建器

```typescript
/**
 * 类型安全的查询构建器
 * 
 * 利用 keyof + 泛型实现：
 * - where 条件的字段名必须是实体上存在的字段
 * - 字段的值类型必须匹配
 * - select 指定的字段返回正确的类型
 */

// 比较操作符
type ComparisonOp =
  | '=' | '!=' | '>' | '>=' | '<' | '<='
  | 'LIKE' | 'IN' | 'IS NULL' | 'IS NOT NULL'

// 条件表达式
type Condition<T, K extends keyof T> =
  | { field: K; op: '=' | '!=' | '>' | '>=' | '<' | '<='; value: T[K] }
  | { field: K; op: 'LIKE'; value: string }
  | { field: K; op: 'IN'; value: T[K][] }
  | { field: K; op: 'IS NULL' | 'IS NOT NULL' }
  | { and: Array<Condition<T, keyof T>> }
  | { or: Array<Condition<T, keyof T>> }

// 查询选项
interface QueryOptions<T> {
  where?: Condition<T, keyof T>
  orderBy?: { field: keyof T; direction: 'ASC' | 'DESC' }
  limit?: number
  offset?: number
  select?: Array<keyof T>
}

// 查询结果
interface QueryResult<T, SelectedFields extends keyof T | never = never> {
  items: SelectedFields extends never
    ? T[]
    : Array<Pick<T, SelectedFields>>
  count: number
  hasMore: boolean
}

/**
 * 查询构建器类
 */
class QueryBuilder<T extends { id: string }> {
  private options: QueryOptions<T> = {}

  /**
   * 设置过滤条件
   * field 必须是 T 的有效属性
   */
  where<K extends keyof T>(
    condition: Condition<T, K>
  ): QueryBuilder<T> {
    this.options.where = condition as Condition<T, keyof T>
    return this
  }

  /**
   * 设置排序
   * field 必须是 T 的有效属性
   */
  orderBy<K extends keyof T>(
    field: K,
    direction: 'ASC' | 'DESC' = 'ASC'
  ): QueryBuilder<T> {
    this.options.orderBy = { field, direction }
    return this
  }

  /**
   * 限制返回数量
   */
  limit(count: number): QueryBuilder<T> {
    this.options.limit = count
    return this
  }

  /**
   * 偏移量（用于分页）
   */
  offset(count: number): QueryBuilder<T> {
    this.options.offset = count
    return this
  }

  /**
   * 选择特定字段
   * 所有字段必须是 T 上存在的
   */
  select<K extends keyof T>(fields: K[]): QueryBuilder<T> {
    this.options.select = fields
    return this
  }

  /**
   * 执行查询（模拟）
   */
  async execute(): Promise<QueryResult<T>> {
    // 实际实现会发送数据库查询
    console.log('Executing query with options:', this.options)
    return {
      items: [] as any,
      count: 0,
      hasMore: false,
    }
  }

  /**
   * 执行并返回单个结果
   */
  async executeFirst(): Promise<T | null> {
    this.limit(1)
    const result = await this.execute()
    return result.items[0] ?? null
  }
}

// ===== 定义实体 =====

interface Product {

  name: string
  description: string
  price: number
  category: string
  stock: number
  rating: number
  isActive: boolean
  createdAt: Date
  updatedAt: Date

// ===== 使用示例 =====

async function demoQueries() {
  const qb = new QueryBuilder<Product>()

  // 示例 1：简单查询
  const allProducts = await qb.execute()
  // items: Product[]

  const activeProducts = await qb
    .where({ field: 'isActive', op: '=', value: true })  // value 必须是 boolean
    .where({ and: [{ field: 'stock', op: '>', value: 0 }] }) // value 必须是 number
    .orderBy('createdAt', 'DESC')

  // 示例 3：模糊搜索
  const searchedProducts = await qb

    .where({ field: 'price', op: '<=', value: 500 }) // price 是 number
    .orderBy('price', 'ASC')
    .execute()

  // 示例 4：选择特定字段
  const productListing = await qb
    .select(['id', 'name', 'price', 'rating'])  // 只能选 Product 上存在的字段
    .limit(20)
    .execute()
  // productListing.items: Array<Pick<Product, 'id' | 'name' | 'price' | 'rating'>>

  productListing.items.forEach(item => {
    console.log(`${item.name}: $${item.price} (⭐ ${item.rating})`)
    // item.description ❌ 未被 select，不可访问

      field: 'category',
```

```typescript
/**
 * 基于 keyof + 泛型的动态表单验证器
 * 
 * 验证规则与字段类型紧密绑定，
 * 确保每个字段的验证规则与其数据类型兼容
 */

// 验证规则类型
type ValidationRule<T, K extends keyof T> =
  | { rule: 'required'; message?: string }
  | { rule: 'minLength'; min: number; message?: string }
  | { rule: 'maxLength'; max: number; message?: string }
  | { rule: 'pattern'; regex: RegExp; message?: string }
  | { rule: 'min'; value: T[K] extends number ? number : never; message?: string }
  | { rule: 'max'; value: T[K] extends number ? number : never; message?: string }
  | { rule: 'email'; message?: string }
  | { rule: 'custom'; validator: (value: T[K], allValues: T) => string | null }

// 字段验证配置
type FieldValidation<T, K extends keyof T> = {
  rules: Array<ValidationRule<T, K>>
  label?: string
}

// 整体验证 schema
type ValidationSchema<T> = {
  [K in keyof T]?: FieldValidation<T, K>
}

// 验证结果
interface ValidationResult<T> {
  valid: boolean
  values: T
  errors: Partial<Record<keyof T, string[]>>
}

/**
 * 验证器类
 */
class FormValidator<T extends Record<string, unknown>> {
  constructor(private schema: ValidationSchema<T>) {}

  validate(data: Partial<T>): ValidationResult<T> {
    const errors = {} as Partial<Record<keyof T, string[]>>
    const values = { ...data } as T

    for (const [field, fieldConfig] of Object.entries(this.schema)) {
      const key = field as keyof T
      const value = data[key]
      const fieldErrors: string[] = []

      if (!fieldConfig) continue

      const label = fieldConfig.label ?? field

      for (const rule of fieldConfig.rules) {
        const error = this.evaluateRule(rule, value, label, values)
        if (error) {
          fieldErrors.push(error)
        }
      }

      if (fieldErrors.length > 0) {
        errors[key] = fieldErrors
      }
    }

    return {
      valid: Object.keys(errors).length === 0,
      values,
      errors,
    }
  }

  private evaluateRule<T, K extends keyof T>(
    rule: ValidationRule<T, K>,
    value: T[K],
    label: string,
    allValues: T
  ): string | null {
    switch (rule.rule) {
      case 'required':
        if (value === undefined || value === null || value === '') {
          return rule.message ?? `${label} 是必填项`
        }
        break

      case 'minLength':
        if (typeof value === 'string' && value.length < rule.min) {
          return rule.message ?? `${label} 至少需要 ${rule.min} 个字符`
        }
        break

      case 'maxLength':
        if (typeof value === 'string' && value.length > rule.max) {
          return rule.message ?? `${label} 不能超过 ${rule.max} 个字符`
        }
        break

      case 'pattern':
        if (typeof value === 'string' && !rule.regex.test(value)) {
          return rule.message ?? `${label} 格式不正确`
        }
        break

      case 'min':
        if (typeof value === 'number' && value < rule.value) {
          return rule.message ?? `${label} 不能小于 ${rule.value}`
        }
        break

      case 'max':
        if (typeof value === 'number' && value > rule.value) {
          return rule.message ?? `${label} 不能大于 ${rule.value}`
        }
        break

      case 'email':
        if (typeof value === 'string' && !/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value)) {
          return rule.message ?? `${label} 不是有效的邮箱地址`
        }
        break

      case 'custom': {
        const customError = rule.validator(value, allValues)
        return customError
      }
    }

    return null
  }
}
```

```typescript
/** 列定义 */
interface ColumnDefinition {
  type: 'string' | 'number' | 'boolean' | 'date' | 'json'
  nullable: boolean
  defaultValue?: unknown
  primaryKey?: boolean
  unique?: boolean
  indexed?: boolean
}

/** 表定义 —— 键是列名，值是列的定义 */
type TableSchema = Record<string, ColumnDefinition>

/** 行数据 —— 根据 TableSchema 推导出的行类型 */
type RowFromSchema<T extends TableSchema> = {
  [K in keyof T]: T[K]['nullable'] extends true
    ? T[K]['type'] extends 'json'
      ? unknown | null
      : T[K]['type'] extends 'string'
        ? string | null
        : T[K]['type'] extends 'number'
          ? number | null
          : T[K]['type'] extends 'boolean'
            ? boolean | null
            : T[K]['type'] extends 'date'
              ? Date | null
              : unknown | null
    : T[K]['type'] extends 'json'
      ? unknown
      : T[K]['type'] extends 'string'
        ? string
        : T[K]['type'] extends 'number'

  TUpSchema extends TableSchema = TableSchema,
  TDownSchema extends TableSchema = TableSchema
> {
  name: string
  version: number
  description: string
  upSchema?: TUpSchema
  downSchema?: TDownSchema
}

/**
 * Migration 泛型类
 * TUp: 向上迁移时的表结构
 * TDown: 向下迁移（回滚）时的表结构
 */
abstract class Migration<
  TUp extends TableSchema = TableSchema,
  TDown extends TableSchema = TableSchema
> {
  abstract readonly options: MigrationOptions<TUp, TDown>

  /**
   * 向上迁移（升级）—— 由子类实现
   */
  abstract up(
    db: DatabaseClient,
    params?: Record<string, unknown>
  ): Promise<Array<RowFromSchema<TUp>>>

  /**
   * 向下迁移（回滚）—— 由子类实现
   */
  abstract down(
    db: DatabaseClient,
    params?: Record<string, unknown>
  ): Promise<Array<RowFromSchema<TDown>>>

  /**
   * 获取此迁移影响的列名列表
   */
  getAffectedColumns(direction: 'up' | 'down'): string[] {
    const schema = direction === 'up' ? this.options.upSchema : this.options.downSchema
    return schema ? Object.keys(schema) : []
  }
}

    console.log(`[DB] Dropped column "${column}" from table "${table}"`)
  }

  async addColumn(table: string, column: string, def: ColumnDefinition): Promise<void> {

  }

  private migrations = new Map<number, TMigrations>()

  register(migration: TMigrations): void {
    const version = migration.options.version
    if (this.migrations.has(version)) {
      throw new Error(`Migration version ${version} already registered`)
    }
    this.migrations.set(version, migration)
  }

  async migrateUp(db: DatabaseClient, targetVersion?: number): Promise<void> {
    const sortedVersions = Array.from(this.migrations.keys()).sort((a, b) => a - b)
    const currentVersion = await this.getCurrentVersion(db)

    for (const version of sortedVersions) {
      if (version <= currentVersion) continue
      if (targetVersion !== undefined && version > targetVersion) break

      const migration = this.migrations.get(version)!
      console.log(`\n[MIGRATE UP] ${migration.options.name} v${migration.options.version}`)
      console.log(`Description: ${migration.options.description}`)
      console.log(`Columns affected: ${migration.getAffectedColumns('up').join(', ')}`)

      await migration.up(db)
      await this.updateVersion(db, version)

      console.log(`[MIGRATE UP] Completed successfully\n`)
    }
  }

  async migrateDown(db: DatabaseClient, steps = 1): Promise<void> {
    const sortedVersions = Array.from(this.migrations.keys()).sort((a, b) => b - a)
    const currentVersion = await this.getCurrentVersion(db)

    let stepped = 0
    for (const version of sortedVersions) {
      if (version > currentVersion) continue
      if (stepped >= steps) break

      console.log(`Rolling back...`)

      await migration.down(db)
      await this.updateVersion(db, version - 1)
      stepped++

      console.log(`[MIGRATE DOWN] Rolled back successfully\n`)
    }
  }

    // 实际项目中从 migrations 表读取

  }
```

## 总结

本章涵盖了泛型编程的三个进阶维度，每个维度都代表了类型系统能力的跃升：

**默认泛型参数**解决的是**易用性**问题。它让泛型在保持强大能力的同时不会给调用者带来过多的类型书写负担。好的默认值设计体现了库作者对用户使用场景的理解深度。

**泛型类**解决的是**封装性**问题。它将泛型的类型参数化能力融入面向对象的设计范式中，使得 Repository 模式、Observer 模式、Store 架构等经典设计都能享受类型系统的保护。关键是要记住静态成员与实例泛型参数的限制关系。

**keyof 与泛型结合**解决的是**精确性**问题。它是连接"运行时数据操作"与"编译期类型检查"的桥梁。通过 `K extends keyof T` 这种约束模式，我们能写出既通用又精确的代码——通用在于它适用于任何对象类型，精确在于每个属性名的访问都有对应的类型保障。

三者合在一起，构成了 TypeScript 泛型编程的核心武器库。掌握了它们，你就具备了应对大多数类型级编程挑战的能力。下一章我们将探索更多高级主题——条件类型、映射类型、模板字面量类型——它们将进一步拓展你的类型编程边界。
