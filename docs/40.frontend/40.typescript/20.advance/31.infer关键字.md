# infer 关键字 —— 在条件类型中提取类型

在条件类型中，我们已经学习了如何用 `extends ? :` 做类型的分支判断。但很多时候，我们不仅想知道"某个类型是否匹配某种模式"，还想要**从模式中提取出具体的部分类型**。这就是 `infer` 关键字的用武之地。

`infer` 是 TypeScript 条件类型系统中最强大的特性之一，它让类型层面的"解构与提取"成为可能。内置的 `ReturnType`、`Parameters`、`Awaited` 等工具类型，其底层实现都依赖 `infer`。

## 1. infer 是什么？

`infer` 是条件类型中的**类型变量声明关键字**，用于在类型匹配过程中**推断**（infer）出某一位置的子类型。

### 核心定义

```typescript
// infer 只能出现在 extends 后的类型模式中
type ExtractType<T> = T extends Array<infer U> ? U : never
//                    ^^^^^^^^^^^^
//                    infer 声明了类型变量 U，编译器会尝试将 T 匹配为 Array<某种类型>，
//                    并将那个"某种类型"绑定到 U 上
```

### 关键约束：位置限制

`infer` **只能**出现在条件类型的 `extends` 子句中——即三元表达式的 `?` 左侧、`extends` 右侧的类型位置。以下写法都是非法的：

```typescript
// ❌ 错误：infer 不能在普通类型别名中使用
type Bad<T> = infer U   // 编译错误

// ❌ 错误：infer 不能在 ? 的右侧（true 分支）中使用
type AlsoBad<T> = T extends string ? infer U : never

// ✅ 正确：infer 必须在 extends 右侧的模式中
type Good<T> = T extends Array<infer U> ? U : never
```

### 与普通类型参数的区别

```typescript
// 普通类型参数：调用者显式提供
function identity<T>(value: T): T {
  return value
}
const x = identity<number>(42)  // T 由调用者指定为 number

// infer 类型变量：由编译器根据模式匹配自动推断
type GetElement<T> = T extends Array<infer E> ? E : never
type Elem = GetElement<string[]>  // E 由编译器自动推断为 string，无需显式指定
```

本质区别：普通类型参数是**由外向内注入**的类型信息；而 `infer` 声明的变量是**由内向外提取**的类型片段。

## 2. infer 基本语法与工作机制

### 语法形式

```
Type extends Pattern<infer Var> ? TrueBranch : FalseBranch
```

当 `Type` 能够被结构化匹配到 `Pattern<某种类型>` 的形式时，`Var` 就会被绑定为那个"某种类型"，并在 true 分支中使用。

### 模式匹配机制详解

TypeScript 的 `infer` 模式匹配本质上是一种**结构化类型解构**：

```typescript
type UnwrapPromise<T> = T extends Promise<infer V> ? V : never

// 当传入 Promise<string> 时：
// 编译器检查：Promise<string> 是否匹配 Promise<infer V> 这个模式？
// 匹配过程：将 Promise<string> 与 Promise<infer V> 对齐
//   - 外层 Promise ✓ 匹配
//   - 内层 string 被绑定到 V
// 结果：V = string，返回 string

type Result1 = UnwrapPromise<string[]>          // never（string[] 不是 Promise）
type Result2 = UnwrapPromise<Promise<number>>    // number
type Result3 = UnwrapPromise<Promise<{ a: b }>>  // { a: b }
```

### 单个 infer 变量的最简示例

```typescript
// 从函数类型中提取返回值类型（ReturnType 的核心原理）
type MyReturnType<T extends (...args: any) => any> = T extends (...args: any) => infer R ? R : any

function getUser(id: number): { name: string; age: number } {
  return { name: 'Alice', age: 30 }
}

type User = MyReturnType<typeof getUser>
// User = { name: string; age: number }
```

## 3. 提取数组元素类型

### 基本用法：从数组类型中提取元素类型

```typescript
/**
 * 从数组类型中提取元素类型
 * 类似于内置的 ArrayItemType 或解包操作
 */
type ArrayElement<A> = A extends readonly (infer E)[] ? E : never

// 基本数组
type NumArr = ArrayElement<number[]>           // number
type StrArr = ArrayElement<string[]>           // string

// 元组也是数组的子集，同样可以匹配
type TupleElem = ArrayElement<[string, number]> // string | number

// 不匹配的情况
type NotArray = ArrayElement<string>            // never

// readonly 数组也能匹配
type ReadonlyArr = ArrayElement<readonly boolean[]> // boolean
```

### 处理嵌套数组

对于多维数组，一次 `infer` 只能解开一层：

```typescript
type FirstLevel<T> = T extends (infer E)[] ? E : never

type Matrix = number[][]
type Row = FirstLevel<Matrix>     // number[]（只解开了一层）
type Cell = FirstLevel<Row>       // number（再解开一层）

// 如果想直接获取最深层的元素类型，需要递归（后文详述）
```

## 4. 提取函数类型信息

这是 `infer` 最经典的应用场景，TypeScript 内置了多个相关工具类型。

### ReturnType：提取函数返回值

```typescript
// 内置 ReturnType 的简化实现
type MyReturnType<T extends (...args: any) => any> =
  T extends (...args: any) => infer R ? R : never

// 示例
function add(a: number, b: number): number {
  return a + b
}
function fetchData(url: string): Promise<Response> {
  return fetch(url)
}
const greet = (name: string) => `Hello, ${name}` as const

type AddReturn = MyReturnType<typeof add>         // number
type FetchReturn = MyReturnType<typeof fetchData>  // Promise<Response>
type GreetReturn = MyReturnType<typeof greet>      // `Hello, ${string}`
```

### Parameters：提取参数元组类型

```typescript
// 内置 Parameters 的简化实现
type MyParameters<T extends (...args: any) => any> =
  T extends (...args: infer P) => any ? P : never

// 示例
function createUser(name: string, age: number, active?: boolean): void {}

type CreateParams = MyParameters<typeof createUser>
// [name: string, age: number, active?: boolean | undefined]
// 返回的是一个元组类型，保留了参数名和可选性

// 实际应用：将参数传递给另一个函数
function wrapCreateUser(...args: CreateParams): void {
  console.log('Creating user with:', args)
  createUser(...args)
}
```

### ThisParameterType / OmitThisParameter：this 参数处理

```typescript
// 提取 this 参数类型
function toHex(this: Number): string {
  return this.toString(16)
}

type ThisArg = ThisParameterType<typeof toHex>  // Number

// 移除 this 参数后的函数类型
type NoThis = OmitThisParameter<typeof toHex>
// () => string
```

### 函数重载时的行为

当函数存在多个重载签名时，`ReturnType` 取**最后一个**（即实现签名的）返回值类型：

```typescript
interface Overloaded {
  (x: string): string
  (x: number): number
  (x: boolean): boolean
}

// 使用最后一个重载签名的返回值
type OverRet = ReturnType<Overloaded>  // boolean
```

### 实战：高阶函数包装器的类型推导

```typescript
/**
 * 带日志的高阶函数包装器
 * 完美保留原函数的参数和返回值类型
 */
function withLog<T extends (...args: any[]) => any>(fn: T): T {
  return function (this: unknown, ...args: Parameters<T>): ReturnType<T> {
    console.log(`[CALL] ${fn.name || 'anonymous'}(${args.map(String).join(', ')})`)
    const result = fn.apply(this, args)
    console.log(`[RETURN]`, result)
    return result
  } as T
}

const safeAdd = withLog(function add(a: number, b: number): number {
  return a + b
})

// safeAdd 的类型完美保留：(a: number, b: number) => number
const result = safeAdd(3, 5)  // result: number，类型推导完全正确
```

## 5. 提取 Promise 内部类型

异步编程是现代 JavaScript/TypeScript 的核心范式，`infer` 在处理 Promise 类型时尤为重要。

### 解包单层 Promise

```typescript
type UnwrapPromise<T> = T extends Promise<infer V> ? V : never

type AsyncNum = UnwrapPromise<Promise<number>>          // number
type AsyncStr = UnwrapPromise<Promise<string>>          // string
type AsyncNested = UnwrapPromise<Promise<Promise<boolean>>>  // Promise<boolean>（只解一层）
type NotAPromise = UnwrapPromise<string>                // never
```

### 处理 Promise 嵌套与 Awaited（TS 4.5+）

TypeScript 4.5 引入了内置的 `Awaited` 工具类型，支持递归解包所有层级的 Promise：

```typescript
/**
 * Awaited 的简化实现思路（实际源码更完善）
 */
type MyAwaited<T> =
  T extends null | undefined ? T :
  T extends Promise<infer V> ? MyAwaited<V> : T

// 使用示例
type DeepUnwrap = MyAwaited<Promise<Promise<Promise<string>>>>  // string

// async 函数的返回值自动包装了一层 Promise
async function getUserId(): Promise<number> {
  return 42
}
type UserId = MyAwaited<ReturnType<typeof getUserId>>  // number
```

### async 函数返回值的类型提取

```typescript
// 综合应用：提取任意函数的"最终返回值"（自动解包 Promise）
type FinalReturn<T extends (...args: any[]) => any> =
  MyAwaited<ReturnType<T>>

async function fetchUser(): Promise<{ id: number; name: string }> {
  return { id: 1, name: 'Alice' }
}

function syncGetConfig(): { theme: string } {
  return { theme: 'dark' }
}

type UserData = FinalReturn<typeof fetchUser>    // { id: number; name: string }
type ConfigData = FinalReturn<typeof syncGetConfig> // { theme: string }
```

## 6. 提取构造函数类型

### InstanceType：从构造函数获取实例类型

```typescript
// 内置 InstanceType 的简化实现
type MyInstanceType<T extends abstract new (...args: any) => any> =
  T extends abstract new (...args: any) => infer I ? I : never

class Person {
  constructor(public name: string, public age: number) {}
  greet() { return `Hi, I'm ${this.name}` }
}

type PersonInstance = MyInstanceType<typeof Person>
// PersonInstance = Person（即通过 new Person() 得到的实例类型）

// 可以用来约束工厂函数的返回类型
function createInstance<C extends abstract new (...args: any) => any>(
  ctor: C,
  ...args: ConstructorParameters<C>
): MyInstanceType<C> {
  return new ctor(...args)
}

const person = createInstance(Person, 'Bob', 25)
// person 的类型是 Person，拥有 name、age 和 greet()
person.greet()  // ✅ 正确
person.foo()    // ❌ 编译错误：Person 没有 foo 方法
```

### ConstructorParameters：获取构造函数参数

```typescript
type MyConstructorParameters<T extends abstract new (...args: any) => any> =
  T extends abstract new (...args: infer P) => any ? P : never

type CtorParams = MyConstructorParameters<typeof Person>
// [name: string, age: number]

// 与 InstanceType 配合使用，实现类型安全的对象克隆
function cloneInstance<T extends abstract new (...args: any) => any>(
  instance: MyInstanceType<T>,
  ctor: T,
  ...args: MyConstructorParameters<T>
): MyInstanceType<T> {
  return new ctor(...args)
}
```

### 与 new() 约束配合使用

```typescript
// 泛型约束：确保传入的是构造函数
function invokeConstructor<C extends abstract new () => any>(
  ctor: C
): InstanceType<C> {
  return new ctor()
}

class Engine {}
class Wheel {}
class Car {
  constructor(
    public engine: Engine,
    public wheels: Wheel[]
  ) {}
}

const engine = invokeConstructor(Engine)
const car = invokeConstructor(Car)  // ❌ 编译错误：Car 需要 engine 和 wheels 参数
```

## 7. infer 在字符串模板中的使用

TypeScript 支持在模板字面量类型中使用 `infer` 来提取字符串的子部分。

### 提取前缀和后缀

```typescript
/**
 * 提取 "prefix_rest" 格式中的 prefix 部分
 */
type GetPrefix<S extends string> =
  S extends `${infer P}_${infer Rest}` ? P : never

/**
 * 提取 ".ext" 扩展名
 */
type GetExt<S extends string> =
  S extends `${infer Name}.${infer Ext}` ? Ext : never

type Prefix1 = GetPrefix<'user_name'>      // 'user'
type Prefix2 = GetPrefix<'config_value'>   // 'config'

type Ext1 = GetExt<'photo.jpg'>            // 'jpg'
type Ext2 = GetExt<'archive.tar.gz'>       // 'gz'（注意：只取最后一个点之后的部分）
type Ext3 = GetExt<'README'>               // never（没有扩展名）
```

### Split 字符串的实现思路

```typescript
/**
 * 将字符串按分隔符拆分为元组
 * 这是一个递归实现的简化版 Split
 */
type Split<
  S extends string,
  Delim extends string
> = S extends `${infer Head}${Delim}${infer Tail}`
  ? [Head, ...Split<Tail, Delim>]
  : [S]

type PathParts = Split<'usr/local/bin', '/'>
// ['usr', 'local', 'bin']

type CSVRow = Split<'apple,banana,cherry', ','>
// ['apple', 'banana', 'cherry']
```

### 路由路径参数提取

这是一个非常实用的实战场景——从路由路径模板中提取动态参数：

```typescript
/**
 * 从路径 "/users/:userId/posts/:postId" 中提取参数名和对应的值类型
 */

// 第一步：提取路径段
type PathSegments<P extends string> = Split<P, '/'>
// ['/users/:userId', ':posts/:postId']

// 第二步：识别以 : 开头的动态段
type IsParam<S extends string> = S extends `:${string}` ? true : false

// 第三步：提取参数名称
type ExtractParamName<S extends string> =
  S extends `:${infer Name}` ? Name : never

type ParamName = ExtractParamName<':userId'>  // 'userId'

// 第四步：完整提取路径中的所有参数名
type ExtractPathParams<P extends string> =
  PathSegments<P>[number] extends `:${infer Param}` ? Param : never
  // 简化版：实际需要遍历每个段来判断

// 更完整的实现
type CollectParams<Segments extends any[], Acc extends string = ''> =
  Segments extends [infer First, ...infer Rest]
    ? First extends `:${infer Name}`
      ? CollectParams<Rest, Acc extends '' ? Name : `${Acc}&${Name}`>
      : CollectParams<Rest, Acc>
    : Acc

type RouteParams = CollectParams<PathSegments<'/users/:userId/posts/:postId'>>
// 'userId&postId'
```

## 8. 多个 infer 同时使用

在一个条件类型中，可以在不同位置同时声明多个 `infer` 变量。

### 元组元素逐个提取

```typescript
/**
 * 提取二元组的两个元素
 */
type PairElements<T> = T extends [infer First, infer Second]
  ? [First, Second]
  : never

type Pair = PairElements<[string, number]>
// [string, number]

type Triple = PairElements<[boolean, string, number]>
// never（不匹配二元组模式）
```

### 函数参数列表的解构

```typescript
/**
 * 提取函数的前两个参数类型
 */
type FirstTwoParams<T extends (...args: any) => any> =
  T extends (arg0: infer A0, arg1: infer A1, ...rest: any[]) => any
    ? [A0, A1]
    : never

function example(x: string, y: number, z: boolean): void {}

type F2 = FirstTwoParams<typeof example>
// [string, number]
```

### 交换元组元素顺序

```typescript
/**
 * 交换二元组的两个元素
 */
type SwapPair<T> = T extends [infer A, infer B] ? [B, A] : never

type Swapped = SwapPair<[string, number]>
// [number, string]
```

### 同一位置多个 infer 的行为（协变 vs 逆变）

这是 `infer` 中一个较为高级且容易踩坑的点：

```typescript
/**
 * 协变位置（如数组元素、函数返回值）：
 * 同一位置的多个 infer 推断结果取联合类型（Union）
 */
type UnionInfer<T> = T extends (infer U)[] ? U : never

type UnionResult = UnionInfer<string[] | number[]>
// string | number
// 因为 T 本身可能是 string[] 或 number[]，
// 所以 U 可能是 string 或 number → 联合类型

/**
 * 逆变位置（如函数参数）：
 * 同一位置的多个 infer 推断结果取交叉类型（Intersection）
 */
type IntersectInfer<T> = T extends (x: infer U) => any ? U : never

type IntersectResult = IntersectInfer<(x: string) => void | (x: number) => void>
// string & number → 即 never（因为没有任何值同时满足 string 和 number）
// 这是因为要使函数类型安全，参数必须是所有可能情况都能接受的类型

// 一个更有意义的例子
type CallbackInfer = IntersectInfer<(x: { name: string }) => void | (x: { name: string; age: number }) => void>
// { name: string } & { name: string; age: number }
// = { name: string; age: number }
// 这是正确的：回调函数必须同时兼容两种签名，所以参数必须同时满足两者
```

**规则总结**：
- **协变位置**（输出端）：`infer` 取 **联合类型**
- **逆变位置**（输入端）：`infer` 取 **交叉类型**

这个设计的原因与 TypeScript 的类型系统安全性有关——它保证了在分布式条件类型场景下不会出现类型漏洞。

## 9. infer + 条件类型递归

递归条件类型是 `infer` 的高级用法，可以实现复杂的类型变换。需要注意 TypeScript 对递归深度的限制（通常几十到几百层）。

### Flatten：深度拍平数组

```typescript
/**
 * 递归拍平任意维度的数组
 *
 * 思路：
 * 1. 如果元素本身是数组，则继续递归展开
 * 2. 如果元素不是数组，则保留原样
 */
type Flatten<T extends any[]> =
  T extends [infer First, ...infer Rest]
    ? First extends any[]
      ? [...Flatten<First>, ...Flatten<Rest>]  // 首元素是数组，递归展开
      : [First, ...Flatten<Rest>]               // 首元素不是数组，保留并继续
    : []

type Flat1 = Flatten<[[1, 2], [3, [4, 5]], 6]>
// [1, 2, 3, 4, 5, 6]

type Flat2 = Flatten<[[[['a']]]]>
// ['a']
```

### Reverse：反转元组

```typescript
/**
 * 反转元组顺序
 *
 * 思路：逐个取出首元素放到结果末尾
 */
type Reverse<T extends any[], Acc extends any[] = []> =
  T extends [infer First, ...infer Rest]
    ? Reverse<Rest, [First, ...Acc]>  // 将首元素移到累加器前面
    : Acc

type Reversed = Reverse<[1, 2, 3, 4, 5]>
// [5, 4, 3, 2, 1]
```

### 字符串替换

```typescript
/**
 * 替换字符串中第一次出现的子串
 */
type Replace<
  S extends string,
  From extends string,
  To extends string
> = From extends ''
  ? S
  : S extends `${infer Start}${From}${infer End}`
    ? `${Start}${To}${End}`
    : S

type Replaced = Replace<'hello world', 'world', 'TypeScript'>
// 'hello TypeScript'

type NotReplaced = Replace<'hello world', 'foo', 'bar'>
// 'hello world'（没有匹配到，返回原字符串）
```

### 递归深度性能考虑

```typescript
// ⚠️ 注意：TypeScript 对条件类型递归有深度限制
// 过深的嵌套可能导致编译器报错或性能问题

// 安全范围通常在 50-100 层以内
type SafeDepth = Flatten<[1, 2, 3, 4, 5]>  // ✅ 正常工作

// 极深层级可能触发 TS2589: Type instantiation is excessively deep and possibly infinite.
// 如果遇到此类问题，考虑：
// 1. 设置递归上限
// 2. 使用迭代式的替代方案
// 3. 简化类型逻辑

// 设置递归上界的示例
type FlattenWithLimit<
  T extends any[],
  Depth extends number = 10,
  Current extends any[] = []
> = Current['length'] extends Depth
  ? T  // 到达深度限制，停止递归
  : T extends [infer F, ...infer R]
    ? F extends any[]
      ? FlattenWithLimit<[...FlattenWithLimit<F, Depth, [any, ...Current]>, ...R], Depth, Current>
      : [F, ...FlattenWithLimit<R, Depth, Current>]
    : T
```

## 10. 内置工具类型的 infer 原理剖析

理解 TypeScript 内置工具类型的源码级实现，是掌握 `infer` 的最佳方式。

### ReturnType 源码解析

```typescript
// TypeScript 内置（lib.d.ts 中）
/**
 * Obtain the return type of a function type.
 */
type ReturnType<T extends (...args: any) => any> =
  T extends (...args: any) => infer R ? R : any
```

关键设计决策：
- 约束 `T extends (...args: any) => any` 确保传入的是函数类型
- 用 `(infer R)` 占位返回值位置
- fallback 为 `any`（而非 `never`），因为函数一定有返回值（即使隐式返回 undefined）

### Parameters 源码解析

```typescript
// TypeScript 内置
/**
 * Obtain the parameters of a function type in a tuple.
 */
type Parameters<T extends (...args: any) => any> =
  T extends (...args: infer P) => any ? P : readonly any[]
```

注意 fallback 是 `readonly any[]` 而非 `never`，保证即使非函数类型也不会报错。

### ConstructorParameters & InstanceType

```typescript
// ConstructorParameters
type ConstructorParameters<T extends abstract new (...args: any) => any> =
  T extends abstract new (...args: infer P) => any ? P : never

// InstanceType
type InstanceType<T extends abstract new (...args: any) => any> =
  T extends abstract new (...args: any) => infer I ? I : any
```

关键区别在于约束使用 `abstract new (...args: any) => any`，这表示抽象或非抽象的构造函数签名。

### Awaited（TS 4.5+）源码

```typescript
/**
 * Recursively unwrap Promises to get their non-Promise resolved type.
 * @since 4.5
 */
type Awaited<T> =
  T extends null | undefined ? T :                      // 处理 null/undefined
  T extends PromiseLike<infer V> ? Awaited<V> : T        // 递归解包 Promise
```

设计要点：
- 先处理原始类型（null、undefined），避免不必要的递归
- 使用 `PromiseLike` 而非 `Promise`，兼容 thenable 对象
- 递归结构简洁优雅，但需注意上述的深度限制

## 11. 常见错误与陷阱

### 陷阱 1：infer 必须在 extends 子句的模式中

```typescript
// ❌ 错误：infer 不能出现在普通位置
type Wrong1 = infer X

// ❌ 错误：infer 不能在 true 分支中
type Wrong2<T> = T extends string ? infer Y : never

// ❌ 错误：infer 不能在 false 分支中
type Wrong3<T> = T extends string ? number : infer Z

// ✅ 正确：只在 extends 右侧的模式中使用
type Right<T> = T extends Promise<infer V> ? V : never
```

### 陷阱 2：推断失败时的 fallback 行为

```typescript
type TryExtract<T> = T extends { a: infer Val } ? Val : never

type Success = TryExtract<{ a: string }>  // string — 匹配成功，Val = string
type Fail = TryExtract<{ b: number }>     // never  — 匹配失败，走 false 分支

// 💡 设计建议：根据语义选择合适的 fallback
// - 如果提取失败意味着"不应该传入此类型"，用 never（严格）
// - 如果提取失败时希望保持原类型，用 T（宽容）
// - 如果不确定，用 unknown（安全）
type LenientExtract<T> = T extends Array<infer E> ? E : T
type UnknownFallback<T> = T extends Array<infer E> ? E : unknown
```

### 陷阱 3：never 类型的特殊处理

```typescript
type CheckNever<T> = T extends infer U ? U : never

type Test1 = CheckNever<string>   // string
type Test2 = CheckNever<never>    // never！

// never 在条件类型中有特殊行为：
// 它会被"分发"成空联合类型，导致整体结果为 never
// 这是分布式条件类型的一个边界行为

// 如果想让 never 正常流经 infer，可以用元组包裹
type SafeCheck<T> = [T] extends [infer U] ? U : never
type Test3 = SafeCheck<never>  // never，但这次是正确的行为
```

### 陷阱 4：分布式条件类型与 infer 的交互

```typescript
// 分布式条件类型：当类型参数是裸类型参数时，条件类型会自动分发到联合类型的每个成员
type Distributed<T> = T extends Array<infer E> ? E : never

type DistResult = Distributed<string[] | number[] | boolean>
// string | number
// 解释：
//   string[] → string
//   number[] → number
//   boolean → never（不是数组）
// 合并 → string | number

// 如果不想触发分布行为，用元组包裹
type NonDistributed<T> = [T] extends [Array<infer E>] ? E : never

type NonDistResult = NonDistributed<string[] | number[] | boolean>
// string | number
// 这次是因为 [string[] | number[] | boolean] 作为整体去匹配 [Array<infer E>]
// 整体匹配失败（boolean 不是数组），所以返回 never
// 但实际上这里的结果取决于具体写法...
// 核心要点：裸类型参数触发分发，包裹后不触发
```

### 陷阱 5：过度使用导致可读性问题

```typescript
// ❌ 反面示例：过度复杂的 infer 链式调用
type BadIdea<T> =
  T extends ((...a: infer A) => infer B)
    ? B extends (x: infer C) => infer D
      ? D extends Promise<infer E>
        ? E[keyof E] extends infer F
          ? F
          : never
        : never
      : never
    : never

// ✅ 推荐：分解为多个有命名的中间类型
type FuncInfo<T extends (...args: any) => any> = {
  params: Parameters<T>
  return: ReturnType<T>
}

type UnpackedReturn<T> = T extends Promise<infer V> ? V : T

type DeepKey<T> = keyof T extends infer K ? K : never
```

### 案例 2：API 响应数据解包器

```typescript
/**
 * 通用的 API 响应解包工具类型
 * 支持 Promise 包装和数据字段提取
 */

interface ApiResponse<T> {
  code: number
  message: string
  data: T
  timestamp: number
}

/**
 * 从 API 响应类型中提取 data 字段的类型
 */
type ResponseData<T> = T extends Promise<ApiResponse<infer D>> ? D
  : T extends ApiResponse<infer D> ? D : T

// API 函数定义
async function fetchUsers(): Promise<ApiResponse<User[]>> {
  return { code: 200, message: 'ok', data: [], timestamp: Date.now() }
}

async function getConfigSync(): ApiResponse<AppConfig> {
  return { code: 200, message: 'ok', data: { theme: 'dark' }, timestamp: Date.now() }
}

// 类型提取
type UsersData = ResponseData<ReturnType<typeof fetchUsers>>
// User[] — 自动穿透 Promise 和 ApiResponse

type ConfigData = ResponseData<ReturnType<typeof getConfigSync>>
// AppConfig — 直接提取 ApiResponse 中的 data

// 封装一个安全的 API 调用函数
async function safeApiCall<T extends (...args: any[]) => Promise<any>>(
  apiFn: T,
  ...args: Parameters<T>
): Promise<ResponseData<ReturnType<T>>> {
  const response = await apiFn(...args)
  if (response.code !== 200) {
    throw new Error(response.message)
  }
  return response.data
}
```

### 案例 3：DeepPromiseResolve —— 递归解包所有层级

```typescript
/**
 * 递归解包任意层级的 Promise（以及类 Promise 结构）
 * 比 Awaited 更激进：也解包 { then: () => any } 形式的 thenable
 */
type DeepResolve<T> =
  T extends null | undefined
    ? T
    : T extends PromiseLike<infer Inner>
      ? DeepResolve<Inner>
      : T extends { then: (fn: (val: infer V) => any) => any }
        ? DeepResolve<V>
        : T

// 测试各种嵌套层级
type Level1 = DeepResolve<Promise<string>>                        // string
type Level2 = DeepResolve<Promise<Promise<number>>>               // number
type Level3 = DeepResolve<Promise<Promise<Promise<boolean>>>>     // boolean

// 处理混合嵌套
type Mixed = DeepResolve<Promise<{ status: 'ok', data: Promise<string[]> }>>
// { status: 'ok'; data: string[] }

// 处理 thenable 对象
class CustomThenable {
  then(fn: (val: number) => void) { fn(42) }
}
type ThenableResult = DeepResolve<CustomThenable>  // number
```

### 案例 4：函数组合（compose/pipe）的完整类型实现

```typescript
/**
 * 类型安全的函数组合
 * compose(f, g)(x) 等价于 f(g(x))
 * pipe(x, f, g) 等价于 g(f(x))
 */

// 辅助类型：获取两个可组合函数的组合结果类型
type ComposeResult<F, G> =
  G extends (...args: infer A) => infer RG
    ? F extends (arg: RG) => infer RF
      ? (...args: A) => RF
      : never
    : never

// 两函数 compose
function compose2<A, B, C>(
  f: (b: B) => C,
  g: (a: A) => B
): (a: A) => C {
  return (a: A) => f(g(a))
}

// 泛化版本：支持任意数量的函数组合
type ComposeAny<Fns extends any[]> =
  Fns extends [(...args: infer A) => infer R]
    ? (...args: A) => R
    : Fns extends [...any[], (arg: infer LastArg) => infer LastRet]
      ? ComposeAny<Init<Fns>> extends (...args: any[]) => LastArg
        ? (...args: Parameters<ComposeAny<Init<Fns>>>) => LastRet
        : never
      : never

// 辅助类型：去掉元组的最后一个元素（简化实现）
type Init<T extends any[]> = T extends [...infer I, any] ? I : []

// 使用示例
function toString(n: number): string { return n.toString() }
function toLength(s: string): number { return s.length }
function isEven(n: number): boolean { return n % 2 === 0 }

const composed = compose2(isEven, toLength)
// (s: string) => boolean
const result = composed('hello')  // true（长度为 5，奇数... 等等应该是 false 😅）
```

## 13. 总结与最佳实践

### 何时应该使用 infer

| 场景 | 是否推荐 infer | 说明 |
|------|---------------|------|
| 从函数/构造函数中提取参数/返回值类型 | ✅ 首选 | 这是 infer 的核心用途 |
| 从 Promise/Array 等容器类型中解包 | ✅ 首选 | 标准做法 |
| 字符串模板解析与提取 | ✅ 适用 | TS 4.1+ 支持良好 |
| 复杂的条件类型变换 | ⚠️ 谨慎 | 优先考虑能否用已有内置类型组合 |
| 超过 3 层的嵌套 infer 链 | ❌ 避免 | 可读性差，维护成本高 |

### 性能考量

1. **递归深度**：TypeScript 编译器对条件类型递归有限制（约 50-100 层），超出会报 `Type instantiation is excessively deep` 错误
2. **计算复杂度**：涉及联合类型的分布式条件类型会对每个成员分别求值，成员过多时可能影响编译速度
3. **缓存友好**：TypeScript 会缓存相同类型参数的工具类型实例化结果，重复使用已计算的 infer 结果不会有额外开销

### 可读性建议

```typescript
// ✅ 好的做法
/** 从 API 响应中提取数据字段的类型 */
type ApiData<T> = T extends { data: infer D } ? D : never

// 给中间步骤起有意义的名字
type RawResponse = Promise<{ items: Item[]; total: number }>
type Items = DeepResolve<RawResponse> extends { items: infer It } ? It : never

// ❌ 避免的做法
// 一行代码塞满 infer 链，无注释，无中间类型
type Bad<T>=T extends Promise<{data:infer D}>?D[keyof D] extends infer K?K:never:never
```

### 核心心法

`infer` 的本质是在**编译期做模式匹配与类型解构**。把它理解为"类型级别的解构赋值"最为贴切——正如运行时可以从数组/对象中解构出元素一样，编译期也可以从类型结构中提取出子类型。掌握了这一点，就能理解为什么 `ReturnType` 能提取返回值、`Parameters` 能提取参数、`Awaited` 能解包 Promise——它们都是在对应的位置放上一个 `infer` 占位符，让编译器把那部分的类型"抓"出来。
