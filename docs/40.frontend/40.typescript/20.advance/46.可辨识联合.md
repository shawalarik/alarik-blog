## 什么是可辨识联合？

在类型系统理论中，**可辨识联合（Discriminated Union）**，也称为 **Tagged Union** 或 **Algebraic Data Type 中的变体（Variant）**，是一种特殊的联合类型：它的每个成员都携带一个共同的判别属性（discriminant），且该属性在每个成员中取不同的字面量值。

从数学角度看，可辨识联合是带标签的不相交并集。TypeScript 通过控制流分析（Control Flow Analysis）识别这种模式，并在运行时根据判别属性的值自动收窄类型。

### 形式化定义

一个合法的可辨识联合必须满足三个条件：

1. 所有成员共享一个公共属性名（判别属性）
2. 该属性的类型必须是字面量类型（string literal / number literal / boolean / enum）
3. 不同成员的判别属性取值互不相同

```typescript
// 标准的可辨识联合
type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'rectangle'; width: number; height: number }
  | { kind: 'triangle'; base: number; height: number }

// kind 就是判别属性（discriminant），它的字面量值唯一标识了每个成员
```

### 与普通联合类型的区别

普通联合类型没有结构化的判别机制，TypeScript 无法自动进行精确的分支推断：

```typescript
// 普通联合 —— 无法自动按成员区分
type CommonUnion = Circle | Rectangle | Triangle

// 需要手动使用类型守卫（type guard）来收窄
function isCircle(shape: CommonUnion): shape is Circle {
  return 'radius' in shape
}

// 可辨识联合 —— 自动收窄
function area(shape: Shape): number {
  // switch 对 shape.kind 的判断会自动收窄 shape 的类型
  switch (shape.kind) {
    case 'circle':
      // 此处 shape 被自动收窄为 { kind: 'circle', radius: number }
      return Math.PI * shape.radius ** 2
    case 'rectangle':
      // 此处 shape 被自动收窄为 { kind: 'rectangle', width: number; height: number }
      return shape.width * shape.height
    case 'triangle':
      // 此处 shape 被自动收窄为 { kind: 'triangle', base: number; height: number }
      return (shape.base * shape.height) / 2
  }
}
```

关键区别在于：**普通联合依赖开发者编写的类型守卫来实现收窄，而可辨识联合利用已有的数据结构本身作为判别依据，TypeScript 编译器能直接理解并自动化这一过程。**

## 判别属性的语法要求

### 字面量类型约束

判别属性必须是字面量类型或由字面量组成的联合类型。这是 TypeScript 控制流分析能够工作的基础——编译器需要知道所有可能的离散取值。

```typescript
// 合法的判别属性类型

// 1. 字符串字面量（最常用）
type RequestState =
  | { status: 'idle' }
  | { status: 'loading'; progress: number }
  | { status: 'success'; data: string }
  | { status: 'error'; message: string }

// 2. 数字字面量
type HttpStatusCode =
  | { code: 200; body: string }
  | { code: 404; reason: string }
  | { code: 500; error: Error }

// 3. 布尔值
type ToggleState =
  | { on: true; value: string }
  | { on: false }

// 4. 枚举（枚举的值本质上也是一组离散常量）
enum EventType { Click = 'CLICK', Focus = 'FOCUS', Blur = 'BLUR' }
type DOMEvent =
  | { type: EventType.Click; x: number; y: number }
  | { type: EventType.Focus; target: HTMLElement }
  | { type: EventType.Blur; relatedTarget: HTMLElement | null }
```

### 非法形式

以下写法**不会**被 TypeScript 识别为可辨识联合：

```typescript
// 错误：判别属性是宽泛的 string 类型
type BadUnion1 =
  | { type: string; a: number }   // type 可以是任意字符串
  | { type: string; b: boolean }  // 无法区分

// 错误：判别属性不是公共属性
type BadUnion2 =
  | { tag: 'A', value: number }
  | { label: 'B', text: string }  // 属性名不同

// 错误：判别属性值不唯一
type BadUnion3 =
  | { kind: 'rect', width: number }
  | { kind: 'rect', height: number }  // 两个成员的 kind 值相同
```

### 多判别属性

TypeScript 支持多个属性组合作为判别依据，但实际场景中较少使用：

```typescript
type MultiDiscriminant =
  | { category: 'math', op: 'add'; left: number; right: number }
  | { category: 'math', op: 'sub'; left: number; right: number }
  | { category: 'text', op: 'concat'; parts: string[] }
  | { category: 'text', op: 'split'; source: string; delimiter: string }

function evalMulti(expr: MultiDiscriminant): unknown {
  if (expr.category === 'math') {
    // 收窄为前两个成员的联合
    if (expr.op === 'add') {
      return expr.left + expr.right  // 进一步收窄
    }
    return expr.left - expr.right
  }
  // 收窄为后两个成员的联合
  if (expr.op === 'concat') {
    return expr.parts.join('')
  }
  return expr.source.split(expr.delimiter)
}
```

## 类型收窄机制深度解析

### 控制流分析如何工作

TypeScript 的控制流分析引擎会在代码执行路径上追踪变量的可能类型集合。对于可辨识联合，当检测到对判别属性的等值检查时，编译器会自动将联合类型过滤为匹配的成员。

```typescript
type Result<T> =
  | { success: true; data: T }
  | { success: false; error: Error }

function handleResult<T>(result: Result<T>): string {
  // 检查点 A：result 的完整类型是 Result<T>
  
  if (result.success) {
    // 检查点 B：result 被收窄为 { success: true; data: T }
    return `OK: ${JSON.stringify(result.data)}`
    //        ^^^^ data 在此分支一定存在
  } else {
    // 检查点 C：result 被收窄为 { success: false; error: Error }
    return `Error: ${result.error.message}`
    //              ^^^^^^ error 在此分支一定存在
  }
}
```

收窄的核心逻辑可以概括为：

```
原始类型: T1 | T2 | T3 | ... | Tn
判别条件: x.discriminant === value_k（value_k 是 Tk 的判别值）
收窄结果: Tk（排除所有其他 Ti，i ≠ k）
```

### switch 语句中的完整收窄

switch 语句天然适合处理可辨识联合，因为每个 case 分支对应一个判别值：

```typescript
type NetworkResponse =
  | { status: 'pending'; requestId: string }
  | { status: 'success'; payload: JSONValue }
  | { status: 'failure'; errorCode: number; errorMessage: string }
  | { status: 'timeout'; elapsed: ms }

function renderResponse(resp: NetworkResponse): ReactNode {
  switch (resp.status) {
    case 'pending':
      // resp: { status: 'pending', requestId: string }
      return <Spinner text={`Request ${resp.requestId}...`} />

    case 'success':
      // resp: { status: 'success', payload: JSONValue }
      return <DataViewer data={resp.payload} />

    case 'failure':
      // resp: { status: 'failure', errorCode: number, errorMessage: string }
      return <ErrorCard code={resp.errorCode} msg={resp.errorMessage} />

    case 'timeout':
      // resp: { status: 'timeout', elapsed: number }
      return <RetryButton elapsed={resp.elapsed} />
  }
}
```

### 函数参数中的收窄行为

当函数接收可辨识联合类型的参数时，收窄发生在函数体内部：

```typescript
type AsyncAction =
  | { type: 'FETCH_USER'; userId: string }
  | { type: 'CREATE_POST'; title: string; content: string }
  | { type: 'DELETE_COMMENT'; commentId: string; postId: string }

async function dispatchAction(action: AsyncAction): Promise<void> {
  const apiClient = getAPIClient()

  switch (action.type) {
    case 'FETCH_USER': {
      // action 被收窄为 FETCH_USER 类型
      const user = await apiClient.get(`/users/${action.userId}`)
      store.set('currentUser', user)
      break
    }
    case 'CREATE_POST': {
      // action 被收窄为 CREATE_POST 类型
      const post = await apiClient.post('/posts', {
        title: action.title,
        content: action.content,
      })
      router.push(`/posts/${post.id}`)
      break
    }
    case 'DELETE_COMMENT': {
      // action 被收窄为 DELETE_COMMENT 类型
      await apiClient.delete(
        `/posts/${action.postId}/comments/${action.commentId}`
      )
      break
    }
  }
}
```

## 经典实战案例：Result 模式

### 问题背景

JavaScript/TypeScript 中处理可能失败的操作通常有两种方式：

1. **try-catch 异常机制**：控制流不直观，异常信息类型不明确
2. **返回 null/undefined + 外部错误变量**：类型不安全，容易遗漏空检查

Result 模式提供了一种显式的、类型安全的错误处理方式，其核心就是可辨识联合。

### Result 类型定义

```typescript
/**
 * Result<T, E> — 表示操作可能成功返回 T 类型的值，
 * 或失败返回 E 类型的错误。
 *
 * 设计灵感来源于 Rust 的 std::result::Result<T, E>
 */
type Result<T, E = Error> =
  | { ok: true; value: T }
  | { ok: false; error: E }

// 便捷构造器
const Ok = <T>(value: T): Result<T, never> => ({ ok: true, value })
const Err = <E>(error: E): Result<never, E> => ({ ok: false, error })
```

### 使用示例

```typescript
/**
 * 安全解析 JSON 字符串
 * 返回 Result 而非抛出异常
 */
function safeParseJSON<T>(input: string): Result<T, SyntaxError> {
  try {
    const value = JSON.parse(input) as T
    return Ok(value)
  } catch (e) {
    if (e instanceof SyntaxError) {
      return Err(e)
    }
    // 将非 SyntaxError 包装
    return Err(new SyntaxError(`Invalid JSON: ${String(e)}`))
  }
}

/**
 * 使用 Result 的业务代码
 */
function processConfig(raw: string): string {
  const result = safeParseJSON<{ apiUrl: string; timeout: number }>(raw)

  // 可辨识联合让每个分支都有完整的类型信息
  if (result.ok) {
    // result.value 存在且类型为 { apiUrl: string; timeout: number }
    console.log(`API URL: ${result.value.apiUrl}`)
    console.log(`Timeout: ${result.value.timeout}ms`)
    return result.value.apiUrl
  } else {
    // result.error 存在且类型为 SyntaxError
    console.error(`配置解析失败 (行 ${result.error.lineNumber}): ${result.message}`)
    return '/api/default'
  }
}

// 使用 match 风格的处理函数（穷尽性检查）
function unwrapOrFallback<T, E>(
  result: Result<T, E>,
  fallback: T
): T {
  if (result.ok) return result.value
  return fallback
}

// 实际调用
const config = processConfig('{"apiUrl":"https://example.com","timeout":5000}')
```

### 与 try-catch 的对比

| 维度 | try-catch | Result<T, E> |
|------|-----------|---------------|
| 错误类型 | 任意 Error 子类（需 instanceof 过滤） | 泛型参数 E 精确指定 |
| 控制流 | 跳出当前作用域，可能跨越多层调用栈 | 线性流程，就地处理 |
| 编译期保证 | 无——忘记 catch 会导致未捕获异常 | 必须检查 ok 才能访问 value |
| 组合性 | 差——嵌套 try-catch 导致"金字塔"问题 | 好——支持 flatMap / andThen 链式组合 |
| 性能 | V8 中 try 块有少量额外开销 | 零开销（纯对象创建） |

### Result 的链式操作

```typescript
// 为 Result 添加链式方法
interface ResultMethods<T, E> {
  map<U>(fn: (value: T) => U): Result<U, E>
  flatMap<U>(fn: (value: T) => Result<U, E>): Result<U, E>
  mapErr<F>(fn: (error: E) => F): Result<T, F>
  unwrapOr(fallback: T): T
}

function withMethods<T, E>(result: Result<T, E>): Result<T, E> & ResultMethods<T, E> {
  return Object.assign(result, {
    map<U>(fn: (value: T) => U): Result<U, E> {
      return result.ok ? Ok(fn(result.value)) : result as unknown as Result<U, E>
    },
    flatMap<U>(fn: (value: T) => Result<U, E>): Result<U, E> {
      return result.ok ? fn(result.value) : result as unknown as Result<U, E>
    },
    mapErr<F>(fn: (error: E) => F): Result<T, F> {
      return result.ok ? result as unknown as Result<T, F> : Err(fn(result.error))
    },
    unwrapOr(fallback: T): T {
      return result.ok ? result.value : fallback
    },
  })
}

// 链式调用示例
function fetchUserProfile(userId: string): Promise<Result<UserProfile, NetworkError>> {
  return fetch(`/api/users/${userId}`)
    .then(res => res.json())
    .then(data => withMethods(Ok(data)))
    .catch(err => withMethods(Err(new NetworkError(err.message))))
}

// 使用链式操作
fetchUserProfile('u123')
  .then(result =>
    withMethods(result)
      .map(profile => profile.avatarUrl)       // 成功时提取头像URL
      .flatMap(url => fetchImage(url))          // 再发起一次请求
      .mapErr(err => new DisplayError(err))     // 转换错误类型
      .unwrapOr('/default-avatar.png')          // 提供默认值
  )
```

## 状态机实现

可辨识联合天然适合建模有限状态机（Finite State Machine）。每个状态是一个联合成员，状态转换通过判别属性驱动。

### 基础状态机模型

```typescript
/**
 * 订单状态机
 *
 * 状态转换规则：
 *   Created -> Paid -> Shipped -> Delivered
 *                        \-> Cancelled
 *   Created -> Cancelled
 */
type OrderState =
  | { status: 'created'; orderId: string; items: OrderItem[]; total: number }
  | { status: 'paid'; paymentId: string; paidAt: Date }
  | { status: 'shipped'; trackingNumber: string; shippedAt: Date }
  | { status: 'delivered'; deliveredAt: Date }
  | { status: 'cancelled'; reason: string; cancelledAt: Date }

// 定义合法的状态转换映射
type ValidTransitions = {
  created: 'paid' | 'cancelled'
  paid: 'shipped' | 'cancelled'
  shipped: 'delivered'
  delivered: never           // 终态，无出边
  cancelled: never           // 终态，无出边
}

// 类型安全的转换函数
function transition<S extends keyof ValidTransitions>(
  state: Extract<OrderState, { status: S }>,
  nextStatus: ValidTransitions[S]
): OrderState {
  // 根据目标状态构造新的状态对象
  // 实际实现中这里会有具体的业务逻辑
  switch (nextStatus) {
    case 'paid':
      return { status: 'paid', paymentId: generatePaymentId(), paidAt: new Date() }
    case 'shipped':
      return { status: 'shipped', trackingNumber: generateTrackingNo(), shippedAt: new Date() }
    case 'delivered':
      return { status: 'delivered', deliveredAt: new Date() }
    case 'cancelled':
      return { status: 'cancelled', reason: 'User request', cancelledAt: new Date() }
  }
}
```

### 异步请求状态机（前端核心场景）

这是前端开发中最常见的可辨识联合应用场景之一：

```typescript
/**
 * 异步请求的四种标准状态
 */
type AsyncState<T, E = string> =
  | { phase: 'idle' }                                    // 尚未开始
  | { phase: 'loading'; abortController: AbortController } // 进行中
  | { phase: 'success'; data: T; fetchedAt: number }     // 完成
  | { phase: 'error'; error: E; failedAt: number }       // 失败

/**
 * 状态机驱动的异步请求 Hook（概念实现）
 */
function useAsyncQuery<T>(
  queryFn: () => Promise<T>
): {
  state: AsyncState<T>
  execute: () => void
  reset: () => void
} {
  const [state, setState] = useState<AsyncState<T>>({ phase: 'idle' })

  const execute = useCallback(() => {
    // 只允许从 idle / error 状态启动请求
    if (state.phase !== 'idle' && state.phase !== 'error') return

    const controller = new AbortController()

    setState({ phase: 'loading', abortController: controller })

    queryFn()
      .then(data => {
        setState({
          phase: 'success',
          data,
          fetchedAt: Date.now(),
        })
      })
      .catch(error => {
        setState({
          phase: 'error',
          error: String(error),
          failedAt: Date.now(),
        })
      })

    return () => controller.abort()
  }, [state.phase, queryFn])

  const reset = useCallback(() => {
    setState({ phase: 'idle' })
  }, [])

  return { state, execute, reset }
}

/**
 * 组件中使用 —— 利用可辨识联合的收窄能力做渲染
 */
function UserProfile({ userId }: { userId: string }) {
  const { state, execute } = useAsyncQuery(() => fetchUser(userId))

  // 渲染逻辑完全基于状态机的相位
  return (
    <div className="profile-container">
      {/* 头部始终显示 */}
      <h1>User Profile</h1>

      {state.phase === 'idle' && (
        <button onClick={execute}>Load Profile</button>
      )}

      {state.phase === 'loading' && (
        <>
          <LoadingSpinner />
          <button onClick={() => state.abortController.abort()}>
            Cancel
          </button>
        </>
      )}

      {state.phase === 'success' && (
        <ProfileCard
          name={state.data.name}
          email={state.data.email}
          avatar={state.data.avatar}
        />
      )}

      {state.phase === 'error' && (
        <div className="error-panel">
          <p>Failed to load: {state.error}</p>
          <button onClick={execute}>Retry</button>
        </div>
      )}
    </div>
  )
}
```

这个模式的威力在于：

1. **不可能出现非法状态**：不存在 `phase: 'loading'` 但 `data` 有值的矛盾状态
2. **编译期完备性检查**：如果遗漏某个 phase 的处理，配合 exhaustive check 能在编译期发现
3. **自文档化**：状态的定义即文档，新开发者可以直接从类型定义理解全部可能的状态

## Redux/Vuex/Pinia 的 Action 类型安全

### Action 作为可辨识联合

Redux 的 Action 天然符合可辨识联合的结构：`type` 属性作为判别字段，payload 作为伴随数据。

```typescript
/**
 * 定义 Action 可辨识联合
 */
type TodoAction =
  | { type: 'ADD_TODO'; payload: { id: string; text: string } }
  | { type: 'TOGGLE_TODO'; payload: { id: string } }
  | { type: 'DELETE_TODO'; payload: { id: string } }
  | { type: 'SET_FILTER'; payload: FilterType }
  | { type: 'CLEAR_COMPLETED' }

/**
 * State 类型
 */
interface TodoState {
  todos: Todo[]
  filter: FilterType
}

/**
 * Reducer 函数 —— switch 自动收窄
 */
function todoReducer(state: TodoState, action: TodoAction): TodoState {
  switch (action.type) {
    case 'ADD_TODO':
      // action 被收窄为 { type: 'ADD_TODO', payload: { id: string; text: string } }
      return {
        ...state,
        todos: [...state.todos, {
          id: action.payload.id,
          text: action.payload.text,
          completed: false,
        }],
      }

    case 'TOGGLE_TODO':
      // action 被收窄为 { type: 'TOGGLE_TODO', payload: { id: string } }
      return {
        ...state,
        todos: state.todos.map(todo =>
          todo.id === action.payload.id
            ? { ...todo, completed: !todo.completed }
            : todo
        ),
      }

    case 'DELETE_TODO':
      // action 被收窄为 { type: 'DELETE_TODO', payload: { id: string } }
      return {
        ...state,
        todos: state.todos.filter(t => t.id !== action.payload.id),
      }

    case 'SET_FILTER':
      // action 被收窄为 { type: 'SET_FILTER', payload: FilterType }
      return { ...state, filter: action.payload }

    case 'CLEAR_COMPLETED':
      // 这个 action 没有 payload，收窄后只有 type 字段
      return {
        ...state,
        todos: state.todos.filter(t => !t.completed),
      }

    default:
      // 如果使用了 exhaustiveness check，这行永远不会到达
      return state
  }
}
```

### 类型安全的 Dispatch 工具

```typescript
/**
 * 创建类型安全的 dispatch 函数
 * 确保 dispatch 的参数必须是合法的 Action 成员
 */
type Dispatch<A> = (action: A) => void

// Action Creator 工厂
function makeActionCreator<T extends string>() {
  return <P extends Record<string, unknown>>(type: T) =>
    (payload: P): { type: T } & { payload: P } =>
      ({ type, payload } as { type: T } & { payload: P })
}

// 创建具体的 action creators
const addTodo = makeActionCreator<'ADD_TODO'>()('ADD_TODO')
const toggleTodo = makeActionCreator<'TOGGLE_TODO'>()('TOGGLE_TODO')
const deleteTodo = makeActionCreator<'DELETE_TODO'>()('DELETE_TODO')
const setFilter = makeActionCreator<'SET_FILTER'>()('SET_FILTER')
const clearCompleted = () => ({ type: 'CLEAR_COMPLETED' as const })

// 使用示例 —— dispatch 参数类型完全受控
const dispatch: Dispatch<TodoAction> = action => {
  console.log('Dispatching:', action)
}

// 这些都是类型正确的
dispatch(addTodo({ id: '1', text: 'Learn TypeScript' }))
dispatch(toggleTodo({ id: '1' }))
dispatch(setFilter('active'))
```

## AST / 表达式求值器

可辨识联合非常适合表示抽象语法树（AST）节点，因为 AST 本质上是一个递归的变体结构。

### AST 节点定义

```typescript
/**
 * 简单算术表达式的 AST 节点
 * 展示嵌套可辨识联合的使用方式
 */

// 基础表达式类型
type Expr =
  | NumberLiteral
  | BinaryOp
  | UnaryOp
  | VariableRef
  | FunctionCall

// 字面量
interface NumberLiteral {
  kind: 'number'
  value: number
}

// 二元运算
interface BinaryOp {
  kind: 'binary'
  operator: '+' | '-' | '*' | '/'
  left: Expr
  right: Expr
}

// 一元运算
interface UnaryOp {
  kind: 'unary'
  operator: '-' | '!'
  operand: Expr
}

// 变量引用
interface VariableRef {
  kind: 'variable'
  name: string
}

// 函数调用
interface FunctionCall {
  kind: 'call'
  callee: string
  arguments: Expr[]
}
```

### 类型安全的求值器

```typescript
/**
 * 表达式求值器 —— 递归处理可辨识联合
 * 每个分支都能访问到对应节点的完整属性
 */
function evaluate(expr: Expr, env: Map<string, number>): number {
  switch (expr.kind) {
    case 'number':
      // expr: NumberLiteral
      return expr.value

    case 'binary':
      // expr: BinaryOp —— left 和 right 都是 Expr（递归）
      const leftVal = evaluate(expr.left, env)
      const rightVal = evaluate(expr.right, env)

      switch (expr.operator) {
        case '+': return leftVal + rightVal
        case '-': return leftVal - rightVal
        case '*': return leftVal * rightVal
        case '/':
          if (rightVal === 0) throw new Error('Division by zero')
          return leftVal / rightVal
      }

    case 'unary':
      // expr: UnaryOp
      const val = evaluate(expr.operand, env)
      return expr.operator === '-' ? -val : val ? 0 : 1

    case 'variable':
      // expr: VariableRef
      const bound = env.get(expr.name)
      if (bound === undefined) {
        throw new ReferenceError(`${expr.name} is not defined`)
      }
      return bound

    case 'call':
      // expr: FunctionCall
      // 这里可以扩展内置函数表
      switch (expr.callee) {
        case 'abs':
          return Math.abs(evaluate(expr.arguments[0], env))
        case 'min':
          return Math.min(...expr.arguments.map(a => evaluate(a, env)))
        case 'max':
          return Math.max(...expr.arguments.map(a => evaluate(a, env)))
        default:
          throw new Error(`Unknown function: ${expr.callee}`)
      }
  }
}

// ===== 使用示例 =====

// 构建表达式: (2 + 3) * -x
const ast: Expr = {
  kind: 'binary',
  operator: '*',
  left: {
    kind: 'binary',
    operator: '+',
    left: { kind: 'number', value: 2 },
    right: { kind: 'number', value: 3 },
  },
  right: {
    kind: 'unary',
    operator: '-',
    operand: { kind: 'variable', name: 'x' },
  },
}

// 设置环境变量
const env = new Map<string, number>()
env.set('x', 4)

// 求值: (2 + 3) * (-4) = -20
console.log(evaluate(ast, env)) // -20
```

### 类型安全的 AST 转换器

除了求值，AST 的遍历和变换同样受益于可辨识联合的类型收窄：

```typescript
/**
 * AST 变换器 —— 常量折叠优化
 * 在编译期预计算常量子表达式
 */
function optimize(expr: Expr): Expr {
  switch (expr.kind) {
    case 'number':
      return expr  // 叶子节点无需优化

    case 'variable':
      return expr  // 变量无法静态求值

    case 'unary':
      // 先递归优化子节点
      const optimizedOperand = optimize(expr.operand)
      // 如果子节点变成了数字字面量，尝试折叠
      if (optimizedOperand.kind === 'number') {
        const val = expr.operator === '-' ? -optimizedOperand.value : 0
        return { kind: 'number', value: val }
      }
      return { ...expr, operand: optimizedOperand }

    case 'binary':
      const optLeft = optimize(expr.left)
      const optRight = optimize(expr.right)

      // 两边都是常量 → 直接计算
      if (optLeft.kind === 'number' && optRight.kind === 'number') {
        const result = simpleEval(optLeft.value, expr.operator, optRight.value)
        return { kind: 'number', value: result }
      }

      return { ...expr, left: optLeft, right: optRight }

    case 'call':
      // 递归优化参数列表
      return {
        ...expr,
        arguments: expr.arguments.map(arg => optimize(arg)),
      }
  }
}

function simpleEval(left: number, op: '+' | '-' | '*' | '/', right: number): number {
  switch (op) {
    case '+': return left + right
    case '-': return left - right
    case '*': return left * right
    case '/': return right !== 0 ? left / right : NaN
  }
}
```

## 方案对比

| 维度 | 可辨识联合 | class + 继承 | 普通 object + type 字段 |
|------|-----------|-------------|---------------------|
| **类型安全性** | 编译期保证，自动收窄 | 依赖 instanceof 运行时检查 | 手动断言 as，无编译期保障 |
| **运行时开销** | 零开销（纯对象字面量） | 原型链查找开销 | 零开销 |
| **内存占用** | 每个实例独立存储属性 | 共享原型方法，但每实例有隐藏类开销 | 同可辨识联合 |
| **穷尽性检查** | 支持（配合 never 类型） | 不支持 | 不支持 |
| **不可变性** | 天然支持（对象冻结即可） | 需要额外设计（freeze/seal） | 同左 |
| **序列化/反序列化** | 原生兼容 JSON | 需要自定义 toJSON/fromJSON | 原生兼容 JSON |
| **模式匹配** | switch/if 天然适配 | visitor 模式或手动分发 | 手动分发 |
| **学习曲线** | 低（纯 TypeScript 语法） | 中等（OOP 概念） | 低但危险 |
| **适用场景** | 数据建模、状态机、协议 | 行为丰富的大型对象、生命周期管理 | 快速原型、内部工具 |

### 选择建议

- **优先选择可辨识联合**的场景：纯数据载体、状态机、协议消息、API 响应格式
- **考虑 class 继承**的场景：需要封装复杂行为、有生命周期管理需求、需要私有状态
- **仅用普通 object**的场景：一次性脚本、不需要类型安全的数据传递

### 陷阱一：判别属性非字面量类型

```typescript

  value: unknown

    // item.value 被自动收窄为 number
```

### 陷阱三：缺少分支导致类型未完全收窄

```typescript
function incompleteSwitch(shape: Shape): number {
  switch (shape.kind) {
    case 'circle':
      return Math.PI * shape.radius ** 2
    case 'rectangle':
      return shape.width * shape.height
    // 遗漏了 triangle！如果后续代码访问 shape，
    // 它仍然是 circle | rectangle | triangle
  }

  // 到达此处时 shape 仍然是完整联合
  // TypeScript 4.9+ 会给出警告但不报错

}
```

### 解决方案：Exhaustive Check（穷尽性检查）

利用 `never` 类型确保所有分支都被处理：

```typescript
/**
 * 穷尽性检查辅助函数
 * 如果所有 case 都已覆盖，传入的参数类型应该是 never
 * 如果传入了非 never 值，说明有遗漏的分支
 */
function assertNever(x: never): never {
  throw new Error(`Unexpected object: ${x}`)
}

function exhaustiveArea(shape: Shape): number {
  switch (shape.kind) {
    case 'circle':
      return Math.PI * shape.radius ** 2
    case 'rectangle':
      return shape.width * shape.height
    case 'triangle':
      return (shape.base * shape.height) / 2
    default:
      // 如果新增了 Square 成员但没有对应的 case，
      // shape 的类型在这里会是 { kind: 'square', size: number }
      // 而 never 不能接受它，编译器报错
      return assertNever(shape)
  }
}
```

当未来某天给 `Shape` 新增了 `Square` 成员却忘记更新 `exhaustiveArea` 时：

```typescript
type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'rectangle'; width: number; height: number }
  | { kind: 'triangle'; base: number; height: number }
  | { kind: 'square'; size: number }  // 新增！

// assertNever(shape) 这行会报错：
// Argument of type '{ kind: "square"; size: number; }' is not assignable to parameter of type 'never'.
```

这就是**编译期的回归测试**——新增联合成员时，所有使用该类型的穷尽性检查位置都会报错，强制开发者逐一审查和更新。

### 陷阱四：函数返回可辨识联合时的类型推导问题

### Pattern Matching 库的设计思路

虽然 TypeScript 没有原生的 pattern matching 语法，但可以利用可辨识联合构建类 pattern matching 的 API：

```typescript
/**
 * 简易 Match 实现
 * 利用可辨识联合的自动收窄 + 函数重载实现类型安全的匹配
 */
type Matcher<T, R> = {
  cases: Partial<{
    [K in T['kind']]: (value: Extract<T, { kind: K }>) => R
  }>
  default?: (value: Exclude<T, { kind: keyof NonNullable<Matcher<T, R>['cases']> }>) => R
}

function match<T extends { kind: string }, R>(
  value: T,
  matcher: Matcher<T, R>
): R {
  const handler = matcher.cases[value.kind]
  if (handler) {
    return handler(value as Extract<T, { kind: typeof value.kind }>)
  }
  if (matcher.default) {
    return matcher.default(value as any)
  }
  throw new Error(`Non-exhaustive match for kind: ${value.kind}`)
}

// 使用
const result = match(someShape, {
  cases: {
    circle: ({ radius }) => Math.PI * radius ** 2,
    rectangle: ({ width, height }) => width * height,
    triangle: ({ base, height }) => (base * height) / 2,
  },
})
```

### Builder 模式构建可辨识联合

当可辨识联合的成员较多或某些成员构造复杂时，Builder 模式可以简化构建过程：

```typescript
/**
 * HTTP Response Builder
 * 用 fluent API 构建可辨识联合
 */
class ResponseBuilder<T = unknown> {
  private response?: ApiResponse<T>

  ok(data: T, timestamp = Date.now()): ResponseBuilder<T> {
    this.response = { status: 'success', data, timestamp }
    return this
  }

  fail(code: number, message: string): ResponseBuilder<T> {
    this.response = { status: 'error', code, message }
    return this
  }

  build(): ApiResponse<T> {
    if (!this.response) {
      throw new Error('ResponseBuilder: must call ok() or fail() before build()')
    }
    return this.response
  }
}

// 使用
const response = new ResponseBuilder<UserProfile>()
  .ok({ name: 'Alice', email: 'alice@example.com' })
  .build()
```

```typescript
  | { status: 'error'; error: AppError }
  | { status: 'empty' }

  error: (error: AppError): ResourceState<never> => ({ status: 'error', error }),
  empty: (): ResourceState<never> => ({ status: 'empty' }),

  isLoaded: <T>(s: ResourceState<T>): s is ResourceState<T> & { status: 'loaded' } =>
    s.status === 'loaded',

  map: <T, U>(s: ResourceState<T>, fn: (data: T) => U): ResourceState<U> => {

    return s as unknown as ResourceState<U>
  },
```

## 综合案例：类型安全的 API 响应处理器

### 需求描述

在实际项目中，API 响应可能有多种格式：标准成功响应、分页响应、错误响应、空响应等。我们希望用一个统一的处理器处理所有情况，同时保证每种响应格式的字段访问都是类型安全的。

### 定义响应联合类型

```typescript
/**
 * API 基础错误类型
 */
interface ApiErrorInfo {
  code: string
  message: string
  details?: Record<string, string[]>
  requestId: string
  timestamp: string
}

/**
 * 统一的 API 响应可辨识联合
 * 涵盖所有可能的响应格式
 */
type ApiResponseBody<T = unknown> =
  // 标准 CRUD 操作的成功响应
  | {
      outcome: 'ok'
      data: T
      meta?: { version: number; etag: string }
    }
  // 分页列表响应
  | {
      outcome: 'page'
      items: T[]
      pagination: {
        page: number
        pageSize: number
        total: number
        totalPages: number
        hasNext: boolean
        hasPrev: boolean
      }
    }
  // 批量操作的局部成功响应
  | {
      outcome: 'partial'
      succeeded: T[]
      failed: Array<{ item: T; error: ApiErrorInfo }>
      summary: { total: number; successCount: number; failureCount: number }
    }
  // 业务逻辑错误（非 HTTP 错误）
  | {
      outcome: 'business_error'
      error: ApiErrorInfo & { category: 'validation' | 'permission' | 'conflict' | 'rate_limit' }
    }
  // 系统级错误
  | {
      outcome: 'system_error'
      error: ApiErrorInfo & { category: 'internal' | 'upstream' | 'timeout' }
    }
  // 空内容（如 DELETE 204）
  | {
      outcome: 'no_content'
    }

/**
 * 完整的 API 响应（包含 HTTP 元信息）
 */
type ApiResponse<T = unknown> = {
  httpStatus: number
  headers: Record<string, string>
  duration: ms
  body: ApiResponseBody<T>
}
```

### 统一处理器实现

```typescript
/**
 * 类型安全的 API 响应处理器
 */
class ApiResponder<T> {
  constructor(private response: ApiResponse<T>) {}

  /**
   * 核心处理方法 —— 根据 outcome 分发
   */
  handle(handlers: {
    onData: (data: T, meta?: { version: number; etag: string }) => void
    onPage: (items: T[], pagination: ApiResponseBody<T>['pagination']) => void
    onPartial: (result: Extract<ApiResponseBody<T>, { outcome: 'partial' }>) => void
    onBusinessError: (error: ApiErrorInfo & { category: string }) => void
    onSystemError: (error: ApiErrorInfo & { category: string }) => void
    onNoContent: () => void
  }): void {
    const { body } = this.response

    switch (body.outcome) {
      case 'ok':
        handlers.onData(body.data, body.meta)
        break

      case 'page':
        handlers.onPage(body.items, body.pagination)
        break

      case 'partial':
        handlers.onPartial(body)
        break

      case 'business_error':
        handlers.onBusinessError(body.error)
        break

      case 'system_error':
        handlers.onSystemError(body.error)
        break

      case 'no_content':
        handlers.onNoContent()
        break

      default:
        // 穷尽性检查 —— 如果未来新增 outcome 值，这里会报错
        const _exhaustive: never = body
        console.warn('Unhandled response outcome:', _exhaustive)
    }
  }

  /**
   * 快捷方法：提取数据或抛出错误
   */
  unwrap(): T {
    const { body } = this.response
    if (body.outcome === 'ok') return body.data
    if (body.outcome === 'page') return body.items[0] as T

    const errorMsg = body.outcome === 'no_content'
      ? 'No content in response'
      : body.error?.message ?? `Unexpected outcome: ${body.outcome}`

    throw new ApiProcessingError(errorMsg, body)
  }

  /**
   * 快捷方法：提取数据或返回默认值
   */
  unwrapOr(fallback: T): T {
    try {
      return this.unwrap()
    } catch {
      return fallback
    }
  }
}

class ApiProcessingError extends Error {
  constructor(message: public msg: string, public rawBody: ApiResponseBody) {
    super(message)
    this.name = 'ApiProcessingError'
  }
}
```

```typescript
 * 根据响应的错误信息查找本地化消息

  response: ApiResponse,
  locale: keyof typeof errorMessages = 'zh'
): string {
  const { body } = response

  if (body.outcome !== 'business_error' && body.outcome !== 'system_error') {
    return errorMessages[locale].INTERNAL_ERROR
  }
```

### 完整使用流程

```typescript
// ===== 完整使用示例 =====

async function fetchUsers(page: number): Promise<ApiResponse<User>> {
  const start = performance.now()
  const res = await fetch(`/api/users?page=${page}&size=20`)
  const duration = performance.now() - start
  const headers: Record<string, string> = {}
  res.headers.forEach((v, k) => { headers[k] = v })

  let body: ApiResponseBody<User>
  const rawData = await res.json()

  if (res.status >= 200 && res.status < 300) {
    if (Array.isArray(rawData)) {
      body = {
        outcome: 'page',
        items: rawData,
        pagination: {
          page,
          pageSize: 20,
          total: parseInt(res.headers.get('X-Total-Count') ?? '0'),
          totalPages: Math.ceil(parseInt(res.headers.get('X-Total-Count') ?? '0') / 20),
          hasNext: !!res.headers.get('X-Has-Next'),
          hasPrev: page > 1,
        },
      }
    } else if (rawData === null || rawData === undefined) {
      body = { outcome: 'no_content' }
    } else {
      body = { outcome: 'ok', data: rawData }
    }
  } else if (rawData.category === 'validation' || rawData.category === 'permission') {
    body = { outcome: 'business_error', error: rawData }
  } else {
    body = { outcome: 'system_error', error: rawData }
  }

  return { httpStatus: res.status, headers, duration, body }
}

// 处理响应
const response = await fetchUsers(1)
const responder = new ApiResponder<User>(response)

responder.handle({
  onData: (user, meta) => {
    console.log(`Got user: ${user.name}`, meta?.etag ? `(ETag: ${meta.etag})` : '')
  },

  onPage: (users, pagination) => {
    console.log(`Page ${pagination.page}/${pagination.totalPages}: ${users.length} users`)
    console.log(`Total: ${pagination.total}, HasNext: ${pagination.hasNext}`)
  },

  onPartial: result => {
    console.warn(`Partial success: ${result.summary.successCount}/${result.summary.total}`)
    result.failed.forEach(({ item, error }) => {
      console.error(`  Failed for ${item.id}: ${error.code} - ${error.message}`)
    })
  },

  onBusinessError: error => {
    showToast(getLocalizedErrorMessage(response), 'warning')
    trackError(error.code, error.requestId)
  },

  onSystemError: error => {
    showToast(getLocalizedErrorMessage(response), 'error')
    reportToSentry(error, response.headers)
  },

  onNoContent: () => {
    console.log('Operation succeeded (no content)')
  },
})
```

## 总结

可辨识联合是 TypeScript 类型系统中极具实用价值的特性，它将代数数据类型的思想融入到了 JavaScript 的实际开发中。其核心价值体现在三个层面：

**类型安全性**：通过判别属性的自动收窄，消除了大量手动的类型断言和防御性检查。每一个分支内部的代码都在确定的类型上下文中工作，编译器充当了严格的守门人。

**表达力**：状态机、Result 模式、AST、Action 系统——这些工程实践中反复出现的模式都可以用可辨识联合优雅地表达。它是一种"数据即代码"的建模方式：结构的差异本身就编码了语义的差异。

**可维护性**：配合穷尽性检查（exhaustive check），新增联合成员时所有消费位置的编译报错构成了强制的变更通知机制。这在大型代码库中尤为重要——它防止了"新增了一个 case 但忘了更新某处 switch"这类隐蔽的回归缺陷。

掌握可辨识联合，意味着掌握了用类型系统对业务领域进行结构化建模的能力。它是连接"写出的代码能跑"和"写出的代码正确"之间的关键桥梁之一。
