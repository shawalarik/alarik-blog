## 回顾：基础类型守卫

TypeScript 的类型守卫是编译器进行**类型窄化**的核心机制。在深入高级模式之前，先快速回顾三种内置守卫形式。

### typeof 守卫

用于区分原始类型：

```typescript
function printId(id: string | number) {
  if (typeof id === 'string') {
    // 此处 id 被收窄为 string
    console.log(id.toUpperCase());
  } else {
    // 此处 id 被收窄为 number
    console.log(id.toFixed(2));
  }
}
```

typeof 守卫能识别的类型集合有限：`string`、`number`、`bigint`、`boolean`、`symbol`、`undefined`、`object`、`function`。注意 `null` 的 typeof 结果是 `'object'`，这是一个历史遗留问题。

### in 操作符守卫

用于检查对象是否拥有某个属性：

```typescript
interface Cat {
  meow(): void;
}
interface Dog {
  bark(): void;
}

function makeSound(animal: Cat | Dog) {
  if ('meow' in animal) {
    // animal 被收窄为 Cat
    animal.meow();
  } else {
    // animal 被收窄为 Dog
    animal.bark();
  }
}
```

### instanceof 守卫

用于判断构造函数的原型链关系：

```typescript
class HttpError extends Error { /* ... */ }
class ValidationError extends Error { /* ... */ }

function handle(error: Error) {
  if (error instanceof HttpError) {
    // error 被收窄为 HttpError
    console.log(`HTTP ${error.status}`);
  }
  if (error instanceof ValidationError) {
    console.log(error.fields);
  }
}
```

### 简单的 isXxx 函数

当内置守卫无法覆盖时，可以自定义 `isXxx` 形式的守卫函数：

```typescript
function isString(value: unknown): value is string {
  return typeof value === 'string';
}

function process(input: string | number[]) {
  if (isString(input)) {
    // input 收窄为 string
    return input.split(',');
  }
  // input 收窄为 number[]
  return input.map(n => n * 2);
}
```

`value is T` 是 TypeScript 提供的**谓词语法**，告诉编译器：当此函数返回 true 时，参数的实际类型就是 T。

### 基础守卫的局限性

以上四种方式在日常开发中已足够应对大部分场景，但在以下情况下会显得力不从心：

1. **复杂联合类型的精细化判别**——需要同时校验多个属性或深层嵌套结构
2. **需要提前终止执行流而非分支处理**——输入不合法时应直接抛异常
3. **对象状态随方法调用而改变**——需要表达"调用此方法后 this 类型发生变化"
4. **运行时验证与编译期类型的桥接**——需要将第三方验证库的结果转化为 TS 类型信息
5. **动态生成守卫逻辑**——根据配置或 schema 自动产生守卫函数

这些场景正是本文要探讨的"高级模式"。

## 自定义类型守卫函数

### value is T 断言机制详解

自定义类型守卫的核心语法是返回值类型注解中的 `value is T` 形式：

```typescript
type Fish = { swim: () => void };
type Bird = { fly: () => void };

function isFish(pet: Fish | Bird): pet is Fish {
  return ('swim' in pet);
}
```

这段声明包含两层语义：

- **运行时层**：函数体执行实际的类型检查，返回 boolean 值
- **编译期层**：返回值类型注解 `pet is Fish` 是一个**类型谓词**，它向编译器承诺：若函数返回 true，则第一个参数（此处即 pet）的类型可被收窄为 Fish

关键点在于：类型谓词中的参数名必须与函数签名的形参名一致。以下写法会导致编译错误：

```typescript
// 错误：谓词参数名 'animal' 与形参名 'pet' 不匹配
function isFishWrong(pet: Fish | Bird): animal is Fish {
  return ('swim' in pet);  // 编译错误
}
```

### 与普通布尔函数的本质区别

从运行时行为看，守卫函数和普通布尔函数完全一致——都返回 true 或 false。区别仅存在于**编译期类型推断**阶段：

```typescript
// 普通布尔函数
function checkIsString(value: unknown): boolean {
  return typeof value === 'string';
}

// 自定义守卫函数
function isString(value: unknown): value is string {
  return typeof value === 'string';
}

function demo(x: unknown) {
  if (checkIsString(x)) {
    // x 的类型仍然是 unknown —— 编译器不会收窄
    console.log(x.length); // Error: 'x' is of type 'unknown'
  }

  if (isString(x)) {
    // x 被收窄为 string
    console.log(x.length); // OK
  }
}
```

这种差异源于 TypeScript 对**控制流分析**的实现方式。编译器维护了一个类型收窄表，当遇到 `value is T` 形式的条件判断时，会在 true 分支中将对应变量标记为 T 类型。

### 运行时安全性与编译期信任

TypeScript 的类型系统在编译后被擦除，这意味着守卫函数的运行时检查是唯一的实际安全保障。如果守卫函数的实现有缺陷，编译期仍然会基于其返回值进行错误的类型收窄：

```typescript
// 危险示例：运行时行为与类型谓词不一致
function unsafeIsNumber(x: unknown): x is number {
  return true;  // 永远返回 true，但 x 可能不是 number
}

const val: unknown = 'hello';
if (unsafeIsNumber(val)) {
  // 编译器认为 val 是 number，但实际是 string
  console(val.toFixed(2)); // 运行时 TypeError!
}
```

因此编写守卫函数时必须确保**运行时检查的严谨性**，这是开发者应承担的契约责任。

## 断言守卫（asserts 关键字）

TypeScript 3.7 引入了断言守卫，用 `asserts` 关键字表示"若函数正常返回，则某个条件成立；若条件不成立，函数会抛出异常"。这与普通守卫形成了互补。

### 两种语法形式

**形式一：`asserts condition`**

```typescript
function assert(condition: unknown, msg?: string): asserts condition {
  if (!condition) throw new Error(msg || 'Assertion failed');
}

let value: number | undefined = fetchValue();

assert(value !== undefined);

// value 在此处被收窄为 number
console.log(value.toFixed(2));
```

`asserts condition` 表示：如果函数正常返回（未抛异常），则 condition 为 truthy。编译器据此在后续代码中排除 falsy 的可能性。

**形式二：`asserts value is T`**

```typescript
function assertIsString(value: unknown): asserts value is string {
  if (typeof value !== 'string') {
    throw new TypeError(`Expected string, got ${typeof value}`);
  }
}

function processInput(input: unknown) {
  assertIsString(input);
  // input 被收窄为 string
  return input.trim();
}
```

`asserts value is T` 结合了断言和类型谓词：正常返回时 value 的类型为 T，抛出异常时控制流中断。

### 普通守卫 vs 断言守卫的行为差异

理解两者的区别至关重要。下面通过控制流图来对比：

```typescript
// 普通 is 守卫
function isString(v: unknown): v is string {
  return typeof v === 'string';
}

// asserts 守卫
function assertIsString(v: unknown): asserts v is string {
  if (typeof v !== 'string') throw new TypeError('Not a string');
}

function demo(data: unknown) {
  // ====== 普通 is 守卫 ======
  if (isString(data)) {
    // [✓] data → string
    processData(data);
  } else {
    // [!] data → unknown （未被收窄！）
    handleNonString(data);
  }

  // ====== asserts 守卫 ======
  assertIsString(data);
  // [✓] data → string
  // 异常路径已被排除，不存在 else 分支
  processData(data);
}
```

核心差异总结：

| 特性 | `is T` 守卫 | `asserts` 守卫 |
|------|------------|----------------|
| false/throw 分支 | 变量保持原类型 | 控制流终止，无需关心 |
| true 分支 | 变量收窄为目标类型 | 变量收窄为目标类型 |
| 使用模式 | if-else 双分支处理 | 单路径提前校验 |
| 适用场景 | 需要对两种情况分别处理 | 输入合法性前置校验 |

### 实战案例集

**assertDefined：消除 undefined 和 null**

```typescript
function assertDefined<T>(
  value: T | null | undefined,
  msg?: string
): asserts value is T {
  if (value === null || value === undefined) {
    throw new Error(msg ?? 'Value is null or undefined');
  }
}

function getFirstElement<T>(arr: T[]): T {
  assertDefined(arr[0], 'Array must not be empty');
  return arr[0];  // arr[0] 已确认为 T
}
```

**assertNever：穷尽性检查辅助**

```typescript
type Status = 'idle' | 'loading' | 'success' | 'error';

function handleStatus(status: Status): string {
  switch (status) {
    case 'idle': return '空闲';
    case 'loading': return '加载中';
    case 'success': return '成功';
    case 'error': return '出错';
    default:
      // 如果新增了 Status 成员但忘记处理，这里会捕获到
      assertNever(status);
  }
}

function assertNever(value: never): never {
  throw new Error(`Unexpected value: ${value}`);
}
```

`assertNever` 利用 TypeScript 的 `never` 类型特性：如果一个联合类型已经穷尽了所有成员，那么 default 分支的值类型应为 `never`。传入任何实际值都会导致类型错误，从而在编译期提醒开发者遗漏了 case。

**assertIsArray：安全的数组类型断言**

```typescript
function assertIsArray<T>(value: unknown): asserts value is T[] {
  if (!Array.isArray(value)) {
    throw new TypeError(`Expected array, got ${typeof value}`);
  }
}

function parseConfig(raw: unknown) {
  assertIsArray<string>(raw);
  // raw → string[]
  return raw.map(s => s.toUpperCase());
}
```

### asserts vs return 的细微差别

断言守卫函数的返回类型标注为 `asserts ...` 时，函数体的隐式返回类型变为 `void`（或说返回值的语义被重新定义）：

```typescript
// 这个函数的"有效"返回类型不是 boolean，而是 asserts
function myAssert(cond: boolean): asserts cond {
  if (!cond) throw new Error();
  // 不需要显式 return —— 正常到达末尾即表示断言通过
  // 但也可以写 return; 或 return void 0;
}
```

即使函数体中有显式 return 语句，只要返回类型标注为 `asserts ...`，编译器就按断言语义处理。实践中建议不在 asserts 函数中写有意义的 return 值，以避免混淆。

## this is 类型守卫

TypeScript 允许在类的方法或接口方法签名中使用 `this is SomeType` 作为返回类型注解，实现一种特殊的**隐式类型窄化**——调用该方法后，对象的 this 类型会被收窄。

### 核心概念

`this is Type` 声明的作用是告诉编译器：**调用此方法后，该对象的类型将从当前类型收窄为指定的 Type**。这是一种基于方法调用的类型转换机制，不需要创建新对象或手动类型断言。

### 状态机对象的典型应用

这是 `this is` 最经典的使用场景。考虑一个文件上传的状态机：

```typescript
interface UploadStateIdle {
  status: 'idle';
  file: File | null;
  select(file: File): UploadStateWithFile;
}

interface UploadStateWithFile {
  status: 'selected';
  file: File;
  upload(): UploadStateUploading | UploadStateFailed;
  cancel(): UploadStateIdle;
}

interface UploadStateUploading {
  status: 'uploading';
  progress: number;
  cancel(): UploadStateCancelled;
}

interface UploadStateSuccess {
  status: 'success';
  url: string;
  download(): void;
}

interface UploadStateFailed {
  status: 'failed';
  error: string;
  retry(): UploadStateUploading;
  reset(): UploadStateIdle;
}

interface UploadStateCancelled {
  status: 'cancelled';
  reset(): UploadStateIdle;
}

type UploadState =
  | UploadStateIdle
  | UploadStateWithFile
  | UploadStateUploading
  | UploadStateSuccess
  | UploadStateFailed
  | UploadStateCancelled;

class Uploader implements UploadState {
  status: UploadState['status'] = 'idle';
  file: File | null = null;
  progress = 0;
  url = '';
  error = '';

  select(file: File): this is UploadStateWithFile {
    this.file = file;
    this.status = 'selected';
    return true;  // this is 要求返回 boolean
  }

  upload(): this is UploadStateUploading | UploadStateFailed {
    if (!this.file) throw new Error('No file selected');

    this.status = 'uploading';

    // 模拟上传
    try {
      const url = simulateUpload(this.file);
      this.url = url;
      this.status = 'success';
      return true;
    } catch (e) {
      this.error = String(e);
      this.status = 'failed';
      return true;
    }
  }

  cancel(): this is UploadStateCancelled {
    this.status = 'cancelled';
    return true;
  }

  reset(): this is UploadStateIdle {
    this.status = 'idle';
    this.file = null;
    this.progress = 0;
    this.error = '';
    this.url = '';
    return true;
  }

  retry(): this is UploadStateUploading {
    this.status = 'uploading';
    this.error = '';
    return true;
  }

  download(): void {
    if (this.status !== 'success') throw new Error('Not downloadable');
    window.open(this.url);
  }
}
```

使用时的类型安全性体现得淋漓尽致：

```typescript
const uploader = new Uploader();

uploader.select(someFile);

// uploader 被 TypeScript 收窄为 UploadStateWithFile
// 可以安全地访问 .file 且类型为 File（非 null）
console.log(uploader.file.name);

uploader.upload();

// uploader 现在可能是 UploadStateUploading 或 UploadStateSuccess 或 UploadStateFailed
switch (uploader.status) {
  case 'success':
    // uploader → UploadStateSuccess
    uploader.download();  // OK
    break;
  case 'failed':
    // uploader → UploadStateFailed
    uploader.retry();     // OK
    uploader.reset();     // OK
    break;
}
```

### 与直接赋值新对象的区别

传统做法通常是每次状态变化返回一个新的对象实例：

```typescript
// 传统模式：每次返回新对象
function select(state: IdleState, file: File): SelectedState {
  return { ...state, status: 'selected', file };
}

function upload(state: SelectedState): UploadingState {
  return { ...state, status: 'uploading', progress: 0 };
}
```

`this is` 模式的优势：

1. **原地修改**——不需要创建新对象，内存效率更高
2. **引用一致性**——所有持有该对象引用的代码都能感知到状态变化
3. **更符合命令式编程直觉**——对于 UI 组件状态等场景更自然

劣势：

1. **可变性**——违反不可变数据的原则，在 Redux 等架构中可能引发问题
2. **调试困难**——对象的历史状态无法回溯
3. **限制更多**——只能在类方法中使用，不能用在独立函数中

### 使用限制

`this is` 类型守卫只能在以下位置使用：
- 类的实例方法的返回类型
- 接口中方法声明的返回类型
- 对象字面量的方法返回类型

不能用于：
- 独立函数
- 箭头函数
- 类的静态方法

```typescript
class Example {
  // ✓ 合法：实例方法
  isValid(): this is ValidatedExample {
    return this.check();
  }

  // ✗ 非法：静态方法中没有 this 实例
  static create(): this is Example {  // 编译错误
    return new Example();
  }
}

// ✗ 非法：独立函数
function validate(obj: Obj): this is ValidObj {  // 编译错误
  return obj.valid;
}
```

## 联合类型的精细化守卫

### 可辨识联合的判别属性守卫

可辨识联合是 TypeScript 中最强大的类型模式之一，而判别属性守卫是其自然伴侣：

```typescript
type ApiResponse =
  | { status: 'success'; data: User[] }
  | { status: 'error'; error: { code: number; message: string } }
  | { status: 'pending'; estimatedTime: number };

function handleResponse(res: ApiResponse) {
  switch (res.status) {
    case 'success':
      // res → { status: 'success'; data: User[] }
      res.data.forEach(u => console.log(u.name));
      break;
    case 'error':
      // res → { status: 'error'; error: {...} }
      logApiError(res.error.code, res.error.message);
      break;
    case 'pending':
      // res → { status: 'pending'; estimatedTime: number }
      showProgress(res.estimatedTime);
      break;
  }
}
```

TypeScript 编译器会自动识别 switch/if 中对判别属性（discriminant）的检查，并在各分支中自动收窄类型。这是目前最简洁的联合类型处理方式。

### 多条件复合守卫

有时单一属性不足以区分联合成员，需要同时检查多个属性：

```typescript
type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'rectangle'; width: number; height: number }
  | { kind: 'triangle'; base: number; height: number };

// 复合守卫函数
function isRectangle(shape: Shape): shape is Shape & { kind: 'rectangle' } {
  return shape.kind === 'rectangle' && 'width' in shape && 'height' in shape;
}

// 或者用 type guard + 类型交叉
function isCircle(shape: Shape): shape is Extract<Shape, { kind: 'circle' }> {
  return shape.kind === 'circle' && 'radius' in shape;
}
```

对于深层嵌套的结构，复合守卫可以逐层展开：

```typescript
type ApiResult<T> =
  | { ok: true; value: T }
  | { ok: false; error: { type: 'network' | 'timeout' | 'server'; detail: string } };

async function fetchData<T>(url: string): Promise<ApiResult<T>> {
  try {
    const res = await fetch(url);
    const data = await res.json() as T;
    return { ok: true, value: data };
  } catch (e) {
    if (e instanceof TypeError) {
      return { ok: false, error: { type: 'network', detail: e.message } };
    }
    if ((e as { name: string }).name === 'TimeoutError') {
      return { ok: false, error: { type: 'timeout', detail: 'Request timeout' } };
    }
    return { ok: false, error: { type: 'server', detail: String(e) } };
  }
}

// 复合守卫：同时判断 ok 和 error.type
function isNetworkError<T>(res: ApiResult<T>): res is ApiResult<T> & {
  ok: false;
  error: { type: 'network' };
} {
  return !res.ok && res.error.type === 'network';
}
```

### 守卫函数的组合与复用

守卫函数可以像普通布尔函数一样组合使用：

```typescript
// 组合守卫：AND 逻辑
function isPositiveInteger(value: unknown): value is number {
  return typeof value === 'number' && Number.isInteger(value) && value > 0;
}

// 组合守卫：OR 逻辑
function isTextOrNumber(value: unknown): value is string | number {
  return typeof value === 'string' || typeof value === 'number';
}

// 守卫复用：基于已有守卫构建更高层的守卫
function isNonEmptyString(value: unknown): value is string {
  return isString(value) && value.length > 0;
}

// 高阶守卫组合器
function and<T, U extends T>(
  g1: (v: T) => v is U,
  g2: (v: U) => v is unknown
): (v: T) => v is U & ReturnType<typeof g2> extends infer R ? R : never {
  return (v: T): v is any => g1(v) && g2(v as any);
}

function or<T>(g1: (v: T) => v is any, g2: (v: T) => v is any): (v: T) => v is any {
  return (v: T) => g1(v) || g2(v);
}
```

## 泛型类型守卫

### 守卫函数携带泛型参数

泛型使守卫函数能够适应多种类型场景，而不必为每种类型单独编写守卫：

```typescript
/**
 * 检查对象是否拥有指定属性，并将该属性的类型纳入类型系统
 */
function hasProperty<T, K extends string>(
  obj: T,
  prop: K
): obj is T & Record<K, unknown> {
  return Object.prototype.hasOwnProperty.call(obj, prop);
}

function processUser(user: unknown) {
  if (hasProperty(user, 'name') && hasProperty(user, 'age')) {
    // user 的类型被丰富化：包含 name 和 age 属性
    console.log(`${user.name} is ${user.age} years old`);
  }
}
```

### 泛型约束确保类型安全

通过泛型约束可以在编译期就排除非法的使用方式：

```typescript
/**
 * 检查数组元素是否都是指定类型
 */
function isArrayOf<T>(
  arr: unknown[],
  guard: (item: unknown) => item is T
): arr is T[] {
  return arr.every(guard);
}

// 使用
const data: unknown = JSON.parse('[1, 2, "3"]');

if (Array.isArray(data) && isArrayOf(data, isNumber)) {
  // data → number[]（但注意："3" 会使整个检查失败）
  console.log(data.reduce((a, b) => a + b, 0));
}
```

### 高级泛型守卫：属性类型精确提取

结合条件类型和 infer，可以写出非常精细的泛型守卫：

```typescript
/**
 * 检查对象是否匹配部分形状，保留原始类型的其余属性
 */
function matchesShape<T, S extends Partial<T>>(
  value: T,
  shape: S
): value is T & Required<S> {
  return (Object.keys(shape) as Array<keyof S>).every(
    key => value[key] === shape[key]
  );
}

// 使用示例
interface Product {
  id: string;
  name: string;
  price: number;
  stock: number;
  category: string;
}

function findExpensiveProducts(products: Product[]): Product[] {
  return products.filter(
    p => matchesShape(p, { price: 100, stock: 0 })
  );
  // 过滤后每个元素仍具有完整的 Product 类型信息
}
```

## 守卫函数工厂

### 高阶函数生成守卫

守卫工厂是一种高阶函数模式，它接受配置参数，返回定制化的守卫函数：

```typescript
/**
 * 创建属性存在性守卫
 */
function propertyGuard<K extends string>(prop: K) {
  return <T>(obj: T): obj is T & Record<K, unknown> =>
    obj !== null &&
    typeof obj === 'object' &&
    prop in obj;
}

// 使用
const hasName = propertyGuard('name');
const hasId = propertyGuard('id');

function processEntity(entity: unknown) {
  if (hasName(entity) && hasId(entity)) {
    // entity 同时拥有 name 和 id 属性
    saveToDb({ id: entity.id, name: entity.name });
  }
}
```

### 从 Schema 自动生成守卫

更进阶的做法是根据类型描述自动生成对应的守卫函数：

```typescript
type FieldValidator = (value: unknown) => boolean;
type SchemaDefinition = Record<string, FieldValidator>;

/**
 * 根据字段 Schema 创建对象守卫函数
 */
function createObjectSchemaGuard<T extends object>(
  schema: SchemaDefinition & { [K in keyof T]: FieldValidator }
): (value: unknown) => value is T {
  return (value: unknown): value is T => {
    if (value === null || typeof value !== 'object') return false;
    const record = value as Record<string, unknown>;
    return Object.entries(schema).every(
      ([field, validator]) => validator(record[field])
    );
  };
}

// 定义验证规则
const userGuard = createObjectSchemaGuard<{
  name: string;
  age: number;
  email: string;
}>({
  name: (v): v is string => typeof v === 'string' && v.length > 0,
  age: (v): v is number => typeof v === 'number' && v >= 0 && v <= 150,
  email: (v): v is string => typeof v === 'string' && /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(v),
});

// 应用
function handleUserData(raw: unknown) {
  if (userGuard(raw)) {
    // raw → { name: string; age: number; email: string }
    createUser(raw);
  } else {
    throw new ValidationError('Invalid user data format');
  }
}
```

### 动态守卫链

对于复杂的数据结构，可以用链式 API 组合多个守卫：

```typescript
class GuardChain<T> {
  private guards: Array<(v: unknown) => v is T> = [];

  add<U extends T>(guard: (v: T) => v is U): GuardChain<U> {
    this.guards.push(guard as any);
    return this as any;
  }

  test(value: unknown): value is T {
    return this.guards.every(guard => guard(value));
  }
}

// 使用
const positiveNumberGuard = new GuardChain<number>()
  .add((v): v is number => typeof v === 'number')
  .add((v): v is number => Number.isFinite(v))
  .add((v): v is number => v > 0)
  .add((v): v is number => Number.isInteger(v));

if (positiveNumberGuard.test(someValue)) {
  // someValue → 正整数
}
```

## 守卫与第三方验证库集成

### 为什么需要集成？

手写守卫函数有两个主要痛点：
1. **繁琐**——复杂结构的验证代码量大且易出错
2. **重复**——验证逻辑往往与类型定义高度重复，违反 DRY 原则

成熟的验证库提供了声明式的 Schema 定义方式，配合类型推导可以实现"定义一次，类型和验证双保障"。

### Zod 集成方案

Zod 是当前生态中最流行的 TypeScript-first 验证库：

```typescript
import { z } from 'zod';

// 定义 Schema（同时也是类型来源）
const UserSchema = z.object({
  id: z.string().uuid(),
  name: z.string().min(1).max(100),
  age: z.number().int().min(0).max(150),
  email: z.string().email(),
  role: z.enum(['admin', 'user', 'guest']),
  createdAt: z.coerce.date(),
});

// 自动推导类型
type User = z.infer<typeof UserSchema>;

// Zod 内置的守卫方法
function processApiResponse(raw: unknown) {
  const result = UserSchema.safeParse(raw);

  if (result.success) {
    // result.data 的类型自动推导为 User
    const user: User = result.data;
    return user;
  }

  // result.error 包含详细的验证错误信息
  console.error(result.error.flatten());
  throw new ValidationError('Invalid user data');
}
```

Zod 的 `.safeParse()` 方法返回 `{ success: true; data: T } | { success: false; error: ZodError }` 可辨识联合，天然支持类型守卫。

### 从 Zod Schema 提取守卫函数

如果需要在多处复用守卫逻辑，可以从 Zod Schema 提取独立的守卫函数：

```typescript
function createZodGuard<T>(schema: z.ZodType<T>): (v: unknown) => v is T {
  return (v: unknown): v is T => schema.safeParse(v).success;
}

// 批量创建
const isUser = createZodGuard(UserSchema);
const isOrder = createZodGuard(OrderSchema);
const isProduct = createZodGuard(ProductSchema);

// 在业务代码中直接使用
function handleMessage(msg: unknown) {
  if (isUser(msg)) {
    // msg → User
    updateUser(msg);
  } else if (isOrder(msg)) {
    // msg → Order
    processOrder(msg);
  }
}
```

### 其他库的支持情况

**Valibot**（轻量级替代）：

import * as v from 'valibot';

const UserSchema = v.object({

// Valibot 的 guard 函数

### 选择决策因素

| 维度 | Zod | Valibot | io-ts | Yup |
|------|-----|---------|-------|-----|
| 包体积 | 较大 | 最小 | 中等 | 中等 |
| 学习曲线 | 低 | 低 | 高（FP概念） | 低 |
| 类型推导 | 完善 | 完善 | 完善 | 需插件 |
| 内置守卫 | safeParse() | is() | is() | 无 |
| 生态成熟度 | 最高 | 快速增长 | 成熟 | 成熟 |

对于新项目推荐优先考虑 Zod 或 Valibot，两者的开发体验最佳且与 TypeScript 类型系统集成最为紧密。

## 类型守卫的性能考量

### 守卫函数的运行时开销

守卫函数本质上是在运行时执行的 JavaScript 函数，每次调用都会带来一定的 CPU 开销。常见操作的成本排序（从低到高）：

```typescript
// 1. 最低开销：typeof 检查（V8 引擎优化极佳）
function isString(v: unknown): v is string {
  return typeof v === 'string';  // ~纳秒级
}

// 2. 低开销：in 操作符 / 属性读取
function hasId(v: object): v is { id: unknown } {
  return 'id' in v;  // ~微秒级
}

// 3. 中等开销：instanceof 检查（涉及原型链遍历）
function isError(v: unknown): v is Error {
  return v instanceof Error;  // 取决于原型链深度
}

// 4. 较高开销：正则表达式匹配
function isEmail(v: unknown): v is string {
  return typeof v === 'string' && EMAIL_REGEX.test(v);  // ~微秒到毫秒级
}

// 5. 高开销：深度对象遍历
function isDeepStructure(v: unknown): v is ComplexType {
  return deepEqual(v, expectedShape);  // 取决于数据规模
}
```

### 热路径 vs 冷路径策略

**热路径**（高频调用、性能敏感的场景）：

```typescript
// 渲染循环、动画帧回调中的守卫应尽量简单
function renderLoop(entities: Entity[]) {
  for (const entity of entities) {
    // ✅ 使用最轻量的守卫
    if (typeof entity.visible === 'boolean' && entity.visible) {
      draw(entity);
    }

    // ❌ 避免在此处做复杂的 Schema 验证
    // if (complexGuard(entity)) { ... }
  }
}
```

**冷路径**（低频调用、非性能瓶颈场景）：

```typescript
// API 响应解析、初始化流程可以使用完整验证
async function initializeApp(config: unknown) {
  const parsed = AppConfigSchema.parse(config);
  // 完整的 Zod 验证在此处完全可接受
  app.start(parsed);
}
```

### 守卫结果缓存

对于纯函数性质的守卫，可以对相同输入缓存结果：

```typescript
function memoizedGuard<T>(
  guard: (v: unknown) => v is T
): (v: unknown) => v is T {
  const cache = new WeakMap<object, boolean>();

  return (v: unknown): v is T => {
    if (v === null || typeof v !== 'object') {
      return guard(v);
    }

    let cached = cache.get(v as object);
    if (cached === undefined) {
      cached = guard(v);
      cache.set(v as object, cached);
    }

    return cached;
  };
}
```

WeakMap 的使用避免了内存泄漏风险——当对象不再被其他地方引用时，缓存条目会被自动回收。

需要注意的是，大多数场景下守卫的开销并不足以成为性能瓶颈，过早优化的收益通常很低。建议先保证正确性，再通过性能剖析工具确认真正的热点。

## 常见陷阱与调试技巧

### 陷阱一：守卫后变量未被正确收窄

这是最常见的困惑来源：

```typescript
interface Config {
  host?: string;
  port?: number;
}

function loadConfig(): Config {
  return JSON.parse(localStorage.getItem('config') ?? '{}');
}

function connect() {
  const config = loadConfig();

  // ❌ 错误用法：解构后再守卫
  const { host, port } = config;
  if (host && port) {
    // host 和 port 的类型仍然是 string | undefined 和 number | undefined
    // 因为解构创建了新的绑定，与原对象无关
    initClient(host, port);  // 可能报错
  }

  // ✅ 正确用法：守卫原对象属性
  if (config.host && config.port) {
    // 此时 config.host → string, config.port → number
    initClient(config.host, config.port);
  }
}
```

根本原因在于 TypeScript 的类型窄化作用于**变量绑定**，而非值本身。解构操作产生了新的绑定，这些新绑定没有参与原始的类型窄化过程。

### 陷阱二：闭包中的守卫失效

闭包可能捕获的是变量的宽类型版本：

```typescript
function processItems(items: (string | null)[]) {
  const results: string[] = [];

  items.forEach(item => {
    if (item !== null) {
      // item 在此处被收窄为 string ✓
      results.push(item.toUpperCase());
    }
  });

  // ✅ forEach 回调内部守卫工作正常
  // 因为 TypeScript 能追踪回调参数的类型窄化
}
```

但以下情况可能出问题：

```typescript
function problem(items: (string | null)[]) {
  let current: string | null = null;

  for (const item of items) {
    current = item;
    if (current !== null) {
      // current 被收窄为 string
      useString(current);  // OK
    }
    // 循环结束后 current 又回到 string | null
  }

  // ❌ 问题场景：异步回调
  items.forEach(async item => {
    await processItem(item);
    if (item !== null) {
      // await 后的类型窄化在某些 TS 版本中可能丢失
      useString(item);  // 可能报错，取决于 TS 版本
    }
  });
}
```

### 陷阱三：any 类型对守卫的破坏

`any` 类型是类型系统的黑洞，它会阻止守卫生效：

```typescript
function brokenGuard(value: any): value is string {
  return typeof value === 'string';
}

function demo(data: any) {
  if (brokenGuard(data)) {
    // data 的类型仍然是 any，不会被收窄！
    // 因为 any 本身就"包含"了一切类型，收窄无意义
    console.log(data.anyMethod());  // 不会报错，但这很危险
  }
}
```

解决方案是尽量避免使用 `any`，改用 `unknown`：

```typescript
function safeDemo(data: unknown) {
  if (brokenGuard(data)) {
    // data 被正确收窄为 string
    console.log(data.toUpperCase());
  }
}
```

### 陷阱四：回调函数中守卫结果的传播

守卫结果不会自动传播到外部作用域：

```typescript
function findString(arr: unknown[]): string | undefined {
  let result: string | undefined;

  arr.forEach(item => {
    if (isString(item)) {
      result = item;  // item 是 string，赋值给 result
      // result 的类型取决于其声明时的类型注解
    }
  });

  return result;  // result → string | undefined
}
```

这个例子实际上能正常工作，因为 `result` 的类型声明包含了 `string`。但如果声明为 `let result: unknown`，则在 forEach 之后 result 仍然为 `unknown`——forEach 回调中的窄化不会外溢。

### 调试工具：expects 辅助函数

当守卫没有如预期工作时，可以使用 `expects` 辅助函数定位问题：

```typescript
/**
 * 用于调试的辅助函数
 * 如果类型推断不符合预期，此函数会在编译期报错
 */
function expects<T>(_value: T): void {}

function debugGuard(value: unknown) {
  if (typeof value === 'string') {
    // 用 expects 检查当前推断出的类型
    expects<string>(value);  // 如果 value 不是 string，这里会报错

    // 更进一步，检查特定属性
    expects<{ length: number; toUpperCase(): string }>(value);

    console.log(value.toUpperCase());
  }
}
```

`expects` 的巧妙之处在于利用 TypeScript 的类型推断：传入的实参会触发编译器的类型推导，如果推导结果与期望的泛型参数不兼容，就会产生编译错误。这在排查复杂守卫链的问题时特别有用。

另一个实用的调试技巧是在守卫函数内添加类型注释：

```typescript
function complexGuard(value: unknown): value is MyComplexType {
  // 逐步检查每一步的中间状态
  const isObj = typeof value === 'object' && value !== null;
  if (!isObj) return false;

  const obj = value as Record<string, unknown>;
  const hasRequiredProps = 'a' in obj && 'b' in obj && 'c' in obj;
  if (!hasRequiredProps) return false;

  // 到这里应该已经满足 MyComplexType 的要求
  // 可以用 expects 验证
  expects<MyComplexType>(obj);  // 如果不对，编译器立刻告诉你

  return true;
}
```

## 实战综合案例

### 案例一：API 响应数据的多层守卫管道

```typescript
type ApiResponse<T> =
  | { success: true; data: T; timestamp: number }
  | { success: false; error: { code: string; message: string }; timestamp: number };

/**
 * 构建多层守卫管道，逐层验证 API 响应
 */
class ResponseGuardPipeline<T> {
  private guards: Array<(res: unknown) => res is ApiResponse<T>> = [];

  addBasicCheck(): this {
    this.guards.push((res): res is ApiResponse<T> => {
      return (
        res !== null &&
        typeof res === 'object' &&
        'success' in res &&
        typeof (res as any).success === 'boolean' &&
        'timestamp' in res &&
        typeof (res as any).timestamp === 'number'
      );
    });
    return this;
  }

  addSuccessGuard(dataGuard: (data: unknown) => data is T): this {
    this.guards.push((res): res is ApiResponse<T> => {
      return (
        (res as any).success === true &&
        'data' in res &&
        dataGuard((res as any).data)
      );
    });
    return this;
  }

  addErrorGuard(): this {
    this.guards.push((res): res is ApiResponse<T> => {
      if ((res as any).success === false) {
        const err = (res as any).error;
        return (
          err !== null &&
          typeof err === 'object' &&
          'code' in err &&
          'message' in err
        );
      }
      return true;  // success 分支由其他守卫处理
    });
    return this;
  }

  execute(response: unknown): response is ApiResponse<T> {
    return this.guards.every(guard => guard(response));
  }
}

// 使用示例
const UserResponseGuard = new ResponseGuardPipeline<User>()
  .addBasicCheck()
  .addSuccessGuard(isUser)
  .addErrorGuard();

async function fetchUsers() {
  const response = await api.get('/users');

  if (!UserResponseGuard.execute(response)) {
    throw new Error('Invalid API response structure');
  }

  if (response.success) {
    // response.data → User[]
    renderUserList(response.data);
  } else {
    // response.error → { code: string; message: string }
    showError(response.error.message);
  }
}
```

### 案例二：表单数据的安全提取器

```typescript
interface LoginForm {
  username: string;
  password: string;
  rememberMe: boolean;
}

const LoginFormSchema = {
  username: (v: unknown): v is string =>
    typeof v === 'string' && v.length >= 3 && v.length <= 50,

  password: (v: unknown): v is string =>
    typeof v === 'string' && v.length >= 8,

  rememberMe: (v: unknown): v is boolean =>
    typeof v === 'boolean',
} satisfies Record<keyof LoginForm, (v: unknown) => v is any>;

function extractLoginForm(formData: FormData): LoginForm {
  const raw: Record<string, unknown> = {};

  formData.forEach((value, key) => {
    raw[key] = value;
  });

  const errors: string[] = [];

  // 逐一验证每个字段
  for (const [key, guard] of Object.entries(LoginFormSchema)) {
    const value = raw[key];
    if (!guard(value)) {
      errors.push(`Invalid field: ${key}`);
    }
  }

  if (errors.length > 0) {
    throw new FormValidationError(errors);
  }

  // 经过全部守卫后，可以安全地断言
  return raw as LoginForm;
}

// React 组件中的使用
function LoginPage() {
  const handleSubmit = (e: React.FormEvent<HTMLFormElement>) => {
    e.preventDefault();
    const formData = new FormData(e.currentTarget);

    try {
      const loginData = extractLoginForm(formData);
      // loginData → LoginForm，完全类型安全
      auth.login(loginData.username, loginData.password, loginData.rememberMe);
    } catch (err) {
      if (err instanceof FormValidationError) {
        setErrors(err.messages);
      }
    }
  };

  return (
    <form onSubmit={handleSubmit}>
      <input name="username" />
      <input name="password" type="password" />
      <input name="rememberMe" type="checkbox" />
      <button type="submit">登录</button>
    </form>
  );
}
```

### 案例三：localStorage 数据的类型安全读取

localStorage 只能存储字符串，读写时需要序列化和反序列化，这带来了类型安全隐患：

```typescript
/**
 * 类型安全的 localStorage 封装
 */
class TypedStorage {
  /**
   * 读取并验证存储的数据
   */
  static get<T>(key: string, guard: (v: unknown) => v is T): T | null {
    try {
      const raw = localStorage.getItem(key);
      if (raw === null) return null;

      const parsed = JSON.parse(raw);
      return guard(parsed ? parsed : null) ? parsed : null;
    } catch {
      // JSON 解析失败或守卫不通过
      return null;
    }
  }

  /**
   * 写入数据（带过期时间选项）
   */
  static set<T>(key: string, value: T, ttlMs?: number): void {
    const entry = ttlMs
      ? { __data: value, __expiresAt: Date.now() + ttlMs }
      : { __data: value };
    localStorage.setItem(key, JSON.stringify(entry));
  }

  /**
   * 读取带 TTL 的数据（自动清理过期的条目）
   */
  static getWithTTL<T>(
    key: string,
    dataGuard: (v: unknown) => v is T
  ): T | null {
    interface StorageEntry<T> {
      __data: T;
      __expiresAt: number;
    }

    const entry = TypedStorage.get<StorageEntry<T>>(key, (v): v is StorageEntry<T> => (
      v !== null &&
      typeof v === 'object' &&
      '__data' in v &&
      '__expiresAt' in v &&
      typeof (v as any).__expiresAt === 'number'
    ));

    if (!entry) return null;

    // 检查是否过期
    if (Date.now() > entry.__expiresAt) {
      localStorage.removeItem(key);
      return null;
    }

    // 再次验证数据部分
    return dataGuard(entry.__data) ? entry.__data : null;
  }
}

// 定义用户偏好设置的 Schema
const UserPrefsGuard = (v: unknown): v is {
  theme: 'light' | 'dark';
  fontSize: number;
  language: string;
} => {
  if (!v || typeof v !== 'object') return false;
  const o = v as Record<string, unknown>;
  return (
    o.theme === 'light' || o.theme === 'dark') &&
    typeof o.fontSize === 'number' &&
    typeof o.language === 'string'
  );
};

// 在应用初始化时使用
function loadUserPreferences() {
  const prefs = TypedStorage.getWithTTL('user_prefs', UserPrefsGuard);
  if (prefs) {
    applyTheme(prefs.theme);       // prefs.theme → 'light' | 'dark'
    setFontSize(prefs.fontSize);   // prefs.fontSize → number
    setLanguage(prefs.language);   // prefs.language → string
  } else {
    useDefaultPreferences();
  }
}
```

### 案例四：WebSocket 消息的分发守卫

WebSocket 服务端可能发送多种类型的消息，客户端需要根据消息类型做不同的处理：

```typescript
// 消息类型定义
type WSMessage =
  | { type: 'chat'; senderId: string; content: string; timestamp: number }
  | { type: 'user_joined'; userId: string; username: string }
  | { type: 'user_left'; userId: string }
  | { type: 'typing'; userId: string }
  | { type: 'system'; content: string; level: 'info' | 'warning' | 'error' }
  | { type: 'pong' };

// 各类消息的守卫函数
const wsMessageGuards = {
  chat: (msg: unknown): msg is WSMessage & { type: 'chat' } => {
    if (!msg || typeof msg !== 'object') return false;
    const m = msg as Record<string, unknown>;
    return m.type === 'chat' &&
      typeof m.senderId === 'string' &&
      typeof m.content === 'string' &&
      typeof m.timestamp === 'number';
  },

  userJoined: (msg: unknown): msg is WSMessage & { type: 'user_joined' } => {
    if (!msg || typeof msg !== 'object') return false;
    const m = msg as Record<string, unknown>;
    return m.type === 'user_joined' &&
      typeof m.userId === 'string' &&
      typeof m.username === 'string';
  },

  userLeft: (msg: unknown): msg is WSMessage & { type: 'user_left' } => {
    if (!msg || typeof msg !== 'object') return false;
    const m = msg as Record<string, unknown>;
    return m.type === 'user_left' && typeof m.userId === 'string';
  },

  typing: (msg: unknown): msg is WSMessage & { type: 'typing' } => {
    if (!msg || typeof msg !== 'object') return false;
    const m = msg as Record<string, unknown>;
    return m.type === 'typing' && typeof m.userId === 'string';
  },

  system: (msg: unknown): msg is WSMessage & { type: 'system' } => {
    if (!msg || typeof msg !== 'object') return false;
    const m = msg as Record<string, unknown>;
    return m.type === 'system' &&
      typeof m.content === 'string' &&
      (m.level === 'info' || m.level === 'warning' || m.level === 'error');
  },

  pong: (msg: unknown): msg is WSMessage & { type: 'pong' } => {
    if (!msg || typeof msg !== 'object') return false;
    return (msg as Record<string, unknown>).type === 'pong';
  },
};

// 分发器
class WSMessageDispatcher {
  private handlers: Partial<
    Record<WSMessage['type'], (message: WSMessage) => void>
  > = {};

  on<K extends WSMessage['type']>(
    type: K,
    handler: (message: Extract<WSMessage, { type: K }>) => void
  ): this {
    this.handlers[type] = handler;
    return this;
  }

  dispatch(raw: unknown): boolean {
    if (!raw || typeof raw !== 'object') return false;

    const type = (raw as Record<string, unknown>).type;
    if (typeof type !== 'string') return false;

    // 根据消息类型选择守卫
    const guardMap: Record<string, (m: unknown) => m is WSMessage> = {
      chat: wsMessageGuards.chat,
      user_joined: wsMessageGuards.userJoined,
      user_left: wsMessageGuards.userLeft,
      typing: wsMessageGuards.typing,
      system: wsMessageGuards.system,
      pong: wsMessageGuards.pong,
    };

    const guard = guardMap[type];
    if (!guard || !guard(raw)) return false;

    // 找到对应的处理器
    const handler = this.handlers[type as WSMessage['type']];
    if (handler) {
      handler(raw);
    }

    return true;
  }
}

// 使用
const dispatcher = new WSMessageDispatcher()
  .on('chat', msg => {
    // msg → { type: 'chat'; senderId: string; content: string; timestamp: number }
    displayChatMessage(msg.senderId, msg.content);
  })
  .on('user_joined', msg => {
    // msg → { type: 'user_joined'; userId: string; username: string }
    showNotification(`${msg.username} 加入了聊天`);
  })
  .on('system', msg => {
    // msg → { type: 'system'; content: string; level: 'info'|'warning'|'error' }
    if (msg.level === 'error') {
      alert(msg.content);
    } else {
      showToast(msg.content);
    }
  });

// WebSocket 连接的消息处理
ws.onmessage = (event) => {
  try {
    const data = JSON.parse(event.data);
    if (!dispatcher.dispatch(data)) {
      console.warn('Unknown or malformed WebSocket message:', data);
    }
  } catch (e) {
    console.error('Failed to parse WebSocket message:', e);
  }
};
```

## 总结：何时用哪种守卫

面对具体的类型窄化需求，可以参照以下决策树选择合适的守卫策略：

```
需要做类型收窄？
│
├─ 判断原始类型（string/number/boolean...）
│  └──→ typeof 守卫
│
├─ 判断属性是否存在
│  └──→ in 操作符守卫
│
├─ 判断类的实例关系
│  └──→ instanceof 守卫
│
├─ 需要对真假两分支分别处理
│  └──→ 普通 isXxx 守卫函数（value is T）
│
├─ 输入不合法时应立即终止（抛异常），不需要 else 分支
│  └──→ asserts 断言守卫
│
├─ 对象调用某方法后类型/状态会发生转换
│  └──→ this is 类型守卫
│
├─ 需要根据判别属性区分联合类型成员
│  └──→ 可辨识联合 + switch/if 判别属性守卫
│
├─ 验证逻辑需要复用/组合/动态生成
│  └──→ 泛型守卫 + 守卫工厂
│
├─ 数据结构较复杂，手写守卫成本高
│  └──→ 第三方验证库（Zod/Valibot）+ 守卫封装
│
└─ 以上都不是 / 不确定
   └──→ 先尝试最简单的 typeof/in/instanceof，再逐步升级
```

### 最佳实践清单

1. **优先使用内置守卫**——`typeof`、`in`、`instanceof` 是零成本的类型收窄手段
2. **守卫函数命名规范**——统一使用 `is` 或 `assert` 前缀，清晰传达意图
3. **保证运行时正确性**——类型谓词只是编译期的"承诺"，运行时检查才是真实保障
4. **避免过度抽象**——简单的守卫不需要工厂模式或高阶函数包装
5. **善用第三方库**——Zod 等工具能显著减少样板代码，提升类型安全性
6. **注意闭包和作用域**——守卫效果不会跨越异步边界或逃逸出当前作用域
7. **慎用 any**——any 会阻断所有类型窄化机制，用 unknown 替代
8. **性能敏感路径简化守卫**——热路径中避免深拷贝或正则等昂贵操作
9. **用 expects 调试**——当守卫行为不符合预期时，expects 函数是高效的排错工具
10. **文档化复杂守卫**——为非显而易见的守卫逻辑添加注释说明设计意图

类型守卫是连接 TypeScript 静态类型系统和 JavaScript 动态运行时的桥梁。掌握从基础到高级的各种守卫模式，能够在享受编译期类型安全的同时，灵活应对各种运行时数据的不确定性。
