# 符号与唯一符号

Symbol 是 ES2015 引入的第七种原始类型。在 JavaScript 的类型体系中，它填补了一个长期存在的空白：一种**绝对不与其他任何值冲突的标识符**。TypeScript 在此基础上进一步引入了 `unique symbol` 类型，将这种运行时的唯一性延伸到了编译期，形成了一套从值到类型的完整唯一性保证机制。

## 一、JavaScript Symbol 基础回顾

### 1.1 原始类型的新成员

ES2015 之前，JavaScript 有六种原始类型：`undefined`、`null`、`boolean`、`number`、`string`、`bigint`。Symbol 作为第七种原始类型的加入，并非为了数值计算或文本处理这类"常规用途"，而是为了解决一个更根本的问题——**标识符的唯一性保证**。

```ts
// 每次调用 Symbol() 都会返回一个全新的、唯一的值
const s1 = Symbol();
const s2 = Symbol();

console.log(s1 === s2); // false
console.log(typeof s1); // "symbol"
```

描述字符串（description）仅用于调试目的，不影响唯一性判断：

```ts
const s3 = Symbol('debug');
const s4 = Symbol('debug');

console.log(s3 === s4); // false —— 描述相同，但仍是不同的值
```

### 1.2 三种创建方式

```ts
// 方式一：Symbol() —— 每次创建唯一的值
const localSym = Symbol('local');

// 方式二：Symbol.for(key) —— 全局注册表查找或创建
const globalSym1 = Symbol.for('app.id');
const globalSym2 = Symbol.for('app.id');
console.log(globalSym1 === globalSym2); // true

// 方式三：Symbol.keyFor() —— 反查全局注册表中的 key
console.log(Symbol.keyFor(globalSym1)); // 'app.id'
console.log(Symbol.keyFor(localSym));   // undefined（非全局注册表中的 Symbol）
```

`Symbol.for()` 维护一个全局的 **symbol 注册表**（string-to-symbol 映射）。传入相同的字符串 key 会返回同一个 Symbol 实例，这使其适合跨模块、跨上下文共享 symbol 标识符的场景。

**底层原理**：全局注册表在 JavaScript 引擎内部以类似 `WeakMap<string, Symbol>` 的结构实现。引擎在堆内存中维护一个持久化的哈希表，key 为传入的描述字符串，value 为对应的 Symbol 对象。这个注册表的生命周期与运行时环境相同——在浏览器中随页面存在，在 Node.js 中随进程存在。值得注意的是，`Symbol.for()` 的查找使用的是**值相等（same-value equality）**而非引用相等，这意味着即使从不同的代码路径调用，只要传入的字符串内容相同，就能获取到同一个 Symbol。

**实际项目中的使用建议**：`Symbol.for()` 主要用于以下场景：
1. 跨 iframe/Worker 通信时共享协议标识
2. 第三方库之间需要协商一个公共标识但不引入外部依赖
3. 插件系统中的扩展点标记

**错误演示**：常见错误是误以为 `Symbol.for()` 的作用域是模块级别的：

```ts
// ❌ 错误理解：认为每个模块有独立的注册表
// 实际上 Symbol.for 的注册表是全局的
const localKey = Symbol.for('myapp:config');
// 另一个文件中同样调用 Symbol.for('myapp:config') 会得到完全相同的值
// 这可能导致跨模块的意外耦合

// ✅ 正确做法：如果需要模块级唯一性，用 Symbol() 而非 Symbol.for()
const moduleScopedKey = Symbol('myapp:config'); // 每次调用都返回新值

// ✅ 如果确实需要全局共享，使用命名空间前缀避免冲突
const sharedKey = Symbol.for('@mylib/core:init'); // 加上库作用域前缀
```

### 1.3 作为对象属性键

Symbol 值可以作为对象的属性键使用，这是其最核心的应用场景：

```ts
const id = Symbol('id');
const user = {
  name: 'Alice',
  [id]: 42,       // 计算属性名语法
};

console.log(user[id]);     // 42
console.log(user['id']);   // undefined —— 字符串 'id' 和 Symbol 不匹配
```

用 Symbol 作键的最大优势在于**不会与任何字符串属性名产生冲突**：

```ts
const metadata = Symbol('metadata');

function attachMeta(obj: object, data: unknown) {
  (obj as any)[metadata] = data;
}

const target = { name: 'test' };
attachMeta(target, { created: Date.now() });

// 目标对象原有的 name 属性完全不受影响
// metadata 属性也不会被普通的对象遍历意外获取
```

**为什么需要 Symbol 键**：在 JavaScript 中，所有字符串键共享同一个命名空间。当多个库或模块操作同一对象时，键名冲突几乎是不可避免的。例如，两个不同的库可能都使用 `data` 或 `meta` 作为属性名。Symbol 通过引入一个**独立的命名空间**从根本上解决了这个问题——Symbol 键和字符串键永远不会相等（即使使用相同的描述字符串），不同 Symbol 之间也永远不相等。

**更多实际示例**：

**示例：安全地扩展第三方对象**

```ts
// 扩展一个来自第三方的用户对象，不污染其原有属性
function enrichUser(user: Record<string, any>) {
  const _cache = Symbol('cache');
  const _computed = Symbol('computed');

  // 存储派生数据，不影响原始对象的 JSON 序列化
  (user as any)[_cache] = {
    fullName: `${user.firstName} ${user.lastName}`,
    displayName: user.nickname || user.firstName,
  };

  // 标记已处理状态
  (user as any)[_computed] = true;

  return user;
}

// 原有行为不受影响
const user = enrichUser({ firstName: '张', lastName: '三', nickname: '阿三' });
console.log(JSON.stringify(user));
// {"firstName":"张","lastName":"三","nickname":"阿三"} —— Symbol 键被自动排除
```

**示例：防止原型链污染攻击**

```ts
// 安全的配置合并 —— 即使恶意输入包含 __proto__、constructor 等键也不受影响
const MERGE_TARGET = Symbol('mergeTarget');

function safeMerge(base: any, override: any): any {
  // 使用 Symbol 作为内部存储键，彻底隔离用户输入
  const result = { [MERGE_TARGET]: base };

  for (const key of Object.keys(override)) {
    if (key !== '__proto__' && key !== 'constructor' && key !== 'prototype') {
      result[key] = override[key];
    }
  }

  return result;
}

// 即使传入恶意数据
safeMerge({}, { __proto__: { malicious: true } });
// 结果对象的原型链不会被污染，因为赋值目标使用了 Symbol 隔离
```

## 二、TypeScript 中对 Symbol 的类型支持

### 2.1 基本类型声明

TypeScript 将 `symbol` 作为一个独立的原始类型，与 `string`、`number` 等平级：

```ts
let sym: symbol = Symbol();
let str: string = 'hello';

sym = str; // Error: Type 'string' is not assignable to type 'symbol'
str = sym; // Error: Type 'symbol' is not assignable to type 'string'
```

### 2.2 作为属性键的类型签名

当需要表示一个以 Symbol 为键的对象属性时，可以使用计算属性名语法配合类型标注：

```ts
const myKey = Symbol('myKey');

interface Container {
  name: string;
  [myKey]: number;        // 特定 unique symbol 作为键
  [index: symbol]: string; // 任意 symbol 作为键的索引签名
}
```

这里有两种截然不同的用法：
- `[myKey]`: 绑定到一个**具体的 unique symbol** 变量，该属性只能通过这个确切的 symbol 访问
- `[index: symbol]`: 索引签名，允许任意 symbol 值作为键

**TypeScript 编译器如何处理 Symbol 键的类型**：当编译器遇到 `[uniqueSymbol]: Type` 形式的声明时，它会在内部创建一个名为 `typeof variableName` 的特殊类型，该类型是 `symbol` 的子类型，且仅包含该变量的唯一值。对于索引签名 `[index: symbol]`，编译器则将其视为一个开放的 symbol 键集合。这两者的关键区别在于：前者是**确定的、可枚举的**（在类型层面），后者是**不确定的**。

**实际项目中的使用建议**：
- 当你需要为对象定义已知的、固定的 Symbol 属性时，使用 unique symbol 索引签名
- 当你需要接受任意的 Symbol 键时（如构建通用字典），使用 `symbol` 索引签名
- 两种索引签名可以同时存在于同一接口中

### 2.3 内置 Well-known Symbols 一览

ECMAScript 规范定义了一组内置的 well-known symbols（知名符号），它们作为某些语言内部协议的钩子存在。TypeScript 为这些内置 symbol 提供了完整的类型定义：

| Well-known Symbol | 用途 | 对应协议 |
|---|---|---|
| `Symbol.iterator` | 迭代器方法 | for...of 循环、展开运算符 |
| `Symbol.asyncIterator` | 异步迭代器方法 | for await...of 循环 |
| `Symbol.toStringTag` | Object.toString() 的描述标签 | `Object.prototype.toString.call()` |
| `Symbol.toPrimitive` | 类型转换钩子 | 隐式转换场景 |
| `Symbol.hasInstance` | instanceof 操作符行为 | `instanceof` 表达式 |
| `Symbol.isConcatSpreadable` | Array.concat 是否展平 | `Array.prototype.concat()` |
| `Symbol.species` | 派生对象构造函数选择 | map/filter 等返回新实例的方法 |
| `Symbol.match` | 字符串匹配行为 | `String.prototype.match()` |
| `Symbol.replace` | 字符串替换行为 | `String.prototype.replace()` |
| `Symbol.search` | 字符串搜索行为 | `String.prototype.search()` |
| `Symbol.split` | 字符串分割行为 | `String.prototype.split()` |

这些 well-known symbols 是全局单例，可以直接引用：

```ts
// 这些是全局存在的内置 symbol 值
const iter = Symbol.iterator;      // typeof iter === "symbol"
const asyncIter = Symbol.asyncIterator;
const tag = Symbol.toStringTag;
```

## 三、unique symbol —— TS 特有的类型

### 3.1 什么是 unique symbol

`unique symbol` 是 TypeScript 引入的一种特殊类型，它是 `symbol` 类型的**子类型**。可以把 unique symbol 理解为 Symbol 值的字面量类型等价物——正如 `"hello"` 是 `string` 的字面量类型、`42` 是 `number` 的字面量类型一样，每个被声明为 unique symbol 的变量都拥有一个**独一无二的类型标识**。

```ts
const s1 = Symbol(); // 类型为 unique symbol
const s2 = Symbol(); // 类型为 unique symbol（与 s1 的类型不同）

let s3: symbol = Symbol(); // 类型为普通 symbol

s3 = s1; // ok —— unique symbol 可以赋值给 symbol（子类型赋值给父类型）
s1 = s3; // Error —— 不能将 symbol 赋值给 unique symbol
s1 = s2; // Error —— 即使都是 unique symbol，也不能互相赋值
```

### 3.2 const 与 let 的关键差异

推断是否为 unique symbol，取决于声明方式：

```ts
// const 声明 —— 推断为 unique symbol
const a = Symbol('a');      // typeof a === unique symbol

// let 声明 —— 推断为普通 symbol
let b = Symbol('b');         // typeof b === symbol

// 显式标注 —— 只能标注为普通 symbol（无法手动写 unique symbol）
const c: symbol = Symbol();  // typeof c === symbol（显式标注覆盖了推断）

// 如果确实需要 unique symbol，可以用 as const 断言
const d = Symbol() as const; // typeof d === unique symbol
```

核心规则：**只有用 `const` 声明且未显式标注类型的 Symbol 才会被推断为 unique symbol**。这是因为 `let` 声明的变量可以被重新赋值，而 unique symbol 的本质要求是不可变的唯一性绑定。

**编译器推断的完整决策树**：

```
声明一个 Symbol 值
  ├─ 用 const 声明？
  │   ├─ 是 → 显式标注了类型（: symbol）？
  │   │   ├─ 是 → 类型为 symbol（普通类型）
  │   │   └─ 否 → 类型为 unique symbol
  │   └─ 否（用 let）→ 类型为 symbol
  └─ 使用 as const 断言？→ 类型为 unique symbol
```

**为什么 TypeScript 这样设计**：unique symbol 的核心语义是"这个变量绑定到一个不可变的、唯一的值"。`let` 允许重新赋值，这与"不变性"矛盾；显式类型标注 `: symbol` 则是开发者明确表示"我只关心它是 symbol，不需要唯一性"。TypeScript 通过这种保守策略避免了类型系统中的矛盾。

**边界情况示例**：

```ts
// 解构声明 —— 推断为普通 symbol
let { sym } = { sym: Symbol() }; // typeof sym === symbol

// 数组元素 —— 推断为普通 symbol
const syms = [Symbol(), Symbol()]; // typeof syms === symbol[]

// 对象属性值 —— 推断为普通 symbol
const obj = { key: Symbol() };     // typeof obj.key === symbol

// 函数返回值 —— 推断为普通 symbol
function createSym() {
  return Symbol(); // 返回类型为 symbol
}

// ✅ 获取 unique symbol 的可靠方式
const unique = Symbol('desc');           // const + 无标注
const alsoUnique = Symbol('desc') as const; // as const 断言

// ❌ 常见的错误尝试
function getUnique(): unique symbol { // Error: 不能用 unique symbol 作为返回类型标注
  return Symbol();
}
```

### 3.3 核心特征总结

unique symbol 具有以下四个关键特征：

**特征一：每个变量绑定唯一的类型标识**

```ts
const keyA = Symbol('a'); // 类型：typeof keyA（一个独有的类型名称）
const keyB = Symbol('b'); // 类型：typeof keyB（另一个独有的类型名称）
// TypeScript 内部为每个 unique symbol 生成一个基于变量名的类型名称
```

**特征二：只能赋值给它自己**

```ts
const target = Symbol('target');
let other: symbol = Symbol();

target = other; // Error: Type 'symbol' is not assignable to type 'typeof target'
target = target; // ok —— 赋值给自己是允许的（虽然无意义）
```

**特征三：不能用普通 symbol 类型替代**

```ts
function acceptUnique(sym: typeof someUniqueSym) { /* ... */ }
acceptUnique(Symbol()); // Error —— 参数不是那个特定的 unique symbol
acceptUnique(someUniqueSym); // ok
```

**特征四：编译期级别的属性唯一性保证**

```ts
const privateField = Symbol('private');

interface HasPrivate {
  [privateField]: string;
  [anotherUnique]: number; // 假设 anotherUnique 也是 const 声明的
}

// 编译器能区分这两个属性，即使它们在运行时都是 Symbol 类型的键
```

## 四、用 unique symbol 定义私有属性/方法

### 4.1 问题背景

在 ES2020 引入私有字段语法（`#field`）之前，JavaScript 没有真正意义上的私有属性。开发者通常采用以下变通方案：

- **下划线前缀约定**：`_private` —— 仅靠命名约定，无实际保护
- **闭包模式**：构造函数内定义局部变量 —— 无法在原型方法上访问
- **WeakMap 模式**：用实例作为 WeakMap 键 —— 存储分离，语法繁琐

unique symbol + 计算属性名提供了一种兼顾可读性和安全性的方案。

### 4.2 完整实现示例

```ts
const _name = Symbol('name');
const _validate = Symbol('validate');

class User {
  public id: number;

  constructor(id: number, name: string) {
    this.id = id;
    this[_name] = name;
  }

  get userName(): string {
    return this[_name];
  }

  set userName(value: string) {
    this[_validate](value);
    this[_name] = value;
  }

  private [_validate](value: string): void {
    if (value.length < 2) {
      throw new Error('Name must be at least 2 characters');
    }
  }
}

const user = new User(1, 'Alice');

console.log(user.userName); // Alice
user.userName = 'Bob';      // ok
user.userName = 'A';        // Error: Name must be at least 2 characters

// 外部代码无法直接访问这些属性
user[_name];          // Error —— _name 未在该作用域中定义（如果 _name 未导出）
user['name'];         // undefined —— 字符串键和 Symbol 键不同
```

**关键点**：如果 `_name` 和 `_validate` 不导出，外部模块根本无法获取这两个 symbol 值，因此也就无法访问对应的属性。这实现了**真正的私有性**。

**更多实际示例——带泛型的私有属性类**：

```ts
// 实现一个类型安全的 observable（可观察）包装器
const _value = Symbol('value');
const _listeners = Symbol('listeners');
const _emit = Symbol('emit');

class Observable<T> {
  constructor(initialValue: T) {
    (this as any)[_value] = initialValue;
    (this as any)[_listeners] = new Set<(val: T, prev: T) => void>();
  }

  get value(): T {
    return (this as any)[_value];
  }

  set value(newValue: T) {
    const prev = (this as any)[_value];
    (this as any)[_value] = newValue;
    (this as any)[_emit](newValue, prev);
  }

  subscribe(listener: (val: T, prev: T) => void): () => void {
    (this as any)[_listeners].add(listener);
    // 返回取消订阅函数
    return () => { (this as any)[_listeners].delete(listener); };
  }

  private [_emit](newValue: T, prev: T): void {
    for (const listener of (this as any)[_listeners]) {
      listener(newValue, prev);
    }
  }
}

const count = new Observable(0);
const unsub = count.subscribe((val, prev) => {
  console.log(`Count changed: ${prev} -> ${val}`);
});

count.value = 1; // Count changed: 0 -> 1
count.value = 5; // Count changed: 1 -> 5
unsub(); // 取消订阅
count.value = 10; // 不再输出 —— 已取消订阅

// 外部无法访问内部状态
console.log(count[_listeners]); // Error —— _listeners 未定义
```

### 4.3 与其他方案的对比

```ts
// 方案 A：private 关键字（TS 编译时检查，编译后仍可访问）
class A {
  private secret = 123;
}

// 编译为 JS 后：
// A.prototype.secret 或实例.secret 仍然可以访问
// private 仅在 TS 编译期生效

// 方案 B：# 私有字段（ES2020 语法，运行时强制私有）
class B {
  #secret = 456;

  getSecret() { return this.#secret; }
}

const b = new B();
b.#secret; // SyntaxError —— 语法层面就不允许外部访问

// 方案 C：unique symbol（TS 3.9+ 之前的主流方案）
const _secret = Symbol('secret');
class C {
  [_secret] = 789;
}
// 外部无法获取 _secret 这个 Symbol，因此无法访问对应属性
```

| 特性 | `private` 关键字 | `#` 私有字段 | `unique symbol` |
|---|---|---|---|
| 编译期检查 | 有 | 不适用（语法级限制） | 有 |
| 运行时保护 | 无（编译后消失） | 有（语法错误） | 有（需获取 symbol） |
| 子类可访问 | 可（protected） | 不可 | 取决于 symbol 可见性 |
| 兼容性 | 所有 TS 版本 | ES2020+ / TS 3.8+ | 所有支持 Symbol 的版本 |
| 序列化 | 正常序列化 | 正常序列化 | 被 JSON.stringify 跳过 |

### 4.4 为什么仍需了解这个模式

尽管 ES2020 的 `#` 私有字段语法更为简洁，了解 unique symbol 私有属性模式仍有其价值：

- **维护旧代码库**：大量 TS 3.9 之前的代码使用了此模式
- **跨实例共享私有状态**：`#` 字段是按实例存储的，而 unique symbol 可以配合 WeakMap 实现类级别的私有存储
- **动态属性场景**：需要在运行时动态添加私有属性时，`#` 语法不支持，而 symbol 方案灵活得多
- **mixin 和装饰器**：这些元编程场景下，`#` 语法受限较多

## 五、Symbol 在接口和类中的使用

### 5.1 接口中定义 Symbol 属性索引签名

```ts
interface SymbolValuedMap {
  // 字符串索引
  [key: string]: unknown;
  // Symbol 索引
  [key: symbol]: unknown;
}

// 同时支持两种键的类型
interface HybridMap {
  [key: string]: string;
  [key: symbol]: number;
}

const map: HybridMap = {};
map['name'] = 'Alice';
map[Symbol('id')] = 42; // ok
```

注意：接口中不能同时拥有数字索引签名和字符串索引签名（因为数字会被转换为字符串），但 **symbol 索引签名可以和字符串索引签名共存**，因为 symbol 和字符串永远不会冲突。

### 5.2 实现 Symbol.iterator —— 自定义迭代器

```ts
class Range {
  constructor(
    private start: number,
    private end: number,
    private step: number = 1
  ) {}

  [Symbol.iterator](): Iterator<number> {
    let current = this.start;
    return {
      next(): IteratorResult<number> {
        if (current < this.end) {
          const value = current;
          current += this.step;
          return { value, done: false };
        }
        return { value: undefined as any, done: true };
      },
    };
  }
}

// 使用 for...of 循环遍历
for (const n of new Range(0, 10, 2)) {
  console.log(n); // 0, 2, 4, 6, 8
}

// 使用展开运算符
console.log([...new Range(1, 5)]); // [1, 2, 3, 4]
```

### 5.3 实现 Symbol.asyncIterator —— 异步迭代器

```ts
class AsyncRange {
  constructor(
    private start: number,
    private end: number
  ) {}

  async *[Symbol.asyncIterator](): AsyncIterableIterator<number> {
    for (let i = this.start; i < this.end; i++) {
      await new Promise(resolve => setTimeout(resolve, 100)); // 模拟异步操作
      yield i;
    }
  }
}

// 使用 for await...of
async function consume() {
  for await (const n of new AsyncRange(0, 5)) {
    console.log(n);
  }
}
```

### 5.4 Symbol.toPrimitive 的类型安全实现

```ts
type Hint = 'default' | 'number' | 'string';

class Currency {
  constructor(private amount: number, private code: string = 'CNY') {}

  [Symbol.toPrimitive](hint: Hint): string | number {
    switch (hint) {
      case 'string':
        return `${this.amount.toFixed(2)} ${this.code}`;
      case 'number':
        return this.amount;
      default:
        return `${this.amount}`;
    }
  }
}

const price = new Currency(99.99);

console.log(String(price));   // "99.99 CNY"
console.log(+price);          // 99.99
console.log(`${price}`);      // "99.99"（default hint）
```

`[Symbol.toPrimitive]` 方法接收一个 `hint` 参数，指示期望的转换目标类型。TypeScript 要求返回类型兼容 `string | number`（或包含 `boolean` + `bigint` 的联合类型）。

**为什么需要 Symbol.toPrimitive**：JavaScript 引擎在进行隐式类型转换时，会按以下优先级查找转换方法：
1. 如果存在 `Symbol.toPrimitive`，优先调用它
2. 否则根据 hint 分别尝试 `valueOf()`（`number`）或 `toString()`（`string`）

通过 `Symbol.toPrimitive` 可以统一控制所有隐式转换行为，避免 `valueOf` 和 `toString` 之间逻辑不一致的问题。

**更多实际示例——自定义布尔包装类**：

```ts
class SafeBoolean {
  constructor(private value: boolean) {}

  [Symbol.toPrimitive](hint: string): boolean | string | number {
    switch (hint) {
      case 'string':
        return this.value ? 'true' : 'false';
      case 'number':
        return this.value ? 1 : 0;
      default:
        // default hint 用于算术运算和字符串拼接
        return this.value;
    }
  }
}

const truthy = new SafeBoolean(true);
const falsy = new SafeBoolean(false);

console.log(String(truthy));  // "true"
console.log(+truthy);         // 1
console.log(`${falsy}`);      // "false"

// 在条件判断中也能正确工作
if (truthy) { /* 执行 */ }   // 正确进入分支
```

### 5.5 Symbol.toStringTag 定制

```ts
class CustomCollection<T> implements Iterable<T> {
  private items: T[] = [];

  add(item: T): void {
    this.items.push(item);
  }

  get [Symbol.toStringTag](): string {
    return 'CustomCollection';
  }

  [Symbol.iterator](): Iterator<T> {
    return this.items[Symbol.iterator]();
  }
}

const coll = new CustomCollection<string>();
coll.add('a');
coll.add('b');

console.log(Object.prototype.toString.call(coll));
// "[object CustomCollection]" —— 而非默认的 "[object Object]"
```

这对于开发库和框架特别有用：用户调用 `Object.prototype.toString` 时能看到有意义的类型信息而非千篇一律的 `"[object Object]"`。

## 六、Symbol 在映射/字典中的优势

### 6.1 字符串键的风险

用普通字符串作为字典的键存在潜在风险：

```ts
const dict: Record<string, number> = {};

dict['__proto__'] = 1;  // 可能影响原型链
dict['constructor'] = 2; // 可能覆盖继承的属性

for (const k in dict) {
  console.log(k); // 可能遍历到非预期的继承属性
}
```

即使使用 `Object.create(null)` 创建无原型对象来规避这个问题，也无法从根本上消除**键名冲突的可能性**——两个不同模块可能恰好选择了相同的字符串键名。

### 6.2 Symbol 键的天然安全性

```ts
const dict: Record<symbol, number> = {};

const moduleAKey = Symbol('moduleA.data');
const moduleBKey = Symbol('moduleB.data');

dict[moduleAKey] = 1;
dict[moduleBKey] = 2;

// 两个键永远不会冲突，无论描述字符串是否相同
// 也不会影响任何原型链属性
```

### 6.3 选择策略对比

```ts
// Record<string, T>
// 适用：键是用户输入、需要序列化、需要与 JSON 互通
const config: Record<string, string> = {
  host: 'localhost',
  port: '3000',
};

// Map<Symbol, T>
//适用：键是程序内部生成的标识符、需要保证唯一性
const eventHandlers = new Map<symbol, Function>();
const clickHandler = Symbol('click');
eventHandlers.set(clickHandler, () => { /* ... */ });

// WeakMap<object, T>
// 适用：键是对象、需要自动垃圾回收
const metaData = new WeakMap<object, { created: number }>();
metaData.set(obj, { created: Date.now() });
```

**决策树**：
- 需要 JSON 序列化 → `Record<string, T>` 或 `Map<string, T>`
- 键是对象且需要 GC 回收 → `WeakMap<object, T>`
- 需要绝对的键唯一性保证 → `Map<Symbol, T>`
- 键既可能是字符串也可能是 Symbol → 接口中同时定义两种索引签名

### 6.4 实战案例：事件系统的事件名设计

```ts
// event-types.ts —— 集中管理事件 Symbol
export const EVENTS = {
  // 用户相关
  USER_LOGIN: Symbol('user.login'),
  USER_LOGOUT: Symbol('user.logout'),
  USER_UPDATE: Symbol('user.update'),

  // 数据相关
  DATA_FETCH: Symbol('data.fetch'),
  DATA_SAVE: Symbol('data.save'),

  // UI 相关
  MODAL_OPEN: Symbol('ui.modal.open'),
  MODAL_CLOSE: Symbol('ui.modal.close'),
} as const;

// emitter.ts
type EventHandler = (...args: unknown[]) => void;

class EventEmitter {
  private handlers = new Map<symbol, Set<EventHandler>>();

  on(event: symbol, handler: EventHandler): void {
    if (!this.handlers.has(event)) {
      this.handlers.set(event, new Set());
    }
    this.handlers.get(event)!.add(handler);
  }

  emit(event: symbol, ...args: unknown[]): void {
    const handlers = this.handlers.get(event);
    if (handlers) {
      handlers.forEach(h => h(...args));
    }
  }

  off(event: symbol, handler?: EventHandler): void {
    if (!handler) {
      this.handlers.delete(event);
      return;
    }
    this.handlers.get(event)?.delete(handler);
  }
}

// 使用方
import { EVENTS } from './event-types';

const emitter = new EventEmitter();

emitter.on(EVENTS.USER_LOGIN, (userId) => {
  console.log(`User logged in: ${userId}`);
});

emitter.emit(EVENTS.USER_LOGIN, 'user-123');
```

使用 Symbol 作为事件名的优势：
- **零冲突风险**：不同模块的事件名绝不会意外重复
- **类型安全**：传入错误的 Symbol 会在编译期被发现
- **不可伪造**：外部代码无法猜测或枚举合法的事件名
- **自文档化**：集中的事件注册表一目了然

## 七、元数据键模式（Metadata Key Pattern）

### 7.1 核心思想

利用 Symbol 属性的三个特性来实现"隐藏属性"的效果：

1. **不参与常规遍历**：`Object.keys()`、`Object.entries()`、`for...in` 都不会返回 Symbol 键属性
2. **不被 JSON 序列化**：`JSON.stringify()` 会跳过所有 Symbol 键属性
3. **不与字符串属性冲突**：Symbol 键和字符串键是完全独立的命名空间

### 7.2 库内部状态标记

```ts
// library.ts
const _initialized = Symbol('initialized');
const _version = Symbol('version');

function createInstance(options: Options) {
  const instance = {
    // 公开 API
    doWork() { /* ... */ },

    // 隐藏的内部状态
    [_initialized]: false,
    [_version]: '2.0.0',
  };

  initInternal(instance); // 内部初始化逻辑
  return instance;
}
```

使用者调用 `Object.keys(instance)` 时看不到 `_initialized` 和 `_version`，对 JSON 序列化也完全透明。

### 7.3 依赖注入的 token

```ts
// di-tokens.ts —— 定义依赖注入的 token
export const DI_TOKENS = {
  DATABASE: Symbol('di.database'),
  LOGGER: Symbol('di.logger'),
  CONFIG: Symbol('di.config'),
  CACHE: Symbol('di.cache'),
} as const;

// container.ts
class DIContainer {
  private providers = new Map<symbol, any>();

  register<T>(token: symbol, provider: () | T): void {
    this.providers.set(token, provider);
  }

  resolve<T>(token: symbol): T {
    const provider = this.providers.get(token);
    if (!provider) throw new Error(`No provider for token`);
    return provider as T;
  }
}

// 使用方
container.register(DI_TOKENS.DATABASE, new DatabaseClient());
const db = container.resolve<DatabaseClient>(DI_TOKENS.DATABASE);
```

用 Symbol 做 DI token 比用字符串更安全——不可能因拼写错误而意外匹配到另一个服务的 token。

### 7.4 装饰器元数据存储

```ts
const METADATA_KEY = Symbol('design:metadata');

function Entity(tableName: string) {
  return function (constructor: Function) {
    Reflect.defineMetadata(METADATA_KEY, { tableName }, constructor);
  };
}

@Entity('users')
class User {
  constructor(public name: string) {}
}

// 读取元数据
const meta = Reflect.getMetadata(METADATA_KEY, User);
console.log(meta); // { tableName: 'users' }
```

实际上，TypeScript 的实验性装饰器元数据系统（`emitDecoratorMetadata`）内部就大量使用了 Symbol 来存储反射信息。

### 7.5 缓存/记忆化的标记位

```ts
const _cached = Symbol('cached');
const _result = Symbol('result');

function memoize<T extends (...args: any[]) => any>(fn: T): T {
  const memoized = function (this: any, ...args: Parameters<T>) {
    if ((memoized as any)[_cached]) {
      return (memoized as any)[_result];
    }
    const result = fn.apply(this, args);
    (memoized as any)[_cached] = true;
    (memoized as any)[_result] = result;
    return result;
  } as T;

  return memoized;
}

const expensiveCalculation = memoize((n: number) => {
  console.log('Computing...');
  return n * n * n;
});

expensiveCalculation(5); // Computing... -> 125
expensiveCalculation(5); // 直接返回缓存结果 125，不再打印

// 缓存标记对外部不可见
console.log(Object.keys(expensiveCalculation)); // [] —— 看不到 _cached 和 _result
```

## 八、Symbol 在泛型编程中的应用

### 8.1 泛型约束中包含 Symbol

```ts
// 约束键可以是 string | number | symbol
function getProperty<K extends string | symbol>(
  obj: Record<K, any>,
  key: K
): any {
  return obj[key];
}

const symKey = Symbol('key');
getProperty({ [symKey]: 42 }, symKey); // ok
getProperty({ name: 'test' }, 'name');  // ok
```

### 8.2 类型安全的字典操作

```ts
type SymbolDict<V> = {
  get<K extends symbol>(key: K): V | undefined;
  set<K extends symbol>(key: K, value: V): void;
  has<K extends symbol>(key: K): boolean;
};

class TypedSymbolMap<V> implements SymbolDict<V> {
  private data = new Map<symbol, V>();

  get<K extends symbol>(key: K): V | undefined {
    return this.data.get(key);
  }

  set<K extends symbol>(key: K, value: V): void {
    this.data.set(key, value);
  }

  has<K extends symbol>(key: K): boolean {
    return this.data.has(key);
  }
}

// 使用
const map = new TypedSymbolMap<string>();
const key1 = Symbol('k1');
const key2 = Symbol('k2');

map.set(key1, 'value1');
map.get(key1); // 'value1'
map.has(key2); // false
```

### 8.3 Record<symbol, V> 的实际用途

`Record<symbol, V>` 表示一个所有可能的 Symbol 键都映射到 V 类型的对象。这在实践中较少直接使用（因为无法穷举所有 Symbol），但在类型组合中有其价值：

```ts
// 混合键类型
interface MixedStore {
  // 字符串键映射到字符串值
  strings: Record<string, string>;
  // Symbol 键映射到数字值
  symbols: Record<symbol, number>;
}

function createStore(): MixedStore {
  const store: any = {};

  // 代理方式同时支持两种键
  return new Proxy(store, {
    get(target, prop) {
      if (typeof prop === 'symbol') return target[prop];
      // 处理字符串键...
      return undefined;
    },
  });
}
```

更实用的做法是将特定的一组 unique symbol 作为联合类型：

```ts
const KEY_A = Symbol('a') as const;
const KEY_B = Symbol('b') as const;
const KEY_C = Symbol('c') as const;

type KnownSymbols = typeof KEY_A | typeof KEY_B | typeof KEY_C;

interface SymbolConfig {
  [KEY_A]: string;
  [KEY_B]: number;
  [KEY_C]: boolean;
}

function getConfigValue<K extends KnownSymbols>(
  config: SymbolConfig,
  key: K
): SymbolConfig[K] {
  return config[key];
}

const cfg: SymbolConfig = {
  [KEY_A]: 'hello',
  [KEY_B]: 42,
  [KEY_C]: true,
};

getConfigValue(cfg, KEY_A); // 类型为 string
getConfigValue(cfg, KEY_B); // 类型为 number
```

这种模式结合了 unique symbol 的**精确类型推导**和联合类型的**灵活约束**。

## 九、运行时行为与类型系统的交互

理解 Symbol 的运行时行为对于正确设计类型至关重要。

### 9.1 序列化行为

```ts
const sym = Symbol('mySymbol');
const obj = {
  name: 'test',
  [sym]: 42,
  nested: { [sym]: 'hidden' },
};

console.log(JSON.stringify(obj));
// '{"name":"test","nested":{}}'
// Symbol 键属性被完全忽略
```

这意味着 **不能用 Symbol 键来存储需要持久化的数据**。如果数据需要序列化传输，必须使用字符串键。

**实际项目中的使用建议——Symbol 键与数据持久化策略**：

```ts
// 场景：一个既有运行时元数据又有可序列化数据的对象
const _runtimeMeta = Symbol('runtimeMeta');

interface PersistableUser {
  id: string;
  name: string;
  email: string;
  [_runtimeMeta]?: {
    lastAccessTime: number;
    requestCount: number;
    isDirty: boolean;
  };
}

// 序列化时自动排除运行时元数据 —— 无需手动过滤
function saveUser(user: PersistableUser): string {
  return JSON.stringify(user);
  // _runtimeMeta 属性被自动忽略
}

// 反序列化后重新附加运行时元数据
function loadUser(json: string): PersistableUser {
  const data = JSON.parse(json) as PersistableUser;
  (data as any)[_runtimeMeta] = {
    lastAccessTime: Date.now(),
    requestCount: 0,
    isDirty: false,
  };
  return data;
}

const user = { id: '1', name: '张三', email: 'z@example.com' };
(user as any)[_runtimeMeta] = { lastAccessTime: Date.now(), requestCount: 5, isDirty: true };

const serialized = saveUser(user); // {"id":"1","name":"张三","email":"z@example.com"}
const restored = loadUser(serialized);
console.log((restored as any)[_runtimeMeta]); // 运行时元数据已恢复
```

**错误演示——误用 Symbol 键存储持久化数据**：

```ts
// ❌ 错误做法：将需要持久化的数据存在 Symbol 键下
const sessionToken = Symbol('sessionToken');

function login(credentials: Credentials) {
  const user = processLogin(credentials);
  // 将 token 存储在 Symbol 键下
  (user as any)[sessionToken] = generateToken();
  
  // 发送到客户端或存入 localStorage
  sendToClient(JSON.stringify(user));
  // 问题：token 在序列化过程中丢失！客户端收到的是不完整的用户对象
}

// ✅ 正确做法：需要持久化的数据使用字符串键
interface SessionData {
  user: UserInfo;      // 用户基本信息（可序列化）
  token: string;        // token（可序列化）
}
```

### 9.2 对象遍历行为

```ts
const sym = Symbol('iter');
const obj = {
  a: 1,
  b: 2,
  [sym]: 3,
};

console.log(Object.keys(obj));           // ['a', 'b']
console.log(Object.getOwnPropertyNames(obj)); // ['a', 'b']
console.log(Object.entries(obj));         // [['a', 1], ['b', 2]]

// 只有以下方法能获取到 Symbol 属性
console.log(Object.getOwnPropertySymbols(obj)); // [Symbol(iter)]
console.log(Reflect.ownKeys(obj));             // ['a', 'b', Symbol(iter)]
```

| 方法 | 字符串属性 | Symbol 属性 |
|---|---|---|
| `for...in` | 枚举自身+继承的可枚举字符串属性 | 不返回 |
| `Object.keys()` | 自身的可枚举字符串属性 | 不返回 |
| `Object.entries()` | 自身的可枚举字符串属性 | 不返回 |
| `Object.getOwnPropertyNames()` | 自身所有字符串属性 | 不返回 |
| `Object.getOwnPropertySymbols()` | 不返回 | 自身所有 Symbol 属性 |
| `Reflect.ownKeys()` | 自身所有字符串属性 | 自身所有 Symbol 属性 |

### 9.3 对类型设计的影响

上述运行时特性直接影响类型设计决策：

**场景一：需要隐藏的配置项**

```ts
const _internal = Symbol('internal');

interface Config {
  visibleOption: string;
  [_internal]: InternalOptions; // 外部代码难以发现和访问
}
```

**场景二：需要遍历的数据**

```ts
// ❌ 不要这样做 —— Symbol 键无法被 for...of 遍历
interface BadDesign {
  [key: symbol]: Item;
}

// ✅ 使用 Map 代替
const itemMap = new Map<symbol, Item>();
itemMap.forEach((v, k) => { /* 可以遍历 */ });
```

**场景三：需要克隆/合并的对象**

```ts
function clone<T extends object>(obj: T): T {
  const cloned = { ...obj }; // 浅拷贝
  // 注意：展开运算符会复制 Symbol 键的可枚举属性
  return cloned;
}

// 但 JSON.parse(JSON.stringify()) 这种深拷贝方式会丢失 Symbol 键属性
```

## 十、常见陷阱

### 陷阱一：Symbol 不是构造函数

```ts
// ❌ 错误
const s = new Symbol(); // TypeError: Symbol is not a constructor

// ✅ 正确
const s = Symbol();     // 作为函数调用，不用 new
```

Symbol 设计上故意禁止 `new` 调用，因为它不需要包装对象（不像 `Number()`、`String()` 等）。`Symbol()` 总是返回一个原始 symbol 值。

### 陷阱二：Symbol.for 不是 unique symbol

```ts
// Symbol.for() 返回的是普通 symbol 类型，不是 unique symbol
const shared1 = Symbol.for('shared');
const shared2 = Symbol.for('shared');

console.log(shared1 === shared2); // true —— 它们是同一个值

// 类型角度
let s1: symbol = Symbol.for('x');  // 普通 symbol
const s2 = Symbol('y');            // unique symbol
```

`Symbol.for` 的语义是**全局共享**，这与 unique symbol 的**唯一绑定**理念正好相反。两者服务于不同的场景：
- `Symbol.for()`：跨模块/跨上下文共享同一个 symbol
- `Symbol()` + `const`：确保本地唯一、不可复制的标识符

### 陷阱三：unique symbol 不能作为函数参数类型（过于严格）

```ts
const specificSym = Symbol('specific');

// ❌ 过于严格 —— 几乎没有实用价值
function process(sym: typeof specificSym) {
  // 只有 exact same value 能传进来
}
process(specificSym); // ok
process(Symbol());    // Error —— 这正是 unique symbol 的设计意图
                       // 但在实际函数设计中往往过于严格了

// ✅ 更实用的写法 —— 使用普通 symbol 类型
function processData(sym: symbol) {
  // 任何 symbol 都可以传入
}
processData(specificSym); // ok —— unique symbol 是 symbol 的子类型
processData(Symbol());     // 也 ok
```

**经验法则**：unique symbol 主要用于**属性键**和**类型级别的标识**，而不是函数参数类型。函数参数通常应使用 `symbol` 类型以保持足够的灵活性。

### 陷阱四：跨模块传递 unique symbol

```ts
// constants.ts
export const MODULE_KEY = Symbol('module.key'); // unique symbol

// consumer.ts
import { MODULE_KEY } from './constants';

const obj = { [MODULE_KEY]: 'value' }; // ok —— 导入的 unique symbol 可以正常使用

// 但要注意：每次重新编译/重新求值都会生成新的 unique symbol
// 对于 Symbol.for 则不存在这个问题
```

对于**跨多个独立运行时上下文**共享 symbol 的场景（如多窗口通信、Worker 通信），必须使用 `Symbol.for()`，因为 unique symbol 无法跨上下文传递。

### 陷阱五：类型断言绕过限制

```ts
const symA = Symbol('a');
const symB = Symbol('b');

// ❌ 类型断言可以绕过 unique symbol 的类型检查
let slot: typeof symA = symB as typeof symA; // 运行时 symB 被当作 symA 使用
// 编译器放行，但运行时行为可能不符合预期

// ✅ 如需运行时校验，额外添加守卫
function assignSlot(slot: typeof symA, value: symbol): void {
  if (value !== symA) {
    throw new Error('Invalid symbol');
  }
  // ...
}
```

TypeScript 的类型检查仅在编译期生效，`as` 断言可以在任何时候绕过。对于安全性要求高的场景，建议添加运行时验证。

## 十一、综合实战案例

### 案例 1：类型安全的事件总线

```ts
// event-bus.ts

// 定义事件类型映射
interface EventMap {
  [EVENTS.USER_LOGIN]: { userId: string; timestamp: number };
  [EVENTS.USER_LOGOUT]: { userId: string };
  [EVENTS.DATA_FETCH_COMPLETE]: { data: unknown[] };
  [EVENTS.ERROR]: { message: string; code: number };
}

// 事件 Symbol 定义
export const EVENTS = {
  USER_LOGIN: Symbol('events:user-login'),
  USER_LOGOUT: Symbol('events:user-logout'),
  DATA_FETCH_COMPLETE: Symbol('events:data-fetch-complete'),
  ERROR: Symbol('events:error'),
} as const;

type EventKey = keyof EventMap;

// 类型安全的订阅者类型
type Listener<K extends EventKey> = (payload: EventMap[K]) => void;

class EventBus<E extends Record<symbol, any>> {
  private listeners = new Map<symbol, Set<Function>>();

  on<K extends keyof E>(event: K, listener: Listener<K & symbol>): () => void {
    if (!this.listeners.has(event)) {
      this.listeners.set(event, new Set());
    }
    this.listeners.get(event)!.add(listener);

    // 返回取消订阅函数
    return () => this.off(event, listener);
  }

  once<K extends keyof E>(
    event: K,
    listener: Listener<K & symbol>
  ): () => void {
    const wrapper: Listener<K & symbol> = (payload) => {
      listener(payload);
      this.off(event, wrapper);
    };
    return this.on(event, wrapper);
  }

  emit<K extends keyof E>(event: K, payload: E[K]): void {
    const handlers = this.listeners.get(event);
    if (handlers) {
      handlers.forEach(h => h(payload));
    }
  }

  private off(event: symbol, listener: Function): void {
    this.listeners.get(event)?.delete(listener);
  }

  clear(event?: symbol): void {
    if (event) {
      this.listeners.delete(event);
    } else {
      this.listeners.clear();
    }
  }
}

// 使用
const bus = new EventBus<EventMap>();

// 类型安全：payload 类型自动推导
bus.on(EVENTS.USER_LOGIN, ({ userId }) => {
  console.log(`${userId} logged in`);
});

bus.on(EVENTS.ERROR, ({ message, code }) => {
  console.error(`Error ${code}: ${message}`);
});

// 类型安全：emit 时必须提供正确的 payload 类型
bus.emit(EVENTS.USER_LOGIN, { userId: 'u1', timestamp: Date.now() });
// bus.emit(EVENTS.USER_LOGIN, { userId: 'u1' }); 
// Error: Property 'timestamp' is missing

// 一次性监听
bus.once(EVENTS.DATA_FETCH_COMPLETE, (data) => {
  console.log(`Fetched ${data.length} items`);
});
```

这个事件总线的优势在于：
- **事件名不可伪造**：只有 `EVENTS` 对象中定义的 Symbol 才能用作事件名
- **payload 类型安全**：每个事件都有对应的 payload 类型，编译期就能检测出类型错误
- **自动补全友好**：IDE 可以列出所有可用事件及其 payload 结构

### 案例 2：Symbol 实现 Mixin 模式的私有存储

```ts
// mixin-store.ts
const _mixinState = Symbol('_mixinState');

// Mixin 存储容器
interface MixinStateHolder {
  [_mixinState]?: Map<symbol, any>;
}

function getMixinStorage(host: MixinStateHolder): Map<symbol, any> {
  if (!host[_mixinState]) {
    host[_mixinState] = new Map();
  }
  return host[_mixinState]!;
}

// Loggable Mixin
const LOG_ENTRIES = Symbol('log:entries');
const LOG_ENABLED = Symbol('log:enabled');

const LoggableMixin = {
  initLog(this: MixinStateHolder) {
    const storage = getMixinStorage(this);
    storage.set(LOG_ENTRIES, []);
    storage.set(LOG_ENABLED, true);
  },

  log(this: MixinStateHolder, message: string) {
    const storage = getMixinStorage(this);
    if (storage.get(LOG_ENABLED)) {
      const entries = storage.get(LOG_ENTRIES) as string[];
      entries.push(`[${new Date().toISOString()}] ${message}`);
    }
  },

  getLogs(this: MixinStateHolder): readonly string[] {
    const storage = getMixinStorage(this);
    return (storage.get(LOG_ENTRIES) as string[]) || [];
  },
};

// Timestampable Mixin
const CREATED_AT = Symbol('ts:created');
const UPDATED_AT = Symbol('ts:updated');

const TimestampableMixin = {
  initTimestamp(this: MixinStateHolder) {
    const storage = getMixinStorage(this);
    storage.set(CREATED_AT, new Date());
    storage.set(UPDATED_AT, new Date());
  },

  touch(this: MixinStateHolder) {
    const storage = getMixinStorage(this);
    storage.set(UPDATED_AT, new Date());
  },
};

// 组合使用
class Document implements MixinStateHolder {
  constructor(public title: string, public content: string) {
    LoggableMixin.initLog.call(this);
    TimestampableMixin.initTimestamp.call(this);
    LoggableMixin.log.call(this, `Document created: ${title}`);
  }

  updateContent(newContent: string) {
    this.content = newContent;
    TimestampableMixin.touch.call(this);
    LoggableMixin.log.call(this, 'Content updated');
  }

  showInfo() {
    console.log(`Title: ${this.title}`);
    console.log(`Logs:`, LoggableMixin.getLogs.call(this));
  }
}

const doc = new Document('Test Doc', 'Hello');
doc.updateContent('World');
doc.showInfo();
// Title: Test Doc
// Logs: [
//   "[2026-02-25T...] Document created: Test Doc",
//   "[2026-02-25T...] Content updated"
// ]

// 外部无法直接访问 mixin 的内部状态
console.log(doc[LOG_ENTRIES]); // Error（如果 LOG_ENTRIES 未导出）
console.log(Object.keys(doc)); // ['title', 'content'] —— 看不到 mixin 状态
```

这种模式的精髓在于：**每个 Mixin 用自己的 unique symbol 作为存储键**，不同 Mixin 之间完全隔离，且所有存储对外部透明。

### 案例 3：用 unique symbol 做依赖注入容器

```ts
// di-container.ts

// Token 类型 —— 必须是 symbol
type Token<T = any> = symbol & { __brand: T };

// 创建类型安全 token 的工厂
function createToken<T>(description: string): Token<T> {
  return Symbol(description) as Token<T>;
}

// 服务 token 定义
export const TOKENS = {
  DatabaseService: createToken<DatabaseService>('services:database'),
  LoggerService: createToken<LoggerService>('services:logger'),
  ConfigService: createToken<ConfigService>('services:config'),
  CacheService: createToken<CacheService>('services:cache'),
} as const;

// 服务接口
interface DatabaseService {
  query(sql: string): Promise<any[]>;
  transaction<T>(fn: () => Promise<T>): Promise<T>;
}

interface LoggerService {
  info(msg: string): void;
  error(msg: string, err?: Error): void;
}

interface ConfigService {
  get<T>(key: string): T;
}

interface CacheService {
  get<T>(key: string): Promise<T | null>;
  set(key: string, value: any, ttl?: number): Promise<void>;
}

// 依赖注入容器
class DIContainer {
  private providers = new Map<symbol, () => any>();
  private instances = new Map<symbol, any>();

  register<T>(token: Token<T>, factory: () | T): void {
    this.providers.set(token, factory);
  }

  resolve<T>(token: Token<T>): T {
    // 单例缓存
    if (this.instances.has(token)) {
      return this.instances.get(token) as T;
    }

    const factory = this.providers.get(token);
    if (!factory) {
      throw new Error(`No provider registered for token: ${token.toString()}`);
    }

    const instance = factory();
    this.instances.set(token, instance);
    return instance as T;
  }

  reset(): void {
    this.instances.clear();
  }
}

// 初始化容器
function bootstrapContainer(): DIContainer {
  const container = new DIContainer();

  container.register(TOKENS.DatabaseService, ({
    query: async (sql) => { /* ... */ },
    transaction: async (fn) => fn(),
  }));

  container.register(TOKENS.LoggerService, ({
    info: (msg) => console.log(`[INFO] ${msg}`),
    error: (msg, err) => console.error(`[ERROR] ${msg}`, err),
  }));

  return container;
}

// 使用方
const container = bootstrapContainer();

// 类型安全解析 —— 返回类型由 token 决定
const db = container.resolve(TOKENS.DatabaseService); // 类型为 DatabaseService
const logger = container.resolve(TOKENS.LoggerService); // 类型为 LoggerService

// IDE 自动补全可用
db.query('SELECT * FROM users').then(console.log);
logger.info('Application started');

// ❌ 无法混淆 token —— 编译期类型检查防止误用
// container.resolve(TOKENS.DatabaseService).info('test');
// Error: Property 'info' does not exist on type 'DatabaseService'
```

这个 DI 容器的亮点：
- **Token 即类型**：每个 token 不仅是一个唯一标识符，还携带了所代表服务的类型信息
- **编译期验证**：取出的服务自动具有正确的类型，无需手动类型断言
- **不可伪造**：外部代码无法创建与已有 token 冲突的标识符

## 总结

Symbol 和 unique symbol 构成了一条从运行时到编译期的完整唯一性保证链：

| 层面 | 机制 | 保证级别 |
|---|---|---|
| 运行时唯一 | `Symbol()` | 每个调用返回不同的值 |
| 全局共享 | `Symbol.for()` | 相同 key 返回同一实例 |
| 编译期唯一 | `unique symbol` | 每个变量独有类型标识 |
| 属性隔离 | computed property key | Symbol 键不与字符串键冲突 |
| 遍历隐蔽 | 隐藏于常规遍历之外 | `Object.keys()` 等不返回 |

掌握这套机制的核心在于理解**何时需要哪种层级的唯一性保证**：需要跨上下文共享就用 `Symbol.for()`，需要本地唯一标识就用 `const` + `Symbol()` 获得 `unique symbol`，需要类型安全的属性隔离就将 unique symbol 用作计算属性名。这三者在实际工程中各司其职，共同构成了 TypeScript 中处理唯一性标识的完整工具箱。
