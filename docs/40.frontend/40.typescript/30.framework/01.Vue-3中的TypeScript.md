# Vue 3 中的 TypeScript

> **一句话总结**：Vue 3 从设计之初就将 TypeScript 作为一等公民——`defineComponent`、`PropType`、`ref`/`reactive` 的类型推导构成了一个完整的类型安全体系。掌握它们，意味着你的每一个组件、每一条响应式数据、每一次 props 传递都在编译器的保护之下。

## 一、为什么 Vue 3 + TS 是"天作之合"？

在深入语法之前，先理解 Vue 3 与 TypeScript 的契合点：

```
┌──────────────────────────────────────────────────────┐
│              Vue 3 + TypeScript 契合度分析             │
│                                                      │
│  Vue 3 核心特性              TS 能力                  │
│  ──────────────            ───────                   │
│  Composition API          ✅ 完美推断函数返回值       │
│    → setup() 返回对象        类型                     │
│  响应式系统                ✅ 泛型重载实现精确推导     │
│    → ref/reactive          不同输入→不同输出           │
│  组件 Props                ✅ 泛型约束确保类型安全      │
│    → defineComponent       的 props 校验               │
│  模板编译                  ✅ 编译时类型检查模板表达式   │
│    → 模板中的属性访问         自动补全                 │
│  生命周期钩子               ✅ 函数签名精确匹配         │
│    → this 上下文            类型推断                   │
│  Provide/Inject            ✅ Key-Value 类型关联        │
│    → 依赖注入的             数据流动可追踪              │
│                                                      │
│  结论：Vue 3 的 API 设计本身就是"对类型推导友好的"      │
└──────────────────────────────────────────────────────┘
```

**生活类比**：如果把 Vue 3 比作一家**精密制造工厂**，TypeScript 就是它的**全自动质检系统**。每一颗螺丝（props）、每一条传送带（响应式数据）、每一个装配工（setup 函数）都有对应的质检标准（类型定义）。没有 TS，工厂也能运转，但次品率（运行时错误）会大幅上升。

## 二、defineComponent —— 组件类型的基石

### 2.1 为什么不用普通对象字面量？

```typescript
// ❌ 方式一：直接导出对象（丢失类型）
export default {
  name: 'UserCard',
  // props、data、methods 全部 any！
}

// ❌ 方式二：手动标注 Vue 组件接口（繁琐且容易出错）
import { DefineComponent } from 'vue'
const component: DefineComponent<{}, {}, {}, {}> = {
  // 需要手动填 4 个泛型参数...
}

// ✅ 方式三：defineComponent（推荐）
import { defineComponent } from 'vue'

export default defineComponent({
  name: 'UserCard',
  // 所有选项自动获得完整的类型推断和检查
})
```

### 2.2 defineComponent 的核心价值

`defineComponent` 不是简单的类型包装器——它做了三件关键的事：

```typescript
/**
 * defineComponent 内部简化示意：
 * 
 * 它是一个泛型函数，接受组件配置对象，
 * 返回带有完整类型信息的组件构造器。
 */
function defineComponent<
  // Props 类型（可选，不传则默认为 {})
  Props = {},
  // RawBindings（setup 中可能用到的非响应式绑定）
  RawBindings = {},
  // D（自定义的实例方法/计算属性）
  D = {},
  // C（自定义的 Computed）
  C = {},
  // Methods
  M = {},
  // Mixin（组合式）
  Mixin = Mixin,
  // Extends（继承）
  Extends = {},
  // Setup context 的额外配置
  SetupContext = {}
>(
  options: ComponentOptionsWithObjectProps<Props>
): DefineComponent<
  Props,
  RawBindings,
  D,
  C,
  M,
  Mixin,
  Extends,
  SetupContext
> { /* ... */ }
```

**关键能力一览：**

| 能力 | 无 defineComponent | 有 defineComponent |
|------|-------------------|---------------------|
| **Props 类型推断** | `any` | 精确到每个 prop 的类型 |
| **this 上下文类型** | `any` | data/computed/methods 都有正确类型 |
| **setup() 参数** | `unknown` | props 和 context 精确类型 |
| **template 编译** | 无补全 | 属性名和方法名自动补全 |
| **inheritAttrs** | 不受控 | 可声明式配置 |

### 2.3 基础用法：带 Props 的组件

```typescript
import { defineComponent, PropType } from 'vue'

// ===== 场景一：简单 Props =====
export const SimpleCard = defineComponent({
  props: {
    title: { type: String, required: true },
    subtitle: String,
    count: { type: Number, default: 0 },
    isActive: Boolean,
  },

  // setup 中的 this.props 自动推断为：
  // {
  //   title: string
  //   subtitle?: string | undefined
  //   count: number
  //   isActive?: boolean | undefined
  // }

  setup(props) {
    // ✅ props.title 是 string
    console.log(props.title.toUpperCase())
    
    // ✅ props.count 是 number
    const doubleCount = computed(() => props.count * 2)
    
    return { doubleCount }
  },

  template: `
    <div class="card">
      <h2>{{ title }}</h2>
      <p v-if="subtitle">{{ subtitle }}</p>
      <span>Count: {{ count }} (x2: {{ doubleCount }})</span>
    </div>
  `,
})
```

### 2.4 进阶用法：基于类型的 Props 声明

这是 Vue 3 + TS 最推荐的写法——**Props 用纯 TypeScript 接口/类型定义**：

```typescript
// ===== 定义 Props 接口（复用性强）=====

interface UserCardProps {
  /** 用户 ID */
  userId: string
  /** 是否显示头像 */
  showAvatar?: boolean
  /** 自定义尺寸 */
  size?: 'small' | 'medium' | 'large'
  /** 点击回调 */
  onClick?: (userId: string) => void
  /** 用户数据 */
  user: {
    id: string
    name: string
    email: string
    avatarUrl?: string
    role: 'admin' | 'editor' | 'viewer'
  }
}

// ===== 使用基于类型的 Props =====

export const UserCard = defineComponent<UserCardProps>({
  props: ['userId', 'showAvatar', 'size', 'onClick', 'user'],

  // 注意：基于类型的 props 必须用数组形式声明！

  emits: {
    // emit 也完全类型安全
    click: [id: string] => id.length > 0,
    follow: [user: UserCardProps['user']] => true,
  },

  setup(props, { emit }) {
    // props.userId → string
    // props.user.name → string
    // props.user.role → 'admin' | 'editor' | 'viewer'
    // props.onClick?.(props.userId) → void
    
    const handleClick = () => {
      emit('click', props.userId)
      props.onClick?.(props.userId)
    }

    const handleFollow = () => {
      emit('follow', props.user)
    }

    return { handleClick, handleFollow }
  },
})
```

### 2.5 复杂场景：混合式 Props 声明

当部分 prop 用运行时验证、部分用类型声明时：

```typescript
interface ComplexProps {
  /** 必填项 */
  id: string
  /** 带校验的复杂类型 */
  tags: string[]
  /** 回调 */
  onConfirm: (result: boolean) => void
  /** 可选配置 */
  options?: {
    theme: 'light' | 'dark'
    animation: boolean
  }
}

const ComplexComponent = defineComponent({
  // 混合模式：既有运行时声明，也有类型声明
  props: {
    // 运行时校验 + 类型推断（基础类型）
    id: { type: String, required: true },
    
    // 运行时校验 + 类型推断（使用 PropType）
    tags: {
      type: Array as PropType<string[]>,
      default: () => [],
    },

    // 纯类型声明（无运行时校验，仅编译期检查）
    onConfirm: { type: Function as PropType<(result: boolean) => void>, required: true },

    // 嵌套对象
    options: {
      type: Object as PropType<ComplexProps['options']>,
      default: () => ({ theme: 'light', animation: true }),
    },
  },

  setup(props) {
    // 所有 prop 都有正确的类型
    const hasTags = computed(() => props.tags.length > 0)

    return { hasTags }
  }
})
```

### 2.6 setup 上下文的完整类型

`defineComponent` 让 `setup()` 函数内部拥有完整的上下文类型：

```typescript
const FullFeatured = defineComponent({
  props: {
    initialCount: { type: Number, default: 0 },
    step: { type: Number, default: 1 },
  },

  // data() 中的属性在 this 上可用
  data() {
    return {
      internalState: 'idle',  // string
      history: [] as number[],   // number[]
    }
  },

  // methods 在 this 上可用
  methods: {
    increment() {
      this.initialCount += this.step  // ✅ 类型安全
      this.history.push(this.initialCount)
    },
    reset() {
      this.internalState = 'reset'
      this.history.splice(0)
    },
  },

  // computed 在 this 上可用
  computed: {
    doubled(): number {
      return this.initialCount * 2  // ✅ 能访问 props 和其他 computed
    },
  },

  setup(props) {
    // ====== 响应式引用 ======
    const counter = ref(props.initialCount)     // Ref<number>
    const status = ref<'active' | 'inactive'>('active')  // Ref<'active' | 'inactive'>
    const items = reactive<string[]>([])        // ReactiveArray<string>

    // ====== 计算属性 ======
    const total = computed(() => counter.value * props.step)  // ComputedRef<number>

    // ====== 方法 ======
    function increment() {
      counter.value += props.step
    }

    function addItem(item: string) {
      items.push(item)
    }

    // ====== 生命周期钩子（全部有正确的 this 类型）=====
    onMounted(() => {
      console.log('Mounted! Count:', counter.value)
    })

    watch(counter, (newVal, oldVal) => {
      console.log(`Changed: ${oldVal} → ${newVal}`)
    })

    // ====== expose（暴露给模板引用）=====
    // defineExpose 限制外部能访问的内容
    expose({
      counter,    // Ref<number>
      reset: () => { counter.value = 0 },  // () => void
    })

    return {
      counter, status, items, total,
      increment, addItem,
    }
  },
})

// 外部通过 ref 获取组件实例时，只有 expose 出来的内容可用
const compRef = ref<InstanceType<typeof FullFeatured>>()
compRef.value?.counter.value    // ✅ number
compRef.value?.reset()           // ✅ () => void
// compRef.value?.items          // ❌ 未 expose，不可访问
```

## 三、PropType —— 复杂 Prop 类型的救星

### 3.1 为什么需要 PropType？

Vue 的 `props` 选项中，基础类型（String, Number, Boolean 等）可以直接用。但遇到**复杂类型**时就不够了：

```typescript
// ❌ 问题一：数组元素类型丢失
props: {
  tags: Array,       // 只知道是数组，不知道元素是什么
  scores: Array,     // 同上
}

// ❌ 问题二：对象类型变成 plain object
props: {
  config: Object,    // 只知道是对象，所有属性都是 any
  user: Object,      // 无法访问 .name, .email 等
}

// ❌ 问题三：联合类型无法表达
props: {
  // 想要 "small" | "medium" | "large"，但做不到
  size: String,      // 只能是 string
  role: String,      // 无法限定为特定字符串
}

// ❌ 问题四：函数签名无法约束
props: {
  onSave: Function,  // 只知道是函数，参数和返回值都是 any
}
```

### 3.2 PropType 的原理与用法

`PropType<T>` 是一个工具函数，它利用 TypeScript 的**类型断言绕过机制**，将复杂的类型信息"注入"到运行时的 prop 声明中：

```typescript
/**
 * PropType 的源码（极度简化版）：
 * 
 * 它的作用是欺骗 TypeScript 的类型检查，
 * 让 T 类型的值可以赋值给 PropConstructor 类型。
 */
function PropType<T>(value: T): { type: PropConstructor<T> } {
  return { type: value as any }
}

// 实际上它更像是：
function PropType<T>(raw: T): { type: Prop<T> } {
  return raw as unknown as { type: Prop<T> }
}
```

**完整示例：**

```typescript
import { defineComponent, PropType } from 'vue'

interface DataTableProps {
  /** 列定义 */
  columns: Array<{
    key: string
    title: string
    width?: number | string
    sortable?: boolean
    render?: (value: any, row: Record<string, any>) => VNode | string
  }>
  /** 数据源 */
  data: Array<Record<string, any>>
  /** 行唯一标识 */
  rowKey: string | ((row: Record<string, any>) => string)
  /** 排序变化回调 */
  onSortChange?: (sortKey: string, direction: 'asc' | 'desc') => void
  /** 分页信息 */
  pagination?: {
    current: number
    pageSize: number
    total: number
  }
  /** 自定义空状态渲染 */
  emptyText?: string | (() => VNode)
}

export const DataTable = defineComponent({
  props: {
    // 数组 + 元素结构化类型
    columns: {
      type: Array as PropType<DataTableProps['columns']>,
      required: true,
    },
    // 数组
    data: {
      type: Array as PropType<DataTableProps['data']>,
      default: () => [],
    },
    // 字符串或函数（联合类型 + 函数重载）
    rowKey: {
      type: [String, Function] as PropType<DataTableProps['rowKey']>,
      required: true,
    },
    // 函数签名完整保留
    onSortChange: {
      type: Function as PropType<DataTableProps['onSortChange']>,
    },
    // 对象或 undefined
    pagination: {
      type: Object as PropType<DataTableProps['pagination']>,
    },
    // 字符串或渲染函数
    emptyText: {
      type: [String, Function] as PropType<DataTableProps['emptyText']>,
    },
  },

  setup(props) {
    // ✅ columns[0].render 存在且类型正确
    // ✅ rowKey 可以是 string 也可以是函数
    // ✅ onSortChange 参数类型完整
    // ✅ pagination?.current 是 number

    const sortedData = ref([...props.data])

    function handleSort(sortKey: string, direction: 'asc' | 'desc') {
      props.onSortChange?.(sortKey, direction)
    }

    return { sortedData, handleSort }
  },
})
```

### 3.3 PropType vs validator 函数

对于更复杂的校验逻辑，PropType 可以配合 validator 使用：

```typescript
props: {
  // 方式一：PropType 提供类型 + validator 提供运行时校验
  price: {
    type: Number as PropType<number>,  // 编译期：必须是 number
    required: true,
    validator: (value: unknown) => {
      return typeof value === 'number' && value > 0 && value <= 999999
    },
  },

  // 方式二：只使用 validator（类型较宽泛）
  email: {
    type: String as PropType<string>,
    validator: (v: string) => /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(v),
  },

  // 方式三：PropType 用于无法用基础类型表达的复杂形状
  dateRange: {
    type: Object as PropType<{
      start: Date | string
      end: Date | string
      inclusive?: boolean
    }>,
    validator: (val) => {
      if (!val || !val.start || !val.end) return false
      const start = new Date(val.start).getTime()
      const end = new Date(val.end).getTime()
      return val.inclusive ? start <= end : start < end
    },
  },
},
```

## 四、ref 和 reactive 的类型推导体系

### 4.1 ref 的类型推导规则

`ref` 是 Vue 3 中最常用的响应式 API，它的类型推导非常精妙：

```typescript
/**
 * ref 的类型签名（简化版）：
 *
 * function ref<T>(value: T): Ref<UnwrapNestedRefs<T>>
 *
 * 关键：根据输入值的不同，输出不同的 Ref 类型
 */

// ===== 场景一：基本类型 =====
const count = ref(0)                    // Ref<number>
const name = ref('Alice')               // Ref<string>
const flag = ref(true)                  // Ref<boolean>

// 访问 .value 时类型正确
count.value.toFixed(2)    // ✅ number 方法可用
name.value.toUpperCase()  // ✅ string 方法可用
// count.value.push(1)     // ❌ number 没有 push


// ===== 场景二：显式指定泛型参数 =====
const maybe = ref<string | null>(null)   // Ref<string | null>

if (maybe.value !== null) {
  // TypeScript 收窄：这里 maybe.value 是 string
  console.log(maybe.value.length)
}


// ===== 场景三：对象（注意陷阱！）=====
const userObj = ref({ name: 'Alice', age: 30 })
// Ref<{ name: string; age: number }>
//
// ⚠️ 注意：ref 包裹的对象不会自动"解包"！
// userObj.value.name ✅ （需要 .value 才能访问）
// 这与 reactive 不同！


// ===== 场景四：ref 解包（自动解包嵌套的 ref）=====
const a = ref(1)                          // Ref<number>
const b = ref(a)                           // Ref<Ref<number>>
const c = b.value                         // Ref<number>（自动解包一层）

// 但在模板中不需要 .value（Vue 编译器自动处理）


// ===== 场景五：初始值为 null/undefined =====
const asyncData = ref<UserProfile | null>(null)
// 常见模式：先声明为 null，异步获取后赋值

onMounted(async () => {
  asyncData.value = await fetchUserProfile()
  // 此时 asyncData.value 是 UserProfile
})
```

### 4.2 reactive 的类型推导

```typescript
/**
 * reactive 的类型签名（简化版）：
 *
 * function reactive<T extends object>(target: T): UnwrapNestedRefs<T>
 *
 * 关键区别：reactive 不需要 .value，但要求传入对象
 */

// ===== 基本用法 =====
const state = reactive({
  user: null as UserProfile | null,
  isLoading: false,
  error: null as Error | null,
})
// Reactive 类型，直接访问属性（无需 .value）

state.isLoading = true
state.user = await fetchUser()
console.log(state.user?.name)  // ✅ 直接访问


// ===== reactive 的类型限制 =====
// reactive 只接受 object（string/number/boolean/bigint/symbol 不行）
// const x = reactive('hello')     // ❌ Argument of type 'string' is not assignable to parameter of type 'object'
// const y = reactive(42)          // ❌ 同上


// ===== reactive vs ref 的选择指南 =====

/*
┌────────────────────┬─────────────────────┬─────────────────────┐
│                    │       ref            │     reactive        │
├────────────────────┼─────────────────────┼─────────────────────┤
│ 适用类型           │ 任意类型（含原始类型） │ 仅对象/数组         │
│ 访问方式           │ xxx.value            │ xxx（直接访问）      │
│ 解构后响应性       │ 丧失（需 toRefs）     │ 丧失（需 toRefs）     │
│ 替换整个值         │ ✅ value = newObj    │ ❌ 不能替换根对象    │
│ TypeScript 推导    │ Ref<T>              │ UnwrapNestedRefs<T>  │
│ 推荐场景           │ 单个值/基本类型       │ 对象/状态集合       │
│ 在 setup 返回      │ ✅ 保持响应性         │ ✅ 保持响应性        │
└────────────────────┴─────────────────────┴─────────────────────┘
*/
```

### 4.3 组合式函数（Composables）的类型编写规范

这是实际项目中最常见的 TS + Vue 3 使用场景：

```typescript
/**
 * ✅ 最佳实践：类型化的 useFetch
 * 
 * 关键要点：
 * 1. 泛型 T 表示响应数据类型
 * 2. 返回值包含 loading/error/data/refetch 的标准结构
 * 3. 所有字段都有明确的类型
 */
function useFetch<T>(
  url: MaybeRef<string>,
  options?: {
    immediate?: boolean
    params?: MaybeRef<Record<string, string>>
    onSuccess?: (data: T) => void
    onError?: (error: Error) => void
  }
) {
  const data = shallowRef<T | null>(null)    // ShallowRef<T | null>
  const error = ref<Error | null>(null)       // Ref<Error | null>
  const isLoading = ref(false)              // Ref<boolean>

  const fetchData = async () => {
    isLoading.value = true
    error.value = null

    try {
      const actualUrl = unref(url)
      const actualParams = unref(options?.params ?? {})
      
      const queryString = new URLSearchParams(actualParams).toString()
      const fullUrl = queryString ? `${actualUrl}?${queryString}` : actualUrl
      
      const response = await fetch(fullUrl)
      if (!response.ok) throw new Error(`HTTP ${response.status}`)
      
      const result: T = await response.json()
      data.value = result
      options?.onSuccess?.(result)
    } catch (e) {
      error.value = e instanceof Error ? e : new Error(String(e))
      options?.onError?.(error.value!)
    } finally {
      isLoading.value = false
    }
  }

  // 如果设置 immediate=true，立即请求
  if (options?.immediate !== false) {
    fetch_data()
  }

  // 返回标准的响应式元组
  return {
    data: readonly(data),     // ReadonlyShallowRef<T | null>
    error: readonly(error),    // Readonly<Ref<Error | null>>
    isLoading: readonly(isLoading), // Readonly<Ref<boolean>>
    refresh: fetchData,       // () => Promise<void>
  }
}


// ===== 使用 =====

interface Article {
  id: string
  title: string
  content: string
}

// 在组件中使用
export default defineComponent({
  setup() {
    const { data: article, isLoading, error, refresh } = useFetch<Article>('/api/articles/1')

    // article.value?.title → string | undefined
    // isLoading.value → boolean
    // error.value?.message → string | undefined
    // refresh() → () => Promise<void>

    return { article, isLoading, error, refresh }
  },
})
```

```typescript
/**
 * ✅ 类型化的 useStorage —— 持久化的响应式状态
 */
function useStorage<T>(
  key: string,
  initialValue: T,
  storage: Storage = localStorage
) {
  // 从存储读取（可能有旧数据或无数据）
  const storedRaw = storage.getItem(key)
  
  let parsedInitial: T
  try {
    parsedInitial = storedRaw ? JSON.parse(storedRaw) as T : initialValue
  } catch {
    parsedInitial = initialValue
    // 如果解析失败，清除损坏的数据
    storage.removeItem(key)
  }

  // 创建响应式数据
  const data = ref<T>(parsedInitial)

  // 监听变化，自动持久化
  watch(
    data,
    (newValue) => {
      storage.setItem(key, JSON.stringify(newValue))
    },
    { deep: true }
  )

  // 提供 remove 方法
  function remove() {
    data.value = initialValue
    storage.removeItem(key)
  }

  return {
    data: readonly(data),  // Readonly<Ref<T>>
    remove,                  // () => void
  }
}


// ===== 使用 =====

// 布置偏好（自动保存到 localStorage）
const { data: theme, remove: resetTheme } = useStorage<'light' | 'dark'>(
  'app-theme',
  window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light'
)

// theme.value → 'light' | 'dark'
// 修改后自动保存
theme.value = 'dark'        // localStorage 自动更新
resetTheme()               // 恢复默认值并清除存储
```

import { defineComponent, PropType, ref, computed, watch } from 'vue'

// ===== 子组件：ModalButton =====
interface ModalButtonProps {
  text: string
  type: 'primary' | 'secondary' | 'danger' | 'ghost'
  disabled?: boolean
  loading?: boolean
  onClick?: () => void | Promise<void>
}

const ModalButton = defineComponent<ModalButtonProps>({
  props: {
    text: { type: String, required: true },
    type: { type: String as PropType<ModalButtonProps['type']>, default: 'primary' },
    disabled: Boolean,
    loading: Boolean,
  },

  emits: { click: [] },

  setup(props, { emit }) {
    const isHandling = ref(false)

    async function handleClick() {
      if (props.disabled || props.loading || isHandling.value) return
      
      isHandling.value = true
      try {
        await props.onClick?.()
        emit('click')
      } finally {
        isHandling.value = false
      }
    }

    const buttonClass = computed(() => [
      'modal-btn',
      `modal-btn--${props.type}`,
      { 'is-disabled': props.disabled || isHandling.value },
      { 'is-loading': props.loading || isHandling.value },
    ])

    return { handleClick, buttonClass, isHandling }
  },
})


// ===== 主组件：Modal =====
interface ModalProps {
  modelValue: boolean        // 受控：是否可见
  title: string              // 标题
  width?: string | number    // 宽度
  closable?: boolean         // 是否显示关闭按钮
  maskClosable?: boolean     // 点击遮罩关闭
  escClosable?: boolean       // ESC 键关闭
  confirmText?: string       // 确认按钮文字
  cancelText?: string        // 取消按钮文字
  confirmLoading?: boolean   // 确认按钮 loading
  danger?: boolean           // 危险操作样式
  destroyOnClose?: boolean   // 关闭时销毁内容
  footer?: null              // 隐藏底部
  // 插槽内容
  bodyStyle?: Record<string, string>
  // 事件
  onConfirm?: () => void | Promise<void>
  onCancel?: () => void
  onAfterClose?: () => void
}

export const Modal = defineComponent<ModalProps>({
  props: {
    modelValue: { type: Boolean, required: true },
    title: { type: String, required: true },
    width: { type: [String, Number] as PropType<ModalProps['width']>, default: 520 },
    closable: { type: Boolean, default: true },
    maskClosable: { type: Boolean, default: false },
    escClosable: { type: Boolean, default: true },
    confirmText: { type: String, default: '确定' },
    cancelText: { type: String, default: '取消' },
    confirmLoading: Boolean,
    danger: Boolean,
    destroyOnClose: Boolean,
    footer: { type: Boolean, default: undefined as any },
    bodyStyle: { type: Object as PropType<ModalProps['bodyStyle']> },
  },

  emits: {
    'update:modelValue': [(value: boolean) => true],  // v-model 支持
    confirm: [],
    cancel: [],
    'after-close': [],
  },

  setup(props, { emit, slots }) {
    const visible = ref(props.modelValue)

    // 同步外部 modelValue 变化
    watch(() => props.modelValue, (val) => { visible.value = val })
    watch(visible, (val) => { emit('update:modelValue', val) })

    const isConfirming = ref(false)

    // 确认处理
    async function handleConfirm() {
      isConfirming.value = true
      try {
        await props.onConfirm?.()
        visible.value = false
        emit('confirm')
      } finally {
        isConfirming.value = false
      }
    }

    // 取消处理
    function handleCancel() {
      props.onCancel?.()
      visible.value = false
      emit('cancel')
    }

    // 关闭后回调
    function afterClose() {
      props.onAfterClose?.()
      emit('after-close')
    }

    // ESC 键监听
    function handleKeydown(e: KeyboardEvent) {
      if (e.key === 'Escape' && props.escClosable && !isConfirming.value) {
        handleCancel()
      }
    }

    // 挂载时添加键盘监听
    onMounted(() => {
      document.addEventListener('keydown', handleKeydown)
    })
    onUnmounted(() => {
      document.removeEventListener('keydown', handleKeydown)
    })

    const modalClass = computed(() => [
      'modal',
      'modal-wrapper',
      { 'modal--danger': props.danger },
      { 'modal--no-footer': props.footer === null },
    ])

    const modalStyle = computed(() => ({
      ...(typeof props.width === 'number'
        ? { width: `${props.width}px` }
        : props.width ? { maxWidth: props.width } : {}),
      ...props.bodyStyle,
    }))

    return {
      visible,
      isConfirming,
      modalClass,
      modalStyle,
      handleConfirm,
      handleCancel,
      afterClose,
      slots,
    }
  },
})

// ===== 使用示例 =====

## 六、常见陷阱与避坑指南

### 陷阱一：丢失响应性

```typescript
// ❌ 解构 ref 会失去响应性
setup() {
  const state = reactive({ count: 0 })
  const { count } = state  // count 是一个普通的 number！不是 Ref！
  // 修改 count 不会触发重新渲染
  
  // ✅ 解决方案 1：始终通过 state.xxx 访问
  // ✅ 解决方案 2：使用 toRefs()
  const { count: countRef } = toRefs(state)  // countRef 是 Ref<number>
}
```

### 陷阱二：ref 包裹对象的冗余 `.value`

```typescript
// ❌ 不要用 ref 包裹对象
const userData = ref({
  name: 'Alice',
  age: 30,
})  // 访问时要 userData.value.name —— 冗余

// ✅ 对象应该用 reactive
const userData = reactive({ name: 'Alice', age: 30 })
// 直接 userData.name —— 干净
```

### 陷阱三：defineComponent 中遗漏 emit 类型声明

```typescript
// ❌ emit 没有类型约束
setup(_, { emit }) {
  emit('update:value', 123)  // 任何参数都能传，没有类型保护
  emit('nonexistent')          // 拼写事件名也不会报错
}

// ✅ 通过 emits 选项声明
emits: {
  'update:value': [(value: number) => value >= 0],
  'change': [(payload: { id: string; checked: boolean }) => !!payload.id],
},
setup(_, { emit }) {
  emit('update:value', 42)           // ✅
  emit('update:value', -1)           // ✅ 运行时通过（validator 只做类型收窄）
  // emit('update:value', 'hello')     // ❌ 编译错误！string 不能赋给 number
  // emit('wrong-event')               // ❌ 编译错误！事件不存在
}
```

## 总结

Vue 3 + TypeScript 的类型安全体系围绕三个核心构建：

1. **`defineComponent`** —— 组件级别的类型容器。它把 props、data、computed、methods、setup 全部纳入类型推导网络，让 `this`、`props`、`context` 每一处都有精确的类型信息。

2. **`PropType<T>`** —— 复杂 Prop 类型的桥梁。当基础的 `String` / `Number` / `Array` 不够用时，`PropType` 将完整的 TypeScript 类型注入到运行时声明中，让数组元素类型、对象形状、函数签名、联合类型等复杂结构都能被精确描述。

3. **`ref` / `reactive`** —— 响应式数据的类型推导引擎。`ref<T>` 根据输入值的类型自动推导出 `Ref<UnwrapNestedRefs<T>>`，`reactive<T>` 则将深层对象的每个属性都变为响应式的同时保持类型链路完整。

三者结合，使得从**单行变量**（ref）到**整个组件**（defineComponent），从**Props 入口**（PropType）到**组合式函数**（useFetch/useStorage），TypeScript 的类型保护覆盖了 Vue 3 开发的每一个环节。这就是为什么说 Vue 3 是目前前端框架中对 TypeScript 支持最自然、最完善的一个。
