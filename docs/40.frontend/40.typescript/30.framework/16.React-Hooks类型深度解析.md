# React Hooks 类型深度解析

> **一句话总结**：Hooks 是 React 状态管理的核心机制。理解 useState、useReducer、useContext 以及自定义 Hook 的类型推导原理，意味着你能精确控制每一个状态值的类型流转——从初始值到更新函数再到最终消费，全程在 TypeScript 的监控之下。

## 一、Hook 的类型本质

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│   Hook = 一个特殊函数                                       │
│                                                            │
│   特征：                                                       │
│   1. 以 "use" 开头                                          │
│   2. 只能在组件/其他 Hook 顶层调用                            │
│   3. 返回值有固定的类型约定                                   │
│   4. 可以维护状态跨重渲染                                      │
│                                                            │
│   从类型角度看，每个 Hook 都是一个"状态容器 + 类型通道"       │
│   输入：初始值/配置                                              │
│   输出：响应式状态 + 操作方法                                    │
│                                                            │
└──────────────────────────────────────────────────────────────┘
```

### Hook 类型签名的通用模式

```typescript
/**
 * 通用模式（简化版）：
 *
 * function useXxx<TInitial, TReturn>(
 *   initialValue: TInitial,
 *   ...options?
 * ): [StateType, ActionType, ...]
 */
```

## 二、useState —— 状态的基础类型化

### 2.1 类型推导规则

```typescript
/**
 * useState 的类型签名：
 *
 * function useState<S>(
 *   initialState: S | (() => S)
 * ): [S, Dispatch<SetStateAction<S>>]
 *
 * 核心要点：
 * 1. S 由初始值的类型决定
 * 2. 返回一个元组：[当前状态, 设置状态的函数]
 * 3. setState 支持两种模式：直接赋值 和函数式更新
 */

// ===== 场景一：基本类型 =====
const [count, setCount] = useState(0)
// count → number
// setCount → Dispatch<SetStateAction<number>>

const [name, setName] = useState('Hello')
// name → string

const [flag, toggleFlag] = useState(true)
// flag → boolean


// ===== 场景二：对象类型（注意引用不变性！）=====
interface User {
  id: string
  name: string
  email: string
}

// ⚠️ 注意这里的问题
const [user, setUser] = useState<User>({ id: '', name: '', email: '' })
// user → User
// setUser → Dispatch<SetStateAction<User>>

// ❌ 错误做法：只更新部分字段会丢失其他字段！
setUser({ name: 'New Name' })
// 现在 user 变成了 { id: '', name: 'New Name', email: '' }  ← id 和 email 丢失了！

// ✅ 正确做法：展开运算符保留已有字段
setUser(prev => ({ ...prev, name: 'New Name' }))
// prev 是旧值，展开后只覆盖 name，id 和 email 保留


// ===== 场景三：null 作为初始值 =====
// 当数据异步加载时，这是最常见的模式
const [data, setData] = useState<UserProfile | null>(null)
// data → UserProfile | null

if (data !== null) {
  // 在条件块内，data 被 TypeScript 收窄为 UserProfile
  console.log(data.email)  // ✅ 安全访问
}

// ===== 场景四：回调函数初始化（惰性初始化）=====
const [expensiveValue, setExpensiveValue] = useState(() => {
  // 这个函数只在首次渲染时执行一次
  // 适用于计算成本高的初始值
  console.log('Computing expensive initial value...')
  return heavyComputation()
})
// expensiveValue 的类型由函数返回值推断
```

### 2.2 useState 的泛型形式

```typescript
// 显式指定类型（当初始值为 null/undefined 时特别有用）
const [items, setItems] = useState<string[]>([])
// 即使初始值是空数组，类型也是 string[] 而非 never[]

const [config, setConfig] = useState<AppConfig>(() => loadConfig())
// AppConfig 由 loadConfig() 的返回值决定

// 回调函数类型的 state
const [callback, setCallback] = useState<((x: number) => x * 2>(console.log))
// callback: (x: number) => number
callback(5)  // 输出 10
```

### 2.3 useReducer —— 复杂状态的类型安全替代方案

当状态更新涉及复杂的逻辑（依赖前值、多种 action 类型），`useState` 的 `Dispatch` 就显得力不从心了。`useReducer` 提供**基于 action 的确定性状态转换**：

```typescript
/**
 * useReducer 类型签名：
 *
 * function useReducer<S, A>(
 *   reducer: Reducer<S, A>,
 *   initialState: S,
 *   init?: undefined
 * ): [S, Dispatch<A>]
 *
 * 其中：
 * S = State 类型
 * A = Action 类型（通常是联合类型）
 * Reducer = (state: S, action: A) => S
 */


// ===== 定义 Action 联合类型 =====
type TodoAction =
  | { type: 'ADD'; payload: { id: string; text: string } }
  | { type: 'TOGGLE'; payload: { id: string } }
  | { type: 'DELETE'; payload: { id: string } }
  | { type: 'SET_FILTER'; payload: 'all' | 'active' | 'completed' }
  | { type: 'CLEAR_COMPLETED' }


// ===== 定义 State 类型 =====
interface TodoState {
  todos: TodoItem[]
  filter: 'all' | 'active' | 'completed'
  nextId: number
}

interface TodoItem {
  id: string
  text: string
  completed: boolean
  createdAt: Date
}


// ===== Reducer（纯函数，易于测试）=====
function todoReducer(state: TodoState, action: TodoAction): TodoState {
  switch (action.type) {
    case 'ADD':
      return {
        ...state,
        todos: [
          ...state.todos,
          {
            id: action.payload.id,
            text: action.payload.text,
            completed: false,
            createdAt: new Date(),
          },
        ],
        nextId: state.nextId + 1,
      }

    case 'TOGGLE':
      return {
        ...state,
        todos: state.todos.map(todo =>
          todo.id === action.payload.id
            ? { ...todo, completed: !todo.completed }
            : todo
        ),
      }

    case 'DELETE':
      return {
        ...state,
        todos: state.todos.filter(todo => todo.id !== action.payload.id),
      }

    case 'SET_FILTER':
      return { ...state, filter: action.payload }

    case 'CLEAR_COMPLETED':
      return {
        ...state,
        todos: state.todos.filter(t => !t.completed),
      }

    default:
      // 利用 never 类型检查是否覆盖了所有 case
      const _exhaustive: never = action
      return _exhaustive
  }
}


// ===== 使用 =====
const [state, dispatch] = useReducer(todoReducer, {
  todos: [],
  filter: 'all',
  nextId: 1,
})

// dispatch 的参数类型被收窄为 TodoAction 联合类型
dispatch({ type: 'ADD', payload: { id: '1', text: 'Learn TS' }})      // ✅
dispatch({ type: 'TOGGLE', payload: { id: '1' }})                      // ✅
dispatch({ type: 'INVALID', payload: {} })                           // ❌ 编译错误！

// state 的类型始终是 TodoState
state.todos.map(t => t.text)  // string[]
state.filter                // 'all' | 'active' | 'completed'
```

### 2.4 useReducer 的 lazy initialization

```typescript
// 当初始状态需要计算时，使用第三个参数（init 函数）
function init(initialCount: number): TodoState {
  const savedTodos = localStorage.getItem('todos')
  return {
    todos: savedTodos ? JSON.parse(savedTodos) : [],
    filter: 'all',
    nextId: initialCount,
  }
}

const [state, dispatch] = useReducer(todoReducer, 100, init)
```

### 2.5 useState vs useReducer 选择指南

```
┌──────────────────────┬───────────────────┬──────────────────────────────┐
│ 使用场景             │ useState          │ useReducer                   │
├──────────────────────┼───────────────────┼──────────────────────────────┤
│ 状态结构             │ 简单（原始/扁平）  │ 复杂（嵌套/关联）           │
│ 更新逻辑             │ 简单替换         │ 复杂条件/依赖前值         │
│ Action 种类数         │ 无明确区分       │ 多种操作（联合类型）       │
│ 可测试性             │ 需要模拟组件     │ 纯函数，独立测试容易       │
│ 性能                 │ 相同             │ 相同（React 内部优化）    │
│ 典型场景             │ 表单输入、开关     │ 状态机、购物车、复杂表单   │
└──────────────────────┴───────────────────┴──────────────────────────────┘
```

## 三、useContext —— 跨组件类型传递

### 3.1 创建类型安全的 Context

```typescript
/**
 * Context 类型安全的三个步骤：
 * 1. 创建 Context 时提供默认值类型
 * 2. Provider 提供具体值
 * 3. Consumer/useContext 消费值
 */

import { createContext, useContext } from 'react'


// 步骤 1：创建 Context（带类型）
interface ThemeContextValue {
  theme: 'light' | 'dark'
  toggleTheme: () => void
  primaryColor: string
  backgroundColor: string
}

const ThemeContext = createContext<ThemeContextValue>({
  theme: 'light',
  toggleTheme: () => {},
  primaryColor: '#007bff',
  backgroundColor: '#ffffff',
})


// 步骤 2：Provider 提供值（在组件树顶层）
function AppProviders({ children }: { children: React.ReactNode }) {
  const [theme, setTheme] = useState<'light' | 'dark'>('light')

  const contextValue: ThemeContextValue = {
    theme,
    toggleTheme: () => setTheme(prev => prev === 'light' ? 'dark' : 'light'),
    primaryColor: theme === 'light' ? '#007bff' : '#f8f9fa',
    backgroundColor: theme === 'light' ? '#ffffff' : '#1a1a1a',
  }

  return (
    <ThemeContext.Provider value={contextValue}>
      {children}
    </ThemeContext.Provider>
  )
}


// 步骤 3：在任何深层组件中安全消费
function ThemedButton() {
  // useContext 自动获取正确的类型
  const { theme, toggleTheme, primaryColor, backgroundColor } = useContext(ThemeContext)

  // 所有值都有正确的类型！
  return (
    <button
      style={{ color: primaryColor, backgroundColor }}
      onClick={toggleTheme}
    >
      Current theme: {theme}
    </button>
  )
}
```

### 3.2 避免 undefined 默认值陷阱

```typescript
// ❌ 问题：没有默认值的 Context 可能导致运行时错误
const BadContext = createContext<User | null>(null)

function Child() {
  const user = useContext(BadContext)
  // user 可能是 null！每次使用都要检查
  
  if (!user) return <LoginPrompt />
  return <Welcome name={user.name} />
}

// ✅ 解决方案一：使用默认值
const GoodContext = createContext<User>({} as User)

// ✅ 解决方案二：自定义 Hook 封装 null check
function useRequiredContext<T>(context: React.Context<T | null>): T {
  const value = useContext(context)
  if (value === null) {
    throw new Error(`${context.displayName ?? 'Context} must be used within a Provider`)
  }
  return value
}

// 使用
const config = useRequiredContext(ConfigContext)
// 如果不在 Provider 内部，立即抛出有意义的错误
```

## 四、自定义 Hook 的类型设计规范

### 4.1 标准模式

```typescript
/**
 * 自定义 Hook 的标准类型模板
 *
 * 命名约定：use + 功能名称（大驼峰）
 * 返回值：只读的状态 + 操作方法
 * 参数：灵活但要有合理约束
 */

// ===== 示例：useToggle =====
interface UseToggleOptions {
  initialValue?: boolean
  onToggle?: (value: boolean) => void
}

interface UseToggleReturn {
  value: Readonly<Ref<boolean>>
  toggle: () => void
  setTrue: () => void
  setFalse: () => void
  set: (v: boolean) => void
}

function useToggle(options: UseToggleOptions = {}): UseToggleReturn {
  const value = ref(options.initialValue ?? false)

  function toggle() {
    value.value = !value.value
    options.onToggle?.(value.value)
  }

  function setTrue() { value.value = true }
  function setFalse() { value.value = false }
  function set(v: boolean) { value.value = v }

  return {
    value: readonly(value),  // 外部不能直接赋值
    toggle,
    setTrue,
    setFalse,
    set,
  }
}

// 使用
const { value: isDark, toggle } = useToggle()
// isDark.value → boolean（只读）
// toggle() → 切换
```

### 4.2 高级模式：带清理副作用的自定义 Hook

```typescript
/**
 * useEventListener —— 类型安全的事件监听器 Hook
 * 
 * 关键：确保在组件卸载时清理事件监听，
 * 并保持事件处理器参数的正确类型
 */
function useEventListener<
  K extends keyof HTMLElementEventMap,
>(
  target: Ref<HTMLElement | null> | EventTarget,
  event: K,
  handler: (ev: HTMLElementEventMap[K]) => void,
  options?: AddEventListenerOptions
): void {
  // 当前 effect 引用的 handler 保持稳定引用
  const stableHandlerRef = useRef(handler)
  stableHandlerRef.current = handler

  useEffect(() => {
    const el = target && ('current' in target) ? target.current : target
    
    if (!el) return

    el.addEventListener(event, stableHandlerRef.current, options)

    return () => {
      el.removeEventListener(event, stableHandlerRef.current, options)
    }
  }, [target, event])
}

// 使用
const buttonRef = useRef<HTMLButtonElement>(null)

useEventListener(
  buttonRef,
  'click',
  (e: MouseEvent) => {
    console.log('Clicked at:', e.clientX, e.clientY)
  }
)
```

### 4.3 Hook 组合模式

```typescript
/**
 * useAsyncTask —— 将 async 逻辑封装为类型安全的 Hook
 * 
 * 这是实际项目中最有用的自定义 Hook 模板之一
 */
interface AsyncTaskOptions<T> {
  task: () => Promise<T>
  onSuccess?: (data: T) => void
  onError?: (error: Error) => void
  immediate?: boolean
}

interface AsyncTaskReturn<T> {
  data: Readonly<ShallowRef<T | null>>
  error: Readonly<Ref<Error | null>>
  isLoading: Ref<boolean>
  execute: () => Promise<void>
  reset: () => void
}

function useAsyncTask<T>(options: AsyncTaskOptions<T>): AsyncTaskReturn<T> {
  const data = shallowRef<T | null>(null)
  const error = ref<Error | null>(null)
  const isLoading = ref(false)

  async function execute() {
    isLoading.value = true
    error.value = null
    try {
      const result = await options.task()
      data.value = result
      options.onSuccess?.(result)
    } catch (e) {
      error.value = e instanceof Error ? e : new Error(String(e))
      options.onError?.(error.value)
    } finally {
      isLoading.value = false
    }
  }

  function reset() {
    data.value = null
    error.value = null
    isLoading.value = false
  }

  // 自动执行？
  if (options.immediate !== false) {
    execute()
  }

  return {
    data: readonly(data),
    error: readonly(error),
    isLoading,
    execute,
    reset,
  }
}

// ===== 使用：API 调用 =====
function fetchUserProfile(userId: string): Promise<UserProfile> {
  return fetch(`/api/users/${userId}`).then(r => r.json())
}

function ProfilePage({ userId }: { userId: string }) {
  const { data: user, isLoading, error, execute: refresh } = useAsyncTask({
    task: () => fetchUserProfile(userId),
    immediate: true,
  })

  if (isLoading) return <Spinner />
  if (error) return <ErrorDisplay error={error.message} />
  if (!data) return null

  return <UserProfileCard user={data} />
}
```

## 总结

React Hooks 的类型系统建立在三个核心原则之上：

1. **`useState` 的类型由初值决定**——传入什么类型就是什么类型，但要注意对象更新的不可变性陷阱。
2. **`useReducer` 通过联合类型 Action 实现确定性状态转换**——适合复杂状态机场景，类型安全性远超 `useState`。
3. **`useContext` + `createContext<T>` 形成类型传递管道**——让深层组件也能安全地获取祖先提供的值。

而自定义 Hook 则是将这些能力组合复用的粘合剂。一个好的自定义 Hook 应该做到：**泛型化以适配不同场景、返回 readonly 保护内部状态、提供清晰的返回值结构、并在必要时处理清理副作用**。

掌握这些模式后，你在 React 中编写的每一行状态管理代码都将在编译期接受严格审查——这就是 TypeScript 赋予 React 开发者最强大的武器。
