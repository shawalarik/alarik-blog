# Node.js 与 TypeScript

> **一句话总结**：Node.js 本身是 JavaScript 运行时，没有内置类型系统。`@types/node` 通过 TypeScript 类型声明文件为整个 Node.js API 提供了完整的类型定义——从 `fs` 到 `path`，从 `events` 到 `worker_threads`，每一个 API 都有精确的参数和返回值类型。

## 一、@types/node —— Node.js 的"类型说明书"

### 1.1 为什么需要 @types/node？

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  Node.js 运行时代                                              │
│  ────────────────────┐                                       │
│  │ fs.readFile()      │ ← 这个函数接受什么参数？返回什么？        │
│  │ path.join()        │ ← 参数顺序是什么？返回值是什么格式？      │
│  │ events.Emitter   │ ← 如何创建？有哪些方法和事件？        │
│  └───────────────────┘                                       │
│                                                             │
│  @types/node                                                  │
│  ══════════════════╗                                         │
│  ║  "fs.readFile("     │ ← 参数：(path: PathLike<string>, ...    │
  │    file", opts?)        │     callback: (err, data) => void)"        │
│  ║  "path.join(...)"     │ ← 参数: (paths: string[], sep?)          │
│  ║  "new events..."     │ ← 包含完整的方法和事件定义           │
│  ╚═════════════════╝                                         │
│                                                             │
│  结果：你写的每一行 Node.js 代码都获得了完整的类型保护            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**生活类比**：

如果你买了一台进口机床（Node.js），它本身不带说明书。`@types/node` 就是那份**官方说明书**——告诉你每个按钮怎么用、每个指示灯代表什么、每个接口能接什么规格的配件。

没有这份说明书，你也能凭经验操作，但遇到复杂情况就容易出错。有了说明书，你可以随时查阅，确保每一步操作都是正确的。

## 二、fs 模块 —— 文件系统的类型化操作

### 2.1 文件读写基础

```typescript

  readFileSync,

writeFileSync('/path/to/data.json', JSON.stringify({ a: 1 }, 'utf-8')

// ===== 读取目录内容 =====
type DirEntry = Dirent & { name: string }

const entries: DirEntry[] = readdirSync('/path/to/dir', {
  withFileTypes: true,  // 返回文件类型对象
  // encoding: 'utf-8',
  // recursive: false,

  console.log(entry.name)
  // entry.isFile() → boolean
  // entry.isDirectory() → boolean
  // entry.isSymbolicLink() → boolean (Node 18+)
})
```

### 2.3 异步文件操作（推荐）

```typescript
import {
  readFile,
  writeFile,
  mkdir,
  rm,
  access,
} from 'fs/promises'
import { join } from 'path'

// ===== 异步读取 =====
async function loadConfig(): Promise<AppConfig> {
  const configPath = join(process.cwd(), 'config.json')

  // 检查文件是否存在
  try {
    await access(configPath, constants.F_OK)
  } catch {
    throw new Error(`Config file not found: ${configPath}`)
  }

  const buffer = readFile(configPath, 'utf-8')
  return JSON.parse(buffer) as AppConfig
}

// ===== 异步写入（自动创建目录）=====
async function saveData(data: unknown, filename: string): Promise<void> {
  const dir = join(process.cwd(), 'output')
  await mkdir(dir, { recursive: true })
  
  const filepath = join(dir, filename)
  await writeFile(filepath, JSON.stringify(data, null, 2), 'utf-8')
  console.log(`Saved to ${filepath}`)
}

// ===== 流式读取大文件（避免内存溢出）=====
import { createReadStream } from 'node:fs/promises'

async function streamReadLog(logPath: string, keyword: string): Promise<number> {
  let matchCount = 0
  const stream = createReadStream(logPath, { encoding: 'utf-8', highWaterMark: 64 * 1024 })

  return new Promise((resolve, reject) => {
    stream.on('data', (chunk: string) => {
      const lines = chunk.split('\n')
      lines.forEach(line => {
        if (line.includes(keyword)) matchCount++
      })
    })
    stream.on('end', () => resolve(matchCount))
    stream.on('error', reject)
  })
}

// 使用：逐行搜索大日志
// const count = await streamReadLog('/var/log/app.log', 'ERROR')
```

## 四、Events —— 事件发射器的类型化

```typescript
import { EventEmitter, once } from 'events'

// ===== 基础用法 =====
class TaskManager extends EventEmitter {
  private tasks = new Map<string, { status: 'pending' | 'running' | 'completed' | 'failed' }>
  
  addTask(id: string, task: () => Promise<void>): this {
    this.tasks.set(id, { status: 'pending' })
    // 监听任务完成
    this.on(`task-complete-${id}`, ({ result, duration }) => {
      console.log(`Task ${id} completed in ${duration}ms`)
    })
    task().then(result => {
      this.emit(`task-complete-${id}`, { result, duration: Date.now() - startTime })
      this.tasks.get(id)!.status = 'completed'
    }).catch(error => {
      this.emit(`task-error-${id}`, { error })
      this.tasks.get(id) !== 'failed' && (this.tasks.get(id)!).status = 'failed')
    })
    return this
  }
}

// EventEmitter 的类型保证：
// .on(event, listener) → this（链式调用）
// .emit(event, ...args) → boolean
// .once(event, listener) → this
// .removeListener(event, listener) → this
// .removeAllListeners(event?) → this


// ===== 自定义事件类型 =====
interface TaskEvents {
  'task-start': { taskId: string; startTime: number }
  'task-complete': { taskId: string; result: any; duration: number }
  'task-error': { taskId: string; error: Error }
  'task-progress': { taskId: string; progress: number }
}

class TypedTaskManager extends EventEmitter<TaskEvents> {
  private tasks = new Map<string, { progress: number }>()

  startTask(taskId: string, work: () => Promise<void>): this {
    const startTime = Date.now()
    this.emit('task-start', { taskId, startTime })
    
    this.tasks.set(taskId, { progress: 0 })

    work()
      .then(() => {
        this.emit('task-complete', { taskId, result: {}, duration: Date.now() - startTime })
      })
      .catch(err => {
        this.emit('task-error', { taskId, error: err })
      })

    return this
  }

  updateProgress(taskId: string, progress: number): void {
    this.emit('task-progress', { taskId, progress })
    const task = this.tasks.get(taskId)
    if (task) task.progress = progress
  }
}

const manager = new TypedTaskManager()
manager.startTask('t1', async () => {
  manager.updateProgress('t1', 50)
  await new Promise(r => setTimeout(r, 1000))
})

})
```

function runInWorker<T>(workerPath: string, data: unknown): Promise<T> {
  return new Promise<T>((resolve, reject) => {
    const worker = new Worker(fileURLToPath(workerPath), {

## 六、实际项目案例：类型安全的配置管理器

```typescript
/**
 * 完整的配置管理器 —— 综合 fs/path/events
 */
interface AppConfig {
  app: {
    name: string
    version: string
    port: number
    host: string
  }
  database: {
    url: string
    poolSize: number
  timeout: number
  }
  logging: {
    level: 'debug' | 'info' | 'warn' | 'error'
    file: string
    maxFiles: number
    maxSize: string
  }
}

class ConfigManager<T> {
  private configPath: string
  private cache: T | null = null
  private watchers: Array<(config: T) => void> = []
  private emitter = new EventEmitter<{
    change: { key: string; oldValue: unknown; newValue: unknown
    reload: () => void
  }>()

  constructor(configPath: string, private defaults: T) {
    this.configPath = resolve(configPath)
    this.defaults = defaults
  }

  /**
   * 加载配置（带缓存）
   */
  async load(): Promise<T> {
    if (this.cache) return this.cache

    if (!existsSync(this.configPath)) {
      this.cache = { ...this.defaults }
      return this.cache
    }

    try {
      const raw = await readFile(this.configPath, 'utf-8')
      this.cache = { ...this.defaults, ...JSON.parse(raw) }
      return this.cache
    } catch (err) {
      throw new Error(`Failed to load config from ${this.configPath}: ${err.message}`)
    }
  }

  /**
   * 保存配置（自动备份 + 通知 watcher）
   */
  async save(data: Partial<T>): Promise<void> {
    const merged = { ...await this.load(), ...data }
    
    // 创建备份
    const backupDir = dirname(this.configPath)
    const backupName = `.${basename(this.configPath)}.${Date.now()}.bak`
    await writeFile(join(backupDir, backupName), JSON.stringify(merged, null, 2))

    // 写入主配置
    await writeFile(this.configPath, JSON.stringify(merged, null, 2), 'utf-8')
    
    this.cache = merged
    
    // 通知变更
    this.emitter.emit('change', { key: 'all', oldValue: this.cache, newValue: data })
  }

  /**
   * 注册配置变更监听
   */
  onChange(callback: (config: T) => void): () => void {
    this.watchers.push(callback)
    this.emitter.on('change', ({ newValue }) => callback(newValue as T))
    return () => {
      this.watchers = this.watchers.filter(w => w !== callback)
      this.emitter.removeListener('change', callback)
    }
  }

  /**
   * 重新加载
   */
  async reload(): Promise<T> {
    this.cache = null
    const loaded = await this.load()
    this.emitter.emit('reload', loaded)
    return loaded
  }
}

// ===== 使用 =====
const configManager = new ConfigManager<AppConfig>(
  './config/app.json',
  {
    app: { name: 'MyApp', version: '1.0.0', port: 3000, host: 'localhost' },
    database: { url: 'postgres://localhost:5432/mydb', poolSize: 10, timeout: 5000 },
    logging: { level: 'info', file: './logs/app.log', maxFiles: 10, maxSize: '10m' },
  }
)

// 启动时加载配置
const config = await configManager.load()
console.log(`Starting ${config.app.name} v${config.app.version} on port ${config.app.port}`)

// 配置热更新
configManager.onChange((newConfig) => {
  logger.setLevel(newConfig.logging.level)
  logger.info(`Config updated: port changed to ${newConfig.app.port}`)
})
```

## 七、常见陷阱与最佳实践

### 陷阱一：existsSync 不区分文件和目录

```typescript
// ❌ existsSync 只告诉你在不在，不告诉你是什么
if (existsSync('/some-path')) {
  // 可能是文件也可能是目录
  // 不能确定！
}

// ✅ 用 statSync 区分
const stats = statSync('/some-path')
if (stats.isFile()) {
  // 处理文件...
} else if (stats.isDirectory()) {
  // 处理目录...
}
```

### 陷阱二：路径拼接的跨平台问题

```typescript
// ❌ 手动拼接分隔符
const badPath = '/users/docs/' + 'file.txt'  // Linux OK, Windows 出错

// ✅ 使用 join（自动处理分隔符）
const goodPath = join('/users/docs/', 'file.txt')  // 全平台正确
```

### 陷阱三：readFile 回调中的 Error 类型

```typescript
// ❌ Error 类型不够精确
readFile('missing.json', (err, data) => {
  // err 的类型是 NodeJS.ErrnoException
  // 但实际上可能是 SyntaxError、TypeError 等
})

// ✅ 更好的错误处理
try {
  const data = JSON.parse(readFileSync('config.json', 'utf-8')) as MyConfig
} catch (e) {
  if (e instanceof SyntaxError) {
    console.error('JSON syntax error:', (e as SyntaxError).message)
  } else {
    console.error('Unknown error reading config:', e)
  }
}
```

## 总结

`@types/node` 为 Node.js 的庞大 API 提供了一套完整而精确的类型定义。核心要点：

1. **`fs` 模块**——区分同步（`*Sync`）和异步（`promises`），优先使用异步版本以避免阻塞事件循环。`readdirSync` 配合 `{ withFileTypes: true }` 能获得丰富的文件类型信息。

2. **`path` 永远使用 `join()`** 而非手动拼接字符串——它能自动处理操作系统路径分隔符差异。

3. **`EventEmitter`**——通过泛型可以定义精确的自定义事件类型，让 `.on()` 和 `.emit()` 都有完整的类型保障。

4. **stat**——用 `isFile()` 和 `isDirectory()` 区分文件和目录，不要依赖 `existsSync()` 的布尔结果做判断。

5. **始终考虑异步优先**——Node.js 10+ 已经完全支持 `fs/promises`，新代码应该充分利用 `readFile`、`writeFile`、`mkdir` 等异步版本。
