# Express + TS 高级路由 —— Request/Response 泛型、中间件类型扩展

> **核心问题**：Express 是 JavaScript 时代的产物，原生类型定义非常宽松（`any` 满天飞）。如何让 Request/Response 携带精确的类型信息？如何在中间件中注入自定义属性并保持类型安全？本章将带你从"能用"到"好用"。

---

## 为什么需要强化 Express 的类型系统？

### 1.1 原生 Express 类型的问题

先看一个典型的 Express 路由处理函数：

```typescript
import { Request, Response, Router } from 'express'

const router = Router()

// 原生写法 —— 类型信息极其贫乏
router.get('/users/:id', (req: Request, res: Response) => {
  // req.params.id 的类型是什么？
  // → string （所有路径参数都是 string）
  
  // req.query 的类型是什么？
  // → Record<string, string | string[] | QueryString.ParseOptions | QueryString.SimpleParseOptions>
  // → 说白了就是 any，没有任何约束
  
  // req.body 的类型是什么？
  // → any！（除非你用 json() 中间件，但那只是断言，不是真正的类型推导）
  
  const id = req.params.id          // string —— OK 但不够精确
  const page = req.query.page        // string | string[] | ... —— 太宽泛
  const name = (req.body as any).name // any！完全失去保护
  
  res.json({ id, name })            // 返回值没有类型检查
})
```

**问题清单**：

| 问题 | 影响 |
|------|------|
| `req.params` 全是 `string` | 无法区分 `'42'` 和 `abc`，不能自动转数字 |
| `req.query` 几乎是 `any` | 写错查询参数名不会报错 |
| `req.body` 默认是 `any` | 传错字段名、少传字段都不会被捕获 |
| `res.json()` 无返回类型 | 无法知道客户端会收到什么结构 |
| 中间件注入的属性丢失 | `req.user`、`req.session` 等都需要手动 `as any` |

### 1.2 目标状态：完全类型安全的路由

我们想要达到的效果：

```typescript
// ✅ 理想状态 —— 一切都有类型保护
router.get('/users/:id', async (
  req: Request<{ params: { id: number }; query: { page?: number; search?: string } }>,
  res: Response<{ data: User; total: number }>
) => {
  const id = req.params.id       // number! 自动从字符串转换
  const page = req.query.page     // number | undefined! 不是 string
  
  if (page !== undefined && page < 1) {
    // TypeScript 知道 page 是 number 这里可以做数值比较
    return res.status(400).json({ error: 'page must be >= 1' })
  }
  
  const user = await User.findById(id)
  res.json({ data: user, total: 1 })
  //   ^^^ 返回值的形状被严格检查！
})
```

这就是本章的目标：**让每一个 `.` 操作都有类型提示，每一处赋值都有编译期验证**。

## Express 类型系统架构深度剖析

### 2.1 Request 的泛型签名

Express 的 `Request` 类型其实是一个**高度泛型化的接口**：

```typescript
// @types/express/index.d.ts —— 简化版
interface Request<P = ParamsDictionary, 
                  ResBody = any, 
                  ReqBody = any, 
                  ReqQuery = qs.ParsedQs, 
                  Locals extends Record<string, any> = Record<string, any>> {
  // 路径参数
  params: P
  
  // 查询字符串
  query: ReqQuery
  
  // 请求体（POST/PUT/PATCH）
  body: ReqBody
  
  // 自定义 Locals 对象（用于中间件间传递数据）
  locals: Locals
  
  // 其他内置属性
  method: string
  path: string
  headers: IncomingHttpHeaders
  cookies: { [key: string]: string }
  // ...
}
```

**五个泛型参数的含义**：

```
Request<P, ResBody, ReqBody, ReqQuery, Locals>
   │      │         │         │         │
   │      │         │         │         └── 中间件共享的本地存储
   │      │         │         └── 查询字符串 ?key=value
   │      │         └── 请求体 JSON / form-data
   │      └── 响应体类型（用于 res.json() 的返回类型）
   └── 路径参数 :id, :slug
```

### 2.2 Response 的泛型签名

```typescript
// @types/express/index.d.ts —— 简化版
interface Request<
  P = ParamsDictionary,
  ResBody = any,    // ← 这个参数控制 res.json() 的返回类型
  ReqBody = any,
  ReqQuery = qs.ParsedQs,
  Locals extends Record<string, any> = Record<string, any>
> {
  // 关键方法：res.json() 的返回值类型由 ResBody 决定
  json(body?: ResBody): Response
  send(body?: ResBody): Response
  status(code: number): this
  
  // 泛型方法：可以在调用点指定返回类型
  json<ResBodyType>(body?: ResBodyType): Response<ResBodyType>
}
```

**关键发现**：`ResBody` 这个泛型参数同时出现在 `Request` 和 `Response` 上。这是因为 Express 的设计中，Request 承载了响应类型的元信息。

### 2.3 理解设计：为什么 ResBody 在 Request 上？

这是一个常见的困惑点。让我们用类比来理解：

```typescript
/**
 * 类比：餐厅点餐
 * 
 * Request = 顾客的点菜单
 * Response = 厨师端出的菜
 * 
 * 点菜单上写着 "我要一份辣子鸡（Response 类型）"
 * 厨师根据这个描述来烹饪
 * 
 * 所以 "期望的菜的类型" 信息是在 Request（点菜单）上声明的，
 * 而不是在 Response（菜品本身）上。
 */

// Express 的设计思路类似：
// Request 上声明了 "这个路由应该返回什么类型的 Response"
type MyRouteRequest = Request<{}, ApiResponse<User>>
//                                              ^^^^^^^^^^^^^^^^
//                                        这是期望的响应体类型

app.get('/user', (req: MyRouteRequest, res) => {
  res.json({ code: 200, data: getUser(), msg: 'ok' })
  //   ^^^ TypeScript 会检查这个对象是否符合 ApiResponse<User>
})
```

## 三、基础用法：为单个路由指定类型

### 3.1 最简方式：内联泛型

```typescript
import { Request, Response, Router } from 'express'

const router = Router()

// ════════════════════════════════════════
// 场景 1：只有路径参数
// ════════════════════════════════════════
router.get('/posts/:postId/comments/:commentId',
  (req: Request<{ postId: string; commentId: string }>, res) => {
    // req.params.postId → string
    // req.params.commentId → string
    
    const postId = Number(req.params.postId)     // 需要手动转换
    const commentId = Number(req.params.commentId)
    
    res.json({ postId, commentId, text: '...' })
  }
)


// ════════════════════════════════════════
// 场景 2：路径参数 + 查询参数 + 响应类型
// ════════════════════════════════════════
interface PaginatedResponse<T> {
  data: T[]
  pagination: {
    page: number
    limit: number
    total: number
    hasMore: boolean
  }
}

router.get('/products',
  (req: Request<{}, any, any, { page?: string; limit?: string; category?: string }>,
   res: Response<PaginatedResponse<Product>>) => {
    
    const page = Number(req.query.page) || 1
    const limit = Math.min(Number(req.query.limit) || 20, 100)
    const category = req.query.category
    
    // 业务逻辑...
    const products = Product.findMany({ page, limit, category })
    
    res.json({
      data: products,
      pagination: { page, limit, total: products.length, hasMore: false }
    })
    // ↑ TypeScript 检查返回值是否符合 PaginatedResponse<Product>
  }
)


// ════════════════════════════════════════
// 场景 3：完整的 POST 请求（含 Body）
// ════════════════════════════════════════
interface CreateUserBody {
  email: string
  password: string           // 最小 8 位
  name?: string              // 可选
  avatar?: string            // URL
  role?: 'admin' | 'user'    // 枚举
}

interface UserResponse {
  id: string
  email: string
  name: string
  createdAt: string
  role: string
}

router.post('/users',
  (req: Request<{}, UserResponse, CreateUserBody>,
   res: Response<UserResponse>) => {
     
    // req.body 完全类型安全
    const { email, password, name, role } = req.body
    //  ^^^^^^  ^^^^^^^^  ^^^^  ^^^^ 全部有提示和校验
     
    // 验证逻辑...
    if (!email.includes('@')) {
      return res.status(400).json({ error: 'Invalid email' } as any)
    }
    
    const user = UserService.create({ email, password, name, role })
    
    res.json(user)
    //  ^^^ 返回类型必须是 UserResponse
  }
)
```

### 3.2 用接口封装复用

每个路由都写一长串泛型参数很痛苦。更好的做法是预定义类型别名：

```typescript
// types/routes.ts

// ════════════════════════════════════════
// 第一步：定义领域模型
// ════════════════════════════════════════

export interface User {
  id: string
  email: string
  name: string
  role: 'admin' | 'user' | 'editor'
  createdAt: Date
}

export interface Post {
  id: string
  title: string
  content: string
  authorId: string
  tags: string[]
  publishedAt: Date | null
}


// ════════════════════════════════════════
// 第二步：定义标准响应格式
// ════════════════════════════════════════

export interface ApiSuccess<T> {
  code: 200
  data: T
  message: string
}

export interface ApiError {
  code: number
  error: string
  details?: Record<string, string[]>
}

export type ApiResponse<T> = ApiSuccess<T> | ApiError


// ════════════════════════════════════════
// 第三步：为每个路由组合 Request/Response 类型
// ════════════════════════════════════════

import { Request as ExprReq, Response as ExprRes } from 'express'

// 用户相关路由
export type GetUserReq = ExprReq<{ params: { id: string } }, ApiSuccess<User>>
export type GetUserRes = ExprRes<User>

export type CreateUserReq = ExprReq<{}, ApiSuccess<User>, {
  email: string
  password: string
  name?: string
}>
export type CreateUserRes = ExprRes<ApiSuccess<User>>

// 文章相关路由
export type ListPostsReq = ExprReq<{}, ApiSuccess<Post[]>, any, {
  page?: number
  limit?: number
  tag?: string
  authorId?: string
}>
export type ListPostsRes = ExprRes<ApiSuccess<Post[]>>


// ════════════════════════════════════════
// 第四步：在路由中使用
// ════════════════════════════════════════

// routes/user.ts
import { GetUserReq, CreateUserReq } from '../types/routes'

router.get('/users/:id', async (req: GetUserReq, res) => {
  const user = await UserService.findById(req.params.id)
  res.json({ code: 200, data: user!, message: 'OK' })
})

router.post('/users', async (req: CreateUserReq, res) => {
  const { email, password, name } = req.body  // 完全类型化
  const user = await UserService.create({ email, password, name })
  res.status(201).json({ code: 200, data: user, message: 'Created' })
})
```

## 四、核心挑战：中间件类型扩展

### 4.1 问题的本质

Express 中间件的典型模式是**在 `req` 或 `res` 上附加自定义属性**：

```typescript
// 认证中间件 —— 在 req 上添加 user 属性
function authMiddleware(req, res, next) {
  const token = req.headers.authorization?.replace('Bearer ', '')
  
  try {
    const decoded = jwt.verify(token, SECRET)
    req.user = decoded    // ← 注入了自定义属性!
    next()
  } catch {
    res.status(401).json({ error: 'Unauthorized' })
  }
}

// 在路由中使用
router.get('/profile', authMiddleware, (req, res) => {
  // 我们希望 req.user 有类型提示
  const userId = req.user.id       // ❌ TypeScript 报错！
  //         ^^^ Property 'user' does not exist on type 'Request'
  
  const userName = req.user.name   // ❌ 同样报错
})
```

**根本原因**：Express 的 `Request` 接口不知道你的中间件会往上面挂什么属性。这是**声明合并（Declaration Merging）**的经典应用场景！

### 4.2 方案一：全局声明合并（最常用）

```typescript
// types/express.d.ts

// 导入原始的 Express 命名空间
import 'express'

// 使用声明合并扩展全局的 Express namespace
declare global {
  namespace Express {
    // 扩展 Request 接口
    interface Request {
      // 认证用户信息
      user?: {
        id: string
        email: string
        role: 'admin' | 'user' | 'editor'
        permissions: string[]
      }
      
      // 会话信息（如果使用 express-session）
      session?: {
        sessionId: string
        userId: string
        createdAt: Date
        data: Record<string, any>
      }
      
      // 请求 ID（用于日志追踪）
      requestId: string
      
      // 请求日志记录器
      logger: {
        info(msg: string, meta?: object): void
        error(msg: string, error?: Error): void
      }
    }

    // 扩展 Response 接口（如果需要）
    interface Response {
      success<T>(data: T, message?: string): Response
      error(code: number, message: string, details?: object): Response
    }
  }
}
```

现在全局所有地方都能使用这些扩展属性了：

```typescript
// middleware/auth.ts
import { Request, Response, NextFunction } from 'export'

export function authMiddleware(
  req: Request,
  res: Response,
  next: NextFunction
) {
  const token = extractToken(req)
  
  const payload = verifyJwt(token)
  
  // ✅ 现在 TypeScript 知道 req.user 存在
  req.user = {
    id: payload.sub,
    email: payload.email,
    role: payload.role,
    permissions: getPermissions(payload.role),
  }
  
  // ✅ requestId 也有类型
  req.requestId = generateId()
  
  // ✅ logger 方法可用
  req.logger.info('Authenticated user', { userId: req.user.id })
  
  next()
}


// routes/profile.ts
router.get('/profile', authMiddleware, (req, res) => {
  // ✅ 完美的类型提示和检查
  const userId = req.user!.id          // string
  const email = req.user!.email        // string
  const role = req.user!.role          // 'admin' | 'user' | 'editor'
  const perms = req.user!.permissions  // string[]
  
  res.success({ userId, email, role })
  // ^^^ 自定义的成功响应方法也有类型
})
```

### 4.3 方案二：使用 Locals 参数（推荐用于局部传递）

如果你不想污染全局命名空间，可以用 Express 内置的 `locals` 机制：

```typescript
// 定义 Locals 类型
interface RouteLocals {
  currentUser: User
  cacheKey: string
  startTime: number
}

// 在路由处理器中指定
router.get('/data',
  (req: Request<{}, any, any, any, RouteLocals>, res, next) => {
    // 通过 middleware 设置 locals
    req.locals.currentUser = await getCurrentUser(req)
    req.locals.cacheKey = `data:${req.locals.currentUser.id}`
    req.locals.startTime = Date.now()
    
    next()
  },
  (req, res) => {
    // ✅ locals 完全类型化
    const user = req.locals.currentUser
    console.log(`Request took ${Date.now() - req.locals.startTime}ms`)
    
    res.json({ data: getData(user.id) })
  }
)
```

### 4.4 方案三：自定义 Request 类（高级）

当项目很大时，可以创建自己的 Request 子类：

```typescript
// types/AuthenticatedRequest.ts
import { Request } from 'express'

// 定义认证后的请求接口
export interface AuthenticatedUser {
  id: string
  email: string
  tenantId: string
  role: UserRole
  scopes: PermissionScope[]
}

// 创建增强版的 Request 接口
export interface AuthenticatedRequest extends Request {
  user: AuthenticatedUser
  session: SessionData
  tenant: {
    id: string
    name: string
    plan: 'free' | 'pro' | 'enterprise'
  }
  auditLog: (action: string, details?: object) => void
}


// middleware/auth.ts
import { AuthenticatedRequest } from '../types/AuthenticatedRequest'

export function requireAuth(
  req: AuthenticatedRequest,
  _res: Response,
  next: NextFunction
) {
  const token = req.headers.authorization?.split(' ')[1]
  
  if (!token) {
    throw new UnauthorizedError('Missing authentication token')
  }
  
  const payload = verifyAndDecodeToken(token)
  
  // 填充所有增强字段
  req.user = {
    id: payload.sub,
    email: payload.email,
    tenantId: payload.tenantId,
    role: payload.role,
    scopes: payload.scopes,
  }
  
  req.tenant = await TenantService.getById(payload.tenantId)
  req.session = await SessionService.get(payload.sessionId)
  
  // 自定义审计日志方法
  req.auditLog = (action, details) => {
    AuditService.record({
      userId: req.user.id,
      action,
      details,
      timestamp: new Date(),
      requestId: req.headers['x-request-id'] as string,
    })
  }
  
  next()
}


// routes/admin.ts
router.delete('/users/:id',
  requireAuth,  // ← 注入完整类型
  requireRole('admin'),  // ← 角色检查
  async (req: AuthenticatedRequest, res) => {
    
    // 完整的类型安全
    req.auditLog('USER_DELETED', { targetUserId: req.params.id })
    
    await UserService.softDelete(req.params.id, {
      deletedBy: req.user.id,
      tenantId: req.tenant.id,
    })
    
    res.success(null, 'User deleted successfully')
  }
)
```

## 五、实战：构建类型安全的路由工厂

### 5.1 目标

封装一个 `createTypedRouter` 工厂函数，让路由定义变得既简洁又类型安全：

```typescript
// 期望的使用方式
const userRouter = createTypedRouter()
  .get('/:id', {
    params: { id: string } as const,
    response: ApiSuccess<User>,
    handler: async (req) => {
      const user = await User.findById(Number(req.params.id))
      return { code: 200, data: user, message: 'OK' }
    },
  })
  .post('/', {
    body: CreateUserDTO,
    response: ApiSuccess<User>,
    handler: async (req) => {
      const user = await User.create(req.body)
      return { code: 201, data: user, message: 'Created' }
    },
  })
  .build()

app.use('/api/users', userRouter)
```

### 5.2 实现

```typescript
// lib/typed-router.ts
import { Router, Request, Response, NextFunction } from 'express'

// 定义路由配置的类型
interface RouteConfig<B = any, P = Record<string, string>, Q = any, R = any> {
  params?: Record<string, string>
  body?: new () => B  // 用类来标识 body 类型
  query?: Record<string, string | number | boolean>
  response?: new () => R
  middlewares?: Array<(req: Request, res: Response, next: NextFunction) => void>
  handler: (req: Request<P, R, B, Q>) => Promise<R> | R
  validate?: {
    body?: ZodSchema<B>
    params?: ZodSchema<P>
    query?: ZodSchema<Q>
  }
}

// 类型化的路由构建器
class TypedRouterBuilder {
  private router = Router()

  get<P = {}, B = any, Q = any, R = any>(
    path: string,
    config: RouteConfig<B, P, Q, R>
  ): TypedRouterBuilder {
    const handler = async (
      req: Request<P, R, B, Q>,
      res: Response<R>,
      next: NextFunction
    ) => {
      try {
        // 可选的 Zod 验证
        if (config.validate?.params) {
          const result = config.validate.params.safeParse(req.params)
          if (!result.success) {
            return res.status(400).json({
              code: 400,
              error: 'Invalid params',
              details: result.error.flatten(),
            })
          }
        }
        
        if (config.validate?.body) {
          const result = config.validate.body.safeParse(req.body)
          if (!result.success) {
            return res.status(400).json({
              code: 400,
              error: 'Invalid body',
              details: result.error.flatten(),
            })
          }
        }
        
        if (config.validate?.query) {
          const result = config.validate.query.safeParse(req.query)
          if (!result.success) {
            return res.status(400).json({
              code: 400,
              error: 'Invalid query',
              details: result.error.flatten(),
            })
          }
        }
        
        // 执行业务 handler
        const result = await config.handler(req)
        
        // 自动包装响应
        res.json(result)
      } catch (error) {
        next(error)
      }
    }

    const middlewares = config.middlewares || []
    this.router.get(path, ...middlewares, handler)
    
    return this
  }

  post<P = {}, B = any, Q = any, R = any>(
    path: string,
    config: RouteConfig<B, P, Q, R>
  ): TypedRouterBuilder {
    // 与 get 逻辑相同...
    // (省略重复代码)
    return this
  }

  put<P = {}, B = any, Q = any, R = any>(
    path: string,
    config: RouteConfig<B, P, Q, R>
  ): TypedRouterBuilder {
    return this
  }

  delete<P = {}, B = any, Q = any, R = any>(
    path: string,
    config: RouteConfig<B, P, Q, R>
  ): TypedRouterBuilder {
    return this
  }

  build(): Router {
    return this.router
  }
}

export function createTypedRouter(): TypedRouterBuilder {
  return new TypedRouterBuilder()
}
```

### 5.3 使用示例

```typescript
// routes/api/users.ts
import { z } from 'zod'
import { createTypedRouter } from '../../lib/typed-router'
import { ApiSuccess, User } from '../../types/models'

// Zod Schema 同时用于运行时验证和类型推断
const CreateUserSchema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
  name: z.string().min(1).max(50).optional(),
  role: z.enum(['admin', 'user']).optional().default('user'),
})

const ListUsersQuerySchema = z.object({
  page: z.coerce.number().int().positive().default(1),
  limit: z.coerce.number().int().positive().max(100).default(20),
  search: z.string().optional(),
  role: z.enum(['admin', 'user']).optional(),
})

const userRouter = createTypedRouter()
  // GET /api/users/:id
  .get('/:id', {
    params: { id: String } as const,
    validate: {
      params: z.object({
        id: z.string().uuid(),
      }),
    },
    response: ApiSuccess<User>,
    handler: async (req) => {
      const user = await UserRepo.findById(req.params.id)
      if (!user) {
        throw new NotFoundError('User not found')
      }
      return { code: 200, data: user, message: 'OK' }
    },
  })

  // GET /api/users (列表)
  .get('/', {
    validate: {
      query: ListUsersQuerySchema,
    },
    response: ApiSuccess<User[]>,
    handler: async (req) => {
      // req.query 已经通过 Zod 验证并有正确的类型
      const { page, limit, search, role } = req.query
      //  ^^^^^  ^^^^^  ^^^^^^  ^^^^ 全部有正确类型!
      
      const result = await UserRepo.findMany({ page, limit, search, role })
      return { code: 200, data: result.users, message: 'OK' }
    },
  })

  // POST /api/users
  .post('/', {
    validate: {
      body: CreateUserSchema,
    },
    response: ApiSuccess<User>,
    handler: async (req) => {
      // req.body 已经是推断出的类型
      const { email, password, name, role } = req.body
      //  ^^^^^^  ^^^^^^^^  ^^^^  ^^^^ 类型安全!
      
      const hashedPassword = await bcrypt.hash(password, 10)
      const user = await UserRepo.create({
        email,
        password: hashedPassword,
        name,
        role,
      })
      
      return { code: 201, data: user, message: 'User created' }
    },
  })

  .build()
```

```typescript
// types/dependencies.ts

// 定义依赖项接口
interface Database {
  users: UserRepository
  posts: PostRepository
  transactions(): Promise<void>
}

interface CacheService {
  get<T>(key: string): Promise<T | null>
  set(key: string, value: any, ttlSeconds?: number): Promise<void>
  del(key: string): Promise<void>
}

interface Logger {
  info(ctx: object, msg: string): void
  error(ctx: object, err: Error): void
}

// 将所有依赖聚合为一个上下文
interface RequestContext {
  db: Database
  cache: CacheService
  logger: Logger
  req: Express.Request
  res: Express.Response
}


// lib/di-router.ts
import { Router, Request, Response, NextFunction } from 'express'

// 依赖上下文类型
type Deps = Partial<RequestContext>

// 增强版请求类型
interface DepInjectableRequest<D extends Deps = Deps> extends Request {
  dependencies: D
}

// 处理器类型
type DepInjectedHandler<D extends Deps = Deps> = (
  req: DepInjectableRequest<D>,
  res: Response
) => Promise<any> | any


class DIRouter<D extends Deps = Deps> {
  private router = Router()
  private dependencyProvider: () => D

  constructor(provider: () => D) {
    this.dependencyProvider = provider
  }

  private injectDependencies(
    req: Request,
    res: Response,
    next: NextFunction
  ) {
    const deps = this.dependencyProvider()
    ;(req as DepInjectableRequest<D>).dependencies = deps
    next()
  }

  get(
    path: string,
    handler: DepInjectedHandler<D>
  ): DIRouter<D> {
    this.router.get(
      path,
      this.injectDependencies.bind(this),
      async (req, res, next) => {
        try {
          const result = await handler(
            req as DepInjectableRequest<D>,
            res
          )
          if (result !== undefined) {
            res.json(result)
          }
        } catch (error) {
          next(error)
        }
      }
    )
    return this
  }

  // post, put, delete... 类似实现
  post(path: string, handler: DepInjectedHandler<D>): DIRouter<D> { /* ... */ }
  put(path: string, handler: DepInjectedHandler<D>): DIRouter<D> { /* ... */ }
  delete(path: string, handler: DepInjectedHandler<D>): DIRouter<D> { /* ... */ }

  build(): Router {
    return this.router
  }
}

function createDIRouter<D extends Deps>(provider: () => D): DIRouter<D> {
  return new DIRouter(provider)
}
```

## 七、错误处理的类型安全

### 7.1 定义错误类层次

```typescript
// errors/base.ts

/**
 * 应用错误的基类
 * 所有业务错误都应该继承此类
 */
export abstract class AppError extends Error {
  abstract readonly statusCode: number
  abstract readonly code: string
  readonly details?: Record<string, unknown>
  readonly isOperational = true  // 标识这是预期内的业务错误

  constructor(message: string, details?: Record<string, unknown>) {
    super(message)
    this.details = details
    Error.captureStackTrace(this, this.constructor)
  }
}

/** 400 - 请求参数错误 */
export class ValidationError extends AppError {
  readonly statusCode = 400
  readonly code = 'VALIDATION_ERROR'
  
  constructor(
    public fields: Record<string, string[]>
  ) {
    super('Validation failed', { fields })
  }
}

/** 401 - 未认证 */
export class AuthenticationError extends AppError {
  readonly statusCode = 401
  readonly code = 'AUTHENTICATION_ERROR'
  
  constructor(message = 'Authentication required') {
    super(message)
  }
}

/** 403 - 无权限 */
export class AuthorizationError extends AppError {
  readonly statusCode = 403
  readonly code = 'AUTHORIZATION_ERROR'
  
  constructor(
    public requiredPermission: string,
    message?: string
  ) {
    super(message ?? `Required permission: ${requiredPermission}`, {
      requiredPermission,
    })
  }
}

/** 404 - 资源不存在 */
export class NotFoundError extends AppError {
  readonly statusCode = 404
  readonly code = 'NOT_FOUND'
  
  constructor(resource: string, id?: string) {
    super(
      id
        ? `${resource} with id '${id}' not found`
        : `${resource} not found`,
      { resource, id }
    )
  }
}

/** 409 - 冲突 */
export class ConflictError extends AppError {
  readonly statusCode = 409
  readonly code = 'CONFLICT_ERROR'
  
  constructor(message: string, public conflictFields?: string[]) {
    super(message, { conflictFields })
  }
}

/** 429 - 速率限制 */
export class RateLimitError extends AppError {
  readonly statusCode = 429
  readonly code = 'RATE_LIMITED'
  
  constructor(
    public retryAfterSeconds: number,
    message?: string
  ) {
    super(message ?? `Too many requests. Retry after ${retryAfterSeconds}s`, {
      retryAfterSeconds,
    })
  }
}
```

### 7.2 类型安全的错误处理中间件

```typescript
// middleware/error-handler.ts
import { Request, Response, NextFunction } from 'express'
import { AppError } from '../errors/base'

// 标准化的错误响应格式
interface ErrorResponse {
  code: number
  error: string
  message: string
  details?: Record<string, unknown>
  requestId?: string
  timestamp: string
}

export function errorHandler(
  err: Error,
  req: Request,
  res: Response<ErrorResponse>,
  _next: NextFunction
) {
  // 记录错误日志
  console.error(`[ERROR] ${err.message}`, {
    stack: err.stack,
    path: req.path,
    method: req.method,
    requestId: (req as any).requestId,
  })

  // 如果是我们定义的操作性错误
  if (err instanceof AppError) {
    const responseBody: ErrorResponse = {
      code: err.statusCode,
      error: err.code,
      message: err.message,
      details: err.details,
      requestId: (req as any).requestId,
      timestamp: new Date().toISOString(),
    }

    // 特殊头
    if (err instanceof RateLimitError) {
      res.set('Retry-After', String(err.retryAfterSeconds))
    }

    return res.status(err.statusCode).json(responseBody)
  }

  // Zod 验证错误
  if ('issues' in err) {
    return res.status(400).json({
      code: 400,
      error: 'VALIDATION_ERROR',
      message: 'Request validation failed',
      details: { issues: (err as any).issues },
      requestId: (req as any).requestId,
      timestamp: new Date().toISOString(),
    })
  }

  // 未知错误 —— 不泄露内部细节
  const responseBody: ErrorResponse = {
    code: 500,
    error: 'INTERNAL_ERROR',
    message: process.env.NODE_ENV === 'development'
      ? err.message
      : 'An unexpected error occurred',
    requestId: (req as any).requestId,
    timestamp: new Date().toISOString(),
  }

  res.status(500).json(responseBody)
}
```

## 八、OpenAPI/Swagger 类型联动

### 8.1 从 TypeScript 类型自动生成 API 文档

```typescript
// lib/openapi-generator.ts

import type { OpenAPIV3 } from 'openapi-typescript'

interface RouteMetadata {
  method: 'get' | 'post' | 'put' | 'delete' | 'patch'
  path: string
  summary?: string
  description?: string
  tags?: string[]
  params?: Record<string, { type: string; description?: string }>
  query?: Record<string, { type: string; required?: boolean; description?: string }>
  requestBody?: {
    required: boolean
    content: {
      'application/json': {
        schema: OpenAPIV3.SchemaObject
      }
    }
  }
  responses: Record<string, {
    description: string
    content?: {
      'application/json': {
        schema: OpenAPIV3.SchemaObject
      }
    }
  }>
}

// 简易的元数据收集器
class OpenAPIGenerator {
  private routes: RouteMetadata[] = []

  addRoute(meta: RouteMetadata) {
    this.routes.push(meta)
  }

  generateSpec(basePath: string): OpenAPIV3.Document {
    const paths: OpenAPIV3.PathsObject = {}

    for (const route of this.routes) {
      const pathItem: OpenAPIV3.PathItemObject = {
        [route.method]: {
          summary: route.summary,
          description: route.description,
          tags: route.tags,
          parameters: [
            ...Object.entries(route.params ?? {}).map(([name, schema]) => ({
              name,
              in: 'path' as const,
              required: true,
              schema: { type: schema.type },
              description: schema.description,
            })),
            ...Object.entries(route.query ?? {}).map(([name, schema]) => ({
              name,
              in: 'query' as const,
              required: schema.required ?? false,
              schema: { type: schema.type },
              description: schema.description,
            })),
          ],
          requestBody: route.requestBody,
          responses: route.responses,
        },
      }

      paths[`${basePath}${route.path}`] = pathItem
    }

    return {
      openapi: '3.0.0',
      info: {
        title: 'My API',
        version: '1.0.0',
      },
      paths,
    }
  }
}
```

## 十、最佳实践清单

### 10.1 DO ✅

```
✅ 为每个路由组定义明确的 Request/Response 类型
✅ 使用声明合并在全局扩展 Express 的类型
✅ 用 Zod 或类似库做运行时验证 + 类型推导
✅ 定义统一的错误类层次结构
✅ 封装路由工厂减少样板代码
✅ 使用 DI 容器管理路由依赖
✅ 保持类型文件与路由文件分离
✅ 为异步处理器统一 try-catch 包装
```

### 10.2 DON'T ❌

```
❌ 在路由处理器中使用 any
❌ 手动 as 断言绕过类型检查（除非确实无法避免）
❌ 在多个地方重复定义相同的 Body/Params 类型
❌ 忽略中间件注入属性的类型声明
❌ 把所有逻辑塞在一个巨大的路由文件里
❌ 用 console.log 替代结构化日志
❌ 在错误响应中泄露内部细节到生产环境
```

## 总结

本章覆盖了 Express + TypeScript 类型集成的完整知识体系：

**第一层：理解架构** —— Express 的 Request/Response 本质上是高度泛型化的接口，5 个泛型参数分别控制路径参数、请求体、响应体、查询字符串和本地存储。

**第二层：基础应用** —— 学会为单个路由内联指定泛型参数，以及用接口封装复用类型定义。

**第三层：中间件扩展** —— 掌握声明合并技术，在全局或局部级别扩展 req/res 的类型，解决中间件注入属性的"消失"问题。

**第四层：工程实践** —— 通过路由工厂模式、DI 容器、Zod 联合验证、错误类层次、OpenAPI 联动等手段，将类型安全融入整个开发工作流。

**核心理念**：类型不是负担，而是力量。在 Express 这样的动态框架中投入类型系统的建设，换来的是重构信心、IDE 支持和团队协作效率的提升。前期投入越大，后期维护越轻松。
