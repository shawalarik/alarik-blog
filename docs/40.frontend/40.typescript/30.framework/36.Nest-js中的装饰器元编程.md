# Nest.js 中的装饰器元编程 —— Reflector、自定义装饰器、元数据反射

> **核心问题**：Nest.js 的灵魂是装饰器（Decorator）。`@Controller()`、`@Get()`、`@Body()`、`@Injectable()`……每一个都是装饰器。它们是如何工作的？背后的元数据反射机制是什么？如何编写自己的装饰器？本章将从原理到实践全面拆解 Nest.js 的元编程体系。

---

## 一、什么是装饰器？

### 1.1 从生活类比开始

想象你有一个**纯白色的花瓶**：

```
┌─────────────┐
│             │
│   🏺 花瓶    │   ← 这是"目标"（class / method / property）
│   (纯白色)   │
│             │
└─────────────┘
```

装饰器就是给花瓶**贴标签、系丝带、刷漆**的动作：

```
步骤 1: @Controller('users')  → 贴一个标签："我是用户控制器"
步骤 2: @UseGuards(AuthGuard) → 包一层保护膜："需要登录才能碰我"
步骤 3: @ApiTags('User')      → 系一根丝带："API文档归到 User 分类"
步骤 4: @Post()               → 刷一道漆："响应 HTTP POST 请求"

最终结果：
┌─────────────────────────────────────┐
│  🏺                                  │
│  ├─📌 标签: "用户控制器"             │
│  ├─🛡️ 保护膜: "需认证"              │
│  ├─🎀 丝带: "API Tag: User"         │
│  └─🎨 漆: "HTTP POST Handler"       │
└─────────────────────────────────────┘
```

**关键洞察**：花瓶本身没有被改变（代码逻辑不变），但外部世界对它的认知丰富了。这就是装饰器的本质——**在不修改原有代码的前提下，为其附加额外的元数据和功能**。

### 1.2 五种装饰器

TypeScript 支持 5 种位置的装饰器：

```
╔══════════════════════════════════════════════════════╗
║                                                      ║
║  @ClassDecorator()        ← 类装饰器                 ║
║  class MyClass {                                    ║
║                                                      ║
║    @PropertyDecorator()   ← 属性装饰器               ║
║    myProp: string                                 ║
║                                                      ║
║    @MethodDecorator()    ← 方法装饰器                ║
║    myMethod(                                      ║
║      @ParameterDecorator()  ← 参数装饰器             ║
║      param: string                                ║
║    ) {}                                           ║
║  }                                                 ║
║                                                      ║
║  // 还有第五种：访问器装饰器（getter/setter）         ║
║                                                      ║
╚══════════════════════════════════════════════════════╝
```

| 位置 | 语法 | 接收参数 | 典型用途 |
|-----|------|---------|---------|
| **类** | `@Dec class Foo {}` | `(constructor: Function)` | 注册组件、注入元数据 |
| **属性** | `@Dec prop: Type` | `(target: Object, propertyKey: string)` | 字段验证、依赖注入标记 |
| **方法** | `@Dec method(){}` | `(target, propertyKey, descriptor)` | 路由注册、拦截器、日志 |
| **参数** | `@dec method(@dec param){}` | `(target, propertyKey, parameterIndex)` | `@Body()`、`@Query()`、`@Param()` |
| **访问器** | `@Dec get x(){}` | `(target, propertyKey, descriptor)` | 计算属性的额外行为 |

## 二、装饰器的底层机制：Reflect Metadata

### 2.1 什么是元数据（Metadata）？

**元数据 = 关于数据的数据**。

就像图书馆的卡片目录：

```
书（实际内容）:
  "《三体》讲述了地球文明与三体文明的信息交流、搏杀及两个文明在宇宙兴衰历程..."

元数据（关于这本书的数据）:
  作者: 刘慈欣
  ISBN: 978-7-5366-9293-0
  页数: 302
  分类: 科幻小说
  出版年: 2008
  语言: 中文
  馆藏位置: A区3排12架
```

在程序中，元数据是**附加在类、方法、属性上的键值对信息**：

```typescript
@Controller('users')        // metadata: { path: 'users' }
class UsersController {

  @Get(':id')               // metadata: { method: 'GET', path: ':id' }
  findOne(@Param('id') id: string) {  // metadata: { param: 'id', index: 0 }
    return this.userService.findOne(id)
  }
}
```

### 2.2 Reflect Metadata API

Nest.js 使用 `reflect-metadata` 库来实现元数据的存取。核心 API 只有 4 个方法：

```typescript
import 'reflect-metadata'

// ====== 存取元数据的核心 API ======

// 1. 定义元数据 Key（通常用 Symbol）
const ROUTE_PATH = Symbol.for('route_path')
const ROUTE_METHOD = Symbol.for('route_method')

// 2. 存储元数据
Reflect.defineMetadata(ROUTE_PATH, '/users', UsersController)
Reflect.defineMetadata(ROUTE_METHOD, 'GET', UsersController, 'findOne')

// 3. 读取元数据
const path = Reflect.getMetadata(ROUTE_PATH, UsersController)
// → '/users'

const method = Reflect.getMetadata(ROUTE_METHOD, UsersController, 'findOne')
// → 'GET'

// 4. 检查是否有某个元数据
const hasPath = Reflect.hasMetadata(ROUTE_PATH, UsersController)
// → true

// 5. 获取自身的元数据 Keys
const ownKeys = Reflect.getMetadataKeys(UsersController)
// → [Symbol(route_path)]

// 6. 获取包含继承的所有元数据 Keys
const allKeys = Reflect.getMetadataKeys(UsersController, 'findOne')
// → [Symbol(route_method), ...其他可能的 key]
```

### 2.3 设计元数据 Key 的最佳实践

```typescript
// ❌ 错误：用字符串容易冲突
const PATH = 'path'        // 可能和其他库的 'path' 冲突
const METHOD = 'method'    // 可能和其他库的 'method' 冲突

// ✅ 正确：使用 Symbol 保证唯一性
const METADATA = {
  // 路由相关
  CONTROLLER_PATH: Symbol.for('nestjs:controller:path'),
  ROUTE_METHOD: Symbol.for('nestjs:route:method'),
  ROUTE_PATH: Symbol.for('nestjs:route:path'),

  // 注入相关
  SELF: Symbol.for('nestjs:inject:self'),
  OPTIONAL: Symbol.for('nestjs:inject:optional'),

  // 守卫/拦截器
  GUARDS: Symbol.for('nestjs:guards'),
  INTERCEPTORS: Symbol.for('nestjs:interceptors'),

  // 自定义
  ROLES: Symbol.for('app:roles'),
  RATE_LIMIT: Symbol.for('app:rate_limit'),
  CACHE_TTL: Symbol.for('app:cache_ttl'),
} as const
```

## 三、手写 Nest.js 核心装饰器

### 3.1 @Controller() —— 类装饰器

```typescript
/**
 * @Controller() 的简化实现
 *
 * 功能：将类标记为控制器，并记录路由前缀路径
 */
function Controller(prefix?: string) {
  // 类装饰器接收构造函数作为参数
  return function <T extends { new (...args: any[]): any }>(constructor: T) {
    // 将前缀路径作为元数据存入类
    if (prefix) {
      Reflect.defineMetadata(METADATA.CONTROLLER_PATH, prefix, constructor)
    }

    // 让新类继承原类（不改变原类的行为）
    // 这样做的目的是可以在这里做一些额外的初始化
    class ControlledClass extends constructor {
      constructor(...args: any[]) {
        super(...args)
        console.log(`[Controller] ${prefix || ''} initialized`)
      }
    }

    // 重要：保留原类的原型链上的元数据
    // 否则方法上的装饰器元数据会丢失
    const originalPrototype = constructor.prototype
    const newPrototype = ControlledClass.prototype

    // 复制原型方法和元数据
    Object.getOwnPropertyNames(originalPrototype).forEach(name => {
      if (name !== 'constructor') {
        const descriptor = Object.getOwnPropertyDescriptor(originalPrototype, name)!
        Object.defineProperty(newPrototype, name, descriptor)
      }
    })

    return ControlledClass
  }
}

// 使用
@Controller('api/v1/users')
class UsersController {
  // ...
}

// 读取元数据
const path = Reflect.getMetadata(METADATA.CONTROLLER_PATH, UsersController)
console.log(path)  // → 'api/v1/users'
```

### 3.2 @Get() / @Post() —— 方法装饰器

```typescript
/**
 * HTTP 方法装饰器工厂
 *
 * @param path - 路由路径（可选）
 */
function createRouteDecorator(method: 'GET' | 'POST' | 'PUT' | 'DELETE' | 'PATCH') {
  return function (path?: string) {
    // 方法装饰器接收三个参数：
    // target: 类的原型（对于静态方法是构造函数本身）
    // propertyKey: 方法名
    // descriptor: 属性描述符（value 就是方法本身）
    return function (
      target: Object,
      propertyKey: string | symbol,
      descriptor: TypedPropertyDescriptor<any>
    ) {
      // 存储路由方法（GET/POST/...）
      Reflect.defineMetadata(METADATA.ROUTE_METHOD, method, target, propertyKey)

      // 存储路由路径
      Reflect.defineMetadata(METADATA.ROUTE_PATH, path || '', target, propertyKey)

      // 可选：保留原方法引用（用于后续包装）
      const originalMethod = descriptor.value!

      // 修改方法（例如添加日志）
      descriptor.value = function (...args: any[]) {
        console.log(`[Route] ${method} ${path || '/'}`)
        return originalMethod.apply(this, args)
      }

      return descriptor
    }
  }
}

// 导出各种 HTTP 方法装饰器
const Get = createRouteDecorator('GET')
const Post = createRouteDecorator('POST')
const Put = createRouteDecorator('PUT')
const Delete = createRouteDecorator('DELETE')
const Patch = createRouteDecorator('PATCH')


// 使用
@Controller('users')
class UserController {
  @Get(':id')
  findById(@Param('id') id: string) {
    // 这里的元数据：
    // Class → { controller_path: 'users' }
    // Method 'findById' → { route_method: 'GET', route_path: ':id' }
    return `User ${id}`
  }

  @Post()
  createUser(@Body() dto: CreateUserDto) {
    // 这里的元数据：
    // Method 'createUser' → { route_method: 'POST', route_path: '' }
    return 'Created'
  }
}
```

### 3.3 @Body() / @Param() / @Query() —— 参数装饰器

```typescript
/**
 * 参数装饰器工厂
 *
 * Nest.js 的精髓：通过参数装饰器标注"这个参数从哪里取值"
 */
function createParamDecorator(factory: (req: any, res: any) => any) {
  // 参数装饰器只接收三个参数：
  // target: 类的原型
  // propertyKey: 方法名
  // parameterIndex: 参数的位置索引（从 0 开始）
  return function (target: Object, propertyKey: string | symbol, parameterIndex: number) {
    // 获取该方法的已有参数元数据（数组），如果没有则初始化
    const existingParams =
      Reflect.getMetadata(METADATA.PARAMETERS, target, propertyKey) || []

    // 在对应位置存入参数提取器
    existingParams[parameterIndex] = factory

    // 存回元数据
    Reflect.defineMetadata(METADATA.PARAMETERS, existingParams, target, propertyKey)
  }
}

// ====== 各种内置参数装饰器 ======

// 从 request.body 取值
function Body(propertyKey?: string) {
  return createParamDecorator((req: any) =>
    propertyKey ? req.body?.[propertyKey] : req.body
  )
}

// 从 request.params 取值
function Param(key: string) {
  return createParamDecorator((req: any) => req.params[key])
}

// 从 request.query 取值
function Query(key?: string) {
  return createParamDecorator((req: any) =>
    key ? req.query[key] : req.query
  )
}

// 从 request.headers 取值
function Headers(key: string) {
  return createParamDecorator((req: any) => req.headers[key.toLowerCase()])
}

// 从 Ip 地址
function Ip() {
  return createParamDecorator((req: any) => req.ip)
}

// 从当前登录用户（需要配合 Auth Guard）
function User(propertyKey?: string) {
  return createParamDecorator((req: any) =>
    propertyKey ? req.user?.[propertyKey] : req.user
  )
}


// 使用示例
@Controller('posts')
class PostsController {
  // 参数按顺序对应不同的装饰器
  @Get(':id')
  async getPost(
    @Param('id') id: string,           // 参数索引 0 → 从 params 取 id
    @Query('includeComments') include: boolean,  // 参数索引 1 → 从 query 取
    @Headers('accept-language') lang: string,    // 参数索引 2 → 从 headers 取
    @Ip() ip: string,                            // 参数索引 3 → 从 connection 取
    @User('userId') viewerId: string,            // 参数索引 4 → 从 req.user 取
  ) {
    return { id, include, lang, ip, viewerId }
  }
}
```

### 3.4 @Injectable() —— 依赖注入标记

```typescript
/**
 * @Injectable() 的简化实现
 *
 * 功能：将类标记为可被依赖注入的 Provider
 */
function Injectable(options?: { scope?: ScopeType }) {
  return function <T extends new (...args: any[]) => any>(constructor: T) {
    // 标记为可注入
    Reflect.defineMetadata(METADATA.SELF, constructor, constructor)

    // 可选的作用域配置
    if (options?.scope) {
      Reflect.defineMetadata(METADATA.SCOPE, options.scope, constructor)
    }

    return constructor
  }

  enum ScopeType {
    DEFAULT,    // 每次注入共享同一实例（单例）
    REQUEST,    // 每个请求创建新实例
    TRANSIENT,  // 每次注入都创建新实例
  }
}


// 使用
@Injectable()
class UsersService {
  constructor(
    private repo: UsersRepository,  // 通过构造函数注入
    private logger: LoggerService,
  ) {}

  findAll() {
    return this.repo.findAll()
  }
}
```

## 四、Nest.js Reflector 服务详解

### 4.1 Reflector 是什么？

Reflector 是 Nest.js 内置的服务类，专门用于**读取装饰器设置的元数据**：

```typescript
// nestjs/core -> Reflector 类的核心方法

class Reflector {
  /**
   * 读取类或方法上的单个元数据
   */
  get<T>(metadataKey: any, target: Type<any> | Function): T

  /**
   * 读取方法上的元数据，如果没有则向上查找类级别的同名元数据
   * 这就是所谓的"元数据继承"
   */
  getAllAndOverride<T>(
    metadataKey: any,
    targets: [Type<any> | Function, (string | symbol)]
  ): T

  /**
   * 合并类和方法两级的同名元数据（通常是数组）
   * 例如：类上的 @UseGuards(A) + 方法上的 @UseGuards(B) = [A, B]
   */
  getAllAndMerge<T>(
    metadataKey: any,
    targets: [Type<any> | Function, (string | symbol)]
  ): T[]
}
```

### 4.2 getAllAndOverride 的魔法

这是 Nest.js 最强大的特性之一——**元数据的层级继承**：

```typescript
// 定义角色装饰器
export const ROLES_KEY = 'roles'

export const Roles = (...roles: string[]) => SetMetadata(ROLES_KEY, roles)

// 在类级别设置默认角色
@Roles('user')
@Controller('account')
class AccountController {
  // 继承类级别的 roles: ['user']
  @Get('profile')
  getProfile() { /* ... */ }


  // 方法级别覆盖类级别
  @Roles('admin')
  @Get('admin-panel')
  getAdminPanel() { /* ... */ }
}

// 在 Guard 中使用 Reflector 读取
@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    // getAllAndOverride: 方法上有就用方法的，否则用类上的
    const requiredRoles = this.reflector.getAllAndOverride<string[]>(ROLES_KEY, [
      context.getHandler(),   // 当前方法
      context.getClass(),     // 所属类
    ])

    // requiredRoles 对于 getProfile → ['user']（来自类）
    // requiredRoles 对于 getAdminPanel → ['admin']（来自方法，覆盖了类）

    const { user } = context.switchToHttp().getRequest()

    return requiredRoles.some(role => user.roles?.includes(role))
  }
}
```

**执行流程图**：

```
@Roles('user')                    ← 类级元数据
class AccountController {

  @Get('profile')
  getProfile() { ... }
  // Reflector.get('roles') → 查找顺序：
  //   ① 方法 'getProfile' → 没有 →
  //   ② 类 AccountController → ['user'] ✓
  // 结果: ['user']

  @Roles('admin')                 ← 方法级元数据（覆盖）
  @Get('admin-panel')
  getAdminPanel() { ... }
  // Reflector.get('roles') → 查找顺序：
  //   ① 方法 'getAdminPanel' → ['admin'] ✓（找到就停止）
  // 结果: ['admin']
}
```

### 4.3 getAllAndMerge 用于合并数组

当元数据是数组时，类和方法的元数据应该**合并**而不是**覆盖**：

```typescript
@UseGuards(JwtAuthGuard)           // 类级守卫
@UseInterceptors(LoggingInterceptor, TransformInterceptor)  // 类级拦截器
@Controller('products')
class ProductsController {
  // 合并后：Guards = [JwtAuthGuard, RolesGuard]
  //        Interceptors = [LoggingInterceptor, TransformInterceptor, CacheInterceptor]
  @UseGuards(RolesGuard)
  @UseInterceptors(CacheInterceptor)
  @Get(':id')
  getProduct() { /* ... */ }
}

@Injectable()
export class SomeInterceptor implements NestInterceptor {
  constructor(private reflector: Reflector) {}

  intercept(context: ExecutionContext, next: CallHandler) {
    // getAllAndMerge: 数组类型元数据进行合并
    const interceptors = this.reflector.getAllAndMerge<任何类型>(
      METADATA.INTERCEPTORS,
      [context.getHandler(), context.getClass()]
    )
    // → [LoggingInterceptor, TransformInterceptor, CacheInterceptor]

    return next.handle()
  }
}
```

## 五、自定义装饰器实战

### 5.1 组合装饰器

```typescript
/**
 * @Auth() —— 组合认证 + 角色检查
 *
 * 替代反复写 @UseGuards(JwtAuthGuard, RolesGuard) + @Roles(...)
 */
export function Auth(...roles: string[]) {
  return applyDecorators(
    // 启用 JWT 认证守卫
    UseGuards(JwtAuthGuard, RolesGuard),
    // 设置所需角色
    Roles(...roles),
    // 添加 Swagger 标签
    ApiBearerAuth(),
    // 添加响应示例
    ApiUnauthorizedResponse({ description: '未登录或令牌过期' }),
    ApiForbiddenResponse({ description: '权限不足' }),
  )
}

// 使用
@Controller('admin')
export class AdminController {
  @Get('users')
  @Auth('admin')  // 一行搞定！
  listUsers() { /* ... */ }

  @Post('announcements')
  @Auth('admin', 'editor')  // 多个角色任选其一
  createAnnouncement() { /* ... */ }
}
```

### 5.2 自定义参数装饰器

```typescript
/**
 * @CurrentUser() —— 获取当前登录用户（带类型）
 */
export const CurrentUser = createParamDecorator(
  (data: keyof JwtPayload | undefined, ctx: ExecutionContext): JwtPayload | any => {
    const request = ctx.switchToHttp().getRequest()

    const user = request.user as JwtPayload

    // 如果指定了属性名，只返回那个属性
    if (data) {
      return user[data]
    }

    // 否则返回整个用户对象
    return user
  }
)

/**
 * @IP() —— 获取客户端 IP（支持代理场景）
 */
export const IP = createParamDecorator(
  (_data: unknown, ctx: ExecutionContext): string => {
    const request = ctx.switchToHttp().getRequest()

    // 检查常见代理头
    return (
      request.headers['x-forwarded-for']?.split(',')[0]?.trim() ||
      request.headers['x-real-ip'] ||
      request.ip ||
      '127.0.0.1'
    )
  }
)

/**
 * @Pagination() —— 自动解析分页参数
 */
export interface PaginationQuery {
  page: number
  limit: number
  offset: number
}

export const Pagination = createParamDecorator(
  (_data: unknown, ctx: ExecutionContext): PaginationQuery => {
    const request = ctx.switchToHttp().getRequest()
    const query = request.query

    // 默认值 + 边界限制
    const page = Math.max(Number(query.page) || 1, 1)
    const limit = Math.min(Math.max(Number(query.limit) || 20, 1), 100)
    const offset = (page - 1) * limit

    return { page, limit, offset }
  }
)

/**
 * @Search() —— 解析搜索关键词
 */
export const Search = createParamDecorator(
  (_data: unknown, ctx: ExecutionContext): string | undefined => {
    const request = ctx.switchToHttp().getRequest()
    const q = request.query.q || request.query.search || request.query.keyword
    return typeof q === 'string' ? q.trim() || undefined : undefined
  }
)


// 使用示例
@Controller('items')
@UseGuards(JwtAuthGuard)
export class ItemsController {
  constructor(private itemsService: ItemsService) {}

  @Get()
  async findAll(
    @CurrentUser('userId') userId: string,  // 只取 userId
    @CurrentUser() fullUser: JwtPayload,    // 取完整用户对象
    @IP() clientIp: string,                  // 客户端 IP
    @Pagination() pagination: PaginationQuery,  // 分页参数
    @Search() keyword: string | undefined,   // 搜索词
  ) {
    return this.itemsService.findAll({
      requesterId: userId,
      clientIp,
      ...pagination,
      keyword,
    })
  }
}
```

### 5.3 自定义方法/类装饰器

```typescript
/**
 * @RateLimit() —— 限流装饰器
 */
export const RateLimit = (
  windowMs: number,    // 时间窗口（毫秒）
  maxRequests: number  // 最大请求数
) => {
  return function (
    target: any,
    propertyKey: string,
    descriptor: PropertyDescriptor
  ) {
    const originalMethod = descriptor.value
    const store = new Map<string, { count: number; resetAt: number }>()

    descriptor.value = async function (...args: any[]) {
      const ctx = args[0] as ExecutionContext
      const request = ctx.switchToHttp().getRequest()
      const key = request.ip || request.user?.id || 'anonymous'

      const now = Date.now()
      const entry = store.get(key)

      if (!entry || now > entry.resetAt) {
        store.set(key, { count: 1, resetAt: now + windowMs })
      } else if (entry.count >= maxRequests) {
        const retryAfter = Math.ceil((entry.resetAt - now) / 1000)
        throw new HttpException(
          'Too many requests',
          HttpStatus.TOO_MANY_REQUESTS,
          {
            description: `Rate limit exceeded. Try again after ${retryAfter}s`,
            headers: { 'Retry-After': String(retryAfter) },
          }
        )
      } else {
        entry.count++
      }

      return originalMethod.apply(this, args)
    }

    return descriptor
  }
}

/**
 * @Cache() —— 缓存装饰器（基于 Redis）
 */
export const Cache = (ttlSeconds: number) => {
  return function (
    target: any,
    propertyKey: string,
    descriptor: PropertyDescriptor
  ) {
    const originalMethod = descriptor.value

    descriptor.value = async function (...args: any[]) {
      const cacheService: CacheService = this.cacheService  // 假设注入了
      const ctx = args[0] as ExecutionContext
      const request = ctx.switchToHttp().getRequest()

      // 生成缓存 key
      const cacheKey = `cache:${target.constructor.name}:${propertyKey}:${JSON.stringify(request.params)}`

      // 尝试命中缓存
      const cached = await cacheService.get(cacheKey)
      if (cached) {
        return cached
      }

      // 缓存未命中，执行原方法
      const result = await originalMethod.apply(this, args)

      // 写入缓存
      await cacheService.set(cacheKey, result, ttlSeconds)

      return result
    }

    return descriptor
  }
}

/**
 * @AuditLog() —— 审计日志装饰器
 */
export const AuditLog = (action: string) => {
  return function (
    target: any,
    propertyKey: string,
    descriptor: PropertyDescriptor
  ) {
    const originalMethod = descriptor.value

    descriptor.value = async function (...args: any[]) {
      const ctx = args[0] as ExecutionContext
      const request = ctx.switchToHttp().getRequest()
      const startTimestamp = Date.now()

      try {
        const result = await originalMethod.apply(this, args)

        // 记录成功日志
        await this.auditLogService.record({
          action,
          userId: request.user?.id,
          ipAddress: request.ip,
          method: request.method,
          url: request.originalUrl,
          status: 'SUCCESS',
          duration: Date.now() - startTimestamp,
        })

        return result
      } catch (error) {
        // 记录失败日志
        await this.auditLogService.record({
          action,
          userId: request.user?.id,
          ipAddress: request.ip,
          method: request.method,
          url: request.originalUrl,
          status: 'FAILURE',
          error: error.message,
          duration: Date.now() - startTimestamp,
        })

        throw error
      }
    }

    return descriptor
  }
}
```

## 七、元数据驱动的框架设计

### 7.1 思想：元数据即配置

传统框架的配置往往是 XML / YAML / JSON 文件：

```yaml
# Spring 风格的 XML 配置
<beans>
  <bean id="userService" class="com.app.UserService">
    <property name="repo" ref="userRepository"/>
  </bean>
</beans>
```

Nest.js 的革命之处在于：**配置直接写在代码旁边，以装饰器（元数据）的形式存在**：

```typescript
// 配置就在它所配置的代码旁边！
@Injectable()
class UsersService {
  constructor(@InjectRepository(User) private repo: Repository<User>) {}
}
```

这带来了几个巨大优势：

| 传统配置文件 | 装饰器元数据 |
|------------|-------------|
| 配置和代码分离，跳转麻烦 | **就近原则**：配置就在代码上方 |
| IDE 不能检查配置的正确性 | **类型安全**：写错就有红色波浪线 |
| 重构时容易遗忘更新配置 | **同步重构**：改名时配置一起改 |
| 运行时才能发现问题 | **编译时就暴露问题** |

### 7.2 元数据驱动路由扫描器

让我们实现一个极简版本的 Nest.js 路由扫描器，展示元数据如何驱动框架行为：

```typescript
// mini-nestjs/scanner.ts

interface RouteDefinition {
  path: string
  method: string
  handlerName: string
  handler: Function
  parameters: Array<{
    index: number
    extractor: (req: any) => any
  }>
}

class RoutesScanner {
  scan(controllerClass: any, app: any): void {
    // 1. 读取控制器的路径前缀
    const controllerPath = Reflect.getMetadata(
      METADATA.CONTROLLER_PATH,
      controllerClass
    ) || ''

    // 2. 获取控制器实例
    const instance = new controllerClass(/* 依赖注入 */)

    // 3. 遍历原型上的所有方法
    const prototype = controllerClass.prototype

    Object.getOwnPropertyNames(prototype).forEach(methodName => {
      // 跳过构造函数
      if (methodName === 'constructor') return

      // 读取方法的路由元数据
      const routeMethod = Reflect.getMetadata(
        METADATA.ROUTE_METHOD,
        prototype,
        methodName
      )

      const routePath = Reflect.getMetadata(
        METADATA.ROUTE_PATH,
        prototype,
        methodName
      )

      // 如果有路由元数据，注册路由
      if (routeMethod) {
        const fullPath = `${controllerPath}/${routePath}`.replace(/\/+/g, '/')

        // 读取参数元数据
        const paramExtractors = Reflect.getMetadata(
          METADATA.PARAMETERS,
          prototype,
         methodName
        ) || []

        // 注册路由
        app[routeMethod.toLowerCase()](fullPath, async (req: any, res: any) => {
          // 根据参数装饰器提取参数
          const args = paramExtractors.map((extractor: any) =>
            extractor ? extractor(req, res) : undefined
          )

          // 调用处理方法
          const result = await prototype[methodName].call(instance, ...args)

          // 返回结果
          res.json(result)
        })

        console.log(`[Route registered] ${routeMethod} ${fullPath}`)
      }
    })
  }
}
```

### 7.3 元数据驱动的依赖注入容器

```typescript
// mini-nestjs/container.ts

class DependencyInjectionContainer {
  private providers = new Map<any, any>()
  private instances = new Map<any, any>()

  /**
   * 注册 Provider
   */
  register(providerClass: any) {
    this.providers.set(providerClass, providerClass)
  }

  /**
   * 获取实例（支持单例模式）
   */
  get<T>(providerClass: new (...args: any[]) => T): T {
    // 已有实例直接返回（单例）
    if (this.instances.has(providerClass)) {
      return this.instances.get(providerClass)
    }

    // 分析构造函数参数的类型
    const paramTypes = Reflect.getMetadata('design:paramtypes', providerClass) || []

    // 递归解析依赖
    const dependencies = paramTypes.map((depClass: any) => this.get(depClass))

    // 创建实例
    const instance = new providerClass(...dependencies)

    // 缓存实例
    this.instances.set(providerClass, instance)

    return instance
  }
}

// 关键：需要在 tsconfig.json 中启用
// "experimentalDecorators": true,
// "emitDecoratorMetadata": true,
// 这样 TypeScript 编译器才会自动发出 design:typeinfo 元数据
```

## 八、装饰器的高级模式

### 8.1 装饰器工厂的闭包陷阱

```typescript
// ⚠️ 常见错误：循环中的闭包问题
function BadDecoratorFactory() {
  let counter = 0

  return function (target: any, key: string) {
    counter++  // ❌ 所有实例共享同一个 counter！
    // 因为装饰器只在模块加载时执行一次
  }
}

// ✅ 正确做法：每个实例独立的状态应该存在实例自身上
function GoodDecoratorFactory() {
  return function (target: any, key: string) {
    const originalInit = target.init || function() {}

    target.init = function() {
      // 在WeakMap中维护每个实例的状态
      if (!counterMap.has(this)) {
        counterMap.set(this, 0)
      }
      const count = counterMap.get(this)! + 1
      counterMap.set(this, count)
      originalInit.call(this)
    }
  }
}

const counterMap = new WeakMap<object, number>()
```

### 8.2 装饰器执行顺序

```typescript
// 装饰器的执行顺序很重要！
// 规则：从内到外，从下到上

function First() {
  console.log('First: factory evaluated')
  return function (target, key, desc) {
    console.log('First: decorator applied')
  }
}

function Second() {
  console.log('Second: factory evaluated')
  return function (target, key, desc) {
    console.log('Second: decorator applied')
  }
}

class Example {
  @Second()  // 外层
  @First()   // 内层（先应用）
  method() {}
}

// 输出：
// First: factory evaluated   ← 工厂从上往下求值
// Second: factory evaluated
// First: decorator applied   ← 装饰器从下往上应用
// Second: decorator applied
```

```typescript
    Controller(entity),
    ApiTags(EntityName),

    ApiExtraModels(PaginatedResponse),
    ApiOkResponse({ schema: { $ref: `#/components/schemas/${EntityName}` } }),
  )
```

### 9.1 元数据浏览器工具

```typescript
// utils/metadata-inspector.ts

/**
 * 打印目标对象上所有的元数据
 * 用于调试和排查问题
 */
export function inspectMetadata(target: any, propertyKey?: string) {
  console.group(`📋 Metadata Inspector`)
  console.log(`Target: ${target.name || target.constructor?.name || '(anonymous)'}`)

  if (propertyKey) {
    console.log(`Property: ${String(propertyKey)}`)
    console.log('--- Method-level metadata ---')
  } else {
    console.log('--- Class-level metadata ---')
  }

  const keys = propertyKey
    ? Reflect.getMetadataKeys(target, propertyKey)
    : Reflect.getMetadataKeys(target)

  for (const key of keys) {
    const value = Reflect.getMetadata(key, target, propertyKey)
    console.log(`${String(key)}:`, formatValue(value))
  }

  console.groupEnd()
}

function formatValue(value: any): string {
  if (typeof value === 'function') {
    return `[Function: ${value.name}]`
  }
  if (typeof value === 'symbol') {
    return `Symbol(${value.description})`
  }
  if (Array.isArray(value)) {
    return `[${value.length} items]`
  }
  if (typeof value === 'object' && value !== null) {
    return JSON.stringify(value, null, 2).slice(0, 500)
  }
  return String(value)
}

// 使用：在任何装饰器中调用 inspectMetadata(target, propertyKey)
// 即可看到当前对象上挂载的所有元数据
```

## 十、最佳实践总结

### 10.1 设计原则

```
┌────────────────────────────────────────────────────────────┐
│                   装饰器设计原则                           │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  1. 单一职责                                                │
│     一个装饰器只做一件事                                   │
│     @Auth() ≠ @AuthWithLoggingWithCacheWithRateLimit()     │
│                                                            │
│  2. 可组合优于可配置                                        │
│     用 applyDecorators 组合小装饰器                         │
│     而不是做一个接受 10 个参数的巨无霸装饰器                 │
│                                                            │
│  3. 元数据 Key 用 Symbol                                    │
│     避免不同库之间的命名冲突                               │
│                                                            │
│  4. 善用 Reflector                                          │
│     用 getAllAndOverride/getAllAndMerge 处理层级关系        │
│                                                            │
│  5. 运行时验证 + 编译时类型                                  │
│     装饰器负责元数据，Guard/Interceptor/Pipe 负责运行时逻辑  │
│                                                            │
│  6. 文档即代码                                              │
│     装饰器名称应自解释                                      │
│     必要时配合 JSDoc 说明参数含义                           │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

### 10.2 性能注意

```
⚠️ 装饰器只在应用启动时执行一次，不影响请求性能
   但是：
   
   • 不要在装饰器工厂中做 I/O 操作
   • 不要在装饰器中创建大量临时对象
   • Reflect.metadata 的读写是 O(1) 的，可以放心用
   • 复杂的元数据处理放在 Module 初始化阶段，而非每次请求
   
   ✅ 好的模式：
   - 装饰器只设置元数据（纯操作）
   - Guard/Interceptor 在首次运行时缓存元数据解析结果
   - 用 WeakMap 缓存计算结果
```

## 总结

Nest.js 的装饰器系统是其最核心的设计。理解它意味着你理解了：

**第一层：语法认知** —— 五种装饰器（类/属性/方法/参数/访问器）、各自的参数签名、基本用法。

**第二层：底层原理** —— Reflect Metadata 库的工作方式、元数据的存储与读取、`design:*` 系列自动元数据的来源。

**第三层：框架集成** —— Reflector 服务的三个核心方法、`getAllAndOverride` 的层级继承、`getAllAndMerge` 的数组合并。

**第四层：工程实践** —— 自定义装饰器的创建、`applyDecorators` 组合、元数据驱动的架构设计、调试技巧。

**终极洞察**：装饰器本质上是一种**声明式的元编程**。它让你用"声明什么"代替"命令怎么做"，将横切关注点（认证、日志、缓存、权限）从业务逻辑中剥离出来，以优雅的注解形式表达。这种思想不仅限于 Nest.js——Angular 也采用同样的模式，甚至 Java 的 Spring Annotation、Python 的 Decorator 都是同一思想的体现。
