# 编写类型声明文件（.d.ts）—— 为纯 JS 库编写类型、模块声明、全局类型

> **核心问题**：世界上有海量的 JavaScript 库没有 TypeScript 类型定义。如何为它们写 `.d.ts` 声明文件？如何声明全局变量、模块、命名空间？如何处理 CommonJS / ES Module 的差异？本章将让你成为"类型补完者"。

---

## 一、为什么需要 .d.ts 文件？

### 1.1 从现实痛点说起

你一定遇到过这种情况：

```typescript
// 安装了一个很棒的 JS 库
import coolLib from 'some-cool-js-lib'

// 但是……没有任何类型提示 😱
coolLib.doSomething(???)
//            ^^^^ 这个函数接受什么参数？返回什么？
// IDE 完全不知道！只能去翻文档……

// 更惨的是，你甚至不能确定这个方法是否存在
coolLib.maybeThisExists()
//   ^^^^^^^^^^^^^^^^ TypeScript 不会报错（因为默认是 any）
// 但运行时会直接崩溃！
```

**`.d.ts` 文件就是解决方案**——它是一份"类型说明书"，告诉 TypeScript 某段 JS 代码的形状：

```
JavaScript 库（运行时代码）    .d.ts 声明文件（类型说明）
┌─────────────────────┐      ┌─────────────────────────────┐
│                     │      │                             │
│  function add(a,b){ │ ──→ │  declare function add(       │
│    return a + b     │      │    a: number,               │
│  }                  │      │    b: number                │
│                     │      │  ): number                  │
│                     │      │                             │
└─────────────────────┘      └─────────────────────────────┘
         运行时使用                   编译时检查
```

### 1.2 .d.ts 的本质

**关键理解**：`.d.ts` 文件中只有类型声明，没有实现代码。它不会被编译成 JavaScript。

```typescript
// utils.ts —— 普通的 TS 文件（有实现）
export function add(a: number, b: number): number {
  return a + b  // ← 有具体实现！会编译成 JS
}

// utils.d.ts —— 声明文件（只有类型）
declare function add(a: number, b: number): number
//                    ↑ 只有签名，没有函数体！
//                    ↑ 不会被编译到 JS 中

declare class Calculator {
  add(a: number, b: number): number
  //   ↑ 同样没有方法体
}

declare interface Point {
  x: number
  y: number
}
// ↑ 接口本来就没有实现，所以接口在 .d.ts 和 .ts 中写法一样
```

### 1.3 d.ts 与 ts 的区别

| 特性 | `.ts` 文件 | `.d.ts` 文件 |
|------|-----------|-------------|
| 包含实现代码 | ✅ `function f() { ... }` | ❌ 只能声明 |
| 包含类型 | ✅ `interface I {}` | ✅ `interface I {}` |
| 编译输出 | ✅ 生成 `.js` 文件 | ❌ 不生成任何东西 |
| import/export | ✅ 正常导入导出 | ✅ 可以用 `import()` 语法 |
| `declare` 关键字 | 不需要 | **必须**用于值级声明 |
| 用途 | 写业务代码 | 为已有 JS 补充类型 |

## 二、环境声明（Ambient Declarations）

### 2.1 declare 关键字

`declare` 告诉 TypeScript："这个东西已经存在于运行时了，我只是在这里描述它的类型"。

```typescript
// types.d.ts

// ====== 声明一个变量 ======
declare const VERSION: string
declare let debugMode: boolean
declare var globalConfig: {
  apiUrl: string
  timeout: number
}

// ====== 声明一个函数 ======
declare function createElement(tag: string, attrs?: Record<string, any>): HTMLElement
declare function formatDate(date: Date, format?: string): string

// ====== 声明一个类 ======
declare class EventEmmiter {
  on(event: string, listener: (...args: any[]) => void): this
  off(event: string, listener: Function): this
  emit(event: string, ...args: any[]): boolean
}

// ====== 声明枚举 ======
declare enum HttpMethod {
  GET = 'GET',
  POST = 'POST',
  PUT = 'PUT',
  DELETE = 'DELETE',
}

// ====== 声明命名空间 ======
declare namespace MyLib {
  interface Config {
    debug: boolean
    version: string
  }

  function init(config: Config): void
  function getVersion(): string

  namespace Utils {
    function clone<T>(obj: T): T
    function debounce(fn: Function, ms: number): Function
  }
}
```

### 2.2 全局声明 vs 模块声明

这是 `.d.ts` 中最重要的区分：

```typescript
// ════════════════════════════════════════
// 情况 A：全局声明（无任何 import/export）
// → 声明的内容在整个项目中全局可用
// ════════════════════════════════════════

// globals.d.ts

// 声明全局变量
declare const __APP_VERSION__: '1.0.0' | '2.0.0'
declare const __API_BASE_URL__: string

// 扩展已有的全局接口（声明合并）
interface Window {
  // 给 window 对象添加自定义属性
  __INITIAL_DATA__: any
  myCustomMethod(): void
}

interface String {
  // 给 String 原型添加自定义方法
  toKebabCase(): string
  capitalize(): string
}

// 使用时无需 import：
const v = __APP_VERSION__        // 直接可用
window.__INITIAL_DATA__ = {}     // 可用
'hello world'.capitalize()       // 可用


// ════════════════════════════════════════
// 情况 B：模块声明（包含 import 或 export）
// → 声明的内容只在 import 后可用
// ════════════════════════════════════════

// some-js-library.d.ts

// 一旦出现 import 或 export，此文件就变成模块作用域
export default function main(options?: Options): void
export function helper(): string
export const CONSTANTS: Readonly<Record<string, string>>
export interface Options {
  verbose?: boolean
  outputDir?: string
}

// 使用时需要 import：
import { helper } from 'some-js-library'  // 必须导入才能使用
helper()
```

### 2.3 三斜线指令

三斜线指令用于在 `.d.ts` 中引入其他声明文件的依赖：

```typescript
/// <reference path="./other.d.ts" />           // 引入同路径下的其他声明文件
/// <reference types="node" />                   // 引入 @types/node 的类型
/// <reference types="jquery" />                 // 引入 @types/jquery 的类型
/// <reference lib="es2018" />                   // 引入内置的 ES2018 类型库

// 示例：为一个依赖 jQuery 的插件写声明
/// <reference types="jquery" />

declare namespace JQuery {
  interface Fn {
    // 给 jQuery 原型添加插件方法
    myPlugin(options?: PluginOptions): JQuery
  }
}

interface PluginOptions {
  color?: string
  speed?: number
  onComplete?: () => void
}
```

## 三、为第三方库编写声明

### 3.1 完整实战：为虚拟库 `tiny-utils` 编写声明

假设有一个 JavaScript 工具库，源码如下（我们看不到它的内部实现，只能看到文档）：

```javascript
// tiny-utils/index.js (纯 JS，没有类型)

// 格式化日期
exports.formatDate = function(date, pattern) {
  // ...
}

// 防抖函数
exports.debounce = function(fn, wait, immediate) {
  // ...
}

// 深度合并对象
exports.deepMerge = function(target, ...sources) {
  // ...
}

// 创建发布订阅器
exports.createEventBus = function() {
  return {
    on(event, handler) {},
    off(event, handler) {},
    emit(event, data) {},
    once(event, handler) {},
    clear() {},
  }
}
```

现在为它写完整的声明文件：

```typescript
// types/tiny-utils/index.d.ts

/**
 * tiny-utils 的 TypeScript 类型声明
 * 
 * 版本: 1.2.0
 * 来源: https://github.com/example/tiny-utils
 */

// ==================== 函数声明 ====================

/**
 * 格式化日期
 * @param date - 要格式化的日期
 * @param pattern - 格式模式串（默认 'YYYY-MM-DD HH:mm:ss'）
 * @returns 格式化后的字符串
 */
export function formatDate(
  date: Date | string | number,
  pattern?: string
): string

/**
 * 防抖函数
 * @param fn - 要防抖的函数
 * @param wait - 等待时间（毫秒）
 * @param immediate - 是否立即执行一次
 * @returns 防抖后的新函数（支持 cancel 方法）
 */
export function debounce<T extends (...args: any[]) => any>(
  fn: T,
  wait: number,
  immediate?: boolean
): T & { cancel(): void }

/**
 * 深度合并多个对象
 * @param target - 目标对象
 * @param sources - 要合并的源对象
 * @returns 合并后的新对象（不修改原对象）
 */
export function deepMerge<T extends object, S extends object[]>(
  target: T,
  ...sources: S
): T & S[number]

// ==================== 接口声明 ====================

/** EventBus 的事件映射类型 */
export type EventBusEvents = Record<string, any>

/** EventBus 事件处理器 */
export type EventHandler<E> = (data: E) => void

/** EventBus 实例 */
export interface EventBus<E extends EventBusEvents = EventBusEvents> {
  /** 监听事件 */
  on<K extends keyof E>(event: K, handler: EventHandler<E[K]>): this
  /** 取消监听 */
  off<K extends keyof E>(event: K, handler: EventHandler<E[K]>): this
  /** 触发事件 */
  emit<K extends keyof E>(event: K, data: E[K]): boolean
  /** 只监听一次 */
  once<K extends keyof E>(event: K, handler: EventHandler<E[K]>): this
  /** 清除所有监听器 */
  clear(): void
}

// ==================== 工厂函数返回类型推断 ====================

/**
 * 创建事件总线
 * @returns 新的 EventBus 实例
 */
export function createEventBus<E extends EventBusEvents = {}>(): EventBus<E>
```

### 3.2 处理复杂情况

#### 动态属性的对象

```typescript
// CSS Modules 的样式对象
declare module '*.module.css' {
  const classes: {
    [key: string]: string
  }
  export default classes
}

// SVG 图片导入
declare module '*.svg' {
  const content: string
  export default content
}

// JSON 导入（TS 4.9+ 已内置支持，但旧版本可能需要）
declare module '*.json' {
  const value: any
  export default value
}

// Markdown 文件
declare module '*.md' {
  const content: string
  export default content
}
```

#### 可链式调用的 API

```typescript
// 类似 jQuery / lodash 的链式 API
interface Chainable<T> {
  /** 获取当前值的快照 */
  value(): T
  
  /** 映射每个元素 */
  map<U>(callback: (item: T) => U): Chainable<U[]>
  
  /** 过滤元素 */
  filter(predicate: (item: T) => boolean): Chainable<T[]>
  
  /** 排序 */
  sort(compareFn?: (a: T, b: T) => number): Chainable<T[]>
  
  /** 取前 N 个 */
  take(n: number): Chainable<T[]>
  
  /** 归约 */
  reduce<U>(callback: (acc: U, item: T) => U, initialValue: U): Chainable<U>
}

declare function chain<T>(value: T): Chainable<T>
```

#### 回调风格的异步 API

```typescript
// Node.js callback 风格
declare function readFile(
  path: string,
  encoding: string,
  callback: (err: Error | null, data: string) => void
): void

// 更通用的回调类型
type Callback<T = void, E = Error> = (err: E | null, result: T) => void

declare function fsReadFile(path: string, cb: Callback<string>): void
declare function dbQuery(sql: string, params: any[], cb: Callback<any[]>): void
```

## 四、模块声明技巧

### 4.1 declare module —— 万能模块声明

当某个模块没有类型，或者你想覆盖其类型时：

```typescript
// ════════════════════════════════════════
// 场景 1：为完全无类型的 npm 包创建壳声明
// ════════════════════════════════════════

// declarations.d.ts
declare module 'some-untyped-package' {
  // 在这里可以写任何类型声明
  export default function main(options?: Options): Promise<Result>
  export function helper(input: string): number
  export interface Options { /* ... */ }
  export interface Result { /* ... */ }

  // 或者简单粗暴地导出 any
  // export default any
}


// ════════════════════════════════════════
// 场景 2：增强已有模块的类型（声明合并）
// ════════════════════════════════════════

// 扩展 express
declare module 'express' {
  interface Request {
    // 添加自定义属性
    user?: AuthUser
    session?: SessionData
    requestId: string
  }

  interface Response {
    // 添加自定义响应方法
    apiSuccess(data: any): Response
    apiError(code: number, message: string): Response
  }
}


// ════════════════════════════════════════
// 场景 3：通配符模块声明（处理各种资源导入）
// ════════════════════════════════════════

declare module '*.vue' {
  import { DefineComponent } from 'vue'
  const component: DefineComponent<object, object, any>
  export default component
}

declare module '*?raw' {
  const content: string
  export default content
}

declare module '*?url' {
  const src: string
  export default src
}
```

### 4.2 declare namespace vs declare module

```typescript
// namespace：组织一组相关的类型/值（通常用于全局或 UMD 库）
declare namespace MyApp {
  interface Config { /* ... */ }
  type Theme = 'light' | 'dark'
  function init(config: Config): void
  
  namespace Utils {
    function format(str: string): string
  }
}

// 使用：MyApp.Config, MyApp.init(), MyApp.Utils.format()

// module：声明一个外部模块的形状
declare module 'my-app' {
  interface Config { /* ... */ }
  type Theme = 'light' | 'dark'
  function init(config: Config): void
}

// 使用：import { init } from 'my-app'
```

### 4.3 处理不同的模块系统

```typescript
// ════════════════════════════════════════
// ES Module（推荐）
// ════════════════════════════════════════

// es-module.d.ts
export default function esMain(): void
export function esHelper(): string
export const version: number

// ════════════════════════════════════════
// CommonJS（module.exports）
// ════════════════════════════════════════

  export function resolve(id: string): string

export = cjsRequire

// UMD（同时支持两种用法）
// ════════════════════════════════════════

  function umdMethod(): void

// import UMDLib from 'umd-lib'          // ES Module 方式

// UMDLib.umdMethod()                     // 全局方式（通过 script 标签加载后）
```

## 五、高级声明模式

### 5.1 泛型重载

当一个函数根据参数不同返回不同类型时：

```typescript
// lodash get 的简化声明
declare function get<T>(object: T, path: string): any
declare function get<T, P1 extends keyof T>(
  object: T,
  path: P1
): T[P1]
declare function get<T, P1 extends keyof T, P2 extends keyof NonNullable<T[P1]>>(
  object: T,
  path: [P1, P2]
): NonNullable<T[P1]>[P2]
declare function get<T, P1 extends keyof T, P2 extends keyof NonNullable<T[P1]>, P3 extends keyof NonNullable<NonNullable<T[P1]>[P2]>>(
  object: T,
  path: [P1, P2, P3]
): NonNullable<NonNullable<T[P1]>[P2]>[P3]


// 使用效果
const user = { name: 'Alice', address: { city: 'Beijing', zip: '100000' } }

get(user, 'name')              // → string
get(user, ['address'])         // → { city: string; zip: string }
get(user, ['address', 'city']) // → "Beijing"
get(user, 'nonexistent')       // → any（回退）
```

### 5.2 条件类型的声明

```typescript
// axios 响应类型的条件推断
declare namespace Axios {
  interface AxiosResponse<T = any> {
    data: T
    status: number
    statusText: string
    headers: RawAxiosResponseHeaders
    config: InternalAxiosRequestConfig
    request?: any
  }

  interface AxiosInstance {
    get<T = any, R = AxiosResponse<T>>(url: string, config?: AxiosRequestConfig): Promise<R>
    post<T = any, R = AxiosResponse<T>>(url: string, data?: any, config?: AxiosRequestConfig): Promise<R>
  }
}

// Promise 解包
declare type UnwrapPromise<T> = T extends Promise<infer U> ? U : T

// 数组解包
declare type UnwrapArray<T> = T extends (infer U)[] ? U : T
```

### 5.3 模板字面量类型的声明

```typescript
// 事件名称的类型安全
declare class EventEmitter<Events extends Record<string, any[]>> {
  on<E extends keyof Events>(event: E, handler: (...args: Events[E]) => void): this
  emit<E extends keyof Events>(event: E, ...args: Events[E]): boolean
  off<E extends keyof Events>(event: E, handler: (...args: Events[E]) => void): this
}

// 定义事件映射
interface MyEvents {
  'user:login': [userId: string, timestamp: number]
  'user:logout': [userId: string]
  'message:send': [from: string, to: string, content: string]
  'file:upload': [file: File, progress: (pct: number) => void]
}

const bus = new EventEmitter<MyEvents>()

// ✅ 完全类型安全
bus.on('user:login', (userId, timestamp) => {
  // userId → string, timestamp → number
})

bus.emit('message:send', 'Alice', 'Bob', 'Hello!')
//                                 ^^^^^^ ^^^  ^^^^^^^^
//                                 string string string —— 参数类型和数量都正确!

// ❌ 错误会在编译时捕获
bus.emit('user:login', 'only-one-arg')
//                        ^^^^^^^^^^^^^^^^
//                        缺少第二个参数 timestamp！

bus.on('unknown-event', handler)
//    ^^^^^^^^^^^^^^
//    不存在的事件名！
```

### 5.4 使用 typeof 从现有值推导类型

```typescript
// 有时候从实际的对象/配置中提取类型比手写更准确

// config.js (运行时的配置对象)
const CONFIG = Object.freeze({
  API_URL: 'https://api.example.com',
  TIMEOUT: 5000,
  RETRY_COUNT: 3,
  FEATURES: {
    darkMode: true,
    notifications: false,
  },
})

// config.d.ts —— 使用 typeof 推导
declare const CONFIG: {
  readonly API_URL: string
  readonly TIMEOUT: number
  readonly RETRY_COUNT: number
  readonly FEATURES: {
    readonly darkMode: boolean
    readonly notifications: boolean
  }
}

export { CONFIG }

// 更好的做法：直接导出类型
export type AppConfig = typeof CONFIG
```

## 六、声明文件的组织结构

### 6.1 推荐的项目结构

```
your-project/
├── src/
│   └── (你的源代码)
├── types/                          # 所有自定义类型声明
│   ├── index.d.ts                  # 入口文件（re-export 所有类型）
│   ├── globals.d.ts               # 全局变量/接口扩展
│   ├── env.d.ts                   # 环境变量声明
│   ├── modules/                   # 第三方模块的类型增强
│   │   ├── express.d.ts
│   │   └── vue-router.d.ts
│   └── third-party/              # 无类型库的声明
│       ├── some-old-lib.d.ts
│       └── another-lib.d.ts
├── tsconfig.json
└── package.json
```

### 6.2 index.d.ts 入口示例

```typescript

}
```

## 七、常见陷阱与解决

### 7.1 陷阱清单

```typescript
// ❌ 陷阱 1：在模块化的 .d.ts 中意外声明全局内容
// some.d.ts
export {}
declare const oopsGlobal = 'hi'  // 这不会成为全局变量 ✓
// 但如果去掉 export {}，oopsGlobal 就泄漏为全局变量了！

// ✅ 解决：始终明确是否要全局/模块
// 全局声明文件 → 不要任何 import/export
// 模块声明文件 → 至少有一个 import 或 export {}


// ❌ 陷阱 2：declare 和实现混在一起
// bad.ts
export declare function foo(): string  // 多余！export 本身就暗示了声明
export function foo(): string {        // 如果有实现就不需要 declare
  return 'hello'
}

// ✅ .ts 文件中有实现 → 不用 declare
// ✅ .d.ts 文件中没有实现 → 必须用 declare


// ❌ 陷阱 3：忘记声明可选参数的可选性
// real library: fn(a, b?) — b 是可选的
declare function fn(a: string, b: string): void
//                                              ^^^^ 应该是 b?: string

// ✅ 正确
declare function fn(a: string, b?: string): void


// ❌ 陷阱 4：过度使用 any
declare function process(data: any): any  // 失去了类型安全的意义

// ✅ 至少使用泛型
declare function process<T>(data: T): Promise<T>


// ❌ 陷阱 5：不处理 this 类型
class BadWidget {
  // 如果原始 JS 库的方法使用了 this，必须声明 this 类型
  onClick(handler: Function): void { /* ... */ }
}

// ✅ 正确：显式声明 this
class GoodWidget {
  onClick(this: GoodWidget, handler: (widget: GoodWidget) => void): void {
    // 现在 this 被正确绑定
  }
}
```

## 八、发布到 DefinitelyTyped

### 8.1 DT 发布流程概览

DefinitelyTyped（DT）是 TypeScript 社区维护的**所有第三方库类型声明的中央仓库**。

```
你的流程:
1. Fork https://github.com/DefinitelyTyped/DefinitelyTyped
2. 创建 types/your-lib-name/index.d.ts
3. 编写完整的类型声明
4. 提交 Pull Request
5. DT 维护者 review
6. 合并后用户 npm i -D @types/your-lib-name 即可安装
```

### 8.2 DT 的目录结构规范

```
DefinitelyTyped/
└── types/
    └── your-lib-name/
        ├── index.d.ts          # 主入口声明（必须有）
        ├── your-lib-name-tests.ts  # 测试文件（必须有！）
        ├── other-module.d.ts   # 子模块声明（可选）
        └── package.json        # 元信息（自动生成）
```

**index.d.ts 最简模板**：

```typescript
// Type definitions for your-lib-name
// Project: https://github.com/you/your-lib-name
// Definitions by: Your Name <email@example.com>
// TypeScript Version: 4.5

export as namespace YourLibName
export = YourLibName

declare namespace YourLibName {
  interface Options {
    debug?: boolean
  }

  function main(options?: Options): Result
  function helper(): void

  interface Result {
    success: boolean
    data?: any
  }
}
```

**your-lib-name-tests.ts 测试模板**：

```typescript
import YourLibName = require('your-lib-name')

// 基本功能测试
const result = YourLibName.main({ debug: true })
if (result.success) {
  console.log(result.data)
}

YourLibName.helper()

// 类型错误测试（确保以下行确实报错）
// 取消注释这些行来验证类型是否正确工作：
// YourLibName.main("wrong argument")  // 期望报错
// const x: number = YourLibName.main()  // 期望报错
```

### 8.3 DT 贡献最佳实践

```
✅ DO:
   • 先阅读 DT 的 CONTRIBUTING.md 指南
   • 提供测试文件证明类型正确性
   • 支持该库的所有公开 API（不要只声明部分）
   • 使用正确的模块格式（ESM/CJS/UMD）
   • 处理泛型和回调的复杂场景
   • 关注 PR review 反馈并及时修改

❌ DON'T:
   • 不要提交自己项目的私有库类型（除非开源）
   • 不要复制粘贴 AI 生成的未经验证的类型
   • 不要忽略测试文件（DT 强制要求测试！）
   • 不要使用 any 来回避复杂的类型问题
   • 不要一次性提交巨型 PR（拆分成小改动）
```

## 总结

编写 `.d.ts` 类型声明文件是一项极其重要的技能：

**第一层：基础语法** —— `declare` 关键字、全局声明 vs 模块声明、三斜线指令、五种可声明构造（变量/函数/类/枚举/命名空间）。

**第二层：模块声明** —— `declare module` 通配符语法、ESM/CJS/UMD 三种模块系统的声明方式、`declare namespace` vs `declare module` 的选择。

**第三层：高级模式** —— 泛型重载、条件类型、模板字面量类型、`typeof` 推导、事件系统的类型安全设计。

**第四层：工程实践** —— 项目中的声明文件组织结构、tsconfig 配合、调试技巧、DefinitelyTyped 贡献流程。

**终极价值**：掌握 `.d.ts` 意味着你可以为任何 JavaScript 生态补全类型。这不仅是个人开发的效率工具，更是对整个社区的贡献——每一个高质量的 `.d.ts` 都能让无数开发者受益。
