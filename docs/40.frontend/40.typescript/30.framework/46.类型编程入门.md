# 类型编程入门 —— 类型作为值的计算（Fibonacci、加法、字符串解析）

> **核心问题**：你知道 TypeScript 的类型系统是图灵完备的吗？这意味着它本质上是一门"运行在编译期的编程语言"。你可以在类型层面做加法、判断素数、解析字符串、计算斐波那契数列……这就是所谓的"类型体操"或"类型编程"。本章将带你推开这扇神奇的大门。

---

## 一、什么是类型编程？

### 1.1 从值编程到类型编程

你已经熟悉了**值层面的编程**——用变量存储数据，用函数处理数据：

```typescript
// 值编程（日常写法）
function add(a: number, b: number): number {
  return a + b
}

const result = add(3, 5)  // result = 8 (number 类型)
```

**类型编程**则是同样的思想搬到**类型层面**——用类型参数作为"变量"，用条件/递归等作为"操作"：

```typescript
// 类型编程（本章重点）
type Add<A extends number, B extends number> = 
  [...BuildArray<A>, ...BuildArray<B>]['length']

type Result = Add<3, 5>  // Result = 8 (数字字面量类型 8)
//                         ^^^ 不是运行时的 8！而是编译期就确定的类型 8
```

**核心对比**：

```
╔══════════════════════════════════════════════════════════════╗
║                                                              ║
║  值编程                          类型编程                     ║
║  ══════                         ══════                       ║
║  数据存在 内存/寄存器中           数据存在 编译器的类型系统中    ║
║  运行时计算                      编译期计算                    ║
║  结果是 runtime value            结果是 compile-time type      ║
║  变量: let / const               变量: 泛型参数 T / infer U    ║
║  分支: if / else                 分支: extends ? :            ║
║  循环: for / while               循环: 递归类型                ║
║  函数: function                  函数: 条件类型 / 映射类型      ║
║  输出: console.log               输出: 类型报错/IDE提示        ║
║                                                              ║
║  性能影响: 占用 CPU/内存           性能影响: 增加编译时间        ║
║  调试: debugger / console         调试: 查看推断出的类型        ║
║                                                              ║
╚══════════════════════════════════════════════════════════════╝
```

### 1.2 为什么学习类型编程？

**理由一：极致的类型安全**

```typescript
// 没有类型编程：运行时才发现错误
function routeTo(path: string) {
  // 拼错路径？多写斜杠？大小写错误？全部要到运行才知道
  window.location.href = '/api/usr/profile'  // 应该是 /api/user/profile
}

// 有类型编程：编译时就拦截错误
type Route = '/api/users' | '/api/posts/:id' | '/auth/login'

function safeRoute<P extends Route>(path: P) {
  window.location.href = path
}

safeRoute('/api/users')           // ✅
safeRoute('/api/usr/profile')     // ❌ 编译错误！不是合法路由
```

**理由二：消除重复代码**

```typescript
// 没有：手动同步类型
interface UserCreateDTO {
  name: string
  email: string
  age: number
}

interface UserUpdateDTO {
  name?: string
  email?: string
  age?: number
}
// 手动把每个字段改成 optional，容易遗漏

// 有：类型编程一键转换
type PartialBy<T, K extends keyof T> = Omit<T, K> & Partial<Pick<T, K>>

type UserUpdateDTO = PartialBy<UserCreateDTO, 'name' | 'email' | 'age'>
// 自动生成，永远一致
```

**理由三：框架/库的核心能力**

Vue 3 的 `ref<T>`、React 的 `useState<S>`、Zod 的 `z.infer<T>`、Prisma 的 `$inferSelect`……所有现代 TypeScript 框架的核心都建立在类型编程之上。

### 1.3 图灵完备意味着什么？

TypeScript 类型系统是**图灵完备**的，这意味着理论上它可以**计算任何可计算函数**（只要编译器不崩溃）。

```
图灵完备 = 能模拟通用图灵机 = 能完成任何"可计算"的任务

实际含义:
✓ 可以做算术运算（加减乘除）
✓ 可以做逻辑运算（与或非）
✓ 可以做循环/递归（斐波那契、阶乘）
✓ 可以做数据结构操作（数组、字符串、对象）
✓ 可以做解析（JSON parser、SQL parser）

限制:
✗ 受递归深度限制（通常约 1000 层）
✗ 不能做 I/O（不能读文件、发网络请求——当然，它是编译期的）
✗ 计算是单向的（类型→类型，无法在运行时读取类型信息）
```

## 二、类型编程的"原子"

就像化学物质由原子构成一样，类型编程由以下基础构件组成：

### 2.1 字面量类型（Literals）—— 原始数据

```typescript
// 这些是最基本的"值"，对应值编程中的基本数据类型
type True = true
type False = false
type Zero = 0
type One = 1
type FortyTwo = 42
type Hello = 'hello'
type Empty = ''
type Nil = null
type Undefined = undefined

// 元组类型充当"数组"
type Pair = [string, number]        // 固定长度数组
type Triple = [boolean, string, number]

// 联合类型充当"集合"
type Colors = 'red' | 'green' | 'blue'
type Numbers = 1 | 2 | 3 | 4 | 5
```

### 2.2 条件类型（Conditional Types）—— if/else

```typescript
// 基本形式: T extends U ? X : Y
// 含义: 如果 T 是 U 的子类型，则类型为 X，否则为 Y

type IsString<T> = T extends string ? true : false

type A = IsString<'hello'>   // true
type B = IsString<42>        // false
type C = IsString<string>    // true（string 是 string 的子类型）

// 嵌套条件类型 = 多分支 if-else
type TypeName<T> =
  T extends string ? 'string' :
  T extends number ? 'number' :
  T extends boolean ? 'boolean' :
  T extends undefined ? 'undefined' :
  T extends Function ? 'function' :
  'object'

type T1 =TypeName<string>    // 'string'
type T2 =TypeName<true>       // 'boolean'
type T3 =TypeName<() => void> // 'function'
type T4 =TypeName<{ a: 1 }>   // 'object'
```

### 2.3 infer 关键字 —— 变量绑定

`infer` 是类型编程中最强大的特性之一。它在条件类型中**声明一个新的类型变量**，用来"捕获"类型的一部分：

```typescript
// 基本用法：提取数组元素的类型
type ElementOf<T> = T extends (infer E)[] ? E : never

type ArrElement = ElementOf<[string, number, boolean]>
// → string | number | boolean（联合类型！后面解释原因）

type StrArrElement = ElementOf<string[]>
// → string

// 提取函数返回值
type ReturnType<T> = T extends (...args: any[]) => infer R ? R : never

type FnReturn = ReturnType<(x: number) => string>
// → string

// 提取函数参数（元组形式）
type Params<T> = T extends (...args: infer P) => any ? P : never

type FnParams = Params<(a: string, b: number) => void>
// → [string, number]

// 提取 Promise 内部的类型
type UnpackedPromise<T> = T extends Promise<infer U> ? U : never

type PromiseValue = UnpackedPromise<Promise<{ id: number; name: string }>>
// → { id: number; name: string }

// 提取数组第一个元素
type First<T extends any[]> = T extends [infer F, ...any[]] ? F : never

type Head = First<[number, string, boolean]>
// → number

// 提取数组最后一个元素
type Last<T extends any[]> = T extends [...any[], infer L] ? L : never

type Tail = Last<[number, string, boolean]>
// → boolean
```

### 2.4 映射类型（Mapped Types）—— for 循环

```typescript
// 基本形式: { [K in Keys]: Type }
// 含义: 遍历 Keys 中的每个 key，生成对应的属性

// 把所有字段变成可选
type Optional<T> = { [K in keyof T]?: T[K] }

type User = { name: string; age: number; email: string }
type OptionalUser = Optional<User>
// → { name?: string; age?: number; email?: string }

// 把所有字段变成只读
type Readonly<T> = { readonly [K in keyof T]: T[K] }

// 把所有字段变成 nullable
type Nullable<T> = { [K in keyof T]: T[K] | null }

// 把所有字段包装一层包装器
type Wrapper<T> = { [K in keyof T]: { value: T[K]; changed: boolean } }

type WrappedUser = Wrapper<User>
// → {
//     name: { value: string; changed: boolean };
//     age: { value: number; changed: boolean };
//     email: { value: string; changed: boolean };
//   }

// 只保留特定字段
type Pick<T, K extends keyof T> = { [P in K]: T[P] }

type NameAndAge = Pick<User, 'name' | 'age'>
// → { name: string; age: number }
```

### 2.5 模板字面量类型（Template Literal Types）—— 字符串操作

```typescript
// 字符串拼接
type Greeting<T extends string> = `Hello, ${T}!`

type Msg = Greeting<'World'>  // → "Hello, World!"

// 字符串模式匹配（配合 infer）
type ExtractRouteParams<T extends string> =
  T extends `${string}:${infer Param}/${string}` ? Param :
  T extends `${string}:${infer Param}` ? Param :
  never

type Params1 = ExtractRouteParams<'/users/:id/posts/:postId'>
// → 'id' | 'postId'

// 大小写转换
type UpperCase<T extends string> = intrinsic   // 内置
type LowerCase<T extends string> = intrinsic   // 内置
type Capitalize<T extends string> = intrinsic  // 内置
type Uncapitalize<T extends string> = intrinsic  // 内置

type Up = UpperCase<'hello'>  // → "HELLO"
type Low = LowerCase<'HELLO'> // → "hello"
type Cap = Capitalize<'hello'> // → "Hello"
```

### 2.6 递归类型（Recursive Types）—— 循环

由于类型系统中没有 while/for 循环，**递归是实现重复操作的唯一方式**：

```typescript
// 构建指定长度的数组（类型编程的基础设施）
type BuildArray<N extends number, T extends any[] = []> =
  T['length'] extends N ? T : BuildArray<N, [...T, any]>

type Length3 = BuildArray<3>
// → [any, any, any] （长度为 3 的元组）
type Length0 = BuildArray<0>
// → [] （空数组）
type Length5 = BuildArray<5>
// → [any, any, any, any, any] （长度为 5 的元组）
```

这段代码值得逐行理解：

```
BuildArray<3> 的执行过程（展开追踪）:

Step 1: BuildArray<3, []>
        [] 的 length = 0 ≠ 3 → 继续递归
        → BuildArray<3, [any]>

Step 2: BuildArray<3, [any]>
        [any] 的 length = 1 ≠ 3 → 继续递归
        → BuildArray<3, [any, any]>

Step 3: BuildArray<3, [any, any]>
        length = 2 ≠ 3 → 继续
        → BuildArray<3, [any, any, any]>

Step 4: BuildArray<3, [any, any, any]>
        length = 3 = 3! ✅ 匹配成功!
        返回: [any, any, any]

结果: 长度为 3 的元组
```

## 三、算术运算

### 3.1 自然数表示法

TypeScript 的类型系统没有原生的数值运算能力。但我们可以利用**元组长度代表数字**来实现：

```
数字 0 → []           （空数组，长度 0）
数字 1 → [any]        （含 1 个元素，长度 1）
数字 2 → [any, any]   （含 2 个元素，长度 2）
数字 3 → [any, any, any]
...
数字 N → 长度为 N 的元组
```

这就是**皮亚诺公理**的思想——自然数可以用"后继"操作来定义：
- 0 是自然数
- 每个自然数的后继也是自然数
-在我们的表示中，[...T, any] 就是 T 的"后继"

### 3.2 加法

```typescript
type BuildArray<N extends number, T extends any[] = []> =
  T['length'] extends N ? T : BuildArray<N, [...T, any]>

// 加法的原理：拼接两个数组 → 新数组的长度就是和
type Add<A extends number, B extends number> =
  [...BuildArray<A>, ...BuildArray<B>]['length']

// 测试
type Sum1 = Add<2, 3>   // → 5
type Sum2 = Add<0, 0>    // → 0
type Sum3 = Add<10, 20>  // → 30
type Sum4 = Add<100, 200>// → 300
```

**可视化理解**：

```
Add<2, 3> 的计算过程:

BuildArray<2> → [any, any]        (长度 2)
BuildArray<3> → [any, any, any]   (长度 3)

拼接: [any, any, any, any, any]    (两个元组合并)

取 length: 5                        ← 这就是 2 + 3 的结果！
```

### 3.3 减法

减法稍微复杂一些。思路是通过"配对消耗"两个数组：

```typescript
/**
 * 减法原理：
 * 从被减数数组中逐一移除元素，每移除一个就同时移除减数数组中的一个
 * 当减数数组耗尽时，被减数数组剩余的长度就是差
 */
type Subtract<A extends number, B extends number> =
  BuildArray<A> extends [...(infer _ extends any[]), ...BuildArray<B>]
    ? BuildArray<A> extends [...(infer Rest), ...BuildArray<B>]
      ? Rest['length']
      : never
    : never

// 简化版（更易理解的版本）:
type SubtractSimple<
  A extends number,
  B extends number,
  U extends any[] = [],
  V extends any[] = []
> =
  B extends 0
    ? A
    : A extends 0
      ? 0
      : U['length'] extends A
        ? V['length']  // A 个元素消耗完后，V 的长度 = B 被消耗的数量 = A - B? 不对...
        // 让我重新思考...

// 更清晰的减法实现
type Minus<
  A extends number,
  B extends number,
  U extends unknown[] = BuildArray<A>,
  V extends unknown[] = []
> =
  B extends 0
    ? V['length']
    : U extends [unknown, ...infer Rest]
      ? Minus<A, Exclude<B, B> & number extends 0 ? 0 : Decrement<B>, Rest, [...V, unknown]>
      : never

// 辅助：数字减 1（Decrement）
type Decrement<N extends number> =
  BuildArray<N> extends [any, ...infer Rest] ? Rest['length'] : 0

// 测试减法
type Diff1 = Subtract<5, 3>   // → 2
type Diff2 = Subtract<10, 4>  // → 6
type Diff3 = Subtract<3, 3>   // → 0

// 注意：不支持负数结果（因为数组长度不能为负）
```

### 3.4 比较运算

```typescript
// 判断相等
type Equals<A, B> = A extends B ? (B extends A ? true : false) : false

type Eq1 = Equals<3, 3>   // true
type Eq2 = Equals<2, 3>   // false

// 判断大于（GreaterThan）
type GreaterThan<
  A extends number,
  B extends number,
  U extends any[] = BuildArray<A>,
  V extends any[] = BuildArray<B>
> =
  V extends []  // B 已经减到 0 了，A 还有剩余 → A > B
    ? U extends []
      ? false   // 同时减到 0 → A == B
      : true    // B 先耗尽 → A > B
    : U extends []
      ? false   // A 先耗尽 → A < B
      : GreaterThan<A, B, DropFirst<U>, DropFirst<V>>  // 各自减 1 继续

type DropFirst<T extends any[]> = T extends [any, ...infer Rest] ? Rest : []

type GT1 = GreaterThan<5, 3>   // true
type GT2 = GreaterThan<3, 5>   // false
type GT3 = GreaterThan<5, 5>   // false
```

### 3.5 斐波那契数列

有了上面的基础设施，我们可以实现经典的斐波那契：

```typescript
/**
 * Fib<N> 计算 第 N 个斐波那契数
 * 
 * 定义: Fib(0)=0, Fib(1)=1, Fib(n)=Fib(n-1)+Fib(n-2)
 */
type Fib<
  N extends number,
  Memo extends { k: number; v: number }[] = [{ k: 0; v: 0 }, { k: 1; v: 1 }]
> =
  N extends 0
    ? 0
    : N extends 1
      ? 1
      : Memo extends [...infer _, { k: N; v: infer V }]
        ? V  // 在备忘录中找到了，直接返回
        : Memo extends [...infer Rest, { k: infer LastKey; v: infer LastVal }]
          ?
            // 计算下一个值
            Rest extends [...infer _, { k: infer PrevKey; v: infer PrevVal }]
              ? Fib<N, [...Memo, { k: Add<LastKey, 1>; v: Add<LastVal, PrevVal }> ]>
              : never
          : never

// 等等，这个实现过于复杂且可能有 bug。让我们用更清晰的方式：

// 简洁版斐波那契（使用元组累加）
type Fibonacci<
  N extends number,
  CurrentIdx extends unknown[] = [],
  Prev extends unknown[] = [],   // Fib(i-2) 表示为长度
  Curr extends unknown[] = [unknown]  // Fib(i-1) 表示为长度，初始化为 Fib(1)=1
> =
  CurrentIdx['length'] extends N
    ? Curr['length']  // 到达目标索引，返回当前值
    : Fibonacci<N, [...CurrentIdx, unknown], Curr, [...Prev, ...Curr]>
    // 下一步: Prev=Curr, Curr=Prev+Curr (即拼接两数组)

// 测试
type F0 = Fibonacci<0>   // → 0
type F1 = Fibonacci<1>   // → 1
type F2 = Fibonacci<2>   // → 1  (0+1)
type F3 = Fibonacci<3>   // → 2  (1+1)
type F4 = Fibonacci<4>   // → 3  (1+2)
type F5 = Fibonacci<5>   // → 5  (2+3)
type F6 = Fibonacci<6>   // → 8  (3+5)
type F10 = Fibonacci<10> // → 55
```

**执行追踪（Fibonacci<4>）**：

```
初始状态:  CurrentIdx=[],  Prev=[],  Curr=[*] (len=1)

i=0: CurrentIdx=[*],  Prev=[*](1),  Curr=[*,*](2)     ← 新Curr = Prev+Curr = 0+1 = 1
i=1: CurrentIdx=[*,*], Prev=[*,*](2), Curr=[*,*,*](3)  ← 新Curr = 1+1 = 2
i=2: CurrentIdx=[*,*,*], Prev=[*,*,*](3), Curr=[*,*,*,*](4) ← 新Curr = 1+2 = 3
i=3: CurrentIdx=[*,*,*,*] 长度=4 = N → 返回 Curr.length = 3 ✅

Fibonacci<4> = 3 ✓
```

## 四、字符串操作

### 4.1 字符串长度

```typescript
// 将字符串转为字符数组（元组），然后取长度
type StringToChars<S extends string> =
  S extends `${infer First}${infer Rest}`
    ? [First, ...StringToChars<Rest>]
    : []

type StringLength<S extends string> = StringToChars<S>['length']

type Len1 = StringLength<'hello'>   // → 5
type Len2 = StringLength<''>        // → 0
type Len3 = StringLength<TypeScript'>  // → 10
```

### 4.2 字符串反转

```typescript
type Reverse<S extends string> =
  S extends `${infer First}${infer Rest}`
    ? `${Reverse<Rest>}${First}`
    : S

type Rev1 = Reverse<'abc'>     // → "cba"
type Rev2 = Reverse<'hello'>   // → "olleh"
type Rev3 = Reverse<''>        // → ""
type Rev4 = Reverse<'racecar'> // → "racecar" （回文！）
```

### 4.3 字符串替换

```typescript
type Replace<
  S extends string,
  From extends string,
  To extends string
> =
  From extends ''
    ? S
    : S extends `${infer Start}${From}${infer End}`
      ? `${Start}${To}${Replace<End, From, To>}`
      : S

type R1 = Replace<'foobar', 'bar', 'baz'>  // → "foobaz"
type R2 = Replace<'abcabc', 'bc', 'x'>     // → "axaxc"
type R3 = Replace<'hello', 'xyz', '123'>   // → "hello" (无匹配则不变)
```

### 4.4 字符串分割

```typescript
type Split<
  S extends string,
  Delim extends string
> =
  S extends `${infer Part}${Delim}${infer Rest}`
    ? [Part, ...Split<Rest, Delim>]
    : [S]

type Parts = Split<'a-b-c-d', '-'>
// → ["a", "b", "c", "d"]

type URLParts = Split<'https://example.com/api/users', '/'>
// → ["https:", "example.com", "api", "users"]
```

### 4.5 字符串转数字

```typescript
// 数字字符到数字的映射
type DigitMap = {
  '0': []; '1': [any]; '2': [any, any]; '3': [any, any, any];
  '4': [any, any, any, any]; '5': [any, any, any, any, any];
  '6': [any, any, any, any, any, any]; '7': [any, any, any, any, any, any, any];
  '8': [any, any, any, any, any, any, any, any];
  '9': [any, any, any, any, any, any, any, any, any];
}

type ToDigit<D extends keyof DigitMap> = DigitMap[D]['length']

type StringToNumber<S extends string> =
  S extends `${infer D extends keyof DigitMap}${infer Rest}`
    ? Add<Mul<ToDigit<D>, PowerOf10<StringLength<Rest>>>, StringToNumber<Rest>>
    : 0

// （PowerOf10 和 Mul 的实现留作练习，或参见进阶章节）
```

## 五、条件类型的分布式行为

这是一个极其重要的高级特性，理解它能解开很多困惑：

### 5.1 什么是分布式？

当条件类型的**被检测参数是一个裸类型参数（naked type parameter）**时，联合类型会被**分发**（distribute）到条件的每个成员上：

```typescript
// 裸类型参数 = 直接是 T，没有被数组/元组/Promise 等包裹
type ToArray<T> = T[]

// 当传入联合类型时，会发生分布式行为：
type Result = ToArray<string | number>
// → string[] | number[]  （不是 (string | number)[]！）

// 等价于：
// ToArray<string> | ToArray<number>
// → string[] | number[]
```

**对比：包裹后的参数不会触发分布**：

```typescript
// T 被 [] 包裹了 → 不是裸类型参数 → 不分发
type WrappedToArray<T> = [T][]

type Result2 = WrappedToArray<string | number>
// → (string | number)[]   （整体作为一个数组元素的类型）

// T 被 Promise 包裹 → 不分发
type Promised<T> = Promise<T>

type Result3 = Promised<string | number>
// → Promise<string | number>   （整体放在 Promise 里）
```

### 5.2 分布式的实际应用

**过滤 Never**：

```typescript
// 联合类型中的 never 会自动消失
type NeverGone<T> = T extends never ? true : false

type Test = NeverGone<string | never>
// → NeverGone<string> | NeverGone<never>
// → true | never
// → true （never 被吸收了）

// 这就是为什么 Exclude<T, U> 可以过滤掉某些类型：
// type Exclude<T, U> = T extends U ? never : T
```

**Extract 提取满足条件的类型**：

```typescript
type Extract<T, U> = T extends U ? T : never

// 只提取函数类型
type OnlyFunctions<T> = Extract<T, Function>

type Mixed = string | number | (() => void) | { run(): void }
type FunctionsOnly = OnlyFunctions<Mixed>
// → (() => void) | { run(): void }

// 只提取具有某属性的类型
type WithName<T> = Extract<T, { name: any }>

type Named = WithName<{ name: string } | { age: number } | { name: string; age: number }>
// → { name: string } | { name: string; age: number }
```

**禁止分发的技巧**：

```typescript
// 如果不想让分布式发生，把参数包裹在元组中
type NoDistribute<T> = [T] extends [U] ? ... : ...

// 或者在 T 上交叉任意类型
type Identity<T> = T & {}
type NoDist<T> = (Identity<T>) extends U ? X : Y
```

## 六、综合案例：微型类型级解析器

### 6.1 JSON Parser（类型级别）

```typescript
// 一个极度简化的 JSON 类型解析器（仅演示概念）

// 空白字符
type Whitespace = ' ' | '\n' | '\t' | '\r'

// 去除首尾空白
type Trim<S extends string> =
  S extends `${Whitespace}${infer Rest}` ? Trim<Rest> :
  S extends `${infer Rest}${Whitespace}` ? Trim<Rest> :
  S

// 解析字符串字面量
type ParseStringLiteral<S extends string> =
  S extends `"${infer Content}"`
    ? ParseEscaped<Content>
    : never

type ParseEscaped<S extends string> =
  S extends '' ? '' :
  S extends `\\${infer C}${infer Rest}`
    ? C extends 'n' ? `\n${ParseEscaped<Rest>}>` :
      C extends 't' ? `\t${ParseEscaped<Rest>}>` :
      `${C}${ParseEscaped<Rest>}}`
    : S extends `${infer C}${infer Rest}` ? `${C}${ParseEscaped<Rest>}>` :
    ''

// 解析数字
type ParseNumber<S extends string> =
  S extends `${infer N extends number}` ? N : never

// 解析 JSON 值
type ParseJSON<S extends string> =
  Trim<S> extends `{${infer ObjContent}}` ? ParseObject<ObjContent> :
  Trim<S> extends `[${infer ArrContent}]` ? ParseArray<ArrContent> :
  Trim<S> extends ParseStringLiteral<infer Str> ? Str :
  Trim<S> extends ParseNumber<infer Num> ? Num :
  Trim<S> extends 'true' ? true :
  Trim<S> extends 'false' ? false :
  Trim<S> extends 'null' ? null :
  never

// （ParseObject 和 ParseArray 的完整实现非常复杂，这里省略）
```

### 6.2 路径参数提取器

```typescript
/**
 * 从 Express/Koa 风格的路由路径中提取参数类型
 */
type ExtractPathParams<Path extends string> =
  Path extends `${string}:${infer Param}/${infer Rest}`
    ? Param | ExtractPathParams<`/${Rest}`>
    : Path extends `${string}:${infer Param}`
      ? Param
      : never

// 测试
type UserPathParams = ExtractPathParams<'/users/:userId/posts/:postId/comments/:commentId'>
// → 'userId' | 'postId' | 'commentId'

type SimplePath = ExtractPathParams<'/about'>
// → never （没有参数）
```

### 6.3 CSS 单位解析器

```typescript
type CSSToken =
  | 'px' | 'rem' | 'em' | '%' | 'vw' | 'vh'
  | 'deg' | 'rad' | 's' | 'ms'
  | 'fr'

type ParseCSSValue<S extends string> =
  S extends `${infer Num extends number}${infer Unit extends CSSToken}`
    ? { value: Num; unit: Unit }
    : S extends `${infer Value}`
      ? { value: Value; unit: 'unknown' }
      : never

type Size1 = ParseCSSValue<'16px'>    // { value: 16; unit: 'px' }
type Size2 = ParseCSSValue<'100%'>    // { value: 100; unit: '%' }
type Size3 = ParseCSSValue<'1.5rem'>  // { value: 1.5; unit: 'rem' }
type Size4 = ParseCSSValue<'90deg'>   // { value: 90; unit: 'deg' }
```

## 七、实用工具类型集

### 7.1 深层操作

```typescript
// DeepPartial —— 递归将所有嵌套字段变为可选
type DeepPartial<T> = {
  [P in keyof T]?: T[P] extends object ? DeepPartial<T[P]> : T[P]
}

// DeepRequired —— 递归将所有嵌套字段变为必填
type DeepRequired<T> = {
  [P in keyof T]-?: Required<DeepRequired<T[P]>>
}

// DeepReadonly —— 递归只读
type DeepReadonly<T> = {
  readonly [P in keyof T]: T[P] extends object ? DeepReadonly<T[P]> : T[P]
}

// DeepWritable —— 取消只读
type DeepWritable<T> = {
  -readonly [P in keyof T]: T[P] extends object ? DeepWritable<T[P]> : T[P]
}
```

### 7.2 集合操作

```typescript
// UnionToIntersection —— 联合类型转交集类型
type UnionToIntersection<U> =
  (U extends any ? (k: U) => void : never) extends ((k: infer I) => void) ? I : never

type UI = UnionToIntersection<{ a: string } | { b: number }>
// → { a: string } & { b: number }

// LastOf —— 获取联合类型的最后一个成员
type LastOf<T> = UnionToIntersection<T extends any ? () => T : never> extends () => infer R ? R : never

// UnionToArray —— 联合类型转元组（保持顺序）
type UnionToArray<T, L = LastOf<T>> = [T] extends [never]
  ? []
  : [...UnionToArray<Exclude<T, L>>, L]
```

### 7.3 函数工具

```typescript
// If —— 类型级的 if
type If<C extends boolean, T, F> = C extends true ? T : F

// IsNever —— 判断是否是 never
type IsNever<T> = [T] extends [never] ? true : false

// IsAny —— 判断是否是 any
type IsAny<T> = 0 extends 1 & T ? true : false

// IsUnion —— 判断是否是联合类型
type IsUnion<T, U = T> = T extends any ? ([U] extends [T] ? false : true) : false
```

## 八、性能优化与限制

### 8.1 编译性能考量

```
⚠️ 类型编程的性能陷阱:

1. 递归深度限制（通常 50~1000 层）
   → 超过限制报: "Type instantiation is excessively deep and possibly infinite."
   
2. 联合类型成员数量限制（约 100,000 个）
   → 超过可能导致编译器变慢或崩溃
   
3. 条件类型嵌套复杂度
   → 每一层条件都会增加类型检查的计算量
   
4. 大量的 infer 声明
   → 每个 infer 都需要额外的模式匹配计算

优化策略:
✓ 使用尾递归（尽量让递归调用是最后一个操作）
✓ 预计算并缓存中间结果（用元组/对象存储）
✓ 避免不必要的联合类型展开
✓ 对于特别深的递归，考虑分阶段计算
✓ 使用 @ts-expect-error 跳过已知正确的复杂类型检查
```

### 8.2 调试技巧

```typescript
// 技巧 1：用辅助类型查看中间结果

```

## 总结

类型编程是 TypeScript 最迷人也最具挑战性的领域：

**第一层：基础构件** —— 字面量类型（数据）、条件类型（分支）、infer（变量绑定）、映射类型（循环）、模板字面量（字符串操作）、递归（循环）。

**第二层：算术与逻辑** —— 通过元组长度表示自然数，实现加减乘除、比较大小、斐波那契等经典算法。

**第三层：字符串处理** —— 利用模板字面量类型的模式匹配能力，实现反转、替换、分割、解析等操作。

**第四层：工程实践** —— DeepPartial/DeepReadonly 等深层工具类型、联合类型的集合操作、分布式行为的运用与规避、性能优化与调试技巧。

**思维转变**：类型编程要求你换一种思维方式。不再是"写代码让它运行"，而是"定义规则让编译器帮你推理"。这种能力一旦掌握，你就拥有了一把瑞士军刀——可以在编译期完成大量原本需要在运行时做的工作，从而让程序更安全、更高效、更易于维护。

> **一句话总结**：类型编程 = 用类型系统本身作为编程语言。它的输入是类型，输出也是类型，而"运行环境"就是 TypeScript 编译器。学会它，你就是真正的 TypeScript 大师。
