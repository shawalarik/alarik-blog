# 递归类型与尾递归优化 —— 处理深度递归、TS 中的递归限制

> **核心问题**：TypeScript 的类型系统通过"递归"来实现循环。但递归有深度限制——超过约 50~1000 层就会报 "Type instantiation is excessively deep" 错误。如何写出高效的递归类型？如何优化避免栈溢出？本章深入探讨 TS 递归类型的艺术与工程实践。

---

## 一、为什么需要递归类型？

### 1.1 TS 类型系统没有循环结构

TypeScript 的类型系统**没有 for 循环、没有 while 循环、没有 do-while**。唯一能实现"重复操作"的方式就是**递归**：

```
值编程中的循环          类型编程中的等价物
═══════════            ═══════════════════

for (let i=0; i<n; i++)   type BuildArray<N, T=[]> =
{                             T['length'] extends N ? T : BuildArray<N, [...T, any]
  // do something           }

while (condition)         type While<Cond, Acc> =
{                             Cond extends true ?
  // do something             ? { result: Acc } : While<Cond, Next<Acc>>
}

for (const x of arr)     type ForEach<A extends any[], Fn> =
{                             A extends [infer F, ...infer R]
  process(x)               ? [Fn<F>, ...ForEach<R, Fn>] : []
}
```

### 1.2 一个直观的例子：数组长度

```typescript
// 问题：如何获取数字字面量 N 对应的长度为 N 的元组？

// 答案：递归！
type BuildArray<
  N extends number,       // 目标长度
  T extends unknown[] = [] // 当前累积的数组（初始为空）
> = 
  T['length'] extends N    // 基准条件：当前长度是否达到目标？
    ? T                    // 是 → 返回结果
    : BuildArray<N, [...T, unknown]>  // 否 → 追加一个元素，继续递归

// 使用
type Len3 = BuildArray<3>
// 展开追踪:
// BuildArray<3, []>        length=0 ≠ 3 → 继续
// BuildArray<3, [?]>       length=1 ≠ 3 → 继续  
// BuildArray<3, [?, ?]>    length=2 ≠ 3 → 继续
// BuildArray<3, [?, ?, ?]> length=3 = 3 ✅ 返回 [?, ?, ?]

// 结果: [unknown, unknown, unknown] —— 长度为 3 的元组
```

### 1.3 递归的三要素

每个正确的递归类型都必须具备三个要素：

```typescript
/**
 * ═══ 递归三要素 ═══
 *
 * ① 基准条件 (Base Case)
 *    → 何时停止递归？没有基准条件 = 无限递归 = 编译器崩溃
 *
 * ② 递归步骤 (Recursive Step)  
 *    → 每一步如何推进问题规模？
 *    必须确保每次调用都更接近基准条件
 *
 * ③ 收敛保证 (Convergence)
 *    → 递归是否一定会在有限步内到达基准条件？
 */

// 示例：计算数组元素数量（不用 .length）
type Count<T extends unknown[]> =
  T extends []              // ① 基准条件：空数组，计数为 0
    ? 0
    : T extends [unknown, ...infer Rest]  // ② 递归步骤：去掉头部
      ? Count<Rest> extends infer C      //   计数剩余部分
        ? C extends number 
          ? 1 + C                         //   +1（加上被去掉的那个）
          : never
        : never
      : never

// 测试
type C1 = Count<[1,2,3]>
// Count<[1,2,3]> → Count<[2,3]> + 1 → Count<[3]> + 1 + 1 → Count<()> + 1 + 1 + 1 → 3

type C2 = Count<[]>
// 直接命中基准条件 → 0
```

## 二、常见递归模式

### 2.1 列表遍历（最基础）

```typescript
// Map：对每个元素做变换
type Map<T extends any[], F> =
  T extends [infer First, ...infer Rest]
    ? [F<First>, ...Map<Rest, F>]
    : []

type Double<T> = T extends number ? T * 2 : never
type Mapped = Map<[1, 2, 3], Double>  // [2, 4, 6]


// Filter：过滤满足条件的元素
type Filter<T extends any[], Cond> =
  T extends [infer First, ...infer Rest]
    ? First extends Cond
      ? [First, ...Filter<Rest, Cond>]
      : Filter<Rest, Cond>
    : []

type IsString<T> = T extends string ? T : never
type Filtered = Filter<[1, 'a', 2, 'b', true], string>
// → ['a', 'b']


// Find：查找第一个满足条件的元素
type Find<T extends any[], Cond> =
  T extends [infer First, ...infer _]
    ? First extends Cond
      ? First
      : Find<T extends [any, ...infer Rest] ? Rest : [], Cond>
    : never

type Found = Find<[1, 'hello', 3, 'world'], string>
// → "hello"


// Reduce：折叠/归约
type Reduce<T extends any[], Init, Fn> =
  T extends [infer First, ...infer Rest>
    ? Reduce<Rest, Fn<Init, First>, Fn>
    : Init

// 需要先定义 Add（加法）和 Mul（乘法）工具
// （假设已有实现）
type Sum = Reduce<[1, 2, 3, 4, 5], 0, Add>
// Add(Add(Add(Add(0,1),2),3),4) → 15


// Every：是否所有元素都满足条件
type Every<T extends any[], Cond> =
  T extends [infer First, ...infer Rest]
    ? First extends Cond
      ? Every<Rest, Cond>
      : false  // 只要有一个不满足就是 false
    : true    // 全部检查完毕，都满足

type AllStrings = Every<['a', 'b', 'c'], string>  // true
type NotAllNums = Every<[1, 'x', 3], number>      // false


// Some：是否有任意元素满足条件
type Some<T extends any[], Cond> =
  T extends [infer First, ...infer Rest>
    ? First extends Cond
      ? true   // 找到一个就够了
      : Some<Rest, Cond>
    : false   // 全部检查完毕都没找到

type HasString = Some<[1, 2, 'three'], string>  // true
type NoBool = Some<[1, 2, 3], boolean>          // false
```

### 2.2 树形结构操作

```typescript
// 定义一棵二叉树
interface TreeNode<T> {
  value: T
  left?: TreeNode<T>
  right?: TreeNode<T>
}

// 深度优先搜索收集所有值（中序遍历）
type InOrderValues<T> =
  T extends TreeNode<infer V>
    ? [
        ...(T['left'] extends TreeNode<any> ? InOrderValues<T['left']> : []),
        V,
        ...(T['right'] extends TreeNode<any> ? InOrderValues<T['right']> : [])
      ]
    : []

// 测试
const tree: TreeNode<number> = {
  value: 4,
  left: {
    value: 2,
    left: { value: 1 },
    right: { value: 3 },
  },
  right: {
    value: 6,
    left: { value: 5 },
    right: { value: 7 },
  },
}

type Values = InOrderValues<typeof tree>
// → [1, 2, 3, 4, 5, 6, 7]  （中序遍历结果）


// 获取树的最大深度
type TreeDepth<T> =
  T extends TreeNode<any>
    ? T['left'] extends TreeNode<any>
      ? T['right'] extends TreeNode<any>
        ? 1 + Max<TreeDepth<T['left']>, TreeDepth<T['right']>>
        : 1 + TreeDepth<T['left']>
      : T['right'] extends TreeNode<any>
        ? 1 + TreeDepth<T['right']>
        : 1
    : 0

type Depth = TreeDepth<typeof tree>
// 左子树深度 2, 右子树深度 2 → 1 + max(2, 2) = 3
```

### 2.3 对象深层操作

```typescript
// DeepPick —— 从深层嵌套对象中选取路径指定的字段
type DeepPick<T, Paths extends string> =
 Paths extends `${infer Key}.${infer Rest}`
	? Key extends keyof T
		? { [K in Key]: DeepPick<T[K], Rest> }
		: never
	: Paths extends keyof T
		? { [K in Paths]: T[K] }
	: never

// 扁平化合并多个 DeepPick
type MergeDeepPicks<T, P extends string> =
	P extends `${infer Head},${infer Tail}`
		? DeepMerge<DeepPick<T, Head>, MergeDeepPicks<T, Tail>>
		: DeepPick<T, P>

// 辅助：深度合并两个对象类型
type DeepMerge<A, B> =
	A & B extends infer O
	? { [K in keyof O]: O[K] }
	: never

// 测试
type User = {
	id: number
	name: string
	profile: {
		avatar: string
		bio: string
		settings: {
			theme: 'light' | 'dark'
			notifications: boolean
		}
	}
	posts: {
		id: number
		title: string
		content: string
	}[]
}

type Selected = DeepPick<User, 'id|name,profile.avatar,profile.settings.theme'>
// → {
//     id: number;
//     name: string;
//     profile: { avatar: string };
//   }


// DeepOmit —— 深层排除字段
type DeepOmit<T, Paths extends string> =
	T extends object
		? {
				[P in keyof T as Exclude<P, Paths>]: T[P] extends object
					? DeepOmit<T[P], ExtractAfterDot<Paths, P>>
					: T[P]
			}
		: T

// （ExtractAfterDot 的实现略）
```

### 2.4 字符串递归处理

```typescript
// Split —— 分割字符串（完整版，支持多字符分隔符）
type Split<S extends string, Delim extends string, Acc extends string[] = []> =
	S extends ''
		? [...Acc, '']
		: S extends `${infer Part}${Delim}${infer Rest}`
			? Split<Rest, Delim, [...Acc, Part]>
			: [...Acc, S]

type Parts = Split<'apple/banana/cherry', '/'>
// → ['apple', 'banana', 'cherry']

// Join —— 连接字符串数组
type Join<T extends string[], Sep extends string = ''> =
	T extends [infer First extends string, ...infer Rest extends string[]]
		? Rest extends []
			? First
			: `${First}${Sep}${Join<Rest, Sep>}`
		: ''

type Joined = Join<['Hello', 'World', '!'], ' '>
// → "Hello World !"


// ReplaceAll —— 替换所有匹配（非贪婪版）
type ReplaceAll<S, From extends string, To extends string> =
	From extends ''
		? S
		: S extends `${infer Start}${From}${infer Rest}`
			? `${Start}${To}${ReplaceAll<Rest, From, To>}`
			: S

type Replaced = ReplaceAll<'ababababa', 'ab', 'cd'>
// → "cdcdcdcda"


// CamelCase —— 将 kebab-case / snake_case 转 camelCase
type CamelCase<S extends string> =
	S extends `${infer First}-${infer Rest}`
		? `${First}${Capitalize<CamelCase<Rest>>}`
		: S extends `${infer First}_${infer Rest}`
			? `${First}${Capitalize<CamelCase<Rest>>}`
			: S

type Camel1 = CamelCase<'my-variable-name'>
// → "myVariableName"
type Camel2 = CamelCase<'my_variable_name'>
// → "myVariableName"
```

## 三、TS 递归的限制

### 3.1 递归深度限制

TypeScript 编译器对递归深度有内部限制：

```
╔════════════════════════════════════════════════════════╗
║                                                      ║
║   TS 递归深度限制                                     ║
║   ─────────────────                                   ║
║                                                      ║
║   • 官方文档未明确说明确切数值                        ║
║   • 经验数据:                                        ║
║     - 简单递归: ~50 ~1000 层                        ║
║     - 条件类型嵌套: ~50 层                           ║
║     - 联合类型展开: 受具体场景影响                   ║
║                                                      ║
║   错误信息:                                          ║
║   "Type instantiation is excessively deep and        ║
║    possibly infinite."                               ║
║                                                      ║
║   或:                                                 ║
║   "Excessive stack depth comparing types..."          ║
║                                                      ║
╚══════════════════════════════════════════════════════╝
```

### 3.2 触发限制的实际例子

```typescript
// 这个简单的递归在 N=50 时就可能出错
type CountUpTo<
	N extends number,
	Current extends unknown[] = []> =
	Current['length'] extends N
		? Current['length']
		: CountUpTo<N, [...Current, unknown]>

type Small = CountUpTo<20>   // ✅ 正常工作
type Medium = CountUpTo<45>  // ⚠️ 可能接近极限
type Large = CountUpTo<100>  // ❌ "Type instantiation is excessively deep!"
```

### 3.3 为什么会有这个限制？

```
原因分析:

1. 编译器使用栈来跟踪类型实例化过程
   → 每一层递归都会压入新的栈帧
   → 栈空间是有限的

2. 无限递归检测
   → 如果编译器不设限，一个错误的无限递归会导致编译器挂起
   → 设置上限是一种安全保护

3. 性能考量
   → 过深的递归会显著增加编译时间
   → 限制深度可以保持合理的编译速度
```

## 四、尾递归优化

### 4.1 什么是尾递归？

**尾递归（Tail Recursion）**是指：递归调用是函数的**最后一个操作**。这意味着不需要保留当前的栈帧来做后续操作。

```typescript
// ═══ 非 尾递归 ═══
// 递归调用后还需要执行其他操作（+1），所以不是尾递归
type Length_NonTail<T extends unknown[]> =
	T extends [unknown, ...infer Rest>
		? 1 + Length_NonTail<Rest>  // ← 递归调用后面还有 "+1"
		: 0

// 展开时每一层都需要记住 "+1" 操作：
// Length([a,b,c]) = 1 + Length([b,c]) = 1 + (1 + Length([c])) = 1+(1+(1+Length([]))) = 1+(1+(1+0))


// ═══ 尾递归形式 ═══
// 使用累加器（accumulator）存储中间结果，递归调用是最后一步
type Length_Tail<
	T extends unknown[],
	Acc extends number = 0    // ← 累加器
> =
	T extends []
		? Acc                    // ← 基准条件直接返回累加器
		: T extends [unknown, ...infer Rest]
			? Length_Tail<Rest, Incr<Acc>>  // ← 递归调用是最后操作
			: never

// Incr 是数字 +1 的辅助类型（假设已有实现）

// 展开：每一步都不需要"记住"什么
// Length_Tail([a,b,c], 0) → Length_Tail([b,c], 1) → Length_Tail([c], 2) → Length_Tail([], 3) → 3
```

### 4.2 TS 中尾递归真的有效吗？

**残酷的现实：TypeScript 编译器目前不做尾调用优化（TCO）。**

但尾递归形式仍然有价值：

```
尾递归在 TS 中的实际效果:

❌ 不会减少内存占用（编译器不优化）
✅ 代码更清晰易读
✅ 更容易转换为迭代式写法
✅ 某些场景下确实能减少展开层数（当问题本身允许时）
⚠️ 但对于纯类型层面的递归深度限制，帮助有限
```

### 4.3 真正有效的优化策略

#### 策略一：分治法（Divide and Conquer）

```typescript
// 不用线性递归 O(n)，而是用对数递归 O(log n)

// 传统线性递归 —— O(N) 层深度
type SumLinear<N extends number> =
	N extends 0 ? 0 : Add<SumLinear<Decrement<N>>, 1>
// SumLinear<1000> 需要 1000 层 → 💥 超限！

// 对数递归 —— O(log N) 层深度
// 思想: 把范围 [0,N] 二分，分别求左右两半的和
type SumLog<
	Start extends number,
	End extends number
> =
	Start extends End
		? Start
		: GreaterThan<Subtract<End, Start>, 1> extends true
			? Add<
					SumLog<Start, Middle<Start, End>>,
					SumLog<Inc<Middle<Start, End>>, End>
				>
			: Add<Start, End>

// SumLog<0, 1000> 只需要约 log2(1000) ≈ 10 层深度！✅
```

#### 策略二：批处理（Chunking / Batching）

```typescript
// 一次处理一批而不是单个元素

type BatchSize = 10  // 每批处理 10 个

// 分批构建数组
type BatchBuildArray<
	N extends number,
	Current extends unknown[] = [],
	Batch extends unknown[] = []  // 当前批次
> =
	Current['length'] extends N
		? Current
		: Batch['length'] extends BatchSize
			// 当前批次满了 → 合并入 Current 并开始新批次
			? BatchBuildArray<N, [...Current, ...Batch], []>
			// 当前批次未满 → 继续填充
			: BatchBuildArray<N, Current, [...Batch, unknown]>

// 效果：每 10 个元素才增加一层递归
// 对于 N=1000，只需要约 100 层而非 1000 层
```

#### 策略三：查表法（Memoization / Lookup Table）

```typescript
// 预先计算并存储常用值

// 斐波那契数列查表
type FibTable = {
	0: 0; 1: 1; 2: 1; 3: 2; 4: 3; 5: 5; 6: 8; 7: 13; 8: 21; 9: 34;
	10: 55; 11: 89; 12: 144; 13: 233; 14: 377; 15: 610;
	16: 987; 17: 1597; 18: 2584; 19: 4181; 20: 6765;
}

// 先查表，找不到再用递归（适用于小范围）
type FastFib<N extends number> =
	N extends keyof FibTable
		? FibTable[N]
		: N extends 0
			? 0
			: N extends 1
				? 1
				: Add<FastFib<Decrement<N>>, FastFib<Decrement<Decrement<N>>>>
```

#### 策略四：类型擦除与运行时回退

```typescript
// 当类型编程太复杂时，优雅地降级到 any

// 安全的类型包装器
type Safe<T, Fallback = unknown> =
	[T] extends [never]  // 检测是否计算失败（变成 never）
		? Fallback
		: T

// 在复杂类型中使用
type ComplexComputation<Input> =
	// ... 大量递归类型运算 ...
	// 如果失败就返回原始输入
	Safe<ActualResult<Input>, Input>


// 或者使用 @ts-expect-error 抑制已知正确的复杂类型错误
type KnownCorrectComplexType<T> =
	// ... 复杂但已知正确的类型推导 ...
	// @ts-expect-error 已验证正确，抑制深度警告
	T extends any ? Result : never
```

## 五、高级技巧

### 5.1 互递归（Mutual Recursion）

两个或更多类型互相调用对方的场景：

```typescript
// 判断奇偶性（经典互递归示例）
type IsOdd<N extends number> =
	N extends 0 ? false : IsEven<Decrement<N>>

type IsEven<N extends number> =
	N extends 0 ? true : IsOdd<Decrement<N>>

type Odd3 = IsOdd<3>  // true  → IsEven<2> → IsOdd<1> → IsEven<0> → true
type Even4 = IsEven<4> // true  → IsOdd<3> → IsEven<2> → IsOdd<1> → IsEven<0> → true
```

### 5.2 Y 组合子（Y Combinator）

将递归转化为非递归的高阶抽象（理论上的优雅方案）：

```typescript
// Y 组合子的类型级实现（概念演示）
type Y<F> = F extends (f: (x: infer A) => infer B) => (x: A) => B
	? (x: A) => B
	: never

// 实际上在 TS 类型系统中，Y 组合子并不能绕过递归深度限制
// 因为类型系统的本质仍然是基于替换的求值模型
// 这里仅作为概念展示
```

### 5.3 惰性求值模拟

```typescript
// 通过条件延迟计算，只在真正需要时才展开
type Lazy<T> = () => T  // 包装为函数类型以延迟求值

// 使用时强制求值
type Force<L> = L extends () => infer T ? T : never

// 应用：延迟构建大型元组
type LazyBuild<N extends number> =
	N extends 0 ? [] : (() => [...LazyBuild<Decrement<N>>, unknown])

// 只有在访问时才真正展开
type Forced = Force<LazyBuild<5>>  // 此时才触发完整计算
```

### 6.2 JSON Schema 类型生成器（简化版）

```typescript
// 从简化的 JSON Schema 定义生成 TypeScript 类型
type FromSchema<S> =
	S extends { type: 'string' }
		? string
		: S extends { type: 'number' }

			: S extends { type: 'boolean' }
				? boolean
				: S extends { type: 'array'; items: infer Items }
					? FromSchema<Items>[]
					: S extends { type: 'object'; properties: infer Props }
						? { [K in keyof Props]: FromSchema<Props[K]> }
						: S extends { enum: infer E extends (string | number | boolean | null)[] }
							? E[number]
							: any

// 使用
type UserSchema = {
	type: 'object'
	properties: {
		name: { type: 'string' }
		age: { type: 'number' }
		active: { type: 'boolean' }
		role: { enum: ['admin', 'user', 'guest'] }
		tags: { type: 'array'; items: { type: 'string' } }
	}
}

type UserType = FromSchema<UserSchema>
// → {
//     name: string;
//     age: number;
//     active: boolean;
//     role: 'admin' | 'user' | 'guest';
//     tags: string[];
//   }
```

## 七、调试递归类型

### 7.1 常见错误及诊断

```
错误 1: "Type instantiation is excessively deep and possibly infinite"
─────────────────────────────────────────────────────────────
原因: 递归无法收敛（缺少或不正确的基准条件）
诊断: 
  • 检查每次递归调用是否真的让参数向基准条件靠近
  • 打印每一步的中间状态
  • 确认不存在"反向递归"（参数变大而非变小）

错误 2: "Excessive stack depth comparing types"
─────────────────────────────────────────────────────
原因: 类型比较时的深度超限（通常涉及交叉类型或条件类型嵌套）
诊断:
  • 简化比较逻辑
  • 用辅助类型拆分步骤
  • 减少联合类型的成员数量

错误 3: 计算结果为 never 但期望不是
─────────────────────────────────────────────────────
原因: 某个条件分支走到了 never
诊断:
  • 逐层检查每个条件判断
  • 确认 infer 匹配是否如预期
  • 注意 never 在联合类型中被吸收的特性
```

### 7.2 可视化调试工具类型

```typescript
// 调试辅助：显示当前状态
type Trace<V, H extends string = ''> =
	{ __trace__: H; __value__: V }

// 使用：包裹你想查看的类型
type DebugStep1 = Trace<SomeComplexType, 'Step 1 after map'>
// hover over DebugStep1 可以看到当前状态

// 逐步追踪
type Step1 = Transform1<Input>
type Debug1 = Trace<Step1, 'after step 1'>

type Step2 = Transform2<Step1>
type Debug2 = Trace<Step2, 'after step 2'>

// 如果某步输出异常就能精确定位
```

## 总结

递归类型是类型编程的核心机制之一：

**第一层：理解本质** —— TS 类型系统没有循环结构，递归是实现重复的唯一方式。掌握基准条件、递归步骤、收敛保证三要素。

**第二层：常见模式** —— 列表遍历（Map/Filter/Find/Reduce/Every/Some）、树形结构操作（DFS/BFS/深度计算）、对象深层操作（DeepPick/DeepOmit）、字符串递归处理。

**第三层：理解限制** —— TS 有递归深度限制（~50~1000 层），超出时报错。了解限制的原因和表现形式。

**第四层：优化策略** —— 尾递归形式化、分治法降低复杂度、批处理减少层级、查表法预存结果、类型擦除优雅降级、惰性求值延迟计算。

**终极建议**：不要为了炫技而写过度复杂的递归类型。好的类型代码应该像好的值代码一样——清晰、可维护、在必要时有注释解释思路。能用简单方法解决的就不要上重型递归。
