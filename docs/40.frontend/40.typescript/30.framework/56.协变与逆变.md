# 协变与逆变 —— 函数参数的反变、返回值的协变、in/out 标注

> **核心问题**：为什么 `Dog[]` 可以赋值给 `Animal[]`，但 `(dog: Dog) => void` 不能赋值给 `(animal: Animal) => void`？反过来却可以？这就是**型变（Variance）**的问题——它决定了父子类型关系如何在复合类型中传递。理解它是深入 TypeScript（以及 Java、C#、Scala 等）类型系统的关键。

---

## 一、从直觉开始：什么是型变？

### 1.1 生活类比：容器的继承关系

假设有一个动物 hierarchy：

```
                Animal (动物)
               /       \
              /         \
           Dog (狗)    Cat (猫)
             |
         Husky (哈士奇)
```

**基本规则**：Husky 是一种 Dog，Dog 是一种 Animal。这叫**子类型化（Subtyping）**。

现在的问题是：**装 Husky 的容器，是不是也是装 Animal 的容器？**

```
┌──────────────────────────────────────────────────────────┐
│                                                          │
│   场景 1：只读容器（笼子上的观察窗）                       │
│   ═══════════════════════════════                        │
│                                                          │
│   你有一笼子哈士奇                                       │
│   通过观察窗只能看里面的狗                                │
│                                                          │
│   有人问："我能把它当成'一笼动物'来看吗？"                 │
│   回答：当然可以！因为哈士奇本身就是动物                   │
│                                                          │
│   Dog[] ⊆ Animal[]  ✓  协变（Covariance）                │
│                                                          │
├──────────────────────────────────────────────────────────┤
│                                                          │
│   场景 2：只写容器（空的投喂口）                           │
│   ═══════════════════════════════                        │
│                                                          │
│   你有一个标着"请投喂动物"的入口                          │
│   任何动物都能放进去                                      │
│                                                          │
│   有人问："我能把这个入口当成'只接受狗'的吗？"             │
│   回答：不行！万一有人塞进来一只猫怎么办？                  │
│   但是反过来：如果入口只接受狗，那它肯定也接受动物吗？       │
│         也不行！如果要求必须放狗，你放一只普通动物不行！     │
│                                                          │
│   反过来想：                                            │
│   "接受一切动物的入口" 是否可以当作 "接受狗的入口"？        │
│   不行！因为入口可能收到猫。                              │
│                                                          │
│   "接受狗的入口" 是否可以当作 "接受 Husky 的入口"？        │
│   可以！因为所有放入的东西都是狗，而 Husky 就是狗。        │
│                                                          │
│   这就是逆变（Contravariance）！                          │
│   关系反转了：Container<Dog> ⊇ Container<Animal>          │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

### 1.2 三种型变

| 型变类型 | 符号 | 含义 | 例子 |
|---------|------|------|------|
| **协变（Covariant）** | `→` 保持方向 | 子类型关系**不变** | `Dog[]` → `Animal[]` ✅ |
| **逆变（Contravariant）** | `←` 反转方向 | 子类型关系**反转** | `((d: Dog) => void)` ← `((a: Animal) => void)` |
| **不变（Invariant）** | `≡` 双向要求 | 同时要求协变+逆变 | 双向都不自动成立 |

## 二、协变（Covariance）

### 2.1 定义

如果 `A 是 B 的子类型`，那么 `Container<A>` 也是 `Container<B>` 的子类型。**子类型关系方向相同**。

### 2.2 TypeScript 中的协变位置

#### 数组和只读属性

```typescript
class Animal {
  name: string = 'animal'
}

class Dog extends Animal {
  bark() { console.log('woof!') }
}

class Husky extends Dog {
  pullSled() { console.log('mushing!') }
}


// ═══ 数组（默认协变）═══
const huskies: Husky[] = [new Husky(), new Husky()]

// ✅ 协变：Husky[] 可以赋值给 Dog[] 和 Animal[]
const dogs: Dog[] = huskies
const animals: Animal[] = huskys

// 为什么安全？因为我们只会从数组中读取
const animal = animals[0]
// animal 的类型是 Animal，而 Husky 确实是 Animal ✓

// ═══ 只读属性 ═══
interface ReadOnlyBox<T> {
  readonly value: T
}

const huskyBox: ReadOnlyBox<Husky> = { value: new Husky() }

// ✅ 协变
const animalBox: ReadOnlyBox<Animal> = huskyBox
animalBox.value.name  // OK, name 存在于 Animal 上


// ═══ Promise 的 resolve 值（只读出口）═══
const huskyPromise: Promise<Husky> = Promise.resolve(new Husky())

// ✅ 协变
const animalPromise: Promise<Animal> = huskyPromise
```

### 2.3 为什么只读位置天然协变？

```
只读意味着：你只能从中"取出"值，不能"写入"

取出时：
  Container<Husky> 取出的是 Husky
  把它当 Container<Animal> 用，取出后当作 Animal
  → Husky is Animal → 安全 ✓

类比：如果你有一箱金条（Gold）
     把它当作"贵重物品"（Valuable）箱子来用
     拿出来的东西确实是 Valuable → 安全
```

### 2.4 out 关键字标注（Scala/Kotlin 中的概念）

某些语言（如 Kotlin）用 `out` 关键字显式标注协变：

```typescript
// TypeScript 没有 out 关键字，但语义上是类似的
// interface Box<out T> { readonly value: T }  // 概念性的

// TypeScript 默认行为：
// - readonly 属性 → 协变
// - 数组的读取操作 → 协变
// - Promise<T> 的 then 返回值 → 协变
```

## 三、逆变（Contravariance）

### 3.1 定义

如果 `A 是 B 的子类型`，那么 `Container<B>` 反而是 `Container<A>` 的子类型。**子类型关系方向相反**。

这是最违反直觉的部分，让我们仔细理解。

### 3.2 函数参数是逆变的！

```typescript
// 这是理解逆变的钥匙！

// 一个接受 Animal 的函数
type AnimalHandler = (animal: Animal) => void

// 一个接受 Dog 的函数
type DogHandler = (dog: Dog) => void

// 问题：AnimalHandler 能不能赋值给 DogHandler？
// 即：能不能把"能处理任何动物的函数"当作"能处理狗的函数"？


// ═══ 直觉思考 ═══
const handleAnimal: AnimalHandler = (animal) => {
  console.log(`Handling ${animal.name}`)
}

const handleDog: DogHandler = (dog) => {
  console.log(`${dog.name} says woof!`)
  dog.bark()
}


// ✅ AnimalHandler 可以赋值给 DogHandler ！
const dogHandlerRef: DogHandler = handleAnimal  // ← 这竟然合法！

// 为什么？
// dogHandlerRef 期望接收一个 Dog
// 我们给它一个实际上能接收 Animal 的函数
// 当传入 Dog 时，这个函数当然也能处理（因为 Dog is Animal）
//
// 类比：
// 你需要一个"能遛狗的人"（DogHandler）
// 我给你一个"能照顾一切动物的人"（AnimalHandler）
// 当然可以！他能遛狗（甚至做得更好）



// ❌ 反过来不行！DogHandler 不能赋值给 AnimalHandler
const animalHandlerRef: AnimalHandler = handleDog
//                                 ^^^^^^^^^^ Error!
//
// 为什么？
// animalHandlerRef 应该能接收任何 Animal（包括 Cat）
// 但我们给的函数只能处理 Dog！
// 如果有人传了一个 Cat → 💥 崩溃！
```

### 3.3 逆变的可视化

```
函数参数的型变规则：

  Dog ⊆ Animal（Dog 是 Animal 的子类型）
  
  ↓ 方向反转 ↓
  
  ((x: Animal) => void) ⊆ ((x: Dog) => void)
  ↑                      ↑
  更通用                 更特定
  (AnimalHandler)        (DogHandler)


记忆口诀：

"函数参数是逆变的"
= "需要得越少（只接受 Animal），能力越强（可以替代接受 Dog 的角色）"

类比招聘：
- 招聘"能处理一切动物的兽医"（AnimalHandler）→ 很难找到
- 招聘"能处理狗的医生"（DogHandler）→ 容易找到

前者可以做后者的工作（但不能反过来）
所以 AnimalHandler 是 DogHandler 的"子类型"（更通用 = 更可替代）
```

### 3.4 更多逆变例子

```typescript
// ═══ 回调函数参数 ═══
function registerCallback(cb: (data: string) => void): void { /* ... */ }

// ✅ 更通用的回调可以注册到更特定的槽位
registerCallback((data: any) => {
  // data 的类型是 string（由声明决定），不是 any
  // 但 any 兼容一切，所以合法
})

// ═══ 事件监听器 ═══
element.addEventListener('click', (e: MouseEvent) => { /* ... */ })

// addEventListener 的回调签名实际上是 (e: Event) => void
// 但我们可以传一个 (e: MouseEvent) => void
// 为什么？因为 MouseEvent handler 更特定，Event handler 更通用
// 等等……这似乎是协变？

// 实际上 addEventListener 的回调参数类型是逆变位置
// (e: MouseEvent) => void 可以赋值给 (e: Event) => void
// 这符合逆变：MouseEvent ⊆ Event ⇒ handler(Event) ⊆ handler(MouseEvent)


// ═══ Array.forEach ═══
const numbers = [1, 2, 3]

// forEach 的回调参数是 (item: number, index: number, array: number[]) => void
numbers.forEach((item) => {
  // item 自动推断为 number ✓
})
```

## 四、不变（Invariance）

### 4.1 定义

既不协变也不逆变。**没有任何自动的子类型关系**。

### 4.2 什么时候出现不变？

当一个类型参数**同时出现在协变位置（读/返回）和逆变位置（写/参数）**时：

```typescript
// 最经典的例子：可变数组 / 可变容器
interface MutableBox<T> {
  get(): T        // 协变位置（产出 T）
  set(value: T): void  // 逆变位置（消费 T）
}

// ═══ 不变的原因 ═══
const huskyBox: MutableBox<Husky> = {
  get: () => new Husky(),
  set: (husky) => { /* set a husky */ },
}

// ❌ 不能赋值给 MutableBox<Animal>
// const animalBox: MutableBox<Animal> = huskyBox  // Error!
//
// 为什么不行？两方面的安全问题：
//
// 1. 读的时候（协变角度）：
//    animalBox.get() 返回 Animal → 但实际可能返回 Husky → 安全 ✓
//
// 2. 写的时候（逆变角度）：
//    animalBox.set(new Cat())  ← 合法！因为参数类型是 Animal
//    但实际 box 只接受 Husky → 放了一只 Cat 进去！💥 不安全！
//
// 结论：由于写操作的存在，不能安全地协变


// ❌ 反过来也不行
// const huskyBox2: MutableBox<Husky> = someAnimalBox  // Error!
//
// 为什么？
// huskyBox2.set(new Husky())  ← 合法
// 但实际 box 可能期望接收任何 Animal
// 而 set 方法只能处理 Husky → 如果需要放 Cat 就完蛋了
//
// 结论：由于读操作的存在，也不能安全地逆变
```

### 4.3 不变的本质

```
不变 = 同时需要协变安全性 + 逆变安全性
     = 两者都不能自动满足
     = 只有完全相同的类型才能赋值

MutableBox<Dog> ≢ MutableBox<Animal>  （两个方向都不行）
只有：MutableBox<Dog> ≡ MutableBox<Dog>
```

## 五、TypeScript 中的型变规则详解

### 5.1 各位置的型变性总结

```typescript
interface Example<
  TCov,      // 只用于"读"/返回的位置 → 协变
  TContra,   // 只用于"写"/参数的位置 → 逆变
  TInv       // 同时用于读写 → 不变
> {
  // ═════ 协变位置（out）═════
  readonly covField: TCov              // 只读属性
  getCov(): TCov                       // 返回值
  covArray: ReadonlyArray<TCov>       // 只读数组
  
  // ═════ 逆变位置（in）═════
  setContra(value: TContra): void     // 参数
  acceptContra(fn: (x: TContra) => void): void  // 函数参数
  contraCompare(other: TContra): number  // 参数
  
  // ═════ 不变位置（in + out）═════
  invField: TInv                      // 可读写属性！
  getInv(): TInv                      // 返回
  setInv(value: TInv): void           // 参数
  invArray: TInv[]                    // 可变数组
  invMethod(invArg: TInv): TInv       // 又是参数又是返回
}
```

### 5.2 strictFunctionTypes 的影响

```typescript
// tsconfig.json: "strictFunctionTypes": true（推荐开启）

// 开启前（宽松）：函数参数双向协变
type LooseFn = (x: Animal) => void
type SpecificFn = (x: Dog) => void

let f: LooseFn
let s: SpecificFn = f  // 旧版本允许！但不安全

// 开启后（严格）：函数参数逆变
// s = f  // ✅ 允许（AnimalHandler → DogHandler，逆变）
// f = s  // ❌ 不允许（DogHandler → AnimalHandler，需要协变但不安全）
```

### 5.3 in / out 显式标注

TypeScript 4.7+ 支持**显式型变标注**（受 Scala/Kotlin 启发）：

```typescript
// 使用 in 关键字标注逆变
type Consumer<in T> = (value: T) => void

// 使用 out 关键字标注协变
type Producer<out T> = () => T

// 使用 in out 标注不变
type Box<in out T> = { value: T }

// 实际应用
interface Animal Shelter<out T extends Animal> {
  adopt(): T          // out → 协变
  // accept(pet: T): void  // 如果有这行就需要 in → 变成不变
}

const huskyShelter: Animal Shelter<Husky> = { /*...*/ }
const shelter: Animal Shelter<Animal> = huskyShelter  // ✅ 协变
```

## 六、双射型变（Bivariance）

### 6.1 什么是双射？

**双射**意味着既是协变又是逆变——即两个方向都可以赋值。这是**最宽松**的型变。

### 6.2 TypeScript 中的双射场景

```typescript
// 旧版 TS 中（strictFunctionTypes 关闭时），函数参数是双射的
// 现在仅在方法参数中存在

interface OldStyle {
  method(x: Animal): void  // 方法参数（非函数类型属性）→ 双射
}

interface NewStyle {
  method: (x: Animal) => void  // 函数类型属性 → 逆变（strictFunctionTypes）
}

// 方法参数的双射行为：
const obj: OldStyle = {
  method: (x: Dog) => {  // Dog → Animal 被允许！（协变方向）
    x.bark()             // 但这里可能 unsafe
  }
}
// 也允许反方向：
const obj2: OldStyle = {
  method: (x: Animal) => {  // Animal → Dog 也被允许！（逆变方向）
    // ...
  }
}
```

### 6.3 为什么方法参数是双射的？

历史原因——为了兼容旧的 JavaScript 代码风格，TypeScript 对对象方法的参数做了特殊处理。但在新代码中应该始终使用函数类型属性来获得更安全的逆变检查。

## 七、实用案例

### 7.1 事件系统中的型变

```typescript
type EventHandler<T = void> = (data: T) => void

class EventEmitter<Events extends Record<string, any>> {
  private handlers = new Map<string, Set<EventHandler<any>>>()

  // on 的参数是逆变的
  on<K extends keyof Events>(event: K, handler: EventHandler<Events[K]>): this {
    if (!this.handlers.has(event)) {
      this.handlers.set(event, new Set())
    }
    this.handlers.get(event)!.add(handler)
    return this
  }

  // emit 产出的类型是协变的
  emit<K extends keyof Events>(event: K, data: Events[K]): void {
    this.handlers.get(event)?.forEach(h => h(data))
  }
}

// 定义事件
interface AppEvents {
  'user:login': { userId: string; timestamp: number }
  'user:logout': { userId: string }
  'notification': { title: string; body: string }
}

const bus = new EventEmitter<AppEvents>()

// ✅ 逆变允许更通用的处理器
bus.on('user:login', (data: { userId: string }) => {
  // 我们可以只声明需要的最小类型
  console.log(data.userId)
})

// ✅ 甚至可以用 any 类型的处理器（最通用）
bus.on('user:logout', (_data: any) => {
  console.log('someone logged out')
})
```

### 7.2 依赖注入容器中的型变

```typescript
// 容器接口
interface DIContainer {
  get<T>(token: Token<T>): T
  register<T>(token: Token<T>, factory: () => T): void
}

// Token 类型
class Token<T> {
  readonly __brand!: T
  constructor(public readonly name: string) {}
}

// 注册服务
const USER_TOKEN = Token<User>('user')
const ANIMAL_TOKEN = Token<Animal>('animal')

container.register(USER_TOKEN, () => new Dog())  // ✅ Dog 是 User 的子类型？不一定...
// 实际上这里取决于工厂返回类型和 token 声明类型的兼容性
```

### 7.3 泛型约束中的型变

```typescript
// 约束本身也涉及型变
function process<T extends Animal>(animal: T): string {
  return animal.name
}

const dog: Dog = new Dog()

process(dog)  // ✅ T 推断为 Dog

process<Animal>(dog)  // ✅ Dog 可以作为 Animal 使用

// process<string>(dog)  // ❌ string 不符合 extends Animal 约束
```

## 八、型变陷阱

### 8.1 常见误区

```typescript
// ❌ 误区 1：认为所有泛型都是协变的
const fn: ((x: Dog) => void) = (x: Animal) => {}  // ✅ 逆变，不是协变
// const arr: Dog[] = [new Animal()]  // ❌ 这才是错的

// ❌ 误区 2：忽略 strictFunctionTypes
// 在关闭的情况下写出的不安全代码可能在开启后报错

// ❌ 误区 3：混淆数组的读写
const dogs: Dog[] = [new Dog()]
const animals: Animal[] = dogs  // ✅ 协变允许

animals.push(new Cat())  // ⚠️ 编译通过！但 dogs 数组里混进了 Cat！
// 这就是为什么 TypeScript 对可变数组是协变的（出于实用性考虑）
// 但理论上这里存在安全隐患

// 更安全的做法：使用 ReadonlyArray
const safeDogs: ReadonlyArray<Dog> = [new Dog()]
const safeAnimals: ReadonlyArray<Animal> = safeDogs  // ✅ 协变
// safeAnimals.push(...)  // ❌ 不存在 push 方法！安全了！
```

### 8.2 如何选择正确的型变

```
设计 API 时的决策指南：

你的泛型参数 T 是主要用于……
  │
  ├─ 读取/产出（返回值、只读属性）     → 设计为协变（自然发生）
  │   例：ReadOnlyList<T>, Option<T>, Future<T>
  │
  ├─ 写入/消费（参数、可变属性）       → 设计为逆变（自然发生）
  │   例：Comparator<T>, Predicate<T>, Consumer<T>
  │
  └─ 两者都有（读写属性、可变容器）    → 不变（自然发生）
      例：MutableList<T>, Cell<T>, ArrayBuffer<T>
```

## 总结

型变（Variance）是类型系统中最微妙也最重要的概念之一：

**第一层：直觉建立** —— 通过"只读容器"理解协变（Husky[] 是 Animal[] 的子类型），通过"函数参数"理解逆变（AnimalHandler 是 DogHandler 的子类型），通过"可变容器"理解不变（双向都不安全）。

**第二层：规则掌握** —— TypeScript 中各位置的默认型变性：只读/返回 = 协变，参数 = 逆变，读写兼具 = 不变。`strictFunctionTypes` 影响函数参数的双射 vs 逆变行为。

**第三层：显式控制** —— TypeScript 4.7+ 支持 `in`/`out` 关键字显式标注型变意图，提升表达力和安全性。

**第四层：实践应用** —— 在设计泛型 API（事件系统、DI 容器、集合类）时正确利用型变规则，避免类型安全漏洞。

**一句话记忆**："产出者 out 协变，消费者 in 逆变，又进又出不变"。理解这句话，你就掌握了型变的核心。
