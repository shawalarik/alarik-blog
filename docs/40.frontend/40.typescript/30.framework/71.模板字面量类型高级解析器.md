# 模板字面量类型高级解析器 —— 解析路径字符串、CSS 单位、SQL 查询

> **核心问题**：TypeScript 4.1 引入了**模板字面量类型（Template Literal Types）**，它让你能在类型层面操作字符串——拼接、拆分、模式匹配、转换大小写……这听起来像是正则表达式的能力，但实际上是在编译期完成的。本章将深入这个特性，构建路径解析器、CSS 单位验证器和 SQL 查询构造器等高级应用。

---

## 一、模板字面量类型基础

### 1.1 从值到类型的映射

你已经在 JavaScript 中熟悉了模板字符串（Template Literals）：

```javascript
// 值层面的模板字符串（运行时）
const greeting = `Hello, ${name}!`
// name = "World" → "Hello, World!"
// name = "Alice" → "Hello, Alice!"
```

**模板字面量类型**把同样的思想搬到了**编译期**：

```typescript
// 类型层面的模板字面量（编译期）
type Greeting<T extends string> = `Hello, ${T}!`

type G1 = Greeting<'World'>   // "Hello, World!"
type G2 = Greeting<'Alice'>   // "Hello, Alice!"
//
// 注意！这里的 "Hello, World!" 不是运行时字符串，
//      而是一个字面量字符串类型（String Literal Type）！
```

**生活类比：填空题试卷**

```
═══════════════════════════════════════════════════
         模板字面量类型 = 编译期的"填空题"
═══════════════════════════════════════════════════

【运行时的模板字符串】= 学生在考试时填写答案
───────────────────────
  考卷发下来了，学生拿笔在横线上写字：
  
    "我最喜欢的科目是 _____"
    
  学生 A 填："数学"  → "我最喜欢的数学是数学" ...嗯？
  学生 B 填："英语"  → "我最喜欢的英语是英语"

  这是动态的、发生在程序运行的时候


【类型层面的模板字面量】= 老师出题时印好的试卷
───────────────────────────
  老师在出题时就确定了每个空格可以填什么：
  
  type Answer = '数学' | '英语' | '物理'
  type Question = `我最喜欢的是 ${Answer}`
  
  这张试卷被印出来后：
  - 批改者（TypeScript 编译器）一看就知道
    答案只能是三种之一
  - 如果学生填了"体育"，直接判错（编译报错）
```

### 1.2 核心语法

模板字面量类型的语法和 JavaScript 模板字符串几乎一模一样：

```typescript
// ═══════════════════════════════════════
// 基本形式
// ═══════════════════════════════════════

type T1 = `hello`                          // 字面量 "hello"（没变化）
type T2 = `hello ${string}`                // 以 hello 开头的任意字符串
type T3 = `${string} world`                // 以 world 结尾的任意字符串
type T4 = `${string} and ${string}`        // 包含 "and " 的字符串


// ═══════════════════════════════════════
// 使用联合类型作为占位符
// ═══════════════════════════════════════

type Color = 'red' | 'green' | 'blue'
type Size = 'small' | 'medium' | 'large'

// 联合类型的笛卡尔积展开
type CSSClass = `${Color}-${Size}`
// 
// 结果：11 种组合！
// "red-small" | "red-medium" | "red-large" |
// "green-small" | "green-medium" | "green-large" |
// "blue-small" | "blue-medium" | "blue-large"


// ═══════════════════════════════════════
// 与其他类型特性的组合
// ═══════════════════════════════════════

// + 条件类型
type IsGreeting<T extends string> = T extends `Hello ${string}` ? true : false
type IG1 = IsGreeting<'Hello World'>     // true
type IG2 = IsGreeting<'Hi there'>       // false

// + 映射类型
type EventNames = {
  [K in 'click' | 'hover' | 'focus']: `on${Capitalize<K}>`
}
// 结果：
// {
//   click: 'onClick'
//   hover: 'onHover'
//   focus: 'onFocus'
// }

// + infer（模式匹配提取）
type ExtractFirstSegment<T extends string> = 
  T extends `${infer First}/${infer Rest}` ? First : T

type EFS = ExtractFirstSegment<'api/users/profile'>
// 结果："api"
```

### 1.3 内置字符串工具类型

TypeScript 提供了四个内置的字符串转换工具类型：

```typescript
/**
 * Uppercase<StringType> —— 全部转大写
 */
type U1 = Uppercase<'hello'>   // "HELLO"
type U2 = Uppercase<'HeLLo'>   // "HELLO"


/**
 * Lowercase<StringType> —— 全部转小写
 */
type L1 = Lowercase<'HELLO'>   // "hello"
type L2 = Lowercase<'HeLLo'>   // "hello"


/**
 * Capitalize<StringType> —— 首字母大写
 */
type C1 = Capitalize<'hello'>  // "Hello"
type C2 = Capitalize<'HELLO'>  // "HELLO"（只影响第一个字符！）


/**
 * Uncapitalize<StringType> —— 首字母小写
 */
type UC1 = Uncapitalize<'Hello'>  // "hello"
type UC2 = Uncapitalize<'HELLO'>  // "hELLO"（只影响第一个字符！）


/**
 * 注意：这些是真正的类型级操作，不是运行时函数！
```

```typescript

type Uppercase<S extends string> =
  // 对 S 的每个字符进行大写映射
  // 'a'→'A', 'b'→'B', ..., 'z'→'Z', 其他保持不变

type Capitalize<S extends string> =
  // 第一个字母 → 大写，其余不变
```

## 二、模式匹配与字符串拆分

### 2.1 infer 的魔法：在字符串中提取子串

`infer` 关键字配合模板字面量类型，可以实现类似正则表达式的**捕获组（Capture Group）**功能：

```typescript
/**
 * 基本的模式匹配提取
 */

// 提取 "Hello " 后面的部分
type AfterHello<T extends string> = 
  T extends `Hello ${infer Rest}` ? Rest : never

type AH1 = AfterHello<'Hello World'>    // " World"
type AH2 = AfterHello<'Hello Alice!'>   // " Alice!"
type AH3 = AfterHello<'Hi there'>       // never（不匹配）


// 提取两部分之间的内容
type Between<T extends string, Start extends string, End extends string> =
  T extends `${Start}${infer Middle}${End}` ? Middle : never

type BM1 = Between<'[important]', '[', ']'>              // "important"
type BM2 = Between<'<div>content</div>', '<div>', '</div>'>  // "content"
type BM3 = Between<'a-b-c', '-', '-'>                     // "b"


// 同时提取多个部分
type SplitThree<T extends string> =
  T extends `${infer Part1}-${infer Part2}-${infer Part3}` 
    ? [Part1, Part2, Part3] 
    : never

type ST = SplitThree<'2026-04-16'>
// 结果：["2026", "04", "16"]  （年-月-日 的解析）
```

### 2.2 用生活场景类比 infer 模式匹配

```
想象你在处理一叠快递包裹：

每个包裹上的标签格式都是固定的：
  "发件人: XXX 收件人: YYY 重量: ZZZkg"

你想从中提取三个信息。

【没有 infer】你只有一把剪刀
────────────────
  你知道标签的大致结构，但无法精确地
  把"发件人"、"收件人"、"重量"分别剪下来
  
【有 infer + 模板字面量】你有了一把智能模具
──────────────────────
  模具上写着：
    "发件人: ${____} 收件人: ${____} 重量: ${____}kg"
  
  你把标签往上一盖：
  - 第一个洞里透出 "张三"
  - 第二个洞里透出 "李四"
  - 第三个洞里透出 "2.5"
  
  这就是 infer 在模板字面量中做的事！
  `${infer XXX}` 就像模具上镂空的洞，
  让特定位置的信息"漏"进来
```

### 2.3 递归字符串分割

利用递归 + infer，我们可以实现完整的字符串分割功能：

```typescript
/**
 * Split —— 将字符串按分隔符分割为元组
 *
 * 这是一个递归类型，每次从头部提取一个片段
 */
type Split<S extends string, Delim extends string = ','> =
  // 空字符串的情况
  S extends '' 
    ? []
    // 分隔符不在字符串中 → 返回整个字符串
    : S extends `${infer Head}${Delim}${infer Tail}`
      ? [Head, ...Split<Tail, Delim>]   // 递归处理剩余部分
      : [S]                              // 没有更多分隔符了


// 测试基本用法
type CommaSplit = Split<'a,b,c,d'>
// 结果：["a", "b", "c", "d"]

type DashSplit = Split<'2026-04-16', '-'>
// 结果：["2026", "04", "16"]

type PathSplit = Split<'api/users/profile', '/'>
// 结果：["api", "users", "profile"]

type NoDelimiter = Split<'hello'>
// 结果：["hello"]（没有找到分隔符，整体返回）

type EmptyStr = Split<''>
// 结果：[]（空字符串返回空数组）


/**
 * Join —— 将元组的元素连接为字符串
 */
type Join<T extends string[], Delim extends string = ''> =
  T extends [infer First extends string, ...infer Rest extends string[]]
    ? Rest extends []
      ? First
      : `${First}${Delim}${Join<Rest, Delim}>`
    : ''

type J1 = Join<['a', 'b', 'c'], ', '>           // "a, b, c"
type J2 = Join<['2026', '04', '16'], '-'>       // "2026-04-16"
type J3 = Join<['hello'] >                       // "hello"
type J4 = Join<[], ', '>                         // ""
```

### 2.4 字符串替换

```typescript
/**
 * Replace —— 替换字符串中第一次出现的模式
 */
type Replace<
  S extends string,
  From extends string,
  To extends string
> = From extends ''
  ? S
  : S extends `${infer Start}${From}${infer End}`
    ? `${Start}${To}${End}`
    : S

type R1 = Replace<'hello world', 'world', 'TypeScript'>
// "hello TypeScript"

type R2 = Replace<'abc abc', 'abc', 'xyz'>
// "xyz abc"（只替换第一个）


/**
 * ReplaceAll —— 替换所有出现
 */
type ReplaceAll<
  S extends string,
  From extends string,
  To extends string
> = From extends ''
  ? S
  : S extends `${infer Start}${From}${infer End}`
    ? ReplaceAll<`${Start}${To}${End}`, From, To>
    : S

type RA1 = ReplaceAll<'abc abc abc', 'abc', 'xyz'>
// "xyz xyz xyz"

type RA2 = ReplaceAll<'GET /api/users/:id', ':id', '123'>
// "GET /api/users/123"
```

## 三、实战案例一：路径字符串解析器

### 3.1 需求分析

在现代 Web 开发中，路由（Routing）是一个核心概念。我们经常需要处理这样的路径字符串：

```
/api/users/:userId/posts/:postId
/dashboard/settings/profile
/static/images/logo.png
/admin/users/:id/edit
```

**目标**：用模板字面量类型在编译期验证和解析这些路径，做到：
1. 静态路径必须精确匹配
2. 参数路径（`:param`）可以被提取
3. 通配符路径（`*`）可以匹配多段
4. 错误的路由在编译期就被拦截

### 3.2 基础路径解析器

```typescript
/**
 * 路径段的定义
 */
type Segment = string  // 一个路径段可以是任何非斜杠字符串

/**
 * 解析静态路径 —— 精确匹配每一层
 */
type ParseStaticPath<Path extends string> =
  Path extends `/${infer Segment}/${infer Rest}`
    ? [Segment, ...ParseStaticPath<`/${Rest}>]
    : Path extends `/${infer Last}`
      ? [Last]
      : []

// 测试
type P1 = ParseStaticPath<'/api/users/profile'>
// ["api", "users", "profile"]

type P2 = ParseStaticPath<'/dashboard'>
// ["dashboard"]

type P3 = ParseStaticPath<''>
// []


/**
 * 检查路径是否以指定前缀开头
 */
type StartsWith<Path extends string, Prefix extends string> =
  Path extends `${Prefix}${infer _}` ? true : false

type SW1 = StartsWith<'/api/users', '/api'>          // true
type SW2 = StartsWith<'/static/images', '/api'>      // false
type SW3 = StartsWith<'/api/v2/users', '/api/v2'>    // true
```

### 3.3 带参数的路径解析

```typescript
/**
 * 判断一个段是否是参数段（以 : 开头）
 */
type IsParam<Seg extends string> = Seg extends `:${string}` ? true : false

type IP1 = IsParam<':userId'>    // true
type IP2 = IsParam<'users'>      // false
type IP3 = IsParam<':_id'>       // true（:_id 也算参数）


/**
 * 提取参数名（去掉前面的 :）
 */
type ParamName<Seg extends string> =
  Seg extends `:${infer Name}` ? Name : never

type PN1 = ParamName<':userId'>   // "userId"
type PN2 = ParamName<':id'>       // "id"


/**
 * 完整的带参数路径解析
 * 
 * 返回一个对象，记录每段是静态的还是参数
 */
type ParsedRoute<
  Path extends string,
  Params extends Record<string, string> = {}
> =
  // 匹配 /xxx/... 格式（中间段）
  Path extends `/${infer Seg}/${infer Rest}`
    ? Seg extends `:${infer ParamName}`
      // 参数段：记录参数名
      ? ParsedRoute<`/${Rest}`, Params & { [K in ParamName]: string }>
      // 静态段：不改变参数
      : ParsedRoute<`/${Rest}`, Params>
    // 匹配 /xxx 格式（最后一段）
    : Path extends `/${infer LastSeg}`
      ? LastSeg extends `:${infer LastName>`
        ? Params & { [K in LastName]: string }
        : Params
    : Params


// 测试
type Route1 = ParsedRoute<'/api/users/:userId/posts/:postId'>
// 结果：
// {
//   userId: string;
//   postId: string
// }
// 成功提取出了两个参数！

type Route2 = ParsedRoute<'/static/css/style.css'>
// 结果：{}（无参数，纯静态路径）

type Route3 = ParsedRoute<'/admin/:id/edit'>
// 结果：{ id: string }
```

### 3.4 路径验证器

```typescript
/**
 * 定义合法的路由配置
 */
type DefinedRoutes =
  | '/'                                              // 首页
  | '/about'                                         // 关于页
  | '/api/users'                                     // 用户列表
  | '/api/users/:id'                                 // 用户详情
  | '/api/users/:id/posts'                           // 用户帖子列表
  | '/api/users/:id/posts/:postId'                   // 帖子详情
  | '/posts/new'                                     // 新建帖子
  | '/posts/:id/edit'                                // 编辑帖子
  | '/dashboard/settings/*'                           // 设置页面（通配符）


/**
 * 检查给定路径是否匹配某个已定义路由
 */
type MatchRoute<Candidate extends string> =
  Candidate extends DefinedRoutes ? true : false

type M1 = MatchRoute<'/api/users'>            // true ✓
type M2 = MatchRoute<'/api/users/42'>         // true ✓ (匹配 :id)
type M3 = MatchRoute<'/unknown/path'>         // false ✗
type M4 = MatchRoute<'/api/posts'>            // false ✗ (未定义此路由)
```

### 3.5 构建类型安全的路由函数

```typescript
/**
 * 结合上面的类型能力，创建一个类型安全的路由导航函数
 */

type RouteParams<Route extends string> = ParsedRoute<Route>

// 导航函数 —— 路由和参数必须在编译期匹配
function navigate<Route extends string>(
  route: Route,
  params: RouteParams<Route> & Record<string, string | number>
): void {
  // 实际实现会根据 route 和 params 构建 URL
  console.log(`Navigating to ${route} with`, params)
}

// ✅ 正确使用
navigate('/api/users/:userId', { userId: '42' })
navigate('/api/users/:userId/posts/:postId', { userId: '42', postId: '100' })
navigate('/', {})

// ❌ 编译错误！缺少必需参数
navigate('/api/users/:userId', {})
// Error: Property 'userId' is missing in type '{}'

// ❌ 多余参数不会报错（因为用了 & 交叉类型）
// 但可以通过 stricter 版本来禁止
```

## 四、实战案例二：CSS 单位验证器

### 4.1 CSS 单位的类型定义

CSS 中有各种长度单位，我们可以用模板字面量类型来确保传入的值带有正确的单位：

```typescript
/**
 * CSS 长度单位
 */
type CSSLengthUnit = 
  | 'px'    // 像素
  | 'em'    // 相对父元素字体大小
  | 'rem'   // 相对根元素字体大小
  | '%'     // 百分比
  | 'vw'    // 视口宽度的百分比
  | 'vh'    // 视口高度的百分比
  | 'cm'    // 厘米
  | 'mm'    // 毫米
  | 'in'    // 英寸
  | 'pt'    // 点
  | 'pc'    // 派卡
  | 'ch'    // "0"字符的宽度
  | 'ex'    // "x"高度
  | 'vmin'  | 'vmax'  // 视口最小/最大尺寸


/**
 * CSS 长度值 —— 数字 + 单位
 */
type CSSLength = `${number}${CSSLengthUnit}`

// 测试
type L1 = CSSLength  // 所有合法的 CSS 长度值的联合类型
// 包含如 "0px", "1.5em", "100vw", "-50%" 等


/**
 * 更精细的控制：不允许负值的单位
 */
type NonNegativeUnit = Exclude<CSSLengthUnit, '%'>  // % 可以负
type PositiveLength = `${number}${NonNegativeUnit}`

/**
 * 角度单位
 */
type AngleUnit = 'deg' | 'rad' | 'grad' | 'turn'
type CSSAngle = `${number}${AngleUnit}`

/**
 * 时间单位
 */
type TimeUnit = 's' | 'ms'
type CSSTime = `${number}${TimeUnit}`
```

### 4.2 类型安全的 CSS 属性设置

```typescript
/**
```

### 4.3 CSS 类名生成器

```typescript
/**
 * BEM 命名规范的类型安全实现
 * 
 * BEM = Block__Element--Modifier
 * 例如：card__title--large
 */

type BEM<
  Block extends string,
  Element extends string = '',
  Modifier extends string = ''
> = Element extends ''
  ? Modifier extends ''
    ? Block                            // .card
    : `${Block}--${Modifier}`          // .card--large
  : Modifier extends ''
    ? `${Block}__${Element}`           // .card__title
    : `${Block}__${Element}--${Modifier}`  // .card__title--large


// 类型安全的 BEM 类名函数
function bem<Block extends string>(block: Block) {
  return {
    /**
     * 添加元素
     */
    el<Element extends string>(element: Element): BEM<Block, Element> {
      return `${block}__element` as BEM<Block, Element>
    },
    
    /**
     * 只添加修饰符
     */
    mod<Modifier extends string>(modifier: Modifier): BEM<Block, '', Modifier> {
      return `${block}--${modifier}` as unknown as BEM<Block, '', Modifier>
    },
    
    /**
     * 直接获取 block 名
    toString(): Block {
      return block
    }
  }
}

// 使用
const card = bem('card')
const cardTitle = card.el('title')          // "card__title" (类型: BEM<"card", "title">)
const cardImage = card.el('image')          // "card__image"
const cardTitleLarge = card.el('title').mod('large')  // 需要链式支持

// 更实用的方式：直接使用类型别名
type CardBlock = 'card'
type CardElement = 'title' | 'body' | 'footer' | 'image'
type CardModifier = 'large' | 'small' | 'dark' | 'highlighted'

type CardClass = 
  | BEM<CardBlock>
  | BEM<CardBlock, CardElement>
  | BEM<CardBlock, CardElement, CardModifier>
  | BEM<CardBlock, '', CardModifier>

// 现在 cardClass 必须是以上几种形式之一
let cardClass: CardClass
cardClass = 'card'                    // ✓
cardClass = 'card__title'             // ✓
cardClass = 'card__title--large'      // ✓
cardClass = 'card--dark'              // ✓
cardClass = 'card__header'            // ✗ "header" 不是合法的 Element
cardClass = 'btn__primary'            // ✗ "btn" 不是合法的 Block
```

### 5.2 类型安全的 SELECT 查询

这是一个简化的但功能完整的类型安全 SQL 构造器：

```typescript
/**
 * 表的定义
 */
interface TableSchema {
  users: {
    id: number
    name: string
    email: string
    age: number
    created_at: string
  }
  posts: {
    id: number
    user_id: number
    title: string
    content: string
    published: boolean
  }
  comments: {
    id: number
    post_id: number
    user_id: number
    body: string
  }
}

type TableName = keyof TableSchema
type ColumnName<T extends TableName> = keyof TableSchema[T]


/**
 * SELECT 查询的类型表示
 */
interface SelectQuery<T extends TableName> {
  __table: T
  columns: ColumnName<T>[] | '*'
  where?: string
  orderBy?: ColumnName<T>
  limit?: number
}

/**
 * 构造一个 SELECT 查询
 */
function select<T extends TableName>(
  table: T,
  columns: ColumnName<T>[] | '*'
): SelectQuery<T> {
  return { __table: table, columns } as SelectQuery<T>
}

// ✅ 正确的查询
const q1 = select('users', ['id', 'name', 'email'])
// 类型：SelectQuery<"users">
// columns 只能是 users 表的字段子集

const q2 = select('posts', '*')


// ❌ 错误：使用了不存在的列
const q3 = select('users', ['id', 'nonexistent'])
//                                          ^^^^^^^^^^^^
// Error: Argument of type '"nonexistent"' is not assignable to parameter
// of type 'keyof TableSchema["users"]'

// ❌ 错误：使用了其他表的列
const q4 = select('users', ['id', 'title'])
//                                      ^^^^^
// Error: '"title"' is not in '"id" | "name" | "email" | "age" | "created_at"'
```

### 5.3 WHERE 条件的类型安全

```typescript
/**
 * WHERE 条件 —— 确保比较的列和值的类型匹配
 */

type ColumnType<Table extends TableName, Col extends ColumnName<Table>> = 
  TableSchema[Table][Col]

type WhereCondition<
  Table extends TableName,
  Col extends ColumnName<Table>
> = {
  column: Col
  operator: SQLOperator
  value: ColumnType<Table, Col>
}

// 使用示例
const condition1: WhereCondition<'users', 'age'> = {
  column: 'age',
  operator: '>',
  value: 18          // ✓ age 是 number，18 也是 number
}

const condition2: WhereCondition<'users', 'name'> = {
  column: 'name',
  operator: '=',
  value: 'Alice'     // ✓ name 是 string，'Alice' 也是 string
}

// ❌ 类型不匹配
const badCondition: WhereCondition<'users', 'age'> = {
```

### 5.4 完整查询构建器

```typescript
/**
 * QueryBuilder —— 流式 API 构建类型安全的 SQL 查询
 */
class QueryBuilder<T extends TableName> {
  private _columns: (ColumnName<T> | '*')[]
  private _wheres: string[]
  private _orderBys: { column: ColumnName<T>; direction: 'ASC' | 'DESC' }[]
  private _limitCount?: number

  constructor(table: T) {}

  /**
   * 选择列
   */
  select(...cols: ColumnName<T>[]): this {
    this._columns = cols
    return this
  }

  selectAll(): this {
    this._columns = ['*']
    return this
  }

  /**
   * 添加 WHERE 条件
   * 这里简化处理：实际项目中可以做更精细的类型约束
   */
  where(condition: string): this {
    this._wheres.push(`WHERE ${condition}`)
    return this
  }

  /**
   * 排序
   */
  orderBy(col: ColumnName<T>, dir: 'ASC' | 'DESC' = 'ASC'): this {
    this._orderBays.push({ column: col, direction: dir })
    return this
  }

  /**
   * 限制结果数
   */
  limit(count: number): this {
    this._limitCount = count
    return this
  }

  /**
   * 构建最终 SQL
   */
  build(): string {
    const parts: string[] = []

    // SELECT 子句
    const cols = this._columns.length > 0 
      ? this._columns.join(', ') 
      : '*'
    parts.push(`SELECT ${cols}`)

    // FROM 子句（这里简化了）
    // parts.push(`FROM ???`) 

    // WHERE 子句
    if (this._wheres.length > 0) {
      parts.push(this._wheres.join(' '))
    }

    // ORDER BY
    if (this._orderBays.length > 0) {
      const orderStr = this._orderBays
        .map(ob => `ORDER BY ${ob.column} ${ob.direction}`)
        .join(', ')
      parts.push(orderStr)
    }

    // LIMIT
    if (this._limitCount !== undefined) {
      parts.push(`LIMIT ${this._limitCount}`)
    }

    return parts.join(' ')
  }
}

// 使用示例
const sql = new QueryBuilder<'users'>()
  .select('id', 'name', 'email')
  .where('age > 18')
  .orderBy('name', 'ASC')
  .limit(10)
  .build()

// 结果：
// "SELECT id, name, email WHERE age > 18 ORDER BY name ASC LIMIT 10"
```

### 5.5 SQL 注入防护（编译期）

虽然模板字面量类型不能防止运行时的 SQL 注入，但它可以在编译期确保查询结构的正确性：

```typescript
/**
 * 安全的参数化查询类型
 * 
 * 确保每个 ? 占位符都有对应的参数值
 */
type CountPlaceholders<SQL extends string> =
  SQL extends `${string}?${infer Rest}`
    ? 1 + CountPlaceholders<Rest>
    : 0

type ValidateParams<SQL extends string, Params extends any[]> =
  CountPlaceholders<SQL> extends Params['length']
    ? true
    : false

// 测试
type V1 = ValidateParams<'SELECT * FROM users WHERE id = ?', [number]>
// CountPlaceholders = 1, Params.length = 1 → true ✓

type V2 = ValidateParams<
  'SELECT * FROM users WHERE id = ? AND name = ?',
  [number, string]
>
// CountPlaceholders = 2, Params.length = 2 → true ✓

type V3 = ValidateParams<'SELECT * FROM users', []>
// CountPlaceholders = 0, Params.length = 0 → true ✓

type V4 = ValidateParams<'SELECT * FROM users WHERE id = ?', [number, string]>
// CountPlaceholders = 1, Params.length = 2 → false ✗ 参数多了！
```

```typescript
// 不要到处都用复杂模板类型

type OptimizedCheck<T extends string> =
```

## 七、总结

模板字面量类型将 TypeScript 的类型系统从"处理形状和结构"扩展到了"处理字符串本身"。这打开了一扇全新的大门。

**核心能力总结**：

| 能力 | 语法 | 典型用途 |
|------|------|---------|
| **字符串拼接** | `` `${A}-${B}` `` | 生成 CSS 类名、事件名称 |
| **模式匹配提取** | `T extends \`prefix\${infer R}\`` | 解析路径、提取 URL 参数 |
| **字符串转换** | `Uppercase<>` / `Capitalize<>` | 统一命名规范 |
| **递归拆分** | 递归条件类型 | Split/Join/ReplaceAll |
| **联合展开** | 联合类型 + 模板 | 自动枚举所有组合 |
| **类型验证** | `T extends Pattern` | 路由校验、SQL 结构检查 |

> **一句话带走**：模板字面量类型让 TypeScript 的类型系统拥有了"字符串处理超能力"。它就像一把**编译期的瑞士军刀**——能切（Split）、能拼（Join）、能找（Pattern Match）、能换（Replace），而且所有操作都在代码运行之前完成，零运行时开销。掌握它，你就能在类型层面构建出路由引擎、CSS 校验器、SQL 查询构建器等令人惊叹的工具。
