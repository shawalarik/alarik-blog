# 编译 API 入门 —— 使用 ts-morph 或 TypeScript Compiler API 进行代码分析

> **核心问题**：TypeScript 编译器本身就是用 TypeScript 写的！这意味着你可以直接使用它的内部 API 来**分析、转换、生成 TypeScript/JavaScript 代码**。无论是构建 lint 工具、自动重构工具、文档生成器，还是 IDE 插件、代码度量系统——编译 API 都是最强大的基础设施工具。本章将带你从零掌握 Compiler API 和其友好封装库 ts-morph。

---

## 一、为什么需要编译 API？

### 1.1 从"写代码"到"操作代码"

作为开发者，我们每天都在**写代码**。但有些场景下，你需要的是**操作代码本身**：

```
═══════════════════════════════════════════════════
       "写代码" vs "操作代码" 的区别
═══════════════════════════════════════════════════

【写代码（日常开发）】
───────────────
  你是创作者：
  function add(a: number, b: number): number {
    return a + b
  }
  
  你关心的是：
  • 这个函数的逻辑对不对？
  • 类型标注是否正确？
  • 命名是否有意义？


【操作代码（元编程 / 工具开发）】
───────────────────
  你是手术医生（或建筑师）：
  
  你拿到一段代码，需要：
  • 找出所有没有测试覆盖的函数
  • 统计项目中每个文件的平均圈复杂度
  • 把所有的 var 替换为 let/const
  • 自动给所有公共方法生成 JSDoc 注释
  • 检测循环依赖关系
  • 把旧的 require() 转成 import
  
  这些任务都需要你能够"理解"代码的语法结构
  而不仅仅是把它当作纯文本处理

═══════════════════════════════════════════════════
```

### 1.2 为什么不用正则表达式？

很多开发者第一反应是用正则表达式来处理代码。这是一个**常见的错误**：

```typescript
/**
 * 任务：找出所有函数声明及其参数数量
 */

// ❌ 正则表达式的做法（脆弱且不可靠）
function countParamsWithRegex(code: string) {
  const funcRegex = /function\s+(\w+)\s*\(([^)]*)\)/g
  const results: { name: string; paramCount: number }[] = []
  
  let match
  while ((match = funcRegex.exec(code)) !== null) {
    const name = match[1]
    // 问题来了：参数列表可能包含：
    // - 默认值中有括号：(x = (a, b) => a + b)
    // - 解构参数：({ x, y }: Props)
    // - 泛型约束：<T extends U>
    // - 函数类型参数：(cb: (err: Error) => void)
    // - 多行定义
    // ...正则根本无法可靠地处理这些情况
    const paramsStr = match[2]
    const paramCount = paramsStr.split(',').length
    results.push({ name, paramCount })
  }
  
  return results
}

// ✅ Compiler API 的做法（准确且健壮）
function countParamsWithCompilerAPI(filePath: string) {
  const sourceFile = project.getSourceFileOrThrow(filePath)
  const functions = sourceFile.getFunctions()
  
  return functions.map(fn => ({
    name: fn.getName(),
    paramCount: fn.getParameters().length,
    // 还能获取更多信息：
    parameters: fn.getParameters().map(p => p.getName()),
    isExported: fn.isExported(),
    isAsync: fn.isAsync(),
    returnType: fn.getReturnType()?.getText(),
  }))
}
```

**生活类比**：

```
【正则表达式】= 用放大镜看文本
──────────────
  你在一张纸上搜索 "function(" 这个模式。
  如果有人写了：
    // 这不是 function(
    const text = "function("
  或者：
    /* function( 
       多行的 */
  正则就会出错或者漏掉

【编译 API】= 理解语法的阅读者
────────────────
  就像一个精通语言的人读这篇文章。
  他知道什么是注释、什么是字符串字面量、
  什么是代码——不会被表象迷惑。
```

### 1.3 TypeScript 编译器架构概览

在开始编码之前，先理解 TypeScript 编译器的工作流程：

```
═══════════════════════════════════════════════════
        TypeScript 编译器流水线
═══════════════════════════════════════════════════

  源码文件 (.ts/.tsx)
       │
       ▼
  ┌─────────────────┐
  │ Scanner/Tokenizer│ ← 词法分析：把字符流变成 token 流
  │ （扫描器）       │   例： "function" → T_FUNCTION 关键字
  └────────┬────────┘
           │ Token 流
           ▼
  ┌─────────────────┐
  │ Parser          │ ← 语法分析：把 token 流变成 AST
  │ （解析器）       │   （抽象语法树）
  └────────┬────────┘
           │ AST（抽象语法树）
           ▼
  ┌─────────────────┐
  │ Binder          │ ← 绑定：建立符号表，解析作用域和引用关系
  │ （绑定器）       │   让每个节点知道它"是什么"、"在哪里定义的"
  └────────┬────────┘
           │ 带符号信息的 AST
           ▼
  ┌─────────────────┐
  │ Type Checker     │ ← 类型检查：验证所有类型是否正确
  │ （类型检查器）   │   推断隐式类型，检查赋值兼容性
  └────────┬────────┘
           │ 类型信息
           ▼
  ┌─────────────────┐
  │ Emitter         │ ← 发射器：生成输出代码 (.js/.d.ts)
  │ （发射器）       │   可以是 JS、JSX、declaration 等
  └─────────────────┘
           
  输出文件 (.js / .d.ts / sourceMap)

═══════════════════════════════════════════════════
```

**我们可以介入的阶段**：

| 阶段 | 可做的事 | 典型用途 |
|------|---------|---------|
| **Parser 之后** | 遍历 AST，读取语法结构 | 代码格式化、lint 规则 |
| **Binder 之后** | 解析符号引用、查找定义 | 跳转定义、查找引用、重命名 |
| **Type Checker 之后** | 获取完整类型信息 | 自动补全、类型提示 |

### 2.3 使用 Visitor 模式遍历 AST

`ts.forEachChild` 和 `ts.visitNode` 是遍历 AST 的核心工具：

```typescript
/**
 * 基础遍历：打印 AST 中所有节点的种类
 */
function printAstStructure(node: ts.Node, indent: number = 0) {
  const padding = '  '.repeat(indent)
  const kindName = ts.SyntaxKind[node.kind]
  const extraInfo = ''

  // 根据节点类型添加额外信息
  if (ts.isIdentifier(node)) {
    // Identifier 节点：显示名称
    ;(node as any).extra = `"${node.text}"`
  } else if (ts.isStringLiteral(node)) {
    // 字符串字面量：显示内容
    ;(node as any).extra = `"${node.text}"`
  }

  console.log(`${padding}${kindName}${extraInfo ? ` [${extraInfo}]` : ''}`)

  // 递归遍历子节点
  node.forEachChild(child => printAstStructure(child, indent + 1))
}

// 使用
printAstStructure(sourceFile)

// 输出示例：
// SourceFile
//   FunctionDeclaration [greet]
//     Identifier [greet]
//     Parameter [name]
//       Identifier [name]
//       StringKeyword
//     Parameter [age]
//       Identifier [age]
//       NumberKeyword
//     StringKeyword
//     Block
//       ReturnStatement
//         TemplateExpression
//           ...
```

### 2.4 实用的代码分析示例

#### 示例 1：找出所有未使用的导入

```typescript
/**
 * 分析未使用的导入
 */
function findUnusedImports(sourceFile: ts.SourceFile): string[] {
  const imports: { name: string; used: boolean }[] = []
  
  // 第一轮：收集所有 import 声明
  ts.forEachChild(sourceFile, node => {
    if (ts.isImportDeclaration(node)) {
      const clause = node.importClause
      if (clause?.namedBindings && ts.isNamedImports(clause.namedBindings)) {
        for (const element of clause.namedBindings.elements) {
          imports.push({ name: element.name.text, used: false })
        }
      }
      // 默认导入
      if (clause?.name) {
        imports.push({ name: clause.name.text, used: false })
      }
    }
  })

  // 第二轮：检查标识符的使用情况
  function visit(node: ts.Node) {
    if (ts.isIdentifier(node)) {
      const importItem = imports.find(i => i.name === node.text)
      if (importItem) {
        importItem.used = true
      }
    }
    node.forEachChild(visit)
  }
  visit(sourceFile)

  // 返回未使用的导入
  return imports.filter(i => !i.used).map(i => i.name)
}
```

#### 示例 2：统计代码复杂度（圈复杂度）

```typescript
/**
 * 圈复杂度（Cyclomatic Complexity）计算
 *
 * 圈复杂度衡量代码中独立路径的数量
 * 每多一个 if/else/case/for/while/&&/||，复杂度+1
 */
function calculateComplexity(node: ts.Node): number {
  let complexity = 1  // 基础复杂度为 1

  function visit(n: ts.Node) {
    switch (n.kind) {
      case ts.SyntaxKind.IfStatement:
      case ts.SyntaxKind.CaseClause:
      case ts.SyntaxKind.ForStatement:
      case ts.SyntaxKind.ForInStatement:
      case ts.SyntaxKind.ForOfStatement:
      case ts.SyntaxKind.WhileStatement:
      case ts.SyntaxKind.DoStatement:
      case ts.SyntaxKind.CatchClause:
        complexity++
        break
      
      case ts.SyntaxKind.BinaryExpression: {
        const binExpr = n as ts.BinaryExpression
        if (
          binExpr.operatorToken.kind === ts.SyntaxKind.AmpersandAmpersandToken ||
          binExpr.operatorToken.kind === ts.SyntaxKind.BarBarToken
        ) {
          complexity++
        }
        break
      }

      case ts.SyntaxKind.ConditionalExpression:
        complexity++
        break
    }

    n.forEachChild(visit)
  }

  visit(node)
  return complexity
}
```

## 三、ts-morph：更友好的 API 封装

虽然原生 Compiler API 功能强大，但它的 API 设计偏向"编译器内部实现"，对外不够友好。**ts-morph** 是一个流行的第三方库，它在 Compiler API 之上提供了更加面向对象、更符合直觉的 API。

### 3.1 安装与初始化

```bash
npm install ts-morph
```

```typescript
import { Project, SyntaxKind, Node } from 'ts-morph'

// 创建项目
const project = new Project({
  // 可以指定 tsconfig.json 路径，会自动读取配置
  tsConfigFilePath: './tsconfig.json',
  
  // 或者手动配置编译选项
  compilerOptions: {
    target: ts.ScriptTarget.ES2020,
    module: ts.ModuleKind.ESNext,
  },
})

// 添加源文件
const sourceFile = project.addSourceFileAtPath('src/utils/helper.ts')

// 或者从字符串创建
const newSourceFile = project.createSourceFile(
  'temp.ts',
  `export function add(a: number, b: number) { return a + b }`,
  { overwrite: true }
)
```

### 3.2 ts-morph vs 原生 API 对比

```typescript
/**
 * 同样的任务：获取一个文件中所有导出的函数名和它们的参数列表
 */

// ═══════════════════════════════════════
// 原生 Compiler API 的做法
// ═══════════════════════════════════════

function getExportsNative(program: ts.Program, filePath: string) {
  const sourceFile = program.getSourceFile(filePath)!
  const checker = program.getTypeChecker()
  const results: { name: string; params: string[] }[] = []

  ts.forEachChild(sourceFile, node => {
    if (
      ts.isFunctionDeclaration(node) &&
      // 检查是否有 export 修饰符
      node.modifiers?.some(m => m.kind === ts.SyntaxKind.ExportKeyword)
    ) {
      const name = node.name!.getText()
      const params = node.parameters.map(p => p.name.getText())
      
      // 获取返回值类型
      const signature = checker.getSignatureFromDeclaration(node)
      const returnType = signature 
        ? checker.typeToString(checker.getReturnTypeOfSignature(signature))
        : 'unknown'
        
      results.push({ name, params })
    }
  })

  return results
}


// ═══════════════════════════════════════
// ts-morph 的做法（简洁得多！）
// ═══════════════════════════════════════

function getExportsMorph(sourceFile: SourceFile) {
  return sourceFile.getFunctions().map(fn => ({
    name: fn.getName(),
    params: fn.getParameters().map(p => ({
      name: p.getName(),
      type: p.getType().getText(),
    })),
    returnType: fn.getReturnType().getText(),
    isExported: fn.isExported(),
    isDefaultExport: fn.isDefaultExport(),
  }))
}

// 使用
const file = project.getSourceFile('src/utils/helper.ts')!
const exports = getExportsMorph(file)

console.log(exports)
// 输出：
// [
//   { name: 'add', params: [{ name: 'a', type: 'number' }, { name: 'b', type: 'number' }], returnType: 'number' }
// ]
```

**对比总结**：

| 维度 | 原生 API | ts-morph |
|------|---------|----------|
| **风格** | 函数式（大量 `ts.isXxx()` 判断 + 类型断言） | 面向对象（`.getXxx()` 方法链） |
| **导航** | `node.getChildAt(index)` 手动索引 | `.getParent()`, `.getChildren()` 语义清晰 |
| **修改** | 需要手动操作 AST 节点 | `.insertText()`, `.remove()`, `.rename()` 高级 API |
| **学习曲线** | 较陡峭，需理解编译器架构 | 平缓，API 设计直观 |
| **性能** | 更快（无额外开销） | 稍慢但通常可忽略 |
| **适用场景** | 性能敏感的工具、底层操作 | 大多数应用场景 |

```typescript
  }

  // 保存所有修改
  await project.save()

/**
 * 示例：自动添加 JSDoc 注释到所有公共方法
 */

async function generateJSDocs(project: Project) {
  for (const sourceFile of project.getSourceFiles()) {
    // 只处理 .ts 文件
    if (!sourceFile.getFilePath().endsWith('.ts')) continue

    for (const cls of sourceFile.getClasses()) {
      for (const method of cls.getInstanceMethods()) {
        // 跳过已经有 JSDoc 的方法
        if (method.getJsDocs().length > 0) continue

        // 跳过私有方法
        if (method.isPrivate()) continue
        
        // 构建注释内容
        const methodName = method.getName()
        const params = method.getParameters()
        const returnType = method.getReturnType()

        let doc = `/**\n`
        doc += ` * ${methodName} — 自动生成的文档\n`
        
        for (const param of params) {
          doc += ` * @param {${param.getType().getText()}} ${param.getName()}\n`
        }
        
        doc += ` * @returns {${returnType.getText()}}\n`
        doc += ` */`

        // 添加到方法前面
        method.insertBefore(doc)
      }
    }
  }

  await project.save()
}
```

### 3.4 用 ts-morph 进行代码生成

```typescript
/**
 * 示例：根据 OpenAPI 规范自动生成 TypeScript 类型定义
 */

interface ApiEndpoint {
  path: string
  method: 'GET' | 'POST' | 'PUT' | 'DELETE'
  summary: string
  request?: {
    body: Record<string, { type: string; required?: boolean }>
    params?: Record<string, { type: string }>
  }
  response: {
    [statusCode: string]: Record<string, { type: string; required?: boolean }>
  }
}

function generateTypesFromApi(endpoints: ApiEndpoint[], outputPath: string) {
  const project = new Project({
    useInMemoryFileSystem: true,
  })

  const sourceFile = project.createSourceFile(outputPath)

  // 添加文件头注释
  sourceFile.addStatements([
    '/**',
    ' * Auto-generated API types',
    ' * DO NOT EDIT MANUALLY',
    ' * Generated at: ' + new Date().toISOString(),
    ' */',
    '',
  ])

  // 为每个 endpoint 生成类型
  for (const ep of endpoints) {
    const typeName = `${ep.method}${ep.path.split('/').map(s => 
      s.charAt(0).toUpperCase() + s.slice(1)
    ).join('')}Request`

    // 请求类型
    if (ep.request?.body) {
      const props = Object.entries(ep.request.body).map(([name, info]) => {
        const prop = {
          name,
          type: info.type,
        }
        if (!info.required) (prop as any).hasQuestionToken = true
        return prop
      })

      sourceFile.addInterface({
        name: `${typeName}Body`,
        isExported: true,
        properties: props,
      })
    }

    // 响应类型
    for (const [code, schema] of Object.entries(ep.response)) {
      sourceFile.addInterface({
        name: `${typeName}Response_${code}`,
        isExported: true,
        properties: Object.entries(schema).map(([name, info]) => ({
          name,
          type: info.type,
          hasQuestionToken: !info.required,
        })),
      })
    }

    sourceFile.addBlankLine()
  }

  // 保存结果
  console.log(sourceFile.getText())
  // sourceFile.save()  // 写入磁盘
}
```

## 四、实战案例：构建自定义 Lint 规则

### 4.1 需求：禁止在 map/filter 中使用 async 回调

这是一个真实场景中的问题——很多人会在 `Array.map()` 中使用 `async` 回调，这会导致返回 Promise 数组而非预期的结果数组，容易引发隐蔽的 bug：

```typescript
// ❌ 常见错误
const results = items.map(async item => {
  return await fetchData(item.id)
})
// results 是 Promise<DataType>[]，而不是 DataType[]！

// ✅ 正确做法
const results = await Promise.all(
  items.map(item => fetchData(item.id))
)
```

### 4.2 实现 Lint 规则

```typescript
import * as ts from 'typescript'

/**
 * 自定义 Lint 规则：no-async-in-array-method
 *
 * 检测 Array.prototype.map/filter/reduce/find/some/every 中的 async 箭头函数
 */
class NoAsyncInArrayMethodRule implements ts.LintRules {
  private errors: { line: number; message: string }[] = []

  check(sourceFile: ts.SourceFile) {
    this.errors = []
    this.visit(sourceFile)
    return this.errors
  }

  private visit(node: ts.Node) {
    // 检查调用表达式
    if (ts.isCallExpression(node)) {
      this.checkArrayMethodCall(node)
    }

    node.forEachChild(n => this.visit(n))
  }

  private checkArrayMethodCall(callExpr: ts.CallExpression) {
    // 检查是否是 .map(), .filter() 等数组方法的调用
    const arrayMethods = ['map', 'filter', 'reduce', 'find', 'some', 'every']
    
    // 表达式形式：array.map(...)
    if (
      ts.isPropertyAccessExpression(callExpr.expression) &&
      arrayMethods.includes(callExpr.expression.name.text)
    ) {
      this.checkCallbackForAsync(callExpr.arguments[0])
    }
  }

  private checkCallbackForAsync(callback: ts.Expression | undefined) {
    if (!callback) return

    // 箭头函数：async (x) => ...
    if (ts.isArrowFunction(callback)) {
      if (callback.modifiers?.some(m => m.kind === ts.SyntaxKind.AsyncKeyword)) {
        const pos = callback.getStart(sourceFile)
        const lineAndChar = sourceFile.getLineAndCharacterOfPosition(pos)
        this.errors.push({
          line: lineAndChar.line + 1,
          message: `Don't use async callbacks in Array.${''}. Use Promise.all() instead.`,
        })
      }
    }
    
    // 普通函数表达式：async function(x) { ... }
    if (ts.isFunctionExpression(callback)) {
      if (callback.modifiers?.some(m => m.kind === ts.SyntaxKind.AsyncKeyword)) {
        const pos = callback.getStart(sourceFile)
        const lineAndChar = sourceFile.getLineAndCharacterOfPosition(pos)
        this.errors.push({
          line: lineAndChar.line + 1,
          message: `Don't use async callbacks in array methods. Use Promise.all() instead.`,
        })
      }
    }
  }
}
```

## 六、总结

Compiler API 是 TypeScript 生态中最强大但也最被低估的能力之一。它让你站在了和 TypeScript 团队同样的位置上——你能看到编译器看到的每一件事物。

**关键收获**：

1. **AST 是一切的起点**——无论你想做什么代码操作，首先学会遍历和理解 AST
2. **ts-morph 降低了门槛**——对于大多数应用场景，ts-morph 比原生 API 友好得多
3. **TypeChecker 是魔法所在**——绑定器和类型检查器赋予了 AST 语义层面的理解能力
4. **Visitor 模式是核心范式**——递归遍历 AST 是几乎所有代码操作的基础

> **一句话带走**：如果说写 TypeScript 是"说一门语言"，那么使用 Compiler API 就是"研究语言学"。当你掌握了 Compiler API，你就不再是代码的被动编写者，而是代码的主动驾驭者——你能让代码自我分析、自我修复、甚至自我生成。这是从程序员进化为编程语言工程师的关键一步。
