# 贡献 DefinitelyTyped —— 为开源库提交类型定义的完整流程

> **核心问题**：JavaScript 生态中有海量的优秀库没有内置 TypeScript 类型定义。DefinitelyTyped 项目通过 `@types/*` 包为这些库提供了社区维护的类型定义。本章将手把手教你如何为一个 JavaScript 库编写高质量的类型定义，并通过 PR 提交到 DefinitelyTyped，让你的贡献造福全球数百万 TypeScript 开发者。

---

## 一、DefinitelyTyped 是什么？

### 1.1 问题的起源

```
═══════════════════════════════════════════════════
            类型定义缺失的问题
═══════════════════════════════════════════════════

场景：你想在一个 TypeScript 项目中使用 lodash

import _ from 'lodash'

const result = _.map([1, 2, 3], n => n * 2)

// 💥 编译报错：
// Could not find a declaration file for module 'lodash'.
// 'lodash' implicitly has an 'any' type.

为什么？因为 lodash 是用纯 JavaScript 写的，
它自身不带 .d.ts 类型声明文件。

TypeScript 不知道这个模块导出了什么、
每个函数接受什么参数、返回什么类型...

于是它只能假设：嗯，lodash 导出的东西大概是 any 吧
→ 失去了所有的类型安全


解决方案：@types/lodash
───────────────
npm install --save-dev @types/lodash

安装后 TypeScript 立刻知道了一切：
_.map([1,2,3], n => n * 2)  // result: number[]
_.capitalize('hello')        // result: string
_.debounce(fn, 300)          // result: DebouncedFunc<typeof fn>

这些类型信息从哪里来？
→ 来自 DefinitelyTyped 项目！

═══════════════════════════════════════════════════
```

## 三、编写你的第一个类型定义

### 3.1 选择目标库

我们将以一个虚构的 JavaScript 库为例，演示完整流程：

```javascript
// ====== 这是一个叫 "fancy-util" 的 JS 工具库 ======

// 版本号
module.exports.version = '3.2.1'

// 字符串反转
function reverse(str) {
  return str.split('').reverse().join('')
}

// 深度合并对象
function deepMerge(target, ...sources) {
  const result = { ...target }
  for (const src of sources) {
    for (const key in src) {
      if (typeof src[key] === 'object' && src[key] !== null && !Array.isArray(src[key])) {
        result[key] = result[key] ? deepMerge(result[key], src[key]) : src[key]
      } else {
        result[key] = src[key]
      }
    }
  }
  return result
}

// 防抖函数
function debounce(fn, delay, options = {}) {
  let timerId
  let lastArgs
  let lastThis
  function debounced(...args) {
    lastArgs = args
    lastThis = this
    if (options.leading && !timerId) {
      fn.apply(this, args)
    }
    clearTimeout(timerId)
    timerId = setTimeout(() => {
      if (!options.trailing) return
      fn.apply(lastThis, lastArgs)
    }, delay)
  }
  debounced.cancel = () => clearTimeout(timerId)
  debounced.flush = () => {
    cancel()
    return fn.apply(lastThis, lastArgs)
  }
  return debounced
}

// 创建事件发射器
function createEmitter() {
  const listeners = {}
  return {
    on(event, handler) {
      ;(listeners[event] ??= []).push(handler)
      return () => off(event, handler)
    },
    off(event, handler) {
      const list = listeners[event]
      if (list) {
        const idx = list.indexOf(handler)
        if (idx > -1) list.splice(idx, 1)
      }
    },
    emit(event, ...args) {
      ;(listeners[event] ??= []).forEach(h => h(...args))
    },
    once(event, handler) {
      const wrapper = (...args) => {
        handler(...args)
        off(event, wrapper)
      }
      on(event, wrapper)
    },
  }
}

module.exports = { reverse, deepMerge, debounce, createEmitter }
```

### 3.2 创建类型定义文件

```typescript
/**
 * types/fancy-util/index.d.ts
 *
 * 这是 @types/fancy-util 的主入口文件
 */

// ========== 导出声明 ==========

// 声明版本常量（只读）
export const version: string

// ---------- reverse ----------
/**
 * 反转字符串
 * @param str 要反转的字符串
 * @returns 反转后的字符串
 */
export function reverse(str: string): string


// ---------- deepMerge ----------
/**
 * 深度合并多个对象
 * 后面的对象属性会覆盖前面的
 * 
 * 泛型设计要点：
 * - T 是目标对象的类型
 * - Sources 是要合并的源对象类型（可变参数）
 * - 返回类型是 T & 所有源类型的交叉
 */
export function deepMerge<T extends object, S extends object[]>(
  target: T,
  ...sources: S
): DeepMergeResult<T, S[number]>


// ---------- Debounce 相关类型 ----------

/**
 * 防抖选项
 */
export interface DebounceOptions {
  /** 是否在延迟开始时立即触发一次（默认 false）*/
  leading?: boolean
  /** 是否在延迟结束后触发最后一次（默认 true）*/
  trailing?: boolean
}

/**
 * 防抖后的函数类型
 * 
 * 在原函数的基础上增加了 .cancel() 和 .flush() 方法
 */
export interface DebouncedFunc<T extends (...args: any[]) => any> {
  (...args: Parameters<T>): ReturnType<T> | void
  /** 取消待执行的调用 */
  cancel(): void
  /** 立即执行待调用的调用（如有）并取消定时器 */
  flush(): ReturnType<T>
}

/**
 * 创建防抖函数
 * 
 * @param fn 要防抖的原函数
 * @param delay 延迟时间（毫秒）
 * @param options 防抖选项
 * @returns 防抖后的函数
 */
export function debounce<
  T extends (...args: any[]) => any
>(
  fn: T,
  delay: number,
  options?: DebounceOptions
): DebouncedFunc<T>


// ---------- EventEmitter 相关类型 ----------

/**
 * 通用的事件映射类型
 * 
 * Key = 事件名称
 * Value = 该事件处理器接收的参数元组
 * 
 * 例如：{ click: [x: number, y: number], keydown: [key: string] }
 */
export interface EventMap {
  [event: string]: unknown[]
}

/**
 * 事件监听器的移除函数
 * 调用它即可取消监听
 */
export type Unsubscribe = () => void

/**
 * 事件处理器函数
 */
export type EventHandler<T extends unknown[] = any[]> = (...args: T) => void

/**
 * 事件发射器接口
 */
export interface Emitter<M extends EventMap = EventMap> {
  /**
   * 监听事件
   * @param event 事件名称
   * @param handler 处理器函数
   * @returns 取消监听的函数
   */
  on<K extends keyof M & string>(
    event: K,
    handler: EventHandler<M[K]>
  ): Unsubscribe

  /**
   * 移除事件监听
   */
  off<K extends keyof M & string>(
    event: K,
    handler: EventHandler<M[K]>
  ): void

  /**
   * 触发事件
   * @param event 事件名称
   * @param args 传递给处理器的参数
   */
  emit<K extends keyof M & string>(event: K, ...args: M[K]): void

  /**
   * 监听一次性事件（触发后自动移除）
   */
  once<K extends keyof M & string>(
    event: K,
    handler: EventHandler<M[K]>
  ): Unsubscribe
}

/**
 * 创建一个新的事件发射器
 */
export function createEmitter<M extends EventMap = EventMap>(): Emitter<M>


// ========== 辅助类型（放在底部或单独文件）==========

/**
 * DeepMerge 的辅助类型
 * 递归地将两个对象类型深度合并
 */
type DeepMergeResult<T, S> = T & {
  [K in Exclude<keyof S, keyof T>]?: S[K]
} & {
  [K in keyof T & keyof S]:
    T[K] extends object
      ? S[K] extends object
        ? DeepMergeResult<T[K], S[K]>  // 递归合并嵌套对象
        : S[K]
      : S[K]
}
```

### 3.3 编写测试文件（至关重要！）

**DefinitelyTyped 要求每个类型定义都必须有对应的测试文件**。测试文件不仅是验证类型正确性的手段，也是未来维护者了解预期行为的最佳参考。

```typescript
// ====== types/fancy-util/test/main.ts ======

// 导入库
import {
  version,
  reverse,
  deepMerge,
  debounce,
  createEmitter,
} from 'fancy-util'


// ========== 测试 reverse ==========

const reversed: string = reverse('Hello')
// ✓ 返回类型是 string

// @ts-expect-error 数字不能传入
reverse(123)


// ========== 测试 deepMerge ==========

const merged1 = deepMerge(
  { a: 1, nested: { x: 'hello' } },
  { b: 2, nested: { y: 'world' } },
  { c: 3 }
)
// merged1 应该有 a, b, c, nested.x, nested.y 属性

merged1.a        // number ✓
merged1.b        // number ✓
merged1.c        // number ✓
merged1.nested.x // string ✓
merged1.nested.y // string ✓


// ========== 测试 debounce ==========

function myFunc(name: string, count: number): void {
  console.log(`${name}: ${count}`)
}

const debounced = debounce(myFunc, 300)
// debounced 的类型是 DebouncedFunc<typeof myFunc>

debounced('test', 42)  // ✓ 参数类型匹配

debounced.cancel()     // ✓ 有 cancel 方法
debounced.flush()      // ✓ 有 flush 方法，返回 void

// 带 options
const debounced2 = debounce(myFunc, 200, { leading: true, trailing: false })


// ========== 测试 createEmitter ==========

const emitter = createEmitter<{
  click: [x: number, y: number]
  message: [text: string, sender: string]
}>()

// on —— 返回 unsubscribe 函数
const unsub = emitter.on('click', (x, y) => {
  // x: number, y: number ✓
  console.log(`Clicked at (${x}, ${y})`)
})

unsub()  // Unsubscribe 类型 ✓

// emit —— 传递正确的参数
emitter.emit('click', 100, 200)
emitter.emit('message', 'hello', 'Alice')

// @ts-expect-error 缺少参数
emitter.emit('message', 'only one arg')

// once —— 一次性监听
emitter.once('message', (text, sender) => {
  console.log(`From ${sender}: ${text}`)
})


// 无泛型参数时 —— 宽松模式
const looseEmitter = createEmitter()
looseEmitter.on('any-event', (...args) => {
  // args: any[]
  console.log(args)
})
```

### 4.4 常见的 Review 意见及如何应对

Maintainer 可能会提出以下反馈（按频率排序）：

| 常见意见 | 含义 | 如何修正 |
|---------|------|---------|
| "Missing `@ts-expect-error` directives" | 你的测试没有覆盖错误场景 | 给预期报错的行加 `@ts-expect-error` |
| "Use `unknown` instead of `any`"` | 不应该出现 `any` 类型 | 将 `any` 替换为 `unknown` 或具体类型 |
| "Should use generics here" | 某个地方应该用泛型增加灵活性 | 添加适当的泛型参数 |
| "Missing JSDoc comments" | 公共 API 需要文档注释 | 为导出的类型和函数添加 `/** */` |
| "`strict` mode issues" | 代码不能通过 strict 模式 | 修复类型错误，通常是缺少 `undefined` 检查等 |
| "Consider using template literal types" | 某些字符串可以用模板字面量增强 | 如 CSS 类名、事件名等 |

## 五、高级技巧

### 5.1 处理复杂的泛型推断

```typescript
/**
 * 技巧：使用 infer 来推导回调函数的参数类型
 * 这样用户在使用时就不用手动指定泛型参数了
 */

// 库提供的 forEach 函数
export function forEach<T>(
  obj: Record<string, T>,
  callback: (key: string, value: T, obj: Record<string, T>) => void | boolean
): void

// 用户使用时完全不需要写 <string, number> —— 自动推断
forEach({ a: 1, b: 2 }, (key, value, originalObj) => {
  // key: string ✓
  // value: number ✓（从对象值推断出来的）
  // originalObj: Record<string, number> ✓
})
```

### 5.2 处理模块格式的差异

不同的 JS 库有不同的模块格式，类型定义需要适配：

```typescript
// ====== CommonJS 格式（require/module.exports）=====

// 原库：module.exports = { foo: ... }
// 类型定义：
declare function foo(): string
export = foo

// 或者多导出：
declare namespace foo {
  export function bar(): number
  export const baz: string
}
export = foo


// ====== ES Module 格式（export/import）=====

// 原库：export function foo() {}
// 类型定义：
export function foo(): string
export function bar(): number


// ====== UMD 格式（通用）=====

// 同时支持 CJS 和 ESM
export as namespace foo
export function foo(): string
```

### 5.3 处理版本兼容性

当原库发布新 API 时，类型定义也需要更新：

```typescript
/**
 * 技巧：用条件类型处理新旧版本的 API 差异
 */

// 假设 v3.0 新增了 optional 参数
export function processData(
  input: string,
  options?: ProcessDataOptions
): ResultData

// v2.x 只有两个参数
// v3.x 有可选的第三个选项参数
// 通过 ? 让两种用法都合法

interface ProcessDataOptions {
  format?: 'json' | 'xml' | 'csv'
  encoding?: 'utf-8' | 'ascii'
  validate?: boolean
}
```

### 5.4 利用 dts-gen 快速起步

如果你面对的是一个很大的库，可以先用微软官方的工具快速生成初版类型定义：

```bash
# 安装 dts-gen
npm install -g dts-gen

# 从 npm 包生成初始类型定义（基于运行时反射）
dts-gen -m fancy-util

# 生成的文件质量参差不齐，但它提供了一个好的起点
# 你需要在它的基础上：
# 1. 把 any 替换成具体的类型
# 2. 添加泛型支持
# 3. 补充 JSDoc 文档
# 4. 编写全面的测试
```

## 八、总结

贡献 DefinitelyTyped 是每一位 TypeScript 开发者都能参与的、最有价值的开源活动之一。它不需要你是一个编程天才，只需要你愿意花时间去仔细阅读一个库的 API，然后用 TypeScript 的类型系统精确地描述它。

**核心心法**：

```
╔══════════════════════════════════════════════════════════╗
║                                                          ║
║  贡献 DT 的四层境界                                       ║
║                                                          ║
║  Level 1: 能跑就行                                        ║
║    用 dts-gen 生成初版，基本能用                           ║
║                                                          ║
║  Level 2: 类型正确                                        ║
║    手动完善所有 any，保证类型安全和自动补全                 ║
║                                                          ║
║  Level 3: 优雅好用                                        ║
║    泛型推断流畅、JSDoc 完善、边缘情况都考虑到              ║
║                                                          ║
║  Level 4: 艺术品级别                                      ║
║    类型即文档、类型即教程、使用者无需查阅其他资料          ║
║                                                          ║
║  目标：至少达到 Level 2，争取 Level 3                     ║
║                                                          ║
╚══════════════════════════════════════════════════════════╝
```

> **一句话带走**：每一次 `@types` 的贡献都是一座桥——连接着 JavaScript 的自由海洋和 TypeScript 的安全港湾。当你为一个没有类型的库写出精准的定义，你不仅仅是在"修类型"，而是在帮助全世界使用这个库的开发者写出更安全、更高效的代码。这就是开源最美的地方——你的几小时付出，可以节省无数人的调试时间。
