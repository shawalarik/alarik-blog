# 数据类型全景图 —— 7种原始类型 + 引用类型，typeof 陷阱，instanceof 原理

> **核心内容**：JavaScript 的类型系统是整个语言的基石。本文将从底层实现的角度，系统讲解 JavaScript 的 **8 种数据类型**（7 种原始类型 + 1 种引用类型），深入剖析 `typeof` 的历史遗留陷阱、`instanceof` 的原型链查找原理，以及包装对象的隐式转换机制。

## 一、JavaScript 类型总览

### 1.1 为什么先要理解类型？

在 JavaScript 中，**每个值都属于且仅属于一种类型**。类型决定了引擎如何存储这个值、如何对它进行操作、以及它能参与哪些运算。不理解类型，就无法真正理解后续的类型转换、相等比较、运算符行为等一切核心概念。

《你不知道的JavaScript（上卷）》开篇就强调：

> "JavaScript 的类型系统看似简单，实则暗藏玄机。很多令人困惑的行为，归根结底都是因为对类型的理解不够深入。"

### 1.2 八大类型全景图

ECMAScript 规范明确定义了 **8 种类型**（ES2020 起）：

```
JavaScript 类型体系
├── 原始类型（Primitive Types）—— 7 种
│   ├── Undefined    —— undefined
│   ├── Null         —— null
│   ├── Boolean      —— true / false
│   ├── String       —— "hello"
│   ├── Number       —— 42, 3.14, NaN, Infinity
│   ├── Symbol       —— Symbol("id")        （ES6 新增）
│   └── BigInt       —— 9007199254740991n    （ES2020 新增）
│
└── 对象类型（Object Type）—— 1 种
    ├── 普通对象     —— { name: "Alice" }
    ├── 数组         —— [1, 2, 3]
    ├── 函数         —— function() {}
    ├── 日期         —— new Date()
    ├── 正则         —— /pattern/
    ├── Map / Set    —— new Map(), new Set()
    └── ...其他内置对象
```

::: tip 核心要点
原始类型和对象类型最本质的区别是：**原始类型是不可变的（immutable）的，而对象类型是可变的（mutable）的**。这是理解整个类型系统的第一块基石。
:::

### 1.3 原始类型的"不可变性"

当我们说一个原始值是不可变的，意思是：**你无法修改它本身，任何看起来像是在"修改"的操作，实际上都创建了一个新值**：

```javascript
// 字符串的不可变性
let str = "hello";
str[0] = "H";          // 尝试修改第一个字符
console.log(str);       // "hello" —— 没有变化！原始字符串不会被修改
str = str.toUpperCase(); // 这不是修改，而是创建了一个新字符串 "HELLO"
console.log(str);       // "HELLO"

// 数字的不可变性
let num = 100;
num.toFixed(2);         // 返回新字符串 "100.00"，num 本身不变
console.log(num);       // 100

// 布尔值的不可变性
let flag = true;
flag.toString();        // 返回 "true"，flag 本身不变
console.log(flag);      // true
```

**通俗类比**：原始值就像刻在石碑上的文字——一旦刻好，你就无法擦掉某个字重新写。你只能另找一块新石碑，重新刻上修改后的内容。而对象就像一块白板，你可以随时在上面擦除、涂改、添加内容。

```javascript
// 对象的可变性（对比）
let user = { name: "Alice", age: 25 };
user.name = "Bob";      // ✅ 直接修改了对象本身！
user.city = "Beijing";  // ✅ 直接添加新属性
console.log(user);      // { name: "Bob", age: 25, city: "Beijing" }
```

## 二、七大原始类型逐一详解

### 2.1 Undefined 类型

`undefined` 类型只有一个值：`undefined`。它表示**"缺少值"**或**"声明了但未赋值"**的状态。

```javascript
let x;                    // 声明了但未赋值
console.log(x);           // undefined
console.log(typeof x);    // "undefined"

let y = undefined;        // 显式赋值为 undefined（不推荐）
console.log(y);           // undefined
```

**`undefined` 出现的场景**：

| 场景 | 示例 | 说明 |
|------|------|------|
| 变量未赋值 | `let x;` → `x === undefined` | 最常见的场景 |
| 访问不存在的属性 | `obj.unknownProp` | 不报错，返回 undefined |
| 函数无 return | `function f() {}` → `f() === undefined` | 隐式返回 undefined |
| 函数参数缺失 | `f(a)` 中 `a` 未传时为 undefined | 参数默认值机制的基础 |
| `void` 运算符 | `void 0` | 一种获取 undefined 的可靠方式 |

**为什么推荐用 `void 0` 而不是直接用 `undefined`？**

```javascript
// 在极少数情况下，undefined 可能被覆盖（非严格模式中）
var undefined = "Oops";   // 竟然可以这样做！（不要这么做）

console.log(undefined);   // "Oops"  —— 已经不是我们期望的那个 undefined 了！

// void 0 是绝对可靠的
const safeUndefined = void 0;  // 无论什么环境，始终返回真正的 undefined
console.log(safeUndefined);    // undefined ✓
```

::: warning 重要提示
在 ES5+ 的严格模式以及现代模块化环境中，全局 `undefined` 已被设为只读属性，无法被覆盖。但在维护老旧代码时，仍需注意这一隐患。`void 0` 是获取 `undefined` 最安全的方式。
:::

**通俗类比**：`undefined` 就像一个**空白的快递包裹标签**。你知道这里应该有个东西（地址栏存在），但上面什么都没填——既没有寄件人信息，也没有物品描述。它代表一种"尚未定义"的状态，与"明确为空"有本质区别。

### 2.2 Null 类型

`null` 类型同样只有一个值：`null`。它表示**"有意为之的空值"**或**"无对象指向"**。

```javascript
let data = null;           // 明确表示 data 当前没有有效数据
console.log(typeof null);  // "object" ← 这是著名的 typeof 陷阱！

// 典型用法场景
let result = findUserById(123);
if (result === null) {     // 明确区分"找到了但为空"和"没找到"
  console.log("用户不存在");
}
```

#### `null` vs `undefined` 的本质区别

这是一个面试必考题，也是日常开发中最容易混淆的概念之一：

| 特征 | `undefined` | `null` |
|------|------------|--------|
| 含义 | **缺少值**（系统级的、出乎意料的） | **有意为空**（程序级的、正常的） |
| 谁来设置 | JavaScript 引擎自动赋予 | 由开发者主动赋值 |
| 是否需要显式使用 | 通常不需要 | 需要主动使用 |
| `==` 比较 | `null == undefined` 为 `true` | 同左 |
| `===` 比较 | `null !== undefined` | 同左 |

```javascript
// 实际开发中的典型区别
function getFirstElement(arr) {
  if (!arr) {
    return undefined;   // 异常情况：参数无效，调用方应检查
  }

  if (arr.length === 0) {
    return null;        // 正常情况：数组为空，但没有错误
  }

  return arr[0];
}

let result1 = getFirstElement(null);   // 返回 undefined（传入非法参数）
let result2 = getFirstElement([]);     // 返回 null（数组合法但为空）
let result3 = getFirstElement([1,2]);  // 返回 1（正常结果）

// 调用方的判断逻辑
if (result1 === undefined) { /* 处理参数异常 */ }
if (result2 === null) { /* 处理空数组 */ }
if (result3 !== undefined && result3 !== null) { /* 使用正常结果 */ }
```

**通俗类比**：
- `undefined` 是**你问前台"我的快递到了吗？"，前台一脸茫然说"我不知道你说的什么"**——信息完全缺失。
- `null` 是**你问前台，前台查了一下记录后告诉你"确实没有你的快递"**——信息完整，结果是"无"。

### 2.3 Boolean 类型

布尔类型只有两个值：`true` 和 `false`。它是所有条件判断（`if`/`for`/`while`/`?:`）的核心基础。

```javascript
let isOnline = true;
let hasPermission = false;

// 布尔值常用于控制流程
if (isOnline) { /* 用户在线时的操作 */ }
while (!hasPermission) { /* 等待权限 */ }
```

** falsy 值表**（会被转换为 `false` 的值）：

| 值 | 类型 | `Boolean()` 结果 |
|---|------|-----------------|
| `false` | Boolean | false（本身就是） |
| `0` / `-0` | Number | false |
| `0n` | BigInt | false |
| `""` | String | false |
| `null` | Null | false |
| `undefined` | Undefined | false |
| `NaN` | Number | false |

**除此之外的所有值都是 truthy**（包括 `"0"`、`"false"`、`[]`、`{}` 等）。

```javascript
// 经典的 falsy 陷阱
if (0)         { console.log("不会执行"); }  // 0 是 falsy
if ("")        { console.log("不会执行"); }  // 空字符串是 falsy
if ("0")       { console.log("会执行"); }    // 非空字符串是 truthy！
if ([])        { console.log("会执行"); }    // 空数组是 truthy！
if ({})        { console.log("会执行"); }    // 空对象是 truthy！
if (NaN)       { console.log("不会执行"); }  // NaN 是 falsy
if (null)      { console.log("不会执行"); }  // null 是 falsy
if (undefined) { console.log("不会执行"); }  // undefined 是 falsy
```

**通俗类比**：布尔值就像电路中的**开关**——只有开（true）和关（false）两种状态。而 JavaScript 中的" falsy 值"就像是各种形式的"断路"：零电量（0）、断开的线路（空字符串）、不存在的连接（null/undefined）、损坏的信号（NaN）。只要不是这些特殊情况，JavaScript 就认为开关是"接通"的（truthy）。

### 2.4 String 类型

String 类型表示文本数据。JavaScript 中的字符串是 **UTF-16 编码**的字符序列。

#### 字符串创建方式

```javascript
// 方式一：单引号（推荐）
let single = 'Hello World';

// 方式二：双引号
let double = "Hello World";

// 方式三：反引号（模板字符串，ES6）
let name = "Alice";
let template = `Hello, ${name}!`;   // 支持插值和多行
```

#### 字符串的不可变性（再次强调）

```javascript
let str = "JavaScript";

// 所有"修改"方法都不会改变原字符串
console.log(str.toUpperCase());   // "JAVASCRIPT"
console.log(str.slice(0, 4));     // "Java"
console.log(str.replace("a", "A")); // "JAvaScript"
console.log(str);                 // "JavaScript" —— 原封不动！

// 要得到"修改后"的结果，必须重新赋值
str = str.toUpperCase();           // 创建新字符串并赋值给 str
console.log(str);                 // "JAVASCRIPT"
```

#### 特殊字符与 Unicode

```javascript
// 转义字符
let quote = 'It\'s a nice day';     // 单引号内的单引号
let newline = "Line1\nLine2";        // \n 换行
let tab = "Col1\tCol2";             // \t 制表符
let backslash = "C:\\Users\\admin"; // \\ 反斜杠

// Unicode 表示法
let heart = "\u2764";               // ❤️
let emoji = "\u{1F600}";            // 😊（ES6 大括号语法支持码点 > 0xFFFF）

// 字符串长度与码点的差异（常见坑）
let smile = "😊";
console.log(smile.length);          // 2！（占用两个 UTF-16 编码单元）
console.log([...smile].length);     // 1（正确计数，使用展开运算符拆分为数组）
console.log(smile.codePointAt(0));  // 128512（正确的 Unicode 码点）
```

**通俗类比**：字符串就像一卷**已经印刷好的胶带**。你不能擦掉胶带上已有的文字再重新书写——你只能剪下一截新的胶带，在上面印上新文字，然后把旧的那段换掉。

### 2.5 Number 类型

JavaScript 的 Number 类型是一个**奇特的设计**：它同时表示整数和浮点数，采用 IEEE 754 双精度浮点数标准（64 位）存储。

#### 数字的各种形态

```javascript
// 整数
let integer = 42;

// 浮点数
let float = 3.14159;

// 科学计数法
let big = 3e8;              // 300000000（3 × 10^8）
let tiny = 1e-6;           // 0.000001

// 特殊数值
let infinity = Infinity;    // 正无穷
let negInfinity = -Infinity; // 负无穷
let nan = NaN;              // Not a Number（不是一个数字）

// 不同方式产生 NaN
console.log(0 / 0);        // NaN
console.log("abc" * 2);    // NaN
console.log(NaN + 1);      // NaN（NaN 与任何值的运算结果都是 NaN）
console.log(NaN === NaN);  // false（NaN 不等于任何值，包括自己！）
```

#### 浮点数的精度问题（重要！）

这是 Number 类型最容易踩坑的地方：

```javascript
// 经典的 0.1 + 0.2 ≠ 0.3
console.log(0.1 + 0.2);           // 0.30000000000000004

// 为什么？
// 0.1 在二进制中是无限循环小数，无法精确表示
// 类似于十进制中 1/3 = 0.333... 无法精确写出一样

// 解决方案一：使用 toFixed 格式化输出
let sum = 0.1 + 0.2;
console.log(sum.toFixed(2));      // "0.30"（字符串形式）

// 解决方案二：使用整数运算（金额计算等场景推荐）
let price = 10;                   // 以"分"为单位而非"元"
let tax = 3;
let total = price + tax;          // 13（精确！）
console.log(total / 100 + "元");  // "0.13元"

// 解决方案三：使用 ES2020 的 Math.round 方法
// 或使用第三方库如 decimal.js、bignumber.js

// 整数安全范围
console.log(Number.MAX_SAFE_INTEGER);  // 9007199254740991 (2^53 - 1)
console.log(Number.MIN_SAFE_INTEGER);  // -9007199254740991 (-(2^53 - 1))

// 超出安全范围的整数运算会丢失精度
console.log(Number.MAX_SAFE_INTEGER + 1 === Number.MAX_SAFE_INTEGER + 2); // true！
// 9007199254740992 === 9007199254740993 —— 它们被当成同一个数了！
```

**IEEE 754 存储结构**（《你不知道的JavaScript》第2章详解）：

```
64位双精度浮点数结构:
┌────┬─────────────┬──────────────────────────────┐
│符号 │   指数部分    │         尾数部分             │
│ 1位 │    11位      │          52位                │
└────┴─────────────┴──────────────────────────────┘

示例：0.1 的二进制存储
符号 = 0（正数）
指数 = 01111111011（-4 的偏移表示）
尾数 = 1001100110011001100110011001100110011001100110011010（无限循环，被截断！）
→ 所以 0.1 无法精确表示
```

**通俗类比**：Number 类型就像一把**只能精确到毫米的尺子**——测量几厘米的东西没问题，但如果让你测量原子级别的距离（比如 0.1 + 0.2 这种涉及二进制无限循环的情况），尺子的精度就不够用了，会出现微小的误差。而超出安全范围的大整数就像是用这把尺子去测量星际距离——读数已经不再准确。

### 2.6 Symbol 类型（ES6）

Symbol 是 ES6 新增的原始类型，用于创建**唯一的标识符**。它的最大用途是为对象添加**不会与其他属性冲突的私有属性名**。

#### 基本特性

```javascript
// 创建 Symbol —— 每次调用 Symbol() 都会产生一个全新的唯一值
let id1 = Symbol("description");
let id2 = Symbol("description");

console.log(id1 === id2);   // false！即使描述相同，它们也不相等

// Symbol 作为对象属性的键
let user = {
  name: "Alice",
  [id1]: "内部ID_12345",    // 使用 [ ] 语法将 Symbol 作为计算属性名
  [id2]: "权限标记_admin",
};

console.log(user[id1]);      // "内部ID_12345"
console.log(user[id2]);      // "权限标记_admin"

// 用 Symbol 做键的属性，不会被普通遍历访问到
for (let key in user) {
  console.log(key);          // 只输出 "name"（Symbol 属性被隐藏了）
}

console.log(Object.keys(user));     // ["name"]
console.log(JSON.stringify(user));  // {"name":"Alice"}（Symbol 属性被忽略）
```

#### 全局 Symbol 注册表

```javascript
// 通过 Symbol.for() 从全局注册表中获取/创建 Symbol
let globalId = Symbol.for("app.id");
let sameGlobalId = Symbol.for("app.id");

console.log(globalId === sameGlobalId);  // true！（从同一个注册表中取出来的）

// 通过 keyFor 反向查找注册名
console.log(Symbol.keyFor(globalId));   // "app.id"
console.log(Symbol.keyFor(Symbol()));   // undefined（非全局 Symbol 无注册名）
```

#### 内置 Symbol（Well-known Symbols）

JavaScript 内置了许多具有特殊含义的 Symbol，用于自定义对象的核心行为：

| 内置 Symbol | 用途 | 示例 |
|------------|------|------|
| `Symbol.iterator` | 使对象可迭代 | `for..of` / 展开运算符依赖此接口 |
| `Symbol.toPrimitive` | 自定义对象转原始值的行为 | `obj + ""` 时触发 |
| `Symbol.toStringTag` | 自定义 `toString` 的标签 | `[object MyArray]` |
| `Symbol.species` | 派生对象构造 | `Array.map` 返回的对象类型 |
| `Symbol.hasInstance` | 自定义 `instanceof` 行为 | `obj instanceof MyClass` |

```javascript
// 示例：让普通对象可迭代
let iterableObj = {
  items: ["apple", "banana", "cherry"],
  [Symbol.iterator]() {
    let index = 0;
    let items = this.items;
    return {
      next() {
        if (index < items.length) {
          return { value: items[index++], done: false };
        }
        return { done: true };
      },
    };
  },
};

for (let fruit of iterableObj) {
  console.log(fruit);  // "apple" → "banana" → "cherry"
}

// 展开运算符也生效
console.log([...iterableObj]);  // ["apple", "banana", "cherry"]
```

**通俗类比**：Symbol 就像**独一无二的身份证号码**。即使两个人的名字相同（Symbol 描述相同），他们的身份证号也绝不相同。而且 Symbol 属性就像贴在物品背面的**隐形标签**——平时看不到（`for...in` 遍历不到），但需要时可以精准地通过身份证号找到对应物品。

### 2.7 BigInt 类型（ES2020）

BigInt 用于表示**任意精度的整数**，解决了 Number 类型安全范围有限的问题（Number 只能安全表示 ±2^53 - 1 以内的整数）。

#### 创建和使用

```javascript
// 方式一：字面量（加 n 后缀）
let bigNum = 9007199254740993n;  // 注意 n 后缀

// 方式二：构造函数
let alsoBig = BigInt("9007199254740993");

// 对比 Number 的精度问题
let num = 9007199254740993;       // Number 类型
console.log(num);                  // 9007199254740992（精度丢失！）
console.log(bigNum);               // 9007199254740993n（精确！）
```

#### 运算规则

```javascript
// 支持：加减乘除、幂运算、位运算
console.log(100n + 50n);           // 150n
console.log(9999999999999999n * 2n); // 19999999999999998n
console.log(10n ** 20n);           // 100000000000000000000n

// 不支持：与 Number 混合运算（需显式转换）
// console.log(100n + 50);          // TypeError!
console.log(100n + BigInt(50));    // 150n（正确做法）

// 除法会向下取整（不是四舍五入）
console.log(10n / 3n);             // 3n（类似 Math.floor）

// 比较运算可以跨类型
console.log(100n === 100);        // false（不同类型！）
console.log(100n == 100);         // true（宽松比较会进行类型转换）
console.log(100n > 99);           // true（跨类型比较正常工作）
```

**何时使用 BigInt**？

| 场景 | 推荐类型 |
|------|---------|
| 普通 ID、索引、计数器 | `Number`（性能更好） |
| 超大整数（超过 2^53）、时间戳（微秒级）、密码学 | `BigInt` |
| JSON 序列化的字段 | `Number`（BigInt 不能 JSON 化） |

::: warning 注意事项
1. `BigInt` **不能**与 `Math` 对象的方法一起使用（`Math.max(1n, 2n)` 会报错）
2. `JSON.stringify()` **不支持** BigInt（会抛出 TypeError）
3. `BigInt` 和 `Number` 之间的**隐式转换是不允许的**
4. 一元 `+` 运算符不能用于 `BigInt`（`+1n` 报错）
:::

## 三、对象类型（Reference Type）

### 3.1 对象的本质

除了 7 种原始类型之外，JavaScript 中的一切**非原始值**都属于 Object 类型。这包括：

```javascript
// 普通对象
let obj = { name: "Alice" };

// 数组（特殊的对象）
let arr = [1, 2, 3];

// 函数（特殊的对象，可调用）
function greet(name) { return `Hello, ${name}`; }

// 其他内置对象
let date = new Date();
let regex = /pattern/gi;
let map = new Map();
let set = new Set();

// 验证它们的 typeof
console.log(typeof obj);    // "object"
console.log(typeof arr);    // "object"（注意：数组也是 object！）
console.log(typeof greet);  // "function"
console.log(typeof date);   // "object"
console.log(typeof regex);  // "object"
```

### 3.2 原始类型 vs 引用类型的内存模型

这是理解两种类型差异的关键：

```javascript
// 原始类型 —— 值直接存储在变量中
let a = 100;          // 变量 a 的内存中直接存放着数字 100
let b = a;            // 将 a 的值复制一份给 b（值拷贝）
b = 200;              // 修改 b
console.log(a);       // 100（a 不受影响）

// 对象类型 —— 变量存储的是"引用"（地址）
let obj1 = { count: 100 };  // obj1 存储的是一个内存地址（指针）
let obj2 = obj1;             // 将 obj1 的引用复制给 obj2（两者指向同一对象）
obj2.count = 200;            // 通过 obj2 修改对象
console.log(obj1.count);     // 200（obj1 也受到了影响！）
```

**图解说明**：

```
原始类型（值拷贝）：
  ┌─────┐     ┌─────┐
  │ a=100│ ──>│ b=100│ → b=200 后：a=100, b=200（互不影响）
  └─────┘     └─────┘

引用类型（引用拷贝）：
  ┌─────┐          ┌──────────────┐
  │ obj1│ ───────> │ {count: 100} │ <──────┐
  └─────┘          └──────────────┘        │
                                           ▼
  ┌─────┐          ┌──────────────┐   obj2.count = 200
  │ obj2│ ───────> │ {count: 200} │   （修改的是同一个对象！）
  └─────┘          └──────────────┘
```

**通俗类比**：
- **原始类型**就像**复印文件**——你有一份原件（a），复印了一份给朋友（b）。你在复印件上乱涂乱画，原件不受影响。
- **引用类型**就像**共享的在线文档链接**——你把文档链接发给了朋友（obj2 = obj1）。朋友打开文档做了修改，你再打开看的时候，文档已经被改了——因为你们操作的是同一个文档。

## 四、typeof 操作符 —— 深入解析

### 4.1 typeof 的基本用法

`typeof` 是 JavaScript 中检测基本类型的最简单工具：

```javascript
typeof undefined;     // "undefined"
typeof true;          // "boolean"
typeof 42;            // "number"
typeof "hello";       // "string"
typeof Symbol();      // "symbol"
typeof 100n;          // "bigint"
typeof null;          // "object" ← ！！！著名的 Bug !!!
typeof {};            // "object"
typeof [];            // "object"
typeof function(){}; // "function"
```

### 4.2 typeof null === "object" —— 历史上最大的 Bug

这是 JavaScript 最著名的设计缺陷之一，至今已存在近 **30 年**。

**为什么会这样？**

根据 Brendan Eich（JavaScript 之父）的自述和《你不知道的JavaScript》第1章的分析：

> JavaScript 最初的类型系统使用**低位机器码**来区分值类型：
> - `000` → 对象
> - `001` → 整数
> - `010` → 浮点数
> - `100` → 字符串
> - `110` → 布尔值
>
> 而 `null` 在底层被表示为**全零**（`00000000`）。当 `typeof` 操作符读取类型标志位时，发现前三位是 `000`，于是判定为"对象"。这就是 `typeof null === "object"` 的根本原因。

```javascript
// 这个 Bug 的影响
typeof null;              // "object"（应该是 "null"）

// 导致的误判风险
function process(data) {
  if (typeof data === "object") {
    // 这里期望 data 是一个对象...
    // 但如果 data === null，就会出错！
    data.name = "test";   // TypeError: Cannot set property 'name' of null
  }
}

process(null);            // 💥 炸了！
```

**为什么一直不改？**

根据 TC39（JavaScript 标准委员会）的讨论记录：

1. **Web 兼容性**：太多现有代码依赖 `typeof null === "object"` 来做兼容性判断
2. **修复代价太大**：一旦修复，大量网站可能崩溃
3. **替代方案成熟**：`data !== null && typeof data === "object"` 已成为通用写法

::: tip 最佳实践
检测"是否为纯对象"（排除 null）的安全写法：
```javascript
// 写法一：显式排除 null
if (typeof value === "object" && value !== null) { /* 是对象 */ }

// 写法二：利用 null 是 falsy 的特性（更简洁）
if (typeof value === "object" && value) { /* 是对象 */ }

// 写法三：使用 Object.prototype.toString（最准确）
Object.prototype.toString.call(null);    // "[object Null]"
Object.prototype.toString.call([]);      // "[object Array]"
Object.prototype.toString.call({});     // "[object Object]"
Object.prototype.toString.call(/reg/);  // "[object RegExp]"
```
:::

### 4.3 typeof 的特殊行为

#### 未声明的变量

`typeof` 是 JavaScript 中**唯一能在变量未声明时不报错**的操作符：

```javascript
console.log(undeclaredVar);     // ReferenceError: undeclaredVar is not defined
console.log(typeof undeclaredVar); // "undefined"（不报错！）

// 这使得 typeof 成为一种安全的特征检测方式
if (typeof someAPI !== "undefined") {
  someAPI.doSomething();
}
```

**为什么 `typeof` 能做到这一点？**

这是因为 `typeof` 在引擎层面是一种**特殊查询**，它在编译阶段就能确定变量的类型标签，而不需要在运行时访问变量的值。对于从未声明的变量，`typeof` 直接返回 `"undefined"` 而不触发 `ReferenceError`。

::: warning 但 TDZ 中的变量除外
前面提到过暂时性死区（TDZ）：虽然 `typeof` 对未声明的变量安全，但对**已声明但处于 TDZ 中**的变量会报错：
```javascript
{
  // console.log(typeof tdzVar);  // ReferenceError!（TDZ 中的变量）
  let tdzVar = 42;
}
```
:::

## 五、instanceof 操作符 —— 原型链上的查找

### 5.1 instanceof 的基本用法

`instanceof` 用于检测**构造函数的原型是否存在于对象的原型链上**：

```javascript
let arr = [1, 2, 3];
console.log(arr instanceof Array);       // true
console.log(arr instanceof Object);      // true（Array 的原型链上有 Object）

let date = new Date();
console.log(date instanceof Date);       // true
console.log(date instanceof Object);     // true

let literalObj = {};
console.log(literalObj instanceof Object);  // true
console.log(literalObj instanceof Array);   // false
```

### 5.2 instanceof 的底层原理

`instanceof` 的实际工作过程是**沿着原型链向上查找**：

```javascript
// 手动模拟 instanceof 行为
function myInstanceOf(instance, constructor) {
  // 如果 instance 不是对象（或为 null），直接返回 false
  if (instance == null || (typeof instance !== "object" && typeof instance !== "function")) {
    return false;
  }

  // 获取构造函数的 prototype
  let prototype = constructor.prototype;

  // 从实例的 [[Prototype]] 开始，沿链向上查找
  let currentProto = Object.getPrototypeOf(instance);

  while (currentProto !== null) {
    if (currentProto === prototype) {
      return true;  // 找到了！
    }
    currentProto = Object.getPrototypeOf(currentProto);  // 继续向上找
  }

  return false;  // 到达原型链顶端（null），仍未找到
}
```

**图解查找过程**（以 `[] instanceof Array` 为例）：

```
[]
  │
  ├─ [[Prototype]] ──> Array.prototype  ←── Array.prototype === Array.prototype ? YES! ✓
  │                        │
  │                     [[Prototype]] ──> Object.prototype
  │                                          │
  │                                       [[Prototype]] ──> null（原型链终点）
```

### 5.3 instanceof 的局限性与注意事项

```javascript
// 局限 1：原始值永远返回 false
console.log(42 instanceof Number);       // false（原始值不是对象）
console.log("hello" instanceof String);  // false
// 但包装对象可以
console.log(new Number(42) instanceof Number);  // true

// 局限 2：跨 iframe/窗口的 Array 判断失败
// iframe 中的数组 instanceof 主窗口的 Array → false
// 因为每个窗口有自己的全局环境，Array 构造函数不同

// 局限 3：可以通过修改原型链欺骗 instanceof
let fakeArr = { __proto__: Array.prototype };
console.log(fakeArr instanceof Array);  // true！（但它不是真的数组）
```

**最佳实践**：

```javascript
// 推荐的精确类型检测方案
function getType(value) {
  // null 的特殊处理
  if (value === null) return "Null";

  // 原始类型：用 typeof
  const primType = typeof value;
  if (primType !== "object" && primType !== "function") {
    return primType.charAt(0).toUpperCase() + primType.slice(1); // 首字母大写
  }

  // 引用类型：用 toString
  return Object.prototype.toString.call(value).slice(8, -1);
}

// 测试
getType(undefined);     // "Undefined"
getType(null);         // "Null"
getType(true);         // "Boolean"
getType(42);           // "Number"
getType("hello");      // "String"
getType(Symbol());     // "Symbol"
getType(100n);         // "Bigint"
getType({});           // "Object"
getType([]);           // "Array"
getType(function(){})  // "Function"
getType(/regex/);      // "RegExp"
getType(new Date());   // "Date"
getType(new Map());    // "Map"
```

## 六、包装对象（Wrapper Objects）—— 原始值的"伪装"

### 6.1 什么是包装对象？

你可能有过这样的疑问："既然原始值不是对象，那为什么 `'hello'.toUpperCase()` 可以正常调用呢？"

答案就是**包装对象**（也叫"临时对象"或"自动装箱"）。

```javascript
let str = "hello";

// 当你调用 str.toUpperCase() 时，JavaScript 引擎幕后做了以下事情：

// 第一步：创建一个临时的 String 包装对象
let tempStr = new String(str);

// 第二步：在包装对象上调用方法
let result = tempStr.toUpperCase();

// 第三步：销毁临时对象（立即释放）
tempStr = null;

// 最终效果就像原始字符串自带了方法
console.log(result);  // "HELLO"
```

**三种原始类型对应的包装对象**：

| 原始类型 | 包装构造函数 | 主要提供的方法 |
|---------|-----------|--------------|
| string | `String` | `toUpperCase()`, `slice()`, `charAt()`, `includes()` 等 |
| number | `Number` | `toFixed()`, `toPrecision()`, `toString()` 等 |
| boolean | `Boolean` | 几乎不用（极少手动使用） |

### 6.2 包装对象的"一次性"特性

```javascript
let str = "myString";
str.testProp = "added";    // ① 创建 String 包装对象，添加 testProp
                            // ② 立即销毁该包装对象

console.log(str.testProp); // undefined
// ③ 再次尝试访问 testProp
// ④ 又创建了全新的 String 包装对象（没有 testProp 属性）
// ⑤ 访问不到，返回 undefined
// ⑥ 再次销毁包装对象
```

**通俗类比**：包装对象就像**一次性手套**。你需要用手触碰某些东西时（调用方法），引擎会给你戴上一只手套（创建包装对象）。操作完成后，手套立刻被丢弃（销毁）。下次你再想操作时，又会发一只新手套（全新创建），之前那只手套上写的笔记（添加的属性）自然就不在了。

### 6.3 不要手动使用包装构造函数

```javascript
// ❌ 不推荐：使用包装构造函数
let badStr = new String("hello");
let badNum = new Number(42);
let badBool = new Boolean(true);

// 问题 1：typeof 表现不一致
console.log(typeof "hello");       // "string"
console.log(typeof badStr);        // "object"（不再是 string 了！）

// 问题 2：=== 比较失败
console.log(badStr === "hello");  // false（一个是对象，一个是原始值）
console.log(badStr == "hello");   // true（== 会触发拆箱转换）

// 问题 3：造成混乱
console.log(String(badStr) === String("hello"));  // true（绕了一大圈才相等）
```

## 七、类型检测方法总结

### 7.1 各方法的适用场景

| 方法 | 适用场景 | 优点 | 缺点 |
|------|---------|------|------|
| `typeof` | 区分原始类型（除 null 外） | 简单、安全（不报错） | `typeof null` 为 "object"；无法细分对象类型 |
| `instanceof` | 判断对象是否属于某类 | 可处理继承关系 | 跨 iframe 失效；原始值无效；可被伪造 |
| `Object.prototype.toString.call()` | **精确识别所有类型** | 最全面、最可靠 | 写法较长 |
| `Array.isArray()` | 专门检测数组 | 精确、跨 iframe 安全 | 仅适用于数组 |
| `value === null` / `value === undefined` | 精确检测空值 | 最简洁 | 只能检测特定值 |
|鸭子类型 (`duck typing`) | 检测对象能力而非类型 | 灵活、实用 | 不够严格 |

### 7.2 终极类型检测函数

结合以上所有知识，我们可以构建一个生产级类型检测工具：

```javascript
/**
 * 精确的 JavaScript 类型检测
 * @param {*} value 待检测的值
 * @returns {string} 类型名称
 */
function typeOf(value) {
  // 快速路径：null
  if (value === null) return "null";

  // 快速路径：原始类型（利用 typeof）
  const baseType = typeof value;
  if (
    baseType !== "object" &&
    baseType !== "function"
  ) {
    return baseType;
  }

  // 慢速路径：对象类型（利用 toString）
  const tag = Object.prototype.toString
    .call(value)
    .replace(/^\[object (.+)\]$/, "$1");

  return tag;
}

// 完整测试矩阵
console.table([
  { value: undefined, result: typeOf(undefined) },       // "undefined"
  { value: null, result: typeOf(null) },                  // "null"
  { value: true, result: typeOf(true) },                  // "boolean"
  { value: 42, result: typeOf(42) },                      // "number"
  { value: "hi", result: typeOf("hi") },                  // "string"
  { value: Symbol(), result: typeOf(Symbol()) },          // "symbol"
  { value: 100n, result: typeOf(100n) },                  // "bigint"
  { value: {}, result: typeOf({}) },                      // "Object"
  { value: [], result: typeOf([]) },                      // "Array"
  { value: () => {}, result: typeOf(() => {}) },          // "Function"
  { value: /reg/, result: typeOf(/reg/) },               // "RegExp"
  { value: new Date(), result: typeOf(new Date()) },      // "Date"
  { value: new Map(), result: typeOf(new Map()) },        // "Map"
  { value: new Set(), result: typeOf(new Set()) },        // "Set"
  { value: Promise.resolve(), result: typeOf(Promise.resolve()) }, // "Promise"
]);
```

## 八、知识图谱

```
JavaScript 类型系统
│
├── 原始类型（Primitive）—— 不可变、按值传递
│   ├── Undefined —— 缺少值，系统自动赋予
│   ├── Null —— 有意为空，开发者主动赋值
│   ├── Boolean —— true/false，条件判断基础
│   ├── String —— 文本，UTF-16 编码，不可变
│   ├── Number —— IEEE 754 双精度浮点数
│   │   ├── 整数 + 浮点数统一
│   │   ├── 特殊值：NaN, Infinity
│   │   └── 精度问题：0.1 + 0.2 ≠ 0.3
│   ├── Symbol（ES6）—— 唯一标识符
│   │   ├── Symbol() vs Symbol.for()
│   │   ├── 作为对象属性键（不可枚举）
│   │   └── Well-known Symbols（Symbol.iterator 等）
│   └── BigInt（ES2020）—— 任意精度整数
│       ├── 解决 Number 安全范围限制
│       └── 不能与 Number 隐式混合运算
│
├── 对象类型（Object）—— 可变、按引用传递
│   ├── 普通对象 { }
│   ├── 数组 [ ]
│   ├── 函数 function
│   ├── 内置对象：Date, RegExp, Map, Set, WeakMap, WeakSet
│   └── 内存模型：变量存储引用，多个变量可指向同一对象
│
├── 类型检测方法
│   ├── typeof —— 原始类型首选（注意 null 陷阱）
│   ├── instanceof —— 原型链查找
│   ├── Object.prototype.toString.call() —— 最精确
│   ├── Array.isArray() —— 数组专属
│   └── Duck Typing —— 能力检测
│
├── 包装对象（Wrapper Objects）
│   ├── String / Number / Boolean
│   ├── 自动装箱：原始值调用方法时临时创建
│   ├── 一次性的：属性赋值后立即销毁
│   └── 不要手动使用 new String() 等
│
└── 常见陷阱
    ├── typeof null === "object"（历史 Bug）
    ├── NaN !== NaN（IEEE 754 规定）
    ├── 0.1 + 0.2 ≠ 0.3（浮点精度）
    ├── [] 是 truthy 但 ![] 也是 true
    └── typeof 未声明变量不报错（但 TDZ 中变量会报错）
```
