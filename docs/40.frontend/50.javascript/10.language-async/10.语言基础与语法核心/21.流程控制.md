# 流程控制 —— if 的 falsy 值、switch 的严格相等、for...in 与 for...of 的差异

> **核心内容**：流程控制是任何编程语言的核心骨架，它决定了代码的执行路径。本文将从执行引擎的角度，系统讲解 JavaScript 中 `if/else` 条件分支、`switch` 多路选择、`while`/`do...while`/`for` 三大循环结构、以及 `for...in` 与 `for...of` 的本质差异。你将理解 falsy 值在条件判断中的行为机制、switch 的"穿透"问题、循环的底层语义，以及如何用 `break`/`continue`/标签语句精确控制程序流向。

## 一、if/else —— 条件分支的基础

### 1.1 if 语句的本质：布尔上下文中的 ToBoolean 转换

当你在 `if (condition)` 中写下某个表达式时，JavaScript 引擎做的第一件事并不是直接读取这个值的真假——而是**对这个值执行内部抽象操作 `ToBoolean`**：

```javascript
// if 的工作原理（简化版）：
// 1. 计算 condition 表达式得到值 V
// 2. 对 V 执行 ToBoolean(V) 得到布尔值 B
// 3. 如果 B 为 true → 执行 if 块；否则跳过或进入 else

// 这意味着 if 括号里的内容可以是任意类型的值！
if (42) { console.log("数字是 truthy"); }           // ✓ 输出
if ("hello") { console.log("字符串是 truthy"); }     // ✓ 输出
if ({}) { console.log("对象是 truthy"); }            // ✓ 输出
if ([]){ console.log("数组是 truthy"); }             // ✓ 输出
if (0) { console.log("不会输出"); }                  // ✗ 不输出
if ("") { console.log("不会输出"); }                 // ✗ 不输出
if (null) { console.log("不会输出"); }                // ✗ 不输出
```

**通俗类比**：`if` 就像一个**安检门卫**。每个想进门的人都必须先接受检查。门卫手里有一份只有 6 个名字的黑名单（6 个 falsy 值）：undefined、null、false、0、""、NaN。只要你的名字不在黑名单上，门卫就会放行（truthy）；如果你的名字恰好在黑名单上，就会被拦下（falsy）。注意：即使你两手空空（空数组 [] 或空对象 {}），只要你有实体（是一个引用），门卫也会放行。

### 1.2 falsy 值表 —— 仅此 6 个

这是 JavaScript 中最重要的基础知识之一，值得反复强调：

| Falsy 值 | 类型 | ToBoolean 结果 | 常见出现场景 |
|---------|------|-----------------|-------------|
| `undefined` | Undefined | `false` | 变量未声明/未赋值 |
| `null` | Null | `false` | 显式设为空 |
| `false` | Boolean | `false` | 布尔假值 |
| `0` / `-0` | Number | `false` | 计数归零 |
| `NaN` | Number | `false` | 无效数学运算结果 |
| `""` | String | `false` | 空字符串 |

**除此之外的所有值都是 truthy**，包括一些容易误判的：

```javascript
// 这些全是 truthy！（新手常以为它们是 falsy）
if ("0")       { /* 执行 */ }   // 非空字符串就是 truthy
if (" ")       { /* 执行 */ }   // 空格也是非空字符
if ("false")   { /* 执行 */ }   // 字符串 "false" ≠ 布尔值 false
if (-1)        { /* 执行 */ }   // 非零数字就是 truthy
if (Infinity)  { /* 执行 */ }   // 无穷大也是 truthy
if ([])        { /* 执行 */ }   // 空对象（数组也是对象）是 truthy
if ({})        { /* 执行 */ }   // 空对象是 truthy
if (function(){}) { /* 执行 */ }  // 函数永远是 truthy
if (Symbol()) { /* 执行 */ }    // Symbol 也是 truthy
```

### 1.3 else 与 else if 链

```javascript
// 基本 if-else 结构
let score = 85;

if (score >= 90) {
  console.log("优秀");
} else {
  console.log("需要继续努力");
}
// 输出："需要继续努力"

// else if 链 —— 处理多个互斥条件
if (score >= 90) {
  console.log("A 级");
} else if (score >= 80) {
  console.log("B 级");
} else if (score >= 70) {
  console.log("C 级");
} else if (score >= 60) {
  console.log("D 级");
} else {
  console.log("F 级");
}
// 输出："B 级"

// ★ 关键理解：else if 链是"短路"的
// 一旦某个条件为 true，对应的块被执行后，整个链就结束了
// 后续的条件不会再被评估
```

**else if 链的执行模型**：

```
if (条件 A)
  │── true → 执行 A 块 ──→ 整个 if-else-if 链结束
  │
  └── false → if (条件 B)
              │── true → 执行 B 块 ──→ 结束
              │
              └── false → if (条件 C)
                          │── true → 执行 C 块 ──→ 结束
                          │
                          └── false → else 块 → 结束
```

### 1.4 if-else 的最佳实践

```javascript
// ✅ 推荐 1：始终使用花括号，即使只有一行
if (isAdmin) {
  grantAccess();      // 清晰、安全
}

// ❌ 不推荐：省略花括号（容易出错）
if (isAdmin)
  grantAccess();
  sendNotification();  // 缩进欺骗了眼睛——这行不在 if 内！

// ✅ 推荐 2：把"正常情况"放在 if 里，"异常/默认情况"放在 else 里
if (user.isLoggedIn) {
  showDashboard();
} else {
  redirectToLogin();
}

// ✅ 推荐 3：使用早期返回（early return）减少嵌套
// ❌ 过度嵌套（"箭头型"代码）
function processData(data) {
  if (data) {
    if (data.isValid) {
      if (data.hasPermission) {
        // 真正的逻辑被埋在三层缩进里
        doWork(data);
      }
    }
  }
}

// ✅ 早期返回（"扁平型"代码）
function processData(data) {
  if (!data) return;
  if (!data.isValid) return;
  if (!data.hasPermission) return;

  doWork(data);          // 主逻辑在最外层
}
```

**通俗类比**：早期返回模式就像**机场安检的快速通道**。如果你不符合基本要求（没带证件、行李超标），安检员会立刻让你走人，不会让你继续排队等待后续检查。这既节省了你的时间，也让后面的检查员能专注于真正需要仔细审查的乘客。

## 二、switch 语句 —— 多路选择与严格相等

### 2.1 switch 的基本语法与工作原理

`switch` 用于将一个值与多个候选值进行匹配，它比冗长的 `else if` 链更清晰（当所有条件都是对同一个变量的等值比较时）：

```javascript
let day = 3;

switch (day) {
  case 1:
    console.log("星期一");
    break;
  case 2:
    console.log("星期二");
    break;
  case 3:
    console.log("星期三");    // ← 匹配到这里
    break;
  default:
    console.log("未知日期");
}

// 输出："星期三"
```

**switch 的工作原理**（《JavaScript 权威指南》第5.7节详解）：

```
switch (expression) {
  case value1:
    statements1;
  case value2:
    statements2;
  default:
    statements3;
}

执行流程：
1. 计算 expression 的值
2. 用严格相等（===）依次与每个 case 的 value 比较
3. 匹配成功 → 从该 case 进入，顺序执行后续所有语句
4. 遇到 break → 跳出整个 switch
5. 如果没有匹配且存在 default → 从 default 进入
6. 如果没有匹配也没有 default → 什么都不做
```

### 2.2 switch 使用的是严格相等（===）

这是一个关键点：**switch 不会进行类型转换**，它使用 `===` 进行比较：

```javascript
let x = "42";

switch (x) {
  case 42:
    console.log("数字 42");    // 不会执行！"42" !== 42
    break;
  case "42":
    console.log("字符串 42");  // ✓ 执行这个
    break;
}

// 同样地：
switch (0) {
  case false:
    console.log("匹配 false");  // 不会执行！0 !== false
    break;
  case "":
    console.log("匹配空字符串"); // 不会执行！0 !== ""
    break;
  default:
    console.log("无匹配");
}
```

这与 `==` 宽松比较形成了鲜明对比。`if (x == false)` 在 `x = 0` 时会成立，但 `case false:` 在 `x = 0` 时不会匹配。这种严格性是 `switch` 的设计特点之一——**它更安全、更可预测**。

### 2.3 "穿透"（fall-through）现象

如果不写 `break`，执行流会**穿透到下一个 case**——这是 switch 最著名的特性（也最容易引发 bug）：

```javascript
let level = 2;

switch (level) {
  case 1:
    console.log("一级权限");   // 不会执行
    break;
  case 2:
    console.log("二级权限");   // ✓ 匹配！开始执行
    // 没有 break → 穿透下去 ↓
  case 3:
    console.log("三级权限");   // 也会执行！（穿透了）
    // 没有 break → 继续穿透 ↓
  case 4:
    console.log("四级权限");   // 也会执行！
    break;
  default:
    console.log("其他");
}
// 输出：
// 二级权限
// 三级权限
// 四级权限
```

#### 什么时候利用穿透？

有意设计的穿透可以用来合并逻辑：

```javascript
let month = 2;  // 2月
let days;

switch (month) {
  case 1: case 3: case 5: case 7: case 8: case 10: case 12:
    days = 31;              // 大月：31 天（故意穿透合并）
    break;
  case 4: case 6: case 9: case 11:
    days = 30;              // 小月：30 天
    break;
  case 2:
    days = isLeapYear ? 29 : 28;  // 2月特殊处理
    break;
}

// 更推荐的写法（显式注释意图）
switch (month) {
  case 1:
  case 3:
  case 5:
  case 7:
  case 8:
  case 10:
  case 12:
    days = 31;  // 大月
    break;
  // ...
}
```

::: warning 最佳实践
如果是有意的穿透，务必添加注释说明原因。大多数情况下，忘记写 `break` 是 bug 而不是特性。
:::

### 2.4 switch vs else if —— 如何选择？

| 特征 | `switch` | `else if` 链 |
|------|----------|-----------|
| **比较方式** | 严格相等 `===` | 任意布尔表达式 |
| **比较目标** | 只能是同一个变量 | 可以是不同的条件 |
| **适用场景** | 单个变量的多值匹配 | 多条件的范围判断 |
| **可读性（多分支时）** | 高（结构清晰） | 低（可能很长） |

```javascript
// ✅ 适合用 switch：单个变量的多值匹配
switch (status) {
  case "pending":   handlePending(); break;
  case "active":    handleActive(); break;
  case "completed": handleCompleted(); break;
  case "failed":    handleFailed(); break;
}

// ✅ 适合用 else if：复杂的多条件判断
if (age < 13) {
  category = "儿童";
} else if (age < 18) {
  category = "少年";
} else if (age < 65) {
  category = "成人";
} else {
  category = "老人";
}

// ❌ 不要用 switch 来做范围判断
switch (true) {
  case age < 13: ... break;  // 这种用法很怪异，不如用 else if
}
```

## 三、三大循环结构 —— while、do-while、for

### 3.1 循环的本质概念

什么是循环？从计算机科学的角度看，循环是一种**控制流结构**，它让一段代码可以被**重复执行零次、一次或多次**，直到某个条件不再满足为止。

**通俗类比**：循环就像一个**自动旋转的磨坊水车**。只要上游有水流下来（条件为真），水车的叶片就会不断转动（循环体反复执行）。一旦水源枯竭（条件变为 false），水车就停止转动，整个系统归于平静。

### 3.2 while 循环 —— 先判断后执行

`while` 循环是最基本的循环形式。它的特点是：**每次迭代前都先检查条件**——这意味着如果初始条件就不满足，循环体一次都不会执行：

```javascript
// 基本语法
while (condition) {
  // 循环体（条件为 true 时重复执行）
}

// 示例：打印 0 到 2
let i = 0;
while (i < 3) {
  console.log(i);    // 0, 1, 2
  i++;
}
// 当 i 变成 3 时，i < 3 为 false，循环结束

// 示例：条件一开始就不满足
let j = 10;
while (j < 5) {
  console.log("永远不会执行");
}
console.log("直接跳过了");
```

**while 循环的执行流程图**：

```
┌──────────────┐
│  检查条件    │ ←──┐
│ condition?   │    │
└──────┬───────┘    │
       │            │
   false│         │true
       ▼            │
┌──────────────┐    │
│  执行循环体   │    │
│  body        │    │
└──────┬───────┘    │
       │            │
       └────────────┘

条件为 false → 退出循环
```

**适用场景**：当你**不知道确切要循环多少次**，但知道**什么条件下应该停止**时，`while` 是最佳选择：

```javascript
// 场景 1：处理用户输入直到满足条件
let input;
while (!(input = prompt("输入 'ok' 结束:", "")).toLowerCase().startsWith("ok")) {
  alert(`你输入了 "${input}"，请重新输入`);
}
alert("输入正确！");

// 场景 2：异步轮询（模拟等待某操作完成）
let data = null;
while (!data) {
  data = tryFetchData();  // 尝试获取数据
  if (!data) sleep(1000);   // 失败则等 1 秒再试
}
console.log("数据获取成功", data);
```

### 3.3 do-while 循环 —— 先执行后判断

`do-while` 与 `while` 的唯一区别在于：**它至少执行一次循环体**，然后再检查是否继续：

```javascript
// 基本语法
do {
  // 循环体（至少执行一次）
} while (condition);

// 示例：至少询问一次
let userInput;
do {
  userInput = prompt("请输入一个大于 0 的数字:", "");
  if (userInput === null) break;  // 用户取消
  userInput = Number(userInput);
} while (isNaN(userInput) || userInput <= 0);

alert(`你输入的数字是 ${userInput}`);
```

**do-while 的执行流程图**：

```
┌──────────────┐
│  执行循环体   │ ←── 第一次无条件进入
│  body        │
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  检查条件    │ ──→ true → 回到顶部再执行
│ condition?   │
└──────┬───────┘
   false│
       ▼
   退出循环
```

**适用场景**：当你需要**至少执行一次操作**（比如初始化、展示 UI、获取首次输入），然后根据结果决定是否重复时，`do-while` 最合适：

```javascript
// 场景：游戏循环（至少渲染一次画面）
do {
  renderGameFrame();          // 渲染一帧
  processUserInput();        // 处理用户输入
  updateGameState();          // 更新游戏状态
} while (!game.isOver);

// 场景：验证密码（至少让用户尝试一次）
let attempts = 0;
let maxAttempts = 3;
let success = false;

do {
  let pwd = prompt("请输入密码:");
  if (pwd === SECRET_PASSWORD) {
    success = true;
  } else {
    attempts++;
    alert(`错误！还剩 ${maxAttempts - attempts} 次机会`);
  }
} while (!success && attempts < maxAttempts);

success ? alert("登录成功!") : alert("尝试次数已用完!");
```

### 3.4 for 循环 —— 最常用的循环结构

`for` 循环将**初始化、条件检查、更新步骤**整合在一行中，是 JavaScript 中使用最频繁的循环形式：

```javascript
// 标准语法
for (begin; condition; step) {
  // 循环体
}

// 各部分的含义：
// begin    → 初始化（只在循环开始前执行一次）
// condition → 每次迭代前检查的条件
// step     → 每次迭代结束后执行的更新操作

// 示例：打印 0 到 4
for (let i = 0; i < 5; i++) {
  console.log(i);    // 0, 1, 2, 3, 4
}

// 执行顺序详解：
// ① begin:   let i = 0;        （i = 0）
// ② condition: i < 5?          （0 < 5 → true，进入循环）
// ③ body:     console.log(0)     （输出 0）
// ④ step:     i++               （i 变成 1）
// ⑤ condition: i < 5?          （1 < 5 → true）
// ⑥ body:     console.log(1)     （输出 1）
// ⑦ step:     i++               （i 变成 2）
// ... 重复直到 i=5 时 condition 为 false
```

**for 循环的执行时机图**：

```
for (begin → condition → body → step → condition → body → step → ...)
  │         │        │       │         │        │
  ▼         ▼        ▼       ▼         ▼        ▼
 [init] → [check] → [body] → [update] → [check] → [body] → [update] → ...
                │                                    │
              false                                 false
                ▼                                     ▼
             [退出]                                [退出]
```

#### for 的各部分都可以省略（但分号不能省）

```javascript
// 省略 begin（在外部初始化）
let i = 0;
for (; i < 3; i++) {
  console.log(i);
}

// 省略 step（在循环体内更新）
for (let j = 0; j < 3;) {
  console.log(j);
  j++;
}

// 全部省略 → 无限循环
// for (;;) { /* 永远执行 */ }

// 无限循环配合 break 使用
let k = 0;
for (;;) {
  console.log(k);
  k++;
  if (k >= 3) break;   // 必须有退出条件，否则死循环！
}

// 使用 for 遍历数组（传统方式）
let arr = ["a", "b", "c"];
for (let idx = 0; idx < arr.length; idx++) {
  console.log(idx, arr[idx]);
}
// 0 "a", 1 "b", 2 "c"

// 优化版：缓存 length（性能微优化）
for (let idx = 0, len = arr.length; idx < len; idx++) {
  console.log(arr[idx]);  // 避免每次查询 length 属性
}
```

### 3.5 三种循环的选择决策

| 维度 | `while` | `do-while` | `for` |
|------|--------|-----------|------|
| **条件检查位置** | 循环体之前 | 循环体之后 | 循环体之前 |
| **最少执行次数** | 0 次 | **1 次** | 0 次 |
| **适合已知次数？** | 否 | 否 | **是** |
| **初始化位置** | 循环外部 | 循环外部 | 循环头部 |
| **典型用途** | 不确定次数的遍历 | 至少执行一次的操作 | 计数循环、数组索引遍历 |

```javascript
// 选择 while：不确定次数
while (queue.hasNext()) {
  process(queue.dequeue());
}

// 选择 do-while：交互式输入、至少运行一次
do {
  let choice = getMenuChoice();
  executeChoice(choice);
} (choice !== "quit");

// 选择 for：确定次数
for (let round = 1; round <= 10; round++) {
  playRound(round);
}
```

## 四、for...in 与 for...of —— 本质完全不同

### 4.1 for...in —— 遍历对象的键

`for...in` 用于**遍历对象的可枚举属性键**（包括原型链上的属性）：

```javascript
// 遍历普通对象
let person = {
  name: "Alice",
  age: 25,
  city: "Beijing"
};

for (let key in person) {
  console.log(key, "→", person[key]);
}
// name → Alice
// age → 25
// city → Beijing

// ⚠️ 注意：for...in 会遍历到原型链上的属性！
let parentObj = { inheritedProp: "来自父级" };
let childObj = Object.create(parentObj);
childObj.ownProp = "自己的属性";

for (let key in childObj) {
  console.log(key, "→", childObj[key]);
}
// ownProp → 自己的属性
// inheritedProp → 来自父级（通常不是我们想要的！）

// 解决方案：使用 hasOwnProperty 过滤
for (let key in childObj) {
  if (Object.prototype.hasOwnProperty.call(childObj, key)) {
    console.log("自有属性:", key, "=", childObj[key]);
  }
}
```

### 4.2 for...of —— 遍历可迭代的值

`for...of` 是 ES6 引入的新循环语法，用于**遍历可迭代对象的值**（而非键）。它依赖于对象的 `[Symbol.iterator]` 接口：

```javascript
// 遍历数组
let colors = ["red", "green", "blue"];
for (let color of colors) {
  console.log(color);    // red, green, blue（直接拿到值！）
}

// 遍历字符串
for (let char of "Hello") {
  console.log(char);    // H e l l o
}

// 遍历 Map
let map = new Map([["a", 1], ["b", 2]]);
for (let [key, value] of map) {
  console.log(key, "=>", value);  // a => 1, b => 2
}

// 遍历 Set
let set = new Set([1, 2, 3, 2, 1]);
for (let val of set) {
  console.log(val);     // 1, 2, 3（去重后的值）
}
```

### 4.3 for...in vs for...of 完整对比

| 特征 | `for...in` | `for...of` |
|------|-----------|-----------|
| **ES 版本** | ES1（1997） | ES6（2015） |
| **遍历目标** | 对象的键（字符串） | 可迭代对象的值 |
| **适用于数组？** | ❌ 不推荐 | **✅ 推荐** |
| **适用于普通对象** | **✅ 推荐** | ❌ 不可用（普通对象不可迭代） |
| **遍历顺序** | 不保证整数顺序 | 按迭代器定义的顺序 |
| **包含原型链？** | **是**（除非过滤） | **否**（只遍历自身） |
| **能否遍历 Map/Set？** | 得到键名 | 得到键值对/值 |
| **能否遍历字符串？** | 得到索引（0,1,2...） | 得到字符 |

```javascript
let arr = ["apple", "banana", "cherry"];

// for...in 遍历数组（不推荐！）
for (let index in arr) {
  console.log(index);        // "0", "1", "2"（得到的是字符串索引！）
  console.log(typeof index); // "string"
}

// for...of 遍历数组（推荐！）
for (let item of arr) {
  console.log(item);         // "apple", "banana", "cherry"（直接得到元素值！）
  console.log(typeof item);  // "string"
}
```

**为什么 for...in 不适合遍历数组？**

1. **得到的索引是字符串**：`for...in` 总是返回字符串类型的键，即使是数组的数字索引
2. **包含原型链上的属性**：如果有人修改了 `Array.prototype` 添加了自定义方法，`for...in` 会遍历到它
3. **顺序不确定**：规范不保证 `for...in` 按数值顺序遍历数组
4. **语义不清**：读代码的人看到 `for...in + 数组` 会感到困惑

```javascript
// 危险示例：Array.prototype 被污染后
Array.prototype.customMethod = function() {};

let myArr = [10, 20, 30];

for (let key in myArr) {
  console.log(key);  // "0", "1", "2", "customMethod" !!!
  // 意外地遍历到了原型上的方法
}

// for...of 安全得多
for (let val of myArr) {
  console.log(val);  // 10, 20, 30（干净利落）
}
```

**通俗类比**：
- **`for...in`** 就像是在**清点库存**。你拿着清单逐一核对物品的编号（键/索引），不管这些物品是什么类型、放在哪里，只要是登记过的都会被列出来。问题是，有时候仓库管理员可能在别处也偷偷登记了一些东西（原型链属性），导致你的清单上出现了不该有的条目。
- **`for...of`** 就像是**流水线传送带**。物品按规定的顺序一个接一个地传送到你面前。你不需要关心它们的编号，只需要拿过来使用就行。而且传送带只负责运送当前仓库的物品，不会把隔壁仓库的东西混进来。

## 五、break 和 continue —— 精细控制循环流

### 5.1 break —— 立即终止循环

`break` 用于**立即跳出当前所在的循环**（或 switch 语句），不再执行剩余的迭代：

```javascript
// 示例：找到第一个负数就停止
let numbers = [3, 7, -2, 9, -5, 1];
let firstNegative;

for (let i = 0; i < numbers.length; i++) {
  if (numbers[i] < 0) {
    firstNegative = numbers[i];
    console.log(`发现负数: ${numbers[i]}，位于索引 ${i}`);
    break;                   // 找到了！立即退出循环
  }
}
// 只输出：发现负数: -2，位于索引 1
// 后面的 -5 和 1 都不会被访问到

// 示例：用于无限循环的安全出口
let input;
while (true) {                          // 无限循环
  input = prompt("输入 'stop' 结束:", "");
  if (input === null || input.toLowerCase() === "stop") {
    break;                               // 用户取消或输入 stop → 退出
  }
  console.log(`你输入了: ${input}`);
}
```

### 5.2 continue —— 跳过本次迭代

`continue` 用于**立即结束当前这次迭代**，跳到下一次迭代的条件检查：

```javascript
// 示例：只输出奇数
for (let i = 0; i < 10; i++) {
  if (i % 2 === 0) {
    continue;               // 偶数 → 跳过，直接进入下一轮
  }
  console.log(i);            // 1, 3, 5, 7, 9
}

// 示例：跳过空值和无效项
let dataList = [10, null, "", 20, undefined, 30, NaN, 40];
let sum = 0;

for (let item of dataList) {
  // 跳过所有无效值
  if (item == null || item !== item || item === "") {
    continue;               // null, undefined, NaN, "" 全部跳过
  }
  sum += item;
}
console.log(sum);              // 100（只累加了 10+20+30+40）
```

### 5.3 break vs continue 的对比

| 特性 | `break` | `continue` |
|------|--------|-----------|
| **作用** | 终止**整个**循环 | 跳过**当前次**迭代 |
| **之后** | 循环彻底结束 | 进入下次迭代（如果条件允许） |
| **影响范围** | 当前所在的最内层循环 | 当前迭代步 |
| **可用于 switch** | **可以** | **不可以** |

```javascript
// 直观对比
for (let i = 0; i < 5; i++) {
  if (i === 2) {
    console.log("-- break --");
    break;                  // i=2 时，整个循环终止
    // 3 和 4 不会被输出
  }
  if (i === 3) {
    console.log("-- continue --");
    continue;              // i=3 时，本次跳过
    // 但 4 还会被正常输出
  }
  console.log("i =", i);
}

// 实际输出：
// i = 0
// i = 1
// -- break --
// （循环结束，i=2 之后全部停止）
```

## 六、标签语句 —— 跨越多层循环的跳转

### 6.1 为什么需要标签？

普通的 `break` 和 `continue` 只能影响**最内层的那一个循环**。但如果你处于**多层嵌套循环**中，想要从内层直接跳出外层怎么办？答案是——**标签（label）**：

```javascript
// 场景：二维坐标搜索，找到目标后立即跳出两层循环
outer: for (let i = 0; i < 3; i++) {          // 外层循环标签 "outer"
  for (let j = 0; j < 3; j++) {              // 内层循环
    let coord = `${i},${j}`;
    let input = prompt(`坐标 ${coord} 的值（空=停止）:`, "");

    if (input === "" || input === null) {
      console.log("用户取消搜索");
      break outer;                              // 直接跳出外层循环！
    }

    grid[coord] = Number(input);
  }
}
console.log("搜索完成！");
```

**没有标签的话会怎样？**

```javascript
// ❌ 普通 break 只能跳出内层循环
for (let i = 0; i < 3; i++) {
  for (let j = 0; j < 3; j++) {
    if (shouldExit) {
      break;            // 这里只能跳出内层的 j 循环
    }
    // 外层的 i 循环仍然继续...
  }
  // 即使 shouldExit 为 true，这里还会执行！
  console.log("i still runs...");
}
```

### 6.2 标签与 continue 配合使用

标签不仅可以和 `break` 搭配，也可以和 `continue` 搭配——表示"跳过当前迭代，进入**指定标签循环**的下一次迭代"：

```javascript
// 打印 3x3 乘法表，但跳过对角线位置（i == j 时）
outer: for (let i = 1; i <= 3; i++) {
  inner: for (let j = 1; j <= 3; j++) {
    if (i === j) {
      continue outer;      // 跳过对角线，直接进入外层循环的下一次迭代
    }
    console.log(`${i} × ${j} = ${i * j}`);
  }
}

// 输出：
// 1 × 2 = 2
// 1 × 3 = 3
// 2 × 1 = 2
// 2 × 3 = 6
// 3 × 1 = 3
// 3 × 2 = 6
// （1×1, 2×2, 3×3 被跳过了）
```

### 6.3 标签的限制

```javascript
// ✅ 标签可以用在循环（for/while/do-while）和代码块（{}）上
labelName: {
  // ...
  if (someCondition) break labelName;  // 合法
}

// ⚠️ 标签不能随意跳转（不像某些语言的 goto）
myLabel: {
  console.log("before");
  // 不能在这里用 goto 跳转到其他位置
}

// ❌ 标签不能用在三元运算符中
// (x > 5) ? result : continue myLabel;  // SyntaxError!

// ❌ 标签不能跨函数边界
function foo() {
  bar: for (...) {
    // break bar;  // ✅ 合法
  }
  // break bar;    // ❌ SyntaxError! 标签不在作用域内
}
```

## 七、异常处理流程控制 —— try/catch/finally

虽然异常处理不属于传统的循环/分支范畴，但它同样是重要的流程控制机制：

### 7.1 基本结构

```javascript
try {
  // 可能抛出错误的代码
  riskyOperation();
  anotherRiskyCall();
} catch (error) {
  // 错误发生时的处理
  console.error("出错了:", error.message);
} finally {
  // 无论是否出错都会执行的清理代码
  cleanupResources();
  console.log("清理完成");
}
```

### 7.2 执行流程图

```
try 块
  │
  ├─ 成功（无异常）────┐
  │                      │
  │                      ▼
  │               [跳过 catch 块]
  │                      │
  ├─ 抛出异常 ──────────┤
  │                      │
  │                      ▼
  │              [进入 catch 块]
  │              [处理 error]
  │                      │
  └──────────────────────┘
              │
              ▼
       [finally 块] ← 无论哪种路径最终都会到达
              │
              ▼
         [继续后续代码]
```

```javascript
// finally 的强制执行特性
function demo() {
  try {
    console.log("try 开始");
    throw new Error("测试异常");
    console.log("这行不会执行");  // 异常后跳过了
  } catch (e) {
    console.log("catch 捕获:", e.message);
    return "catch 的返回值";        // 注意：finally 还没执行！
  } finally {
    console.log("finally 执行");  // 即便 catch 有 return，finally 仍会执行
  }
  console.log("demo 结束");
}

demo();
// 输出：
// try 开始
// catch 捕获: 测试异常
// finally 执行        ← return 被 finally 暂停了
// demo 结束            // 最终返回值仍是 "catch 的返回值"
```

::: tip 核心要点
`finally` 块的执行是**不可阻止的**。即使在 `try` 或 `catch` 中使用了 `return`、`break` 或 `continue`，`finally` 中的代码依然会执行。唯一能让 `finally` 不执行的情况是进程被强行杀死（如 `process.exit()`）或机器断电。
:::

## 八、流程控制的进阶模式

### 8.1 提前返回模式（Early Return Pattern）

```javascript
// ❌ 深层嵌套（"回调地狱"式的条件判断）
function validateUser(user) {
  if (user) {
    if (user.name) {
      if (user.email) {
        if (user.age >= 18) {
          return { valid: true };
        } else {
          return { valid: false, reason: "未成年" };
        }
      } else {
        return { valid: false, reason: "缺少邮箱" };
      }
    } else {
      return { valid: false, reason: "缺少姓名" };
    }
  } else {
    return { valid: false, reason: "用户不存在" };
  }
}

// ✅ 提前返回（扁平结构）
function validateUser(user) {
  if (!user)                    return { valid: false, reason: "用户不存在" };
  if (!user.name)              return { valid: false, reason: "缺少姓名" };
  if (!user.email)             return { valid: false, reason: "缺少邮箱" };
  if (user.age < 18)            return { valid: false, reason: "未成年" };
  return { valid: true };        // 所有检查通过
}
```

### 8.2 条件赋值模式

```javascript
// 传统 if-else 赋值
let statusText;
if (status === "success") {
  statusText = "操作成功";
} else if (status === "error") {
  statusText = "操作失败";
} else if (status === "pending") {
  statusText = "处理中...";
} else {
  statusText = "未知状态";
}

// 用对象映射替代（更简洁、易扩展）
const statusMap = {
  success: "操作成功",
  error: "操作失败",
  pending: "处理中..."
};

let statusText = statusMap[status] ?? "未知状态";

// 用查找表替代长 switch
function getGrade(score) {
  const gradeTable = [
    { min: 90, grade: "A" },
    { min: 80, grade: "B" },
    { min: 70, grade: "C" },
    { min: 60, grade: "D" }
  ];
  for (let row of gradeTable) {
    if (score >= row.min) return row.grade;
  }
  return "F";
}
```

### 8.3 循环中的函数抽象

```javascript
// ❌ 一个函数里塞太多逻辑
function processUsers(users) {
  let results = [];
  for (let user of users) {
    if (user && user.isActive && !user.isBanned) {
      if (user.permissions.includes("read")) {
        if (user.subscription && !user.subscription.expired) {
          results.push(processUserData(user));
        }
      }
    }
  }
  return results;
}

// ✅ 拆分为独立的谓词函数
function isActive(user) {
  return user?.isActive && !user.isBanned;
}

function canRead(user) {
  return user?.permissions?.includes("read");
}

function hasValidSubscription(user) {
  return user?.subscription && !user.subscription.expired;
}

function processUsers(users) {
  return users
    .filter(isActive)
    .filter(canRead)
    .filter(hasValidSubscription)
    .map(processUserData);
}
```
