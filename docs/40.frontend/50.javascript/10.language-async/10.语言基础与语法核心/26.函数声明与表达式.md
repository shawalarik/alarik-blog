# 函数声明与表达式 —— 提升、命名函数表达式、箭头函数的词法 this、new.target

> **核心内容**：JavaScript 中定义函数的四种方式（声明、表达式、箭头函数、NFE），函数提升的底层机制，词法 `this` 的原理，以及如何在实际开发中选择最合适的写法。

---

## 一、函数是 JavaScript 的"一等公民"

在 JavaScript 的世界里，函数的地位非常特殊。它不仅仅是"一段可执行的代码"，而是一个**完整的值**——你可以把它赋给变量、作为参数传递、从其他函数中返回，甚至给它添加属性。这种"函数即值"的特性，是理解后续所有高级概念（闭包、回调、装饰器、高阶组件等）的根本基石。

打个通俗的比方：在其他编程语言中，函数可能像是一个**固定的工具箱**——你只能用它，不能带着它到处走。而在 JavaScript 里，函数更像是一张**可折叠的便携式工具卡**：你可以在任何地方展开它使用，可以把它装进另一个包里，甚至可以把这张卡片复印多份分发给不同的人。这种灵活性让 JavaScript 的代码组织方式变得极其丰富和强大。

### 1.1 函数是特殊的对象

既然函数是一种"值"，那么它本质上是什么？答案是：**函数是一种特殊的对象**。它拥有普通对象的所有能力（添加属性、按引用传递），同时还有一个独门绝技——可以被调用（通过 `()` 运算符）。

```javascript
function sayHi() {
  console.log("Hello!");
}

// 作为对象，可以添加属性
sayHi.createdBy = "Alarik";
sayHi.callCount = 0;
console.log(sayHi.createdBy); // "Alarik"

// 可以赋给变量
let greet = sayHi; // 复制的是引用，不是副本
greet();           // "Hello!"

// 可以作为参数传递
function runTwice(fn) {
  fn();
  fn();
}
runTwice(sayHi);   // 输出两次 "Hello!"
```

这个特性意味着：当你把一个函数赋值给变量时，你并不是把"函数的定义"复制了一份过去，而是让新变量指向了**同一个函数对象**。就像两个人手里拿着同一张名片——无论谁看，名片上的信息都是一样的。如果有人修改了名片上的字（比如给函数添加了属性），另一个人看到的也是修改后的版本：

```javascript
function counter() {
  counter.count = (counter.count || 0) + 1;
  console.log(`第 ${counter.count} 次调用`);
}

let myCounter = counter;
myCounter(); // 第 1 次调用
myCounter(); // 第 2 次调用
console.log(counter.count); // 2 —— 共享同一个计数器！
```

### 1.2 函数对象的内置属性

每个函数天生就自带两个只读属性：`name` 和 `length`。它们就像是函数自带的"身份名片"和"规格说明"：

```javascript
function add(a, b) { return a + b; }
const multiply = function(x, y) { return x * y; };
const arrow = (n) => n * 2;

console.log(add.name);      // "add"
console.log(multiply.name); // "multiply" —— 引擎自动推断变量名
console.log(arrow.name);    // "arrow"

console.log(add.length);      // 2 —— 定义时的形参个数
console.log(multiply.length); // 2
console.log(arrow.length);    // 1

// rest 参数不计入 length
function many(a, b, ...rest) {}
console.log(many.length); // 2
```

**`name` 属性**的作用远不止于调试时看看函数叫什么名字。现代框架（如 React、Vue）在渲染组件树时依赖它来显示组件名称；性能分析工具用它在火焰图中标注函数入口；错误堆栈中也会显示函数名以便快速定位问题。值得注意的是，即使你创建了一个匿名函数表达式，引擎也会尝试根据上下文推断出一个名称——比如赋值语句中的变量名、对象方法的方法名等。这种"上下文命名"是引擎的一种善意行为，但在某些复杂场景下可能推断失败（比如数组元素中的函数）。

**`length` 属性**则常用于实现"多态式"的函数设计。例如，可以根据回调函数是否接受参数来决定传递什么内容：

```javascript
function ask(question, ...handlers) {
  let answer = confirm(question);
  for (let handler of handlers) {
    if (handler.length === 0) {
      // 无参处理函数 → 只在用户点"确定"时调用
      if (answer) handler();
    } else {
      // 有参处理函数 → 把答案传过去
      handler(answer);
    }
  }
}

ask("你喜欢 JavaScript 吗？",
  () => alert("太好了！"),          // 无参：只在确认时执行
  (result) => alert(`你的选择：${result}`) // 有参：接收结果
);
```

## 二、函数声明的完整语法

### 2.1 基本形式

**函数声明（Function Declaration）**是最经典、最常见的定义函数的方式。它的标准语法结构如下：

```javascript
function 函数名(参数1, 参数2, ...) {
  // 函数体
}
```

关键特点：
- 以关键字 `function` 开头
- **必须有函数名**
- 独立存在于作用域中（不依赖于任何赋值操作）

```javascript
function greet(name) {
  return `你好，${name}！`;
}

console.log(greet("世界")); // "你好，世界！"
```

函数声明就像是在你的代码世界里**注册了一个官方机构**——一旦声明完成，整个作用域内都可以找到它并使用它。这跟你在政府机关登记一家公司的感觉类似：只要手续办完（声明完成），不管你在城市的哪个角落，这家公司都是合法存在且可被查询到的。

### 2.2 函数声明必须具名

这一点非常重要：**函数声明不允许匿名**。你必须给它一个名字，因为这个名字就是它在作用域中的"身份证号"。如果你写了没有名字的函数声明，解析器会直接报错：

```javascript
// ❌ 语法错误：函数声明必须有名称
function() {
  console.log("我是谁？");
}

// ✅ 正确写法
function saySomething() {
  console.log("我有名字！");
}
```

为什么要有这个限制？因为函数声明的核心价值之一就是**提升**——它需要在声明之前就能被访问到。如果函数没有名字，那在声明之前你根本无法引用它，提升也就失去了意义。这就好比你要提前预约一家餐厅——如果连餐厅的名字都不知道，你怎么预约呢？

## 三、函数表达式的灵活用法

### 3.1 基本形式

**函数表达式（Function Expression）**则是另一种完全不同的思路。它不把函数当作一个独立的实体来声明，而是把它当作一个**值**，通过赋值、传参等方式来使用：

```javascript
const 变量名 = function(参数1, 参数2, ...) {
  // 函数体
};
```

注意这里的微妙区别：`function` 关键字不再是语句的开头，而是赋值表达式的一部分。整个 `function(...) {...}` 是一个表达式，它的结果（也就是那个函数对象）被赋给了左边的变量。

```javascript
// 函数表达式：函数是值，被赋给变量
const add = function(a, b) {
  return a + b;
};

console.log(add(3, 5)); // 8
```

函数表达式更像是**雇佣一名临时工**——你不是在政府部门给他注册编制，而是直接把他请进来干活。这名临时工的存在与否，取决于你是否真的发出了聘书（执行了赋值语句）。如果没有走到赋值的那一步，这名临时工就不存在。

### 3.2 匿名函数表达式

最常见的函数表达式形式是**匿名的**——`function` 关键字后面没有名字：

```javascript
const greet = function(name) {
  return `你好，${name}`;
};
```

匿名函数表达式简洁明了，在日常开发中被大量使用。但它的缺点也很明显：当你在调试器中查看调用栈时，看到的是一个 `(anonymous function)` 而不是有意义的名字；当函数内部需要递归调用自身时，也没有现成的名字可用。

### 3.3 命名函数表达式（NFE）

为了解决上述问题，JavaScript 提供了**命名函数表达式（Named Function Expression，简称 NFE）**的语法。它给函数表达式内部的函数体赋予了一个名字，但这个名字只在函数**内部**有效：

```javascript
const factorial = function fact(n) {
  if (n <= 1) return 1;
  return n * fact(n - 1);  // 内部可以通过 fact 调用自身
};

console.log(factorial(5));  // 120
// fact();                   // ❌ 外部无法访问 fact
```

这里发生了一件很有趣的事：`fact` 这个名字只在函数体的作用域内可见，外部是完全不可访问的。这就像是给这位临时工发了一个**内部代号**——只有在他自己工作时才能使用这个代号来指代自己，外界根本不知道有这个代号的存在。

NFE 的优势在于**可靠性**。考虑以下场景：

```javascript
// 使用 NFE 的递归 —— 安全可靠
const countDown = function countdown(n) {
  if (n > 0) {
    console.log(n);
    countdown(n - 1);
  }
};

countDown(3); // 3, 2, 1

// 如果不用 NFE，依赖外部变量名进行递归 —— 有风险
let riskyCount = function(n) {
  if (n > 0) {
    console.log(n);
    riskyCount(n - 1); // 依赖外部变量名
  }
};

let saved = riskyCount;
riskyCount = null;     // 假设外部变量被重新赋值
saved(3);              // 💥 报错！riskyCount is not a function
```

第二种情况下，因为递归依赖的是外部的 `riskyCount` 变量名，一旦这个变量被重新赋值为 `null`，递归调用就会崩溃。而使用 NFE 时，内部的 `countdown` 名字不受外部影响，始终指向函数本身。这就是 NFE 存在的核心价值——**提供了一种不依赖外部环境的可靠自引用机制**。

### 3.4 函数表达式可以匿名也可以具名

总结一下函数表达式的两种形态：

| 形态 | 语法 | 内部可自引 | 外部可访问 |
|------|------|-----------|-----------|
| 匿名表达式 | `const f = function(){}` | ❌ 需要用变量名 | 通过变量名 |
| 命名表达式(NFE) | `const f = function fn(){}` | 可用 `fn` | 仅通过变量名 |

## 四、函数提升（Hoisting）的深层原理

这是本章最重要的概念之一，也是面试中的高频考点。

### 4.1 什么是提升？

**提升（Hoisting）**是指 JavaScript 引擎在执行代码之前，会将**函数声明**整体移动到其所在作用域顶部的行为。这意味着你可以在函数声明之前调用它，而且不会出错：

```javascript
// 在声明之前调用 —— 完全合法
console.log(sum(10, 20)); // 30

// 函数声明在这里才出现
function sum(a, b) {
  return a + b;
}
```

这段代码看起来违反了"先定义后使用"的基本常识，但实际上它是完全正确的。为什么会这样？因为 JavaScript 引擎在正式逐行执行代码之前，会先做一个**预编译阶段**的工作。在这个阶段，引擎会扫描整个代码，找出所有的函数声明，然后把它们的定义"搬"到各自作用域的最顶端。等到真正执行代码的时候，函数早就已经在那里等着了。

用一个生活化的类比：假设你去参加一场考试。虽然试卷上题目是按顺序排列的，但聪明的你可能先快速浏览整张试卷，先把所有题目的位置记在心里（预编译阶段），然后才开始从头作答。当你做到后面某道题发现需要用到前面的知识时，其实你已经知道那些知识在哪里了。函数提升就是这个道理——引擎先"浏览"一遍，记住所有函数的位置。

### 4.2 只有函数声明会提升，函数表达式不会！

这是一个极其关键的区分点，也是无数 bug 的根源：

```javascript
// ========== 函数声明：提升生效 ==========
sayHello(); // "Hello!" ✅ 正常工作

function sayHello() {
  console.log("Hello!");
}

// ========== 函数表达式：提升不生效 ==========
sayGoodbye(); // TypeError: sayGoodbye is not a function ❌ 报错

var sayGoodbye = function() {
  console.log("Goodbye!");
};
```

为什么第二个会报错？因为对于函数表达式来说，提升的不是函数本身，而是**变量声明**。上面的代码实际上等效于：

```javascript
var sayGoodbye;            // 变量声明被提升了（值为 undefined）
sayGoodbye();              // undefined() → 报错！

sayGoodbye = function() {  // 赋值还在原地，没有被提升
  console.log("Goodbye!");
};
```

注意这里发生的不是 `ReferenceError`（未定义），而是 `TypeError`（不是一个函数）。这说明变量 `sayGoodbye` 确实存在（因为它被声明了），但它当前的值是 `undefined`，而 `undefined` 当然不能像函数一样被调用。

这个区别可以这样记忆：**函数声明的提升是"整体搬迁"**——连人带家当一起搬到顶部；**函数表达式的提升只是"挂了个空牌匾"**——变量的名字挂在上面了，但实际的内容还没搬过来。就像一家公司宣布要开分公司，牌子已经挂出去了（变量声明），但员工和设备还没有到位（赋值还未执行）。

### 4.3 提升的实际影响

提升不仅仅是一个学术概念，它在实际开发中有重要的影响：

**场景一：条件声明的问题**

不要试图用条件语句来控制函数声明——这在不同的浏览器中表现不一致：

```javascript
// ⚠️ 不推荐的做法
if (true) {
  function foo() { return 1; }
} else {
  function foo() { return 2; }
}
// 不同浏览器可能返回 1 或 2，行为不确定

// ✅ 推荐做法：使用函数表达式
let bar;
if (true) {
  bar = function() { return 1; };
} else {
  bar = function() { return 2; };
}
```

**场景二：代码组织的可读性**

有些人喜欢把所有函数放在文件底部（保持主逻辑在顶部清晰可见），利用提升来实现这种组织方式：

```javascript
// 主逻辑 —— 清晰展示程序流程
initApp();
loadData();
renderUI();

// 函数定义 —— 放在底部，不影响运行
function initApp() { /* ... */ }
function loadData() { /* ... */ }
function renderUI() { /* ... */ }
```

这种写法在某些团队中很受欢迎，但也有争议。反对者认为它降低了代码的可读性——读者需要跳来跳去才能找到函数定义的位置。我的建议是：遵循团队的代码规范，如果没有明确规范，优先采用"在使用前就近声明"的方式，因为这符合大多数人的阅读直觉。

### 4.4 块级作用域中的提升（ES6+）

在 ES6 之后，如果在块级作用域中使用函数声明，行为变得更加复杂：

```javascript
{
  hoisted(); // 不会报错，但不一定输出期望的结果
  function hoisted() {
    console.log("I am hoisted");
  }
}

hoisted(); // ReferenceError! （在严格模式下）
```

在严格模式下，块级函数的提升仅限于块内部。出了块之后，函数就不存在了。这种行为在不同环境下可能有差异，因此最佳实践是：**避免在块级作用域中使用函数声明**，改用函数表达式或 `let/const` 配合。

## 五、立即执行函数表达式（IIFE）

在 ES6 模块化流行之前，IIFE（Immediately Invoked Function Expression，立即执行函数表达式）是 JavaScript 中创建独立作用域的标准模式。虽然现在有了 `let/const` 的块级作用域和 ES Modules，了解 IIFE 仍然对理解历史代码和某些特定场景有帮助。

### 5.1 基本 IIFE

IIFE 的本质就是一个**被立刻执行的函数表达式**。它由两部分组成：第一部分是用圆括号包裹的匿名函数（使其成为表达式而非声明），第二部分是紧随其后的另一组圆括号（用于调用该函数）：

```javascript
(function() {
  let temp = "我在自己的小房间里";
  console.log(temp);
})();

// console.log(temp); // ReferenceError: temp is not defined
```

IIFE 就像是搭建了一间**临时的隔音工作室**——你在里面做的所有事情（声明的变量、定义的函数）都不会泄漏到外面的世界去。在那个还没有 `let/const` 的年代，开发者们只能用 IIFE 来防止全局变量污染。

### 5.2 IIFE 的常见变体

```javascript
// 变体1：带参数
(function(name) {
  console.log(`你好，${name}`);
})("World"); // "你好，World"

// 变体2：返回值
const result = (function(a, b) {
  return a * a + b * b;
})(3, 4);
console.log(result); // 25

// 变体3：箭头函数版
((msg) => {
  console.log(msg);
})("箭头函数 IIFE 也行");

// 变体4：使用一元运算符代替外层括号
+function() { console.log("加号触发执行"); }();
!function() { console.log("感叹号触发执行"); }();
~function() { console.log("波浪号触发执行"); }();
void function() { console.log("void 触发执行"); }();
```

最后几种使用一元运算符的变体看起来很奇怪，但它们确实是有效的语法。这些运算符的作用仅仅是把后面的函数声明"转换"成函数表达式（因为表达式可以作为运算符的操作数），然后紧跟的括号就会立即调用它。不过这些写法的可读性较差，不建议在生产代码中使用。

### 5.3 IIFE 的现代替代方案

如今大多数情况下，我们已经不需要 IIFE 了：

```javascript
// 旧时代：用 IIFE 创建作用域
(function() {
  let secret = 123;
  // ...
})();

// 新时代：用块级作用域 + let/const
{
  let secret = 123;
  // ...
}

// 或者直接使用 ES Modules（自带作用域隔离）
```

但 IIFE 并非完全没有用武之地。在一些特殊场景下——比如需要在一个表达式中执行一段复杂的初始化逻辑、或者在模块顶层做一些一次性配置——IIFE 仍然是优雅的选择。

## 六、箭头函数与词法 `this`

箭头函数是 ES6 引入的新语法糖，它不仅提供了更简洁的书写方式，更重要的是引入了**词法 `this`**这一革命性的概念。

### 6.1 基本语法速查

```javascript
// 完整写法
const add = (a, b) => {
  return a + b;
};

// 单表达式简写（省略花括号和 return）
const multiply = (a, b) => a * b;

// 单参数（省略参数括号）
const double = n => n * 2;

// 无参数（保留空括号）
const greet = () => console.log("Hello!");

// 返回对象字面量（需用括号包裹）
const createUser = (name, age) => ({ name, age });
```

箭头函数的语法简洁性是其表面优势，但真正的核心差异在于 `this` 的行为。

### 6.2 什么是词法 `this`？

在普通函数中，`this` 的值是在**函数被调用的时候**确定的——它取决于函数是如何被调用的（作为方法调用？用 `new` 调用？用 `call/apply/bind`？还是独立调用？）。这种动态绑定的机制有时会导致令人困惑的行为：

```javascript
const user = {
  name: "Alice",
  friends: ["Bob", "Charlie", "Diana"],
  
  printFriends() {
    // 这里的 this 是 user 对象 ✓
    this.friends.forEach(function(friend) {
      // 但这里呢？this 是什么？
      console.log(`${this.name} 的朋友：${friend}`);
      // 这里的 this 不是 user 了！
    });
  }
};

user.printFriends();
// "undefined 的朋友：Bob"
// "undefined 的朋友：Charlie"
// "undefined 的朋友：Diana"
```

上面的代码中，`forEach` 的回调函数是一个普通函数，它有自己的 `this` 绑定。当它被执行时，`this` 不再指向 `user` 对象（除非处于非严格模式下，此时 `this` 可能是 `window`）。这是一个经典的"丢失 `this`"陷阱。

箭头函数完美地解决了这个问题。**箭头函数没有自己的 `this`**——它的 `this` 值是从定义它的外层作用域中继承过来的（即"词法绑定"）：

```javascript
const user = {
  name: "Alice",
  friends: ["Bob", "Charlie", "Diana"],
  
  printFriends() {
    // 这里 this 是 user
    this.friends.forEach((friend) => {
      // 箭头函数继承了外层的 this → 也是 user ✓
      console.log(`${this.name} 的朋友：${friend}`);
    });
  }
};

user.printFriends();
// "Alice 的朋友：Bob"
// "Alice 的朋友：Charlie"
// "Alice 的朋友：Diana"
```

### 6.3 词法 `this` 的本质

词法 `this` 的原理可以用一个简单的类比来解释：

想象一下普通函数和箭头函数在处理 `this` 时的区别：

- **普通函数**就像一个**临时演员**——每次上场时都要问导演："我今天演谁？"（每次调用时重新确定 `this`）
- **箭头函数**就像一个**固定角色演员**——他在排练时就确定了自己要扮演的角色（定义时确定 `this`），不管在哪个舞台演出，角色都不变

具体来说，箭头函数在定义时，会"记住"当时外层作用域中的 `this` 值，并在自己的函数体内一直使用这个值。这个过程发生在代码编写时（静态分析），而不是运行时（动态查找）：

```javascript
function Team() {
  this.members = [];
  
  // 普通函数：this 动态绑定，容易出问题
  // setInterval(function() {
  //   this.members.push(new Date()); // this 可能不是 Team 实例
  // }, 1000);

  // 箭头函数：this 词法绑定，永远指向 Team 实例
  setInterval(() => {
    this.members.push(new Date()); // ✓ this 就是当前 Team 实例
  }, 1000);
}

const team = new Team();
```

### 6.4 箭头函数不能用作构造函数

由于箭头函数没有自己的 `this`，它自然也不能用作构造函数。当你尝试用 `new` 调用一个箭头函数时，会直接抛出错误：

```javascript
const Person = (name) => {
  this.name = name;
};

const p = new Person("Alice");
// TypeError: Person is not a constructor
```

这是因为构造函数的关键步骤之一是创建一个新对象并将 `this` 绑定到这个新对象上，而箭头函数根本没有这个能力——它连自己的 `this` 都没有，怎么去绑定新对象呢？

同样的原因，箭头函数也没有 `prototype` 属性：

```javascript
function normalFn() {}
const arrowFn = () => {};

console.log(normalFn.prototype); // { constructor: f }
console.log(arrowFn.prototype);  // undefined
```

### 6.5 没有 `arguments` 对象

除了 `this`，箭头函数也没有自己的 `arguments` 对象。如果你在箭头函数内部使用 `arguments`，它会指向外层普通函数的 `arguments`（如果有），或者直接抛出 ReferenceError：

```javascript
function outer() {
  const inner = () => {
    // 这里的 arguments 来自 outer 函数
    console.log(arguments);
  };
  inner(1, 2, 3); // 打印的是调用 outer 时的参数
}

outer("a", "b"); // ["a", "b"]
```

如果箭头函数不在任何普通函数内，则 `arguments` 直接不存在：

```javascript
const standalone = () => {
  // console.log(arguments); // ReferenceError: arguments is not defined
};

standalone(1, 2, 3);
```

解决方案是使用**剩余参数（Rest Parameters）**来替代：

```javascript
const sumAll = (...args) => args.reduce((sum, n) => sum + n, 0);
console.log(sumAll(1, 2, 3, 4)); // 10
```

### 6.6 没有 `super` 和 `new.target`

箭头函数同样没有自己的 `super` 和 `new.target`。这两个关键字都跟类的继承和构造过程相关，而箭头函数从一开始就不是为这些场景设计的：

```javascript
class Animal {
  constructor(name) {
    this.name = name;
  }

  // 普通方法：可以使用 super
  speak() {
    console.log(`${this.name} 发出声音`);
  }
}

class Dog extends Animal {
  // 箭头函数不能作为类的方法（因为需要 super）
  // bark = () => super.speak(); // ❌ SyntaxError
  
  // 但可以在方法内部使用箭头函数
  delayedBark() {
    setTimeout(() => {
      console.log(`${this.name}: 汪！`); // this 词法绑定 ✓
    }, 1000);
  }
}
```

## 七、`new.target` 的妙用

`new.target` 是一个特殊的元属性，用来检测当前函数是否是通过 `new` 操作符调用的。

### 7.1 基本用法

当一个函数被 `new` 调用时，`new.target` 的值就是这个构造函数本身；如果是普通调用，则为 `undefined`：

```javascript
function User(name) {
  if (!new.target) {
    console.warn("警告：应该用 new 调用 User()");
    return new User(name); // 自动修正
  }
  this.name = name;
}

const u1 = new User("Alice"); // 正常用 new
const u2 = User("Bob");        // 忘记 new → 自动修正

console.log(u1 instanceof User); // true
console.log(u2 instanceof User); // true
```

这个特性常用于**安全构造函数模式**——即使开发者忘记写 `new`，也能确保正确的行为。很多库的内部实现都用到了这种技巧。

### 7.2 与箭头函数的关系

正如前文提到的，箭头函数中没有 `new.target`。如果你在箭头函数中使用它，得到的将是外层的 `new.target` 值（如果有的话）：

```javascript
function Factory() {
  const check = () => {
    console.log(new.target === Factory); // true
  };
  check();
}

new Factory();
```

## 八、四种定义方式的完整对比

现在让我们把所有定义函数的方式放在一起做一个全面的对比：

### 8.1 核心特性对照表

| 特性 | 函数声明 | 匿名函数表达式 | NFE | 箭头函数 |
|------|---------|--------------|-----|---------|
| **提升** | 整体提升到作用域顶部 | 仅变量声明提升（值为 `undefined`） | 同左 | 同左 |
| **必须具名** | 是 | 否 | 内部名可选 | 通常匿名 |
| **可作为构造函数** | 是 | 是 | 是 | **否** |
| **`this` 绑定** | 动态（调用时确定） | 动态 | 动态 | **词法**（定义时确定） |
| **`arguments`** | 有 | 有 | 有 | **无** |
| **`super`** | 有（在方法中） | 有 | 有 | **无** |
| **`new.target`** | 有 | 有 | 有 | **无** |
| **`prototype`** | 有 | 有 | 有 | **无** |
| **适用场景** | 工具函数、主要逻辑 | 条件赋值、回调和事件处理器 | 递归、调试友好的回调 | 短回调、保留外层 `this` |

### 8.2 如何选择？

面对这么多选择，什么时候该用哪种方式？以下是一些实用的决策指南：

**使用函数声明的场景：**
- 这是一个主要的工具函数或核心逻辑函数
- 你希望在声明之前就能调用它（利用提升）
- 代码需要良好的自描述性（函数名出现在栈追踪中）

```javascript
// ✅ 工具函数：使用函数声明
function formatDate(date) {
  // ...
}
```

**使用函数表达式的场景：**
- 函数需要作为值传递（回调、高阶函数参数）
- 函数的定义依赖于某个条件
- 你想要更好的代码组织（将函数赋值到对象上）

```javascript
// ✅ 回调：使用函数表达式
button.addEventListener('click', function() {
  // ...
});

// ✅ 条件定义
const validator = useStrictMode ? strictValidator : looseValidator;
```

**使用 NFE 的场景：**
- 函数需要递归调用自身
- 你希望调试时有清晰的函数名
- 你担心外部变量名可能会被改变

```javascript
// ✅ 递归：使用 NFE
const traverse = function walk(node) {
  if (!node) return;
  process(node);
  walk(node.left);
  walk(node.right);
};
```

**使用箭头函数的场景：**
- 简短的单行回调（数组方法、Promise 链）
- 需要保留外层 `this` 的嵌套函数
- 不需要 `arguments`/`super`/`new` 的纯计算函数

```javascript
// ✅ 简短回调：使用箭头函数
const names = users.map(u => u.name);
const adults = users.filter(u => u.age >= 18);

// ✅ 保留 this
class Timer {
  constructor() {
    this.seconds = 0;
    setInterval(() => this.seconds++, 1000);
  }
}
```

**不应该使用箭头函数的场景：**
- 作为对象的方法（需要动态 `this`）
- 作为构造函数（需要 `prototype`）
- 作为需要 `arguments` 的函数
- 作为 Vue/React 组件的方法（需要特定的 `this` 绑定）

```javascript
// ❌ 不要这样做
const obj = {
  name: "test",
  sayName: () => {
    console.log(this.name); // this 不是 obj！
  }
};

// ✅ 应该用普通方法
const obj = {
  name: "test",
  sayName() {
    console.log(this.name); // this 正确指向 obj
  }
};
```

## 九、回调函数与高阶函数

理解了函数作为值的特性后，一个自然的延伸就是**回调函数（Callback）**和**高阶函数（Higher-Order Function）**的概念。

### 9.1 什么是回调函数？

回调函数就是**作为参数传递给另一个函数的函数**。接收回调函数的函数被称为高阶函数。这是一种极其常见的模式——几乎所有的异步操作（事件监听、定时器、网络请求）都以回调为基础：

```javascript
// 定时器回调
setTimeout(() => console.log("1秒后执行"), 1000);

// 数组方法的回调
[1, 2, 3].map(n => n * 2);       // [2, 4, 6]
[1, 2, 3].filter(n => n > 1);    // [2, 3]
[1, 2, 3].reduce((s, n) => s + n); // 6

// 事件回调
element.addEventListener('click', function(e) {
  console.log("被点击了！", e);
});

// Promise 回调
fetch('/api/data')
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error(error));
```

### 9.2 高阶函数的模式

高阶函数不仅能接收函数作为参数，还能**返回函数**。这让很多强大的编程模式成为可能：

```javascript
// 工厂模式：生成具有预设行为的函数
function createMultiplier(factor) {
  return function(number) {
    return number * factor;
  };
}

const double = createMultiplier(2);
const triple = createMultiplier(3);

console.log(double(5));  // 10
console.log(triple(5));  // 15
```

这个模式之所以能工作，是因为返回的内部函数"记住"了创建它时的环境——这就是**闭包（Closure）**的力量。虽然本章的重点是函数定义方式，但闭包是函数表达式最重要的应用场景之一，值得在后续章节深入学习。

### 9.3 函数组合

高阶函数还可以用来实现**函数组合**——把多个简单的函数串联起来形成复杂的管道：

```javascript
const compose = (...fns) => x => fns.reduceRight((v, f) => f(v), x);

const trim = s => s.trim();
const toLowerCase = s => s.toLowerCase();
const split = s => s.split(/\s+/);

const normalize = compose(split, toLowerCase, trim);

console.log(normalize("  Hello World  "));
// ["hello", "world"]
```

## 十、常见陷阱与最佳实践

### 10.1 陷阱清单

**陷阱 1：在循环中创建闭包丢失索引**

```javascript
// ❌ 经典错误
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// 输出：3, 3, 3（而不是 0, 1, 2）

// ✅ 用 let 解决（块级作用域）
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// 输出：0, 1, 2
```

**陷阱 2：箭头函数作为对象方法**

```javascript
const calculator = {
  value: 0,
  increment: () => this.value++,  // this 不是 calculator！
};

calculator.increment();
console.log(calculator.value); // 还是 0，没变化
```

**陷阱 3：用 `typeof` 检测提升后的变量**

```javascript
console.log(typeof undeclaredVar); // "undefined"（不会报错）
console.log(typeof declaredLater); // "undefined"（已提升但未赋值）

var declaredLater = 42;
```

**陷阱 4：IIFE 中的严格模式**

```javascript
// IIFE 中的严格模式只作用于函数内部
(function() {
  'use strict';
  // 这里的代码在严格模式下运行
})();
```

### 10.2 最佳实践建议

1. **默认使用函数声明**来定义主要的业务逻辑函数
2. **使用函数表达式**来定义回调和需要条件赋值的函数
3. **善用 NFE** 来编写需要递归且调试友好的函数
4. **优先使用箭头函数**来编写简短的回调（尤其是需要保留外层 `this` 时）
5. **避免在对象字面量的方法中使用箭头函数**（除非你有充分的理由）
6. **不要依赖函数声明的条件性提升**（行为不一致）
7. **利用 `new.target`** 来创建安全的构造函数

## 十一、知识图谱

```
函数定义方式总览
├── 函数声明（Function Declaration）
│   ├── 语法：function name() {}
│   ├── 特性：整体提升、必须具名
│   └── 适用：核心逻辑、工具函数
│
├── 函数表达式（Function Expression）
│   ├── 匿名表达式：const fn = function() {}
│   ├── 命名表达式（NFE）：const fn = function fname() {}
│   │   └── 内部名仅函数体内可见，用于可靠自引用
│   ├── 特性：仅变量提升、不必须具名
│   └── 适用：回调、条件赋值、高阶函数
│
├── 箭头函数（Arrow Function）
│   ├── 语法：const fn = () => expression
│   ├── 核心：词法 this（无 own this/arguments/super/new.target）
│   ├── 不能：作为构造函数、使用 arguments、有 prototype
│   └── 适用：短回调、保留外层 this
│
├── IIFE（立即执行函数表达式）
│   ├── 语法：(function() {})()
│   ├── 作用：创建独立作用域
│   └── 现代：多数情况被 let/const 块替代
│
└── 相关概念
    ├── 提升机制（Hoisting）
    │   ├── 函数声明 → 整体搬迁
    │   ├── var 变量 → 声明提升（值 undefined）
    │   └── let/const → 暂时性死区 TDZ
    ├── this 绑定规则
    │   ├── 默认绑定：独立调用
    │   ├── 隐式绑定：obj.method()
    │   ├── 显式绑定：call/apply/bind
    │   └── new 绑定：构造函数调用
    └── 函数对象属性
        ├── name：函数名（可推断）
        └── length：形参个数（不含 rest）
```
