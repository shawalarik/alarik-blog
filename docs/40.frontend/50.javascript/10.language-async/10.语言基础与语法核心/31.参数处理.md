# 参数处理 —— 默认参数、剩余参数、arguments 对象、参数解构

> **核心内容**：JavaScript 函数参数的完整机制——形参与实参的传递规则、默认值的惰性求值、剩余参数的收集原理、`arguments` 类数组对象的历史与局限、解构参数的高级模式，以及如何在实际开发中设计灵活而清晰的函数接口。

---

## 一、参数的本质：形参与实参

在深入各种参数处理技巧之前，我们需要先厘清两个经常被混淆的基本概念：**形参（Parameter）**和**实参（Argument）**。

### 1.1 形参与实参的区别

这两个术语看起来很像，但它们描述的是完全不同的东西：

```javascript
//          形参（Parameters）：函数声明时定义的"占位符"
//          ↓        ↓
function greet(name, greeting) {
  return `${greeting}，${name}！`;
}

//                          实参（Arguments）：调用时实际传入的具体值
greet("Alice", "你好");   // "你好，Alice！"
greet("Bob", "欢迎");     // "欢迎，Bob！"
```

用生活中的类比来说明：**形参就像餐厅菜单上的"菜品名称"和"备注栏"**——它们是预先定义好的空位，告诉厨师这道菜需要什么信息；**实参就像顾客点餐时填写的具体内容**——"我要一份宫保鸡丁，微辣"。菜单模板不会变（形参固定），但每次顾客点的具体内容可以不同（实参灵活）。

理解这个区别非常重要，因为后续所有的参数处理技巧都是围绕着"当实参没有按预期提供时，函数该如何应对"这个问题展开的。

### 1.2 参数传递机制：值复制

JavaScript 中所有函数参数都是通过**值传递（pass by value）**的方式进行的。这意味着当你把一个值传给函数时，函数接收到的是该值的**副本**，而不是原始值本身。对于原始类型来说，这意味着对参数的修改完全不会影响外部变量：

```javascript
function tryToModify(value) {
  value = value + " [已修改]";
  console.log("函数内部:", value); // "hello [已修改]"
}

let message = "hello";
tryToModify(message);
console.log("函数外部:", message); // "hello" —— 原值未被改变！
```

这个行为可以这样理解：你把一份文件复印了一份交给同事修改（传参）。同事拿到的是复印件，他可以在复印件上随意涂改、标注，但你手里拿着的原件纹丝不动。

对于引用类型（对象、数组），虽然传递的仍然是"值的副本"，但这个"值"本身是一个引用（内存地址），所以函数内部可以通过这个引用来修改对象的属性：

```javascript
function modifyUser(user) {
  user.name = user.name + " Jr."; // 通过引用修改了原对象的属性
}

let person = { name: "John" };
modifyUser(person);
console.log(person.name); // "John Jr." —— 对象被修改了！

// 但如果直接替换整个参数变量：
function replaceUser(user) {
  user = { name: "Stranger" }; // 只是让局部变量指向了一个新对象
}

let another = { name: "Alice" };
replaceUser(another);
console.log(another.name); // "Alice" —— 外部对象未受影响
```

这里的关键区别在于：**修改对象内部的属性**是通过共享的引用操作的（像是在同一个房间里重新摆放家具）；而**替换整个参数变量**只是让局部指针转向了另一个地方（像是你自己搬到了另一间房子，原来的房子还在那里）。

## 二、默认参数

默认参数是 JavaScript 处理"缺失参数"最直观的方式。它允许你在定义函数时就为每个参数指定一个"后备值"，当调用者没有传入对应位置的实参（或者传入了 `undefined`）时，这个后备值就会自动生效。

### 2.1 基本语法

使用 `=` 运算符为参数设置默认值：

```javascript
function greet(name, greeting = "你好") {
  return `${greeting}，${name}！`;
}

console.log(greet("世界"));         // "你好，世界！" —— 使用默认问候语
console.log(greet("Alice", "欢迎")); // "欢迎，Alice！" —— 使用提供的问候语
```

默认参数的工作方式非常自然——它就像是给每个形参位置放了一张**备用的入场券**。如果客人自己带了票（提供了实参），就用客人的；如果没带，就发给他那张备用的。整个流程对调用者来说是透明的，不需要做任何额外的判断或检查。

### 2.2 默认参数只在值为 `undefined` 时触发

这是一个极其重要但容易被误解的细节：**只有当对应位置的参数严格等于 `undefined` 时，默认值才会生效**。传入 `null`、`0`、空字符串 `""` 或 `false` 这些"假值"都不会触发默认值：

```javascript
function showValue(value = "默认值") {
  console.log(`"${value}"`);
}

showValue();       // "默认值"      ← 没传参数 → undefined → 触发默认值 ✓
showValue(undefined); // "默认值"      ← 显式传 undefined → 触发默认值 ✓
showValue(null);    // "null"         ← null ≠ undefined → 不触发 ✗
showValue(0);       // "0"            ← 0 ≠ undefined → 不触发 ✗
showValue("");      // ""             ← 空字符串 ≠ undefined → 不触发 ✗
showValue(false);   // "false"        ← false ≠ undefined → 不触发 ✗
```

这种设计的逻辑是合理的：`undefined` 的语义是"这个值不存在/未知"，所以需要用一个默认值来填补；而 `null` 的语义是"这个值存在，但它是空的/无意义的"，它本身就是一种有意义的值，不应该被随意覆盖。这就像是你去银行开户：如果你说"我不知道填什么"（undefined），工作人员会帮你填上默认选项；但如果你明确写了"无"（null），那就尊重你的选择。

### 2.3 默认值可以是任意表达式

默认参数的强大之处在于它不限于简单的字面量——你可以写任何合法的 JavaScript 表达式作为默认值：

```javascript
function createMessage(text, timestamp = Date.now()) {
  return { text, timestamp };
}

console.log(createMessage("Hello"));
// { text: "Hello", timestamp: 1740000000000 }（当前时间戳）
```

更关键的是：**默认表达式是惰性求值的（lazily evaluated）**——只有在真正需要默认值的时候（即参数为 `undefined` 时），表达式才会被求值计算。如果调用者提供了参数，那么默认表达式根本不会执行：

```javascript
let callCount = 0;

function expensiveDefault() {
  callCount++;
  console.log("执行了昂贵的默认值计算！");
  return Math.random();
}

function processData(data = expensiveDefault()) {
  return data * 2;
}

processData(10);    // expensiveDefault 不会被调用！
processData(10);    // 还是不会被调用
console.log(callCount); // 0

processData();      // 这次才调用 expensiveDefault
processData();      // 再次调用
console.log(callCount); // 2
```

这种"按需执行"的特性非常实用。想象一下你有一个默认值需要从数据库查询、从 API 获取、或者进行复杂的数学运算——你不希望每次调用函数都白白执行这些操作。惰性求值保证了**只有在真正需要时才付出代价**，类似于"按需打印"的服务——只有客户真的下单了才去印刷，避免了浪费。

### 2.4 默认值可以使用前面的参数

默认表达式中可以引用前面已经声明的参数：

```javascript
function createUser(name, role = "用户", greeting = `${role} ${name}`) {
  return { name, role, greeting };
}

console.log(createUser("张三"));
// { name: "张三", role: "用户", greeting: "用户 张三" }

console.log(createUser("李四", "管理员"));
// { name: "李四", role: "管理员", greeting: "管理员 李四" }
```

注意这里的顺序限制：**默认值只能引用其左侧（前面）的参数**。这是因为 JavaScript 引擎是从左到右依次解析参数的，右侧的参数在那一刻还没有被赋值。试图引用后面的参数会导致抛出 `ReferenceError`（处于暂时性死区 TDZ 中）：

```javascript
// ❌ 错误：不能引用后面尚未初始化的参数
function badExample(a = b, b) {
  return [a, b];
}
// TDZ Error: Cannot access 'b' before initialization

// ✅ 正确：只能引用前面的参数
function goodExample(a, b = a * 2) {
  return [a, b];
}
goodExample(5); // [5, 10]
```

### 2.5 历史遗留：ES6 之前的默认值写法

在 ES6 引入正式的默认参数语法之前，开发者们用各种 workaround 来模拟相同的行为。了解这些历史写法对于维护老代码很有帮助：

**方法一：显式检查 `undefined`**

```javascript
function showMessage(from, text) {
  if (text === undefined) {
    text = '没有消息';
  }
  console.log(`${from}: ${text}`);
}
```

这是最精确的做法——严格检查是否为 `undefined`，行为与现代默认参数语法完全一致。

**方法二：使用 `||` 运算符（短路求值）**

```javascript
function showMessage(from, text) {
  text = text || '没有消息';  // 如果 text 是假值，就用默认值
  console.log(`${from}: ${text}`);
}
```

这种写法简洁但有一个陷阱：**所有假值都会触发默认值**，不仅仅是 `undefined`。如果你希望允许传入 `0`、空字符串等有效值，这种方式就会出问题：

```javascript
function showCount(count) {
  count = count || 10; // ⚠️ 问题：count 为 0 时也会变成 10！
  return count;
}

showCount(0); // 10 —— 但我们明明传了 0！
```

**方法三：使用现代的 `??` 空值合并运算符**

```javascript
function showCount(count ??= 10) {
  return count;
}

showCount(0);    // 0 —— 正确保留了 0 ✓
showCount(null); // 10 —— null 触发默认值 ✓
showCount();     // 10 —— undefined 触发默认值 ✓
```

`??` 运算符只会在左边的值为 `null` 或 `undefined` 时返回右边的值，完美地弥补了 `||` 的缺陷。它是现代代码中处理默认值的最佳选择之一。

## 三、剩余参数（Rest Parameters）

剩余参数是 ES6 引入的一个革命性特性，它解决了长期以来 JavaScript 开发者在处理"可变数量参数"时的痛点。

### 3.1 基本语法与工作原理

使用三个点 `...` 作为前缀来声明剩余参数。它会将**所有未被其他形参匹配到的实参**收集到一个真正的数组中：

```javascript
function sumAll(...numbers) {
  let total = 0;
  for (const num of numbers) {
    total += num;
  }
  return total;
}

console.log(sumAll(1));           // 1
console.log(sumAll(1, 2));        // 3
console.log(sumAll(1, 2, 3, 4)); // 10
console.log(sumAll());            // 0 —— 没有参数时得到空数组
```

剩余参数的工作过程可以用一个生动的场景来比喻：假设你开了一家快递代收点。普通参数就像是指定了特定收货人的包裹（比如"给张三的"、"给李四的"），而剩余参数就是一个写着**"其他人"的大筐子**——所有不属于已指定收货人的包裹，全部扔进这个筐子里。最后你会得到一个完整的清单（数组），里面包含了所有"其他包裹"的信息。

### 3.2 混合使用：普通参数 + 剩余参数

剩余参数可以和普通的命名参数一起使用，但它必须放在参数列表的**最后面**。前面的普通参数会按顺序一一匹配，剩下的全部归剩余参数：

```javascript
function introduce(firstName, lastName, ...titles) {
  console.log(`姓名: ${firstName} ${lastName}`);
  console.log(`头衔: ${titles.join(', ')}`);
}

introduce("尤利乌斯", "凯撒", "执政官", "独裁官", "大祭司");
// 姓名: 尤利乌斯 凯撒
// 头衔: 执政官, 独裁官, 大祭司
// titles 数组的内容是: ["执政官", "独裁官", "大祭司"]
```

为什么必须放在最后？这是出于逻辑一致性的考虑。如果把剩余参数放在中间，引擎就不知道哪些实参应该归它、哪些应该给后面的参数了。就像你不能在点名册的中间写一行"其余所有人"——那后面的人到底算不算"其余"呢？

```javascript
// ❌ 语法错误：Rest parameter must be last formal parameter
function invalid(first, ...rest, last) {
  // rest 和 last 之间怎么划分？
}
```

### 3.3 剩余参数得到的是真正的数组

这一点至关重要：**剩余参数产生的是一个真正的 `Array` 实例**，而不是类似数组的对象。这意味着你可以直接在上面使用所有数组方法（`map`、`filter`、`reduce` 等），而不需要额外的转换：

```javascript
function analyze(...values) {
  const stats = {
    count: values.length,
    sum: values.reduce((s, v) => s + v, 0),
    avg: values.reduce((s, v) => s + v, 0) / values.length,
    positive: values.filter(v => v > 0),
    doubled: values.map(v => v * 2),
  };
  return stats;
}

console.log(analyze(-2, 5, 0, 8, -3));
// {
//   count: 5,
//   sum: 8,
//   avg: 1.6,
//   positive: [5, 8],
//   doubled: [-4, 10, 0, 16, -6]
// }
```

### 3.4 剩余参数与函数 length 属性的关系

回顾我们在函数声明章节提到的 `length` 属性：**剩余参数不计入函数的 `length`**。这是因为 `length` 反映的是函数在被调用前就能确定的"期望参数个数"，而剩余参数的数量是不确定的：

```javascript
function fixedArgs(a, b, c) {}
function withRest(a, b, ...rest) {}

console.log(fixedArgs.length);  // 3
console.log(withRest.length);  // 2 —— rest 不计入
```

这个特性有时会被用来实现一些巧妙的模式，比如根据 `length` 属性来判断一个回调函数是否接受参数，从而采取不同的调用策略。

## 四、`arguments` 对象：历史遗产

在 ES6 引入剩余参数之前，JavaScript 提供了一个内置的 **`arguments` 对象**来访问函数接收到的所有实参。

### 4.1 什么是 arguments？

`arguments` 是一个**类数组对象（array-like object）**，它在每个非箭头函数体内自动可用，包含了一次函数调用中传入的所有实参信息：

```javascript
function listArguments() {
  console.log(arguments);
  console.log("长度:", arguments.length);
  
  for (let i = 0; i < arguments.length; i++) {
    console.log(`arguments[${i}] =`, arguments[i]);
  }
}

listArguments("苹果", "香蕉", "橙子");
// Arguments(3) ["苹果", "香蕉", "橙子"]
// 长度: 3
// arguments[0] = 苹果
// arguments[1] = 香蕉
// arguments[2] = 橙子
```

注意 `arguments` 有几个特点：
- 它**有 `length` 属性**和数字索引（像数组一样可以通过下标访问元素）
- 它**不是真正的 `Array`**实例（不能用 `map`、`filter` 等数组方法）
- 它包含了**所有实参**，无法像剩余参数那样排除掉前面已被命名的参数

### 4.2 为什么说 arguments 是"类数组"？

`arguments` 对象之所以被称为"类数组"，是因为它的长相和行为介于数组和普通对象之间。你可以把它理解成一个**穿着数组马甲的普通对象**——它确实有编号的位置和长度信息，但缺少数组应有的核心技能：

```javascript
function checkArguments() {
  console.log(Array.isArray(arguments));              // false —— 不是数组
  console.log(typeof arguments.forEach);               // "undefined" —— 没有 forEach
  console.log(Object.prototype.toString.call(arguments));
  // "[object Arguments]" —— 它自己的类型
}

checkArguments(1, 2, 3);
```

如果你想对 `arguments` 使用数组方法，必须先把它转换成真正的数组：

```javascript
// 方法一：Array.from() —— 最推荐
const args1 = Array.from(arguments);

// 方法二：展开运算符
const args2 = [...arguments];

// 方法三：旧式写法（slice 劫持）
const args3 = Array.prototype.slice.call(arguments);

// 转换后就可以自由使用数组方法了
args1.filter(x => x > 0).map(x => x * 2);
```

这些转换方法的背后原理各不相同：`Array.from()` 可以将任何可迭代对象或类数组对象转为数组；展开运算符利用了 `arguments` 的迭代器协议（如果支持的话）；而 `slice.call()` 则是一种利用原型链借用的经典 hack——让 `arguments` 借用 `Array.prototype.slice` 方法来创建一个新的数组副本。

### 4.3 arguments 与剩余参数的核心差异

| 特性 | `arguments` | 剩余参数 `...args` |
|------|------------|-------------------|
| **类型** | 类数组对象 | 真正的 Array |
| **数组方法** | 需要手动转换 | 直接可用 |
| **箭头函数** | 不可用 | 可用 |
| **作用范围** | 包含**所有**参数 | 仅包含**未匹配**的参数 |
| **可读性** | 隐式的特殊变量 | 显式声明的参数 |
| **严格模式限制** | 行为受限（不再映射形参变化） | 无限制 |

在现代 JavaScript 开发中，**几乎所有的 `arguments` 用法都应该被剩余参数替代**。剩余参数更清晰、更安全、功能更强。唯一的例外是需要维护不支持 ES6 的极旧环境（如 IE11）时。

### 4.4 箭头函数中没有 arguments

正如我们在函数声明章节中学到的，箭头函数**没有自己的 `arguments` 对象**。如果在箭头函数内部使用 `arguments`，它引用的是外层普通函数中的 `arguments`（如果有），否则会直接报错：

```javascript
function outer() {
  // 这里的 arguments 属于 outer
  const inner = () => {
    console.log(arguments); // 打印 outer 的 arguments
  };
  inner("A", "B"); // 但这里传的参数不影响输出
}

outer("X", "Y", "Z");
// Arguments(3) ["X", "Y", "Z"] —— 来自 outer

// 在顶层箭头函数中使用
const standalone = () => {
  // console.log(arguments); // ReferenceError: arguments is not defined
};
```

这也是为什么要优先使用剩余参数的原因之一——它在箭头函数中也能正常工作。

## 五、展开运算符（Spread Syntax）

展开运算符 `...` 和剩余参数使用了相同的三个点符号，但它们的语义恰好相反：**剩余参数是把多个值"打包"成数组，展开运算符则是把数组"拆包"成多个独立的值**。区分两者的关键看上下文：出现在函数**定义**的参数位置就是 Rest（收集）；出现在函数**调用**或字面量中就是 Spread（展开）。

### 5.1 在函数调用中展开数组

最常见的用途是将数组元素作为独立参数传递给函数：

```javascript
const numbers = [3, 7, 1, 9, 5];

// ❌ 直接传数组：Math.max 接收到的是单个数组参数
console.log(Math.max(numbers)); // NaN —— 数组转数字得到 NaN

// ✅ 展开后传参：Math.max 接收到的是 5 个独立数字
console.log(Math.max(...numbers)); // 9
```

这个过程就像是把一个**密封的礼盒（数组）打开**，把里面的每一份礼物（元素）单独拿出来递给收礼物的人（函数参数）。如果不打开盒子直接递过去，对方只会看到一个盒子，不知道里面装的是什么。

展开运算符还支持**同时展开多个数组**以及**混合普通值和展开值**：

```javascript
const arr1 = [1, -2, 3, 4];
const arr2 = [8, 3, -8, 1];

// 混合多个展开和普通值
const maxVal = Math.max(0, ...arr1, 100, ...arr2, 50);
// 等价于 Math.max(0, 1, -2, 3, 4, 100, 8, 3, -8, 1, 50)
// 结果: 100
```

### 5.2 在数组字面量中展开

展开运算符可以用来合并数组、复制数组或在数组中插入元素：

```javascript
const part1 = [1, 2, 3];
const part2 = [7, 8, 9];

// 合并数组
const merged = [...part1, 4, 5, 6, ...part2];
console.log(merged); // [1, 2, 3, 4, 5, 6, 7, 8, 9]

// 浅拷贝数组
const copy = [...part1];
console.log(copy === part1); // false —— 是新的数组
console.log(JSON.stringify(copy) === JSON.stringify(part1)); // true —— 内容相同

part1.push(999);
console.log(copy); // [1, 2, 3] —— 不受原数组影响
```

浅拷贝的概念很重要：展开运算符只复制了数组的第一层数据。如果数组中包含对象或其他引用类型的元素，复制的只是它们的引用，而非深层的克隆：

```javascript
const original = [{ id: 1 }, { id: 2 }];
const shallowCopy = [...original];

shallowCopy[0].id = 999; // 修改嵌套对象
console.log(original[0].id); // 999 —— 原数组也被影响了！
```

### 5.3 将字符串展开为字符数组

由于展开运算符底层依赖迭代器协议（Iterator Protocol），它可以作用于**任何可迭代对象**，包括字符串：

```javascript
const str = "你好世界";
const chars = [...str]; // ['你', '好', '世', '界']

// 这比 String.prototype.split('') 更可靠
// 因为 split 对某些 Unicode 字符（如表情符号）的处理可能有问题
const emoji = "👨‍👩‍👧‍👦";
console.log([...emoji].length);  // 1 —— 正确识别为一个字符簇
console.log(emoji.split('').length); // 8 —— 错误地拆成了多个部分
```

### 5.4 在对象字面量中展开

ES2018 将展开运算符扩展到了对象字面量中（称为 Object Spread/Rest Properties），用于对象的浅拷贝和合并：

```javascript
const baseConfig = {
  theme: "dark",
  language: "zh-CN",
  fontSize: 16,
};

// 合并配置（后者覆盖前者）
const userConfig = {
  ...baseConfig,
  fontSize: 20,       // 覆盖基础配置
  showLineNumbers: true, // 新增属性
};

console.log(userConfig);
// { theme: "dark", language: "zh-CN", fontSize: 20, showLineNumbers: true }

// 注意：baseConfig 不受影响
console.log(baseConfig.fontSize); // 16
```

对象展开的**覆盖规则**是：当多个源对象中有相同的属性时，**后出现的值胜出**。这就像给一张表单填写答案——每个人都可以填写字段，但最后一个填写的版本才是最终生效的版本。

## 六、解构参数（Destructuring Parameters）

解构赋值与函数参数的结合，是现代 JavaScript 中设计优雅函数接口的最强大工具之一。它让你可以在函数定义的那一刻就直接"拆开"传入的对象或数组，提取出你关心的数据。

### 6.1 对象解构参数

当函数需要接收大量可选参数时，传统的做法是按位置列出所有参数，既难记又难以扩展：

```javascript
// 传统做法：参数多到令人崩溃
function createUser(name, age, email, phone, address, city, country, isActive) {
  // 第5个参数是什么来着？address？city？
  // 调用时很容易搞混顺序...
}
createUser("Alice", 30, "alice@example.com", "138...", "...", "Beijing", "CN", true);
```

使用对象解构参数后，一切都变得清晰明了：

```javascript
// 现代做法：解构参数，清晰且灵活
function createUser({ name, age, email, phone, address, city, country, isActive }) {
  console.log(`创建用户: ${name}, ${age}岁`);
}

// 调用时传入一个对象，属性名一目了然
createUser({
  name: "Alice",
  age: 30,
  email: "alice@example.com",
  phone: "138...",
  address: "...",
  city: "Beijing",
  country: "CN",
  isActive: true,
});
```

这种方式的优点显而易见：
- **自文档化**：每个参数都有名字，不需要记忆位置
- **顺序无关**：调换属性的顺序不影响结果
- **可选择性**：只需要传你关心的属性，其他的可以省略
- **可扩展性**：新增参数不会破坏已有的调用代码

### 6.2 解构参数的默认值

解构参数同样支持默认值，而且可以为**每个单独的属性**设置不同的默认值：

```javascript
function drawCircle({
  x = 0,
  y = 0,
  radius = 10,
  color = "black",
  filled = true,
}) {
  console.log(`在 (${x}, ${y}) 画半径 ${radius} 的${color}${filled ? '实心' : '空心'}圆`);
}

drawCircle({ radius: 20, color: "red" });
// 在 (0, 0) 画半径 20 的红色实心圆
// x、y、filled 都使用了各自的默认值
```

这里有一个重要的细节需要注意：**解构参数本身的默认值和解构内属性的默认值是两个不同层次的东西**：

```javascript
// 只设置了属性的默认值
function fn1({ a = 1, b = 2 }) {
  return { a, b };
}
fn1();   // TypeError: Cannot destructure property 'a' of 'undefined'
         // 因为传入的参数整体是 undefined，无法对一个 undefined 进行解构

// 同时设置了参数整体的默认值和属性的默认值
function fn2({ a = 1, b = 2 } = {}) {
  return { a, b };
}
fn2();   // { a: 1, b: 2 } —— 整体默认为 {} 后再解构
fn2({}); // { a: 1, b: 2 } —— 传入空对象后解构
fn2({ a: 99 }); // { a: 99, b: 2 } —— a 使用传入值，b 用默认值
```

`= {}` 这个外层的默认值就像是给函数门口放了一个**空托盘**（空对象 `{}`）。即使调用者什么东西都没带（没传参数），至少还有这个空托盘可以让函数开始"拆包"操作。没有这个托盘的话，函数面对的就是一片虚无（`undefined`），当然没法从中提取出任何属性。

### 6.3 解构参数中的重命名

有时候外部传入的属性名称和你希望在函数内部使用的变量名不一致，这时可以使用冒号语法来进行重命名：

```javascript
function handleResponse({
  status: statusCode,    // status → statusCode
  data: payload,          // data → payload
  error: errMsg = "OK",   // error → errMsg，带默认值
}) {
  console.log(`${statusCode}: ${payload?.message || errMsg}`);
}

handleResponse({
  status: 200,
  data: { message: "成功" },
});
// 200: 成功

handleResponse({
  status: 404,
  error: "页面未找到",
});
// 404: 页面未找到
```

### 6.4 数组解构参数

除了对象解构，也可以在参数中对数组进行解构：

```javascript
// 解构数组的前几个元素
function processCoordinates([x, y, z = 0]) {
  return { x, y, z };
}

processCoordinates([10, 20]);        // { x: 10, y: 20, z: 0 }
processCoordinates([1, 2, 3]);       // { x: 1, y: 2, z: 3 }

// 结合剩余参数
function summarize([first, second, ...rest]) {
  return { first, second, restCount: rest.length, allCount: 1 + 1 + rest.length };
}

summarize(["a", "b", "c", "d", "e"]);
// { first: "a", second: "b", restCount: 3, allCount: 5 }
```

### 6.5 嵌套解构参数

对于复杂的数据结构，解构模式可以多层嵌套：

```javascript
function renderWidget({
  size: { width = 300, height = 200 },
  style: { color = "#333", bg = "#fff" },
  items: [title, ...otherItems],
  visible = true,
} = {}) {
  return `
    <div style="width:${width}px;height:${height}px;background:${bg};color:${color}">
      <h3>${title}</h3>
      ${otherItems.join('<br/>')}
      ${visible ? '' : '(隐藏)'}
    </div>
  `;
}

renderWidget({
  size: { width: 500 },
  style: { bg: '#f0f0f0' },
  items: ["标题", "项目一", "项目二"],
});

// 渲染出一个宽 500px、高 200px（默认）、灰底黑字的 widget
// 内容为标题 + 项目列表
```

嵌套解构虽然功能强大，但如果层级过深会影响代码的可读性。一般来说，超过两层的嵌套就应该考虑是否值得这样做了。

## 七、综合对比与最佳实践

### 7.1 四种参数处理技术对比

| 技术 | 适用场景 | 优势 | 注意事项 |
|------|---------|------|---------|
| **默认参数** | 单个可选参数 | 语法简洁、惰性求值 | 只对 `undefined` 触发 |
| **剩余参数** | 可变数量参数 | 得到真数组、语义清晰 | 必须在参数末尾 |
| **`arguments`** | 兼容旧环境 | 无需 ES6 支持 | 类数组、箭头函数不可用 |
| **解构参数** | 多个可选/配置参数 | 自文档化、顺序无关 | 注意 `= {}` 外层默认值 |

### 7.2 设计函数接口的原则

**原则一：位置参数用于必需项**

```javascript
// ✅ 必需参数放在前面，用位置参数
function fetchData(url, options = {}) { /* ... */ }
fetchData('/api/users');
```

**原则二：配置对象用于可选项**

```javascript
// ✅ 多个可选参数用对象解构
function animate(element, { duration = 300, easing = 'ease', delay = 0 } = {}) { /* ... */ }
animate(div, { duration: 500 });
```

**原则三：剩余参数用于不确定数量的同类数据**

```javascript
// ✅ 同类型的不定参数用 rest
function mergeObjects(...sources) {
  return Object.assign({}, ...sources);
}
mergeObjects({ a: 1 }, { b: 2 }, { c: 3 });
```

**原则四：避免过多的位置参数**

```javascript
// ❌ 参数过多，容易混淆顺序
function createUser(name, age, email, isAdmin, department, startDate) { /* ... */ }

// ✅ 用解构替代
function createUser({ name, age, email, isAdmin, department, startDate }) { /* ... */ }
```

**原则五：善用默认值减少条件判断**

```javascript
// ❌ 函数体里到处都是 if 判断
function oldStyle(config) {
  const timeout = config.timeout || 5000;
  const retries = config.retries !== undefined ? config.retries : 3;
  const method = config.method || 'GET';
  // ...
}

// ✅ 用默认参数一次性搞定
function newStyle({ timeout = 5000, retries = 3, method = 'GET' } = {}) {
  // 直接用 timeout、retries、method 即可
}
```

### 7.3 常见反模式

**反模式一：滥用 `arguments` 替代剩余参数**

```javascript
// ❌ 旧式写法
function sum() {
  var args = Array.prototype.slice.call(arguments);
  return args.reduce(function(s, n) { return s + n; }, 0);
}

// ✅ 现代写法
function sum(...args) {
  return args.reduce((s, n) => s + n, 0);
}
```

**反模式二：用解构参数强制要求某个属性**

```javascript
// ❌ 这样写 name 不是必需的——不传也不会报错
function greet({ name }) {
  console.log(`你好，${name}`);
}
greet({}); // "你好，undefined"

// ✅ 如果想要求必传，应该手动校验
function greet({ name }) {
  if (!name) throw new Error('name 是必需的！');
  console.log(`你好，${name}`);
}
```

**反模式三：忽略 `undefined` 和 `null` 的区别**

```javascript
// ⚠️ 默认参数不捕获 null
function process(data = getDefault()) { /* ... */ }
process(null); // data 是 null，不是默认值！

// 如果你需要同时处理 undefined 和 null
function process(data) {
  data ??= getDefault(); // 用 ??= 同时覆盖两者
}
```

## 八、知识图谱

```
JavaScript 函数参数处理体系
│
├── 基础概念
│   ├── 形参（Parameter）：函数声明时的占位符
│   ├── 实参（Argument）：调用时传入的实际值
│   └── 传递机制：值复制（原始类型）/ 引用复制（引用类型）
│
├── 默认参数
│   ├── 语法：param = defaultValue
│   ├── 触发条件：仅当值为 undefined 时
│   ├── 支持表达式（惰性求值）
│   ├── 可引用前面的参数
│   └── 历史替代：|| / ?? / if 检查
│
├── 剩余参数（Rest Parameters）
│   ├── 语法：...paramName（必须在参数末尾）
│   ├── 功能：收集多余实参为真正的数组
│   └── 不计入函数 .length 属性
│
├── arguments 对象（历史遗留）
│   ├── 类数组对象（有 length/索引，无数组方法）
│   ├── 包含所有实参（无法选择性收集）
│   ├── 箭头函数中不可用
│   ├── 转换为数组：Array.from() / [...args] / slice.call()
│   └── 建议：现代代码优先使用 ...rest
│
├── 展开运算符（Spread Syntax）
│   ├── 函数调用：将数组展开为独立参数
│   ├── 数组字面量：合并/拷贝数组
│   ├── 对象字面量：合并/拷贝对象（浅拷贝）
│   └── 可用于任何可迭代对象（字符串、Set、Map 等）
│
└── 解构参数（Destructuring Parameters）
    ├── 对象解构：{ prop1, prop2 } = options
    │   ├── 属性重命名：{ sourceProp: localVar }
    │   ├── 默认值：{ prop = default }
    │   └── 外层默认值：= {}（防止 undefined 报错）
    ├── 数组解构：[first, second, ...rest]
    └── 嵌套解构：{ obj: { nestedProp } }
```
