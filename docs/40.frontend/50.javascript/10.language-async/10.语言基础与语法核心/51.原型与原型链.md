# 原型与原型链 —— [[Prototype]]、`__proto__`、`prototype`、原型链查找、`Object.create`

> **核心内容**：深入 JavaScript 对象系统的核心机制——`[[Prototype]]` 内部槽与 `__proto__` 的关系、`prototype` 与 `[[Prototype]]` 的区别（最容易混淆的两个概念）、原型链查找的完整过程、属性读写的不对称性、`Object.create`/`getPrototypeOf`/`setPrototypeOf` 等现代 API、原生原型链全景图，以及如何利用原型实现继承和代码复用。

---

## 一、为什么需要理解原型？

在 JavaScript 中，几乎所有的数据都是对象——数组是对象，函数是对象，正则表达式也是对象。但如果你仔细观察，会发现一件神奇的事情：一个空数组竟然有 `push`、`pop`、`map`、`filter` 等几十个方法；一个普通函数也有 `call`、`apply`、`bind` 这些方法；甚至一个空字符串都有 `toUpperCase`、`slice`、`trim` 等方法。

这些方法从哪里来的？显然不是每次创建数组或函数时都重新定义一遍的——那样太浪费内存了。答案就是：**原型（Prototype）**。

原型机制让 JavaScript 实现了一种优雅的对象关系模式——对象可以"继承"另一个对象的属性和方法。这种继承不是复制粘贴式的，而是一种**动态的引用链式查找**。你可以把它理解为一种"委托"机制：当自己没有某个东西时，就去委托给"上级对象"去找。这个委托链可以一直向上延伸，直到找到为止或者确认真的不存在。这条链就是**原型链（Prototype Chain）**。

打个通俗的比方：假设你是一名新员工入职一家公司（创建了一个新对象）。你自己的工位上只有一支笔和一个笔记本（自身属性）。但如果有人问你要一份公司的组织架构图，你虽然自己没有，但你**知道可以去哪里找**——你的导师那里可能有（你的原型对象）。如果你的导师也没有，他知道去部门经理那里找（原型的原型）。就这样一层层委托上去，直到 CEO 那里（原型链的顶端）。这就是原型链的工作方式——**自己没有就往上找**。

## 二、[[Prototype]]——隐藏的原型指针

### 2.1 什么是 [[Prototype]]？

每个普通的 JavaScript 对象在内部都有一个隐藏的属性，ECMAScript 规范称之为 **`[[Prototype]]`**（注意两边是双中括号，表示这是一个内部槽/内部属性）。它的值要么是 `null`，要么是对另一个对象的引用：

```javascript
const obj = {};

// [[Prototype]] 是一个内部隐藏属性，不能直接访问
// 但可以通过以下方式间接查看：
console.log(Object.getPrototypeOf(obj)); // [object Object] —— 即 Object.prototype

// 或者用已标准化的 __proto__ 属性（浏览器环境中）
console.log(obj.__proto__);             // [object Object]
```

`[[Prototype]]` 的存在就像每个人出生时都会被分配一个**紧急联系人**——当你自己无法处理某件事时，就去联系那个紧急联系人（通过 `[[Prototype]]` 引用的对象），让他来处理。

### 2.2 [[Prototype]] 的三条规则

规范对 `[[Prototype]]` 设定了三条基本规则：

1. **不能形成闭环**：如果 A 的原型是 B，B 的原型就不能再设回 A（否则会无限循环）
2. **值只能是对象或 null**：`[[Prototype]]` 不能指向原始类型（数字、字符串等）
3. **只能有一个直接原型**：一个对象不能同时继承自两个不同的父对象（单继承）

```javascript
const a = {};
const b = {};

a.__proto__ = b;
b.__proto__ = a; // ❌ TypeError: Cyclic __proto__ value 不允许闭环

const c = {};
c.__proto__ = 42;  // ❌ TypeError: 只能是对象或 null
```

### 2.3 原型链的终点：null

所有原型链最终都必须终止于 `null`。这意味着在 JavaScript 中，最顶层的对象的原型就是 `null`——它上面再也没有任何东西了：

```
普通对象的完整原型链:

{ name: "Alice" }
    ↓ [[Prototype]]
Object.prototype (toString, hasOwnProperty, ...)
    ↓ [[Prototype]]
null ← 终点！再往上找就会返回 undefined
```

```javascript
const obj = { name: "Alice" };
console.log(Object.getPrototypeOf(obj));               // [object Object]
console.log(Object.getPrototypeOf(Object.prototype));   // null
```

`null` 在这里扮演的角色就像是公司里的**最高决策者**——他不需要再向任何人请示（因为他的 `[[Prototype]]` 是 null），所有问题到他这里就终结了。如果连他都解决不了的问题，那就真的无解了（返回 `undefined`）。

## 三、prototype vs [[Prototype]]——最重要的区分

这是初学者最容易混淆的地方，也是面试中的必考题：**`prototype` 和 `[[Prototype]]`（即 `__proto__`）是完全不同的两个东西**。

### 3.1 核心区别一览表

| | `[[Prototype]]` / `__proto__` | `prototype` |
|---|---|---|
| **所属者** | 每个普通**对象**都有的属性 | 只有**函数**才有的属性 |
| **含义** | "我的原型是谁？"（指向父对象） | "我作为构造函数时，创建的实例将以此为原型" |
| **作用** | 用于**读取属性时**沿链查找 | 用于**构建继承体系** |
| **类型** | 可以是任意对象或 `null` | 通常是一个对象或 `null` |
| **修改影响** | 影响当前对象的原型查找 | 影响未来创建的所有实例 |

用一个类比来说明两者的关系：如果把函数想象成一个**模具工厂**（Function），那么：

- **`prototype`** 就是工厂墙上贴的一张**产品规格说明书**——上面写着"本厂生产的每个产品都应该具备这些默认功能"。这张说明书是给产品看的，不是给工厂本身用的。
- **`[[Prototype]]`** 则是每个**出厂产品**身上的标签——上面写着"如果我有不会的功能，就去查某某号规格书"。

### 3.2 prototype 的真正用途

`prototype` 属性只在函数作为**构造函数**（配合 `new` 使用）时才有意义。它是这样工作的：

```javascript
function Animal(name) {
  this.name = name;
}

// Animal.prototype 就是一张"产品规格书"
Animal.prototype.eats = true;       // 所有实例都能吃
Animal.prototype.walk = function() { // 所有实例都会走
  console.log(`${this.name} 正在走路`);
};

// 当 new 被调用时，引擎做了什么？
const cat = new Animal("小猫");
// 1. 创建一个新的空对象 {}
// 2. 将新对象的 [[Prototype]] 设置为 Animal.prototype
// 3. 执行 Animal 函数，this 指向新对象
// 4. 返回新对象

console.log(cat.__proto__ === Animal.prototype); // true ✓
// cat 的 [[Prototype]] 指向了 Animal.prototype！

cat.walk();     // "小猫 正在走路" —— 从原型链上找到 walk 方法
console.log(cat.eats); // true —— 从原型链上找到 eats 属性
```

关键的理解点：**`new` 操作符把函数的 `prototype` 属性赋给了新创建实例的 `[[Prototype]]`**。这就是 `prototype` 和 `[[Prototype]]` 之间唯一的桥梁——它们在 `new` 调用时被连接在一起。

### 3.3 关系图解

```
┌──────────────────────────────────────────────┐
│              函数对象 Animal                   │
│                                              │
│  code: function(name) { this.name = name; }  │
│  prototype ──→ ┌─────────────────────────┐   │
│                 │  Animal.prototype        │   │
│                 │  eats: true              │   │
│                 │  walk: [Function]        │   │
│                 │  constructor: Animal      │   │
│                 │  [[Prototype]] ────┐     │   │
│                 └──────────────────────┼─────┘   │
└────────────────────────────────────────┼───────┘
                                         │
                    new Animal("小猫") 时 │
                                         ▼
┌──────────────────────────────────────────────┐
│              实例对象 cat                     │
│                                              │
│  name: "小猫"                                │
│  [[Prototype]] ──────────────────────────────┼──► Animal.prototype
└──────────────────────────────────────────────┘
```

## 四、原型链查找过程详解

当一个属性被从对象中读取时，JavaScript 引擎执行的是一次沿着原型链的搜索。这个过程是自动且透明的。

### 4.1 读取属性的完整算法

假设我们执行 `rabbit.color`，引擎内部的查找流程如下：

```
步骤1: 在 rabbit 自身的属性中查找 color
  ├── 找到了 → 返回值 ✅ 结束
  └── 没找到 ↓

步骤2: 取出 rabbit 的 [[Prototype]]（假设是 animal）
  ├── 如果 [[Prototype]] === null → 返回 undefined ❌ 结束（到头了）
  └── 在 animal 的属性中查找 color
      ├── 找到了 → 返回值 ✅ 结束
      └── 没找到 ↓

步骤3: 取出 animal 的 [[Prototype]]（可能是 Object.prototype）
  ... 继续递归查找 ...
```

```javascript
const animal = {
  eats: true,
  legs: 4,
};

const rabbit = {
  jumps: true,
  __proto__: animal, // rabbit 的原型是 animal
};

const longEarRabbit = {
  earLength: 10,
  __proto__: rabbit, // longEarRabbit 的原型是 rabbit
};

// 查找 longEarRabbit.earLength → 自身找到了 ✓ → 10
console.log(longEarRabbit.earLength); // 10

// 查找 longEarRabbit.jumps → 自身没有 → 去 rabbit 找 → 找到了 ✓ → true
console.log(longEarRabbit.jumps); // true

// 查找 longEarRabbit.eats → 自身没有 → rabbit 没有 → 去 animal 找 → 找到了 ✓ → true
console.log(longEarRabbit.eats); // true

// 查找 longEarRabbit.toString → 自身/rabbit/animal 都没有 → 去 Object.prototype 找 → 找到了 ✓
console.log(longEarRabbit.toString()); // "[object Object]"
```

这整条查找路径就是**原型链（Prototype Chain）**：

```
longEarRabbit { earLength: 10 }
    ↓ [[Prototype]]
rabbit { jumps: true }
    ↓ [[Prototype]]
animal { eats: true, legs: 4 }
    ↓ [[Prototype]]
Object.prototype { toString, hasOwnProperty, valueOf, ... }
    ↓ [[Prototype]]
null ← 终点
```

### 4.2 属性读写的根本不对称性

这是原型系统中最关键也最容易被误解的特性：**原型只参与属性的读取过程，不参与写入（大部分情况）**。

#### 读取——沿原型链查找

```javascript
const parent = {
  name: "Parent",
  greet() {
    return `Hello from ${this.name}`;
  }
};

const child = {
  __proto__: parent
};

// child 没有 name 属性，去原型 parent 上找
console.log(child.name);    // "Parent"
console.log(child.greet()); // "Hello from Parent"
```

#### 写入——直接写入当前对象（不涉及原型）

```javascript
child.name = "Child";
console.log(child.name);    // "Child" —— 写入 child 自身
console.log(parent.name);   // "Parent" —— parent 未受影响
```

写入操作**永远**作用于当前对象本身。即使原型上有同名属性，也不会修改它——而是在当前对象上创建一个**同名的自有属性**，这就叫**属性遮蔽（Property Shadowing）**：

```javascript
const base = {
  version: "1.0",
  showVersion() {
    return this.version;
  }
};

const derived = {
  __proto__: base
};

console.log(derived.version);     // "1.0" —— 从 base 读到的

derived.version = "2.0";          // 写入 derived 自身，遮蔽了 base.version
console.log(derived.version);     // "2.0" —— 从自身读到
console.log(base.version);         // "1.0" —— base 未受影响
console.log(derived.showVersion()); // "2.0" —— this 指向 derived，读自身的 version
```

属性遮蔽可以这样理解：假设你在办公室里问同事要一份文件（读取属性），同事说"我没有，但我老板那里有"，于是你去老板那里拿到了（原型链查找）。后来你自己买了一份同样的文件放在桌上（写入自身属性）。下次再需要这份文件时，你先看自己的桌面上有没有——有就用自己的，不再去找老板了（遮蔽生效）。

**唯一例外：Setter/Getter 访问器**

如果原型上的属性是一个 Setter（设置器），那么赋值操作会触发 Setter 函数，而不是简单地在当前对象上创建新属性：

```javascript
const user = {
  firstName: "John",
  
  set fullName(value) {
    // 这是一个 Setter —— 赋值时会调用此函数
    const parts = value.split(" ");
    this.firstName = parts[0];
  },
  
  get fullName() {
    return this.firstName;
  }
};

const admin = {
  isAdmin: true,
  __proto__: user
};

admin.fullName = "Alice Cooper";
// 这里触发了原型上的 Setter！
// Setter 内部的 this 指向 admin
// 所以 this.firstName = "Alice" 是写入了 admin 自身

console.log(admin.firstName); // "Alice" ✓
console.log(user.firstName);  // "John" （user 未受影响）
```

### 4.3 delete 删除操作

`delete` 也只删除对象自身的属性，不会触及原型上的同名属性：

```javascript
const proto = { x: 100 };
const obj = { x: 200, __proto__: proto };

delete obj.x;           // 删除 obj 自身的 x
console.log(obj.x);     // 100 —— 现在读到的是原型上的 x 了

delete proto.x;          // 再删掉原型上的 x
console.log(obj.x);     // undefined —— 彻底没了
```

## 五、this 在原型方法中的行为

无论方法是定义在对象自身还是存在于原型链的某一层级上，**`this` 的值始终取决于调用时的点号前面的对象**。这一点对于正确理解原型行为至关重要：

```javascript
const animal = {
  stomach: [],  // ⚠️ 注意：引用类型数据放在原型上是有风险的！
  
  eat(food) {
    this.stomach.push(food);
  },
  
  isHungry() {
    return this.stomach.length === 0;
  }
};

const rabbit = { __proto__: animal };
const hamster = { __proto__: animal };

rabbit.eat("胡萝卜");
hamster.eat("瓜子");

console.log(rabbit.stomach);  // ["胡萝卜", "瓜子"] !!??
console.log(hamster.stomach); // ["胡萝卜", "瓜子"] !!??
```

发生了什么？让我们追踪一下 `rabbit.eat("胡萝卜")` 的执行过程：

1. `rabbit.eat("胡萝卜")` 被调用
2. `eat` 方法不在 `rabbit` 自身上 → 沿原型链找到 `animal` 上的 `eat` 方法
3. 方法开始执行，此时 `this` === **rabbit**（因为调用者是 `rabbit`）
4. `this.stomach.push(...)` → 先找 `rabbit` 有没有 `stomach` 属性
5. **rabbit 没有 `stomach`** → 沿原型链找到 `animal.stomach`（一个数组引用）
6. **对这个数组 push 操作** → 修改的是 `animal.stomach` 这个共享数组！

这就是经典的**共享状态陷阱**——所有通过原型继承的对象都在操作同一个引用类型的属性。

**修复方案一：确保状态存储在每个实例自身**

```javascript
// 正确做法：在构造函数中初始化每个实例的状态
function createAnimal() {
  return {
    stomach: [],  // 每个实例有自己的胃
    __proto__: animal
  };
}

const rabbit = createAnimal();
const hamster = createAnimal();

rabbit.eat("胡萝卜");
console.log(rabbit.stomach);  // ["胡萝卜"] ✓
console.log(hamster.stomach); // [] ✓ （互不影响）
```

**修复方案二：使用构造函数 + prototype**

```javascript
// 更标准的做法：用构造函数初始化实例属性
function Animal() {
  this.stomach = []; // 每次 new 都创建新的数组
}

Animal.prototype.eat = function(food) {
  this.stomach.push(food);
};

const rabbit = new Animal();
const hamster = new Animal();

rabbit.eat("胡萝卜");
console.log(rabbit.stomach);  // ["胡萝卜"] ✓
console.log(hamster.stomach); // [] ✓
```

**设计原则总结**：**把方法放在原型上以实现复用，把数据（特别是引用类型的数据）放在每个实例自身以避免共享冲突**。

## 六、现代原型操作 API

### 6.1 Object.getPrototypeOf(obj)

获取指定对象的原型（即其 `[[Prototype]]` 值）：

```javascript
const arr = [];
console.log(Object.getPrototypeOf(arr) === Array.prototype); // true
console.log(Object.getPrototypeOf(arr) === Object.prototype); // false

const fn = function() {};
console.log(Object.getPrototypeOf(fn) === Function.prototype); // true
```

### 6.2 Object.setPrototypeOf(obj, proto)

设置指定对象的原型（慎用！有性能代价）：

```javascript
const animal = { eats: true };
const rabbit = {};

Object.setPrototypeOf(rabbit, animal);

console.log(rabbit.eats); // true

// ⚠️ 性能警告：动态改变原型会破坏引擎优化
// 推荐在对象创建时就确定好原型
```

为什么 `setPrototypeOf` 会影响性能？因为现代 JavaScript 引擎会对属性访问做大量预判和优化（比如预测属性的位置、内联缓存等）。如果你在对象创建后突然改变了它的原型，引擎之前所有的优化假设都可能失效，导致后续所有的属性访问都变慢。因此，**最佳实践是在创建对象时就设定好原型，之后不要修改**。

### 6.3 Object.create(proto, descriptors?)

`Object.create` 是创建对象的最强大方式之一，它可以精确控制新对象的原型和初始属性：

**用法一：创建具有指定原型的空对象**

```javascript
const animal = { eats: true };
const rabbit = Object.create(animal);

console.log(rabbit.eats);                              // true
console.log(Object.getPrototypeOf(rabbit) === animal);  // true
console.log(rabbit.hasOwnProperty('eats'));             // false（继承的）
```

**用法二：同时指定原型和属性描述符**

```javascript
const animal = { eats: true };

const rabbit = Object.create(animal, {
  name: {
    value: '小白兔',
    writable: true,
    enumerable: true,
    configurable: true
  },
  jumps: {
    value: true,
    enumerable: true
  }
});

console.log(rabbit.name);  // '小白兔'
console.log(rabbit.jumps); // true
console.log(rabbit.eats);  // true（从原型继承）
```

**用法三：创建真正的纯净对象——`Object.create(null)`**

```javascript
// 普通 {} 至少继承了 Object.prototype
const normalObj = {};
console.log(normalObj.toString); // [Function: toString] — 来自原型

// 纯净对象没有任何原型
const pureDict = Object.create(null);
console.log(pureDict.toString); // undefined — 没有任何继承的方法
console.log(Object.getPrototypeOf(pureDict)); // null
```

`Object.create(null)` 创建的对象被称为**纯净字典对象（Pure Dictionary Object）**。它最大的用途是用作安全的键值对容器——因为没有任何原型方法（包括可能造成问题的 `__proto__` getter/setter），所以可以把任何字符串当作键名而不担心冲突：

```javascript
// 场景：用户输入的数据作为键
const dict = Object.create(null);

dict['__proto__'] = 'test';  // 这只是一个普通属性！
dict['toString'] = 'hello';  // 这也只是普通属性！

for (let key in dict) {
  console.log(key); // '__proto__', 'toString' —— 都是普通键
}

console.log(dict['__proto__']); // 'test' —— 安全地取回了值
```

如果是普通对象 `{}`，`obj['__proto__'] = 'xxx'` 不会创建名为 `__proto__` 的属性，而是试图修改原型（可能导致安全问题或意外行为）。

### 6.4 浅拷贝对象的完整方案

利用 `Object.create` 结合其他 API，可以实现比 `...spread` 或 `Object.assign()` 更完整的对象拷贝（保留不可枚举属性、Setter/Getter 和正确的原型链）：

```javascript
function deepClone(obj) {
  return Object.create(
    Object.getPrototypeOf(obj),            // 保持原型链一致
    Object.getOwnPropertyDescriptors(obj)   // 复制所有自有属性（含不可枚举的）
  );
}
```

## 七、属性检测方法全解析

在处理原型链相关的代码时，经常需要判断一个属性到底属于对象自身还是继承而来的。JavaScript 提供了几种不同的检测方式，它们的语义各不相同。

### 7.1 in 操作符

`in` 操作符检查属性是否存在于对象**或其原型链的任何位置**：

```javascript
const animal = { eats: true };
const rabbit = { jumps: true, __proto__: animal };

console.log('jumps' in rabbit); // true —— 自身属性
console.log('eats' in rabbit);  // true —— 继承属性
console.log('fly' in rabbit);   // false —— 完全不存在
```

### 7.2 hasOwnProperty()

`hasOwnProperty()` 是定义在 `Object.prototype` 上的方法，检查属性是否是对象**自身拥有的**（不包括继承的）：

```javascript
console.log(rabbit.hasOwnProperty('jumps')); // true
console.log(rabbit.hasOwnProperty('eats'));  // false —— 来自原型
console.log(rabbit.hasOwnProperty('fly'));   // false
```

有趣的是：`hasOwnProperty` 方法本身就是从 `Object.prototype` 继承来的。即使是 `Object.create(null)` 创建的纯净对象也没有这个方法——因为它连 `Object.prototype` 都没继承：

```javascript
const pure = Object.create(null);
pure.key = 'value';

// pure.hasOwnProperty('key'); // ❌ TypeError! hasOwnProperty 不存在

// 替代方案：使用 Object.prototype.hasOwnProperty.call()
console.log(Object.prototype.hasOwnProperty.call(pure, 'key')); // true ✓

// 或使用 ES2022 的 Object.hasOwn()
console.log(Object.hasOwn(pure, 'key')); // true ✓
```

### 7.3 for...in 循环

`for...in` 会遍历对象**自身及原型链上所有可枚举的属性**：

```javascript
const animal = { eats: true };
const rabbit = { jumps: true, __proto__: animal };

for (let key in rabbit) {
  const isOwn = rabbit.hasOwnProperty(key);
  console.log(`${key}: ${isOwn ? '自身' : '继承'}`);
}
// 输出:
// jumps: 自身
// eats: 继承
```

注意 `for...in` **不会列出不可枚举的属性**（如 `constructor`、`hasOwnProperty`、`toString` 等——这些方法的 `enumerable` 标志为 `false`）。这也是为什么遍历普通对象时看不到一堆内置方法的原因。

### 7.4 Object.keys() / Object.values() / Object.entries()

这三个方法**只会返回对象自身的可枚举属性**，完全忽略原型链：

```javascript
console.log(Object.keys(rabbit));       // ['jumps']
console.log(Object.values(rabbit));     // [true]
console.log(Object.entries(rabbit));   // [['jumps', true]]

// 对比 for...in
const allKeys = [];
for (let key in rabbit) allKeys.push(key);
console.log(allKeys); // ['jumps', 'eats'] —— 包含继承的
```

### 7.5 属性检测方法对比表

| 方法 | 检测范围 | 包括不可枚举 | 包括 Symbol | 包括继承 |
|------|---------|------------|-----------|---------|
| `'prop' in obj` | 自身+原型链 | 是 | 否 | 是 |
| `obj.hasOwnProperty(prop)` | 仅自身 | 是 | 否 | 否 |
| `Object.hasOwn(obj, prop)` | 仅自身 | 是 | 是 | 否 |
| `Object.keys(obj)` | 仅自身可枚举 | 否 | 否 | 否 |
| `for...in` | 自身+原型链可枚举 | 否 | 否 | 是 |
| `Object.getOwnPropertyNames(obj)` | 仅自身 | **是** | 否 | 否 |
| `Object.getOwnPropertySymbols(obj)` | 仅自身 Symbol | - | **仅 Symbol** | 否 |

## 八、instanceof 操作符的原理

`instanceof` 用于检测一个对象是否是某个构造函数的实例。它的底层原理正是基于原型链的查找：

```javascript
function Rabbit() {}

const rabbit = new Rabbit();
console.log(rabbit instanceof Rabbit); // true
console.log(rabbit instanceof Object); // true
console.log(rabbit instanceof Array);  // false
```

`instanceof` 的工作原理大致如下：

```
instanceof 的伪代码实现：

function instanceOf(obj, Constructor) {
  // 获取构造函数的 prototype
  let proto = Constructor.prototype;
  
  // 从 obj 的 [[Prototype]] 开始，沿链逐级比较
  let current = Object.getPrototypeOf(obj);
  
  while (current !== null) {
    if (current === proto) return true; // 在链上找到了匹配项
    current = Object.getPrototypeOf(current); // 继续往上一级找
  }
  
  return false; // 整条链都没找到
}
```

```javascript
// 验证：手动模拟 instanceof
function myInstanceof(obj, Constructor) {
  if (typeof Constructor !== 'function') return false;
  
  let proto = Constructor.prototype;
  
  // 处理原始值的情况
  if (obj !== null && (typeof obj !== 'object' && typeof obj !== 'function')) {
    return false;
  }
  
  let current = Object.getPrototypeOf(obj ?? Object.prototype);
  
  while (current !== null) {
    if (current === proto) return true;
    current = Object.getPrototypeOf(current);
  }
  
  return false;
}

console.log(myInstanceof([], Array));    // true
console.log(myInstanceof({}, String));   // false
```

## 九、JavaScript 原生原型链全景图

理解 JavaScript 内置类型的原型链结构，对于深入掌握语言至关重要。下面是完整的原生类型原型链图：

```
                        ┌─────────────────────┐
                        │    null (终点)      │
                        └──────────┬──────────┘
                                   │
                ┌──────────────────┼──────────────────┐
                │                  │                  │
    ┌───────────▼──────────┐    │    ┌─────────────────▼──────────┐
    │  Function.prototype  │    │    │    Object.prototype          │
    │  [[Prototype]] ──────┼────┘    │    toString, valueOf,         │
    │  call, apply, bind,  │         │    hasOwnProperty, isProto.. │
    │  Function (自身循环)  │         │    [[Prototype]] ──→ null     │
    └───────────┬──────────┘         └──────────────┬───────────────┘
                │                                  │
    ┌───────────▼──────────┐         ┌──────────────┼───────────────┐
    │  Array.prototype    │         │              │               │
    │  [[Prototype]] ─────┼─────────┤    ┌─────────▼────────┐      │
    │  push, pop, map,   │         │    │  String.prototype │      │
    │  filter, forEach,  │         │    │  charAt, slice,   │      │
    │  indexOf, includes, │         │    │  toUpperCase, .. │      │
    │  length=0 (空数组)  │         │    │  [[Prototype]] ──┼──────┘
    └───────────┬──────────┘         │    └──────────────────┘
                │                      │
    ┌───────────▼──────────┐         │    ┌─────────▼────────┐
    │  Number.prototype   │         │    │ RegExp.prototype│
    │  toFixed, toExpo..  │         │    │  test, exec,     │
    │  [[Prototype]] ─────┼─────────┤    │  [[Prototype]] ───┤
    └─────────────────────┘         │    └──────────────────┘
                                    │
    ┌─────────────────────────────┐  │
    │ Date.prototype              │  │
    │ getFullYear, toISOString.. │  │
    │ [[Prototype]] ──────────────┼──┘
    └─────────────────────────────┘
    
    注：所有 .prototype 的 [[Prototype]] 最终都指向 Object.prototype
    而 Object.prototype 的 [[Prototype]] 为 null
    
    特殊情况：Function.prototype 的 [[Prototype]] 也是 Object.prototype
    且 Function 本身的 [[Prototype]] 指向 Function.prototype（自身循环）
```

几个关键事实：

```javascript
// 所有普通对象的最终原型都是 Object.prototype
({}).__proto__.__proto__; // null

// 数组的原型链：Array.prototype -> Object.prototype -> null
[].__proto__ === Array.prototype;          // true
[].__proto__.__proto__ === Object.prototype; // true

// 函数的原型链：Function.prototype -> Object.prototype -> null
(function(){}).__proto__ === Function.prototype;  // true

// Function.prototype 本身也是一个特殊的函数对象
typeof Function.prototype; // 'function' (!)
Function.prototype(); // 空函数，什么都不做

// Function 构造函数的原型指向 Function.prototype
Function.__proto__ === Function.prototype; // true（自引用！）
```

**所有内置方法的来源**：

```javascript
// 你调用的每一个"魔法方法"，其实都是来自原型链
[1,2,3].map(x => x*2);  // map 来自 Array.prototype
'hello'.toUpperCase();  // toUpperCase 来自 String.prototype
(123.45).toFixed(2);     // toFixed 来自 Number.prototype
new Date().getFullYear();// getFullYear 来自 Date.prototype
/abc/.test('abc');       // test 来自 RegExp.prototype
```

## 十、经典陷阱与最佳实践

### 10.1 陷阱一：修改原生原型的风险

理论上你可以给任何内置原型添加方法，但这是一种极其危险的做法：

```javascript
// ❌ 危险：修改全局原型
Array.prototype.first = function() {
  return this[0];
};

[1, 2, 3].first(); // 1 —— 看起来很方便...

// 但问题是：所有使用数组的代码都会受到影响
// 第三方库可能会依赖 Array.prototype 的纯净性
// 未来 ECMAScript 新增的同名方法可能与你的产生冲突
```

**正确的替代方式**：使用工具函数或在必要时使用封装类：

```javascript
// ✅ 方案一：工具函数
function first(arr) {
  return arr[0];
}

first([1, 2, 3]); // 1

// ✅ 方案二：扩展子类（ES6 Class）
class SmartArray extends Array {
  first() {
    return this[0];
  }
}

const arr = new SmartArray(1, 2, 3);
arr.first(); // 1
```

### 10.2 陷阱二：循环引用原型

```javascript
const a = {};
const b = {};

a.__proto__ = b;
b.__proto__ = a; // ❌ RangeError: Cyclic __proto__ value
```

### 10.3 陷阱三：__proto__ 作为字面量键的特殊性

在普通对象字面量中使用 `__proto__` 键时行为特殊：

```javascript
// 特殊行为：__proto__ 不是普通属性
const obj1 = { __proto__: { x: 1 } };
console.log(obj1.x);       // 1 —— 它变成了原型设置！
console.log(obj1.__proto__); // { x: 1 }

// 但如果写成计算属性，就是普通属性了
const key = '__proto__';
const obj2 = { [key]: { x: 2 } };
console.log(obj2.x);       // undefined
console.log(obj2[key]);    // { x: 2 } —— 这次是普通属性
```

### 10.4 最佳实践清单

1. **优先使用 `Object.create` / `class` 来管理原型**，避免直接操作 `__proto__`
2. **不要修改原生原型**（`Array.prototype`、`Object.prototype` 等）
3. **不要在原型上放置可变的状态数据**（特别是引用类型）
4. **方法放原型，数据放实例**——充分利用原型的复用优势
5. **使用 `Object.create(null)` 创建纯净字典对象**
6. **使用 `Object.hasOwn()`（ES2022）代替 `hasOwnProperty()`** 以应对无原型对象场景
7. **理解 `in` / `hasOwnProperty` / `Object.keys` / `for...in` 的差异**——选择适合场景的工具
