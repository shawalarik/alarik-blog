# 继承方式演进 —— 原型链继承、构造函数继承、组合继承、寄生组合、class 语法

> **核心内容**：完整回顾 JavaScript 继承机制的进化史——从 ES3 的原型链继承和构造函数借用、到 ES5 的组合继承与寄生组合继承（圣杯模式）、再到 ES6 class 语法糖的底层原理。每一步改进都解决了前一种方案的核心缺陷，理解这个演进过程不仅有助于面试应对，更能让你真正理解 `extends`/`super`/`class` 背后的原型机制。

---

## 一、为什么需要继承？

在软件工程中，**继承（Inheritance）** 是代码复用的核心手段之一。它的本质思想是：当多个"子类型"共享某些"父类型"的特征和行为时，不需要在每个子类型中重复编写相同的代码，而是让它们从父类型中"继承"这些共性。

打个通俗的比方：假设你在开发一个动物园管理系统。你需要管理狮子、老虎、兔子等多种动物。每种动物都有名字、年龄等基本信息（共性），但又有各自独特的行为——狮子会咆哮、老虎会游泳、兔子会跳。如果没有继承，你就要在每种动物的代码里都重复写一遍"名字""年龄"这些属性和"吃""睡"这些通用方法。有了继承，你可以先定义一个通用的"动物"基类，然后让各种具体动物从中派生出来，只添加自己特有的部分。

JavaScript 作为一门动态语言，它实现继承的方式经历了漫长的演变过程。从最初粗糙的原型操作，到精巧的设计模式，再到今天优雅的 `class` 语法——每一步都凝聚着社区的经验和智慧。

## 二、ES3 时代的基础模式

### 2.1 原型链继承（Prototype Chain Inheritance）

这是最早也最直接的继承方式——通过让子类型的 prototype 指向父类型的实例来实现：

```javascript
// 父类：动物
function Animal(name) {
  this.name = name;
  this.species = '动物';
}

Animal.prototype.eat = function(food) {
  console.log(`${this.name} 正在吃 ${food}`);
};

Animal.prototype.sleep = function() {
  console.log(`${this.name} 正在睡觉...`);
};

// 子类：狗 —— 通过原型链继承 Animal
function Dog(name, breed) {
  this.name = name;
  this.breed = breed; // 子类特有属性
}

// 核心：将 Dog 的 prototype 设为 Animal 的实例
Dog.prototype = new Animal();
Dog.prototype.constructor = Dog; // 修复 constructor 指向

// 在 Dog.prototype 上添加子类特有方法
Dog.prototype.bark = function() {
  console.log(`${this.name}(${this.breed}): 汪汪！`);
};

const dog = new Dog('旺财', '金毛');

dog.eat('骨头');   // "旺财 正在吃 骨头" —— 来自 Animal.prototype ✓
dog.sleep();       // "旺财 正在睡觉..." —— 来自 Animal.prototype ✓
dog.bark();        // "旺财(金毛): 汪汪！" —— 来自 Dog.prototype ✓
```

**工作原理图解**：

```
new Dog() 实例
    │
    ├── name: "旺财"
    ├── breed: "金毛"
    │
    └── [[Prototype]] ──► Dog.prototype (被设为 new Animal())
                              ├── species: "动物"
                              ├── [[Prototype]] ──► Animal.prototype
                              │                             │
                              │   constructor: Dog          eat: [Function]
                              │                             sleep: [Function]
                              │                             constructor: Animal
                              │
                              └── bark: [Function]           └── [[Prototype]] → Object.prototype → null
```

#### 原型链继承的优缺点

**优点**：
- 简单直观，直接利用了 JavaScript 原生原型机制
- 父类的方法只存在一份（在原型上），所有实例共享，节省内存
- 可以通过 `instanceof` 正确识别继承关系：`dog instanceof Dog` 和 `dog instanceof Animal` 都为 true

**致命缺点**：
- **引用类型属性的共享陷阱**：如果父类的属性包含引用类型（数组、对象），所有子类实例将**共享同一个引用**

```javascript
function Parent() {
  this.colors = ['red', 'blue', 'green']; // 引用类型！
}

function Child() {}
Child.prototype = new Parent();

const c1 = new Child();
const c2 = new Child();

c1.colors.push('yellow'); // 修改了数组

console.log(c1.colors); // ["red", "blue", "green", "yellow"]
console.log(c2.colors); // ["red", "blue", "green", "yellow"] !!??
// c2 也被影响了！因为 colors 是同一个数组的引用
```

为什么会这样？因为 `Child.prototype = new Parent()` 时，`Parent` 构造函数执行了一次，创建了一个包含 `colors` 数组的对象作为 `Child.prototype`。之后所有通过 `new Child()` 创建的实例都通过原型链指向这**同一个** `colors` 数组。任何对它的修改都会影响所有实例。

- **无法向父类构造函数传参**：子类型无法在创建时向父类传递初始化参数

```javascript
function Child(name) {
  // 没有办法在这里调用 Parent(name)!
  // 因为 Parent 已经在定义 prototype 时就被调用了
}
Child.prototype = new Parent();
```

### 2.2 构造函数借用（Constructor Stealing）

为了解决原型链继承中无法传参和引用类型共享的问题，开发者们想出了一种完全不同的思路——**借用构造函数**：

```javascript
// 父类
function Animal(name) {
  this.name = name;
  this.colors = ['red', 'blue', 'green'];
}

Animal.prototype.eat = function() { /* ... */ };

// 子类：不操作 prototype，而是在子类构造函数中调用父类构造函数
function Dog(name, breed) {
  Animal.call(this, name); // ⭐ 核心：借用！把 this 传给 Animal
  this.breed = breed;
}

const dog1 = new Dog('旺财', '金毛');
const dog2 = new Dog('小黑', '拉布拉多');

dog1.colors.push('yellow');
console.log(dog1.colors); // ["red", "blue", "green", "yellow"]
console.log(dog2.colors); // ["red", "blue", "green"] ✓ 不受影响！

console.log(dog1.eat()); // TypeError: dog1.eat is not a function ❌
```

**工作原理**：`Animal.call(this, name)` 使用 `call` 方法将 `Dog` 中新创建的 `this` 对象作为 `Animal` 函数执行时的 `this`。这样 `Animal` 内部的 `this.name = name` 和 `this.colors = [...]` 就会在**每个子类实例自身**上创建独立的属性副本，而不是共享同一份。

这就好比是：不是去借一本公共的参考书（原型链），而是每次需要时都**请原作者来你的办公室里现场写一份**（构造函数借用）——这样每份都是独立的，不会互相干扰。

#### 构造函数借用的优缺点

**优点**：
- 解决了引用类型共享问题（每个实例都有独立副本）
- 可以向父类构造函数传递参数

**致命缺点**：
- **方法不在原型上**——父类定义在 `prototype` 上的方法无法被子类继承
- **方法无法复用**——每次创建子类实例，如果要在子类中定义方法，要么重复定义，要么也在 `prototype` 上手动复制
- **instanceof 关系断裂**：`dog1 instanceof Animal` 为 false（因为没有原型链连接）

```javascript
console.log(dog1 instanceof Animal); // false ❌
// 因为 dog1 的原型链是: dog1 → Dog.prototype → Object.prototype
// 根本没有经过 Animal.prototype
```

## 三、ES5 时代的成熟模式

### 3.1 组合继承（Combination Inheritance）

既然原型链继承擅长处理方法的复用，而构造函数借用擅长处理实例属性的独立，那为什么不把它们结合起来？这就是**组合继承**的思路：

```javascript
// 父类
function Animal(name) {
  this.name = name;
  this.colors = ['red', 'blue', 'green'];
}

Animal.prototype.eat = function(food) {
  console.log(`${this.name} 正在吃 ${food}`);
};

Animal.prototype.sleep = function() {
  console.log(`${this.name} 正在睡觉...`);
};

// 子类
function Dog(name, breed) {
  Animal.call(this, name);        // 第一次调用 Animal —— 借用构造函数
  this.breed = breed;
}

Dog.prototype = new Animal();     // 第二次调用 Animal —— 创建原型链
Dog.prototype.constructor = Dog;

Dog.prototype.bark = function() {
  console.log(`${this.name}(${this.breed}): 汪汪！`);
};
```

**效果检验**：

```javascript
const d1 = new Dog('旺财', '金毛');
const d2 = new Dog('小黑', '拉布拉多');

// 1. 引用类型独立性 ✓
d1.colors.push('yellow');
console.log(d1.colors); // ["red","blue","green","yellow"]
console.log(d2.colors); // ["red","blue","green"] ✓

// 2. 方法继承 ✓
d1.eat('骨头');          // "旺财 正在吃 骨头"
d1.sleep();              // "旺财 正在睡觉..."
d1.bark();               // "旺财(金毛): 汪汪！"

// 3. instanceof ✓
console.log(d1 instanceof Dog);     // true
console.log(d1 instanceof Animal);  // true
```

看起来一切完美！但有一个隐藏的问题——**父类构造函数被调用了两次**：

```
第一次: Animal.call(this, name)
  → 在 d1 自身上创建了 name, colors 属性

第二次: new Animal()
  → 在 Dog.prototype 上也创建了 name, colors 属性（无用！）
  → 然后 d1 通过原型链找到的是自身的属性（遮蔽了原型上的）
```

这意味着：
- 内存浪费：原型上有一些永远不会被使用的冗余属性（被实例自有属性遮蔽）
- 效率低下：父类构造函数中的逻辑被执行了两遍

虽然在实际应用中这个问题通常不会导致明显的 bug（因为自有属性总是优先于原型属性），但它确实是一个设计上的瑕疵——不够优雅和高效。

### 3.2 寄生组合继承（Parasitic Combination Inheritance）—— 圣杯模式

这是 JavaScript 社区公认的最佳传统继承模式，被称为**圣杯模式（Holy Grail Pattern）**。它在保留组合继承所有优点的同时，彻底解决了"父类被调用两次"的问题：

```javascript
// 工具函数：创建指定原型的空对象
// （在现代环境中等同于 Object.create，但在 ES5 之前需要 polyfill）
function inheritPrototype(child, parent) {
  // 方案一（现代）：使用 Object.create
  const prototype = Object.create(parent.prototype);
  
  // 方案二（兼容旧环境）：利用一个空的中间函数
  // function F() {}
  // F.prototype = parent.prototype;
  // const prototype = new F(); // 这里没有调用 parent 构造函数！
  
  prototype.constructor = child;
  child.prototype = prototype;
}

// 父类
function Animal(name) {
  this.name = name;
  this.colors = ['red', 'blue', 'green'];
}

Animal.prototype.eat = function(food) {
  console.log(`${this.name} 正在吃 ${food}`);
};

// 子类
function Dog(name, breed) {
  Animal.call(this, name);  // 只调用一次 Animal ✓
  this.breed = breed;
}

// 关键：不再用 new Animal() 来设置原型
inheritPrototype(Dog, Animal);
// 等价于: Dog.prototype = Object.create(Animal.prototype);

Dog.prototype.bark = function() {
  console.log(`${this.name}(${this.breed}): 汪汪！`);
};
```

**核心突破**：`Object.create(parent.prototype)` 创建的是一个**干净的空对象**，其 `[[Prototype]]` 指向 `parent.prototype`，但**不会执行 parent 的构造函数**。这样就避免了在设置原型链时不必要地调用父类构造函数。

对比一下两种方式的区别：

```
组合继承的问题:
  Dog.prototype = new Animal();
  ↑ 这一步执行了 Animal() 构造函数
  → Dog.prototype 上有了多余的 name 和 colors 属性
  
寄生组合继承的解决方案:
  Dog.prototype = Object.create(Animal.prototype);
  ↑ 这一步只建立了原型链接
  → Dog.prototype 是干净空对象，只有 __proto__ 指向正确
```

**寄生组合继承的完整特性验证**：

| 特性 | 结果 | 说明 |
|------|------|------|
| 引用类型独立 | ✓ | `call()` 确保每个实例有独立副本 |
| 方法可继承 | ✓ | 原型链正确连接 |
| 可传参给父类 | ✓ | `call(this, name)` 传入参数 |
| `instanceof` 正确 | ✓ | 原型链完整 |
| 父类只调用一次 | ✓ | 只在子类构造函数中 `call()` 一次 |
| 无冗余属性 | ✓ | 原型上是干净的对象 |

这就是为什么它被称为"圣杯模式"——它几乎满足了继承的所有理想需求。在 ES6 `class` 出现之前的很长一段时间里，这是业界最推荐的继承写法。

### 3.3 各种继承方式总结对比

| 继承方式 | 实例属性独立 | 方法复用 | 可传参 | instanceOf | 父类调用次数 | 推荐度 |
|---------|-----------|---------|-------|-----------|------------|-------|
| 原型链继承 | ❌ 共享 | ✓ | ❌ | ✓ | 1 次 | ★☆☆ |
| 构造函数借用 | ✓ 独立 | ❌ | ✓ | ✗ | 1 次 | ★★☆ |
| 组合继承 | ✓ 独立 | ✓ | ✓ | ✓ | **2 次** | ★★★ |
| **寄生组合继承** | **✓ 独立** | **✓** | **✓** | **✓** | **1 次** | **★★★★** |

## 四、ES6 Class 语法糖

ES2015（ES6）引入了 `class` 关键字，让继承的书写变得极其简洁优雅。但必须强调：**class 本质上是一种语法糖（Syntactic Sugar）**——它的底层仍然是基于原型的继承机制，只是用更清晰的语法封装了起来。

### 4.1 基本语法对照

让我们把上面的寄生组合继承改写成 class 版本，看看简化了多少：

```javascript
// ====== ES5 寄生组合继承（约 30 行） ======
function Animal(name) {
  this.name = name;
  this.colors = ['red', 'blue', 'green'];
}
Animal.prototype.eat = function(food) { ... };
Animal.prototype.sleep = function() { ... };

function Dog(name, breed) {
  Animal.call(this, name);
  this.breed = breed;
}
inheritPrototype(Dog, Animal); // 工具函数调用
Dog.prototype.bark = function() { ... };


// ====== ES6 Class（约 15 行，更清晰） ======
class Animal {
  constructor(name) {
    this.name = name;
    this.colors = ['red', 'blue', 'green'];
  }
  
  eat(food) {
    console.log(`${this.name} 正在吃 ${food}`);
  }
  
  sleep() {
    console.log(`${this.name} 正在睡觉...`);
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name);         // ← 对应 Animal.call(this, name)
    this.breed = breed;
  }
  
  bark() {
    console.log(`${this.name}(${this.breed}): 求汪！`);
  }
}
```

class 语法的优势一目了然：
- **结构清晰**：代码按逻辑分组（constructor、方法），而不是散落在各处
- **自动处理**：不需要手动设置 `prototype`、修复 `constructor`、调用工具函数
- **语义明确**：`extends` 明确表达了继承关系，`super` 明确表达了对父类的调用

### 4.2 class 不是纯粹的语法糖

虽然我们常说 class 是"语法糖"，但它和手写的构造函数+原型之间还是有一些**重要的行为差异**：

| 特性 | class | 普通函数+原型 |
|------|-------|-------------|
| 必须用 `new` 调用 | ✅ 否则报错 | ❌ 可以直接调用 |
| 自动严格模式 | ✅ 所有代码都在 strict 下运行 | ❌ 默认非严格 |
| 方法不可枚举 | ✅ `enumerable: false` | ❌ 默认可枚举 |
| 没有 `[[Construct]]`（不能 `new`）标记 | — | — |
| 内部标记 `[[IsClassConstructor]]` | ✅ 有 | ❌ 没有 |

```javascript
class User {}
User(); // TypeError: Class constructor cannot be invoked without 'new'

function Person() {}
Person(); // 正常执行（可能产生全局副作用）
```

class 的这种严格性是有意为之的设计——它能防止很多因误用而导致的 bug，让代码的行为更加可预测。

### 4.3 extends 的底层原理

当引擎看到 `class Dog extends Animal` 时，它做了以下几件事（概念层面）：

```javascript
// 概念上的等价转换：
class Dog extends Animal {
  constructor(name, breed) {
    super(name);
    this.brend = breed;
  }
  bark() { /* ... */ }
}

// 大致等价于以下 ES5 代码：

// 1. 设置原型链
Dog.prototype = Object.create(Animal.prototype);
Dog.prototype.constructor = Dog;

// 2. 设置静态成员继承（后面详述）
Object.setPrototypeOf(Dog, Animal);

// 3. constructor 中的 super() 等价于 Animal.call(this, ...)
```

关键点：`extends` 不仅设置了 `Dog.prototype.__proto__ === Animal.prototype`（实例方法继承），还设置了 `Dog.__proto__ === Animal`（静态方法/属性的继承）。

### 4.4 super 关键字的深入解析

`super` 是 class 继承中最重要也最容易出错的关键字。它有两种用法：

#### 用法一：super(...) —— 在构造函数中调用父类构造器

```javascript
class Rabbit extends Animal {
  constructor(name, earLength) {
    super(name);  // ← 必须！且必须在访问 this 之前
    this.earLength = earLength;
  }
}
```

**为什么必须在 this 之前调用 super？**

这是一个非常底层的机制问题。对于普通类（不使用 `extends` 的类），`new` 操作符在调用 constructor 之前就已经创建好了一个新的空对象并赋值给 `this`。但对于派生类（使用了 `extends` 的类），情况不同——**派生类的构造函数不会自动创建 `this` 对象**。它期望父类的构造函数来完成这项工作。所以如果你在调用 `super()` 之前就尝试使用 `this`，会发现 `this` 还未初始化：

```javascript
class BadRabbit extends Animal {
  constructor(name) {
    this.name = name;  // 💥 ReferenceError: Must call super before accessing this
    super();
  }
}
```

可以这样理解：普通类的 constructor 就像是**自己动手建房子**——工具材料都准备好了（`this` 已就绪）。派生类的 constructor 更像是**装修队进场**——房子已经由开发商（父类 constructor）建好了主体结构，你只需要在此基础上进行装修（添加子类特有的属性）。但你总得等开发商先把主体盖好吧？——所以在你动工之前，必须先等 `super()` 把房子的框架搭好。

#### 用法二：super.method(...) —— 调用父类的同名方法

```javascript
class Rabbit extends Animal {
  stop() {
    // 先执行父类的 stop 逻辑
    super.stop();  // 调用 Animal.prototype.stop.call(this)
    
    // 再执行子类特有的逻辑
    console.log(`${this.name} 躲进了洞穴！`);
  }
}
```

**super 的内部机制：[[HomeObject]]**

`super` 的实现依赖于一个名为 `[[HomeObject]]` 的内部属性。当一个方法被定义为类方法或对象的简写方法时，引擎会给这个函数打上一个隐式标签——记录它"出生在哪个对象上"。`super` 就是利用这个信息来找到正确的父原型：

```javascript
let animal = {
  name: "Animal",
  sayHi() { return `I'm ${this.name}`; }
};

let rabbit = {
  __proto__: animal,
  name: "Rabbit",
  sayHi() { return `${super.sayHi()} (from rabbit)`; }  // super 记住了"我属于 rabbit"
};

// ⚠️ 如果把这个方法复制到另一个对象上...
let plant = {
  name: "Plant",
  sayHi: rabbit.sayHi  // 复制了 rabbit.sayHi
};

plant.sayHi(); 
// 输出: "I'm Animal (from rabbit)" !!??
// 因为 [[HomeObject]] 还是 rabbit，super 找到了 animal 的方法
```

这就是 `[[HomeObject]]` 的"永久绑定"特性——一旦函数创建，它记住的就永远是创建时的那个上下文。这就像是一张名片上印着"所属公司：A 公司"，即使你把这张名片转给了 B 公司的人，上面写的依然是 A 公司。

**箭头函数与 super**：箭头函数没有自己的 `super`，它会从外层的普通函数中继承 `super` 的值：

```javascript
class Rabbit extends Animal {
  stop() {
    setTimeout(() => super.stop(), 1000);  // ✓ 正确：从外部 stop() 继承 super
    
    // 下面这样会报错：
    // setTimeout(function() { super.stop(); }, 1000);  // ❌ SyntaxError
  }
}
```

### 4.5 字段初始化顺序陷阱

class 的字段（class fields）初始化顺序是一个容易踩坑的地方：

```javascript
class Animal {
  name = 'animal';
  
  constructor() {
    console.log(`构造函数中的 name: ${this.name}`);
  }
}

class Rabbit extends Animal {
  name = 'rabbit';  // 尝试覆盖
}

new Animal();  // "构造函数中的 name: animal"
new Rabbit();  // "构造函数中的 name: animal" !!?? 为什么不是 rabbit？
```

**原因**：字段初始化遵循固定的顺序——**基类的字段先于派生类**。具体流程如下：

```
new Rabbit() 执行过程:

1. 检查 Rabbit 是否有 [[ConstructorKind]]: "derived"
2. 创建 this 对象... 但不赋值（等待 super）
3. 进入 Rabbit 的 constructor
4. 遇到 super() → 跳转到 Animal 的 constructor
5. 此时开始初始化基类 Animal 的字段
   → name = 'animal'  ← 基类字段先初始化
6. Animal 的 constructor 执行
   → 打印 this.name → "animal"（此时 Rabbit.name 尚未初始化）
7. super() 返回，回到 Rabbit
8. 此时才开始初始化派生类 Rabbit 的字段
   → name = 'rabbit'（太晚了！constructor 已经执行过了）
9. Rabbit 的 constructor 继续...
```

这个陷阱告诉我们：**不要依赖子类覆盖的字段值来影响父类的构造函数行为**。如果需要在子类中提供不同的初始值，应该通过构造函数参数来传递，而不是靠字段覆盖。

### 4.6 继承内置类

class 的 `extends` 不仅可以用于自定义类，还可以继承 JavaScript 的内置类型（如 Array、Error、Map 等）。这在 ES5 时代是无法做到的：

```javascript
// 继承 Array
class PowerArray extends Array {
  isEmpty() {
    return this.length === 0;
  }
  
  // 可以重写内置方法
  push(...items) {
    super.push(...items);  // 调用父类（即 Array）的 push
    console.log(`已添加 ${items.length} 个元素，当前长度: ${this.length}`);
  }
}

const arr = new PowerArray(1, 2, 3);
console.log(arr.isEmpty()); // false
arr.push(4, 5);
// "已添加 2 个元素，当前长度: 5"

console.log(arr instanceof PowerArray); // true
console.log(arr instanceof Array);      // true —— 内置类关系保持不变
```

注意：要正确继承内置类，有一些特殊要求——子类必须正确地与内部插槽（Internal Slots）交互。这也是为什么 ES5 无法通过常规手段继承 Array 的原因——ES5 的 `new Array()` 会返回特殊的数组 exotic object，而普通的原型链操作无法复制这种特殊行为。

### 4.7 静态属性与方法的继承

`extends` 同时继承了实例成员（通过 prototype）和**静态成员（通过函数对象本身）**：

```javascript
class Animal {
  static kingdom = 'Animalia';  // 静态属性
  static describe() {            // 静态方法
    console.log('动物是多细胞真核生物');
  }
  
  constructor(name) { this.name = name; }
}

class Rabbit extends Animal {
  static kingdom = 'Lagomorpha';
  
  static jump() {
    console.log('兔子善于跳跃');
  }
}

console.log(Rabbit.kingdom);     // "Lagomorpha"（子类自己的）
console.log(Rabbit.describe());  // "动物是真核生物"（继承自 Animal）
Rabbit.jump();                 // "兔子善于跳跃"（子类自己的）
```

静态成员的继承是通过 `Dog.__proto__ === Animal` 实现的。当访问 `Rabbit.describe()` 时，先在 `Rabbit` 自身找 → 没有 → 去 `Rabbit.__proto__`（即 `Animal`）找 → 找到了。

## 五、Mixins——多重继承的替代方案

JavaScript 的原型链是单继承的——一个对象只能有一个直接原型。但有时候我们需要"混入"来自多个来源的能力。Mixin（混入）模式就是解决这个问题的方案：

### 5.1 基本 Mixin 模式

```javascript
// Mixin: 让对象具备"能飞"的能力
let flyable = {
  fly() {
    console.log(`${this.name} 正在飞翔！`);
  },
  
  land() {
    console.log(`${this.name} 已降落`);
  }
};

// Mixin: 让对象具备"能游泳"的能力
let swimmable = {
  swim() {
    console.log(`${this.name} 正在游泳`);
  }
};

// 使用 Object.assign 将 mixin 合并到类的 prototype 上
class Bird {
  constructor(name) {
    this.name = name;
  }
}

// 将 mixin 方法合并到 Bird.prototype
Object.assign(Bird.prototype, flyable, swimmable);

const eagle = new Eagle('老鹰');
eagle.fly();   // "老鹰 正在飞翔！"
eagle.swim();  // "老鹰 正在游泳"
eagle.land();  // "老鹰 已降落"
```

### 5.2 更安全的工厂函数 Mixin

使用工厂函数可以创建更灵活的 mixin：

```javascript
const Flyable = (SuperClass) => class extends SuperClass {
  fly() { console.log(`${this.name} takes off!`); }
  land() { console.log(`${this.name} lands.`); }
};

const Swimmable = (SuperClass) => class extends SuperClass {
  swim() { console.log(`${this.name} swims.`); }
  dive(depth) { console.log(`${this.name} dives to ${depth}m`); }
};

// 组合使用
class Duck {}
const FlyingSwimmingDuck = Swimmable(Flyable(Duck));

const duck = new FlyingSwimmingDuck();
duck.name = '唐老鸭';
duck.fly();    // "唐老鸭 takes off!"
duck.swim();   // "唐老鸭 swims."
duck.dive(10);  // "唐老鸭 dives to 10m"
```

Mixin 的思路就像是**自助餐**——你不能同时有两个亲爹（单继承限制），但你可以从多个"技能培训课程"（Mixin）那里学习不同的能力，然后把它们全部装进自己的技能包里。

## 六、知识图谱

```
JavaScript 继承方式演进全景

├── ES3 时代（基础探索）
│   │
│   ├── 原型链继承
│   │   做法: Child.prototype = new Parent()
│   │   优点: 方法复用、instanceof 正确
│   │   缺点: 引用类型共享陷阱、无法传参
│   │   适用: 简单场景，无引用类型数据
│   │
│   └── 构造函数借用
│       做法: Parent.call(this, args...)
│       优点: 实例属性独立、可传参
│       缺点: 方法不继承、instanceof 断裂
│       适用: 只需数据不需方法的场景
│
├── ES5 时代（成熟方案）
│   │
│   ├── 组合继承
│   │   做法: 借用构造函数 + 原型链
│   │   优点: 兼具两者之长
│   │   缺点: 父类构造函数调用两次（性能浪费）
│   │
│   └── 寄生组合继承（圣杯模式）⭐
│       做法: Object.create(Parent.prototype) + call()
│       优点: 完美——独立+复用+传参+instanceOf+仅调一次
│       地位: ES6 class 出现前的最佳实践
│
├── ES6+ 时代（现代标准）
│   │
│   ├── class 基本语法
│   │   ├── class 声明 / 表达式 / 动态创建
│   │   ├── constructor / 方法 / getter/setter
│   │   ├── 字段（实例字段 / 静态字段 / 私有字段 #）
│   │   └── 与函数+原型的差异（必须 new / 严格模式 / 不可枚举）
│   │
│   └── class extends 继承
│       ├── extends 底层: prototype 链 + [[HomeObject]]
│       ├── super(...)
│       │   ├── 构造器中: 必须在 this 前（派生类不创建 this）
│       │   └── 方法中: 调用父类方法
│       ├── super 内部: [[HomeObject]] 固定绑定
│       ├── 字段初始化顺序: 基类先于派生类（陷阱!）
│       ├── 继承内置类: Array/Error/Map/Promise 等
│       └── 静态成员继承: 通过函数对象的 __proto__ 链
│
└── 高级技巧
    ├── Mixin 模式（模拟多继承）
    │   ├── Object.assign 合并
    │   └── 工厂函数包装
    │
    └── 设计原则
        ├── 方法放原型（复用）
        ├── 数据放实例（独立）
        ├── 优先使用 class（简洁安全）
        └── 理解底层原型（调试必备）
```
