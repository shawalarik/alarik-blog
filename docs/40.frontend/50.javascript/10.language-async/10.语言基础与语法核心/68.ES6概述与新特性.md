# ES6 概述与新特性 —— ECMAScript 2015 核心特性全景

> **核心内容**：ES6（ECMAScript 2015）的完整特性概览——历史背景与设计哲学、块级作用域（let/const）、箭头函数、模板字符串、增强的对象字面量、解构赋值、默认参数与剩余参数、展开运算符、Symbol 原始类型、Map/Set 集合类型、Promise 与异步编程基础、Class 类语法、Module 模块化，以及各特性的设计动机与最佳实践。

---

## 一、ES6 是什么——JavaScript 的"文艺复兴"

### 1.1 从"玩具语言"到"一等公民"

1995 年，Brendan Eich 用了 **10 天**时间创造了 JavaScript。这门语言的诞生本身就是一个奇迹——但它的快速成长也意味着早期设计中的很多决策是仓促的。在随后的近 20 年里（1995–2015），JavaScript 经历了以下阶段：

```
JavaScript 发展历程

1995 ──→ JS 1.0（Netscape）     "能跑就行"
         │
2005 ──→ AJAX 爆发 Web 2.0    "原来前端可以做这么多"
         │                    jQuery / Prototype.js 盛行
         │
2009 ──→ ES5 规范化           "终于有标准了"
         │                    strict mode / JSON / Array 方法
         │                    但仍然缺少很多现代语言特性
         │
2015 ──→ ⭐ ES6 (ES2015)      "质的飞跃！"
         │                    近 20 年来最大的升级
         │                    JavaScript 正式进入"现代语言"行列
         │
至今  ──→ ES2024+             "持续进化中"
         ├── ES2017: async/await
         ├── ES2018: 对象展开 / 异步迭代
         ├── ES2019: Array.flat / Object.fromEntries
         ├── ES2020: 可选链 ?.
         ├── ES2021: 逻辑运算符 ??=
         ├── ES2022: at() / top-level await
         └── ES2023+ ...
```

**ES6（ECMAScript 2015）** 是 JavaScript 标准自诞生以来**最大的一次更新**。它不是小修小补，而是一次全面的现代化改造。这次更新的规模如此之大，以至于它几乎可以被看作是 JavaScript 2.0。

### 1.2 为什么叫 ES6 而不是 ES2015？

这是一个常见的命名困惑：

| 名称 | 含义 | 使用场景 |
|------|------|---------|
| **ES6** | 第 6 版本的 ECMAScript | 社区通用称呼（更流行） |
| **ES2015** | 2015 年发布的版本 | 官方规范命名 |
| **Harmony** | 开发代号 | 早期内部名称 |

"ES6" 这个名字虽然技术上不准确（因为后续还有 ES7/ES8...），但由于它代表了那个划时代的重大版本，社区已经习惯了这个称呼。就像人们把 "The Great War" 叫作"第一次世界大战"一样——虽然当时还没有第二次，但这个名字已经深入人心。

### 1.3 ES6 解决了哪些痛点？

在 ES6 之前，JavaScript 开发者长期被这些问题困扰：

| 痛点 | ES6 前的状态 | ES6 的解决方案 |
|------|-------------|--------------|
| **变量提升导致意外全局污染** | `var` 在代码运行前就被声明，值是 `undefined` | `let` / `const` + 块级作用域 + TDZ |
| **回调地狱** | 多层嵌套的 `function(err, data)` 形成"厄运金字塔" | `Promise` → `async/await` |
| **函数 this 绑定混乱** | `this` 取决于调用方式而非定义位置 | **箭头函数**词法绑定 this |
| **对象操作啰嗦** | `var obj = {}; obj.x = 1; obj.y = 2;` | 增强的字面量 `{x, y, method() {}}` |
| **字符串拼接痛苦** | `"Hello " + name + ", you are " + age` | **模板字符串** `` `Hello ${name}` `` |
| **参数处理原始** | `arguments` 类数组、无默认值 | 默认参数、剩余参数 `...rest` |
| **没有模块系统** | 依赖 IIFE / 全局变量避免冲突 | **原生 Module** (`import/export`) |
| **没有类语法** | 用原型链模拟 OOP，写法丑陋 | **class** 关键字 |
| **集合数据结构弱** | 只能用对象模拟 Map/Set | **Map / Set / WeakMap / WeakSet** |

### 1.4 设计哲学：向后兼容是第一原则

ES6 的一个至关重要的设计原则是**100% 向后兼容**——任何用 ES5 写成的代码，在 ES6 引擎中必须能够正常运行。这意味着：

```javascript
// 这段 ES5 代码在任何版本的浏览器和 Node.js 中都能工作
// 包括支持 ES6 的环境
var name = "Alice";
function greet(name) {
  return "Hello, " + name;
}
console.log(greet(name)); // "Hello, Alice"
```

**ES6 是"加法式"升级，不是"替换式"重写**。它不会破坏你已有的代码，只是在原有基础上添加了大量新特性。这就像是给一栋老房子加装了电梯和新空调——原来的房间和水管依然正常运作，但整体居住体验大幅提升了。

## 二、let 与 const —— 块级作用域革命

### 2.1 var 的问题回顾

在深入 let/const 之前，我们需要先理解为什么需要它们。`var` 有几个让新手和老手都头疼的问题：

```javascript
// 问题一：变量提升（hoisting）导致意外的 undefined
console.log(x); // undefined 而不是报错！
var x = 10;

// 问题二：函数级作用域——变量穿透 if/for 块
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// 输出：3, 3, 3 （不是 0, 1, 2）——因为 var i 是函数级别的

// 问题三：重复声明静默覆盖
var a = 1;
var a = 2; // 不报错！只是悄悄覆盖
console.log(a); // 2
```

这些问题的根源在于：**`var` 缺乏"块级作用域"的概念，且存在不受控的提升行为**。

### 2.2 let —— 块级声明的变量

`let` 引入了真正的**块级作用域（Block Scope）**——变量只在最近的 `{ }` 块内有效：

```javascript
{
  let blockScoped = "我在这个大括号内有效";
  
  if (true) {
    let innerVar = "我在 if 块内";
    console.log(blockScoped); // ✓ 可以访问外层的 blockScoped
  }
  
  console.log(innerVar); 
  // 💥 ReferenceError: innerVar is not defined
  // 出了 if 块就看不到了
}

console.log(blockScoped); 
// 💥 ReferenceError: blockScoped is not defined
// 出了大括号就看不到了
```

**类比**：`var` 就像是**整栋楼共享的大喇叭广播系统**——你在任何一个房间喊话，整栋楼都能听到。`let` 就像是**每个房间的内部对讲机**——声音传不出当前房间（`{ }` 块）。这极大地减少了"串音"（变量污染）的可能性。

### 2.3 const —— 不可变的绑定

`const` 与 `let` 一样具有块级作用域，但它还多了一个约束：**一旦声明就不能重新赋值**：

```javascript
const API_URL = 'https://api.example.com';

API_URL = 'https://evil.com';
// 💥 TypeError: Assignment to constant variable.

// ⚠️ 注意：const 保护的是"绑定"不可变，而不是"值"不可变
const user = { name: "Alice", age: 28 };
user.name = "Bob";       // ✓ 合法！修改的是对象的属性，不是 user 本身
user = { name: "Charlie" }; // 💥 TypeError! 不能重新赋值 user
```

**关键认知**：
- `const x = 10` → `x = 20` ❌ 报错（基本类型不能改）
- `const arr = []` → `arr.push(1)` ✅ 可以（数组引用不变，内容可变）
- `const obj = {}` → `obj.key = val` ✅ 可以（同上）

**类比**：`const` 就像是在一个信封上盖了火漆印章——你不能撕开信封换里面的内容（重新赋值），但如果里面装的是一个透明的袋子，你还是可以往袋子里塞东西（修改对象属性）。

### 2.4 暂时性死区（TDZ）

这是 `let` 和 `const` 最重要也最容易被忽视的特性之一。当执行流进入某个块作用域时，变量就已经被"注册"了（引擎知道有这个变量的存在），但在到达 `let` / `const` 声明语句之前，变量处于一种特殊的**未初始化状态**——这就是**暂时性死区（Temporal Dead Zone，TDZ）**：

```javascript
{
  // 进入块的那一刻，a 已经被"感知"，但不能使用
  // 这段区域就是 a 的 TDZ
  
  console.log(a);  // 💥 ReferenceError: Cannot access 'a' before initialization
  
  let a = 10;         // ← 到了这一行，TDZ 结束，a 变得可用
  console.log(a);  // 10 ✓
}
```

**为什么要有 TDZ？** 这是一种**预防性安全机制**。想象你在餐厅预订了一个位置（变量被注册），但你还没到用餐时间（还没执行到声明行）就想坐下吃饭——餐厅会告诉你："你的位置虽然预留了，但还没到时候。"TDZ 就是 JavaScript 引擎对你说："我知道你要用这个变量了，但还没到时候，请等一下。"

### 2.5 最佳实践：优先 const > let >>> var

现代 JavaScript 开发中有一条广泛接受的规则：

```
选择变量的优先级：

1. const → 定义后不再改变的绑定（大部分情况）
2. let   → 需要重新赋值的循环计数器等
3. var   → 基本不推荐使用（除非维护旧代码）
```

## 三、箭头函数 —— 更简洁的函数表达

### 3.1 语法糖的本质

箭头函数是 ES6 引入的一种**语法糖**——它提供了一种更简洁的方式来编写函数表达式。注意：它是**函数表达式**的简写，不能用来声明命名函数（不能用做构造函数或生成器）：

```javascript
// 传统函数表达式
const add = function(a, b) {
  return a + b;
};

// 箭头函数（等效写法）
const add = (a, b) => a + b;

// 更简洁！省略了 function、return、花括号
```

### 3.2 三种形式

| 形式 | 语法 | 说明 | 返回值 |
|------|------|------|--------|
| **无花括号** | `(args) => expression` | 单行简洁体 | 自动返回表达式结果 |
| **有花括号** | `(args) => { body }` | 多行函数体 | 必须显式 return |
| **单参数** | `arg => expression` | 只有一个参数时可省略括号 | 同上 |
| **无参数** | `() => expression` | 无参数时必须有空括号 | 同上 |

```javascript
// 形式一：无花括号（自动返回）
const double = n => n * 2;
double(5); // 10

// 形式二：有花括号（需显式 return）
const process = (data) => {
  const cleaned = data.trim();
  const uppered = cleaned.toUpperCase();
  return uppered;
};

// 形式三：无参数
const getRandom = () => Math.floor(Math.random() * 100);

// 形式四：用于回调（最常见的使用场景）
const numbers = [1, 2, 3, 4, 5];
const evens = numbers.filter(n => n % 2 === 0);
evens; // [2, 4]
```

### 3.3 箭头函数的"特殊体质"

除了语法更简洁之外，箭头函数还有一个根本性的行为差异——**它没有自己的 `this`**：

```javascript
// 普通 function：this 由调用方式决定（动态绑定）
const team = {
  members: ["Alice", "Bob"],
  
  introduce() {
    // 这里的 this 取决于谁调用了 introduce()
    return this.members.map(function(member) {
      return `${member} is in team`;
      // 这个普通函数有自己的 this
      // 如果不绑定 this，这里的 this 可能指向 window 或 undefined
    });
  }
};

// 箭头函数：this 继承自外部词法作用域
const team2 = {
  members: ["Carol", "Dave"],
  
  introduce() {
    // 箭头函数的 this 来自外层 introduce() 的 this
    return this.members.map(member => `${member} is in team`);
    // 不需要 .bind(this) 了！
  }
};
```

**类比**：普通函数就像是一个**临时演员**——每次被调用（演出）时，它的角色（this）由导演（调用者）临时指定。箭头函数则像一个**固定角色演员**——从诞生起就确定了自己的角色（this），无论谁来调用都不会改变。这使得箭头函数特别适合作为回调函数使用——因为你通常希望回调里的 `this` 与外层保持一致。

### 3.4 箭头函数的限制

由于上述特性，箭头函数也有一些不适合使用的场景：

| 场景 | 能否使用箭头函数 | 原因 |
|------|:-:|------|
| 作为对象的方法 | ⚠️ 不推荐 | 没有 `this`，无法通过点号访问自身属性 |
| 作为构造函数 | ❌ 不能 | `new` 会报错 |
| 需要 `arguments` 对象 | ❌ 没有 | 箭头函数没有自己的 arguments |
| 需要原型方法 | ❌ 不能 | 没有 `prototype` 属性 |
| 回调函数 / 箭式操作 | ✅ 推荐 | 词法 this 刚好是需要的 |
| 数组方法回调 | ✅ 推荐 | `.map(fn)` / `.filter(fn)` 完美适配 |

## 四、模板字符串 —— 字符串的超进化

### 4.1 从拼接插值到嵌入表达式

ES6 之前的字符串拼接既丑陋又容易出错：

```javascript
// ES5 及以前的方式
var name = "Alice";
var age = 28;
var greeting = "Hello, " + name + "! You are " + age + " years old.";
// 又是加号又是引号，嵌套多了简直是噩梦

// 如果是多行文本？更惨：
var html = "<div class='card'>" +
  "<h2>" + title + "</h2>" +
  "<p>" + content + "</p>" +
  "</div>";
```

ES6 的**模板字符串（Template Literals）**用反引号 `` ` `` `` 包裹，彻底解决了这个问题：

```javascript
const name = "Alice";
const age = 28;

// 基本插值：${expression}
const greeting = `Hello, ${name}! You are ${age} years old.`;
// 干净！清晰！无需关心引号的转义

// 多行文本天然支持
const html = `
  <div class="card">
    <h2>${title}</h2>
    <p>${content}</p>
  </div>
`;

// 表达式可以是任意的 JavaScript 表达式
const a = 5, b = 3;
const math = `Sum: ${a + b}, Product: ${a * b}, Is even: ${(a * b) % 2 === 0}`;
// "Sum: 8, Product: 15, Is even: false"
```

**`${}` 内部可以是任何有效的 JavaScript 表达式**——算术运算、三元运算、函数调用，甚至嵌套模板字符串。这让构建复杂的字符串变得前所未有的优雅。

### 4.2 标签模板（Tagged Templates）

模板字符串还可以在反引号前加一个**标签函数**，实现对模板内容的自定义处理：

```javascript
function highlight(strings, ...values) {
  // strings: 模板中被 ${} 分隔开的纯文本部分
  // values:   每个 ${} 内的表达式计算结果
  
  return strings.reduce((result, str, i) => {
    return result + str + (values[i] ? `<mark>${values[i]}</mark>` : '');
  }, '');
}

const name = "ES6";
const version = "2015";

const output = highlight`Hello ${name}, welcome to ES${version}!`;
// "Hello <mark>ES6</mark>, welcome to <mark>2015</mark>!"
```

标签模板在国际化（i18n）、SQL 查询构建、CSS-in-JS 等库中有广泛应用。虽然日常开发中不太常见，但它展示了模板字符串强大的可扩展性。

### 4.3 模板字符串 vs 普通字符串的关键差异

| 特性 | 普通字符串 `'...'` / `"..."` | 模板字符串 `` `...` `` |
|------|:-:|:-:|
| **换行** | ❌ 需要用 `\n` 转义 | ✅ 天然支持直接回车 |
| **插值** | ❌ 需要用 `+` 拼接 | ✅ `${expression}` 内联 |
| **引号嵌套** | 麻烦，需要转义 | 无此问题（三种引号不同） |
| **标签处理** | ❌ 不支持 | ✅ 支持标签模板 |

**类比**：普通字符串就像是**手写信件**——你想加什么内容都得一笔一划地写在纸上。模板字符串就像是**邮件合并工具**——你可以先写好模板，然后在特定位置插入动态数据，一键生成最终内容。

## 五、增强的对象字面量

### 5.1 属性简写（Property Shorthand）

当属性值来自同名变量时，ES6 允许省略重复的部分：

```javascript
// ES5 写法
var x = 10, y = 20;
var point = { x: x, y: y };
// "x: x" —— 名字写了两次，冗余

// ES6 写法
const x = 10, y = 20;
const point = { x, y };        // 自动推断为 { x: x, y: y }
// 简洁！只写一次名字
```

这在从变量创建对象、从函数参数构建配置对象等场景下极为常用。

### 5.2 方法简写（Method Shorthand）

对象中的函数属性也有简写语法：

```javascript
// ES5
var user = {
  name: "Alice",
  sayHi: function() {
    return "Hi, I'm " + this.name;
  }
};

// ES6
const user = {
  name: "Alice",
  sayHi() {               // 省略了 : function
    return `Hi, I'm ${this.name}`;
  },
  
  // 配合属性简写效果更好
  greet() {
    return `${this.name} says hello!`;
  }
};
```

### 5.3 计算属性名（Computed Property Names）

有时属性名需要由表达式动态决定——ES6 允许在方括号内写入任意表达式：

```javascript
const keyName = "dynamicKey";
const prefix = "user_";
const id = 42;

const obj = {
  [keyName]: "value from variable",
  [`${prefix}${id}`]: "computed property name",
  
  // 还可以用 Symbol 作为键
  [Symbol("id")]: "symbol key value"
};

console.log(obj.dynamicKey);           // "value from variable"
console.log(obj.user_42);              // "computed property name"
console.log(obj[Object.getOwnPropertySymbols(obj)[0]]); // "symbol key value"
```

**组合使用示例——工厂函数创建对象**：

```javascript
function makeUser(name, role) {
  const id = Date.now().toString(36);
  return {
    [`user_${id}`]: name,
    [`role_${role}`]: role,
    createdAt: new Date(),
    
    getInfo() { return `${name} (${role})`; }
  };
}

const admin = makeUser("Admin", "superadmin");
// { user_17abc...: "Admin", role_superadmin: "superadmin", ..., getInfo: f }
```

### 5.4 Object.assign —— 对象合并

ES6 新增的 `Object.assign()` 方法用于将一个或多个源对象的所有可枚举属性复制到目标对象：

```javascript
const defaults = { theme: "light", lang: "en", timeout: 5000 };
const userSettings = { theme: "dark", fontSize: "18px" };

const config = Object.assign({}, defaults, userSettings);
// 将 defaults 和 userSettings 合并到一个空对象上

console.log(config);
// { theme: "dark", lang: "en", timeout: 5000, fontSize: "18px" }
// 注意：theme 被 userSettings 的 "dark" 覆盖了 defaults 的 "light"
```

**重要细节**：`Object.assign` 执行的是**浅拷贝**——如果属性值是对象或数组，拷贝的是引用而非深拷贝。对于深层克隆，需要配合递归或 JSON 序列化技巧。

## 六、默认参数与剩余参数

### 6.1 默认参数 —— 函数的"默认选项"

ES6 允许在函数参数声明时直接设置默认值：

```javascript
// ES5 方式（检查是否为 undefined）
function createUser(name) {
  var userName = name || "Guest";  // 手动设置默认值
  // ...
}

// ES6 方式（声明式默认值）
function createUser(name = "Guest") {
  // 参数自带文档化的默认值，一目了然
  const userName = name;
  // ...
}

createUser();            // name = "Guest"
createUser("Alice");    // name = "Alice"
```

**触发条件**：只有当传入的值为 `undefined` 时才会使用默认值。`null`、`0`、`false`、空字符串等不会触发默认值——这与解构赋值的默认值行为一致。

### 6.2 剩余参数 ...rest —— 收集多余参数

当函数需要接受不定数量的参数时，`...rest` 语法可以将多余的参数收集到一个真正的数组中：

```javascript
function sumAll(...numbers) {
  // numbers 是一个真正的 Array，不是类数组的 arguments
  return numbers.reduce((sum, n) => sum + n, 0);
}

sumAll(1);          // 1
sumAll(1, 2, 3);    // 6
sumAll(1, 2, 3, 4, 5); // 15
```

**与 `arguments` 的区别**：

| 特性 | `arguments` | `...rest` |
|------|:-:|:-:|
| 类型 | 类数组对象（伪数组） | **真正的 Array** |
| 能否用数组方法 | ❌ 需要手动转换 | ✅ 直接 `.map/.filter/.reduce` |
| 是否包含所有参数 | ✅ 所有参数 | ⚠️ 仅匹配的剩余参数 |
| 箭头函数可用性 | ❌ 没有自己的 | ✅ 可以使用 |
| 位置限制 | 无 | **必须在最后** |

**快递代收点的类比**：`...rest` 就像是快递代收点门口的那个**"其他人筐子"**——不属于任何已命名的专属包裹的东西都会被丢进这个筐子里，方便你统一处理。

### 6.3 展开运算符 ...spread —— 拆包分发

`...` 的另一种用法——在**函数调用**或**字面量**中将数组/对象"拆开"为独立的元素/键值对：

```javascript
// 函数调用中展开
const nums = [3, 5, 1, 9, 7];
Math.max(...nums);          // 9  ≡ 等于 Math.max(3,5,1,9,7)
Math.max.apply(null, nums); // ES5 的旧方式

// 数组合并
const part1 = [1, 2, 3];
const part2 = [4, 5, 6];
const merged = [...part1, 0, ...part2, 7]; // [1,2,3,0,4,5,6,7]

// 浅拷贝
const original = { a: 1, b: 2, c: 3 };
const copy = { ...original };        // { a:1, b:2, c:3 }
const override = { ...original, b: 99, d: 4 }; // { a:1, b:99, c:3, d:4 }

// 字符串转字符数组
[..."hello"];  // ['h','e','l','l','o']
```

**区分 rest 和 spread 的简单口诀**：

```
看到 ... 怎么判断？
│
├── 在函数声明的参数列表中 → REST（打包收集）
│   function fn(...rest) { }  ← 收集起来
│
└── 在函数调用或字面量中 → SPREAD（拆散展开）
    fn(...arr)                  ← 拆散开来
    [...arr, 1, 2]              ← 拆散开来
```

## 七、解构赋值

### 7.1 一句话总结

解构赋值允许你用类似**声明式模式**的方式从数组或对象中提取值并赋给变量，而不需要逐个按索引或属性名去访问：

```javascript
// 数组解构
const colors = ["red", "green", "blue"];
const [first, second, third] = colors;
// first="red", second="green", third="blue"

// 对象解构
const config = { apiUrl: "https://api.example.com", timeout: 5000, retries: 3 };
const { apiUrl, timeout, retries = 5 } = config;
// apiUrl="https://api.example.com", timeout=5000, retries=5

// 函数参数解构（最实用的用法）
function process({ title, items = [], verbose = false }) {
  console.log(`Processing: ${title}`);
  if (verbose) console.log(items);
}
process({ title: "Report", items: ["A", "B"], verbose: true });
```

## 八、Symbol —— 第七种原始类型

### 8.1 什么是 Symbol？

ES6 引入了全新的**第七种原始类型**——`Symbol`（符号）。它的每一个值都是**唯一的**，即使描述相同也不会相等：

```javascript
const id1 = Symbol("id");
const id2 = Symbol("id");

console.log(id1 === id2);  // false！描述相同但不相等
console.log(id1.toString()); // "Symbol(id)" — 只有 toString() 能转为字符串
console.log(`${id1}`);         // TypeError! 不能隐式转为字符串
```

**唯一性保证**是 Symbol 最重要的特征。这让它成为创建**隐藏属性**的理想键名：

```javascript
const SECRET = Symbol("internalState");
const user = { name: "Alice" };
user[SECRET] = "sensitive_data";

// 第三方代码遍历 user 对象时看不到这个属性
for (let key in user) {
  console.log(key);  // 只输出 "name"，SECRET 被跳过
}
Object.keys(user);       // ["name"] — 没有 SECRET
JSON.stringify(user);   // '{"name":"Alice"}' — SECRET 被忽略

// 只有持有 Symbol 引用的代码才能访问
console.log(user[SECRET]);  // "sensitive_data" ✓
```

### 8.2 全局 Symbol 注册表

如果你需要在不同的地方使用**同一个 Symbol 实例**（跨文件/跨模块），可以使用全局注册表：

```javascript
// 创建或获取全局 Symbol
const appId = Symbol.for("app.id");    // 第一次：创建并存入注册表
const sameId = Symbol.for("app.id");   // 第二次：从注册表取出同一个
console.log(appId === sameId);       // true ✓

// 反查
console.log(Symbol.keyFor(appId));       // "app.id"
```

### 8.3 系统知名 Symbol（Well-known Symbols）

JavaScript 内置了许多具有特殊含义的 Symbol，用于定制对象的行为：

| System Symbol | 用途 |
|---------------|------|
| `Symbol.iterator` | 让对象可被 `for...of` 遍历（实现迭代器协议） |
| `Symbol.toPrimitive` | 控制对象转换为原始值时的行为（如 `Number(obj)` / `String(obj)` / `` `${obj}` ``） |
| `Symbol.toStringTag` | 控制 `Object.prototype.toString.call()` 的输出 |
| `Symbol.hasInstance` | 自定义 `instanceof` 操作的行为 |
| `Symbol.isConcatSpreadable` | 控制数组展开时是否包含该对象 |

这些系统 Symbol 是实现元编程（Meta Programming）的基础——让你可以改变 JavaScript 内置操作的行为。

## 九、Map 与 Set —— 新的数据结构

### 9.1 Map —— 更好的键值对容器

在 ES6 之前，开发者一直用普通对象 `{}` 来模拟"字典"或"哈希表"。但这种方式有几个严重的缺陷：

```javascript
// 用对象模拟 Map 的问题

// 问题一：键会被自动转为字符串
const mapLike = {};
mapLike[{}] = "value";           // 键变成了 "[object Object]"
mapLike[{x:1}] = "another";   // 键变成了 "[object Object]" — 两者相同！
console.log(mapLike[{}]);           // "another" — 不是我们期望的！

// 问题二：键的类型信息丢失
const mapLike2 = {};
const key1 = { id: 1 };
const key2 = { id: 1 };  // 内容相同的不同对象
mapLike2[key1] = "A";
mapLike2[key2] = "B";           // 覆盖了！因为 key1 !== key2 但转成字符串后可能相同
```

**Map** 解决了以上所有问题：

```javascript
const map = new Map();

// 键可以是任何类型，不会被转换
const keyObj = { id: 42 };
map.set(keyObj, "value for object key");  // 对象作为键 ✓
map.set(123, "value for number key");       // 数字作为键 ✓
map.set(true, "value for boolean key");      // 布尔值作为键 ✓
map.set("string", "value for string key");    // 字符串作为键 ✓

console.log(map.get(keyObj)); // "value for object key"
console.log(map.get({ id: 42 })); // undefined — 不同对象引用

// Map 有 size 属性（不像对象的 length 那样需要手动维护）
console.log(map.size); // 4

// Map 是有序的（按插入顺序遍历）
for (const [key, value] of map) {
  console.log(`${key}: ${value}`);
}

// Map 有方便的 CRUD 方法
map.has(key);     // 检查是否存在
map.delete(key);  // 删除
map.clear();       // 清空
```

**Map vs Object 适用场景对比**：

| 场景 | Object `{}` | Map |
|------|:-:|:-:|
| 键必须是字符串/ Symbol | ✅ 任意类型（含对象/函数） |
| 频繁增删键值对 | ❌ 性能差 | ✅ 针对 CRUD 优化 |
| 需要知道元素数量 | ❌ 手动维护 length | ✅ `.size` 属性 |
| 需要保持插入顺序 | ❌ 不保证 | ✅ 保证插入顺序 |
| 需要 JSON 序列化 | ✅ JSON.stringify | ❌ 需要手动转换 |
| 简单的配置存储 | ✅ 够够了 | 大材小用 |

### 9.2 Set —— 唯一值的集合

`Set` 是**不允许重复值**的集合。当你需要存储一组唯一的元素时，它比数组更合适：

```javascript
// 数组无法自动去重
const arr = [1, 2, 2, 3, 3, 3];
Array.from(new Set(arr)); // [1, 2, 3] — 手动去重

// Set 天然去重
const unique = new Set([1, 2, 2, 3, 3, 3]);
console.log(unique); // Set { 1, 2, 3 }
console.log(unique.size); // 3

// Set 的主要操作
unique.add(4);      // 添加（如果已存在则忽略）
unique.has(2);      // 检查是否存在
unique.delete(2);   // 删除
unique.clear();      // 清空

// 常见用途
const setA = new Set([1, 2, 3]);
const setB = new Set([2, 3, 4]);
const intersection = new Set([...setA].filter(x => setB.has(x))); // 交集: {2, 3}
const union = new Set([...setA, ...setB]);                   // 并集: {1, 2, 3, 4}
const diff = new Set([...setA].filter(x => !setB.has(x)));   // 差集: {1}
```

### 9.3 WeakMap 和 WeakSet —— 弱引用版本

`WeakMap` 和 `Set` 是 Map 和 Set 的"弱引用"变体——它们的键（或值）是弱引用，不影响垃圾回收：

| 特性 | Map / Set | WeakMap / WeakSet |
|------|:-:|:-:|
| **键/值的引用强度** | 强引用（阻止 GC） | **弱引用**（不阻止 GC） |
| **可枚举** | ✅ 可以遍历 | ❌ 不可遍历 |
| **size** | ✅ 有 size 属性 | ❌ 没有 size 属性 |
| **适用场景** | 一般用途 | 缓存/关联元数据（对象 GC 后自动清理） |

**典型应用——缓存**：

```javascript
const cache = new WeakMap();

function getData(keyObj) {
  // 先查缓存
  if (cache.has(keyObj)) {
    return cache.get(keyObj);
  }
  
  // 缓存中没有，计算并存储
  const result = expensiveComputation(keyObj);
  cache.set(keyObj, result);
  return result;
}

// 当 keyObj 被垃圾回收时，缓存条目也会自动清除
// 不会有内存泄漏风险！
```

## 十、Promise —— 异步编程的基础设施

### 10.1 从回调到 Promise

ES6 标准化了 `Promise` 对象，为异步编程提供了统一的接口和可组合的模式：

```javascript
// 回调风格（ES5）
fs.readFile('data.json', function(err, data) {
  if (err) { handleError(err); return; }
  parseData(data, function(err, parsed) {
    if (err) { handleError(err); return; }
    saveToDB(parsed, function(err) {
      // ...无限嵌套的回调...
    });
  });
});

// Promise 链式调用（ES6）
readFile('data.json')
  .then(data => parseData(data))
  .then(parsed => saveToDB(parsed))
  .catch(handleError);  // 统一的错误处理
```

**Promise 的三大优势**：
1. **错误传播统一**：`.catch()` 可以捕获前面任何一步的错误
2. **可组合**：`Promise.all()` / `Promise.race()` 等静态方法支持并行异步
3. **状态明确**：pending / fulfilled / rejected 三态模型让生命周期可控

Promise 的完整讲解见本文档的《61.错误处理》章节，async/await 详见异步编程系列的其他章节。

## 十一、Class 类语法

### 11.1 从原型链模拟到正式语法

ES6 之前，要用面向对象的方式组织代码，你需要这样写：

```javascript
// ES5 的"类"（实际上只是函数+原型链的伪装）
function Person(name, age) {
  this.name = name;
  this.age = age;
}
Person.prototype.greet = function() {
  return `I'm ${this.name}, ${this.age} years old`;
};
Person.prototype.haveBirthday = function() {
  this.age++;
};
```

ES6 的 `class` 语法提供了更清晰的面向对象编程体验：

```javascript
class Person {
  constructor(name, age) {    // 构造函数
    this.name = name;
    this.age = age;
  }

  greet() {                 // 方法（自动挂载到 prototype 上）
    return `I'm ${this.name}, ${this.age} years old`;
  }

  haveBirthday() {          // 方法
    this.age++;
    return this.age;
  }

  get isAdult() {            // getter
    return this.age >= 18;
  }

  static createBaby(parentName) { // 静态方法（挂在 Person 类本身上）
    return new Person(parentName + "'s baby", 0);
  }
}

const alice = new Person("Alice", 28);
alice.greet();                          // "I'm Alice, 28 years old"
alice.haveBirthday();                     // 29
console.log(alice.isAdult);                   // true
const baby = Person.createBaby("Alice");      // 静态方法调用
```

**class 不是纯粹的语法糖**——它与基于原型的模拟有几个关键差异：
- `class` 内部的代码默认处于严格模式
- `class` 声明的方法不可枚举（`enumerable: false`）
- `class` 必须用 `new` 调用（否则报错）
- `class` 没有 hoisting（不存在提升）

### 11.2 extends 继承

```javascript
class Animal {
  constructor(name) {
    this.name = name;
  }
  speak() {
    return `${this.name} makes a sound`;
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name);  // 调用父类构造函数
    this.breed = breed;
  }

  speak() {
    return `${super.speak()} — Woof!`;  // super 调用父类方法
  }
}
```

继承的完整讲解见本文档的《56.继承方式演进》章节。

## 十二、Module 模块化

### 12.1 从 IIFE 到原生模块

ES6 之前，JavaScript 没有官方的模块系统。开发者们用各种 hack 来避免全局变量污染：

```javascript
// ES5 的"模块"模式（IIFE + 全局变量）
var MyModule = (function() {
  var privateVar = "secret";
  
  return {
    publicMethod: function() { return privateVar; }
  };
})();
```

ES6 引入了原生的 `import/export` 模块语法：

```javascript
// ====== utils.js ======
export const PI = 3.14159;
export function square(x) { return x * x; }
export default class Calculator { /* ... */ }

// ====== main.js ======
import Calculator, { PI, square } from './utils.js';

console.log(square(5)); // 25
console.log(PI);       // 3.14159
const calc = new Calculator();
```

**模块的核心优势**：
- **作用域隔离**：每个模块都有自己的顶层作用域，不会污染全局
- **显式依赖**：必须显式 import 才能使用其他模块的导出
- **静态分析友好**：工具可以在不运行代码的情况下分析依赖关系
- **Tree-shaking 友好**：打包工具（Webpack/Rollup）可以自动删除未被使用的导出，减小产物体积
