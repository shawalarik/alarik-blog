# Symbol 与 Map Set —— 唯一标识符、键值对集合与唯一值集合

> **核心内容**：Symbol 唯一标识符类型、Map/Set 数据结构、WeakMap/WeakSet 弱引用机制、四大数据结构的完整对比与实战场景

## 一、为什么需要这四种数据结构？

在 ES6（2015）之前，JavaScript 提供给开发者的"数据容器工具箱"相当有限。你只有两种选择：

**第一种是对象 `Object`**——它像一个万能的抽屉柜，什么东西都能往里塞，但它的问题在于：键只能用字符串或 Symbol，数字键会被自动转成字符串，而且它自带一些"出厂配置"（原型链上的属性），这些有时候会干扰你的使用。

**第二种是数组 `Array`**——它像一个带编号的储物柜，按顺序存放东西，但它的编号只能是连续的整数，而且不能保证元素不重复。

这就好比你去图书馆找书：

- **Object 就像一本目录册**，你可以按书名查找，但书名必须是文字，不能拿一本书作为"索引"去查另一本书；而且目录册本身还夹着图书馆自带的说明页。
- **Array 就像一排编号书架**，你可以按编号取书，但无法快速判断某本书是否已经在架子上。

ES6 引入了 **Symbol、Map、Set、WeakMap、WeakSet** 这五种新的数据结构，就像给 JavaScript 的工具箱添置了五件精密仪器：一把独一无二的激光刻印机（Symbol）、一个智能分类文件柜（Map）、一个自动去重的收集篮（Set），以及它们的弱引用版本（WeakMap 和 WeakSet）。

### 四大结构速览

| 数据结构 | 本质 | 核心能力 | 一句话类比 |
|----------|------|---------|-----------|
| **Symbol** | 第七种原始类型 | 创建唯一的、不可变的标识值 | 激光防伪标签 |
| **Map** | 键值对集合 | **任意类型作为键**，保留插入顺序 | 万能钥匙档案柜 |
| **Set** | 唯一值集合 | **自动去重**，存储不重复的值 | 自动过滤的收集篮 |
| **WeakMap** | 弱引用键值对 | 键被 GC 回收时自动清除条目 | 临时便签本 |
| **WeakSet** | 弱引用集合 | 值被 GC 回收时自动清除条目 | 临时标记板 |

## 二、Symbol —— 唯一的防伪标签

### 2.1 什么是 Symbol

Symbol 是 JavaScript 的**第七种原始类型**（前六种分别是：string、number、bigint、boolean、undefined、null）。它代表一种**独一无二**的、不可变的值，主要用于作为对象的属性键，以避免命名冲突。

想象一下这样的场景：你正在开发一个功能模块，需要给某个用户对象添加一个"内部标记"属性来追踪这个用户是否已经被处理过。但问题是，这个用户对象可能是从第三方库获取的，你不能确定它是否已经有一个叫 `"processed"` 的属性了。如果你直接添加 `user.processed = true`，就有可能覆盖掉原有的属性。

这时候，Symbol 就像一张**激光防伪标签**——无论你打印多少张描述相同的标签，每一张都有独特的微观纹理，绝对不会和任何其他标签混淆。

```javascript
// 创建一个 Symbol
let sym1 = Symbol();
let sym2 = Symbol("description"); // 可以附带一段描述文字
let sym3 = Symbol("description");

console.log(typeof sym1);        // "symbol"
console.log(sym2 === sym3);      // false —— 即使描述相同，也是两个不同的值！
```

这段代码揭示了一个关键事实：**每次调用 `Symbol()` 都会创建一个全新的、唯一的值**。"描述"参数只是给人看的备注，就像标签上写的用途说明——两张标签都写着"用于标记已处理"，但它们仍然是两张不同的标签。

这与 Ruby 等其他语言的 symbol 有本质区别。Ruby 中相同名称的 symbol 是同一个实体（类似字符串驻留），而 JavaScript 的 Symbol 每次创建都是全新的唯一值。

### 2.2 Symbol 为什么不自动转为字符串

Symbol 有一个非常特殊的"自我保护"机制——它**拒绝被隐式转换为字符串**：

```javascript
let id = Symbol("id");
console.log("ID: " + id);     // TypeError!
console.log(`${id}`);         // TypeError!
```

这不是设计缺陷，而是**有意为之的安全保护**。如果 Symbol 能被隐式转换为字符串，那么当你不小心把 Symbol 用在了需要字符串的地方时，就会产生难以调试的错误——比如得到一个奇怪的 `Symbol(id)` 字符串而不是你期望的行为。JavaScript 引擎直接抛出错误，强迫你明确表达意图。

正确的做法有两种：

```javascript
let id = Symbol("id");

// 方式一：显式调用 toString()
console.log(id.toString());    // "Symbol(id)"

// 方式二：只获取描述部分
console.log(id.description);   // "id"
```

`.description` 属性返回的是你在创建 Symbol 时传入的描述字符串，这在调试日志中特别有用——你能看到这个 Symbol 是用来做什么的，而不必记住变量名。

### 2.3 Symbol 作为对象的隐藏属性

这是 Symbol 最经典的使用场景——**给对象添加不会与其他属性冲突的"隐藏属性"**。

想象你在为一个第三方库的对象附加元数据。如果你用字符串做键：

```javascript
// ❌ 危险的做法
let user = { name: "John", age: 30 };

user.id = "our-identifier";       // 你的脚本添加的 ID
user.id = "their-identifier";     // 另一个库也用了 "id"！覆盖了！
```

这就是典型的**命名冲突问题**——就像两个人在同一扇门上贴了自己的名字标签，后贴的人把先贴的盖住了。

用 Symbol 就完全不同了：

```javascript
// ✅ 安全的做法
let user = { name: "John", age: 30 };

let myId = Symbol("id");          // 你的专属标签
let theirId = Symbol("id");       // 别人的专属标签（虽然描述一样，但是不同的标签）

user[myId] = "our-identifier";
user[theirId] = "their-identifier";

console.log(user[myId]);          // "our-identifier"
console.log(user[theirId]);       // "their-identifier"
// 两者互不干扰！
```

在对象字面量中使用 Symbol 作为属性键时，必须使用**方括号语法**：

```javascript
const SECRET_KEY = Symbol("secret");

let user = {
  name: "Alice",
  [SECRET_KEY]: "hidden-data"     // 方括号必不可少
};

console.log(user[SECRET_KEY]);    // "hidden-data"
```

方括号告诉 JavaScript 引擎：这里的 `SECRET_KEY` 不是字面量的属性名，而是一个表达式，求值后的结果才是真正的键。

### 2.4 Symbol 属性的"半透明"特性

Symbol 属性有一个非常有趣的特性——**大多数遍历方法都会忽略它**：

```javascript
const HIDDEN = Symbol("hidden");

let obj = {
  visible: "I am visible",
  count: 42,
  [HIDDEN]: "I am hidden"
};

for (let key in obj) {
  console.log(key);               // "visible"、"count" —— 没有 Symbol！
}

console.log(Object.keys(obj));    // ["visible", "count"]
console.log(JSON.stringify(obj)); // '{"visible":"I am visible","count":42}'
```

这意味着 Symbol 属性就像是**写在纸背面的隐形墨水笔记**——普通的翻阅（`for...in`、`Object.keys`）根本看不到它，但你只要知道确切位置就能读到它（`obj[HIDDEN]`）。

不过要注意，Symbol 并非 100% 隐藏。以下方法**可以**获取到 Symbol 属性：

```javascript
// 获取所有 Symbol 键
console.log(Object.getOwnPropertySymbols(obj));  // [Symbol(hidden)]

// 获取所有键（包括 Symbol）
console.log(Reflect.ownKeys(obj));               // ["visible", "count", Symbol(hidden)]
```

这种设计的哲学思想是：**克隆或合并对象时应该包含所有属性**（包括 Symbol），所以 `Object.assign` 会复制 Symbol 属性。但日常遍历时不需要看到这些"内部实现细节"，所以 `for...in` 和 `Object.keys` 会忽略它。

| 操作 | 是否包含 Symbol |
|------|----------------|
| `for...in` 循环 | ❌ 跳过 |
| `Object.keys()` / `Object.values()` | ❌ 忽略 |
| `JSON.stringify()` | ❌ 忽略 |
| `Object.assign()` | ✅ 复制 |
| `展开运算符 ...` | ✅ 复制 |
| `Object.getOwnPropertySymbols()` | ✅ 仅返回 Symbol |
| `Reflect.ownKeys()` | ✅ 返回所有 |

### 2.5 全局 Symbol 注册表 —— 跨文件的共享标签

大多数时候，我们希望每个 Symbol 都是独立的（局部 Symbol）。但有些场景下，我们需要**在不同代码模块之间共享同一个 Symbol**。这时就需要用到全局注册表。

**`Symbol.for(key)`** —— 在全局注册表中查找或创建 Symbol：

```javascript
// 文件 A.js
let globalId = Symbol.for("userId");   // 创建并注册到全局表

// 文件 B.js（可能在完全不同的地方执行）
let sameGlobalId = Symbol.for("userId"); // 从全局表中读取同一个 Symbol

console.log(globalId === sameGlobalId);  // true —— 是同一个 Symbol！
```

全局 Symbol 注册表的运作原理就像一个**公共寄存处**：当你调用 `Symbol.for("key")` 时，引擎会先去全局表中查找是否已经存在名为 "key" 的 Symbol。如果有，就返回已有的那个；如果没有，就新建一个并存入表中。

这与 `Symbol()` 直接创建的根本区别在于：

| 对比项 | `Symbol("desc")` | `Symbol.for("key")` |
|--------|------------------|---------------------|
| **作用域** | 当前代码块/模块 | 全局（整个运行时环境） |
| **相同描述** | 返回不同实例 | 返回同一实例 |
| **比喻** | 私人印章 | 公司公章 |

**`Symbol.keyFor(sym)`** —— 反向查询全局 Symbol 的名称：

```javascript
let globalSym = Symbol.for("appName");
let localSym = Symbol("appName");

console.log(Symbol.keyFor(globalSym));  // "appName" —— 在全局表中找到了
console.log(Symbol.keyFor(localSym));   // undefined  —— 不在全局表中

// 但所有 Symbol 都有 .description
console.log(localSym.description);       // "appName"
```

注意 `Symbol.keyFor` 只对**全局 Symbol** 有效。对于通过 `Symbol()` 直接创建的局部 Symbol，它会返回 `undefined`。但所有 Symbol（无论是全局还是局部）都有 `.description` 属性可以查看描述文字。

### 2.6 系统 Symbol —— 定制对象行为的魔法接口

JavaScript 内部定义了一组**系统级知名 Well-known Symbol**，它们是引擎与开发者之间的"协议接口"。通过在你的对象中定义这些特殊属性，你可以**定制对象的内置行为**。

最常用的系统 Symbol 包括：

| Symbol | 控制的行为 | 使用场景 |
|--------|-----------|---------|
| **`Symbol.iterator`** | 使对象可被 `for...of` 遍历 | 自定义迭代器 |
| **`Symbol.toPrimitive`** | 对象转为原始值的规则 | 自定义类型转换 |
| `Symbol.toStringTag` | `Object.prototype.toString` 的结果标签 | 自定义类型检测 |
| `Symbol.hasInstance` | `instanceof` 操作符的行为 | 自定义实例判断 |

#### Symbol.iterator —— 让对象变得"可迭代"

```javascript
// 定义一个范围对象，可以用 for...of 遍历
let range = {
  from: 1,
  to: 5,

  [Symbol.iterator]() {
    let current = this.from;
    let last = this.to;

    return {
      next() {
        if (current <= last) {
          return { value: current++, done: false };
        }
        return { done: true };
      }
    };
  }
};

for (let num of range) {
  console.log(num);  // 1, 2, 3, 4, 5
}
```

当 JavaScript 引擎遇到 `for...of` 时，它会在目标对象上寻找 `Symbol.iterator` 方法。找到后调用该方法获取一个迭代器，然后反复调用 `next()` 直到 `{done: true}`。

#### Symbol.toPrimitive —— 自定义对象如何变身为基本类型

```javascript
let user = {
  name: "Alice",
  balance: 5000,

  [Symbol.toPrimitive](hint) {
    switch (hint) {
      case "string":  return `User(${this.name})`;
      case "number":  return this.balance;
      default:        return `${this.name}: $${this.balance}`;
    }
  }
};

console.log(String(user));  // hint="string" → "User(Alice)"
console.log(+user);         // hint="number" → 5000
console.log(user + "");     // hint="default" → "Alice: $5000"
```

`hint` 参数告诉你的方法：引擎想要什么类型的值。`"string"` 用于字符串拼接和模板字面量，`"number"` 用于数学运算，`"default"` 用于其他比较宽松的场景（如 `+` 运算符）。

## 三、Map —— 万能钥匙档案柜

### 3.1 什么是 Map

Map 是一种**键值对的有序集合**，它与普通 Object 最大的区别在于：**Map 允许任何类型的值作为键**——包括对象、函数、数字、布尔值等等，而且键不会被自动转换为字符串。

如果把 Object 比作一个**传统纸质档案柜**，每份文件夹的名字必须手写为文字；那么 Map 就像是一个**现代智能档案柜**，你可以用任何东西来做索引——一张照片、一把钥匙、一个数字编码、甚至另一份文件夹本身。

```javascript
// 创建 Map
let map = new Map();

// 各种类型的键都可以用
map.set("name", "Alice")           // 字符串键
   .set(1, "one")                  // 数字键（不会被转成字符串！）
   .set(true, "yes")               // 布尔键
   .set(undefined, "nothing")      // undefined 键
   .set({}, "empty object")        // 对象键！

console.log(map.get(1));            // "one" —— 数字 1，不是字符串 "1"
console.log(map.get("1"));          // undefined —— 字符串 "1" 找不到
```

注意上面这个关键区别：在 Object 中，`obj[1]` 和 `obj["1"]` 访问的是同一个属性（因为键会被转为字符串）。但在 Map 中，`map.get(1)` 和 `map.get("1")` 是完全不同的操作——数字 1 和字符串 "1" 是两个**不同的键**。

### 3.2 Map 完整 API

| 方法 / 属性 | 功能 | 返回值 |
|------------|------|--------|
| `new Map([iterable])` | 创建 Map，可选传入 `[key, value]` 数组初始化 | 新的 Map 实例 |
| `map.set(key, value)` | 设置键值对 | **返回 map 本身**（支持链式调用） |
| `map.get(key)` | 获取键对应的值 | 值 或 `undefined` |
| `map.has(key)` | 判断键是否存在 | `true` / `false` |
| `map.delete(key)` | 删除指定键 | 成功 `true` / 失败 `false` |
| `map.clear()` | 清空所有内容 | 无返回值 |
| `map.size` | 当前的键值对数量 | 数字 |

```javascript
// 用数组初始化 Map
let recipeMap = new Map([
  ["cucumber", 500],    // 每个 [key, value] 是一个条目
  ["tomatoes", 350],
  ["onion", 50]
]);

console.log(recipeMap.size);              // 3
console.log(recipeMap.get("cucumber"));   // 500
console.log(recipeMap.has("onion"));      // true
recipeMap.delete("tomatoes");
console.log(recipeMap.size);              // 2
```

`set()` 方法返回 map 本身的设计非常巧妙——这让**链式调用**成为可能：

```javascript
map.set("a", 1)
   .set("b", 2)
   .set("c", 3);   // 一行搞定多个设置
```

### 3.3 Map vs Object 的全面对比

这是面试中最常见的选择题之一。理解两者的差异有助于在实际项目中做出正确的技术选型。

| 特性维度 | **Object** | **Map** |
|-----------|-----------|---------|
| **键的类型** | 只能是 String 或 Symbol | **任意类型**（含对象、函数等） |
| **键的自动转换** | Number → String（`obj[1]` ≡ `obj["1"]`） | **不做转换**，保持原类型 |
| **插入顺序** | 整数键有序，其他无保证 | **严格保留插入顺序** |
| **获取大小** | `Object.keys(obj).length`（需手动计算） | `map.size`（O(1) 直接获取） |
| **遍历方式** | `for...in`（含原型链）/ `Object.keys()` 等 | `for...of` / `forEach` / `keys()` / `values()` / `entries()` |
| **默认键** | 含原型链属性（`toString`, `constructor` 等） | **无默认键**（干净） |
| **频繁增删性能** | 较差（引擎优化难度大） | **更好**（专门为此优化） |
| **JSON 序列化** | ✅ 原生支持 | ❌ 需手动转换 |
| **键的比较算法** | 字符串匹配 | **SameValueZero**（`NaN === NaN` 为 true） |

#### SameValueZero 的特殊性

Map 使用 `SameValueZero` 算法比较键，这意味着一个有趣的现象——**在 Map 中，NaN 等于自身**：

```javascript
let m = new Map();
m.set(NaN, "not a number");

console.log(m.get(NaN));  // "not a number" —— 找到了！
```

而在普通相等性比较中，`NaN === NaN` 是 `false`。Map 的这个特性使得用 NaN 作为键时行为更加符合直觉。

#### 对象作为键的真实威力

Map 最强大的能力之一就是**用对象作为键**：

```javascript
// 场景：记录每个用户的访问次数

// ❌ 用 Object 做——灾难！
let visitsCountObj = {};
let john = { name: "John" };
visitsCountObj[john] = 100;   // 键变成了 "[object Object]"！

let pete = { name: "Pete" };  // 另一个人
visitsCountObj[pete] = 200;   // 键也是 "[object Object]"！！覆盖了 John 的数据！

console.log(visitsCountObj[john]);  // 200 —— 错误！这是 Pete 的数据

// ✅ 用 Map 做——完美
let visitsCountMap = new Map();
visitsCountMap.set(john, 100);     // john 对象本身就是键
visitsCountMap.set(pete, 200);     // pete 对象是另一个键

console.log(visitsCountMap.get(john));  // 100 —— 正确
console.log(visitsCountMap.get(pete));  // 200 —— 正确
```

当对象被用作 Object 的键时，JavaScript 会调用 `.toString()` 方法将其转为字符串——所有普通对象都变成 `"[object Object]"`，所以不同对象会互相覆盖。而 Map **直接用对象的引用身份作为键**，每个对象都是独一无二的。

### 3.4 Map 的遍历

Map 内置了完善的迭代能力，且**遍历顺序就是插入顺序**：

```javascript
let menu = new Map([
  ["salad", 35],
  ["soup", 25],
  ["steak", 120]
]);

// 遍历所有键
for (let dish of menu.keys()) {
  console.log(dish);     // salad, soup, steak
}

// 遍历所有值
for (let price of menu.values()) {
  console.log(price);    // 35, 25, 120
}

// 遍历 [key, value] 对（最常用）
for (let entry of menu.entries()) {  // 或者直接 for (let entry of menu)
  console.log(entry[0], entry[1]);
}

// forEach（注意参数顺序：value 在前，key 在后）
menu.forEach((price, dish) => {
  console.log(`${dish}: ¥${price}`);
});
```

特别注意的是 `forEach` 的回调参数顺序是 `(value, key, map)`——**值在前，键在后**。这与 Array 的 `forEach` 不同（数组的 `(item, index, array)` 是元素在前，索引在后）。这是因为 Map 的设计中更强调"值"的重要性。

### 3.5 Map 与 Object 的相互转换

实际工作中经常需要在 Map 和 Object 之间转换：

```javascript
// ====== Object → Map ======
let userObj = { name: "Bob", age: 28 };
let userMap = new Map(Object.entries(userObj));
// Object.entries 返回 [["name","Bob"], ["age",28]]
// Map 构造函数接受 [key,value] 数组

console.log(userMap.get("name"));  // "Bob"

// ====== Map → Object ======
let configMap = new Map([
  ["theme", "dark"],
  ["fontSize", 14]
]);

let configObj = Object.fromEntries(configMap);
// configObj = { theme: "dark", fontSize: 14 }

console.log(configObj.theme);  // "dark"
```

这个转换模式在数据处理流水线中特别有用——先用 Map 方便地进行增删改查和过滤操作，最后再转回 Object 以便 JSON 序列化或传给其他 API：

```javascript
// 实战：过滤掉值为 falsy 的属性
function cleanObject(obj) {
  return Object.fromEntries(
    new Map(
      Object.entries(obj).filter(([_, val]) => Boolean(val))
    )
  );

  // 等价于：
  // 1. Object.entries(obj) → [["a",1],["b",0],["c","",["d","hello"]]]
  // 2. .filter(...) → [["a",1],["d","hello"]]
  // 3. new Map([...]) → Map { "a"→1, "d"→"hello" }
  // 4. Object.fromEntries(map) → { a: 1, d: "hello" }
}

clean({ a: 1, b: 0, c: "", d: "hello" });  // { a: 1, d: "hello" }
```

## 四、Set —— 自动去重的收集篮

### 4.1 什么是 Set

Set 是一种**值的集合**，其中每个值只能出现一次——**重复的值会被自动忽略**。如果说数组是一个什么都能装的购物袋，那 Set 就是一个带有智能感应器的收集篮——当你往里面放入一件已经存在的东西时，它会默默拒绝。

```javascript
let set = new Set();

let guest1 = { name: "Alice" };
let guest2 = { name: "Bob" };
let guest3 = { name: "Charlie" };

set.add(guest1);
set.add(guest2);
set.add(guest3);
set.add(guest1);  // 重复！被忽略
set.add(guest3);  // 重复！被忽略

console.log(set.size);  // 3 —— 只有三个不同的对象
```

Set 的这个特性让它成为**数组去重**的最佳工具：

```javascript
// 经典应用：数组去重
let numbers = [1, 2, 2, 3, 3, 3, 4, 5, 5];
let uniqueNumbers = [...new Set(numbers)];
console.log(uniqueNumbers);  // [1, 2, 3, 4, 5]

// 或者用 Array.from
let unique = Array.from(new Set([1, 1, 2, 2, 3]));  // [1, 2, 3]
```

这比传统的 `filter + indexOf` 方法简洁得多，而且性能更好——尤其是对于大型数组。

### 4.2 Set 完整 API

| 方法 / 属性 | 功能 | 返回值 |
|------------|------|--------|
| `new Set([iterable])` | 创建 Set，可选传入数组初始化 | 新的 Set 实例 |
| `set.add(value)` | 添加值（重复则忽略） | **返回 set 本身**（支持链式调用） |
| `set.has(value)` | 判断值是否存在 | `true` / `false` |
| `set.delete(value)` | 删除指定值 | 成功 `true` / 失败 `false` |
| `set.clear()` | 清空所有内容 | 无返回值 |
| `set.size` | 当前的元素数量 | 数字 |

```javascript
let colors = new Set(["red", "green", "blue"]);
console.log(colors.has("green"));   // true
console.log(colors.has("yellow"));  // false
colors.add("yellow");
colors.delete("red");
console.log(colors.size);           // 3
```

### 4.3 Set 的遍历

有趣的是，Set 也提供了 `keys()`、`values()`、`entries()` 方法——这是为了让 Set 和 Map 的 API 保持一致的"接口兼容"：

```javascript
let set = new Set(["apple", "banana", "cherry"]);

// values() —— 遍历所有值
for (let fruit of set.values()) {
  console.log(fruit);   // apple, banana, cherry
}

// keys() —— 在 Set 中等同于 values()
for (let fruit of set.keys()) {
  console.log(fruit);   // apple, banana, cherry（同样的结果）
}

// entries() —— 返回 [value, value] 对
for (let pair of set.entries()) {
  console.log(pair);    // ["apple","apple"], ["banana","banana"]...
}

// forEach —— 参数也是 (value, valueAgain, set)
set.forEach((val, valAgain) => {
  console.log(val === valAgain);  // true —— 两次都是同一个值
});
```

为什么 `entries()` 要返回 `[value, value]`？为什么 `forEach` 要传两个相同的值？这是为了让你在编写代码时能够轻松地在 Set 和 Map 之间切换，而不用大幅修改遍历逻辑——因为 Map 的 `entries()` 返回的是 `[key, value]`，`forEach` 传入的是 `(value, key)`。Set 模仿同样的格式，只是 key 和 value 相同而已。

### 4.4 集合运算 —— 数学中的交并差集

Set 天然适合进行数学意义上的集合运算。虽然 JavaScript 没有内置这些运算符，但我们可以很方便地自己实现：

```javascript
let A = new Set([1, 2, 3, 4]);
let B = new Set([3, 4, 5, 6]);

// 并集 (Union): A ∪ B —— 两边有的都要
let union = new Set([...A, ...B]);
console.log([...union]);  // [1, 2, 3, 4, 5, 6]

// 交集 (Intersection): A ∩ B —— 共同拥有的
let intersection = new Set([...A].filter(x => B.has(x)));
console.log([...intersection]);  // [3, 4]

// 差集 (Difference): A \ B —— A 有但 B 没有的
let difference = new Set([...A].filter(x => !B.has(x)));
console.log([...difference]);  // [1, 2]

// 对称差集 (Symmetric Difference): A Δ B —— 不共有的
let symDiff = new Set(
  [...A].filter(x => !B.has(x)).concat([...B].filter(x => !A.has(x)))
);
console.log([...symDiff]);  // [1, 2, 5, 6]

// 子集判断: A ⊆ B
let isSubset = [...A].every(x => B.has(x));
console.log(isSubset);  // false
```

这些运算在实际项目中的应用场景包括：

- **权限管理**：用户的角色权限是一个 Set，资源要求的角色是另一个 Set，用交集判断是否有权访问
- **标签筛选**：文章标签和筛选条件分别用 Set 存储，交集就是符合条件的文章
- **数据比对**：新旧两份数据分别用 Set 存储，差集就是新增或删除的部分

### 4.5 Set 的去重原理 —— SameValueZero 算法

Set 判断两个值是否相同，使用的也是 `SameValueZero` 算法（与 Map 相同）。这意味着几个重要的细节：

```javascript
let s = new Set();

s.add(NaN); s.add(NaN);     // NaN 只算一个（SameValueZero 认为 NaN === NaN）
console.log(s.size);        // 1

s.add(+0); s.add(-0);       // +0 和 -0 算作同一个
console.log(s.size);        // 还是 1（相对于之前）

s.add({}); s.add({});       // 两个空对象是不同的（引用不同）
console.log(s.size);        // 2
```

**对象只有在引用相同时才被视为重复**——即使两个对象的内容完全一样，它们也是两个不同的值：

```javascript
let obj1 = { x: 1 };
let obj2 = { x: 1 };

let s = new Set();
s.add(obj1);
s.add(obj2);

console.log(s.size);  // 2 —— 内容相同但不是同一个引用
```

这就像现实生活中的身份证——两个人的资料可能完全同名同龄同地址，但他们持有的是两张不同的证件。

## 五、WeakMap —— 自动清理的便签本

### 5.1 为什么需要 WeakMap

在了解 WeakMap 之前，我们需要先回顾 JavaScript 的垃圾回收（GC）机制中的一个基本原则：**可达性（Reachability）**。

如果一个值还能被某个变量、属性或其他引用路径"触及"，它就被认为是"可达"的，引擎就不会回收它。只有当一个值彻底没有任何途径能被访问到时，才会被当作垃圾清理掉。

这带来一个问题——**常规的数据结构会对它所包含的对象形成强引用**，阻止那些对象被回收：

```javascript
let john = { name: "John Doe" };

// 假设我们要记录每个用户的访问次数
let visitCounts = new Map();
visitCounts.set(john, 1);   // Map 持有对 john 的引用

john = null;                 // 我们不再需要 john 了...
// 但 john 对象依然存在于 Map 中！内存泄漏！
```

这就像你在一个笔记本上记下了某人的信息，然后把他的名片扔掉了——但笔记本上的记录还在，那个人（的数据）就无法真正"离开"。除非你同时擦除笔记本上的记录，否则这块内存永远不会被释放。

WeakMap 就是解决这个问题的方案——它是**弱引用**版本。当作为键的对象在外部已经没有其他引用时，它可以被垃圾回收，而 WeakMap 中的对应条目也会随之消失。

### 5.2 WeakMap 的三大限制

为了实现弱引用机制，WeakMap 做出了一些重要妥协——它**只提供最基本的四个方法**：

| 支持的操作 | 不支持的操作 |
|------------|-------------|
| `get(key)` | `keys()` |
| `set(key, value)` | `values()` |
| `has(key)` | `entries()` |
| `delete(key)` | `size` 属性 |
| | `clear()` |
| | `for...of` 遍历 |
| | `forEach` |

为什么有这么多限制？原因很简单：**垃圾回收的时机是不确定的**。引擎可以在任何时候决定清理某个不可达的对象，这意味着 WeakMap 中的条目可能随时消失。既然当前有多少个有效条目都无法确定，自然就不可能提供遍历、计数等功能。

另外，**键必须是对象**（或 non-registered Symbol），不能用字符串、数字等原始值：

```javascript
let wm = new WeakMap();
let obj = {};

wm.set(obj, "ok");        // ✅ 正常工作
wm.set("hello", "oops");  // ❌ TypeError! 键必须是对象
```

### 5.3 WeakMap 核心机制详解

```javascript
// ========== 内存管理对比 ==========

// 普通 Map —— 强引用，阻止垃圾回收
let user1 = { name: "Alice" };
let normalMap = new Map();
normalMap.set(user1, "some data");

user1 = null;  // 我们放弃了对 user1 的引用
// 但 { name: "Alice" } 仍然被 normalMap 引用着！不会被回收！

// WeakMap —— 弱引用，允许垃圾回收
let user2 = { name: "Bob" };
let weakMap = new WeakMap();
weakMap.set(user2, "some data");

user2 = null;  // 我们放弃了对 user2 的引用
// 现在 { name: "Bob"} 只有 WeakMap 一个弱引用
// 垃圾回收器会在适当的时候把它清理掉
// weakMap 里的这条记录也随之消失
```

可以把 WeakMap 想象成**便利贴**——你把一张便利贴贴在某人的背上（给他关联了一些额外数据），当他离开房间后（外部引用消失），便利贴也就跟着消失了，不会堆积下来。

而普通 Map 更像是**登记簿**——一旦登记了某人的信息，即使他本人离开了，登记簿上的记录还在。

### 5.4 WeakMap 的典型应用场景

#### 场景一：为外部对象附加额外数据

这是 WeakMap 最经典的用法——你想给别人的对象附加上自己的数据，但不希望阻碍该对象被回收：

```javascript
// 缓存计算结果的例子
let cache = new WeakMap();

function heavyComputation(obj) {
  if (!cache.has(obj)) {
    // 如果缓存中没有，执行耗时计算
    let result = /* ... 复杂计算过程 ... */;
    cache.set(obj, result);
    console.log("计算完成并缓存");
  } else {
    console.log("命中缓存");
  }

  return cache.get(obj);
}

let data = { x: 100, y: 200 };
heavyComputation(data);  // "计算完成并缓存"
heavyComputation(data);  // "命中缓存"

data = null;  // data 不再需要了
// cache 中的缓存也会在下次 GC 时自动清除
// 不会有内存泄漏！
```

#### 场景二：私有属性的模拟（ES2022 class private fields 出现前的重要模式）

```javascript
// 用 WeakMap 实现"真正的"私有属性
const _privateData = new WeakMap();

class BankAccount {
  constructor(owner, initialBalance) {
    this.owner = owner;
    // 将"私有"数据存入 WeakMap，键就是实例本身
    _privateData.set(this, {
      balance: initialBalance,
      pin: "1234",
      transactions: []
    });
  }

  deposit(amount) {
    const data = _privateData.get(this);
    data.balance += amount;
    data.transactions.push({ type: "deposit", amount });
    return data.balance;
  }

  getBalance() {
    // 只有类的方法能通过 this 访问到私有数据
    return _privateData.get(this).balance;
  }
}

let account = new BankAccount("Alice", 1000);
account.deposit(500);

console.log(account.getBalance());  // 1500

// 外部无法访问私有数据
console.log(_privateData.get(account));  // 需要拿到 _privateData 引用才行
// account._balance ?? 不存在这个属性
// 即使拿到 _privateData，没有 account 实例也无法访问
account = null;
// 实例被回收，私有数据也被自动清理
```

在这个模式中，WeakMap 的键是类的实例对象，值是该实例的私有数据。由于 `_privateData` 这个 WeakMap 变量如果在模块作用域内声明，外部代码就无法访问它——从而实现了真正的封装。

#### 场景三：DOM 节点的关联数据

```javascript
// 给 DOM 元素绑定额外的元数据，不污染 DOM 本身
let elementData = new WeakMap();

function attachMetadata(element, metadata) {
  elementData.set(element, metadata);
}

function getMetadata(element) {
  return elementData.get(element);
}

// 使用
let btn = document.getElementById("myButton");
attachMetadata(btn, { clickedCount: 0, createdAt: Date.now() });

btn.addEventListener("click", () => {
  let meta = getMetadata(btn);
  meta.clickedCount++;
  console.log(`点击了 ${meta.clickedCount} 次`);
});

// 当按钮被从 DOM 中移除后
// btn.remove();  // 或 innerHTML 替换
// btn = null;
// 关联数据会被自动清理，不会造成内存泄漏
```

## 六、WeakSet —— 自动清理的标记板

### 6.1 什么是 WeakSet

WeakSet 是 Set 的弱引用版本。它的特点与 WeakMap 高度相似：

- **值必须是对象**（不能用原始类型）
- **弱引用**——对象在外部不可达时会被自动清除
- **不支持遍历**，没有 `size`，没有 `clear()`
- **只有三个方法**：`add(value)`、`has(value)`、`delete(value)`

```javascript
let ws = new WeakSet();

let obj = { name: "test" };
ws.add(obj);             // ✅ 正常
ws.add("hello");         // ❌ TypeError! 值必须是对象

console.log(ws.has(obj));// true
ws.delete(obj);
console.log(ws.has(obj));// false
```

### 6.2 WeakSet 的典型应用

WeakSet 通常用于存储"是/否"型的标记信息——即某个对象是否具有某种状态或已被处理过：

```javascript
// 场景：标记消息为"已读"

let messages = [
  { text: "Hello", from: "John" },
  { text: "How are you?", from: "Jane" },
  { text: "See you!", from: "Tom" }
];

// 用 WeakSet 来记录哪些消息已被读
let readMessages = new WeakSet();

readMessages.add(messages[0]);  // 第一条已读
readMessages.add(messages[1]);  // 第二条已读

// 检查
console.log(readMessages.has(messages[0]));  // true
console.log(readMessages.has(messages[2]));  // false

// 当消息从列表中被移除
messages.shift();  // 删除第一条消息
// readMessages 中对应的标记也会在 GC 时自动清除
```

另一个常见的场景是**防止重复处理**：

```javascript
let processedObjects = new WeakSet();

function processOnce(obj) {
  if (processedObjects.has(obj)) {
    console.log("已处理过，跳过");
    return;
  }

  // 执行处理逻辑...
  console.log("首次处理");
  processedObjects.add(obj);  // 标记为已处理
}

let item = { id: 1 };
processOnce(item);  // "首次处理"
processOnce(item);  // "已处理过，跳过"

item = null;  // 标记也会被自动清理
```

### 6.3 WeakMap vs WeakSet 的选择

两者的区别其实很简单——就像问"你需要记笔记还是只需要打个勾"：

| 维度 | **WeakMap** | **WeakSet** |
|------|------------|-------------|
| **存的是什么** | 键值对（键→数据的映射） | 单个值（存在与否的标记） |
| **能存多少信息** | 丰富——可以为对象附加任意数据 | 有限——只有"在里面/不在里面"两种状态 |
| **比喻** | 便利贴（可以写字） | 打孔器（打孔标记） |
| **适用场景** | 缓存、私有属性、计数器 | 已读标记、防重复处理、成员资格检查 |
| **API** | get/set/has/delete | add/has/delete |

## 七、五大数据结构完整对比

### 7.1 选择决策指南

面对具体问题时，如何在这五种数据结构中选择？

```
你需要存储的是？
│
├─ 需要唯一的标识符（用作属性键）──→ Symbol
│
├─ 需要 键→值 映射关系？
│   ├─ 键可以是任意类型吗？（特别是对象）──→ Map
│   └─ 键只是字符串/符号就够了？
│       ├─ 需要遍历/知道大小 ──→ Map（或 Object）
│       ├─ 需要序列化为 JSON ──→ Object
│       └─ 键对象需随 GC 回收 ──→ WeakMap
│
├─ 需要存储一组值，且要求唯一（去重）？
│   ├─ 需要遍历/知道大小 ──→ Set
│   └─ 值需随 GC 回收 ──→ WeakSet
│
└─ 其他情况 ──→ 数组 [] 或 Object {}
```

### 7.2 综合特性矩阵

| 特性 | Object | Map | Set | WeakMap | WeakSet |
|------|--------|-----|-----|---------|---------|
| **存储形式** | 键值对 | 键值对 | 值 | 键值对（弱） | 值（弱） |
| **键/值类型限制** | 键: String/Symbol | 任意 | 任意 | 键: 仅对象 | 值: 仅对象 |
| **插入顺序** | 部分（整数键有序） | ✅ 保证 | ✅ 保证 | ✅ 保证 | ✅ 保证 |
| **size / length** | 手动计算 | `O(1)` | `O(1)` | ❌ 不可用 | ❌ 不可用 |
| **遍历** | `for...in`/`Object.*` | `for...of`/forEach | `for...of`/forEach | ❌ 不可遍历 | ❌ 不可遍历 |
| **自动去重** | ❌ | ❌ | ✅ | N/A | ✅ |
| **JSON 支持** | ✅ 原生 | ❌ 需转换 | ❌ 需转换 | ❌ | ❌ |
| **GC 友好** | ❌ 强引用 | ❌ 强引用 | ❌ 强引用 | ✅ 弱引用 | ✅ 弱引用 |
| **常用方法数** | ~15 个 | ~8 个 | ~7 个 | 4 个 | 3 个 |

## 八、实战案例综合运用

### 案例 1：LRU 缓存（Map 的有序性 + 大小限制）

利用 Map **保留插入顺序**的特性，可以实现一个简单的 LRU（最近最少使用）缓存：

```javascript
class LRUCache {
  constructor(maxSize = 100) {
    this.cache = new Map();
    this.maxSize = maxSize;
  }

  get(key) {
    if (!this.cache.has(key)) return undefined;

    // 访问后重新插入到末尾（变为"最近使用"）
    const value = this.cache.get(key);
    this.cache.delete(key);
    this.cache.set(key, value);

    return value;
  }

  set(key, value) {
    if (this.cache.has(key)) {
      this.cache.delete(key);  // 先删除旧位置
    }

    this.cache.set(key, value);

    // 超出容量时删除最早的（Map 的第一个条目）
    if (this.cache.size > this.maxSize) {
      const oldestKey = this.cache.keys().next().value;
      this.cache.delete(oldestKey);
    }
  }
}

let cache = new LRUCache(3);
cache.set("a", 1);
cache.set("b", 2);
cache.set("c", 3);
cache.get("a");  // 访问 a，a 变为最近使用
cache.set("d", 4);  // 超容，淘汰 b（最早未被访问的）

console.log(cache.get("b"));  // undefined —— b 已被淘汰
console.log(cache.get("a"));  // 1 —— a 因为刚被访问所以保留了
```

Map 的有序性在这里起到了关键作用：新访问/新增的条目排在后面，要淘汰时只需删掉第一个（最早未用的）即可。这个技巧在很多前端框架的缓存实现中被广泛使用。

### 案例 2：Redux action 类型安全（Symbol 枚举）

用 Symbol 替代字符串常量来定义 action type，确保不会出现拼写错误或值冲突：

```javascript
// actionTypes.js
const ActionTypes = {
  ADD_TODO: Symbol("todo:add"),
  REMOVE_TODO: Symbol("todo:remove"),
  TOGGLE_TODO: Symbol("todo:toggle"),
  SET_FILTER: Symbol("filter:set")
};

export default ActionTypes;

// reducer.js
import ActionTypes from "./actionTypes";

function todoReducer(state = [], action) {
  switch (action.type) {
    case ActionTypes.ADD_TODO:
      return [...state, action.payload];

    case ActionTypes.REMOVE_TODO:
      return state.filter(item => item.id !== action.payload.id);

    case ActionTypes.TOGGLE_TODO:
      return state.map(item =>
        item.id === action.payload.id ? { ...item, done: !item.done } : item
      );

    default:
      return state;
  }
}

// 使用时的优势：
// 1. Symbol 值永远唯一，不可能和其他模块冲突
// 2. 无法用字符串伪造 dispatch({ type: "ADD_TODO" }) —— 必须引用真实的 Symbol
// 3. 调试时有描述信息便于定位
```

### 案例 3：DOM 事件代理（WeakMap 存储组件实例数据）

在构建轻量级 UI 框架时，用 WeakMap 将 DOM 元素与组件数据关联：

```javascript
class ComponentRegistry {
  constructor() {
    this.components = new WeakMap();  // Element → Component Instance
  }

  register(element, component) {
    this.components.set(element, component);
  }

  getComponent(element) {
    return this.components.get(element);
  }
}

// 使用示例
const registry = new ComponentRegistry();

class Button {
  constructor(el, onClick) {
    this.el = el;
    this.onClick = onClick;
    registry.register(el, this);
    el.addEventListener("click", this.handleClick.bind(this));
  }

  handleClick(e) {
    this.onClick(e);
  }

  destroy() {
    this.el.removeEventListener("click", this.handleClick);
    this.el = null;  // 组件销毁，WeakMap 条目将自动清理
  }
}

// 创建按钮
const btnEl = document.getElementById("submitBtn");
new Button(btnEl, () => console.log("Clicked!"));

// 当按钮被从 DOM 移除 + 组件 destroy 后
// 所有相关内存都会被正确回收
```

## 九、陷阱与注意事项

### 9.1 常见陷阱一览

| # | 陷阱 | 说明 | 解决方案 |
|---|------|------|---------|
| 1 | **Map 键的对象引用变化** | `map.set(obj, v)` 后修改 `obj` 的属性不影响查找，但如果 `obj = null` 则丢失键 | 注意保持键引用的有效性 |
| 2 | **Set 去重只看引用不看内容** | `{x:1} !== {x:1}`，两个内容相同的对象在 Set 中占两个位置 | 如果需要按内容去重，先序列化或自定义比较 |
| 3 | **JSON.stringify 忽略 Symbol** | 包含 Symbol 键的对象序列化后 Symbol 属性丢失 | 需 replacer 函数手动处理 |
| 4 | **Map/Set 无法直接序列化** | `JSON.stringify(new Map())` → `{}` | 用 `Object.fromEntries` 转换后再序列化 |
| 5 | **WeakMap/WeakSet 不可枚举** | 不能遍历、不能看 size、不能 clear | 它们是辅助工具，不适合做主要存储 |
| 6 | **Symbol.for 的全局副作用** | `Symbol.for("key")` 创建全局 Symbol，可能跨模块冲突 | 只在确实需要跨模块共享时使用 |
| 7 | **Map 的 NaN 键行为** | `NaN` 作为 Map 的键只有一个（SameValueZero 规则） | 这是特性不是 bug，合理利用 |

### 9.2 序列化与反序列化

由于 Map 和 Set 无法直接 `JSON.stringify`，需要手动转换：

```javascript
// Map → JSON
let map = new Map([["name", "Alice"], ["age", 30]]);

// 序列化
let jsonStr = JSON.stringify(Array.from(map.entries()));
// '[["name","Alice"],["age",30]]'

// 反序列化
let restoredMap = new Map(JSON.parse(jsonStr));

// Set → JSON
let set = new Set([1, 2, 3]);

// 序列化
jsonStr = JSON.stringify([...set]);  // '[1,2,3]'

// 反序列化
let restoredSet = new Set(JSON.parse(jsonStr));

// 封装为通用工具
function serializeMap(map) {
  return JSON.stringify([...map.entries()]);
}

function deserializeMap(str) {
  return new Map(JSON.parse(str));
}
```

### 9.3 性能考量

| 操作 | Object | Map | Set |
|------|--------|-----|-----|
| **频繁增删键值对** | 一般 | **优秀** | **优秀** |
| **大量数据查找** | 良好（V8 优化后） | 优秀 | 优秀 |
| **内存占用** | 较低（结构简单） | 较高（维护更多元数据） | 较低 |
| **初始化速度** | 快 | 稍慢（构造开销） | 稍慢 |

一般来说，如果你的数据量不大（几百条以内），Object 的性能完全够用，而且更便于序列化和调试。Map 在**大量数据、频繁增删、需要非字符串键**的场景下才显示出明显优势。

## 十、最佳实践总结

### 何时用什么

| 场景 | 推荐 | 原因 |
|------|------|------|
| 简单配置/选项/JSON 数据 | **Object** | 原生序列化，语法简洁 |
| 频繁增删键值对 | **Map** | 性能好，有 size 属性 |
| 键是对象或需要非字符串键 | **Map**（或 **WeakMap**） | Object 会把键转字符串 |
| 需要保持插入顺序 | **Map** | 有序保证 |
| 需要去重 | **Set** | 自动去重，语义清晰 |
| 需要做集合运算（交并差） | **Set** | 天然适配 |
| 为外部对象附加大数据 | **WeakMap** | 自动 GC，避免内存泄漏 |
| 标记对象状态（是/否） | **WeakSet** | 同上，且语义简洁 |
| 隐藏属性/避免命名冲突 | **Symbol** | 不可枚举，唯一性保证 |
| 自定义对象行为 | **系统 Symbol** | `iterator`/`toPrimitive` 等 |
| Redux action types | **Symbol** | 不可伪造，全局唯一 |
| 缓存（键是对象） | **WeakMap** | 键被回收时自动清缓存 |

### 设计原则

1. **优先考虑语义清晰度**：需要映射用 Map，需要集合用 Set，不要强行用 Object 模拟
2. **关注 GC 影响**：涉及大量临时对象的关联数据时，优先考虑 WeakMap/WeakSet
3. **注意序列化需求**：如果数据需要持久化或网络传输，Object 仍是最佳选择
4. **Symbol 用于约定而非加密**：Symbol 属性并非真的"不可访问"，只是不被常规遍历发现
5. **不要过度使用**：新语法 ≠ 更好的选择，在简单的场景下 Object 和数组往往更直观

```
Symbol 与 Map/Set 数据体系
│
├── Symbol（第七种原始类型）
│   ├── 基础特性
│   │   ├── typeof === "symbol"
│   │   ├── 唯一性：每次 Symbol() 都是新值
│   │   ├── 不可变性：创建后不能改变
│   │   └── 拒绝隐式转换（保护机制）
│   │
│   ├── 创建方式
│   │   ├── Symbol(desc) —— 局部 Symbol（推荐）
│   │   └── Symbol.for(key) —— 全局 Symbol（跨模块共享）
│   │
│   ├── 作为对象属性键
│   │   ├── 隐藏性：for...in/Object.keys 忽略
│   │   ├── 克隆性：Object.assign/展开运算符 会复制
│   │   └── 可检索：getOwnPropertySymbols / Reflect.ownKeys
│   │
│   └── 系统 Well-known Symbol
│       ├── Symbol.iterator ──→ 可迭代协议
│       ├── Symbol.toPrimitive ──→ 类型转换
│       ├── Symbol.toStringTag ──→ toString 标签
│       └── Symbol.hasInstance ──→ instanceof 行为
│
├── Map（键值对集合）
│   ├── 核心：任意类型作为键 + 保留插入顺序
│   ├── CRUD API：set/get/has/delete/clear/size
│   ├── 遍历：keys/values/entries/forEach/for...of
│   ├── 与 Object 互转：Object.entries ↔ Object.fromEntries
│   └── SameValueZero 比较（NaN === NaN）
│
├── Set（唯一值集合）
│   ├── 核心：自动去重 + 值的唯一性
│   ├── CRUD API：add/has/delete/clear/size
│   ├── 遍历：values/keys/entries/forEach/for...of
│   └── 集合运算：并集/交集/差集/对称差集/子集判断

选择策略树：
需求分析
├── 需要唯一标识符？──→ Symbol
├── 需要 键→值 映射？
│   ├── 键是非字符串？──→ Map / WeakMap
│   ├── 需要GC友好？─────→ WeakMap
│   └── 其他 ────────────→ Map / Object
├── 需要去重/集合运算？──→ Set
│   └── 需要GC友好？───────→ WeakSet
└── 简单数据/JSON需求？──→ Object / Array
```
