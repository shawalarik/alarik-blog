# 异步生成器与异步迭代 —— for await...of、async function*、异步可迭代协议

> **核心内容**：在掌握了同步迭代器和普通生成器之后，现实世界向我们抛出了一个更复杂的挑战——**数据本身是异步产生的**。分页 API 的逐页加载、WebSocket 的消息流、文件系统的逐行读取、Node.js 流式数据处理……这些场景中，"下一个值"不是一个立即可拿的东西，而是一个需要等待 Promise 才能获取的未来值。ES2018 引入的**异步迭代器（Async Iterator）**和**异步生成器（Async Generator）**正是为解决这类问题而生。它们将 `await` 和 `yield` 融为一体，让异步数据流的消费变得像遍历数组一样自然优雅。

---

## 1. 为什么需要异步迭代 —— 同步协议的天花板

### 1.1 同步迭代器的局限

回顾我们之前学过的同步迭代器协议：它的核心假设是 **`next()` 调用会立即返回结果**——一个包含 `{value, done}` 的普通对象。

```javascript
// 同步迭代器：next() 立即返回结果
const syncIterator = {
  [Symbol.iterator]() {
    let n = 0;
    return {
      next() {
        if (n < 3) return { value: n++, done: false };
        return { value: undefined, done: true };
      }
    };
  }
};

for (const num of syncIterator) {
  console.log(num);  // 0, 1, 2 —— 立即输出，没有任何延迟
}
```

这种同步模型在面对以下场景时就会遇到根本性的困难：

**场景一：分页数据加载**

```javascript
// 假设我们想遍历 GitHub 上某个仓库的所有 commit
// API 每次只返回 30 条，我们需要反复请求直到没有下一页
// 问题: 每次 fetch 都是异步的，同步迭代器无法表达"等待网络请求"
function* syncCommits(repo) {
  let url = `https://api.github.com/repos/${repo}/commits`;
  
  while (url) {
    const response = fetch(url);  // ❌ 返回的是 Promise，不是实际数据！
    // 同步迭代器不能 await！这里无法等待请求完成
    const data = response.json();  // 同样是 Promise
    // ...
    url = getNextPageUrl(response);
    
    for (const commit of data) yield commit;
  }
}
```

**场景二：延迟产生的数据流**

```javascript
// 想要每隔1秒产生一个数字
// 问题: setTimeout 是异步的，同步迭代器无法在其中"暂停并等待"
function* delayedSequence() {
  for (let i = 1; i <= 5; i++) {
    setTimeout(() => {}, 1000);  // ❌ 这不会真正阻塞1秒！
    yield i;                     // 所有值几乎同时产出
  }
}
```

**场景三：用户交互事件流**

```javascript
// 想要逐个处理用户的点击事件
// 问题: 事件是未来才发生的，同步迭代器无法"等待下一个事件"
function* clickStream(button) {
  while (true) {
    // ❌ 如何在这里"等待下一次点击"？同步代码做不到
    const event = /* ??? */;
    yield event;
  }
}
```

### 1.2 理论分析：同步 vs 异步的数据产生模式

从计算机科学的角度看，数据的产生方式可以分为两类：

| 特征 | 同步数据源 | 异步数据源 |
|------|-----------|-----------|
| 数据就绪时间 | **立即可用** | **需要等待**（不确定的时间点）|
| 数据位置 | 已在内存/栈中 | 在外部系统（网络、磁盘、用户输入）|
| 获取代价 | O(1) 直接读取 | 取决于 I/O 操作的完成时间 |
| 典型例子 | 数组、字符串、Set、Map | HTTP 请求、数据库查询、文件读取、用户事件 |
| 迭代器行为 | `next()` 立即返回 `{value, done}` | `next()` 应该返回 **Promise<{value, done}>` |

**核心洞察**：同步迭代器的 `next()` 是一个**纯函数调用**——调用后立刻得到结果。但异步场景下的 `next()` 本质上是一个**耗时操作**——它发起一次 I/O 请求，然后必须等待响应才能返回结果。在 JavaScript 中，表达"耗时操作的结果"的标准方式就是 **Promise**。

因此，异步迭代的思路非常自然：让 `next()` 不再返回 `{value, done}`，而是返回 **`Promise<{value, done}>`**。这样，消费者就可以用 `await` 来等待每个值的到达。

### 1.3 通俗类比：外卖配送 vs 食堂自取

把数据获取想象成**吃饭**：
- **同步迭代 = 食堂自取**：饭菜已经做好摆在窗口前，你走过去就能拿到。拿到一份后伸手拿下一份，整个过程连续不断。
- **异步迭代 = 外卖配送**：你下单后不能立即拿到食物，必须等骑手送过来。每次吃完一份后要再等下一份送达。中间的等待时间是不确定的（取决于距离、天气、交通），但你可以在等待时去做别的事。

同步迭代器只能处理"食堂自取"式的数据，而异步迭代器则能完美应对"外卖配送"式的数据流——这也是为什么现代 Web 开发中异步迭代如此重要。

## 2. 异步迭代协议 —— 从 Symbol.iterator 到 Symbol.asyncIterator

### 2.1 协议定义

异步迭代协议是同步迭代协议的自然扩展，核心变化只有三处：

**同步可迭代协议**：
```
对象[Symbol.iterator]() → 返回迭代器对象
迭代器.next()           → 返回 { value, done }        （普通对象）
循环语法                → for (const x of iterable)     （for...of）
```

**异步可迭代协议**：
```
对象[Symbol.asyncIterator]() → 返回异步迭代器对象
异步迭代器.next()            → 返回 Promise<{ value, done }>   （Promise！）
循环语法                     → for await (const x of iterable) （for await...of）
```

注意这个精妙的变化链：
- 键名变了：`Symbol.iterator` → **`Symbol.asyncIterator`**
- `next()` 的返回值类型变了：普通对象 → **Promise**
- 循环语法变了：`for...of` → **`for await...of`**

每一步变化都是为了让协议能够承载"异步"这个维度。

### 2.2 手工实现一个异步可迭代对象

让我们从零开始实现一个最简单的异步迭代器——每秒产出一个数字：

```javascript
const asyncRange = {
  from: 1,
  to: 5,
  
  // ① 使用异步迭代符号
  [Symbol.asyncIterator]() {
    console.log('[Symbol.asyncIterator] 被调用了');
    
    return {
      current: this.from,
      last: this.to,
      
      // ② next() 方法返回 Promise（通过 async 实现）
      async next() {
        // ③ 内部可以使用 await —— 这是关键！
        await new Promise(resolve => setTimeout(resolve, 1000));
        
        if (this.current <= this.last) {
          return { done: false, value: this.current++ };
        } else {
          return { done: true };  // done: true 时 value 可省略（默认 undefined）
        }
      }
    };
  }
};
```

**使用 `for await...of` 消费它**：

```javascript
// 注意：for await...of 必须在 async 函数内部使用（因为它要用 await）
(async () => {
  console.log('--- 开始遍历 ---');
  
  for await (const value of asyncRange) {
    console.log(`收到值: ${value}`);
    // 每隔约 1 秒输出一行: 1, 2, 3, 4, 5
  
    // 可以随时 break 中断（就像普通的 for...of 一样）
    // if (value === 3) break;
  }
  
  console.log('--- 遍历结束 ---');
})();
```

运行效果：
```
[Symbol.asyncIterator] 被调用了
--- 开始遍历 ---
收到值: 1       ← 等待约1秒
收到值: 2       ← 再等约1秒
收到值: 3       ← 再等约1秒
收到值: 4       ← 再等约1秒
收到值: 5       ← 再等约1秒
--- 遍历结束 ---
```

### 2.3 逐步解析 for await...of 的执行过程

理解 `for await...of` 底层做了什么非常重要：

```javascript
// for await...of 的底层逻辑（概念性伪代码）
async function forAwaitOfLoop(asyncIterable, callback) {
  // 步骤 1: 获取异步迭代器工厂方法
  const asyncIteratorMethod = asyncIterable[Symbol.asyncIterator];
  
  if (typeof asyncIteratorMethod !== 'function') {
    // 如果没有 asyncIterator，尝试 fallback 到同步 iterator
    // （某些情况下 for await...of 可以用于同步可迭代对象）
    throw new TypeError(`${asyncIterable} is not async iterable`);
  }
  
  // 步骤 2: 调用工厂方法获得异步迭代器
  const asyncIterator = asyncIteratorMethod.call(asyncIterable);
  
  // 步骤 3: 反复调用 next() 并 await 其结果
  try {
    while (true) {
      // next() 返回的是 Promise！必须 await
      const result = await asyncIterator.next();
      
      // 步骤 4: 检查是否完成
      if (result.done) {
        break;
      }
      
      // 步骤 5: 将 value 传给循环体
      callback(result.value);
    }
  } finally {
    // 步骤 6: 如果迭代器有 return() 方法，清理资源
    if (typeof asyncIterator.return === 'function') {
      await asyncIterator.return();  // 注意: return() 也可能返回 Promise!
    }
  }
}
```

**对比同步版本的关键差异**：

```javascript
// 同步 for...of:
const result = iterator.next();         // 立即得到结果
if (result.done) break;

// 异步 for await...of:
const result = await asyncIterator.next();  // 等待 Promise resolve！
if (result.done) break;
```

仅仅多了一个 `await`，但这个 `await` 打开了异步世界的大门。

### 2.4 for await...of 对同步可迭代对象的兼容性

`for await...of` 有一个实用的特性：**它可以用于同步可迭代对象**。如果对象有 `Symbol.iterator` 但没有 `Symbol.asyncIterator`，`for await...of` 会自动将其包装为异步迭代器使用：

```javascript
const syncIterable = [10, 20, 30];  // 普通数组，只有 Symbol.iterator

(async () => {
  // ✅ 可以用 for await...of 遍历同步可迭代对象
  for await (const value of syncIterable) {
    console.log(value);  // 10, 20, 30
  }
})();
```

这相当于对每个值做了一次 `Promise.resolve(value)` 的包装。但如果对象**同时拥有**两个符号，优先使用 `Symbol.asyncIterator`。

### 2.5 通俗类比：快递代收点

把异步迭代协议想象成一个**快递代收点的运作流程**：

**`[Symbol.asyncIterator]()` = 开通会员**：你到代收点说"我要寄快递"，工作人员给你开通了一个专属服务账号（创建迭代器）。

**`next()` = 下单一趟快递**：你每次去问"我的快递到了吗？"（调用 `next()`）。但快递还在路上呢，所以工作人员给你一张**取件单**（Promise），告诉你"到了之后凭单来取"。

**`await` = 等待送达**：你拿着取件单坐在旁边等。快递车来了，包裹送到（Promise resolved），你去取货（得到 `{value, done}`）。

**`for await...of` = 包年套餐**：你不希望每次都去问、每次都等，于是你办了个包年服务。代收点承诺：只要有新包裹就通知你，你只需要在门口等着收就行。整个过程自动化了。

## 3. 异步生成器 —— async function*

### 3.1 基本语法

手工编写异步迭代器虽然可行，但代码冗长（如上一节所示）。ES2018 提供了**异步生成器函数（Async Generator Function）**作为语法糖，大幅简化异步迭代器的创建：

```javascript
// 异步生成器声明: async + function* 的组合
async function* asyncGenerator() {
  // 内部可以同时使用 await 和 yield！
  yield await fetchData(1);
  yield await fetchData(2);
  yield await fetchData(3);
}

// 其他声明形式:
const asyncGenExpr = async function* () { ... };

const obj = {
  async *method() { ... }  // 对象方法简写
};

class MyClass {
  async *instanceMethod() { ... }
  static async *staticMethod() { ... }
}
```

**关键字组合的含义**：
- `async`：使函数成为异步函数，内部可以使用 `await`
- `*`（生成器）：使函数可以 `yield` 多个值
- `async function*`：两者结合——既可以 `await` 异步操作，又可以 `yield` 多个值

### 3.2 最简单的异步生成器示例

```javascript
// 每隔 1 秒产出一个数字
async function* delayedNumbers(start, end) {
  for (let i = start; i <= end; i++) {
    // 先等待 1 秒
    await new Promise(resolve => setTimeout(resolve, 1000));
    // 然后产出当前数字
    yield i;
  }
}

// 使用
(async () => {
  const gen = delayedNumbers(1, 5);
  
  for await (const num of gen) {
    console.log(`📦 收到: ${num}`);
  }
})();

/*
输出（每个间隔约 1 秒）:
📦 收到: 1
📦 收到: 2
📦 收到: 3
📦 收到: 4
📦 收到: 5
*/
```

### 3.3 异步生成器 vs 同步生成器 vs 普通 async 函数

这是一个非常重要的对照表，理解它能帮你建立完整的概念体系：

```javascript
// 类型1: 普通 async 函数 —— 只能返回一个 Promise（单个值）
async function singleValue() {
  const data = await fetch('/api/data');
  return data.json();  // 一个最终值
}

// 类型2: 同步生成器 function* —— 可以 yield 多个同步值
function* syncMultipleValues() {
  yield 1;      // 立即产出
  yield 2;      // 立即产出
  return 3;     // 最终值
}

// 类型3: 异步生成器 async function* —— 可以 yield/await 多个异步值
async function* asyncMultipleValues() {
  const a = await fetch('/api/a');  // 等待
  yield await a.json();            // 产出异步值
  
  const b = await fetch('/api/b');  // 再次等待
  yield await b.json();            // 产出另一个异步值
  
  return 'done';                   // 最终值
}
```

**详细对比**：

| 特性 | `async function` | `function*` | `async function*` |
|------|------------------|-------------|------------------|
| 能否使用 `await` | ✅ | ❌ | ✅ |
| 能否使用 `yield` | ❌ | ✅ | ✅ |
| 返回值 | `Promise<T>` | Generator 对象 | **AsyncGenerator 对象** |
| `next()` 返回 | N/A | `{value, done}` | **`Promise<{value, done}>`** |
| 遍历方式 | 直接调用 `.then()` | `for...of` | **`for await...of`** |
| 适用场景 | 单次异步操作 | 同步序列生成 | **异步数据流** |

### 3.4 异步生成器的 next() 行为详解

异步生成器的 `next()` 方法返回的是 **Promise**——这是与同步生成器最本质的区别：

```javascript
async function* demo() {
  console.log('启动...');
  const result = yield '第一步';
  console.log(`收到传入值: ${result}`);
  
  const result2 = yield '第二步';
  console.log(`收到第二个传入值: ${result2}`);
  
  return '完成';
}

const gen = demo();

// 第一次 next() 启动生成器
const p1 = gen.next();
console.log('p1:', p1);  // p1: Promise {<pending>}
// p1 是一个 Promise，不是直接的结果！

p1.then(result => {
  console.log('result1:', result);  // { value: '第一步', done: false }
  
  // 第二次 next() —— 可以传值进去
  const p2 = gen.next('来自外部的答案A');
  return p2;
}).then(result => {
  console.log('result2:', result);  // { value: '第二步', done: false }
  
  // 第三次 next()
  const p3 = gen.next('来自外部的答案B');
  return p3;
}).then(finalResult => {
  console.log('finalResult:', finalResult);  // { value: '完成', done: true }
});
```

**执行流程图示**：

```
gen.next()
  ↓
生成器执行到第一个 yield "第一步"
  ↓
返回 Promise（pending 状态）
  ↓  ← 你需要 .then() 或 await 这个 Promise
Promise resolved 为 { value: "第一步", done: false }
  ↓
gen.next("答案A")  ← 将 "答案A" 传给第一个 yield 表达式
  ↓
生成器继续执行，遇到 yield "第二步"
  ↓
返回新的 Promise
  ↓ ... 以此类推
```

### 3.5 通俗类比：带休息区的传送带

把三种函数类型比作三种不同的**工厂生产线**：

- **普通 async 函数 = 单件定制车间**：客户下一个订单（调用函数），车间开始制作。制作过程中可能需要等原材料送来（`await`），完成后交付一件成品（`return`），然后下班。每次只接一个订单。
- **同步生成器 = 高速流水线**：产品源源不断地从流水线上出来（`yield`），不需要等待任何东西。传送带不停运转，客户站在旁边一件件拿走产品（`for...of`）。速度极快但没有灵活性。
- **异步生成器 = 带休息区的智能流水线**：这是最灵活的模式。流水线每生产一件产品后会进入**休息区**等待（`await`），原材料到了再继续工作。产品完成后放到出货区（`yield`），通知客户来取（`Promise resolve`）。客户不需要一直守着，可以去做别的事，产品好了再去拿（`for await...of`）。

异步生成器结合了"等待能力"和"批量生产能力"，是处理异步数据流的最佳工具。

## 4. 实战应用场景

### 4.1 分页 API 数据流 —— 最经典的应用

异步迭代器最典型的用途就是**将分页逻辑封装成线性数据流**，让消费者完全不用关心分页细节：

```javascript
/**
 * 异步生成器: 自动处理分页，逐条 yield 每个 commit
 * 使用者完全不需要知道有多少页、如何翻页
 */
async function* fetchCommits(repo) {
  let url = `https://api.github.com/repos/${repo}/commits?per_page=100`;
  
  while (url) {
    console.log(`🌐 正在请求: ${url.slice(0, 50)}...`);
    
    const response = await fetch(url, {
      headers: { 'User-Agent': 'Learning-Script' }
    });
    
    // 解析当前页的 commits
    const commits = await response.json();
    
    // 从 Link header 中提取"下一页" URL
    // GitHub API 用 Link header 表示分页信息
    const linkHeader = response.headers.get('Link') || '';
    const nextMatch = linkHeader.match(/<([^>]+)>;\s*rel="next"/);
    url = nextMatch ? nextMatch[1] : null;  // 没有下一页了
    
    // 逐条 yield 当前页的每个 commit
    for (const commit of commits) {
      yield {
        author: commit.author?.login || 'unknown',
        message: commit.commit.message.split('\n')[0],  // 只取第一行
        date: commit.commit.author?.date,
        sha: commit.sha.slice(0, 7)
      };
    }
    
    // 礼貌性延迟，避免触发 GitHub API 速率限制
    if (url) {
      await new Promise(r => setTimeout(r, 300));
    }
  }
}

// ==================== 消费者代码 ====================

(async () => {
  let count = 0;
  
  // 看起来就像在遍历一个简单的数组！分页逻辑被完全隐藏了
  for await (const commit of fetchCommits('vuejs/vue')) {
    count++;
    console.log(`#${count} ${commit.sha} ${commit.author}: ${commit.message}`);
    
    // 随时可以停止，不需要"取消所有剩余请求"
    if (count >= 15) {
      console.log(`\n已获取 ${count} 条记录，停止`);
      break;
    }
  }
})();
```

**这段代码的美妙之处在于**：
- 生产者（`fetchCommits`）封装了所有分页复杂性：HTTP 请求、Link header 解析、错误重试、速率限制
- 消费者（`for await...of`）看到的是一个干净、线性的数据流
- 两者解耦——如果将来 API 改成了 cursor 分页而不是 page 分页，只需修改生产者

### 4.2 文件逐行读取

在 Node.js 环境中，异步迭代非常适合处理大文件的流式读取：

```javascript
import { createReadStream } from 'fs';
import { createInterface } from 'readline';
import { once } from 'events';

/**
 * 异步生成器: 逐行读取大文件
 * 内存友好: 不会一次性加载整个文件到内存
 */
async function* readLines(filePath) {
  const fileStream = createReadStream(filePath);
  const rl = createInterface({
    input: fileStream,
    crlfDelay: true  // 正确处理 \r\n 换行符
  });
  
  try {
    for await (const line of rl) {
      yield line.trim();  // 逐行产出，去掉首尾空白
    }
  } finally {
    rl.close();
    fileStream.destroy();
  }
}

// 使用: 统计日志文件中的错误数量

      errorCount++;
      errorLines.push(line.slice(0, 80));
      
      // 只保留最近 5 条
      if (errorLines.length > 5) errorLines.shift();
    }
  }
  
  console.log(`总共发现 ${errorCount} 个错误`);
  console.log('最近的错误:');
  errorLines.forEach(l => console.log(' ', l));
```

### 4.3 WebSocket 消息流

```javascript
/**
 * 异步生成器: 将 WebSocket 消息转换为可迭代的数据流
 */
async function* websocketMessageStream(url) {
  return new Promise((resolve, reject) => {
    const ws = new WebSocket(url);
    const messageQueue = [];
    let resolver = null;
    
    ws.onmessage = (event) => {
      try {
        const data = JSON.parse(event.data);
        if (resolver) {
          resolver({ value: data, done: false });
          resolver = null;
        } else {
          messageQueue.push(data);
        }
      } catch (e) {
        // 忽略非 JSON 消息或处理错误
      }
    };
    
    ws.onerror = (error) => reject(error);
    ws.onclose = () => {
      if (resolver) {
        resolver({ done: true });
      } else {
        // 将结束信号放入队列
        messageQueue.push('__CLOSE__');
      }
    };
    
    // 创建异步迭代器
    const asyncIterator = {
      async next() {
        if (messageQueue.length > 0) {
          const msg = messageQueue.shift();
          if (msg === '__CLOSE__') return { done: true };
          return { value: msg, done: false };
        }
        
        return new Promise(r => { resolver = r; });
      },
      
      async return() {
        ws.close(1000, 'Consumer ended iteration');
        return { done: true };
      }
    };
    
    resolve(asyncIterator);
  }).then(iterator => ({
    [Symbol.asyncIterator]() { return iterator; }
  }));
}

// 使用
(async () => {
  const stream = await websocketMessageStream('wss://example.com/realtime');
  
  for await (const msg of stream) {
    console.log('收到消息:', msg.type, msg.payload);
    
    if (msg.type === 'shutdown') {
      console.log('服务器关闭，退出监听');
      break;
    }
  }
})();
```

### 4.5 并发控制的异步队列

```javascript
/**
 * 异步生成器: 带并发限制的任务队列
 * 同时最多运行 N 个任务，但保持结果的有序输出
 */
async function* concurrentQueue(tasks, maxConcurrency = 3) {
  const executing = new Set();
  
  for (const task of tasks) {
    // 创建任务的 Promise（但不立即 await）
    const taskPromise = executeTask(task).then(result => {
      executing.delete(taskPromise);  // 完成后移除
      return result;
    });
    
    executing.add(taskPromise);
    yield { status: 'started', task };
    
    // 如果达到并发上限，等待任意一个完成
    if (executing.size >= maxConcurrency) {
      // 等待最快的那个任务完成
      const completed = await Promise.race(executing);
      yield { status: 'completed', result: completed };
    }
  }
  
  // 等待所有剩余任务完成
  while (executing.size > 0) {
    const completed = await Promise.race(executing);
    yield { status: 'completed', result: completed };
  }
}

function executeTask(task) {
  const duration = Math.random() * 2000 + 500;
  return new Promise(resolve => {
    setTimeout(() => {
      resolve(`${task} (${duration.toFixed(0)}ms)`);
    }, duration);
  });
}

// 使用
(async () => {
  const tasks = ['task-A', 'task-B', 'task-C', 'task-D', 'task-E', 'task-F'];
  
  for await (const event of concurrentQueue(tasks, 2)) {
    console.log(event.status === 'started' 
      ? `▶️  开始: ${event.task}` 
      : `✅ 完成: ${event.result}`
    );
  }
})();
```

## 5. 高级特性与深入理解

### 5.1 yield* 在异步生成器中的委托

异步生成器中的 `yield*` 可以委托给另一个**异步可迭代对象**（包括另一个异步生成器或普通可迭代对象）：

```javascript
// 子异步生成器: 获取用户详细信息
async function* fetchUserDetails(userId) {
  const profile = await fetch(`/api/users/${userId}`).then(r => r.json());
  yield { type: 'profile', data: profile };
  
  const posts = await fetch(`/api/users/${userId}/posts`).then(r => r.json());
  yield { type: 'posts', data: posts };
}

// 主异步生成器: 组合多个子生成器
async function* fullUserReport(userIds) {
  for (const id of userIds) {
    yield { type: 'header', message: `=== 用户 #${id} ===` };
    
    // 使用 yield* 委托给子生成器
    yield* fetchUserDetails(id);
    
    yield { type: 'footer', message: `--- 用户 #${id} 结束 ---` };
  }
}

(async () => {
  for await (const item of fullUserReport([101, 102])) {
    switch (item.type) {
      case 'header':
        console.log(item.message);
        break;
      case 'profile':
        console.log('  👤', item.data.name, `<${item.data.email}>`);
        break;
      case 'posts':
        console.log('  📝', item.data.length, '篇文章');
        break;
      case 'footer':
        console.log(item.message);
        console.log('');
        break;
    }
  }
})();
```

**`yield*` 在异步生成器中的特殊行为**：当 `yield*` 委托的对象是**同步可迭代对象**时，异步生成器会自动将其每个值包装为 Promise 后再 yield：

```javascript
async function* mixedYieldStar() {
  // 委托给同步可迭代对象 —— 每个值会被自动包装
  yield* [1, 2, 3];  // 相当于: yield 1; yield 2; yield 3;
  
  // 委托给异步可迭代对象
  yield* anotherAsyncGenerator();
  
  // 委托给字符串（同步可迭代对象）
  yield* "hello";  // 逐字符产出: 'h','e','l','l','o'
}
```

### 5.2 错误处理与恢复

异步生成器中的错误处理遵循与普通 async 函数相同的原则，但有一些额外的考虑：

```javascript
/**
 * 带重试机制的异步生成器
 * 自动重试失败的操作，最多尝试指定次数
 */
async function* withRetry(asyncIterable, maxRetries = 3) {
  let retryCount = 0;
  
  for await (const item of asyncIterable) {
    retryCount = 0;
    let success = false;
    
    while (!success && retryCount <= maxRetries) {
      try {
        // 尝试处理项目（可能是异步操作）
        const processed = await processItem(item);
        success = true;
        yield processed;  // 处理成功后才产出
      } catch (error) {
        retryCount++;
        console.warn(`⚠️ 处理失败 (第${retryCount}/${maxRetries}次): ${error.message}`);
        
        if (retryCount <= maxRetries) {
          // 指数退避等待
          const delay = Math.pow(2, retryCount) * 1000;
          console.log(`   ⏳ 等待 ${delay}ms 后重试...`);
          await new Promise(r => setTimeout(r, delay));
        } else {
          console.error(`❌ 放弃该项目:`, error.message);
          yield { error: true, original: item, reason: error.message };
        }
      }
    }
  }
}

// 模拟处理函数（随机失败）
async function processItem(item) {
  await new Promise(r => setTimeout(r, 200));  // 模拟耗时
  if (Math.random() < 0.4) throw new Error(`随机失败: ${item}`);
  return `${item}-processed`;
}

// 测试
(async () => {
  const items = ['alpha', 'beta', 'gamma', 'delta', 'epsilon'];
  
  for await (const result of withRetry(items)) {
    if (result.error) {
      console.log(`  💀 失败项: ${result.original}`);
    } else {
      console.log(`  ✅ 成功: ${result}`);
    }
  }
})();
```

### 5.4 无限异步数据流

```javascript
/**
 * 无限的事件时间戳流
 * 每秒产出一个包含当前时间的对象
 */
async function* timestampStream(intervalMs = 1000) {
  let tick = 0;
  while (true) {
    tick++;
    yield {
      tick,
      timestamp: new Date().toISOString(),
      uptime: `${Math.floor(tick * intervalMs / 1000)}s`
    };
    
    await new Promise(r => setTimeout(r, intervalMs));
  }
}

// 配合 take 操作安全地消费无限流
async function* take(iterable, count) {
  let taken = 0;
  for await (const value of iterable) {
    if (taken >= count) break;
    yield value;
    taken++;
  }
}

// 使用: 获取前5个时间戳
(async () => {
  for await (const ts of take(timestampStream(), 5)) {

  }
  console.log('采样完成');
})();

    yield Math.floor(Math.random() * (max - min + 1)) + min;
```

### 5.5 异步生成器与 async/await 的关系

理解异步生成器与 `async/await` 的关系有助于建立完整的知识体系：

**历史演进路线**：

```
ES6 (2015)
  └─ 生成器 (function*) + Promise
       └─ 社区发明 "generator runner" 模式
            └─ 证明 "看似同步的异步代码" 可行

ES7/ES8 (2016-2017)
  └─ async/await 语法糖正式化
       └─ 解决了大多数"单次异步操作"场景

ES2018
  └─ 异步迭代器 + 异步生成器 (async function*)
       └─ 解决了"多次异步操作 / 异步数据流"场景
```

**本质上**：
- `async/await` = 让**单个异步操作**看起来像同步代码
- `async function*` + `for await...of` = 让**一系列异步操作的流**看起来像同步迭代

前者解决了"一步到位"的问题，后者解决了"步步为营"的问题。两者互补，共同构成了现代 JavaScript 异步编程的完整工具集。

### 5.6 通俗类比：智能物流系统

把整个异步迭代体系想象成一个**现代化的智能物流配送系统**：

**`async function`（普通异步函数）= 单件快递**：
客户下一个订单，快递员出发去送货。路上可能遇到堵车（`await`），但最终只送这一件货物。送完就回来了。

**`function*`（同步生成器）= 工厂直发专线**：
仓库有一条专用传送带，产品源源不断地从传送带上出来。快递员就在传送带末端等着，来一件拿一件。没有等待时间，但也不能控制节奏。

**`async function*`（异步生成器）= 智能调度中心**：
这是最强大的模式。调度中心连接着多个供应商（各种异步数据源），每个供应商供货速度不同。调度中心统一接收订单后：
1. 向供应商 A 下单，然后**等待**到货（`await`）
2. 货到了就打包发货给客户（`yield`）
3. 同时向供应商 B 下单（并行）
4. B 的货到了再打包发给客户（`yield`）
5. 如果某个供应商缺货（异常），自动联系备用供应商（错误处理）

**`for await...of` = 客户的收货地址**：
客户只需要坐在家里等就行了（`for await...of` 循环），每次门铃响了就去开门收货（循环体）。不管背后有多复杂，客户看到的就是一个简单的过程：等、收、等、收……如果不想再收了，打个电话取消后续配送（`break`）。

```javascript
// service-worker.js
self.addEventListener('install', (event) => {
```

## 8. 性能与注意事项

### 8.1 异步迭代的性能考量

**优势**：
- **内存效率**：不需要一次性将所有数据加载到内存。对于大文件、大量分页数据尤其明显
- **响应性**：可以先处理已到的数据，不必等待全部完成
- **可中断性**：随时可以通过 `break` 停止，不会浪费未请求数据的网络传输

**需要注意的点**：

```javascript
// ❌ 低效: 不必要的串行化
async function* inefficient(items) {
  for (const item of items) {
    const result = await slowOperation(item);  // 等待每一个
    yield result;
  }
}

// ✅ 更高效: 并行预取（在合理范围内）
async function* efficientWithPrefetch(items, prefetchWindow = 2) {
  const queue = [];
  
  // 初始预取
  for (let i = 0; i < Math.min(prefetchWindow, items.length); i++) {
    queue.push(slowOperation(items[i]).catch(e => ({ error: e.message, item: items[i] })));
  }
  
  let index = prefetchWindow;
  
  while (queue.length > 0 || index < items.length) {
    // 取出最早的一个（FIFO）
    const result = await queue.shift();
    yield result;
    
    // 补充一个新的到队列末尾
    if (index < items.length) {
      queue.push(slowOperation(items[index]));
      index++;
    }
  }
}
```

### 8.2 常见陷阱

#### 陷阱1: 忘记 for await...of 必须在 async 函数内

```javascript
// ❌ 错误: for await 不能在顶层作用域使用（除非模块支持顶层 await）
function processData(stream) {
  for await (const chunk of stream) {  // SyntaxError in non-async context
    console.log(chunk);
  }
}

// ✅ 正确: 包装在 async 函数中
async function processData(stream) {
  for await (const chunk of stream) {
    console.log(chunk);
  }
}

// 或者使用立即执行的 async IIFE
(function() {
  // ...
})()
```

#### 陷阱2: 混淆 for...of 和 for await...of

```javascript
async function* numbers() {
  yield 1;
  yield Promise.resolve(2);  // 即使 yield 的是 Promise
  yield 3;
}

const gen = numbers();

// ❌ for...of 不会 await 内部的 Promise
for (const n of gen) {
  console.log(n);
  // 输出: 1, Promise{<resolved>: 2}, 3
  // 第二个是 Promise 对象本身，不是 2！
}

// ✅ for await...of 会正确 await 每个 yield 出来的值
const gen2 = numbers();
for await (const n of gen2) {
  console.log(n);
  // 输出: 1, 2, 3 —— 全部都是解析后的值
}
```

#### 陷阱3: 展开运算符不适用于异步可迭代对象

```javascript
async function* asyncVals() {
  yield 1;
  yield 2;
  yield 3;
}

// ❌ 错误: 展开运算符不支持异步可迭代对象
const arr = [...asyncVals()];  // TypeError!

// ✅ 解决方案1: 使用 for await...of 收集
const arr1 = [];
for await (const v of asyncVals()) arr1.push(v);

// ✅ 解决方案2: 使用 Array.fromAsync（较新的 API）
const arr2 = await Array.fromAsync(asyncVals());
```

#### 陷阱4: 忽略异步迭代的顺序保证

异步迭代器**严格保证**值的产出顺序与代码中的 `yield` 顺序一致，即使某些操作先完成：

```javascript
async function* orderedResults() {
  // 虽然 C 的请求可能最先完成，但产出顺序仍然是 A → B → C
  console.log('发起请求 A...');
  yield fetch('/api/A').then(r => r.json());  // 可能最慢
  
  console.log('发起请求 B...');
  yield fetch('/api/B').then(r => r.json());
  
  console.log('发起请求 C...');
  yield fetch('/api/C').then(r => r.json());  // 可能最快
}

(async () => {
  for await (const result of orderedResults()) {
    console.log('收到:', result.id);
  }
  // 输出顺序一定是 A → B → C，不取决于谁先返回
})();
```

如果你需要"谁先完成就先产出"的顺序，需要额外的并发管理逻辑（参见前面的 `concurrentQueue` 示例）。

### 8.3 最佳实践清单

#### ✅ 推荐做法

```javascript
// 1. 用异步迭代器封装分页/流式 API，隐藏复杂性
async function* paginatedApi(baseUrl, params = {}) {
  let nextPageToken = null;
  
  do {
    const url = buildUrl(baseUrl, { ...params, pageToken: nextPageToken });
    const response = await fetch(url);
    const data = await response.json();
    
    nextPageToken = data.nextPageToken || null;
    
    for (const item of data.items) {
      yield transformItem(item);
    }
  } while (nextPageToken);
}

// 2. 在 finally 中确保资源清理
async function* withCleanup(resource) {
  try {
    yield* processResource(resource);
  } finally {
    await resource.close();
  }
}

// 3. 合理设置并发限制，避免过载
async function* rateLimited(iterable, intervalMs) {
  for await (const item of iterable) {
    yield item;
    await sleep(intervalMs);  // 限速
  }
}

// 4. 使用 take 等工具函数安全消费无限流
async function* take(iterable, limit) {
  let count = 0;
  for await (const value of iterable) {
    if (count++ >= limit) return;
    yield value;
  }
}

// 5. 提供清晰的错误信息和恢复策略
async function* resilient(iterable, options = {}) {
  const { retries = 3, backoffMs = 1000 } = options;
  
  for await (const item of iterable) {
    let attempt = 0;
    while (attempt <= retries) {
      try {
        yield await process(item);
        break;  // 成功就跳出重试循环
      } catch (err) {
        attempt++;
        if (attempt > retries) {
          yield { __error__: err, __original__: item };
          break;
        }
        await sleep(backoffMs * Math.pow(2, attempt - 1));
      }
    }
  }
}
```

#### ❌ 应避免的做法

```javascript
// 1. 不要在异步生成器中进行重量级的同步计算
// 这会阻塞事件循环
async function* blockingGen(data) {
  for (const item of data) {
    heavySyncComputation(item);  // ❌ 阻塞！
    yield result;
  }
}

// 2. 不要忽略 break 时的资源清理需求
async function* withoutCleanup() {
  const conn = db.connect();
  yield* queryData(conn);
  // ❌ 如果消费者 break 了，conn 不会被关闭！
  // 应该用 try...finally 包裹
}

// 3. 不要过度嵌套 yield*
// 保持扁平化，必要时提取为独立函数
async function* deeplyNested() {
  yield* (
    async function* () {
      yield* (
        async function* () {  // 过于深层
          yield* innerMost();
        }()
      );
    }()
  );
}
```

## 9. 总结

### 9.1 核心知识点对照

| 概念 | 同步版 | 异步版 |
|------|--------|--------|
| 迭代器符号 | `Symbol.iterator` | **`Symbol.asyncIterator`** |
| `next()` 返回 | `{value, done}` | **`Promise<{value, done}>`** |
| 循环语法 | `for (x of iter)` | **`for await (x of asyncIter)`** |
| 生成器声明 | `function*` {} | **`async function*` {} |
| 生成器内可用 | `yield`, `return` | **`yield`, `await`, `return`** |
| `gen.next()` 返回 | `{value, done}` | **`Promise<{value, done}>`** |
| 展开运算符 | `[...iter]` ✅ | `[...asyncIter]` ❌ |
| `Array.from` | `Array.from(iter)` ✅ | `Array.from(asyncIter)` ❌ (用 `Array.fromAsync`) |

### 9.2 一句话总结

> **异步生成器 (`async function*`) 和异步迭代 (`for await...of`) 是 JavaScript 异步编程体系的"最后一块拼图"。如果说 `async/await` 解决了"单次异步操作"的表达问题，那么异步迭代解决的就是**"异步数据流的顺序表达"**问题。它们将 `await`（等待异步操作）和 `yield`（逐步产出多个值）融为一体，让分页加载、流式读取、消息推送等复杂场景的代码变得像遍历数组一样简洁直观。
