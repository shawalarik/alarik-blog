# 并发控制 —— Promise.all、Promise.race、并发限制（p-limit）、串行/并行队列

> **核心内容**：在异步编程中，"让代码跑通"只是第一步。当你的应用需要同时处理数十个网络请求、管理多个定时任务、协调不同速率的数据源时，"并发控制"就成为了决定系统生死的关键能力。JavaScript 是单线程的，但这并不意味着它不能做并发——通过事件循环和 Promise 的巧妙组合，我们可以精确地控制多个异步操作的执行策略：是全部同时出发？还是排队一个接一个？还是允许最多 N 个同时跑？这些选择直接影响着用户体验、服务器压力、内存占用乃至系统的稳定性。本文将从底层原理到工业级实现，全面剖析 JavaScript 并发控制的完整图景。

---

## 一、并发的本质 —— 单线程中的"伪并行"

### 1.1 JavaScript 的单线程现实

首先需要明确一个基本事实：**JavaScript 引擎只有一个主线程**。在同一时刻，只能有一段 JavaScript 代码在执行。这与 Java、Go 等多线程语言有本质区别。

```javascript
// 无论你怎么写，JS 永远不会真正"并行"执行两个函数
function heavyTask(name, duration) {
  const start = Date.now();
  while (Date.now() - start < duration) {
    // CPU 密集型计算 —— 会完全阻塞主线程
  }
  console.log(`${name} 完成`);
}

// 这两个任务不可能同时进行
heavyTask('A', 2000);  // 先跑 A，耗时 2 秒
heavyTask('B', 1000);  // A 结束后才能跑 B
// 总耗时: 3 秒（串行），不是 2 秒
```

**那为什么我们常说 JS 支持"并发"？**

关键在于：**I/O 操作不会阻塞主线程**。当你发起 `fetch`、`setTimeout` 或文件读取时，实际的工作被交给浏览器或 Node.js 的底层 C++ 线程池去处理了。JS 主线程继续往下走，等 I/O 完成后通过回调/Promise 把结果送回来。

这就是 **"基于事件循环的协作式并发"（Cooperative Concurrency via Event Loop）**——不是真正的多线程并行，而是通过"发起-等待-回调"的模式，在等待期间切换去处理其他事情。

### 1.2 同步执行 vs 异步并发

让我们用一个最简单的例子来对比：

```javascript
// ====== 场景：获取3个用户的信息 ======

// ❌ 方式一：同步串行（总耗时 = 所有操作时间之和）
async function serialFetch() {
  const t0 = performance.now();
  
  const u1 = await fetch('/api/users/1').then(r => r.json());  // 等 300ms
  const u2 = await fetch('/api/users/2').then(r => r.json());  // 等 300ms
  const u3 = await fetch('/api/users/3').then(r => r.json());  // 等 300ms
  
  console.log(`串行耗时: ${(performance.now() - t0).toFixed(0)}ms`);
  return [u1, u2, u3];
}
// 预期耗时: ~900ms（300 + 300 + 300）

// ✅ 方式二：异步并发（总耗时 = 最慢的那个操作的耗时）
async function concurrentFetch() {
  const t0 = performance.now();
  
  // 三个请求几乎同时发出！
  const [u1, u2, u3] = await Promise.all([
    fetch('/api/users/1').then(r => r.json()),  // ~300ms
    fetch('/api/users/2').then(r => r.json()),  // ~300ms
    fetch('/api/users/3').then(r => r.json())   // ~300ms
  ]);
  
  console.log(`并发耗时: ${(performance.now() - t0).toFixed(0)}ms`);
  return [u1, u2, u3];
}
// 预期耗时: ~300ms（三者中最慢的一个）
```

**速度提升：3 倍！** 这就是并发控制的价值所在。

### 1.3 理论深入：为什么 I/O 可以"并行"

理解这个问题的关键在于区分两种类型的操作：

| 操作类型 | 特征 | 是否阻塞主线程 | 能否并发 |
|---------|------|--------------|---------|
| **CPU 密集型** | 大量计算（加密、排序、渲染） | ✅ 阻塞 | ❌ 不能 |
| **I/O 密集型** | 网络/磁盘/数据库请求 | ❌ 不阻塞（委托给工作线程） | ✅ 可以 |

```javascript
// CPU 操作 —— 无法并发优化
const result1 = heavyComputation(data1);   // 必须等它完成
const result2 = heavyComputation(data2);   // 才能开始下一个

// I/O 操作 —— 天然适合并发
const promise1 = fetch(url1);  // 发出请求后立即返回 Promise
const promise2 = fetch(url2);  // 不用等第一个完成！立即发第二个
const promise3 = fetch(url3);  // 同理

// 三个请求在网络层并行传输
const [r1, r2, r3] = await Promise.all([promise1, promise2, promise3]);
```

**通俗类比：厨房里的厨师 vs 外卖员**

把 JavaScript 主线程想象成一位**厨师**：
- **CPU 密集型操作** = 厨师亲自切菜、炒菜——同一时间只能做一件事
- **I/O 操作** = 厨师点外卖（网络请求）、叫快递（文件读取）——点完之后不用干等着，可以去做别的事

并发控制的核心就是：**让这位厨师尽可能多地点外卖（发起 I/O），而不是傻等一份外卖送到才点下一份。**

## 二、基础并发模式 —— Promise 静态方法全解

ES6 为 Promise 提供了一系列静态方法来处理常见的并发场景。它们是并发控制的基石。

### 2.1 Promise.all —— "全部完成才算成功"

**语义**：传入一个可迭代的 Promise 数组，等待**所有** Promise 都 resolve 后返回所有结果数组；如果**任意一个** reject，整个 `Promise.all()` 立即 reject。

```javascript
/**
 * Promise.all 核心行为演示
 */

// 基础示例
Promise.all([
  new Promise(r => setTimeout(() => r(1), 3000)),  // 3秒后完成
  new Promise(r => setTimeout(() => r(2), 2000)),  // 2秒后完成
  new Promise(r => setTimeout(() => r(3), 1000))   // 1秒后完成
]).then(console.log);
// 输出: [1, 2, 3] （注意：顺序与输入一致！不管谁先完成）

// 实战：并行获取多个用户数据
async function fetchUsers(usernames) {
  const requests = usernames.map(name =>
    fetch(`https://api.github.com/users/${name}`)
      .then(res => res.json())
  );
  
  // 所有请求同时发出，等最慢的完成后统一返回
  const users = await Promise.all(requests);
  return users;  // 数组顺序与 usernames 一致
}

fetchUsers(['iliakan', 'remy', 'jeresig'])
  .then(users => users.forEach(u => console.log(u.name)));
```

**关键特性详解**：

```javascript
// ① 结果顺序保持性
const promises = [
  slowRequest('A'),  // 可能5秒完成
  fastRequest('B'),  // 可能1秒完成
  mediumRequest('C') // 可能3秒完成
];

const results = await Promise.all(promises);
console.log(results[0]); // ← 一定是 'A' 的结果（不是 'B'！）
console.log(results[1]); // ← 一定是 'B' 的结果
// 结果数组的位置对应原始 Promise 的位置，而非完成顺序

// ② 快速失败（Fail-Fast）特性
Promise.all([
  Promise.resolve('OK'),
  Promise.reject(new Error('失败!')),  // 第二个就失败了
  Promise.resolve('永远不会到达')     // 这个被忽略了
]).catch(err => {
  console.error(err.message);  // '失败!'
  // 注意: 第三个 Promise 可能还在运行（资源浪费问题！）
});

// ③ 空数组的行为
await Promise.all([]);           // → [] （立即 resolve）
await Promise.all([1, 2, 3]);   // → [1, 2, 3]（非 Promise 值会自动包装）
```

### 2.2 Promise.allSettled —— "尽力而为，全部报告"

**语义**：等待**所有** Promise 都结束（无论成功还是失败），返回每个 Promise 的最终状态对象。**不会因为某个失败而中断。**

这是 ES2020 新增的方法，解决了 `Promise.all` "快速失败"过于激进的痛点：

```javascript
/**
 * Promise.allSettled —— 更温和的并发策略
 */

// 对比: all vs allSettled 在面对部分失败时的行为差异

const urls = [
  'https://api.example.com/users',     // 正常
  'https://api.example.com/posts',     // 正常
  'https://non-existent-api.test',      // 失败!
  'https://api.example.com/comments'    // 正常
];

// ❌ Promise.all: 一个失败，全军覆没
try {
  const results = await Promise.all(urls.map(u => fetch(u)));
  console.log(results.length);  // 不会到这里
} catch (err) {
  console.error('任何错误都导致整体失败:', err.message);
}

// ✅ Promise.allSettled: 逐个报告每个结果
const settledResults = await Promise.allSettled(
  urls.map(url => fetch(url))
);

settledResults.forEach((result, i) => {
  if (result.status === 'fulfilled') {
    console.log(`✅ ${urls[i]}: HTTP ${result.value.status}`);
  } else {
    console.warn(`❌ ${urls[i]}: ${result.reason.message}`);
  }
});

/*
输出:
✅ https://api.example.com/users: HTTP 200
✅ https://api.example.com/posts: HTTP 200
❌ https://non-existent-api.test: Failed to fetch
✅ https://api.example.com/comments: HTTP 200
全部4个结果都能看到！
*/

// 返回值结构
/*
[
  { status: 'fulfilled', value: Response },
  { status: 'fulfilled', value: Response },
  { status: 'rejected', reason: Error },
  { status: 'fulfilled', value: Response }
]
*/
```

**典型应用场景**：
- 批量上传文件：即使部分失败也要知道哪些成功了
- 多源数据聚合：从多个 API 获取数据，某些源不可用时降级处理
- 表单批量验证：逐个字段校验，收集所有错误一次性展示

### 2.3 Promise.race —— "谁快听谁的"

**语义**：传入一组 Promise，返回**第一个 settle（完成或拒绝）**的结果。其他 Promise 继续运行但结果被忽略。

```javascript
/**
 * Promise.race —— 竞速模式
 */

// 最经典的应用: 超时控制
function fetchWithTimeout(url, timeoutMs) {
  return Promise.race([
    fetch(url),
    new Promise((_, reject) =>
      setTimeout(() => reject(new Error(`超时 (${timeoutMs}ms)`)), timeoutMs)
    )
  ]);
}

fetchWithTimeout('/api/slow-endpoint', 5000)
  .then(r => r.json())
  .then(data => console.log('✅ 数据:', data))
  .catch(err => {
    if (err.message.includes('超时')) {
      console.log('⏰ 请求超时');
    } else {
      console.error('❌ 其他错误:', err.message);
    }
  });

// 另一个场景: 多源竞速（取最快响应的结果）
function fetchFromFastestMirror(mirrors) {
  return Promise.race(
    mirrors.map(url => fetch(url).then(r => r.json()))
  );
}

// 从多个镜像服务器取数据，哪个先返回就用哪个
const data = await fetchFromFastestMirror([
  'https://mirror1.api.com/data',
  'https://mirror2.api.com/data',
  'https://mirror3.api.com/data'
]);
console.log('来自最快的镜像的数据:', data);
```

**重要细节**：

```javascript
// ① "已拒绝"也会赢
Promise.race([
  new Promise((_, rej) => setTimeout(() => rej('快速失败'), 100)),
  new Promise(res => setTimeout(() => res('慢速成功'), 5000))
]).then(
  val => console.log('成功:', val),
  err => console.log('失败:', err)  // 输出: 失败: 快速失败
);

// ② 未被选中的 Promise 不会被取消
const slow = new Promise(res => setTimeout(() => {
  console.log('慢的那个也完成了（但结果没人管）');
  res('ignored');
}, 2000));

const fast = Promise.resolve('winner');

Promise.race([slow, fast])
  .then(result => console.log('胜出者:', result));  // winner
// 2秒后会打印 "慢的那个也完成了（但结果没人管）"
```

### 2.4 Promise.any —— "只要有一个成功就行"

**语义**：等待**第一个 fulfilled（成功）** 的 Promise。忽略失败的，直到遇到成功的为止。如果**全部失败**，返回 `AggregateError`（聚合错误）。

ES2021 新增，与 `race` 的核心区别在于对"失败"的态度：

```javascript
/**
 * Promise.any —— 乐观竞速
 * 与 race 的对比:
 *   race: 第一个结束的就赢（不管成败）
 *   any:  第一个**成功的**才赢（失败的被忽略）
 */

// 场景: CDN 多节点容错 —— 只要有一个节点能访问就行
const cdnUrls = [
  'https://cdn1.example.com/config.json',
  'https://cdn2.example.com/config.json',
  'https://cdn3.example.com/config.json',
  'https://cdn4.example.com/config.json'
];

try {
  const config = await Promise.any(
    cdnUrls.map(url =>
      fetch(url)
        .then(r => {
          if (!r.ok) throw new Error(`HTTP ${r.status}`);
          return r.json();
        })
    )
  );
  console.log('✅ 从以下CDN获取到配置:', config.source);
} catch (aggregateError) {
  // 全部失败时的特殊错误类型
  console.error('❌ 所有CDN节点均不可用:');
  console.error('错误详情:', aggregateError.errors);
  /*
  AggregateError [
    Error: Failed to fetch (cdn1),
    Error: Failed to fetch (cdn2),
    Error: Failed to fetch (cdn3),
    Error: Failed to fetch (cdn4)
  ]
  */
}
```

**四种方法的决策树**：

```
我有多个 Promise 需要处理...
│
├── 我需要所有结果？
│   ├── 是的，任何一个失败都不能接受
│   │   └── 🎯 Promise.all（门模式）
│   │
│   └── 我要知道每个的成功/失败状态
│       └── 🎯 Promise.allSettled（尽力而为）
│
├── 我只需要一个结果？
│   ├── 谁先完成都行（成功或失败）
│   │   └── 🎯 Promise.race（竞速/超时）
│   │
│   └── 我要第一个**成功的**
│       └── 🎯 Promise.any（容错/多源备选）
│
└── 我已经有一个值，想包装成 Promise？
    └── 🎯 Promise.resolve / Promise.reject
```

## 三、串行执行模式 —— 控制流的艺术

并非所有场景都需要并发。有时候你必须按顺序执行异步操作——比如第二个请求依赖第一个的结果，或者操作之间有严格的先后关系。

### 3.1 for...of + await —— 最直观的串行

```javascript
/**
 * 方式一: for 循环中逐个 await（推荐，代码清晰）
 */
async function processUsersSequentially(userIds) {
  const results = [];
  
  for (const id of userIds) {        // 一个接一个
    const user = await fetchUser(id);  // 等当前完成
    results.push(user);                // 再处理下一个
    
    console.log(`处理完成: ${user.name}`);
  }
  
  return results;
}

// 执行流程:
// fetch(1) → 完成 → fetch(2) → 完成 → fetch(3) → 完成
// 总耗时 = sum(all individual times)

processUsersSequentially([1, 2, 3]);
```

### 3.2 Array.reduce 串联 —— 函数式的优雅写法

```javascript
/**
 * 方式二: reduce 构建串行 Promise 链
 */
async function processWithReduce(items) {
  const results = await items.reduce(async (accPromise, item) => {
    const acc = await accPromise;         // 等待前一步完成
    const result = await processData(item); // 处理当前项
    return [...acc, result];               // 累加结果
  }, Promise.resolve([]));                 // 初始值: 空 Promise
  
  return results;
}

// 等价于:
// Promise.resolve([])
//   .then(acc => [...acc, await fn(items[0])])
//   .then(acc => [...acc, await fn(items[1])])
//   .then(acc => [...acc, await fn(items[2])])
```

### 3.3 递归串行 —— 适用于动态长度

```javascript
/**
 * 方式三: 递归方式（适合条件驱动的序列）
 */
async function processRecursively(items, index = 0, results = []) {
  if (index >= items.length) return results;  // 基准情况
  
  try {
    const result = await handleItem(items[index]);
    return processRecursively(items, index + 1, [...results, result]);
  } catch (error) {
    // 可选: 错误时决定是否继续
    console.warn(`第 ${index + 1} 项失败: ${error.message}, 跳过`);
    return processRecursively(items, index + 1, [...results, null]);
  }
}
```

### 3.4 何时必须串行？

```javascript
// ✅ 必须串行的场景: 后续操作依赖前面的结果
async function buildReport(userId) {
  const user = await fetchUser(userId);              // 步骤1: 获取用户
  const posts = await fetchUserPosts(user.id);      // 步骤2: 用用户ID获取文章
  const comments = await fetchPostComments(posts[0].id); // 步骤3: 用文章ID获取评论
  // 每一步都依赖上一步的结果，无法并行
  return { user, posts, comments };
}

// ✅ 必须串行的场景: 有严格的顺序要求
async function deployInOrder(services) {
  for (const service of services) {
    console.log(`部署: ${service}`);
    await deployService(service);     // 等当前服务部署完成
    await healthCheck(service);       // 确认健康后才部署下一个
    console.log(`${service} 就绪 ✓\n`);
  }
  console.log('全部部署完成!');
}

// ⚠️ 可以改为并发的场景（但要注意顺序保证）
async function fetchAllPages(startUrl) {
  let url = startUrl;
  const allData = [];
  
  while (url) {
    const response = await fetch(url);     // 当前页必须等上一页拿到 nextUrl
    const data = await response.json();
    allData.push(...data.items);
    url = data.nextPageUrl;             // 下一页 URL 从当前响应中获取
  }
  
  return allData;
}
```

### 3.5 通俗类比：流水线 vs 批量发货

**串行执行 = 工厂流水线**：
产品必须经过一道工序后才能进入下一道工序。原材料进入→切割→打磨→喷漆→质检→打包，每一步都必须等上一步完成。你不能在还没切割的时候就拿去喷漆。

**并发执行 = 批量发货**：
你有10个包裹要寄往同一个地方，你一次叫10个快递员（或者一辆大货车）全部拉走。不需要等第一个寄到了才发第二个——它们在路上是同时运输的。

选择哪种模式取决于你的业务逻辑：**后面的步骤是否依赖前面步骤的结果**？

## 四、并发限制（Concurrency Limiting）—— p-limit 模式

### 4.1 为什么需要限制并发数？

你可能认为："既然并发更快，为什么不把所有操作都一起发出去？"

答案是：**无限制的并发会带来灾难性的后果。**

```javascript
// ❌ 危险: 无限制并发
async function dangerousConcurrent(filePaths) {
  // 假设有 10,000 个文件要上传
  const promises = filePaths.map(path => uploadToS3(path));
  
  // 10,000 个请求同时发出！
  await Promise.all(promises);
}

// 后果:
// 1. 浏览器/Node.js 同时维护 10,000 个 HTTP 连接 → 内存爆炸 💥
// 2. 服务器瞬间收到 10,000 个请求 → 被限流/DOS防护拦截 🚫
// 3. 带宽被占满 → 其他正常的请求也变慢 🐌
// 4. 文件句柄耗尽 → 打开新文件报错 ⚠️
```

**理论要点**：根据**小定律（Little's Law）**，系统中平均请求数 = 请求到达率 × 平均处理时间。当并发数超过系统的处理容量时，排队时间会指数级增长，最终导致系统雪崩。

### 4.2 p-limit 核心思想

**p-limit（Parallelism Limit）** 的核心思想是：**维持一个固定大小的"活跃任务池"，任何时候只有 N 个任务在执行，其余的任务排队等待。每当有一个任务完成，就从队列中取出下一个补充进来。**

N 就是**并发上限（concurrency limit）**。

```javascript
/**
 * p-limit 基础实现
 * @param {Iterable|Array} tasks     任务列表（每个元素是返回 Promise 的函数）
 * @param {number} concurrency 最大并发数
 * @returns {Promise<Array>}        所有任务的返回值数组
 */
async function pLimit(tasks, concurrency = 5) {
  const results = [];
  const executing = new Set();       // 正在执行的任务集合
  const queue = [...tasks];         // 待执行队列（浅拷贝）
  
  return new Promise((resolve, reject) => {
    // 尝试启动下一个任务（如果有空位且还有待办任务的话）
    const attemptNext = () => {
      // 如果队列为空且没有正在执行的任务，说明全部完成
      if (queue.length === 0 && executing.size === 0) {
        resolve(results);
        return;
      }
      
      // 如果还有空位且有任务，启动新任务
      while (executing.size < concurrency && queue.length > 0) {
        const taskFn = queue.shift();  // 取出一个任务
        const taskPromise = taskFn().then(result => {
          results.push(result);        // 收集结果
          executing.delete(taskPromise); // 从执行集中移除
          attemptNext();               // 尝试补充下一个
        }).catch(error => {
          results.push(undefined);      // 或者记录错误
          executing.delete(taskPromise);
          reject(error);                // 或者: attemptNext()（继续执行其他任务）
          // 注意: 这里一旦 reject 整个 pLimit 就结束了
          // 更健壮的实现应该用 allSettled 风格
        });
        
        executing.add(taskPromise);    // 加入执行集
      }
      // 如果没有空位了（executing.size >= concurrency），什么都不做
      // 等某个任务完成后会调用 attemptNext() 补充
    };
    
    attemptNext();  // 启动第一批任务（最多 concurrency 个）
  });
}
```

### 4.3 执行过程可视化

假设 `pLimit([A, B, C, D, E, F], concurrency = 2)`：

```
时间轴:
  |----A+B----|--C+D--|--E+F--|
  0   1   2   3   4   5   6   时间(ms)

执行情况:
  T=0: 启动 A, B（并发数=2，满了）
  T=1: A 完成 → 启动 C（B 还在跑）
  T=2: B 完成 → 启动 D
  T=3: C 完成 → 启动 E
  T=4: D 完成 → 启动 F
  T=5: E 完成
  T=6: F 完成 → 全部完成!

任意时刻最多只有 2 个任务在同时执行。
```

### 4.4 完整的 p-limit 实现（生产级别）

下面是一个功能完整、可直接用于项目的 `p-limit` 实现：

```javascript
/**
 * 生产级 p-limit 实现
 * 
 * 特性:
 *   - 支持并发数限制
 *   - 保持结果顺序与输入一致
 *   - 支持错误处理（stop-on-first-error 或 continue-others）
 *   - 支持取消（AbortController）
 *   - 进度回调支持
 */
class PLimit {
  constructor(concurrency = 5, options = {}) {
    this.concurrency = concurrency;
    this.options = {
      stopOnError: false,            // 是否遇到首个错误就停止
      onProgress: null,               // 进度回调 (completed, total, currentTask)
      ...options
    };
    
    this.pendingQueue = [];           // 待执行队列
    this.runningCount = 0;            // 当前正在执行的数量
    this.completedCount = 0;          // 已完成任务数
    this.results = [];                // 结果收集器（保序）
    this.taskMap = new Map();          // 任务 → 索引映射（用于保序）
  }
  
  /**
   * 执行一组任务
   * @param {Array<Function>} tasks  任务函数数组
   * @returns {Promise<Array>}         结果数组
   */
  async run(tasks) {
    // 初始化
    this.totalTasks = tasks.length;
    this.results = new Array(this.totalTasks);
    this.resolver = null;
    this.rejector = null;
    
    // 创建主 Promise
    const mainPromise = new Promise((resolve, reject) => {
      this.resolver = resolve;
      this.rejector = reject;
    });
    
    // 将所有任务加入队列，并记录索引位置
    tasks.forEach((taskFn, index) => {
      this.pendingQueue.push({ taskFn, index });
    });
    
    // 开始调度
    this._scheduleNext();
    
    return mainPromise;
  }
  
  _scheduleNext() {
    // 尝试填充空位
    while (this.runningCount < this.concurrency && this.pendingQueue.length > 0) {
      const { taskFn, index } = this.pendingQueue.shift();
      this.runningCount++;
      
      // 启动任务
      taskFn()
        .then(result => {
          this.results[index] = { status: 'fulfilled', value: result };
        })
        .catch(error => {
          this.results[index] = { status: 'rejected', reason: error };
          
          if (this.options.stopOnError) {
            this.rejector?.(new AggregateError([error]));
            this._drainAndReject(error);
            return;
          }
        })
        .finally(() => {
          this.runningCount--;
          this.completedCount++;
          
          // 报告进度
          this.options.onProgress?.({
            completed: this.completedCount,
            total: this.totalTasks,
            running: this.runningCount
          });
          
          // 补充下一个任务
          this._scheduleNext();
          
          // 检查是否全部完成
          if (this.completedCount >= this.totalTasks && this.runningCount === 0) {
            this.resolver?.(this.results);
          }
        });
    }
  }
  
  _drainAndReject(error) {
    // 停止模式: 取消剩余任务
    while (this.pendingQueue.length > 0) {
      const { index } = this.pendingQueue.shift();
      this.results[index] = { status: 'rejected', reason: error };
      this.completedCount++;
    }
    this.runningCount = 0;
  }
}

// ==================== 使用示例 ====================

// 示例1: 批量上传文件（限制并发为3）
async function batchUpload(files, maxConcurrent = 3) {
  const limiter = new PLimit(maxConcurrent, {
    onProgress: ({ completed, total }) => {
      process.stdout.write(`\r📤 上传进度: ${completed}/${total}`);
    }
  });
  
  const uploadTasks = files.map(file => async () => {
    const result = await s3.upload({
      Bucket: 'my-bucket',
      Key: file.name,
      Body: file
    });
    return { name: file.name, etag: result.ETag };
  });
  
  const results = await limiter.run(uploadTasks);
  console.log('\n\n上传完成!');
  return results.filter(r => r.status === 'fulfilled');
}

// 示例2: 并发爬虫（限制并发避免被封IP）
async function crawlWebsites(urls, maxConcurrent = 5) {
  const limiter = new PLimit(maxConcurrent, {
    stopOnError: false  // 即使某站点失败也继续爬其他的
  });
  
  const tasks = urls.map(url => async () => {
    const resp = await fetch(url);
    if (!resp.ok) throw new Error(`${resp.status}: ${url}`);
    return { url, html: await resp.text(), status: resp.status };
  });
  
  const results = await limiter.run(tasks);
  
  const successful = results.filter(r => r.value?.status === 'fulfilled');
  const failed = results.filter(r => r.value?.status === 'rejected');
  
  console.log(`✅ 成功: ${successful.length}, ❌ 失败: ${failed.length}`);
  return { successful, failed };
}
```

### 4.5 通俗类比：餐厅座位管理

**p-limit = 餐厅的座位数控制**：

想象一家有 **N 张桌子** 的餐厅（`concurrency = N`）：
- 门外排着长队（`pending queue`），每桌客人就是一个"任务"
- 服务员每次有空桌就让下一桌入座（`scheduleNext`）
- 某桌吃完离开后（`task completed`），服务员立刻安排下一桌入座
- 任意时刻店内只有 N 桌客人在用餐（`runningCount <= N`）
- 如果不限制（`concurrency = Infinity`），餐厅会被挤爆——厨房忙不过来、服务员乱成一团、体验极差

这就是为什么需要 p-limit：**给并发加上合理的上限，既充分利用资源又不至于压垮系统。**

## 五、队列模式 —— 结构化的任务调度

### 5.1 串行队列（Serial Queue）

串行队列保证**严格按顺序、同一时间只执行一个任务**。它是防抖和节流的更通用形式。

```javascript
/**
 * 串行队列（FIFO - First In First Out）
 */
class SerialQueue {
  constructor() {
    this.queue = [];
    this.isProcessing = false;
  }
  
  /**
   * 添加任务到队列末尾
   * @param {Function} task 返回 Promise 的函数
   * @returns {Promise} 该任务的执行结果
   */
  enqueue(task) {
    return new Promise((resolve, reject) => {
      this.queue.push({ task, resolve, reject });
      this._processNext();
    });
  }
  
  async _processNext() {
    if (this.isProcessing || this.queue.length === 0) return;
    
    this.isProcessing = true;
    const { task, resolve, reject } = this.queue.shift();
    
    try {
      const result = await task();
      resolve(result);
    } catch (error) {
      reject(error);
    } finally {
      this.isProcessing = false;
      this._processNext();  // 自动处理下一个
    }
  }
  
  /** 获取当前队列长度 */
  get length() {
    return this.queue.length;
  }
  
  /** 清空队列 */
  clear() {
    this.queue.forEach(({ reject }) => 
      reject(new Error('Queue cleared'))
    );
    this.queue = [];
  }
}

// ==================== 使用示例 ====================

// 场景1: 自动保存草稿 —— 只保留最后一次
const saveQueue = new SerialQueue();

editor.on('change', content => {
  saveQueue.enqueue(async () => {
    console.log('💾 保存内容...');
    await api.saveDraft(content);
    console.log('✅ 已保存');
  });
});
// 用户疯狂打字时，每次 change 都入队
// 但实际上只会依次保存最后一次之前所有的版本
// 最后那次 change 的保存会在前面所有保存完成后执行

// 场景2: 写操作互斥 —— 保证写入顺序
const writeQueue = new SerialQueue();

// 多个地方可能同时触发写入，但队列保证顺序执行
buttonA.onclick = () => writeQueue.enqueue(() => writeFile('data-A'));
buttonB.onclick = () => writeQueue.enqueue(() => writeFile('data-B'));
buttonC.onclick = () => writeQueue.enqueue(() => writeFile('data-C'));
// 不管按钮怎么点，写入顺序一定是 A → B → C
```

### 5.2 并行队列（Parallel Queue with Limit）

结合 p-limit 思想的队列，支持指定最大并发数：

```javascript
/**
 * 受限并发队列
 * 结合了队列的结构化管理和 p-limit 的并发控制
 */
class BoundedQueue {
  constructor(concurrency = 3) {
    this.concurrency = concurrency;
    this.queue = [];
    this.running = 0;
  }
  
  add(task) {
    return new Promise((resolve, reject) => {
      this.queue.push({ task, resolve, reject });
      this._tryProcess();
    });
  }
  
  _tryProcess() {
    while (this.running < this.concurrency && this.queue.length > 0) {
      const { task, resolve, reject } = this.queue.shift();
      this.running++;
      
      task()
        .then(resolve)
        .catch(reject)
        .finally(() => {
          this.running--;
          this._tryProcess();  // 补充新任务
        });
    }
  }
  
  get pending() { return this.queue.length; }
  get active() { return this.running; }

  /** 暂停队列（不再启动新任务，但不影响正在运行的） */
  pause() {
    this._paused = true;
  }
  
  /** 恢复队列 */
  resume() {
    this._paused = false;
    this._tryProcess();
  }
}

// ==================== 使用示例 ====================

const imageQueue = new BoundedQueue(5);  // 最多同时下载5张图片

imageUrls.forEach(url => {
  imageQueue.add(async () => {
    const blob = await fetchImageAsBlob(url);
    await displayImage(blob);
    return url;
  }).then(url => console.log(`✅ 加载完成: ${url}`));
});
```

### 5.3 优先级队列（Priority Queue）

有时任务有优先级之分——紧急的任务应该插队：

```javascript
/**
 * 优先级队列（数值越小优先级越高）
 */
class PriorityQueue {
  constructor() {
    this.queue = [];
  }
  
  add(task, priority = 0) {
    return new Promise((resolve, reject) => {
      const item = { task, priority, resolve, reject, addedAt: Date.now() };
      
      // 按优先级插入（保持同优先级的 FIFO 顺序）
      const insertIndex = this.queue.findIndex(
        existing => existing.priority > priority ||
                  (existing.priority === priority && existing.addedAt > item.addedAt)
      );
      
      if (insertIndex === -1) {
        this.queue.push(item);
      } else {
        this.queue.splice(insertIndex, 0, item);
      }
      
      this._process();
    });
  }
  
  async _process() {
    if (this.isProcessing || this.queue.length === 0) return;
    this.isProcessing = true;
    
    // 取出优先级最高的（排在最前面的）
    const { task, resolve, reject } = this.queue.shift();
    
    try {
      const result = await task();
      resolve(result);
    } catch (e) {
      reject(e);
    } finally {
      this.isProcessing = false;
      this._process();  // 继续下一个
    }
  }
}

// 使用: 关键操作优先处理
const actionQueue = new PriorityQueue();

// 用户点击"立即购买" —— 最高优先级
buyButton.addEventListener('click', () => {
  actionQueue.add(processPurchase, 0);  // P0 最高优先
});

// 自动保存草稿 —— 低优先级
editor.addEventListener('input', () => {
  actionQueue.add(saveDraft, 10);  // P10 低优先
});

// 分析数据上报 —— 最低优先级
window.addEventListener('beforeunload', () => {
  actionQueue.add(sendAnalytics, 20);  // P20 最低
});
```

### 5.4 通俗类比：医院急诊分诊

三种队列就像医院的**急诊分诊系统**：

- **串行队列 = 单医生诊室**：不管多少人排队，医生一次只能看一个病人。病人严格按挂号顺序就诊。简单但可能很慢。
- **有限并发队列 = 多个诊室同时开放**：医院开放 5 个诊室，同时可以有 5 位病人在看病。其他人候诊。效率高了很多，但诊室数量（并发数）要根据医生人数合理设定。
- **优先级队列 = 分诊护士的判断**：虽然大家都在排队，但心跳骤停的病人（P0）肯定比普通感冒（P10）先被安排进诊室。生命攸关的事情不能等！

## 六、高级并发模式

### 6.1 动态并发调整

根据系统负载自动调整并发数——负载低时加大并发提高吞吐量，负载高时降低并发保护系统：

```javascript
/**
 * 自适应并发控制器
 */
class AdaptiveConcurrency {
  constructor(initialConcurrency = 5) {
    this.currentLimit = initialConcurrency;
    this.minLimit = 1;
    this.maxLimit = 20;
    this.successStreak = 0;
    this.failureStreak = 0;
    this.activeRequests = 0;
    this.responseTimes = [];  // 最近 N 次的响应时间
  }
  
  recordSuccess(responseTime) {
    this.successStreak++;
    this.failureStreak = 0;
    this.responseTimes.push(responseTime);
    if (this.responseTimes.length > 10) this.responseTimes.shift();
    
    // 连续成功 + 响应快 → 可以增加并发
    if (this.successStreak >= 5 && this._avgResponseTime() < 200) {
      this.currentLimit = Math.min(this.currentLimit + 1, this.maxLimit);
      this.successStreak = 0;
      console.log(`⬆️ 并发提升至: ${this.currentLimit}`);
    }
  }
  
  recordFailure() {
    this.failureStreak++;
    this.successStreak = 0;
    
    // 连续失败 → 降低并发以减轻压力
    if (this.failureStreak >= 3) {
      this.currentLimit = Math.max(Math.floor(this.currentLimit / 2), this.minLimit);
      this.failureStreak = 0;
      console.log(`⬇️ 并发降至: ${this.currentLimit}`);
    }
  }
  
  _avgResponseTime() {
    if (this.responseTimes.length === 0) return 0;
    return this.responseTimes.reduce((a, b) => a + b, 0) / this.responseTimes.length;
  }
  
  get limit() { return this.currentLimit; }
}
```

### 6.2 请求管道化（Pipelining）

一种高级模式：将大量任务分成多个批次（pipeline stages），每批内部并发执行，批间串行：

```javascript
/**
 * 管道化批处理器
 * 将 tasks 分成每批 batchSize 个，批次间串行，批次内并发
 */
async function pipelineBatches(tasks, { batchSize = 10, batchDelay = 100 }) {
  const allResults = [];
  
  for (let i = 0; i < tasks.length; i += batchSize) {
    const batch = tasks.slice(i, i + batchSize);
    console.log(`\n📦 批次 ${Math.floor(i / batchSize) + 1}: ${batch.length} 个任务`);
    
    const batchResults = await Promise.allSettled(
      batch.map(task => task())
    );
    
    allResults.push(...batchResults);
    
    // 批间延迟（给服务器喘息时间）
    if (i + batchSize < tasks.length) {
      await sleep(batchDelay);
    }
  }
  
  return allResults;
}

// 使用: 100个请求，每批10个并发，批间间隔200ms
const allResults = await pipelineBatches(
  Array.from({ length: 100 }, (_, i) => () => fetchItem(i)),
  { batchSize: 10, batchDelay: 200 }
);
```

### 6.3 背景任务与前台任务分离

Web 应用中通常有两类任务：
- **前台任务**：响应用户交互（点击、输入、滚动），要求低延迟
- **后台任务**：数据分析、日志上报、预加载，允许高延迟

```javascript
/**
 * 双优先级的任务调度器
 * 使用 requestIdleCallback（浏览器空闲时执行后台任务）
 * 或 MessageChannel（微任务间隔）来调度
 */
class DualPriorityScheduler {
  constructor() {

    return this.foregroundQueue.enqueue(task);

  // 后台任务：非紧急
  scheduleBackground(task) {
    return this.backgroundQueue.add(task);
  }
}

scheduler.scheduleBackground(() => sendAnalytics());
scheduler.scheduleBackground(() => syncLocalStorage());
```

## 七、性能陷阱与最佳实践

### 7.1 常见陷阱

#### 陷阱1: 无意中的串行化

```javascript
// ❌ 看起来像并发，实际上是串行
async function看起来并发其实串行() {
  const a = await fetch('/a');  // 等 a
  const b = await fetch('/b');  // 等 b
  const c = await fetch('/c');  // 等 c
  return [a, b, c];
}

// 因为 await 在每一行都暂停了！
// 正确做法: 不要 await 每个 fetch，而是收集 Promise 后统一 await

async function真正的并发() {
  const pa = fetch('/a');  // 立即返回 Promise，不等待
  const pb = fetch('/b');  // 立即返回 Promise
  const pc = fetch('/c');  // 立即返回 Promise
  
  const [a, b, c] = await Promise.all([pa, pb, pc]);  // 并行等待
  return [a, b, c];
}
```

#### 陷阱2: Promise.all 的内存压力

```javascript
// ❌ 危险: 一次性创建太多 Promise
const urls = generateMillionUrls();  // 100万个URL
const promises = urls.map(u => fetch(u));  // 100万个请求同时发出！
const results = await Promise.all(promises);  // 内存可能爆掉

// ✅ 安全: 使用 p-limit 控制
const limiter = new PLimit(50);  // 最多50个并发
const safeResults = await limiter.run(urls.map(u => () => fetch(u)));
```

#### 陷阱3: 错误吞噬

```javascript
// ❌ Promise.all 内部的 reject 可能被遗漏
try {
  const results = await Promise.all(tasks);
} catch (e) {
  // 如果第3个任务失败，这里确实能捕获
  // 但此时其他正在运行的 Promise 的结果丢失了
}

// ✅ 更安全: 用 allSettled + 过滤
const settled = await Promise.allSettled(tasks);
const successes = settled
  .filter(s => s.status === 'fulfilled')
  .map(s => s.value);
const failures = settled
  .filter(s => s.status === 'rejected')
  .map(s => s.reason);
```

#### 陷阱4: 循环中的 await 导致的性能退化

### 7.2 最佳实践清单

```javascript

  fetchUser(),
  fetchSettings(),
  fetchNotifications()
]);

// 2. CPU 操作谨慎使用并发（可能导致主线程阻塞）
// 对于 CPU 密集型任务，考虑 Web Worker 或分片执行

// 3. 始终设置合理的并发上限
// 浏览器: 同域名并发连接限制通常为 6
// Node.js: 取决于可用内存和文件描述符限制

// 4. 大批量操作使用 p-limit 或管道化
// 不要一次性创建 10000 个 Promise

// 5. 优先使用 allSettled 进行批量操作
// 除非你确定"任一失败则全部放弃"是正确的行为

// 6. 记录并发指标（可选但有价值）
// 监控活跃请求数、平均响应时间、错误率
```

## 八、总结

### 8.1 并发控制工具箱

| 工具/模式 | 适用场景 | 核心API |
|----------|---------|--------|
| **Promise.all** | 全部成功才算成功，需要所有结果 | `Promise.all(iterable)` |
| **Promise.allSettled** | 尽力而为，需要每个结果的状态 | `Promise.allSettled(iterable)` |
| **Promise.race** | 超时控制、多源竞速 | `Promise.race(iterable)` |
| **Promise.any** | 多源容错、取最快成功的 | `Promise.any(iterable)` |
| **for+await** | 串行执行、后续依赖前置 | `for (x of arr) { await x; }` |
| **p-limit** | 限制并发数、保护资源 | 自定义类/第三方库 |
| **串行队列** | 严格顺序、互斥访问 | 自定义队列类 |
| **优先级队列** | 不同任务有不同紧急度 | 自定义带优先级的队列 |

### 8.2 选择决策流程

```
面对一组异步任务，如何选择执行策略?

1. 这些任务之间有依赖关系吗？
   ├── 是 → 使用串行执行（for+await / reduce链 / 递归）
   └── 否 → 继续 ↓

2. 你需要所有结果吗？
   ├── 全部成功才行 → Promise.all
   ├── 每个成功/失败都要知道 → Promise.allSettled
   └── 只要一个就够了 → 继续 ↓

3. 你要的是"最先完成的"还是"最先成功的"？
   ├── 不管成败 → Promise.race（含超时场景）
   └── 只要成功 → Promise.any（含容错/多源场景）
   └── 以上都不完全是 → 继续 ↓

4. 任务数量很大吗？（>10? >100? >1000?）
   ├── 是 → 使用 p-limit 限制并发数
   ├── 且需要有序列 → 使用队列模式
   └── 否（少量任务）→ 直接 Promise.all 即可
```

### 8.3 一句话总结

> **并发控制是异步编程的"流量管控系统"。**如果说 Promise 和 async/await 让我们学会了"如何表达单个异步操作"，那么并发控制教我们的就是"如何管理一堆异步操作的生命周期"。`Promise.all/race/any/allSettled` 是内置的基础工具；`p-limit` 是保护系统不过载的安全阀；队列模式则是结构化任务调度的框架。掌握它们，意味着你不仅能写出正确的异步代码，还能写出**高效、稳定、可控**的异步代码。
