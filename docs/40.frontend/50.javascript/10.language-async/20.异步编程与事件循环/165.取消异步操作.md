# 取消异步操作 —— AbortController 与 AbortSignal、fetch 取消、Promise 取消的模拟

> **核心内容**：在异步编程的世界里，我们学会了如何"发起"操作——用 Promise、async/await、fetch 发出网络请求。但一个经常被忽视的、同样重要的问题是：**如何让已经发出的操作"停下来"？** 用户点击了搜索按钮后改变了主意，正在进行的请求还有意义吗？组件卸载了，还在跑的后台任务不应该被清理吗？ES2017 引入的 `AbortController` 正是为解决这类问题而生——它提供了一种标准化的、可组合的、可传递的"取消信号"机制。理解它，意味着你不仅能写出能跑的异步代码，还能写出**可控、可清理、资源友好**的生产级代码。

---

## 一、为什么需要取消？—— 被遗忘的操作之痛

### 1.1 Promise 的单向性困境

让我们从一个令人不安的事实开始：**原生的 Promise 是不可取消的。**

```javascript
// 你发起了这样一个请求：
const promise = fetch('/api/heavy-computation');

// 然后你意识到用户已经离开了这个页面
// 或者用户点击了其他按钮，这个结果不再需要了
// 但是！没有任何办法告诉 fetch "停下来"

// promise 还在后台运行着...
// 服务器还在处理这个请求...
// 网络带宽还在被占用...
// 内存中还有一个未完成的 Promise 对象...

// 你唯一的选择就是"忽略它的结果"
// 但它依然在消耗资源！
```

这不是一个小问题。想象以下真实场景：

**场景一：搜索框的竞态条件**

```javascript
// ❌ 问题代码：快速输入时产生大量废弃请求
const searchInput = document.getElementById('search');

searchInput.addEventListener('input', (e) => {
  const query = e.target.value;
  
  // 每输入一个字符就发一次请求
  // 输入 "javascript" → 发出10次请求
  // 但实际上只有最后一次的结果是有用的
  // 前9次请求还在跑，浪费带宽和服务器资源
  fetch(`/api/search?q=${query}`)
    .then(r => r.json())
    .then(results => renderResults(results));  
    // 如果第10次先返回了，这里会显示旧数据！
});
```

**场景二：组件卸载后的幽灵请求**

```javascript
// ❌ React 组件卸载后，异步操作仍在运行
function UserProfile({ userId }) {
  useEffect(() => {
    // 组件挂载时发起请求
    fetchData(userId).then(data => {
      setState({ data });  // ⚠️ 组件可能已经卸载了！
      // 这会导致 "Can't perform state update on unmounted component" 警告
      // 甚至内存泄漏
    });
    
    // 没有清理函数返回！请求无法取消
  }, [userId]);
}
```

**场景三：无限等待的死锁**

```javascript
// ❌ 用户永远卡在加载状态
async function loadCriticalData() {
  showLoadingSpinner();
  
  try {
    // 如果服务器卡死了（不响应也不关闭连接）
    const data = await fetch('/api/slow-server');
    hideLoadingSpinner();
    return data;
  } catch (err) {
    hideLoadingSpinner();
    showError(err);
  }
}

// 如果服务器只是很慢（30秒才响应）
// 用户要盯着 loading spinner 看 30 秒
// 他可能会刷新页面、重复点击、甚至直接关掉
```

### 1.2 理论分析：取消操作的三大价值

从软件工程的角度看，"能够取消"一个操作带来的好处远不止是"少等一会儿"：

**第一层：用户体验优化**
- 用户不需要的响应就不应该浪费他们的时间
- 快速交互（如搜索）应该只显示最终状态
- 长时间的操作应该有进度指示或取消按钮

**第二层：资源保护**
- 减少不必要的网络流量（节省用户带宽和服务器成本）
- 降低服务端并发压力
- 防止内存泄漏（未完成的 Promise 和回调引用）

**第三层：系统可靠性**
- 组件生命周期管理（挂载时开始，卸载时清理）
- 优雅降级（主源失败时切换到备用源）
- 避免竞态条件（旧结果覆盖新结果）

### 1.3 通俗类比：打电话 vs 发短信

把不可取消的异步操作比作**打电话**：

你拨了一个号码，对方接通了但一直在说个不停。你想结束这次对话，但你不能——因为你没有挂断键。你只能等着对方说完，或者干脆扔掉手机（但这不优雅，而且手机还占着线）。

而**可取消的操作就像发短信**：
- 你发出消息（发起操作）
- 对方还没回复时，你可以随时决定"算了，不想要了"
- 你可以明确地发送一个"取消"信号
- 双方都知道这件事结束了

`AbortController` 就是给 JavaScript 的异步世界装上了"挂断键"。

## 二、AbortController 基础 —— 取消令牌与信号

### 2.1 最简模型

`AbortController` 的 API 设计极其精简，只有两个核心成员：

```javascript
// 第一步：创建一个控制器（相当于买一个遥控器）
const controller = new AbortController();

// 第二步：获取控制器上的信号（相当于遥控器的接收端）
const signal = controller.signal;

console.log(signal.aborted);  // false — 初始状态：没有被中止

// 第三步：在需要的时候触发中止（按下遥控器上的停止键）
controller.abort();

console.log(signal.aborted);  // true — 现在被标记为已中止
```

就这么简单。三个概念：

| 概念 | 角色 | 类比 |
|------|------|------|
| `AbortController` | 控制者，拥有 `abort()` 方法 | 遥控器本体 |
| `AbortSignal` | 信号载体，可被监听 | 遥控器的无线信号 |
| `signal.aborted` | 只读布尔值，表示是否已取消 | 信号灯（亮=已取消） |

### 2.2 abort 事件 —— 信号的真正威力

`signal` 不仅仅是一个状态标志，它还是一个**事件发射器**。当 `controller.abort()` 被调用时，`signal` 会触发 `'abort'` 事件。这才是它真正的强大之处：

```javascript
const controller = new AbortController();
const { signal } = controller;

// 在 signal 上注册事件监听器
signal.addEventListener('abort', () => {
  console.log('🛑 收到中止信号!');
  console.log('原因:', signal.reason);  // 可选的中止原因
});

// 同时也可以检查属性
if (!signal.aborted) {
  console.log('安全，可以继续执行');
}

// ... 一段时间后 ...
controller.abort('用户取消了操作');  // 触发 abort 事件

/*
输出:
🛑 收到中止信号!
原因: 用户取消了操作
*/
```

**关键洞察**：这种设计使得 `signal` 可以被**传递**给任何函数、任何对象、任何模块。它们不需要持有 `controller` 的引用，只需要持有 `signal`——一个只读的、可被观察的对象。这实现了**控制权与执行权的分离**。

### 2.3 signal 的传递性（核心设计模式）

这是 `AbortController` 最精妙的设计之一：**signal 可以像令牌一样在代码中传递**，任何持有它的代码都可以感知到取消事件。

```javascript
/**
 * Signal 传递链演示
 */

function stepA(signal) {
  if (signal.aborted) return;           // 检查点1
  signal.addEventListener('abort', cleanupA);  // 监听点1
  console.log('A 开始工作...');
  stepB(signal);  // 将 signal 传给下一步
}

function stepB(signal) {
  if (signal.aborted) return;           // 检查点2
  signal.addEventListener('abort', cleanupB);  // 监听点2
  console.log('B 开始工作...');
  stepC(signal);
}

function stepC(signal) {
  if (signal.aborted) return;
  signal.addEventListener('abort', () => {
    console.log('C 被通知清理');
  });
  console.log('C 开始工作...');
  simulateLongTask();
}

function cleanupA() { console.log('→ A 清理完毕'); }
function cleanupB() { console.log('→ B 清理完毕'); }
function simulateLongTask() { 
  // 模拟耗时操作...
}

// ==================== 使用 ====================
const controller = new AbortController();

// 将 signal 传入整条调用链
stepA(controller.signal);

// 此时 A、B、C 都在工作
// ...

// 5秒后决定取消所有步骤
setTimeout(() => {
  console.log('\n⚡ 执行全局取消!');
  controller.abort('超时强制终止');
}, 5000);

/*
预期输出（5秒后）:
⚡ 执行全局取消!
→ A 清理完毕
→ B 清理完毕
C 被通知清理

注意: A、B、C 都收到了取消通知并执行了自己的清理逻辑！
这就是 signal 传递性的威力。
*/
```

## 三、Fetch 与 AbortController —— 原生支持

### 3.1 基本用法

`fetch` API 原生支持 `AbortSignal`。这是目前 `AbortController` 使用最广泛的场景：

```javascript
/**
 * 可取消的 fetch 请求
 */
async function cancellableFetch(url, options = {}) {
  // 创建控制器
  const controller = new AbortController();
  
  // 设置超时自动取消（可选）
  const timeout = options.timeout || 10000;
  const timeoutId = setTimeout(() => {
    controller.abort(`请求超过 ${timeout}ms 未响应`);
  }, timeout);
  
  try {
    // 将 signal 传给 fetch
    const response = await fetch(url, {
      ...options,
      signal: controller.signal  // 🔑 关键！
    });
    
    clearTimeout(timeoutId);
    
    if (!response.ok) {
      throw new Error(`HTTP ${response.status}: ${response.statusText}`);
    }
    
    return await response.json();
    
  } catch (error) {
    clearTimeout(timeoutId);
    
    // 区分"主动取消"和其他错误
    if (error.name === 'AbortError') {
      console.log('⏱️ 请求被取消:', error.message);
      return null;  // 或返回默认值/缓存值
    }
    
    throw error;  // 其他错误继续抛出
  }
}

// ==================== 使用示例 ====================

// 场景1: 带取消按钮的搜索
let currentController = null;

searchButton.addEventListener('click', async () => {
  // 如果之前的请求还在跑，先取消掉
  if (currentController && !currentController.signal.aborted) {
    currentController.abort('用户发起新搜索');
  }
  
  currentController = new AbortController();
  
  try {
    const data = await cancellableFetch(
      `/api/search?q=${searchInput.value}`,
      { signal: currentController.signal }  // 也可以直接传
    );
    displayResults(data);
  } catch (e) {
    if (e.name !== 'AbortError') showError(e);
  }
});

cancelButton.addEventListener('click', () => {
  if (currentController) {
    currentController.abort('用户手动取消');
    console.log('✅ 搜索已取消');
  }
});
```

### 3.2 fetch 被 abort 后发生了什么？

这是理解 `AbortController` + `fetch` 工作原理的关键：

```javascript
const controller = new AbortController();

const fetchPromise = fetch('/api/data', {
  method: 'POST',
  body: JSON.stringify({ large: 'payload' }),
  signal: controller.signal
});

// 当 controller.abort() 被调用时:
controller.abort('不再需要这些数据了');

// fetchPromise 会发生什么？
fetchPromise.catch(error => {
  console.error(error.name);       // 'AbortError'
  console.error(error.message);     // '不再需要这些数据了'
});

// 底层实际发生的事情:
// 1. 浏览器中断底层的 TCP 连接（不是等它超时！而是立刻断开）
// 2. 停止读取响应体（如果正在流式传输）
// 3. 将 fetch 返回的 Promise 标记为 rejected
// 4. 抛出一个 AbortError（特殊的 DOMException 子类）
// 5. 相关的网络资源被释放
```

**对比 Promise.race 实现的超时**：

```javascript
// ❌ Promise.race 方式：无法真正取消请求
function raceTimeout(fetchPromise, ms) {
  return Promise.race([
    fetchPromise,
    new Promise((_, reject) => 
      setTimeout(() => reject(new Error('超时')), ms)
    )
  ]);
}

// ⚠️ 问题：即使超时触发了，原始 fetch 可能仍在后台运行！
// 只是我们的代码不再关心它的结果了

// ✅ AbortController 方式：真正取消请求
function abortTimeout(fetchPromise, ms) {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), ms);
  
  return fetchPromise
    .finally(() => clearTimeout(timer));
  // 但 fetch 本身已经绑定了 signal
  // 所以需要在创建 fetch 时就传入 signal
}
```

### 3.3 一个 signal 控制多个请求

同一个 `AbortSignal` 可以同时绑定到多个 `fetch` 上，实现"一键全部取消"：

```javascript
/**
 * 批量下载器：一个取消按钮停止所有下载
 */
class BatchDownloader {
  constructor() {
    this.controller = new AbortController();
    this.downloads = [];
  }
  
  add(url) {
    const downloadPromise = fetch(url, {
      signal: this.controller.signal  // 所有请求共用同一个 signal
    }).then(r => r.blob())
      .then(blob => saveAsFile(blob, url.split('/').pop()))
      .then(() => this.markComplete(url))
      .catch(err => {
        if (err.name !== 'AbortError') this.markFailed(url, err);
      });
    
    this.downloads.push({ url, promise: downloadPromise });
    return downloadPromise;
  }
  
  cancelAll() {
    // 一个 abort() 取消所有进行中的请求！
    this.controller.abort('用户取消了批量下载');
    console.log(`⛔ 已取消 ${this.downloads.length} 个下载`);
  }
  
  markComplete(url) {
    console.log(`✅ 下载完成: ${url}`);
  }
  
  markFailed(url, err) {
    console.warn(`❌ 下载失败: ${url} - ${err.message}`);
  }
}

// 使用
const downloader = new BatchDownloader();

download.add('https://example.com/file1.zip');
downloader.add('https://example.com/file2.pdf');
downloader.add('https://example.com/video.mp4');
downloader.add('https://example.com/archive.tar.gz');

document.getElementById('cancel-all').addEventListener('click', () => {
  downloader.cancelAll();  // 一个动作，全部取消
});
```

## 四、自定义可取消的异步操作

`fetch` 天然支持 `AbortSignal`，但你的自定义异步函数呢？如何让它们也能被取消？

### 4.1 手动实现可取消的 Promise

```javascript
/**
 * 创建一个可被 AbortController 取消的异步操作包装器
 * @param {Function} asyncFn        异步函数（应返回 Promise）
 * @param {AbortSignal} signal       取消信号
 * @param {...any} args               传给 asyncFn 的参数
 * @returns {Promise}                操作结果或 AbortError
 */
async function cancellable(asyncFn, signal, ...args) {
  // 快速路径：如果在开始前就已经被取消了
  if (signal.aborted) {
    throw new DOMException('Operation aborted', 'AbortError');
  }
  
  return new Promise((resolve, reject) => {
    // 监听取消信号
    const onAbort = () => reject(
      new DOMException(signal.reason || 'Operation aborted', 'AbortError')
    );
    
    signal.addEventListener('abort', onAbort, { once: true });
    
    // 启动实际的异步操作
    asyncFn(...args)
      .then(resolve)
      .catch(reject)
      .finally(() => {
        // 无论成功还是失败，都移除监听器（防止内存泄漏）
        signal.removeEventListener('abort', onAbort);
      });
  });
}

// ==================== 使用示例 ====================

/**
 * 示例1: 可取消的长轮询
 */
async function pollUntilCondition(signal, checkFn, interval = 1000) {
  while (!signal.aborted) {
    const result = await checkFn();
    if (result) return result;
    await sleep(interval);
  }
  throw new DOMException('Polling cancelled', 'AbortError');
}

// 使用
const controller = new AbortController();

pollUntilCondition(
  controller.signal,
  () => isJobReady(jobId),  // 检查任务是否完成
  2000  // 每2秒检查一次
).then(result => console.log('✅ 任务完成:', result))
  .catch(err => {
    if (err.name === 'AbortError') {
      console.log('⏱️ 轮询被取消');
    }
  });

// 10秒后自动取消（模拟用户离开）
setTimeout(() => controller.abort('用户离开了页面'), 10000);


/**
 * 示例2: 可取消的动画帧循环
 */
function animateWithCancel(signal, callback, duration = 3000) {
  return new Promise((resolve, reject) => {
    const startTime = performance.now();
    let animationFrameId = null;
    
    const animate = (now) => {
      if (signal.aborted) {
        cancelAnimationFrame(animationFrameId);
        reject(new DOMException('Animation aborted', 'AbortError'));
        return;
      }
      
      const elapsed = now - startTime;
      
      if (elapsed >= duration) {
        cancelAnimationFrame(animationFrameId);
        resolve(elapsed);
        return;
      }
      
      callback(elapsed, duration);
      animationFrameId = requestAnimationFrame(animate);
    };
    
    signal.addEventListener('abort', () => {
      cancelAnimationFrame(animationFrameId);
      reject(new DOMException('Animation aborted', 'AbortError'));
    }, { once: true });
    
    animationFrameId = requestAnimationFrame(animate);
  });
}


/**
 * 示例3: 可取消的超时包装（更完善的版本）
 */
function withTimeout(promise, ms, signal) {
  // 如果外部提供了 signal，合并超时和外部取消
  const internalController = new AbortController();
  const targetSignal = signal || internalController.signal;
  
  const timeoutId = setTimeout(() => {
    internalController.abort(`超时 (${ms}ms)`);
  }, ms);
  
  // 合并信号：外部 abort 或内部超时都会触发
  const combinedSignal = targetSignal.aborted ? targetSignal : internalController.signal;
  
  // 如果使用内部控制器，监听其 abort
  if (!signal) {
    combinedSignal.addEventListener('abort', () => clearTimeout(timeoutId));
  }
  
  const wrappedPromise = promise.then(value => {
    clearTimeout(timeoutId);
    if (!internalController.signal.aborted) {
      return value;  // 正常完成
    }
  }).catch(error => {
    clearTimeout(timeoutId);
    throw error;  // 重新抛出
  });
  
  // 让 fetch/promise 能感知到取消
  // （如果原始操作支持 signal 就传入，否则通过 race 实现）
  if (typeof promise.then === 'function' && !promise._hasSignal) {
    return Promise.race([wrappedPromise, new Promise((_, rej) => {
      combinedSignal.addEventListener('abort', () => 
        rej(new DOMException(combinedSignal.reason || 'Timed out', 'AbortError'))
      , { once: true });
    })]);
  }
  
  return wrappedPromise.finally(() => clearTimeout(timeoutId));
}
```

### 4.2 AbortController + 自定义异步迭代器

结合前面学到的异步生成器，可以实现可取消的数据流：

```javascript
/**
 * 可取消的异步数据流生成器
 */
async function* cancellableStream(source, { transform, signal }) {
  for await (const item of source) {
    // 每次产出前检查是否被取消
    if (signal.aborted) {
      console.log('🛑 流被中止');
      return;
    }
    
    // 应用转换函数
    const transformed = await transform(item);
    yield transformed;
  }
  
  // 如果因为 abort 跳出循环，finally 仍然会执行
}

// 使用: 可取消的分页数据加载
const dataStream = cancellableStream(paginationSource, {
  transform: async (pageData) => {
    return pageData.items.map(enrichWithData);
  },
  signal: cancelSignal
});

for await (const item of dataStream) {
  renderItem(item);
}

// 用户随时可以通过 cancelSignal.controller.abort() 停止加载
```

## 五、框架中的取消模式实战

### 5.1 React 中的请求取消

React 中最常见的需求就是**组件卸载时取消未完成的请求**：

```jsx
import { useState, useEffect } from 'react';

/**
 * ✅ 正确做法: 使用 AbortController 管理请求生命周期
 */
function UserProfile({ userId }) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    // 每次依赖变化都创建新的 controller
    const controller = new AbortController();
    
    async function loadUser() {
      setLoading(true);
      setError(null);
      
      try {
        const response = await fetch(`/api/users/${userId}`, {
          signal: controller.signal  // ← 关键!
        });
        
        if (!response.ok) throw new Error(`HTTP ${response.status}`);
        
        const data = await response.json();
        setUser(data);
      } catch (err) {
        // 忽略 AbortError（组件卸载导致的取消不应报错）
        if (err.name !== 'AbortError') {
          setError(err.message);
        }
      } finally {
        setLoading(false);
      }
    }
    
    loadUser();
    
    // 清理函数: 组件卸载时取消请求
    return () => {
      controller.abort('组件卸载，取消请求');
    };
  }, [userId]);  // userId 变化时会重新创建 controller

  if (loading) return <LoadingSpinner />;
  if (error) return <ErrorMessage message={error} />;
  if (user) return <UserCard data={user} />;
}
```

### 5.3 通用的 useCancellableRequest Hook

将取消逻辑封装成可复用的 Hook：

```javascript
/**
 * 通用型可取消请求 Hook
 * 支持自动重试、竞态取消、防抖
 */
function useCancellableRequest(options = {}) {
  const {
    autoCleanup = true,          // 组件卸载时自动取消
    dedupeKey = null,            // 相同 key 复用请求
    debounceMs = 0,             // 防抖延迟
    onSuccess, onError
  } = options;
  
  const controllerRef = useRef(null);
  const pendingRequests = useRef(new Map()); // 用于去重
  
  // 清理函数
  const cleanup = useCallback(() => {
    controllerRef.current?.abort('Hook cleanup');
    controllerRef.current = null;
  }, []);
  
  // 自动清理（可选）
  useEffect(() => {
    if (autoCleanup) return cleanup;
  }, [autoCleanup]);
  
  const execute = useCallback(async (requestFn, requestOptions = {}) => {
    // 取消上一个请求（如果有的话）
    if (controllerRef.current && !controllerRef.current.signal.aborted) {
      controllerRef.current.abort('新请求替代');
    }
    
    // 创建新控制器
    const controller = new AbortController();
    controllerRef.current = controller;
    
    // 防抖处理
    if (debounceMs > 0) {
      await new Promise(r => setTimeout(r, debounceMs));
      if (controller.signal.aborted) return; // 防抖期间被取消
    }
    
    try {
      const result = await requestFn(controller.signal, requestOptions);
      onSuccess?.(result);
      return result;
    } catch (error) {
      if (error.name === 'AbortError') {
        console.log('请求被取消:', error.message);
        return null; // 或静默处理
      }
      onError?.(error);
      throw error;
    }
  }, [autoCleanup, debounceMs, onSuccess, onError]);
  
  return { execute, cleanup, getController: () => controllerRef.current };
}

// 使用示例
function SearchComponent({ onSearch }) {
  const { execute } = useCancellableRequest({
    onSuccess: (data) => onSearch(data),
    debounceMs: 300  // 300ms 防抖
  });
  
  return (
    <input 
      onChange={e => execute(
        (signal) => fetch(`/api/search?q=${e.target.value}`, { signal })
      )} 
    />
  );
}
```

### 6.1 取消 + 重试 = 弹性容错

将取消和重试结合起来：第一次尝试超时后取消，然后换策略重试：

```javascript
/**
 * 带取消的重试机制
 * 第一次尝试用短超时（快速失败），
 * 失败后换用更长超时的备用方案
 */
async function resilientFetch(url, primaryOptions = {}, fallbackOptions = {}) {
  const primaryController = new AbortController();
  
  try {
    // 第一次尝试：短超时（3秒）
    return await withTimeout(
      fetch(url, { ...primaryOptions, signal: primaryController.signal }),
      3000,
      primaryController.signal
    );
  } catch (primaryError) {
    if (primaryError.name !== 'AbortError') throw primaryError;
    
    console.log('⚠️ 主源超时，切换到备用源...');
    
    const fallbackController = new AbortController();
    
    // 第二次尝试：长超时（15秒），可能用不同的 URL 或参数
    return await withTimeout(
      fetch(url.replace('api.', 'backup-api.'), {
        ...fallbackOptions,
        signal: fallbackController.signal
      }),
      15000,
      fallbackController.signal
    );
  }
}

resilientFetch('/api/critical-data')
  .then(data => console.log('✅ 数据获取成功'))
  .catch(err => console.error('❌ 主备源均失败:', err.message));
```

### 6.2 取消传播（Cancellation Propagation）

在复杂系统中，取消信号需要跨层级传播：

```javascript
/**
 * 多层级取消传播
 */
class CancelableWorkflow {
  constructor(name) {
    this.name = name;
    this.controller = new AbortController();
    this.childWorkflows = [];
  }
  
  get signal() {
    return this.controller.signal;
  }
  
  /**
   * 添加子工作流（子工作流继承父级的取消信号）
   */
  addChild(workflow) {
    // 将父级 signal 传递给子工作流
    workflow.setParentSignal(this.controller.signal);
    this.childWorkflows.push(workflow);
    return workflow;
  }
  
  /**
   * 取消整个工作流及其所有子工作流
   */
  cancel(reason) {
    console.log(`\n⛔ 取消工作流 [${this.name}]`);
    this.controller.abort(reason);
    
    // 广播取消给子工作流
    for (const child of this.childWorkflows) {
      child.cancel(`父级 [${this.name}] 被取消: ${reason}`);
    }
  }
}

// 使用: 构建多层级的可取消系统
const mainWorkflow = new CancelableWorkflow('主流程');

const dbStep = new CancelableWorkflow('数据库查询');
const cacheStep = new CancelableWorkflow('缓存更新');
const analyticsStep = new CancelableWorkflow('分析上报');

mainWorkflow.addChild(dbStep);
mainWorkflow.addChild(cacheStep);
mainWorkflow.addChild(analyticsStep);

// 任何一级的取消都会传播下去
mainWorkflow.cancel('用户退出应用');
/*
输出:
⛔ 取消工作流 [主流程]
⛔ 取消工作流 [数据库查询] — 父级 [主流程] 被取消: 用户退出应用
⛔ 取消工作流 [缓存更新] — 父级 [主流程] 被取消: 用户退出应用
⛔ 取消工作流 [分析上报] — 父级 [主流程] 被取消: 用户退出应用
*/
```

### 6.3 竞态条件防御（Race Condition Guard）

经典的"搜索框竞态问题"的终极解决方案：

```javascript
/**
 * 竞态安全的搜索组件
 * 解决: 快速输入导致旧请求覆盖新结果的问题
 */
class RaceSafeSearch {
  constructor(inputElement, resultRenderer) {
    this.input = inputElement;
    this.renderer = resultElementRenderer;
    this.requestId = 0;         // 递增的请求 ID
    this.latestRequestId = 0;    // 最新确认的请求 ID
    this.controller = null;
  }
  
  start() {
    this.input.addEventListener('input', () => this.onInput());
  }
  
  onInput() {
    const query = this.input.value.trim();
    if (!query.length) return;
    
    this.requestId++;  // 新请求 ID
    
    // 取消上一次请求（如果有且还在跑的话）
    if (this.controller && !this.controller.signal.aborted) {
      this.controller.abort(`新搜索替代 (ID#${this.requestId})`);
    }
    
    this.controller = new AbortController();
    const currentRequestId = this.requestId;
    
    this.performSearch(query, this.controller.signal)
      .then(results => {
        // 🎯 关键检查：确保这是最新的请求
        if (currentRequestId >= this.latestRequestId) {
          this.latestRequestId = currentRequestId;
          this.renderer.render(results);
        }
        // 否则: 这是一个过期的旧请求，忽略其结果
      })
      .catch(err => {
        if (err.name !== 'AbortError' && currentRequestId >= this.latestRequestId) {
          this.renderer.showError(err.message);
        }
      });
  }
  
  async function performSearch(query, signal) {
    const response = await fetch(`/api/search?q=${encodeURIComponent(query)}`, {
      signal
    });
    
    if (!response.ok) throw new Error(`Search failed: ${response.status}`);
    return response.json();
  }
}

// 使用
new RaceSafeSearch(searchInput, resultsContainer).start();
```

**这段代码解决了什么？**

```
时间线:
  t=0ms   用户输入 "j"    → 请求 #1 发出 (ID=1)
  t=200ms 用户输入 "ja"   → 请求 #1 被取消! 请求 #2 发出 (ID=2)
  t=400ms 用户输入 "jav"  → 请求 #2 被取消! 请求 #3 发出 (ID=3)
  t=600ms 用户输入 "java"  → 请求 #3 被取消! 请求 #4 发出 (ID=4)
  ...
  t=1200ms 用户停止输入    → 请求 #N 完成 (ID=N)

  t=1300ms 请求 #N-1 返回 → 检查: N-1 < N → 忽略！（过期）
  t=1400ms 请求 #N   返回 → 检查: N === N ✓ → 显示结果！

只有最后一次搜索的结果会被显示，
中间所有的废弃请求都被及时取消了。
```

```javascript
const http = require('http');

const server = http.createServer(async (req, res) => {

  // 为每个请求设置超时

      controller.abort('Request timeout');
    }
  }, 5000);
  
  try {
    // 将超时信号传递给下游处理器
    const result = await handleRequest(url.pathname, controller.signal);
    
    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify(result));
    
  } catch (error) {
    if (error.code === 'ERR_ABORTED' || error.name === 'AbortError') {
      res.writeHead(504, { 'Content-Type': 'text/plain' });
      res.end('Gateway Timeout');
    } else {
      res.writeHead(500, { 'Content-Type': 'text/plain' });
      end('Internal Server Error');
    }
  }
});

async function handleRequest(pathname, signal) {
  switch (pathname) {
    case '/api/fast':
      return { data: 'fast response', timestamp: Date.now() };
      
    case '/api/slow':
      // 模拟慢接口
      await new Promise(r => setTimeout(r, 8000));  // 8秒
      
      // 在长时间操作中检查取消
      if (signal.aborted) throw Object.assign(new Error('Cancelled'), { code: 'ERR_ABORTED' });
      
      return { data: 'slow response', timestamp: Date.now() };
      
    default:
      return { error: 'Not found', code: 404 };
  }
};

server.listen(3000, () => console.log('Server running on :3000'));
```

### 7.2 定时任务的优雅停止

```javascript
/**
 * 可取消的定时调度器
 */
class CancelableScheduler {
  constructor() {
    this.timers = new Map();
    this.controllers = new Map();
  }
  
  /**
   * 安排一个定时任务（可取消）
   * @returns {Function} 取消该任务的函数
   */
  schedule(delay, task, taskId = Symbol('task')) {
    const timer = setTimeout(async () => {
      try {
        await task();
      } catch (err) {
        console.error(`任务 [${taskId.description}] 出错:`, err);
      }
      this.timers.delete(taskId);
      this.controllers.delete(taskId);
    }, delay);
    
    this.timers.set(taskId, timer);
    
    // 返回取消函数
    return () => {
      const timer = this.timers.get(taskId);
      if (timer) {
        clearTimeout(timer);
        this.timers.delete(taskId);
      }
      const ctrl = this.controllers.get(taskId);
      if (ctrl) ctrl.abort('任务被取消');
      this.controllers.delete(taskId);
    };
  }
  
  /**
   * 取消所有定时任务
   */
  cancelAll() {
    for (const [id, timer] of this.timers) {
      clearTimeout(timer);
      console.log(`⏹ 取消定时任务 [${id.description}]`);
    }
    for (const [, ctrl] of this.controllers) {
      ctrl.abort('全局取消');
    }
    this.timers.clear();
    this.controllers.clear();
  }
}

// 使用
const scheduler = new CancelableScheduler();

// 每30秒同步一次数据
const cancelSync = scheduler.schedule(30000, async () => {
  console.log('🔄 开始同步...', new Date().toLocaleTimeString());
  await syncToRemote();
  console.log('✅ 同步完成', new Date().toLocaleTimeString());
}, { description: '定时同步' });

// 每5分钟清理缓存
scheduler.schedule(300000, async () => {
  await cleanExpiredCache();
}, { description: '缓存清理' });
```

## 八、设计哲学与最佳实践

### 8.1 取消的三种策略

根据业务需求，选择合适的取消粒度：

| 策略 | 描述 | 适用场景 |
|------|------|---------|
| **即时取消 (Immediate)** | 调用 `abort()` 立即生效 | 用户主动点击取消、组件卸载 |
| **超时取消 (Timeout)** | 设定时限，超时自动取消 | 请求超时保护、防止死等 |
| **惰性取消 (Lazy)** | 不立即取消，但在消费结果前检查 | 竞态条件防御（搜索框）、批处理跳过已取消项 |
| **优雅降级 (Graceful)** | 取消主源后启动备用方案 | 主API失败切换CDN、本地缓存兜底 |

### 8.2 最佳实践清单

```javascript
// ✅ 推荐:

// 1. 组件卸载时总是清理异步操作

  const result = await doSearch(query);

  // ...

  } else {

  }
}

// 5. 资源密集型操作考虑使用 Web Worker + MessageChannel 取消

// 需要通过 postMessage 通信来协调取消
```

### 8.3 何时不需要取消？

并不是所有异步操作都需要取消能力。以下情况可以不加取消：

```javascript

await logEvent(event);  // 日志上报失败了也没关系
```

## 九、总结

### 9.1 AbortController API 速查表

| API | 类型 | 说明 |
|-----|------|------|
| `new AbortController()` | 构造函数 | 创建新的控制器实例 |
| `controller.signal` | 属性 (AbortSignal) | 控制器关联的信号对象 |
| `controller.abort(reason)` | 方法 | 触发中止信号（可传原因字符串） |
| `signal.aborted` | 属性 (boolean) | 是否已被中止 |
| `signal.reason` | 属性 (any) | 中止原因（传给 abort() 的参数） |
| `signal.addEventListener('abort', fn)` | 事件 | 注册中止监听器 |
| `fetch(url, { signal })` | fetch 参数 | 原生支持取消的请求 |

### 9.2 核心模式速查

| 模式 | 代码模式 | 典型场景 |
|------|---------|---------|
| **基础取消** | `ctrl.abort()` | 按钮取消、组件卸载 |
| **超时取消** | `setTimeout(() => ctrl.abort())` | 请求超时保护 |
| **竞态防御** | `reqId++ + if (latest < current) return` | 搜索框、路由切换 |
| **批量取消** | 多个请求共用同一 signal | 批量下载、批量上传 |
| **级联取消** | 父 signal 传递给子操作 | 多层级工作流 |
| **取消+重试** | abort 后换策略再试 | 主备源容错 |
| **Hook 封装** | `useCancellableRequest()` | React/Vue 组件复用 |

### 9.3 一句话总结

> **`AbortController` 给 JavaScript 的异步世界装上了"紧急停止按钮"。** 它的设计精髓在于**控制权（controller）与执行权（signal）的分离**——你不需要知道谁在执行任务，只需持有一个可以被观察的 `signal` 令牌。当你决定"不需要这个操作了"时，按下 `abort()` 按钮，信号就会沿着代码中预先布置好的传播链扩散开来，每个环节都能感知到取消事件并执行相应的清理工作。从 `fetch` 的原生集成，到 React/Vue 的生命周期管理，再到多层级的工作流传播，掌握取消模式意味着你的代码不再是"发了就不管"的甩手掌柜式风格，而是**有始有终、有责任心的成熟工程实践**。
