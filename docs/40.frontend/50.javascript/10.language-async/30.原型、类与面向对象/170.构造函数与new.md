# 构造函数与 new

## 为什么需要构造函数？

在 JavaScript 的世界里，对象是第一等公民。我们每天都在创建对象、使用对象、操作对象。最简单直接的创建方式是**对象字面量**：

```javascript
let user1 = {
  name: "张三",
  age: 25,
  greet() {
    console.log("你好，我是" + this.name);
  }
};

let user2 = {
  name: "李四",
  age: 30,
  greet() {
    console.log("你好，我是" + this.name);
  }
};
```

这种写法看起来没什么问题——但想象一下，你需要创建 **100 个用户对象**。每个对象都有相同的结构（`name`、`age`、`greet` 方法），只是数据不同。如果用字面量的方式写 100 遍，不仅代码冗余到令人窒息，更可怕的是：**`greet` 方法会被重复定义 100 次**！这就像你开了一家连锁餐厅，每家店都单独请了一位厨师，而实际上所有店用的都是同一份菜单——既浪费人力，又增加了管理成本，而且一旦菜单要改（比如某个菜品的配方更新了），你得通知 100 个厨师分别去改。

这就是**构造函数（Constructor）**要解决的核心问题：**提供一种可复用、可配置的对象创建模板**。它允许你定义一次"对象的蓝图"，然后通过传入不同的参数来批量生成结构相同但数据各异的对象实例。

### 构造函数的理论本质

从计算机科学的角度来看，构造函数实现了两个关键的设计目标：

1. **封装初始化逻辑**：将"如何创建一个完整对象"的步骤封装在一个地方，而不是散落在调用方的每一处代码里
2. **实现工厂模式**：同一个函数可以根据不同的输入参数，生产出具有相同接口但内部状态不同的多个产品

这与面向对象编程中的**工厂方法模式（Factory Method Pattern）**一脉相承。区别在于，JavaScript 的构造函数不需要显式声明"类"，它本身就是函数——只是恰好被 `new` 关键字调用了而已。《你不知道的 JavaScript》的作者 Kyle Simpson 在书中反复强调了一个重要观点："在 JavaScript 中，并不存在真正的'构造函数'，只存在'函数的构造调用'。"这句话的含义是深远的——它揭示了 JavaScript 的构造函数本质上没有任何特殊之处，特殊性完全来自于 `new` 操作符对函数调用方式的改变。

要真正理解为什么需要构造函数，我们必须从更深层的理论视角来审视这个问题。在软件工程中有一个核心原则叫做 **DRY（Don't Repeat Yourself，不要重复自己）**。这个原则告诉我们：系统中的每一份知识都应该有单一、明确、权威的表示。当我们在 100 个地方用字面量创建相似的对象时，我们实际上是在严重违反 DRY 原则——"如何创建一个用户对象"这份知识被分散到了 100 个不同的位置。

一旦需求发生变化（比如需要在用户对象上添加一个 `email` 属性或修改 `greet` 方法的逻辑），你就必须找到并修改全部 100 处代码。这不仅工作量巨大，而且极易遗漏某些位置，从而引入隐蔽的 bug。在实际的大型项目中，这种"散弹式修改"往往是导致系统逐渐变得难以维护的根本原因之一。构造函数通过**集中化对象创建逻辑**来优雅地解决这个问题——"如何创建一个用户对象"的知识只存在于一个地方（即构造函数体本身），任何修改只需要进行一次即可全局生效。

从**内存管理**和运行时性能的角度看，构造函数配合原型机制还能带来显著的内存优势。当我们把方法定义在构造函数的 `prototype` 上时，无论创建多少个实例，这些方法在内存中都只存在一份副本，所有实例通过 `[[Prototype]]` 链共享访问它们。而如果使用对象字面量的方式把方法写在每个对象内部，每个对象都要携带自己的方法副本。假设一个方法占用 200 字节的内存，创建 1000 个实例时，放在原型上只需要 200 字节，而写在对象内部则需要 200,000 字节——差距是 1000 倍！现代浏览器虽然会对相同函数文本做一些内部优化，但这种优化并不可靠，且对于复杂的方法对象来说，内存开销依然可观，同时垃圾回收器还需要额外的工作来清理这些大量重复的函数对象。

从**类型标识**和**代码语义**的角度看，构造函数为对象创建行为提供了一个明确的"信号"。当一个开发者看到 `new User()` 这样的代码时，他能立即明白这是在创建一个新的 User 类型实例；而当他看到一个普通的函数调用 `createUser()` 时，他可能需要查看函数实现才能确定返回值的结构和类型。这种语义上的清晰性在大规模团队协作中尤为重要——它能显著降低认知负荷，减少沟通成本和代码审查的时间。PascalCase 的命名约定（首字母大写）进一步强化了这个信号，就像医生穿白大褂、警察穿制服一样，是一种让代码"自解释"的社会契约。

此外，构造函数还天然支持 **`instanceof` 运算符**进行运行时类型检查。当你拿到一个来源不明的对象时，可以通过 `obj instanceof Constructor` 快速判断它是否是由某个构造函数创建的。这对于编写防御性代码、实现多态行为、以及构建类型化的 API 接口都非常重要。比如在一个处理多种数据类型的函数中，你可以根据 `instanceof` 结果走不同的分支逻辑；而在单元测试中，你可以用它验证工厂函数返回的对象是否符合预期的类型。普通工厂函数或字面量创建的对象则不具备这一能力（除非借助 `Symbol.hasInstance` 等高级特性手动实现，但这又增加了复杂度）。

最后，从**继承与扩展**的角度来看，构造函数提供了基于原型的继承机制。你可以轻松地让一个构造函数"继承"另一个构造函数的属性和方法，形成清晰的类型层级关系。这种能力在构建复杂的领域模型时不可或缺——比如 `Animal` → `Dog` → `GoldenRetriever` 这样的继承链，能够很好地表达现实世界中的泛化-特化关系（"是一个 / is-a"关系），同时也实现了代码的高度复用。子类可以复用父类的所有能力，只需专注于自己特有的行为，这是面向对象编程的核心优势之一。

### 通俗类比：模具与零件

把构造函数想象成工业生产中的**金属模具**：
- 模具本身不是最终产品，它只是一个"形状的描述"
- 你往模具里注入不同的原材料（参数），就能压出形状相同但材质/颜色各异的零件（对象实例）
- 每个零件都是独立的个体，修改一个不会影响其他零件
- 但所有零件共享同一套模具定义的"标准规格"（方法和属性结构）

为了更好地理解这一点，让我们用一个更加生活化的场景来说明。假设你是一家**连锁奶茶店的老板**，计划在城市里开 10 家分店。每家门店都需要：

- 店名（每家不同）
- 地址（每家不同）
- 店长姓名（每家不同）
- 一套标准的饮品制作流程（所有店完全相同）
- 一套标准的服务规范用语（所有店完全相同）
- 一套标准的收银操作流程（所有店完全相同）

如果你不用"构造函数"思维，而是每家店独立编写一套完整的运营手册，那么"如何制作珍珠奶茶"、"如何处理客户投诉"、"如何盘点库存"这些通用流程就会被重复书写 **10 份**。一旦你需要更新饮品配方（比如换一种茶叶基底），就得跑去 10 家店分别修改各自的手册——既耗时耗力，又极容易在某家店遗漏或写错。

但如果你采用"构造函数"思维——先在总部编写一本**《标准运营手册》**（相当于构造函数的 `prototype`），里面记录所有通用的流程和规范，然后每家新开店时只需填写一张**《门店信息卡》**（相当于传入构造函数的参数），上面记录该店特有的店名、地址、店长等信息。这样，当总部决定更新通用流程时，只修改《标准运营手册》一次即可全局生效；而各店的特有信息仍然保持独立，互不干扰。

更进一步说，这本《标准运营手册》在整个系统中物理上只存在 **一本**（存放在总部/原型上），所有店长都可以随时查阅参考。但如果把所有内容（包括通用流程）都各自抄写在每家店的《门店信息卡》上，那就等于每家店都要保存一本完整的手册副本——浪费纸张（内存空间）不说，一旦要更新，就是前面说的噩梦场景。

这就是构造函数的核心价值所在：**分离"变"与"不变"**。"不变"的部分（方法、共享行为、通用逻辑）放在原型上统一管理、统一维护；"变"的部分（实例特有的数据、个性化属性）通过参数传入，存储在每个实例自身。这种分离不仅提高了代码的可维护性和运行效率，也使得程序的结构更加清晰、更加符合人类的自然思维方式。当你理解了这一层设计哲学后，你会发现 JavaScript 的整个对象系统——从构造函数到原型链再到 class 语法糖——都是围绕这个核心理念构建的。

## 构造函数的基本语法

### 命名约定

JavaScript 社区有一个广为接受的命名惯例：**构造函数名使用 PascalCase（帕斯卡命名法/大驼峰），即首字母大写**。这不是语言强制要求（你完全可以写 `function user(name)` 然后用 `new` 调用它），但它是开发者之间的一种重要的社会契约和视觉信号：

```javascript
// 这是一个构造函数（首字母大写 —— 社区约定的信号）
function User(name, age) {
  this.name = name;
  this.age = age;
}

// 这是一个普通函数（首字母小写）
function createUser(name, age) {
  return { name, age };
}
```

这个约定的作用类似于交通标志或职业制服——当你看到 `User` 这个名字出现在代码中时，你的大脑会立刻激活一种预期："哦，这是一个要用 `new` 来调用的构造函数！"就像你在医院看到穿白大褂的人会本能地认为他是医生、在路口看到红灯会本能地停车一样。虽然不穿白大褂的人也可能医术高超，虽然闯红灯偶尔也不会出事，但这些视觉提示能大幅降低沟通成本和出错概率。在大型团队协作中，这种"一眼就能识别函数用途"的能力能够显著提高代码审查的效率和准确性。

从更深层的角度来看，这种命名约定体现了 **Humane Interface（人性化界面）** 的设计思想——好的代码不仅要能让机器正确执行，还要能让人类读者快速、准确地理解其意图。PascalCase 命名就是一种极其低成本的意图传达方式：仅通过大小写的差异，就能传递"此函数用于构造对象"这一重要信息，而不需要额外的注释或文档。

### 使用 new 调用

```javascript
function User(name, age) {
  // this = {} （隐式创建的新空对象）
  this.name = name;    // 给新对象添加 name 属性
  this.age = age;      // 给新对象添加 age 属性
  // return this; （隐式返回新对象）
}

let user = new User("张三", 25);
console.log(user.name); // "张三"
console.log(user.age);  // 25
console.log(user instanceof User); // true —— 确认 user 是 User 的实例
```

当你在函数调用前面加上 `new` 关键字时，JavaScript 引擎会自动执行一系列隐式操作，将一次普通的函数调用转变为一次"构造调用"。这个过程就像是给普通的函数披上了一件特殊的"外衣"，让它具备了创建和管理新对象的能力。下面我们来详细拆解 `new` 操作符到底做了什么。

## new 操作符的底层机制 —— 四大步骤

理解 `new` 到底做了什么是掌握构造函数的关键，也是理解整个 JavaScript 对象系统的基石。《你不知道的 JavaScript》明确指出：**"并不存在所谓的'构造函数'，只有对于函数的'构造调用'。"** 这句话的含义非常深刻：任何普通函数都可以被 `new` 调用，函数本身并没有什么特殊之处——特殊性完全来自 `new` 操作符的行为。换句话说，是 `new` 让函数变成了构造函数，而不是函数天生就是构造函数。

当一个函数被 `new` 调用时，JavaScript 引擎会在内部依次执行以下 **4 个关键步骤**：

### 步骤 1：创建一个全新的空对象

```javascript
// new 内部首先做了这件事：
let thisObj = Object.create(Object.prototype); // 或者简化理解为 let thisObj = {};
```

引擎会在堆内存（Heap）中分配一块连续的空间，创建一个全新的、空的普通对象。这个对象此时还是一张"白纸"——没有任何自有属性、没有方法、只有一个指向 `Object.prototype` 的默认 `[[Prototype]]` 链接。你可以把它想象成刚出厂的手机——硬件已经就位（内存已分配），但还没有安装任何应用、没有存储任何联系人信息、没有任何个性化设置。

这个步骤之所以必要，是因为 JavaScript 的对象在使用之前必须先"存在"。你不能给一个不存在的东西添加属性，所以引擎必须先"准备好容器"。值得注意的是，这个新对象的内部 `[[Prototype]]` 在这一步之后会被步骤 2 重新设置，这里创建的只是一个初始的空壳。

### 步骤 2：将新对象的 [[Prototype]] 连接到构造函数的 prototype 属性

```javascript
// 然后建立原型连接（这是最关键的一步！）：
Object.setPrototypeOf(thisObj, User.prototype);
// 或者用旧式的写法：
thisObj.__proto__ = User.prototype;
```

**这一步是整个 `new` 机制中最核心、最精妙的一步。** 它让新创建的对象可以通过**原型链（Prototype Chain）** 访问到构造函数 `prototype` 对象上定义的所有属性和方法。这意味着你可以把那些不需要每个实例各自保存一份的方法放到 `User.prototype` 上，从而实现所有实例的**方法共享**。

为什么这如此重要？让我们用一个直观的类比来理解：假设你是一家公司的 HR，你要给新入职的 100 名员工每人发一本《员工手册》。你有两种做法：

**做法 A（没有原型链）**：打印 100 本一模一样的《员工手册》，人手一本。好处是人手一册随时可查；坏处是要消耗 100 倍的纸张和印刷成本，而且如果公司政策变了，你得重新打印 100 本发给所有人替换。

**做法 B（有原型链）**：在公司前台放一本《员工手册》（公共版本），然后给每位员工发一把前台的钥匙（`__proto__` 指针）。员工需要查阅手册时，自己去前台翻阅即可。好处是只需要一本手册，节省了大量成本，而且政策变更时只需更新前台那一本；坏处是……其实没有什么明显的坏处（查找速度在现代引擎中已经极度优化过）。

JavaScript 的原型链就是"做法 B"的实现。每个实例对象都持有一把"钥匙"（`[[Prototype]]` / `__proto__`），指向其构造函数的 `prototype` 对象。当实例自身找不到某个属性或方法时，引擎就会自动顺着这把钥匙去找，直到找到为止或者到达链的末端（`null`）。这种机制既保证了数据的独立性（每个实例有自己的属性），又实现了方法的共享（所有实例共用原型上的方法），堪称一举两得的设计。

### 步骤 3：将新对象绑定到函数调用的 this

```javascript
// 接着执行构造函数体，this 指向新创建的对象：
User.call(thisObj, "张三", 25);
// 等价于：
// thisObj.name = "张三";
// thisObj.age = 25;
```

这是整个过程中**最关键、最神奇的一步**。构造函数体内的 `this` 不再指向全局对象（非严格模式下）或 `undefined`（严格模式下），而是指向那个刚刚在步骤 1 创建出来的新对象。所以当你在函数体内写 `this.name = name` 时，你实际上是在给新对象添加属性——而不是在给 `window` 添加属性（那将是灾难性的全局污染）！

`this` 绑定的改变是通过 `.call()` 或 `.apply()` 方法实现的。这两个方法是 `Function.prototype` 上的内置方法，允许你在调用函数时显式指定 `this` 的值。`new` 操作符在内部正是利用了这个能力，将新创建的对象作为 `this` 传给了构造函数。这也解释了为什么 `new` 绑定的优先级高于其他 `this` 绑定规则——因为 `new` 实际上是最后才执行 `.call()` 的操作。

为了更直观地理解这一步的作用，让我们看看如果没有正确的 `this` 绑定会发生什么：

```javascript
function User(name) {
  this.name = name;
  // 如果没有 new，在非严格模式下 this === window（浏览器环境）
  // 所以 window.name = name —— 全局变量被污染了！
}
User("测试"); // 没有 new！
console.log(window.name); // "测试" —— 全局对象被意外修改 😱
```

这就是为什么忘记写 `new` 会如此危险——构造函数内的 `this.name = name` 本意是"给新对象设置 name 属性"，但在没有 `new` 的情况下却变成了"给全局对象设置 name 属性"。步骤 3 的存在就是为了确保 `this` 始终指向正确的新对象，避免这种危险的全局污染。

### 步骤 4：处理返回值

```javascript
// 最后一步：决定最终返回什么
if (typeof result === 'object' && result !== null || typeof result === 'function') {
  return result;        // 如果构造函数显式返回了对象/函数，则返回该对象
} else {
  return thisObj;       // 否则返回新创建的对象
}
```

注意这里的条件判断逻辑。如果构造函数显式地返回了一个非原始值（即一个对象或函数），那么 `new` 表达式的结果将是那个返回的对象，而不是步骤 1 创建的新对象。如果返回的是原始值（数字、字符串、布尔值、`undefined`、`null`、`Symbol`、`BigInt`）或者根本没有 `return` 语句，那么 `new` 会自动返回步骤 1 创建的新对象。

这个"逃生舱"机制在某些高级场景中非常有用，后面我们会详细讨论它的实际应用。但从常规使用的角度来说，99% 的构造函数都不需要写 `return` 语句——`new` 会自动帮你处理好一切。

### 用代码模拟 new 行为

为了加深理解，也为了证明 `new` 确实只是几个可手动执行的步骤的组合，我们可以自己写一个函数来模拟 `new` 的行为：

```javascript
function myNew(Constructor, ...args) {
  // 步骤 1：创建新对象
  let obj = {};

  // 步骤 2：设置原型链接
  Object.setPrototypeOf(obj, Constructor.prototype);

  // 步骤 3：绑定 this 并执行构造函数
  let result = Constructor.apply(obj, args);

  // 步骤 4：处理返回值
  if (typeof result === 'object' && result !== null || typeof result === 'function') {
    return result;
  }
  return obj;
}

// 测试我们的模拟版本
function Foo(name) {
  this.name = name;
}
Foo.prototype.greet = function () {
  return "你好，我是" + this.name;
};

let foo = myNew(Foo, "测试");
console.log(foo.name);              // "测试"
console.log(foo.greet());           // "你好，我是测试"
console.log(foo instanceof Foo);    // true —— instanceof 也正常工作
```

这个模拟版本展示了 `new` 的全部核心机制。当然，真正的 `new` 操作符还会处理一些额外的边缘情况（如正确设置 `new.target` 等），但对于理解基本原理来说已经足够了。当你能亲手写出 `myNew` 并且理解其中每一个步骤的意义时，你就真正掌握了 `new` 操作符的本质——它不是魔法，只是一系列精心设计的、可预测的操作序列。

## this 在构造函数中的绑定规则

### 四条 this 绑定规则回顾

在第 2 章"this 全面解析"（《你不知道的 JavaScript》）中，作者详细阐述了 JavaScript 中 `this` 绑定的四条基本规则。理解这些规则的优先级关系对于掌握构造函数至关重要：

| 规则 | 触发条件 | this 指向 |
|------|---------|----------|
| **默认绑定** | 独立函数调用（`foo()`） | 严格模式：`undefined`；非严格模式：全局对象（`window` / `global`） |
| **隐式绑定** | `obj.method()` 形式的调用 | 点号前面的对象（`obj`） |
| **显式绑定** | 使用 `.call()` / `.apply()` / `.bind()` | 手动指定的第一个参数 |
| **new 绑定** | **`new` 调用函数** | **新创建的对象** |

这四条规则按照优先级从低到高排列。也就是说，如果一个函数同时满足多条规则的触发条件，**优先级最高的规则将胜出**。而 `new` 绑定的优先级是最高的——它会覆盖其他所有绑定方式。

### 优先级验证实验

让我们通过具体的代码来验证 `new` 绑定的优先级确实高于显式绑定（`.bind()`）：

```javascript
function Foo(something) {
  this.a = something;
  console.log("Foo 内部 this.a =", this.a);
}

let obj1 = { a: "来自 obj1 的值" };

// 尝试用 bind 把 this 强制绑定为 obj1
// bind 返回一个硬绑定的新函数
let boundFoo = Foo.bind(obj1);

// 但是 new 会覆盖 bind 的硬绑定！
let obj2 = new boundFoo("来自 new 的值");

console.log(obj2.a);   // "来自 new 的值" —— new 绑定获胜！
console.log(obj1.a);   // "来自 obj1 的值" —— obj1 完全未受影响
```

输出结果：
```
Foo 内部 this.a = 来自 new 的值
来自 new 的值
来自 obj1 的值
```

这个结果可能会让人感到意外甚至困惑：我们已经用 `bind` 硬编码了 `this` 为 `obj1`，`bind` 的目的不就是"永久锁定 this 的指向"吗？为什么 `new` 还能把它覆盖？

答案隐藏在 `bind` 的内部实现细节中：**`bind` 在创建硬绑定函数时，会检测该函数是否被 `new` 调用。如果是，`bind` 会主动放弃硬绑定，转而使用 `new` 创建的新对象作为 `this`**。这是一个精心设计的"安全阀"机制——它确保了即使你对一个函数使用了 `bind`，你依然可以通过 `new` 将其作为构造函数正常使用。ECMAScript 规范明确规定了这一行为，所以这不是某个引擎的特殊实现，而是语言标准的一部分。

### 通俗类比：多重指令系统

想象你在指挥一个机器人工作。机器人接收指令的方式有多种，每种方式对应一条 `this` 绑定规则：

- **默认绑定**：你没有给任何特定指令，机器人按出厂设置的默认程序行动（可能四处乱跑，因为默认程序不知道该做什么）。这就像直接调用 `foo()` 而没有任何上下文。
- **隐式绑定**：你说"跟着这个人走"，机器人就把注意力集中在指定的人身上。这就像 `obj.foo()` 中的 `obj` 为 `this` 提供了上下文。
- **显式绑定（bind）**：你给机器人贴了一个不可撕除的标签"永远跟着张三走"。看起来这次是铁板钉钉了。这就像 `let boundFoo = foo.bind(obj)`。
- **new 绑定**：你说"制造一个新的机器人，让它先做这些初始化动作"。这是一条更高层级的制造指令。

当你同时使用了 `bind` 和 `new` 时，相当于你既给机器人贴了"跟着张三走"的 `bind` 标签，同时又下达了"制造新机器人"的 `new` 指令。这时候 `new` 的指令优先级更高——它会覆盖 `bind` 的效果，让新机器人的 `this` 指向它自己（而不是张三）。这是因为"制造"是一个比"跟随"更根本的操作——你正在创造一个全新的实体，这个实体当然应该以自身为中心。

## 构造函数内部的 return 行为

这是一个非常重要但容易被初学者忽略的知识点。正常情况下，构造函数不需要写 `return` 语句——`new` 会自动返回步骤 1 创建的那个新对象。但如果构造函数中包含了 `return` 语句，情况就会变得微妙起来。

### 情况一：没有 return 或 return 原始值

```javascript
function Foo1(a) {
  this.a = a;
  // 场景 A：没有 return 语句
  // 场景 B：return undefined;
  // 场景 C：return 42;
  // 场景 D：return "hello";
  // 场景 E：return true;
  // 场景 F：return null;
  // 以上所有场景的效果都一样！
}

let f1 = new Foo1(100);
console.log(f1.a);            // 100
console.log(f1 instanceof Foo1); // true —— 返回的是 new 创建的新对象
console.log(typeof f1);       // "object"
```

**理论总结**：如果构造函数中没有 `return` 语句，或者 `return` 后面跟的是**原始值（Primitive Value）**——包括 `undefined`、数字、字符串、布尔值、`null`、`Symbol`、`BigInt`——那么这些返回值都会被**静默忽略**，`new` 表达式最终返回的仍然是步骤 1 中创建的那个新对象。`null` 虽然在某些情况下表现得像对象（`typeof null === 'object'` 是一个历史遗留 bug），但在 `return` 判断中它被当作原始值处理。

为什么原始值会被忽略？从设计哲学的角度来看，构造函数的目的是**创建对象**。如果你返回的是一个数字或字符串，这与构造函数的语义不符——调用者期望得到一个对象实例。因此 JavaScript 引擎选择忽略这些"不合理"的返回值，以保证 `new` 表达式的结果始终是一个对象（除非你显式返回了一个对象）。

### 情况二：return 一个对象

```javascript
function Foo2(a) {
  this.a = a;          // 这行确实执行了，但...
  return { b: "我是替代者", special: true };  // 这个对象会替代 new 创建的对象！
}

let f2 = new Foo2(100);
console.log(f2.a);       // undefined —— 新对象上的属性丢失了！
console.log(f2.b);       // "我是替代者" —— 得到的是 return 的对象
console.log(f2.special); // true
console.log(f2 instanceof Foo2); // false —— 不是 Foo2 的实例！
console.log(f2.constructor);     // [Function: Object] —— 继承自 Object
```

**理论总结**：如果构造函数显式返回了一个**对象**（包括普通对象、数组、函数、正则表达式、Date 实例等所有引用类型），那么 `new` 表达式返回的就是这个对象，而不是 `new` 内部在步骤 1 创建的那个新对象！这意味着步骤 1 创建的那个对象被"抛弃"了（如果没有其他引用指向它，它将被垃圾回收），步骤 3 中给 `this` 设置的所有属性也都白费了。

这种行为看似奇怪，但实际上是非常有用的设计。它提供了一个"逃生舱口"，允许构造函数在特殊情况下返回一个不同于常规实例的对象。这在实现某些高级设计模式（如单例模式、对象池模式、条件性创建等）时非常有价值。

### 实际应用场景

#### 应用一：单例模式（Singleton Pattern）

单例模式确保一个类在整个程序运行期间只有一个实例。利用构造函数的 `return` 对象行为，我们可以轻松实现这一模式：

```javascript
function DatabaseConnection(url) {
  // 检查是否已有实例 —— 如果有，直接返回已有实例
  if (DatabaseConnection.instance) {
    console.log("复用已有的数据库连接");
    return DatabaseConnection.instance;
  }

  // 第一次调用时，正常初始化
  this.url = url;
  this.connected = false;
  this.queryCount = 0;

  this.connect = function () {
    this.connected = true;
    console.log("✅ 已连接到数据库: " + this.url);
  };

  this.query = function (sql) {
    if (!this.connected) {
      throw new Error("数据库尚未连接");
    }
    this.queryCount++;
    console.log(`📤 执行查询 #${this.queryCount}: ${sql}`);
    return { rows: [], affectedRows: 0 };
  };

  this.disconnect = function () {
    this.connected = false;
    console.log("❌ 数据库连接已关闭");
  };

  // 缓存实例
  DatabaseConnection.instance = this;
  console.log("🆕 创建新的数据库连接");
}

// 第一次调用 —— 正常创建实例
let db1 = new DatabaseConnection("mysql://localhost/myapp");
db1.connect();
db1.query("SELECT * FROM users");
// 输出：
// 🆕 创建新的数据库连接
// ✅ 已连接到数据库: mysql://localhost/myapp
// 📤 执行查询 #1: SELECT * FROM users

// 第二次调用 —— 返回的是同一个实例！
let db2 = new DatabaseConnection("mysql://localhost/other_db");
// 输出：复用已有的数据库连接

console.log(db1 === db2); // true —— 它们是完全相同的对象！
db2.query("SELECT * FROM products"); // 查询计数继续累加
// 输出：📤 执行查询 #2: SELECT * FROM products
```

在这个例子中，无论调用多少次 `new DatabaseConnection()`，始终只会得到第一个创建的实例。这对于数据库连接池、全局配置管理器、日志记录器等需要全局唯一性的场景非常有用。第二次及之后的 `new` 调用虽然在语法层面触发了步骤 1~3（创建了新对象、设置了属性），但因为 `return` 返回了已有的实例，那些新建的对象都被丢弃了。

#### 应用二：基于参数的条件性对象创建

有时候我们需要根据输入参数的不同，返回不同类型的对象：

```javascript
function NumberWrapper(value) {
  // 场景 1：如果传入的已经是 NumberWrapper 实例，直接返回（防止重复包装）
  if (value instanceof NumberWrapper) {
    return value;
  }

  // 场景 2：如果是 NaN，返回一个包含特殊信息的对象
  if (typeof value === 'number' && isNaN(value)) {
    return {
      type: 'Special',
      description: 'NaN - Not a Number',
      originalValue: value,
      isSpecial: true,
      valueOf() { return 0; },
      toString() { return 'NaN'; }
    };
  }

  // 场景 3：如果是无穷大或无穷小
  if (!isFinite(value)) {
    return {
      type: 'Infinite',
      description: value > 0 ? '正无穷大' : '负无穷大',
      originalValue: value
    };
  }

  // 默认情况：正常的数值包装
  this.value = value;
  this.isInteger = Number.isInteger(value);
  this.type = 'Normal';
}

let n1 = new NumberWrapper(42);
console.log(n1.value);      // 42
console.log(n1.isInteger);  // true
console.log(n1.type);       // "Normal"

let n2 = new NumberWrapper(NaN);  // 返回特殊对象
console.log(n2.description); // "NaN - Not a Number"
console.log(n2.isSpecial);   // true

let n3 = new NumberWrapper(Infinity); // 返回无穷大对象
console.log(n3.description);  // "正无穷大"
console.log(n3.type);         // "Infinite"

let n4 = new NumberWrapper(n2);  // 直接返回 n2（防重复包装）
console.log(n4 === n2);         // true
```

### 通俗类比：工厂的特殊出口通道

让我们用一个工厂流水线的比喻来理解 `return` 的两种行为：

普通情况下，流水线生产出的零件都会从**"常规出口"**送出来（相当于 `new` 自动返回新对象）。这是 99% 产品走的路径——原材料进入→加工成型→常规出口→交付客户。

但是，如果你在流水线上安装了一条**"特殊传送带"（`return 对象`）**，并且满足触发条件时，产品就会被引导到这条特殊传送带上，绕过常规出口，从**"特殊出口"**送出来。客户拿到的产品可能是另一种规格的产品，甚至可能是从仓库里取出的现成品（如单例模式中的复用实例）。

关键细节在于：**只有当"产品"是一个完整的物件（对象）时，特殊出口才会生效**。如果传送带上放的是一些原材料碎片（原始值——如一颗螺丝、一块布料、一滴油漆），质量检测系统会说："这不构成一个有效产品"，然后把它们丢弃，产品仍然走常规出口。这就是为什么 `return 42` 或 `return "hello"` 会被忽略的原因。

## 构造函数与 prototype

### prototype 属性的本质

每一个 JavaScript 函数都有一个特殊的 `prototype` 属性。这是由语言的规格决定的——当你用 `function` 关键字声明一个函数时，引擎会自动为这个函数对象附加一个名为 `prototype` 的属性。对于普通函数来说，这个属性几乎不会被用到；但对于构造函数而言，这个属性至关重要——它是**所有由该构造函数创建的实例所共同连接的原型对象**。

```javascript
function User(name) {
  this.name = name;
}

// prototype 是一个普通的对象
console.log(typeof User.prototype);                // "object"
console.log(User.prototype.constructor === User);   // true —— 默认带有 constructor 属性
console.log(User.prototype);                       // { constructor: User } —— 这就是默认的原型对象
```

这里有几个关键点必须彻底搞清楚，它们构成了理解 JavaScript 原型系统的基础：

#### 要点 1：prototype 只存在于函数上，普通对象没有

```javascript
function Foo() {}
let obj = {};

console.log(typeof Foo.prototype);   // "object" —— 函数有 prototype 属性
console.log(typeof obj.prototype);   // "undefined" —— 普通对象没有 prototype 属性
```

这个区别经常让初学者困惑。记住一句话：**`prototype` 是函数的"专属财产"，普通对象没有资格拥有它**。普通对象有的是 `[[Prototype]]`（也叫 `__proto__`），这是另一回事——我们马上会详细讨论两者的区别。

#### 要点 2：函数的 prototype 和对象的 [[Prototype]]（__proto__）是两回事！

**这是初学者最容易混淆的两个概念，也是理解原型链最大的拦路虎。请务必彻底搞清楚它们的区别：**

```javascript
function User(name) {
  this.name = name;
}
let user = new User("张三");

// ====== 函数的 prototype ======
// 这是构造函数 User 自身的一个属性
// 它是一个普通对象，存放着所有 User 实例共享的方法和数据
console.log(User.prototype);
// 输出：{ constructor: User }

// ====== 实例对象的 __proto__（[[Prototype]]）=====
// 这是实例对象 user 的一个内部属性（指针）
// 它指向构造函数的 prototype 对象
console.log(user.__proto__);
// 输出：{ constructor: User }

// ====== 它们指向同一个对象！=======
console.log(User.prototype === user.__proto__); // true ✅ 这是最关键的等式！
```

让我们用一张图来理清这三者之间的关系：

```
User（构造函数 / 蓝图）
  │
  │  ← 拥有 prototype 属性
  │
  └───┬── User.prototype ──────────────────────┐
      │                                        │
      │  （原型对象 / 公共资源库）               │
      │  {                                     │
      │    constructor: User  ←── 指回构造函数   │
      │    greet: function() {...}  ←── 共享方法 │
      │    isAdult: function() {...}             │
      │  }                                      │
      │                         ▲                │
      │                         │                │
      │  通过 new 创建时        │ [[Prototype]]  │
      │  自动建立连接           │ (内部指针)      │
      │                         │                │
      └───┬── user（实例对象） ──┘                │
          │                                      │
          ├── name: "张三"  （自有属性）           │
          ├── age: 25       （自有属性）           │
          │                                      │
          └── __proto__ ─────────────────────────┘
             （对外暴露的 [[Prototype]] 访问接口）
```

从这个图中我们可以清晰地看出：

- **`User`** 是构造函数（蓝图），它有一个 `prototype` 属性
- **`User.prototype`** 是一个真实的对象（原型对象），它就像一个"公共工具箱"
- **`user`** 是通过 `new User()` 创建的实例（具体产品），它有一个 `__proto__` 属性（内部 `[[Prototype]]` 的公开访问方式）
- **`user.__proto__`** 和 **`User.prototype`** 指向的是**同一个对象**

#### 通俗类比：公司的组织架构

把上面的关系映射到一个公司的组织架构中会更加直观：

- **`User`（构造函数）**：好比是**公司的人力资源部（HR 部门）**——它负责制定招聘标准和入职流程，但它本身不是一个"员工"
- **`User.prototype`（原型对象）**：好比是**公司的公共培训资料库 / 内部知识库**——里面存放着《员工手册》《标准作业流程》《常见问题解答》等所有员工共享的文档和培训材料
- **`user`（实例对象）**：好比是**部门里的某位具体员工**——他有自己的工牌号（`name`）、工龄（`age`）、个人绩效评分等**私有信息**
- **`user.__proto__`**：好比是员工手中的**知识库访问权限 / 门禁卡**——通过这张卡，员工可以随时去查阅公共知识库中的资料

每个员工都有自己的私人物品和工作业绩（实例属性），这些是独立的、互不干扰的。但同时，所有员工都可以通过门禁卡去同一个知识库查阅共享资料（原型上的方法）。当知识库中的《标准作业流程》更新时，所有员工下次查阅时都能自动获取最新版本——无需逐个通知。这种设计既保证了每个人都有独立的数据空间，又避免了重复存储相同的信息，极大地节省了资源。

### 在原型上添加方法

理解了 `prototype` 的作用之后，让我们来看看如何在实践中使用它：

```javascript
function User(name, age) {
  // 这些属性放在实例上 —— 因为每个用户的姓名和年龄都不同
  this.name = name;
  this.age = age;
  this._createdAt = Date.now(); // 下划线前缀表示"内部属性"
}

// 这些方法放在原型上 —— 所有用户共用同一份方法实现
User.prototype.greet = function () {
  console.log(`你好，我是 ${this.name}，今年 ${this.age} 岁`);
};

User.prototype.isAdult = function () {
  return this.age >= 18;
};

User.prototype.getAgeInYears = function (targetYear) {
  const currentYear = new Date().getFullYear();
  const diff = targetYear - currentYear;
  return Math.max(0, this.age + diff);
};

User.prototype.toString = function () {
  return `[User: ${this.name}, ${this.age}岁]`;
};

// 创建多个实例
let u1 = new User("张三", 25);
let u2 = new User("李四", 15);
let u3 = new User("王五", 30);

// 调用方法 —— 注意方法来自原型，但 this 指向各个实例
u1.greet();            // "你好，我是 张三，今年 25 岁"
u2.greet();            // "你好，我是 李四，今年 15 岁"
u3.greet();            // "你好，我是 王五，今年 30 岁"

console.log(u1.isAdult()); // true —— 25岁算成年
console.log(u2.isAdult()); // false —— 15岁未成年
console.log(u3.isAdult()); // true

// 关键验证：方法是共享的！（所有实例的 greet 指向同一个函数对象）
console.log(u1.greet === u2.greet);     // true ✅ 同一个函数
console.log(u2.greet === u3.greet);     // true ✅ 还是同一个
console.log(u1.greet === u3.greet);     // true ✅ 全部相同
```

注意最后一组 `===` 比较的结果：三个实例的 `greet` 方法在内存中完全是**同一个函数对象**。这就证明了原型上的方法是被所有实例共享的——无论创建多少个 `User` 实例，`greet` 方法在内存中始终只占一份空间。

作为对比，我们来看看如果把方法写在构造函数内部会发生什么：

```javascript
function BadUser(name, age) {
  this.name = name;
  this.age = age;

  // ❌ 错误做法：每次创建实例都会创建一个新的函数对象
  this.greet = function () {
    console.log(`你好，我是 ${this.name}`);
  };
}

let b1 = new BadUser("A", 20);
let b2 = new BadUser("B", 30);

// 每个实例有自己的 greet 方法副本 —— 它们不是同一个函数！
console.log(b1.greet === b2.greet); // false ❌ 不相等！

// 更糟糕的是，每次 new 都会创建新的闭包和新的函数对象
// 创建 1000 个实例就有 1000 个 greet 函数副本在内存中
```

**性能差异分析**：假设一个方法对象占用约 200 字节的内存（包括函数代码、作用域链引用等），创建 1000 个用户对象时：

- **方法放在 prototype 上**：总内存消耗 = 1000 个实例对象（属性数据）+ **1 份**方法 ≈ 高效
- **方法写在构造函数内**：总内存消耗 = 1000 个实例对象（含属性数据）+ **1000 份**方法副本 ≈ 浪费 1000 倍方法内存

此外，垃圾回收器（GC）在回收这些废弃的函数对象时也需要额外的工作量。所以在创建大量实例的场景下，**方法务必放在 `prototype` 上**是一条不容妥协的最佳实践。

### constructor 属性

每个函数的 `prototype` 对象在被创建时，都会自动获得一个名为 `constructor` 的属性，它指回构造函数本身：

```javascript
function User(name) {
  this.name = name;
}

// constructor 存在于 prototype 上，指回构造函数
console.log(User.prototype.constructor === User); // true
console.log(User.prototype.constructor.name);     // "User" —— 可以获取构造函数的名字

let user = new User("测试");

// 通过原型链，实例也能访问到 constructor
console.log(user.constructor === User);     // true（继承自原型链）
console.log(user.constructor.name);         // "User"
```

`constructor` 属性的实用价值在于：当你拿到一个对象但不清楚它的"出身"时，可以通过 `instance.constructor` 找到创建它的构造函数，进而了解它的类型信息和创建方式。这在某些需要"反射"或"内省"的场景下很有用。

但需要特别注意的是：**`constructor` 并不像很多人以为的那样可靠！** 因为它本质上只是一个普通的、可以被随意修改或覆盖的属性：

```javascript
function Foo() {}

// ⚠️ 危险操作：用全新对象覆盖了 prototype
Foo.prototype = {
  // 新对象没有 constructor 属性！
  greet() { console.log("你好!"); }
};

let f = new Foo();

// constructor 属性丢失了！现在指向 Object
console.log(f.constructor === Foo);     // false ❌
console.log(f.constructor === Object);  // true —— 继承自 Object.prototype
console.log(f.constructor);             // [Function: Object]
```

为什么会变成 `Object`？因为当我们用 `{ greet() {} }` 这个字面量对象完全替换掉 `Foo.prototype` 时，这个新对象本身是没有 `constructor` 属性的。于是当访问 `f.constructor` 时，引擎沿着原型链向上查找，最终在 `Object.prototype` 上找到了 `constructor`（它指向 `Object`），于是就返回了 `Object`。

修复方法很简单——在覆盖 `prototype` 时手动补上 `constructor`：

```javascript
// 正确的做法：手动维护 constructor 的引用
Foo.prototype = {
  constructor: Foo,  // 手动补回来，保持引用的正确性
  greet() {
    console.log("你好!");
  }
};

let f2 = new Foo();
console.log(f2.constructor === Foo); // true ✅ 修复成功
```

## new.target：检测是否被 new 调用

ES6（ECMAScript 2015）引入了 `new.target` 这个元属性（meta-property），它允许你在函数内部检测该函数是否是通过 `new` 关键字调用的。这个名字看起来像是一个属性访问（`new.target`），但实际上它并不是任何对象的属性——它是一个语法层面的特殊标识符，只能在函数内部使用。

### 基本用法

```javascript
function User(name) {
  // new.target 的值取决于函数是如何被调用的
  if (!new.target) {
    throw new Error(`函数 User 必须通过 new 关键字调用，请使用: new User(...)`);
  }
  this.name = name;
  this.createdAt = Date.now();
}

// 正确的调用方式 —— 使用 new
try {
  let u1 = new User("张三");
  console.log(u1.name); // "张三" —— 正常工作 ✅
} catch (e) {
  console.error(e.message);
}

// 错误的调用方式 —— 忘记了 new
try {
  let u2 = User("李四");  // 没有 new！
} catch (e) {
  console.error(e.message); // "函数 User 必须通过 new 关键字调用..."
}
```

### new.target 的取值规则

`new.target` 的取值遵循以下简单规则：

- 当函数**通过 `new` 调用**时，`new.target` 的值为**当前被执行的构造函数本身**
- 当函数**作为普通函数调用**时（不加 `new`），`new.target` 的值为 **`undefined`**

```javascript
function testNewTarget() {
  console.log("new.target 的值:", new.target);
  console.log("new.target 的名称:", new.target?.name ?? "undefined");
}

testNewTarget();
// 输出：
// new.target 的值: undefined
// new.target 的名称: undefined

let instance = new testNewTarget();
// 输出：
// new.target 的值: [Function: testNewTarget]
// new.target 的名称: testNewTarget
```

### new.target 在继承链中的表现

当涉及类继承（class extends）时，`new.target` 的行为变得更加有趣且有用：

```javascript
class Parent {
  constructor() {
    console.log("Parent 构造函数中:");
    console.log("  new.target.name =", new.target?.name);
  }
}

class Child extends Parent {
  constructor() {
    super();  // 调用父类 Parent 的构造函数
    console.log("Child 构造函数中:");
    console.log("  new.target.name =", new.target?.name);
  }
}

class GrandChild extends Child {
  constructor() {
    super();
    console.log("GrandChild 构造函数中:");
    console.log("  new.target.name =", new.target?.name);
  }
}

// 用最底层的类来创建实例
let gc = new GrandChild();
```

输出结果：
```
Parent 构造函数中:
  new.target.name = GrandChild   ← 注意！不是 Parent！
Child 构造函数中:
  new.target.name = GrandChild   ← 也不是 Child！
GrandChild 构造函数中:
  new.target.name = GrandChild   ← 只有这里才是"显而易见"的
```

这个例子展示了一个微妙但极其重要的行为：**在整个继承链中，`new.target` 始终指向最初被 `new` 调用的那个最底层类**（即 `GrandChild`），而不是当前正在执行的构造函数（如 `Parent` 或 `Child`）。

这个特性的意义何在？它让框架和库的设计者可以在基类构造函数中精确知道**最终的实例化目标到底是哪个类**。这在某些高级场景中非常有价值——例如，基类可以根据 `new.target` 的值来做不同的初始化策略，或者某些依赖 `new.target` 的库（如某些 ORM 框架、依赖注入容器）可以利用它来实现智能的对象创建逻辑。

### 实际应用：安全的构造函数模式

利用 `new.target`，我们可以实现一种"安全模式"（Safe Constructor Pattern）——无论用户是否记得使用 `new`，函数都能正确地工作：

```javascript
function SafeUser(name) {
  // 如果检测到没有被 new 调用，自动帮用户补上 new
  if (!new.target) {
    console.log("⚠️ 检测到未使用 new，自动为你转换...");
    return new SafeUser(name);
  }

  // 正常的初始化逻辑
  this.name = name;
  this._id = Math.random().toString(36).substr(2, 9);
}

// 两种调用方式都能正确工作
let s1 = new SafeUser("用了 new 的用户");
let s2 = SafeUser("忘了 new 的用户");  // 内部自动帮你补上了 new

console.log(s1.name);                   // "用了 new 的用户"
console.log(s2.name);                   // "忘了 new 的用户"
console.log(s1 instanceof SafeUser);    // true
console.log(s2 instanceof SafeUser);    // true
console.log(typeof s1._id);             // "string"
console.log(typeof s2._id);             // "string"
```

很多 JavaScript 的内置对象采用了类似的容错策略，允许在不使用 `new` 的情况下也能正常创建实例：

```javascript
// 以下内置构造函数都不强制要求 new
let arr = Array(1, 2, 3);           // [1, 2, 3] —— 不需要 new
let obj = Object({ a: 1 });         // { a: 1 } —— 不需要 new
let date = Date();                  // 当前时间的字符串表示
let map = Map([['key', 'value']]);  // Map {"key" => "value"} —— 不需要 new
let set = Set([1, 2, 3]);           // Set {1, 2, 3} —— 不需要 new
let err = Error("出了点问题");        // Error: 出了点问题 —— 不需要 new
```

不过需要注意的是，ES6 的 `class` 语法**不允许**这种容错——如果你对一个 class 使用普通调用（不加 `new`），会直接抛出 `TypeError`。这是一种更严格、也更安全的设计选择：

```javascript
class ModernUser {
  constructor(name) {
    this.name = name;
  }
}

ModernUser("测试");
// TypeError: Class constructor ModernUser cannot be invoked without 'new'
```

## instanceof 运算符的原理

在深入探讨内置构造函数之前，有必要先理解 `instanceof` 运算符的工作原理——因为它是检验构造函数创建的对象的"身份证"的重要工具，也是后续讨论的基础。

### instanceof 的基本用法

`instanceof` 用于检查一个对象是否是某个构造函数的实例（或者说，对象的原型链中是否存在该构造函数的 `prototype`）：

```javascript
function User(name) {
  this.name = name;
}

let user = new User("张三");
let plainObj = { name: "李四" };

console.log(user instanceof User);      // true —— user 是 User 的实例
console.log(plainObj instanceof User);   // false —— 普通对象不是 User 的实例
console.log(user instanceof Object);    // true —— user 也是 Object 的实例（继承链顶端）
console.log([] instanceof Array);       // true
console.log([] instanceof Object);      // true —— 数组也是对象
```

### instanceof 的底层算法

`instanceof` 并不是什么魔法——它的底层算法可以用以下伪代码来表达：

```javascript
function myInstanceOf(instance, Constructor) {
  // 左侧必须是对象，右侧必须是函数
  if (typeof instance !== 'object' || instance === null) {
    return false;
  }
  if (typeof Constructor !== 'function') {
    throw new TypeError('Right-hand side of instanceof must be a function');
  }

  // 获取构造函数的 prototype
  let proto = Constructor.prototype;

  // 从实例的 [[Prototype]] 开始，沿链向上查找
  let currentObj = instance;
  while (currentObj !== null) {
    // 获取当前对象的原型
    currentObj = Object.getPrototypeOf(currentObj);

    // 如果找到了，说明在原型链上
    if (currentObj === proto) {
      return true;
    }
  }

  // 遍历完整个链都没找到
  return false;
}
```

翻译成通俗的语言：**`instanceof` 就是沿着对象的原型链一层一层往上找，看看能不能找到构造函数的 `prototype`。找到了返回 `true`，一直找到顶（`null`）还没找到就返回 `false`。**

```javascript
// 用自定义的 instanceof 来验证
function Animal() {}
function Dog() {}
Dog.prototype = Object.create(Animal.prototype); // Dog 继承 Animal

let dog = new Dog();

console.log(myInstanceOf(dog, Dog));     // true
console.log(myInstanceOf(dog, Animal));  // true —— Dog.prototype 在 Animal.prototype 之上
console.log(myInstanceOf(dog, Object));  // true —— 最顶层
console.log(myInstanceOf(dog, Array));   // false
```

### instanceof 与原型链的关系图

```
dog（实例对象）
 │
 │ __proto__
 ▼
Dog.prototype ────── myInstanceOf(dog, Dog)?  ✅ 找到了!
 │
 │ __proto__
 ▼
Animal.prototype ─── myInstanceOf(dog, Animal)?  ✅ 找到了!
 │
 │ __proto__
 ▼
Object.prototype ── myInstanceOf(dog, Object)?  ✅ 找到了!
 │
 │ __proto__
 ▼
null ─────────────── 到终点了，停止查找
```

### instanceof 的局限性

`instanceof` 有几个值得注意的局限性：

**1. 跨 realm（iframe/worker）失效**：

```javascript
// 在主页面中
let arr = [];
console.log(arr instanceof Array); // true

// 但如果在 iframe 中比较（iframe 有自己的全局环境和 Array 构造函数）
// iframe.contentWindow.Array !== window.Array
// 此时 arr instanceof iframe.contentWindow.Array 可能返回 false
```

解决方案是使用更可靠的 `Array.isArray()` 或 `Object.prototype.toString.call()`。

**2. 原型被篡改后结果不准确**：

```javascript
function Foo() {}
let f = new Foo();
console.log(f instanceof Foo); // true

// 如果有人恶意修改了原型链
Object.setPrototypeOf(f, null);
console.log(f instanceof Foo); // false —— 即使 f 确实是用 Foo 创建的！
```

**3. 无法区分原始类型**：

```javascript
console.log(42 instanceof Number);     // false —— 原始值不是 Number 的实例
console.log("hello" instanceof String); // false
console.log(true instanceof Boolean);   // false
```

## 内置构造函数

JavaScript 引擎在启动时会预定义一系列内置的构造函数，用于包装原始值、创建特定类型的对象或实现各种内置功能。了解它们的特性有助于写出更健壮、更符合语言习惯的代码。

### 原始类型的包装构造函数

JavaScript 有 7 种原始类型（primitive types）：`Undefined`、`Null`、`Boolean`、`Number`、`String`、`Symbol`、`BigInt`。其中，除了 `Undefined` 和 `Null`（它们没有对应的包装类型），其余 5 种都有对应的**包装构造函数（Wrapper Constructors）**：

```javascript
// ========== String 包装构造函数 ==========
let strPrimitive = "hello";           // 字符串原始值（primitive）
let strObject = new String("hello");  // String 包装对象（object）

console.log(typeof strPrimitive);           // "string"
console.log(typeof strObject);              // "object" —— 注意区别！
console.log(strPrimitive instanceof String); // false —— 原始值不是实例
console.log(strObject instanceof String);    // true —— 包装对象是实例


// ========== Number 包装构造函数 ==========
let numPrimitive = 42;
let numObject = new Number(42);

console.log(typeof numPrimitive);    // "number"
console.log(typeof numObject);       // "object"


// ========== Boolean 包装构造函数 ==========
let boolPrimitive = true;
let boolObject = new Boolean(true);

console.log(typeof boolPrimitive);   // "boolean"
console.log(typeof boolObject);      // "object"


// ========== Symbol（不能用 new！）==========
let sym = Symbol("id");               // ✅ 正确 —— 只能用函数调用形式
// let badSym = new Symbol("id");      // ❌ TypeError: Symbol is not a constructor


// ========== BigInt（同样不能用 new！）==========
let bigint = BigInt(9007199254740991); // ✅ 正确
// let badBigint = new BigInt(9007199254740991); // ❌ TypeError
```

**理论深度：为什么 Symbol 和 BigInt 不能用 `new`？**

这是因为 `Symbol` 和 BigInt 的设计目标是表示**不可变的、唯一的原始值**。如果允许 `new Symbol()` 或 `new BigInt()` 创建包装对象，就会引入歧义——你是想要原始值还是包装对象？而且包装对象的存在会导致 `===` 比较失败（`new String("x") === "x"` 是 `false`）、`typeof` 返回 `"object"` 而非 `"symbol"`/`"bigint"` 等一系列混乱。为了避免这些问题，JavaScript 规范直接禁止了对它们使用 `new`——它们的内部 `[[Construct]]` 方法被设置为 `undefined`，尝试调用会立刻抛出 `TypeError`。

### 重要警告：不要使用 new String() / new Number() / new Boolean()

在实际开发中，**强烈建议避免**使用 `new String()`、`new Number()`、`new Boolean()`。原因有很多，每一个都可能导致难以排查的 bug：

```javascript
// ====== 问题 1：条件判断陷阱 ======
let s = new String("");
if (s) {
  // 这里总是会执行！！
  // 因为 s 是一个对象，所有对象都是 truthy 的
  // 即使 s 是 new String("") —— 一个"空字符串"的对象包装
  console.log("字符串非空？不一定！这是个对象！");
}


// ====== 问题 2：严格等于（===）比较失败 ======
console.log(new String("hello") === "hello");  // false ❌
console.log(new String("hello") == "hello");   // true  （== 会触发类型转换）
// === 比较不会触发类型转换，对象永远不会严格等于原始值


// ====== 问题 3：typeof 判断失准 ======
console.log(typeof "hello");                 // "string" ✅
console.log(typeof new String("hello"));     // "object"  ❌ 不是 "string"！
// 这会让类型检查代码出错


// ====== 问题 4：意外的布尔转换 ======
let b = new Boolean(false);
if (b) {
  // 即使包装的是 false，这个分支也会执行！
  // 因为 b 是一个对象（truthy）
  console.log("等等...b 明明是 false 啊？！");
}
```

**推荐做法**：始终使用原始值的字面量形式，只在必要时依赖 JavaScript 引擎的**临时自动装箱（Autoboxing）**机制：

```javascript
let str = "hello";

// 当你调用方法时，引擎会"临时地"将原始值转换为对应的包装对象
// 调用结束后，临时对象立即被销毁（不被任何变量引用）
console.log(str.length);       // 5 —— 引擎临时创建 String 包装对象来访问 .length
console.log(str.toUpperCase()); // "HELLO" —— 同上
console.log(str.charAt(0));    // "h" —— 同上

// 整个过程对开发者透明，你不需要关心
// 这就是为什么原始值可以调用方法的原因！
```

**理论补充：自动装箱机制的详细过程**

当你在一个原始值上调用方法时（如 `"hello".toUpperCase()`），JavaScript 引擎内部会执行以下步骤：

1. 检测到原始值 `"hello"` 需要访问属性（`toUpperCase` 方法）
2. 临时创建一个对应的**包装对象**（`new String("hello")`）
3. 在这个临时包装对象上查找并调用 `toUpperCase` 方法
4. 获取返回值（`"HELLO"`）
5. **销毁临时包装对象**（因为没有变量引用它，GC 会回收）

整个过程在瞬间完成，开发者感知不到。这也是为什么原始值可以像对象一样使用点号调用方法的原因——**它们并非真的变成了对象，而是被引擎临时"包装"了一下**。

### 其他常用内置构造函数

除了包装构造函数之外，JavaScript 还提供了许多实用的内置构造函数：

```javascript
// ========== Array 构造函数 ==========
let arr1 = new Array(1, 2, 3);    // [1, 2, 3] —— 传入多个元素
let arr2 = new Array(3);          // [, , ,] ⚠️ 注意！单个数字表示"长度"而非元素
let arr3 = new Array("3");        // ["3"] —— 字符串不受影响
let arr4 = Array.of(3);           // [3] —— 安全的方式，总是创建包含该元素的数组
let arr5 = Array.from("hello");   // ["h", "e", "l", "l", "o"] —— 从可迭代对象创建


// ========== Object 构造函数 ==========
let obj1 = new Object({ a: 1 });  // { a: 1 }
let obj2 = Object({ a: 1 });      // 同上（不需要 new 也可以）
let obj3 = new Object(null);      // {} —— 普通空对象
let obj4 = Object.create(null);   // 真·无原型的空对象（没有 toString 等方法）


// ========== Function 构造函数（动态创建函数）==========
let fn = new Function('a', 'b', 'return a + b');
```

## 原型链完整机制深度解析

在掌握了构造函数、`new` 操作符和 `prototype` 之后，让我们把这些概念串联起来，形成一个完整的、关于 JavaScript 原型链运作机制的系统性认识。

### 什么是原型链？

原型链（Prototype Chain）是 JavaScript 实现**属性查找**和**继承**的核心机制。它的基本思想是：当一个对象自身不包含某个属性或方法时，JavaScript 引擎不会立即放弃，而是会沿着一个预定义的"链条"向上搜索，直到找到该属性或者到达链条的尽头（`null`）为止。

这个"链条"是由每个对象内部的 `[[Prototype]]` 属性（通过 `__proto__` 或 `Object.getPrototypeOf()` 访问）串联起来的。每个对象的 `[[Prototype]]` 都指向另一个对象（或 `null`），这样就形成了一棵倒置的树形结构——或者说，一条条从下往上的"查找路径"。

### 原型链的构建过程

让我们追踪一下 `new User("张三")` 执行时，原型链是如何一步步建立起来的：

```javascript
function User(name) {
  this.name = name;
}

User.prototype.greet = function () {
  return `你好，${this.name}`;
};

let user = new User("张三");
```

在这个过程中发生的原型链构建如下：

```
第 1 步：引擎发现 User 是一个函数，它有一个 prototype 属性
         User.prototype = { constructor: User }

第 2 步：new 创建了一个空对象 user
         user = {}

第 3 步：new 将 user 的 [[Prototype]] 链接到 User.prototype
         user.__proto__ === User.prototype ✅

第 4 步：执行 User 构造函数，this = user
         user.name = "张三"

第 5 步：返回 user

最终的原型链结构：
user ──→ User.prototype ──→ Object.prototype ──→ null
```

当我们在 `user` 上访问 `greet` 方法时：

```javascript
user.greet()
```

引擎的查找过程是这样的：

1. **检查 `user` 自身**：有没有 `greet` 属性？→ **没有**（`user` 只有 `name`）
2. **沿着 `[[Prototype]]` 向上走到 `User.prototype`**：有没有 `greet`？→ **有了！** → 返回这个方法
3. 执行 `greet` 方法，此时 `this` 指向 `user`（调用方），所以输出 "你好，张三"

如果我们访问 `user.toString()` 呢？（我们没有在 `User.prototype` 上定义 `toString`）

1. **检查 `user` 自身**：没有 `toString`
2. **检查 `User.prototype`**：没有 `toString`
3. **继续向上走到 `Object.prototype`**：有 `toString`！ → 返回这个方法
4. 执行 `toString()`，输出类似 `"[object Object]"`

这就是原型链的威力——**属性和方法不需要在每个对象上都存在，只要在链上的某一层存在就可以被所有下游对象共享访问**。

### 原型链的写入规则：屏蔽（Shadowing）

前面讲的都是属性的**读取**过程。那么**写入**（赋值）呢？这是一个非常重要的区别：

**原型链只参与属性读取，不参与属性写入！** 当你对一个对象的属性进行赋值时，如果该属性在原型上存在，它不会修改原型上的值，而是在对象自身创建一个新的同名属性——这叫做**属性屏蔽（Property Shadowing）**：

```javascript
function Animal() {}
Animal.prototype.species = "未知物种";
Animal.prototype.describe = function () {
  return `${this.name} 属于 ${this.species} 种`;
};

let cat = new Animal();
cat.name = "小花";

// 读取 species —— 自身没有，去原型上找
console.log(cat.species);  // "未知物种" —— 来自 Animal.prototype
console.log(cat.describe()); // "小花 属于 未知物种"

// 写入 species —— 在自身创建新属性，不影响原型
cat.species = "猫科动物";
console.log(cat.species);  // "猫科动物" —— 来自自身（屏蔽了原型的值）
console.log(Animal.prototype.species); // "未知物种" —— 原型没变！

// describe 方法中 this.species 现在读取的是自身的值
console.log(cat.describe()); // "小花 属于 猫科动物"
```

**为什么这样设计？** 试想如果写入操作会影响原型，那么任何一个实例的修改都会影响到所有其他实例——这将是一场灾难。`cat.species = "猫科动物"` 不应该影响 `dog` 或 `bird` 的 `species` 值。属性屏蔽机制保护了实例之间的数据独立性。

**唯一的例外：Setter**。如果原型上的属性是一个访问器属性（有 setter），那么赋值操作会调用 setter 而不是创建屏蔽属性：

```javascript
function User(firstName, lastName) {
  this.firstName = firstName;
  this.lastName = lastName;
}

// 在原型上定义 fullName 的 getter/setter
Object.defineProperty(User.prototype, 'fullName', {
  get() {
    return `${this.firstName} ${this.lastName}`;
  },
  set(value) {
    // setter 中的 this 指向赋值的对象（admin）
    const parts = value.split(' ');
    this.firstName = parts[0] || '';
    this.lastName = parts[1] || '';
  },
  enumerable: true
});

let admin = new User("张", "三");
console.log(admin.fullName); // "张 三"

// 这里触发了原型上的 setter！
admin.fullName = "李 四";
console.log(admin.firstName);  // "李" —— 被 setter 修改了
console.log(admin.lastName);   // "四" —— 被 setter 修改了
```

### for...in 循环与原型链

在遍历对象属性时，原型链的行为也需要特别注意：

```javascript
function Animal() {}
Animal.prototype.eats = true;
Animal.prototype.walks = true;

let rabbit = new Animal();
rabbit.jumps = true;

// for...in 会遍历自身属性 + 原型链上所有的可枚举属性
for (let key in rabbit) {
  console.log(key);  // 输出: jumps, eats, walks（包含继承的属性）
}

// Object.keys 只返回自身的可枚举属性
console.log(Object.keys(rabbit)); // ["jumps"]

// Object.values 同样只返回自身的值
console.log(Object.values(rabbit)); // [true]

// 如何过滤掉继承的属性？
for (let key in rabbit) {
  if (rabbit.hasOwnProperty(key)) {
    console.log('自身:', key);    // "jumps"
  } else {
    console.log('继承:', key);    // "eats", "walks"
  }
}
```

### 经典易错案例：共享的可变状态

这是一个非常经典的原型链陷阱——**如果在原型上放置了可变的引用类型数据（如数组、对象），所有实例可能会意外地共享状态**：

```javascript
// ❌ 错误示范：把可变状态放在原型上
function Hamster() {}
Hamster.prototype.stomach = [];  // 胃 —— 放在原型上了！

Hamster.prototype.eat = function(food) {
  // push 操作修改的是 stomach 数组本身
  // stomach 不在实例自身，所以去原型上找
  // 找到了！然后就往原型的数组里 push 了
  this.stomach.push(food);
};

let speedy = new Hamster();  // 仓鼠"快快"
let lazy = new Hamster();    // 仓鼠"懒懒"

speedy.eat("苹果");
speedy.eat("胡萝卜");

console.log(speedy.stomach);  // ["苹果", "胡萝卜"]
console.log(lazy.stomach);    // ["苹果", "胡萝卜"]  😱 ？？？
// 懒懒明明什么都没吃啊！为什么它的胃里也有食物？
```

**原因分析**：`stomach` 数组存在于 `Hamster.prototype` 上，所有实例共享同一个数组。当 `speedy.eat("苹果")` 执行时，`this.stomach.push("苹果")` 中的 `this.stomach` 经过原型链查找到的是同一个数组对象，所以 push 操作直接影响到了所有实例。

**解决方案 1：确保每个实例有自己的 stomach**：

```javascript
function GoodHamster() {
  this.stomach = [];  // 在构造函数中初始化 —— 每个实例有自己的胃
}

GoodHamster.prototype.eat = function(food) {
  this.stomach.push(food);  // this.stomach 现在是实例自身的属性
};

let h1 = new GoodHamster();
let h2 = new GoodHamster();

h1.eat("坚果");
console.log(h1.stomach);  // ["坚果"]
console.log(h2.stomach);  // [] —— 空的，正确！✅
```

**解决方案 2：在方法中使用赋值代替直接修改**：

```javascript
function BetterHamster() {}
BetterHamster.prototype.stomach = [];

BetterHamster.prototype.eat = function(food) {
  // 先用 = 赋值（这会在自身创建属性，屏蔽原型）
  // 然后再操作
  this.stomach = this.stomach.slice(); // 复制一份到自身
  this.stomach.push(food);
};
```

**经验法则**：**永远不要在原型上放置可变的共享状态（数组、对象）**。原型上只应该放不变的数据（如常量）和方法的定义。每个实例独有的可变数据应该在构造函数中初始化。

### 示例 2：任务队列（Task Queue）

```javascript
/**
 * Task —— 任务构造函数
 * 用于构建异步任务管理系统
 */
function Task(name, handler, priority) {
  this.id = Task.nextId++;
  this.name = name;
  this.handler = handler;  // 异步处理函数
  this.priority = priority || 0;  // 数字越大越优先
  this.status = "pending";  // pending | running | completed | failed
  this.createdAt = Date.now();
  this.completedAt = null;
  this.error = null;
  this.result = null;
}

Task.nextId = 1;  // 自增 ID 计数器（静态属性）

Task.prototype.run = async function () {
  this.status = "running";
  try {
    this.result = await this.handler();  // 执行异步处理器
    this.status = "completed";
    this.completedAt = Date.now();
  } catch (err) {
    this.status = "failed";
    this.error = err.message;
  }
};

Task.prototype.getDuration = function () {
  if (!this.completedAt) return null;
  return ((this.completedAt - this.createdAt) / 1000).toFixed(2) + "s";
};

Task.prototype.toString = function () {
  return `[#${this.id}] ${this.name} (优先级: ${this.priority}★) - [${this.status}]`;
};


/**
 * TaskQueue —— 任务调度器
 */
function TaskQueue(maxConcurrency) {
  this.tasks = [];              // 待执行任务队列
  this.maxConcurrency = maxConcurrency || 3;  // 最大并发数
  this.runningCount = 0;       // 正在运行的任务数
  this.completedTasks = [];    // 已完成任务列表
  this.failedTasks = [];       // 失败任务列表
}

TaskQueue.prototype.add = function (task) {
  if (!(task instanceof Task)) {
    throw new Error("只能添加 Task 类型的任务");
  }
  this.tasks.push(task);
  // 按优先级排序（高优先级的排前面）
  this.tasks.sort((a, b) => b.priority - a.priority);
  return this;  // 支持链式调用: queue.add(a).add(b).add(c)
};

TaskQueue.prototype.process = async function () {
  while (this.tasks.length > 0 && this.runningCount < this.maxConcurrency) {
    const task = this.tasks.shift();  // 取出最高优先级的任务
    this.runningCount++;

    await task.run().then(() => {
      this.runningCount--;
      if (task.status === "completed") {
        this.completedTasks.push(task);
      } else if (task.status === "failed") {
        this.failedTasks.push(task);
      }
      this.process();  // 递归处理下一个任务
    });
  }
};

TaskQueue.prototype.getStatus = function () {
  return {
    total: this.nextId - 1,
    pending: this.tasks.length,
    running: this.runningCount,
    completed: this.completedTasks.length,
    failed: this.failedTasks.length
  };
};


// ====== 使用示例 ======
async function demoTaskQueue() {
  let queue = new TaskQueue(2);

  queue
    .add(new Task("备份数据库", async () => {
      await new Promise(r => setTimeout(r, 2000));
      return "备份完成";
    }, 10))
    .add(new Task("发送邮件通知", async () => {
      await new Promise(r => setTimeout(r, 500));
      return "邮件发送完成";
    }, 5))
    .add(new Task("清理缓存", async () => {
      await new Promise(r => setTimeout(r, 300));
      return "缓存清理完成";
    }, 3))
    .add(new Task("生成报告", async () => {
      await new Promise(r => setTimeout(r, 800));
      return "报告生成完毕";
    }, 8));

  await queue.process();
  console.log(queue.getStatus());
}
```

### 示例 3：事件发射器（EventEmitter）

事件发射器是 Node.js 和前端框架中最基础也最重要的设计模式之一。下面我们用构造函数来实现一个简化版的 EventEmitter：

```javascript
/**
 * EventEmitter —— 事件发射器
 * 实现发布-订阅（Publish-Subscribe）模式
 */
function EventEmitter() {
  this._events = {};  // 事件名 → 监听器数组的映射表
}

// 订阅事件
EventEmitter.prototype.on = function (event, listener) {
  if (typeof listener !== 'function') {
    throw new TypeError("监听器必须是一个函数");
  }
  if (!this._events[event]) {
    this._events[event] = [];
  }
  this._events[event].push(listener);
  return this;  // 支持链式调用
};

// 取消订阅
EventEmitter.prototype.off = function (event, listener) {
  if (!this._events[event]) return this;
  this._events[event] = this._events[event].filter(fn => fn !== listener);
  // 如果某个事件没有监听器了，清理掉节省内存
  if (this._events[event].length === 0) {
    delete this._events[event];
  }
  return this;
};

// 触发事件
EventEmitter.prototype.emit = function (event, ...args) {
  if (!this._events[event]) return false;

  // 复制一份监听器数组，防止在遍历过程中被修改
  const listeners = this._events[event].slice();
  listeners.forEach(fn => {
    try {
      fn.apply(this, args);
    } catch (err) {
      console.error(`[EventEmitter] 事件 "${event}" 的处理器抛出错误:`, err);
      // 选择：是否要让一个监听器的错误影响其他监听器的执行？
      // 这里选择不中断，继续执行其余监听器
    }
  });

  return true;
};

// 订阅一次性事件（触发后自动移除）
EventEmitter.prototype.once = function (event, listener) {
  const self = this;
  const wrapper = function (...args) {
    listener.apply(this, args);
    self.off(event, wrapper);  // 执行完后自动取消订阅
  };
  wrapper._originalListener = listener;  // 保留原始函数的引用
  return this.on(event, wrapper);
};

// 获取事件的监听器数量
EventEmitter.prototype.listenerCount = function (event) {
  return this._events[event] ? this._events[event].length : 0;
};

// 移除某事件的所有监听器
EventEmitter.prototype.removeAllListeners = function (event) {
  if (event) {
    delete this._events[event];
  } else {
    this._events = {};  // 清空全部事件
  }
  return this;
};


// ====== 使用示例 ======
const emitter = new EventEmitter();

// 定义事件处理函数
function onLogin(user) {
  console.log(`🔐 用户 "${user}" 登录了系统`);
}

function logLoginEvent(user) {
  console.log(`📊 [审计] 记录登录事件: 用户=${user}, 时间=${new Date().toISOString()}`);
}

// 订阅事件
emitter.on("login", onLogin);
emitter.on("login", logLoginEvent);
console.log(emitter.listenerCount("login")); // 2

emitter.once("firstLaunch", () => {
  console.log("🎉 这是首次启动！");
});

// 触发事件
emitter.emit("login", "admin");
// 输出：
// 🔐 用户 "admin" 登录了系统
// 📊 [审计] 记录登录事件: 用户=admin, 时间=...

emitter.emit("login", "guest");
// 输出：
// 🔐 用户 "guest" 登录了系统
// 📊 [审计] 记录登录事件: 用户=guest, 时间=...

emitter.emit("firstLaunch");  // 输出: 🎉 这是首次启动！
emitter.emit("firstLaunch");  // 无输出 —— 已经被自动移除了

// 取消订阅
emitter.off("login", logLoginEvent);
emitter.emit("login", "tester");
// 输出：
// 🔐 用户 "tester" 登录了系统
// （不再输出审计日志了）
```

## 常见陷阱与最佳实践

### 陷阱 1：忘记使用 new

这是构造函数最常见的错误之一，后果也非常严重。如果不小心漏掉了 `new`，在**非严格模式**下，构造函数内部的 `this` 会指向**全局对象**（浏览器中是 `window`，Node.js 中是 `global`），导致严重的全局变量污染：

```javascript
function User(name) {
  this.name = name;  // 没有 new 时，this === window（非严格模式）
  this.email = name + "@example.com";
}

// 忘记了 new！
let user = User("张三");
console.log(user);         // undefined —— 函数没有 return，默认返回 undefined
console.log(window.name);  // "张三" —— 全局对象被污染了！😱
console.log(window.email); // "zhangsan@example.com" —— 又一个全局变量！
```

这种 bug 特别危险，因为它**不会立即报错**——代码看起来正常运行了，但实际上在悄悄地污染全局命名空间，可能在很久以后引发莫名其妙的冲突和行为异常。

**防御方案**：

```javascript
// 方案 1：使用 new.target 检测（ES6+ 推荐）
function SafeUser(name) {
  if (!new.target) {
    throw new Error(`SafeUser 必须通过 new 关键字调用: new SafeUser(...)`);
  }
  this.name = name;
}

// 方案 2：自纠正模式（兼容 ES5）
function SelfCorrectingUser(name) {
  // 如果 this 不是自己的实例，说明没有用 new
  if (!(this instanceof SelfCorrectingUser)) {
    return new SelfCorrectingUser(name);  // 自己补上 new
  }
  this.name = name;
}

// 方案 3：使用 class 语法（ES6+ 最推荐）
// class 默认要求 new 调用，忘记 new 会直接抛出 TypeError
class ModernUser {
  constructor(name) {
    this.name = name;
  }
}
```

### 陷阱 2：在构造函数中返回原始值

虽然前面提到过 `return` 的行为，但这个问题太常见了，值得再次强调：**千万不要在构造函数中返回原始值——它不会有任何效果，只会让阅读你代码的其他开发者困惑**：

```javascript
function ConfusingConstructor(value) {
  this.value = value * 2;
  return 42;  // ⚠️ 这个 42 会被静默忽略！没有任何意义！
}

let c = new ConfusingConstructor(10);
console.log(c.value); // 20（不是 42！return 被忽略了）
```

如果你的本意是想返回计算结果，那构造函数不是合适的工具——应该使用**普通函数**。构造函数的职责是创建和初始化对象，而不是计算和返回值。

### 陷阱 3：在构造函数中不当使用箭头函数

箭头函数没有自己的 `this`——它会从外层词法作用域继承 `this`。在构造函数中使用箭头函数需要格外小心：

```javascript
// ⚠️ 危险用法：箭头函数作为实例方法
function BadExample(items) {
  this.items = items || [];

  // 箭头函数的 this 不会绑定到新创建的实例！
  // 它会从外层作用域继承 this（通常是 window 或 undefined）
  this.addItem = (item) => {
    this.items.push(item);  // 这里的 this 可能不对！
  };
}

let bad = new BadExample(["a"]);
bad.addItem("b");  // 可能在非严格模式下污染了 window.items

// ✅ 正确做法：使用普通函数
function GoodExample(items) {
  this.items = items || [];

  this.addItem = function (item) {
    // 普通 function 的 this 由调用方式决定
    // 通过 new 调用时，this 绑定到新实例
    this.items.push(item);
  };
}

let good = new GoodExample(["x"]);
good.addItem("y");
console.log(good.items); // ["x", "y"] ✅
```

不过有一种特殊情况——**箭头函数用作回调时反而能正确捕获 `this`**，这正是箭头函数的优势场景：

```javascript
function Timer(delay) {
  this.delay = delay;
  this.count = 0;

  // ✅ 这里箭头函数很合适！
  // 因为它从外层（构造函数作用域）继承了正确的 this
  setInterval(() => {
    this.count++;  // this 指向 Timer 实例
    console.log(`⏱️ 计时: ${this.count}秒`);
  }, delay);
}

let timer = new Timer(1000);
// 每秒输出一次计时 —— this 正确绑定到 timer 实例
```

**经验法则**：在构造函数中，如果需要一个方法将来作为回调函数被异步调用（如 `setTimeout`、事件监听器、Promise.then 等），使用箭头函数可以方便地捕获正确的 `this`。但如果是一个普通的实例方法（需要通过 `instance.method()` 调用的），应该使用普通 `function`。

### 陷阱 4：构造函数承担过多职责

构造函数应该只负责**轻量级的同步初始化**——创建对象、设置初始属性值。它不应该包含复杂的业务逻辑、I/O 操作、网络请求、大量计算等：

```javascript
// ❌ 反面示例：构造函数做了太多事情
function BadService(apiUrl) {
  // 在构造函数中进行网络请求？！
  fetch(apiUrl)
    .then(res => res.json())
    .then(data => {
      this.data = data;  // 异步赋值 —— 对象创建时 data 还是 null
    })
    .catch(err => {
      console.error("加载失败:", err);
    });

  // 大量的同步计算
  for (let i = 0; i < 1000000; i++) {
    // 重计算某些东西...
  }

  // 对象创建时间很长，阻塞主线程！
}

// ✅ 正确做法：分离初始化和配置
function GoodService(config) {
  // 只做轻量级的同步初始化
  this.config = config;
  this.data = null;
  this.initialized = false;
  this.error = null;
}

GoodService.prototype.init = async function () {
  try {
    const response = await fetch(this.config.apiUrl);
    this.data = await response.json();
    this.initialized = true;
    return this;  // 支持链式调用: new Service(cfg).init().then(...)
  } catch (err) {
    this.error = err.message;
    this.initialized = false;
    throw err;
  }
};

// 使用方式清晰明了
let service = new GoodService({ apiUrl: "/api/data" });
service.init()
  .then(s => console.log("服务初始化完成:", s.data))
  .catch(err => console.error("服务初始化失败:", err));
```

### 最佳实践清单

| 做法 | 说明 | 原因 |
|------|------|------|
| **PascalCase 命名** | 构造函数名首字母大写（如 `User`, `HttpRequest`） | 明确的视觉信号，防止遗漏 `new`，社区共识 |
| **方法放原型上** | 共享方法定义在 `prototype` 上 | 节省内存（只存一份），支持动态扩展，所有实例即时获得新方法 |
| **数据放实例上** | 每个实例独有的数据用 `this.xxx = ...` 定义 | 保证数据独立性，避免实例间相互干扰 |
| **使用 class** | ES6+ 项目优先使用 class 语法 | 自动 new 检测（忘写 new 直接报错），语义更清晰，继承语法简洁 |
| **避免 new String/Number/Boolean** | 使用原始值字面量（`""`, `42`, `true`） | 避免 typeof 失准、=== 比较失败、条件判断陷阱 |
| **考虑工厂函数替代** | 对于不需要原型继承的场景 | 更灵活、更安全（不需要 new）、可通过闭包实现真正的私有变量 |
| **防御性 new 检测** | 在构造函数开头检查 `new.target` | 兼容 ES5 时的安全保障，提供清晰的错误信息 |
| **保持构造函数精简** | 只做同步、快速的状态初始化 | 避免阻塞主线程，便于错误处理，职责分离 |

## 工厂函数 vs 构造函数

### 什么是工厂函数？

工厂函数（Factory Function）是指**任何返回新对象的函数**——它不需要 `new` 关键字，也不依赖原型继承机制。它的名字通常不以大写字母开头（遵循普通函数的命名惯例）：

```javascript
// 工厂函数风格 —— 简洁、直接、不需要 new
function createUser(name, age) {
  return {
    name: name,
    age: age,
    greet() {
      return `你好，我是 ${this.name}，今年 ${this.age} 岁`;
    }
  };
}

let u1 = createUser("张三", 25);
let u2 = createUser("李四", 30);

u1.greet(); // "你好，我是 张三，今年 25 岁"
u2.greet(); // "你好，我是 李四，今年 30 岁"

// 不需要 new，不会忘记 new，不可能因 new 导致全局污染
// 简单、安全、直观
```

### 两者的全面对比

| 特性 | 构造函数 (+ new) | 工厂函数 |
|------|-----------------|----------|
| **调用方式** | `new Foo()` | `foo()` |
| **this 指向** | 新创建的实例对象 | 取决于调用上下文（通常不使用 this） |
| **返回值** | 隐式返回新对象（除非显式 return 对象） | 显式 `return` 一个对象字面量 |
| **方法共享机制** | 通过 `prototype` 实现（内存高效） | 通常每个对象持有各自的方法副本（除非用外部引用） |
| **instanceof 支持** | ✅ 支持（`obj instanceof Foo` → `true`） | ❌ 不支持（`obj instanceof foo` → `false`） |
| **new.target 检测** | ✅ 可用 | N/A（不适用） |
| **遗忘 new 的风险** | ⚠️ 可能导致全局污染（非严格模式） | ✅ 无此风险（根本不需要 new） |
| **内存效率（大量实例）** | 高（原型方法只存一份） | 低（方法需复制或借助外部模块） |
| **私有封装能力** | 弱（属性公开可外部修改） | 强（可通过闭包实现真正的私有变量） |
| **组合灵活性** | 较弱（依赖继承链，单一原型来源） | 强（可自由组合任意对象，mixin 模式天然支持） |
| **学习曲线** | 需要理解 this、prototype、new 等概念 | 低（就是普通函数 + return 对象） |
| **语义意图表达** | "创建同类事物的一个新实例" | "生成/组装一个对象" |

### 工厂函数的优势场景

#### 场景 1：实现真正的私有变量（闭包 encapsulation）

这是工厂函数相对于构造函数的最大优势之一。通过闭包，工厂函数可以实现**真正无法从外部访问的私有变量**：

```javascript
function createCounter(initialValue) {
  // 真正的私有变量 —— 外部绝对无法直接访问！
  // 不需要下划线前缀、不需要 Symbol、不需要 WeakMap 技巧
  let count = initialValue || 0;

  return {
    increment() {
      count++;
      return count;
    },
    decrement() {
      count--;
      return count;
    },
    getCount() {
      return count;
    },
    reset() {
      count = initialValue || 0;
      return count;
    }
  };
}

let counter = createCounter(10);
counter.increment();  // 11
counter.increment();  // 12
counter.getCount();   // 12

counter.count;        // undefined —— 无法访问！
counter.count = 9999;  // 静默无效（只是在 counter 上创建了一个无用的属性）
counter.getCount();   // 仍然是 12 —— 真正的 count 未受影响

// 对比：构造函数无法做到真正的私有
function BadCounter(start) {
  this._count = start;  // 只是"约定"的私有，实际上可以直接访问
}
let bc = new BadCounter(10);
bc._count = 9999;  // 直接修改"私有"变量！😱
```

#### 场景 2：灵活的对象组合（Mixin / Composition）

工厂函数可以自由地将任意多个"能力模块"（mixin）组合到一个对象上，而不受单一原型链的限制：

```javascript
// 定义一些可复用的"能力模块"（Mixins）
const canFly = {
  fly() { console.log(`${this.name} 🦅 展翅高飞!`); },
  altitude: 10000
};

const canSwim = {
  swim() { console.log(`${this.name} 🏊 潜入水中!`); },
  depth: 100
};

const canWalk = {
  walk() { console.log(`${this.name} 🚶 在路上行走!`); },
  speed: 5
};

const canMakeSound = {
  makeSound(noise) { console.log(`${this.name}: "${noise}"`); }
};

// 工厂函数灵活组合能力
function createCreature(name, ...abilities) {
  let creature = { name };  // 基础对象

  // 将所有传入的能力模块合并到 creature 上
  abilities.forEach(ability => {
    Object.assign(creature, ability);
  });

  return creature;
}

// 组合出不同的生物
let duck = createCreature("鸭子", canWalk, canSwim, canFly, canMakeSound);
let fish = createCreature("鱼", canSwim, canMakeSound);
let human = createCreature("人类", canWalk, canSwim, canMakeSound);
let eagle = createCreature("老鹰", canFly, canWalk, canMakeSound);

// 各有各的能力
duck.walk();   // "鸭子 🚶 在路上行走!"
duck.swim();   // "鸭子 🏊 潜入水中!"
duck.fly();    // "鸭子 🦅 展翅高飞!"
duck.makeSound("嘎嘎嘎");  // "鸭子: '嘎嘎嘎'"

fish.swim();   // "鱼 🏊 潜入水中!"
fish.makeSound("咕噜咕噜");

human.walk();  // "人类 🚶 在路上行走!"
human.swim();  // "人类 🏊 潜入水中!"

eagle.fly();   // "老鹰 🦅 展翅高飞!"
eagle.walk();  // "老鹰 🚶 在路上行走!"

// 这种灵活性是单一原型链继承很难实现的
// （虽然也可以通过多重 mixin 工具函数辅助，但工厂函数更直观）
```

### 如何选择？

**选择构造函数（或 class）的场景**：

- 需要创建**大量的相似对象**，内存效率很重要
- 需要 **`instanceof`** 进行类型检查（如 API 参数校验、多态分发）
- 需要原型继承来实现**方法共享和多态行为**
- 团队成员熟悉面向对象编程（OOP）范式
- 需要与现有的基于 class/构造函数的代码或库集成
- 对象之间存在清晰的 **"is-a"（是一个）** 关系层级

**选择工厂函数的场景**：

- 需要**真正的私有封装**（闭包实现）
- 对象的结构差异较大，不适合统一的模板
- 希望**完全避免 `new` 相关的各种陷阱**
- 倾向于**函数式编程（FP）** 或 **组合式编程（Composition）** 风格
- 创建的对象数量较少，内存不是瓶颈
- 对象之间的关系更适合用 **"has-a"（有一个）** 来描述

**现实建议**：在 ES6+ 的项目中，大多数情况下推荐使用 **`class` 语法**（它是构造函数 + 原型的语法糖，提供了更好的语义和安全性），同时在需要私有变量时使用 **`#privateField`** 语法（ES2022+ 的真正私有字段）。只有在需要极致灵活性或与函数式风格统一时，才考虑工厂函数。

## 从构造函数到 ES6 Class

ES6（ECMAScript 2015）引入了 `class` 语法糖，它在很大程度上是对"构造函数 + 原型模式"的语法层面封装。理解了构造函数的全部底层机制之后，你会发现 `class` 其实非常直观——它只是把那些繁琐的手动操作自动化了。

### 逐项对应关系

```javascript
// =============================================
// ES5 构造函数写法（底层实现）
// =============================================

function Animal(name) {
  this.name = name;                      // constructor 体中的初始化逻辑
}
Animal.prototype.speak = function () {    // prototype 上的方法
  console.log(`${this.name} 发出了声音`);
};
Animal.prototype.move = function (distance) {
  console.log(`${this.name} 移动了 ${distance} 米`);
};
Animal.staticMethod = function () {       // 直接挂在构造函数上的静态方法
  console.log("这是 Animal 的静态方法");
};
Animal.type = "哺乳动物";                // 静态属性


// =============================================
// ES6 Class 写法（等价的语法糖）
// =============================================

class Animal {
  static type = "哺乳动物";              // 静态属性（ES2022 语法）

  constructor(name) {                    // 构造方法（对应 ES5 的函数体）
    this.name = name;
  }

  speak() {                              // 原型方法（自动放到 prototype 上）
    console.log(`${this.name} 发出了声音`);
  }

  move(distance) {                       // 也是原型方法
    console.log(`${this.name} 移动了 ${distance} 米`);
  }

  static staticMethod() {                // 静态方法（自动挂到 class 本身）
    console.log("这是 Animal 的静态方法");
  }
}
```

### Class 的额外优势

虽然 `class` 主要是语法糖（底层依然是构造函数 + 原型机制），但它带来了几个构造函数不具备的好处：

#### 1. 自动防止遗忘 new

```javascript
class StrictClass {
  constructor(x) {
    this.x = x;
  }
}

StrictClass(42);
// TypeError: Class constructor StrictClass cannot be invoked without 'new'
// —— 不需要手动的 new.target 检查，语言层面保证！
```

#### 2. 严格模式默认开启

`class` 内部的所有代码默认处于**严格模式（Strict Mode）**，无需手动添加 `'use strict'`：

```javascript
class SilentStrict {
  constructor() {
    // 已经在严格模式中了！
    // undeclaredVar = 1;  // ReferenceError: undeclaredVar is not defined
  }

  method() {
    // 这里也是严格模式
  }
}
```

#### 3. 方法不可被替换为普通属性值

`class` 内部只允许定义方法，不能像普通对象那样定义属性（在 ES2022 之前）：

```javascript
class BadClass {
  // SyntaxError! class 内部不能这样写
  method = function () {};
}

// 但 ES2022 后支持类字段（Class Fields）：
class GoodClass {
  publicField = "公开字段";           // 公共实例字段
  #privateField = "私有字段";         // 私有字段（#前缀）
  static staticField = "静态字段";     // 静态字段

  method() {
    console.log(this.#privateField);  // 可以访问私有字段
  }
}
```

#### 4. 继承语法更清晰、更不容易出错

```javascript
class Dog extends Animal {
  constructor(name, breed) {
    super(name);  // 必须！必须在访问 this 之前调用 super()
    this.breed = breed;
  }

  speak() {
    super.speak();  // 调用父类的 speak 方法
    console.log(`${this.name}（${this.breed}）汪汪叫！`);
  }

  wagTail() {
    console.log(`${this.name} 摇尾巴~`);
  }
}

let dog = new Dog("旺财", "柴犬");
dog.speak();   // "旺财 发出了声音" → "旺财（柴犬）汪汪叫！"
dog.wagTail(); // "旺财 摇尾巴~"
dog.move(10);  // "旺财 移动了 10 米" —— 继承自 Animal
```

### 底层不变的事实：Class 就是构造函数

尽管 `class` 的语法看起来和传统的构造函数写法差别很大，但在 JavaScript 引擎底层，**class 创建的对象与构造函数创建的对象完全一致**——没有任何本质区别：

```javascript
class MyClass {
  constructor(x) {
    this.x = x;
  }
  hello() {
    return "Hello, " + this.x;
  }
}

let obj = new MyClass("World");

// 验证底层机制
console.log(typeof MyClass);                     // "function" —— Class 本质上就是一个函数！
console.log(typeof MyClass.prototype);           // "object"
console.log(MyClass.prototype.constructor);      // [Class: MyClass]
console.log(MyClass.prototype.hasOwnProperty('hello')); // true —— 方法在 prototype 上
console.log(obj.__proto__ === MyClass.prototype); // true —— 原型链接正确
console.log(obj instanceof MyClass);             // true —— instanceof 正常工作
console.log(obj.hello());                        // "Hello, World"
```

### 通俗类比：自动挡 vs 手动挡汽车

构造函数好比**手动挡汽车**——你能完全控制每一个细节：什么时候踩离合、什么时候换档、`this` 怎么绑定、`return` 怎么处理、原型怎么手动设置。这给了你极大的灵活性和控制力，但也需要更高的技术门槛和更多的注意力。一不小心就可能熄火（忘记 `new` 导致全局污染）或者磨坏离合器（错误的 `this` 绑定）。

`Class` 好比**自动挡汽车**——大部分繁琐的操作（原型链接、`super` 调用、`new` 检测、严格模式启用）都被自动处理了，让你能把精力集中在真正重要的事情上：业务逻辑本身。换挡、离合这些底层细节对你来说是透明的。但在引擎盖（hood）下面，两者使用的仍然是**完全相同的引擎**（JavaScript 的对象模型和原型链机制）。自动挡并没有发明一种新的动力系统——它只是让驾驶体验变得更友好、更安全、更高效。

对于新手来说，自动挡（`class`）显然更容易上手，也更难犯致命错误。但对于想要深入理解 JavaScript 语言本质的开发者来说，学习手动挡（构造函数 + 原型）是必不可少的修行——因为只有理解了底层机制，你才能在面对复杂问题时做出正确的决策，才能在阅读源码和调试问题时得心应手。

## 总结

### 核心知识速查表

| 概念 | 核心要点 |
|------|----------|
| **构造函数** | 被 `new` 调用的普通函数，用于批量创建同结构的对象。函数本身没有特殊性——特殊性全来自 `new` |
| **new 的四个步骤** | ① 创建新空对象 → ② 链接 `[[Prototype]]` 到构造函数的 `prototype` → ③ 绑定 `this` 并执行构造函数体 → ④ 处理返回值（返回对象则用之，否则返回新对象） |
| **this 绑定优先级** | `new` 绑定 > 显式绑定（bind）> 隐式绑定（obj.fn()）> 默认绑定。`new` 的优先级最高，甚至会覆盖 `bind` 的硬绑定 |
| **prototype** | 函数的 `prototype` 属性是一个对象，存放所有实例共享的方法。实例通过 `__proto__` / `[[Prototype]]` 链接到它 |
| **return 行为** | 返回原始值（含 `undefined`/`null`）→ 被忽略，返回新对象；返回对象（含函数）→ 替代新对象作为 `new` 的结果 |
| **new.target** | ES6 元属性，函数内部可用。`new` 调用时值为构造函数本身，普通调用时为 `undefined`。可用于安全模式实现 |
| **constructor** | `prototype` 上的默认属性，指回构造函数本身。覆盖 `prototype` 时需手动维护 |
| **instanceof** | 沿原型链查找 `Constructor.prototype` 是否在对象的原型链上。跨 realm 时不可靠 |
| **原型链** | 属性读取沿 `[[Prototype]]` 链向上查找；属性写入直接作用于自身（setter 除外）；`for...in` 遍历含继承属性 |
| **工厂函数** | 不需要 `new` 的对象创建函数，更灵活、更安全，可通过闭包实现真正私有，但无 `instanceof`、方法不共享 |
| **class** | ES6 语法糖，底层仍是构造函数 + 原型机制。提供自动 new 检测、严格模式、简洁继承等优势 |

### 设计原则

1. **数据放实例，方法放原型** —— 保证每个实例数据独立的同时最大化方法共享，兼顾正确性和内存效率
2. **命名用 PascalCase** —— 首字母大写是最好的"自我注释"，降低沟通成本和出错率
3. **善用 `new.target`** —— 在需要兼容 ES5 时，用 `new.target` 实现安全的构造函数
4. **理解优于记忆** —— `new` 只是语法层面的便捷包装，本质上是 4 个可手动模拟的步骤。理解了原理，就不需要死记硬背
5. **选择合适的工具** —— 构造函数/class 用于同构对象的批量生产和类型体系；工厂函数用于灵活的、组合式的、注重封装的对象创建
6. **警惕原型上的可变状态** —— 不要把数组和对象放在原型上作为实例的共享可变状态，否则会出现"一只仓鼠吃两只仓鼠的食物"的诡异 bug
