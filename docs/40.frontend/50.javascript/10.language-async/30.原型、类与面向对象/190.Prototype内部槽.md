# `[[Prototype]]` 内部槽 —— 原型链的物理基础

## 从一个"奇怪"的现象说起

在深入学习 JavaScript 原型系统的过程中，几乎每个人都会遇到这样一个看似矛盾的现象：

```javascript
let obj = {};
console.log(obj.__proto__ === Object.prototype); // true
console.log(obj.prototype);                    // undefined
```

同样的"原型"概念，为什么 `obj` 有一个 `__proto__` 属性指向了某个对象，但 `obj.prototype` 却是 `undefined`？这两个名字看起来如此相似的东西，到底有什么区别？更让人困惑的是，你可能在不同的教程中看到过 `prototype`、`__proto__`、`[[Prototype]]` 这三种写法——它们是同一个东西的三种不同名称吗？如果不是，那各自代表什么？

如果你曾经被这些问题困扰过，那么本章就是为你准备的。我们将彻底厘清这三个概念的本质差异，深入理解 JavaScript 引擎内部是如何通过 `[[Prototype]]` 这个**内部槽（Internal Slot）**来构建整个原型链机制的。这不是什么"高级技巧"或"面试考点"——这是理解 JavaScript 对象系统如何运作的**地基性知识**。

### 为什么这个话题如此重要？

`[[Prototype]]` 的重要性怎么强调都不为过。它是以下所有概念的**底层物理基础**：

- **属性查找（Property Lookup）**：当你访问 `obj.propName` 而 `obj` 自身没有 `propName` 时，引擎去哪里找？——沿着 `[[Prototype]]` 链
- **`in` 操作符和 `for...in` 循环**：为什么会遍历到对象上"不存在"的属性？——因为那些属性在 `[[Prototype]]` 链上
- **`instanceof` 运算符**：`obj instanceof Foo` 是如何判断的？——检查 `Foo.prototype` 是否在 obj 的 `[[Prototype]]` 链上
- **继承（Inheritance）**：子类为什么能使用父类的方法？——因为子类实例的 `[[Prototype]]` 指向父类的 `prototype`
- **`class` 语法糖**：`extends` 关键字背后做了什么？——设置 `[[Prototype]]` 的链接

不理解 `[[Prototype]]`，你就只能在这些概念的表面滑行，知其然而不知其所以然。一旦你真正理解了它，整个 JavaScript 面向对象体系就会变得通透而自然。

### 通俗类比：家谱查询系统

为了建立一个直觉性的心理模型，让我们先打一个比方。

想象每个人都有自己的**个人档案**（这就是对象本身），但同时每个人都属于一个**家族**（这就是原型）。家族中有一本**族谱**（`[[Prototype]]`），记录着你的父亲是谁、祖父是谁、曾祖父是谁……一直追溯到"始祖"（`null`）。

当你在自己的档案里找不到某条信息时（比如你想知道"我的祖先来自哪里"），你可以翻开族谱，先查父亲，父亲那里没有就查祖父，祖父那里没有就查曾祖父……沿着这条血缘链条一路向上追溯，直到找到答案或者到达族谱的尽头（始祖之前没有人了，返回"未找到"）。

在这个比喻中：
- **你的个人档案** = 对象自身（Own Properties）
- **族谱/血缘关系** = `[[Prototype]]` 内部槽
- **你的父亲** = 对象的原型对象（Prototype Object）
- **"沿族谱查找"的过程** = 原型链查找（Prototype Chain Lookup）
- **始祖（族谱终点）** = `null`

关键细节在于：**族谱是你自己持有的（存在于你的档案夹里），而不是家族统一保管的公共记录**。每个人都有自己的一份族谱副本，只是这些副本恰好都指向相同的祖先而已。这就像每个员工都有一张组织架构图在自己工位上——图上的内容相同，但每份图纸都是独立的。

## 三种 "Prototype" 的正名与辨析

JavaScript 中涉及"原型"的概念有三个不同的名字，经常被混淆。让我们一次性彻底理清它们的关系。

### 1. `[[Prototype]]` —— 内部槽（Internal Slot）

**定义**：`[[Prototype]]` 是 ECMAScript 规范中定义的对象**内部插槽（Internal Slot）**。它是一个隐藏的、无法通过普通属性访问方式直接读写的内部引用。

**存在位置**：**每一个** JavaScript 对象（除了 `Object.create(null)` 创建的无原型对象）都有 `[[Prototype]]`。注意是**每一个对象**——包括数组、函数、正则表达式、Date 实例等——它们都有。

**存储内容**：要么是 `null`，要么是对另一个对象的引用（即该对象的原型/Prototype）。

**访问方式**：不能直接用点号或方括号访问。必须通过专门的 API 间接操作：
- `Object.getPrototypeOf(obj)` —— 读取
- `Object.setPrototypeOf(obj, proto)` —— 设置
- `obj.__proto__` —— 非标准但广泛支持的便捷访问器（getter/setter）

```javascript
let obj = { x: 1 };

// [[Prototype]] 存在但不可直接访问
// 你不能写 obj.[[Prototype]] 或类似的语法
// 它是引擎内部的元数据

// 通过标准 API 间接读取
let proto = Object.getPrototypeOf(obj);
console.log(proto === Object.prototype); // true

// [[Prototype]] 的值是什么？
// 就是 Object.prototype 这个对象！
```

**理论深挖：什么是"内部插槽"（Internal Slot）？**

在 ECMAScript 规范中，用双方括号 `[[]]` 包裹的名字表示对象的"内部插槽"。它们是对象内部的特殊存储位置，具有以下特征：

1. **不是普通的可枚举属性**：`for...in` 循环不会遍历到它们，`Object.keys()` 也不会返回它们
2. **不是用点号/方括号能访问的**：`obj.[[Prototype]]` 是语法错误
3. **由引擎内部控制**：普通 JavaScript 代码无法创建新的内部插槽（只有规范预定义的那些存在）
4. **有特定的类型约束**：比如 `[[Prototype]]` 只能是 null 或 Object

常见的内部插槽包括：

| 内部插槽 | 类型 | 说明 |
|---------|------|------|
| `[[Prototype]]` | Null 或 Object | 原型指针 |
| `[[Extensible]]` | Boolean | 是否允许添加新属性 |
| `[[GetOwnProperty]]` | 内部方法 | 获取自身属性描述符 |
| `[[DefineOwnProperty]]` | 内部方法 | 定义/修改自身属性 |
| `[[Get]]` | 内部方法 | 属性获取（触发原型链查找） |
| `[[Set]]` | 内部方法 | 属性设置 |

可以把内部插槽想象成对象上的**"密封隔间"**——里面存放着引擎运行所需的元数据，但这些数据对普通代码是不可见的。你能看到房间的外墙（对象本身），但看不到里面藏着什么东西（内部插槽）。你需要通过特殊的"工具"（如 `Object.getPrototypeOf`）来间接地查看或操作里面的东西。

### 2. `prototype` —— 函数的显式属性

**定义**：`prototype` 是函数对象上的一个**普通的、公开的属性**。它的值默认是一个对象（自动创建，带有 `constructor` 属性指回函数本身）。

**存在位置**：**只有函数对象**才有 `prototype` 属性！普通对象（如 `{}`、`[]`）**没有** `prototype` 属性。

```javascript
function Foo() {}
let obj = {};

console.log(typeof Foo.prototype);   // "object" ✅ 函数有 prototype
console.log(typeof obj.prototype);     // "undefined" ❌ 普通对象没有

// 函数的 prototype 默认值是什么？
console.log(Foo.prototype);
// { constructor: Foo } —— 一个包含 constructor 的对象
console.log(Foo.prototype.constructor === Foo); // true
```

**核心作用**：当你使用 `new Foo()` 创建新对象时，引擎会将新对象的 `[[Prototype]]` 设置为 `Foo.prototype`。换句话说：**`prototype` 是 `[[Prototype]]` 的"原材料"或"来源"**——它是构造函数提供的一个蓝图，告诉引擎"请把我设为新对象的原型"。

**理论补充：为什么函数会有 prototype？**

这是因为 JavaScript 中的函数设计为既可以作为"普通调用"使用，也可以作为"构造调用"使用。为了支持构造调用（`new` 操作符），每个函数都需要一个地方来存放"由该函数创建的实例所共享的方法和数据"。这个"地方"就是 `prototype` 属性。

这是一种语言层面的设计决策——让函数身兼二职：
- **作为普通函数执行逻辑**（`foo()`）
- **作为构造器提供原型**（`new foo()` 时使用 `foo.prototype`）

这种设计虽然灵活但也容易引起混淆——初学者很难理解同一个函数在不同调用方式下扮演的角色差异。

### 3. `__proto__` —— 已废弃但广泛使用的便捷访问器

**定义**：`__proto__`（读作 "dunder-proto" 或 "prototo"）是对象上的一个**属性访问器（Accessor Property）**，其 getter 和 setter 分别对应 `Object.getPrototypeOf` 和 `Object.setPrototypeOf`。

**存在位置**：**`Object.prototype`** 上定义了这个 getter/setter。由于几乎所有普通对象的原型链最终都会指向 `Object.prototype`，所以几乎所有对象都能通过 `obj.__proto__` 来"看到"自己的 `[[Prototype]]`。

**当前状态**：在 ES6 规范中被归入 **Annex B（附录 B）**——意味着它被保留只是为了向后兼容，不被推荐在新代码中使用。但在实际开发中，所有现代浏览器和 Node.js 环境都支持它。

```javascript
let obj = { x: 1 };

// __proto__ 可以直接访问（虽然不推荐）
console.log(obj.__proto__ === Object.prototype); // true

// 等价于
console.log(Object.getPrototypeOf(obj) === Object.prototype); // true

// __proto__ 甚至可以在字面量中使用！
let obj2 = { y: 2, __proto__: { z: 3 } };
console.log(obj2.z);    // 3 —— 从指定的原型上获取
console.log(obj2.x);    // undefined —— 自身没有 x
```

### 三者关系图谱

现在让我们把三者的关系画清楚：

```
function User(name) {
  this.name = name;
}
User.prototype.greet = function () { ... };

let user = new User("张三");
```

```
User (函数)
│
├── prototype (函数的显式属性) ──────────────────────┐
│   {                                             │
│     constructor: User,                            │
│     greet: function() {...}                      │
│   }                                              │
│                                                  │
│  ← new 时，user 的 [[Prototype]] 被设置为这里        │
│                                                  ▼
user (实例对象)                                       │
│                                                   │
├── name: "张三" (自有属性)                           │
│                                                   │
├── [[Prototype]] (内部槽) ────────────────────────────┘ （指向上面的 prototype 对象）
│
├── __proto__ (便捷访问器) ───────────────────────────────→ 也指向上面！
│
└── prototype → undefined                              （普通对象没有这个属性！）
```

**一句话总结三者关系**：

> - **`[[Prototype]]`**：每个**对象**都有的内部指针，指向它的原型对象。这是引擎内部使用的。
> - **`prototype`**：每个**函数**都有的外部属性，作为 `new` 操作符设置 `[[Prototype]]` 的"原材料"。这是开发者使用的。
> - **`__proto__`**：一个 deprecated 但广泛支持的便捷方式，让你能在代码层面"看到" `[[Prototype]]` 的值。

**最常犯的错误**：混淆 `prototype` 和 `[[Prototype]]`（或 `__proto__`）。记住：一个是**函数身上**的属性，另一个是**对象身上**的内部指针。它们通常指向同一个对象（当通过 `new` 创建后），但它们的"主人"不同、"身份"也不同。

## [[Prototype]] 的完整行为机制

### 属性查找算法（The Property Lookup Algorithm）

`[[Prototype]]` 的核心价值体现在**属性查找**的过程中。当你在代码中写下 `obj.propertyName` 来获取一个属性的值时，引擎会执行以下算法（ECMAScript 规范中的简化版）：

```
GetProperty(obj, "propertyName"):

  1. 让 currentObj = obj

  2. 重复以下步骤:
     a. 让 desc = currentObj 的自身属性中名为 "propertyName" 的属性描述符
        ├── 如果找到了:
        │   如果是数据属性 → 返回属性值（查找结束 ✅）
        │   如果是访问器属性(getter) → 执行 getter，返回结果（查找结束 ✅）
        │
        └── 如果没找到 ↓
     
     b. 让 proto = currentObj.[[Prototype]]
        ├── 如果 proto === null → 返回 undefined（查找结束 ⛔ 未找到）
        └── 否则 → 让 currentObj = proto，回到步骤 a 继续查找
```

用代码来模拟这个过程会更直观：

```javascript
function simulateLookup(obj, propName) {
  let current = obj;
  let depth = 0;

  while (current !== null) {
    depth++;
    console.log(`  [深度 ${depth}] 检查对象: ${getObjectLabel(current)}`);

    if (propName in current && current.hasOwnProperty(propName)) {
      // 在当前对象自身找到了
      const value = current[propName];
      console.log(`  ✅ 在深度 ${depth} 处找到 "${propName}" = ${JSON.stringify(value)}`);
      return value;
    }

    // 自身没有 → 沿 [[Prototype]] 向上
    current = Object.getPrototypeOf(current);
  }

  console.log(`  ⛂ 到达原型链顶端（null），"${propName}" 不存在`);
  return undefined;
}

// 辅助函数：给对象一个简短的标签
function getObjectLabel(o) {
  if (o === null) return 'null';
  if (Array.isArray(o)) return `Array[${o.length}]`;
  if (o.constructor) return `(${o.constructor.name})`;
  return '(anonymous)';
}

// ====== 测试 ======
function GrandParent() {}
GrandParent.familyName = "王家";

function Parent() {}
Object.setPrototypeOf(Parent.prototype, GrandParent.prototype);
Parent.surname = "李";

function Child() {}
Object.setPrototypeOf(Child.prototype, Parent.prototype);
Child.givenName = "小明";

let child = new Child();
child.toy = "变形金刚";  // 自己的属性

simulateLookup(child, "toy");       // 自身属性 → 直接找到
simulateLookup(child, "givenName");   // 自身属性 → 直接找到
simulateLookup(child, "surname");    // 自身没有 → 去 Parent.prototype 上找
simulateLookup(child, "familyName"); // 自身+Parent都没有 → 去 GrandParent.prototype 上找
simulateLookup(child, "nonExistent"); // 全链都没找到 → 返回 undefined
```

输出：
```
  [深度 1] 检查对象: (Child)
  ✅ 在深度 1 处找到 "toy" = "变形金刚"

  [深度 1] 检查对象: (Child)
  ✅ 在深度 1 处找到 "givenName" = "小明"

  [深度 1] 检查对象: (Child)

  [深度 2] 检查对象: (Parent)
  ✅ 在深度 2 处找到 "surname" = "李"

  [深度 1] 检查对象: (Child)

  [深度 2] 检查对象: (Parent)

  [深度 3] 检查对象: (GrandParent)
  ✅ 在深度 3 处找到 "familyName" = "王家"

  [深度 1] 检查对象: (Child)

  [深度 2] 检查对象: (Parent)

  [深度 3] 检查对象: (GrandParent)

  [深度 4] 检查对象: null
  ⛠ 到达原型链顶端（null），"nonExistent" 不存在
```

从这个模拟输出中可以清晰地看到属性查找是如何一层层向上进行的：**先找自己，自己没有就去问"父亲"，父亲没有就去问"祖父"……直到找到答案或者问到祖宗十八代都没有为止。**

### 写入操作的特殊行为

读取属性时会沿原型链向上查找，但**写入（赋值）操作则完全不同**——它只作用于对象自身，不会影响原型链**（有一个重要的例外情况我们稍后讨论）：

```javascript
function Ancestor() {
  sharedValue = "来自祖先";
}
Ancestor.prototype.sharedMethod = function () {
  return this.sharedValue;
};

function Descendant() {}
Object.setPrototypeOf(Descendant.prototype, Ancestor.prototype);

let d = new Descendant();

// 读取：沿原型链查找
console.log(d.sharedValue);     // "来自祖先" ← 从 Ancestor.prototype 找到的
console.log(d.sharedMethod());   // "来自祖先" ← 方法也是继承来的

// 写入：只在自身创建属性（屏蔽/Shadowing）
d.sharedValue = "我自己的值";

console.log(d.sharedValue);     // "我自己的值" ← 自身的值，不是原型的
console.log(Ancestor.prototype.sharedValue); // "来自祖先" ← 原型不受影响！✅
```

**为什么这样设计？** 试想如果写入操作会影响原型，会发生什么灾难：

```javascript
function Counter() {}
Counter.prototype.count = 0;

let c1 = new Counter();
let c2 = new Counter();

c1.count++;  // 如果这修改了原型 → c2.count 也变成 1 了！！
// 所有 Counter 实例共享同一个 count → 彻底乱了套
```

所以写入操作的"本地化"策略是一种**保护机制**——确保每个实例的状态独立性，防止意外污染其他对象。

**例外：Setter（访问器属性）**

唯一的例外是：如果原型上的属性是一个 **setter（写入访问器）**，那么对该属性的赋值会触发 setter 执行：

```javascript
function Person(firstName, lastName) {
  this.firstName = firstName;
  this.lastName = lastName;
}

// 在 prototype 上定义 fullName 的 getter/setter
Object.defineProperty(Person.prototype, 'fullName', {
  get() {
    return `${this.firstName} ${this.lastName}`;
  },
  set(value) {
    // setter 中的 this 指向赋值目标对象！
    const parts = value.split(' ');
    this.firstName = parts[0] || '';
    this.lastName = parts[1] || '';
  },
  enumerable: true
});

let p = new Person("张", "三");

// 读取：正常沿原型链查找
console.log(p.fullName); // "张 三" ← 来自 getter

// 写入：触发了原型上的 setter！
p.fullName = "李 四";
// setter 内部：this.firstName = "李", this.lastName = "四"
// 注意：setter 的 this 指向 p（赋值的接收者），不是 Person.prototype！

console.log(p.firstName); // "李" ← p 被正确修改了
console.log(p.lastName);  // "四"
console.log(Person.prototype.firstName); // "张" ← 原型上的原始值不变 ✅
```

这个例外之所以存在，是因为 setter 本身就是一种"拦截并处理写入"的机制——它的设计意图就是要在属性被赋值时执行自定义逻辑（验证、转换、通知等）。如果连 setter 都不能拦截写入，那 setter 就失去存在的意义了。

## 原型链的构建过程详解

### 使用 new 构建时的原型链接

当我们执行 `new Constructor(...args)` 时，`[[Prototype]]` 是如何被建立起来的？

```javascript
function User(name) {
  this.name = name;  // 步骤 3 中 this 指向新对象
}

// 步骤 2：引擎会在后台做这件事：
// 新对象的 [[Prototype]] = User.prototype
User.prototype.greet = function () { return \`你好，我是 \${this.name}\`; };
```

具体过程如下（以 V8 引擎为例的简化描述）：

```
执行 new User("张三"):

  1. 引擎分配一块内存给新对象 obj
     obj = allocate(User) → { }（空对象）

  2. 引擎设置 obj 的 [[Prototype]]
     obj.[[Prototype]] = User.prototype
     此时 obj.__proto__ === User.prototype → true

  3. 引擎绑定 this 并执行构造函数
     User.call(obj, "张三")
     → this = obj
     → this.name = "张三"（给 obj 添加属性）

  4. 返回 obj
```

最终结果：

```
User (函数)
  │
  └── prototype: { constructor: User, greet: f }
            ▲
            │ [[Prototype]] → Object.prototype
            │
user (实例) ◄───────┘
  │
  ├── name: "张三"（自有属性）
  │
  └── [[Prototype]] ──────────────────→ { constructor: User, greet: f }
                                        │
                                        └── [[Prototype]] → Object.prototype
                                                                    │
                                                                    └── [[Prototype]] → null（终点）
```

### 使用 Object.create 时的原型链接

`Object.create(proto)` 是一种更直接的创建指定原型对象的方式：

```javascript
let proto = {
  greet() { return "Hello from prototype"; },
  version: "1.0"
};

// 方式 A：字面量 + setPrototypeOf（两步）
let a = {};
Object.setPrototypeOf(a, proto);

// 方式 B：Object.create（一步到位）
let b = Object.create(proto);

console.log(a.greet()); // "Hello from prototype"
console.log(b.greet()); // "Hello from prototype"
console.log(Object.getPrototypeOf(a) === proto); // true
console.log(Object.getPrototypeOf(b) === proto); // true
```

`Object.create(null)` 更是一个非常有用的特殊用法：

```javascript
// 普通空对象
let normalObj = {};
console.log(normalObj.toString); // "[object Object]" —— 继承自 Object.prototype
console.log("toString" in normalObj); // true

// 无原型的纯净字典对象
let pureDict = Object.create(null);
console.log(pureDict.toString); // TypeError! pureDict.toString is not a function
console.log("toString" in pureDict);  // false —— 连 toString 都没有！

// 为什么这很有用？
pureDict["__proto__"] = "hack attempt";
// 在普通对象上这样做可能会修改原型链！
// 但在无原型对象上，__proto__ 就是一个普通的字符串键
console.log(pureDict["__proto__"]); // "hack attempt" —— 安全地存为一个键！
console.log(Object.keys(pureDict)); // ["__proto__"] —— 可以被遍历到
```

**`Object.create(null)` 的典型用途**：
- 作为纯净的字典/哈希表（Dictionary/HashMap），不用担心 `__proto__` 键冲突
- 作为高性能的配置对象（不需要内置方法，减少原型链查找开销）
- 在某些安全敏感的场景中存储不可信的用户输入

### 使用 class 时的原型链接

ES6 的 `class` 语法本质上仍然是构造函数 + 原型的语法糖。`extends` 关键字负责设置子类的 `[[Prototype]]` 链接到父类的 `prototype`：

```javascript
class Animal {
  constructor(name) {
    this.name = name;
  }
  speak() { return \`${this.name} 发出了声音\`; }
}

// class A extends B 大致等价于：
// A.prototype.__proto__ = B.prototype;
// A.prototype.constructor = A;
class Dog extends Animal {
  constructor(name, breed) {
    super(name);  // 调用父类构造函数
    this.breed = breed;
  }
  bark() { return \`${this.name}（\${this.breed}）汪汪!\`; }
}

let dog = new Dog("旺财", "柴犬");

// 原型链结构:
console.log(dog.__proto__ === Dog.prototype);         // true
console.log(Dog.prototype.__proto__ === Animal.prototype); // true
console.log(Animal.prototype.__proto__ === Object.prototype); // true
console.log(Object.prototype.__proto__);                  // null

dog.speak();  // "旺财 发出了声音"（从 Animal.prototype 继承来的）
dog.bark();   // "旺财（柴犬）汪汪!"（Dog 自身的）
```

## for...in 与原型链

`for...in` 循环的行为也深受 `[[Prototype]]` 影响：

```javascript
function ProtoBase() {}
ProtoBase.baseProp = "基类属性";
ProtoBase.baseMethod = function () {};

ProtoBase.prototype.inheritedProp = "继承的属性";
ProtoBase.prototype.inheritedMethod = function () {};

let obj = new ProtoBase();
obj.ownProp = "自有属性";
obj.ownMethod = function () {};

console.log("=== for...in 遍历 ===");
for (let key in obj) {
  let isOwn = obj.hasOwnProperty(key);
  console.log(`  ${isOwn ? "🏠️ 自有" : "🔗 继承"}: ${key}`);
}
```

输出：
```
=== for...in 遍历 ===
  🏠️ 自有: ownProp
  🏠️ 自有: ownMethod
  🔗 继承: inheritedProp
  🔗 继承: inheritedMethod
  🔗 继承: baseProp
  🔗 继承: baseMethod
```

可以看到 `for...in` 会遍历到**自身属性 + 原型链上所有的可枚举属性**。这有时是有用的（当你想要获取对象"全部可用属性"时），但有时也会带来困扰（当你只想看自身属性时）。

**过滤掉继承属性**：

```javascript
for (let key in obj) {
  if (obj.hasOwnProperty(key)) {  // 只处理自身属性
    console.log(`[自有] ${key}: ${obj[key]}`);
  }
}

// 或者用 Object.keys() / Object.values() —— 它们只返回自身属性
console.log(Object.keys(obj));
// ["ownProp", "ownMethod"] —— 干净！没有继承属性
```

**有趣现象**：为什么 `for...in` 不会遍历到 `hasOwnProperty`、`toString`、`valueOf` 这些方法？因为它们在 `Object.prototype` 上的 `enumerable` 描述符被设为了 `false`。内建方法的不可枚举性保证了 `for...in` 不会被大量内置方法"污染"。

## [[Prototype]] 的实际测量与调试

### 如何观察完整的原型链

在实际开发和调试中，能够可视化地看到一个对象的完整原型链是非常有用的技能：

```javascript
/**
 * 打印对象完整的原型链信息
 */
function printPrototypeChain(obj, maxDepth = 10) {
  let current = obj;
  let depth = 0;

  console.log(`\n📋 原型链分析: ${getObjectLabel(obj)}\n`);

  while (current !== null && depth < maxDepth) {
    const indent = "  ".repeat(depth * 2);
    const label = getObjectLabel(current);
    
    // 列出自身的可枚举属性（不含 Symbol）
    const ownKeys = Object.keys(current);
    const ownStr = ownKeys.length > 0 
      ? `{ ${ownKeys.join(', ')}}` 
      : '(无自有属性)';
    
    console.log(`${indent}[${depth}] ${label} ${ownStr}`);
    
    // 显示 [[Prototype]] 指向哪里
    let proto = Object.getPrototypeOf(current);
    if (proto !== null) {
      console.log(`${indent}  └── [[Prototype]] → ${getObjectLabel(proto)}`);
    }
    
    current = proto;
    depth++;
  }

  if (depth >= maxDepth) {
    console.log(`\n⚠️ 达到最大深度 ${maxDepth}，停止`);
  } else {
    console.log(`\n✅ 到达原型链终点 (null)\n`);
  }
}

function getObjectLabel(o) {
  if (o === null) return 'null';
  if (Array.isArray(o)) return `Array[${o.length}]`;
  try {
    return o.constructor ? `(o.constructor.name)` : '(anonymous)';
  } catch { return '(error getting label)'; }
}

// ====== 测试 ======
class A {
  constructor() { this.a = 1; }
  methodA() { return 'A'; }
}
class B extends A {
  constructor() { super(); this.b = 2; }
  methodB() { return 'B'; }
}
class C extends B {
  constructor() { super(); this.c = 3; }
  methodC() { return 'C'; }
}

let instance = new C();
printPrototypeChain(instance);
```

预期输出：
```
📋 原型链分析: (C)

[0] (C) { a, b, c }
  └── [[Prototype]] → (B)
    [1] (B) { a, b, methodB }
      └── [[Prototype]] → (A)
        [2] (A) { a, methodA }
          └── [[Prototype]] → (Object)
            [3] (Object) { [很多内置方法...] }
              └── [[Prototype]] → null

✅ 到达原型链终点 (null)
```

### 性能考虑：原型链长度的影响

理论上，原型链越长（层级越深），属性查找就越慢（需要经过更多的 `[[Prototype]]` 跳转）。但实际上现代 JS 引擎（V8、SpiderMonkey）对此有高度优化：

```javascript
// 测试不同深度的原型链查找性能
const DEPTH = 1000;
let root = { value: "root" };
let current = root;

// 创建一条很深的原型链
for (let i = 0; i < DEPTH; i++) {
  current = Object.create(current);
  current.value = `level-${DEPTH - i}`;
}
let deepObj = current;

// 性能测试
console.time('deep lookup');
for (let i = 0; i < 100000; i++) {
  let v = deepObj.value;  // 每次都要沿 1000 层链查找！
}
console.timeEnd('deep lookup');

// 对比：浅层查找
let shallow = { value: "shallow" };
console.time('shallow lookup');
for (let i = 0; i < 100000; i++) {
  let v = shallow.value;
}
console.timeEnd('shallow lookup');
```

在 V8 中，两者的差距可能只有几毫秒甚至几乎相等。这是因为引擎使用了 **内联缓存（Inline Cache, IC）** 技术——对于频繁访问的属性路径，引擎会"记住"结果，后续访问时直接跳过查找步骤。此外，V8 的 **隐藏类（Hidden Class）** 优化也会将原型链的结构信息编码到对象中，加速属性查找。

**但这并不意味着你可以肆无忌惮地创建深层原型链**。深层继承仍然会导致：
- 对象占用更多内存（每层原型都是一个对象）
- 垃圾回收压力增大
- 代码可读性和可维护性降低
- 某些引擎优化（如 IC）在原型链结构变化时需要"去优化再优化"

**经验法则**：原型链深度控制在 **3-5 层以内** 是最佳实践。如果需要更深层次的类型体系，优先考虑组合（Composition）而非深层继承。

## 特殊情况与边缘场景

### 1. 循环引用

`[[Prototype]]` 链不允许形成循环（环形引用）。如果尝试这样做，引擎会抛出错误：

```javascript
let a = {};
let b = {};

// 尝试创建循环引用
// a.__proto__ = b;
// b.__proto__ = a;  // 如果前面已经把 a 的原型设为 b...

// 结果：TypeError: Cyclic __proto__ value
```

这是有道理的——如果允许循环引用，属性查找就会陷入无限递归，导致栈溢出或程序挂起。语言的这一限制保护了引擎的安全性和稳定性。

### 2. [[Prototype]] 只能是对象或 null

`[[Prototype]]` 的值只能是以下两种之一：
- **`null`**：表示原型链的终点（不再有更上层的原型）
- **对象（Object）**：表示下一层原型

你不能将 `[[Prototype]]` 设为原始值：

```javascript
let obj = {};
Object.setPrototypeOf(obj, 42);        // TypeError!
Object.setPrototypeOf(obj, "hello");    // TypeError!
Object.setPrototypeOf(obj, undefined); // TypeError!
Object.setPrototypeOf(obj, true);      // TypeError!
```

这同样是为了保证属性查找机制的正确性和一致性。

### 3. Object.create(null) 的 [[Prototype]]

`Object.create(null)` 创建的对象的 `[[Prototype]]` 为 `null`。这意味着：

```javascript
let pure = Object.create(null);

console.log(pure.toString);    // TypeError!
console.log(pure.valueOf);     // TypeError!
console.log(pure + "");          // TypeError![Cannot convert object to primitive value]
console.log(\`\${pure}\`);        // "[object Object]" —— 这里用了模板字面量的隐式转换

// 唯一安全的操作：当作纯键值对来使用
pure.key = "value";
console.log(pure.key);           // "value"
console.log("key" in pure);         // true
delete pure.key;
console.log("key" in pure);         // false
```

### 4. 修改已有对象的 [[Prototype]]

虽然可以用 `Object.setPrototypeOf()` 修改已存在对象的 `[[Prototype]]`，但这**强烈不建议在生产代码中使用**（性能敏感路径除外）：

```javascript
let cat = { name: "猫", meow() { console.log("喵~"); } };
let dog = { name: "狗", woof() { console.log("汪!"); } };

let pet = cat;

// 改变 pet 的原型
Object.setPrototypeOf(pet, dog);
pet.woof();  // "汪！" —— cat 突然叫了"汪"！😱

// 问题 1：性能问题 —— 引擎需要对 pet 进行"去优化"
// 问题 2：语义混乱 —— cat 叫"汪"不符合直觉
// 问题 3：原有关系断裂 —— cat 原本的关联丢失
```

**官方建议**：`Object.setPrototypeOf()` 应该仅在对象**创建之时**（如 `Object.create()` 或 `new` 操作中）使用。对于已经创建完成并在多处引用的对象，避免修改其原型。

## 总结

### 核心知识点速查表

| 概念 | 类型 | 拥有者 | 可访问方式 | 用途 |
|------|------|--------|---------|------|
| **`[[Prototype]]`** | 内部槽 | **每个对象** | `Object.getPrototypeOf(obj)` | 属性查找的基础 |
| **`prototype`** | 显式属性 | **每个函数** | `Fn.prototype` | `new` 时作为 [[Prototype]] 的来源 |
| **`__proto__`** | 访问器 | **(通过原型链)几乎所有对象** | `obj.__proto__` | 开发调试时的便捷访问 |

### 三者关系一句话总结

> **`[[Prototype]]`** 是每个对象内部隐藏着的"家谱"，指引着属性查找的方向；**`prototype`** 是函数身上的"蓝图"，告诉 `new` 应该如何设置新对象的家谱；**`__proto__`** 则是一扇方便的门，让你不用打开复杂的工具箱就能窥见那个隐藏的家谱。三者共同构成了 JavaScript 原型链机制的完整图景。

### 最佳实践建议

| 建议 | 说明 |
|------|------|
| 优先使用 `Object.getPrototypeOf` / `setPrototypeOf` | 标准化、可靠、明确语义 |
| 避免 `__proto__` 在生产代码中使用 | 已废弃（Annex B），仅用于控制台调试 |
| 避免运行时修改已有对象的 `[[Prototype]]` | 可能导致引擎去优化，影响性能 |
| 原型链深度控制在 3-5 层 | 过深会导致性能和维护性问题 |
| 需要纯净字典时使用 `Object.create(null)` | 避免 `__proto__` 键冲突和原型链干扰 |
| 理解属性查找的"自身优先"规则 | 读沿链向上；写作用于自身（setter 除外） |
