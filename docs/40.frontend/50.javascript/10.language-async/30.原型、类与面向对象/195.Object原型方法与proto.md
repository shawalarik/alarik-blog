# Object 原型方法与 `__proto__`

## 原型操作的"三剑客"——三种方式操作同一个东西

在 JavaScript 原型系统的工具箱中，有三件密切相关的"武器"经常被一起讨论和使用——它们分别是 `Object.prototype` 上的 `__proto__` 属性访问器、`Object.getPrototypeOf()` 静态方法和 `Object.setPrototypeOf()` 静态方法。这三者虽然都围绕着对象的 **`[[Prototype]]`（内部原型指针）** 进行操作，但它们的定位、行为、适用场景和可靠性各不相同。

很多开发者对它们的关系一知半解：什么时候该用哪一个？为什么 MDN 文档上说 `__proto__` 不推荐使用？`getPrototypeOf` 和 `setPrototypeOf` 到底比它好在哪里？本章将对这三种原型操作方式进行一次彻底的、无死角的深度剖析。

### 为什么需要三种方式来操作原型？

你可能会想："既然都是操作原型（`[[Prototype]]`），为什么不统一用一种方式就好了？" 这就像问："为什么我们需要锤子、螺丝刀和钳子三种工具？它们不都能用来'弄东西'吗？"答案是：**不同的场景需要不同精度的工具**。

- **`__proto__`** 就像一把**多功能瑞士军刀**——方便、快捷、什么都能凑合着用，但不适合做精细活
- **`Object.getPrototypeOf / setPrototypeOf`** 就像**专业级精密仪器**——功能专一、结果可靠、适合正式场合
- **`Object.create()`** 就像**3D 打印机**——直接按照图纸创建具有指定原型的全新对象

理解每种工具的特性、边界和最佳适用场景，是成为 JavaScript 原型系统真正高手的必经之路。本章将帮助你完成这个进阶。

### 通俗类比：查看和修改家谱的三种途径

让我们用一个生活化的比喻来建立直觉：

想象每个人（对象）都有一份**家谱记录**（`[[Prototype]]` 内部槽），记载着自己的父亲是谁（原型对象）。现在你想了解或修改这份家谱，有三种途径：

- **`__proto__`（瑞士军刀）**：就像直接翻开某人家里的那本**纸质族谱册子**。很方便——走到哪儿翻到哪儿。但这本册子可能不是官方版本（可能是自己手抄的），而且如果这个人根本没有族谱册子（比如 `Object.create(null)` 创建的对象），你就翻不到任何东西。此外，如果你在册子上乱涂乱画（修改 `__proto__`），可能会引起家族混乱。
- **`Object.getPrototypeOf`（显微镜）**：就像去**户籍管理部门**查询官方记录。流程正规、结果可靠、不会出错。无论这个人有没有自己的族谱册子，官方记录里都有完整的登记信息（即使是 `null` 也有明确记录）。这是最值得信赖的方式。
- **`Object.setPrototypeOf`（手术刀）**：就像通过**正式的领养程序**修改一个人的法定父子关系。这是一个非常严肃的操作——需要走完所有法律程序（引擎需要做大量内部调整），而且一旦完成，可能会影响整个家族系统（性能影响）。

## 核心前提：[[Prototype]] 的存在

在深入具体 API 之前，我们必须先确认一个基础事实——这是后续所有讨论的共同基石：

> **每个普通 JavaScript 对象都有一个内部隐藏属性叫做 `[[Prototype]]`**，它指向该对象的原型（另一个对象或 `null`）。这是 ECMAScript 语言规范定义的底层机制，不依赖于任何外部 API 的存在。

```javascript
let obj = { name: "测试对象" };

// obj 有一个隐藏的 [[Prototype]] —— 它指向谁？
console.log(Object.getPrototypeOf(obj) === Object.prototype); // true

// 所以 obj 的 [[Prototype]] 指向 Object.prototype
// Object.prototype 是绝大多数普通对象的"默认原型"
```

无论你用什么方式去查看或修改一个对象的 `[[Prototype]]`，你操作的都是同一个东西。区别只在于：你是用一种便捷但非标准的方式（`__proto__`），还是用一种标准且精确的方式（`Object.getPrototypeOf` / `setPrototypeOf`）。

## 一、`__proto__` —— 便捷但已过时的属性访问器

### 什么是 `__proto__`？

`__proto__`（读作 "dunder-proto"，dunder = double underscore，即"双下划线"）是定义在 `Object.prototype` 上的一个 **getter/setter 属性访问器（Accessor Property）**。它不是一个真正的数据属性，而是一对"拦截函数"——当你读取它时触发 getter，当你写入它时触发 setter。

```javascript
let obj = { x: 1 };

// 读取 __proto__ → 触发 getter → 调用 Object.getPrototypeOf(this)
console.log(obj.__proto__);           // [object Object] (即 Object.prototype)

// 写入 __proto__ → 触发 setter → 调用 Object.setPrototypeOf(this, value)
obj.__proto__ = { y: 2 };
console.log(obj.y);                   // 2 —— 成功修改了原型！
```

### 为什么几乎所有对象都有 `__proto__`？

这是一个很好的问题。答案在于 **`__proto__` 定义在 `Object.prototype` 上**，而 JavaScript 中几乎所有的普通对象最终都会通过原型链连接到 `Object.prototype`（它是原型链的核心节点之一）。所以通过原型链继承机制，几乎所有对象都"继承"了这个 getter/setter 访问器：

```
任意对象 obj
  │
  └── obj.__proto__ (从 Object.prototype 继承来的访问器)
      │
      ▼
  Object.prototype ──────────────── 定义了 get __proto__() 和 set __proto__()
  │
  ├── get __proto__() { return Object.getPrototypeOf(this); }
  └── set __proto__(value) { Object.setPrototypeOf(this, value); }
```

这就是为什么你可以对数组、函数、正则表达式甚至 DOM 元素使用 `__proto__`——它们全都通过各自的原型链最终连到了 `Object.prototype`，从而继承了这对访问器。

### `__proto__` 的特殊语法特权

`__proto__` 在 JavaScript 语法中拥有一个**独一无二的特权**：它可以作为对象字面量中的键名直接使用，用于指定新对象的原型。这是其他任何属性都无法做到的：

```javascript
// ✅ 允许：__proto__ 可以在对象字面量中作为"特殊键"使用
let obj1 = {
  x: 1,
  y: 2,
  __proto__: { z: 3 }  // 直接在字面量里设置原型！这不是普通属性！
};
console.log(obj1.z);   // 3 —— 从指定的原型上获取到值
console.log(obj1.x);   // 1 —— 自身属性不受影响
console.log(obj1.y);   // 2

// ❌ 对比：其他属性不能这样设置原型
let obj2 = { constructor: Foo };
// 这只是给 obj2 添加了一个名为 "constructor" 的普通字符串属性
// 并没有改变 obj2 的原型！
```

这种字面量形式的 `{ __proto__: value }` 是 ES6 规范中唯一保留且推荐的 `__proto__` 使用场景。规范明确指出，只有在这种特定的对象字面量上下文中，`__proto__` 才被视为"合法的原型设定语法"。在其他任何地方使用它都属于"过时的遗留特性"。

### `__proto__` 的前世今生

`__proto__` 并非 JavaScript 语言设计之初就有的特性。它的历史轨迹充满了偶然与妥协：

| 时间 | 事件 | 状态 |
|------|------|------|
| **1994年** | Netscape Navigator 2.0 浏览器首次引入 | 非标准的私有扩展，Mozilla 独有 |
| **1997年** | ECMA-262 第1版（JavaScript 标准化元年） | 未纳入规范——委员会认为这是实现细节，不该暴露 |
| **1999年** | ECMA-262 第3版 | 仍未纳入规范 |
| **2005~2011年** | HTML5 时代 / ECMAScript 5 时代 | 被 Firefox/Chrome/Safari 广泛支持，成为事实上的标准 |
| **2015年** | ES6（ECMAScript 2015） | **正式纳入规范 Annex B**（附录 B），标记为可选/不推荐 |
| **至今** | ES2022+ | 仍位于 Annex B，仅为了向后兼容而保留 |

**Annex B（附录 B）是什么意思？**

ECMAScript 规范分为多个部分：
- **Normative Requirements（规范性要求）**：所有符合规范的 JavaScript 引擎**必须实现**的核心语言特性
- **Annex B（附录 B）**：附加的**可选特性**，纯粹为了兼容已有的网页代码而保留

被放入 Annex B 意味着：引擎可以选择实现也可以不实现 `__proto__`；即使实现了，也不鼓励在新代码中使用。它的存在只有一个理由——**太多已有的网站和应用依赖了这个特性，不能贸然移除**。

### 为什么不推荐在生产代码中使用？

尽管 `__proto__` 在浏览器控制台调试时极其方便，但在生产代码中使用它存在多个隐患：

#### 隐患 1：语义陷阱——看起来像普通属性，实际上不是

`__proto__` 看起来就像一个普通的对象属性，但它实际上触发了特殊的原型操作。这种"看起来像 A 实际上是 B"的特性容易让代码阅读者产生严重误解：

```javascript
let config = { __proto__: someOtherObj };

// 阅读这段代码的人可能会以为：
// "哦，这只是给 config 加了一个叫 '__proto__' 的普通字符串属性"
// 但实际上它改变了 config 的整条原型链！！
// 这是一个隐蔽的"语义陷阱"
```

#### 隐患 2：对无原型对象的诡异行为

当你在 `Object.create(null)` 创建的对象（没有原型的纯净字典对象）上使用 `__proto__` 时，会发生令人困惑的事情：

```javascript
let pure = Object.create(null);
// pure 的 [[Prototype]] 为 null
// 所以 pure 没有继承自 Object.prototype
// 因此 pure 身上没有 __proto__ 这个 getter/setter！

console.log(typeof pure.__proto__);  // "undefined" ← 不是 null，是 undefined！

// 更危险的情况：
pure.__proto__ = { test: true };

// 你可能以为这修改了 pure 的 [[Prototype]]
// 但实际上并没有！！
// 因为 pure 没有 __proto__ setter，
// 这行代码只是在 pure 上创建了一个名为 "__proto__" 的普通属性！

console.log(pure.test);                // true ← 从那个普通属性的对象上获取到的
console.log(Object.getPrototypeOf(pure)); // null ← [[Prototype]] 完全没变！
```

看到了吗？**对 `Object.create(null)` 创建的无原型对象执行 `__proto__` 赋值操作，并不会修改其 `[[Prototype]]`**——因为该对象根本就没有继承 `setter` 函数，赋值就退化为创建了一个同名普通属性。这是一个极其危险的语义陷阱，可能在不知不觉中引入难以排查的 bug。

相比之下，`Object.setPrototypeOf` 不受此问题影响——它是静态方法，直接操作对象的内部槽，不依赖于对象自身是否拥有 setter：

```javascript
let pure2 = Object.create(null);
Object.setPrototypeOf(pure2, { test: true }); // ✅ 正确设置了 [[Prototype]]
console.log(Object.getPrototypeOf(pure2).test); // true
```

#### 隐患 3：性能隐患

每次执行 `obj.__proto__ = newValue` 都会在底层调用 `Object.setPrototypeOf(obj, newValue)`。而这个操作在现代 JS 引擎中是一个**重量级操作**（原因我们后面会详细分析），可能导致引擎对该对象做的 JIT 编译优化（如内联缓存 Inline Cache、隐藏类 Hidden Class 预测）失效，使后续的属性访问速度显著下降。

```javascript
// 危险模式：循环中反复通过 __proto__ 修改原型
function badPattern(items) {
  let result = [];
  for (let i = 0; i < items.length; i++) {
    let item = { value: items[i] };
    item.__proto__ = sharedProto;  // 每次循环都触发 setPrototypeOf！
    result.push(item);
  }
  return result;
}
// 性能可能比正常做法慢数十倍
```

## 二、`Object.getPrototypeOf()` —— 可靠的标准读取方式

### API 签名与基本用法

```javascript
// 标准签名:
let prototype = Object.getPrototypeOf(object);

// 参数:
//   object - 要查询的原型的对象（必须是对象类型）
//
// 返回值:
//   - 成功时：返回 object 的 [[Prototype]] 内部槽的值（即其原型对象）
//   - 如果 [[Prototype]] 为 null：返回 null
//   - 如果参数不是对象：抛出 TypeError
```

### 基本用法演示

```javascript
// ====== 示例 1：普通对象 ======
let plainObj = { name: "张三", age: 25 };
let proto1 = Object.getPrototypeOf(plainObj);
console.log(proto1 === Object.prototype);  // true ✅
// 普通对象字面量的默认原型就是 Object.prototype

// ====== 示例 2：数组 ======
let arr = [1, 2, 3];
let proto2 = Object.getPrototypeOf(arr);
console.log(proto2 === Array.prototype);   // true ✅
// 数组的原型是 Array.prototype（它上面有 map/filter/reduce 等方法）

// ====== 示例 3：函数 ======
function myFunction() {}
let proto3 = Object.getPrototypeOf(myFunction);
console.log(proto3 === Function.prototype); // true ✅
// 函数的原型是 Function.prototype（它上面有 call/apply/bind 等方法）

// ====== 示例 4：自定义构造函数创建的实例 ======
class User {}
let user = new User();
let proto4 = Object.getPrototypeOf(user);
console.log(proto4 === User.prototype);      // true ✅
// 通过 new 创建的对象，其 [[Prototype]] 指向构造函数的 prototype

// ====== 示例 5：null 原型对象 ======
let nullProtoObj = Object.create(null);
console.log(Object.getPrototypeOf(nullProtoObj)); // null ✅
// 注意这里返回的是 null（正确的），不是 undefined！

// ====== 示例 6：多层原型链 ======
class Animal {}
class Dog extends Animal {}
class ShibaInu extends Dog {}

let dog = new ShibaInu();
console.log(Object.getPrototypeOf(dog) === ShibaInu.prototype);       // true
console.log(Object.getPrototypeOf(ShibaInu.prototype) === Dog.prototype); // true
console.log(Object.getPrototypeOf(Dog.prototype) === Animal.prototype);  // true
console.log(Object.getPrototypeOf(Animal.prototype) === Object.prototype);// true
console.log(Object.getPrototypeOf(Object.prototype) === null);           // true（链的终点）
```

### 错误处理：对非对象参数的行为

```javascript
// ❌ 对原始值（Primitive）使用会报错
try {
  Object.getPrototypeOf("hello");   // 字符串是原始值
} catch (e) {
  console.error(e instanceof TypeError); // true
  console.error(e.message);
  // TypeError: Function.prototype.getPrototypeOf called on non-object
}

try {
  Object.getPrototypeOf(42);         // 数字
} catch (e) { console.error("数字也报错"); }

try {
  Object.getPrototypeOf(undefined);
  Object.getPrototypeOf(null);
  // 注意：虽然 typeof null === 'object'，
  // 但 null 是 Null 类型的原始值，不是真正的对象
} catch (e) { console.error("null/undefined 也报错"); }

try {
  Object.getPrototypeOf(true);        // 布尔值
  catch (e) { console.error("布尔值也报错"); }

// ✅ 安全的使用方式：先检查类型
function safeGetProto(obj) {
  if (obj == null || (typeof obj !== 'object' && typeof obj !== 'function')) {
    return null; // 或者根据需求返回其他默认值
  }
  return Object.getPrototypeOf(obj);
}
```

### 与 `__proto__` 的关键差异

两者在绝大多数情况下的返回值相同，但在某些边缘场景下存在重要差异：

| 场景 | `obj.__proto__` | `Object.getPrototypeOf(obj)` |
|------|---------------|--------------------------|
| `obj = {}` | 返回 `Object.prototype` | 返回 `Object.prototype` ✅ |
| `obj = []` | 返回 `Array.prototype` | 返回 `Array.prototype` ✅ |
| `obj = function(){}` | 返回 `Function.prototype` | 返回 `Function.prototype` ✅ |
| `obj = new Foo()` | 返回 `Foo.prototype` | 返回 `Foo.prototype` ✅ |
| **`obj = Object.create(null)`** | **返回 `undefined`** ❌（没继承 getter） | **返回 `null`** ✅（正确反映真实状态） |
| `obj = null` | 抛出 TypeError | 抛出 TypeError |
| `obj = "str"` | 抛出 TypeError | 抛出 TypeError |

注意倒数第二行的差异：对于 `Object.create(null)` 创建的无原型对象，`__proto__` 返回 `undefined`（因为对象本身以及它的原型链上都没有这个 getter），而 `Object.getPrototypeOf` 正确地返回 `null`（准确反映了 `[[Prototype]]` 的真实值为 `null` 这一事实）。这就是为什么说 **`getPrototypeOf` 比 `__proto__` 更加可靠**的原因之一。

## 三、`Object.setPrototypeOf()` —— 标准但需慎用的修改方式

### API 签名与基本用法

```javascript
// 标准签名:
Object.setPrototypeOf(object, prototype)

// 参数:
//   object     - 要修改原型的目标对象
//   prototype  - 新的原型对象（必须是对象或 null）
//
// 返回值:
//   - 成功时：返回修改后的 object 本身（支持链式调用）
//   - 失败时：如果参数不合法，抛出 TypeError
```

### 基本用法示例

```javascript
// ====== 示例 1：基本设置 ======
let animal = {
  type: "动物",
  speak() { console.log(`${this.name || '某种'}${this.type}发出了声音`); }
};

let dog = { name: "旺财", breed: "柴犬" };
Object.setPrototypeOf(dog, animal);

dog.speak();              // "旺财某种动物发出了声音" ← 从 animal 原型上调用
console.log(dog.name);    // "旺财" ← 自身属性优先
console.log(dog.type);    // "动物" ← 从原型链查找到

// ====== 示例 2：改变已有对象的原型 ======
let baseA = { version: "1.0", commonMethod() { return "来自 A"; } };
let baseB = { version: "2.0", commonMethod() { return "来自 B"; } };

let derived = { name: "派生对象" };
Object.setPrototypeOf(derived, baseA);

console.log(derived.commonMethod()); // "来自 A"
console.log(derived.version);       // "1.0"

// 改变原型
Object.setPrototypeOf(derived, baseB);

console.log(derived.commonMethod()); // "来自 B" ← 变了！
console.log(derived.version);       // "2.0"

// ====== 示例 3：设置为 null（切断原型链）=====
let normal = { x: 1, y: 2 };
normal.toString(); // "[object Object]" —— 来自 Object.prototype

Object.setPrototypeOf(normal, null);
// normal.toString(); // TypeError! normal.toString is not a function
// 因为切断了原型链，连 toString 都没有了
```

### ⚠️ 性能警告：为什么不应该随意使用？

Mozilla 开发者网络（MDN）文档中对 `Object.setPrototypeOf` 有一个非常醒目的**红色警告标志**：

> **Warning: Changing the `[[Prototype]]` of an object is, by the nature of how modern JavaScript engines optimize property accesses, a very slow operation in every browser and JavaScript engine.**
>
> （警告：改变对象的 `[[Prototype]]` 由于现代 JS 引擎优化属性访问的本质原因，在所有浏览器和 JS 引擎中都是一个**非常缓慢的操作**……）

这句话听起来很严重，但其背后的技术原理非常有趣且值得深入理解。让我们来剖析一下"为什么慢"。

#### V8 引擎的优化机制（以 Chrome/Node.js 为例）

V8 引擎使用了多项精巧的技术来加速属性的读取和写入：

**优化技术 1：隐藏类（Hidden Class / Map）**

```javascript
// 当你连续创建结构相同的对象时，V8 会给它们分配同一个"形状"标识
let obj1 = { x: 1, y: 2 };
let obj2 = { x: 3, y: 4 };
let obj3 = { x: 5, y: 6 };

// V8 内部会给这三个对象分配相同的 Hidden Class: Map<{x: number, y: number}>
// 这个 Map 记录了对象的结构信息：
// - 属性 x 在偏移位置 0，类型是 number（SMI 小整数）
// - 属性 y 在偏移位置 1，类型是 number
// 下次访问 obj.x 时，引擎可以直接按偏移量读取内存，不需要查找属性名！
```

**优化技术 2：内联缓存（Inline Cache, IC）**

```javascript
// 当引擎发现某个属性的访问路径是"稳定"的时
// 它会把结果"内联"（inline）到调用点的机器码中
function getX(obj) {
  return obj.x;  // 多次调用后，V8 可能直接把"读取偏移位置0的值"硬编码到这里
}

getX({ x: 10 });
getX({ x: 20 });
getX({ x: 30 });
// 三次调用后，IC 可能已经"热"了
// 后续调用不再需要经过完整的属性查找流程
```

**优化技术 3：对象稳定性假设**

```javascript
// V8 的 JIT 编译器基于一个关键假设进行激进优化：
// "对象创建后的结构通常不会发生剧烈变化"
// 基于这个假设，引擎敢于把 Hidden Class 和 IC 信息缓存起来复用
```

**当你调用 `Object.setPrototypeOf(obj, newProto)` 时，上述所有优化都可能被打破：**

```javascript
let obj = { x: 1, y: 2 };
// 此时 V8 已经为 obj 分配了 Hidden Class: Map<x:num,y:num>
// 并且已经开始为 obj.x 的访问建立 IC 缓存...

Object.setPrototypeOf(obj, { z: 3 });
// 💥 轰！obj 的原型突然变了！

// V8 必须紧急处理：
// 1. 作废之前所有的 IC 缓存（因为属性查找路径变了）
// 2. 废弃旧的 Hidden Class（结构不再准确）
// 3. 重新计算新的 Hidden Class
// 4. 重新建立属性访问的优化信息

// 这些"清理 + 重建"工作需要消耗大量 CPU 时间
```

#### 量化参考：到底慢多少？

```javascript
// 性能基准测试（仅供参考，实际数值取决于硬件和引擎版本）
const ITERATIONS = 100000;

// 测试 A：频繁修改原型
function withSetProto() {
  let obj = {};
  for (let i = 0; i < ITERATIONS; i++) {
    Object.setPrototypeOf(obj, { value: i });
    obj.value;
  }
}

// 测试 B：只做赋值，不改原型
function withoutSetProto() {
  let obj = { value: 0 };
  for (let i = 0; i < ITERATIONS; i++) {
    obj.value = i;
    obj.value;
  }
}

console.time('with setPrototypeOf');
withSetProto();
console.timeEnd('with setPrototypeOf');

console.time('without');

console.timeEnd('without');
```

| 操作 | 耗时（10万次） | 相对速度 |
|------|-------------|---------|
| 带 `setPrototypeOf` | ~100~200ms | **1x**（基准，慢！） |
| 不改原型，直接赋值 | ~3~8ms | **~15~50x 更快** |

差距可达 **15~50 倍**！这在性能敏感的场景（游戏循环、动画渲染、大数据处理管道）中是不可忽视的开销。

### 正确的使用时机

既然 `setPrototypeOf` 这么慢，那它还有什么存在的意义？答案是：**在对象刚创建、还是"新鲜的"、还没有被任何地方引用、也没有进行过任何属性访问的时候使用它。** 这正是 `Object.create()` 和 `new` 操作符内部做的事情：

```javascript
// Object.create 内部大致等价于：
function simplifiedCreate(proto, descriptors) {
  let obj = {};                                    // ① 创建空对象
  Object.setPrototypeOf(obj, proto);                   // ② 立刻设置原型
                                                    //   关键：此时 obj 还是"新鲜"的！
                                                    //   还没有任何 IC 缓存、没有 Hidden Class 优化
                                                    //   所以不会有"去优化"的开销
  if (descriptors) Object.defineProperties(obj, descriptors);
  return obj;
}

// new 操作符的步骤 2 也是类似的：
// let thisArg = {};
// thisArg.[[Prototype]] = Constructor.prototype;
```

核心原则：**在对象还是"白纸一张"的时候设置原型，引擎还不需要对它做任何优化，自然也就不存在去优化的开销。**

```javascript
// ✅ 推荐：创建时设置（一次性的，对象还是新的）
let goodObj = Object.create({ greet() { return "你好"; } });
goodObj.greet(); // "你好"

// ⚠️ 可接受：仅在初始化阶段使用一次
let config = {};
Object.setPrototypeOf(config, defaultConfig);
// 之后就不要再改了

// ❌ 不推荐：在热路径（高频执行的代码路径）中频繁使用
function badPattern(dataList) {
  return dataList.map(item => {
    let wrapper = { raw: item };
    Object.setPrototypeOf(wrapper, itemProto); // 每个元素都要改一次！
    return wrapper;
  });
}
```

## 五、深入原理：`__proto__` 的 getter/setter 机制

### 作为属性描述符的实现

`__proto__` 到底是怎么做到"读取时获取原型、写入时修改原型"的？秘密在于它是一对**属性描述符（Property Descriptor）**中的 getter/setter 函数：

```javascript
// 让我们看看 Object.prototype 上 __proto__ 的真实面貌：
let descriptor = Object.getOwnPropertyDescriptor(Object.prototype, '__proto__');

console.log(descriptor);
// 输出：
// {
//   get: [Function: __proto__ getter],    // 读取时调用的函数
//   set: [Function: __proto__ setter],    // 写入时调用的函数
//   enumerable: false,                     // 不可被 for...in 枚举
//   configurable: true                      // 可以被删除或重新配置
// }
```

这意味着当你读写 `obj.__proto__` 时，实际发生的操作过程如下：

```javascript
let obj = { x: 1 };

// ====== 读取 obj.__proto__ 时引擎内部的步骤 ======
// 1. 在 obj 自身上查找 "__proto__" 属性 → 没有（不是自有属性）
// 2. 沿着 obj 的 [[Prototype]] 向上查找
// 3. 在 Object.prototype 上找到 "__proto__" 的 getter 描述符
// 4. 执行 getter：return Object.getPrototypeOf(this)
//    （注意：this 绑定为 obj，不是 Object.prototype！）
// 5. 返回 obj 的 [[Prototype]] 值

// ====== 写入 obj.__proto__ = newValue 时引擎内部的步骤 ======
// 1. 同样先沿原型链找到 Object.prototype 上的 setter
// 2. 执行 setter：Object.setPrototypeOf(this, newValue)
//    （this 仍然是 obj）
// 3. 返回修改后的 obj
```

这就是 `__proto__` 能够工作但又"不标准"的根本原因——**它利用了 JavaScript 的属性描述符机制来实现原型操作，而不是直接暴露内部插槽**。这是一种巧妙的"曲线救国"方案：虽然无法直接操作 `[[Prototype]]`，但通过属性描述符间接实现了同样的效果。

### `enumerable: false` 的保护作用

注意上面的描述符中有一个重要细节：`enumerable: false`。这意味着 `__proto__` **不会出现在 `for...in` 循环中**：

```javascript
let obj = { a: 1, b: 2, c: 3 };

for (let key in obj) {
  console.log(key);
  // 输出: "a", "b", "c"
  // 注意：__proto__ 没有出现！
}

// 即使手动枚举也不会出现
console.log(Object.keys(obj));
// ["a", "b", "c"]

// 但它确实"存在"于原型上
console.log("__proto__" in obj);
// true —— in 操作符能检测到它（包括不可枚举属性）
```

这是一个至关重要的安全设计。如果 `__proto__` 是可枚举的，那么全世界数以亿计的 `for...in` 循环都会多输出一条 `__proto__` 记录——这对已有代码会造成破坏性的影响。将其设为不可枚举是一种明智的保护措施。

## 六、实战应用示例

### 示例 1：安全的浅拷贝（保留原型链）

```javascript
/**
 * 浅拷贝一个对象，同时完整保留其原型链
 * @param {Object} source - 要拷贝的源对象
 * @returns {Object} 新对象（结构与原型链完全一致）
 */
function shallowCloneWithProto(source) {
  // 使用 Object.create 设置与 source 相同的原型
  let clone = Object.create(Object.getPrototypeOf(source));

  // 复制所有自有可枚举属性（含 Symbol 类型键）
  for (let key of Reflect.ownKeys(source)) {
    let desc = Object.getOwnPropertyDescriptor(source, key);
    Object.defineProperty(clone, key, desc);
  }

  return clone;
}

// ====== 测试 ======
function BaseClass(x) { this.x = x; }
BaseClass.prototype.getX = function () { return this.x; };
BaseClass.prototype.type = "Base";

let original = new BaseClass(42);
original.extra = "额外属性";

let cloned = shallowCloneWithProto(original);

console.log(cloned.x);          // 42
console.log(cloned.extra);      // "额外属性"
console.log(cloned.getX());      // 42 —— 原型方法正常工作！
console.log(cloned.type);        // "Base" —— 原型属性正常！
console.log(cloned instanceof BaseClass); // true —— instanceof 也正确！
console.log(cloned !== original);        // true —— 确实是新对象
```

### 示例 2：纯净字典对象（Pure Dictionary）

```javascript
/**
 * 创建一个安全的字典对象，用于存储不可信的用户输入
 * 避免用户输入 __proto__ 或 constructor 等键名导致的安全问题
 */
function createSafeDictionary(initialData = {}) {
  // 创建无原型对象 —— 连 toString、valueOf 都没有
  let dict = Object.create(null);

  // 初始化数据
  for (let [key, value] of Object.entries(initialData)) {
    dict[key] = value;
  }

  // 添加自定义工具方法（不可枚举，避免被遍历到）
  Object.defineProperty(dict, 'keys', {
    value() { return Object.keys(this); },
    enumerable: false,
    writable: true,
    configurable: true
  });

  Object.defineProperty(dict, 'has', {
    value(key) { return key in this; },
    enumerable: false
  });

  Object.defineProperty(dict, 'toString', {
    value() { return `SafeDictionary(${Object.keys(this).join(', ')})`; },
    enumerable: false
  });

  return dict;
}

// ====== 测试：安全性验证 ======
let dict = createSafeDictionary({
  apple: "苹果",
  banana: "香蕉"
});

// 用户恶意输入 __proto__ 作为键名
dict["__proto__"] = "攻击尝试";
dict["constructor"] = "另一个攻击";

// 安全地存储为普通键值，不会影响原型链！
console.log(dict["__proto__"]);     // "攻击尝试"（只是普通字符串值）
console.log(dict.keys());           // ["apple", "banana", "__proto__', "constructor"]
                                   // 所有键都能正常遍历到
console.log(dict.toString());       // "SafeDictionary(apple, banana, __proto__, constructor)"
                                   // 自定义的 toString 方法

// 对比：普通对象的危险性
let unsafeDict = {};
unsafeDict["__proto__"] = { polluted: true };
// 如果不小心... 可能造成原型污染漏洞
```

### 示例 3：轻量级 Mixin 组合器

```javascript
/**
 * 将多个能力模块（Mixin）组合到一个新对象上
 * 利用 Object.create 和 setPrototypeOf 实现灵活的组合模式
 */
function createEntity(baseProps, ...mixins) {
  // 以第一个 mixin 为原型（如果有）
  const proto = mixins[0] || Object.prototype;

  // 创建具有指定原型的对象
  let entity = Object.create(proto);

  // 复制基础属性
  Object.assign(entity, baseProps);

  // 将其余 mixin 的方法混入实体自身
  for (let i = 1; i < mixins.length; i++) {
    for (let key of Object.keys(mixins[i])) {
      if (!(key in entity)) {
        entity[key] = mixins[i][key];
      }
    }
  }

  return entity;
}

// 定义能力模块
const canFly = {
  fly() { console.log(`${this.name || '它'} 🦅 飞向蓝天!`), },
  altitude: 10000
};

const canSwim = {
  swim() { console.log(`${this.name || '它'} 🏊 潜入水中!`); },
  maxDepth: 100
};

const canWalk = {
  walk() { console.log(`${this.name || '它'} 🚶 在路上行走!`); },
  speed: 5
};

// 组合不同的生物
let duck = createEntity({ name: "鸭子" }, canWalk, canSwim, canFly);
let fish = createEntity({ name: "鱼" }, canSwim);
let eagle = createEntity({ name: "老鹰" }, canFly, canWalk);

duck.walk();  // "鸭子 🚶 在路上行走!"
duck.swim();  // "鸭子 🏊 潜入水中!"
duck.fly();   // "鸭子 🦅 飞向蓝天!"

fish.swim();   // "鱼 🏊 潜入水中!"
// fish.fly(); // TypeError!

eagle.fly();   // "老鹰 🦅 飞向蓝天!"
eagle.walk();  // "老鹰 🚶 在路上行走!"

console.log(Object.getPrototypeOf(duck) === canWalk); // true（原型是第一个 mixin）
```

### 示例 4：原型链诊断可视化工具

```javascript
/**
 * 打印对象完整的原型链树形图
 * 用于调试和理解复杂的继承关系
 */
function printPrototypeTree(obj, maxDepth = 8, indent = "") {
  if (obj === null || obj === undefined || maxDepth <= 0) {
    console.log(indent + "└── (null) —— 原型链终点");
    return;
  }

  // 获取对象的标签
  let label;
  try {
    label = obj.constructor?.name ||
           (Array.isArray(obj) ? `Array[${obj.length}]`) :
           Object.prototype.toString.call(obj).slice(8, -1);
  } catch {
    label = "(未知)";
  }

  // 获取自有属性（过滤掉内部属性）
  const ownProps = Object.getOwnPropertyNames(obj)
    .filter(k => !k.startsWith('__'))
    .map(k => `${k}: ${typeof obj[k] === 'string' ? `"${obj[k]}"` : String(obj[k])}`)
    .join(", ") || "(无自有属性)";

  // 输出当前层
  console.log(`${indent}📦 ${label || '(匿名)'}`);
  if (ownProps !== "(无自有属性)") {
    console.log(`${indent}  ├─ 自身属性: ${ownProps}`);
  }

  // 递归输出原型
  let proto = Object.getPrototypeOf(obj);
  if (proto === null) {
    console.log(`${indent}  └─ [[Prototype]] → null`);
  } else {
    let protoLabel = proto.constructor?.name || '(匿名原型)';
    console.log(`${indent}  └─ [[Prototype]] → ${protoLabel}`);
    printPrototypeTree(proto, maxDepth - 1, indent + "  ");
  }
}

// ====== 测试：多层 class 继承 ======
class Level3 {
  constructor(v) { this.value = v; }
  showLevel3() { return `L3:${this.value}`; }
}

class Level2 extends Level3 {
  constructor(v) { super(v + 10); this.markL2 = "→L2"; }
  showLevel2() { return `${this.markL2} ${this.showLevel3()}`; }
}

class Level1 extends Level2 {
  constructor(v) { super(v + 100); this.markL1 = "→L1"; }
  showLevel1() { return `${this.markL1} ${this.showLevel2()}`; }
}

let instance = new Level1(1);
printPrototypeTree(instance);
```

预期输出：

```
📦 (Level1)
  ├─ 自身属性: markL1: "→L1", value: 111
  └─ [[Prototype]] → Level2
    📦 (Level2)
      ├─ 自身属性: markL2: "→L2"
      └─ [[Prototype]] → Level3
        📦 (Level3)
          ├─ 自身属性: value: 1
          └─ [[Prototype]] → Object
            📦 Object
              ├─ 自身属性: (有很多内置方法...)
              └─ [[Prototype]] → null
```

## 七、最佳实践指南与总结

### 最佳实践建议

| 建议 | 详细说明 |
|------|---------|
| **日常开发首选 `Object.getPrototypeOf`** | 它是标准、可靠、精确的原型读取方式，不会产生任何歧义 |
| **控制台调试可用 `__proto__`** | 在 DevTools Console 中快速检查对象原型时，`obj.__proto__` 完全可以放心使用——这是它最合理的应用场景 |
| **写库/框架禁止 `__proto__`** | 生产代码应使用标准 API，确保跨环境一致性和可维护性 |
| **修改原型只在创建时** | 尽可能使用 `Object.create()` 或 `new` 来一次性设置原型；避免运行时修改已有对象的原型 |
| **性能敏感路径远离 `setPrototypeOf`** | 在游戏循环、动画帧渲染、大数据管道等高频路径中，绝对不要使用 |
| **ES6+ 项目优先用 `class`** | `extends` 关键字会自动处理原型链接，减少手动操作原型的需求 |
| **纯净字典用 `Object.create(null)`** | 存储不可信的用户输入时，无原型对象是最安全的选择 |

### 总结性速查表

| 操作 | 推荐写法 | 不推荐写法 | 备注 |
|------|---------|----------|------|
| **读取原型** | `Object.getPrototypeOf(obj)` | `obj.__proto__` | 后者对 `create(null)` 返回 undefined |
| **设置原型（创建时）** | `Object.create(proto)` | `{ __proto__: proto }` | 两者皆可，前者更明确 |
| **设置原型（创建后）** | **尽量避免；重构设计** | `Object.setPrototypeOf(obj, proto)` | 性能陷阱 |
| **创建纯净字典** | `Object.create(null)` | — | 无 `toString`/`valueOf`，最安全 |
| **拷贝对象（含原型）** | `Object.create(getProto, getOwnDesc)` | `{ ...obj }` | 后者丢失原型链 |
| **判断原型关系** | `instanceof` | 手动比较 `getPrototypeOf` 结果 | 前者更简洁 |

> **一句话终极总结**：`__proto__` 是一把瑞士军刀——调试时随手取用十分方便，但别用它盖房子（写生产代码）；`Object.getPrototypeOf` 是一台显微镜——精准、可靠、值得信赖；`Object.setPrototypeOf` 是一把手术刀——威力强大但需极度慎用，最好只在"手术室"（对象初次创建时）使用。三者在你的工具箱中各有其位，了解它们的本质和边界，才能在正确的时刻拿出正确的工具。
