# 函数的 `prototype` 属性与 `constructor` 属性

## 一对"孪生兄弟"——两个经常被混淆的概念

在 JavaScript 的原型系统中，有两个名字极其相似但本质完全不同的属性：函数身上的 **`prototype`** 和原型对象上的 **`constructor`**。它们像一对形影不离的"孪生兄弟"——一个住在"父亲身上"（函数），一个住在"孩子身上"（原型对象）；一个指向对方，另一个也指回对方，形成了一个完美的双向引用环。

很多初学者（甚至一些有经验的开发者）对这对概念的理解停留在模糊的阶段：知道它们存在，知道大概有什么用，但说不清它们的精确关系、什么时候会出问题、为什么需要特别小心地维护。本章将彻底厘清这两个概念的来龙去脉。

### 为什么这两个属性如此重要？

**`prototype`** 是整个 JavaScript 原型继承系统的**基石性机制**——没有它，`new` 操作符就无法建立对象与原型的链接，继承就无从谈起。每次你写 `new Foo()` 时，引擎都在背后使用 `Foo.prototype` 来决定新对象的"出身"。

**`constructor`** 则是原型链上的**身份标识**——它让每个实例都能回答"我是谁创建的"这个问题。当你拿到一个来源不明的对象时，可以通过 `obj.constructor` 追溯到它的构造函数，进而了解它的类型信息、创建方式、以及如何复制同类对象。

理解这两个属性的精确行为和相互关系，是掌握 JavaScript 面向对象编程的必修课。

### 通俗类比：出生证明与户籍登记

让我们用一个更贴近生活的比喻来建立直觉：

想象每个构造函数（如 `User`、`Animal`、`Product`）都是一家**医院**（或更准确地说，是一家**生育中心**）。每家医院在注册成立时，都会自动获得一份标准的**出生证明模板**——这就是 **`prototype`**。这份模板上预先印好了"接生医院名称"字段（即 `constructor` 字段，指向医院自己）。

当医院接生了一个新生儿（通过 `new` 创建的**实例对象**）时：
1. 医院会把那份标准模板（`prototype`）复印一份作为新生儿的**健康档案**（新对象的 `[[Prototype]]`）
2. 档案的第一页写着"本档案由 XX 医院出具"（`constructor` 指向构造函数）
3. 新生儿长大后（代码运行时），如果想查自己是在哪家医院出生的，翻开健康档案第一页就能看到（通过 `obj.constructor` 查询）

关键点在于：
- **模板（prototype）属于医院（函数），不属于婴儿（实例）**
- **模板复印件（[[Prototype]]）属于婴儿（实例），上面记载了医院的名字（constructor）**
- 如果你把医院的模板换成了另一家医院的（覆盖 `prototype`），但没有更新上面的"接生医院名称"字段——那新生儿翻看档案时会看到错误的信息！

这就是 `prototype` 和 `constructor` 之间关系的精髓所在。

## 函数的 `prototype` 属性 —— "出生证明模板"

### 什么是 `prototype`？

**定义**：每一个 JavaScript 函数对象都有一个名为 `prototype` 的属性。这是一个**普通的、可写的、可枚举的数据属性**，其值默认是一个对象。

**关键事实**：

```javascript
// 普通函数有 prototype
function ordinaryFunction() {}
console.log(typeof ordinaryFunction.prototype); // "object"

// 箭头函数也有 prototype！（虽然不能用作构造函数）
const arrowFn = () => {};
console.log(typeof arrowFn.prototype);         // "object"

// 类也有 prototype（class 本质是语法糖）
class MyClass {}
console.log(typeof MyClass.prototype);          // "object"

// 内置构造函数当然也有
console.log(typeof Array.prototype);             // "object"
console.log(typeof Object.prototype);            // "object"
```

**重要**：`prototype` 是**函数**特有的属性！普通对象（如 `{}`、`[]`）**没有** `prototype` 属性：

```javascript
let obj = {};           // 普通对象
let arr = [];           // 数组

console.log(obj.prototype);    // undefined ❌
console.log(arr.prototype);    // undefined ❌

// 但它们有 [[Prototype]]（内部槽）和 __proto__（访问器）
console.log(Object.getPrototypeOf(obj) === Object.prototype); // true ✅
```

这个区别是初学者最容易混淆的地方之一。请记住一句话：**`prototype` 是函数的"私有财产"，普通对象没有资格拥有它。**

### 默认的 `prototype` 结构

当一个函数被创建时（无论用什么方式——`function` 声明、箭头函数、`class` 定义），JavaScript 引擎都会自动为它生成一个 `prototype` 对象。这个对象的**默认结构非常简单——只包含一个 `constructor` 属性**：

```javascript
// 当你写下这行代码时：
function User(name) {
  this.name = name;
}

// 引擎在后台自动做了这件事（等价于）：
// User.prototype = {
//   constructor: User   // ← 自动添加！指向 User 函数本身
// };

// 验证：
console.log(User.prototype);                    // { constructor: User }
console.log(User.prototype.constructor === User); // true ✅
console.log(User.prototype.constructor.name);     // "User"
```

**理论补充：为什么引擎要自动设置 `constructor`？**

这是 ECMAScript 规范的要求。规范规定：每当创建一个函数对象 `F` 时，必须同时执行以下操作：

1. 创建一个普通对象 `P`
2. 将 `P` 的 `constructor` 属性设为 `F`（不可枚举、不可配置、可写）
3. 将 `F.prototype` 设为 `P`

这样做的目的是提供一种**反向追溯能力**——从实例出发，沿着原型链找到 `constructor`，就能知道是哪个函数创建了这个实例。这是一种语言级别的便利设施，虽然不是强制性的（开发者可以随意修改甚至删除它），但它提供了有用的语义信息。

### `prototype` 在 `new` 操作中的作用

`prototype` 属性的核心价值体现在 `new` 调用时。回顾我们在《构造函数与 new》一章中分析的四个步骤：

```
执行 new Constructor(...args) 时：

  步骤 2（关键！）：
  新对象.[[Prototype]] = Constructor.prototype
                              ↑
                        就是这里！
                        引擎读取了函数的 prototype 属性，
                        把它的值设为新对象的原型
```

也就是说：**`Constructor.prototype` 是 `new` 操作符用来初始化新对象原型的"原材料"。** 它就像一张蓝图——告诉引擎"请按照这张图的结构来设定新对象的家谱关系"。

```javascript
function Animal(species) {
  this.species = species;
}

// 我们在 prototype 上定义方法
// 这些方法会成为所有 Animal 实例共享的能力
Animal.prototype.speak = function () {
  console.log(`${this.species || '某种动物'}发出了声音`);
};

Animal.prototype.isMammal = function () {
  return ['猫', '狗', '鲸鱼', '人类'].includes(this.species);
};

// new 发生时的步骤 2：
// let animal = Object.create(Animal.prototype)
// 等价于：animal.__proto__ = Animal.prototype
// 现在 animal 可以访问 Animal.prototype 上的一切！

let cat = new Animal('猫');
cat.speak();        // "某种动物发出了声音" ← 从原型链获取到的方法
cat.isMammal();     // true ← 同样来自原型
console.log(cat instanceof Animal); // true ← 原型链接正确

let dog = new Animal('狗');
dog.speak();        // "某种动物发出了声音" ← 同一个方法！
console.log(cat.speak === dog.speak); // true ✅ 方法共享
```

### 修改 `prototype` 的影响范围

对 `Function.prototype` 的操作有两种完全不同的模式，理解它们的区别至关重要：

#### 模式 A：修改 `prototype` 内部的属性 → 影响所有实例（包括已创建的和未来创建的）

```javascript
function Counter() { this.count = 0; }
Counter.prototype.increment = function () { this.count++; };
Counter.prototype.reset = function () { this.count = 0; };

let c1 = new Counter();
let c2 = new Counter();

c1.increment();
c1.increment();
console.log(c1.count); // 2

// 现在在原型上新增一个方法 —— 所有已有的和新创建的实例都能立即使用
Counter.prototype.getLog = function () {
  return `[Count=${this.count}]`;
};

console.log(c1.getLog()); // "[Count=2]" —— 已有的 c1 也获得了新方法！✅
console.log(c2.getLog()); // "[Count=0]" —— 同样适用于 c2！✅

let c3 = new Counter();  // 未来创建的新实例自然也有
console.log(c3.getLog()); // "[Count=0]"
```

这是因为**所有实例的 `[[Prototype]]` 都指向同一个原型对象**。修改这个对象的内容（添加/删除/修改属性），所有指向它的实例都能感知到变化——就像公司更新了公共资料室里的《操作手册》，所有持钥匙的员工下次查阅时都会看到最新版本。

#### 模式 B：整体替换 `prototype` → 只影响之后 `new` 创建的新实例，已有实例不受影响

```javascript
function Greeter() {}
Greeter.prototype.hello = function () { return "你好（旧版）"; };

let oldInstance = new Greeter();
console.log(oldInstance.hello()); // "你好（旧版）"

// 整体替换 prototype —— 注意这里是赋值一个新的对象！
Greeter.prototype = {
  hello: function () { return "Hello! （新版）"; },
  bye: function () { return "再见！" }
};

let newInstance = new Greeter();
console.log(newInstance.hello()); // "Hello! （新版）" ✅ 新实例使用新原型
console.log(newInstance.bye());   // "再见！"

// 关键：已有实例仍然持有对旧原型的引用！
console.log(oldInstance.hello()); // "你好（旧版）" ✅ 不受影响！
console.log(oldInstance.bye);      // TypeError! 旧原型上没有 bye 方法
```

为什么会这样？因为 `new` 操作发生在**调用那一刻**——执行 `new Greeter()` 时，引擎读取了当时的 `Greeter.prototype` 的值，并将其设为了新对象的 `[[Prototype]]`。之后即使你把 `Greeter.prototype` 变量指向了另一个对象，已经创建的对象的 `[[Prototype]]` 仍然指着旧的对象。

**通俗类比**：这就好比一家公司更换了新的《员工手册》（替换 `prototype`），但老员工的工位上还放着旧版的副本（已有实例的 `[[Prototype]]` 没变）。只有新入职的员工才会拿到新版手册（新实例使用新 `prototype`）。如果公司在旧版手册上贴了一份通知说"明天放假"（修改原型内部的属性），那所有持有旧版手册的老员工都能看到这个通知。

## `constructor` 属性 —— "出生证明上的印章"

### 什么是 `constructor`？

**定义**：`constructor` 是原型对象上的一个属性，默认情况下它指向创建该原型对象的构造函数。由于原型继承机制，通过该原型对象创建的所有实例都可以访问到这个属性。

```javascript
function Person(name) {
  this.name = name;
}

// Person.prototype 默认就有 constructor 属性
console.log(Person.prototype.constructor === Person); // true ✅

// 通过 new 创建的实例可以沿原型链访问到 constructor
let alice = new Person("爱丽丝");
console.log(alice.constructor === Person);  // true ✅（继承自原型链）
console.log(alice.constructor.name);        // "Person"
```

### `constructor` 的默认创建过程

当我们声明一个函数 `F` 时，引擎自动执行的完整过程如下（ECMAScript 规范层面）：

```
1. 创建函数对象 F
2. 创建一个普通对象 P
3. 给 P 添加属性 constructor，值为 F
4. 将 P 设为不可枚举（enumerable: false）、可写（writable: true）、可配置（configurable: true）
5. 将 F.prototype 设为 P
6. 返回 F
```

用代码模拟这个过程：

```javascript
function simulateFunctionCreation(F) {
  // 步骤 2-3：创建默认原型对象
  let P = {};

  // 步骤 4：添加 constructor 属性
  Object.defineProperty(P, 'constructor', {
    value: F,
    enumerable: false,    // 不会被 for...in 遍历到
    writable: true,       // 允许修改
    configurable: true    // 允许删除或重新定义
  });

  // 步骤 5：绑定到函数
  F.prototype = P;

  return F;
}
```

### `constructor` 的实际用途

`constructor` 最常见的用途有三个：

#### 用途 1：类型判断与实例重建

```javascript
function Widget(id, config) {
  this.id = id;
  this.config = config || {};
}

let w1 = new Widget("widget-1", { theme: "dark" });

// 用途 1a：类型检查
if (w1.constructor === Widget) {
  console.log("w1 是 Widget 的实例"); // ✅
}

// 用途 1b：利用 constructor 创建同类型的新实例
function clone(instance) {
  // 不需要硬编码构造函数名
  // 通过 instance.constructor 就能找到正确的构造函数
  return new instance.constructor();
}

let w2 = clone(w1);
console.log(w2 instanceof Widget); // true ✅
console.log(w2.constructor === Widget); // true
```

这种方式在某些泛型工具库中很有价值——比如一个通用的深拷贝函数可以根据 `constructor` 信息来正确恢复对象的类型。

#### 用途 2：获取构造函数名称用于调试日志

```javascript
function logCreation(instance) {
  const typeName = instance.constructor?.name ?? 'Unknown';
  console.log(`[${typeName}] 实例已被创建`);
  console.log(`  构造函数: ${instance.constructor.toString().slice(0, 50)}...`);
}

class UserService {}
class DatabaseService {}

logCreation(new UserService());
// [UserService] 实例已被创建
//   构造函数: class UserService { ... }

logCreation(new DatabaseService());
// [DatabaseService] 实例已被创建
//   构造函数: class DatabaseService { ... }
```

#### 用途 3：在类继承体系中追踪层级关系

```javascript
class Animal {
  constructor(name) {
    this.name = name;
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name);
    this.breed = breed;
  }
}

class ShibaInu extends Dog {
  constructor(name, age) {
    super(name, "柴犬");
    this.age = age;
  }
}

let dog = new ShibaInu("小柴", 3);

// constructor 反映的是"直接构造者"，不是最顶层的父类
console.log(dog.constructor === ShibaInu);  // true
console.log(dog.constructor === Dog);       // false
console.log(dog.constructor === Animal);    // false
console.log(dog.constructor.name);          // "ShibaInu"

// 如果想查看完整的继承链，需要结合 getPrototypeOf
let currentProto = Object.getPrototypeOf(dog);
while (currentProto && currentProto !== Object.prototype) {
  console.log(`↑ ${currentProto.constructor.name}`);
  currentProto = Object.getPrototypeOf(currentProto);
}
// 输出: ↑ ShibaInu → ↑ Dog → ↑ Animal
```

## `constructor` 丢失问题与修复方案

### 问题场景：覆盖 `prototype` 导致 `constructor` 丢失

这是 `constructor` 相关的最常见也是最危险的问题。当开发者选择用一个全新的对象来**整体替换**函数的 `prototype` 时，新对象上不会自动带有 `constructor` 属性：

```javascript
// ❌ 危险做法：整体覆盖 prototype
function Rabbit() {}

Rabbit.prototype = {
  jumps: true,        // 添加自定义属性
  runs: true
  // ⚠️ 注意：没有 constructor 属性！
};

let rabbit = new Rabbit();

console.log(rabbit.jumps);              // true ✅（正常）
console.log(rabbit.constructor === Rabbit); // false ❌！！
// constructor 去哪儿了？
```

`rabbit.constructor` 为什么不等于 `Rabbit` 了？

因为 `Rabbit.prototype` 现在是一个全新的 `{ jumps: true, runs: true }` 对象——这个对象是我们手动创建的字面量，引擎并没有在上面自动添加 `constructor` 属性。所以当访问 `rabbit.constructor` 时：

1. rabbit 自身没有 `constructor`
2. 沿 `[[Prototype]]` 找到 `Rabbit.prototype`（那个 `{ jumps, runs }` 对象）
3. 这个对象上也没有 `constructor`
4. 继续向上找……最终可能在 `Object.prototype` 上找到了 `constructor`（它指向 `Object`）
5. 所以 `rabbit.constructor === Object` 为 `true`！

```javascript
console.log(rabbit.constructor === Object); // true ← 错误地指向了 Object！
console.log(rabbit.constructor.name);        // "Object" 而不是 "Rabbit"！
```

**后果是什么？**

```javascript
// 后果 1：类型判断出错
if (rabbit.constructor === Rabbit) {
  console.log("这是一只兔子");
} else {
  console.log("这不是一只兔子？!");  // 进入了错误的分支 💥
}

// 后果 2：基于 constructor 的克隆功能失效
function badClone(obj) {
  return new obj.constructor();  // 期望创建同类型的实例
}

let clonedRabbit = badClone(rabbit);
// clonedRabbit 实际上是 new Object() 的结果
// 没有 jumps 属性、没有 runs 方法、没有任何 Rabbit 的特征
console.log(clonedRabbit.jumps); // undefined 💥

// 后果 3：调试信息误导
console.log(`创建了 ${rabbit.constructor.name} 的实例`);
// 输出："创建了 Object 的实例" 而不是 "Rabbit 的实例" 😱
```

### 修复方案

有两种方式可以避免或修复这个问题：

#### 方案一（推荐）：不覆盖 `prototype`，只在原有对象上添加属性

```javascript
// ✅ 安全做法：保持原始 prototype 对象不变，只在其上添加属性
function GoodRabbit() {}

GoodRabbit.prototype.jumps = true;
GoodRabbit.prototype.runs = true;
// 没有替换 prototype 对象，原始的 constructor 保留完好！

let goodRabbit = new GoodRabbit();

console.log(goodRabbit.jumps);                // true ✅
console.log(goodRabbit.constructor === GoodRabbit); // true ✅ constructor 正确！
console.log(goodRabbit.constructor.name);         // "GoodRabbit" ✅
```

这是最推荐的做法——因为它最简单、最不容易出错，而且保留了引擎自动管理的所有默认设置。

#### 方案二（备选）：如果必须覆盖，手动补回 `constructor`

某些情况下你可能确实需要整体替换 `prototype`（比如你想一次性定义大量方法和属性，或者使用 `Object.create` 来实现继承）。这时务必手动补回 `constructor`：

```javascript
// ✅ 可接受做法：覆盖 + 手动补回 constructor
function BetterRabbit() {}

BetterRabbit.prototype = {
  // 先写自定义属性
  jumps: true,
  runs: true,
  earLength: "long",

  // 然后显式补回 constructor
  constructor: BetterRabbit  // ← 手动修正！
};

let betterRabbit = new BetterRabbit();

console.log(betterRabbit.jumps);                  // true ✅
console.log(betterRabbit.constructor === BetterRabbit); // true ✅
console.log(betterRabbit.constructor.name);          // "BetterRabbit" ✅

// 克隆功能也能正常工作
let cloned = new betterRabbit.constructor();
console.log(cloned.jumps); // true
console.log(cloned instanceof BetterRabbit); // true
```

### 还有一种隐蔽的丢失情况：`Object.create()` 继承

使用 `Object.create()` 来模拟继承时，如果不注意也会丢失 `constructor`：

```javascript
function Parent() {}
Parent.prototype.parentMethod = function () { return "来自 Parent"; };

function Child() {}
// 使用 Object.create 实现 Child 继承 Parent
Child.prototype = Object.create(Parent.prototype);

// 添加子类自己的方法
Child.prototype.childMethod = function () { return "来自 Child"; };

let child = new Child();
child.childMethod();  // "来自 Child" ✅
child.parentMethod();  // "来自 Parent" ✅（继承了）

// 但是！
console.log(child.constructor === Child);  // false ❌
console.log(child.constructor === Parent); // true ← 指向了 Parent！
```

原因：`Object.create(Parent.prototype)` 创建的新对象的 `constructor` 来自 `Parent.prototype`，指向的是 `Parent` 而非 `Child`。

**修复**：

```javascript
Child.prototype = Object.create(Parent.prototype, {
  constructor: {
    value: Child,
    enumerable: false,   // 保持与原生一致（不可枚举）
    writable: true,
    configurable: true
  }
});

// 或者更简洁地在后面单独赋值：
// Child.prototype.constructor = Child;
```

## `prototype` 与 `constructor` 的循环引用

### 双向关系的图解

当一切正常时，`prototype` 和 `constructor` 形成一个完美的**双向引用环**：

```
函数 (Function)
│
├── prototype ──────────────────────┐
│   (原型对象 / Prototype Object)   │
│   {                               │
│     constructor: Function ◄───┘   │
│     (其他自定义方法...)             │
│   }                                │
│                                    │
│  new 时，实例的 [[Prototype]] ──────┘
│
实例 (Instance)
│
├── name: "xxx" (自有属性)
│
├── [[Prototype]] ────────────────→ 指向上面的原型对象
│                                    │
│  通过原型链继承到的:                │
├── constructor ───────────────────→ Function（从原型上继承来的）
```

用代码验证这个环：

```javascript
function Circle(radius) {
  this.radius = radius;
}

Circle.prototype.area = function () {
  return Math.PI * this.radius * this.radius;
};

Circle.prototype.circumference = function () {
  return 2 * Math.PI * this.radius;
};

let circle = new Circle(5);

// 验证环的三个环节
console.log(Circle.prototype.constructor === Circle);     // 环节 1: 原型的 constructor 指回函数 ✅
console.log(Object.getPrototypeOf(circle) === Circle.prototype); // 环节 2: 实例的原型指向函数的 prototype ✅
console.log(circle.constructor === Circle);               // 环节 3: 实例的 constructor（从原型继承）指向函数 ✅

// 更直观的验证：
console.log(circle.constructor.prototype === Circle.prototype); // true —— 彻底闭环！
console.log(circle.constructor.prototype.constructor === Circle); // true —— 继续闭环...
```

### 循环引用的意义

这个双向引用环的设计是有意义的：

1. **从函数出发** → 通过 `F.prototype` 找到原型对象 → 可以在上面定义所有实例共享的方法和数据
2. **从实例出发** → 通过 `instance.constructor` 找回创建它的函数 → 可以进行类型判断、克隆、或者了解对象的"出身"

两者互为补充，共同构成了 JavaScript 对象系统中"创造者"与"被创造者"之间的完整联系。

### 特殊情况：内置对象的 `constructor` 有时不太可靠

需要注意的是，对于某些内置对象（特别是跨上下文环境创建的对象），`constructor` 可能不如预期那样工作：

```javascript
let arr = [];
console.log(arr.constructor === Array); // true ✅ 正常

let str = "hello";
console.log(str.constructor === String); // true ✅ 正常

// 但在 iframe 场景中可能失效：
// let iframeArr = iframe.contentWindow.Array(1,2,3);
// iframeArr.constructor === Array; // 可能是 false！
// 因为 iframe 有自己的 Array 构造函数

// 解决方案：
console.log(arr instanceof Array);           // 推荐：更可靠的类型检测
console.log(Array.isArray(arr));             // 最佳：专门针对数组的 API
console.log(Object.prototype.toString.call(arr)); // "[object Array]" — 万能兜底
```

## 高级话题：动态 `constructor` 与设计模式

### 利用 `constructor` 实现多态克隆

`constructor` 属性可以被用来实现一种优雅的多态克隆模式——不需要知道具体类型就能创建同类对象：

```javascript
/**
 * 多态克隆工厂 —— 利用 constructor 实现类型无关的对象复制
 */
function polymorphicClone(instance, overrides = {}) {
  // 通过 constructor 获取构造函数
  const Constructor = instance.constructor;

  // 收集实例自身的可枚举属性
  const ownDescriptorMap = {};
  for (let key of Reflect.ownKeys(instance)) {
    ownDescriptorMap[key] = Object.getOwnPropertyDescriptor(instance, key);
  }

  // 创建新实例（利用 constructor！）
  const clone = new Constructor();

  // 复制自身属性到新实例
  Object.defineProperties(clone, ownDescriptorMap);

  // 应用覆盖属性
  Object.assign(clone, overrides);

  return clone;
}

// ====== 测试 ======
class Point {
  constructor(x, y) {
    this.x = x;
    this.y = y;
  }
  distance() {
    return Math.sqrt(this.x ** 2 + this.y ** 2);
  }
  toString() {
    return `(${this.x}, ${this.y})`;
  }
}

let p1 = new Point(3, 4);
let p2 = polymorphicClone(p1, { x: 10 });  // 覆盖 x 坐标

console.log(p2.toString());   // "(10, 4)" —— y 从 p1 复制过来，x 被覆盖
console.log(p2.distance());   // √116 ≈ 10.77 —— 原型方法正常工作
console.log(p2.constructor === Point); // true ✅ 类型正确
console.log(p2 instanceof Point);      // true ✅
```

### `constructor` 在序列化/反序列化中的应用

```javascript
/**
 * 带类型信息的 JSON 序列化器
 * 将 constructor 名称存入元数据，反序列化时可据此还原类型
 */
class TypedJSON {
  static stringify(obj) {
    const meta = {
      __type__: obj.constructor.name,
      data: obj
    };
    return JSON.stringify(meta);
  }

  static parse(str, typeRegistry = {}) {
    const meta = JSON.parse(str);
    const TypeName = meta.__type__;
    const data = meta.data;

    if (!TypeName) return data; // 无类型信息，返回纯数据

    // 根据类型名查找构造函数
    const Constructor = typeRegistry[TypeName];
    if (!Constructor) {
      throw new Error(`未知的类型: ${TypeName}`);
    }

    // 利用 constructor 重建实例
    const instance = Object.create(Constructor.prototype);
    Object.assign(instance, data);
    return instance;
  }
}

// ====== 测试 ======
class Vector2D {
  constructor(x, y) {
    this.x = x;
    this.y = y;
  }
  magnitude() {
    return Math.sqrt(this.x ** 2 + this.y ** 2);
  }
}

// 注册类型
const registry = { Vector2D };

let v1 = new Vector2D(3, 4);
let serialized = TypedJSON.stringify(v1);
// '{"__type__":"Vector2D","data":{"x":3,"y":4}}'

let v2 = TypedJSON.parse(serialized, registry);
console.log(v2.x, v2.y);           // 3 4
console.log(v2.magnitude());         // 5 —— 原型方法可用！
console.log(v2 instanceof Vector2D); // true
```

## 总结

### 核心知识点速查表

| 概念 | 所属位置 | 类型 | 默认值 | 主要用途 |
|------|---------|------|--------|---------|
| **`F.prototype`** | 函数 `F` 身上 | 对象（可写） | `{ constructor: F }` | 作为 `new F()` 时新对象的 `[[Prototype]]` |
| **`constructor`** | `F.prototype` 对象上 | 数据属性（指向函数） | `F`（指回函数自身） | 让实例能追溯其构造函数；类型判断；克隆 |

### 关键规则速查

| 操作 | 影响 | 注意事项 |
|------|------|---------|
| 读取 `F.prototype` | 无副作用 | 只是获取当前值 |
| 修改 `F.prototype.xxx = value` | **影响所有实例**（含已创建的） | 因为修改了原型对象本身的内容 |
| 替换 `F.prototype = newObj` | **只影响之后 new 的实例** | 已有实例保持旧原型引用；`constructor` 会丢失！ |
| 删除 `delete F.prototype.xxx` | **影响所有实例** | 该属性从原型上移除，所有实例都无法再访问 |
| 读取 `instance.constructor` | 无副作用 | 沿原型链查找；如果 prototype 被覆盖且未补 constructor，结果可能错误 |

### 最佳实践清单

| 建议 | 说明 |
|------|------|
| **优先追加而非覆盖** | 用 `F.prototype.method = ...` 而非 `F.prototype = {...}` |
| **若必须覆盖，补回 constructor** | `F.prototype = { ..., constructor: F }` |
| **Object.create 继承时也要处理** | `Object.create(Parent.prototype, { constructor: { value: Child } })` |
| **不要过度依赖 constructor 做类型检查** | `instanceof` 和 `Array.isArray()` 更可靠 |
| **理解引用 vs 赋值的区别** | 修改原型对象内容 ≠ 替换原型对象引用 |

> **一句话总结**：`prototype` 是函数身上的"蓝图仓库"，规定了由此函数创建的所有对象将共享什么能力和数据；`constructor` 是蓝图仓库门口挂着的"铭牌"，记录着这份蓝图的出品方是谁。两者形成双向引用，共同构成了 JavaScript 原型继承系统的基础架构——维护好这个关系（尤其是不要轻易覆盖 `prototype`），你的代码就会更加健壮、更加可预测。
