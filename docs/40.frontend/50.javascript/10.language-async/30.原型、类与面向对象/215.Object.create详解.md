# `Object.create` 详解与 `Object.create(null)` 的用途

## 对象创建的"瑞士军刀"——比 `new` 更灵活、比字面量更精确

在 JavaScript 提供的所有对象创建方式中，`Object.create()` 是一个独特而强大的存在。它不像 `new` 操作符那样需要预先定义构造函数（"先建工厂再生产产品"），也不像对象字面量 `{}` 那样只能得到一个固定原型为 `Object.prototype` 的普通对象。`Object.create()` 给了你一种**"直接指定出身"**的能力——你可以精确地告诉引擎："请给我创建一个新对象，它的父亲是某某某。"

这种能力看似简单，但它解锁了许多传统方式难以优雅实现的模式：纯净字典对象、精确克隆（含不可枚举属性）、灵活的继承组合、以及无污染的键值存储。本章将对 `Object.create()` 的每一个细节进行彻底剖析。

### 为什么需要 `Object.create`？

在 ES5（2009年）引入 `Object.create()` 之前，JavaScript 开发者只有以下几种方式来创建对象并控制其原型：

| 创建方式 | 原型控制能力 | 局限性 |
|---------|------------|--------|
| `let obj = {}` | 固定为 `Object.prototype` | 无法指定其他原型 |
| `new Constructor()` | 自动设为 `Constructor.prototype` | 必须先有构造函数；会执行构造函数体（可能有副作用） |
| `{ __proto__: someObj }` | 可指定任意原型 | 语法非标准（ES6 才纳入 Annex B） |

**`Object.create()` 的出现填补了这些空白**——它可以：
- **不执行任何函数体**就创建具有指定原型的对象（纯数据对象）
- **精确到属性描述符级别**地定义初始属性
- **创建完全没有原型的对象**（`null` 作为第一个参数）
- **作为实现继承的核心工具**（在 `class` 语法出现之前）

### 通俗类比：定制化"出生证明"

想象每当你需要一个新对象时，就像在办理一份出生证明。不同的创建方式对应不同的办理流程：

- **`{}` 字面量**就像去**默认窗口**办理——工作人员看都不看你一眼，直接在"父亲/母亲"栏填上 `Object.prototype`（系统默认值）。你无法选择。
- **`new Foo()`**就像去**指定工厂的窗口**办理——你必须先提供工厂名称（构造函数），工厂会运行它的生产线（执行构造函数体），然后产品带着 `Foo.prototype` 的血缘证明出厂。流程繁琐但标准化程度高。
- **`Object.create(proto)` 就像是走**VIP 定制通道**——你直接把想要的"血缘关系文件"递给工作人员，说："我要这个对象做我孩子的父亲。" 工作人员立刻为你办好一份精准定制的出生证明——不经过任何生产线，没有任何额外流程，孩子一出生就拥有你指定的家族背景。

而且 VIP 通道还有一个特殊选项：如果你递交的是一张空白纸（`null`），那就意味着这个孩子**没有父母**——一个真正意义上的"独立个体"，不隶属于任何家族体系。

## 一、API 签名与参数详解

### 完整语法

```javascript
// 标准签名:
let newObj = Object.create(proto [, propertiesObject]);

// 参数:
//   proto             - 必须。新对象的 [[Prototype]]（可以是对象或 null）
//   propertiesObject  - 可选。要添加到新对象上的可枚举属性描述符对象
//
// 返回值:
//   一个新创建的对象，其 [[Prototype]] 为指定的 proto，
//   并包含（如果提供了第二个参数）指定的自身属性
```

### 参数 1：`proto` —— 新对象的"生父"

这是 `Object.create()` 最核心、最重要的参数。它决定了新对象的**整个原型链起点**。

```javascript
// ====== 场景 A：proto 为普通对象 ======
let animal = {
  type: "动物",
  speak() { console.log(`${this.name || '某种'}${this.type || ''}发出了声音`); }
};

let cat = Object.create(animal);
cat.name = "咪咪";

console.log(Object.getPrototypeOf(cat) === animal); // true ✅
cat.speak();  // "咪咪动物发出了声音" ← 从 animal 原型上继承的方法
console.log(cat.type);  // "动物" ← 从 animal 原型上继承的属性

// ====== 场景 B：proto 为 null（无原型对象）=====
let pure = Object.create(null);

console.log(Object.getPrototypeOf(pure)); // null ✅ 彻底无原型
console.log(pure.toString);               // undefined ❌ 连 toString 都没有！
console.log(pure.hasOwnProperty);         // undefined ❌ 也没有 hasOwnProperty！

// 这是一个真正的"白板对象"

// ====== 场景 C：proto 为某个类的 prototype（模拟 new）=====
class User {
  constructor(name) { this.name = name; }
  greet() { return `你好，我是 ${this.name}`; }
}

// 不用 new，用 Object.create 手动创建 User 的实例
let user = Object.create(User.prototype);
user.name = "张三";  // 手动初始化（因为没有执行 constructor）

console.log(user instanceof User);  // true ✅
console.log(user.greet());          // "你好，我是 张三" ✅ 原型方法可用
```

### 参数 2：`propertiesObject` —— 精细化的属性描述符

第二个参数允许你在创建对象的**同时**定义其自有属性，并且可以精确控制每个属性的**描述符标志（flags）**。

**关键注意**：这里的属性描述符默认值与普通的属性赋值完全不同！

```javascript
// 普通赋值的默认行为：
let normalObj = { x: 1, y: 2 };
// 等价于：
// x: { value: 1, writable: true, enumerable: true, configurable: true }
// y: { value: 2, writable: true, enumerable: true, configurable: true }

// Object.create 第二个参数的默认行为（⚠️ 不同！）：
let createObj = Object.create(Object.prototype, {
  x: { value: 1 },  // 只写了 value
  y: { value: 2 }   // 只写了 value
});
// 等价于：
// x: { value: 1, writable: false, enumerable: false, configurable: false } ⚠️
// y: { value: 2, writable: false, enumerable: false, configurable: false } ⚠️
```

看到了吗？当使用第二个参数时，**如果不显式声明 `writable`、`enumerable`、`configurable`，它们全部默认为 `false`**。这是一个极其容易踩坑的地方——很多开发者以为 `Object.create(obj, { x: 1 })` 会创建一个可写的、可枚举的 `x` 属性，但实际上它创建的是一个**只读、不可枚举、不可删除**的属性。

```javascript
// 正确做法：显式设置所有需要的标志
let correctObj = Object.create(Object.prototype, {
  id: {
    value: "obj-001",
    writable: false,      // ID 不可修改
    enumerable: true,     // 但可以被遍历到
    configurable: false   // 不可删除或重新配置
  },
  name: {
    value: "测试对象",
    writable: true,       // 名字可以改
    enumerable: true,
    configurable: true    // 可以删除
  },
  _internalCounter: {
    value: 0,
    writable: true,
    enumerable: false,   // 内部计数器不应该被遍历到
    configurable: false
  },
  // 还支持 getter/setter 访问器！
  displayName: {
    get() {
      return `[${this.name} (#${this.id})]`;
    },
    enumerable: true,
    configurable: true
  }
});

console.log(correctObj.id);            // "obj-001"
console.log(correctObj.displayName);  // "[测试对象 (#obj-001)]"
correctObj.id = "hacked";              // 静默失败！（writable: false）
console.log(correctObj.id);            // 仍然是 "obj-001" ✅

for (let key in correctObj) {
  console.log(key);
  // 输出: id, name, displayName
  // 注意：_internalCounter 没有出现（enumerable: false）
}
```

## 二、`Object.create(null)` —— 纯净字典对象（Pure Dictionary）

### 什么是纯净字典对象？

`Object.create(null)` 是 JavaScript 中创建**完全没有原型（`[[Prototype]] === null`）的对象的唯一标准方式**。这样的对象被称为**"纯净字典对象"（Very Plain Dictionary / Pure Hash Map）**。

为什么叫"字典"？因为它就像一本空白的笔记本——上面没有任何预印的内容（没有继承自 `Object.prototype` 的任何方法或属性）。你可以随意在上面写任何东西（作为键值对存储），不用担心与已有的内容冲突。

### 为什么需要纯净字典？

让我们通过一个经典问题来理解其必要性：

#### 问题场景：键名冲突导致的意外行为

```javascript
// 使用普通对象作为字典/哈希表存储用户输入
let lookupTable = {};

// 存储一些正常数据
lookupTable["apple"]  = "苹果";
lookupTable["banana"] = "香蕉";
lookupTable["cherry"] = "樱桃";

// 用户输入了一些特殊的键名（可能来自 URL 参数、JSON 数据库等）
lookupTable["toString"]  = "用户输入的 toString";
lookupTable["__proto__"] = { hacked: true };
lookupTable["constructor"] = "危险输入";

console.log(lookupTable["apple"]);     // "苹果" ✅ 正常
console.log(lookupTable["toString"]);  // ??? 可能不是 "用户输入的 toString"！
// 问题出在哪里？
```

问题在于：普通对象 `{}` 继承了 `Object.prototype`，所以它身上已经自带了 `toString`、`constructor`、`hasOwnProperty`、`valueOf` 等内置属性和方法。当用户输入恰好使用了这些名字时，会产生以下隐患：

**隐患 1：`toString` 被覆盖后影响字符串转换**

```javascript
let dict = {};
dict["toString"] = "恶意覆盖";

// 当某些内部机制调用 toString 时...
console.log("" + dict);        // "[object Object]" —— 还是正常的？
// 但如果覆盖的是一个函数：
dict["toString"] = () => "被劫持了!!!";
console.log(dict.toString()); // "被劫持了!!!" 💥
console.log("Value: " + dict);  // "Value: 被劫持了!!!" 💥
```

**隐患 2：`__proto__` 导致的原型污染攻击**

这是最严重的安全问题之一：

```javascript
let userData = {};

// 攻击者精心构造的数据
let maliciousInput = JSON.parse('{ "__proto__": { "isAdmin": true } }');

// 开发者天真地把用户数据复制到对象上
Object.assign(userData, maliciousInput);

// 看起来没什么问题？但...
let emptyObj = {};
console.log(emptyObj.isAdmin); // true 😱！！！
// 空对象突然有了 isAdmin 属性？！
// 因为 __proto__ 被当作原型设置操作而非普通属性！
// 这就是著名的"原型污染漏洞"（Prototype Pollution）
```

#### 解决方案：`Object.create(null)`

```javascript
// ✅ 安全方案：使用无原型对象
let safeDict = Object.create(null);

safeDict["apple"]      = "苹果";
safeDict["banana"]     = "香蕉";
safeDict["toString"]   = "用户的 toString";  // 只是普通字符串键
safeDict["__proto__"]  = "用户的 __proto__";  // 也只是普通字符串键
safeDict["constructor"] = "用户的 constructor";

// 所有键都安全地作为普通属性存储
console.log(safeDict["apple"]);      // "苹果" ✅
console.log(safeDict["toString"]);   // "用户的 toString" ✅（不会被误认为方法）
console.log(safeDict["__proto__"]);   // "用户的 __proto__" ✅（不会触发原型设置）

// 验证：确实没有任何内置方法
console.log(safeDict.toString);       // undefined ✅（连 toString 都没有）
console.log(safeDict.hasOwnProperty); // undefined ✅
console.log(safeDict.constructor);     // undefined ✅
console.log(Object.keys(safeDict));
// ["apple", "banana", "toString", "__proto__", "constructor"]
// 所有键都被正确列出
```

### 纯净字典的操作限制与替代方案

既然 `Object.create(null)` 创建的对象没有继承任何方法，那我们该如何操作它呢？答案是：**使用 `Object` 上的静态方法**（这些方法不需要对象自身拥有任何方法）：

```javascript
let dict = Object.create(null);
dict["name"] = "Alice";
dict["age"] = 30;
dict["city"] = "北京";

// ====== 不能用的（因为对象自身没有这些方法）======
// dict.toString()           → TypeError!
// dict.hasOwnProperty("name") → TypeError!
// dict.valueOf()             → TypeError!

// ====== 可以用的替代方案 ======

// 1. 检查属性是否存在 → Object.hasOwn() 或 in 操作符
console.log(Object.hasOwn(dict, "name"));  // true（推荐，ES2022+）
console.log("name" in dict);                // true（in 操作符不需要对象自身有方法）

// 旧环境兼容写法：
console.log(Object.prototype.hasOwnProperty.call(dict, "name")); // true

// 2. 获取所有键 → Object.keys()
console.log(Object.keys(dict));
// ["name", "age", "city"]

// 3. 获取所有值 → Object.values()
console.log(Object.values(dict));
// ["Alice", 30, "北京"]

// 4. 获取键值对 → Object.entries()
for (let [key, value] of Object.entries(dict)) {
  console.log(`  ${key}: ${value}`);
}
//   name: Alice
//   age: 30
//   city: 北京

// 5. 字符串转换 → 手动构建或使用 JSON
console.log(JSON.stringify(dict));
// {"name":"Alice","age":30,"city":"北京"} ✅
```

### 何时使用纯净字典？——决策指南

| 场景 | 推荐使用 | 说明 |
|------|---------|------|
| **存储不可信的用户输入** | ✅ **强烈推荐** | 防止 `__proto__`/`constructor` 键名导致原型污染 |
| **作为配置映射表/查找表** | ✅ 推荐 | 键名不受限制，不会与内置属性冲突 |
| **解析来自外部的 JSON 数据** | ✅ 推荐 | 数据源不可控时最安全的选择 |
| **缓存/记忆化容器** | ✅ 可用 | 性能好且无额外属性干扰迭代 |
| **需要调用 toString/valueOf 的对象** | ❌ 不适合 | 无原型对象没有这些方法 |
| **需要 instanceof 类型检查的对象** | ❌ 不适合 | 无原型对象不属于任何类型 |
| **需要参与常规 OOP 继承体系的对象** | ❌ 不适合 | 它们无法访问任何原型方法 |

## 三、用 `Object.create` 实现继承

在 ES6 `class` 语法出现之前，`Object.create()` 是实现原型继承的**核心工具**。即使今天，在某些高级场景下它仍然是不可或缺的。

### 基础继承模式

```javascript
// ====== 父类原型 ======
function Animal(name) {
  this.name = name;
}
Animal.prototype.eat = function (food) {
  return `${this.name || '某种生物'} 吃了 ${food}`;
};
Animal.prototype.sleep = function () {
  return `${this.name || '某种生物'} 正在睡觉...`;
};

// ====== 子类：使用 Object.create 设置原型链 ======
function Rabbit(name, breed) {
  Animal.call(this, name);  // 调用父类构造函数，初始化继承来的属性
  this.breed = breed;
}

// 核心：让 Rabbit.prototype 的原型指向 Animal.prototype
Rabbit.prototype = Object.create(Animal.prototype);
// 现在 new Rabbit() 创建的对象将能沿原型链找到 Animal.prototype 上的方法

// 重要：修正 constructor（因为上面的替换操作丢失了它！）
Rabbit.prototype.constructor = Rabbit;

// 添加子类特有的方法
Rabbit.prototype.jump = function () {
  return `${this.name}（${this.breed}）跳了一下!`;
};
Rabbit.prototype.burrow = function () {
  return `${this.name} 挖了一个洞`;
};

// ====== 测试 ======
let rabbit = new Rabbit("小兔", "荷兰垂耳兔");

// 自身属性
console.log(rabbit.name);   // "小兔"
console.log(rabbit.breed);  // "荷兰垂耳兔"

// 继承自 Animal 的方法
console.log(rabbit.eat("胡萝卜"));  // "小兔 吃了 胡萝卜" ✅
console.log(rabbit.sleep());         // "小兔 正在睡觉..." ✅

// Rabbit 特有的方法
console.log(rabbit.jump());  // "小兔（荷兰垂耳兔）跳了一下!" ✅
console.log(rabbit.burrow()); // "小兔 挖了一个洞" ✅

// instanceof 检查
console.log(rabbit instanceof Rabbit);  // true ✅
console.log(rabbit instanceof Animal);  // true ✅（继承了！）

// 原型链验证
console.log(Object.getPrototypeOf(Rabbit.prototype) === Animal.prototype); // true ✅
```

### 这段代码做了什么？——逐步拆解

让我们聚焦最关键的那行代码：`Rabbit.prototype = Object.create(Animal.prototype)`

**这行代码之前的状态：**
```
Rabbit 函数
│
└── Rabbit.prototype ──→ { constructor: Rabbit }
                        （引擎自动生成的默认原型对象）
                        │
                        └── [[Prototype]] → Object.prototype
                            （默认继承自根对象）
```

**这行代码之后的状态：**
```
Rabbit 函数
│
└── Rabbit.prototype ──→ { constructor: Rabbit }  ← 全新的对象！
                        （由 Object.create 创建的）
                        │
                        └── [[Prototype]] → Animal.prototype  ← 指向父类原型！
                            │
                            ├── eat(): function
                            ├── sleep(): function
                            │
                            └── [[Prototype]] → Object.prototype
```

**变化的关键点：**
1. `Rabbit.prototype` 不再是一个默认的新对象，而是一个以 `Animal.prototype` 为原型的新对象
2. 因此，从 `Rabbit` 实例出发沿着原型链往上找，最终能找到 `Animal.prototype` 上的 `eat()` 和 `sleep()` 方法
3. 这就是 JavaScript 原型继承的本质——**通过原型链接来实现方法和属性的共享与复用**

**通俗类比**：这就像是给 `Rabbit` 办理了一份新的家谱——不再让它直接认 `Object.prototype` 做"爷爷"，而是中间插入了一位"父亲" `Animal.prototype`。这样 `Rabbit` 家族的人不仅能继承 `Object.prototype` 的遗产（如 `toString`），还能额外继承 `Animal.prototype` 的遗产（如 `eat`、`sleep`）。

### 与 `class extends` 的关系

实际上，现代 JavaScript 引擎在处理 `class Rabbit extends Animal` 时，底层做的事情与我们手写的 `Object.create` 继承几乎等价：

```javascript
// class 语法（现代写法）
class Animal {
  constructor(name) { this.name = name; }
  eat(food) { return `${this.name} 吃了 ${food}`; }
  sleep() { return `${this.name} 正在睡觉...`; }
}

class Rabbit extends Animal {
  constructor(name, breed) {
    super(name);
    this.breed = breed;
  }
  jump() { return `${this.name} 跳了一下!`; }
}

// 引擎底层大致等价于：
// Rabbit.prototype = Object.create(Animal.prototype, {
//   constructor: { value: Rabbit, writable: true, enumerable: false, configurable: true },
//   jump: { value: function() {...}, writable: true, enumerable: true, configurable: true }
// });
```

了解 `Object.create` 的手动继承模式有助于你理解 `class` 的工作原理，以及在无法使用 `class` 语法的环境下（如某些旧版构建工具或特殊约束条件）实现继承。

## 四、精确克隆（Deep Property Clone）

### 为什么需要精确克隆？

普通的浅拷贝（如展开运算符 `{ ...obj }` 或 `Object.assign({}, obj)`）有以下局限：

1. **丢失原型链**——新对象的 `[[Prototype]]` 变成了 `Object.prototype`
2. **丢失不可枚举属性**——`for...in` 和 `Object.assign` 都跳过不可枚举属性
3. **丢失属性描述符信息**——getter/setter 变成普通数据属性
4. **丢失 Symbol 类型的键**——展开运算符和 `Object.assign` 忽略 Symbol 键

`Object.create()` 结合 `Object.getOwnPropertyDescriptors()` 可以实现**完美的属性级克隆**：

```javascript
/**
 * 精确克隆对象（保留原型链和所有属性描述符信息）
 * @param {Object} source - 要克隆的源对象
 * @returns {Object} 克隆后的新对象
 */
function preciseClone(source) {
  // 第一步：创建与 source 具有相同原型的新对象
  let clone = Object.create(
    Object.getPrototypeOf(source),                    // 保持原型链不变
    Object.getOwnPropertyDescriptors(source)           // 复制所有自身属性（含描述符）
  );
  
  return clone;
}

// ====== 测试：复杂对象克隆 ======
function Entity(id) {
  this.id = id;
  this.createdAt = Date.now();
}

// 在 prototype 上添加方法
Entity.prototype.getType = function () { return "Entity"; };
Entity.prototype.isValid = function () { return !!this.id; };

// 创建实例并添加各种类型的属性
let original = new Entity("ent-42");

// 普通（可枚举、可写）属性
original.name = "原始实体";
original.version = 1.0;

// 用 defineProperty 添加特殊属性
Object.defineProperty(original, 'internalId', {
  value: "sec-xxx-yyy",
  writable: false,
  enumerable: false,    // 不可枚举！
  configurable: false
});

// getter/setter 访问器属性
Object.defineProperty(original, 'displayName', {
  get() { return `[${this.name}:${this.id}]`; },
  enumerable: true,
  configurable: true
});

// Symbol 类型的键
const SECRET_KEY = Symbol("secretKey");
original[SECRET_KEY] = "机密数据";

// ====== 执行克隆 ======
let cloned = preciseClone(original);

// 验证 1：普通属性
console.log(cloned.name);           // "原始实体" ✅
console.log(cloned.version);        // 1.0 ✅
console.log(cloned.id);            // "ent-42" ✅

// 验证 2：不可枚举属性也被保留了！
console.log(cloned.internalId);     // "sec-xxx-yyy" ✅
console.log(cloned.propertyIsEnumerable('internalId')); // false ✅（描述符也保留了）

// 验证 3：getter/setter 正常工作
console.log(cloned.displayName);    // "[原始实体:ent-42]" ✅（动态计算的！）

// 验证 4：Symbol 键也被保留了！
console.log(cloned[SECRET_KEY]);    // "机密数据" ✅

// 验证 5：原型链完好！
console.log(cloned instanceof Entity);  // true ✅
console.log(cloned.getType());          // "Entity" ✅（原型方法可用）
console.log(cloned.isValid());          // true ✅

// 验证 6：确实是独立的副本
cloned.name = "克隆实体";
console.log(original.name);        // "原始实体" ✅（互不影响）
console.log(cloned.name);          // "克隆实体" ✅
```

这就是 `Object.create` 与 `getOwnPropertyDescriptors` 组合的威力——它能做到**真正的、完整的、无损的属性级别克隆**。

## 五、性能考量

### `Object.create` vs 其他创建方式的性能对比

```javascript
const ITERS = 1000000;

// 测试 A：对象字面量
console.time("object literal");
for (let i = 0; i < ITERS; i++) {
  let obj = { x: i, y: i + 1 };
}
console.timeEnd("object literal");

// 测试 B：Object.create（有原型）
let proto = { method() { return 1; } };
console.time("Object.create with proto");
for (let i = 0; i < ITERS; i++) {
  let obj = Object.create(proto);
  obj.x = i;
}
console.timeEnd("Object.create with proto");

// 测试 C：Object.create(null)（无原型）
console.time("Object.create null");
for (let i = 0; i < ITERS; i++) {
  let obj = Object.create(null);
  obj.x = i;
}
console.timeEnd("Object.create null");

// 测试 D：new 构造函数
function Foo(x) { this.x = x; }
console.time("new constructor");
for (let i = 0; i < ITERS; i++) {
  let obj = new Foo(i);
}
console.timeEnd("new constructor");
```

典型 V8 环境下的结果：

| 创建方式 | 100万次耗时 | 相对速度 |
|---------|-----------|----------|
| 对象字面量 `{}` | ~15~30ms | **1x**（基准，最快） |
| `new Foo()` | ~30~60ms | **~2x** |
| `Object.create(null)` | ~40~80ms | **~2~3x** |
| `Object.create(proto)` | ~60~120ms | **~3~4x** |

**分析**：
- **对象字面量最快**——V8 引擎对其做了极致优化（隐藏类预测、内联缓存等）
- **`new` 操作符次之**——需要执行构造函数体，但有 JIT 内联优化
- **`Object.create(null)` 比 `Object.create(proto)` 快**——因为不需要建立原型链接
- **`Object.create(proto)` 最慢**——需要同时完成对象创建 + 原型链接 + 可能的去优化处理

**但这意味着不应该用 `Object.create` 吗？绝对不是！** 这些差距是在百万次的极端循环中测量的。在实际应用中，单次 `Object.create` 的耗时通常在纳秒到微秒级别，完全可以忽略。更重要的是代码的可读性、安全性和语义正确性。

### `Object.create` vs `setPrototypeOf` 的性能差异

```javascript
// 方式 A：创建时设定原型（推荐 ✅）
function approachA() {
  let base = { sharedMethod() { return 1; } };
  let objs = [];
  for (let i = 0; i < 10000; i++) {
    let obj = Object.create(base);  // 创建时就设定好原型
    obj.value = i;
    objs.push(obj);
  }
  return objs;
}

// 方式 B：先创建后修改原型（不推荐 ❌）
function approachB() {
  let base = { sharedMethod() { return 1; } };
  let objs = [];
  for (let i = 0; i < 10000; i++) {
    let obj = { value: i };       // 先创建
    Object.setPrototypeOf(obj, base); // 再修改原型
    objs.push(obj);
  }
  return objs;
}

console.time("create on init");
approachA();
console.timeEnd("create on init");

console.time("setPrototypeOf after");
approachB();
console.timeEnd("setPrototypeOf after");
```

结果差异可能非常显著（`approachB` 可能比 `approachA` 慢 **5~20 倍甚至更多**）：

| 方式 | 相对耗时 | 原因 |
|------|---------|------|
| `Object.create(proto)` 创建时设定 | **1x**（基准） | 对象还是"新鲜"的，引擎无需去优化 |
| 先 `{}` 再 `setPrototypeOf` | **5~20x** | 触发去优化；IC 缓存失效；Hidden Class 重建 |

**核心原则**：永远优先在对象创建时就设定好原型（`Object.create` 或 `new`），避免事后修改。

## 六、实战应用示例

### 示例 1：安全的查询参数解析器

```javascript
/**
 * 将 URL 查询字符串解析为纯净字典对象
 * 防止键名冲突和安全漏洞
 */
class SafeQueryParser {
  /**
   * 解析查询字符串（如 "?name=alice&age=25&__proto__[isAdmin]=true"）
   * @param {string} queryString - URL 查询字符串
   * @returns {Object|null} 纯净字典对象（无原型）
   */
  static parse(queryString) {
    if (!queryString || typeof queryString !== 'string') {
      return Object.create(null);
    }
    
    // 去掉开头的 ? 或 #
    let str = queryString.replace(/^[?#]/, '');
    if (!str) return Object.create(null);
    
    let result = Object.create(null);  // 纯净字典！
    
    // 分割键值对
    let pairs = str.split('&');
    for (let pair of pairs) {
      let [rawKey, rawValue] = pair.split('=');
      if (rawKey === undefined) continue;
      
      // 解码
      let key = decodeURIComponent(rawKey.trim());
      let value = rawValue !== undefined 
        ? decodeURIComponent(rawValue.trim()) 
        : '';
      
      // 处理重复键（变成数组）
      if (key in result) {
        let existing = result[key];
        result[key] = Array.isArray(existing) 
          ? [...existing, value]
          : [existing, value];
      } else {
        result[key] = value;
      }
    }
    
    return result;
  }
  
  /**
   * 从纯净字典中安全地获取值
   */
  static get(params, key, defaultValue = undefined) {
    return Object.hasOwn(params, key) ? params[key] : defaultValue;
  }
}

// ====== 测试 ======
let query = "?name=张三&age=25&tags=A&tags=B&toString=hacked&__proto__[admin]=true";
let params = SafeQueryParser.parse(query);

console.log(SafeQueryParser.get(params, "name"));    // "张三" ✅
console.log(SafeQueryParser.get(params, "age"));     // "25" ✅
console.log(SafeQueryParser.get(params, "tags"));    // ["A", "B"] ✅（重复键变数组）
console.log(SafeQueryParser.get(params, "toString")); // "hacked" ✅（只是普通字符串）
console.log(SafeQueryParser.get(params, "__proto__")); // undefined（这个键名不在查询中）

// 安全性验证：
let emptyObj = {};
console.log(emptyObj.admin); // undefined ✅ 没有受到原型污染
```

### 示例 2：轻量级事件总线（Event Emitter）

```javascript
/**
 * 轻量级发布-订阅事件总线
 * 使用纯净字典存储事件监听器，防止键名冲突
 */
class EventBus {
  constructor() {
    // 用纯净字典存储事件名→监听器列表的映射
    // 这样事件名可以是任何字符串（包括 "toString", "constructor" 等）
    this._listeners = Object.create(null);
    this._onceListeners = Object.create(null);
    this._maxListeners = 10;
  }
  
  /**
   * 注册事件监听器
   */
  on(event, callback) {
    if (typeof callback !== 'function') {
      throw new TypeError("回调必须是函数");
    }
    
    if (!Object.hasOwn(this._listeners, event)) {
      this._listeners[event] = [];
    }
    
    this._listeners[event].push(callback);
    
    // 防止内存泄漏：监听器数量警告
    if (this._listeners[event].length > this._maxListeners) {
      console.warn(
        `[EventBus] 事件 "${event}" 的监听器数量 (${this._listeners[event].length}) ` +
        `超过上限 (${this._maxListeners})，可能的内存泄漏`
      );
    }
    
    return this; // 支持链式调用
  }
  
  /**
   * 注册一次性监听器（触发一次后自动移除）
   */
  once(event, callback) {
    const wrapper = (...args) => {
      this.off(event, wrapper);
      callback.apply(this, args);
    };
    wrapper._original = callback;  // 保留引用以便移除
    
    if (!Object.hasOwn(this._onceListeners, event)) {
      this._onceListeners[event] = [];
    }
    this._onceListeners[event].push(wrapper);
    
    return this;
  }
  
  /**
   * 移除事件监听器
   */
  off(event, callback) {
    // 从普通监听器中移除
    if (Object.hasOwn(this._listeners, event)) {
      this._listeners[event] = this._listeners[event].filter(
        listener => listener !== callback && listener._original !== callback
      );
    }
    
    // 从一次性监听器中移除
    if (Object.hasOwn(this._onceListeners, event)) {
      this._onceListeners[event] = this._onceListeners[event].filter(
        listener => listener !== callback && listener._original !== callback
      );
    }
    
    return this;
  }
  
  /**
   * 触发事件
   */
  emit(event, ...args) {
    let firedCount = 0;
    
    // 触发普通监听器
    if (Object.hasOwn(this._listeners, event)) {
      // 复制数组以防止在回调中修改原数组的问题
      const listeners = [...this._listeners[event]];
      for (let listener of listeners) {
        listener.apply(this, args);
        firedCount++;
      }
    }
    
    // 触发一次性监听器
    if (Object.hasOwn(this._onceListeners, event)) {
      const onceListeners = [...this._onceListeners[event]];
      delete this._onceListeners[event];  // 清空一次性监听器
      for (let listener of onceListeners) {
        listener.apply(this, args);
        firedCount++;
      }
    }
    
    return firedCount;
  }
  
  /**
   * 获取事件的监听器数量
   */
  listenerCount(event) {
    const regular = Object.hasOwn(this._listeners, event) ? this._listeners[event].length : 0;
    const once = Object.hasOwn(this._onceListeners, event) ? this._onceListeners[event].length : 0;
    return regular + once;
  }
  
  /**
   * 移除事件的所有监听器
   */
  removeAllListeners(event) {
    if (event) {
      delete this._listeners[event];
      delete this._onceListeners[event];
    } else {
      this._listeners = Object.create(null);
      this._onceListeners = Object.create(null);
    }
    return this;
  }
}

// ====== 测试 ======
const bus = new EventBus();

bus.on('user:login', (user) => {
  console.log(`✅ 用户登录: ${user.name}`);
});

bus.on('user:login', (user) => {
  console.log(`📊 登录日志已记录`);
});

bus.once('app:start', () => {
  console.log('🚀 应用首次启动！');
});

bus.emit('app:start');
// 🚀 应用首次启动！

bus.emit('app:start');  // （无输出——once 监听器已被移除）

bus.emit('user:login', { name: '张三' });
// ✅ 用户登录: 张三
// 📊 登录日志已记录

console.log(bus.listenerCount('user:login')); // 2
bus.removeAllListeners('user:login');
console.log(bus.listenerCount('user:login')); // 0
```

## 七、与其他对象创建方式的全面对比

### 创建方式总览

| 特性 | `{}` 字面量 | `new Fn()` | `Object.create(proto)` | `Object.create(null)` |
|------|-----------|----------|---------------------|---------------------|
| **原型** | 固定为 `Object.prototype` | 设为 `Fn.prototype` | 可**自定义**任意对象 | **无原型** (`null`) |
| **执行构造函数** | 否 | **是**（会运行函数体） | 否 | 否 |
| **第二参数** | 不支持 | 不支持 | 支持**属性描述符** | 支持**属性描述符** |
| **适用场景** | 简单数据容器 | OOP 类实例 | 灵活继承/精确克隆 | 安全字典/哈希表 |
| **安全性** | 一般 | 一般 | 一般 | **最高**（防原型污染） |
| **性能** | **最快** | 快 | 较快 | 较快 |

### 选择决策树

```
需要创建一个新对象吗？
│
├─→ 是否需要存储不受控的外部数据（用户输入、API 返回等）？
│   │
│   └─→ 是 → Object.create(null) ✅（纯净字典，最安全）
│
├─→ 是否需要精确控制属性描述符（writable/enumerable/configurable）？
│   │
│   └─→ 是 → Object.create(proto, descriptors) ✅
│
├─→ 是否需要实现继承但不使用 class 语法？
│   │
│   └─→ 是 → Object.create(Parent.prototype) + 手动补 constructor ✅
│
├─→ 是否需要精确克隆对象（保留原型链+描述符）？
│   │
│   └─→ 是 → Object.create(getProto, getOwnDescs) ✅
│
├─→ 是否只是创建一个简单的数据对象？
│   │
│   └─→ 是 → {} 或 { x: 1, y: 2 } ✅（最简洁最快）
│
└─→ 是否需要 OOP 封装（私有字段、方法、继承等）？
    │
    └─→ 是 → class / new Constructor() ✅（现代推荐）
```

## 八、总结

### 核心知识点速查表

| 要点 | 详情 |
|------|------|
| **基本用法** | `Object.create(proto)` —— 创建以 `proto` 为原型的新对象 |
| **纯净字典** | `Object.create(null)` —— 创建无原型对象，最适合存外部数据 |
| **第二参数** | `Object.create(proto, descriptors)` —— 同时定义带描述符的自有属性（默认 flags 全为 false！）|
| **实现继承** | `Child.prototype = Object.create(Parent.prototype)` —— 核心继承模式 |
| **精确克隆** | `Object.create(getProto, getOwnDescs)` —— 保留原型链+描述符的完美拷贝 |
| **vs `new`** | 不执行构造函数体，更轻量；但需要手动初始化属性 |
| **vs `{}`** | 可自定义原型，灵活性更高；但稍慢且语法更冗长 |

### 最佳实践清单

| 建议 | 说明 |
|------|------|
| **存储不可信数据时用 `Object.create(null)`** | 防止 `__proto__` 等键名引发原型污染 |
| **用第二参数时务必显式设置所有 flags** | 否则属性默认为不可写、不可枚举、不可配置 |
| **继承时记得修复 `constructor`** | `Child.prototype = Object.create(Parent.prototype)` 后要补回 `constructor: Child` |
| **优先在创建时设定原型** | 避免 `setPrototypeOf` 的性能惩罚 |
| **用 `Object.keys/values/entries` 操作纯净字典** | 纯净字典没有 `hasOwnProperty` 等方法 |
| **简单对象优先用字面量** | 只有需要特定原型或纯净字典时才用 `Object.create` |

> **一句话总结**：`Object.create()` 是 JavaScript 中最灵活的对象创建 API——它既能创建一个"无父无母"的纯净字典（用于安全存储任意键值数据），又能精确地"指腹为婚"为新对象安排任意的原型父亲（用于实现灵活的继承和精确克隆）。掌握它，你就掌握了超越 `new` 和 `{}` 的对象操控力——在需要极致灵活性或安全性的场景下，它是无可替代的工具。
