# 类中的访问器（getter/setter）+ 私有字段（`#field`）与私有方法

## 为什么需要访问器和私有性：封装的两把钥匙

面向对象编程的核心理念之一是**封装**——将数据（状态）和操作数据的代码（行为）捆绑在一起，同时对外隐藏不必要的实现细节。封装不是在故弄玄虚，而是出于两个务实的考量：一是**保护数据的完整性**，防止外部代码随意修改内部状态导致程序进入不一致的状态；二是**降低认知负担**，使用者只需要知道"这个对象能做什么"，而不需要知道"它是如何做到的"。

JavaScript 的类提供了两种机制来实现不同层次的封装。第一种是**访问器（Getter/Setter）**，它允许你在属性的读写操作中间插入拦截逻辑——就像在门上装了一个门卫，所有进出的人都要经过它的检查和登记。第二种是**私有字段（Private Fields）**，它通过 `#` 前缀语法提供真正的、语言层面的访问限制——这不是一扇可以绕过去的门，而是一面完全无法穿透的墙，只有类内部的代码才能看到墙后的东西。

这两种机制经常配合使用：用私有字段来存储真正敏感的数据，再用访问器来提供受控的外部接口。理解它们的工作原理和最佳实践，是编写健壮、可维护的 JavaScript 类的关键一步。

## 访问器（Getter/Setter）：属性读写的中介层

### 什么是访问器

访问器是一对特殊的方法，它们让你能够以"读写普通属性"的形式来执行自定义逻辑。从使用者的角度看，`obj.property` 和 `obj.property = value` 就是在对一个普通的属性进行读取和写入操作；但在底层，这些操作实际上被重定向到了你定义的 getter 和 setter 方法上：

```javascript
class Temperature {
  constructor(celsius) {
    // 这里会触发 setter
    this.celsius = celsius;
  }

  get celsius() {
    console.log('正在读取摄氏温度...');
    return this._celsius;
  }

  set celsius(value) {
    console.log(`正在设置摄氏温度为 ${value}°C...`);
    if (typeof value !== 'number') {
      throw new Error('温度必须是数字');
    }
    if (value < -273.15) {
      throw new Error('温度不能低于绝对零度（-273.15°C）');
    }
    this._celsius = value;
  }
}

const temp = new Temperature(25);
// 正在设置摄氏温度为 25°C...

console.log(temp.celsius);
// 正在读取摄氏温度...
// 25

temp.celsius = 100;
// 正在设置摄氏温度为 100°C...

temp.celsius = -300;
// Error: 温度不能低于绝对零度（-273.15°C）
```

注意这段代码中的一个关键设计模式：我们使用了 `_celsius`（带下划线前缀）作为实际存储数据的属性，而对外的接口叫 `celsius`（不带下划线）。这样做的原因是：如果 setter 中写成 `this.celsius = value`，那么赋值操作又会再次触发 setter 自身，形成无限递归调用直到栈溢出。所以必须用一个不同的名字来存储真实的数据，而下划线前缀是一种广泛使用的命名约定，用来表示"这是内部实现细节，请勿直接使用"。

### Getter 与 Setter 的不对称性

一个重要的细节是：**getter 和 setter 不一定非要成对出现**。你可以只定义 getter 而不定义 setter，从而创建一个"只读属性"；也可以只定义 setter（虽然这种用法比较少见）：

```javascript
class Circle {
  constructor(radius) {
    this.radius = radius;
  }

  get area() {
    return Math.PI * this.radius ** 2;
  }

  // 注意：没有定义 set area(...)
}

const circle = new Circle(5);
console.log(circle.area);   // 78.5398...

circle.area = 100;          // 静默失败！不会报错，但也不会生效
console.log(circle.area);   // 还是 78.5398...
```

当只有 getter 没有 setter 时，尝试写入该属性在非严格模式下会被**静默忽略**，而在严格模式下会抛出 `TypeError`。这是因为引擎发现这个属性确实存在（有一个 getter），但它没有对应的 setter，所以写入操作无法完成。

只读计算属性在实际开发中非常常见。比如一个表示矩形的类，其"面积"和"周长"都是完全由长和宽派生出来的值，不应该被独立修改：

```javascript
class Rectangle {
  constructor(width, height) {
    this.width = width;
    this.height = height;
  }

  get area() { return this.width * this.height; }
  get perimeter() { return 2 * (this.width + this.height); }
  get isSquare() { return this.width === this.height; }

  set area(value) {
    throw new Error('面积是计算属性，不能直接赋值 —— 请修改 width 或 height');
  }
}
```

### 访问器的存储位置

从技术层面来说，类的 getter 和 setter 被定义在 **prototype** 上，而不是每个实例上：

```javascript
class Box {
  #internalValue = 42;

  get value() {
    return this.#internalValue;
  }

  set value(v) {
    this.#internalValue = v;
  }
}

const box1 = new Box();
const box2 = new Box();

// getter/setter 定义在 prototype 上
const descriptor = Object.getOwnPropertyDescriptor(Box.prototype, 'value');
console.log(descriptor);     // { get: [Function], set: [Function], ... }

console.log(box1.value === box2.value); // true —— 共享同一个 getter
```

这意味着所有实例共享同一份 getter/setter 的实现代码，但每次调用时它们各自操作的 `this` 是不同的实例，所以行为上是独立的。这和方法存储在原型上的原理完全一致。

可以把访问器想象成一家公司的"客户服务窗口"。所有客户（实例）都面对的是同一个窗口（prototype 上的 getter/setter），但每个客户递交的业务资料（`this` 指向的实例）是不同的，窗口工作人员根据当前客户的资料来处理具体事务。

### 实际应用场景

#### 数据验证与清洗

最常见的用途是在赋值时检查数据的合法性和格式：

```javascript
class UserRegistration {
  constructor(email, password) {
    this.email = email;      // 触发 setter
    this.password = password; // 触发 setter
  }

  set email(value) {
    if (!value || typeof value !== 'string') {
      throw new Error('邮箱不能为空且必须是字符串');
    }
    const trimmed = value.trim().toLowerCase(); // 自动清理空白并转小写
    if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(trimmed)) {
      throw new Error('邮箱格式无效');
    }
    this._email = trimmed;
  }

  get email() { return this._email; }

  set password(value) {
    if (!value || typeof value !== 'string') {
      throw new Error('密码不能为空且必须是字符串');
    }
    if (value.length < 8) {
      throw new Error('密码至少需要8个字符');
    }
    if (!/[A-Z]/.test(value)) {
      throw new Error('密码必须包含至少一个大写字母');
    }
    if (!/[0-9]/.test(value)) {
      throw new Error('密码必须包含至少一个数字');
    }
    // 实际项目中这里应该进行哈希处理
    this._passwordHash = this.#hashPassword(value);
  }

  get password() {
    // 密码不应该被明文读取出去！
    return '[已加密存储]';
  }

  #hashPassword(password) {
    // 简化示例 —— 生产环境应使用专业的加密库
    let hash = 0;
    for (let i = 0; i < password.length; i++) {
      const char = password.charCodeAt(i);
      hash = ((hash << 5) - hash) + char;
      hash |= 0;
    }
    return Math.abs(hash).toString(16).padStart(8, '0');
  }
}

// 正常注册
const user = new UserRegistration(' Example@Email.COM ', 'MyPass123');
console.log(user.email);    // example@email.com （已自动清理）
console.log(user.password); // [已加密存储]

// 异常情况
new UserRegistration('', 'short'); // Error: 密码至少需要8个字符
```

这个例子展示了访问器作为"数据守门员"的能力：邮箱地址被自动去除了首尾空白、统一转成了小写、通过了格式校验；密码经过了复杂度检查、被哈希后安全存储、读取时返回脱敏信息。对于使用者来说，他们只是简单地写了 `this.email = email`，所有的安全检查都是自动完成的。

#### 延迟计算（Lazy Evaluation）

有些属性的计算成本很高，而且可能永远不会被用到。这时可以用 getter 实现"按需计算"：

```javascript
class ExpensiveData {
  #cachedResult = null;

  get expensiveValue() {
    if (this.#cachedResult === null) {
      console.log('正在执行昂贵计算...');
      // 模拟耗时操作：遍历大量数据
      let sum = 0;
      for (let i = 0; i < 10_000_000; i++) {
        sum += Math.sqrt(i);
      }
      this.#cachedResult = sum;
    }
    return this.#cachedResult;
  }
}

const data = new ExpensiveData();

// 第一次读取时才会计算
console.log(data.expensiveValue);  // 正在执行昂贵计算... → 结果
// 后续读取直接返回缓存
console.log(data.expensiveValue);  // 直接返回结果（无日志输出）
```

这种模式的思路是："我不确定你是否真的需要这个值，所以先不计算；等你第一次来取的时候我再算好，之后就一直给你缓存的结果"。这在处理大型数据集、复杂图表渲染、文件解析等场景中非常有价值——它避免了不必要的性能开销。

#### 日志记录与审计追踪

setter 可以在不改变核心业务逻辑的前提下，插入横切关注点（Cross-cutting Concern）：

```javascript
class AuditableAccount {
  #balance = 0;
  #transactionLog = [];

  constructor(initialBalance) {
    this.balance = initialBalance;
  }

  get balance() { return this.#balance; }

  set balance(newBalance) {
    const oldBalance = this.#balance;
    this.#balance = newBalance;

    // 自动记录每笔变动
    this.#transactionLog.push({
      timestamp: new Date().toISOString(),
      from: oldBalance,
      to: newBalance,
      delta: newBalance - oldBalance,
      stackTrace: new Error().stack.slice(0, 200) // 简化的调用栈
    });
  }

  deposit(amount) { this.balance += amount; }
  withdraw(amount) { this.balance -= amount; }

  getTransactionHistory() {
    return [...this.#transactionLog];
  }
}

const account = new AuditableAccount(1000);
account.deposit(500);
account.withdraw(200);

console.log(account.getTransactionHistory());
// [
//   { timestamp: '...', from: 0, to: 1000, delta: 1000, ... },
//   { timestamp: '...', from: 1000, to: 1500, delta: 500, ... },
//   { timestamp: '...', from: 1500, to: 1300, delta: -200, ... }
// ]
```

通过 setter 来拦截每一次余额变化，我们可以在不修改任何业务方法（deposit/withdraw）的情况下自动建立完整的审计日志。这就是所谓的"开放-封闭原则"的实际体现——对扩展开放（你可以随时加入新的审计逻辑），对修改封闭（已有的业务方法不需要改动一行代码）。

## 私有字段（#field）：语言级别的硬隔离

### 从约定到强制：为什么下划线不够用了

在 ES2022 引入私有字段语法之前，JavaScript 开发者长期使用一种基于**命名约定**的方式来标记"私有"成员——给属性名加上下划线前缀，比如 `_name`、`_internalData`。这是一种源自 Python 社区的惯例，含义是："我知道你能访问到这个属性，但我希望你不要这么做，因为它属于内部实现细节，随时可能在版本更新中被修改或删除。"

问题在于这仅仅是一个**君子协定**，没有任何强制性：

```javascript
class CoffeeMachine {
  // "伪私有" —— 只靠约定
  _waterAmount = 0;
  _heatTemperature = 90;

  constructor(water) {
    this._waterAmount = water;
  }

  brew() {
    if (this._waterAmount > 0 && this._waterAmount >= 30) {
      console.log(
        `☕ 用 ${this._waterAmount}ml 水、${this._heatTemperature}°C 冲泡咖啡`
      );
      this._waterAmount = 0;
      return true;
    }
    console.log('❌ 水量不足');
    return false;
  }
}

const machine = new CoffeeMachine(200);
machine.brew(); // ☕ 正常冲泡

// 但是没有任何东西阻止外部代码这样做：
machine._waterAmount = -999;       // 负数水量？没问题！
machine._heatTemperature = 30000;  // 三万度？随便改！

machine.brew(); // ☕ 用 -999ml 水、30000° 冲泡咖啡 ← 完全不合理的状态
```

下划线约定就像是在自家院子的围栏上挂了一块"私人领地，请勿入内"的牌子。大多数有素质的路人（开发者）看到了会尊重你的意愿绕道而行，但如果有人执意要翻进来，那块牌子拦不住他——他可以直接修改你的内部数据，让你的对象进入一种你自己从未预料过的错误状态。

ES2022 的私有字段（以 `#` 开头）则完全不同。它不是一块牌子，而是一堵**钢筋混凝土墙**——不管谁试图从外面访问，都会被语法本身拒绝：

```javascript
class SecureCoffeeMachine {
  // 真正私有的字段 —— 以 # 开头
  #waterAmount = 0;
  #heatTemperature = 90;

  constructor(water) {
    this.#waterAmount = water;  // ✅ 类内部正常访问
  }

  brew() {
    if (this.#waterAmount > 0 && this.#waterAmount >= 30) {
      console.log(
        `☕ 用 ${this.#waterAmount}ml 水、${this.#heatTemperature}°C 冲泡咖啡`
      );
      this.#waterAmount = 0;
      return true;
    }
    console.log('❌ 水量不足');
    return false;
  }
}

const secureMachine = new SecureCoffeeMachine(200);
secureMachine.brew(); // ☕ 正常冲泡

secureMachine.#waterAmount = -999;
//                    ^^^^^^^^^^^^
// SyntaxError: Private field '#waterAmount' must be declared in an enclosing class
```

注意这里的错误类型——是 **SyntaxError**（语法错误），而不是运行时的 `TypeError` 或 `ReferenceError`。这意味着引擎在**解析代码阶段**就阻止了这种访问，甚至不需要等到代码执行。你不可能在类的外面写出能成功编译的、访问私有字段的代码。这种保护比任何运行时检查都要彻底。

### 私有字段的声明规则

私有字段有几个非常重要的语法规则，违反任何一个都会导致语法错误：

**第一，必须在类体的顶层声明**。你不能在方法内部或条件语句中声明私有字段：

```javascript
class WrongDeclaration {
  method() {
    #secret = 123; // ❌ 语法错误 —— 不能在方法体内声明
  }

  if (true) {           // ❌ 语法错误 —— 不能在块级作用域内声明
    #field = 'hello';
  }
}
```

**第二，声明和使用必须使用完全一致的名称**（包括 `#` 号）：

```javascript
class FieldNaming {
  #myField = 42;

  read() {
    return this.#myField;   // ✅ 正确
    // return this.myField; // ❌ 访问的是另一个属性（如果存在的话）
    // return this.#myfield; // ❌ 大小写敏感，这是不同的名字
  }
}
```

`#` 是名称的一部分，不是修饰符。`#myField` 和 `myField` 是两个完全不相关的属性，就像 `foo` 和 `bar` 一样没有任何关联。这一点和 TypeScript 的 `private` 关键字有本质区别——TypeScript 的 `private` 只是编译时的类型检查，编译出来的 JavaScript 代码中这些属性仍然是普通的公开属性；而 JavaScript 的 `#` 字段是语言层面的硬隔离。

**第三，私有字段不能动态创建或通过代理访问**：

```javascript
class Container {
  #data = [];

  add(item) {
    this.#data.push(item);
  }
}

const container = new Container();
container.add('item1');

// 这些方式都无法突破私有性的保护：
container['#data'];             // undefined —— 这只是在找一个名为 '#data' 的公开属性
Object.keys(container);         // [] —— 私有字段不出现在键列表中
JSON.stringify(container);      // {} —— 私有字段不会被序列化
Reflect.get(container, '#data'); // undefined —— 反射 API 也无法访问
for (const key in container) {}  // 无输出 —— for...in 遍历不到
```

即使是用到了 Proxy 这种强大的元编程工具，也无法拦截对私有字段的访问——因为私有字段在语法层面就不允许从外部引用，Proxy 根本没有机会介入。

### 私有字段的初始化时机

私有字段的初始化遵循和公有字段相同的规则：在 `constructor` 执行之前，按照声明的顺序依次初始化：

```javascript
class InitOrderDemo {
  #first = console.log('① #first 初始化');
  #second = console.log('② #second 初始化');

  constructor() {
    console.log('③ constructor 执行');
  }

  #third = console.log('④ #third 初始化');  // 同样优先于 constructor
}

new InitOrderDemo();
// 输出：① → ② → ④ → ③
```

无论私有字段写在类体的什么位置，它们的初始化都先于构造函数。这保证了构造器执行时所有私有字段都已经有了初始值（哪怕只是 `undefined`）。

### 私有字段与 this 的绑定

和公有字段一样，私有字段也是绑定到**实例**上的，而不是原型上的：

```javascript
class InstanceLevelPrivate {
  #id;
  static counter = 0;

  constructor() {
    this.#id = InstanceLevelPrivate.counter++;
  }

  getId() {
    return this.#id;
  }
}

const a = new InstanceLevelPrivate();
const b = new InstanceLevelPrivate();
const c = new InstanceLevelPrivate();

console.log(a.getId()); // 0
console.log(b.getId()); // 1
console.log(c.getId()); // 2
// 每个 #id 都是独立的，互不影响
```

每个实例拥有自己的 `#id` 副本，和其他实例完全隔离。这正是私有字段的核心意义所在——它保证了一个对象的内部状态不会被其他对象（即使是同类实例）窥视或篡改。

## 私有方法（#method）：不可见的内部行为

### 基本语法

ES2022 不仅引入了私有字段，还引入了**私有方法**。私有方法的语法和私有字段类似——同样使用 `#` 作为前缀：

```javascript
class Authenticator {
  #username = '';
  #hashedPassword = '';

  constructor(username, password) {
    this.#username = username;
    this.#hashedPassword = this.#hash(password);
  }

  // 私有方法：只能在类内部调用
  #hash(input) {
    // 简化的哈希算法 —— 仅作演示
    let hash = 2166136261;
    for (let i = 0; i < input.length; i++) {
      hash ^= input.charCodeAt(i);
      hash = Math.imul(hash, 16777619);
    }
    return (hash >>> 0).toString(16).padStart(8, '0');
  }

  // 另一个私有方法：密码强度检测
  #validateStrength(pwd) {
    const issues = [];
    if (pwd.length < 8) issues.push('至少8个字符');
    if (!/[A-Z]/.test(pwd)) issues.push('至少一个大写字母');
    if (!/[0-9]/.test(pwd)) issues.push('至少一个数字');
    if (!/[^A-Za-z0-9]/.test(pwd)) issues.push('至少一个特殊字符');
    return issues;
  }

  // 公共方法：创建账户
  createAccount(username, password) {
    const issues = this.#validateStrength(password);
    if (issues.length > 0) {
      throw new Error(`密码不符合要求: ${issues.join(', ')}`);
    }
    this.#username = username;
    this.#hashedPassword = this.#hash(password);
    return { success: true };
  }

  // 公共方法：验证登录
  verifyLogin(password) {
    return this.#hash(password) === this.#hashedPassword;
  }
}

const auth = new Authenticator('admin', 'SecurePass123!');
console.log(auth.verifyLogin('SecurePass123!')); // true
console.log(auth.verifyLogin('wrongpassword'));  // false

auth.#hash('anything');
//    ^^^^^^
// SyntaxError: Private field '#hash' must be declared in an enclosing class
```

私有方法和私有字段共享同一个命名空间——你不能让一个私有方法和一个私有字段拥有相同的名字：

```javascript
class NamingConflict {
  #data = 42;
  #data() { } // ❌ 语法错误 —— #data 已经被声明为字段了
}
```

### 私有方法 vs 公有方法加下划线前缀

很多团队在私有方法出现之前，一直用 `_methodName` 的命名约定来表达"这是一个内部方法，不要在外部调用"。但这和真正的私有方法有着根本性的差异：

```javascript
class PublicWithConvention {
  // 约定式"私有"方法
  _internalLogic(x) {
    return x * x + 2 * x + 1;
  }

  publicMethod(n) {
    return this._internalLogic(n);
  }
}

class WithTruePrivate {
  // 真正的私有方法
  #internalLogic(x) {
    return x * x + 2 * x + 1;
  }

  publicMethod(n) {
    return this.#internalLogic(n);
  }
}

const publicObj = new PublicWithConvention();
const privateObj = new WithTruePrivate();

publicObj._internalLogic(10);     // 返回 121 —— 可以调用，只是"不应该"
privateObj.#internalLogic(10);    // SyntaxError —— 根本无法编译
```

约定式的做法依赖于开发者自律，而私有方法由编译器/解释器强制执行。在大型团队协作、开源项目发布、或者需要向第三方暴露 API 的场景中，这种强制的隐私保护至关重要。你永远不知道下游的使用者会怎么使用你的代码——也许他们会依赖某个"本应是私有"的内部方法来做业务逻辑，当你重构代码时改变了这个方法的行为，他们的程序就会无声地出错。

可以把约定式私有比作"办公室里写着'员工专用'的门"，任何人只要愿意都能推开进去看看；而真正的私有方法则是"需要指纹识别才能打开的安全室门"，除非你是授权人员（类内部的代码），否则连把手都摸不到。

### 私有 getter/setter

私有字段不仅可以搭配普通的私有方法，还可以定义**私有的 getter 和 setter**——也就是用 `#` 前缀的访问器：

```javascript
class SmartCounter {
  #count = 0;

  // 私有 getter —— 只有类内部可以用 this.#count 访问
  get #count() {
    console.log('[内部] 读取计数值');
    return this.#count;
  }

  // 私有 setter —— 只有类内部可以用 this.#count = value 赋值
  set #count(value) {
    console.log(`[内部] 设置计数值为 ${value}`);
    if (value < 0) {
      throw new Error('计数器不能为负数');
    }
    this.#count = value;
  }

  increment() {
    this.#count++;  // 触发私有 getter 和 setter
  }

  decrement() {
    this.#count--;
  }

  reset() {
    this.#count = 0;
  }

  get displayCount() {
    // 公共 getter 通过私有 getter 间接读取
    return `当前计数: ${this.#count}`;
  }
}

const counter = new SmartCounter();
counter.increment();
counter.increment();
counter.increment();
console.log(counter.displayCount);  // 当前计数: 3

counter.decrement();
console.log(counter.displayCount);  // 当前计数: 2
```

私有访问器的作用是对**类内部的代码**也施加一层控制。比如上面的例子中，每次内部代码读写 `#count` 时都会打印日志——这对于调试复杂的类非常有帮助。当然，更常见的用途是在私有 setter 中添加额外的校验逻辑，确保即使在类内部，数据也不会被意外地设为一个非法值。

## 静态私有字段与方法：类级别的秘密

### 语法与基本概念

除了实例级的私有成员，JavaScript 还支持**静态私有字段和静态私有方法**。它们属于类本身（而非类的实例），并且同样受到严格的访问控制：

```javascript
class DatabaseConnection {
  // 静态私有字段 —— 所有代码共享一份，且完全不可从外部访问
  static #connectionPool = [];
  static #maxPoolSize = 10;
  static #activeConnections = 0;

  // 静态私有方法
  static #isPoolAvailable() {
    return DatabaseConnection.#activeConnections < DatabaseConnection.#maxPoolSize;
  }

  constructor(connectionString) {
    this.connectionString = connectionString;
    this.id = ++DatabaseConnection.#activeConnections;
    DatabaseConnection.#connectionPool.push(this);
    console.log(`连接 #${this.id} 已创建 (${connectionString})`);
  }

  query(sql) {
    console.log(`[连接#${this.id}] 执行: ${sql}`);
    return { connectionId: this.id, sql, result: 'mock_data' };
  }

  close() {
    const index = DatabaseConnection.#connectionPool.indexOf(this);
    if (index > -1) {
      DatabaseConnection.#connectionPool.splice(index, 1);
      DatabaseConnection.#activeConnections--;
      console.log(`连接 #${this.id} 已关闭`);
    }
  }

  // 静态公共方法 —— 提供受控的外部接口
  static getConnection(connectionString) {
    if (!DatabaseConnection.#isPoolAvailable()) {
      throw new Error('连接池已达上限');
    }
    return new DatabaseConnection(connectionString);
  }

  static getStatus() {
    return {
      activeConnections: DatabaseConnection.#activeConnections,
      maxCapacity: DatabaseConnection.#maxPoolSize,
      availableSlots: DatabaseConnection.#maxPoolSize - DatabaseConnection.#activeConnections
    };
  }
}

// 使用连接池
const db1 = DatabaseConnection.getConnection('mysql://db1');
const db2 = DatabaseConnection.getConnection('mysql://db2');

db1.query('SELECT * FROM users');
db2.query('SELECT * FROM products');

console.log(DatabaseConnection.getStatus());
// { activeConnections: 2, maxCapacity: 10, availableSlots: 8 }

// 外部无法触及任何私有成员
DatabaseConnection.#connectionPool;         // SyntaxError
DatabaseConnection.#maxPoolSize = 999;      // SyntaxError
DatabaseConnection.#isPoolAvailable();      // SyntaxError
```

静态私有成员的价值在于管理**跨实例共享的、但又不应暴露的实现细节**。连接池的大小限制、连接列表、可用性检查逻辑——这些都是数据库连接模块的"家务事"，外部使用者既不需要知道也不应该有能力去干预。

### 设计哲学：为什么需要"静态私有"

考虑一个 ID 生成器的场景，要求全局唯一且递增：

```javascript
class IdGenerator {
  static #nextId = 1;  // 静态私有 —— 下一个可用的ID

  constructor(prefix = '') {
    this.id = `${prefix}${IdGenerator.#nextId++}`;
  }
}

const item1 = new IdGenerator('ITEM-'); // ITEM-1
const item2 = new IdGenerator('ITEM-'); // ITEM-2
const user1 = new IdGenerator('USER-'); // USER-3

console.log(item1.id); // ITEM-1
console.log(item2.id); // ITEM-2
console.log(user1.id); // USER-3

// 外部无法篡改计数器
IdGenerator.#nextId = 99999; // SyntaxError —— 无法破坏ID的唯一性和连续性
```

如果把 `#nextId` 改成公有的 `static nextId = 1`，任何代码都可以在任何时候把它改成任意值，导致后续生成的 ID 出现重复或不连续的问题。静态私有字段从根本上杜绝了这种可能性——计数器的完整性和安全性得到了语言本身的保障。

## 继承中的私有性：子类能否访问父类的私有成员？

### 子类无法访问父类的私有字段

这是一个非常重要且容易误解的特性：**子类不能访问父类中定义的私有字段和方法**。每一个类的私有成员都严格限定在该类的作用域之内，即使继承关系也无法打破这堵墙：

```javascript
class Parent {
  #secret = '父级的秘密';

  #privateMethod() {
    return '父级的私有方法被调用了';
  }

  revealSecret() {
    return this.#secret;          // ✅ 父类自己可以访问
  }

  callPrivateMethod() {
    return this.#privateMethod(); // ✅ 父类自己可以调用
  }
}

class Child extends Parent {
  tryAccessParentSecret() {
    // return this.#secret;       // ❌ SyntaxError —— 子类无法访问父类的 #secret
    // return this.#privateMethod(); // ❌ SyntaxError —— 同理
    return '子类无法触碰父类的私有领域';
  }
}

const child = new Child();
console.log(child.revealSecret());        // 父级的秘密
console.log(child.tryAccessParentSecret());// 子类无法触碰父类的私有领域
```

这个设计是有意为之的。私有字段的意义在于"强封装"——如果一个子类可以随意访问父类的私有成员，那封装就被打破了。子类应该通过父类提供的**公共或受保护的接口**来交互，而不是直接伸手进父类的"黑盒子"里面翻找。

可以把继承关系想象成一家公司和它的子公司。总公司（父类）有一些机密文件放在保险柜（私有字段）里，子公司（子类）可以使用总公司提供的各种办公系统和流程（公共方法），但不能直接拿钥匙开总公司的保险柜看里面的内容。如果子公司需要某些信息，应该走正式的申请渠道（公共API）。

### 子类可以定义同名的私有成员

有趣的是，子类完全可以定义和父类**同名**的私有字段或方法——它们之间不会冲突，因为它们分属不同的作用域：

```javascript
class Animal {
  #type = '动物';

  getType() {
    return this.#type; // 访问 Animal 自己的 #type
  }
}

class Dog extends Animal {
  #type = '狗';  // Dog 有自己的 #type，和 Animal 的 #type 完全无关

  getDogType() {
    return this.#type; // 访问 Dog 自己的 #type
  }
}

const dog = new Dog();
console.log(dog.getType());   // 动物 —— 来自 Animal.#type
console.log(dog.getDogType()); // 狗 —— 来自 Dog.#type
```

同一个 `dog` 实例上实际上存在两个名为 `#type` 但分属不同作用域的私有字段。当代码在 `Animal` 的方法中执行时，`this.#type` 指向 `Animal.#type`；当代码在 `Dog` 的方法中执行时，`this.#type` 指向 `Dog.#type`。这种"同名但不冲突"的机制被称为"**私有名称作用域**"（Private Name Scope），它确保了每个类的私有成员都有自己独立的命名空间。

## 三级访问控制体系：Public、Protected 与 Private

### JavaScript 缺少内置的 protected 修饰符

Java、C#、Python 等语言通常提供三档访问级别：`public`（所有人可访问）、`protected`（子类可访问）、`private`（仅自身可访问）。但 JavaScript 的原生语法只有两档：**公开的**（默认）和**私有的**（`#`）。没有原生的 `protected` 修饰符。

不过，社区发展出了一套成熟的**约定模式**来弥补这个空缺：

```javascript
class Vehicle {
  // 🔓 公共接口 —— 任何人都可以使用
  brand;
  model;

  // 🛡️ 受保护成员 —— 约定用单个下划线前缀
  // 含义：子类可以访问和覆盖，但外部代码不应该直接使用
  _engineStatus = 'off';
  _mileage = 0;

  // 🔒 私有成员 —— 语言强制保护
  #serialNumber;
  #manufactureDate;

  constructor(brand, model, serialNumber) {
    this.brand = brand;
    this.model = model;
    this.#serialNumber = serialNumber;
    this.#manufactureDate = new Date().toISOString();
  }

  // 🔓 公共方法
  start() {
    this._engineStatus = 'on';
    console.log(`${this.brand} ${this.model} 已启动`);
    this.#logEvent('engine_start');
  }

  stop() {
    this._engineStatus = 'off';
    console.log(`${this.brand} ${this.model} 已熄火`);
    this.#logEvent('engine_stop');
  }

  drive(distanceKm) {
    if (this._engineStatus === 'off') {
      console.warn('警告：请先启动车辆！');
      return;
    }
    this._mileage += distanceKm;
    console.log(`行驶了 ${distanceKm} 公里，累计里程: ${this._mileage}km`);
  }

  // 🛡️ 受保护方法 —— 子类可能会重写此方法来自定义报告格式
  _generateReport() {
    return {
      brand: this.brand,
      model: this.model,
      mileage: this._mileage,
      status: this._engineStatus
    };
  }

  // 🔒 私有方法 —— 纯粹的内部实现细节
  #logEvent(eventType) {
    console.log(
      `[事件日志] ${eventType} | 序列号: ${this.#serialNumber} | 时间: ${new Date().toLocaleString()}`
    );
  }

  // 🔓 公共的 getter —— 提供受控的信息访问
  get info() {
    return `${this.brand} ${this.model} | 里程: ${this._mileage}km`;
  }
}

// 子类可以访问和覆盖受保护成员
class ElectricVehicle extends Vehicle {
  #batteryLevel = 100;

  constructor(brand, model, serialNumber) {
    super(brand, model, serialNumber);
  }

  // 🛡️ 重写受保护的自定义报告方法
  _generateReport() {
    const base = super._generateReport(); // 调用父类的受保护方法
    return {
      ...base,
      batteryLevel: this.#batteryLevel + '%',
      type: 'electric'
    };
  }

  charge(amount) {
    this.#batteryLevel = Math.min(100, this.#batteryLevel + amount);
    console.log(`充电中... 电量: ${this.#batteryLevel}%`);
  }
}

// ========== 使用示例 ==========

const car = new Vehicle('丰田', 'Camry', 'SN-2024-001234');
car.start();            // 丰田 Camry 已启动
car.drive(50);          // 行驶了 50 公里，累计里程: 50km
car.stop();             // 丰田 Camry 已熄火

console.log(car.info);  // 丰田 Camry | 里程: 50km

// 公共成员可以自由访问
console.log(car.brand); // 丰田

// 受保护成员技术上可以访问（但不推荐）
console.log(car._mileage); // 50 —— 能访问，但你应该用公共接口

// 私有成员完全不可访问
// car.#serialNumber;     // SyntaxError

// 子类正常工作
const tesla = new ElectricVehicle('Tesla', 'Model 3', 'SN-2024-009876');
tesla.start();           // Tesla Model 3 已启动
tesla.drive(80);
tesla.charge(30);        // 充电中... 电量: 100%
```

这套三级体系的总结如下：

| 层级 | 语法 | 可被外部访问 | 可被子类访问 | 典型用途 |
|------|------|-------------|-------------|----------|
| **Public**（公开） | `name` | ✅ | ✅ | 对外暴露的 API |
| **Protected**（受保护） | `_name` | ⚠️ 技术可行，但不建议 | ✅ | 子类可扩展的内部机制 |
| **Private**（私有） | `#name` | ❌ 语法层面禁止 | ❌ 语法层面禁止 | 绝对的内部实现细节 |

### 何时使用哪一级？

选择合适的访问级别是一门艺术，以下是一些实用的指导原则：

**使用 Private (`#`) 当：**
- 数据涉及安全性（密码、令牌、密钥）
- 数据结构可能在未来重构中改变
- 你想防止外部代码产生对该内部实现的依赖
- 该成员纯粹是实现细节，与"这个类做什么"无关，只与"这个类怎么做"有关

**使用 Protected (`_`) 当：**
- 子类需要访问或覆盖该成员来完成自己的功能
- 该成员是"内部 API"的一部分——不是给终端用户用的，但是给继承你的类的开发者用的
- 你在使用纯 JavaScript（非 TypeScript），且需要在灵活性和封装性之间取得平衡

**使用 Public（默认）当：**
- 这是类的核心功能，是其他代码使用这个类的主要方式
- 该成员构成了类的"契约"（contract）——一旦发布就不应轻易改变
- 它回答了"这个类能做什么"这个问题

## 协同实战：安全的银行账户系统

让我们综合运用前面学到的所有知识，构建一个接近真实的银行账户模型。这个案例展示了访问器和私有字段如何协同工作来构建一个既有完善的外部 API 又有坚固内部防护的系统：

```javascript
class BankAccount {
  // ====== 🔒 绝对私有的核心数据 ======
  #balance = 0;
  #pinHash = '';
  #accountNumber;
  #createdAt;
  #transactionHistory = [];

  // ====== 🛡️ 受保护的配置项（子类可定制） ======
  _currency = 'CNY';
  _dailyLimit = 50000;
  _overdraftAllowed = false;

  // ====== 🔓 公开的标识信息 ======
  ownerName;
  accountType;

  constructor(ownerName, accountNumber, pin, initialDeposit = 0) {
    this.ownerName = ownerName;
    this.#accountNumber = accountNumber;
    this.#pinHash = this.#hashPin(pin);
    this.#createdAt = new Date();
    this.accountType = 'standard';

    if (initialDeposit > 0) {
      this.#processDeposit(initialDeposit, '初始存款');
    }
  }

  // ====== 🔓 公共 API: 存款 ======

  deposit(amount) {
    if (amount <= 0) {
      throw new Error('存款金额必须大于零');
    }
    this.#processDeposit(amount, '存款');
    return this;
  }

  // ====== 🔓 公共 API: 取款 ======

  withdraw(amount, pin) {
    this.#verifyPin(pin);

    if (amount <= 0) {
      throw new Error('取款金额必须大于零');
    }

    if (amount > this._dailyLimit) {
      throw new Error(`单笔取款不能超过每日限额 ${this._currency} ${this._dailyLimit}`);
    }

    const availableBalance = this.#getAvailableBalance();
    if (amount > availableBalance) {
      if (!this._overdraftAllowed) {
        throw new Error(
          `余额不足！可用余额: ${this._currency} ${availableBalance.toFixed(2)}`
        );
      }
      console.warn(`⚠️ 透支取款: ${this._currency} ${(amount - availableBalance).toFixed(2)}`);
    }

    this.#processWithdrawal(amount, '取款');
    return this;
  }

  // ====== 🔓 公共 API: 转账 ======

  transferTo(targetAccount, amount, pin) {
    this.withdraw(amount, pin);
    targetAccount.deposit(amount);
    this.#recordTransaction('transfer_out', -amount, `转账至 ${targetAccount.ownerName}`);
    targetAccount.#recordTransaction('transfer_in', amount, `收到来自 ${this.ownerName} 的转账`);

    console.log(
      `✅ 已转账 ${this._currency} ${amount} 给 ${targetAccount.ownerName}`
    );
    return this;
  }

  // ====== 🔓 公共 Getter（只读视图）=====

  get balance() {
    return {
      current: this.#balance,
      currency: this._currency,
      formatted: `${this._currency} ${this.#balance.toFixed(2)}`
    };
  }

  get accountInfo() {
    return {
      owner: this.ownerName,
      type: this.accountType,
      currency: this._currency,
      openedAt: this.#createdAt.toLocaleDateString(),
      maskedAccount: this.#maskAccountNumber()
    };
  }

  get transactions() {
    return [...this.#transactionHistory]; // 返回副本，防止外部修改原始数组
  }

  // ====== 🛡️ 受保护的方法（供子类扩展）======

  _calculateInterest(rate, days) {
    const dailyRate = rate / 365;
    const interest = this.#balance * dailyRate * days;
    return Math.round(interest * 100) / 100;
  }

  _formatCurrency(amount) {
    return `${this._currency} ${amount.toFixed(2)}`;
  }

  // ====== 🔒 私有辅助方法 ======

  #hashPin(pin) {
    let hash = 0;
    for (let i = 0; i < pin.length; i++) {
      const char = pin.charCodeAt(i);
      hash = ((hash << 5) - hash) + char;
      hash |= 0;
    }
    return Math.abs(hash).toString(16).padStart(8, '0');
  }

  #verifyPin(pin) {
    if (this.#hashPin(pin) !== this.#pinHash) {
      throw new Error('PIN 码错误');
    }
  }

  #getAvailableBalance() {
    return this.#balance;
  }

  #processDeposit(amount, description) {
    this.#balance += amount;
    this.#recordTransaction('deposit', amount, description);
  }

  #processWithdrawal(amount, description) {
    this.#balance -= amount;
    this.#recordTransaction('withdrawal', -amount, description);
  }

  #recordTransaction(type, amount, description) {
    this.#transactionHistory.push({
      id: this.#transactionHistory.length + 1,
      type,
      amount,
      balanceAfter: this.#balance,
      description,
      timestamp: new Date().toISOString()
    });
  }

  #maskAccountNumber() {
    const str = String(this.#accountNumber);
    return str.slice(0, 4) + '*'.repeat(str.length - 4);
  }
}

// ========== 子类：支持利息的储蓄账户 ==========

class SavingsAccount extends BankAccount {
  #interestRate = 0.035; // 3.5% 年利率

  constructor(ownerName, accountNumber, pin, initialDeposit, interestRate) {
    super(ownerName, accountNumber, pin, initialDeposit);
    this.accountType = 'savings';
    if (interestRate) {
      this.#interestRate = interestRate;
    }
  }

  // 利用父类的受保护方法来计算利息
  applyMonthlyInterest(daysInMonth = 30) {
    const interest = this._calculateInterest(this.#interestRate, daysInMonth);
    if (interest > 0) {
      this.deposit(interest);
      console.log(
        `🏦 本月利息入账: ${this._formatCurrency(interest)} (年利率: ${this.#interestRate * 100}%)`
      );
    }
    return interest;
  }

  get savingsSummary() {
    return {
      ...super.accountInfo,
      annualRate: `${this.#interestRate * 100}%`,
      estimatedMonthlyEarnings: this._calculateInterest(this.#interestRate, 30),
      projectedYearlyEarnings: this._calculateInterest(this.#interestRate, 365)
    };
  }
}

// ========== 实际使用 ==========

// 开立账户
```

这个案例完整地展示了三级访问控制的协作关系：

- **`#` 私有字段**保护着最敏感的数据：余额、PIN 码哈希、账号、交易历史。这些数据的安全性是整个系统的基石，任何外部篡改都可能造成严重的后果。
- **`_` 受保护成员**提供了可扩展的钩子：货币符号、每日限额、利息计算方法等。子类可以根据自己的业务需求来定制这些参数和行为。
- **公开的 API**构成了清晰的对外接口：存钱、取钱、转账、查余额。使用者不需要知道背后发生了什么复杂的校验和记录过程。

### 协同实战：游戏角色状态管理系统

再来看一个更有趣的游戏开发场景，展示私有字段和访问器如何在状态管理和规则约束方面发挥作用：

```javascript
class GameCharacter {
  // ====== 🔒 核心状态（完全私有）======
  #hp;
  #maxHp;
  #mp;
  #maxMp;
  #level = 1;
  #experience = 0;
  #expToNextLevel = 100;
  #isAlive = true;
  #buffs = [];       // 增益效果
  #debuffs = [];      // 减益效果

  // ====== 🔓 公开属性 ======
  name;
  characterClass;

  constructor(name, characterClass, maxHp, maxMp) {
    this.name = name;
    this.characterClass = characterClass;
    this.#maxHp = maxHp;
    this.#hp = maxHp;
    this.#maxMp = maxMp;
    this.#mp = maxMp;
  }

  // ----- 战斗相关 -----

  takeDamage(amount, attacker) {
    if (!this.#isAlive) {
      console.log(`${this.name} 已经倒下了`);
      return;
    }

    // 应用减伤 buff
    let finalDamage = this.#applyDamageModifiers(amount);
    finalDamage = Math.max(0, finalDamage);

    this.#hp -= finalDamage;

    console.log(
      `${attacker} 对 ${this.name} 造成 ${finalDamage} 点伤害！` +
      `(剩余 HP: ${this.#hp}/${this.#maxHp})`
    );

    if (this.#hp <= 0) {
      this.#die();
    }
  }

  heal(amount, healer) {
    if (!this.#isAlive) {
      console.log(`${this.name} 无法被治疗 —— 已经死亡`);
      return;
    }

    const actualHeal = Math.min(amount, this.#maxHp - this.#hp);
    this.#hp += actualHeal;

    console.log(
      `${healer} 为 ${this.name} 恢复了 ${actualHeal} 点生命值！` +
      `(HP: ${this.#hp}/${this.#maxHp})`
    );
  }

  useMana(amount) {
    if (this.#mp < amount) {
      console.warn(`${this.name} 法力不足！(需要 ${amount}, 当前 ${this.#mp})`);
      return false;
    }
    this.#mp -= amount;
    return true;
  }

  restoreMana(amount) {
    this.#mp = Math.min(this.#mp + amount, this.#maxMp);
    console.log(`${this.name} 恢复法力！(MP: ${this.#mp}/${this.#maxMp})`);
  }

  // ----- 经验与升级 -----

  gainExperience(exp) {
    if (!this.#isAlive) return;

    this.#experience += exp;
    console.log(`${this.name} 获得 ${exp} 点经验值！(总计: ${this.#experience}/${this.#expToNextLevel})`);

    while (this.#experience >= this.#expToNextLevel) {
      this.#levelUp();
    }
  }

  // ----- Buff/Debuff 系统 -----

  addBuff(buff) {
    this.#buffs.push({ ...buff, remainingTurns: buff.duration });
    console.log(`✨ ${this.name} 获得 [${buff.name}] 效果，持续 ${buff.duration} 回合`);
  }

  addDebuff(debuff) {
    this.#debuffs.push({ ...debuff, remainingTurns: debuff.duration });
    console.log(`💀 ${this.name} 受到 [${debuff.name}] 影响，持续 ${debuff.duration} 回合`);
  }

  processTurnEffects() {
    this.#processBuffs();
    this.#processDebuffs();
  }

  // ----- 🔓 公开 Getter（只读视图） -----

  get status() {
    return {
      name: this.name,
      class: this.characterClass,
      level: this.#level,
      hp: { current: this.#hp, max: this.#maxHp },
      mp: { current: this.#mp, max: this.#maxMp },
      alive: this.#isAlive,
      exp: { current: this.#experience, nextLevel: this.#expToNextLevel },
      buffs: [...this.#buffs],
      debuffs: [...this.#debuffs]
    };
  }

  get hpPercentage() {
    return Math.round((this.#hp / this.#maxHp) * 100) + '%';
  }

  get canAct() {
    return this.#isAlive && this.#hp > 0;
  }

  // ----- 🛡️ 受保护方法（供子类职业系统扩展）------

  _calculateBaseDamage(attackPower) {
    return attackPower;
  }

  _getLevelBonus() {
    return this.#level * 5;
  }

  // ----- 🔒 私有辅助方法 -----

  #die() {
    this.#isAlive = false;
    this.#hp = 0;
    console.log(`💀 ${this.name} 倒下了！`);
  }

  #levelUp() {
    this.#experience -= this.#expToNextLevel;
    this.#level++;
    this.#expToNextLevel = Math.floor(this.#expToNextLevel * 1.5);
    this.#maxHp += 20;
    this.#maxMp += 10;
    this.#hp = this.#maxHp; // 升级回满血
    this.#mp = this.#maxMp;  // 升级回满蓝
    console.log(`🎉 ${this.name} 升级了！当前等级: ${this.#level}`);
  }

  #applyDamageModifiers(rawDamage) {
    let modified = rawDamage;

    // 检查是否有减伤 buff
    for (const buff of this.#buffs) {
      if (buff.type === 'damageReduction') {
        modified = Math.floor(modified * (1 - buff.value));
        console.log(`  🛡️ [${buff.name}] 减少 ${Math.round(buff.value * 100)}% 伤害`);
      }
    }

    return modified;
  }

  #processBuffs() {
    for (let i = this.#buffs.length - 1; i >= 0; i--) {
      this.#buffs[i].remainingTurns--;
      if (this.#buffs[i].remainingTurns <= 0) {
        console.log(`⏰ [${this.#buffs[i].name}] 效果消退`);
        this.#buffs.splice(i, 1);
      }
    }
  }

  #processDebuffs() {
    for (let i = this.#debuffs.length - 1; i >= 0; i--) {
      this.#debuffs[i].remainingTurns--;
      if (this.#debuffs[i].remainingTurns <= 0) {
        console.log(`✅ [${this.#debuffs[i].name}] 效果解除`);
        this.#debuffs.splice(i, 1);
      } else {
        // debuff 在回合结束时生效（比如中毒掉血）
        if (this.#debuffs[i].tickEffect && this.#isAlive) {
          const effect = this.#debuffs[i];
          if (effect.type === 'poison') {
            const poisonDamage = Math.floor(this.#maxHp * effect.value);
            this.#hp -= poisonDamage;
            console.log(`  ☠️ 中毒伤害: -${poisonDamage} HP (${this.#hp}/${this.#maxHp})`);
            if (this.#hp <= 0) this.#die();
          }
        }
      }
    }
  }
}

// ========== 子类：战士职业 ==========

class Warrior extends GameCharacter {
  #rage = 0;
  #maxRage = 100;

  constructor(name, maxHp, maxMp) {
    super(name, '战士', maxHp, maxMp);
  }

  _calculateBaseDamage(attackPower) {
    // 战士有怒气加成
    const rageBonus = Math.floor(this.#rage / 10);
    return super._calculateBaseDamage(attackPower) + rageBonus;
  }

  rageAttack(target, baseDamage) {
    if (!this.canAct) {
      console.log(`${this.name} 无法攻击！`);
      return;
    }

    const damage = this._calculateBaseDamage(baseDamage);
    target.takeDamage(damage, this.name);
    this.#rage = Math.min(this.#rage + 15, this.#maxRage);
    console.log(`  ⚔️ 怒气: ${this.#rage}/${this.#maxRage}`);
  }

  get warriorStatus() {
    return {
      ...super.status,
      rage: { current: this.#rage, max: this.#maxRage }
    };
  }
}

// ========== 游戏实际运行 ==========

const hero = new Warrior('亚瑟', 500, 100);
const monster = new GameCharacter('哥布林', 80, 20);

console.log(hero.warriorStatus);
// { name: '亚瑟', level: 1, hp: {current: 500, max: 500}, ..., rage: {current: 0, max: 100} }

// 战斗开始
hero.rageAttack(monster, 50);
// 亚瑟 对 哥布林 造成 50 点伤害！(剩余 HP: 30/80)
// ⚔️ 怒气: 15/100

monster.takeDamage(30, '环境陷阱');
// 环境陷阱 对 哥布林 造成 30 点伤害！(剩余 HP: 0/80)
// 💀 哥布林 倒下了！

// 亚瑟获得经验
hero.gainExperience(50);
// 亚瑟 获得 50 点经验值！(总计: 50/100)

// 使用 buff/debuff 系统
hero.addBuff({ name: '铁壁', type: 'damageReduction', value: 0.3, duration: 3 });
// ✨ 亚瑟 获得 [铁壁] 效果，持续 3 回合

hero.addDebuff({ name: '剧毒', type: 'poison', value: 0.05, tickEffect: true, duration: 5 });
// 💀 亚瑟 受到 [剧毒] 影响，持续 5 回合

hero.processTurnEffects();
// ⏰ [铁壁] 剩余 2 回合
// ☠️ 中毒伤害: -25 HP (475/500)

// 安全性 —— 所有核心数据都受到保护
hero.#hp = 999999;       // SyntaxError —— 不能作弊！
hero.#level = 99;        // SyntaxError —— 同上
hero.#experience = 9999; // SyntaxError —— 同上
```

这个游戏角色的例子展示了访问器和私有字段如何在一个具有复杂状态的系统中发挥作用：

- **战斗数值**（HP、MP、经验值）被彻底私有化，防止玩家或外部代码通过作弊手段修改游戏状态
- **Getter 提供了只读的状态视图**，UI 层可以安全地渲染角色面板而不必担心副作用
- **受保护方法**为子类（如 `Warrior`）提供了扩展点，让每种职业可以有自己的伤害计算公式
- **Buff/Debuff 系统**完全封装在内部，外界只需调用简单的 API（`addBuff`、`processTurnEffects`），不需要了解效果处理的复杂逻辑
