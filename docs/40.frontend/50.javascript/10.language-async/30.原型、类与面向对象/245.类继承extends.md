# 类继承：`extends` 关键字的行为 —— 从原型链到 super 的完整机制

## 为什么需要继承：站在巨人的肩膀上

在现实世界中，知识和技术是通过代际传承来积累的——每一代人不需要从零开始发明轮子，而是在前人的基础上改进和创新。编程世界中的继承（Inheritance）正是这种思维的直接映射。它让你能够定义一个"基础类"，封装通用的属性和行为，然后通过**继承**机制创建"子类"来复用这些能力，同时添加或修改自己特有的部分。

假设你正在开发一个游戏，里面有几十种不同的角色：战士、法师、弓箭手、盗贼、牧师……每种角色都有名字、等级、生命值这些基本属性，也都有移动、攻击、受伤这些通用行为。如果没有继承，你需要在每个角色的代码中重复编写这些相同或相似的逻辑。一旦你需要修改"受伤后判断是否死亡"的规则，就得修改几十个文件。而有了继承，你只需要在一个基类（比如 `GameCharacter`）中写一次通用逻辑，所有子类自动获得这份能力，后续的修改也只需要在一处完成。

JavaScript 的 `extends` 关键字就是实现这种继承关系的语法工具。它的底层仍然是基于原型的链式查找机制（这一点和 Java、C++ 等基于类的语言有本质区别），但 `extends` 提供了一种声明式的、清晰的方式来表达"这个类是那个类的扩展"。理解它的工作原理、规则边界以及那些容易踩坑的细节，是每一个想要写出高质量面向对象 JavaScript 代码的开发者的必修课。

## `extends` 的基本语法与底层原理

### 最简单的继承示例

让我们从一个最简单的例子开始：

```javascript
class Animal {
  constructor(name) {
    this.name = name;
  }

  eat() {
    console.log(`${this.name} 正在吃东西`);
  }

  sleep() {
    console.log(`${this.name} 正在睡觉`);
  }
}

// Dog 继承自 Animal
class Dog extends Animal {
  bark() {
    console.log(`${this.name}: 汪汪汪！`);
  }
}

const dog = new Dog('旺财');
dog.eat();   // 旺财 正在吃东西 —— 继承自 Animal
dog.sleep();// 旺财 正在睡觉 —— 继承自 Animal
dog.bark(); // 旺财: 汪汪汪！   —— Dog 自己的方法
```

这段代码做了什么？当你写下 `class Dog extends Animal` 时，引擎执行了几个关键操作：

1. 创建一个新的函数对象 `Dog`（这就是子类的构造器）
2. 将 `Dog.prototype` 的内部原型指针 `[[Prototype]]` 指向 `Animal.prototype`
3. 建立 `Dog` 和 `Animal` 之间的继承关系

这意味着当你在 `dog` 实例上调用 `eat()` 时，引擎的查找路径是这样的：

```
dog 实例自身 → Dog.prototype → Animal.prototype → Object.prototype → null
     没有          没有            找到了!           (不需要继续)
```

`eat` 方法定义在 `Animal.prototype` 上，但通过原型链，`Dog` 的实例也能找到并调用它。这就是继承的核心——**不是复制，而是链接**。

可以把继承关系想象成一个家族谱系。`Animal` 是祖先，他掌握着吃饭和睡觉这两项基本生存技能；`Dog` 是后代，他不仅天然继承了祖先生存技能，还学会了狗特有的吠叫技能。后代不需要重新学习怎么吃饭睡觉——这些本领刻在基因（原型链）里了。

### 验证原型链关系

我们可以用多种方式来验证上述继承关系确实按照预期建立了：

```javascript
class Animal { constructor(name) { this.name = name; } eat() {} }
class Dog extends Animal { bark() {} }

const dog = new Dog('旺财');

// 1. instanceof 检测
console.log(dog instanceof Dog);      // true  —— dog 是 Dog 的实例
console.log(dog instanceof Animal);   // true  —— dog 也是 Animal 的实例！（继承关系）
console.log(dog instanceof Object);   // true  —— 所有对象都是 Object 的实例

// 2. 原型链验证
console.log(Object.getPrototypeOf(dog) === Dog.prototype);              // true
console.log(Object.getPrototypeOf(Dog.prototype) === Animal.prototype);// true
console.log(Object.getPrototypeOf(Animal.prototype) === Object.prototype); // true

// 3. isPrototypeOf 方法
console.log(Dog.prototype.isPrototypeOf(dog));        // true
console.log(Animal.prototype.isPrototypeOf(dog));     // true
console.log(Animal.prototype.isPrototypeOf(Dog.prototype)); // true

// 4. 属性查找路径验证
console.log(dog.hasOwnProperty('name'));    // true  —— 自身属性
console.log(dog.hasOwnProperty('bark'));    // false —— 在 prototype 上
console.log(dog.hasOwnProperty('eat'));     // false —— 在 Animal.prototype 上
console.log('bark' in dog);                 // true  —— 通过 in 可以检测到（含原型链）
console.log('eat' in dog);                  // true  —— 同上
```

每一条验证都在确认同一个事实：`Dog` 的实例不仅能访问自己定义的东西，还能一路向上追溯到 `Animal` 甚至更远的祖先所拥有的全部公开成员。这种"可追溯性"是 JavaScript 动态类型系统的重要特征——你可以在运行时检查任意对象的"血统"，并根据结果采取不同的处理策略。

### `extends` 不限于类名：动态继承

`extends` 关键字后面不仅可以跟类名，还可以跟**任何表达式**，只要这个表达式的值是一个合法的构造器函数（或者 `null`）。这为动态创建继承关系提供了可能：

```javascript
function chooseBaseClass(environment) {
  if (environment === 'browser') {
    return class BrowserWidget {
      render() { console.log('渲染到 DOM'); }
      attachEvent() { console.log('绑定 DOM 事件'); }
    };
  } else if (environment === 'node') {
    return class CLIWidget {
      render() { console.log('渲染到终端'); }
      attachEvent() { console.log('绑定 process 事件'); }
    };
  } else {
    return class BaseWidget {
      render() { console.log('默认渲染'); }
      attachEvent() { console.log('默认事件'); }
    };
  }
}

// 根据运行环境动态选择父类
class Button extends chooseBaseClass(typeof window !== 'undefined' ? 'browser' : 'node') {
  constructor(label) {
    super();
    this.label = label;
  }

  click() {
    console.log(`按钮 "${this.label}" 被点击`);
  }
}

const btn = new Button('提交');
btn.render();    // 渲染到 DOM （或终端，取决于环境）
btn.click();     // 按钮 "提交" 被点击
btn.attachEvent();// 绑定 DOM 事件
```

这种模式在一些需要跨平台运行的库和框架中非常实用。核心的业务逻辑（按钮被点击时做什么）写在子类中不变，而平台相关的实现（如何渲染、如何绑定事件）根据运行环境选择不同的父类来提供。`extends` 接收表达式的能力让这种"运行时决策"成为可能。

另一个常见的用途是根据配置参数来选择不同的基类实现：

```javascript
class SmartInput extends (features.touchScreen ? TouchableInput : MouseInput) {
  // ...
}
```

### 继承自 null：创建真正干净的原型链

如果你不希望你的类继承自 `Object`（从而避免继承 `toString`、`valueOf` 等方法），可以用 `extends null`：

```javascript
class NullExtends extends null {
  constructor() {}
}

const obj = new NullExtends();
console.log(obj.toString);
// TypeError: obj.toString is not a function
// 因为原型链上没有 Object.prototype！

console.log(Object.getPrototypeOf(obj));
// null —— 原型链到此为止
```

这在某些特殊的元编程场景中有用——比如你需要一个完全没有任何预置方法的"纯净"对象。不过要注意，使用 `extends null` 的类必须在构造器中手动创建返回值（因为没有父类构造器帮你创建 `this`），否则会抛出错误。

## 方法重写（Override）：让子类有自己的声音

### 什么是方法重写

当一个子类定义了一个和父类同名的方法时，子类的方法会**覆盖（Override）**父类的方法。之后通过子类实例调用该方法时，执行的将是子类的版本：

```javascript
class Animal {
  speak() {
    console.log('动物发出声音');
  }
}

class Cat extends Animal {
  speak() {
    console.log('喵喵喵~');
  }
}

class Dog extends Animal {
  speak() {
    console.log('汪汪汪！');
  }
}

const animal = new Animal();
const cat = new Cat();
const dog = new Dog();

animal.speak(); // 动物发出声音
cat.speak();    // 喵喵喵~     ← 子类覆盖了父类
dog.speak();    // 汪汪汪！     ← 同理
```

重写的意义在于**特化**（Specialization）。父类的 `speak` 方法提供了一个通用的、抽象的实现（"动物发出声音"），但这只是一个占位符——每种具体的动物应该有自己的叫声方式。子类通过重写来实现这种"具体化"。这就像一本烹饪书的通用配方说"加入调味料"，而具体的菜谱会告诉你这道菜到底该加盐还是加糖。

### 用 `super` 扩展而非完全替换

大多数时候，我们不想**彻底抛弃**父类方法的逻辑，而是想在它的基础上增加一些额外的行为。这时就需要用 `super` 来调用父类的原始方法：

```javascript
class Vehicle {
  start() {
    console.log('引擎启动...');
    console.log('系统自检完成');
    this.status = 'running';
  }

  stop() {
    console.log('引擎熄火...');
    this.status = 'stopped';
  }
}

class ElectricCar extends Vehicle {
  #batteryLevel;

  constructor(batteryCapacity) {
    super();
    this.#batteryLevel = batteryCapacity;
  }

  start() {
    // 先执行父类的启动流程
    super.start();

    // 再加上电动车特有的启动步骤
    if (this.#batteryLevel < 10) {
      console.warn('⚠️ 电量过低，建议充电');
    }
    console.log('电机就绪 🌿');
    console.log(`当前电量: ${this.#batteryLevel}%`);
  }

  stop() {
    // 先执行电动车特有的停车操作
    console.log('再生制动系统激活... 回收能量');

    // 然后执行父类的停止流程
    super.stop();
    console.log('充电口已锁定 🔒');
  }
}

const car = new ElectricCar(85);
car.start();
// 引擎启动...
// 系统自检完成
// 电机就绪 🌿
// 当前电量: 85%

car.stop();
// 再生制动系统激活... 回收能量
// 引擎熄火...
// 充电口已锁定 🔒
```

注意 `super.start()` 出现的位置不同导致了执行顺序的差异：在子类 `start` 中先调用 `super.start()` 再做额外操作（**先父后子**）；在子类 `stop` 中先做额外操作再调用 `super.stop()`（**先子后父**）。这两种模式分别对应两种不同的业务需求：
- **先调 super**：父类的基础逻辑必须先执行完毕，子类才能在此基础上做增强
- **后调 super**：子类需要先做一些准备工作或善后工作，然后再触发父类的标准流程

### 多态（Polymorphism）：同一个接口，不同的行为

方法重写是实现**多态**的基础。多态意味着你可以用统一的方式处理不同类型的对象，每个对象会用自己特定的方式来响应：

```javascript
class Shape {
  area() {
    throw new Error('Shape.area() 必须被子类实现');
  }

  perimeter() {
    throw new Error('Shape.perimeter() 必须被子类实现');
  }

  describe() {
    console.log(
      `${this.constructor.name}: 面积=${this.area().toFixed(2)}, 周长=${this.perimeter().toFixed(2)}`
    );
  }
}

class Circle extends Shape {
  #radius;

  constructor(radius) {
    super();
    this.#radius = radius;
  }

  area() {
    return Math.PI * this.#radius ** 2;
  }

  perimeter() {
    return 2 * Math.PI * this.#radius;
  }
}

class Rectangle extends Shape {
  #width;
  #height;

  constructor(width, height) {
    super();
    this.#width = width;
    this.#height = height;
  }

  area() {
    return this.#width * this.#height;
  }

  perimeter() {
    return 2 * (this.#width + this.#height);
  }
}

class Triangle extends Shape {
  #a; #b; #c;

  constructor(a, b, c) {
    super();
    this.#a = a; this.#b = b; this.#c = c;
  }

  area() {
    const s = (this.#a + this.#b + this.#c) / 2;
    return Math.sqrt(s * (s - this.#a) * (s - this.#b) * (s - this.#c));
  }

  perimeter() {
    return this.#a + this.#b + this.#c;
  }
}

// 统一处理不同形状的多态函数
function processShapes(shapes) {
  for (const shape of shapes) {
    shape.describe(); // 每个形状用自己的方式计算面积和周长
  }

  // 计算总面积
  const totalArea = shapes.reduce((sum, s) => sum + s.area(), 0);
  console.log(`\n总占地面积: ${totalArea.toFixed(2)} 平方单位`);
}

const shapes = [
  new Circle(5),
  new Rectangle(4, 7),
  new Triangle(3, 4, 5)
];

processShapes(shapes);
// Circle: 面积=78.54, 周长=31.42
// Rectangle: 面积=28.00, 周长=22.00
// Triangle: 面积=6.00, 周长=12.00
//
// 总占地面积: 112.54 平方单位
```

注意看 `describe` 这个方法——它定义在父类 `Shape` 中，但它调用的 `area()` 和 `perimeter()` 却是多态的。当 `Circle` 的实例调用 `describe()` 时，内部的 `this.area()` 会调用 `Circle` 版本的 `area()`；当 `Rectangle` 的实例调用时，就会调用 `Rectangle` 的版本。这是因为在 JavaScript 中，方法调用始终基于 `this` 的实际指向（即运行时的对象类型），而不是定义时的类型。这种**动态分派**（Dynamic Dispatch）机制就是多态的核心。

可以把多态想象成一家餐厅的服务员。服务员对每位客人说的都是同一句话："请问您要点什么？"（这就是统一的接口/方法）。但客人们的回答各不相同——有人点牛排、有人点沙拉、有人点素食套餐（不同的子类有不同的实现）。服务员不需要知道客人是谁、会点什么，他只需要问同样的问题就行了。这就是多态带来的**解耦**好处：调用者（`processShapes` 函数）不需要知道数组中具体是什么形状，只要它们都有 `area()` 和 `describe()` 方法就能正常工作。

## 构造器重写：super() 的硬性规定

### 必须先调用 super() 才能使用 this

这是继承中最重要的一条规则，也是初学者最容易犯错的地方：**派生类（子类）的构造器在使用 `this` 之前必须调用 `super()`**。

```javascript
class Parent {
  constructor(name) {
    this.name = name;
  }
}

class Child extends Parent {
  constructor(name, age) {
    // 如果在这里直接使用 this 而没先调 super():
    // this.age = age;  // ❌ ReferenceError: Must call super() before accessing 'this'

    super(name);         // ✅ 先调用父类构造器
    this.age = age;      // ✅ 之后才能使用 this
  }

  introduce() {
    console.log(`我叫${this.name}，今年${this.age}岁`);
  }
}

const child = new Child('小明', 12);
child.introduce(); // 我叫小明，今年12岁
```

为什么会这样？这涉及到 `new` 操作符在处理普通类和派生类时的不同行为。

对于**普通类**（没有 `extends` 的类），当执行 `new ClassName()` 时，引擎会自动做以下事情：
1. 创建一个新的空对象
2. 把这个空对象的 `[[Prototype]]` 链接到 `ClassName.prototype`
3. 把这个空对象赋值给 `this`
4. 执行构造函数体
5. 如果构造器没有显式返回对象，则返回 `this`

但对于**派生类**（有 `extends` 的类），过程有所不同。派生类的构造器有一个特殊的内部标记 `[[ConstructorKind]]: "derived"`。当引擎检测到这个标记时，它在第 3 步**不会**自动创建新对象赋给 `this`——它期望由父类构造器来完成这项工作。所以如果你在调用 `super()` 之前尝试访问 `this`，就会发现 `this` 还没有被初始化，因此报出 `ReferenceError`。

可以把这个过程比作一家公司的入职流程。普通员工（普通类）入职时人事部门直接给他发一套工牌和办公设备——他自己就是一切的中心。但实习生（派生类）不一样——他的工牌和设备需要由他的指导老师（父类构造器）去申请和分配。如果实习生还没去找导师就要用电脑（访问 `this`），那肯定不行，因为电脑还没配下来呢。

### super() 会传递参数给父类构造器

`super()` 不仅仅是触发父类构造器的执行——你还可以向它传递参数，就像调用一个普通函数一样：

```javascript
class Character {
  #name;
  #hp;
  #maxHp;

  constructor(name, maxHp) {
    this.#name = name;
    this.#maxHp = maxHp;
    this.#hp = maxHp;
  }

  get name() { return this.#name; }
  get hp() { return this.#hp; }
  get maxHp() { return this.#maxHp; }
}

class Warrior extends Character {
  #strength;
  #weapon;

  constructor(name, hp, strength, weapon) {
    super(name, hp);  // 把 name 和 hp 传给父类 Character 处理
    this.#strength = strength;
    this.#weapon = weapon;
  }

  attack(target) {
    const damage = this.#strength * 1.5;
    console.log(
      `${this.name} 用 ${this.#weapon} 攻击 ${target.name}，造成 ${damage.toFixed(0)} 点伤害！`
    );
    return damage;
  }
}

class Mage extends Character {
  #intelligence;
  #element;

  constructor(name, hp, intelligence, element) {
    super(name, hp);  // 同样传给父类
    this.#intelligence = intelligence;
    this.#element = element;
  }

  castSpell(target) {
    const damage = this.#intelligence * 2.0;
    console.log(
      `${this.name} 释放 ${this.element} 魔法攻击 ${target.name}，造成 ${damage.toFixed(0)} 点魔法伤害！💫`
    );
    return damage;
  }
}

const warrior = new Warrior('亚瑟', 500, 80, '大剑');
const mage = new Mage('梅林', 300, 100, '火焰');

warrior.attack(mage);
// 亚瑟 用 大剑 攻击 梅林，造成 120 点伤害！

mage.castSpell(warrior);
// 梅林 释放 火焰 魔法攻击 亚瑟，造成 200 点魔法伤害！💫
```

在这个例子中，`Character` 父类负责管理所有角色共有的属性（姓名、生命值），而 `Warrior` 和 `Mage` 各自管理自己特有的属性（力量/武器 vs 智力/元素）。通过 `super(name, hp)` 把通用数据的初始化委托给父类，子类只需关注自己的特殊数据。这是一种清晰的**职责分离**。

### 如果子类没有定义构造器呢？

如果一个子类没有显式定义 `constructor`，引擎会自动为其生成一个：

```javascript
class Parent {
  constructor(x) {
    this.x = x;
  }
}

class ChildA extends Parent {
  // 没有定义 constructor
  // 引擎自动生成:
  // constructor(...args) { super(...args); }
}

const childA = new ChildA(42);
console.log(childA.x); // 42 —— 自动传递了参数
```

自动生成的构造器做的事情很简单：把收到的所有参数原封不动地用展开运算符传给 `super()`。这意味着如果你的父类构造器需要特定位置的参数，那么创建子类实例时也要按同样的顺序传入。

## 字段重写的陷阱：初始化顺序的隐形杀手

### 一个反直觉的现象

这是整个类继承体系中最微妙、最容易引发 bug、也最值得深入理解的部分。请仔细阅读下面的例子：

```javascript
class Animal {
  species = '动物';  // 父类字段

  constructor() {
    // 注意：构造器在字段初始化之后才执行
    console.log(`[构造器] this.species = ${this.species}`);
  }
}

class Rabbit extends Animal {
  species = '兔子'; // 子类重写了字段

  constructor() {
    super();  // 这里会触发父类构造器的执行
    console.log(`[Rabbit构造器] this.species = ${this.species}`);
  }
}

const rabbit = new Rabbit();
```

你觉得输出会是什么？直觉上可能会认为 `[构造器] this.species = 兔子`，因为 `Rabbit` 重写了 `species` 字段。但实际上输出的是：

```
[构造器] this.species = 动物    ← 不是 "兔子"！
[Rabbit构造器] this.species = 兔子
```

为什么？问题的根源在于**类字段的初始化顺序**。完整的执行顺序如下：

```
1. Animal 的字段初始化: this.species = '动物'
2. Animal 的 constructor 执行: 打印 this.species → '动物'
3. Rabbit 的字段初始化: this.species = '兔子'（覆盖了父类的值）
4. Rabbit 的 constructor 执行: 打印 this.species → '兔子'
```

关键点是：**父类的构造器执行时，子类的字段还没有被初始化**。所以父类构造器读到的 `species` 还是父类自己设置的 `'动物'`，而不是子类将要设置的 `'兔子'`。

这个顺序可以概括为一句话：**基类字段 → 基类构造器 → 派生类字段 → 派生类构造器**。无论你在代码中书写的位置在哪里，这个顺序都不会变。

### 为什么这样设计？

这个设计是有意为之的，目的是保证父类构造器执行时看到的是一个"完整且一致的"父类状态。如果子类的字段先于父类构造器初始化，那么父类构造器看到的 `this` 就已经被子类"污染"了——父类的某些假设可能会被打破，导致不可预测的行为。

打个比方：父亲在建房子（执行构造器）之前，先把地基打好、框架搭好（字段初始化）；儿子要在父亲的基础上装修（子类字段初始化），但不能在父亲还没建好房子的时候就去刷墙——那时候墙还不存在呢。所以必须等父亲建完了，儿子才能开始自己的工序。

### 方法重写不会遇到这个问题

有趣的是，**方法的重写不受这个初始化顺序的影响**。如果在父类构造器中调用了一个被子类重写的方法，执行的是子类的版本：

```javascript
class Base {
  name = 'Base';

  constructor() {
    this.showName(); // 多态调用！
  }

  showName() {
    console.log(`Base: ${this.name}`);
  }
}

class Derived extends Base {
  name = 'Derived';

  showName() {
    console.log(`Derived: ${this.name}`);
  }
}

const obj = new Derived();
// 输出: Derived: Base
// showName() 是子类的版本 ✅
// 但此时 name 还是 'Base'（子类字段尚未初始化）✅
```

这里发生了两件事：
1. `showName()` 调用的是 `Derived` 的版本（因为方法是存在于原型上的，原型链在对象创建时就建立好了）
2. 但 `this.name` 读到的值是 `'Base'`（因为 `Derived` 的字段 `name` 还没来得及被赋值为 `'Derived'`）

这种"方法已经重写了但字段还没更新"的状态被称为**半熟状态**（Half-initialized State）。它是字段重写陷阱的本质——你的对象处于一个"既不完全像父类、也不完全像子类"的中间阶段。

### 如何规避字段重写陷阱

在实际开发中，有几种策略可以避开这个陷阱：

**策略一：不在父类构造器中读取可能被子类重写的字段**

```javascript
class SafeAnimal {
  constructor(initialSpecies) {
    // 通过参数接收初始值，而不是读取字段
    this._internalSpecies = initialSpecies;
    console.log(`创建了 ${this._internalSpecies}`);
  }
}

class SafeRabbit extends SafeAnimal {
  species = '兔子';

  constructor() {
    super(this.species);  // 显式传入期望的值
  }
}
```

**策略二：使用方法 + getter 替代直接字段访问**

```javascript
class UsingGetter {
  _defaultSpecies = '动物';

  // 使用 getter 提供可被子类覆盖的"虚属性"
  get species() {
    return this._defaultSpecies;
  }

  constructor() {
    // getter 是多态的，但如果子类也用 getter 重写的话，
    // 要确保 getter 内部不依赖尚未初始化的字段
    console.log(`物种: ${this.species}`);
  }
}
```

**策略三：使用初始化回调模式**

```javascript
class WithCallback {
  species = '动物';

  constructor() {
    // 父类只做最基本的初始化
  }

  // 子类可以在完全初始化后调用此方法
  onInitialized() {
    console.log(`完全初始化完成, species=${this.species}`);
  }
}

class CallbackChild extends WithCallback {
  species = '小狗';

  constructor() {
    super();
    // 此时所有字段都已初始化完毕
    this.onInitialized();
  }
}
```

最推荐的实践原则是：**尽量让父类构造器保持简单和独立**，不要在其中依赖那些可能被子类覆盖的字段。如果确实需要某种"钩子"让子类参与初始化过程，应该使用方法（利用多态特性）而不是字段。

## 深入引擎内部：[[HomeObject]] 与 super 的工作机制

### super 到底是怎么找到父类方法的？

前面我们一直在用 `super.methodName()` 来调用父类的方法，但你有没有想过：**引擎是怎么知道"父类的方法在哪里的"？**

一种直观的想法可能是：`super` 就是沿着原型链往上找。类似于 `Object.getPrototypeOf(CurrentClass.prototype).methodName.call(this)`。但这种简单方案有一个致命的问题——在多层继承时会出错：

```javascript
class A {
  sayHi() { console.log('来自 A'); }
}

class B extends A {
  sayHi() {
    console.log('来自 B, 准备调用上层...');
    super.sayHi();
  }
}

class C extends B {
  sayHi() {
    console.log('来自 C, 准备调用上层...');
    super.sayHi();
  }
}

const obj = new C();
obj.sayHi();
// 来自 C, 准备调用上层...
// 来自 B, 准备调用上层...
// 来自 A  ← 正确！C→B→A，逐层向上
```

如果用"当前对象的原型的原型"这种思路，在 C 的 `sayHi` 中，`this` 指向 C 的实例，`this.__proto__` 是 C.prototype，再往上是 B.prototype——没错，找到了 B.sayHi。但当 B.sayHi 执行时，如果它也用同样的"当前对象的原型"来找上一级，它会再次找到 B.prototype（因为 `this` 没变，还是 C 的实例），这就陷入了死循环。

为了解决这个问题，JavaScript 引擎引入了**`[[HomeObject]]`** 这个内部机制。

### [[HomeObject]] 的定义和行为

当一个函数以**方法简写语法**的形式被定义在类或对象字面量中时，引擎会给这个函数添加一个内部属性 `[[HomeObject]]`，其值为**该方法定义所在的对象**：

```javascript
class Parent {
  // 这个方法的 [[HomeObject]] 是 Parent.prototype
  parentMethod() {
    // super.parentMethod() 会去 [[HomeObject]].[[Prototype]] 上找
    // 即 Parent.prototype.[[Prototype]]
    // 即 GrandParent.prototype
  }
}

class Child extends Parent {
  // 这个方法的 [[HomeObject]] 是 Child.prototype
  childMethod() {
    // super.childMethod() 会去 Child.prototype.[[Prototype]] 上找
    // 即 Parent.prototype
  }
}
```

`[[HomeObject]]` 是在**定义时就固定下来**的，而不是在调用时确定的。这意味着不管这个方法后来被怎么转移、赋值、传递，它的 `[[HomeObject]]` 都不会改变——它永远记得自己"出生的地方"。

当你在方法内写 `super.xxx()` 时，引擎的实际查找过程是：
1. 取得当前方法的 `[[HomeObject]]`（比如 `Child.prototype`）
2. 取得 `[[HomeObject]]` 的 `[[Prototype]]`（即 `Parent.prototype`）
3. 在这个原型对象上寻找名为 `xxx` 的方法
4. 找到后以当前 `this` 为上下文调用它

正是因为每层方法的 `[[HomeObject]]` 不同（C 的方法记住的是 C.prototype，B 的方法记住的是 B.prototype），多层继承才能正确地逐级向上查找。

### [[HomeObject]] 带来的限制：方法不能随意复制

`[[HomeObject]]` 的静态绑定特性意味着带有 `super` 的方法**不是自由方法**（Free Method）——你不能安全地把它从一个对象复制到另一个对象上使用：

```javascript
class Animal {
  #name;

  constructor(name) {
    this.#name = name;
  }

  // 这个方法的 [[HomeObject]] 是 Animal.prototype
  identify() {
    return `我是 ${super.constructor?.name ?? '未知'} 类的 ${this.#name}`;
    // super.constructor 会沿着 Animal.prototype 往上找
    // 最终找到 Function.prototype.constructor → Function
  }
}

class Plant extends Animal {
  #species;

  constructor(name, species) {
    super(name);
    this.#species = species;
  }

  identify() {
    return `这是一株 ${this.#species}`;
  }
}

class Robot extends Animal {
  #serialNumber;

  constructor(name, serialNumber) {
    super(name);
    this.#serialNumber = serialNumber;
  }
}

const cat = new Animal('猫咪');
const flower = new Plant('玫瑰', '蔷薇科');
const bot = new Robot('瓦力', 'A113');

// 直接调用都正常
console.log(cat.identify());    // 我是 Function 类的 猫咪
console.log(flower.identify()); // 这是一株 玫瑰
console.log(bot.identify());   // 我是 Function 类的 瓦力

// 危险操作：把 Animal 的方法复制给其他对象
const weirdObj = {
  name: '奇怪的东西',
  identify: Animal.prototype.identify  // [[HomeObject]] 仍然是 Animal.prototype
};

console.log(weirdObj.identify());
// 不会报错，但 super 的查找路径是基于 Animal.prototype 的
// 可能产生不符合预期的行为
```

当 `Animal.prototype.identify` 被复制到 `weirdObj` 上时，它的 `[[HomeObject]]` 依然指向 `Animal.prototype`。所以在 `weirdObj.identify()` 内部，`super.xxx()` 的查找仍然从 `Animal.prototype` 的原型开始，而不是从 `weirdObj` 的原型开始。这在大多数情况下会导致令人困惑的行为。

### 只有方法简写语法才有 [[HomeObject]]

这是一个重要的限制：只有使用 `methodName() {}` 这种简写语法定义的方法才会拥有 `[[HomeObject]]`。如果你用传统的函数表达式形式定义方法，是无法在其中使用 `super` 的：

```javascript
class WorksFine {
  method() {
    // ✅ 有 [[HomeObject]]，可以使用 super
    return 'ok';
  }
}

class SyntaxErrorCase {
  // 这样定义的方法没有 [[HomeObject]]
  brokenMethod = function () {
    // super.anything(); // ❌ SyntaxError: 'super' keyword unexpected here
  };

  // 属性形式的箭头函数也没有
  alsoBroken = () => {
    // super.anything(); // ❌ 同样的错误
  };
}
```

这是因为 `[[HomeObject]]` 的设置是方法简写语法特有的编译期行为。当你写 `method() {}` 时，引擎知道"这是一个属于当前对象的方法"，于是给它打上 `[[HomeObject]]` 的标签。而 `method = function(){}` 只是一个普通的赋值语句——引擎把它看作"给一个属性赋一个函数值"，不做任何特殊处理。

### 箭头函数中的 super

箭头函数本身没有 `this`，也没有自己的 `super`。如果在箭头函数中使用 `super`，它会从外层的普通函数那里借用 `super` 的值：

```javascript
class Timer {
  start() {
    // 普通函数：有自己的 super
    console.log(super.constructor); // [Function: Object] 或父类构造器

    // 箭头函数：借用了外层的 super
    const check = () => {
      console.log(super.constructor); // 和外层的 super 相同 ✅
    };
    check();
  }
}
```

这个特性使得箭头函数在异步回调中使用 `super` 时特别方便——不需要担心 `super` 丢失的问题（不像 `this` 会在普通回调中丢失）：

```javascript
class NetworkFetcher {
  async fetchData(url) {
    try {
      const response = await fetch(url);

      // setTimeout 的回调如果是普通函数，super 可能有问题
      // 但箭头函数可以安全地使用 super
      setTimeout(() => {
        super.processData(response); // ✅ super 正确绑定
      }, 1000);

    } catch (error) {
      super.handleError(error); // ✅
    }
  }

  processData(data) { /* ... */ }
  handleError(err) { console.error(err); }
}

class CachedFetcher extends NetworkFetcher {
  #cache = new Map();

  processData(data) {
    this.#cache.set(Date.now(), data);
    console.log(`数据已缓存，条目数: ${this.#cache.size}`);
    super.processData(data); // 调用父类的处理逻辑
  }

  handleError(error) {
    console.warn('缓存请求出错:', error.message);
    super.handleError(error); // 调用父类的错误处理
  }
}
```

## 实战案例：构建一个完整的 UI 组件继承体系

让我们用一个接近真实项目的案例来综合运用上面学到的所有知识——一个支持主题切换、事件代理、生命周期管理的 UI 组件基类及其子类体系：

```javascript
// ========== 基础组件类 ==========
class Widget {
  // 私有字段
  #element;
  #eventListeners = [];
  #isMounted = false;
  #lifecycleHooks = { beforeMount: [], mounted: [], beforeDestroy: [], destroyed: [] };

  // 受保护配置（允许子类自定义）
  _defaultOptions = {};
  _tagName = 'div';

  constructor(container, options = {}) {
    this.options = { ...this._defaultOptions, ...options };
    this.container = container;
    this.#createElement();
    this.#setupLifecycleProxy();
  }

  // ----- 生命周期 -----

  on(hook, callback) {
    if (Array.isArray(this.#lifecycleHooks[hook])) {
      this.#lifecycleHooks[hook].push(callback);
    }
    return this; // 链式调用
  }

  #runLifecycle(hook) {
    const callbacks = this.#lifecycleHooks[hook] || [];
    callbacks.forEach(cb => cb.call(this));
  }

  #setupLifecycleProxy() {
    // 用 Proxy 拦截挂载/销毁操作，自动触发生命周期钩子
    return new Proxy(this, {
      set: (target, prop, value) => {
        if (prop === '#isMounted') {
          if (value && !target.#isMounted) target.#runLifecycle('beforeMount');
          Reflect.set(target, prop, value);
          if (value && !target.#isMounted) target.#runLifecycle('mounted');
          return true;
        }
        return Reflect.set(target, prop, value);
      }
    });
  }

  mount() {
    if (this.#isMounted) {
      console.warn('组件已挂载');
      return this;
    }
    this.#runLifecycle('beforeMount');
    this.container.appendChild(this.#element);
    this.#isMounted = true;
    this.#runLifecycle('mounted');
    return this;
  }

  destroy() {
    if (!this.#isMounted) return this;
    this.#runLifecycle('beforeDestroy');
    this.#removeAllListeners();
    this.#element.remove();
    this.#isMounted = false;
    this.#runLifecycle('destroyed');
    return this;
  }

  // ----- DOM 操作 -----

  #createElement() {
    this.#element = document.createElement(this._tagName);
    this.#element.className = `widget widget-${this.constructor.name.toLowerCase()}`;

    // 应用选项
    if (this.options.id) this.#element.id = this.options.id;
    if (this.options.className) {
      this.#element.classList.add(...this.options.className.split(' '));
    }
    if (this.options.style) {
      Object.assign(this.#element.style, this.options.style);
    }
  }

  get element() {
    return this.#element;
  }

  // ----- 事件系统 -----

  onEvent(eventType, selector, handler) {
    const wrappedHandler = (e) => {
      const target = e.target.closest(selector);
      if (target && this.#element.contains(target)) {
        handler.call(this, e, target);
      }
    };
    this.#eventListeners.push({ eventType, wrappedHandler });
    this.#element.addEventListener(eventType, wrappedHandler);
    return this;
  }

  #removeAllListeners() {
    this.#eventListeners.forEach(({ eventType, wrappedHandler }) => {
      this.#element.removeEventListener(eventType, wrappedHandler);
    });
    this.#eventListeners = [];
  }

  // ----- 工具方法 -----

  emit(customEventName, detail = {}) {
    this.#element.dispatchEvent(
      new CustomEvent(customEventName, {
        bubbles: true,
        detail: { source: this, ...detail }
      })
    );
  }

  querySelector(selector) {
    return this.#element.querySelector(selector);
  }

  querySelectorAll(selector) {
    return this.#element.querySelectorAll(selector);
  }
}

// ========== 子类：按钮组件 ==========
class ButtonWidget extends Widget {
  _tagName = 'button';
  _defaultOptions = {
    label: 'Button',
    variant: 'primary', // primary, secondary, danger, ghost
    size: 'medium',     // small, medium, large
    disabled: false,
    icon: null
  };

  #clickCount = 0;

  mount() {
    super.mount(); // 先执行父类的挂载逻辑
    this.#render();
    this.#bindEvents();
    return this;
  }

  #render() {
    const el = this.element;
    el.textContent = '';

    if (this.options.icon) {
      const iconSpan = document.createElement('span');
      iconSpan.className = `icon icon-${this.options.icon}`;
      iconSpan.innerHTML = this.#getIconSvg(this.options.icon);
      el.appendChild(iconSpan);
    }

    const labelSpan = document.createElement('span');
    labelSpan.className = 'btn-label';
    labelSpan.textContent = this.options.label;
    el.appendChild(labelSpan);

    // 应用变体样式
    el.classList.add(`btn-${this.options.variant}`, `btn-${this.options.size}`);
    if (this.options.disabled) {
      el.disabled = true;
      el.classList.add('btn-disabled');
    }
  }

  #getIconSvg iconName {
    const icons = {
      search: '<svg>...</svg>',
      plus: '<svg>...</svg>',
      trash: '<svg>...</svg>'
    };
    return icons[iconName] || '';
  }

  #bindEvents() {
    this.element.addEventListener('click', (e) => {
      if (this.options.disabled) return;
      this.#clickCount++;

      this.emit('button:click', {
        count: this.#clickCount,
        label: this.options.label
      });

      console.log(
        `"${this.options.label}" 被点击了第 ${this.#clickCount} 次`
      );
    });
  }

  get clickCount() {
    return this.#clickCount;
  }

  disable() {
    this.options.disabled = true;
    this.element.disabled = true;
    this.element.classList.add('btn-disabled');
    return this;
  }

  enable() {
    this.options.disabled = false;
    this.element.disabled = false;
    this.element.classList.remove('btn-disabled');
    return this;
  }
}

// ========== 子类：输入框组件 ==========
class InputWidget extends Widget {
  _tagName = 'div';
  _defaultOptions = {
    placeholder: '请输入...',
    type: 'text',
    maxlength: undefined,
    validation: null, // 正则表达式或校验函数
    required: false
  };

  #value = '';
  #touched = false;
  #valid = true;
  #errorMessage = '';

  mount() {
    super.mount();
    this.#render();
    this.#bindEvents();
    return this;
  }

  #render() {
    const wrapper = this.element;
    wrapper.innerHTML = `
      <div class="input-wrapper">
        <input
          type="${this.options.type}"
          placeholder="${this.options.placeholder}"
          ${this.options.maxlength ? `maxlength="${this.options.maxlength}"` : ''}
          ${this.options.required ? 'required' : ''}
        />
        <span class="input-error-msg"></span>
      </div>
    `;
  }

  #bindEvents() {
    const input = this.querySelector('input');
    const errorMsg = this.querySelector('.input-error-msg');

    input.addEventListener('input', (e) => {
      this.#value = e.target.value;
      this.emit('input:change', { value: this.#value });

      if (this.#touched) {
        this.#validate();
      }
    });

    input.addEventListener('blur', () => {
      this.#touched = true;
      this.#validate();
    });

    input.addEventListener('focus', () => {
      this.emit('input:focus');
    });
  }

  #validate() {
    if (!this.options.validation) {
      this.#valid = true;
      this.#errorMessage = '';
      this.#updateUI();
      return true;
    }

    const rule = this.options.validation;
    let isValid;

    if (rule instanceof RegExp) {
      isValid = rule.test(this.#value);
    } else if (typeof rule === 'function') {
      isValid = rule(this.#value);
    } else {
      isValid = true;
    }

    this.#valid = isValid;
    this.#errorMessage = isValid ? '' : '输入格式不正确';
    this.#updateUI();

    this.emit('input:validate', {
      valid: this.#valid,
      value: this.#value,
      message: this.#errorMessage
    });

    return isValid;
  }

  #updateUI() {
    const wrapper = this.querySelector('.input-wrapper');
    const errorMsg = this.querySelector('.input-error-msg');

    if (this.#valid) {
      wrapper.classList.remove('input-invalid');
      wrapper.classList.add('input-valid');
      errorMsg.textContent = '';
    } else {
      wrapper.classList.remove('input-valid');
      wrapper.classList.add('input-invalid');
      errorMsg.textContent = this.#errorMessage;
    }
  }

  get value() {
    return this.#value;
  }

  set value(newValue) {
    this.#value = newValue;
    const input = this.querySelector('input');
    if (input) input.value = newValue;
    this.#validate();
  }

  get valid() {
    return this.#valid;
  }

  reset() {
    this.#value = '';
    this.#touched = false;
    this.#valid = true;
    this.#errorMessage = '';
    const input = this.querySelector('input');
    if (input) input.value = '';
    this.#updateUI();
  }
}

// ========== 孙子类：带图标的搜索输入框 ==========
class SearchInputWidget extends InputWidget {
  _defaultOptions = {
    ...super._defaultOptions || {}, // 获取父类的默认选项（注意字段重写陷阱）
    placeholder: '搜索...',
    debounceMs: 300
  };

  #debounceTimer = null;

  mount() {
    super.mount(); // 先挂载 InputWidget
    this.#addSearchIcon();
    this.#addClearButton();
    return this;
  }

  #addSearchIcon() {
    const wrapper = this.querySelector('.input-wrapper');
    const icon = document.createElement('span');
    icon.className = 'search-icon';
    icon.innerHTML = '🔍';
    wrapper.insertBefore(icon, wrapper.firstChild);
  }

  #addClearButton() {
    const wrapper = this.querySelector('.input-wrapper');
    const clearBtn = document.createElement('button');
    clearBtn.className = 'clear-btn';
    clearBtn.type = 'button';
    clearBtn.textContent = '✕';
    clearBtn.style.display = 'none';

    clearBtn.addEventListener('click', () => {
      this.value = ''; // 使用 setter 触发校验
      this.querySelector('input').focus();
      this.emit('search:cleared');
    });

    wrapper.appendChild(clearBtn);

    // 监听输入变化来控制清除按钮显示
    this.on('input:change', ({ value }) => {
      clearBtn.style.display = value.length > 0 ? 'block' : 'none';
    });
  }

  #bindEvents() {
    // 重写事件绑定：添加防抖功能
    const input = this.querySelector('input');

    input.addEventListener('input', (e) => {
      clearTimeout(this.#debounceTimer);
      this.#debounceTimer = setTimeout(() => {
        // 手动触发父类的输入处理（模拟）
        this.#value = e.target.value;
        this.emit('input:change', { value: this.#value });

        if (this.#value.length > 0) {
          this.emit('search:query', { query: this.#value });
        }
      }, this.options.debounceMs);
    });
  }
}
```

这个完整案例展示了类继承在实际项目中的应用方式：

- **`Widget` 基类**封装了所有 UI 组件共有的能力：DOM 元素创建、挂载/卸载的生命周期管理、事件委托系统、自定义事件发射
- **`ButtonWidget`** 继承了所有基础设施，专注于按钮特有的逻辑：图标渲染、点击计数、禁用/启用状态
- **`InputWidget`** 继承了基类，专注于输入框的逻辑：值的双向绑定、校验系统、错误提示
- **`SearchInputWidget`** 作为 `InputWidget` 的子类，进一步添加了搜索图标、防抖查询、清除按钮等功能

每一层都通过 `super` 调用父类的能力，同时添加自己独特的功能。这就是继承的价值所在——**复用而不重复，扩展而不破坏**。

## 继承的设计原则与最佳实践

### 组合优于继承（Composition over Inheritance）

虽然本文的主题是继承，但在实际工程中，有一个重要的设计原则值得牢记：**组合往往比继承更灵活**。继承表达的是"是一种"（is-a）关系，组合表达的是"有一个"（has-a）关系。当你的需求更倾向于后者时，组合通常是更好的选择：

```javascript
// ====== 继承方式（有时过于僵化）======
class FlyingCar extends Car {
  fly() { /* ... */ }
}
// 问题：FlyingCar 真的 "是一辆" Car 吗？它还需要飞机的能力...

// ====== 组合方式（更加灵活）======
class VehicleWithFlight {
  constructor(vehicle, flightSystem) {
    this.vehicle = vehicle;      // has-a: 拥有一辆车
    this.flightSystem = flightSystem; // has-a: 拥有飞行系统
  }

  drive() { return this.vehicle.drive(); }
  fly() { return this.flightSystem.fly(); }
}

const myVehicle = new VehicleWithFlight(
  new SportsCar(),
  new JetPropulsion()
);
```

组合的优势在于：你可以在运行时动态更换组件（换一个飞行系统、换一辆车底座），而不需要创建新的子类。继承层次过深会导致"脆弱基类问题"——对父类的任何修改都可能意外影响到所有后代。

### 里氏替换原则（Liskov Substitution Principle）

这是面向对象设计的五大原则（SOLID）之一，核心思想是：**子类必须能够替换其父类出现在任何地方，而不破坏程序的正确性**。

```javascript
// 符合 LSP 的设计
class Bird {
  fly() { console.log('飞行中...'); }
}

class Sparrow extends Bird {
  fly() { console.log('麻雀扑腾翅膀飞'); }
}

// 任何期待 Bird 对象的地方都可以用 Sparrow 代替
function makeBirdFly(bird) {
  bird.fly(); // 不管传入 Bird 还是 Sparrow 都能正常工作
}

makeBirdFly(new Bird());     // 飞行中...
makeBirdFly(new Sparrow());  // 麻雀扑腾翅膀飞 ✅

// 违反 LSP 的设计（经典反面教材）
class Penguin extends Bird {
  fly() { throw new Error('企鹅不会飞！'); }
}

makeBirdFly(new Penguin()); // 💥 运行时报错！违反了 LSP
```

如果企鹅（Penguin）继承了鸟（Bird）但又不能飞，那说明这里的继承关系本身就是错误的。正确的做法要么是让 `Bird` 不假设所有鸟都会飞（把 `fly` 变成可选行为），要么是不让企鹅继承鸟类，而是让它和其他有共同特征的类共享一个更抽象的祖先（比如 `Animal`）。

### 保持继承层次的浅平

继承层次越深，代码的理解和维护成本越高。作为经验法则，**尽量将继承深度控制在 3 层以内**：

```
✅ 好的设计（浅继承）:
  Widget → ButtonWidget → IconButtonWidget
  (3层)

⚠️ 需要警惕的设计（中等深度）:
  Widget → FormWidget → InputWidget → TextInputWidget → SearchInputWidget → AutoCompleteInputWidget
  (6层)

❌ 应该避免的设计（过深的继承）:
  Widget → ... (8层以上)
```

当继承层级过深时，通常意味着你应该引入组合、混入（Mixin）或其他架构模式来降低耦合度。
