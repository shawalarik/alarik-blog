## 引言：`instanceof`——你真的了解它吗？

在 JavaScript 的日常开发中，`instanceof` 是一个出现频率极高的运算符。我们用它来检查一个对象是否是某个构造函数的实例：

```javascript
const arr = [];
console.log(arr instanceof Array); // true
console.log(arr instanceof Object); // true
```

这段代码看起来简单明了：`arr` 是 `Array` 的实例，同时也是 `Object` 的实例。但你有没有想过：

- 为什么**同一个对象**可以同时是两个不同类的实例？这难道不矛盾吗？
- `instanceof` 内部到底是怎么判断的？它检查的是对象的什么属性？
- 如果我创建了一个"假数组"，让它的原型指向 `Array.prototype`，`instanceof` 会被骗过吗？
- 能不能自定义 `instanceof` 的行为，让它按照我的规则来判断？

这些问题的答案，隐藏在 `instanceof` 运算符的内部机制中。本文将从最基本的概念出发，逐步深入到引擎层面的实现细节，最终掌握如何通过 `Symbol.hasInstance` 完全控制类型检测的行为。

## `instanceof` 的基本用法

### 语法形式

`instanceof` 运算符的基本语法是：

```javascript
object instanceof Constructor
```

- **左操作数**（`object`）：要检测的对象（或任何值）
- **右操作数**（`Constructor`）：一个构造函数（更准确地说，是一个必须有 `[Symbol.hasInstance]` 方法的对象）

返回值是布尔值：`true` 表示左操作数是右操作数的实例，`false` 表示不是。

### 常见使用场景

**1. 类型守卫（Type Guard）**

```javascript
function process(data) {
  if (data instanceof Error) {
    console.error('出错了:', data.message);
  } else {
    console.log('处理数据:', data);
  }
}
```

这是 `instanceof` 最常见的用途——在运行时确定值的类型，然后采取不同的处理逻辑。就像医院分诊台的护士，先看你是感冒还是骨折，再决定把你分到哪个科室。

**2. 区分类层次结构中的不同层级**

```javascript
class Animal { /* ... */ }
class Dog extends Animal { /* ... */ }

const dog = new Dog();
console.log(dog instanceof Dog);    // true  —— 它是一只狗
console.log(dog instanceof Animal); // true  —— 它也是一只动物
```

这里体现了继承的核心思想：子类实例同时也是父类实例。"狗"既是"狗类"的成员，也是"动物类"的成员——就像你既是你公司的员工，也是你家庭的成员，这两个身份并不冲突。

**3. 处理跨框架/跨域对象**

```javascript
// iframe 中的 Array 与主窗口的 Array 不同
const iframeArray = iframe.contentWindow.Array;
const arr = new iframeArray(1, 2, 3);

console.log(arr instanceof Array);           // false！
console.log(arr instanceof iframeArray);     // true
```

这是一个经典的坑点：每个 JavaScript 全局环境都有自己独立的内置构造函数。iframe 中创建的数组，用主窗口的 `Array` 去检测，会返回 `false`。原因稍后详解。

### 左操作数不是对象时的情况

当 `instanceof` 的左操作数不是一个对象（而是原始值）时，`instanceof` **总是返回 `false`**：

```javascript
console.log(42 instanceof Number);     // false
console.log('hello' instanceof String); // false
console.log(true instanceof Boolean);   // false
console.log(Symbol() instanceof Symbol); // false
```

即使原始值通过包装对象转换后可能是某个类的实例，`instanceof` 也**不会**自动做这个转换：

```javascript
// 即使这样也不行
console.log(Object(42) instanceof Number); // true —— 这是包装后的对象
console.log(42 instanceof Number);          // false —— 原始值直接 false
```

这个行为的原因很简单：原始值没有原型链，而 `instanceof` 的核心机制就是沿着原型链查找。没有链可查，自然就是 `false`。

> **通俗理解**：想象你在查一个人的家谱。如果这个人根本不存在于任何家族记录里（原始值没有原型链），那无论你怎么查，都找不到他和目标家族的关系。
