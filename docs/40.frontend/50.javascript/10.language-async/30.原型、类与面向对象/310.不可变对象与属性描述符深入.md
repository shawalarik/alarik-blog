# 实现不可变对象与属性描述符（writable、enumerable、configurable）深入

## 从一个违反直觉的现象说起

在 JavaScript 中，有一个看似简单却让无数开发者困惑的问题：

```javascript
const obj = { name: "张三" };
obj.name = "李四";       // ✅ 正常工作
console.log(obj.name);    // "李四"

const str = "hello";
str[0] = "H";            // 静默失败！没有任何效果
console.log(str);          // "hello" —— 还是原来的值
```

为什么给普通对象的属性赋值可以成功，而给字符串的某个字符赋值却静默失败了？同样都是"赋值操作"，为什么表现截然不同？如果你尝试给一个冻结的对象赋值：

```javascript
const frozen = Object.freeze({ x: 1 });
frozen.x = 99;           // 严格模式下抛出 TypeError，非严格模式下静默失败
console.log(frozen.x);     // 1 —— 原封不动
```

又是一种行为。这些现象背后隐藏着 JavaScript 对象系统中一组精巧且强大的机制——**属性描述符（Property Descriptor）**。它控制着每个属性的"行为规则"：能不能被修改？能不能被枚举？能不能被删除？能不能被重新定义？

理解这套机制，不仅能让你彻底搞懂上面那些奇怪现象的根源，更重要的是，它能让你**精确地控制对象的行为边界**——这是实现不可变对象（Immutable Object）、数据封装、API 设计等高级模式的基础。

本文将从底层原理出发，系统性地讲解属性描述符的每一个细节，然后展示如何利用它来实现各种形式的不可变性。

## 属性的本质：不只是键值对

### 表面视角 vs 内部视角

当你写下 `const obj = { name: "张三", age: 25 }` 时，初学者眼中的对象是这样的：

```
┌─────────────────────┐
│ obj                 │
├─────────────────────┤
│ name: "张三"          │  ← 一个键值对
│ age: 25              │  ← 另一个键值对
└─────────────────────┘
```

这叫**表面视角（Surface View）**。在这个视角下，对象就是一组命名的槽位（slot），每个槽位里存放着一个值。你通过 `obj.name` 来读取或 `obj.name = "新值"` 来写入。简单、直观、符合直觉。

但在 JavaScript 引擎内部，每个属性远不止一个名字和一个值。引擎为每个属性维护了一份完整的**元信息清单（Metadata）**，记录着这个属性的各种"行为规则"。这份清单就是**属性描述符（Property Descriptor）**：

```
┌─────────────────────────────────────────────────┐
│ obj                                           │
├─────────────────────────────────────────────────┤
│ 属性 "name":                                   │
│   ├── value: "张三"          (属性值)             │
│   ├── writable: true        (可写？)             │
│   ├── enumerable: true      (可枚举？)           │
│   ├── configurable: true    (可配置？)           │
│   └── get: undefined        (getter 函数)         │
│   └── set: undefined        (setter 函数)         │
├─────────────────────────────────────────────────┤
│ 属性 "age":                                    │
│   ├── value: 25                                  │
│   ├── writable: true                              │
│   ├── enumerable: true                            │
│   ├── configurable: true                         │
│   └── get/set: undefined                        │
└─────────────────────────────────────────────────┘
```

这就是**内部视角（Internal View）**。每个属性都携带了六个维度的元信息（value、writable、enumerable、configurable、get、set），它们共同决定了这个属性在被访问和修改时的全部行为。

### 六大描述符属性详解

让我们逐一深入理解每个描述符属性的含义和作用：

#### value：属性存储的数据值

最直观的一个——属性实际持有的数据。对于基本类型（string、number、boolean、null、undefined、Symbol），`value` 直接存储数据本身；对于引用类型（object、function），`value` 存储的是引用（指针/内存地址）。

```javascript
let desc = Object.getOwnPropertyDescriptor({ x: 42 }, 'x');
console.log(desc.value);  // 42

desc = Object.getOwnPropertyDescriptor({ fn: function(){} }, 'fn');
console.log(typeof desc.value);  // 'function' — 存储的是函数引用
```

#### writable：是否允许写入

这是一个布尔值开关。当 `writable: false` 时，任何对该属性的直接赋值操作都会失效（严格模式下抛出 `TypeError`，非严格模式下静默忽略）：

```javascript
const obj = {};
Object.defineProperty(obj, 'readonlyName', {
  value: '不能改的名字',
  writable: false  // 设为不可写
});

console.log(obj.readonlyName);  // "不能改的名字"
obj.readonlyName = '我想改';    // 严格模式：TypeError!
                             // 非严格模式：静默失败
console.log(obj.readonlyName);  // 仍然是 "不能改的名字"
```

关键细节：`writable: false` **只阻止直接赋值（`=` 操作符）**，但不阻止 `Object.defineProperty` 重新定义该属性（前提是 `configurable: true`）。也就是说，"不可写"不等于"不可改变"——后者需要更强的限制条件。

#### enumerable：是否可枚举

控制属性是否会在 `for...in` 循环、`Object.keys()`、`JSON.stringify()` 等枚举操作中出现：

```javascript
const obj = {
  visible: '你能看到我',
  hidden: '你看不到我'
};

Object.defineProperty(obj, 'hidden', {
  enumerable: false  // 设为不可枚举
});

// for...in：跳过不可枚举属性
for (let key in obj) {
  console.log(key);
}
// 只输出 "visible"

// Object.keys()：同样跳过
console.log(Object.keys(obj));          // ["visible"]
console.log(Object.values(obj));        // ["你能看到我"]

// JSON.stringify()：也跳过
console.log(JSON.stringify(obj));        // '{"visible":"你能看到我"}'

// 但直接访问仍然可以！
console.log(obj.hidden);                // "你看不到你" —— 它还在，只是"隐形"
```

很多内置属性都是 `enumerable: false` 的：
- 数组的 `length` 属性
- 数组原型的各种方法（`map`、`filter`、`reduce` 等）
- 对象原型的 `constructor`、`__proto__`、`hasOwnProperty` 等

这就是为什么 `for...in` 遍历数组时不会出现这些方法名——它们被标记为了不可枚举，但仍然可以通过点号直接访问。

#### configurable：是否可配置

这是最强力的控制开关。当 `configurable: false` 时：
1. 该属性**不能被删除**（`delete obj.prop` 无效）
2. 该属性**的描述符本身不能再被修改**（不能用 `Object.defineProperty` 改变它的 writable/enumerable/configurable）
3. （额外规则）如果同时 `writable: true`，还可以将 writable 改为 false；但如果已经是 `false`，则连这个也不能改回去

```javascript
const obj = {};

Object.defineProperty(obj, 'locked', {
  value: '我被锁定了',
  writable: true,
  enumerable: true,
  configurable: false  // 最强限制！
);

obj.locked = '试试改';        // 可以改（writable 是 true）
delete obj.locked;           // ❌ 失败！无法删除
Object.defineProperty(obj, 'locked', {  // ❌ 失败！无法修改描述符
  writable: false
});
// TypeError: Cannot redefine property: locked
```

`configurable: false` 是**单向阀门**——一旦关上就再也打不开（在同一个属性上）。这也是 `Object.freeze()` 实现深度不可变的底层机制之一：将所有属性的 `configurable` 设为 `false`，就等于切断了所有后续修改的可能性。

#### get 与 set：访问器（Accessor）

这是一对函数，分别控制属性的**读取**和**写入**行为。当属性拥有 getter/setter 时，它的 `value` 和 `writable` 字段会被忽略（实际上必须省略）：

```javascript
const obj = {
  _radius: 5,

  // getter：读取 diameter 时自动计算
  get diameter() {
    return this._radius * 2;
  },

  // setter：设置直径时反向计算半径
  set diameter(val) {
    if (val <= 0) throw new Error('直径必须为正数');
    this._radius = val / 2;
  }
};

console.log(obj.diameter);  // 10 —— 调用 getter
obj.diameter = 20;         // 调用 setter，_radius 变成 10
console.log(obj._radius);   // 10
obj.diameter = -5;          // 💥 Error: 直径必须为正数
```

查看描述符会发现访问器属性的特殊结构：

```javascript
let desc = Object.getOwnPropertyDescriptor(obj, 'diameter');
console.log(desc);
// {
//   get: [Function: diameter],   ← 有 getter 函数
//   set: [Function: diameter],   ← 有 setter 函数
//   enumerable: true,
//   configurable: true,
//   注意：没有 value！没有 writable！
// }
```

**重要规则**：如果属性有 `get` 或 `set`，则 `value` 和 `writable` 不能同时存在（否则会抛出 TypeError）。这是因为访问器属性本身就是"虚拟属性"——它没有自己的存储空间，每次读写都是动态计算的。

### 数据描述符 vs 访问器描述符

基于上述六种属性的存在组合，属性描述符分为两大类：

| | 数据描述符（Data Descriptor） | 访问器描述符（Accessor Descriptor） |
|--|---------------------------|-------------------------------|
| **必有属性** | `value` | `get` 或 `set`（至少一个） |
| **可选属性** | `writable`, `enumerable`, `configurable` | `enumerable`, `configurable` |
| **互斥关系** | 有 value/writable 时不能有 get/set | 有 get/set 时不能有 value/writable |
| **用途** | 存储静态数据的属性 | 动态计算或校验的"虚拟"属性 |

判断一个描述符属于哪一类的方法很简单：

```javascript
function descriptorType(desc) {
  if ('value' in desc || 'writable' in desc) return 'Data';
  if ('get' in desc || 'set' in desc) return 'Accessor';
  return 'Neither/Both (invalid)';
}

descriptorType({ value: 1, writable: true });     // "Data"
descriptorType({ get: function(){}, set: function(){} });  // "Accessor"
```

## Object.defineProperty：精确操控属性的手术刀

### API 全貌

`Object.defineProperty(obj, propertyName, descriptor)` 是 JavaScript 提供的用于**定义或修改单个属性描述符**的核心方法。它是我们操控属性行为的"精密手术刀"：

```javascript
Object.defineProperty(target, propertyKey, descriptor)
// target: 目标对象
// propertyKey: 属性名（字符串或 Symbol）
// descriptor: 描述符对象
// 返回值: target 对象本身（支持链式调用）
```

使用它可以实现之前提到的所有精细控制：

```javascript
const secureConfig = {};

// 定义一个完全受控的属性
Object.defineProperty(secureConfig, 'apiSecret', {
  value: 'sk_live_xxxxxxxxx',
  writable: false,        // 不允许外部修改
  enumerable: false,      // 不出现在枚举中（防止意外泄露）
  configurable: false     // 不允许删除或重新定义
});

console.log(secureConfig.apiSecret);     // "sk_live_xxxxxxxxx" ✅ 可读
secureConfig.apiSecret = 'hacked';       // ❌ 不可写
for (let k in secureConfig) console.log(k);  // 不输出任何东西 ❌ 不可枚举
delete secureConfig.apiSecret;           // ❌ 不可删除
```

### 默认值陷阱

一个极其重要的细节是：**当使用 `Object.defineProperty` 创建新属性时，如果描述符中没有显式指定某个属性，它的默认值不是 `true`，而是 `false`（除 `value` 为 `undefined` 外）：**

```javascript
const obj = {};

// 只指定 value，其他全用默认值
Object.defineProperty(obj, 'prop', { value: 42 });

let desc = Object.getOwnPropertyDescriptor(obj, 'prop');

desc.writable;       // false!  ← 不是 true！
desc.enumerable;     // false!
desc.configurable;   // false!

// 这意味着 prop 是一个：不可写、不可枚举、不可配置的属性
obj.prop = 99;        // 静默失败
delete obj.prop;      // 静默失败
```

这与使用**字面量语法或赋值操作符**创建属性时的默认值形成鲜明对比：

| 创建方式 | value | writable | enumerable | configurable |
|---------|-------|----------|-----------|-------------|
| `obj.x = 1` 或 `{ x: 1 }` | 给定值 | `true` | `true` | `true` |
| `defineProperty(obj, 'x', { value })` | 给定值 | `false` | `false` | `false` |

这个默认值差异是大量 bug 的来源。很多人以为 `defineProperty` 只是"更声明式"的属性定义方式，却不知道它默认创建的是一个几乎完全锁死的属性。**永远显式指定你需要的每个属性**，不要依赖默认值。

### defineProperties：批量操作的便利方法

如果你需要一次定义多个属性，可以使用 `Object.defineProperties`：

```javascript
const product = {};

Object.defineProperties(product, {
  id: {
    value: 'PROD-001',
    writable: false,
    enumerable: true,
    configurable: false
  },
  name: {
    value: '无线耳机',
    writable: true,
    enumerable: true,
    configurable: true
  },
  price: {
    value: 299,
    writable: false,
    enumerable: true,
    configurable: false
  },
  _internalId: {
    value: 'int_abc123',
    writable: true,
    enumerable: false,   // 内部字段不对外暴露
    configurable: true
  }
});
```

### getOwnPropertyDescriptor 与 getOwnPropertyDescriptors

与"定义"对应的是"查询"——获取已有属性的描述符信息：

```javascript
const user = { name: '张三', age: 25 };

// 获取单个属性的完整描述符
let nameDesc = Object.getOwnPropertyDescriptor(user, 'name');
// { value: '张三', writable: true, enumerable: true, configurable: true, get: undefined, set: undefined }

// 批量获取所有自有属性的描述符
let allDescs = Object.getOwnPropertyDescriptors(user);
// { name: { ... }, age: { ... } }
```

这两个方法是调试和分析对象行为的利器——当你不确定某个属性为什么表现异常时，先看看它的描述符是什么样的，往往就能找到答案。

### 通俗类比：房产证上的登记信息

如果把对象比作一套房子，把属性比作房子里的房间，那么**属性描述符就像是房产证上每个房间的详细登记信息**：

- **value**（面积/户型）：房间的基本数据
- **writable**（能否装修）：你可以搬家具进去吗？还是只能看不能动？
- **enumerable**（是否显示在平面图上）：这个房间会出现在房屋平面图上吗？还是说它是一个隐藏的储藏室？
- **configurable（能否改变用途）：你能把这个卧室改成厨房吗？能拆掉这面墙吗？还是房子的结构是固定的？

有些房间是"公共区域"（enumerable:true），任何人进来都能看到；有些是"私密房间"（enumerable:false），只有知道门牌号的人才能进入。有些房间可以随意布置（writable:true），有些则是"样板间"（writable:false），只能看不能碰。

`Object.defineProperty` 就像是房管部门——你有权力去修改任何房间的登记信息，让一个可改造的房间变成永久性的结构墙（或者反过来，虽然不太常见）。

## 深度不可变性的层级体系

"不可变对象"（Immutable Object）是一个经常被讨论但很少有人真正理解透彻的概念。很多人以为"不可变"就是一个词的意思——但实际上，JavaScript 中的不可变性存在多个层次，每一层提供不同强度的保证。属性描述符是实现这些层次的底层机制之一。

### 第一层：浅层不变性（Shallow Immutability）

最基础的不可变性——阻止对对象自身属性的**直接修改**。但这只保护"第一层"，嵌套的对象不受影响：

```javascript
function makeShallowImmutable(obj) {
  return Object.freeze(obj);
}

const config = makeShallowImmutable({
  apiUrl: 'https://api.example.com',
  timeout: 5000,
  retries: 3,
  metadata: { version: '1.0', author: 'Alarik' }
});

config.apiUrl = 'http://hacked.com';  // ❌ 冻结失败（strict mode 下报错）
config.timeout = 9999;              // ❌ 同上

// 但是！嵌套对象没有被保护
config.metadata.version = 'hacked!';   // ✅ 成功修改了！
config.metadata.author = 'Hacker';     // ✅ 也成功了！

console.log(config.metadata);  // { version: 'hacked!', author: 'Hacker' }
```

`Object.freeze()` 做的事情是：
1. 将每个属性的 `writable` 设为 `false`
2. 将每个属性的 `configurable` 设为 `false`
3. 将对象本身的 `extensible` 设为 `false`（不允许添加新属性）

但它**不会递归地处理嵌套对象**——因为那会导致性能问题和潜在的副作用。所以 `freeze` 是**浅层**的。

### 第二层：深层不变性（Deep Immutability）

真正的深层不可变性需要递归地 freeze 所有嵌套对象：

```javascript
function deepFreeze(obj) {
  // 冻结基础值和非对象
  if (obj === null || typeof obj !== 'object') return obj;

  // 获取所有自有属性（包括不可枚举的）
  const propNames = Object.getOwnPropertyNames(obj);

  // 先递归冻结所有子对象
  for (let name of propNames) {
    let value = obj[name];
    deepFreeze(value);  // 先冻里面的
  }

  // 最后冻结自己
  return Object.freeze(obj);
}

const deepFrozen = deepFreeze({
  level1: {
    level2: {
      value: 42,
      arr: [1, 2, [3, 4]]  // 嵌套数组也要保护
    }
  }
});

deepFrozen.level1.level2.value = 99;    // ❌ 失败
deepFrozen.level1.level2.arr[2][0] = 99; // ❌ 失败
```

深层 freeze 的代价是性能开销——对于大型嵌套结构，递归遍历和 freeze 所有节点需要可观的时间和内存。在生产环境中使用时需要注意调用时机（通常只在初始化时执行一次）。

### 第三层：语义不变性（Semantic Immutability）

还有一种更高阶的不可变性——不仅阻止值的改变，还确保**对象在语义上代表一个恒定的事实**。这在函数式编程中特别重要：

```javascript
// 一个"时间戳"在语义上应该是不可变的
class Timestamp {
  #value;

  constructor(value) {
    this.#value = value;
  }

  get value() { return this.#value; }

  // 返回一个新的 Timestamp，而不是修改当前实例
  add(ms) {
    return new Timestamp(this.#value + ms);
  }

  isBefore(other) {
    return this.#value < other.value;
  }
}

const t1 = new Timestamp(1000);
const t2 = t1.add(500);  // t2 是新实例，t1 未被修改

console.log(t1.value);  // 1000 ✅ 未变
console.log(t2.value);  // 1500
console.log(t1.isBefore(t2)); // true
```

这种不变性的核心思想是：**任何看起来像"修改"的操作都应该返回一个新的对象，而不是修改原有对象。** 这就是 Immutable.js、Immer 等库的设计哲学——它们提供的不是"禁止修改"，而是"修改即复制"的持久化数据结构。

### 四层对比总结

| 层级 | 方法 | 保护范围 | 性能影响 |
|------|------|---------|---------|
| **约定层面**（Convention） | 命名规范如 `_前缀`、注释说明 | 仅靠自觉 | 无 |
| **浅层冻结**（Shallow Freeze） | `Object.freeze()` | 仅第一层属性 | 极低 |
| **深层冻结**（Deep Freeze） | 递归 `freeze` | 所有嵌套层级 | 中等（一次性成本） |
| **语义不变**（Semantic） | 新对象替换旧对象 | 值本身的恒定性 | 取决于复制策略 |

选择哪一层取决于你的需求。如果是简单的配置对象，浅层 freeze 就够了；如果是传递给不可信代码的关键数据，深层 freeze 更安全；如果在做函数式数据流处理，语义不变可能是最自然的选择。

## 属性描述符的高级应用

### 应用一：实现私有属性（ES2022 私有字段之前的时代）

在 ES2022 的 `#` 私有字段语法诞生之前，属性描述符是实现真正私有属性的唯一方式：

```javascript
function createPrivateStore(initialValue) {
  let privateValue = initialValue;

  return {
    get() { return privateValue; },
    set(newValue) { privateValue = newValue; },
    delete() {
      privateValue = undefined;
      return true;
    }
  };
}

function Person(name, secretCode) {
  const secret = createPrivateStore(secretCode);

  Object.defineProperty(this, 'name', {
    value: name,
    writable: true,
    enumerable: true,
    configurable: true
  });

  // 通过闭包 + descriptor 创建"伪私有"属性
  Object.defineProperty(this, '_secretCode', {
    get: () => secret.get(),
    set: (v) => secret.set(v),
    enumerable: false,    // 对外不可见
    configurable: false   // 对外不可改/删
  });

  // 或者更优雅的方式：不暴露任何属性到实例上
  // 私有值完全封闭在闭包内，只通过方法来间接访问
  this.getSecret = () => secret.get();
  this.setSecret = (v) => secret.set(v);
  this.verifySecret = (code) => secret.get() === code;
}

let person = new Person('特工007', 'SPECTRE');

person.name;              // "特工007" ✅ 公开属性
person._secretCode;        // undefined ❌ 不可访问（enumerable:false）
person.getSecret();        // "SPECTRE" ✅ 通过授权方法访问
person.setSecret('NEW');   // 修改成功
person.verifySecret('SPECTRE');  // true
person.verifySecret('WRONG');    // false
```

这种模式的本质是利用**闭包捕获变量 + `enumerable: false` 让属性对外不可见**。虽然不是语言层面的硬隐私（比如可以用 `getOwnPropertyDescriptor` 探测到 getter 函数的存在），但对于日常开发来说已经足够安全了。

### 应用二：实现常量（真正的 CONST）

`const` 声明的变量只是**绑定不可变**（变量名不能重新指向新的值），但它指向的对象本身仍然是可变的：

```javascript
const CONFIG = { maxUsers: 100 };
CONFIG.maxUsers = 999;   // ✅ 你可以改变对象的内容！

// 真正的常量需要属性级别的不可变性
const REAL_CONST = Object.defineProperty({}, 'MAX_CONNECTIONS', {
  value: 10,
  writable: false,       // 不能改值
  configurable: false    // 不能删、不能重定义
});

REAL_CONST.MAX_CONNECTIONS = 99;  // ❌ TypeError in strict mode
delete REAL_CONST.MAX_CONNECTIONS; // ❌ TypeError
```

在实际项目中，这种技术常用于定义**应用级的全局常量**——版本号、功能开关、环境标识等绝对不应该被运行时代码修改的值：

```javascript
const AppConstants = Object.seal(
  Object.defineProperties({}, {
    VERSION: {
      value: '2.1.0',
      writable: false,
      enumerable: true,
      configurable: false
    },
    ENVIRONMENT: {
      value: process.env.NODE_ENV || 'development',
      writable: false,
      enumerable: true,
      configurable: false
    },
    DEBUG_MODE: {
      value: process.env.NODE_ENV === 'development',
      writable: false,
      enumerable: true,
      configurable: false
    },
    __internal__: {
      value: { buildTime: Date.now(), gitHash: 'abc123' },
      writable: false,
      enumerable: false,   // 内部信息不对外暴露
      configurable: false
    }
  })
);
// seal 阻止添加新属性，配合每个属性的 configurable:false 形成双重保险
```

### 应用三：拦截和代理属性访问

属性描述符可以与 `Proxy` 结合，实现对属性读写的精细化拦截：

```javascript
function createValidatedObject(schema) {
  const data = {};  // 内部数据存储

  // 根据 schema 定义带验证的属性
  for (let [fieldName, rules] of Object.entries(schema)) {
    Object.defineProperty(data, fieldName, {
      get() {
        // 每次读取都可以执行逻辑
        if (rules.onRead) rules.onRead.call(this, fieldName);
        return this[`_${fieldName}`];  // 从内部存储读取
      },

      set(newValue) {
        // 写入前进行验证
        if (rules.validator) {
          const result = rules.validator(newValue, fieldName, data);
          if (!result.valid) {
            throw new Error(`[${fieldName}] ${result.message}`);
          }
        }
        if (rules.onWrite) rules.onWrite.call(this, newValue, fieldName);

        this[`_${fieldName}`] = newValue;  // 写入内部存储
      },

      enumerable: rules.enumerable !== false,
      configurable: true
    });

    // 初始化内部存储
    data[`_${fieldName}` = rules.initialValue;
  }

  return data;
}

// 使用：创建一个带有实时校验的用户对象
const user = createValidatedObject({
  email: {
    initialValue: '',
    validator: (v) => ({
      valid: /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(v),
      message: '邮箱格式无效'
    }),
    onWrite: (val) => console.log(`📧 Email 更改为: ${val}`)
  },
  age: {
    initialValue: 0,
    validator: (v) => ({
      valid: Number.isInteger(v) && v >= 0 && v <= 150,
      message: '年龄必须是 0-150 之间的整数'
    })
  }
});

user.email = 'valid@email.com';  // 📧 Email 更改为: valid@email.com ✅
user.age = 25;                // ✅
user.age = -5;                // ❌ Error: [age] 年龄必须是 0-150 之间的整数
user.email = 'invalid';         // ❌ Error: [email] 邮箱格式无效
```

这个例子展示了属性描述符作为**行为注入点**的能力：getter/setter 不再是简单的存取操作，而是变成了**守卫者（Guardian）**——在每次数据进出时执行自定义的逻辑。这是构建响应式系统、表单验证框架、ORM 层的基础技术。

### 应用四：实现懒加载与按需计算

访问器属性结合闭包可以实现惰性求值——只在第一次访问时计算结果，之后缓存返回：

```javascript
function lazyProperty(object, propName, factoryFn) {
  let cacheKey = Symbol('__lazy_cache__');
  let initialized = false;
  let cachedResult;

  Object.defineProperty(object, propName, {
    get() {
      if (!initialized) {
        cachedResult = typeof factoryFn === 'function'
          ? factoryFn.call(object)
          : factoryFn;
        initialized = true;
      }
      return cachedResult;
    },
    enumerable: true,
    configurable: true
  });

  return object;
}

// 使用示例：一个昂贵的数据库查询结果
const dbQuery = {};

lazyProperty(dbQuery, 'activeUsers', async function () {
  console.log('⏳ 正在执行昂贵的数据库查询...');
  // 模拟异步查询
  await new Promise(r => setTimeout(r, 500));
  return Array.from({ length: 1000 }, (_, i) => ({
    id: i + 1,
    name: `User${i}`,
    lastLogin: new Date(Date.now() - Math.random() * 86400000).toISOString().split('T')[0]
  }));
});

(async () => {
  console.log(await dbQuery.activeUsers);  // 第一次：执行查询，返回 1000 条
  console.log(await dbQuery.activeUsers);  // 第二次：直接返回缓存
})();
```

这种模式在性能优化中非常实用。它与 ES2022 的 `accessor` 关键字的功能类似，但通过 `defineProperty` 手动实现让你对其内部工作机制有完全的控制权。

## 属性描述符与 JavaScript 对象模型的完整图景

### [[GetOwnProperty]] 和 [[SetOwnProperty]] 内部方法

在 ECMAScript 规范中，JavaScript 对象的属性操作最终归结为几个**内部方法（Internal Method）**。属性描述符直接控制着这些内部方法的行为：

**当我们执行 `obj.prop = value` 时，引擎内部的简化流程是：**

```
1. 查找 prop 在 obj 自身上的属性描述符
2. 如果找到：
   a. 如果描述符有 setter → 调用 setter
   b. 如果没有 setter 但有 value 且 writable=true → 直接设置 value
   c. 如果 writable=false → 抛出 TypeError（严格模式）/ 忽略（非严格模式）
3. 如果没找到（且 obj 不受 Proxy 拦截）：
   a. 如果 prop 在原型链上 → 沿原型链向上查找（重复上述过程）
   b. 如果原型链上也没有 → 在 obj 上创建新属性（默认描述符）
```

**当我们执行 `obj.prop`（读取）时，流程类似：**

```
1. 查找 prop 的描述符
2. 如果有 getter → 调用 getter 并返回结果
3. 如果没有 getter 但有 value → 返回 value
4. 如果没找到 → 沿原型链向上查找
```

这就是为什么前面提到的字符串字符赋值会静默失败的原因——字符串的 `[[SetOwnProperty]]` 内部方法检查了对应索引位置的属性的描述符，发现其 writable 为 `false`（字符串的所有字符属性都是不可写的），于是拒绝操作。

### 属性描述符与 Prototype Chain 的交互

属性描述符和原型链是两个独立但又相互交织的系统：

- **原型链决定了"去哪里找"属性**
- **属性描述符决定了"找到之后的规则是什么"**

两者协同工作的典型场景：

```javascript
const proto = {
  inheritedProp: '来自原型的值'
};

// 原型属性也是有自己的描述符
let protoDesc = Object.getOwnPropertyDescriptor(proto, 'inheritedProp');
// { value: '来自原型的值', writable: true, enumerable: true, configurable: true }

const child = Object.create(proto);
child.ownProp = '自身的值';

// 子类可以"遮蔽"（Shadow）原型的同名属性
Object.defineProperty(child, 'inheritedProp', {
  value: '被子类覆盖的值',
  writable: true,
  enumerable: true,
  configurable: true
});

console.log(child.inheritedProp);  // "被子类覆盖的值" —— 用的是自己的
delete child.inheritedProp;
console.log(child.inheritedProp);  // "来自原型的值" —— 自己的没了，回退到原型
```

遮蔽（Shadowing）之所以生效，就是因为 JavaScript 引擎查找属性时**优先检查对象自身的描述符**，只有在自身找不到匹配的属性名（或者自身的属性描述符中有 getter 且 getter 调用了 `super.prop`）时才会继续沿原型链向上查找。

### Proxy 对象与描述符的关系

ES6 引入的 `Proxy` 提供了一种比属性描述符更强大的拦截能力——它可以在**属性不存在的时候**也能拦截操作：

```javascript
const target = { x: 1, y: 2 };
const handler = {
  get(target, prop, receiver) {
    console.log(`📖 读取属性: ${prop}`);
    if (prop in target) {
      return target[prop];
    }
    // 即使属性不存在也能拦截并返回值！
    return `[默认值]`;
  },
  set(target, prop, value, receiver) {
    console.log(`✏️ 设置属性: ${prop} = ${value}`);
    if (typeof prop === 'string' && prop.startsWith('_')) {
      return false;  // 拒绝所有以 _ 开头的属性写入
    }
    target[prop] = value;
    return true;
  }
};

const proxy = new Proxy(target, handler);

proxy.x;        // 📖 读取属性: x → 1
proxy.z;        // 📖 读取属性: z → "[默认值]"  ← 属性不存在也能拦截！
proxy._secret = 'hi';  // ✏️ 设置属性: _secret = hi → false (被拒绝!)
```

`Proxy` 可以看作是**动态版的属性描述符**——它能在运行时决定如何处理任何属性的任何操作，而不需要在定义时就确定好规则。但两者并不矛盾：`Proxy` 通常用于横切面的通用拦截（如日志、权限、验证），而属性描述符用于单个属性的精细控制。在实际项目中，两者经常配合使用。

### 通俗类比：属性描述符就像房产登记簿

让我们用一个统一的类比来总结属性描述符的全部能力：

想象每块土地（对象）都有一个**房产登记簿**（Property Descriptor Registry），里面详细记录了每块土地（属性）的信息：

- **value（地块面积）**：这块地有多大？上面建了多少平米的建筑？
- **writable（改建许可）**：这块地上的房子可以翻修扩建吗？还是历史保护建筑，只能维持原样？
- **enumerable（地图标注）**：这块地会出现在公开的城市地图上吗？还是军事禁区，从地图上抹去了？
- **configurable（用途变更许可）**：这块地的用地性质可以改变吗？（住宅→商业？农业→工业？）一旦设为"永久绿地"，就不能再改了。
- **get/set（托管服务）**：这块地是否由物业管理公司代管？如果是的话，你（使用者）不能直接操作，而是要通过物业（getter/setter）来间接管理。

`Object.defineProperty` 就是**不动产登记处的办事窗口**——你带着申请材料（目标对象、属性名、描述符对象）去窗口办理业务，工作人员在你的房产证上登记或修改相应的条目。登记完成后，这块土地（属性）就必须按照登记的规则来运作。

## 总结：掌握属性描述符的意义

### 核心知识速查表

| 描述符属性 | 类型 | 默认值 | 作用 | 典型用法 |
|-----------|------|--------|------|---------|
| `value` | Any | `undefined` | 存储属性的数据值 | 数据属性的核心 |
| `writable` | Boolean | `false`（defineProperty）/ `true`（字面量）| 控制是否可通过 `=` 赋值 | 常量、只读属性 |
| `enumerable` | Boolean | `false`（defineProperty）/ `true`（字面量）| 控制 `for...in`、`keys()`、`JSON` 是否可见 | 内部属性、隐藏字段 |
| `configurable` | Boolean | `false`（defineProperty）/ `true`（字面量）| 控制属性能否被删除或重新定义 | 安全锁定的属性 |
| `get` | Function \| undefined | `undefined` | 读取时的拦截函数 | 计算属性、验证、懒加载 |
| `set` | Function \| undefined | `undefined` | 写入时的拦截函数 | 带校验的属性、事件触发 |

### API 速查表

| 方法 | 作用 | 返回值 |
|------|------|--------|
| `Object.defineProperty(o, p, d)` | 定义/修改单个属性的描述符 | 目标对象 o |
| `Object.defineProperties(o, ds)` | 批量定义多个属性 | 目标对象 o |
| `Object.getOwnPropertyDescriptor(o, p)` | 获取单个属性的描述符 | 描述符对象或 undefined |
| `Object.getOwnPropertyDescriptors(o)` | 获取所有自有属性的描述符 | 描述符对象字典 |
| `Object.freeze(o)` | 浅层冻结（所有属性 writable+configurable=false，对象 extensible=false） | 冻结后的对象 |
| `Object.seal(o)` | 密封（所有属性 configurable=false，对象 extensible=false） | 密封后的对象 |
| `Object.preventExtensions(o)` | 防止添加新属性 | 不可扩展的对象 |
| `Object.isFrozen(o)` | 检查是否被冻结 | Boolean |
| `Object.isSealed(o)` | 检查是否被密封 | Boolean |

### 最终建议

属性描述符是 JavaScript 对象系统的**基础设施层（Infrastructure Layer）**——它不像 Promise 或装饰器那样引人新的编程范式，也不像 class 那样提供高层抽象。它就在那里，默默支撑着你每天写的每一行对象操作代码。

理解属性描述符的价值在于：

1. **调试能力的质变**：当你遇到属性"应该改却改不了"、"应该看到却看不到"、"删除了却还在"等奇怪行为时，你知道该去哪里找原因——检查描述符
2. **精细控制的自由度**：你需要只读属性？需要隐藏属性？需要带校验的属性？需要惰性计算的属性？描述符都能满足
3. **设计更安全的 API**：通过 `configurable: false` 和 `writable: false` 向使用者明确传达"这个属性不应被修改"的契约，而不是依赖文档或命名约定
4. **理解更深层的 JS 机制**：原型链、Proxy、`class` 语法糖——这些高级特性全都建立在属性描述符的基础上

> **属性描述符就像空气——你可能感觉不到它的存在，但你每一步操作都依赖着它。** 理解它不会让你的代码立刻变得多么炫酷，但它会让你从一个"能用 JavaScript 写代码的人"进化为一个"真正理解 JavaScript 为什么这样工作的人"。而这种深层的理解，正是从"写代码"跨越到"设计系统"的分水岭。
