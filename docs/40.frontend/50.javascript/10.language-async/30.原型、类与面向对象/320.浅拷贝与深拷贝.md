# 浅拷贝与深拷贝的实现（含原型链处理）

> **核心内容**：浅拷贝与深拷贝的本质区别、JavaScript 中各种拷贝方式的完整对比（赋值/浅拷贝/深拷贝）、手写深拷贝的递归实现、循环引用的处理、特殊类型的兼容（Date/RegExp/Map/Set/Symbol）、原型链在拷贝中的行为，以及拷贝操作在实际工程中的设计哲学。

## 一个 Bug 引发的灾难

让我们从一段真实场景中的代码开始。这段代码看起来完全正常——它做的事情也很简单：复制一个对象，修改副本，期望原对象不受影响：

```javascript
// 用户配置管理器
const defaultConfig = {
  name: '默认应用',
  version: '1.0.0',
  theme: {
    primaryColor: '#1890ff',
    fontSize: 14,
    borderRadius: 4
  },
  permissions: ['read', 'write'],
  meta: {
    createdAt: new Date('2024-01-01'),
    author: '系统管理员'
  }
};

// 创建用户自定义配置 —— "复制一份默认配置"
const userConfig = { ...defaultConfig };  // 展开运算符，很常用对吧？

// 用户修改自己的主题色
userConfig.theme.primaryColor = '#f5222d';

console.log(userConfig.theme.primaryColor);   // "#f5222d" ✅ 符合预期
console.log(defaultConfig.theme.primaryColor); // "#f5222d" 💥 等等……默认配置也被改了？？
```

这就是**浅拷贝（Shallow Copy）陷阱**的经典案例。开发者以为 `...defaultConfig` 创建了一个"完整的独立副本"，但事实上它只复制了对象的第一层。`theme` 这个属性的值仍然是一个对象的**引用**——原对象和副本共享着同一个 `theme` 对象。修改副本的 `theme.primaryColor`，实际上是在修改两者共用的那个对象。

这个 Bug 的后果可能很严重：
- 如果 `defaultConfig` 是全局共享的默认配置，一个用户的修改会影响所有其他用户
- 如果它是组件的初始状态 props，一次意外的修改可能导致所有同类型组件的状态被污染
- 更隐蔽的情况是——这种 Bug 可能不会立刻暴露，而是在特定的用户操作序列下才触发，排查起来极其困难

本文将彻底厘清 JavaScript 中"拷贝"这件事的全部知识——从最简单的赋值到完美的深拷贝实现，让你在面对任何需要复制对象的场景时，都能做出准确的选择。

## 什么是拷贝？——先搞清"复制"的本质

### 值类型 vs 引用类型：复制的分岔路口

要理解拷贝，首先需要理解 JavaScript 中两种截然不同的数据存储方式：

**基本类型（Primitive Type）**——number、string、boolean、null、undefined、Symbol、bigint——它们的值直接存储在变量绑定的内存位置上。当你把一个基本类型的值赋给另一个变量时，发生的是**值的完整复制**：

```javascript
let a = 42;
let b = a;      // b 得到了 42 的一个独立副本
b = 99;
console.log(a); // 42 ✅ a 不受影响
```

这就像你把一张纸上的数字"42"抄写到另一张纸上——两张纸上的数字彼此独立，改一张不会影响另一张。

**引用类型（Reference Type）**——object（包括普通对象、数组、函数、正则表达式、日期等）——变量中存储的不是对象本身，而是一个指向内存中某处对象的**引用（指针/地址）**：

```javascript
let original = { name: '张三', age: 25 };
let copy = original;  // copy 得到的不是对象的副本，而是同一个引用！

copy.name = '李四';
console.log(original.name);  // "李四" 💥 original 也变了！
```

这就好比两个人手里各拿着同一串钥匙（指向同一间房子）。无论谁用这串钥匙进屋去搬动家具，另一个人再进去时看到的都是改变后的样子——因为这是**同一间房子**，而不是两间一模一样的房子。

### 三层拷贝语义

基于上述区别，我们可以将 JavaScript 中的"拷贝操作"划分为三个层次：

| 层次 | 操作 | 第一层属性 | 嵌套对象 | 典型代表 |
|------|------|-----------|---------|---------|
| **赋值（Assignment）** | `b = a` | 共享引用 | 共享引用 | 普通赋值 |
| **浅拷贝（Shallow Copy）** | 复制第一层 | **独立副本** | **仍共享引用** | `Object.assign()`、展开运算符 |
| **深拷贝（Deep Copy）** | 递归复制全部层级 | 独立副本 | **也创建独立副本** | `structuredClone()`、`JSON.parse(JSON.stringify())`、手写递归 |

下面用一个统一的例子来直观感受三者的差异：

```javascript
const original = {
  level1: '第一层字符串',          // 基本类型
  nested: {                        // 嵌套对象
    level2: '第二层字符串',
    deep: { level3: '第三层' }     // 再嵌套一层
  }
};

// ====== 赋值 ======
const assigned = original;
assigned.level1 = '修改了';
assigned.nested.level2 = '也被改了';

console.log(original.level1);        // "修改了" 💥 原对象受影响
console.log(original.nested.level2); // "也被改了" 💥

// ====== 浅拷贝 ======
const original2 = {
  level1: '第一层字符串',
  nested: { level2: '第二层', deep: { level3: '第三层' } }
};
const shallow = { ...original2 };
shallow.level1 = '浅拷贝修改第一层';
shallow.nested.level2 = '浅拷贝修改第二层';

console.log(original2.level1);        // "第一层字符串" ✅ 第一层不受影响
console.log(original2.nested.level2); // "浅拷贝修改第二层" 💥 但嵌套层受影响！

// ====== 深拷贝 ======
const original3 = {
  level1: '第一层字符串',
  nested: { level2: '第二层', deep: { level3: '第三层' } }
};
const deep = structuredClone(original3);
deep.level1 = '深拷贝修改第一层';
deep.nested.level2 = '深拷贝修改第二层';
deep.nested.deep.level3 = '深拷贝修改第三层';

console.log(original3.level1);             // "第一层字符串" ✅
console.log(original3.nested.level2);       // "第二层" ✅
console.log(original3.nested.deep.level3);  // "第三层" ✅ 全部不受影响！
```

这三者的区别可以用一个生活化的类比来理解：

想象有一本书（原始对象），书的第一页写着基本信息（第一层属性），书的第 50 页夹了一张便利贴（嵌套对象），便利贴上又贴了一个更小的标签纸（深层嵌套）。

- **赋值（Assignment）**：你并没有复印这本书，只是把你手里的那本借给了另一个人。你们俩看的是**同一本书**——任何人在上面做的标记，对方都能看到。
- **浅拷贝（Shallow Copy）**：你复印了这本书的第一页，但对于第 50 页的便利贴，你只是在复印件上也写了一句"见原书第 50 页"。第一页的内容确实是独立的（你在复印件上涂鸦不影响原件），但如果有人通过便利贴写了东西，原书和复印件看到的都是**同一份便利贴上的内容**。
- **深拷贝（Deep Copy）**：你不仅复印了整本书，还把那张便利贴和标签纸也都各自复印了一份。现在原书和复印件是**完全独立的两个实体**——任何一方的修改都不会影响另一方。

## 赋值操作：不是拷贝，是"共用"

在正式进入浅拷贝之前，我们需要先彻底理解为什么普通的 `=` 操作符不是拷贝。这一步看似基础，却是很多困惑的根源。

### 对象赋值的本质：引用传递

```javascript
let objA = { x: 1, y: 2 };
let objB = objA;     // objB 和 objA 指向内存中的同一个对象

console.log(objA === objB);  // true —— 它们是同一个对象！

objB.x = 100;
console.log(objA.x);         // 100 —— 通过 objB 的修改影响了 objA
```

在内存层面，这段代码的实际效果是这样的：

```
objA ─────────────┐
                  │
                  ▼
           ┌─────────────┐
           │  { x: 1,    │  ← 内存中的唯一对象
           │    y: 2 }   │
           └─────────────┘
                  ▲
                  │
objB ─────────────┘
```

`objA` 和 `objB` 就像是两个不同的遥控器，但它们控制的是同一台电视。无论你按哪个遥控器的换台键，屏幕上的画面都会变——因为目标设备是同一个。

### 数组赋值同理

数组也是对象的一种特殊形式，赋值行为完全一致：

```javascript
let arr1 = [1, 2, 3];
let arr2 = arr1;

arr2.push(4);
console.log(arr1);  // [1, 2, 3, 4] —— arr2 的 push 影响了 arr1
console.log(arr2);  // [1, 2, 3, 4] —— 当然，它们本来就是同一个数组
```

### 函数参数传递也是引用

这一点特别重要——当对象作为参数传给函数时，传递的是引用而非副本：

```javascript
function resetUser(user) {
  user.name = '匿名';     // 直接修改传入的对象！
  user.age = 0;
}

let person = { name: '张三', age: 25 };
resetUser(person);
console.log(person);  // { name: '匿名', age: 0 } 💥 原对象被函数内部修改了！
```

这种**副作用（Side Effect）**是大量难以追踪 Bug 的来源。调用 `resetUser(person)` 的开发者可能预期函数会返回一个新的"重置后的用户对象"，或者至少不会修改原始数据。但由于 JavaScript 的引用传递机制，函数内部的修改直接作用在了原对象上。

**防御性编程的做法**——如果函数不应该修改原始对象，应该在入口处先做拷贝：

```javascript
function resetUserSafely(user) {
  const safeCopy = { ...user };  // 先浅拷贝一份
  safeCopy.name = '匿名';
  safeCopy.age = 0;
  return safeCopy;               // 返回新对象，原对象完好无损
}

let person2 = { name: '李四', age: 30 };
let resetPerson = resetUserSafely(person2);
console.log(resetPerson);  // { name: '匿名', age: 0 }
console.log(person2);      // { name: '李四', age: 30 } ✅ 原对象未受影响
```

### 什么时候应该用赋值（不用拷贝）？

赋值并非总是坏事。在某些场景下，**故意共享引用**正是你想要的行为：

- **大型对象的性能考虑**：如果一个对象非常大（比如包含数千个元素的几何网格数据），为了避免拷贝带来的内存和时间开销，多个模块之间共享同一个引用可能是合理的——前提是你要确保不会意外地修改它（配合 `Object.freeze` 使用）
- **响应式状态管理**：Vue.js 或 React 的状态管理中，store 中的状态对象通常就是通过引用来共享的——因为框架需要追踪同一个对象的引用变化来触发更新
- **单例模式（Singleton Pattern）**：全局唯一的实例本身就是通过引用共享的设计模式——所有使用者拿到的都是同一个对象

关键不在于"赋值好不好"，而在于**你是否清楚地知道自己在做什么**——是有意为之的引用共享，还是不小心掉进了"我以为我复制了但其实没有"的陷阱。

## 浅拷贝（Shallow Copy）：只复制表层

### 什么是浅拷贝？

**浅拷贝**创建一个新的对象，并将原始对象的所有自有可枚举属性复制到新对象上。如果属性的值是基本类型，复制的就是值本身；如果属性的值是引用类型（对象、数组等），复制的仍然是引用。

换句话说，浅拷贝解决了**第一层的共享问题**，但没有解决**嵌套层的共享问题**。

### 方式一：Object.assign()

ES5 引入的 `Object.assign(target, ...sources)` 是最早的官方浅拷贝方法之一：

```javascript
const original = { a: 1, b: 2, c: 3 };
const copy = Object.assign({}, original);

console.log(copy);            // { a: 1, b: 2, c: 3 }
console.log(copy === original); // false ✅ 是一个新对象

copy.a = 999;
console.log(original.a);      // 1 ✅ 修改副本不影响原对象
```

`Object.assign` 的工作原理很简单：遍历源对象（source）的所有**可枚举自有属性**，用 `=` 操作符将它们逐一赋值到目标对象（target）上。注意这里的关键词——**可枚举自有属性**，这意味着不可枚举属性和原型链上的属性都会被忽略：

```javascript
const proto = { inherited: '来自原型' };

const original = Object.create(proto);
original.ownProp = '自身属性';
Object.defineProperty(original, 'hidden', {
  value: '不可枚举',
  enumerable: false
});

const copy = Object.assign({}, original);
console.log(copy);
// { ownProp: "自身属性" }
// 注意：inherited（原型链）和 hidden（不可枚举）都被忽略了！
```

关于 `enumerable` 的详细机制，参见《[defineProperty 与枚举属性详解](/frontend/javascript/language-async/defineProperty-enumerable-properties)》。

### 方式二：展开运算符（Spread Operator）

ES2018（ES9）引入的对象展开运算符 `{...obj}` 提供了一种更简洁的浅拷贝语法：

```javascript
const original = { x: 10, y: 20, z: 30 };
const copy = { ...original };

console.log(copy);             // { x: 10, y: 20, z: 30 }
console.log(copy === original); // false ✅ 新对象
```

展开运算符的行为几乎等同于 `Object.assign({}, original)`，但有细微差异：

```javascript
// 差异 1：展开会调用 Symbol.toPrimitive 和 toString/valueOf
// 而 Object.assign 不会
const objWithToPrimitive = {
  [Symbol.toPrimitive]() { return { extra: 'hello' }; }
};

const viaAssign = Object.assign({}, objWithToPrimitive);
// {} —— Object.assign 忽略了 Symbol.toPrimitive

const viaSpread = { ...objWithToPrimitive };
// { extra: "hello" } —— 展开运算符触发了 Symbol.toPrimitive

// 差异 2：展开只枚举自有属性，且行为更接近 for...in 的语义
// （虽然也不含原型链属性）
```

在日常开发中，展开运算符因其简洁性已经成为首选的浅拷贝方式。

### 方式三：Array.slice() 和 Array.concat()

对于数组的浅拷贝，还有两个经典的方法：

```javascript
const originalArr = [1, 2, 3, 4, 5];

// slice() 无参数时复制整个数组
const copy1 = originalArr.slice();
console.log(copy1);              // [1, 2, 3, 4, 5]
console.log(copy1 === originalArr); // false ✅

// concat() 无参数或空数组参数时也能复制
const copy2 = originalArr.concat();
const copy3 = [].concat(originalArr);

// Array.from 也是有效的浅拷贝
const copy4 = Array.from(originalArr);
```

### 浅拷贝的局限性：嵌套对象共享问题

再次强调浅拷贝的核心局限——它只复制了第一层：

```javascript
const original = {
  basic: '基本类型',
  ref: { nested: '我是嵌套对象' },
  arr: [1, 2, { inner: '数组里的对象' }]
};

const shallow = { ...original };

// 第一层的基本类型 —— 安全
shallow.basic = '修改了';
console.log(original.basic);  // "基本类型" ✅ 不受影响

// 第二层的引用类型 —— 危险！
shallow.ref.nested = '被修改了';
console.log(original.ref.nested);  // "被修改了" 💥 原对象也被改了！

shallow.arr[2].inner = '也被改了';
console.log(original.arr[2].inner); // "也被改了" 💥 同样的问题！
```

内存模型如下所示：

```
original ───┐
            ├── basic: "基本类型"（独立值）
            │
shallow ───┤
            │
            ├── ref ──────────────────────┐
            │                              │
            │                         ┌─────────────┐
            │                         │ { nested:    │  ← 唯一的嵌套对象
            │                         │   "..." }    │     两个对象共享！
            │                         └─────────────┘
            │
            ├── arr ─────────────────────┐
                                       ┌──────────────────┐
                                       │ [1, 2, { inner }]│  ← 共享的数组
                                       └──────────────────┘
```

当你的对象只有一层深度（扁平结构），或者你确定不需要修改嵌套层时，浅拷贝就足够了。但如果你的数据结构有嵌套，并且你需要完全隔离的副本，那就必须使用**深拷贝**。

### 通俗类比：复印书的封面

浅拷贝就像你只复印了一本书的封面和目录页。封面上印的书名、作者这些信息确实是你自己的一份（第一层独立了）。但是目录里写的"详细内容见第 50 页"——当你翻到第 50 页时，你和拥有原书的人看的都是**同一页内容**（嵌套层共享）。

这在什么情况下够用呢？如果你只需要一本"看起来一样"的书放在书架上展示（只需要外观信息相同），而不需要真正阅读其中的内容，那复印封面就够了。但如果你需要在复印件上做笔记而不影响原著——那你就得把整本书都复印下来。

## 深拷贝（Deep Copy）：递归复制每一层

### 什么是深拷贝？

**深拷贝**会递归地复制对象及其所有嵌套的子对象，直到遇到基本类型为止。结果是产生一个与原对象在数据上完全相等、但在内存中完全独立的新对象。对新对象任何层级的任何修改，都不会影响原对象。

### 方式一：JSON.parse(JSON.stringify()) —— 最简单但不完美

这是最常见的"穷人版深拷贝"方案——利用 JSON 序列化和反序列化来间接实现拷贝：

```javascript
const original = {
  name: '张三',
  age: 25,
  address: {
    city: '北京',
    district: '朝阳区'
  },
  hobbies: ['读书', '游泳', '编程']
};

const deepCopy = JSON.parse(JSON.stringify(original));

deepCopy.name = '李四';
deepCopy.address.city = '上海';
deepCopy.hobbies.push('旅行');

console.log(original.name);           // "张三" ✅
console.log(original.address.city);   // "北京" ✅
console.log(original.hobbies);        // ["读书", "游泳", "编程"] ✅ 全部安全！
```

它的原理很巧妙：
1. `JSON.stringify(obj)` 将对象转换为 JSON 字符串——这个过程会遍历对象的所有可枚举属性并提取其值
2. `JSON.parse(str)` 将 JSON 字符串解析回全新的对象——所有的值都在新的内存空间中被重新构建

由于中间经过了"文本化"的过程，原对象和新对象之间没有任何引用关系。这是一种**"序列化中介（Serialization Intermediary）"**模式的典型应用。

#### JSON 方式的致命缺陷

尽管简单好用，但 `JSON.parse(JSON.stringify())` 存在一系列严重的局限性：

**缺陷 1：无法处理函数**

```javascript
const obj = {
  fn: function() { return 'hello'; },
  sayHi() { return 'hi'; }
};

const copy = JSON.parse(JSON.stringify(obj));
console.log(copy);
// {} —— 函数全丢了！JSON 不支持函数的序列化
```

这是因为 JSON 规范本身就不支持函数类型——JSON 只有六种数据类型：object、array、string、number、boolean、null。函数在序列化过程中会被静默丢弃。

**缺陷 2：无法处理 undefined**

```javascript
const obj = { a: 1, b: undefined, c: 'hello' };
const copy = JSON.parse(JSON.stringify(obj));
console.log(copy);
// { a: 1, c: "hello" } —— undefined 的属性 b 被丢掉了
```

**缺陷 3：无法处理 Symbol**

```javascript
const sym = Symbol('myKey');
const obj = { [sym]: 'symbolValue', normal: 'normalValue' };
const copy = JSON.parse(JSON.stringify(obj));
console.log(copy);
// { normal: "normalValue" } —— Symbol 键的属性被丢弃
```

**缺陷 4：Date 对象变成字符串**

```javascript
const obj = { birthday: new Date('2000-01-01'), name: '张三' };
const copy = JSON.parse(JSON.stringify(obj));
console.log(typeof copy.birthday);  // "string" ❌ 不再是 Date 对象！
console.log(copy.birthday);         // "2000-01-01T00:00:00.000Z"
```

**缺陷 5：RegExp 对象变成空对象**

```javascript
const obj = { pattern: /^\d+$/g };
const copy = JSON.parse(JSON.stringify(obj));
console.log(copy.pattern);  // {} ❌ 正则表达式丢失了！
```

**缺陷 6：循环引用直接报错**

```javascript
const obj = { name: '循环测试' };
obj.self = obj;  // 自己引用自己

const copy = JSON.parse(JSON.stringify(obj));
// 💥 TypeError: Converting circular structure to JSON
```

**缺陷 7：丢失不可枚举属性**

```javascript
const obj = {};
Object.defineProperty(obj, 'hidden', {
  value: '秘密',
  enumerable: false
});
obj.visible = '可见';

const copy = JSON.parse(JSON.stringify(obj));
console.log(copy);
// { visible: "可见" } —— hidden 被丢弃（因为它不可枚举）
```

**缺陷 8：NaN / Infinity 变成 null**

```javascript
const obj = { nan: NaN, inf: Infinity, negInf: -Infinity };
const copy = JSON.parse(JSON.stringify(obj));
console.log(copy);
// { nan: null, inf: null, negInf: null } ❌ 特殊数值丢失了
```

总结起来，`JSON.parse(JSON.stringify())` 只适合用于**纯数据的、无特殊类型、无循环引用的简单对象**的深拷贝。对于复杂的实际应用场景，它远远不够。

### 方式二：structuredClone() —— 现代浏览器的原生方案

`structuredClone()` 是现代浏览器（Chrome 98+、Firefox 94+、Safari 15.4+、Node.js 17+）提供的原生深拷贝 API，它能正确处理多种复杂类型：

```javascript
const original = {
  num: 42,
  str: 'hello',
  bool: true,
  nullVal: null,
  date: new Date('2024-06-15'),
  regex: /^test$/gi,
  map: new Map([['key1', 'value1']]),
  set: new Set([1, 2, 3]),
  arrayBuffer: new ArrayBuffer(8),
  nested: {
    deep: { value: '深层嵌套' }
  }
};

const copy = structuredClone(original);

// 验证各种类型
console.log(copy.date instanceof Date);                    // true ✅ Date 保留
console.log(copy.regex instanceof RegExp);                 // true ✅ RegExp 保留
console.log(copy.map instanceof Map);                      // true ✅ Map 保留
console.log(copy.set instanceof Set);                      // true ✅ Set 保留
console.log(copy.arrayBuffer instanceof ArrayBuffer);      // true ✅ ArrayBuffer 保留
console.log(copy.nested.deep.value === '深层嵌套');         // true ✅ 深拷贝成功
console.log(copy === original);                            // false ✅ 完全独立的新对象
```

`structuredClone()` 还能正确处理循环引用：

```javascript
const obj = { name: '循环' };
obj.self = obj;
obj.children = [{ parent: obj }];

const copy = structuredClone(obj);
console.log(copy.self === copy);           // true ✅ 循环引用保留了关系
console.log(copy.children[0].parent === copy); // true ✅ 跨层级循环也正确
```

#### structuredClone 的限制

即便如此，`structuredClone()` 也有一些限制：

- **不支持函数**：含有函数属性的对象会抛出 `DataCloneError`
- **不支持 Symbol 键属性**：Symbol 类型的键会被丢弃
- **不支持类的实例**：如果对象是某个 class 的实例，拷贝后只是一个普通对象（丢失原型链和方法）
- **不支持 DOM 节点**：尝试克隆 DOM 元素会抛错
- **不支持 `Error` 及其子类对象**：部分环境支持，但不保证跨平台一致

```javascript
class Person {
  constructor(name) { this.name = name; }
  greet() { return `你好，我是${this.name}`; }
}

const p = new Person('张三');
const cloneP = structuredClone(p);

console.log(cloneP.name);     // "张三" ✅ 数据保留了
console.log(cloneP.greet);    // undefined ❌ 方法丢了！
console.log(cloneP instanceof Person);  // false ❌ 不是 Person 的实例了！
```

### 方式三：手写递归深拷贝 —— 最灵活的方案

为了应对各种复杂场景，我们常常需要自己实现一个深拷贝函数。这是一个经典的面试题，也是理解 JavaScript 数据类型和对象系统的绝佳练习。

#### 版本一：基础递归实现

```javascript
function deepClone(source) {
  // 基础情况：非对象类型直接返回（基本类型天然是"深拷贝"的）
  if (source === null || typeof source !== 'object') {
    return source;
  }

  // 判断是数组还是普通对象，保持类型一致性
  const target = Array.isArray(source) ? [] : {};

  // 遍历所有自有属性（包括不可枚举的）
  for (let key of Object.keys(source)) {
    const value = source[key];
    // 递归处理每个属性值
    target[key] = deepClone(value);
  }

  return target;
}

// 测试
const original = {
  name: '测试',
  scores: [90, 80, 70],
  info: {
    city: '上海',
    contacts: { email: 'test@example.com' }
  }
};

const cloned = deepClone(original);
cloned.scores.push(60);
cloned.info.city = '北京';
cloned.info.contacts.email = 'changed@example.com';

console.log(original.scores);                 // [90, 80, 70] ✅
console.log(original.info.city);              // "上海" ✅
console.log(original.info.contacts.email);   // "test@example.com" ✅
```

这个基础版本可以处理大多数常见的嵌套对象和数组场景。但它还有很多不足之处——接下来我们逐步增强它。

#### 版本二：处理循环引用

上面的版本遇到循环引用会陷入无限递归，最终导致栈溢出（Stack Overflow）：

```javascript
const cyclicObj = { name: '循环' };
cyclicObj.self = cyclicObj;

deepClone(cyclicObj);  // 💥 Maximum call stack size exceeded（栈溢出）
```

解决方案是引入一个 **WeakMap** 来记录已经拷贝过的对象及其对应的副本：

```javascript
function deepCloneWithCycle(source, hash = new WeakMap()) {
  // 基础情况：非对象
  if (source === null || typeof source !== 'object') {
    return source;
  }

  // 如果这个对象已经被拷贝过，直接返回之前的副本
  if (hash.has(source)) {
    return hash.get(source);
  }

  // 保持类型
  const target = Array.isArray(source) ? [] : {};

  // 在开始拷贝前，先将映射存入 hash（防止循环引用）
  hash.set(source, target);

  // 遍历并递归拷贝每个属性
  for (let key of Object.keys(source)) {
    target[key] = deepCloneWithCycle(source[key], hash);
  }

  return target;
}

// 测试循环引用
const cyclicObj = { name: '循环' };
cyclicObj.self = cyclicObj;

const clonedCyclic = deepCloneWithCycle(cyclicObj);
console.log(clonedCyclic.self === clonedCyclic);  // true ✅ 循环关系保持正确
console.log(clonedCyclic === cyclicObj);           // false ✅ 是新对象
```

**为什么用 WeakMap 而不是 Map 或普通对象？** 因为 WeakMap 的键是弱引用——当外部不再持有对原始对象的引用时，WeakMap 中的记录会被垃圾回收器自动清理，避免内存泄漏。对于深拷贝这种可能临时处理大量对象的场景，使用 WeakMap 是更安全的做法。

关于 WeakMap 的更多细节，参见《[WeakMap/WeakSet 内存管理](/frontend/javascript/language-async/weakmap-weakset-memory-management)》。

#### 版本三：处理特殊类型

完善版的深拷贝需要能够识别和处理各种特殊的内置对象类型：

```javascript
function deepCloneAdvanced(source, hash = new WeakMap()) {
  // ====== 基础类型直接返回 ======
  if (source === null || typeof source !== 'object') {
    return source;
  }

  // ====== 循环引用检测 ======
  if (hash.has(source)) {
    return hash.get(source);
  }

  // ====== 特殊类型处理 ======

  // Date
  if (source instanceof Date) {
    return new Date(source.getTime());
  }

  // RegExp
  if (source instanceof RegExp) {
    return new RegExp(source.source, source.flags);
  }

  // Map —— 需要递归拷贝每一个 key-value
  if (source instanceof Map) {
    const target = new Map();
    hash.set(source, target);
    source.forEach((value, key) => {
      target.set(deepCloneAdvanced(key, hash), deepCloneAdvanced(value, hash));
    });
    return target;
  }

  // Set —— 需要递归拷贝每一个元素
  if (source instanceof Set) {
    const target = new Set();
    hash.set(source, target);
    source.forEach(value => {
      target.add(deepCloneAdvanced(value, hash));
    });
    return target;
  }

  // ArrayBuffer / TypedArray
  if (ArrayBuffer.isView(source)) {
    // DataView 或 TypedArray (Uint8Array, Float32Array, etc.)
    return new source.constructor(source);
  }

  // ====== 普通对象或数组 ======
  const target = Array.isArray(source) ? [] : {};
  
  // 先注册映射，防止自引用
  hash.set(source, target);

  // 包含不可枚举属性 + Symbol 属性
  const allKeys = [
    ...Object.keys(source),
    ...Object.getOwnPropertySymbols(source)
  ];

  for (let key of allKeys) {
    const desc = Object.getOwnPropertyDescriptor(source, key);
    
    if (desc.value !== undefined) {
      // 数据属性
      Object.defineProperty(target, key, {
        ...desc,
        value: deepCloneAdvanced(desc.value, hash)
      });
    } else if (desc.get || desc.set) {
      // 访问器属性 —— getter/setter 无法被真正"拷贝"
      // 最佳方案是将 getter 的当前值作为数据属性拷贝过去
      // 或者选择跳过访问器属性（取决于需求）
      try {
        const currentValue = source[key];  // 触发 getter
        Object.defineProperty(target, key, {
          enumerable: desc.enumerable,
          configurable: desc.configurable,
          writable: true,
          value: deepCloneAdvanced(currentValue, hash)
        });
      } catch (e) {
        // getter 抛错了，跳过此属性
      }
    }
  }

  return target;
}
```

#### 版本四：完整的生产级实现

结合以上所有能力，下面是一个相对完善的深拷贝函数：

```javascript
/**
 * 高级深拷贝函数
 * 支持类型：基本类型、普通对象、数组、Date、RegExp、Map、Set、
 *          ArrayBuffer/TypedArray、循环引用、不可枚举属性、Symbol 属性
 * 
 * @param {*} source - 要拷贝的值
 * @param {WeakMap} [hash=new WeakMap()] - 内部使用的循环引用检测表
 * @returns {*} 拷贝结果
 */
function smartClone(source, hash = new WeakMap()) {
  // ─── 第一步：基础守卫 ───
  
  // null 和 undefined
  if (source === null || source === undefined) {
    return source;
  }
  
  // 基本类型（string, number, boolean, bigint, symbol）
  if (typeof source !== 'object') {
    return source;
  }
  
  // 函数（通常不需要拷贝，共享引用即可；也可以选择抛错或返回新函数）
  if (typeof source === 'function') {
    // 策略 A：返回原函数引用
    return source;
    // 策略 B：如果想"克隆"函数，可以通过 toString + eval（不推荐）
    // 策略 C：明确拒绝
    // throw new Error('Cannot clone function');
  }
  
  // ─── 第二步：循环引用检测 ───
  if (hash.has(source)) {
    return hash.get(source);
  }
  
  // ─── 第三步：内置特殊类型 ───
  
  if (source instanceof Date) {
    return new Date(source.getTime());
  }
  
  if (source instanceof RegExp) {
    return new RegExp(source.source, source.flags);
  }
  
  if (source instanceof Error) {
    // Error 对象比较特殊，message 和 stack 可以复制
    const err = new source.constructor(source.message);
    err.stack = source.stack;  // stack 通常是只读的，这里尽力而为
    return err;
  }
  
  if (source instanceof Map) {
    const clone = new Map();
    hash.set(source, clone);
    source.forEach((value, key) => {
      clone.set(smartClone(key, hash), smartClone(value, hash));
    });
    return clone;
  }
  
  if (source instanceof Set) {
    const clone = new Set();
    hash.set(source, clone);
    source.forEach(value => {
      clone.add(smartClone(value, hash));
    });
    return clone;
  }
  
  if (ArrayBuffer.isView(source)) {
    // TypedArray 和 DataView
    return new source.constructor(source.buffer.slice(source.byteOffset, 
                                                       source.byteOffset + source.byteLength));
  }
  
  if (source instanceof ArrayBuffer) {
    return source.slice(0);
  }
  
  // ─── 第四步：普通对象/数组 ───
  
  // 保持构造类型（但要注意不要调用构造函数！）
  let clone;
  
  if (Array.isArray(source)) {
    clone = [];
  } else if (source.constructor && source.constructor !== Object) {
    // 自定义类的实例 —— 用 Object.create 保持原型链
    clone = Object.create(Object.getPrototypeOf(source));
  } else {
    clone = {};
  }
  
  // 注册到哈希表
  hash.set(source, clone);
  
  // 遍历所有自有属性（包括 Symbol 和不可枚举的）
  const allKeys = Reflect.ownKeys(source);
  
  for (let key of allKeys) {
    const descriptor = Object.getOwnPropertyDescriptor(source, key);
    
    if ('value' in descriptor) {
      // 数据属性 —— 递归深拷贝值
      Object.defineProperty(clone, key, {
        ...descriptor,
        value: smartClone(descriptor.value, hash)
      });
    } else if (descriptor.get || descriptor.set) {
      // 访问器属性 —— 尝试获取当前值后转为数据属性
      // 这是一种务实的策略：getter 的"快照"比丢失属性要好
      let value;
      try {
        value = source[key];
      } catch {
        continue;  // getter 出错则跳过
      }
      
      Object.defineProperty(clone, key, {
        configurable: descriptor.configurable,
        enumerable: descriptor.enumerable,
        writable: true,
        value: smartClone(value, hash)
      });
    }
  }
  
  return clone;
}

// ═══════════════════════════════════════
// 综合测试
// ═══════════════════════════════════════

const complexObj = {
  str: '字符串',
  num: 42,
  bool: true,
  nil: null,
  date: new Date('2024-06-15'),
  regex: /^[a-z]+$/i,
  map: new Map([['a', 1], ['b', 2]]),
  set: new Set([10, 20, 30]),
  nested: {
    level2: {
      level3: {
        data: '深层'
      }
    }
  },
  array: [1, { x: 2 }, [3, [4]]],
  fn: function example() { return 'hi'; }
};

// 添加循环引用
complexObj.circular = complexObj;
complexObj.nested.parent = complexObj;

const cloned = smartClone(complexObj);

// 验证独立性
cloned.num = 999;
cloned.nested.level2.level3.data = '被修改';
cloned.array[1].x = 999;
cloned.date.setTime(0);

console.log(complexObj.num);                       // 42 ✅
console.log(complexObj.nested.level2.level3.data); // "深层" ✅
console.log(complexObj.array[1].x);                // 2 ✅
console.log(+complexObj.date);                     // 1718419200000 ✅（未被改为 0）

// 验证特殊类型
console.log(cloned.date instanceof Date);          // true
console.log(cloned.regex instanceof RegExp);       // true
console.log(cloned.map instanceof Map);            // true
console.log(cloned.set instanceof Set);            // true
console.log(cloned.map.get('a'));                 // 1
console.log(cloned.circular === cloned);           // true（循环引用正确）
console.log(cloned.nested.parent === cloned);      // true（跨层级循环正确）

// 验证原对象未被修改
console.log(cloned !== complexObj);                // true（完全独立的新对象）
```

## 原型链在拷贝中的行为

拷贝操作与原型链之间的交互是一个容易被忽视但非常重要的知识点。不同拷贝方式对原型链的处理策略各不相同，了解这些差异可以帮助你避免一些微妙的 Bug。

### 赋值：共享一切（包括原型链）

```javascript
function Dog(name) {
  this.name = name;
}
Dog.prototype.bark = function() { return `${this.name}: 汪汪!`; };

const dog1 = new Dog('旺财');
const dog2 = dog1;  // 赋值

dog2.name = '小黑';
console.log(dog1.name);  // "小黑" —— 共享同一个对象
console.log(dog1.bark()); // "小黑: 汪汪!" —— 共享同一个原型链
```

赋值之后，两个变量指向完全相同的对象——包括其原型链。没有任何东西是独立的。

### 浅拷贝：丢失原型链

```javascript
function Cat(name) {
  this.name = name;
}
Cat.prototype.meow = function() { return `${this.name}: 喵~`; };

const cat1 = new Cat('咪咪');

// 浅拷贝
const cat2 = { ...cat1 };
// 或者: const cat2 = Object.assign({}, cat1)

console.log(cat2.name);       // "咪咪" ✅ 自有属性被复制了
console.log(cat2.meow());    // 💥 TypeError: cat2.meow is not a function!
console.log(cat2 instanceof Cat);  // false ❌ 不再是 Cat 的实例
```

这是一个非常关键的发现：**浅拷贝（`Object.assign` 和展开运算符）只会复制对象的自有可枚举属性，完全不会处理原型链。** 拷贝出来的对象的原型默认是 `Object.prototype`，而不是原来的构造函数的 `prototype`。

这意味着如果你的代码依赖于 `instanceof` 检查或原型链上的方法，浅拷贝可能会破坏这些逻辑：

```javascript
// 场景：事件系统中的事件对象
class CustomEvent {
  constructor(type, data) {
    this.type = type;
    this.data = data;
    this.timestamp = Date.now();
  }
  isExpired(maxAge) {
    return Date.now() - this.timestamp > maxAge;
  }
}

const event = new CustomEvent('click', { x: 100, y: 200 });

// 开发者想保存事件的快照用于日志
const snapshot = { ...event };

console.log(snapshot.type);           // "click" ✅
console.log(snapshot.isExpired);       // undefined ❌ 方法丢了！
console.log(event.isExpired(1000));   // false（正常工作）
// snapshot.isExpired(1000);          // 💥 TypeError
```

### 如何在浅拷贝时保留原型链？

如果你需要在拷贝时同时保留原型链，可以使用 `Object.create()` 配合属性描述符：

```javascript
function shallowCloneWithPrototype(source) {
  // 以原对象的原型为原型，创建新对象
  const clone = Object.create(Object.getPrototypeOf(source));
  
  // 复制所有自有属性的描述符（不仅仅是可枚举的）
  const descriptors = Object.getOwnPropertyDescriptors(source);
  Object.defineProperties(clone, descriptors);
  
  return clone;
}

// 测试
const cat1 = new Cat('咪咪');
const cat2 = shallowCloneWithPrototype(cat1);

console.log(cat2.name);              // "咪咪" ✅
console.log(cat2.meow());            // "咪咪: 喵~" ✅ 方法还在！
console.log(cat2 instanceof Cat);    // true ✅ 类型保持！
console.log(cat2 === cat1);          // false ✅ 是新对象！
```

这种方式的原理是：先用 `Object.create(prototype)` 创建一个具有正确原型的新空对象，然后用 `getOwnPropertyDescriptors` 获取原对象所有自有属性的完整描述符（包括 `writable`、`enumerable`、`configurable`、以及 get/set），最后用 `defineProperties` 将这些描述符一一应用到新对象上。这样既实现了浅拷贝，又保留了原型链和属性特征。

### 深拷贝与原型链

大多数深拷贝实现（包括 `structuredClone()` 和我们手写的版本）都**不会保留自定义原型链**。原因在于：深拷贝的目标通常是**数据的完整性**，而非对象的身份标识（identity）。

```javascript
class User {
  constructor(name) { this.name = name; }
  greet() { return `你好，我是 ${this.name}`; }
}

const user = new User('张三');
const clonedUser = structuredClone(user);

console.log(clonedUser.name);            // "张三" ✅
console.log(clonedUser.greet);           // undefined ❌
console.log(clonedUser instanceof User); // false ❌
```

如果你确实需要在深拷贝的同时保留原型链，可以在我们的高级深拷贝函数中增加相应的处理逻辑——如前面版本四中演示的那样，使用 `Object.create(Object.getPrototypeOf(source))` 来创建带有正确原型的克隆对象。但需要注意：这可能会导致某些类的不变量（Invariant）被破坏——比如类的私有字段（`#field`）是无法在外部复制的。

## 各种拷贝方式的完整对比

为了让你的决策更加清晰，下面是一份全面的对比表：

### 性能基准参考

以下是大致的性能排名（从快到慢）：

```
赋值 > Object.assign ≈ 展开运算符 > slice/concat > structuredClone > 手写深拷贝 > JSON.parse(JSON.stringify())
```

具体耗时取决于数据的大小和结构复杂度。对于简单的扁平对象（少于 10 个属性），`Object.assign` 和展开运算符的性能差异可以忽略不计。对于大型嵌套对象（数百个属性，多层嵌套），`structuredClone` 由于是浏览器原生实现的，通常会比手写 JavaScript 递归快不少。`JSON.parse(JSON.stringify())` 的瓶颈在于序列化/反序列化的开销——对于超大对象可能比手写深拷贝还要慢。

## 实际工程中的应用策略

### 场景一：React/Vue 状态更新中的不可变模式

在现代前端框架中，**不可变性（Immutability）** 是核心范式之一。你需要频繁地创建状态的副本并进行修改，而不是直接修改原始状态：

```javascript
// React 中的常见模式：更新嵌套状态
const [user, setUser] = useState({
  name: '张三',
  profile: {
    nickname: '阿三',
    avatar: '/avatars/default.png',
    settings: {
      theme: 'dark',
      language: 'zh-CN'
    }
  }
});

// ❌ 错误做法：直接修改（违反不可变原则）
user.profile.settings.theme = 'light';

// ✅ 正确做法：使用展开运算符逐层展开
setUser({
  ...user,
  profile: {
    ...user.profile,
    settings: {
      ...user.profile.settings,
      theme: 'light'
    }
  }
});
```

这种"层层展开"的模式虽然繁琐，但它保证了每一层都是新的引用，让 React 能够准确地检测到变化并触发重新渲染。如果你嫌这种方式太冗长，可以考虑使用 Immer 这样的库——它在内部自动处理了深拷贝和变更追踪的工作。

### 场景二：配置对象的合并与覆盖

在库/框架开发中，经常需要将用户提供的配置与默认配置进行合并：

```javascript
const DEFAULT_CONFIG = {
  debug: false,
  timeout: 5000,
  retries: 3,
  theme: {
    primaryColor: '#1890ff',
    fontSize: 14
  },
  callbacks: {
    onSuccess: null,
    onError: null,
    onFinally: null
  }
};

function mergeConfig(userConfig) {
  // 浅拷贝默认配置作为基底
  const merged = { ...DEFAULT_CONFIG };
  
  if (!userConfig) return merged;
  
  // 递归合并 —— 对于对象类型的属性进行深度合并，
  // 对于基本类型的属性直接覆盖
  for (let key of Object.keys(userConfig)) {
    if (
      typeof userConfig[key] === 'object' &&
      userConfig[key] !== null &&
      !Array.isArray(userConfig[key]) &&
      typeof merged[key] === 'object' &&
      merged[key] !== null
    ) {
      // 对象类型 → 递归合并
      merged[key] = mergeConfig.call(null, userConfig[key], merged[key]);
    } else {
      // 基本类型或数组 → 直接覆盖
      merged[key] = userConfig[key];
    }
  }
  
  return merged;
}

// 使用
const userOptions = {
  timeout: 10000,
  theme: {
    primaryColor: '#f5222d'  // 只覆盖主题色，fontSize 保留默认值
  }
};

const finalConfig = mergeConfig(userOptions);
console.log(finalConfig);
// {
//   debug: false,           // 默认值
//   timeout: 10000,         // 用户覆盖
//   retries: 3,             // 默认值
//   theme: {
//     primaryColor: '#f5222d',  // 用户覆盖
//     fontSize: 14              // 默认值保留
//   },
//   callbacks: { ... }       // 默认值
// }
```

这种**深度合并（Deep Merge）**模式在配置管理中极为常见——它介于浅拷贝和深拷贝之间：对于嵌套对象执行"选择性合并"而非完全替换，对于基本类型执行覆盖。

### 场景三：撤销/重做（Undo/Redo）系统

编辑类应用（富文本编辑器、图形设计工具、表格软件等）都需要实现撤销/重做功能。其核心思想就是维护一个**历史状态栈**，每次操作前都要对当前状态做一次深拷贝：

```javascript
class HistoryManager {
  #undoStack = [];   // 撤销栈
  #redoStack = [];   // 重做栈
  #currentState;
  
  constructor(initialState) {
    // 深拷贝初始状态作为起点
    this.#currentState = smartClone(initialState);
  }
  
  get state() {
    return this.#currentState;
  }
  
  // 执行新操作
  execute(action) {
    // 在修改前，先把当前状态压入撤销栈
    this.#undoStack.push(smartClone(this.#currentState));
    
    // 执行 action，修改 currentState
    this.#currentState = action(this.#currentState);
    
    // 清空重做栈（新操作使重做失效）
    this.#redoStack = [];
  }
  
  undo() {
    if (this.#undoStack.length === 0) return false;
    
    // 当前状态压入重做栈
    this.#redoStack.push(smartClone(this.#currentState));
    
    // 弹出撤销栈顶作为当前状态
    this.#currentState = this.#undoStack.pop();
    
    return true;
  }
  
  redo() {
    if (this.#redoStack.length === 0) return false;
    
    // 当前状态压入撤销栈
    this.#undoStack.push(smartClone(this.#currentState));
    
    // 弹出重做栈顶作为当前状态
    this.#currentState = this.#redoStack.pop();
    
    return true;
  }
}

// 使用示例
const editor = new HistoryManager({
  text: 'Hello',
  cursor: { line: 0, column: 5 },
  selection: null
});

editor.execute(state => ({ ...state, text: 'Hello World' }));
editor.execute(state => ({ ...state, text: 'Hello World!', cursor: { line: 0, column: 12 } }));

editor.undo();
console.log(editor.state.text);  // "Hello World"

editor.undo();
console.log(editor.state.text);  // "Hello"

editor.redo();
console.log(editor.state.text);  // "Hello World"
```

在这种场景中，**深拷贝的质量直接决定了撤销/重做功能的可靠性**。如果使用了错误的浅拷贝，那么"撤销"操作可能无法真正恢复到之前的状态——因为历史栈中的状态可能已经被后续操作通过共享引用篡改了。

### 场景四：缓存与快照

服务端渲染（SSR）、离线缓存、数据导出等场景都需要对数据进行"冻结"式的快照：

```javascript
// 服务端：生成页面快照用于缓存
function generatePageSnapshot(requestData) {
  // 从数据库/API 获取数据
  const liveData = fetchPageData(requestData);
  
  // 深拷贝作为快照 —— 后续对 liveData 的修改不会影响缓存
  const snapshot = structuredClone(liveData);
  
  cache.set(requestData.url, {
    data: snapshot,
    generatedAt: Date.now(),
    ttl: 300000  // 5分钟过期
  });
  
  return liveData;  // 返回原始数据供继续处理
}
```

## 哲学思考：拷贝背后的设计哲学

### 身份 vs 相等：拷贝的根本困境

当我们说"拷贝一个对象"时，一个深刻的哲学问题是：**什么样的两个对象才算"拷贝成功"？**

是数据相等就行？（即 `a.name === b.name && a.age === b.age && ...`）还是身份也要保持？（即 `b` 应该是 `a` 所属类的实例？）还是行为也要一致？（即 `b` 上能调用 `a` 所有的方法？）

这个问题没有标准答案——它取决于你的具体需求：

- **纯数据传输场景**（如 API 响应、缓存存储）：只需要数据相等就够了。`structuredClone()` 或 `JSON.parse(JSON.stringify())` 通常足够。
- **面向对象建模场景**（如领域对象、实体）：你可能需要保留原型链甚至类身份。这时需要定制化的深拷贝策略。
- **UI 状态场景**（如 React/Vue 的 state）：你需要的是引用的变化（以触发更新）加上数据的准确性。浅拷贝 + 层层展开往往是最优解。

### 性能与正确性的权衡

拷贝操作本质上是一种**时间换安全性**的策略。你不拷贝，代码跑得更快，但你冒着被意外修改的风险。你做了深拷贝，数据绝对安全，但你付出了时间和内存的代价。

优秀的工程师会在不同的场景中做出合理的取舍：

- **热路径代码**（每秒执行数千次的渲染循环、物理引擎计算）：优先考虑性能，尽量使用浅拷贝或不拷贝（通过约定来避免修改）
- **冷路径代码**（初始化、配置加载、导出操作）：优先考虑正确性和安全性，使用深拷贝
- **边界代码**（API 接口、第三方集成）：永远假设输入是不可信的，进入内部前先做防御性拷贝

### "共享"的价值不应被低估

在讨论拷贝的时候，很容易陷入"拷贝越多越安全"的思维陷阱。但事实上，**共享引用在很多场景下不仅是合理的，而且是必要的**：

- **单一数据源（Single Source of Truth）**：Redux/Vuex store 之所以有效，就是因为所有组件共享同一个状态引用。如果每个组件都持有一个深拷贝副本，那状态同步就会变成噩梦。
- **观察者模式（Observer Pattern）**：被观察者和观察者之间共享同一个对象引用，才能实现对变化的实时感知。
- **性能敏感的大数据**：3D 游戏引擎中的顶点数据、图像处理中的像素缓冲区——拷贝几兆甚至几百兆的数据是不现实的。

关键在于：**有意为之的共享是设计，无意造成的共享是 Bug。** 当你选择不拷贝时，确保这是经过深思熟虑的决定，并且有配套的约束机制（如 `Object.freeze`、只读代理、文档约定）来保护共享的数据不被意外修改。

### 拷贝与不变性（Immutability）的关系

拷贝是**被动的不变性**——你通过创建副本来保护原始数据不被修改。而**主动的不变性**（如 Immutable.js、Immer、`Object.freeze`）则是从源头禁止修改。

这两种策略并不是互斥的，而是互补的：

```javascript
// 策略 1：拷贝保护（被动）
function updateName(user, newName) {
  const copy = { ...user };  // 先拷贝
  copy.name = newName;       // 再修改副本
  return copy;               // 返回新对象
}

// 策略 2：冻结保护（主动）
function createFrozenUser(data) {
  return Object.freeze({ ...data });  // 创建后立即冻结
}
const frozenUser = createFrozenUser({ name: '张三' });
frozenUser.name = '李四';  // 严格模式下 TypeError

// 策略 3：Immer —— 写时拷贝（Copy-on-Write）
import { produce } from 'immer';

const nextState = produce(baseState, draft => {
  draft.name = '新名字';  // 看起来像直接修改，实则 Immer 自动处理了深拷贝
});
```

最好的策略往往是组合式的：对外接口提供不可变的视图（freeze/readonly proxy），内部在必要时使用高效的浅拷贝或写时拷贝（copy-on-write）来优化性能。

## 总结：如何选择正确的拷贝方式

### 决策流程

面对一个需要"复制对象"的场景，你可以按照以下思路做出选择：

```
需要复制对象吗？
│
├─→ 只是需要另一个引用同一份数据的变量？
│   └─→ 直接赋值 (=) 即可
│
├─→ 需要一个独立的第一层副本？
│   ├─→ 数据是扁平的（无嵌套对象）？
│   │   └─→ 展开运算符 (...) 或 Object.assign()
│   │
│   └─→ 有嵌套对象但确定不会修改嵌套层？
│       └─→ 展开运算符 (...) 或 Object.assign()
│
├─→ 需要完全独立的副本（任何层级都不能互相影响）？
│   ├─→ 数据只包含 JSON 兼容的类型？
│   │   └─→ JSON.parse(JSON.stringify()) —— 最简单
│   │
│   ├─→ 有 Date/RegExp/Map/Set/ArrayBuffer 等特殊类型？
│   │   └─→ structuredClone() —— 现代浏览器首选
│   │
│   ├─→ 有函数、Symbol 键、不可枚举属性、或需要保留原型链？
│   │   └─→ 手写/使用库（lodash _.cloneDeep、ramda R.clone 等）
│   │
│   └─→ 有循环引用？
│       └─→ structuredClone() 或带 WeakMap 的手写实现
│
└─→ 需要在拷贝的同时保留原型链和类型信息？
    └─→ 自定义深拷贝（Object.create + getOwnPropertyDescriptors）
```

### 最终建议

**没有银弹。** 不同的拷贝方式解决不同层次的问题，各有适用范围和代价。真正的能力不在于背诵哪一种方式"最好"，而在于：

1. **理解每种方式的精确行为**——哪些层级被复制了、哪些只是共享引用、哪些特性会丢失
2. **清楚自己的需求**——是需要快速的第一层隔离，还是需要完全的数据独立，还需要保留类型信息
3. **做出知情的选择**——在性能、正确性、代码简洁度之间找到最适合当前场景的平衡点

> **拷贝看似是一个简单的"复制粘贴"操作，但其背后涉及了 JavaScript 语言中引用类型、原型链、属性描述符、垃圾回收、特殊内置类型等一系列核心概念。** 每一种拷贝方式都可以看作是这些概念的一个特定"切面"——它展示了在这个特定切面上，语言是如何权衡"便利性"与"安全性"、"性能"与"正确性"的。理解拷贝，就是理解 JavaScript 对象模型的本质。
