# `WeakMap` / `WeakSet` 在面向对象内存管理中的应用

> **核心内容**：JavaScript 垃圾回收机制与弱引用的本质、`Map` vs `WeakMap` 和 `Set` vs `WeakSet` 的完整对比、弱引用在私有属性实现、DOM 关联数据缓存、循环引用检测、观察者模式中的实战应用、以及"所有权（Ownership）"和"生命周期（Lifecycle）"的设计哲学。

## 一段看似正常的代码，正在悄悄吃掉你的内存

让我们从一个真实场景开始。这段代码看起来完全正常——它做的事情也很简单：给页面上的每个按钮绑定事件，并记录一些关联数据：

```javascript
const buttonData = new Map();

function setupButtons() {
  const buttons = document.querySelectorAll('.action-btn');
  
  buttons.forEach((btn, index) => {
    // 记录每个按钮的元数据
    buttonData.set(btn, {
      id: `btn_${index}`,
      clickCount: 0,
      createdAt: Date.now(),
      lastClickAt: null
    });
    
    // 绑定点击事件
    btn.addEventListener('click', () => {
      const data = buttonData.get(btn);
      data.clickCount++;
      data.lastClickAt = Date.now();
      console.log(`按钮 ${data.id} 被点击了 ${data.clickCount} 次`);
    });
  });
}

// 初始化
setupButtons();

// ... 一段时间后，用户触发了某种操作，这些按钮被从 DOM 中移除了
document.querySelectorAll('.action-btn').forEach(btn => btn.remove());
```

代码逻辑清晰、结构合理，没有任何明显的错误。但这里藏着一个**内存泄漏**：

**当按钮被从 DOM 移除后，`buttonData` 这个 Map 仍然强引用着每一个被移除的按钮元素对象。** 只要 `buttonData` 还活着（在这个例子中它是一个全局变量，永远不会被释放），那些已经不存在的 DOM 元素及其关联的数据就永远无法被垃圾回收器（Garbage Collector）回收。

如果这个页面频繁地创建和销毁按钮——比如一个动态列表、聊天消息区域、或者虚拟滚动组件——每次创建都会往 `buttonData` 里添加新记录，但旧记录永远不会被清除。随着时间推移，内存占用会持续增长。在单页应用（SPA）中运行几小时后，浏览器可能因为内存耗尽而变得极其卡顿甚至崩溃。

这就是 **"遗忘式泄漏（Forgotten Leak）"** 的典型模式：你忘记了在对象不再需要时清理对它的引用。

### 用 WeakMap 来解决

解决方案非常简单——把 `Map` 换成 `WeakMap`：

```javascript
const buttonData = new WeakMap();  // ← 就改这一行

function setupButtons() {
  const buttons = document.querySelectorAll('.action-btn');
  
  buttons.forEach((btn, index) => {
    buttonData.set(btn, {
      id: `btn_${index}`,
      clickCount: 0,
      createdAt: Date.now(),
      lastClickAt: null
    });
    
    btn.addEventListener('click', () => {
      const data = buttonData.get(btn);
      if (!data) return;  // 按钮可能已被回收
      
      data.clickCount++;
      data.lastClickat = Date.now();
      console.log(`按钮 ${data.id} 被点击了 ${data.clickCount} 次`);
    });
  });
}

setupButtons();

// 当按钮被从 DOM 移除后……
document.querySelectorAll('.action-btn').forEach(btn => btn.remove());

// 此时，如果没有其他地方持有对这些按钮的引用：
// ✅ 按钮的 DOM 元素可以被垃圾回收
// ✅ buttonData 中对应的条目也会自动消失
// ✅ 关联的数据对象也会被一起回收
```

**一行代码的改变，彻底消除了内存泄漏的风险。** 这就是 `WeakMap` 的威力——它不是通过让你"更小心地手动清理"来解决问题，而是从根本上改变了数据之间的引用关系，让垃圾回收器能够自动完成你容易忘记做的那件事。

本文将深入探讨 `WeakMap` 和 `WeakSet` 的工作原理、适用场景以及它们背后关于"所有权"和"生命周期"的设计哲学。

## 理解基础：JavaScript 的垃圾回收机制

要真正理解 WeakMap/WeakSet 的价值，必须先理解 JavaScript 的垃圾回收（Garbage Collection, GC）机制。它是所有"弱引用"概念的基础。

### 引用计数 vs 标记-清除

现代 JavaScript 引擎（如 V8、SpiderMonkey、JavaScriptCore）主要使用的是**标记-清除（Mark-and-Sweep）**算法来管理内存。其简化工作流程如下：

```
1. 从根对象（Roots）开始遍历：
   - 全局变量
   - 当前调用栈中的局部变量
   - 浏览器环境中的 DOM 节点等

2. 标记阶段（Mark）：
   - 从根出发，递归标记所有"可达"（Reachable）的对象
   - "可达"意味着存在一条由强引用组成的路径从根到该对象
   
3. 清除阶段（Sweep）：
   - 扫描整个堆内存
   - 回收所有未被标记的对象（即不可达对象）
   - 将其占用的内存空间归还给系统
```

关键概念：**一个对象能否被回收，取决于它是否仍然"可达"——即是否存在一条从 GC Root 到该对象的强引用链路。**

```javascript
let user = { name: '张三' };  // user 是一个根引用（全局或局部变量）
let admin = user;              // admin 也引用同一个对象 —— 强引用

user = null;                   // 切断 user 的引用
// 此时对象仍然通过 admin 可达 → 不会被回收

admin = null;                  // 切断 admin 的引用
// 此时对象不再可达 → 下次 GC 时会被回收 ✅
```

### 什么是"强引用"？什么是"弱引用"?

这是理解 WeakMap/WeakSet 最核心的概念：

- **强引用（Strong Reference）**：普通的变量赋值、数组元素、对象属性、Map/Set 中的条目——这些都构成强引用。只要一个对象被至少一个强引用所指向，垃圾回收器就不会回收它。
- **弱引用（Weak Reference）**：一种特殊的引用方式，它允许你访问一个对象，但不阻止该对象被垃圾回收。换句话说，**弱引用不会让对象保持"可达"状态。**

```javascript
// 强引用示例（普通 Map）
let obj = { key: '数据' };
let strongMap = new Map();
strongMap.set(obj, '关联数据');

obj = null;  // 删除了直接变量引用
// 但是！strongMap 仍然强引用着 { key: '数据' } 对象
// → 对象不会被回收 ❌

// 弱引用示例（WeakMap）
let obj2 = { key: '数据2' };
let weakMap = new WeakMap();
weakMap.set(obj2, '关联数据');

obj2 = null;  // 删除了直接变量引用
// weakMap 中的引用是弱引用，不计入可达性判断
// → 如果没有其他强引用指向 { key: '数据2' }，它可以被回收 ✅
```

### 通俗类比：绳索与丝线

想象一下你在放风筝：

- **强引用就像一根粗绳子**——你用粗绳子系住风筝。即使风筝飞远了，只要你手里拽着这根绳子，风筝就不会飘走。无论谁来检查，都能顺着绳子找到风筝。
- **弱引用就像一根细细的蚕丝线**——它也连着风筝，但这根丝太细了，风一吹就会断。如果没有人再用粗绳子牵着这只风筝（没有其他强引用），那么风筝随时可能飘走，而那根丝线对此无能为力——它只能眼睁睁地看着风筝离开。

**WeakMap/WeakMap 中的键就是用这种"蚕丝线"系着的。** 当外部所有的"粗绳子"都松开之后（没有其他强引用），GC 可以毫不犹豫地把对象收走，同时 WeakMap 中的对应条目也自动消失。

## WeakMap 详解：弱键值的映射表

### 基本语法与 API

`WeakMap` 是 ES2015（ES6）引入的数据结构，它的 API 表面看起来和 `Map` 非常相似：

```javascript
const wm = new WeakMap();

// 设置键值对（键必须是对象或 Symbol，不能是基本类型）
wm.set({ id: 1 }, '值1');
wm.set({ id: 2 }, '值2');
wm.set(document.querySelector('#app'), { metadata: '应用节点' });

// 读取值
console.log(wm.get(someObject));     // 存在则返回对应的值，否则返回 undefined

// 检查是否有某键
console.log(wm.has(someObject));     // true 或 false

// 删除某个键
wm.delete(someObject);               // 返回 true 表示成功删除
```

但与 `Map` 相比，`WeakMap` 有几个**关键的差异和限制**：

| 特性 | `Map` | `WeakMap` |
|------|-------|-----------|
| **键的类型** | 任意值（含基本类型、对象、函数） | 仅 **对象** 和 **Symbol** |
| **键的引用强度** | **强引用** | **弱引用** |
| **可枚举性** | 支持 `keys()`、`values()`、`entries()` | ❌ 不支持任何迭代/枚举操作 |
| **size 属性** | ✅ `map.size` | ❌ 没有 size 属性 |
| **clear() 方法** | ✅ 清空所有条目 | ❌ 不支持 |
| **for...of 遍历** | ✅ 可遍历 | ❌ 不可遍历 |

### 为什么不能遍历 WeakMap？

这是一个经常被问到的问题。答案深刻地揭示了弱引用的语义本质：

**如果 WeakMap 支持遍历（比如 `keys()` 或 `values()`），就意味着你能获取到其中存储的所有键对象。但这些键对象都是弱引用持有的——它们可能在遍历过程中的任意时刻被垃圾回收掉。**

这就产生了一个根本性的矛盾：**你无法可靠地列出"当前存在的所有弱引用键"，因为在你的代码执行间隙，GC 可能已经回收了其中的一部分。**

ECMAScript 规范委员会做出了一个明智的决定：既然无法提供一致可靠的枚举行为，那就干脆不支持枚举。这让 WeakMap 的行为变得完全可预测——你只能通过已知的键来查询，而不能"窥探"里面到底有什么。

```javascript
const wm = new WeakMap();

// 这些都不存在：
// wm.keys();       // TypeError: wm.keys is not a function
// wm.values();     // TypeError
// wm.entries();    // TypeError
// wm.forEach(...); // TypeError
// for (let [k,v] of wm) {}  // TypeError: wm is not iterable
// wm.size          // undefined
// wm.clear()       // TypeError

// 你能做的只有这三件事：
wm.get(key);        // 通过已知键取值
wm.has(key);        // 检查已知键是否存在
wm.set(key, value); // 设置键值对
wm.delete(key);     // 删除指定键
```

### 为什么键必须是对象或 Symbol？

同样出于弱引用的一致性考虑。基本类型（number、string、boolean 等）在 JavaScript 中是**不可变的值（Immutable Value）**，它们不存在"被回收"这个概念——字面量 `42` 就是 `42`，它不需要也不应该被垃圾回收。因此，对基本类型使用弱引用是没有意义的。

只有对象（包括数组、函数、正则表达式、Date 实例等引用类型）才存在"生命周期"——它们被创建、被使用、最终可能被销毁。弱引用的意义正是在于**不干预这个自然的生命周期过程**。

```javascript
const wm = new WeakMap();

wm.set('stringKey', 'value');  // 💥 TypeError: Invalid value used as WeakMap key
wm.set(42, 'value');           // 💥 TypeError: Invalid value used as WeakMap key
wm.set(true, 'value');         // 💥 TypeError: Invalid value used as WeakMap key

wm.set({}, 'value');           // ✅ 对象作为键
wm.set([], 'value');           // ✅ 数组也是对象
wm.set(function(){}, 'value'); // ✅ 函数也是对象
wm.set(Symbol('sym'), 'value');// ✅ Symbol 作为键（ES2023+）
```

> 注意：Symbol 作为 WeakMap 键的能力是在 ES2023 中添加的。在此之前的版本中，WeakMap 只接受对象作为键。

## WeakSet 详解：弱引用的成员集合

### 基本语法

`WeakSet` 与 `WeakMap` 类似，是 `Set` 的弱引用版本。它是一个只存储对象（不含值）的弱引用集合，主要用于检测"某个对象是否属于某个集合"：

```javascript
const ws = new WeakSet();

// 添加成员（必须是对象）
ws.add({ id: 1 });
ws.add([1, 2, 3]);
ws.add(document.body);

// 检测是否包含
console.log(ws.has(someObj));  // true 或 false

// 删除成员
ws.delete(someObj);            // 返回 boolean
```

WeakSet 同样受到以下限制：
- 只能存放**对象**（和 ES2023+ 的 Symbol）
- **不可遍历**
- **没有 size 属性**
- **没有 clear() 方法**

### WeakSet 的典型用途

WeakSet 最常见的用法是标记对象的某种"状态"或"身份"，而不需要在对象本身上添加额外属性：

```javascript
const visited = new WeakSet();

function traverseGraph(node) {
  // 避免重复访问（防止图遍历中的无限循环）
  if (visited.has(node)) {
    return;  // 已访问过，跳过
  }
  
  visited.add(node);  // 标记为已访问
  
  // 处理当前节点
  processNode(node);
  
  // 递归处理邻居节点
  node.neighbors?.forEach(neighbor => traverseGraph(neighbor));
}
```

这种模式的优势在于：
- 不需要修改原始对象（不用加 `node.visited = true` 属性）
- 当所有对某个节点的强引用都消失后，visited 集合中的弱引用条目也会自动消失
- 对于大型图的遍历，不会因 visited 集合积累过多已死节点的记录而造成内存浪费

## Map vs WeakMap / Set vs WeakSet 完整对比

为了让你在实际开发中做出准确的选择，下面是一份全面的对比分析：

### 功能覆盖对比

| 维度 | `Map` | `WeakMap` | `Set` | `WeakSet` |
|------|-------|-----------|-------|-----------|
| 键/成员类型 | 任意值 | **仅对象/Symbol** | 任意值 | **仅对象/Symbol** |
| 引用类型 | **强引用** | **弱引用** | **强引用** | **弱引用** |
| 可迭代（for...of） | ✅ | ❌ | ✅ | ❌ |
| keys()/values()/entries() | ✅ | ❌ | N/A（Set 无键值之分） | N/A |
| forEach() | ✅ | ❌ | ✅ | ❌ |
| size 属性 | ✅ | ❌ | ✅ | ❌ |
| clear() | ✅ | ❌ | ✅ | ❌ |
| JSON 序列化支持 | 需转换 | 需转换 | 需转换 | 需转换 |
| 适用场景 | 通用键值存储 | **关联数据的自动清理** | 去重/集合运算 | **身份标记/状态追踪** |

### 何时选择 WeakMap？何时选择 Map？

**选择 `Map` 的场景：**

- 你需要遍历所有键值对
- 你需要知道当前存了多少条目（size）
- 你的键可能是字符串、数字等基本类型
- 你需要一个持久的、不受 GC 影响的存储
- 数据的生命周期应该由你明确控制

```javascript
// 典型的 Map 使用场景：应用配置
const appConfig = new Map([
  ['debug', false],
  ['apiBase', 'https://api.example.com'],
  ['theme', 'dark']
]);

appConfig.forEach((value, key) => {
  console.log(`${key}: ${value}`);  // 遍历配置项
});
console.log(`共 ${appConfig.size} 项配置`);
```

**选择 `WeakMap` 的场景：**

- 你需要将附加数据与对象关联，且希望这些数据随对象的生命周期自动管理
- 你的键是 DOM 元素、对象实例等引用类型的实体
- 你不想（或无法可靠地）在对象被销毁时手动清理关联数据
- 你只需要"通过键来查值"，不需要反向列举

```javascript
// 典型的 WeakMap 使用场景：DOM 元素关联数据
const elementMetadata = new WeakMap();

function annotateElement(el, metadata) {
  elementMetadata.set(el, metadata);
  // el 被移除后，metadata 自动跟随回收
  // 无需在任何清理逻辑中手动删除
}
```

### 决策流程图

```
需要存储键值对吗？
│
├─→ 键是什么类型的？
│   │
│   ├─→ 基本类型（string/number）？
│   │   └─→ 必须用 **Map**
│   │
│   └─→ 对象/Symbol？
│       │
│       ├─→ 需要遍历/查看 size？
│       │   └─→ 用 **Map**
│       │
│       ├─→ 需要在对象被 GC 后自动清理关联数据？
│       │   └─→ 用 **WeakMap** ✅
│       │
│       └─→ 需要长期保存、不受 GC 影响？
│           └─→ 用 **Map**
```

## WeakMap 在面向对象编程中的五大实战应用

### 应用一：实现真正的私有属性（ES2022 # 之前的终极方案）

在 ES2022 引入 `#` 私有字段之前，`WeakMap` 是 JavaScript 中实现真正私有属性的**最优雅方案**之一。它在《[defineProperty 与枚举属性详解](/frontend/javascript/language-async/defineProperty-enumerable-properties)》中也有提及，这里我们展开更深入的讨论：

```javascript
// 私有数据的 WeakMap 存储容器
const _privateData = new WeakMap();

class BankAccount {
  constructor(owner, initialBalance) {
    // 私有数据存储在 WeakMap 中，以实例自身为键
    _privateData.set(this, {
      balance: initialBalance,
      pin: generateRandomPin(),
      transactions: [],
      createdAt: Date.now(),
      isFrozen: false
    });
  }
  
  deposit(amount) {
    const priv = _privateData.get(this);
    
    if (priv.isFrozen) throw new Error('账户已被冻结');
    if (amount <= 0) throw new Error('存款金额需大于0');
    
    priv.balance += amount;
    priv.transactions.push({
      type: 'DEPOSIT',
      amount,
      timestamp: Date.now()
    });
  }
  
  withdraw(amount, inputPin) {
    const priv = _privateData.get(this);
    
    if (inputPin !== priv.pin) throw new Error('密码错误');
    if (amount > priv.balance) throw new Error('余额不足');
    
    priv.balance -= amount;
    priv.transactions.push({
      type: 'WITHDRAW',
      amount,
      timestamp: Date.now()
    });
  }
  
  getBalance(inputPin) {
    const priv = _privateData.get(this);
    if (inputPin !== priv.pin) throw new Error('密码错误');
    return priv.balance;
  }

  getStatement(inputPin) {
    const priv = _privateData.get(this);
    if (inputPin !== priv.pin) throw new Error('密码错误');
    return {
      owner: this.owner,
      balance: priv.balance,
      transactionCount: priv.transactions.length,
      createdAt: new Date(priv.createdAt)
    };
  }
  
  freeze() {
    const priv = _privateData.get(this);
    priv.isFrozen = true;
  }
}

// 使用
const account = new BankAccount('张三', 10000);

account.deposit(5000);                    // 存款 5000
account.withdraw(2000, '123456');         // 取款 2000

console.log(account.getBalance('123456'));// 13000

// 尝试破坏封装
console.log(account.balance);             // undefined ❌ 无法访问
console.log(_privateData.get(account));   // undefined ❌ 外部无法拿到（_privateData 不暴露）

// 当 account 不再被任何地方引用时，
// WeakMap 中的私有数据也会被自动回收 ✅
account = null;
```

#### 为什么 WeakMap 比闭包更适合做私有属性？

你可能还记得《[工厂函数与构造函数对比](/frontend/javascript/language-async/factory-vs-constructor)》中介绍的闭包私有化方案。闭包确实也能实现私有属性，但 WeakMap 方案有几个独特优势：

**优势一：方法之间共享同一份私有数据**

闭包方案的每个方法各自形成独立的闭包，如果要共享私有数据，通常需要在一个更大的闭包中定义所有方法。而 WeakMap 方案中，所有方法都通过 `_privateData.get(this)` 访问同一份数据——自然共享、结构清晰。

**优势二：支持 instanceof 和原型链方法**

闭包方案通常配合工厂函数使用（返回一个新对象，方法定义在工厂内部），这意味着创建的实例不是构造函数的 `instanceof`，也无法利用原型链共享方法。WeakMap 配合 `class` 语法，既实现了真正的私有性，又保留了完整的 OOP 能力。

**优势三：内存自动管理**

当使用闭包时，只要工厂函数的作用域还存在，闭包中的私有变量就不会被回收——即使外部已经不再需要这个实例。而 WeakMap 会在键对象（即类实例）被 GC 回收后，自动释放对应的私有数据。对于大量创建和销毁实例的场景（如粒子系统、游戏对象），这是一个显著的内存优化。

**优势四：调试体验更好**

在现代浏览器开发者工具中，WeakMap 中的数据是可以被查看的（虽然不如直接看属性方便）。而闭包中的变量在调试时往往难以定位和检查。

### 应用二：DOM 元素的关联数据存储

这是 WeakMap 最经典的应用场景之一，也是我们开篇例子中解决的问题：

```javascript
class ElementDataManager {
  #store = new WeakMap();
  
  /**
   * 为 DOM 元素设置关联数据
   * @param {HTMLElement} el - 目标 DOM 元素
   * @param {object} data - 要关联的数据
   */
  set(el, data) {
    this.#store.set(el, {
      ...data,
      __meta__: {
        attachedAt: Date.now(),
        updatedAt: Date.now()
      }
    });
  }
  
  /**
   * 获取 DOM 元素的关联数据
   */
  get(el) {
    return this.#store.get(el);
  }
  
  /**
   * 更新关联数据
   */
  update(el, patch) {
    const existing = this.#store.get(el);
    if (!existing) return false;
    
    Object.assign(existing, patch);
    existing.__meta__.updatedAt = Date.now();
    return true;
  }
  
  /**
   * 移除关联数据（可选操作，不手动移除也不会泄漏）
   */
  remove(el) {
    return this.#store.delete(el);
  }
}

// ====== 实际使用 ======
const domStore = new ElementDataManager();

// 初始化表格行
document.querySelectorAll('tr[data-id]').forEach(row => {
  domStore.set(row, {
    rowId: row.dataset.id,
    originalColor: getComputedStyle(row).backgroundColor,
    isEditing: false,
    pendingChanges: {}
  });
  
  // 双击进入编辑模式
  row.addEventListener('dblclick', () => {
    const data = domStore.get(row);
    data.isEditing = true;
    enableEditMode(row);
  });
});

// 当表格行被动态替换或移除时
function replaceRow(oldRow, newRowHTML) {
  oldRow.outerHTML = newRowHTML;
  // 旧行的关联数据会随旧 DOM 元素一起被 GC 自动回收 ✅
  // 无需手动调用 domStore.remove(oldRow)!
}
```

#### 为什么不用 dataset？

你可能会问：HTML5 不是提供了 `element.dataset.xxx` 来存储自定义数据吗？为什么还需要 WeakMap？

`dataset` 确实可以用来存储数据，但它有严重的局限性：

| 维度 | `dataset` | `WeakMap` 存储 |
|------|----------|---------------|
| **值类型** | 只能是**字符串** | 任意类型（对象、函数、Map 等） |
| **命名冲突** | 可能与 CSS 选择器或其他库冲突 | 完全隔离，不影响 DOM |
| **性能** | 每次读写触发 DOM 操作 | 纯 JavaScript 操作，更快 |
| **可见性** | 出现在 HTML 属性中，可被审查元素看到 | 完全隐藏在 JS 层面 |
| **安全性** | 用户可通过 DevTools 看到/修改 | 外部无法探测 |

```javascript
// dataset 的局限
el.dataset.config = JSON.stringify({ debug: true, apiKey: 'sk_xxx' });  // 必须序列化为字符串
el.dataset.handler = '???';  // 怎么存函数？存不了！

// WeakMap 的自由
domStore.set(el, {
  config: { debug: true, apiKey: 'sk_xxx' },  // 直接存对象
  onClickHandler: () => handleSomething(el),     // 甚至可以存函数！
  cache: new Map(),                              // 可以嵌套任意复杂结构
  abortController: new AbortController()          // AbortController 实例
});
```

### 应用三：对象缓存与记忆化（Memoization）

WeakMap 天然适合用于**基于对象参数的缓存（Object-based Memoization）**。缓存的键是需要计算的对象，缓存的值是计算结果。当对象不再被使用时，缓存也应该随之失效——这正是弱引用擅长的：

```javascript
/**
 * 通用的对象级缓存装饰器
 * @param {Function} fn - 需要被缓存的函数（接收一个对象参数）
 * @returns {Function} 带有缓存功能的包装函数
 */
function memoize(fn) {
  const cache = new WeakMap();
  
  return function(obj) {
    if (cache.has(obj)) {
      console.log('📦 缓存命中');
      return cache.get(obj);
    }
    
    console.log('⏳ 正在计算...');
    const result = fn.call(this, obj);
    cache.set(obj, result);
    return result;
  };
}

// 示例：昂贵的 DOM 尺寸计算
const getBoundingClientRectCached = memoize(function(el) {
  // 这个计算会触发浏览器的 reflow/reflow，开销较大
  return el.getBoundingClientRect();
});

const box = document.querySelector('#main-content');

// 第一次调用：实际计算
const rect1 = getBoundingClientRectCached(box);  // ⏳ 正在计算...

// 第二次及以后（box 未变化）：直接返回缓存
const rect2 = getBoundingClientRectCached(box);  // 📦 缓存命中
console.log(rect1 === rect2);  // true —— 完全相同的引用

// 当 box 被从 DOM 移除后：
// box.remove();
// WeakMap 中的缓存条目会被自动清理 ✅
// 不会有"死缓存"占用内存
```

这种模式特别适用于以下场景：
- **React/Vue 组件中基于 props 的派生数据缓存**
- **图形学中顶点/面的法向量计算缓存**
- **编译器中 AST 节点的分析结果缓存**

### 应用四：深拷贝中的循环引用检测

在《[浅拷贝与深拷贝](/frontend/javascript/language-async/shallow-deep-copy-with-prototype)》中我们已经见过 WeakMap 在手写深拷贝函数中的核心作用——检测和处理循环引用：

```javascript
function deepClone(source, seen = new WeakMap()) {
  // 基础情况：非对象直接返回
  if (source === null || typeof source !== 'object') {
    return source;
  }
  
  // 🔑 循环引用检测的关键步骤
  if (seen.has(source)) {
    // 如果这个对象已经被拷贝过，直接返回之前的副本
    // 这样就避免了无限递归
    return seen.get(source);
  }
  
  // 创建目标对象
  const target = Array.isArray(source) ? [] : {};
  
  // 在开始拷贝前，先注册映射关系
  // （必须在递归子属性之前，否则遇到自引用时会漏掉）
  seen.set(source, target);
  
  // 递归拷贝每个属性
  for (let key of Reflect.ownKeys(source)) {
    const desc = Object.getOwnPropertyDescriptor(source, key);
    if ('value' in desc) {
      Object.defineProperty(target, key, {
        ...desc,
        value: deepClone(desc.value, seen)
      });
    }
  }
  
  return target;
}

// 测试循环引用
const cyclic = { name: '循环' };
cyclic.self = cyclic;
cyclic.children = [{ parent: cyclic }];

const cloned = deepClone(cyclic);

console.log(cloned.self === cloned);           // true ✅
console.log(cloned.children[0].parent === cloned); // true ✅
console.log(cloned.name);                       // "循环"
```

**为什么用 WeakMap 而不是 Map 或普通对象来做这件事？**

因为 `seen` 映射表只是深拷贝过程中的**临时工具**——拷贝完成后就不需要了。使用 WeakMap 可以确保：即使由于某些原因拷贝结果没有被正确返回（或者在外部被丢弃了），`seen` 中累积的临时映射关系不会阻止原始对象被垃圾回收。虽然在这个特定场景下差异不大（因为拷贝通常是同步完成的，`seen` 会随函数调用结束而被回收），但使用 WeakMap 是一种好的防御性编程习惯——特别是在异步深拷贝或长时间运行的拷贝任务中。

### 应用五：观察者模式（Observer Pattern）中的弱引用管理

在构建响应式系统或事件总线时，WeakMap 可以用来安全地管理观察者和目标对象之间的关系：

```javascript
class ReactiveSystem {
  // 以目标对象为弱键，存储其观察者列表
  #observers = new WeakMap();
  
  // 以回调函数为弱键，存储其订阅的目标集合
  #subscriptions = new WeakMap();
  
  /**
   * 订阅目标对象的变化
   * @param {object} target - 被观察的目标对象
   * @param {Function} callback - 变化时的回调函数
   */
  subscribe(target, callback) {
    if (!this.#observers.has(target)) {
      this.#observers.set(target, new Set());
    }
    
    this.#observers.get(target).add(callback);
    
    // 反向索引：记录每个回调订阅了哪些目标
    if (!this.#subscriptions.has(callback)) {
      this.#subscriptions.set(callback, new WeakSet());
    }
    this.#subscriptions.get(callback).add(target);
  }
  
  /**
   * 取消订阅
   */
  unsubscribe(target, callback) {
    const observers = this.#observers.get(target);
    if (observers) {
      observers.delete(callback);
      
      // 如果目标没有任何观察者了，清理空集合
      if (observers.size === 0) {
        this.#observers.delete(target);
      }
    }
  }
  
  /**
   * 通知目标对象的所有观察者
   */
  notify(target, changeInfo) {
    const observers = this.#observers.get(target);
    if (!observers) return;
    
    observers.forEach(callback => {
      try {
        callback(changeInfo);
      } catch (err) {
        console.error('观察者回调出错:', err);
      }
    });
  }
}

// ====== 使用示例 ======
const reactive = new ReactiveSystem();

// 创建一个响应式的用户对象
const user = { name: '张三', age: 25 };

// 订阅变化
reactive.subscribe(user, (changes) => {
  console.log(`🔔 用户信息变更:`, changes);
});

reactive.subscribe(user, (changes) => {
  // 自动持久化到 localStorage
  localStorage.setItem('userData', JSON.stringify(user));
});

// 模拟修改
user.age = 26;
reactive.notify(user, { field: 'age', oldValue: 25, newValue: 26 });

// 当 user 对象不再被使用时：
// user = null;
// WeakMap/WeakSet 中的相关条目自动清理 ✅
// 不会有"僵尸观察者"或"孤儿目标"残留
```

这种设计的精髓在于：**观察者和被观察者之间的绑定关系不会阻碍任何一方被垃圾回收。** 如果一个组件被卸载了（其回调函数不再被引用），它从观察者列表中自动消失；如果一个数据模型被废弃了（目标对象不再被引用），它的观察者列表也随之消失。一切都是自动的、无需手动管理的。

## WeakSet 实战应用

WeakSet 的应用场景相对较少，但在特定的模式下非常优雅：

### 应用一：防重复操作标记

```javascript
const processingSet = new WeakSet();

function processData(item) {
  // 防止同一个对象被重复处理
  if (processingSet.has(item)) {
    console.log('⚠️ 该对象已在处理中，跳过');
    return;
  }
  
  processingSet.add(item);  // 标记为"处理中"
  
  try {
    // 模拟耗时处理
    doExpensiveWork(item);
  } finally {
    processingSet.delete(item);  // 处理完毕，移除标记
  }
}
```

### 应用二：类型安全的类型标记

```javascript
const validatedObjects = new WeakSet();

/**
 * 验证并标记对象
 */
function validateAndMark(obj, schema) {
  const result = validate(obj, schema);
  
  if (result.valid) {
    // 验证通过后打上"已验证"标签
    validatedObjects.add(obj);
    return obj;
  } else {
    throw new Error(`验证失败: ${result.errors.join(', ')}`);
  }
}

/**
 * 类型守卫函数 —— 确保传入的对象已经过验证
 */
function assertValidated(obj) {
  if (!validatedObjects.has(obj)) {
    throw new Error('该对象未经验证，请先调用 validateAndMark()');
  }
}

// 使用
const rawInput = { email: 'test@example.com', age: 25 };
const validated = validateAndMark(rawInput, userSchema);  // 打标

processValidatedUser(validated);  // ✅ 通过

processValidatedUser({ email: 'hacked' });  // 💥 抛错：未经验证
```

这种方式比在对象上加一个 `__validated: true` 属性更加干净——它不在对象上留下任何痕迹，而且标记会随对象的生命周期自动消失。

## 哲学思考：所有权与生命周期的设计哲学

### 所有权（Ownership）的概念

在 Rust 编程语言中，**所有权（Ownership）** 是其最核心的创新——每个值都有一个唯一的所有者，当所有者超出作用域时，值会被自动释放（Drop）。这套规则使得 Rust 无需垃圾回收器就能保证内存安全。

虽然 JavaScript 有 GC，不需要程序员手动管理内存，但**"谁拥有这个数据？""这个数据应该在什么时候消失？"**这些问题依然存在——只不过它们从"编译期强制规则"变成了"运行时需要思考的软性问题"。

WeakMap/WeakSet 提供了一种**声明性的所有权表达方式**：

```javascript
// Map 表达的是："我拥有这些数据，我要对它们的生命周期负责"
const strongCache = new Map();
strongCache.set('key', expensiveData);  // 我负责这个数据的存活

// WeakMap 表达的是："我只是暂时关联这些数据，不干涉它们的生命周期"
const weakAssoc = new WeakMap();
weakAssoc.set(domNode, metadata);  // 我不负责 domNode 的存活，
                                   // 它什么时候消失我不管，我只跟着它
```

这是一种**"非侵入式的关联"**——WeakMap 不控制、不拥有、不强留。它只是一个旁观者，安静地记录着"这个对象曾经关联过什么数据"。当主角谢幕离场时，旁观的笔记也随之散去。

### 生命周期（Lifecycle）的对齐

优秀的软件设计要求**数据的生命周期与其所服务对象的生命周期保持对齐**。如果数据比它服务的对象活得更久，那就是内存泄漏；如果数据提前死亡，那就是潜在的运行时 Bug。

```javascript
// ❌ 生命周期不对齐 —— 数据比对象活得久
const leakedData = new Map();
function createComponent(element) {
  leakedData.set(element.id, { heavy: bigData });  // 全局 Map 永远活着
  // 即使 element 被移除了，leakedData 中的记录还在
}

// ✅ 生命周期对齐 —— 数据随对象一起生灭
const cleanData = new WeakMap();
function createComponentClean(element) {
  cleanData.set(element, { heavy: bigData });
  // element 被移除 → cleanData 条目自动消失 → heavy 数据也被释放
}
```

WeakMap/WeakSet 本质上是 JavaScript 语言层面提供的**生命周期同步工具**——它让关联数据能够自动跟随主对象的生命周期，而不需要程序员手动编写清理逻辑。

### "手动管理"的陷阱

很多开发者倾向于使用普通的 Map/Set + 手动清理策略来管理关联数据。这在原理上完全可以工作，但在实践中却充满了风险：

```javascript
// 手动管理模式
const manualCache = new Map();

function useCache(element, computeFn) {
  let result = manualCache.get(element);
  
  if (!result) {
    result = computeFn();
    manualCache.set(element, result);
  }
  
  // 问题 1：谁来清理？
  // 问题 2：什么时候清理？
  // 问题 3：如果忘记清理呢？
  // 问题 4：如果有异常导致清理代码没执行呢？
  // 问题 5：如果是异步操作，清理时机怎么确定？
  
  return result;
}

function cleanup() {
  // 需要遍历所有条目，逐个检查哪些元素的引用已经无效了
  // 但你怎么知道一个 DOM 元素是否还"有效"？检查 parentNode？检查 isConnected？
  // 这些检测本身就可能有边界问题……
  for (let [el] of manualCache) {
    if (!document.body.contains(el)) {
      manualCache.delete(el);
    }
  }
}
```

手动管理带来的问题是：**你需要记住在每一个可能的出口处执行清理操作**——正常退出、异常退出、用户中断、超时取消……任何一个遗漏都会造成泄漏。而 WeakMap 把这个问题交给了语言运行时——GC 比"人肉清理"可靠得多。

### 弱引用是一种信任的体现

从哲学角度看，使用弱引用体现了对系统的**信任**：我相信当我不再需要一个对象时，GC 能够在合适的时机把它收回；我不需要紧抓不放，不需要过度防御。

这与生活中的人际关系何其相似：

- **强引用就像一段充满控制欲的关系**——你必须时刻确认对方还在，你要主动联系，你要担心失去。这种关系让人疲惫，也容易出问题（当你忘了去维护，关系就僵化了）。
- **弱引用就像一种成熟的陪伴**——我知道你在我身边的时候我会珍惜；如果你需要离开，我不会阻拦。我不占有你，但我记得我们在一起的美好时光。

当然，并不是所有场景都应该用弱引用。有些数据就是需要长期保存的（如用户的偏好设置、应用的常量配置）。关键在于**区分哪些数据是"依附于某个对象的"、哪些是"独立存在的"**——前者适合弱引用，后者适合强引用。

| `values()` | ✅ | ❅ | ✅ | ❌ |
| `entries()` | ✅ | ❌ | N/A | N/A |

### 场景决策速查

| 场景 | 推荐方案 | 原因 |
|------|---------|------|
| DOM 元素关联数据 | **WeakMap** | 元素移除后自动清理 |
| 类私有属性（Pre-ES2022） | **WeakMap** | 随实例自动回收 |
| 对象级缓存/记忆化 | **WeakMap** | 键对象过期后缓存自动失效 |
| 深拷贝循环引用检测 | **WeakMap** | 临时映射，不阻止 GC |
| 观察者/事件系统 | **WeakMap + WeakSet** | 双向弱引用，自动解耦 |
| 通用配置/字典 | **Map** | 需要遍历和持久存储 |
| 字符串键的查找表 | **Map** | WeakMap 不接受基本类型键 |
| 数组/值去重 | **Set** | 需要遍历和 size |
| 已访问标记/类型守卫 | **WeakSet** | 标记不阻碍对象回收 |

### 最佳实践清单

1. **优先考虑 WeakMap** 当你需要将数据关联到对象上时——除非你有明确的理由需要强引用
2. **不要试图遍历 WeakMap/WeakSet**——设计你的代码使其不需要这样做
3. **不要用基本类型作为 WeakMap 的键**——会导致 TypeError
4. **WeakMap 的值可以是任何类型**——包括函数、其他 Map、甚至另一个 WeakMap
5. **结合 `structuredClone` 或深拷贝时注意**：WeakMap 中的数据不会被自动克隆
6. **在调试工具中检查内存时**，注意 WeakMap 中的条目可能随时消失（这是正常现象）
7. **ES2022+ 项目中优先使用 `#` 私有字段**——语法更简洁、引擎优化更好；但在需要跨实例共享私有数据或兼容旧环境的场景，WeakMap 仍然是最佳选择

> **WeakMap 和 WeakSet 是 JavaScript 中少数真正体现"隐式自动化"理念的工具。** 它们不做显眼的事情，不提供花哨的功能，只是在默默地守护着一条原则：**当一个对象完成了它的使命，让它体面地离开，不留痕迹，不占空间。** 这种"得体的退出"能力，正是构建长期运行、内存高效的应用程序的基础。
