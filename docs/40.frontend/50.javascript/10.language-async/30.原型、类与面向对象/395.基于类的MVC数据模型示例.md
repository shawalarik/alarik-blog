# 实现一个完整的基于类的 MVC 或数据模型示例

## 当理论遇见实践：为什么我们需要一个完整的示例？

在前面的探索中，我们已经深入理解了 JavaScript 中类的方方面面——从 `class` 的语法糖本质，到原型链的运作机制；从继承的各种形式，到封装的多种手段。这些知识就像是散落在工具箱里的各种精密工具：你知道锤子怎么用，也知道螺丝刀怎么用，但面对一整面需要装修的墙时，你需要的不是对每件工具的孤立了解，而是一个**将它们协同运用起来的完整方案**。

这就是本文存在的意义：**我们将从零开始，使用 JavaScript 的 `class` 语法，构建一个具有实际意义的 MVC（Model-View-Controller）架构或数据模型系统**。这不仅仅是一段能跑的代码，更是一次将面向对象的设计理念、JavaScript 的语言特性、以及软件工程的架构思想融会贯通的实践旅程。

为什么要选择 MVC 作为示例载体？因为 MVC 是软件工程中最经典、最广泛使用的架构模式之一。它的核心思想——**将数据（Model）、展示（View）和行为逻辑（Controller）分离**——与面向对象编程中"单一职责原则"的精神高度吻合。通过用 JavaScript 的类来实现 MVC 的各个组成部分，我们能够在一个具体的、有意义的场景中，全方位地展示 `class` 语法的实战价值。

### MVC 模式的哲学根基

在深入代码之前，让我们先站在更高的维度审视 MVC 模式背后的哲学思想。

MVC 的诞生可以追溯到 1979 年，由 Trygve Reenskaug 在 Smalltalk 语言环境中首次提出。它的设计初衷非常朴素：**当你在构建一个复杂的交互式系统时，不要把所有事情混在一起做**。这种"分离关注点"（Separation of Concerns）的思想，实际上反映了人类认知的一个基本规律——我们的大脑不擅长同时处理多个不同性质的问题。

想象一下你正在经营一家餐厅：

- **Model（模型）** 就像是餐厅的**厨房和库存管理系统**——它负责管理所有的原材料（数据）、记录库存变化、处理食材的准备和加工。厨房不需要知道顾客坐在哪张桌子上，也不需要知道服务员长什么样子。它只关心一件事：**如何准确地管理和处理数据**。
- **View（视图）** 就像是餐厅的**就餐环境和菜单展示**——它负责把厨房做好的菜品以最诱人的方式呈现给顾客。展示的方式可以多种多样：精美的摆盘、温暖的灯光、优雅的音乐，但这些都不应该影响厨房里菜品的烹饪方式。
- **Controller（控制器）** 就像是餐厅的**服务员团队**——它接收顾客的点单请求（用户交互），将这些请求翻译成厨房能理解的指令，再把厨房的产出传递给顾客。服务员是连接顾客和厨房的桥梁，但它自己既不烹饪也不品尝。

这个类比揭示了一个深刻的道理：**一个设计良好的系统，其各个组成部分应当像餐厅各部门一样各司其职、界限分明**。每一部分都可以独立地被理解、修改、测试，甚至替换，而不需要对其他部分做出大的改动。这正是我们在本文中要用 JavaScript 类来追求的目标。

## 第一步：设计数据模型（Model 层）

任何有意义的 MVC 实现都必须从一个坚实的数据层开始。在我们的示例中，我们将构建一个**任务管理应用（Task Manager）的数据模型**——这个选择并非偶然：任务管理涉及数据的增删改查、状态的流转、验证规则等丰富的业务场景，非常适合用来展示类的各种能力。

### 从领域分析到类设计

在设计 Model 类之前，我们需要先回答几个基本问题：

1. **我们要管理什么样的数据？** → 任务（Task），每个任务有标题、描述、状态、优先级、创建时间等属性
2. **这些数据之间有什么关系？** → 任务属于某个项目/分类，可以有标签
3. **数据有哪些行为？** → 创建、修改、删除、状态切换、标记完成等
4. **需要遵循哪些规则？** → 标题不能为空、优先级必须在合理范围内、某些状态下不允许某些操作

这些问题的答案直接指导着我们的类设计。现在让我们开始编写第一个核心类——`Task`：

```javascript
/**
 * Task 类 —— 任务数据模型
 * 
 * 职责：封装单个任务的全部数据和基本行为
 * 设计原则：
 *   1. 数据私有化：内部状态通过 # 私有字段保护
 *   2. 行为内聚：所有与单个任务相关的操作都在此类中定义
 *   3. 状态机模式：任务的状态变更遵循严格的规则
 */
class Task {
  // ====== 私有字段：外部无法直接访问 ======
  #id;              // 唯一标识符
  #title;           // 任务标题
  #description;     // 详细描述
  #status;          // 当前状态
  #priority;        // 优先级 (1-5)
  #createdAt;       // 创建时间
  #updatedAt;       // 最后更新时间
  #tags;            // 标签集合
  #subtasks;        // 子任务列表

  // ====== 静态常量：状态枚举 ======
  static Status = {
    TODO: 'todo',         // 待办
    IN_PROGRESS: 'in-progress',  // 进行中
    BLOCKED: 'blocked',    // 已阻塞
    REVIEW: 'review',      // 待审核
    DONE: 'done'           // 已完成
  };

  // ====== 静态常量：合法的状态转换路径 ======
  static VALID_TRANSITIONS = {
    'todo': ['in-progress', 'blocked', 'done'],
    'in-progress': ['todo', 'blocked', 'review', 'done'],
    'blocked': ['todo', 'in-progress'],
    'review': ['in-progress', 'done'],
    'done': ['todo', 'in-progress']  // 允许重新打开
  };

  /**
   * 构造函数：创建一个新任务
   * @param {Object} options - 任务配置项
   */
  constructor({ id, title, description = '', priority = 3, tags = [] }) {
    // 参数校验
    if (!title || typeof title !== 'string' || title.trim() === '') {
      throw new Error('任务标题不能为空');
    }
    if (![1, 2, 3, 4, 5].includes(priority)) {
      throw new Error('优先级必须是 1-5 之间的整数');
    }

    this.#id = id || this.#generateId();
    this.#title = title.trim();
    this.#description = description;
    this.#status = Task.Status.TODO;
    this.#priority = priority;
    this.#createdAt = new Date();
    this.#updatedAt = new Date();
    this.#tags = [...new Set(tags)];  // 去重
    this.#subtasks = [];
  }

  // ====== 访问器：受控地暴露内部状态 ======
  get id() { return this.#id; }
  get title() { return this.#title; }
  get status() { return this.#status; }
  get priority() { return this.#priority; }
  get createdAt() { return new Date(this.#createdAt); }  // 返回副本，防止外部修改
  get updatedAt() { return new Date(this.#updatedAt); }
  get tags() { return [...this.#tags]; }                  // 返回副本
  get subtasks() { return [...this.#subtasks]; }

  // 只读属性：判断任务是否已完成
  get isCompleted() { return this.#status === Task.Status.DONE; }

  // 计算属性：任务的综合紧急程度分数
  get urgencyScore() {
    const ageInDays = (Date.now() - this.#createdAt) / (1000 * 60 * 60 * 24);
    const statusWeight = {
      'todo': 1.0,
      'in-progress': 0.8,
      'blocked': 1.2,
      'review': 0.5,
      'done': 0.0
    };
    return (6 - this.#priority) * statusWeight[this.#status] * Math.log(ageInDays + 1);
  }

  // ====== 行为方法 ======

  /** 更新标题 */
  setTitle(newTitle) {
    if (!newTitle?.trim()) throw new Error('标题不能为空');
    this.#title = newTitle.trim();
    this.#touch();
  }

  /** 更新描述 */
  setDescription(desc) {
    this.#description = desc ?? '';
    this.#touch();
  }

  /**
   * 状态转换 —— 核心业务逻辑
   * 使用状态机模式确保只有合法的状态转换才能执行
   */
  transitionTo(newStatus) {
    // 验证目标状态是否有效
    const validStatuses = Object.values(Task.Status);
    if (!validStatuses.includes(newStatus)) {
      throw new Error(`无效的目标状态: ${newStatus}`);
    }

    // 验证转换是否合法
    const allowedTransitions = Task.VALID_TRANSITIONS[this.#status] || [];
    if (!allowedTransitions.includes(newStatus)) {
      throw new Error(
        `不允许从 "${this.#status}" 转换到 "${newStatus}"。` +
        `允许的转换: ${allowedTransitions.join(', ')}`
      );
    }

    const oldStatus = this.#status;
    this.#status = newStatus;
    this.#touch();

    return { oldStatus, newStatus, taskId: this.#id };
  }

  /** 添加标签 */
  addTag(tag) {
    if (tag && !this.#tags.includes(tag)) {
      this.#tags.push(tag);
      this.#touch();
    }
  }

  /** 移除标签 */
  removeTag(tag) {
    const index = this.#tags.indexOf(tag);
    if (index !== -1) {
      this.#tags.splice(index, 1);
      this.#touch();
    }
  }

  /** 设置优先级 */
  setPriority(level) {
    if (![1, 2, 3, 4, 5].includes(level)) {
      throw new Error('优先级必须是 1-5 之间的整数');
    }
    this.#priority = level;
    this.#touch();
  }

  /** 添加子任务 */
  addSubtask(subtask) {
    if (subtask instanceof Task) {
      this.#subtasks.push(subtask);
      this.#touch();
    }
  }

  /** 序列化为纯对象（用于存储或传输） */
  toJSON() {
    return {
      id: this.#id,
      title: this.#title,
      description: this.#description,
      status: this.#status,
      priority: this.#priority,
      createdAt: this.#createdAt.toISOString(),
      updatedAt: this.#updatedAt.toISOString(),
      tags: [...this.#tags],
      subtasks: this.#subtasks.map(st => st.toJSON())
    };
  }

  /** 从 JSON 对象恢复 Task 实例（静态工厂方法） */
  static fromJSON(json) {
    const task = new Task({
      id: json.id,
      title: json.title,
      description: json.description,
      priority: json.priority,
      tags: json.tags
    });
    task.#status = json.status;
    task.#createdAt = new Date(json.createdAt);
    task.#updatedAt = new Date(json.updatedAt);
    // 恢复子任务
    if (json.subtasks) {
      json.subtasks.forEach(stJson => {
        task.#subtasks.push(Task.fromJSON(stJson));
      });
    }
    return task;
  }

  // ====== 私有辅助方法 ======
  #generateId() {
    return 'task_' + Date.now().toString(36) + '_' + 
           Math.random().toString(36).substring(2, 8);
  }

  #touch() {
    this.#updatedAt = new Date();
  }
}
```

### 解构 Task 类的设计决策

上面的 `Task` 类虽然代码量不算少，但每一个部分都有其存在的原因。让我们逐一剖析其中蕴含的设计思想和 JavaScript 特性的运用。

#### 私有字段的选用：为何选择 # 而非 _

你可能注意到了，`Task` 类大量使用了 ES2022 引入的**私有字段（Private Fields）**语法——以 `#` 开头的字段名。这是一个经过深思熟虑的选择。

在 ES2022 之前，JavaScript 开发者通常用下划线前缀（如 `_balance`）来表示"这是私有属性，请不要直接访问"。但这仅仅是一种**约定**（Convention），没有任何强制性。任何外部代码都可以随意读取甚至修改这些所谓的"私有"属性。就像你家门上贴了张"闲人免进"的纸条，但门并没有上锁——有心人完全可以推门而入。

而 `#` 私有字段则是**语言层面上的强制保护**。任何在类外部访问 `#title` 或尝试修改 `#status` 的行为都会导致语法错误（SyntaxError）。这不是运行时的检查，而是在代码解析阶段就会被拒绝。这意味着：

```javascript
let task = new Task({ id: 1, title: "写报告" });

console.log(task.#title);   // SyntaxError! 直接报错
task.#status = "hacked";    // SyntaxError! 无法篡改

// 但通过公开的方法 —— 正常工作
console.log(task.title);       // "写报告"
task.transitionTo("in-progress"); // ✅ 合法操作
```

**哲学思考**：私有字段的引入体现了编程语言发展中一个重要的趋势——**让编译器/解释器承担更多的"守门人"角色，而不是依赖开发者的自律性**。这与现实社会中"制度优于德治"的理念如出一辙：一个安全的社会不应该只依靠每个人都自觉守法（那太理想化了），而应该有一套完善的机制让违法行为在物理上变得困难甚至不可能。

#### 状态机模式的应用

`transitionTo` 方法是 `Task` 类中最具代表性的业务逻辑实现。它采用了**状态机（State Machine）**的设计模式——一个任务在任何时刻都处于一个确定的状态，并且只有预定义的状态转换路径才是合法的。

为什么要这样限制？因为在真实的业务流程中，任务的状态变更是有严格规则的：

- 一个**待办（TODO）**的任务可以直接变为**已完成（DONE）**（也许它太简单了），也可以进入**进行中（IN_PROGRESS）**
- 一个**已阻塞（BLOCKED）**的任务必须先解除阻塞（回到待办或进行中）才能继续推进，不能直接跳到已完成
- 一个**已完成（DONE）**的任务可以被重新打开（回到待办或进行中），这在敏捷开发中很常见

如果不加限制地允许任意状态转换，数据的一致性和可预测性就会遭到破坏。这就好比一家公司的人事流程：你不能把一个刚入职的员工直接变成"已退休"状态——中间必须经历一系列合法的状态流转。

#### getter 的计算属性：urgencyScore

`urgencyScore` 这个 getter 方法展示了类的一个强大能力：**将派生数据（Derived Data）的计算逻辑封装起来**。紧急程度分数不是一个存储在对象中的静态值，而是根据任务的优先级、当前状态、创建时间等多个因素动态计算出来的。调用者只需要读 `task.urgencyScore`，完全不需要知道背后的计算公式是什么。

这种设计的优势在于：**当计算逻辑发生变化时，只需要修改一处**。比如某天产品经理说"我们应该让被阻塞的任务得分更高以引起重视"，你只需修改 `urgencyScore` 的计算公式，所有使用这个属性的代码都会自动获得更新后的结果。

#### toJSON 和 fromJSON：序列化的对称之美

`toJSON()` 和静态的 `fromJSON()` 构成了一对**互逆操作**——前者将对象转换为可存储/传输的纯数据格式（JSON），后者从 JSON 数据重建出完整的对象实例。这对方法是任何需要在客户端和服务端之间持久化传输的数据模型必备的能力。

值得注意的是 `fromJSON` 被设计为**静态工厂方法**而非构造函数的一部分。这是因为从 JSON 重建对象是一个与"从零创建新对象"本质上不同的过程——它需要绕过构造函数中的某些校验（比如 ID 是指定的而不是生成的，某些字段已经有值了）。如果把这些逻辑塞进 `constructor` 里，会让构造函数变得臃肿且职责不清。

### TaskList 类：管理任务集合

单个 `Task` 只是系统的原子单位。在实际应用中，我们还需要一个容器来管理多个任务的集合——这就是 `TaskList` 类的职责：

```javascript
/**
 * TaskList 类 —— 任务集合管理器
 * 
 * 职责：
 *   1. 管理 Task 对象的集合（增删改查）
 *   2. 提供查询和过滤能力
 *   3. 维护集合级别的事件通知机制
 * 
 * 设计模式：观察者模式（Observer Pattern）
 */
class TaskList {
  #tasks;             // Map<id, Task> —— 用 Map 实现 O(1) 查找
  #observers;         // 观察者回调列表
  #nextId;            // 自增 ID 计数器

  constructor(initialTasks = []) {
    this.#tasks = new Map();
    this.#observers = new Set();
    this.#nextId = 1;

    // 批量初始化
    initialTasks.forEach(taskData => {
      this.addTask(taskData);
    });
  }

  // ====== 核心 CRUD 操作 ======

  /** 创建并添加新任务 */
  addTask(options) {
    const task = new Task({
      ...options,
      id: options.id ?? this.#nextId++
    });
    this.#tasks.set(task.id, task);
    this.#notify({ type: 'add', task });
    return task;
  }

  /** 根据 ID 获取任务 */
  getTask(id) {
    return this.#tasks.get(id) ?? null;
  }

  /** 更新任务（通过 ID 定位，传入要更新的字段） */
  updateTask(id, updates) {
    const task = this.#tasks.get(id);
    if (!task) throw new Error(`任务 ${id} 不存在`);

    if (updates.title !== undefined) task.setTitle(updates.title);
    if (updates.description !== undefined) task.setDescription(updates.description);
    if (updates.priority !== undefined) task.setPriority(updates.priority);
    
    this.#notify({ type: 'update', task, updates: Object.keys(updates) });
    return task;
  }

  /** 删除任务 */
  removeTask(id) {
    const task = this.#tasks.get(id);
    if (!task) return false;
    
    this.#tasks.delete(id);
    this.#notify({ type: 'remove', task });
    return true;
  }

  /** 批量状态转换 */
  transitionTasks(ids, newStatus) {
    const results = [];
    ids.forEach(id => {
      const task = this.#tasks.get(id);
      if (task) {
        try {
          const result = task.transitionTo(newStatus);
          results.push({ success: true, ...result });
        } catch (error) {
          results.push({ success: false, id, error: error.message });
        }
      }
    });
    if (results.some(r => r.success)) {
      this.#notify({ type: 'batch-transition', results });
    }
    return results;
  }

  // ====== 查询方法（返回新数组，不影响原数据）======

  /** 获取所有任务 */
  getAll() {
    return Array.from(this.#tasks.values());
  }

  /** 按状态筛选 */
  findByStatus(status) {
    return this.getAll().filter(t => t.status === status);
  }

  /** 按标签筛选 */
  findByTag(tag) {
    return this.getAll().filter(t => t.tags.includes(tag));
  }

  /** 按优先级范围筛选 */
  findByPriorityRange(min, max) {
    return this.getAll().filter(t => t.priority >= min && t.priority <= max);
  }

  /** 多条件复合筛选 */
  filter({ status, tag, priorityMin, priorityMax, searchKeyword }) {
    let results = this.getAll();

    if (status) results = results.filter(t => t.status === status);
    if (tag) results = results.filter(t => t.tags.includes(tag));
    if (priorityMin !== undefined) results = results.filter(t => t.priority >= priorityMin);
    if (priorityMax !== undefined) results = results.filter(t => t.priority <= priorityMax);
    if (searchKeyword) {
      const keyword = searchKeyword.toLowerCase();
      results = results.filter(t =>
        t.title.toLowerCase().includes(keyword) ||
        t.description.toLowerCase().includes(keyword)
      );
    }

    // 按紧急程度排序
    return results.sort((a, b) => b.urgencyScore - a.urgencyScore);
  }

  // ====== 统计信息 ======
  get stats() {
    const all = this.getAll();
    return {
      total: all.length,
      completed: all.filter(t => t.isCompleted).length,
      byStatus: Object.fromEntries(
        Object.values(Task.Status).map(s => [s, all.filter(t => t.status === s).length])
      ),
      byPriority: Object.fromEntries(
        [1, 2, 3, 4, 5].map(p => [p, all.filter(t => t.priority === p).length])
      ),
      averageUrgency: all.length > 0 
        ? all.reduce((sum, t) => sum + t.urgencyScore, 0) / all.length 
        : 0
    };
  }

  // ====== 观察者模式 ======

  /** 注册变更监听器 */
  subscribe(callback) {
    this.#observers.add(callback);
    // 返回取消订阅函数
    return () => this.#observers.delete(callback);
  }

  // ====== 持久化支持 ======

  /** 导出为 JSON */
  exportToJSON() {
    return JSON.stringify(this.getAll().map(t => t.toJSON()), null, 2);
  }

  /** 从 JSON 导入 */
  static importFromJSON(jsonString) {
    const data = JSON.parse(jsonString);
    const list = new TaskList();
    data.forEach(taskJson => {
      const task = Task.fromJSON(taskJson);
      list.#tasks.set(task.id, task);
    });
    return list;
  }

  // ====== 私有方法 ======
  #notify(event) {
    this.#observers.forEach(cb => {
      try { cb(event); } catch (e) {
        console.error('Observer callback error:', e);
      }
    });
  }
}
```

#### 为何选择 Map 而非数组存储任务？

在 `TaskList` 内部，我们选择了 `Map` 来存储任务，而不是更常见的数组。这个选择背后有一个性能考量：

- **数组的 `find` 操作**：O(n) 时间复杂度——每次查找都要遍历整个数组
- **Map 的 `get` 操作**：O(1) 时间复杂度——通过键直接定位

当你管理的任务数量达到数百上千时，这个差异就会变得显著。而且，Map 天然保证了键的唯一性——不会有两个相同 ID 的任务共存。

**通俗类比**：用数组存任务就像在一叠没有分类的文件中找一份特定文件——你得一份份翻看直到找到为止。而用 Map 存任务就像是在一个有标签的文件柜中取文件——你直接走到对应标签的位置就能拿到想要的文件。

#### 观察者模式的集成

`subscribe` 方法和内部的 `#notify` 方法实现了**观察者模式（Observer Pattern）**。这是一种极其重要的设计模式，也是 MVC 架构中 View 层与 Model 层通信的基础机制。

其工作原理很简单：任何对数据感兴趣的组件（通常是 View 层的 UI 组件）都可以向 TaskList 注册一个回调函数。每当 TaskList 中的数据发生变动（添加、修改、删除），所有注册过的回调函数都会被自动触发，收到变更通知。

```javascript
// 使用示例
const myTasks = new TaskList();

// 订阅变更
const unsubscribe = myTasks.subscribe((event) => {
  console.log(`📢 数据变更通知:`);
  console.log(`   类型: ${event.type}`);
  if (event.task) console.log(`   任务: ${event.task.title}`);
  
  // 在真实应用中，这里会触发 UI 更新
});

myTasks.addTask({ title: "新任务" });
// 控制台输出: 📢 数据变更通知: 类型: add, 任务: 新任务

// 不再需要时取消订阅
unsubscribe();
```

**哲学思考**：观察者模式体现了一种**"反向控制"（Inversion of Control）**的思维——传统的做法是数据消费者主动去轮询数据是否有变化（"有没有新消息？"），而观察者模式下，数据生产者在变化发生时主动通知消费者（"嘿，我变了！"）。这种转变类似于从"你去邮局查有没有信"变成了"有信了邮递员送到你家门口"——效率更高，也更实时。

## 第二步：构建控制器（Controller 层）

有了坚实的 Model 层之后，我们需要一个中间层来协调用户的操作意图和数据模型的响应。这就是 Controller 的职责。

### Controller 的本质：翻译官与调度员

如果把 Model 比作厨房，View 比作餐厅的大堂，那么 Controller 就是那位穿梭其中的**服务员兼领班**。它不做菜（那是 Model 的事），不上菜（那是 View 的事），但它要做的是：

1. **翻译**：把顾客模糊的需求（"我要个好吃的"）翻译成厨房精确的指令（"3 号桌，一份宫保鸡丁，微辣"）
2. **协调**：确保厨房不会接超过能力的订单（防止过载）
3. **路由**：把不同的需求分发给正确的处理者（点菜→厨房，结账→收银台）
4. **异常处理**：当出现问题时给出友好的反馈（"抱歉，今天的售罄了"）

在我们的任务管理系统中，`TaskController` 就是这样的角色：

```javascript
/**
 * TaskController 类 —— 任务管理控制器
 * 
 * 职责：
 *   1. 接收用户操作的请求
 *   2. 校验和预处理输入数据
 *   3. 调用 TaskList（Model）执行实际操作
 *   4. 处理错误和边界情况
 *   5. 将结果格式化后返回
 * 
 * 设计原则：
 *   - Controller 本身不持有业务状态（无状态设计）
 *   - 所有数据操作委托给 Model
 *   - 错误信息对用户友好
 */
class TaskController {
  #model;          // TaskList 实例的引用
  #actionLog;      // 操作日志（用于审计和撤销）
  #validators;     // 自定义验证器注册表

  constructor(taskList) {
    if (!(taskList instanceof TaskList)) {
      throw new Error('TaskController 需要一个 TaskList 实例');
    }
    this.#model = taskList;
    this.#actionLog = [];
    this.#validators = new Map();
  }

  // ====== 注册自定义验证器 ======
  registerValidator(name, validatorFn) {
    if (typeof validatorFn !== 'function') {
      throw new Error('验证器必须是一个函数');
    }
    this.#validators.set(name, validatorFn);
  }

  // ====== 任务 CRUD 操作接口 ======

  /** 创建任务（带完整的前置校验）*/
  createTask(data) {
    // 1. 输入清洗
    const cleaned = this.#sanitizeInput(data);

    // 2. 运行注册的自定义验证器
    const validationErrors = this.#runValidators(cleaned);
    if (validationErrors.length > 0) {
      return { success: false, errors: validationErrors };
    }

    // 3. 业务规则校验
    const businessErrors = this.#validateBusinessRules(cleaned);
    if (businessErrors.length > 0) {
      return { success: false, errors: businessErrors };
    }

    // 4. 执行创建
    try {
      const task = this.#model.addTask(cleaned);
      this.#logAction('create', task.id, cleaned);
      
      return {
        success: true,
        data: task.toJSON(),
        message: `任务"${task.title}"创建成功`
      };
    } catch (error) {
      return { success: false, errors: [error.message] };
    }
  }

  /** 获取单个任务详情 */
  getTaskDetail(id) {
    const task = this.#model.getTask(id);
    if (!task) {
      return { success: false, errors: [`任务 ${id} 不存在`] };
    }
    return {
      success: true,
      data: task.toJSON()
    };
  }

  /** 更新任务 */
  updateTask(id, updates) {
    const existingTask = this.#model.getTask(id);
    if (!existingTask) {
      return { success: false, errors: [`任务 ${id} 不存在`] };
    }

    // 清洗更新数据
    const cleanedUpdates = this.#sanitizeInput(updates);
    
    try {
      const updatedTask = this.#model.updateTask(id, cleanedUpdates);
      this.#logAction('update', id, cleanedUpdates);
      
      return {
        success: true,
        data: updatedTask.toJSON(),
        message: `任务"${updatedTask.title}"更新成功`
      };
    } catch (error) {
      return { success: false, errors: [error.message] };
    }
  }

  /** 删除任务（带确认机制）*/
  deleteTask(id, force = false) {
    const task = this.#model.getTask(id);
    if (!task) {
      return { success: false, errors: [`任务 ${id} 不存在`] };
    }

    // 如果任务有子任务，非强制模式下需要确认
    if (!force && task.subtasks.length > 0) {
      return {
        success: false,
        errors: [`该任务包含 ${task.subtasks.length} 个子任务`],
        needsConfirmation: true,
        warning: '删除此任务将同时删除所有子任务'
      };
    }

    const removed = this.#model.removeTask(id);
    if (removed) {
      this.#logAction('delete', id);
      return { success: true, message: `任务已删除` };
    }
    return { success: false, errors: ['删除失败'] };
  }

  // ====== 高级操作 ======

  /** 状态转换（带上下文感知）*/
  changeStatus(id, newStatus, reason = '') {
    const task = this.#model.getTask(id);
    if (!task) {
      return { success: false, errors: [`任务 ${id} 不存在`] };
    }

    // 上下文相关的额外校验
    if (newStatus === Task.Status.DONE && task.subtasks.length > 0) {
      const incompleteSubtasks = task.subtasks.filter(st => !st.isCompleted);
      if (incompleteSubtasks.length > 0 && !force) {
        return {
          success: false,
          errors: [
            `该任务还有 ${incompleteSubtasks.length} 个子任务未完成`,
            '建议先完成所有子任务，或者使用 force=true 强制标记完成'
          ],
          warning: '存在未完成的子任务'
        };
      }
    }

    try {
      const result = task.transitionTo(newStatus);
      this.#logAction('status-change', id, {
        from: result.oldStatus,
        to: result.newStatus,
        reason
      });
      
      return {
        success: true,
        data: result,
        message: `任务状态从"${result.oldStatus}"变更为"${result.newStatus}"`
      };
    } catch (error) {
      return { success: false, errors: [error.message] };
    }
  }

  /** 搜索任务 */
  searchTasks(criteria) {
    const results = this.#model.filter(criteria);
    return {
      success: true,
      data: results.map(t => t.toJSON()),
      total: results.length,
      meta: criteria
    };
  }

  /** 获取仪表板数据 */
  getDashboard() {
    const stats = this.#model.stats;
    const urgentTasks = this.#model.findByPriorityRange(4, 5)
      .filter(t => !t.isCompleted)
      .sort((a, b) => b.urgencyScore - a.urgencyScore)
      .slice(0, 5);

    return {
      success: true,
      data: {
        overview: stats,
        urgentItems: urgentTasks.map(t => ({
          id: t.id,
          title: t.title,
          urgency: Math.round(t.urgencyScore * 100) / 100,
          status: t.status
        })),
        recentActions: this.#actionLog.slice(-10).reverse()
      }
    };
  }

  // ====== 批量操作 ======
  batchUpdate(ids, updates) {
    const results = ids.map(id => this.updateTask(id, updates));
    const succeeded = results.filter(r => r.success).length;
    const failed = results.filter(r => !r.success).length;

    return {
      success: failed === 0,
      summary: { total: ids.length, succeeded, failed },
      details: results
    };
  }

  // ====== 日志和撤销 ======
  getActionHistory(limit = 50) {
    return this.#actionLog.slice(-limit);
  }

  undoLastAction() {
    if (this.#actionLog.length === 0) {
      return { success: false, errors: ['没有可撤销的操作'] };
    }
    
    const lastAction = this.#actionLog.pop();
    // 注意：完整的撤销实现需要更复杂的状态快照机制
    // 这里仅作为概念演示
    return {
      success: true,
      message: `已撤销: ${lastAction.type}`,
      action: lastAction
    };
  }

  // ====== 私有辅助方法 ======
  #sanitizeInput(data) {
    if (!data || typeof data !== 'object') return {};
    
    const sanitized = {};
    const allowedFields = ['title', 'description', 'priority', 'tags'];
    
    for (const field of allowedFields) {
      if (data[field] !== undefined) {
        // 字符串类型字段去除首尾空白
        if (typeof data[field] === 'string') {
          sanitized[field] = data[field].trim();
        } else {
          sanitized[field] = data[field];
        }
      }
    }
    return sanitized;
  }

  #runValidators(data) {
    const errors = [];
    for (const [name, validator] of this.#validators) {
      try {
        const result = validator(data);
        if (result !== true && result) {
          errors.push(String(result));
        }
      } catch (error) {
        console.error(`验证器"${name}"执行出错:`, error);
      }
    }
    return errors;
  }

  #validateBusinessRules(data) {
    const errors = [];

    // 示例业务规则：高优先级任务必须有描述
    if (data.priority >= 4 && (!data.description || data.description.length < 10)) {
      errors.push('高优先级任务（4-5级）必须提供至少10个字符的详细描述');
    }

    // 示例业务规则：标签数量限制
    if (data.tags && data.tags.length > 10) {
      errors.push('每个任务最多只能有10个标签');
    }

    return errors;
  }

  #logAction(type, targetId, details = {}) {
    this.#actionLog.push({
      timestamp: new Date().toISOString(),
      type,
      targetId,
      details,
      user: 'current-user' // 实际应用中应从认证上下文获取
    });
  }
}
```

### Controller 层的设计哲学

#### 无状态设计的重要性

你可能注意到 `TaskController` 的设计遵循了一个重要原则：**Controller 本身几乎不持有任何业务状态**。它所有的数据操作都委托给了 `#model`（即 TaskList 实例）。Controller 自己只维护了日志（`#actionLog`）和验证器注册表（`#validators`），这些都是"横切关注点"（Cross-cutting Concerns），不属于业务数据本身。

这种设计的好处在于：

1. **可预测性**：同一个 Controller 实例在不同时间、不同上下文中表现一致
2. **可测试性**：不需要模拟复杂的内部状态就可以对 Controller 进行单元测试
3. **可替换性**：可以用同一个 Controller 配合不同的 Model 实现（比如一个是内存存储，另一个是数据库存储）

**通俗类比**：无状态的 Controller 就像一位**职业Translator**——他不拥有任何信息，他的全部技能就是准确地把一种语言翻译成另一种语言。无论你给他什么内容，他都能按照既定的规则进行处理，不会因为之前翻译过类似的内容就这次"偷懒"或"发挥"。

#### 分层校验的三道防线

`createTask` 方法展示了三层校验机制的协作：

| 层次 | 名称 | 作用 | 示例 |
|------|------|------|------|
| 第一层 | 输入清洗 (`#sanitizeInput`) | 过滤非法字段、标准化格式 | 去除字符串两端空白 |
| 第二层 | 自定义验证器 (`#runValidators`) | 应用场景特定的规则 | "标题不能包含敏感词" |
| 第三层 | 业务规则校验 (`#validateBusinessRules`) | 强制领域约束 | "高优先级任务必须有详细描述" |

这三道防线层层递进、各司其职。第一层保证数据的基本质量（像安检门检查你是否携带违禁品）；第二层应用具体场景的特殊要求（像海关针对特定国家旅客的额外检查）；第三层 enforcing 领域的核心规则（像法律底线——无论如何都不能违反）。

这种分层设计让校验逻辑变得**可组合、可扩展**。新的校验规则可以随时添加到合适的层次，而不会影响已有的逻辑。

#### 统一的返回格式

仔细观察 `TaskController` 的每个公共方法，你会发现它们都遵循统一的返回格式：

```javascript
{ success: boolean, data?: any, errors?: string[], message?: string }
```

这种一致性看似简单，但对调用方来说极其重要。无论是前端 UI 代码还是其他消费 Controller 服务的模块，都不需要针对每个方法写不同的结果解析逻辑。一个通用的处理器就能应对所有情况：

```javascript
// 通用的结果处理函数
function handleResult(result) {
  if (result.success) {
    showToast(result.message || '操作成功');
    if (result.data) renderData(result.data);
  } else {
    showError(result.errors.join('\n'));
  }
}

// 可以用于任何 Controller 方法的结果
handleResult(controller.createTask({...}));
handleResult(controller.updateTask(1, {...}));
handleResult(controller.deleteTask(99));
```

## 第三步：实现视图层（View 层）

在 MVC 的三要素中，View 层是与用户最直接接触的部分——它是用户能看到、摸到、与之交互的全部界面。在我们的纯 JavaScript 示例中，View 层的实现将采用**命令行界面（CLI）**的形式，因为这样可以避免 HTML/CSS 的干扰，让你聚焦于 View 层本身的架构设计。

### View 层的核心职责

View 层的职责可以用一句话概括：**将 Model 的数据以人类可读的形式呈现出来，并将人类的操作意图转化为标准的指令交给 Controller**。

这句话包含了两个方向的流动：

1. **Model → View（渲染/展示）**：数据变成视觉呈现
2. **View → Controller（事件/输入）**：用户操作变成业务指令

关键点在于：**View 不知道数据是怎么来的，也不知道数据处理后会去哪里**。它只知道两件事："给我什么数据我就怎么显示"和"用户点了什么按钮我就发出什么事件"。这种"无知"恰恰是 View 层保持简洁和可替换的关键。

### TaskView 类的实现

```javascript
/**
 * TaskView 类 —— 任务管理的视图层（CLI 版本）
 * 
 * 职责：
 *   1. 将任务数据渲染为可读的文本输出
 *   2. 提供用户交互界面（输入提示、选项菜单等）
 *   3. 格式化各类信息（统计、详情、表格等）
 * 
 * 设计特点：
 *   - 不直接操作 Model，通过 Controller 间接获取数据
 *   - 渲染逻辑与数据逻辑完全分离
 *   - 支持多种输出格式（简洁/详细/表格）
 */
class TaskView {
  #controller;       // Controller 引用
  #outputTarget;     // 输出目标（默认 console）
  #format;           // 当前输出格式
  #subscriptions;    // 存储订阅句柄（用于清理）

  // ====== 渲染格式常量 ======
  static Format = {
    COMPACT: 'compact',
    DETAILED: 'detailed',
    TABLE: 'table',
    CARD: 'card'
  };

  constructor(controller, options = {}) {
    if (!(controller instanceof TaskController)) {
      throw new Error('TaskView 需要一个 TaskController 实例');
    }
    
    this.#controller = controller;
    this.#outputTarget = options.outputTarget || console;
    this.#format = options.format || TaskView.Format.COMPACT;
    this.#subscriptions = [];
  }

  // ====== 输出配置 ======

  setFormat(format) {
    if (!Object.values(TaskView.Format).includes(format)) {
      throw new Error(`不支持的格式: ${format}`);
    }
    this.#format = format;
    return this;  // 支持链式调用
  }

  setOutput(target) {
    this.#outputTarget = target;
    return this;
  }

  // ====== 主要页面渲染 ======

  /** 渲染主面板/首页 */
  renderDashboard() {
    const result = this.#controller.getDashboard();
    if (!result.success) {
      this.#error(result.errors[0]);
      return;
    }

    const { overview, urgentItems, recentActions } = result.data;
    
    this.#clearScreen();
    this.#banner('📋 任务管理面板');

    // 总览卡片
    this.#section('总览');
    this.#infoGrid([
      ['总任务数', overview.total],
      ['已完成', `${overview.completed} (${Math.round(overview.completed / overview.total * 100)}%)`],
      ['待办', overview.byStatus['todo']],
      ['进行中', overview.byStatus['in-progress']],
      ['已阻塞', overview.byStatus['blocked']],
      ['平均紧急度', overview.averageUrgency.toFixed(2)]
    ]);

    // 紧急任务提醒
    if (urgentItems.length > 0) {
      this.#section('⚠️ 需要关注的任务');
      urgentItems.forEach(item => {
        this.#warn(`${item.title} (紧急度: ${item.urgency})`);
      });
    }

    // 最近操作
    if (recentActions.length > 0) {
      this.#section('最近操作');
      recentActions.slice(-5).forEach(action => {
        const icon = this.#getActionIcon(action.type);
        this.#plain(`  ${icon} ${action.type} → 任务#${action.targetId} (${this.#timeAgo(action.timestamp)})`);
      });
    }

    this.#renderMenu();
  }

  /** 渲染任务列表 */
  renderTaskList(tasks) {
    if (!tasks || tasks.length === 0) {
      this.#empty('暂无任务');
      return;
    }

    switch (this.#format) {
      case TaskView.Format.TABLE:
        this.#renderTable(tasks);
        break;
      case TaskView.Format.CARD:
        this.#renderCards(tasks);
        break;
      case TaskView.Format.DETAILED:
        tasks.forEach(t => this.renderTaskDetail(t));
        break;
      default:
        this.#renderCompactList(tasks);
    }
  }

  /** 渲染单个任务详情 */
  renderTaskDetail(taskData) {
    this.#section('📝 任务详情');
    this.#detailTable([
      ['ID', taskData.id],
      ['标题', taskData.title],
      ['描述', taskData.description || '(无)'],
      ['状态', this.#formatStatus(taskData.status)],
      ['优先级', this.#formatPriority(taskData.priority)],
      ['创建时间', this.#formatDate(taskData.createdAt)],
      ['更新时间', this.#formatDate(taskData.updatedAt)],
      ['标签', taskData.tags.length > 0 ? taskData.tags.join(', ') : '(无)'],
      ['子任务', taskData.subtasks ? taskData.subtasks.length : 0]
    ]);
  }

  /** 渲染搜索结果 */
  renderSearchResults(searchResult) {
    if (!searchResult.success) {
      this.#error(searchResult.errors[0]);
      return;
    }

    this.#section(`🔍 搜索结果 (${searchResult.total} 条匹配)`);
    
    if (searchResult.meta.searchKeyword) {
      this.#plain(`关键词: "${searchResult.meta.searchKeyword}"`);
    }
    if (searchResult.meta.status) {
      this.#plain(`状态过滤: ${searchResult.meta.status}`);
    }

    this.#renderTaskList(searchResult.data);
  }

  // ====== 用户交互方法 ======

  /** 显示创建任务表单 */
  showCreateForm() {
    this.#section('✨ 创建新任务');
    return {
      title: this.#prompt('请输入任务标题'),
      description: this.#prompt('请输入任务描述（可选）', true),
      priority: parseInt(this.#prompt('请输入优先级(1-5)', true) || '3')
    };
  }

  /** 显示编辑表单 */
  showEditForm(currentData) {
    this.#section('✏️ 编辑任务');
    
    const newValue = (field) => {
      const input = this.#prompt(`[${field}] 当前值: "${currentData[field]}"\n输入新值（留空保持不变）`, true);
      return input === '' ? currentData[field] : input;
    };

    return {
      title: newValue('title'),
      description: newValue('description'),
      priority: parseInt(newValue('priority'))
    };
  }

  /** 显示确认对话框 */
  confirm(message) {
    const input = this.#prompt(`${message} (y/n)`);
    return input.toLowerCase() === 'y' || input.toLowerCase() === 'yes';
  }

  /** 显示成功消息 */
  success(message) {
    this.#success(message);
  }

  /** 显示错误消息 */
  error(errors) {
    (Array.isArray(errors) ? errors : [errors]).forEach(e => this.#error(e));
  }

  // ====== 生命周期 ======

  /** 启动自动刷新（订阅 Model 变更）*/
  startAutoRefresh() {
    const unsub = this.#controller.getModel().subscribe((event) => {
      this.#hint(`数据已更新: ${event.type}`);
    });
    this.#subscriptions.push(unsub);
  }

  /** 清理资源 */
  destroy() {
    this.#subscriptions.forEach(unsub => unsub());
    this.#subscriptions = [];
  }

  // ====== 私有渲染方法 ======

  #renderCompactList(tasks) {
    tasks.forEach((t, i) => {
      const statusIcon = this.#getStatusIcon(t.status);
      const priorityBar = '█'.repeat(t.priority) + '░'.repeat(5 - t.priority);
      this.#plain(`  ${i + 1}. ${statusIcon} ${t.title} [${priorityBar}] #${t.id}`);
    });
  }

  #renderTable(tasks) {

    this.#plain(separator.replace(/─/g, '─'));

      this.#plain(line);
    });
    
    this.#plain('└' + '─'.repeat(header.length - 2) + '┘');
  }

  #renderCards(tasks) {
    tasks.forEach(t => {
      this.#box([
        `${this.#getStatusIcon(t.status)} ${t.title}`,

  #renderMenu() {

    this.#divider();
  }

  // ====== 低级 UI 工具方法 ======

  #clearScreen() { process.stdout.write('\x1B[2J\x1B[H'); }
  #banner(text) { this.#outputTarget.log(`\n${'═'.repeat(50)}\n  ${text}\n${'═'.repeat(50)}`); }
  #section(title) { this.#outputTarget.log(`\n─── ${title} ───`); }
  #divider() { this.#outputTarget.log('─'.repeat(50)); }

  #plain(msg) { this.#outputTarget.log(msg); }
  #info(msg) { this.#outputTarget.log(`ℹ️  ${msg}`); }
  #success(msg) { this.#outputTarget.log(`✅ ${msg}`); }
  #warn(msg) { this.#outputTarget.log(`⚠️  ${msg}`); }
  #error(msg) { this.#outputTarget.log(`❌ ${msg}`); }
  #empty(msg) { this.#outputTarget.log(`📭 ${msg}`); }
  #hint(msg) { this.#outputTarget.log(`💡 ${msg}`); }

  #infoGrid(rows) {

    rows.forEach(([key, value]) => {
      this.#plain(`  ${key.padEnd(maxKeyLen + 2)}: ${value}`);

  #detailTable(rows) {

  #box(lines) {

    return '';

    const mins = Math.floor(diff / 60000);
    if (mins < 1) return '刚刚';
    if (mins < 60) return `${mins}分钟前`;
    const hours = Math.floor(mins / 60);
    if (hours < 24) return `${hours}小时前`;
    const days = Math.floor(hours / 24);
    return `${days}天前`;
  }
```

### View 层的设计考量

#### 格式的多态性

`TaskView` 支持四种不同的输出格式：COMPACT（紧凑列表）、DETAILED（详细信息）、TABLE（表格）、CARD（卡片）。同一条数据可以根据不同的场景和用户偏好以不同的方式呈现。

这种灵活性是通过一个简单的**策略选择**实现的——`setFormat` 方法改变 `#format` 的值，然后各个渲染方法根据当前的 format 值选择不同的渲染分支。这比创建四个不同的 View 类要简洁得多，同时也避免了大量的重复代码。

**哲学思考**：同一份数据可以有多种呈现方式，这揭示了"内容与形式的二元性"——数据本身是客观的存在，而展示方式是我们主观的选择。就像同一个人可以在身份证照片、艺术照、漫画肖像中以截然不同的形象出现，但其内在的身份始终不变。优秀的 View 层设计应当让这种"多态呈现"变得简单自然，而不是每种格式都需要重写一套逻辑。

#### 输出目标的抽象

`TaskView` 并没有硬编码使用 `console.log` 作为唯一的输出方式。相反，它通过 `#outputTarget` 来引用输出目标，并通过 `setOutput` 方法允许动态更换。这意味着：

- 在 Node.js 环境中可以输出到控制台
- 在浏览器中可以输出到 DOM 元素
- 在测试中可以输出到内存缓冲区进行断言
- 在远程调试场景中可以通过网络发送到调试终端

这种**依赖注入（Dependency Injection）**的模式极大地增强了 View 层的可测试性和环境适应力。

## 第四步：组装与运行 —— 将一切整合

有了 Model、Controller、View 三个独立的层级，最后一步就是将它们组装成一个能运行的完整应用。这一步看似简单——无非是把 A 给 B，B 给 C——但组装的方式本身也蕴含着设计智慧。

### Application 类：胶水与入口

```javascript
/**
 * TaskApplication 类 —— 应用的入口和组装器
 * 
 * 职责：
 *   1. 组装 MVC 三个层级
 *   2. 管理应用的生命周期
 *   3. 处理顶层路由和全局配置
 *   4. 提供统一的启动/停止接口
 */
class TaskApplication {
  #model;          // TaskList
  #controller;     // TaskController
  #view;           // TaskView
  #config;         // 应用配置
  #running;        // 运行状态

  constructor(config = {}) {
    this.#config = {
      appName: config.appName || 'TaskManager',
      version: config.version || '1.0.0',
      storageEnabled: config.storageEnabled || false,
      autoSaveInterval: config.autoSaveInterval || 30000,
      ...config
    };
    this.#running = false;
  }

  // ====== 生命周期方法 ======

  /** 初始化应用 */
  async init() {
    if (this.#running) {
      throw new Error('应用已经在运行中');
    }

    // 1. 创建 Model
    const initialData = await this.#loadPersistedData();
    this.#model = new TaskList(initialData);

    // 2. 创建 Controller（注入 Model）
    this.#controller = new TaskController(this.#model);

    // 3. 注册全局验证器
    this.#registerGlobalValidators(this.#controller);

    // 4. 创建 View（注入 Controller）
    this.#view = new TaskView(this.#controller, {
      format: this.#config.defaultFormat || TaskView.Format.CARD
    });

    // 5. 启动 View 的自动刷新
    this.#view.startAutoRefresh();

    // 6. 启动持久化定时器
    if (this.#config.storageEnabled) {
      this.#startAutoSave();
    }

    this.#running = true;
    console.log(`✅ ${this.#config.appName} v${this.#config.version} 启动完成`);
    
    return this;
  }

  /** 启动交互循环 */
  run() {
    if (!this.#running) {
      throw new Error('请先调用 init() 初始化应用');
    }

    this.#view.renderDashboard();

    // 在真实应用中，这里会启动事件监听循环
    // 下面的代码是简化版的命令分发器示例
    return {
      // 暴露 API 供外部调用
      handleCommand: (command, ...args) => this.#dispatch(command, ...args),
      getState: () => ({ running: this.#running }),
      shutdown: () => this.shutdown()
    };
  }

  /** 关闭应用 */
  shutdown() {
    if (!this.#running) return;

    // 保存数据
    if (this.#config.storageEnabled) {
      this.#saveData();
    }

    // 清理 View 资源
    this.#view.destroy();

    // 停止定时器
    if (this.#autoSaveTimer) {
      clearInterval(this.#autoSaveTimer);
    }

    this.#running = false;
    console.log(`👋 ${this.#config.appName} 已关闭`);
  }

  // ====== 公开访问器 ======
  get model() { return this.#model; }
  get controller() { return this.#controller; }
  get view() { return this.#view; }
  get config() { return { ...this.#config }; }

  // ====== 私有方法 ======

  async #loadPersistedData() {
    if (!this.#config.storageEnabled) return [];
    
    try {
      // 实际应用中这里会从 localStorage / 文件系统 / 数据库加载
      const saved = localStorage.getItem(`${this.#config.appName}_data`);
      return saved ? JSON.parse(saved) : [];
    } catch {
      console.warn('加载数据失败，使用空白初始状态');
      return [];
    }
  }

  #saveData() {
    try {
      const data = this.#model.exportToJSON();
      localStorage.setItem(`${this.#config.appName}_data`, data);
    } catch (error) {
      console.error('保存数据失败:', error);
    }
  }

  #startAutoSave() {
    this.#autoSaveTimer = setInterval(() => {
      this.#saveData();
    }, this.#config.autoSaveInterval);
  }

  #registerGlobalValidators(controller) {
    // 标题长度验证
    controller.registerValidator('title-length', (data) => {
      if (data.title && data.title.length > 200) {
        return '标题不能超过200个字符';
      }
      return true;
    });

    // 敏感词过滤（示例）
    controller.registerValidator('content-filter', (data) => {
      const sensitiveWords = ['密码', 'secret', '机密'];
      const combined = `${data.title || ''} ${data.description || ''}`;
      const found = sensitiveWords.find(w => combined.includes(w));
      if (found) {
        return `内容包含敏感词: ${found}`;
      }
      return true;
    });
  }

  #dispatch(command, ...args) {
    const handlers = {
      'create': () => {
        const formData = this.#view.showCreateForm();
        const result = this.#controller.createTask(formData);
        if (result.success) {
          this.#view.success(result.message);
        } else {
          this.#view.error(result.errors);
        }
        return result;
      },
      'list': () => {
        const tasks = this.#controller.searchTasks({});
        this.#view.renderSearchResults(tasks);
        return tasks;
      },
      'search': (keyword) => {
        const results = this.#controller.searchTasks({ searchKeyword: keyword });
        this.#view.renderSearchResults(results);
        return results;
      },
      'dashboard': () => {
        this.#view.renderDashboard();
      },
      'help': () => {
        console.log(`
可用命令:
  create    - 创建新任务
  list      - 显示所有任务
  search <关键词> - 搜索任务
  dashboard - 显示仪表盘
  help      - 显示帮助
  exit      - 退出应用
        `);
      }
    };

    const handler = handlers[command];
    if (handler) {
      return handler(...args);
    } else {
      this.#view.error(`未知命令: ${command}。输入 help 查看可用命令。`);
    }
  }

  #autoSaveTimer;
}
```

### 组装过程中的设计洞察

#### 依赖注入的方向性

请注意我们的组装顺序：**Model → Controller → View**。这个顺序不是随意的，它反映了各层之间的依赖关系：

- Controller 依赖于 Model（需要 Model 来执行数据操作）
- View 依赖于 Controller（需要 Controller 来获取和处理数据）
- Model 不依赖任何人（它是最底层的数据实体）

这种单向的依赖关系是健康 MVC 架构的关键特征之一。如果你发现 View 直接依赖了 Model（绕过了 Controller），或者 Controller 直接操纵了 View（越过了 View 的渲染逻辑），那就说明出现了**分层违反（Layer Violation）**——这会导致代码之间的耦合度升高，后续维护变得困难。

**通俗类比**：这就像公司的组织结构：**基层员工（Model）** 完成具体的工作，**中层管理者（Controller）** 协调和分配任务，**高层对外接口（View）** 与外界沟通。基层不需要认识任何人，中层认识基层，高层认识中层。如果高层直接指挥基层（绕过中层），那么中层就被架空了，组织的层级结构也就失去了意义。

#### 闭包与生命周期的管理

`shutdown` 方法展示了资源清理的重要性。在 JavaScript 这种有垃圾回收的语言中，开发者很容易忘记手动清理资源——因为大多数情况下 GC 会帮你处理掉不再使用的对象。但有些资源是需要显式释放的：

- **定时器（Timer/Interval）**：如果不手动 clearInterval，即使应用"关闭"了，定时器回调仍然会继续执行
- **事件监听器（Event Listener）**：如果不移除 DOM 事件的监听器，可能导致内存泄漏
- **订阅（Subscription）**：我们在 `TaskView.destroy()` 中调用了所有 `unsubscribe` 回调来断开与 Model 的观察关系
- **文件句柄/网络连接**：虽然本例中没有用到，但在真实应用中这些也必须在关闭时释放

**哲学思考**：程序的"死亡"和人的离世一样，都需要妥善处理后事。一个设计良好的系统不仅要知道如何"出生"（初始化），还要知道如何"体面地离开"（清理资源）。那些忘记清理资源的程序就像不负责任的房客——搬走后留下了一堆还在运行的定时器和未关闭的连接，最终耗尽系统资源。

## 第五步：扩展 —— 让系统生长的能力

一个真正有价值的技术方案不仅要能用，还要具备**良好的可扩展性**。在本节中，我们将展示如何在已有的 MVC 框架上添加新功能，以此证明好的架构设计能够让系统像生物一样有机地生长。

### 扩展示例 1：添加任务分类（Category）功能

假设产品经理提出了一个新需求：任务需要支持按"分类"（Category）组织，比如"工作"、"学习"、"生活"等。一个好的架构应该如何应对这种变化？

```javascript
/**
 * Category 类 —— 任务分类
 * 
 * 设计说明：
 *   Category 是一个独立的概念，它与 Task 之间的关系是"一对多"
 *   （一个 Category 包含多个 Task）
 */
class Category {
  #id;
  #name;
  #color;          // 显示颜色
  #description;
  #createdAt;

  static VALID_COLORS = [
    '#EF4444', '#F97316', '#F59E0B', '#84CC16', '#22C55E',
    '#14B8A6', '#06B6D4', '#3B82F6', '#6366F1', '#8B5CF6'
  ];

  constructor({ id, name, color, description = '' }) {
    if (!name?.trim()) throw new Error('分类名称不能为空');
    
    this.#id = id ?? 'cat_' + Date.now().toString(36);
    this.#name = name.trim();
    this.#color = Category.VALID_COLORS.includes(color) 
      ? color 
      : Category.VALID_COLORS[Math.floor(Math.random() * Category.VALID_COLORS.length)];
    this.#description = description;
    this.#createdAt = new Date();
  }

  get id() { return this.#id; }
  get name() { return this.#name; }
  get color() { return this.#color; }
  get description() { return this.#description; }

  setName(name) {
    if (!name?.trim()) throw new Error('分类名称不能为空');
    this.#name = name.trim();
  }

  setColor(color) {
    if (!Category.VALID_COLORS.includes(color)) {
      throw new Error('无效的颜色值');
    }
    this.#color = color;
  }

  toJSON() {
    return {
      id: this.#id,
      name: this.#name,
      color: this.#color,
      description: this.#description
    };
  }

  static fromJSON(json) {
    return new Category({
      id: json.id,
      name: json.name,
      color: json.color,
      description: json.description
    });
  }
}
```

接下来，我们需要扩展现有的 `TaskList` 来支持分类管理：

```javascript
// 在 TaskList 类中新增以下方法：

/** 分类相关操作 */

/** 创建分类 */
addCategory(categoryData) {
  const category = new Category(categoryData);
  // 我们需要一个额外的 Map 来存储分类
  if (!this.#categories) this.#categories = new Map();
  this.#categories.set(category.id, category);
  this.#notify({ type: 'category-add', category });
  return category;
}

/** 获取所有分类 */
getCategories() {
  if (!this.#categories) return [];
  return Array.from(this.#categories.values());
}

/** 将任务分配到分类 */
assignTaskToCategory(taskId, categoryId) {
  const task = this.#tasks.get(taskId);
  const category = this.#categories?.get(categoryId);
  
  if (!task) throw new Error(`任务 ${taskId} 不存在`);
  if (!category) throw new Error(`分类 ${categoryId} 不存在`);

  // 通过给任务添加特殊标签来实现关联
  task.addTag(`__category:${categoryId}`);
  this.#notify({ type: 'task-assigned', taskId, categoryId });
  
  return { task, category };
}
```

**关键的架构洞察**：注意我们是如何扩展 `TaskList` 的——我们没有修改已有的任何方法（如 `addTask`、`updateTask` 等），只是**添加了新方法**。已有的功能不受影响，新的功能通过新的接口提供。这符合**开放-封闭原则（Open-Closed Principle）**——对扩展开放，对修改封闭。

### 扩展示例 2：添加撤销/重做功能

另一个常见的需求是支持操作的可撤销和重做（Undo/Redo）。这是一个典型的**命令模式（Command Pattern）**应用场景：

```javascript
/**
 * Command 基类 —— 所有可撤销操作的抽象基类
 */
class Command {
  execute() { throw new Error('子类必须实现 execute()'); }
  undo() { throw new Error('子类必须实现 undo()'); }
  toString() { return this.constructor.name; }
}

/**
 * CreateTaskCommand —— 创建任务的命令
 */
class CreateTaskCommand extends Command {
  #controller;
  #taskData;
  #createdTaskId;

  constructor(controller, taskData) {
    super();
    this.#controller = controller;
    this.#taskData = taskData;
  }

  execute() {
    const result = this.#controller.createTask(this.#taskData);
    if (result.success) {
      this.#createdTaskId = result.data.id;
    }
    return result;
  }

  undo() {
    if (this.#createdTaskId) {
      return this.#controller.deleteTask(this.#createdTaskId, true);
    }
    return { success: false, errors: ['没有可撤销的操作'] };
  }
}

/**
 * ChangeStatusCommand —— 状态变更的命令
 */
class ChangeStatusCommand extends Command {
  #controller;
  #taskId;
  #newStatus;
  #previousStatus;

  constructor(controller, taskId, newStatus) {
    super();
    this.#controller = controller;
    this.#taskId = taskId;
    this.#newStatus = newStatus;
  }

  execute() {
    // 先记录当前状态以便撤销
    const detail = this.#controller.getTaskDetail(this.#taskId);
    if (detail.success) {
      this.#previousStatus = detail.data.status;
    }
    return this.#controller.changeStatus(this.#taskId, this.#newStatus);
  }

  undo() {
    if (this.#previousStatus) {
      return this.#controller.changeStatus(this.#taskId, this.#previousStatus);
    }
    return { success: false, errors: ['没有可撤销的操作'] };
  }
}

/**
 * CommandManager —— 命令管理器（管理撤销栈和重做栈）
 */
class CommandManager {
  #undoStack;   // 撤销栈
  #redoStack;   // 重做栈
  #maxSize;     // 最大历史记录数

  constructor(maxSize = 50) {
    this.#undoStack = [];
    this.#redoStack = [];
    this.#maxSize = maxSize;
  }

  /** 执行命令并压入撤销栈 */
  execute(command) {
    if (!(command instanceof Command)) {
      throw new Error('必须是 Command 的实例');
    }

    const result = command.execute();
    
    if (result.success) {
      this.#undoStack.push(command);
      this.#redoStack = [];  // 执行新操作后清空重做栈
      
      // 限制栈大小
      if (this.#undoStack.length > this.#maxSize) {
        this.#undoStack.shift();
      }
    }

    return result;
  }

  /** 撤销上一个操作 */
  undo() {
    if (this.#undoStack.length === 0) {
      return { success: false, errors: ['没有可撤销的操作'] };
    }

    const command = this.#undoStack.pop();
    const result = command.undo();
    
    if (result.success) {
      this.#redoStack.push(command);
    }

    return {
      success: true,
      action: `已撤销: ${command.toString()}`
    };
  }

  /** 重做上一个被撤销的操作 */
  redo() {
    if (this.#redoStack.length === 0) {
      return { success: false, errors: ['没有可重做的操作'] };
    }

    const command = this.#redoStack.pop();
    const result = command.execute();
    
    if (result.success) {
      this.#undoStack.push(command);
    }

    return {
      success: true,
      action: `已重做: ${command.toString()}`
    };
  }

  get canUndo() { return this.#undoStack.length > 0; }
  get canRedo() { return this.#redoStack.length > 0; }
  get historyCount() { return this.#undoStack.length; }
}
```

**命令模式的美妙之处**在于它将"做什么"和"怎么做"彻底解耦。每个命令对象都是一个自包含的操作单元——它知道自己如何执行（`execute`），也知道自己如何撤销（`undo`）。`CommandManager` 不需要知道命令的具体内容，它只需要管理两个栈（撤销栈和重做栈），并在适当的时候调用命令的方法即可。

**通俗类比**：命令模式就像一台**录像机**。你的每个操作都被"录制"下来（压入撤销栈），按"回退"键时就把最后的操作倒放回去（pop 出来调用 undo），按"前进"键则重新播放（从重做栈取出调用 execute）。录像机不需要知道你录的是什么节目，它只需要管理播放头和磁带的进出。

## 架构反思：我们学到了什么？

通过从头构建一个完整的 MVC 系统，我们实际上经历了一次微型的软件架构设计之旅。在这个过程中，JavaScript 的 `class` 语法扮演了不可或缺的角色。让我们总结一下本文所传达的核心洞见。

### 类作为契约的定义者

在本文的所有代码中，每一个 `class` 都不仅仅是一组属性和方法的集合——它是一种**契约（Contract）**的定义：

- `Task` 类定义了"什么是任务"的契约——任何被称为 Task 的对象都必须有 id、title、status 等属性，都必须能执行 transitionTo、setTitle 等操作
- `TaskList` 类定义了"如何管理一组任务"的契约——必须提供 addTask、removeTask、filter 等标准接口
- `TaskController` 类定义了"如何与任务数据交互"的契约——所有操作都通过统一格式的返回值反馈结果
- `TaskView` 类定义了"如何展示任务信息"的契约——支持多种格式、统一的输出风格

**这种契约精神正是大型工程项目中协作的基础**。当一个团队成员看到 `Task` 类的定义时，他不需要阅读任何使用处的代码就能理解这个对象能做什么、不能做什么。当他需要使用 `TaskController` 时，他清楚地知道每个方法期望什么参数、返回什么格式的结果。这种**可预测性（Predictability）** 是降低协作成本、提高代码质量的根本保障。

### 封装的多层含义

在本文的实践中，我们多次使用了封装，但每次的含义略有不同：

| 封装类型 | 技术手段 | 保护的对象 | 示例 |
|----------|----------|------------|------|
| **数据封装** | `#` 私有字段 | 对象的内部状态不被篡改 | `Task.#status` |
| **行为封装** | 公共方法 | 操作数据的唯一途径 | `task.transitionTo()` |
| **实现封装** | 类的边界 | 内部算法对外不可见 | `TaskList` 内部用 Map 存储任务 |
| **变化封装** | 接口稳定性 | 实现可以改，接口不变 | `TaskController` 的统一返回格式 |

这四层封装共同构成了一个坚固的防御体系——**数据不会被意外破坏，行为不会被绕过，实现细节不会泄露，内部变化不会波及外部**。这就是为什么面向对象的代码在面对需求变更时通常比面向过程的代码更加从容。

### MVC 与 JavaScript 类的天然契合

回望整个实现过程，我们会发现 MVC 的三层架构与 JavaScript `class` 的特性之间存在一种天然的契合关系：

- **Model 层**充分利用了 `#` 私有字段、getter/setter、静态方法等特性来实现**数据的完整性保护**和**行为的内聚**
- **Controller 层**利用类的实例化和依赖注入实现了**无状态的处理逻辑**和**清晰的接口边界**
- **View 层**利用类的多态能力和方法组织实现了**灵活的渲染策略**和**可替换的表现形式**

这种契合并非巧合。MVC 的提出者 Smalltalk 是一门纯粹的面向对象语言，而 JavaScript 的 `class` 语法虽然是原型继承的语法糖，但它确实让 JavaScript 程序员得以用接近传统 OOP 语言的方式来表达 MVC 这样的经典架构模式。

> **更深层的思考**：MVC 不仅是一种技术架构，更是一种**思维方式**。它教导我们将复杂问题分解成三个相互独立又密切配合的方面——数据是什么、数据看起来是什么样的、数据如何被改变。这种思维方式超越了任何一种编程语言、任何一个框架。无论你使用 JavaScript 的 class、Go 语言的结构体、还是 Rust 的 trait，MVC 所倡导的"分离关注点"理念都是适用的。掌握了这种思维，你就获得了一种可以在不同技术语境间迁移的元能力（Meta-Skill）。

## 总结：从代码到思维的跃迁

本文从零开始，使用 JavaScript 的 `class` 语法构建了一套完整的 MVC 任务管理系统。在这个过程中，我们涵盖了以下知识点和实践经验：

**语法层面的收获**：
- `#` 私有字段及其与 `_` 约定私有属性的本质区别
- `static` 静态方法和静态属性的正确使用场景
- `get`/`set` 访问器的强大表达力和适用时机
- `extends` 继承在构建类型体系中的作用

**设计模式的实践**：
- **状态机模式**：Task 的状态转换规则
- **观察者模式**：TaskList 的变更通知机制
- **命令模式**：撤销/重做功能的实现
- **工厂模式**：`Task.fromJSON()` 静态工厂方法
- **策略模式**：View 的多格式渲染

**架构思想的领悟**：
- **分层架构**：Model/Controller/View 各司其职、依赖方向明确
- **依赖注入**：通过构造函数参数传递依赖，增强可测试性
- **开放-封闭原则**：通过扩展而非修改来增加功能
- **接口一致性**：统一的返回格式降低调用方的认知负担

但最重要的是——**代码只是载体，思维才是目的**。本文的几百行代码本身并不那么重要（你可以用很多种方式写出功能相同的代码），重要的是在这些代码背后所体现的那种**将复杂性有序化、将混沌结构化的思维方式**。当你下次面对一个复杂的问题时，希望你能想起本文中的一个核心理念：

> **不要试图一次性解决所有问题。先把问题分解成独立的、职责清晰的小块（Model、View、Controller），然后用类把每块的内部结构和外部契约定义清楚，最后再考虑如何让它们优雅地协作。这就是面向对象编程——乃至所有工程设计——的灵魂所在。**
