# 国际化 API —— Intl 全套（日期、数字、相对时间、段、列表格式化）

## 一、一个被严重低估的内置能力

在 JavaScript 开发的日常中，有一个极其强大却常常被视而不见的 API 体系——**Intl（Internationalization，国际化）**。它不是某个 npm 包的产物，不需要安装依赖，不需要引入 CDN 链接，它就在 `globalThis` 上静静地等待着——从 ECMAScript 2015（ES6）起就内置在了每一个现代 JavaScript 运行时中。

但"存在"和"被使用"之间隔着巨大的鸿沟。很多开发者在需要格式化日期时第一时间想到的是 moment.js 或 dayjs；需要格式化货币时手写正则替换；需要处理多语言复数规则时自己写一串 if-else 判断。他们不知道——或者说没有认真去了解——浏览器已经为他们准备好了一整套经过精心设计的、符合 Unicode 标准的、覆盖数十种语言数百个地区的国际化工具箱。

本文将系统地讲解这套工具箱中的每一件工具：`DateTimeFormat`（日期时间）、`NumberFormat`（数字与货币）、`RelativeTimeFormat`（相对时间）、`ListFormat`（列表连接）、`PluralRules`（复数规则）、`DisplayNames`（名称显示）、`Segmenter`（文本分段）、`Collator`（字符串比较排序）以及 `Locale`（地区标识解析）。每一个 API 都会配合丰富的代码示例、通俗的生活类比和深度的技术思考。

### 1.1 为什么国际化比你想象的更难

在深入 API 之前，先理解一个问题：为什么"让应用支持多种语言和地区"这件事如此困难？很多开发者最初的想法是——不就是做个"中英切换"嘛，准备两套文案不就行了？

这种想法忽略了一个基本事实：**语言差异只是国际化的冰山一角。** 真正的挑战隐藏在海面之下：

```javascript
// ❌ 最朴素（也是最错误）的国际化的样子
const lang = getUserLanguage();

if (lang === 'zh') {
    console.log('价格：¥1,234.56');
    console.log('日期：2025/6/15');
    console.log('3天前');
} else if (lang === 'en') {
    console.log('Price: $1,234.56');     // 格式对了吗？
    console.log('Date: 2025/6/15');       // 美国人写法一样吗？
    console.log('3 days ago');            // 复数形式对吗？
} else if (lang === 'de') {
    // 德语呢？德语的数字格式是 "1.234,56 €"
    // 小数点和千位符跟英语完全相反！
}
```

这段代码至少暴露了以下问题：

**第一，数字格式的地区差异远超直觉。** 同样是 `1234.56` 这个数值：
- 美国：`$1,234.56`（逗号是千位符，点号是小数点）
- 德国：`1.234,56 €`（点号是千位符，逗号是小数点）
- 法国：`1 234,56 €`（空格作为千位符）
- 印度：`₹1,234.56`（独特的 lakh/crore 计数体系，三位后变两位分组）
- 日本：`￥1,235`（默认不含小数，自动四舍五入）

如果你用硬编码的方式处理这些差异，光是数字格式就需要为每个地区写一套转换逻辑。

**第二，日期格式更是五花八门。**

| 地区 | 2025年6月15日 下午2:30 的显示方式 |
|------|----------------------------------|
| 中国大陆 | 2025年6月15日 14:30 |
| 美国 | 6/15/2025, 2:30 PM |
| 英国 | 15/06/2025, 14:30 |
| 日本 | 2025年6月15日 14:30 |
| 德国 | 15.6.2025, 14:30 |
| 法国 | 15/06/2025 à 14:30 |

注意月和日的顺序——美国是"月/日"，大多数欧洲国家是"日/月"。搞混了后果很严重：`3/4/2025` 在美国人眼里是三月四日，在英国人眼里是四月三日。

**第三，复数规则的复杂程度令人绝望。** 英语只有两种复数形式："1 item" 和 "N items"。这看起来很简单——用 `n === 1 ? 'item' : 'items'` 就能解决。但世界上有大约 **6000 种语言**，它们的复数规则各不相同：

- **俄语**：有 one/few/many/other 四种形式（基于尾数的复杂规则）
- **阿拉伯语**：有 zero/one/two/few/many/other 六种形式！（是的，六种！）
- **爱尔兰语**：one/two/few/many/other 五种形式，且规则涉及数字的具体值而非简单的数学规律

手工编写这些规则？不可能的任务。

> **生活类比：国际化的难度就像组织一场跨国晚宴**
>
> 想象你要邀请来自十个不同国家的客人共进晚餐。你面临的挑战包括：
>
> - **座位安排**：某些文化中座次有严格的等级规矩（中国），另一些文化则随意得多（澳大利亚）。就像不同的地区对日期中年/日/年的排列顺序有不同的偏好。
>
> - **菜单翻译**：你不能只把菜名从中文翻译成英文就算完事。有些客人不吃猪肉（穆斯林），有些不吃牛肉（印度教徒），有些人对坚果过敏。你需要了解每一种饮食文化的深层约束。就像不同语言的复数规则——表面上是单复数的区分，背后是一整套复杂的语法系统。
>
> - **餐具摆放**：中国人用筷子，西方人用刀叉，印度部分地区用手抓饭，韩国人用金属筷子配铁勺。你不能只准备一种餐具然后指望所有人凑合使用。就像数字格式——同样是"表示一个金额"，不同地区的小数点符号、千位分隔符、货币符号位置都截然不同。
>
> - **时间观念**：你的请柬上写着"7 点开始"。但有的客人理解为"7 点整到场"，有的理解为"7 点左右到都可以"，还有的理解为"7 点之后慢慢来"。就像相对时间的表达——"3 天前"、"昨天"、"上周"这些说法在不同语言中有完全不同的自然表达方式。
>
> Intl API 就是那位精通十国礼仪、熟悉每种饮食文化、了解每套餐具规范的专业宴会策划师。你只需要告诉他"我要招待哪些国家的客人"，他就会帮你处理好一切细节。

### 1.2 Locale——一切的核心标识

在使用任何 Intl API 之前，必须理解一个核心概念：**Locale（地区标识）**。它是所有 Intl 构造函数的第一个参数，决定了格式化的行为方式。

Locale 不是简单的一个"语言代码"。它的完整结构是一个 **Unicode BCP 47 语言标签**：

```
language-script-region-variants-extensions
```

| 部分 | 示例 | 含义 |
|------|------|------|
| `language` | `zh`, `en`, `fr`, `ar` | ISO 639-1 语言代码 |
| `script` | `Hans`, `Hant`, `Latn`, `Arab` | ISO 15924 脚本代码 |
| `region` | `CN`, `US`, `JP`, `DE` | ISO 3166-1 国家/地区代码 |

实际例子：
- `zh-Hans-CN`：简体中文-中国大陆（简体汉字 + 中国地区习惯）
- `zh-Hant-TW`：繁体中文-中国台湾（繁体汉字 + 台湾地区习惯）
- `en-US`：英语-美国
- `en-GB`：英语-英国（注意：同是英语，美英之间有很多格式差异）
- `sr-Cyrl-SR`：塞尔维亚语（西里尔字母）-塞尔维亚
- `sr-Latn-SR`：塞尔维亚语（拉丁字母）-塞尔维亚

**同一个语言的不同脚本是一个重要的区分维度。** 中文有简体和繁体之分（`Hans` vs `Hant`），塞尔维亚语可以同时用西里尔字母和拉丁字母书写。如果你的用户群体跨越了这些边界，仅凭 `zh` 或 `sr` 这样的语言代码是不够精确的。

```javascript
// 如何获取用户的 Locale 偏好
// 方式一：从 HTML 文档获取
document.documentElement.lang;  // <html lang="zh-CN"> → 'zh-CN'

// 方式二：从浏览器的偏好设置获取
navigator.language;             // 用户首选语言，如 'zh-CN'
navigator.languages;            // 所有偏好的语言列表（按优先级排序）

// 方式三：使用 Intl.Locale 解析和验证标签
const locale = new Intl.Locale('zh-Hans-CN-u-ca-buddhist-nu-thai');
console.log(locale.language);   // 'zh'
console.log(locale.script);     // 'Hans'
console.log(locale.region);     // 'CN'
console.log(locale.calendar);   // 'buddhist'（佛教历，来自 u-ca 扩展）
console.log.locale.numberingSystem;  // 'thai'（泰文数字，来自 nu 扩展）

// Intl.Locale 还能查询该 locale 支持的能力
locale.hourCycles;              // ['h11', 'h23'] 等
locale.collations;              // ['compat', 'eor', ...] 排序规则
locale.timeZones;               // 该地区常用的时区
locale.weekInfo;                // 一周的第一天是哪一天等信息
```

`Intl.Locale` 本身就是一个强大的工具——它能将一个看似简单的语言标签拆解成丰富的结构化信息，还能告诉你这个 locale 有哪些特殊属性（比如一周从周几开始、有哪些可用的排序规则等）。

> **哲学思考**：Locale 这个概念体现了**身份的多层次性**。一个人的"语言身份"不是单一的——他可能说着简体中文、住在中国大陆、使用公历纪年、用阿拉伯数字计数。另一个同样说中文的人可能住在台湾、使用民国纪年、同样用阿拉伯数字。这两个人的 Locale 标识分别是 `zh-Hans-CN` 和 `zh-Hant-TW`——它们共享语言但不共享脚本和地区。这与人类的身份认同何其相似：我们每个人都是多个"子身份"的交集——国籍、母语、文化背景、教育经历……每一个维度都贡献了一部分特征，最终组合成了独一无二的"我"。Locale 的 BCP 47 标签体系不过是把这种多维身份用一种机器可读的形式编码了出来而已。

## 二、Intl.DateTimeFormat——日期时间的千面形态

日期时间格式化是国际化中最常见也最容易出错的需求之一。`Intl.DateTimeFormat` 是专门解决这个问题的构造器。

### 2.1 从痛点出发

在没有 Intl API 的时代，开发者通常这样处理日期显示：

```javascript
// ❌ 手动拼接日期 —— 脆弱且不可靠
function formatDate(date) {
    const y = date.getFullYear();
    const m = date.getMonth() + 1;
    const d = date.getDate();
    
    // 中文的拼接方式
    return `${y}年${m}月${d}日`;
}

formatDate(new Date(2025, 5, 15));
// → "2025年6月15日"

// 但如果用户是美国用户呢？
// 你需要另一套逻辑：
function formatDateEn(date) {
    // 月/日/年 还是 日/月/年？
    // AM/PM 还是 24小时制？
    // 月份缩写还是全称？
}

// 如果用户又换到了德国？日本？阿拉伯世界？
// 每种情况都要重新写一套格式化逻辑
```

这种方式的问题显而易见：**你需要手动编码每一种地区的日期格式规则**，而全世界有数百种有效的 Locale 组合，每种都有自己独特的日期书写习惯。

### 2.2 DateTimeFormat 的两种用法

`Intl.DateTimeFormat` 提供了两种风格的使用方式：**精细控制模式**和**预设样式模式**。

#### 精细控制模式——每个组件单独配置

```javascript
const date = new Date(2025, 5, 27, 14, 30, 0);  // 2025年6月27日 14:30

// 完全控制每个日期时间组件的显示方式
const options = {
    weekday: 'long',          // 星期几："Friday" / "星期五" / "freitag"
    year: 'numeric',          // 年份："2025"
    month: 'long',            // 月份："June" / "6月" / "Juni"
    day: 'numeric',           // 日期："27"
    hour: 'numeric',          // 小时："2 PM" / "14时" / "14 Uhr"
    minute: 'numeric',        // 分钟："30"
    second: 'numeric',        // 秒：（可选）
    timeZoneName: 'shortOffset'  // 时区："GMT+8"
};

// 同样的选项 + 同样的日期对象，不同的 Locale 输出完全不同
new Intl.DateTimeFormat('en-US', options).format(date);
// → "Friday, June 27, 2025 at 2:30 PM GMT+8"

new Intl.DateTimeFormat('zh-CN', options).format(date);
// → "2025年6月27日 星期五 14:30 GMT+8"

new Intl.DateTimeFormat('de-DE', options).format(date);
// → "Freitag, 27. Juni 2025 um 14:30 GMT+8"

new Intl.DateTimeFormat('ja-JP', options).format(date);
// → "2025年6月27日金曜日 14:30 GMT+8"

new Intl.DateTimeFormat('ar-SA', options).format(date);
// → "الجمعة، ٢٧ يونيو ٢٠٢٥ في ٢:٣٠ م GMT+8"
// 注意阿拉伯数字：٢=2،٢٧=27，٢٠٢٥=2025
```

每个选项参数的可选值及其含义：

| 参数 | 可选值 | 说明 |
|------|--------|------|
| `weekday` | `'long'` / `'short'` / `'narrow'` | `"星期五"` / `"周五"` / `"五"` |
| `year` | `'numeric'` / `'2-digit'` | `"2025"` / `"25"` |
| `month` | `'numeric'` / `'2-digit'` / `'long'` / `'short'` / `'narrow'` | `"6"` / `"06"` / `"六月"` / `"6月"` / `"6"` |
| `day` | `'numeric'` / `'2-digit'` | `"27"` / `"27"` |
| `hour` | `'numeric'` / `'2-digit'` | `"2 PM"` / `"02 PM"` 或 `"14"` / `"14"` |
| `minute` | `'numeric'` / `'2-digit'` | `"30"` / `"30"` |
| `second` | `'numeric'` / `'2-digit'` | `"00"` / `"00"` |
| `timeZoneName` | `'long'` / `'short'` / `'shortOffset'` / `'longOffset'` | `"中国标准时间"` / `"CST"` / `"GMT+8"` / `"GMT+08:00"` |

#### 预设样式模式——快速获得常用格式

如果你不需要精细控制，只需要一个"好看的日期/时间显示"，可以使用预设样式：

```javascript
const date = new Date(2025, 5, 27, 14, 30, 0);

// dateStyle + timeStyle 的四种预设组合
const formats = [
    { dateStyle: 'full', timeStyle: 'full' },
    { dateStyle: 'full', timeStyle: 'long' },
    { dateStyle: 'long', timeStyle: 'short' },
    { dateStyle: 'medium', timeStyle: 'medium' },
    { dateStyle: 'short', timeStyle: 'short' }
];

// 英文（美国）
formats.forEach(opts => 
    console.log(new Intl.DateTimeFormat('en-US', opts).format(date))
);

// full+full:  "Friday, June 27, 2025 at 2:30:00 PM China Standard Time"
// full+long:  "Friday, June 27, 2025 at 2:30:00 PM CST"
// long+short: "June 27, 2025, 2:30 PM"
// medium:    "Jun 27, 2025, 2:30 PM"
// short:     "6/27/25, 2:30 PM"


// 中文（中国大陆）
formats.forEach(opts => 
    console.log(new Intl.DateTimeFormat('zh-CN', opts).format(date))
);

// full+full:  "2025年6月27日星期五 中国标准时间 14:30:00"
// full+long:  "2025年6月27日星期五 CST 14:30:00"
// long+short: "2025年6月27日 14:30"
// medium:    "2025/6/27 14:30"
// short:     "25/6/27 14:30"
```

预设样式特别适合那些"我不关心具体长什么样，只要符合当地习惯就行"的场景——比如日志系统的时间戳、UI 上的发布时间显示等。

### 2.3 formatToParts——获取结构化的组成部分

除了返回格式化后的完整字符串，`DateTimeFormat` 还提供了一个 `formatToParts` 方法，能够将结果分解为带有类型标注的结构化数组：

```javascript
const formatter = new Intl.DateTimeFormat('zh-CN', {
    year: 'numeric',
    month: 'long',
    day: 'numeric',
    hour: 'numeric',
    minute: 'numeric'
});

const parts = formatter.formatToParts(new Date(2025, 5, 27, 14, 30));

console.log(parts);
// → [
//     { type: 'year',    value: '2025' },
//     { type: 'literal', value: '年' },
//     { type: 'month',   value: '6' },
//     { type: 'literal', value: '月' },
//     { type: 'day',     value: '27' },
//     { type: 'literal', value: ' ' },
//     { type: 'hour',    value: '14' },
//     { type: 'literal', value: ':' },
//     { type: 'minute',  value: '30' }
// ]

// 实战应用：自定义渲染（比如给日期部分加上特殊样式）
const rendered = parts.map(({ type, value }) => {
    if (type === 'month' || type === 'day') {
        return `<span class="highlight">${value}</span>`;  // 高亮月和日
    }
    return value;
}).join('');

// → "2025<span class="highlight">6</span>月<span class="highlight">27</span> 14:30"
```

`formatToParts` 在需要对格式化结果的特定部分进行定制化处理的场景下非常有价值——比如你想给日期中的某些组件添加特殊的颜色或交互效果，或者需要在非 HTML 环境（如 Canvas 绘图）中精确定位每个组件的位置。

### 2.4 性能优化：复用实例

`DateTimeFormat` 的构造过程有一定的开销（需要加载 locale 数据、初始化格式化引擎）。因此在实际项目中，**应该避免在每次格式化调用时创建新实例**：

```javascript
// ❌ 低效做法：每次调用都创建新实例
function badFormat(date) {
    return new Intl.DateTimeFormat('zh-CN', {
        year: 'numeric', month: 'long', day: 'numeric'
    }).format(date);
}

// ✅ 正确做法：创建一次，重复使用
// 在模块顶层或类初始化时创建
const dateFormatter = new Intl.DateTimeFormat('zh-CN', {
    year: 'numeric', month: 'long', day: 'numeric'
});

const timeFormatter = new Intl.DateTimeFormat('zh-CN', {
    hour: '2-digit', minute: '2-digit', second: '2-digit'
});

const fullFormatter = new Intl.DateTimeFormat('zh-CN', {
    dateStyle: 'full', timeStyle: 'short'
});

// 之后直接调用 .format()
dateFormatter.format(new Date());      // "2026年4月22日"
timeFormatter.format(new Date());      // "16:19:30"
fullFormatter.format(new Date());      // "2026年4月22日星期三 16:19"
```

> **生活类比：专业导游 vs 临时向导**
>
> `DateTimeFormat` 就像一位精通各国日期书写习惯的专业导游。
>
> 如果你每次要展示日期都临时雇一位新导游（`new DateTimeFormat()`），让他先研究一下目的地的日期惯例再给你做讲解——这不仅浪费时间（初始化开销），而且每位导游的风格还可能略有不同（虽然理论上不应该）。
>
> 更聪明的做法是雇佣几位常驻导游，每位专精一种展示风格（日期型、时间型、完整型）。当需要展示日期时，直接叫对应的导游过来就行——他已经准备好了所有知识，随叫随到，响应迅速。
>
> 这就是"复用实例"的本质：**把一次性学习成本转化为长期的知识资产。**

## 三、Intl.NumberFormat——数字、货币与单位的艺术

如果 `DateTimeFormat` 处理的是"什么时候"的问题，那么 `Intl.NumberFormat` 处理的就是"多少"的问题。而"多少"这个问题在国际化的语境下，比大多数人想象的要复杂得多。

### 3.1 数字格式化的地区迷宫

让我们从一个直观的对比开始，感受一下同一个数字在不同地区是如何被表达的：

```javascript
const number = 1234567.89;

// 不同地区对同一个数字的显示方式
const locales = [
    ['en-US', { style: 'decimal' }],           // 美国
    ['de-DE', { style: 'decimal' }],           // 德国
    ['fr-FR', { style: 'decimal' }],           // 法国
    ['zh-CN', { style: 'decimal' }],           // 中国
    ['en-IN', { style: 'decimal' }],           // 印度（英语）
    ['ja-JP', { style: 'decimal' }],           // 日本
    ['ar-EG', { style: 'decimal' }]            // 埃及（阿拉伯语）
];

locales.forEach(([locale, opts]) => {
    console.log(`${locale}: ${new Intl.NumberFormat(locale, opts).format(number)}`);
});

// en-US: 1,234,567.89         （逗号分千位，点号分小数）
// de-DE: 1.234.567,89         （点号分千位，逗号分小数 —— 与美国完全反转！）
// fr-FR: 1 234 567,89          （空格分千位，逗号分小数）
// zh-CN: 1,234,567.89          （与美国相同）
// en-IN: 12,34,567.89          （印度的 lakhs 体系：最后三位一组，前面两位一组！）
// ja-JP: 1,234,567.89          （与美国相同）
// ar-EG: ١٬٢٣٤٬٥٦٧٫٨٩       （阿拉伯-印度数字！）
```

注意几个关键细节：

**德国的点号和逗号与美国完全互换。** 这不是排版错误——在欧洲大陆的大部分国家（德国、法国、意大利、西班牙等），逗号用作小数分隔符，而点号或空格用作千位分隔符。这意味着如果你在美国开发的电商网站简单地切换语言包而不使用 `NumberFormat`，德国用户看到的价格可能是 `1.234,57 €`——这在他们的认知中意味着一千多欧元，而不是你意图的一点多一点。

**印度有独特的数字分组体系。** 印度的数字书写传统不是每三位一分组（千进制），而是采用"拉克（lakh）"和"克若尔（crore）"体系：最低三位为一组（千位），然后往左每两位为一组（万位、亿位等）。所以 `1234567` 在印度写作 `12,34,567`（12 lakh 34 thousand 567）。

**阿拉伯语环境会自动使用阿拉伯-印度数字字符。** 数字 `1234567.89` 在阿拉伯语环境中显示为 `١٢٣٤٥٦٧٫٨٩`——这些是完全不同的 Unicode 字符，但在语义上代表相同的数值。

### 3.2 货币格式化——电商的核心需求

对于任何涉及金钱的应用来说，正确的货币格式化不仅是美观问题，更是**法律合规问题**：

```javascript
const price = 1234567.89;

// ===== 基础货币格式化 =====
new Intl.NumberFormat('en-US', {
    style: 'currency',
    currency: 'USD'
}).format(price);
// → "$1,234,567.89"

new Intl.NumberFormat('de-DE', {
    style: 'currency',
    currency: 'EUR'
}).format(price);
// → "1.234.567,89 €"
// 注意：€ 符号在数字后面！

new Intl.NumberFormat('ja-JP', {
    style: 'currency',
    currency: 'JPY'
}).format(price);
// → "￥1,234,568"
// 注意：日元通常不显示小数（自动四舍五入到整数）

new Intl.NumberFormat('zh-CN', {
    style: 'currency',
    currency: 'CNY'
}).format(price);
// → "¥1,234,567.89"


// ===== currencyDisplay：控制货币符号的显示方式 =====
const currencyOptions = [
    { currencyDisplay: 'symbol' },    // 默认：$ ¥ €
    { currencyDisplay: 'code' },      // ISO 代码：USD CNY EUR
    { currencyDisplay: 'name' },      // 全称：US Dollar 人民币 Euro
    { currencyDisplay: 'narrowSymbol' } // 缩写符号：$ ￥ €（可能无区别）
];

currencyOptions.forEach(opt => {
    console.log(
        new Intl.NumberFormat('en-US', { style: 'currency', currency: 'USD', ...opt })
            .format(price)
    );
});

// symbol:    "$1,234,567.89"
// code:      "USD 1,234,567.89"
// name:      "1,234,567.89 US Dollars"
// narrowSymbol: "$1,234,567.89"


// ===== 不同货币在同一地区的显示 =====
const currencies = ['USD', 'EUR', 'GBP', 'JPY', 'CNY', 'KRW'];
currencies.forEach(curr => {
    console.log(
        `${curr}: ${new Intl.NumberFormat('en-US', { style: 'currency', currency: curr }).format(price)}`
    );
});

// USD: $1,234,567.89
// EUR: €1,234,567.89
// GBP: £1,234,567.89
// JPY: ¥1,234,568        （日元舍入到整数）
// CNY: CN¥1,234,567.89    （CN¥ 区别于人民币 ¥）
// KRW: ₩1,234,568         （韩元也舍入到整数）
```

关于货币格式化，有一个容易踩坑的地方：**`style: 'currency'` 必须配合 `currency` 参数使用**，且 `currency` 必须是有效的 [ISO 4217 货币代码](https://en.wikipedia.org/wiki/ISO_4217)。不能传 `'¥'` 或者 `'美元'` 这样的值——必须是 `'CNY'`、`'USD'`、`'EUR'` 这样的三位字母代码。Intl 引擎会根据目标 locale 自动决定如何显示这个货币的符号、小数位数和位置。

### 3.3 单位格式化——物理量的本地化表达

`NumberFormat` 不仅支持纯数字和货币，还能格式化带单位的物理量：

```javascript
const measurements = [
    { value: 1500, unit: 'meter' },       // 米
    { value: 75.5, unit: 'kilogram' },    // 千克
    { value: 36.6, unit: 'celsius' },     // 摄氏度
    { value: 100, unit: 'kilometerPerHour' },  // km/h
    { value: 500, unit: 'liter' }         // 升
];

// 英文长单位名
const enLong = new Intl.NumberFormat('en-US', {
    style: 'unit',
    unitDisplay: 'long'    // "meters", "kilograms", "degrees Celsius"
});

measurements.forEach(m =>
    console.log(enLong.format(m.value, m.unit))
);

// 1,500 meters
// 75.5 kilograms
// 36.6°C                   ← 温度的单位显示方式特殊
// 100 kilometers per hour
// 500 liters


// 法语短单位名
const frShort = new Intl.NumberFormat('fr-FR', {
    style: 'unit',
    unitDisplay: 'short'   // "m", "kg", "°C"
});

// 中文短单位名
const zhShort = new Intl.NumberFormat('zh-CN', {
    style: 'unit',
    unitDisplay: 'short'
});

// 1,500 m
// 75,5 kg                  ← 法语用逗号作小数点！
// 36,6 °C
// 100 km/h
// 500 l

// 1,500米
// 75.5千克
// 36.6°C
// 100公里/小时
// 500升
```

单位格式化特别适合健康类应用（体重、身高、体温显示）、运动类应用（跑步距离、速度）、物流类应用（包裹重量、体积）等场景。它确保了单位名称也是本地化的——比如 "kilometer per hour" 在中文里变成 "公里/小时"，而不是生硬地直译。

### 3.4 特殊记数法——compact、scientific 与百分比

当数字非常大或非常小时，人类有各种简洁的表达方式。`NumberFormat` 的 `notation` 选项支持几种常见的记数法：

```javascript
const bigNumbers = [
    1200,
    15000,
    2800000,
    1530000000,
    8500000000000
];

// ===== compact 记数法：K/M/B 缩写 =====
const compactEn = new Intl.NumberFormat('en-US', {
    notation: 'compact',
    compactDisplay: 'short'
});

bigNumbers.forEach(n => console.log(compactEn.format(n)));

// 1.2K
// 15K
// 2.8M
// 1.53B
// 8.5T

// 中文环境下 compact 会使用"万""亿"单位
const compactZh = new Intl.NumberFormat('zh-CN', {
    notation: 'compact',
    compactDisplay: 'short'
});

bigNumbers.forEach(n => console.log(compactZh.format(n)));

// 1200
// 1.5万
// 280万
// 15.3亿
// 8.5万亿
// ← 注意中文使用了"万"和"亿的层级，这是中文特有的计数单位！


// ===== scientific 科学记数法 =====
const scientific = new Intl.NumberFormat('en-US', {
    notation: 'scientific'
});
scientific.format(299792458);
// → "2.998×10⁸"        （光速，科学记数法）


// ===== 百分比 =====
const percent = new Intl.NumberFormat('en-US', {
    style: 'percent'
});
percent.format(0.7854);     // → "78.54%"
percent.format(0.07);       // → "7%"
percent.format(1.5);        // → "150%"


// ===== 精度控制 =====
const precise = new Intl.NumberFormat('en-US', {
    minimumFractionDigits: 2,    // 至少2位小数
    maximumFractionDigits: 4,    // 最多4位小数
    useGrouping: false           // 不使用千位分隔符
});
precise.format(Math.PI);
// → "3.1416"
precise.format(100);
// → "100.00"                    // 强制补零到 minimumFractionDigits 位
```

> **哲学思考**：数字是人类最伟大的抽象发明之一。当我们写下 `1234` 时，这个符号序列在不同的文化和场景中承载着完全不同的意义——它可以是一个价格、一段距离、一个温度、一个人口数量、或者一个坐标。`Intl.NumberFormat` 所做的，就是帮助数字找到它在特定文化语境中的"正确形态"。
>
> 这让我想起一个有趣的语言学现象：**萨皮尔-沃夫假说（Sapir-Whorf hypothesis）** 的弱版本认为，一个人所说的语言会影响他的思维方式。虽然这个假说的强版本（语言决定思维）已被广泛质疑，但弱版本在某些领域确实成立——比如数字的认知。说英语的人习惯于按"千-百万-十亿"（每三位一跳）来理解大数字，而说中文的人习惯于按"万-亿-万亿"（四位一跳，但万以上又有变化）来理解。`Intl.NumberFormat` 尊重并适应了这些认知差异，它不是一个简单的"格式化工具"，而是**一座连接抽象数值与具体文化认知之间的桥梁**。

## 四、Intl.RelativeTimeFormat——"多久以前？"的自然表达

社交媒体的时间轴上充满了这样的文字："3 分钟前"、"昨天"、"上周"、"两个月后"。这种**相对时间**的表达方式与绝对日期（"2025年6月15日"）有着本质的区别——它依赖于"当前时刻"作为参照点，并且不同语言的自然表达习惯迥然不同。

### 4.1 基本用法

```javascript
// 创建 RelativeTimeFormat 实例
const rtf = new Intl.RelativeTimeFormat('zh-CN', {
    numeric: 'auto',     // 自动选择：可能用"明天"代替"1天后"
    style: 'long'        // 长格式："3天前"/"2个月后"
});

rtf.format(-1, 'day');    // → "1天前"
rtf.format(1, 'day');     // → "明天"           ← numeric: 'auto' 的魔力！
rtf.format(-7, 'day');    // → "7天前"
rtf.format(3, 'month');   // → "3个月后"
rtf.format(-2, 'year');   // → "2年前"
rtf.format(0.5, 'hour');  // → "30分钟前"       ← 自动转换单位！
```

注意 `numeric: 'auto'` 这个选项的作用。当值为 `-1` 或 `1` 且使用 `auto` 模式时，引擎会尝试使用该语言的**自然表达**来替代数字化的表述：

```javascript
// numeric: 'auto' vs numeric: 'always' 的对比
const autoRtf = new Intl.RelativeTimeFormat('zh-CN', { numeric: 'auto' });
const alwaysRtf = new Intl.RelativeTimeFormat('zh-CN', { numeric: 'always' });

const testCases = [[-1, 'day'], [1, 'day'], [-1, 'year'], [1, 'year']];

testCases.forEach(([value, unit]) => {
    console.log(`${value > 0 ? '+' : ''}${value} ${unit}:`);
    console.log(`  auto:   ${autoRtf.format(value, unit)}`);
    console.log(`  always: ${alwaysRtf.format(value, unit)}`);
});

// +1 day:
//   auto:   明天
//   always: 1 天后
//
// -1 day:
//   auto:   昨天
//   always: 1 天前
//
// +1 year:
//   auto:   明年
//   always: 1 年后
//
// -1 year:
//   auto:   去年
//   always: 1 年前
```

### 4.2 多语言对比与 style 变体

不同语言对相对时间的表达方式差异巨大：

```javascript
const locales = ['zh-CN', 'en-US', 'ja-JP', 'de-DE', 'fr-FR', 'ko-KR'];
const cases = [[-1, 'day'], [-3, 'day'], [1, 'week'], [-2, 'month']];

locales.forEach(loc => {

//
```

### 4.3 实战案例：智能时间显示组件

相对时间格式化最典型的应用就是社交动态流上的时间戳显示。下面是一个完整的实用实现：

```javascript
/**
 * 智能时间显示器
 * 根据时间差自动选择最佳的表达粒度和格式
 */
class SmartTimestamp {
    /**
     * @param {string} locale - 地区标识
     * @param {string} timezone - 时区（如 'Asia/Shanghai'）
     */
    constructor(locale = 'zh-CN', timezone) {
        this.rtf = new Intl.RelativeTimeFormat(locale, { numeric: 'auto' });
        this.dtFull = new Intl.DateTimeFormat(locale, {
            dateStyle: 'full',
            timeStyle: 'short',
            timeZone: timezone
        });
        this.dtShort = new Intl.DateTimeFormat(locale, {
            month: 'short',
            day: 'numeric',
            hour: '2-digit',
            minute: '2-digit',
            timeZone: timezone
        });
        
        this.thresholds = [
            { limit: 60,        unit: 'second' },
            { limit: 3600,       unit: 'minute' },
            { limit: 86400,      unit: 'hour' },
            { limit: 2592000,    unit: 'day',     fallbackToAbsolute: true },
            { limit: 31536000,   unit: 'month' },
            { limit: Infinity,   unit: 'year',    fallbackToAbsolute: true }
        ];
    }

    /**
     * 将 Date 对象转换为友好的时间显示
     * @param {Date|string|number} dateInput
     * @returns {string}
     */
    format(dateInput) {
        const date = new Date(dateInput);
        const now = Date.now();
        const diffMs = now - date.getTime();
        const diffSec = Math.abs(diffMs) / 1000;
        
        // 超过一个月的旧消息，回退到绝对日期
        if (diffSec > this.thresholds[3].limit) {
            return this.dtShort.format(date);
        }

        // 找到合适的粒度单位
        for (const t of this.thresholds) {
            if (diffSec < t.limit) {
                if (t.fallbackToAbsolute && Math.abs(diffSec) > 86400 * 3) {
                    return this.dtShort.format(date);
                }
                
                let value;
                switch (t.unit) {
                    case 'second': value = -Math.round(diffSec); break;
                    case 'minute': value = -(diffSec / 60); break;
                    case 'hour':   value = -(diffSec / 3600); break;
                    case 'day':    value = -(diffSec / 86400); break;
                    case 'month':  value = -(diffSec / 2592000); break;
                    case 'year':   value = -(diffSec / 31536000); break;
                }
                
                return this.rtf.format(value, t.unit);
            }
        }
        
        return this.dtFull.format(date);
    }
}


// 使用演示
const ts = new SmartTimestamp('zh-CN', 'Asia/Shanghai');

const now = new Date();
const samples = [
    new Date(now - 30 * 1000),           // 30秒前
    new Date(now - 5 * 60 * 1000),       // 5分钟前
    new Date(now - 3 * 60 * 60 * 1000),  // 3小时前
    new Date(now - 2 * 24 * 60 * 60 * 1000), // 2天前
    new Date(now - 10 * 24 * 60 * 60 * 1000), // 10天前 → 回退到绝对日期
    new Date(now - 40 * 24 * 60 * 60 * 1000), // 40天前 → 绝对日期
];

samples.forEach((d, i) => {
    console.log(`Sample ${i + 1}: ${ts.format(d)}`);
});

// 可能的输出（取决于当前时间）：
// Sample 1: 30秒前
// Sample 2: 5分钟前
// Sample 3: 3小时前
// Sample 4: 2天前
// Sample 5: 4月12日 16:19     ← 回退到绝对日期
// Sample 6: 3月13日 16:19     ← 绝对日期
```

> **生活类比：相对时间就像描述"距离"**
>
> 当有人问"超市有多远"的时候，你的回答方式取决于实际的距离远近：
> - "就在楼下"（非常近）
> - "走过去大概 5 分钟"（步行距离）
> - "开车 20 分钟"（短途驾驶）
> - "在城东边，大概 15 公里"（需要说明方向和大致距离）
> - "在邻县，走高速一个小时吧"（远距离）
> - "那个啊……你打开地图导航吧"（太远了，不如给坐标）
>
> 相对时间格式化的逻辑与此完全一致：**根据时间差的量级，自动选择最自然的表达粒度。** 几秒钟前发生的事情说"刚才"；几分钟前的说"N分钟前"；昨天的就直接说"昨天"；太久以前的干脆给出具体日期——因为"473天前"对人类大脑来说没有任何直观意义。
>
> `Intl.RelativeTimeFormat` 就是这位擅长用最恰当的方式来描述"时间距离"的向导。他知道在中文世界里"昨天"比"1天前"更自然，也知道在德语世界里"gestern"是昨天、"vor 3 Tagen"是三天前。他甚至知道日语要用"昨日"（比中文多了一个字）和"3日前"。这些都是每种语言在漫长历史中沉淀下来的表达习惯——你不需要自己去学习和记忆，交给他就好了。

## 五、Intl.ListFormat——"A、B 和 C"的语言学奥秘

把一个数组 `[apple, banana, cherry]` 友好地显示出来，看起来是个微不足道的需求——用 `array.join(', ')` 不就行了？但当你考虑多语言场景时，事情立刻变得复杂起来：

```javascript
const fruits = ['苹果', '香蕉', '樱桃'];

// ❌ 简单 join 无法满足多语言需求
fruits.join(', ');    // "苹果, 香蕉, 樱桃"  —— 中文其实不太用逗号连接
fruits.join('、');    // "苹果、香蕉、樱桃"  —— 中文用顿号，但最后一个呢？

// 英语应该是："apples, bananas, and cherries"  （ Oxford comma ）
// 法语应该是："pommes, bananes et cerises"    （ et 替代 and ）
// 日语应该是：「りんご、バナナ、さくらんぼ」   （ 、 连接，无需连词）
// 西班牙语应该是："manzanas, plátanos y cerezas" （ y 替代 and ）
```

`Intl.ListFormat` 就是用来解决这个"列表最后一项用什么连接词"以及"不同语言用什么标点"问题的。

### 5.1 三种列表类型

`ListFormat` 支持三种类型的列表，对应不同的语义：

```javascript
const items = ['Alice', 'Bob', 'Charlie'];

// ===== type: 'conjunction'（并列关系）—— A、B 和 C =====
const conj = new Intl.ListFormat('en-US', { type: 'conjunction' });
conj.format(items);  // "Alice, Bob, and Charlie"

new Intl.ListFormat('zh-CN', { type: 'conjunction' }).format(items);
// "Alice、Bob 和 Charlie"        ← 顿号 + 和

new Intl.ListFormat('ja-JP', { type: 'conjunction' }).format(items);
// "Alice、Bob、Charlie"          ← 只有顿号，没有连词

new Intl.ListFormat('de-DE', { type: 'conjunction' }).format(items);
// "Alice, Bob und Charlie"       ← und（和）

new Intl.ListFormat('fr-FR', { type: 'conjunction' }).format(items);
// "Alice, Bob et Charlie"        ← et（和）


// ===== type: 'disjunction'（选择关系）—— A、B 或 C =====
const disj = new Intl.ListFormat('en-US', { type: 'disjunction' });
disj.format(items);  // "Alice, Bob, or Charlie"

new Intl.ListFormat('zh-CN', { type: 'disjunction' }).format(items);
// "Alice、Bob 或 Charlie"

new Intl.ListFormat('de-DE', { type: 'disjunction' }).format(items);
// "Alice, Bob oder Charlie"      ← oder（或）

new Intl.ListFormat('ja-JP', { type: 'disjunction' }).format(items);
// "Alice、Bob、Charlie"          ← 日语并列和选择形式相同


// ===== type: 'unit'（单位组合）—— 无连词，紧凑连接 =====
const unitFmt = new Intl.ListFormat('en-US', { type: 'unit' });
unitFmt.format(['10', 'kg']);           // "10 kg"
unitFmt.format(['10', 'kg', '500', 'g']); // "10 kg 500 g"

new Intl.ListFormat('zh-CN', { type: 'unit' }).format(['10', 'kg', '500', 'g']);
// "10公斤500克"                       ← 单位合并时自动展开

new Intl.ListFormat('en-US', { type: 'unit', style: 'short' }).format(
    ['3', 'ft', '7', 'in']
);
// "3 ft 7 in"                        ← 英制单位的自然组合
```

### 5.2 style 变体与 formatToParts

与 `DateTimeFormat` 类似，`ListFormat` 也支持 `style` 选项和 `formatToParts` 方法：

```javascript
const items = ['Apple', 'Banana', 'Cherry'];

// style 变体
['long', 'short', 'narrow'].forEach(style => {
    const lf = new Intl.ListFormat('en-US', { type: 'conjunction', style });
    console.log(`${style}: ${lf.format(items)}`);
});

// long:   Apple, Banana, and Cherry
// short:  Apple, Banana, & Cherry
// narrow: Apple, Banana, Cherry


// formatToParts —— 结构化访问每个片段

console.log(parts);
// → [
//     { type: 'element', value: 'Alpha' },
//     { type: 'literal', value: ', ' },
//     { type: 'element', value: 'Beta' }
// ]
```

### 5.3 实际应用场景

`ListFormat` 的典型应用场景包括：

```javascript
/**
 * 场景 1：显示已选择的筛选条件
 */
function renderSelectedFilters(selectedTags) {
    if (selectedTags.length === 0) return '未选择任何条件';
    
    const formatter = new Intl.ListFormat(getUserLocale(), { type: 'conjunction' });
    return `已选：${formatter.format(selectedTags)}`;
}

// 中文用户看到：已选：前端、JavaScript 和 Vue
// 英文用户看到：Selected: Frontend, JavaScript, and Vue


/**
 * 场景 2：错误信息中的字段列举
 */
class ValidationError extends Error {
    constructor(fields, locale = 'zh-CN') {
        const listFmt = new Intl.ListFormat(locale, { type: 'disjunction' });
        super(`以下字段填写有误：${listFmt(fields)}`);
        this.fields = fields;
    }
}

throw new ValidationError(['email', 'password', 'phoneNumber'], 'zh-CN');
// → Error: 以下字段填写有误：email、password 或 phoneNumber

throw new ValidationError(['email', 'password', 'phoneNumber'], 'en-US');
// → Error: The following fields are invalid: email, password, or phoneNumber


/**
 * 场景 3：搜索关键词的高亮展示
 */
function highlightKeywords(text, keywords, locale = 'zh-CN') {
    const listFmt = new Intl.ListFormat(locale, { type: 'disjunction', style: 'short' });
    
    // 用 ListFormat 展示匹配的关键词
    const keywordStr = listFmt(keywords);
    
    // 同时在原文中高亮
    let highlighted = text;
    keywords.forEach(kw => {
        const regex = new RegExp(kw.replace(/[.*+?^${}()|[\]\\]/g, '\\$&'), 'gi');
        highlighted = highlighted.replace(regex, `<mark>$&</mark>`);
    });
    
    return { keywordStr, highlighted };
}
```

> **哲学思考**：列表连接词的差异折射出不同语言的**逻辑思维习惯**。英语严格区分"and"（并列/合取）和"or"（选择/析取），并且在正式书面语中还讲究 Oxford comma（"A, B, and C" 中 and 前面的逗号）。日语在并列和选择时都不使用显式的连接词，而是依靠上下文来隐含这种关系——这是一种更加依赖语境的高语境（High Context）文化特征。法语用 `et`（和）/ `ou`（或），德语用 `und`（和）/ `oder`（或），每种语言都有自己的"逻辑词汇"。
>
> `ListFormat` 所做的不仅仅是插入几个单词——它是在执行一种**语法层面的正确性保证**。就像你在正式场合穿着得体的礼服一样，使用正确的列表连接词让你的应用在用户面前显得"受过良好的教育"、尊重用户的语言习惯。这种尊重感虽然微妙，但它确实会影响用户对产品品质的感知。

## 六、Intl.PluralRules——复数形态的深渊

如果说其他 Intl API 解决的是"怎么显示"的问题，那么 `PluralRules` 解决的是一个更深层的问题：**"用哪种形态显示"。**

### 6.1 为什么复数规则如此复杂

在英语中，复数似乎很简单：`1 item` vs `N items`。一个 if 判断就够了：

```javascript
// 英语的复数 —— 看起来很简单
const text = count === 1 ? `${count} item` : `${count} items`;
```

但这种简单是一种错觉——它只是因为你恰好说英语。来看看世界的其他角落：

```javascript
// 俄语：有 4 种复数形式（基数词）
const prRu = new Intl.PluralRules('ru-RU', { type: 'cardinal' });

[1, 2, 5, 21, 22, 25].forEach(n => {
    console.log(`${n}: ${prRu.select(n)}`);
});

// 1:   one     (1 предмет)
// 2:   two      (2 предмета)
// 5:   other    (5 предметов)   ← 注意 5 直接跳到了 other！
// 21:  one      (21 предмет)    ← 以 1 结尾的数回到 one！
// 22:  few      (22 предмета)   ← 以 2-4 结尾的是 few！
// 25:  other    (25 предметов)


// 阿拉伯语：6 种复数形式！！
const prAr = new Intl.PluralRules('ar-EG', { type: 'cardinal' });

[0, 1, 2, 3, 10, 11, 100, 101].forEach(n => {
    console.log(`${n}: ${prAr.select(n)}`);
});

// 0:    zero
// 1:    one
// 2:    two
// 3:    few       （3-10 之间）
// 10:   few
// 11:   many      （11-99 之间）
// 100:  other     （100 及以上）
// 101:  one       ← 以 1 结尾，又回到了 one！
```

这就是 `PluralRules` 存在的理由：**复数规则无法用简单的数学公式概括，每种语言都有自己独特的历史演变出的复杂规则。** 它们涉及到词尾变化、数字的尾部特征（俄语）、甚至是数字本身的发音（阿拉伯语中某些规则取决于数字读法的语音特征）。

### 6.2 PluralRules 的实际使用模式

`PluralRules` 本身不产生文本——它只返回一个**复数类别键**（如 `"one"`, `"few"`, `"many"`, `"other"`）。你需要结合自己的翻译资源文件来使用这个键：

```javascript
/**
 * 通用的复数消息选择器
 */
class PluralMessage {
    /**
     * @param {string} locale - 地区标识
     * @param {object} messages - 复数消息映射
     * 例如: { one: '{count} 条消息', other: '{count} 条消息' }
     */
    constructor(locale, messages) {
        this.rules = new Intl.PluralRules(locale);
        this.messages = messages;
    }

    format(count) {
        const category = this.rules.select(count);
        const template = this.messages[category] || this.messages['other'];
        return template?.replace('{count}', String(count)) || '';
    }


// 使用示例
const msgZh = new PluralMessage('zh-CN', {
    one: '您有 {count} 条新消息',
    other: '您有 {count} 条新消息'
    // 中文实际上不分单复数，one 和 other 通常相同
});

msgZh.format(0);    // "您有 0 条新消息"
msgZh.format(1);    // "您有 1 条新消息"
msgZh.format(42);   // "您有 42 条新消息"


const msgEn = new PluralMessage('en-US', {
    one: 'You have {count} new message',
    other: 'You have {count} new messages'
});

msgEn.format(0);    // "You have 0 new messages"
msgEn.format(1);    // "You have 1 new message"     ← 单数！
msgEn.format(42);   // "You have 42 new messages"


const msgRu = new PluralMessage('ru-RU', {
    one: 'У вас {count} новое сообщение',
    few: 'У вас {count} новых сообщения',
    many: 'У вас {count} новых сообщений',
    other: 'У вас {count} новых сообщений'
});

msgRu.format(1);    // "У вас 1 новое сообщение"
msgRu.format(2);    // "У вас 2 новых сообщения"
msgRu.format(5);    // "У вас 5 новых сообщений"
msgRu.format(21);   // "У вас 21 новое сообщение"   ← 又回到 one 形式！
```

`PluralRules` 还支持序数词（ordinal）的复数规则：

```javascript
// 序数词：第 1 名、第 2 名、第 3 名……
const ordEn = new Intl.PluralRules('en-US', { type: 'ordinal' });
const ordFr = new Intl.PluralRules('fr-FR', { type: 'ordinal' });

[1, 2, 3, 4, 11, 12, 21, 22, 23].forEach(n => {
    console.log(
        `${n.padStart(2)}: en=${ordEn.select(n).padEnd(6)} fr=${ordFr.select(n)}`
    );
});

// 01: en=one    fr=one
// 02: en=two    fr=one     ← 法语没有 two！
// 03: en=few    fr=one
// 04: en=one    fr=one
// 11: en=one    fr=one
// 12: en=two    fr=one
// 21: en=one    fr=one
// 22: en=two    fr=one
// 23: en=few    fr=one

// 英语序数词的实际映射：
// one   → 1st, 21st, 31st, ...
// two   → 2nd, 22nd, 32nd, ...
// few   → 3rd, 23rd, ...
// other → 4th, 5th, ..., 11th, 12th, ...
```

> **生活类比：复数规则就像不同语言的"计件规则"**
>
> 想象你在经营一家全球连锁面包店。不同国家的顾客对面包数量的称呼方式截然不同：
>
> - **英语国家**的顾客：买 1 个叫 "a loaf"，买 N 个（N≠1）叫 "N loaves"。简单二元对立。
>
> - **俄罗斯**的顾客：买 1 个用一个词形（хлеб），买 2-4 个用另一种词形（хлеба），买 5-20 个又换一种（хлебей），买 21 个居然又回到了第一种！就像面包师在数数时有自己的一套奇怪规则——也许是因为俄罗斯面包太大，拿多了手会酸，所以不同数量要用不同方式拿？
>
> - **阿拉伯世界**的顾客：规则更加离谱——0 个、1 个、2 个、3-10 个、11-99 个、100+ 个各有各的说法。仿佛每一位顾客进店时都要先报出自己的幸运数字，面包师才能决定用哪种包装袋。
>
> - **中文**的顾客：不管买多少个，都说"个"。"1个面包"、"2个面包"、"100个面包"——中文通过在名词前面加数字来表达数量，名词本身不变。这让学中文的外国人松了一口气，也让 `PluralRules` 在中文环境下的输出几乎总是 `"other"`。
>
> `PluralRules` 就是那位背下了所有国家面包店的计件规则手册的超级收银员。无论顾客来自哪里、想买多少个面包，他都能准确地告诉厨房用哪种词形来写在发票上。

## 七、Intl.Segmenter——跨越字符边界的精准手术刀

在前面的所有 API 中，我们处理的都是"已经分割好的数据"——一个 Date 对象、一个 number、一个数组。但 `Intl.Segmenter` 面对的原始材料是最基本的：**字符串本身**。它的任务是将一个字符串按照语言学的规则切分成有意义的片段——字素（grapheme）、词（word）或句子（sentence）。

### 7.1 为什么 split() 不够用？

JavaScript 的字符串是基于 UTF-16 编码单元的，这导致了很多反直觉的行为：

```javascript
// 问题一：Emoji 的"视觉长度"与 .length 不一致
const emoji = '👨‍👩‍👧‍👦';  // 家庭 Emoji（由多个人物 Emoji 通过 ZWJ 连接组成）
emoji.length;
// → 11 ！（不是 1！）

// 问题二：组合字符被拆散
const cafe = 'cafe\u0301';  // café —— e + 重音组合字符
cafe.length;                 // → 4（不是 3！）
cafe.split('');
// → ['c', 'a', 'f', 'é']  （e 和重音符号是分开的！）

// 问题三：中文/日文/韩文（CJK）没有空格分词
const chinese = '我爱编程';
chinese.split(' ');
// → ['我爱编程']     （整个作为一个单元，无法分割出单个词）
chinese.split('');
// → ['我', '爱', '编', '程']  （只能拆成单个字，不是"词"）
```

这些问题在日常开发中会导致严重的 bug：

```javascript
// Bug 1：输入框字数限制出错
function checkLength(input, maxLength) {
    return input.length <= maxLength;  // ❌ 对 Emoji 不准确！
}

checkLength('👨‍👩‍👧‍👦', 10);   // true（length=11>10，被拒绝）——但视觉上只有一个字符！
checkLength('hello world', 10); // true（length=11>10，也被拒绝）——这个倒是合理的


// Bug 2：中文文本截断导致乱码
function truncate(text, maxChars) {
    return text.slice(0, maxChars) + '...';
}

truncate('国际化API非常强大有用', 10);
// → "国际化API非常有..."  —— 截断位置可能在"编"字的中间（UTF-16 中文字占2个编码单元）
//    结果可能出现乱码字符
```

### 7.2 Segmenter 的三种粒度

`Intl.Segmenter` 提供三种分段粒度，通过 `granularity` 选项控制：

#### grapheme（字素）——用户感知的"一个字符"

```javascript
const segmenterGrapheme = new Intl.Segmenter('zh', { granularity: 'grapheme' });

// 测试各种复杂的"字符"
const tests = [
    'Hello',           // 普通 ASCII
    '你好世界',        // CJK 字符
    '👋🌍🎉',           // Emoji
    '👨‍👩‍👧‍👦',          // 家庭 Emoji（ZWJ 序列）
    'e\u0301',         // 组合字符 é
    'Åland',           // 带 diacritic 的拉丁字母
    '🇨🇳',            // 旗帜 Emoji（区域指示符组合）
];

tests.forEach(str => {
    const segments = [...segmenterGrapheme.segment(str)];
    console.log(
        `"${str}".length=${str.length.toString().padStart(2)}, segments=${segments.length}:`,
        segments.map(s => `"${s.segment}"`).join(', ')
    );
});

// "Hello".length= 5, segments= 5: "H", "e", "l", "l", "o"
// "你好世界".length= 4, segments= 4: "你", "好", "世", "界"
// "👋🌍🎉".length= 3, segments= 3: "👋", "🌍", "🎉"
// "👨‍👩‍👧‍👦".length=11, segments= 1: "👨‍👩‍👧‍👦"     ← 关键！11个编码单元→1个可见字符！
// "é".length= 2, segments= 1: "é"                ← e + 重音 = 1个字素！
// "Åland".length= 5, segments= 5: "Å", "l", "a", "n", "d"
// "🇨🇳".length= 4, segments= 1: "🇨🇳"            ← 两个区域指示符 = 1面国旗
```

**grapheme 分段是处理用户输入时的最佳选择**——特别是当你需要计算"可视字符数量"用于限制输入框长度时：

```javascript
/**
 * 基于 grapheme 的安全字符计数器
 */
function getVisibleLength(text, locale = 'zh') {
    const segmenter = new Intl.Segmenter(locale, { granularity: 'grapheme' });
    return [...segmenter.segment(text)].length;
}

// 应用：安全的输入限制
function enforceMaxLength(input, maxLength, locale = 'zh') {
    const segmenter = new Intl.Segmenter(locale, { granularity: 'grapheme' });
    const segments = [...segmenter.segment(input)];
    
    if (segments.length <= maxLength) return input;
    
    // 安全截断：按 grapheme 边界截取
    return segments.slice(0, maxLength)
        .map(s => s.segment)
        .join('');
}

enforceMaxLength('👨‍👩‍👧‍👦Hello你好', 5);
// → "👨‍👩‍👧‍👦Hell"    （1个家庭 Emoji + 4个字母 = 5个可见字符，完美截断）
// 而不会出现截到 Emoji 中间导致的乱码问题
```

#### word（单词）——带语义的分词

```javascript
const segmenterWord = new Intl.Segmenter('en-US', { granularity: 'word' });
const segmenterWordZh = new Intl.Segmenter('zh', { granularity: 'word' });

const textEn = 'Hello, world! This is a test.';
const textZh = '你好，世界！这是一个测试。';

// 英文分词 —— 能识别单词、空格、标点的边界
for (const seg of segmenterWord.segment(textEn)) {
    console.log(JSON.stringify(seg.segment).padEnd(12), `isWordLike: ${seg.isWordLike}`);
}

// "Hello"       isWordLike: true     ← 这是一个真正的单词
// ","           isWordLike: false    ← 标点
// " "           isWordLike: false    ← 空格
// "world"       isWordLike: true
// "!"           isWordLike: false
// " "           isWordLike: false
// "This"        isWordLike: true
// " "           isWordLike: false
// "is"          isWordLike: true
// " "           isWordLike: false
// "a"           isWordLike: true
// " "           isWordLike: false
// "test"        isWordLike: true
// "."           isWordLike: false

console.log('\n--- 中文分词 ---\n');

// 中文分词 —— 按"词"切分（CJK 字符逐字分词，标点独立）
for (const seg of segmenterWordZh.segment(textZh)) {
    console.log(JSON.stringify(seg.segment).padEnd(8), `isWordLike: ${seg.isWordLike}`);
}

// "你好"       isWordLike: true     ← 注意：这里"你好"被视为一个整体！
// "，"         isWordLike: false    ← 标点
// "世界"       isWordLike: true     ← "世界"也是一个整体
// "！"         isWordLike: false
// "这是"       isWordLike: true
// "一个"       isWordLike: true
// "测试"       isWordLike: true
// "。"         isWordLike: false
```

注意中文分词的结果——`isWordLike: true` 的片段不一定是你期望的"词语"（比如"你好"、"世界"、"这是"），这是因为浏览器的 `Segmenter` 实现使用的分词算法比较基础，不像专业的 NLP 分词库那样有完整的词典支撑。但对于前端轻量级场景（如文本高亮、粗略的词频统计），它已经足够好用。

#### sentence（句子）——跨语言的断句

```javascript
const segmenterSentence = new Intl.Segmenter('zh', { granularity: 'sentence' });

const text = `
    第一句话。这是第二句话！第三句呢？第四句。
    "引用的内容也算一句话，"他说。
    第五句话...
`;

for (const seg of segmenterSentence.segment(text)) {
    console.log(seg.segment.trim());
}

// 第一句话。
// 这是第二句话！
// 第三句呢？
// 第四句。
// "引用的内容也算一句话，"他说。
// 第五句话...
```

句子分段在以下场景中特别有用：阅读进度计算、文本摘要提取、分页显示长文本等。

### 7.3 实战案例：多功能文本分析器

```javascript
/**
 * 文本分析器 —— 利用 Segmenter 实现多种文本分析功能
 */
class TextAnalyzer {
    constructor(locale = 'zh') {
        this.graphemer = new Intl.Segmenter(locale, { granularity: 'grapheme' });
        this.worder = new Intl.Segmenter(locale, { granularity: 'word' });
        this.senter = new Intl.Segmenter(locale, { granularity: 'sentence' });
    }

    /** 获取真实的可视字符数 */
    charCount(text) {
        return [...this.graphemer.segment(text)].length;
    }

    /** 获取单词/词元列表（排除空格和标点） */
    words(text) {
        return [...this.worder.segment(text)]
            .filter(s => s.isWordLike)
            .map(s => s.segment);
    }

    /** 词频统计 */
    wordFrequency(text) {
        const freq = new Map();
        this.words(text).forEach(word => {
            const lower = word.toLowerCase();
            freq.set(lower, (freq.get(lower) || 0) + 1);
        });
        return Array.from(freq.entries())
            .sort((a, b) => b[1] - a[1])
            .map(([word, count]) => ({ word, count }));
    }

    /** 句子列表 */
    sentences(text) {
        return [...this.senter.segment(text)]
            .map(s => s.segment.trim())
            .filter(s => s.length > 0);
    }

    /** 平均句子长度（按词计算） */
    avgSentenceLength(text) {
        const sentencess = this.sentences(text);
        if (sentencess.length === 0) return 0;
        
        const totalWords = sentencess.reduce((sum, s) => sum + this.words(s).length, 0);
        return (totalWords / sentencess.length).toFixed(1);
    }

    /** 安全截断（按 grapheme 边界） */
    safeTruncate(text, maxLength) {
        const segments = [...this.graphemer.segment(text)];
        if (segments.length <= maxLength) return text;
        return segments.slice(0, maxLength).map(s => s.segment).join('');
    }
}


// 使用示例
const analyzer = new TextAnalyzer('zh');
const articleText = `
    JavaScript 的 Intl API 是一个非常强大的国际化解决方案。
    它可以帮助开发者轻松地处理日期、数字、货币等格式化需求。
    无论你的用户在世界哪个角落，Intl 都能提供正确的本地化体验。
    这正是 Web 技术的魅力所在！
`;

console.log('可视字符数:', analyzer.charCount(articleText));
console.log('单词列表:', analyzer.words(articleText));
console.log('词频统计:', analyzer.wordFrequency(articleText));
console.log('句子数:', analyzer.sentences(articleText).length);
console.log('平均句长:', analyzer.avgSentenceLength(articleText), '词/句');
console.log('截取30字符:\n', analyzer.safeTruncate(articleText, 30));
```

> **哲学思考**：`Intl.Segmenter` 揭示了一个深刻的事实——**"字符"这个概念比我们以为的要复杂得多。** 在计算机科学的早期，一个字符等于一个字节（ASCII），世界很简单。后来变成了一个字符等于两个字节（UTF-16 的 BMP 范围内），还算可控。但 Unicode 引入了组合字符、变体序列、ZWJ（Zero Width Joiner，零宽连接符）、区域指示符组合（两个字符拼出一面国旗）之后，"一个字符"的定义彻底崩塌了。
>
> 这让人联想到物理学中对"基本粒子"的探索历程。古希腊人认为原子（atomos，意为"不可分割的"）是物质的最小单位。后来发现原子内部有电子、质子、中子。再后来发现夸克。现在我们还在寻找更基本的粒子。每一次"发现最小单位"的努力最终都被证明只是一个中间层——还有更深层的结构等待被发现。
>
> Unicode 的"字素簇（Grapheme Cluster）"概念也是如此。你以为 `e` + `́` 是两个字符？不，在用户眼中它只是一个 `é`。你以为 👨 + ‍ + 👩 + ‍ + 👧 + ‍ + 👦 是六个字符？不，在用户眼中它只是一个家庭 Emoji。`Intl.Segmenter` 的 grapheme 模式所做的，就是帮你在"编码层面"和"感知层面"之间架起桥梁——让你以用户看待文本的方式来处理文本，而不是以计算机存储文本的方式。

## 八、其余重要成员：Collator、DisplayNames 与 Locale

Intl 家族还有几个同样值得了解的重要成员，它们各自解决了特定的国际化需求。

### 8.1 Collator——字符串比较与排序

`Intl.Collator` 用于按照特定语言的规则进行字符串比较和排序。这比默认的 `Array.sort()` 更加智能：

```javascript
const names = ['äpfel', 'banana', 'Äther', 'apple', 'Zebra', 'zebra', '张三', '李四'];

// 默认排序（基于 UTF-16 码点 —— 通常不符合人类预期）
names.slice().sort();
// → ['Zebra', 'äpfel', 'Äther', 'apple', 'banana', 'zebra', '张三', '李四']
// 大写 Z 排在小写 ä 之前？这对任何人都没有意义


// 使用 Collator 进行德语排序
names.slice().sort(new Intl.Collator('de-DE').compare);
// → ['äpfel', 'Äther', 'apple', 'banana', 'Zebra', 'zebra', '张三', '李四']
// 现在 ä/Ä 排在正确的位置了！德语中 ä 等价于 ae，所以排在一起


// 使用 Collator 进行中文拼音排序
names.slice().sort(new Intl.Collator('zh-CN-u-co-pinyin').compare);
// → ['äpfel', 'Äther', 'apple', 'banana', '张三', '李四', 'Zebra', 'zebra']
// 中文名按拼音排序：Lǐ Sì（李四）< Zhāng Sān（张三）


// sensitivity 选项 —— 控制敏感度
const collBase = new Intl.Collator('en', { sensitivity: 'base' });     // 忽略大小写和重音
const collAccent = new Intl.Collator('en', { sensitivity: 'accent' }); // 区分重音但忽略大小写
const collCase = new Intl.Collator('en', { sensitivity: 'case' });     // 区分大小写但忽略重音

const testWords = ['Apple', 'apple', 'Apfel', 'äpfel'];

testWords.slice().sort(collBase.compare);
// → ['Apple', 'apple', 'Apfel', 'äpfel']    （base: A=a=Ä=ä）

testWords.slice().sort(collAccent.compare);
// → ['Apfel', 'Apple', 'apple', 'äpfel']   （accent: Apfel ≠ äpfel, Apple = apple）

testWords.slice().sort(collCase.compare);
// → ['apple', 'Apfel', 'äpfel', 'Apple']   （case: apple ≠ Apple, Apfel = äpfel）


// 实际应用：模糊搜索
function fuzzySearch(query, items, locale = 'zh') {
    const coll = new Intl.Collator(locale, { sensitivity: 'base' });
    query = query.toLowerCase();
    
    return items.filter(item => 
        coll.compare(item.toLowerCase(), query) >= 0 &&
        item.toLowerCase().includes(query.substring(0, 3))
    );
}

fuzzySearch('appl', ['Apple', 'application', 'Apfel', 'äpfel', 'Orange']);
// → ['Apple', 'application', 'Apfel', 'äpfel']
// 即使大小写不同、有变音符号也能匹配到
```

`sensitivity` 选项的四个级别总结：

| 值 | 区分大小写 | 区分重音 | 区分其他变体 | 适用场景 |
|----|-----------|---------|------------|---------|
| `'base'` | 否 | 否 | 否 | 模糊搜索、忽略差异的排序 |
| `'accent'` | 否 | **是** | 否 | 区分重音的语言（法语、德语等） |
| `'case'` | **是** | 否 | 否 | 大小写敏感但忽略重音 |
| `'variant'` | **是** | **是** | **是** | 最严格的比较（默认） |

### 8.2 DisplayNames——代码到名称的翻译官

`Intl.DisplayNames` 能够将各种标准化代码翻译为该语言下的可读名称。这在构建语言选择器、货币选择器等 UI 组件时极为有用：

```javascript
// ===== 语言名称 =====
const langNamesEn = new Intl.DisplayNames('en', { type: 'language' });
const langNamesZh = new Intl.DisplayNames('zh', { type: 'language' });

const codes = ['zh', 'zh-Hans', 'zh-Hant', 'en', 'ja', 'ko', 'ar', 'de', 'fr'];

codes.forEach(code => {
    console.log(
        `${code.padEnd(8)} → EN: ${langNamesEn.of(code)?.padEnd(20)} ZH: ${langNamesZh.of(code)}`
    );
});

// zh       → EN: Chinese               ZH: 中文
// zh-Hans  → EN: Chinese (Simplified)  ZH: 简体中文
// zh-Hant  → EN: Chinese (Traditional) ZH: 繁體中文
// en       → EN: English               ZH: 英语
// ja       → EN: Japanese              ZH: 日语
// ko       → EN: Korean                ZH: 韩语
// ar       → EN: Arabic                ZH: 阿拉伯语
// de       → EN: German                ZH: 德语
// fr       → EN: French                ZH: 法语


// ===== 国家/地区名称 =====
const regionNames = new Intl.DisplayNames('zh', { type: 'region' });

['US', 'CN', 'JP', 'GB', 'DE', 'FR', 'KR', 'TW', 'HK'].forEach(code => {
    console.log(`${code}: ${regionNames.of(code)}`);
});

// US: 美国
// CN: 中国
// JP: 日本
// GB: 英国
// DE: 德国
// FR: 法国
// KR: 韩国
// TW: 台湾
// HK: 香港


// ===== 货币名称 =====
const currencyNames = new Intl.DisplayNames('zh', { type: 'currency' });

['USD', 'EUR', 'CNY', 'JPY', 'GBP', 'KRW'].forEach(code => {
    console.log(`${code}: ${currencyNames.of(code)}`);
});

// USD: 美元
// EUR: 欧元
// CNY: 人民币
// JPY: 日元
// GBP: 英镑
// KRW: 韩圆


// ===== 脚本（书写系统）名称 =====
const scriptNames = new Intl.DisplayNames('zh', { type: 'script' });

['Latn', 'Hans', 'Hant', 'Arab', 'Cyrl', 'Jpan', 'Kore', 'Thai'].forEach(code => {
    console.log(`${code}: ${scriptNames.of(code)}`);
});

// Latn:  拉丁文
// Hans:  简体中文
// Hant:  繁体中文
// Arab:  阿拉伯文
// Cyrl:  西里尔文
// Jpan:  日文
// Kore:  韩文
// Thai:  泰文
```

`DisplayNames` 的 `fallback` 选项控制找不到匹配时的行为：

```javascript
const withCodeFallback = new Intl.DisplayNames('zh', { 
    type: 'currency', 
    fallback: 'code'     // 找不到翻译时返回原始代码
});

withCodeFallback.of('XYZ');  // "XYZ"（未知货币，返回代码本身）

const withNoneFallback = new Intl.DisplayNames('zh', { 
    type: 'currency', 
    fallback: 'none'      // 找不到翻译时返回 undefined
});

withNoneFallback.of('XYZ');  // undefined
```

### 8.3 Intl.Locale——地区标识的瑞士军刀

`Intl.Locale`（ECMAScript 2020 新增）不仅仅是一个字符串包装器——它是一个功能完备的地区标识解析和分析工具：

```javascript
const loc = new Intl.Locale('zh-Hans-CN-u-ca-buddhist-nu-thai-hc-h23');

// 基本信息
loc.baseName;           // "zh-Hans-CN"
loc.language;           // "zh"
loc.script;             // "Hans"
loc.region;             // "CN"

// Unicode 扩展（u-xxx 后缀中的内容）
loc.calendar;           // "buddhist"（使用佛历经）
loc.numberingSystem;    // "thai"（使用泰文数字）
loc.hourCycle;          // "h23"（24小时制）

// 查询能力
loc.weekInfo.firstDay;  // 1 （周一为一周第一天，中国的惯例）
loc.weekInfo.minimalDays;// 4 （一周最少需要几天才算"本周"）
loc.calendars;          // ["buddhist", "gregory", "roc"]
loc.collations;         // ["compat", "eor", "gb2312", ...]
loc.hourCycles;         // ["h11", "h23"]
loc.numberingSystems;   // ["arab", "arabext", "hanidec", "latn", "thai"]


// 实际应用：检测用户的时区偏好
function detectUserTimezone() {
    const navLoc = navigator.language;
    const loc = new Intl.Locale(navLoc);
    
    // 获取该 locale 的常用时区列表
    // 注意：这不是用户的实际时区，而是该地区的典型时区
    const likelyTimezones = loc.timeZones;
    
    // 结合 Intl.DateTimeFormat 检测实际时区
    const userTimezone = Intl.DateTimeFormat().resolvedOptions().timeZone;
    
    return { locale: navLoc, region: loc.region, userTimezone, likelyTimezones };
}

detectUserTimezone();
// { locale: "zh-CN", region: "CN", userTimezone: "Asia/Shanghai", likelyTimezones: ["Asia/Shanghai"] }
```

> **生活类比：DisplayNames 就像一位同声传译员**
>
> 想象你在参加一场联合国会议。台上有来自五十个国家的代表，每个人都说着自己的语言。当法国代表提到 "EUR" 时，中国代表的耳机里听到的是"欧元"；当中国代表说到 "CNY" 时，美国代表的笔记本上记下的是 "Chinese Yuan"。
>
> 这位神奇的翻译员就是 `Intl.DisplayNames`。他能瞬间将各种"代码"——语言代码（`zh`、`fr`）、国家代码（`CN`、`US`）、货币代码（`CNY`、`JPY`）、甚至书写系统代码（`Latn`、`Hans`）——翻译成听众母语中的可读名称。
>
> 更妙的是，你可以随时让他切换工作语言。上一刻他还在为中国观众服务（把 `USD` 翻译成"美元"），下一刻就可以转向法国观众（把同样的 `USD` 翻译成"dollar des États-Unis"）。不需要重新培训，不需要查阅字典——因为他脑中装着整个 Unicode 的 CLDR（Common Locale Data Repository）数据库。

## 九、综合实战案例——完整的国际化工具集

现在我们将前面学到的所有知识整合起来，构建一个可以在真实项目中使用的完整国际化工具库：

```javascript
/**
 * I18nKit —— 基于 Intl API 的完整国际化工具集
 * 
 * 无需任何第三方依赖，全部基于原生 Intl API 实现
 */
class I18nKit {
    /**
     * @param {string} locale - 地区标识（如 'zh-CN', 'en-US'）
     * @param {object} [options] - 配置项
     * @param {string} [options.timezone] - 时区
     * @param {string} [options.currency] - 默认货币
     */
    constructor(locale, options = {}) {
        this.locale = locale;
        this.options = options;

        // 预创建所有格式化器实例（性能优化）
        this._formatters = this._createFormatters();
        this._analyzer = null;  // TextAnalyzer 延迟创建（Segmenter 开销较大）
    }

    _createFormatters() {
        const { timezone, currency = 'CNY' } = this.options;
        const loc = this.locale;

        return {
            // ========== 日期时间 ==========
            dateFull: new Intl.DateTimeFormat(loc, { dateStyle: 'full', timeZone: timezone }),
            dateLong: new Intl.DateTimeFormat(loc, { dateStyle: 'long', timeZone: timezone }),
            dateMedium: new Intl.DateTimeFormat(loc, { dateStyle: 'medium', timeZone: timezone }),
            dateShort: new Intl.DateTimeFormat(loc, { dateStyle: 'short', timeZone: timezone }),
            timeShort: new Intl.DateTimeFormat(loc, { timeStyle: 'short', timeZone: timezone }),
            timeLong: new Intl.DateTimeFormat(loc, { timeStyle: 'long', timeZone: timezone }),
            datetimeFull: new Intl.DateTimeFormat(loc, { dateStyle: 'full', timeStyle: 'short', timeZone: timezone }),
            
            relativeTime: new Intl.RelativeTimeFormat(loc, { numeric: 'auto', style: 'long' }),

            // ========== 数字 ==========
            decimal: new Intl.NumberFormat(loc),
            percent: new Intl.NumberFormat(loc, { style: 'percent' }),
            compact: new Intl.NumberFormat(loc, { notation: 'compact' }),
            
            currency: (curr) => new Intl.NumberFormat(loc, {
                style: 'currency', currency: curr || currency
            }),

            // ========== 其他 ==========
            listConj: new Intl.ListFormat(loc, { type: 'conjunction' }),
            listDisj: new Intl.ListFormat(loc, { type: 'disjunction' }),
            listUnit: new Intl.ListFormat(loc, { type: 'unit' }),
            
            pluralRules: new Intl.PluralRules(loc),
            
            displayLanguage: new Intl.DisplayNames(loc, { type: 'language' }),
            displayRegion: new Intl.DisplayNames(loc, { type: 'region' }),
            displayCurrency: new Intl.DisplayNames(loc, { type: 'currency' }),
            
            collator: new Intl.Collator(loc),
            collatorInsensitive: new Intl.Collator(loc, { sensitivity: 'base' })
        };
    }

    // ==================== 日期时间方法 ====================

    /** 完整日期 */
    date(date) { return this._formatters.dateFull.format(date); }
    
    /** 短日期 */
    dateShort(date) { return this._formatters.dateShort.format(date); }
    
    /** 时间 */
    time(date) { return this._formatters.timeShort.format(date); }
    
    /** 日期+时间 */
    datetime(date) { return this._formatters.datetimeFull.format(date); }
    
    /** 相对时间 */
    relativeTime(value, unit) {
        return this._formatters.relativeTime.format(value, unit);
    }

    /** 智能时间戳（结合绝对时间和相对时间） */
    smartTime(dateInput) {
        const date = new Date(dateInput);
        const now = Date.now();
        const diffHours = (now - date.getTime()) / (1000 * 60 * 60);
        
        if (Math.abs(diffHours) < 48) {
            const diffSec = (now - date.getTime()) / 1000;
            let value, unit;
            if (Math.abs(diffSec) < 60) { value = -diffSec; unit = 'second'; }
            else if (Math.abs(diffSec) < 3600) { value = -(diffSec / 60); unit = 'minute'; }
            else { value = -(diffSec / 60 / 60); unit = 'hour'; }
            return this.relativeTime(value, unit);
        }
        return this.datetime(date);
    }

    // ==================== 数字方法 ====================

    /** 普通数字 */
    num(number) { return this._formatters.decimal.format(number); }
    
    /** 货币 */
    money(amount, currency) {
        return this._formatters.currency(currency).format(amount);
    }
    
    /** 百分比 */
    percent(value) { return this._formatters.percent.format(value); }
    
    /** 紧凑数字（K/M/B） */
    compactNum(number) { return this._formatters.compact.format(number); }

    // ==================== 列表方法 ====================

    /** 并列列表（和） */
    listAnd(items) { return this._formatters.listConj.format(items); }
    
    /** 选择列表（或） */
    listOr(items) { return this._formatters.listDisj.format(items); }
    
    /** 单位组合 */
    listUnit(items) { return this._formatters.listUnit.format(items); }

    // ==================== 文本方法 ====================

    /** 复数消息 */
    plural(count, messages) {
        const category = this._formatters.pluralRules.select(count);
        const template = messages[category] || messages['other'] || '';
        return template.replace('{count}', String(count));
    }

    /** 排序 */
    sort(array) {
        return array.slice().sort(this._formatters.collator.compare);
    }

    /** 模糊匹配 */
    fuzzyMatch(query, items) {
        const q = query.toLowerCase();
        return items.filter(item =>
            this._formatters.collatorInsensitive.compare(item.toLowerCase(), q) === 0 ||
            item.toLowerCase().includes(q)
        );
    }

    /** 显示名称 */
    languageName(code) { return this._formatters.displayLanguage.of(code); }
    regionName(code) { return this._formatters.displayRegion.of(code); }
    currencyName(code) { return this._formatters.displayCurrency.of(code); }

    /** 获取文本分析器（延迟初始化） */
    analyzer() {
        if (!this._analyzer) {
            // 动态 import TextAnalyzer（假设定义在其他地方或内联实现）
            const segmenterG = new Intl.Segmenter(this.locale, { granularity: 'grapheme' });
            const segmenterW = new Intl.Segmenter(this.locale, { granularity: 'word' });
            const segmenterS = new Intl.Segmenter(this.locale, { granularity: 'sentence' });
            
            this._analyzer = {
                visibleLength: (text) => [...segmenterG.segment(text)].length,
                words: (text) => [...segmenterW.segment(text)].filter(s => s.isWordLike).map(s => s.segment),
                sentences: (text) => [...segmenterS.segment(text)].map(s => s.segment.trim()).filter(Boolean),
                safeTruncate: (text, maxLen) => {
                    const segs = [...segmenterG.segment(text)];
                    return segs.length <= maxLen ? text : segs.slice(0, maxLen).map(s => s.segment).join('');
                }
            };
        }
        return this._analyzer;
    }

    /** 切换语言 */
    setLocale(newLocale) {
        this.locale = newLocale;
        this._formatters = this._createFormatters();
        this._analyzer = null;  // 重置分析器
        return this;  // 支持链式调用
    }
}


// ==================== 使用示例 ====================
const i18n = new I18nKit('zh-CN', {
    timezone: 'Asia/Shanghai',
    currency: 'CNY'
});

// 日期
i18n.date(new Date());              // "2026年4月22日 星期三"
i18n.smartTime(Date.now() - 3600000); // "1小时前"
i18n.smartTime(Date.now() - 86400000 * 5); // "2026年4月17日 16:19"

// 数字
i18n.num(1234567.89);              // "1,234,567.89"
i18n.money(99.99);                // "¥99.99"
i18n.money(99.99, 'USD');          // "$99.99"
i18n.percent(0.7854);              // "78.54%"
i18n.compactNum(2500000);          // "250万"

// 列表
i18n.listAnd(['前端', 'JavaScript', 'Vue']);  // "前端、JavaScript 和 Vue"
i18n.listOr(['红色', '蓝色', '绿色']);        // "红色、蓝色 或 绿色"
i18n.listUnit(['3', 'kg', '500', 'g']);      // "3公斤500克"

// 复数
i18n.plural(42, { other: '{count} 条消息' });  // "42 条消息"

// 排序
i18n.sort(['张三', '李四', '王五', '赵六']);
// → ['李四', '王五', '张三', '赵六']  （按拼音排序）

// 名称
i18n.languageName('de');    // "德语"
i18n.regionName('JP');      // "日本"
i18n.currencyName('GBP');   // "英镑"

// 文本分析
const ana = i18n.analyzer();
ana.visibleLength('你好🌍世界');   // 5
ana.words('Hello, World!');        // ['Hello', 'World']
ana.safeTruncate('你好🌍世界这是一段测试文字', 4);  // "你好🌍世界这"


// ===== 切换语言后一切自动适配 =====
i18n.setLocale('en-US').setLocale.bind(i18n);

i18n.date(new Date());              // "Wednesday, April 22, 2026"
i18n.money(99.99);                 // "$99.99"
i18n.smartTime(Date.now() - 3600000); // "1 hour ago"
i18n.listAnd(['Frontend', 'JS', 'React']); // "Frontend, JS, and React"
```

这个 `I18nKit` 类展示了如何将所有 Intl API 整合成一个统一的、易用的接口。它有几个设计亮点：

1. **延迟初始化**：`TextAnalyzer`（包含 `Segmenter` 实例）只在第一次使用时创建，避免了不必要的性能开销。
2. **预创建格式化器**：常用的格式化器在构造时就创建好，之后的每次调用都是 O(1) 的 `.format()` 操作。
3. **链式调用**：`setLocale()` 返回 `this`，方便连续操作。
4. **统一接口**：所有格式化能力通过同一个对象暴露，不需要记住各个独立的 Intl 构造函数。

## 十、总结：Intl API 的全景视图与思考

### 10.1 API 总览速查表

| 构造器 | 功能 | 核心方法 | ES 版本 |
|--------|------|---------|--------|
| `Intl.DateTimeFormat` | 日期时间格式化 | `.format()`, `.formatToParts()` | ES2015 (Intl) |
| `Intl.NumberFormat` | 数字/货币/单位格式化 | `.format()`, `.formatToParts()` | ES2015 (Intl) |
| `Intl.Collator` | 字符串比较排序 | `.compare()`, `.sort()` | ES2015 (Intl) |
| `Intl.PluralRules` | 复数规则判断 | `.select()` | ES2015 (Intl) |
| `Intl.RelativeTimeFormat` | 相对时间格式化 | `.format()` | ES2019 (ES10) |
| `Intl.ListFormat` | 列表格式化 | `.format()`, `.formatToParts()` | ES2019 (ES10) |
| `Intl.DisplayNames` | 代码→名称翻译 | `.of()` | ES2020 (ES11) |
| `Intl.Locale` | 地区标识解析与分析 | 各 getter 属性 | ES2020 (ES11) |
| `Intl.Segmenter` | 文本分段（字素/词/句） | `.segment()` | ES2020 (ES11) |

### 10.2 设计模式的共性

观察所有的 Intl 构造函数，可以发现它们共享着统一的设计模式：

```
1. 创建阶段（一次性开销）
   new Intl.XXXFormat(locale, options)

2. 使用阶段（高性能调用）
   formatter.format(input)

3. 结构化输出（可选）
   formatter.formatToParts(input)
```

**创建和使用分离**是这个设计的核心优势。格式化规则的解析和 locale 数据的加载只在构造时发生一次，后续的每次 `format()` 调用都是高效的查表和拼接操作。这也意味着**复用实例是正确的性能策略**。

> **最后的思考**：Intl API 体现了一种优雅的工程哲学——**将领域的复杂性封装在标准化的接口之下。** 你不需要理解阿拉伯语的复数规则体系，不需要记住印度数字的分组方式，不需要掌握中日韩文字的字素边界规则。你只需要调用一个构造器、传入一个 locale 标识、调用 format 方法。剩下的——CLDR 数据库中存储的数百种语言的文化规则、Unicode 联盟维护的标准规范、各大浏览器引擎团队优化的底层实现——全部在幕后默默地为你工作。
>
> 这种"复杂性隔离"的思想贯穿于优秀的软件设计之中。就像你不需理解 TCP/IP 协议栈的每一个细节就能发送 HTTP 请求一样，你不需掌握每一种语言的语法规则就能写出国际化的代码。**抽象的力量正在于此——它让你站在巨人的肩膀上，用一行代码触达整个世界的语言多样性。**
>
> 所以，下一次当你需要格式化日期时，试试 `Intl.DateTimeFormat`；需要显示货币时，试试 `Intl.NumberFormat`；需要处理多语言列表时，试试 `Intl.ListFormat`。它们一直在那里，安静地等着你——就像一本尘封已久的宝典，一旦翻开，你会发现里面藏着整个世界。
