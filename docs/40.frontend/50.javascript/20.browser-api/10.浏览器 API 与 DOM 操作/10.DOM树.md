# DOM 树 —— 节点类型、document、element、文本节点、注释

## 从 HTML 字符串到可编程对象的认知跃迁

当浏览器收到一段 HTML 源码时，它并不会直接把那些尖括号和标签名扔到屏幕上就了事。在渲染像素之前，浏览器必须完成一项根本性的工作：**把线性的文本流转化为具有结构关系的对象模型**。这个模型就是 **DOM（Document Object Model，文档对象模型）**。

DOM 的本质是一种**跨平台的、与语言无关的接口约定**——它用"树"这种数据结构来表示 HTML（或 XML）文档。每一个 HTML 标签、每一段文字、每一条注释，在 DOM 中都对应一个**节点（Node）**。这些节点之间通过父子、兄弟关系连接成一棵树。JavaScript 之所以能操作网页内容，正是因为它能通过这棵树来访问和修改每个节点。

> **本文的目标**：系统讲解 DOM 树的核心概念——从节点的 12 种类型到 document 全局入口，从元素节点与文本节点的区别到节点间的遍历关系，并揭示 DOM 设计背后的工程哲学。

## 一、DOM 树的诞生过程

### 1.1 从源码到树的五个阶段

当一段 HTML 文本被浏览器解析为 DOM 树，大致经历以下阶段：

```html
<!-- 这是你写的 HTML -->
<html>
<head><title>示例</title></head>
<body>
  <h1>你好</h1>
  <p>世界</p>
</body>
</html>
```

浏览器内部的处理流程：

```
HTML 源码 → 词法分析（Tokenization）→ 语法分析（Parsing）→ DOM 树构建 → 渲染
   ↓              ↓                        ↓                ↓            ↓
原始文本     "<html>"是标签          构建层级关系      对象模型       你看到的页面
             "你好"是文本           确定父子关系      可被 JS 访问
```

这个过程不是一次性完成的。现代浏览器采用**流式解析**策略——边下载边解析，不会等整个 HTML 文件全部到达才开始构建 DOM 树。这也是为什么把 `<script>` 放在 `<body>` 底部能加快页面渲染的原因：不会阻塞 DOM 树的构建。

### 1.2 生活类比：建筑蓝图到实体结构

如果把 HTML 源码比作一张**建筑蓝图**（纸面上的线条和标注），那么 DOM 树就是根据这张蓝图建造出来的**真实建筑结构**：

- **蓝图上的"客厅"三个字** → DOM 中的一个 `Element` 节点（`<div class="living-room">`）
- **蓝图中标注的面积数字** → DOM 中的 `Text` 节点（`"42㎡"`）
- **建筑师手写的备注** → DOM 中的 `Comment` 节点（`<!-- TODO: 增加窗户 -->`）
- **整栋建筑的入口** → DOM 中的 `document` 根节点

蓝图只是纸面上的描述，你没法对蓝图说"把客厅的墙挪两米"。但一旦建成了真实的建筑，你就可以进去拆墙、刷漆、搬家具——这就是 JavaScript 操作 DOM 的本质。

> **哲学思考**：DOM 的存在体现了**抽象层（Abstraction Layer）**的核心价值。人类之所以能建造摩天大楼，是因为我们不直接操作原子和分子，而是在"砖块—墙体—房间—楼层"这样的抽象层次上工作。同样，程序员之所以能用几行代码改变页面布局，是因为 DOM 在底层混乱的字节流和上层有序的编程接口之间建立了一个清晰的中间层。每一层抽象都隐藏了下层的复杂性，同时暴露出上层的可能性。

## 二、节点类型：DOM 宇宙中的 12 种粒子

### 2.1 Node 类型总览

DOM 规范定义了 **12 种节点类型**，每种类型用一个数值常量标识（`nodeType`）。虽然日常开发中只会用到其中的三四种，但了解完整列表有助于建立完整的认知框架：

| nodeType | 常量名 | 名称 | 说明 |
|----------|--------|------|------|
| 1 | `ELEMENT_NODE` | 元素节点 | `<div>`、`<p>`、`<span>` 等 |
| 2 | `ATTRIBUTE_NODE` | 属性节点 | `class="foo"`、`id="bar"`（已废弃） |
| 3 | `TEXT_NODE` | 文本节点 | 标签之间的纯文字内容 |
| 4 | `CDATA_SECTION_NODE` | CDATA 节段 | XML 中用的，HTML 几乎不用 |
| 5 | `ENTITY_REFERENCE_NODE` | 实体引用 | 已废弃 |
| 6 | `ENTITY_NODE` | 实体声明 | 已废弃 |
| 7 | `PROCESSING_INSTRUCTION_NODE` | 处理指令 | XML 中用，如 `<?xml-stylesheet?>` |
| 8 | `COMMENT_NODE` | 注释节点 | `<!-- 注释内容 -->` |
| 9 | `DOCUMENT_NODE` | 文档节点 | 整个文档的根，即 `document` 对象 |
| 10 | `DOCUMENT_TYPE_NODE` | 文档类型 | `<!DOCTYPE html>` |
| 11 | `DOCUMENT_FRAGMENT_NODE` | 文档片段 | 轻量级的文档容器 |
| 12 | `NOTATION_NODE` | 符号节点 | 已废弃 |

### 2.2 四大常用节点类型详解

#### 元素节点（nodeType = 1）

这是最常见也是最重要的节点类型。每一个 HTML 标签就是一个元素节点：

```javascript
// 获取一个元素节点
const h1 = document.querySelector('h1');
console.log(h1.nodeType);        // 1
console.log(h1.nodeName);        // 'H1'（标签名，大写）
console.log(h1.nodeValue);       // null（元素节点没有"值"）
console.log(h1.tagName);         // 'H1'
console.log(h1 instanceof Element);    // true
console.log(h1 instanceof Node);       // true（Element 继承自 Node）
console.log(h1 instanceof HTMLElement); // true（HTMLElement 继承自 Element）
```

注意继承链：`Node ← Element ← HTMLElement`。这意味着元素节点拥有 Node 的所有能力（遍历关系），又额外增加了 Element 特有的能力（属性操作、样式操作等）。

#### 文本节点（nodeType = 3）

标签之间的文字内容不是元素的一部分，而是独立的文本节点：

```javascript
const p = document.querySelector('p');
// 假设 <p>你好，世界</p>
console.log(p.childNodes.length);   // 1（包含一个子节点）
console.log(p.childNodes[0].nodeType);  // 3
console.log(p.childNodes[0].nodeValue);  // '你好，世界'
console.log(p.childNodes[0] instanceof Text);  // true

// 一个容易踩的坑：<p>   </p> 里面只有空白字符
// 这个空白也是一个文本节点！
const emptyP = document.querySelector('p.empty');
console.log(emptyP.childNodes.length);  // 1（空白文本节点）
console.log(emptyP.childNodes[0].nodeValue.trim());  // ''（空字符串）
```

文本节点没有子节点（它是叶子节点），它的"值"就是它所包含的文字本身。

#### 注释节点（nodeType = 8）

HTML 中的注释在 DOM 中也有对应的节点：

```html
<!-- 这是注释 -->
<div id="app">
  <!-- TODO: 重构此模块 -->
  <p>内容</p>
</div>
```

```javascript
// 遍历所有注释节点
const walker = document.createTreeWalker(
    document.body,
    NodeFilter.SHOW_COMMENT
);
const comments = [];
while (walker.nextNode()) {
    comments.push(walker.currentNode.nodeValue.trim());
}
console.log(comments);
// ['这是注释', 'TODO: 重构此模块']
```

注释节点在实际开发中不常直接操作，但有一些有趣的用途——比如用它做模板占位符或调试标记。

#### Document 节点（nodeType = 9）

`document` 是整个 DOM 树的根节点，代表完整的 HTML 文档：

```javascript
console.log(document.nodeType);        // 9
console.log(document.nodeName);        // '#document'
console.log(document.nodeValue);       // null
console.log(document.documentElement); // <html> 元素
console.log(document.head);            // <head> 元素
console.log(document.body);            // <body> 元素
console.log(document instanceof Document);  // true
console.log(document instanceof Node);      // true
```

`document` 是一个特殊的节点——它不是任何元素的子节点，而是整棵树的入口。你可以把它想象成这栋建筑的"产权证持有者"，通过它你才能进入建筑内部。

### 2.3 生活 analogy：DOM 节点的家庭角色

如果把这棵 DOM 树比作一个**家族谱系**：

- **Document 节点是家族的老祖宗**：它记录了整个家族的存在，但自己并不出现在任何照片里。你通过它才能查到家谱。
  
- **Element 节点是家族成员**：爷爷、父亲、儿子、女儿……每个人都有名字（tagName），有自己的特征（属性），可以有自己的后代。
  
- **Text 节点是家庭成员说的话**：话不能独立存在，它总是依附于某个人（父元素节点）。但话本身是有内容的（nodeValue）。
  
- **Comment 节点是家谱旁边的批注**："这个人很聪明""这里需要核实"。批注不影响家族关系，但它确实存在于记录中。

## 三、Document 全局对象：DOM 世界的大门

### 3.1 document 的核心属性与方法

`document` 是 JavaScript 访问 DOM 的唯一入口。浏览器环境中，它是一个全局变量，不需要任何导入就能使用：

```javascript
// === 入口属性 ===
document.documentElement;  // → <html> 元素
document.head;             // → <head> 元素
document.body;             // → <body> 元素（可能为 null，如果 script 在 head 中执行）

// === 文档信息 ===
document.title;            // 页面标题，可读写
document.URL;              // 完整 URL（只读）
document.domain;           // 当前域名（受限）
document.referrer;         // 来源页面 URL
document.cookie;           // Cookie 字符串
document.characterSet;     // 编码格式，通常为 'UTF-8'

// === 文档状态 ===
document.readyState;
// 'loading'   — 正在加载
// 'interactive' — DOM 解析完成（可操作 DOM 了）
// 'complete'   — 所有资源加载完毕

// 监听状态变化（比 DOMContentLoaded 更早的替代方案）
if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', () => {
        console.log('DOM 就绪！');
    });
} else {
    console.log('DOM 已经就绪');
}
```

### 3.2 document 创建节点的方法

`document` 提供了一系列工厂方法用于创建各种节点：

```javascript
// 创建元素节点
const div = document.createElement('div');
div.className = 'card';
div.id = 'card-1';

// 创建文本节点
const text = document.createTextNode('Hello World');

// 创建注释节点
const comment = document.createComment('动态生成的注释');

// 创建文档片段（轻量级容器）
const fragment = document.createFragment();

// 组装
fragment.appendChild(text);
div.appendChild(fragment);
comment.after(div);

console.log(div.outerHTML);
// → <div class="card" id="card-1">Hello World</div><!--动态生成的注释-->
```

### 3.3 生活类比：document 是前台接待处

如果把浏览器环境比作一栋大型办公楼：

- **`window` 是整栋楼的所有者**：它拥有全局视野，管理着所有设施（定时器、网络请求、存储等）。
  
- **`document` 是前台接待处**：当你想进入办公区域时，必须先到前台登记。前台知道每个部门在哪里（`querySelector`）、能帮你联系任何人（`getElementById`）、甚至能帮你创建新的工位（`createElement`）。
  
- 你不能绕过前台直接闯入办公室——所有对 DOM 的操作都必须通过 `document` 或其返回的对象来完成。

> **哲学思考**：`document` 作为全局入口的设计体现了一种**门面模式（Facade Pattern）**的思想。复杂的系统不应该暴露其内部的每一个细节给使用者；相反，它应该提供一个简洁统一的入口，将复杂性隐藏在幕后。当你调用 `document.createElement('div')` 时，你可能不知道浏览器内部经历了内存分配、原型链设置、默认属性初始化等一系列操作——这正是抽象的力量。好的 API 设计让简单的事情变得简单，让复杂的事情变得可能，而不是让一切复杂的事情暴露无遗。

## 四、元素节点 vs 文本节点：容易被忽视的区别

### 4.1 为什么区分它们很重要？

初学者最容易犯的一个错误就是混淆**元素**和**元素的内容**：

```html
<p id="msg">Hello World</p>
```

```javascript
const p = document.getElementById('msg');
// p 本身是元素节点（Element），nodeType = 1
// p 里面的 "Hello World" 是文本节点（Text），nodeType = 3

console.log(p.textContent);    // 'Hello World'（便捷属性，自动拼接所有子文本）
console.log(p.innerText);      // 'Hello World'（类似，但考虑 CSS 样式）
console.log(p.innerHTML);      // 'Hello World'（包含 HTML 标签的完整内容）

// 直接获取第一个子节点
console.log(p.firstChild.nodeValue);  // 'Hello World'

// 一个关键区别：innerHTML 会解析 HTML，textContent 不会
p.innerHTML = '<strong>Bold</strong>';
// 结果: <p id="msg"><strong>Bold</strong></p>  （strong 被渲染为粗体）

p.textContent = '<strong>Not Bold</strong>';
// 结果: <p id="msg">&lt;strong&gt;Not Bold&lt;/strong&gt;  （原样显示为文本）
```

### 4.2 空白文本节点陷阱

这是一个让无数开发者抓狂的问题——**元素之间的换行和空格会被解析为文本节点**：

```html
<ul id="list">
    <li>A</li>
    <li>B</li>
    <li>C</li>
</ul>
```

```javascript
const ul = document.getElementById('list');

// childNodes 包含所有类型的子节点！
console.log(ul.childNodes.length);
// 不是 3，而是 7！

// 具体构成：
// [0]  Text Node: "\n    "  (ul 标签后的换行+缩进)
// [1]  Element:    <li>A</li>
// [2]  Text Node: "\n    " (li 后的换行+缩进)
// [3]  Element:    <li>B</li>
// [4]  Text Node: "\n    "
// [5]  Element:    <li>C</li>
// [6]  Text Node: "\n" (闭合 ul 标签前的换行)

// 所以遍历元素子节点时要用 children 而非 childNodes：
console.log(ul.children.length);  // 3 ✅（只包含元素节点）
console.log(ul.children[0]);      // <li>A</li> ✅

// 或者用 children + Array.from
Array.from(ul.children).forEach(li => {
    console.log(li.textContent);  // A, B, C
});
```

### 4.3 生活类比：信封与信纸

元素节点就像**信封**，文本节点就像**信封里的信纸**：

- 信封上有收件人地址、邮票、邮戳（对应元素的属性：class、id、style）。
- 信纸上写着真正的信息内容（对应文本节点的 textContent）。
- 一封信可以是空的（空元素如 `<img>`、`<input>`），也可以装很多张纸（多个文本/元素子节点）。

你不能对着信封读信的内容——你需要打开信封取出信纸。同理，你不能直接从元素节点读取文字内容，你需要访问它的子文本节点（或者使用便捷属性 `textContent`）。

## 五、节点间的关系导航

### 5.1 DOM 导航属性全景图

每个节点都提供了丰富的属性来访问它在树中的"亲戚们"：

```javascript
const el = document.querySelector('li:nth-child(2)');  // 取中间的 li

// === 父子关系 ===
el.parentNode;           // 父节点（可能是 Element 也可能是 Document）
el.parentElement;        // 父元素（一定是 Element，可能为 null）
el.childNodes;           // 所有子节点（NodeList，含文本、注释等）
el.children;             // 子元素集合（HTMLCollection，只有元素）
el.firstChild;           // 第一个子节点（可能是文本）
el.firstElementChild;    // 第一个子元素
el.lastChild;            // 最后一个子节点
el.lastElementChild;     // 最后一个子元素
el.hasChildNodes();      // 是否有子节点

// === 兄弟关系 ===
el.previousSibling;      // 前一个兄弟节点
el.previousElementSibling;  // 前一个兄弟元素
el.nextSibling;          // 后一个兄弟节点
el.nextElementSibling;   // 后一个兄弟元素

// === 验证关系 ===
el.contains(otherNode);  // el 是否包含 otherNode
el.isEqualNode(otherNode);  // 两个节点是否相等（相同结构）
el.isSameNode(otherNode);   // 是否同一个节点引用（===）
el.matches(selector);   // 元素是否匹配指定选择器
el.closest(selector);   // 向上查找最近的选择器匹配祖先
```

### 5.2 实战：递归打印 DOM 树结构

```javascript
/**
 * 打印 DOM 树的结构化视图
 * @param {Node} node 起始节点
 * @param {number} indent 缩进级别
 */
function printDomTree(node, indent = 0) {
    const prefix = '  '.repeat(indent);
    const typeNames = {
        [Node.ELEMENT_NODE]: 'ELM',
        [Node.TEXT_NODE]: 'TXT',
        [Node.COMMENT_NODE]: 'CMT',
        [Node.DOCUMENT_NODE]: 'DOC'
    };
    
    let info = '';
    if (node.nodeType === Node.ELEMENT_NODE) {
        info = `<${node.tagName.toLowerCase()}${node.id ? '#' + node.id : ''}>`;
    } else if (node.nodeType === Node.TEXT_NODE) {
        const text = node.nodeValue.trim();
        info = text ? `"${text.slice(0, 30)}"` : '(whitespace)';
    } else if (node.nodeType === Node.COMMENT_NODE) {
        info = `/* ${node.nodeValue.trim().slice(0, 30)} */`;
    } else {
        info = node.nodeName;
    }
    
    console.log(`${prefix}[${typeNames[node.nodeType] ?? node.nodeType}] ${info}`);
    
    // 递归处理子节点
    for (const child of node.childNodes) {
        if (child.nodeType !== Node.TEXT_NODE || child.nodeValue.trim()) {
            printDomTree(child, indent + 1);
        }
    }
}

// 使用
printDomTree(document.body);
// 输出示例：
// [ELM] <body>
//   [ELM] <div#app>
//     [ELM] <h1>
//       [TXT] "Hello"
//     [CMT] /* main content */
//     [ELM] <p>
//       [TXT] "World"
```

### 5.3 生活类比：家族族谱查询系统

DOM 的导航属性就像一套**数字化族谱系统**：

- **parentNode / parentElement**：问"我的父亲是谁？"。`parentElement` 更严格——如果你的父亲不是一个"正式成员"（非元素），它会返回 null。
  
- **childNodes / children**：问"我有哪些子女？"。`childNodes` 列出所有人（包括养子、过继的），`children` 只列出血亲（纯元素）。
  
- **previousSibling / nextSibling**：问"排在我前面 / 后面的兄弟姐妹是谁？"。
  
- **closest()**：问"往上找，谁是我们家族中第一个姓王的人？"。这是一次向上搜索。

## 六、DocumentType 与 DocumentFragment

### 6.1 DocumentType：DOCTYPE 声明

```javascript
const doctype = document.doctype;
console.log(doctype.nodeType);       // 10
console.log(doctype.nodeName);       // 'html'
console.log(doctype.name);           // 'html'
// <!DOCTYPE html> 就是 DocumentType 节点
```

DOCTYPE 节点在日常开发中几乎不会被直接操作，但它的存在决定了浏览器的**渲染模式**：

- **标准模式（Standards Mode）**：`<!DOCTYPE html>` → 浏览器按 W3C 标准渲染。
- **怪异模式（Quirks Mode）**：缺少 DOCTYPE 或写法错误 → 浏览器模拟旧版 IE 的行为以兼容老网站。

这是互联网历史遗留的产物。早期浏览器各自为政实现了很多"非标准"行为，为了不让老旧网站突然崩掉，浏览器厂商保留了怪异模式作为兼容方案。

### 6.2 DocumentFragment：高性能批量操作的利器

**文档片段（DocumentFragment）** 是一个非常特殊且有用的节点类型：

```javascript
// 场景：向列表中添加 10000 个项
const list = document.getElementById('big-list');

// ❌ 低效方式：每次插入都触发回流（reflow）/重绘（repaint）
const startBad = performance.now();
for (let i = 0; i < 10000; i++) {
    const li = document.createElement('li');
    li.textContent = `Item ${i}`;
    list.appendChild(li);  // 每一次都触发 DOM 更新！
}
console.log(`慢速: ${performance.now() - startBad}ms`);

// 清空
list.innerHTML = '';

// ✅ 高效方式：先用 DocumentFragment 收集，一次性插入
const startGood = performance.now();
const fragment = document.createDocumentFragment();

for (let i = 0; i < 10000; i++) {
    const li = document.createElement('li');
    li.textContent = `Item ${i}`;
    fragment.appendChild(li);  // 插入片段，不触发 DOM 更新
}

list.appendChild(fragment);  // 一次性！只触发一次回流
console.log(`快速: ${performance.now() - startGood}ms`);
```

为什么 DocumentFragment 能提升性能？因为**片段不在活跃的文档树中**。你对片段做的所有修改都是"离线操作"，不会触发浏览器的渲染引擎。只有当片段被插入真实 DOM 时，浏览器才需要处理一次更新。

### 6.3 生活类比：DocumentFragment 是预制装配车间

想象你要装修一间房子，需要安装 100 盏灯：

- **直接操作 DOM** 就像**每次带一盏灯爬梯子上去安装**，安完下来，再拿一盏再爬上去。爬 100 次梯子，累死不说，每次爬上爬下还会打扰房间里的人（触发重排重绘）。
  
- **使用 DocumentFragment** 就像**在地面的装配车间里先把 100 盏灯全部组装好**，然后**一次性搬到房间里挂上去**。只爬一次梯子，房间里的干扰也最小。

> **哲学思考**：DocumentFragment 体现了计算机科学中的**批处理（Batching）**思想。无论是数据库的事务提交、图形渲染的双缓冲技术、还是网络协议的数据包组装，核心思路都是一样的——把零散的操作收集起来，原子性地一次性完成。这不仅减少了固定开销（如建立连接、上下文切换），更重要的是保证了中间状态的一致性（用户永远不会看到半成品）。自然界中也遵循类似的原则：树木不会每长一片叶子就通知森林，而是静默地完成一轮生长后才展现新的面貌。

## 七、节点操作的核心原则

### 7.1 引用 vs 拷贝

DOM 操作中最重要的一条原则是：**节点是引用类型**。

```javascript
const original = document.querySelector('#my-div');
const reference = original;       // 同一个对象
reference.classList.add('active');
console.log(original.classList.contains('active'));  // true！

// 如果要真正"复制"一个节点：
const shallowCopy = original.cloneNode(false);  // 浅拷贝：只复制自身
const deepCopy = original.cloneNode(true);      // 深拷贝：复制自身 + 所有后代

// cloneNode 复制的是快照，不是实时绑定
original.classList.add('modified');
console.log(deepCopy.classList.contains('modified'));  // false（独立副本）
```

### 7.2 内存泄漏隐患： detached 节点

从 DOM 树中移除的节点如果没有其他引用指向它，最终会被垃圾回收。但如果你的代码仍然保持着对它的引用：

```javascript
function createWidget() {
    const container = document.createElement('div');
    container.innerHTML = '<button>Click me</button>';
    
    const btn = container.querySelector('button');
    
    // ⚠️ 危险：btn 的点击事件闭包引用了 container
    btn.addEventListener('click', () => {
        console.log(container.innerHTML);  // container 被"记住"了
    });
    
    document.body.appendChild(container);
    
    // 后来移除了 container
    document.body.removeChild(container);
    // 但 container 仍然被 btn 的事件处理器引用着！
    // container → btn → 事件闭包 → container（循环引用！）
    // 在旧版浏览器中这会造成内存泄漏
}

// 现代 V8 引擎的垃圾回收器能处理大部分循环引用，
// 但对于包含大量 DOM 节点的场景仍需警惕
```

## 八、总结：理解 DOM 树的心智模型

### 8.1 核心概念映射表

| HTML 概念 | DOM 概念 | nodeType | JavaScript 类型 |
|-----------|---------|----------|----------------|
| `<div>` 标签 | Element | 1 | `HTMLElement` |
| 标签内文字 | Text | 3 | `Text` |
| `<!-- -->` | Comment | 8 | `Comment` |
| `<!DOCTYPE>` | DocumentType | 10 | `DocumentType` |
| 整个文档 | Document | 9 | `Document` |
| 离线容器 | DocumentFragment | 11 | `DocumentFragment` |

### 8.2 避坑指南

| 问题 | 原因 | 解决方法 |
|------|------|---------|
| `childNodes.length` 不等于预期数 | 空白文本节点 | 用 `children` 代替 |
| `firstChild` 返回的不是想要的元素 | 第一个子节点是空白文本 | 用 `firstElementChild` |
| 循环添加大量元素导致卡顿 | 每次操作都触发布局计算 | 使用 `DocumentFragment` 批量操作 |
| 移除节点后内存没释放 | 存在被事件闭包持有的引用 | 及时移除事件监听或置空引用 |

> **最后的思考**：DOM 树不仅是一个技术构件，更是一种世界观的具体表达——**世界是由相互关联的事物构成的**。一棵树、一个家族谱系、一家公司的组织架构、一篇论文的章节结构……树形结构无处不在。DOM 把这种普遍的认知模式引入了网页开发的领域：每个可见或不可见的部分都有其位置，每个位置都定义了与其他部分的关系。理解了这一点，你就不再是在"操作 DOM"，而是在"理解和对话"——你清楚地知道每个节点是谁、在哪里、能做什么。关于如何精确地找到目标节点，推荐阅读[《选择器》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/15.选择器.md)。关于如何修改 DOM 树的结构，推荐阅读[《遍历与修改 DOM》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/20.遍历与修改DOM.md)。
