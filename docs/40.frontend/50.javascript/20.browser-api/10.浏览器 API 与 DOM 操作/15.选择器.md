# 选择器 —— getElementById、querySelector、querySelectorAll、getElementsByClassName

## 从"知道 DOM 存在"到"精准定位目标"的方法论跃迁

在[《DOM 树》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/10.DOM树.md)一文中，我们理解了 DOM 的树形结构——节点、类型、关系导航。但仅有这些还不够。当你面对一棵包含数千个节点的 DOM 树时，如何快速找到你想要操作的那个特定元素？这就需要**选择器（Selector）**。

选择器是连接"你的意图"和"DOM 节点"之间的桥梁。它就像一套精确的地址系统——你告诉浏览器你想要什么，浏览器根据规则在整棵树中搜索并返回匹配的节点。JavaScript 提供了多套不同的选择 API，每套都有其独特的行为特征和适用场景。理解它们的差异不仅是知识储备的问题，更是写出高效、健壮代码的前提。

> **本文的目标**：全面对比 getElement 系列与 querySelector 系列的选择器 API，深入分析返回类型的差异（静态 vs 动态集合）、性能特性、以及在实际工程中的最佳实践策略。

---

## 一、两大家族的对决：getElement 系列 vs querySelector 系列

### 1.1 API 全景图

JavaScript 的 DOM 选择 API 可以分为两大阵营：

```javascript
// ====== 第一阵营：getElement 系列（古老但高效）======
document.getElementById('header');              // 通过 ID 查找单个元素
document.getElementsByTagName('div');           // 通过标签名查找
document.getElementsByClassName('card');        // 通过类名查找
document.getElementsByName('email');            // 通过 name 属性查找

// ====== 第二阵营：querySelector 系列（现代且通用）======
document.querySelector('.container > .item');   // 返回第一个匹配项
document.querySelectorAll('li.selected');       // 返回所有匹配项

// 两套 API 都支持从指定祖先元素开始查找：
element.getElementById(/* 不存在！*/);           // ⚠️ 注意：getElementById 只能在 document 上调用
element.querySelector('.child-item');
element.querySelectorAll('[data-type]');
```

这两套 API 的核心区别远不止名字不同那么简单。它们代表了两个时代的 DOM 设计哲学，返回值类型、性能表现、使用限制都存在本质差异。

## 二、getElement 系列：老当益壮的原生居民

### 2.1 getElementById：最快的单点查询

`getElementById` 是所有选择器 API 中**最快**的一个，没有之一：

```javascript
// 基本用法
const header = document.getElementById('main-header');

// 特点：
// 1. 只能通过 document 调用，不能在其他元素上使用
// 2. ID 在整个文档中应该是唯一的
// 3. 如果找不到，返回 null（不是空数组或 undefined）

if (header) {
    header.classList.add('visible');
} else {
    console.warn('未找到 #main-header 元素');
}

// ⚠️ 一个常见陷阱：如果 id 以数字开头
document.getElementById('123abc');   // 正常工作
document.getElementById(123);        // 也行（自动转字符串）
// 但某些旧版 IE 可能有问题，建议始终传字符串
```

为什么 `getElementById` 最快？因为浏览器内部维护了一个 **ID 到元素的哈希表（Hash Map）**。当你写 `<div id="app">` 时，浏览器就已经把这个元素注册到了哈希表中。后续的 `getElementById('app')` 本质上是一次 O(1) 的哈希查找，和 JavaScript 中 `Map.get()` 的速度相当。不需要遍历 DOM 树，不需要模式匹配，直接按图索骥。

### 2.2 getElementsByTagName：标签名的批量检索

```javascript
// 获取页面中所有的段落
const paragraphs = document.getElementsByTagName('p');
console.log(paragraphs.length);          // 页面中 p 标签的数量
console.log(paragraphs[0]);             // 第一个 p 元素
console.log(paragraphs instanceof HTMLCollection);  // true

// 从指定元素开始查找
const sidebar = document.getElementById('sidebar');
const sidebarLinks = sidebar.getElementsByTagName('a');
console.log(sidebarLinks.length);        // 只统计 sidebar 内的 a 标签

// 使用通配符 '*' 获取所有元素
const allElements = document.getElementsByTagName('*');
console.log(allElements.length);         // 整个文档的元素总数
```

### 2.3 getElementsByClassName：类名的批量匹配

```javascript
// 单类名
const cards = document.getElementsByClassName('card');

// 多类名（同时具有所有指定类名的元素）
const activeCards = document.getElementsByClassName('card active highlighted');

// 类名之间是 AND 关系，不是 OR 关系
// 上面的例子只匹配同时有 card、active、highlighted 三个类的元素
```

### 2.4 生活类比：图书馆的两套检索系统

如果把 DOM 树比作一个**大型图书馆的藏书体系**：

- **getElementById 就像按图书编号检索**：每本书有一个唯一的编号（ID）。你去服务台说"我要 978-7-xxx-xxx"，管理员直接从索引柜里取出对应的索书卡——O(1) 时间，快得惊人。
  
- **getElementsByTagName 就像按书籍分类检索**：你说"我要所有的小说类图书"，管理员带你走到小说区，把那里的书全部指给你看。这比一本本翻找快多了，但还是需要走一段路。
  
- **getElementsByClassName 就像按标签组合检索**：你说"我要精装版 + 科幻类 + 中文译本"的图书，管理员按照这三个条件筛选出符合条件的 subset。
  
- **querySelector 就像自然语言检索台**：你说"给我找那个在历史区第三排架子上、封面红色的、作者是中国人出版的书"。这个描述非常具体和灵活，但管理员需要花更多时间来理解和执行你的请求。

## 三、querySelector 系列：CSS 选择器的威力

### 3.1 querySelector：获取单个匹配项

```javascript
// 基础选择器
document.querySelector('#app');                    // ID 选择器
document.querySelector('.container');               // 类选择器
document.querySelector('h1');                       // 标签选择器

// 层级选择器
document.querySelector('nav ul li a');              // 后代选择器
document.querySelector('.parent > .child');         // 直接子元素选择器
document.querySelector('.item + .next-item');       // 相邻兄弟选择器
document.querySelector('.item ~ .sibling');          // 通用兄弟选择器

// 属性选择器
document.querySelector('[data-id="123"]');
document.querySelector('input[type="email"]')
document.querySelector('[class*="active"]');        // 包含
document.querySelector('[class^="btn-"]');           // 开头匹配
document.querySelector('[class$="-danger"]');        // 结尾匹配

// 伪类和伪元素
document.querySelector('li:first-child');
document.querySelector('li:nth-child(odd)');
document.querySelector(':not(.disabled)');
document.querySelector('input:focus');
document.querySelector('::before');                 // 注意：通常返回 null（伪元素不在 DOM 中）
```

`querySelector` 返回的是**第一个**匹配的元素（按文档顺序），如果没有匹配则返回 `null`。

### 3.2 querySelectorAll：获取所有匹配项

```javascript
// 返回所有匹配项
const items = document.querySelectorAll('.menu li');

console.log(items.length);                    // 匹配数量
console.log(items[0]);                        // 第一个
console.log(items instanceof NodeList);        // true（NodeList，不是 Array！）

// 遍历方式（NodeList 有 forEach，但不一定支持 map/filter）
items.forEach(item => console.log(item.textContent));

// 转换为数组以使用完整的数组方法
Array.from(items).map(item => item.textContent);

// 解构赋值配合遍历
for (const item of items) {  // NodeList 可迭代 ✅
    console.log(item.dataset.id);
}
```

### 3.3 复杂选择器实战

```javascript
// 表格中最后一行的最后一个单元格
document.querySelector('table tr:last-child td:last-child');

// 所有未被禁用的必填输入框
document.querySelectorAll('input[required]:not([disabled])');

// 特定 data 属性下带有某个类的元素
document.querySelectorAll('[data-section="hero"] .highlight');

// 嵌套结构的深层后代
document.querySelector('.sidebar nav > ul > li.active > a[href^="/admin"]');
```

> **哲学思考**：querySelector 系列的出现标志着 Web 平台的一次重要统一。在此之前，开发者需要记忆五六个不同的 API 来完成本质上相同的事——"查找元素"。而 CSS 选择器本身已经是一套成熟、强大、被无数前端工程师熟悉的模式匹配语言。让 JavaScript 复用这套语法，既是 DRY（Don't Repeat Yourself）原则的体现，也降低了认知负担：你不需要学一套新的查询语言，因为你已经会了——那就是 CSS。这种"复用已有知识"的设计思想值得在任何 API 设计中被借鉴。

## 四、关键区别：静态集合 vs 动态集合

这是两套 API 最重要、最容易被忽视的区别。

### 4.1 什么是动态集合？

getElement 系列返回的是 **HTMLCollection**，它是**动态的（live）**——意味着它会随着 DOM 的变化自动更新：

```html
<ul id="list">
    <li>第一项</li>
    <li>第二项</li>
    <li>第三项</li>
</ul>
```

```javascript
const list = document.getElementById('list');
const items = list.getElementsByTagName('li');  // HTMLCollection（动态）

console.log(items.length);  // 3

// 向列表添加新元素
const newItem = document.createElement('li');
newItem.textContent = '第四项';
list.appendChild(newItem);

console.log(items.length);  // 4！自动更新了！

// 再删除一个
list.removeChild(list.firstElementChild);
console.log(items.length);  // 3！又自动减少了
```

注意：你并没有重新调用 `getElementsByTagName`，但 `items.length` 的值变了。这就是"动态"的含义——`items` 不是结果的快照，而是对 DOM 当前状态的一个**实时视图**（Live View）。

### 4.2 什么是静态集合？

querySelectorAll 返回的是 **NodeList**，它是**静态的（static）**——返回的是匹配时刻的快照：

```javascript
const list = document.getElementById('list');
const items = list.querySelectorAll('li');  // NodeList（静态）

console.log(items.length);  // 3

// 添加新元素
const newItem = document.createElement('li');
newItem.textContent = '第四项';
list.appendChild(newItem);

console.log(items.length);  // 3！没变，还是快照时的数量
```

### 4.3 动态集合的双刃剑效应

动态集合既可能带来便利，也可能引发难以追踪的 bug：

```javascript
// ⚠️ 危险场景：遍历动态集合的同时修改 DOM
const divs = document.getElementsByTagName('div');

for (let i = 0; i < divs.length; i++) {
    // 每次循环都会重新评估 divs.length（因为它是动态的！）
    // 同时每次移除元素后，后续元素的索引会前移
    if (someCondition(divs[i])) {
        divs[i].parentNode.removeChild(divs[i]);
        // 移除后 divs.length 减少了 1
        // 但 i 仍然增加了 1 → 可能跳过元素或越界！
    }
}

// ✅ 安全方案 A：倒序遍历
const divs = document.getElementsByTagName('div');
for (let i = divs.length - 1; i >= 0; i--) {
    if (someCondition(divs[i])) {
        divs[i].parentNode.removeChild(divs[i]);
    }
}

// ✅ 安全方案 B：转换为数组（推荐）
const divs = Array.from(document.getElementsByTagName('div'));
divs.forEach(div => {
    if (someCondition(div)) {
        div.parentNode.removeChild(div);
    }
});

// ✅ 安全方案 C：直接用 querySelectorAll（天然静态）
const divs = document.querySelectorAll('div');
divs.forEach(div => {
    if (someCondition(div)) {
        div.parentNode.removeChild(div);
    }
});
```

### 4.4 生活类比：实时摄像头 vs 拍照

- **HTMLCollection（动态集合）就像一台实时监控摄像头**：屏幕上显示的是当前正在发生的画面。如果你离开房间再回来，画面已经变化了。你看到的永远是"此刻"的状态。
  
- **NodeList（静态集合）就像一张照片**：按下快门的瞬间被永久定格了。无论之后房间发生了什么变化，照片上的内容不会改变。

如果你要记录"房间里曾经有什么"（比如做对比分析），你需要的是照片（静态集合）。如果你需要一个永远显示最新状态的仪表盘（比如显示当前在线用户数），你可能需要的是实时摄像头（动态集合）。但在大多数 DOM 操作场景中，**静态集合更安全、更可预测**。

## 五、性能对比与最佳实践

### 5.1 各 API 的相对性能

```javascript
// 性能测试框架
function benchmark(name, fn, iterations = 10000) {
    const start = performance.now();
    for (let i = 0; i < iterations; i++) fn();
    const end = performance.now();
    console.log(`${name}: ${(end - start).toFixed(3)}ms (${iterations}次)`);
}

// 准备测试环境（假设页面上有 #target 元素）
benchmark('getElementById', () => {
    document.getElementById('target');
});

benchmark('querySelector (#id)', () => {
    document.querySelector('#target');
});

benchmark('querySelectorAll', () => {
    document.querySelectorAll('.item');
});

benchmark('getElementsByClassName', () => {
    document.getElementsByClassName('item');
});

// 典型输出结果（相对比例）：
// getElementById:            0.120ms  ← 最快（哈希查找）
// getElementsByClassName:     0.350ms  ← 第二（优化过的原生匹配）
// querySelectorAll:           0.680ms  ← 第三（CSS 选择器引擎解析）
// querySelector (#id):        0.550ms  ← 比 getElementById 慢
```

一般规律（从快到慢）：

```
getElementById ≫ getElementsByName ≫ getElementsByClassName/TagName
             > querySelector/querySelectorAll
```

但这并不意味着你应该总是用 getElement 系列。在现代浏览器中，对于绝大多数场景，性能差异微乎其微（亚毫秒级）。**代码可读性和正确性应该优先于微小的性能收益**。

### 5.2 选择决策指南

| 场景 | 推荐 API | 原因 |
|------|---------|------|
| 通过 ID 获取唯一元素 | `getElementById` | 最快，语义明确 |
| 批量操作后需保持同步 | `getElementsBy*` | 动态集合自动更新 |
| 复杂选择器需求 | `querySelectorAll` | 支持 CSS 完整语法 |
| 遍历时可能修改 DOM | `querySelectorAll` | 静态集合，安全 |
| 需要数组方法 | `querySelectorAll` + `Array.from()` 或展开运算符 |
| 从非 document 节点查找 | `querySelector/All` | getElementById 不支持 |

### 5.3 最佳实践清单

```javascript
// ✅ 推荐做法

// 1. 缓存频繁访问的 DOM 引用
const header = document.getElementById('header');
const menuItems = header.querySelectorAll('.menu-item');

// 2. 使用有意义的选择器
document.querySelector('[data-user-id="42"]');  // 语义化
document.querySelector('.wrapper > .content'); // 明确的结构关系

// 3. 尽量缩小搜索范围
document.querySelector('#sidebar .link');     // 好（限定范围）
document.querySelector('.link');              // 差（全文档搜索）

// ❌ 避免做法

// 1. 在循环中重复查询
// 差
for (let i = 0; i < list.length; i++) {
    document.querySelector(`#item-${i}`).classList.add('show');
}

// 好：缓存父元素，用变量拼接
const container = document.getElementById('list-container');
for (let i = 0; i < list.length; i++) {
    container.querySelector(`[data-index="${i}"]`).classList.add('show');
}

// 2. 过度复杂的选择器
document.querySelector('body > div.container.main > section.content.wrapper > div.card:nth-child(2) > h2.title');
// 这种选择器既难读又脆弱（DOM 结构一变就失效）

// 更好的方案：给目标元素加一个有意义的类名或 data 属性
document.querySelector('[data-card-title="main"]');
```

## 六、特殊场景与陷阱

### 6.1 ID 的特殊性

HTML 规范要求 ID 在文档中必须唯一，但浏览器并不会强制这一点：

```html
<!-- ⚠️ 不要这样做！但浏览器允许 -->
<p id="duplicate">第一段</p>
<p id="duplicate">第二段</p>
```

```javascript
// getElementById 返回第一个（文档顺序）
document.getElementById('duplicate');  // <p id="duplicate">第一段</p>

// querySelectorAll 会全部找到
document.querySelectorAll('#duplicate').length;  // 2
```

### 6.2 特殊字符的转义

当 ID 或类名包含特殊字符时，需要转义：

```html
<div id="my.id" class="foo bar">内容</div>
<div class="my-class" data-value="hello world">更多内容</div>
```

```javascript
// . 在 CSS 选择器中表示 class，所以需要转义
document.querySelector('#my\\.id');      // 双反斜杠（JS 字符串转义一次）

// 属性值中有空格，需要引号包裹
document.querySelector('[data-value="hello world"]');

// 类名以数字开头（不常见但合法）
document.querySelector('\\31item');  // \31 表示字符码为 31（即数字1）
```

### 6.3 作用域问题

```javascript
// getElementById 只能在 document 上使用
const container = document.getElementById('app');
container.getElementById('inner-btn');  // TypeError! 方法不存在

// 其他方法可以在任意元素上调用
container.querySelector('.button');        // OK
container.getElementsByTagName('div');     // OK
```

这是一个经常被忽视的限制。如果你想在某个子树范围内通过 ID 查找元素，只能改用 `querySelector`：

```javascript
// 替代方案
container.querySelector('#inner-btn');     // OK，等价效果
```

## 七、总结：选择器的心智模型

### 7.1 API 速查表

| API | 返回类型 | 集合性质 | 是否支持 CSS 选择器 | 可用位置 |
|-----|---------|---------|-------------------|---------|
| `getElementById` | `Element \| null` | 单个 | 仅 `#id` | 仅 `document` |
| `getElementsByTagName` | `HTMLCollection` | 动态 | 仅标签名 | 任意 Element |
| `getElementsByClassName` | `HTMLCollection` | 动态 | 仅类名 | 任意 Element |
| `querySelector` | `Element \| null` | 单个 | 完整 CSS 语法 | 任意 Element/Document |
| `querySelectorAll` | `NodeList` | 静态 | 完整 CSS 语法 | 任意 Element/Document |

### 7.2 核心原则

1. **简单 ID 查询首选 `getElementById`**——零思考成本，最高性能。
2. **复杂选择器首选 `querySelector/All`**——表达力强，返回静态集合更安全。
3. **批量操作时注意集合的动态性**——如果需要在遍历中修改 DOM，优先使用静态集合。
4. **始终缓存查询结果**——避免重复搜索同一元素。
5. **选择器应具备语义稳定性**——不要依赖容易变化的层级结构，优先使用类名和属性选择器。

> **最后的思考**：选择器 API 的演进史就是 Web 平台从"各立山头"走向"大一统"的缩影。早期的 `getElementById`、`getElementsByName`……每个 API 都是针对一种特定的查找场景设计的专用工具，就像一把螺丝刀、一把锤子、一把钳子。而 `querySelector` 系列的出现带来了一把瑞士军刀——一套语法搞定所有场景。但专用的工具永远不会过时：螺丝刀在某些场景下仍然比瑞士军刀更好用。真正的高手不是只用某一种工具的人，而是清楚每种工具的边界和擅长领域、并能根据具体情况做出最优选择的人。关于如何操作选中的 DOM 节点，推荐阅读[《遍历与修改 DOM》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/20.遍历与修改DOM.md)。关于如何读写元素的属性和内容，推荐阅读[《属性与内容》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/25.属性与内容.md)。
