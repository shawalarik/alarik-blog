# 遍历与修改 DOM —— parentNode、children、appendChild、insertBefore、removeChild、replaceChild

## 从"找到目标"到"改变结构"的能力跃迁

在[《选择器》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/15.选择器.md)一文中，我们掌握了如何在 DOM 树中定位到想要的节点。但找到节点只是第一步——真正让网页"活起来"的，是**修改 DOM 结构**的能力。添加一个列表项、删除一张卡片、把元素从一个容器移到另一个容器……这些操作的本质都是对树的**增删改**。

DOM 的修改操作（Mutation）是一套完整的接口，它定义了如何安全地在树中插入、移动、替换和删除节点。理解这些操作的语义和性能影响，是写出高效动态页面的基础。

> **本文的目标**：系统讲解 DOM 遍历与修改的完整 API 体系——从父子兄弟关系的导航方法，到节点的创建与插入、移动与替换、删除与克隆，以及现代 API（`append`、`prepend`、`before`、`after`、`replaceWith`、`remove`）的使用和最佳实践。

## 一、DOM 遍历：沿着树行走

### 1.1 向下遍历：子节点

```javascript
const parent = document.getElementById('container');

// === 所有子节点（包含文本、注释等）===
parent.childNodes;          // NodeList（实时更新）
// 包含：元素节点、文本节点（含空白）、注释节点

// === 仅子元素（最常用）===
parent.children;            // HTMLCollection（实时更新）
// 只包含 Element 类型的子节点

// === 便捷属性 ===
parent.firstElementChild;   // 第一个子元素
parent.lastElementChild;    // 最后一个子元素
parent.childElementCount;   // 子元素数量（等于 children.length）
```

### 1.2 向上遍历：父节点

```javascript
const child = document.querySelector('.item');

child.parentNode;           // 父节点（可能是 Document 或 Element）
child.parentElement;        // 父元素（一定是 Element，可能为 null）

// 两者的区别：
// 如果 child 直接挂在 document 下（罕见），parentNode 返回 document，
// 但 parentElement 返回 null（因为 document 不是 Element）

// 向上查找最近的匹配祖先
const section = child.closest('.content-section');
// closest 从当前元素开始向上查找（包括自身），
// 返回第一个匹配 CSS 选择器的祖先元素
```

### 1.3 横向遍历：兄弟节点

```javascript
const item = document.querySelector('.list-item');

// 所有兄弟（包括文本节点）
item.previousSibling;
item.nextSibling;

// 仅元素兄弟（常用）
item.previousElementSibling;
item.nextElementSibling;

// 获取所有兄弟元素
function getSiblings(element) {
    return Array.from(element.parentElement.children)
        .filter(child => child !== element);
}
```

### 1.4 深度优先遍历

浏览器原生提供了 `TreeWalker` 接口用于复杂的树形遍历：

```javascript
/**
 * 使用 TreeWalker 进行深度优先遍历
 * 可以精确控制遍历哪些类型的节点
 */
const walker = document.createTreeWalker(
    document.body,                    // 从 body 开始
    NodeFilter.SHOW_ELEMENT,          // 只遍历元素节点
    {                                 // 过滤函数
        acceptNode(node) {
            // 跳过 script 和 style 元素
            if (node.tagName === 'SCRIPT' || node.tagName === 'STYLE') {
                return NodeFilter.FILTER_REJECT;  // 排除该节点及其子节点
            }
            return NodeFilter.FILTER_ACCEPT;      // 接受该节点
        }
    }
);

const elements = [];
while (walker.nextNode()) {
    elements.push(walker.currentNode);
}
console.log(`共遍历 ${elements.length} 个元素`);
```

### 1.5 生活类比：家族探亲路线

DOM 遍历就像在一个大家族中走访亲戚：

- **向下走（children）**：去拜访你的子女们。你可以只看亲生子女（`children`），或者连过继的养子和寄养的都算上（`childNodes`）。
  
- **向上走（parentNode）**：去找你的父母。如果往上追溯到最高辈分，那就是老祖宗 `document`。
  
- **横向走（previous/nextSibling）**：去看你的兄弟姐妹。排在你前面出生的是哥哥姐姐，后面的是弟弟妹妹。
  
- **closest() 就像查族谱**：你问"我往上找，谁是第一个当过老师的人？"——不管隔着几代，第一个满足条件的就是答案。

> **哲学思考**：树形结构的遍历本质上是一种**系统性探索（Systematic Exploration）**策略。人类认识世界的方式也是类似的：我们通过分类（向下）、溯源（向上）、对比（横向）来建立认知框架。DOM 提供的丰富导航 API 让开发者能以任意方向探索文档结构，这种自由度既是强大的工具，也需要审慎的使用——无目的的漫游式遍历往往暗示着代码设计的问题。好的代码应该清楚地知道自己要去哪里，而不是盲目地四处张望。

## 二、创建与插入节点

### 2.1 创建新节点的工厂方法

```javascript
// 创建元素节点
const div = document.createElement('div');
div.className = 'card';
div.id = 'card-42';
div.setAttribute('data-type', 'article');

// 创建文本节点
const text = document.createTextNode('Hello World');

// 空元素没有子节点
console.log(div.childNodes.length);  // 0

// 组合使用
div.appendChild(text);
console.log(div.innerHTML);  // 'Hello World'
```

### 2.2 传统插入方法

DOM 规范定义了四个经典的节点操作方法：

```javascript
const parent = document.getElementById('list');
const newItem = document.createElement('li');
newItem.textContent = '新项目';

// appendChild：追加为最后一个子节点
parent.appendChild(newItem);
// <ul><li>A</li><li>B</li><li>新项目</li></ul>

// insertBefore：在指定节点之前插入
const refNode = parent.children[1];  // 第二个子元素
const anotherItem = document.createElement('li');
anotherItem.textContent = '中间插入';
parent.insertBefore(anotherItem, refNode);
// <ul><li>A</li><li>中间插入</li><li>B</li><li>新项目</li></ul>

// replaceChild：替换指定节点
const replacedItem = document.createElement('li');
replacedItem.textContent = '被替换了';
parent.replaceChild(replacedItem, refNode);
// refNode（原来的第二个子节点）被 replacedItem 取代

// removeChild：移除指定节点
const toRemove = parent.lastElementChild;
parent.removeChild(toRemove);
// 新项目被移除（但变量 toRemove 仍然引用着它！）
```

### 2.3 现代插入方法

现代 DOM 规范新增了更直观的方法，它们同时支持**节点对象**和**字符串**（字符串会被自动解析为 HTML）：

```javascript
const container = document.querySelector('.container');

// ====== 在内部插入 ======

// prepend：在最前面插入
container.prepend('<span>头部</span>', document.createTextNode('内容'));
// 可以一次传入多个参数！

// append：在最后面插入（比 appendChild 更强大）
container.append('<span>尾部</span>', '纯文本也会被转成文本节点');

// 注意：innerHTML = ... 是替换全部内容
// append/prepend 是增量添加

// ====== 在外部插入 ======

// before：在元素之前插入
const box = document.getElementById('box');
box.before('<p>我在前面</p>');

// after：在元素之后插入
box.after('<p>我在后面</p>');

// replaceWith：用新内容替换自己
oldElement.replaceWith('<div class="new">全新的</div>');
// oldElement 被从树中移除，新的 div 取代了它的位置
```

新旧方法的对比：

| 操作 | 传统方法 | 现代方法 | 支持多参数 | 支持字符串 |
|------|---------|---------|----------|-----------|
| 内部末尾追加 | `appendChild(node)` | `append(...items)` | ✅ | ✅ |
| 内部开头插入 | `insertBefore(node, first)` | `prepend(...items)` | ✅ | ✅ |
| 外部前插入 | `parent.insertBefore(node, el)` | `el.before(...items)` | ✅ | ✅ |
| 外部后插入 | 无直接方法 | `el.after(...items)` | ✅ | ✅ |
| 替换 | `parent.replaceChild(new, old)` | `old.replaceWith(...items)` | ✅ | ✅ |
| 删除 | `parent.removeChild(el)` | `el.remove()` | - | - |

## 三、移动节点 vs 复制节点

### 3.1 移动的本质：同一个引用换位置

DOM 中最重要的隐秘知识之一：**appendChild 和 insertBefore 具有"移动"语义**。如果一个节点已经存在于文档树中，再次将它插入另一个位置，它会从原位置**移除**然后**移动**到新位置：

```html
<ul id="list-a">
    <li id="item-1">项目 A</li>
    <li id="item-2">项目 B</li>
</ul>
<ul id="list-b">
    <li id="item-3">项目 C</li>
</ul>
```

```javascript
const listA = document.getElementById('list-a');
const listB = document.getElementById('list-b');
const item1 = document.getElementById('item-1');

// 把 item-1 从 list-A 移动到 list-B
listB.appendChild(item1);

// 结果：
// list-A 只剩下 item-2
// list-B 有 item-3 和 item-1（按此顺序）

console.log(item1.parentNode);  // list-B（不是 list-A 了！）
// item1 还是同一个对象引用，只是位置变了
```

这就像把一本书从书架 A 搬到书架 B——书本身没变，只是位置变了。不需要先"删"再"加"，一步到位。

### 3.2 克隆节点：真正的复制

如果你需要保留原始位置的节点，同时在别处放一份副本：

```javascript
const original = document.getElementById('card');
// 浅拷贝：只复制节点本身，不复制子节点
const shallowCopy = original.cloneNode(false);
// deepCopy：深度复制，包含所有后代节点
const deepCopy = original.cloneNode(true);

document.body.appendChild(deepCopy);

// ⚠️ cloneNode 不会复制事件监听器！
original.addEventListener('click', () => console.log('clicked'));
const copy = original.cloneNode(true);
copy.click();  // 什么都不会发生（事件没有被复制）
```

### 3.3 生活类比：搬家 vs 复印

- **DOM 移动操作就像搬家**：你把沙发从客厅搬到卧室。整个房子里还是只有这一个沙发，只是位置变了。你不需要买新沙发，也不需要扔掉旧沙发。
  
- **cloneNode 就像复印文件**：原件还在原地，复印件可以贴到任何地方。但复印件上的手写批注（事件监听器）不会被一起复印过去，你需要重新写一遍。

## 四、删除与清理

### 4.1 传统删除与现代删除

```javascript
const element = document.getElementById('to-delete');

// ❌ 传统方式（需要父元素引用）
element.parentNode.removeChild(element);

// ✅ 现代方式（不需要父元素引用）
element.remove();
// 更简洁、更语义化
```

`remove()` 方法的出现消除了一个常见的痛点：你需要删除一个元素时，还得先拿到它的父元素引用。这在某些场景下很麻烦——比如在回调函数或闭包中，你可能只有元素自身的引用。

### 4.2 删除所有子元素

```javascript
const container = document.getElementById('container');

// 方法一：innerHTML 清空（最快，但有安全隐患）
container.innerHTML = '';
// ⚠️ 如果用户输入的内容曾被写入 innerHTML，
// 这里可能导致 XSS 攻击（虽然这里是清空操作，风险较低）

// 方法二：逐个删除（安全但较慢）
while (container.firstChild) {
    container.removeChild(container.firstChild);
}

// 方法三：replaceChildren（现代，推荐！）
container.replaceChildren();       // 清空所有子元素
container.replaceChildren(...newChildren);  // 用新元素替换全部
```

### 4.3 删除后的引用问题

```javascript
const el = document.getElementById('my-element');
el.remove();

// el 变量仍然存在！它依然指向那个 DOM 对象
console.log(el.parentNode);       // null（已脱离文档树）
console.log(el.isConnected);      // false（不在活跃文档中）

// 你还可以把它重新插回文档
document.body.appendChild(el);    // 又回来了！
// 这叫"离线编辑"模式：先移除→修改→再插回
```

> **哲学思考**：DOM 节点的生命周期管理体现了**所有权（Ownership）**的概念。当一个节点在文档树中时，它是"被拥有的"（由其父节点持有）；当它被移除后，它变成了"孤儿"——只要 JavaScript 还持有对它的引用，它就不会被垃圾回收。这与 Rust 语言中的所有权模型有异曲同工之妙：每个值都有一个唯一的所有者，当所有者离开作用域时值被释放。理解 DOM 节点的"归属关系"，能帮助你写出内存泄漏更少的代码。

## 五、innerHTML 与批量操作的性能考量

### 5.1 innerHTML 的双面性

`innerHTML` 是最容易使用的 DOM 修改方式，但它也是最容易被滥用的：

```javascript
const container = document.getElementById('container');

// 写入 innerHTML 会：
// 1. 清空容器的所有现有子节点
// 2. 将字符串解析为 HTML
// 3. 创建新的 DOM 子树
// 4. 将新子树插入容器

// 这意味着每次赋值都会触发一系列昂贵的操作
container.innerHTML = '<div>A</div><div>B</div><div>C</div>';

// 如果你需要在循环中这样做：
// ❌ 性能灾难
for (let i = 0; i < 1000; i++) {
    container.innerHTML += `<div>Item ${i}</div>`;
    // 每次循环都在重复：清空 → 解析 → 创建 → 插入
}

// ✅ 正确做法：先拼接好字符串，一次性赋值
let html = '';
for (let i = 0; i < 1000; i++) {
    html += `<div>Item ${i}</div>`;
}
container.innerHTML = html;

// ✅ 更优做法：使用 DocumentFragment（参见《DOM 树》一文）
```

### 5.2 批量操作的策略选择

| 场景 | 推荐方案 | 原因 |
|------|---------|------|
| 大量相似元素的创建 | DocumentFragment | 最小化重排重绘 |
| 已知最终 HTML 结构 | innerHTML（一次性） | 解析器优化 |
| 少量元素的精确操作 | append / before / after 等 | 语义清晰 |
| 需要复用已有元素 | 移动操作 | 零创建开销 |

## 六、实战案例：动态列表管理器

下面是一个综合运用遍历与修改 API 的实用组件：

```javascript
/**
 * 动态列表管理器
 * 展示 DOM 遍历与修改的综合运用
 */
class ListManager {
    constructor(containerSelector) {
        this.container = document.querySelector(containerSelector);
        this.items = [];
        this.render();
    }

    // 添加项目
    addItem(text) {
        const id = Date.now().toString(36);
        this.items.push({ id, text });
        this._appendSingleItem({ id, text });  // 增量更新，不重绘全量
        return id;
    }

    // 删除项目
    removeItem(id) {
        // 通过 data 属性找到对应元素（避免全量重渲染）
        const element = this.container.querySelector(`[data-id="${id}"]`);
        if (element) {
            element.remove();  // 现代 API
        }
        this.items = this.items.filter(item => item.id !== id);
    }

    // 移动项目（从一个位置到另一个位置）
    moveItem(fromIndex, toIndex) {
        if (fromIndex < 0 || fromIndex >= this.items.length) return;
        
        const [item] = this.items.splice(fromIndex, 1);
        this.items.splice(toIndex, 0, item);

        // 利用 DOM 的移动语义——不创建新节点
        const element = this.container.children[fromIndex];
        const reference = this.container.children[toIndex] || null;
        
        if (fromIndex < toIndex) {
            this.container.insertBefore(element, reference?.nextSibling || null);
        } else {
            this.container.insertBefore(element, reference);
        }
    }

    // 清空列表
    clear() {
        this.container.replaceChildren();  // 现代批量清空
        this.items = [];
    }

    // 内部方法：增量追加单个项目
    _appendSingleItem({ id, text }) {
        const li = document.createElement('li');
        li.dataset.id = id;
        li.textContent = text;
        
        // 添加删除按钮
        const btn = document.createElement('button');
        btn.textContent = '×';
        btn.onclick = () => this.removeItem(id);
        li.append(btn);

        this.container.append(li);
    }

    // 初始渲染
    render() {
        this.container.innerHTML = '';
        this.items.forEach(item => this._appendSingleItem(item));
    }
}

// 使用示例
const manager = new ListManager('#todo-list');
manager.addItem('学习 DOM API');
manager.addItem('编写示例代码');
manager.addItem('整理笔记');
manager.removeItem(manager.items[1].id);
```

这个例子展示了几个关键原则：

1. **增量更新优于全量重渲染**：新增一项时只调用 `append`，不动已有的元素。
2. **利用 data 属性做 ID 映射**：避免了维护单独的元素引用映射表。
3. **利用移动语义实现排序**：`insertBefore` 自动处理了从原位置的移除。
4. **现代 API 与传统 API 的合理混用**：`remove()`、`append()`、`replaceChildren()` 配合使用。

## 七、常见陷阱与避坑指南

| 陷阱 | 现象 | 解决方案 |
|------|------|---------|
| 循环中动态集合变化 | 跳过元素或无限循环 | 使用静态集合或倒序遍历 |
| 忘记 innerHTML 会销毁事件 | 替换后交互失效 | 使用事件委托或重新绑定 |
| 移除元素后还持有引用 | 内存泄漏风险 | 及时置空或用 WeakRef |
| insertBefore 的参考节点为 null | 行为等同于 appendChild | 这是标准行为，可加以利用 |
| 传给 insertBefore 的节点已在别处 | 节点被移动而非复制 | 如需保留原位，先 cloneNode |

> **最后的思考**：DOM 修改操作看似简单——不就是增删改嘛？但其背后的设计哲学值得深思。传统 API（`appendChild`、`insertBefore`）要求你始终明确知道"谁的父亲是谁"，这是一种强制性的结构意识训练。而现代 API（`append`、`before`、`remove`）则更加人性化，隐藏了部分复杂性。两者并非替代关系而是互补关系——理解传统 API 能让你明白底层的工作原理，使用现代 API 则能提高开发效率。真正的高效来自于对两者的深刻理解和灵活选用。关于如何读写元素的属性和内容，推荐阅读[《属性与内容》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/25.属性与内容.md)。关于如何操作元素的样式，推荐阅读[《样式操作》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/30.样式操作.md)。
