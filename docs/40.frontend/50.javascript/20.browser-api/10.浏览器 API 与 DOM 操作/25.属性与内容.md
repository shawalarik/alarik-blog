# 属性与内容 —— getAttribute、setAttribute、dataset、innerHTML、textContent、outerHTML

## 从"结构操作"到"数据读写"的能力跃迁

在[《遍历与修改 DOM》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/20.遍历与修改DOM.md)一文中，我们学会了如何在 DOM 树中移动节点——添加、删除、替换、移动元素的位置。但一个 HTML 元素远不止是一个位置标记，它还携带了大量的**信息**：标签名、属性（class、id、href、data-*）、内部文本内容……如何读取和修改这些数据，是本文的主题。

DOM 中关于"属性"和"内容"的 API 存在一套容易混淆的双重体系——**HTML 属性（Attribute）** 与 **DOM 属性（Property）** 的区别，以及 **innerHTML**、**textContent**、**outerHTML** 三者的语义差异。搞清楚这些概念之间的边界，是避免无数隐蔽 bug 的前提。

> **本文的目标**：彻底厘清 Attribute 与 Property 的区别，深入理解 dataset、classList 等便捷 API，以及 innerHTML/textContent/outerHTML 的使用场景和安全考量。

---

## 一、Attribute vs Property：两套平行的体系

### 1.1 什么是 HTML 属性？

HTML 属性是你写在标签里的键值对：

```html
<input id="email" type="text" value="hello@example.com" disabled class="form-input">
```

这里的 `id`、`type`、`value`、`disabled`、`class` 都是 **HTML 属性（Attributes）**。它们是 HTML 源码的一部分，是静态的初始值。

### 1.2 什么是 DOM 属性？

当浏览器把上面的 HTML 解析为 DOM 对象后，这个 `<input>` 元素会变成一个 JavaScript 对象，它拥有对应的**属性（Properties）**：

```javascript
const input = document.getElementById('email');

// DOM 属性 —— JavaScript 对象的属性
input.id;            // 'email'
input.type;          // 'text'
input.value;         // 'hello@example.com'（当前值）
input.disabled;      // true（布尔值！）
input.className;     // 'form-input'（注意：不是 class，是 className）
```

### 1.3 两者的关键区别

```html
<input id="test" value="initial">
```

```javascript
const input = document.getElementById('test');

// === 读取 ===
input.getAttribute('value');   // 'initial'（始终返回 HTML 中的原始字符串）
input.value;                    // ''（用户可能已经清空了输入框！）

// === 修改 ===
input.setAttribute('value', 'new-value');
// HTML 属性变了 → input.getAttribute('value') = 'new-value'
// 但 DOM 属性不一定同步变化！

input.value = 'user-typed';
// DOM 属性变了 → input.value = 'user-typed'
// 但 HTML 属性不变！→ input.getAttribute('value') 还是 'initial'

// === 特殊情况：布尔属性 ===
input.getAttribute('disabled');  // ''（空字符串表示存在）或 null（不存在）
input.disabled;                   // true 或 false（真正的布尔值）

// 设置
input.disabled = true;            // DOM 属性方式（推荐）
// 等价于：
input.setAttribute('disabled', '');  // HTML 属性方式

input.disabled = false;
// 等价于：
input.removeAttribute('disabled');
```

### 1.4 生活类比：身份证 vs 实际状态

- **HTML 属性就像你的身份证上的信息**：上面写着你的姓名、出生日期、住址。这些信息是"登记时填写的"，不会自动更新。如果你搬了家，身份证上还是原来的地址——除非你去重新办理。

- **DOM 属性就像你当前的实际状态**：你现在住在哪里？你现在叫什么名字？这些是可以变化的实时状态。你可能改名了、搬家了，但身份证还没来得及换。

- 有时候两者一致（刚办好的新身份证 = 当前状态），有时候不一致（改了名但还没去换证）。**DOM 属性反映的是当前运行时的真实状态，HTML 属性反映的是初始配置。**

> **哲学思考**：这种"声明式（Declarative）"与"命令式（Imperative）"的对立统一贯穿了整个前端工程。HTML 属性是声明式的——你在源码中"声明"这个输入框的初始值是什么；DOM 属性是命令式的——你通过 JavaScript "命令"它的值变成什么。理解这两套体系的关系，就是理解 Web 平台从静态文档向动态应用演化的关键线索之一。

## 二、getAttribute / setAttribute / removeAttribute

### 2.1 基本用法

```javascript
const link = document.querySelector('a');

// 读取属性
link.getAttribute('href');           // 'https://example.com'
link.getAttribute('target');         // '_blank' 或 null（不存在则返回 null）
link.getAttribute('data-count');     // 自定义 data 属性

// 设置属性
link.setAttribute('href', 'https://new-url.com');
link.setAttribute('target', '_self');
link.setAttribute('data-count', '42');

// 移除属性
link.removeAttribute('target');
// 之后 getAttribute('target') 返回 null

// 检查属性是否存在
link.hasAttribute('target');          // false
link.hasAttribute('href');            // true
```

### 2.2 什么时候必须用 getAttribute/setAttribute？

大多数情况下，直接操作 DOM 属性更方便。但有些场景下只能用 attribute 方法：

```javascript
const div = document.createElement('div');

// 1. 自定义属性（不是标准 DOM 属性）
div.setAttribute('my-custom-attr', 'value');
console.log(div.myCustomAttr);       // undefined！（没有对应的 DOM 属性）
console.log(div.getAttribute('my-custom-attr'));  // 'value'

// 2. 需要保留大小写的属性名称
div.setAttribute('dataViewMode', 'grid');
// HTML 属性名保持原样

// 3. 需要区分"值为空的属性"和"不存在的属性"
// <div hidden="">  vs  <div>
div.getAttribute('hidden');    // ''（空字符串——属性存在但无值）
div.hasAttribute('hidden');    // true

// 4. 批量设置自定义属性
function setElementConfig(el, config) {
    Object.entries(config).forEach(([key, value]) => {
        if (value === null || value === undefined) {
            el.removeAttribute(key);
        } else {
            el.setAttribute(key, String(value));
        }
    });
}

setElementConfig(div, {
    'data-id': '123',
    'aria-label': 'Close button',
    'role': 'button',
    'title': null  // 移除 title
});
```

## 三、dataset：data-* 属性的便捷接口

### 3.1 data-* 属性的由来

HTML5 引入了 `data-*` 自定义属性机制，允许开发者在 HTML 元素上存储自定义数据：

```html
<div id="user-card"
     data-user-id="12345"
     data-user-name="张三"
     data-role="admin"
     data-preferences='{"theme":"dark","lang":"zh"}'>
</div>
```

### 3.2 dataset API 的映射规则

JavaScript 提供了 `dataset` 属性作为访问 `data-*` 属性的便捷接口：

```javascript
const card = document.getElementById('user-card');

// 映射规则：data-xxx-yyy → dataset.xxxYyy（驼峰命名）
card.dataset.userId;              // '12345'
card.dataset.userName;            // '张三'
card.dataset.role;                // 'admin'
card.dataset.preferences;         // '{"theme":"dark","lang":"zh"}'

// 修改
card.dataset.userId = '67890';    // 自动同步到 data-user-id 属性
card.dataset.role = 'super-admin';

// 新增
card.dataset.department = '技术部';
// HTML 变成：data-department="技术部"

// 删除
delete card.dataset.role;
// HTML 中 data-role 属性被移除

// 注意限制：
// 1. 属性名必须以 data- 开头
// 2. 只能通过 dataset 操作，不能直接用 setAttribute 操作 dataset 对象
// 3. 值始终是字符串类型
card.dataset.count = 5;
console.log(typeof card.dataset.count);   // 'string'（数字 5 被转成了 '5'）
```

### 3.3 实战：用 dataset 实现轻量级组件配置

```javascript
/**
 * 使用 data 属性实现可配置的折叠面板
 */
class CollapsePanel {
    constructor(element) {
        this.el = element;
        this.config = {
            autoCollapse: el.dataset.autoCollapse !== 'false',
            duration: parseInt(el.dataset.duration) || 300,
            easing: el.dataset.easing || 'ease',
            startOpen: el.dataset.startOpen === 'true'
        };
        
        this.content = el.querySelector('.panel-content') 
                    || el.nextElementSibling;
        
        this._init();
    }
    
    _init() {
        if (!this.config.startOpen) {
            this.content.style.height = '0';
            this.content.style.overflow = 'hidden';
        }
        
        this.el.querySelector('.panel-header').addEventListener('click', () => {
            this.toggle();
        });
    }
    
    toggle() {
        const isOpen = this.el.classList.contains('open');
        
        if (isOpen) {
            this.close();
        } else {
            // 如果开启了手风琴模式，关闭其他面板
            if (this.config.autoCollapse) {
                document.querySelectorAll('.collapse-panel.open')
                    .forEach(panel => panel.collapsePanel?.close());
            }
            this.open();
        }
    }
    
    open() {
        this.content.style.transition = `height ${this.config.duration}ms ${this.config.easing}`;
        this.content.style.height = this.content.scrollHeight + 'px';
        this.el.classList.add('open');
    }
    
    close() {
        this.content.style.height = '0';
        this.el.classList.remove('open');
    }
}

// HTML 用法：
// <div class="collapse-panel" data-duration="500" data-easing="ease-in-out">
//   <div class="panel-header">点击展开</div>
//   <div class="panel-content">隐藏的内容</div>
// </div
```

这种方式的优势在于**配置与行为分离**：HTML 负责声明配置（声明式），JavaScript 负责执行逻辑（命令式）。修改组件行为不需要改动 JS 代码，只需调整 data 属性即可。

### 3.4 生活类比：data-* 就像商品的标签

想象你在超市买东西。商品本身（DOM 元素）有固定的特征——它是饮料、瓶装、500ml。但超市还需要附加一些管理信息——入库日期、货架编号、促销标识。这些信息就贴在商品上的**小标签（data-* 属性）**上。

- 标签不影响商品本身的用途（喝了还是那个味道）。
- 标签可以被随时更换或撕掉。
- 不同商品可以有不同的标签组合。
- 收银员可以通过扫描标签快速获取信息（`dataset` 就是扫码器）。

## 四、innerHTML、textContent 与 outerHTML

### 4.1 innerHTML：解析器入口

`innerHTML` 是最常用也最危险的 DOM 内容 API：

```javascript
const div = document.getElementById('container');

// 读取：返回所有子节点的 HTML 序列化
div.innerHTML;
// → '<p>Hello <strong>World</strong></p><span>!</span>'

// 写入：将字符串作为 HTML 解析并替换所有子节点
div.innerHTML = '<h1>New Content</h1><p>Paragraph</p>';

// 追加（不覆盖已有内容）
div.innerHTML += '<footer>The End</footer>';
// ⚠️ 这会销毁所有现有子节点并重建！事件监听器全部丢失！
```

### 4.2 textContent：纯文本读写

```javascript
const div = document.getElementById('container');
// 假设 HTML：<p>Hello <strong>World</strong></p>

// 读取：返回所有后代文本节点的拼接（不含标签）
div.textContent;      // 'Hello World!'

// 写入：设置为纯文本（特殊字符会被转义）
div.textContent = '<script>alert("XSS")</script>';
// 页面上显示的字面文本：<script>alert("XSS")</script>
// 不会被执行！✅ 安全

// 对比 innerHTML 的危险行为
div.innerHTML = '<script>alert("XSS")</script>';
// ⚠️ 如果这段内容来自用户输入，脚本会被执行！危险！
```

这是 `textContent` 相对于 `innerHTML` 最大的优势：**它是安全的**。当你需要显示用户生成的内容时，优先使用 `textContent`。

### 4.3 outerHTML：包含自身的完整序列化

```html
<div id="box"><span>内容</span></div>
```

```javascript
const box = document.getElementById('box');

box.innerHTML;    // '<span>内容</span>'      （不包含自身）
box.textContent;  // '内容'
box.outerHTML;    // '<div id="box"><span>内容</span></div>'  （包含自身！）

// 写入 outerHTML 会替换元素自身
box.outerHTML = '<section id="box"><p>全新的结构</p></section>';
// box 变量现在指向一个被移除的元素（不在文档树中了）
// 文档中的 #box 现在是一个 <section> 元素
```

### 4.4 三者对比总结

| 特性 | `innerHTML` | `textContent` | `outerHTML` |
|------|------------|--------------|-------------|
| **读取范围** | 子元素的 HTML | 后代的纯文本 | 包含自身在内的完整 HTML |
| **写入效果** | 替换子元素 | 替换子元素（纯文本） | 替换自身 |
| **是否解析 HTML** | ✅ 会解析 | ❌ 当纯文本处理 | ✅ 会解析 |
| **XSS 风险** | ⚠️ 高危 | ✅ 安全 | ⚠️ 高危 |
| **性能** | 较慢（需解析） | 快 | 较慢 |

### 4.5 XSS 攻击原理与防御

```javascript
// ⚠️ 危险示例：直接将用户输入写入 innerHTML
const commentInput = document.getElementById('comment');
const displayArea = document.getElementById('display');

commentInput.addEventListener('change', () => {
    // 用户如果输入：<img src=x onerror=alert(1)>
    displayArea.innerHTML = commentInput.value;  // 💀 XSS 漏洞！
});

// ✅ 安全方案 A：使用 textContent
displayArea.textContent = commentInput.value;

// ✅ 安全方案 B：先转义再使用 innerHTML
function escapeHtml(str) {
    return str.replace(/[&<>"']/g, char => ({
        '&': '&amp;', '<': '&lt;', '>': '&gt;',
        '"': '&quot;', "'": '&#39;'
    })[char]);
}
displayArea.innerHTML = escapeHtml(commentInput.value);

// ✅ 安全方案 C：使用 DOMPurify 库
// import DOMPurify from 'dompurify';
// displayArea.innerHTML = DOMPurify.sanitize(userInput);
```

> **哲学思考**：innerHTML 的安全性问题揭示了一个更深层的命题——**表达力与安全性的权衡**。innerHTML 之所以强大正是因为它会解析 HTML 字符串，这意味着你可以用一行代码构建复杂的 DOM 结构。但这种"信任输入"的能力也是其致命弱点。textContent 牺牲了表达力换取了绝对的安全——它拒绝解释任何标记语言。这就像自然语言的"双关语"现象：同一个表达在不同上下文中有不同的解读，歧义既是文学修辞的源泉也是误解的温床。工程中不存在完美的解决方案，只有适合场景的取舍。

## 五、classList：类名的精细化管理

### 5.1 为什么不直接操作 className？

```javascript
const el = document.querySelector('.box');

// ❌ 字符串拼接方式——脆弱且冗长
el.className += ' active';
// 问题：可能会重复添加 active
// 问题：需要手动处理空格
// 问题：移除时需要字符串 replace

// ✅ classList API——简洁且可靠
el.classList.add('active');
el.classList.remove('hidden');
el.classList.toggle('visible');
el.classList.contains('active');   // true/false
```

### 5.2 classList 完整 API

```javascript
const el = document.getElementById('card');

// add：添加一个或多个类
el.classList.add('card', 'shadow', 'rounded');

// remove：删除一个或多个类
el.classList.remove('shadow', 'rounded');

// toggle：切换（有则删，无则加）
el.classList.toggle('active');              // 强制切换
el.classList.toggle('visible', force);      // force 为 true 则添加，false 则移除

// contains：检查是否存在
if (el.classList.contains('card')) { /* ... */ }

// replace：替换一个类为另一个
el.classList.replace('old-class', 'new-class');

// forEach：遍历所有类名
el.classList.forEach(cls => console.log(cls));

// length 和索引访问
console.log(el.classList.length);     // 类名数量
console.log(el.classList[0]);         // 第一个类名
console.log(el.classList.value);      // 完整的 className 字符串

// 实用技巧：根据条件批量修改
function updateClasses(el, { add = [], remove = [], toggle = [] }) {
    if (add.length) el.classList.add(...add);
    if (remove.length) el.classList.remove(...remove);
    toggle.forEach(cls => el.classList.toggle(cls));
}

updateClasses(document.body, {
    add: ['theme-dark'],
    remove: ['theme-light'],
    toggle: ['sidebar-open']
});
```

### 5.3 生活类比：classList 就像行李标签管理系统

想象你在机场托运行李：

- **className 是一张写满所有标签的手写纸条**：上面写着 `"large red fragile priority"`。你想去掉 `red` 吗？得拿橡皮擦擦掉再补上新词。想加一个新的吗？找地方挤进去。纸条越写越长，越容易出错。

- **classList 就像一套电子标签系统**：
  - `add('priority')` → 电子系统新增一条记录
  - `remove('red')` → 删除一条记录
  - `contains('fragile')` → 查询是否有某条记录
  - `toggle('checked')` → 有则删除，无则添加
  - 每个标签独立管理，互不干扰

## 六、综合实战：富文本编辑器的核心功能

下面展示属性与内容操作的综合运用：

```javascript
/**
 * 轻量级富文本工具栏
 */
class RichTextToolbar {
    constructor(editorSelector, toolbarSelector) {
        this.editor = document.querySelector(editorSelector);
        this.toolbar = document.querySelector(toolbarSelector);
        this._bindActions();
    }

    _bindActions() {
        // 委托事件到工具栏
        this.toolbar.addEventListener('click', (e) => {
            const btn = e.target.closest('[data-command]');
            if (!btn) return;

            const command = btn.dataset.command;
            const value = btn.dataset.value || null;

            this._execCommand(command, value);
            this._updateToolbarState();
        });

        // 监听选区变化来更新按钮状态
        document.addEventListener('selectionchange', () => {
            this._updateToolbarState();
        });
    }

    _execCommand(command, value) {
        // 让 editor 获得焦点
        this.editor.focus();

        switch (command) {
            case 'bold':
                document.execCommand('bold', false, null);
                break;
            case 'formatBlock':
                document.execCommand('formatBlock', false, value);
                break;
            case 'insertHTML':
                // ⚠️ 仅在可信来源时使用 insertHTML
                document.execCommand('insertHTML', false, value);
                break;
            case 'createLink':
                const url = prompt('请输入链接地址:');
                if (url) document.execCommand('createLink', false, url);
                break;
            case 'clearFormat':
                document.execCommand('removeFormat', false, null);
                break;
        }
    }

    _updateToolbarState() {
        // 根据 document.queryCommandState 更新按钮激活状态
        this.toolbar.querySelectorAll('[data-command]').forEach(btn => {
            const command = btn.dataset.command;
            const isActive = document.queryCommandState(command);

            btn.classList.toggle('active', isActive);
            
            // 用 dataset 存储按钮的状态供 CSS 使用
            btn.dataset.active = isActive;
        });
    }

    // 安全地获取编辑器内容（用于提交服务器）
    getContent(sanitize = true) {
        let html = this.editor.innerHTML;
        
        if (sanitize) {
            // 基本的净化：移除 script 标签和事件属性
            html = html.replace(/<script[\s\S]*?<\/script>/gi, '');
            html = html.replace(/ on\w+\s*=\s*"[^"]*"/g, '');
        }
        
        return html;
    }

    // 安全地设置内容
    setContent(html) {
        // 使用 textContent 先清空（比 innerHTML = '' 更安全）
        // 然后再用受信任的方式设置内容
        this.editor.textContent = '';  
        // 如果确认内容可信，才用 innerHTML
        this.editor.innerHTML = html;  
    }

    // 获取纯文本版本
    getTextContent() {
        return this.editor.textContent;
    }
}
```

这个例子展示了实际项目中属性与内容操作的典型模式：**dataset 用于配置传递**、**classList 用于状态管理**、**innerHTML/textContent 分别用于富文本和纯文本的处理**，以及**对安全边界的明确意识**。

## 七、总结：属性与内容的心智模型

### 7.1 API 选择决策树

```
你需要做什么？
│
├─ 读取标准属性（id/class/href/value...）
│   └─ 直接用 DOM 属性：el.id / el.className / el.value
│
├─ 读取/设置自定义非标准属性
│   └─ 用 getAttribute/setAttribute
│
├─ 操作 data-* 自定义数据
│   └─ 优先用 el.dataset.xxxName
│
├─ 显示用户输入的内容
│   └─ 用 el.textContent（防 XSS）
│
├─ 构建包含 HTML 结构的内容
│   └─ 确认安全后用 el.innerHTML
│
├─ 添加/删除/切换 CSS 类
│   └─ 始终用 el.classList API
│
└─ 替换元素自身（含标签）
    └─ 用 el.outerHTML
```

### 7.2 核心原则

1. **区分 Attribute 与 Property**：前者是 HTML 源码中的初始值，后者是运行时的当前状态。
2. **优先使用 DOM 属性**（如 `el.className`、`el.id`）：更简洁、类型正确（布尔属性返回布尔值）。
3. **用户输入永远走 textContent**：防止 XSS 攻击的第一道防线。
4. **dataset 管理 data-\***：语义清晰，自动驼峰转换。
5. **classList 管理类名**：原子操作，不会出现重复或遗漏。

> **最后的思考**：属性与内容的操作看似琐碎——不就是读读写写嘛？但正是这些细小的 API 设计决定了代码的**安全性**（XSS 防御）、**可维护性**（classList vs 字符串拼接）和**语义清晰度**（dataset vs 随意的自定义属性）。优秀的工程师不仅知道每个 API 怎么用，更知道为什么这么设计以及在哪个场景下应该选择哪一个。这套知识体系就像一把精密的手术刀——每一款都有其特定的用途，混用可能导致灾难性的后果。关于如何操作元素的样式，推荐阅读[《样式操作》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/30.样式操作.md)。关于如何获取元素的尺寸和位置信息，推荐阅读[《尺寸与坐标》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/35.尺寸与坐标.md)。
