# 尺寸与坐标 —— offsetWidth/clientWidth/scrollWidth、getBoundingClientRect、elementFromPoint

## 从"视觉样式"到"空间度量"的认知跃迁

在[《样式操作》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/30.样式操作.md)一文中，我们学习了如何改变元素的外观——颜色、字体、背景。但现代 Web 应用经常需要做的不仅是"好看"，还要"精确定位"——拖拽元素需要知道鼠标在哪里，虚拟滚动需要知道容器有多大，碰撞检测需要知道两个元素是否重叠。这就进入了**尺寸与坐标（Dimensions & Coordinates）**的领域。

DOM 提供了一套丰富但不直观的几何属性 API——offsetWidth/clientWidth/scrollWidth 及其 Height 版本，加上 getBoundingClientRect、elementFromPoint 等方法。这些属性的命名相似但含义迥异，初学者极易混淆。建立正确的心理模型是准确使用它们的前提。

> **本文的目标**：构建一套清晰的 DOM 几何度量心智模型——从盒模型出发，厘清 offset/client/scoll 三套尺寸体系的本质差异，掌握视口坐标与页面坐标的转换，以及在实际场景中的应用技巧。

## 一、盒模型的几何分解

### 1.1 四层嵌套的盒子

理解 DOM 尺寸的前提是深刻理解 CSS 盒模型。每个元素在渲染时实际上由四层嵌套的区域组成：

```css
.box {
    width: 200px;           /* content 区域宽度 */
    height: 150px;          /* content 区域高度 */
    padding: 20px;          /* 内边距 */
    border: 5px solid #333; /* 边框 */
    margin: 15px;           /* 外边距（不计入元素自身尺寸！） */
    overflow: auto;         /* 允许滚动 */
}
```

```
┌──────────────────────────────────────┐ ← 外边距边缘（margin edge）
│  margin: 15px                        │
│  ┌────────────────────────────────┐  │ ← 边框边缘（border edge）
│  │ border: 5px                    │  │
│  │ ┌────────────────────────────┐  │  │ ← 内边距边缘（padding edge）
│  │ │ padding: 20px              │  │  │
│  │ │ ┌────────────────────────┐ │  │  │ ← 内容边缘（content edge）
│  │ │ │                        │ │  │  │
│  │ │ │   content: 200×150     │ │  │  │
│  │ │ │                        │ │  │  │
│  │ │ └────────────────────────┘ │  │  │
│  │                            │  │  │
│  └────────────────────────────┘  │  │
│                                    │
└────────────────────────────────────┘
```

### 1.2 offsetWidth / offsetHeight：元素的占位尺寸

```javascript
const box = document.querySelector('.box');

box.offsetWidth;   // 250 = 200(content) + 20*2(padding) + 5*2(border)
box.offsetHeight;  // 200 = 150(content) + 20*2(padding) + 5*2(border)

// offsetWidth 包含：content + padding + border
// 不包含：margin
// 单位：像素（整数，四舍五入后的值）
```

`offsetWidth/Height` 回答的问题是：**这个元素在页面上占据了多少空间？** 它是包含 border 在内的总可见区域。

### 1.3 clientWidth / clientHeight：内容的可视区域

```javascript
box.clientWidth;   // 240 = 200(content) + 20*2(padding)
box.clientHeight;  // 190 = 150(content) + 20*2(padding)

// clientWidth 包含：content + padding
// 不包含：border、margin、滚动条
// 单位：像素
```

`clientWidth/Height` 回答的问题是：**元素内部有多少空间可以用来放内容？** 它是减去了 border 和滚动条之后的可用面积。对于 `overflow: scroll/auto` 的容器，clientWidth 会**扣除滚动条的宽度（约 17px）**。

### 1.4 scrollWidth / scrollHeight：内容的完整尺寸（含溢出部分）

```javascript
// 假设容器内有大量内容导致溢出
box.scrollWidth;   // 可能是 800（内容的实际宽度，含溢出的不可见部分）
box.scrollHeight;  // 可能是 1200（内容的实际高度）

// scrollWidth = max(内容的实际宽度, clientWidth)
// scrollHeight = max(内容的实际高度,.clientHeight)

// 如果内容没有溢出：scrollWidth ≈ clientWidth
// 如果内容溢出了：scrollWidth > clientWidth
```

`scrollWidth/Height` 回答的问题是：**内容到底有多大？** 不管能不能完全看到，它告诉你全部内容撑开的尺寸是多少。

### 1.5 三种尺寸的对比图示

假设一个容器的 CSS 如下：`width: 200px; padding: 20px; border: 5px; overflow: auto;`，内部有 500px 高的内容。

```
offsetHeight = 200 (content) + 40 (padding) + 10 (border) = 250px
                                          ↑
clientHeight = 200 (content) + 40 (padding) = 240px  (减去 ~17px 滚动条)
                                         ↑
scrollHeight = 500px (实际内容高度)
               ↑
```

### 1.6 生活类比：房间的三种面积测量方式

- **offsetWidth 就像建筑面积**：从外墙外沿测量的总面积。包含了墙体厚度（border）、室内面积（content+padding）。这是房产证上写的面积。
  
- **clientWidth 就像使用面积**：墙内测量的实际可用面积。扣掉了墙体（border）和可能的柱子（滚动条）。这是你真正能放家具的空间。
  
- **scrollWidth 就像仓库的总库存长度**：如果你的物品排成一列，总共有多长。不管你的房间（clientWidth）能放下多少，物品的实际总长度可能是它的好几倍。

> **哲学思考**：同一事物从不同角度测量会得出不同的数字，这不是矛盾而是视角的差异。物理学中有**静质量**与**相对论质量**的区别，经济学中有**名义 GDP** 与 **实际 GDP** 的区分。DOM 的三种尺寸体系同样体现了测量语境的重要性——你想要回答的问题决定了你应该选择哪种度量方式。没有绝对的"正确尺寸"，只有在特定问题下的"合适尺寸"。

## 二、滚动相关的属性

### 2.1 scrollTop / scrollLeft：滚动偏移量

```javascript
const container = document.getElementById('scroll-container');

// 当前滚动了多少距离
container.scrollTop;    // 垂直方向已滚动的像素数
container.scrollLeft;   // 水平方向已滚动的像素数

// 设置滚动位置
container.scrollTop = 200;  // 滚动到距顶部 200px 的位置
container.scrollTo({
    top: 500,
    left: 0,
    behavior: 'smooth'  // 平滑滚动
});

// 滚动到指定元素
const targetItem = container.querySelector('#item-50');
targetItem.scrollIntoView({ behavior: 'smooth', block: 'center' });
```

### 2.2 滚动到底部的常见需求

```javascript
// 聊天窗口自动滚动到底部
const chatMessages = document.getElementById('chat-messages');

function scrollToBottom() {
    chatMessages.scrollTop = chatMessages.scrollHeight;
    // scrollTop 设为 scrollHeight 就是最底部
}

// 但要注意：如果用户正在往上翻阅历史消息，不要强制滚动
let userScrolledUp = false;

chatMessages.addEventListener('scroll', () => {
    const isNearBottom = chatMessages.scrollHeight 
                         - chatMessages.scrollTop 
                         - chatMessages.clientHeight < 50;
    userScrolledUp = !isNearBottom;
});

function addMessage(msg) {
    const el = document.createElement('div');
    el.textContent = msg;
    chatMessages.appendChild(el);
    
    if (!userScrolledUp) {
        scrollToBottom();  // 只有用户在底部时才自动滚动
    }
}
```

### 2.3 判断是否滚动到了底部/顶部

```javascript
const el = document.getElementById('container');

// 是否接近底部
function isNearBottom(threshold = 50) {
    return el.scrollHeight - el.scrollTop - el.clientHeight < threshold;
}

// 是否到达顶部
function isAtTop() {
    return el.scrollTop <= 0;
}

// 无限滚动（Infinite Scroll）的核心逻辑
el.addEventListener('scroll', () => {
    if (isNearBottom(100) && !this.isLoading) {
        loadMoreData();
    }
});
```

## 三、getBoundingClientRect：视口坐标系中的精确定位

### 3.1 基本用法

`getBoundingClientRect()` 返回元素相对于**视口（Viewport）**的位置和尺寸信息：

```javascript
const rect = document.querySelector('.card').getBoundingClientRect();

rect.x;       // 左边缘相对于视口的 x 坐标
rect.y;       // 上边缘相对于视口的 y 坐标
rect.top;     // 同 rect.y
rect.left;    // 同 rect.x
rect.right;   // 右边缘相对于视口的 x 坐标
rect.bottom;  // 下边缘相对于视口的 y 坐标
rect.width;   // 元素的宽度（等于 offsetWidth）
rect.height;  // 元素的高度（等于 offsetHeight）
```

**关键点：返回值的坐标是相对于视口的，不是相对于文档的！** 当页面滚动时，同一个元素的 `getBoundingClientRect()` 值会随之变化。

### 3.2 视口坐标 vs 页面坐标

```
视口（Viewport）= 浏览器中可见的那块矩形区域
页面（Page/Document）= 整个网页（包括滚出去的不可见部分）

视口坐标：原点(0,0) 在视口左上角，滚动时会变
页面坐标：原点(0,0) 在页面左上角（固定不变）
```

```javascript
const el = document.querySelector('.target');
const rect = el.getBoundingClientRect();

// 视口坐标 → 页面坐标的转换
const pageX = rect.left + window.scrollX;
const pageY = rect.top + window.scrollY;

// 反过来：页面坐标 → 视口坐标
const viewportX = pageX - window.scrollX;
const viewportY = pageY - window.scrollY;
```

### 3.3 实战：拖拽功能的实现

```javascript
/**
 * 可拖拽元素实现
 */
class Draggable {
    constructor(element, options = {}) {
        this.el = element;
        this.handle = options.handle || element;
        this.bounds = options.bounds || null;  // 限制范围的父元素
        this.onDrag = options.onDrag || (() => {});
        this.onDragEnd = options.onDragEnd || (() => {});
        
        this.isDragging = false;
        this.offsetX = 0;
        this.offsetY = 0;
        
        this._bindEvents();
    }

    _bindEvents() {
        this.handle.addEventListener('mousedown', this._onMouseDown.bind(this));
        document.addEventListener('mousemove', this._onMouseMove.bind(this));
        document.addEventListener('mouseup', this._onMouseUp.bind(this));

        // 触摸支持
        this.handle.addEventListener('touchstart', this._onTouchStart.bind(this), { passive: false });
        document.addEventListener('touchmove', this._onTouchMove.bind(this), { passive: false });
        document.addEventListener('touchend', this._onMouseUp.bind(this));
    }

    _getEventPos(e) {
        if (e.touches && e.touches.length) {
            return { x: e.touches[0].clientX, y: e.touches[0].clientY };
        }
        return { x: e.clientX, y: e.clientY };
    }

    _onMouseDown(e) {
        if (e.button !== 0) return;  // 只响应左键
        
        this.isDragging = true;
        const pos = this._getEventPos(e);
        const rect = this.el.getBoundingClientRect();
        
        this.offsetX = pos.x - rect.left;
        this.offsetY = pos.y - rect.top;
        
        this.el.style.position = 'fixed';
        this.el.style.zIndex = '1000';
        e.preventDefault();
    }

    _onMouseMove(e) {
        if (!this.isDragging) return;
        
        const pos = this._getEventPos(e);
        let x = pos.x - this.offsetX;
        let y = pos.y - this.offsetY;

        // 边界约束
        if (this.bounds) {
            const boundsRect = this.bounds.getBoundingClientRect();
            x = Math.max(boundsRect.left, Math.min(x, boundsRect.right - this.el.offsetWidth));
            y = Math.max(boundsRect.top, Math.min(y, boundsRect.bottom - this.el.offsetHeight));
        }

        this.el.style.left = x + 'px';
        this.el.style.top = y + 'px';
        
        this.onDrag({ x, y, element: this.el });
    }

    _onMouseUp() {
        if (this.isDragging) {
            this.isDragging = false;
            this.onDragEnd({ element: this.el });
        }
    }

    _onTouchStart(e) { this._onMouseDown(e); }
    _onTouchMove(e) { this._onMouseMove(e); }
}
```

### 3.4 生活类比：GPS 定位 vs 房屋地址

- **getBoundingClientRect 就像 GPS 坐标**：告诉你"你现在距离屏幕左边缘多少厘米、距离屏幕上边缘多少厘米"。这个坐标会随着你移动而改变（就像 GPS 实时追踪你的位置）。
  
- **页面坐标就像房屋的门牌号**："某某路 123 号"。这个地址是固定的，不管你在城市的哪个角落看这张地图，门牌号都不会变。

- **两者的转换关系就像**：GPS 坐标 + 当前视野偏移量 = 门牌号的相对位置。

## 四、elementFromPoint：坐标反向查找

### 4.1 基本用法

`document.elementFromPoint(x, y)` 做的事情正好相反——给定视口坐标，返回该点最顶层的可见元素：

```javascript
// 获取视口中心点的元素
const centerX = window.innerWidth / 2;
const centerY = window.innerHeight / 2;
const centerEl = document.elementFromPoint(centerX, centerY);

// 获取鼠标位置下的元素（在 mousemove 事件中）
document.addEventListener('mousemove', (e) => {
    const el = document.elementFromPoint(e.clientX, e.clientY);
    console.log('鼠标下方:', el.tagName, el.className);
});
```

### 4.2 获取叠加的所有元素

`elementFromPoint` 只返回最顶层的一个元素。如果要获取该点下方的所有元素（包括被遮挡的）：

```javascript
/**
 * 获取指定坐标下所有叠加的元素
 */
function allElementsFromPoint(x, y) {
    const elements = [];
    let el = document.elementFromPoint(x, y);
    
    while (el && el !== document.body && el !== document.documentElement) {
        elements.push(el);
        // 临时隐藏当前元素，以便找到下面的元素
        el.style.pointerEvents = 'none';
        el = document.elementFromPoint(x, y);
    }
    
    // 恢复所有元素的 pointer-events
    elements.forEach(e => { e.style.pointerEvents = ''; });
    
    return elements;
}

// 使用
allElementsFromPoint(100, 200).forEach((el, i) => {
    console.log(`层级 ${i}:`, el.tagName, el.id || el.className);
});
```

### 4.3 实战：碰撞检测

```javascript
/**
 * 简单的矩形碰撞检测
 */
function checkCollision(el1, el2) {
    const r1 = el1.getBoundingClientRect();
    const r2 = el2.getBoundingClientRect();
    
    return !(r1.right < r2.left || 
             r1.left > r2.right || 
             r1.bottom < r2.top || 
             r1.top > r2.bottom);
}

// 检查拖拽元素是否与目标区域重叠
const draggable = document.getElementById('draggable');
const dropZone = document.getElementById('drop-zone');

document.addEventListener('drag', (e) => {
    if (checkCollision(draggable, dropZone)) {
        dropZone.classList.add('highlight');
    } else {
        dropZone.classList.remove('highlight');
    }
});
```

## 五、ResizeObserver：响应尺寸变化的现代 API

### 5.1 监听元素尺寸变化

传统的做法是用 `window.resize` 事件配合定时器检测，但 `ResizeObserver` 提供了原生的高效方案：

```javascript
/**
 * 自适应分栏组件
 * 根据容器宽度决定显示几列
 */
class ResponsiveGrid {
    constructor(container, options = {}) {
        this.container = container;
        this.columnMinWidth = options.columnMinWidth || 250;
        this.gap = options.gap || 16;
        
        this.observer = new ResizeObserver(entries => {
            for (const entry of entries) {
                this._updateColumns(entry.contentRect.width);
            }
        });
        
        this.observer.observe(container);
        this._updateColumns(container.clientWidth);
    }

    _updateColumns(containerWidth) {
        // 计算最多能放几列
        const totalGapSpace = this.gap;
        const availableWidth = containerWidth - totalGapSpace;
        const columns = Math.max(1, Math.floor(availableWidth / this.columnMinWidth));
        
        this.container.style.gridTemplateColumns = `repeat(${columns}, 1fr)`;
        this.container.dataset.columns = columns;
    }

    destroy() {
        this.observer.disconnect();
    }
}

// HTML:
// <div class="responsive-grid" style="display: grid; gap: 16px;">
//   <!-- items -->
// </div>

new ResponsiveGrid(document.querySelector('.responsive-grid'), {
    columnMinWidth: 280,
    gap: 16
});
```

### 5.2 ResizeObserver vs window.resize

| 维度 | ResizeObserver | window.resize |
|------|---------------|---------------|
| **粒度** | 单个元素级别 | 整个视口 |
| **触发时机** | 元素尺寸确实改变时 | 窗口尺寸改变时 |
| **性能** | 高（只观察特定元素） | 低（所有 resize 处理器都会触发） |
| **CSS 影响** | 能检测 CSS 引起的尺寸变化 | 不能 |
| **兼容性** | 现代浏览器均支持 | 所有浏览器 |

> **哲学思考**：DOM 的几何 API 本质上是连接**抽象的逻辑世界**（JavaScript 对象、数据模型）和**具象的物理世界**（屏幕像素、用户视线）的桥梁。当我们调用 `getBoundingClientRect()` 时，我们在问一个问题："这个抽象的 DOM 元素，在用户的物理屏幕上究竟占据了多少空间？"这个问题之所以复杂，是因为中间隔着 CSS 渲染引擎、设备像素比、视口滚动等多个转换层。每一层转换都是一种"坐标系变换"——就像地图投影把球面的地球变成平面的地图一样，信息不可避免地会发生变形或丢失。理解这些变换过程，就是在理解计算机图形学中最基础也最重要的概念。

## 六、总结：尺寸与坐标的心智模型

### 6.1 API 速查表

| 属性/方法 | 含义 | 包含 | 不包含 |
|-----------|------|------|--------|
| `offsetWidth/Height` | 元素占位尺寸 | content + padding + border | margin |
| `clientWidth/Height` | 内部可视区域 | content + padding | border, scrollbar |
| `scrollWidth/Height` | 内容完整尺寸 | 含溢出部分 | - |
| `scrollTop/Left` | 滚动偏移量 | - | - |
| `getBoundingClientRect()` | 视口坐标 + 尺寸 | 全部信息 | - |
| `elementFromPoint(x,y)` | 坐标反查元素 | - | - |

### 6.2 场景匹配指南

```
需要解决什么问题？
│
├─ 元素占了多大空间？
│   └─ offsetWidth / offsetHeight
│
├─ 元素内部能放多少内容？
│   └─ clientWidth / clientHeight
│
├─ 内容有没有溢出？总共多长？
│   └─ scrollWidth / scrollHeight
│
├─ 元素在屏幕上的确切位置？
│   └─ getBoundingClientRect()
│
├─ 这个坐标下是什么元素？
│   └─ elementFromPoint()
│
├─ 滚动到哪里了？/ 滚动到底部了吗？
│   └─ scrollTop / scrollHeight
│
└─ 元素大小改变了怎么办？
    └─ ResizeObserver
```

> **最后的思考**：DOM 几何 API 的复杂性来源于现实世界的复杂性。一个元素在屏幕上的"大小"不是一个简单的问题——取决于你指的是它的"占地面积"（offset）、"内部空间"（client）、还是"内容总量"（scroll）。同样，"位置"也不是唯一的——相对于视口的坐标和相对于文档的坐标是两个不同的参考系。学习这些 API 的过程，实际上是在训练一种**多维度空间思维能力**：同一个对象在不同的参考框架下有不同的度量值，而熟练的开发者能在这些框架之间自由切换。关于 DOM 的事件系统，推荐阅读[《事件模型》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/40.事件模型.md)。关于事件对象的详细分析，推荐阅读[《事件对象》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/45.事件对象.md)。
