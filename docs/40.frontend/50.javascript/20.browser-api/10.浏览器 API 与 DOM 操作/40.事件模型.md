# 事件模型 —— 事件流（捕获、目标、冒泡）、addEventListener 选项（once、passive）

## 从"静态操作"到"响应交互"的范式跃迁

到目前为止，我们讨论的所有 DOM 操作——查找节点、修改结构、读写样式、测量尺寸——本质上都是**命令式**的：你告诉浏览器做什么，它就做。但现代 Web 应用的核心不是"你告诉页面做什么"，而是**"用户做了什么，页面做出响应"**。点击、滚动、输入、触摸……这些用户行为触发的响应机制就是**事件（Event）系统**。

DOM 事件模型是 Web 交互的基石，但它远比"点击按钮执行函数"复杂得多。事件不是在某个元素上凭空发生的——它在 DOM 树中传播，经历捕获、目标和冒泡三个阶段。理解这个完整的生命周期，是写出可靠交互逻辑的前提。

> **本文的目标**：深入剖析 DOM 事件的完整传播机制——从三个阶段的生命周期，到 addEventListener 的每个选项参数的含义和用途，再到事件系统的设计哲学。

## 一、事件流的三个阶段

### 1.1 一个 click 事件的一生

当你在页面上点击一个 `<button>` 元素时，这个 click 事件并非"只发生在 button 上"。它会经历一段完整的旅程：

```
                    document (捕获阶段开始)
                       ↓ capture
                      html
                       ↓ capture
                     body
                       ↓ capture
                     div.container     ← 捕获阶段结束
                       ↓
                   button (目标阶段)    ← 事件到达目标元素
                       ↓
                     div.container      ← 冒泡阶段开始
                       ↓ bubble
                     body
                       ↓ bubble
                      html
                       ↓ bubble
                    document (冒泡阶段结束)
```

这个过程分为三个阶段：

```html
<div id="outer" style="padding: 30px; background: #eee;">
    <div id="middle" style="padding: 20px; background: #ccc;">
        <button id="inner">点我</button>
    </div>
</div>
```

```javascript
const phases = ['NONE', 'CAPTURING_PHASE', 'AT_TARGET', 'BUBBLING_PHASE'];

[document, document.getElementById('outer'), 
 document.getElementById('middle'),
 document.getElementById('inner')].forEach(el => {
    
    // 捕获阶段监听（第三个参数为 true）
    el.addEventListener('click', (e) => {
        console.log(`[捕获] ${el.id || el.tagName} → 阶段: ${phases[e.eventPhase]}`);
    }, true);
    
    // 冒泡阶段监听（第三个参数为 false/省略）
    el.addEventListener('click', (e) => {
        console.log(`[冒泡] ${el.id || el.tagName} → 阶段: ${phases[e.eventPhase]}`);
    });
});
```

点击按钮后的输出：

```
[捕获] DOCUMENT → 阶段: CAPTURING_PHASE
[捕获] outer   → 阶段: CAPTURING_PHASE
[捕获] middle  → 阶段: CAPTURING_PHASE
[冒泡] inner   → 阶段: AT_TARGET          ← 目标阶段
[冒泡] middle  → 阶段: BUBBLING_PHASE
[冒泡] outer   → 阶段: BUBBLING_PHASE
[冒泡] DOCUMENT→ 阶段: BUBBLING_PHASE
```

注意：**目标元素上的处理器不区分捕获和冒泡**——无论注册时第三个参数是什么，都在 AT_TARGET 阶段执行。

### 1.2 捕获阶段（Capturing Phase）

事件从 `window` → `document` → `html` → `body` → ... 一路向下，直到到达目标元素的父节点。

```javascript
// 在捕获阶段拦截事件
document.addEventListener('click', (e) => {
    console.log('事件正在向下传播，当前在:', e.target.tagName);
}, true);  // 第三个参数 true = 捕获阶段触发

// 实际用途：在事件到达目标之前进行全局拦截
document.addEventListener('click', (e) => {
    if (e.target.closest('.disabled-area')) {
        e.stopPropagation();  // 阻止事件继续传播
        return;
    }
}, true);
```

捕获阶段的典型应用场景：
- **全局事件委托的前置过滤**：在事件到达具体元素前判断是否应该放行。
- **调试工具的实现**：DevTools 中的事件监听器面板需要在最早时机记录事件。
- **某些特殊 UI 组件**：如模态框的背景点击关闭功能，用捕获可以确保不被子元素阻止。

### 1.3 目标阶段（Target Phase）

事件到达了被点击的那个元素本身：

```javascript
button.addEventListener('click', (e) => {
    console.log(e.eventPhase === Event.AT_TARGET);  // true
    console.log(e.target === e.currentTarget);       // true
    // target = 触发事件的元素（被点击的那个）
    // currentTarget = 当前处理器的绑定元素（这里也是 button）
});
```

### 1.4 冒泡阶段（Bubbling Phase）

事件从目标元素向上传播回 `document` 和 `window`：

```javascript
// 大多数情况下我们在冒泡阶段监听（默认行为）
document.getElementById('outer').addEventListener('click', (e) => {
    console.log('冒泡到了 outer');
});  // 第三个参数默认为 false = 冒泡阶段

// 冒泡是大多数内置事件（click、keydown、keyup...）的默认行为
// 但有些事件不会冒泡：focus、blur、mouseenter、mouseleave、load...
```

### 1.5 生活类比：公司通知的下达过程

想象一家公司要发布一项通知：

- **捕获阶段就像从 CEO 到员工的逐级下达**：CEO → 副总裁 → 部门经理 → 组长 → 员工。每一级都有机会在通知到达最终接收者之前看到它。
  
- **目标阶段就是员工本人收到通知**："这条通知是发给你的。"
  
- **冒泡阶段就像是员工逐级上报反馈**：员工 → 组长 → 经理 → 副总裁 → CEO。"我已收到并处理了这个通知。"

> **哲学思考**：事件的三阶段模型体现了**分层架构中的信息传播模式**。计算机网络中的 TCP/IP 协议栈、操作系统中的中断处理机制、企业组织中的指令传达流程——它们都遵循类似的"逐层穿透"模式。捕获阶段允许上层对下层进行前置干预（类似防火墙），冒泡阶段允许下层向上层报告结果（类似回调）。这种对称的设计让事件系统既有自顶向下的控制力，又有自底向上的反馈能力。

## 二、addEventListener 深度解析

### 2.1 完整签名

```javascript
element.addEventListener(type, listener, options);
// 或
element.addEventListener(type, listener, useCapture);

// type: 事件类型字符串，如 'click'、'scroll'、'keydown'
// listener: 处理函数（或包含 handleEvent 方法的对象）
// options: 对象形式配置 / useCapture: 布尔值（是否在捕获阶段触发）
```

### 2.2 options 对象的所有选项

```javascript
element.addEventListener('click', handler, {
    capture: false,    // 是否在捕获阶段触发（等同于 useCapture 参数）
    once: false,       // 是否只触发一次后自动移除
    passive: false,    // 是否不允许调用 preventDefault()
    signal: undefined  // AbortSignal 用于取消监听
});

// === 各选项详解 ===

// 1. once: 一次性事件监听器
button.addEventListener('click', () => {
    console.log('只会打印一次');
}, { once: true });

// 等价于手动 removeEventListener，但更简洁且不会遗漏
// 典型场景：初始化加载动画、引导提示、首次交互追踪

// 2. passive: 被动监听器
// 用于滚动事件等高频事件，告诉浏览器"我不会 preventDefault"
window.addEventListener('touchstart', handler, { passive: true });
window.addEventListener('wheel', handler, { passive: true });

// 为什么需要 passive？
// 浏览器在调用你的滚动处理器之前，
// 不知道你是否会调用 e.preventDefault() 来阻止默认滚动
// 所以它必须等待你的处理器完成才能决定是否滚动
// 这会导致最多 ~100ms 的延迟（卡顿！）
// passive: true 告诉浏览器"放心滚吧，我不阻止"，从而实现平滑滚动

// ⚠️ 如果设置了 passive: true 却调用了 preventDefault()：
// 控制台会警告：Unable to preventDefault inside passive event listener
window.addEventListener('touchmove', (e) => {
    // e.preventDefault();  // ❌ 无效且报错
}, { passive: true });

// 3. signal: 可取消的监听器（现代 API）
const controller = new AbortController();
const signal = controller.signal;

element.addEventListener('click', handler, { signal });

// 后续需要移除时：
controller.abort();  // 一次性移除所有使用该 signal 注册的监听器
// 不需要保存 handler 引用，非常方便清理

// 典型用法：组件销毁时清理所有事件
class Component {
    constructor(element) {
        this.abortController = new AbortController();
        element.addEventListener('click', this._onClick.bind(this), 
            { signal: this.abortController.signal });
        window.addEventListener('resize', this._onResize.bind(this), 
            { signal: this.abortController.signal });
    }
    
    destroy() {
        this.abortController.abort();  // 一行代码清理全部
    }
}
```

### 2.3 removeEventListener 的匹配规则

```javascript
function handleClick(e) { /* ... */ }

// 添加
element.addEventListener('click', handleClick, { capture: true });

// 移除时必须满足三个条件完全一致：
// 1. 同一个元素引用
// 2. 同一个事件类型
// 3. 同一个处理器函数引用（不能是匿名函数！）
// 4. 同样的 capture 选项
element.removeEventListener('click', handleClick, { capture: true });

// ⚠️ 常见错误：无法移除匿名函数
element.addEventListener('click', function() {
    console.log('无法移除！');
});
// 因为每次传入的都是一个新的函数引用
element.removeEventListener('click', function() {
    console.log('这不是同一个函数！');
});  // 移除失败！

// 解决方案 A：命名函数
function handler() { console.log('可移除'); }
element.addEventListener('click', handler);
element.removeEventListener('click', handler);

// 解决方案 B：once 选项
element.addEventListener('click', () => { /* 自动移除 */ }, { once: true });

// 解决方案 C：AbortController（推荐）
const ac = new AbortController();
element.addEventListener('click', () => { /* 自动管理 */ }, { signal: ac.signal });
ac.abort();  // 清理
```

## 三、事件对象的完整属性体系

### 3.1 核心属性

每个事件处理函数都会收到一个 **Event 对象**作为参数：

```javascript
element.addEventListener('click', (event) => {
    // === 身份标识 ===
    event.type;           // 'click' — 事件类型
    event.target;         // 触发事件的元素（最深层的那个）
    event.currentTarget;  // 当前处理器绑定的元素
    event.eventPhase;     // 所处阶段（0=None, 1=Capture, 2=At_Target, 3=Bubble）
    event.timeStamp;      // 事件创建的时间戳（毫秒，相对于页面加载）
    
    // === 流程控制 ===
    event.bubbles;        // 是否支持冒泡
    event.cancelable;     // 是否可以阻止默认行为
    
    // === 方法 ===
    event.stopPropagation();     // 阻止事件继续传播
    event.stopImmediatePropagation();  // 阻止传播 + 阻止同元素上其他处理器
    event.preventDefault();       // 阻止默认行为（如果 cancelable 为 true）
});
```

### 3.2 target vs currentTarget：最常混淆的两个属性

```html
<div id="toolbar" class="toolbar">
    <button class="btn-save">保存</button>
    <button class="btn-cancel">取消</button>
</div>
```

```javascript
document.getElementById('toolbar').addEventListener('click', (e) => {
    console.log('target:', e.target.className);        // 'btn-save'（被点的按钮）
    console.log('currentTarget:', e.currentTarget.id);  // 'toolbar'（绑定监听器的元素）
});

// target = 事件的起源地 —— 用户真正操作的那个元素
// currentTarget = 当前的听众 —— 正在执行这个处理器函数的元素
// 在非委托模式下两者相同；在事件委托模式下两者不同
```

### 3.3 stopPropagation vs stopImmediatePropagation

```javascript
const parent = document.getElementById('parent');

parent.addEventListener('click', (e) => {
    console.log('父元素处理器 1');
});

parent.addEventListener('click', (e) => {
    console.log('父元素处理器 2');
    e.stopImmediatePropagation();  // 父元素上后续的处理器不再执行
    // 但子元素的处理器不受影响（因为还没到子元素）
});

parent.addEventListener('click', (e) => {
    console.log('父元素处理器 3');  // ← 不会执行！
});

// 输出结果：
// 父元素处理器 1
// 父元素处理器 2
// （处理器 3 被跳过）
```

对比两者的区别：

| 行为 | `stopPropagation()` | `stopImmediatePropagation()` |
|------|---------------------|-------------------------------|
| 阻止向父/子元素传播 | ✅ | ✅ |
| 阻止同一元素上的其他处理器 | ❌ | ✅ |
| 典型用途 | 事件委托中的边界控制 | 插件冲突时的强制隔离 |

### 3.4 生活类比：消息传递网络中的两种阻断方式

- **stopPropagation 就像切断了一根电话线**：消息不会再传递给上级或下级，但同一个办公室里的人仍然可以通过其他线路收到消息。
  
- **stopImmediatePropagation 就像直接切断了整个办公室的总电源**：不仅外部消息进不来，连办公室内部的其他通讯设备也全部断电。

## 四、不冒泡的事件及其替代方案

### 4.1 常见的不冒泡事件

有些事件出于语义考虑不会冒泡：

```javascript
// 这些事件不会冒泡：
focus, blur, mouseenter, mouseleave, load, unload, abort, error

// 所以以下写法无效：
document.addEventListener('focus', () => { ... });  // 子元素 focus 时不会触发
```

### 4.2 替代方案：focusin / focusout

对于 `focus` 和 `blur`，有对应的冒泡版本：

```javascript
// focus/blur — 不冒泡
input.addEventListener('focus', handler);
input.addEventListener('blur', handler);

// focusin/focusout — 冒泡！（推荐用于事件委托）
form.addEventListener('focusin', (e) => {
    console.log('某个输入框获得了焦点:', e.target.name);
});

form.addEventListener('focusout', (e) => {
    console.log('某个输入框失去了焦点:', e.target.name);
    // 可以在这里做表单验证
});
```

### 4.3 替代方案：mouseover / mouseout（替代 mouseenter / mouseleave）

```javascript
// mouseenter/mouseleave — 不冒泡（但也不会被子元素触发）
// mouseover/mouseout — 冒泡（但会被子元素触发）

// 如果你需要 mouseenter 的"不被子元素干扰"特性 + 冒泡能力：
element.addEventListener('mouseover', (e) => {
    if (e.target === element) {  // 只在进入自身而非子元素时触发
        console.log('进入了元素区域');
    }
});
```

## 五、自定义事件

### 5.1 创建和派发自定义事件

```javascript
// 创建自定义事件
const myEvent = new CustomEvent('user-login', {
    detail: { userId: 42, username: 'Alarik' },
    bubbles: true,      // 允许冒泡
    cancelable: true    // 允许 preventDefault
});

// 监听自定义事件
document.addEventListener('user-login', (e) => {
    console.log('用户登录了:', e.detail.username);
    console.log('用户 ID:', e.detail.userId);
});

// 派发事件
document.dispatchEvent(myEvent);

// 实际应用：模块间解耦通信
class ShoppingCart {
    constructor() {
        this.items = [];
    }

    addItem(product) {
        this.items.push(product);
        
        // 通知外部（不需要知道谁在监听）
        this.dispatchEvent(new CustomEvent('cart-updated', {
            detail: { cart: this.items, action: 'add', product },
            bubbles: true
        }));
    }
}

// 让 ShoppingCart 具备派发事件的能力
Object.assign(ShoppingCart.prototype, EventTarget.prototype);

// 任意地方都可以监听
document.addEventListener('cart-updated', (e) => {
    updateBadge(e.detail.cart.length);
});
```

### 5.2 生活类比：自定义事件就像公司的内部广播系统

标准事件（click、scroll 等）就像**公共广播**——每个人都知道什么时候会发生、什么含义。

自定义事件就像**部门内部的专用频道**——"库存更新了"、"用户登录了"、"支付完成了"。这些频道只有相关人员（订阅者）才会关注，其他人完全不受影响。这种**发布-订阅（Publish-Subscribe）**模式是大型应用中解耦模块间依赖的核心手段。

## 六、总结：事件模型的心智模型

### 6.1 addEventListener 选项速查表

| 选项 | 类型 | 默认值 | 含义 |
|------|------|--------|------|
| `capture` | boolean | false | 在捕获阶段触发 |
| `once` | boolean | false | 触发一次后自动移除 |
| `passive` | boolean | false | 承诺不调用 preventDefault |
| `signal` | AbortSignal | null | 用于批量取消 |

### 6.2 设计原则

1. **优先使用事件委托**：利用冒泡机制在祖先元素上统一处理子元素的事件。
2. **善用 `once` 代替手动 removeEventListener**：减少内存泄漏风险。
3. **高频滚动/触摸事件务必设置 `passive: true`**：避免滚动性能问题。
4. **组件销毁时用 AbortController 批量清理**：简洁且不易遗漏。
5. **需要跨模块通信时考虑 CustomEvent**：比直接调用方法更松耦合。

> **最后的思考**：DOM 事件模型之所以经久不衰（从 2000 年代的 DOM Level 2 Events 到今天），是因为它蕴含了一种优雅的**关注点分离**思想：事件的**产生者**（用户点击）不知道也不关心谁会**消费**（处理）这个事件；消费者也不知道事件来自哪里，只知道发生了什么。这种"生产者-消费者"之间的彻底解耦，正是构建复杂系统所必需的基础架构。理解了这一点，你就会发现 Vue 的 `$emit`、React 的合成事件系统、Node.js 的 EventEmitter——它们的灵魂都是同一个。关于事件对象各属性的详细分析，推荐阅读[《事件对象》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/45.事件对象.md)。关于事件委托的高级用法和自定义事件，推荐阅读[《事件委托与自定义事件》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/50.事件委托与自定义事件.md)。
