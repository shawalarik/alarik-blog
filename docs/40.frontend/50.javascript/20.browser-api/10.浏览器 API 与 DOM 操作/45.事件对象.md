# 事件对象 —— target vs currentTarget、preventDefault、stopPropagation、stopImmediatePropagation

## 从"知道事件发生"到"理解事件全貌"的信息跃迁

在[《事件模型》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/40.事件模型.md)一文中，我们建立了对事件三阶段生命周期的宏观认知——捕获、目标、冒泡。但当一个事件真正发生时，浏览器交给你的不仅仅是一个信号，而是一个**携带丰富信息的对象**——Event 对象。它包含了事件的来源、位置、按键状态、时间戳等一系列数据，还提供了控制事件后续命运的方法。

本文将深入解剖 Event 对象的每一个属性和方法，特别是那些最容易混淆的概念：target 与 currentTarget 的区别、preventDefault 与 stopPropagation 的本质差异、以及各种事件类型特有的扩展属性。

> **本文的目标**：建立 Event 对象的完整认知地图，通过大量实例阐明每个属性的实际用途，以及在不同事件类型下的行为差异。

---

## 一、Event 对象的核心身份信息

### 1.1 事件的基本身份

每个事件对象首先回答的是"你是谁？"这个问题：

```javascript
element.addEventListener('click', (e) => {
    e.type;              // 'click' — 事件类型名称
    e.bubbles;           // true  — 此事件是否会冒泡
    e.cancelable;        // true  — 此事件是否可以用 preventDefault 取消
    e.composed;          // false — 此事件是否会穿过 Shadow DOM 边界
    e.eventPhase;        // 2     — 当前所处阶段
                         // 0: NONE, 1: CAPTURING_PHASE,
                         // 2: AT_TARGET, 3: BUBBLING_PHASE
    e.timeStamp;         // 1724123456789.123 — 时间戳（高精度浮点数）
    e.isTrusted;         // true  — 是否由用户真实操作触发（非程序派发）
});
```

其中几个值得深挖的属性：

#### isTrusted：真伪辨识

```javascript
button.addEventListener('click', (e) => {
    console.log(e.isTrusted);  // 用户点击 → true；程序 dispatchEvent → false
});

// 真实点击
button.click();  // isTrusted: false（这是程序触发的！）

// 区分真实用户操作和模拟操作在某些安全敏感场景下很重要
// 例如防止自动化脚本刷票、防机器人攻击
button.addEventListener('click', (e) => {
    if (!e.isTrusted) {
        console.warn('检测到非用户操作');
        return;  // 忽略程序化触发
    }
    // 只处理真实的用户点击...
});
```

#### timeStamp：高精度计时

```javascript
let startTime;

element.addEventListener('mousedown', (e) => {
    startTime = e.timeStamp;
    performance.mark('interaction-start');
});

element.addEventListener('mouseup', (e) => {
    const duration = e.timeStamp - startTime;
    console.log(`按压时长: ${duration.toFixed(0)}ms`);
    
    if (duration > 500 && duration < 2000) {
        // 可能是长按操作
        triggerLongPressAction(element);
    }
});
```

### 1.2 生活类比：事件对象就像一份完整的快递包裹

当快递员送来一个包裹（Event 对象）时，你可以从中获取丰富的信息：

- **type 就像包裹的类型标签**：这是一份文件（click）、一封紧急信件（error）、还是一个大件货物（scroll）。
  
- **timeStamp 就像邮戳时间**：告诉你这份包裹是什么时候发出的。如果你收到了两份包裹，可以通过邮戳确定先后顺序。
  
- **isTrusted 就像防伪标识**：告诉你这份包裹是从正规渠道寄来的，还是有人伪造的。
  
- **bubbles/cancelable 就像包裹的处理说明**："此件可转发他人"（bubbles）、"收件人有权拒收"（cancelable）。

## 二、target 与 currentTarget：最关键的区分

### 2.1 定义差异

这是 Event 对象中最重要也最容易被混淆的两个属性：

```html
<nav id="main-nav">
    <ul class="nav-list">
        <li><a href="/home">首页</a></li>
        <li><a href="/about">关于</a></li>
        <li><a href="/contact">联系</a></li>
    </ul>
</nav>
```

```javascript
document.getElementById('main-nav').addEventListener('click', (e) => {
    // target：事件的起源 —— 用户实际点击的最深层元素
    console.log(e.target);         // <a href="/home">首页</a>（假设点了这个链接）
    
    // currentTarget：当前的监听者 —— 绑定了当前处理器的元素
    console.log(e.currentTarget);  // <nav id="main-nav">
    
    // 在非委托模式下（处理器直接绑在目标元素上），两者相等
    document.querySelector('a').addEventListener('click', (e) => {
        console.log(e.target === e.currentTarget);  // true（同一个 <a> 元素）
    });
});
```

### 2.2 用图示理解

```
用户点击了 <a> 链接：

    <nav> ← currentTarget（监听器绑定在这里）
      <ul>
        <li>
          <a> ← target（用户实际点击的地方）</a>
        </li>
      </ul>
    </nav>

事件从 <a> 开始，冒泡到 <nav>
当事件到达 <nav> 时：
  - target 始终指向 <a>（事件的源头不变）
  - currentTarget 指向 <nav>（当前正在执行的处理器所属元素）
```

### 2.3 实战：利用 target 实现精确的事件委托

```javascript
/**
 * 表格行点击的高亮效果
 * 利用 target 精确识别被点击的单元格
 */
document.querySelector('.data-table').addEventListener('click', (e) => {
    const row = e.target.closest('tr');  // 从 target 向上找最近的 tr
    if (!row) return;
    
    // 高亮选中的行
    document.querySelectorAll('.data-table .selected')
        .forEach(r => r.classList.remove('selected'));
    row.classList.add('selected');
    
    // 获取行数据
    const rowData = JSON.parse(row.dataset.row);
    console.log('选中了:', rowData);
});
```

### 2.4 life analogy: 报告人和接收人

- **target 是报告人（Whistleblower）**：那个亲眼目睹事件发生的人——"是我看到了有人按下了按钮"。无论报告层层上报到哪里，报告人的身份不会改变。
  
- **currentTarget 是接收人（Recipient）**：当前正在审阅这份报告的人。报告可能经过了多个层级，每个层级都有自己的接收人，他们看的是同一份报告（同一个 target），但他们各自的身份（currentTarget）不同。

> **哲学思考**：target 与 currentTarget 的分离体现了**信息源与处理者的解耦**。在一个分布式系统中，消息的发送者和接收者往往是不同的实体。事件对象同时携带这两个信息，使得每个层级的处理器既能知道"事情从哪里来的"（target），又能知道自己"现在在哪里"（currentTarget）。这种双向感知能力是构建多层中间件架构的基础。

## 三、preventDefault：取消默认行为

### 3.1 什么是"默认行为"？

很多事件都关联着浏览器的**默认行为（Default Action）**——即浏览器在没有 JavaScript 干预时会做的事情：

| 事件类型 | 默认行为 |
|---------|---------|
| `<a>` 的 click | 导航到 href 指定的 URL |
| `<form>` 的 submit | 将表单数据发送到服务器 |
| `<input>` 的 keydown | 在输入框中显示按下的字符 |
| 右键 contextmenu | 弹出浏览器上下文菜单 |
| 鼠标滚轮 wheel | 页面滚动 |
| 触摸 touchstart | 可能触发滚动 |
| 拖放 dragover | 显示拖放光标 |

`preventDefault()` 就是告诉浏览器：**不要执行这些默认行为**。

### 3.2 基本用法

```javascript
// 1. 阻止链接跳转（SPA 路由的核心技术）
document.querySelectorAll('a[href^="/"]').forEach(link => {
    link.addEventListener('click', (e) => {
        e.preventDefault();  // 不跳转
        const path = link.getAttribute('href');
        router.navigate(path);  // 用 JS 自己处理导航
    });
});

// 2. 阻止表单提交（前端验证后再决定是否提交）
form.addEventListener('submit', (e) => {
    if (!validateForm(form)) {
        e.preventDefault();  // 验证不通过，不提交
        showErrors(getValidationErrors(form));
    }
});

// 3. 阻止右键菜单（自定义右键菜单的前提）
element.addEventListener('contextmenu', (e) => {
    e.preventDefault();
    showCustomContextMenu(e.clientX, e.clientY);
});

// 4. 阻止特定按键的默认行为
searchInput.addEventListener('keydown', (e) => {
    if (e.key === 'Enter') {
        e.preventDefault();  // 阻止可能的表单提交
        performSearch(searchInput.value);
    }
});
```

### 3.3 cancelable 与 defaultPrevented

```javascript
element.addEventListener('click', (e) => {
    if (e.cancelable) {
        e.preventDefault();  // 安全调用
    } else {
        console.warn('此事件不可取消');
    }
    
    // 检查是否已经被取消过
    if (e.defaultPrevented) {
        console.log('默认行为已被之前的处理器取消了');
        return;  // 避免重复处理
    }
});
```

### 3.4 return false 与 preventDefault 的区别

这是一个经典的面试题：

```javascript
// 在 DOM0 级别的事件处理方式中（HTML 属性或 onXXX 属性）
element.onclick = function(e) {
    return false;  // 同时阻止了默认行为 AND 阻止冒泡
};

// 但在 addEventListener 中：
element.addEventListener('click', (e) => {
    return false;  // ❌ 没有任何效果！return 值被忽略
    e.preventDefault();    // ✅ 只阻止默认行为
    e.stopPropagation();   // 还需额外调用来阻止冒泡
});
```

### 3.5 生活类比：preventDefault 就像说"不用谢，我自己来"

想象你去餐厅吃饭：

- **默认行为**：服务员把菜端上来后，厨师的工作就结束了——菜被吃掉、盘子被收走。这就是"默认流程"。
  
- **preventDefault** 就像你对服务员说："这盘菜我先不动，我自己来处理它。"也许你要先拍照，也许你要把它打包带走。你阻止了"吃掉这道菜"这个默认行为。

> **注意**：preventDefault **不会阻止事件传播**。即使你阻止了默认行为，事件仍然会继续冒泡（或捕获）。这只是说"不要执行默认动作"，不是说"这件事没有发生过"。

## 四、stopPropagation：截断传播路径

### 4.1 基本用法

```javascript
// 阻止事件继续向外冒泡（或在捕获阶段继续向下）
childElement.addEventListener('click', (e) => {
    e.stopPropagation();  // 到此为止，不再传播
    
    // 父元素上的 click 监听器不会被触发
});
```

### 4.2 stopImmediatePropagation：更强的阻断

```javascript
element.addEventListener('click', (e) => {
    console.log('处理器 1');
    e.stopImmediatePropagation();  // 连同级后续处理器也一并阻断
});

element.addEventListener('click', (e) => {
    console.log('处理器 2');  // ← 永远不会执行
});

element.addEventListener('click', (e) => {
    console.log('处理器 3');  // ← 永远不会执行
});
```

### 4.3 三种"停止"方式的对比

```javascript
element.addEventListener('click', (e) => {
    e.preventDefault();               // 阻止默认行为（链接不跳转、表单不提交）
    // 事件继续传播 ✅
});

element.addEventListener('click', (e) => {
    e.stopPropagation();             // 阻止传播到父/子元素
    // 默认行为仍然执行 ✅（如果没被 preventDefault）
});

element.addEventListener('click', (e) => {
    e.stopImmediatePropagation();    // 阻止传播 + 阻止同元素后续处理器
    // 最强的阻断力度
});
```

### 4.4 生活类比对比

| 方法 | 类比 |
|------|------|
| `preventDefault` | 你说"这道菜我不吃了"，但餐厅照常营业，其他客人照常用餐 |
| `stopPropagation` | 你拉下了防火帘——火灾不会蔓延到隔壁楼层，但你所在的房间内一切照旧 |
| `stopImmediatePropagation` | 你不仅拉下了防火帘，还喊了一声"所有人原地待命"——房间里所有人停止行动 |

## 五、各类事件的对象扩展属性

不同的 Event 类型会在基础 Event 对象上扩展额外的属性。以下是几类最重要的事件类型：

### 5.1 MouseEvent（鼠标事件）

```javascript
element.addEventListener('click', (e) => {
    // === 坐标信息 ===
    e.clientX / e.clientY;     // 相对于视口的坐标
    e.pageX / e.pageY;         // 相对于整个文档的坐标（含滚动偏移）
    e.screenX / e.screenY;     // 相对于屏幕的坐标
    e.offsetX / e.offsetY;     // 相对于目标元素 padding box 左上角的坐标
    e.movementX / e.movementY; // 相于上次 mousemove 事件的位移（可用于计算速度）

    // === 按键状态（触发时刻哪些修饰键被按下）===
    e.altKey;                  // Alt 键
    e.ctrlKey;                 // Ctrl 键
    e.shiftKey;                // Shift 键
    e.metaKey;                 // Mac 上的 Command 键 / Windows 上的 Win 键

    // === 按钮信息 ===
    e.button;                  // 0=左键, 1=中键(滚轮), 2=右键
    e.buttons;                 // 位掩码：1=左键按下, 2=右键按下, 4=中键按下

    // === 实战：区分单击与拖拽的开始 ===
});
```

### 5.2 KeyboardEvent（键盘事件）

```javascript
inputElement.addEventListener('keydown', (e) => {
    // === 按键标识 ===
    e.key;         // 'a', 'Enter', 'ArrowUp', 'F1' ... （按键的逻辑值）
    e.code;        // 'KeyA', 'Enter', 'ArrowUp', 'F1' ... （物理位置的值）
    e.keyCode;     // 数字编码（已废弃，不建议使用）
    e.which;       // 数字编码（已废弃，jQuery 遗留）

    // key vs code 的关键区别：
    // 按 Shift+a:
    //   e.key = 'A'（大写 A，表示输出的字符）
    //   e.code = 'KeyA'（不管大小写，始终是 KeyA）
    
    // 按 Dvorak 键盘布局的同一个物理键：
    //   e.key 可能变化（取决于键盘布局映射到的字符）
    //   e.code 始终是 'KeyA'（物理位置不变）

    // === 修饰键 ===
    e.ctrlKey; e.altKey; e.shiftKey; e.metaKey;
    
    // 是否处于"重复"状态（按住不放连续触发）
    e.repeat;      // true 表示这次 keydown 是长按产生的重复事件

    // === 实战：快捷键系统 ===
});
```

### 5.3 InputEvent（输入事件）

```javascript
inputElement.addEventListener('input', (e) => {
    e.data;            // 本次输入插入的数据（字符串），删除时为 null
    e.inputType;       // 输入类型：'insertText', 'deleteContentBackward',
                        // 'formatBold', 'historyUndo' ...
    e.isComposing;     // 是否正在使用输入法组合（IME 编辑中）

    // IME（输入法）的特殊处理
    if (e.isComposing) return;  // 输入法编辑期间跳过处理
});

// inputType 的常见值：
// 'insertText'          — 普通文字输入
// 'insertLineBreak'     — Enter 键
// 'deleteContentBackward' — Backspace
// 'deleteContentForward'  — Delete
// 'historyUndo' / 'historyRedo'
// 'formatBold' / 'formatItalic' / 'formatUnderline' — 富文本编辑
```

### 5.4 TouchEvent（触摸事件）

```javascript
element.addEventListener('touchstart', (e) => {
    // touches：当前屏幕上所有触摸点的列表
    e.touches[0].clientX;   // 第一个手指的位置
    e.touches[0].clientY;
    e.touches.length;       // 手指数量
    
    // changedTouches：本次事件涉及的触摸点
    e.changedTouches;
    
    // targetTouches：绑定在该元素上的触摸点
    e.targetTouches;
    
    // 注意：touch 事件默认的 preventDefault 会阻止页面滚动
    // 所以建议设置 passive: true（除非你需要阻止滚动）
}, { passive: true });
```

### 5.5 WheelEvent（滚轮事件）

```javascript
container.addEventListener('wheel', (e) => {
    // 滚动量（像素单位，因浏览器和设备而异）
    e.deltaX;    // 水平方向滚动量
    e.deltaY;    // 垂直方向滚动量
    e.deltaZ;    // Z轴方向滚动量（极少用到）
    
    // 滚动模式
    e.deltaMode; // 0=pixel, 1=line, 2=page
    
    // 实现横向滚动容器
    if (Math.abs(e.deltaY) > Math.abs(e.deltaX)) {
        container.scrollLeft += e.deltaY;
        e.preventDefault();  // 需要在非 passive 下调用
    }
}, { passive: false });  // 需要能 preventDefault
```

### 5.6 PointerEvent（统一指针事件）

Pointer Event API 统一了鼠标、触摸、手写笔等多种输入设备：

```javascript
element.addEventListener('pointerdown', (e) => {
    e.pointerId;       // 唯一的指针标识符
    e.pointerType;     // 'mouse' | 'pen' | 'touch'
    e.width;           // 接触区域的宽度
    e.height;          // 接触区域的高度
    e.pressure;        // 压力值（0~1，笔设备有效）
    e.tangentialPressure;  // 切向压力
    e.tiltX;           // X轴倾斜角度（笔设备）
    e.tiltY;           // Y轴倾斜角度
    e.twist;           // 笔的旋转角度
    
    // 区分输入类型
    switch (e.pointerType) {
        case 'mouse': handleMouseInput(e); break;
        case 'touch': handleTouchInput(e); break;
        case 'pen':    handlePenInput(e); break;
    }
});
```

## 六、实战：构建一个完整的事件处理工具库

```javascript
/**
 * EventUtils — 事件处理实用工具集
 */
const EventUtils = {
    /**
     * 创建一次性的事件监听（Promise 版本）
     */
    waitFor(element, eventType, options = {}) {
        return new Promise(resolve => {
            element.addEventListener(eventType, resolve, { once: true, ...options });
        });
    },

    // 使用：等待图片加载完毕
    async loadImage(src) {
        const img = new Image();
        img.src = src;
        await this.waitFor(img, 'load');
        return img;
    },

    /**
     * 防抖（Debounce）：频繁触发只执行最后一次
     */
    debounce(fn, delay = 300) {
        let timer = null;
        return function(...args) {
            clearTimeout(timer);
            timer = setTimeout(() => fn.apply(this, args), delay);
        };
    },

    /**
     * 节流（Throttle）：固定间隔执行一次
     */
    throttle(fn, interval = 100) {
        let lastTime = 0;
        return function(...args) {
            const now = Date.now();
            if (now - lastTime >= interval) {
                lastTime = now;
                fn.apply(this, args);
            }
        };
    },

    /**
     * 检测是否是真正的点击（排除拖拽）
     */
    createTapDetector(threshold = 10, maxDuration = 500) {
        let startX, startY, startTime;

        return {
            onDown(e) {
                startX = e.clientX;
                startY = e.clientY;
                startTime = Date.now();
            },
            onUp(e, callback) {
                const dx = Math.abs(e.clientX - startX);
                const dy = Math.abs(e.clientY - startY);
                const dt = Date.now() - startTime;

                if (dx < threshold && dy < threshold && dt < maxDuration) {
                    callback(e);
                }
            }
        };
    },

    /**
     * 快捷键注册器
     */
    registerShortcut(keyCombo, handler, scope = document) {
        const parseCombo = (combo) => ({
            ctrl: combo.includes('Ctrl+'),
            alt: combo.includes('Alt+'),
            shift: combo.includes('Shift+'),
            key: combo.split('+').pop().toLowerCase()
        });

        const { ctrl, alt, shift, key } = parseCombo(keyCombo);

        scope.addEventListener('keydown', (e) => {
            if (e.key.toLowerCase() === key &&
                e.ctrlKey === ctrl &&
                e.altKey === alt &&
                e.shiftKey === shift) {
                e.preventDefault();
                handler(e);
            }
        });
    }
};

// 使用示例
// 防抖搜索
searchInput.addEventListener('input', EventUtils.debounce((e) => {
    performSearch(e.target.value);
}, 400));

// 节流滚动
window.addEventListener('scroll', EventUtils.throttle((e) => {
    updateScrollProgress();
}, 16));  // ~60fps

// 快捷键
EventUtils.registerShortcut('Ctrl+s', () => saveDocument());
EventUtils.registerShortcut('Ctrl+Shift+P', () => openCommandPalette());
```

## 七、总结：Event 对象的心智模型

### 7.1 核心概念对照表

| 概念 | 作用 | 影响 |
|------|------|------|
| `target` | 事件的起源元素 | 不变（永远是触发源） |
| `currentTarget` | 当前处理器所在元素 | 随事件传播变化 |
| `preventDefault()` | 取消浏览器的默认行为 | 不影响传播 |
| `stopPropagation()` | 截断事件传播链 | 不影响默认行为 |
| `stopImmediatePropagation()` | 最强阻断 | 影响一切后续处理 |
| `isTrusted` | 判定是否用户真实操作 | 安全校验依据 |

### 7.2 设计原则

1. **target 定位来源，currentTarget 定位自身**：事件委托中靠前者找目标，处理器逻辑中靠后者定位自己。
2. **preventDefault 管理默认行为，stopPropagation 管理传播范围**：两者正交，互不影响。
3. **优先使用 PointerEvent 统一处理多种输入设备**：减少代码分支。
4. **IME 组合状态必须检查**：`isComposing` 避免输入法编辑期间的错误处理。
5. **高频事件务必节流/防抖**：scroll、mousemove、resize 等事件的处理器需要限流。

> **最后的思考**：Event 对象是连接"用户的物理世界"和"程序的逻辑世界"的信息桥梁。每一次点击、每一次按键、每一次滑动，都被封装成一个结构化的数据包传递给你的代码。理解这个数据包的每一个字段，就是在理解用户行为的数字化表达。优秀的交互体验来自于对这些信息的精准解读——不是简单地"检测到点击"，而是知道"在哪里点击的"、"用什么设备点的"、"按住了多长时间"、"移动了多少距离"。这些细节的差异决定了产品体验的天壤之别。关于事件委托的高级模式和自定义事件的详细用法，推荐阅读[《事件委托与自定义事件》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/50.事件委托与自定义事件.md)。
