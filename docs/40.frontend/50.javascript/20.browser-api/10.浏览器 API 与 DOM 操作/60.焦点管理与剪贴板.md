# 焦点管理 + 剪贴板 —— focus、blur、tabindex、navigator.clipboard

## 从"被动等待"到"主动引导"的交互跃迁

在[《事件委托与自定义事件》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/50.事件委托与自定义事件.md)一文中，我们探讨了如何高效地处理用户发起的事件。但有些时候，应用需要**主动引导**用户的注意力——当模态框弹出时将焦点锁定在其中、当表单验证失败时光标跳转到出错的输入框、当用户点击"复制"按钮时将文本写入系统剪贴板。这就是**焦点管理（Focus Management）**和**剪贴板 API（Clipboard API）**的领域。

焦点管理不仅是用户体验的关键要素，更是**无障碍访问（Accessibility）** 的基础。屏幕阅读器依赖焦点来告知视障用户当前可操作的元素在哪里。剪贴板操作则是现代 Web 应用提升效率的标准工具——从一键复制分享链接到粘贴富文本内容。

> **本文的目标**：全面讲解 focus/blur 的机制与 tabindex 的规则，深入 Clipboard API 的异步操作模式，并结合无障碍最佳实践构建完整的认知体系。

## 一、焦点的基础概念

### 1.1 什么是焦点？

在任何时刻，整个文档中**最多只有一个元素拥有焦点**（focus）。这个元素就是当前接收键盘输入的目标：

```javascript
// 查看当前拥有焦点的元素
document.activeElement;  // 当前焦点元素
// 如果没有元素获得焦点，返回 <body>

// 判断某个元素是否拥有焦点
document.activeElement === myInput;  // true/false
```

焦点的存在是因为大多数设备只有一个键盘和一个鼠标——操作系统需要知道"用户当前的输入应该发给哪个窗口/哪个元素"。Web 页面作为操作系统的一个"子世界"，同样遵循这一约束。

### 1.2 focus 与 blur 事件

```javascript
const input = document.getElementById('search');

// 获得焦点时触发
input.addEventListener('focus', (e) => {
    console.log('输入框获得了焦点');
    input.parentElement.classList.add('focused');
});

// 失去焦点时触发
input.addEventListener('blur', (e) => {
    console.log('输入框失去了焦点');
    input.parentElement.classList.remove('focused');
    // blur 事件常用于表单验证
    validateField(input);
});
```

**重要区别：focus/blur 不会冒泡！**

```javascript
// ❌ 这段代码不会工作（因为 focus 不冒泡）
form.addEventListener('focus', (e) => {
    console.log(`表单内的 ${e.target.name} 获得了焦点`);
});  // 永远不会触发！

// ✅ 使用 focusin/focusout（它们会冒泡）
form.addEventListener('focusin', (e) => {
    console.log(`${e.target.name || e.target.tagName} 获得了焦点`);
});

form.addEventListener('focusout', (e) => {
    console.log(`${e.target.name || e.target.tagName} 失去了焦点`);
    // 适合做失焦验证
    if (e.target.matches('input')) {
        validateOnBlur(e.target);
    }
});
```

### 1.3 生活类比：焦点就像聚光灯下的舞台

想象一个剧院的舞台：

- **任何时候只有一束聚光灯**照亮一个演员（焦点元素）。观众的眼睛（键盘输入）只会关注被照亮的那个人。
  
- **focus 事件就像灯光师把灯转向某位演员**："现在轮到你表演了。"这位演员开始接收观众的反应（键盘输入）。
  
- **blur 事件就像灯光移开**："你的戏份结束了。"演员不再接收观众输入。
  
- **focusin/focusout 就像广播通知**：灯光切换时会通过全场广播通知所有人"谁上场了""谁下台了"。这就是为什么它能冒泡——消息传到了每个人耳中。

> **哲学思考**：焦点的单一性体现了计算机系统中一种根本性的资源约束——**注意力是稀缺的**。人类的大脑一次只能深度处理一件事情；操作系统一次只能将键盘输入发送给一个进程；Web 页面一次只能有一个焦点元素。这种约束并非缺陷而是特性——它提供了确定性。如果没有焦点的概念，当你按下 Enter 键时，浏览器根本不知道应该触发哪个按钮的点击。焦点的存在让混乱的并行可能性坍缩为有序的串行执行。

## 二、tabindex：控制焦点的可达性

### 2.1 默认的焦点顺序

默认情况下，以下元素可以通过 Tab 键获得焦点（称为"可聚焦元素"）：

- `<a href="...">`
- `<button>`
- `<input>`、`<select>`、`<textarea>`
- `<details>`、`<summary>`
- `contenteditable` 为 true 的元素
- 具有 `tabindex` 属性的任意元素

浏览器按照**文档源码中的顺序**来决定 Tab 导航的顺序：

```html
<form>
    <input name="first" placeholder="1. 第一个">
    <input name="second" placeholder="2. 第二个">
    <input name="third" placeholder="3. 第三个">
    <button type="submit">提交</button>
</form>
<!-- Tab 顺序: first → second → third → 提交 -->
```

### 2.2 tabindex 属性详解

`tabindex` 可以修改元素的焦点行为，它有三个关键值域：

```html
<!-- tabindex="-1"：可以通过编程获得焦点，但不在 Tab 序列中 -->
<div tabindex="-1" role="dialog" id="modal">...</div>

<!-- tabindex="0"：可以通过 Tab 获得焦点（按文档顺序排列）-->
<div class="custom-button" tabindex="0" role="button">自定义按钮</div>

<!-- tabindex="1" 及以上：显式指定 Tab 顺序（强烈不推荐！）-->
<input name="a" tabindex="3">
<input name="b" tabindex="1">
<input name="c" tabindex="2">
<!-- Tab 顺序变成: b → c → a（按 tabindex 数值排序，而非文档顺序）-->
```

**为什么不应该使用正数 tabindex？**

1. **破坏语义化顺序**：Tab 顺序变得与视觉顺序不一致，让键盘用户困惑。
2. **维护噩梦**：每次新增可聚焦元素都需要重新编号。
3. **违反可访问性规范**：WCAG 要求焦点顺序应保持逻辑性和可预测性。

### 2.3 编程方式控制焦点

```javascript
const input = document.getElementById('username');

// 让元素获得焦点
input.focus();

// 带选项的 focus
input.focus({
    preventScroll: false  // 是否滚动到可见区域（默认 false = 会滚动）
});

// 移除焦点
input.blur();

// === 实际应用场景 ===

// 场景 1：页面加载后聚焦到搜索框
window.addEventListener('load', () => {
    const searchInput = document.getElementById('global-search');
    if (searchInput) searchInput.focus();
});

// 场景 2：表单验证后聚焦到第一个错误字段
function validateAndFocus(form) {
    const fields = form.querySelectorAll('[required]');
    for (const field of fields) {
        if (!field.value.trim()) {
            field.focus();
            field.classList.add('error');
            return false;
        }
    }
    return true;
}

// 场景 3：模态框打开时的焦点陷阱
class ModalFocusTrap {
    constructor(modalEl) {
        this.modal = modalEl;
        this.focusableSelectors = [
            'a[href]', 'button:not([disabled])',
            'input:not([disabled])', 'select:not([disabled])',
            'textarea:not([disabled])', '[tabindex]:not([tabindex="-1"])'
        ];
        this._bindEvents();
    }

    get focusableElements() {
        return Array.from(this.modal.querySelectorAll(this.focusableSelectors.join(', ')))
            .filter(el => el.offsetParent !== null || el.offsetWidth > 0);  // 过滤不可见元素
    }

    _bindEvents() {
        this.modal.addEventListener('keydown', (e) => {
            if (e.key === 'Tab') {
                this._trapFocus(e);
            } else if (e.key === 'Escape') {
                this.close();
            }
        });
    }

    _trapFocus(e) {
        const focusable = this.focusableElements;
        if (focusable.length === 0) return;

        const first = focusable[0];
        const last = focusable[focusable.length - 1];

        if (e.shiftKey) {
            // Shift+Tab：反向循环
            if (document.activeElement === first) {
                e.preventDefault();
                last.focus();
            }
        } else {
            // Tab：正向循环
            if (document.activeElement === last) {
                e.preventDefault();
                first.focus();
            }
        }
    }

    open() {
        this.modal.classList.add('visible');
        this.previousActiveElement = document.activeElement;
        // 聚焦到模态框内第一个可聚焦元素
        const focusable = this.focusableElements;
        if (focusable.length > 0) {
            focusable[0].focus();
        } else {
            this.modal.setAttribute('tabindex', '-1');
            this.modal.focus();
        }
    }

    close() {
        this.modal.classList.remove('visible');
        // 恢复之前的焦点
        this.previousActiveElement?.focus();
    }
}
```

焦点陷阱（Focus Trap）是无障碍模态框的核心组件——确保键盘用户在 Tab 循环时不会意外地跳出对话框去操作背后的内容。

## 三、Clipboard API：现代剪贴板操作

### 3.1 从 document.execCommand 到 navigator.clipboard

历史上，复制文本到剪贴板使用的是 `document.execCommand('copy')`：

```javascript
// 旧方式（已废弃，但在某些简单场景仍可用）
function oldCopy(text) {
    const textarea = document.createElement('textarea');
    textarea.value = text;
    textarea.style.position = 'fixed';
    textarea.style.opacity = '0';
    document.body.appendChild(textarea);
    textarea.select();
    document.execCommand('copy');
    document.body.removeChild(textarea);
}
```

这种做法极其笨拙：需要创建一个临时元素、选中内容、调用命令、再清理掉临时元素。而且 `execCommand` 只能用于 `document` 内的内容，无法处理纯数据。

现代的 **Clipboard API** 提供了干净、异步、强大的替代方案：

```javascript
// === 写入剪贴板 ===

// 复制纯文本
await navigator.clipboard.writeText('要复制的文本');

// 复制富文本（HTML）
const htmlContent = '<b>加粗</b>和<i>斜体</i>';
const blob = new Blob([htmlContent], { type: 'text/html' });
await navigator.clipboard.write([
    new ClipboardItem({ 'text/html': blob })
]);

// === 读取剪贴板 ===

try {
    const text = await navigator.clipboard.readText();
    console.log('剪贴板内容:', text);
} catch (err) {
    // 可能被用户拒绝了权限
    console.warn('无法读取剪贴板:', err);
}

// 读取多种格式
try {
    const items = await navigator.clipboard.read();
    for (const item of items.types) {
        if (item === 'text/html') {
            const blob = await items.getType('text/html');
            const html = await blob.text();
            console.log('HTML 内容:', html);
        }
    }
} catch (err) {
    console.warn('权限不足或剪贴板为空:', err);
}
```

### 3.2 权限模型

Clipboard API 受到**权限策略（Permissions Policy）**的保护：

```javascript
// 检查是否有剪贴板写入权限
const writePermission = await navigator.permissions.query({
    name: 'clipboard-write'
});
console.log(writePermission.state);  // 'granted' | 'denied' | 'prompt'

// 读取权限更严格（通常需要用户主动授权）
const readPermission = await navigator.permissions.query({
    name: 'clipboard-read'
});
console.log(readPermission.state);   // 大多数情况下是 'prompt'
```

**重要限制**：`clipboard.writeText()` 通常只在以下上下文中允许：
- 用户点击事件处理器中（如"复制"按钮的 click 回调）
- 已获授予权限的页面上

在后台脚本或非用户手势触发的上下文中调用会失败。

### 3.3 实战：一键复制组件

```javascript
/**
 * CopyButton — 一键复制按钮组件
 */
class CopyButton {
    constructor(triggerSelector, options = {}) {
        this.trigger = document.querySelector(triggerSelector);
        this.targetSelector = options.target;
        this.text = options.text;  // 直接指定要复制的文本
        this.copyTimeout = options.feedbackDuration || 2000;
        this.originalContent = this.trigger.innerHTML;
        
        this._bindEvents();
    }

    _getText() {
        if (this.text) return this.text;
        
        // 从目标元素获取文本
        const target = document.querySelector(this.targetSelector);
        if (target) {
            return target.value ?? target.textContent ?? target.innerText;
        }
        
        // 从 data 属性获取
        return this.trigger.dataset.copyText || '';
    }

    async _copy() {
        const text = this._getText();
        if (!text) return false;

        try {
            await navigator.clipboard.writeText(text);
            this._showFeedback(true);
            return true;
        } catch (err) {
            console.error('复制失败:', err);
            // Fallback 到旧方案
            return this._fallbackCopy(text);
        }
    }

    _fallbackCopy(text) {
        try {
            const textarea = document.createElement('textarea');
            textarea.value = text;
            textarea.style.cssText = 'position:fixed;left:-9999px';
            document.body.appendChild(textarea);
            textarea.select();
            const success = document.execCommand('copy');
            document.body.removeChild(textarea);
            if (success) this._showFeedback(true);
            return success;
        } catch (e) {
            this._showFeedback(false);
            return false;
        }
    }

    _showFeedback(success) {
        this.trigger.classList.toggle('success', success);
        this.trigger.classList.toggle('error', !success);
        this.trigger.innerHTML = success ? '✓ 已复制!' : '✗ 失败';
        this.trigger.disabled = true;

        setTimeout(() => {
            this.trigger.innerHTML = this.originalContent;
            this.trigger.classList.remove('success', 'error');
            this.trigger.disabled = false;
        }, this.copyTimeout);
    }

    _bindEvents() {
        this.trigger.addEventListener('click', () => {
            this._copy();
        });
    }
}

// 使用
// <button id="copy-btn" data-copy-target="#code-block">复制代码</button>
// <pre id="code-block">const x = 42;</pre>
new CopyButton('#copy-btn', { target: '#code-block' });
```

### 3.4 生活类比：剪贴板就像万能便签纸

- **writeText 就像你在一张便签纸上写字**：写完后把便签贴到公告板上。任何人都可以走过来撕下来看（paste）。
  
- **readText 就像你去公告板上撕下一张便签来读**：但因为隐私原因，你不能随便去撕——你需要得到管理员（用户）的许可。
  
- **旧版 execCommand 就像用铅笔在手掌心里写东西**——你得先把手伸出来（创建 textarea），然后握笔写字（select），然后让别人抄走你的掌纹（copy），最后洗手（removeChild）。整个过程既别扭又容易留下痕迹（DOM 残留）。

## 四、Selection API：文本选区管理

### 4.1 基本操作

```javascript
const input = document.getElementById('my-input');

// 获取当前选区的起止位置
input.selectionStart;   // 光标/选区起始索引
input.selectionEnd;     // 选区结束索引
input.selectionDirection;  // 'forward' | 'backward' | 'none'

// 设置选区（高亮指定范围的文字）
input.setSelectionRange(3, 8);     // 选中第 3~7 个字符
input.setSelectionRange(0, 0);     // 光标放到开头（不选中任何内容）
input.setSelectionRange(-1);       // 光标放到末尾

// 选中全部内容
input.select();  // 等价于 setSelectionRange(0, input.value.length)

// 获取选中的文本
input.value.substring(input.selectionStart, input.selectionEnd);
// 或者用 Selection API（适用于任意可编辑元素）
window.getSelection().toString();
```

### 4.2 实战：智能输入增强

```javascript
/**
 * 智能输入框：自动补全括号、引号配对
 */
class SmartInput {
    constructor(element) {
        this.el = element;
        this.pairs = {
            '(': ')', '[': ']', '{': '}', '"': '"', "'": "'", '`': '`'
        };
        this._bindEvents();
    }

    _bindEvents() {
        this.el.addEventListener('keydown', (e) => {
            const { key, selectionStart, selectionEnd } = this.el;

            // 输入左半边配对符号时，自动插入右半边
            if (this.pairs[key] && !this._isSelected()) {
                e.preventDefault();
                const pair = this.pairs[key];
                this.insertAroundCursor(key, pair);
            }

            // 退格删除配对符号
            if (key === 'Backspace') {
                const before = this.el.value[selectionStart - 1] || '';
                const after = this.el.value[selectionStart] || '';
                if (this.pairs[before] && after === this.pairs[before]) {
                    e.preventDefault();
                    this._deleteRange(selectionStart - 1, selectionStart + 1);
                }
            }
        });
    }

    _isSelected() {
        return this.el.selectionStart !== this.el.selectionEnd;
    }

    insertAroundCursor(left, right) {
        const start = this.el.selectionStart;
        const end = this.el.selectionEnd;
        const val = this.el.value;
        
        this.el.value = val.slice(0, start) + left + right + val.slice(end);
        this.el.setSelectionRange(start + 1, start + 1);  // 光标放中间
        this.el.focus();
        
        // 触发 input 事件以便 React/Vue 等框架同步状态
        this.el.dispatchEvent(new Event('input', { bubbles: true }));
    }

    _deleteRange(start, end) {
        this.el.value = this.el.value.slice(0, start) + this.el.value.slice(end);
        this.el.setSelectionRange(start, start);
        this.el.focus();
        this.el.dispatchEvent(new Event('input', { bubbles: true }));
    }
}
```

## 五、总结：焦点管理与剪贴板的心智模型

### 5.1 核心概念速查

| 概念 | 方法/属性 | 关键点 |
|------|----------|--------|
| 当前焦点元素 | `document.activeElement` | 全局唯一 |
| 焦点事件 | `focusin`/`focusout`（冒泡）/`focus`/`blur`（不冒泡） | 优先用冒泡版本 |
| 编程聚焦 | `el.focus(options)` | 支持防止滚动选项 |
| 焦点陷阱 | Tab 键循环 + Escape 退出 | 无障碍必需 |
| 复制文本 | `navigator.clipboard.writeText()` | 需要 user gesture 权限 |
| 读取剪贴板 | `navigator.clipboard.readText()` | 需要用户授权 |
| 文本选区 | `setSelectionRange(start, end)` | 适用于 input/textarea |
| 全局选区 | `window.getSelection()` | 适用于任意元素 |

### 5.2 设计原则

1. **永远实现焦点陷阱**：模态框、弹窗必须阻止 Tab 键逃逸。
2. **焦点恢复**：关闭浮层后，将焦点回到之前的位置。
3. **focusin/focusout 优于 focus/blur**：支持事件委托。
4. **Clipboard API 优先于 execCommand**：更简洁、更强大、更符合安全模型。
5. **始终处理权限拒绝的情况**：剪贴板操作可能因权限问题失败。

> **最后的思考**：焦点管理的本质是对**用户注意力流**的尊重和引导。一个好的 Web 应用像一个周到的向导——它知道用户此刻应该关注哪里，并在恰当的时候把"聚光灯"移到那里。这种能力不仅仅是技术实现，更是产品设计思维的体现：每一次焦点的转移都应该有明确的意图——要么是用户主动的选择（点击、Tab），要么是应用的合理引导（验证错误、模态框出现）。随意地窃取焦点（页面加载时突然聚焦到一个广告）是恶劣的行为，而有意识地管理焦点流动则是专业素养的标志。关于 History API 和单页路由的实现，推荐阅读[《历史 API》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/65.历史API.md)。关于本地存储的使用，推荐阅读[《本地存储》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/70.本地存储.md)。
