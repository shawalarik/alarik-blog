# 存储 —— localStorage、sessionStorage 的容量、作用域、事件

## 从"无状态"到"有记忆"的能力跃迁

在 Web 的早期时代，每个页面都是**无状态**的——关闭浏览器后，用户的所有输入、偏好设置、临时数据全部消失。HTTP 本身是无状态的协议，这意味着服务器不会"记住"你上一次做了什么。但随着应用越来越复杂，持久化存储变得必不可少：用户的主题偏好、购物车内容、未提交的表单草稿、登录令牌……这些数据需要在多次访问之间保持一致。

Web Storage API（`localStorage` 和 `sessionStorage`）是浏览器提供的最简单也最常用的客户端存储方案。它们以键值对的形式存储字符串数据，使用同步 API，极其易用。

> **本文的目标**：全面讲解 localStorage 和 sessionStorage 的完整用法、两者的区别、容量限制与性能考量，以及 storage 事件的跨标签页同步机制。

---

## 一、Web Storage 基础

### 1.1 API 概览

```javascript
// ====== 存储数据 ======
localStorage.setItem('key', 'value');
sessionStorage.setItem('key', 'value');

// ====== 读取数据 ======
localStorage.getItem('key');   // 不存在返回 null（推荐）
localStorage.key;              // 不存在返回 undefined（不推荐，有坑）

// ====== 删除 ======
localStorage.removeItem('key');
delete localStorage.key;        // 属性方式删除

// ====== 清空 ======
localStorage.clear();

// ====== 遍历 ======
for (let i = 0; i < localStorage.length; i++) {
    const key = localStorage.key(i);
    console.log(`${key}: ${localStorage.getItem(key)}`);
}
```

### 1.2 只能存字符串——最重要的规则

```javascript
// ❌ 直接存对象？不行！
localStorage.setItem('user', { name: 'Alarik' });
localStorage.getItem('user');
// → "[object Object]" （toString() 被隐式调用！）

// ✅ JSON 序列化 / 反序列化
const user = { name: 'Alarik', id: 42 };
localStorage.setItem('user', JSON.stringify(user));
const saved = JSON.parse(localStorage.getItem('user'));
console.log(saved.name);  // 'Alarik'

// 封装工具类
const store = {
    set(key, value) { localStorage.setItem(key, JSON.stringify(value)); },
    get(key, fallback = null) {
        try { const v = localStorage.getItem(key); return v ? JSON.parse(v) : fallback; }
        catch { return fallback; }
    },
    remove(key) { localStorage.removeItem(key); }
};
```

### 1.3 生活类比

- **localStorage 就像长期租赁的储物柜**：钥匙自己保管，今天放的东西下周还在。
  
- **sessionStorage 就像进店时的临时置物篮**：逛的过程中可用，走出店门即被收回。

> **哲学思考**：存储让程序拥有了**记忆能力**。没有存储的程序就像患有短期失忆症的人。有了存储，程序就能积累经验、记住偏好、保存进度。人类的智慧也建立在记忆之上。

## 二、localStorage vs sessionStorage

### 2.1 关键区别

| 特性 | localStorage | sessionStorage |
|------|-------------|----------------|
| **生命周期** | 永久（除非主动删除） | 标签页关闭后清除 |
| **容量** | ~5MB | ~5MB |
| **作用域** | 同源下所有标签页共享 | 仅当前标签页独立 |
| **适合场景** | 用户偏好、缓存、配置 | 表单草稿、临时状态 |

### 2.2 选择指南

```javascript
// 用户主题偏好 → localStorage（跨会话保留）
localStorage.setItem('theme', 'dark');

// 购物车 → localStorage（多页面保留）
localStorage.setItem('cart', JSON.stringify(items));

// 多步骤向导中间状态 → sessionStorage
sessionStorage.setItem('wizard-step-1', JSON.stringify(data));

// 敏感临时 token → sessionStorage（关窗自动销毁）
sessionStorage.setItem('temp-token', token);

// 表单草稿自动保存 → sessionStorage
document.querySelectorAll('input, textarea').forEach(field => {
    field.addEventListener('input', () => {
        const draft = collectFormData();
        sessionStorage.setItem('form-draft', JSON.stringify(draft));
    });
});
```

## 三、storage 事件：跨标签页通信

### 3.1 事件机制

当某个标签页修改了 `localStorage`（注意：**不包括 sessionStorage**），其他同源的标签页会收到 `storage` 事件：

```javascript
// 标签页 A：写入
localStorage.setItem('notification', '{"type":"msg","text":"hello"}');

// 标签页 B：监听
window.addEventListener('storage', (e) => {
    console.log(e.key);           // 被修改的键名
    console.log(e.oldValue);      // 修改前的值
    console.log(e.newValue);      // 修改后的值
    console.log(e.storageArea);   // 'localStorage'
    console.log(e.url);           // 触发变化的页面 URL
    
    // ⚠️ 注意：当前修改数据的标签页本身不会收到这个事件！
});

// 只有其他标签页才会收到通知 —— 这是跨标签页通信的基础
```

### 3.2 实战：多标签页状态同步

```javascript
/**
 * 跨标签页主题同步器
 */
class ThemeSyncer {
    constructor() {
        this.storageKey = 'app-theme';
        this.currentTheme = this._loadTheme();
        
        this._applyTheme(this.currentTheme);
        this._listenForChanges();
    }

    _loadTheme() {
        return localStorage.getItem(this.storageKey) || 'light';
    }

    setTheme(theme) {
        this.currentTheme = theme;
        localStorage.setItem(this.storageKey, theme);
        this._applyTheme(theme);
    }

    _applyTheme(theme) {
        document.documentElement.setAttribute('data-theme', theme);
        document.documentElement.className = theme === 'dark' ? 'dark-mode' : '';
    }

    _listenForChanges() {
        window.addEventListener('storage', (e) => {
            if (e.key === this.storageKey && e.newValue !== e.oldValue) {
                this.currentTheme = e.newValue;
                this._applyTheme(e.newValue);
            }
        });
    }
}

// 所有打开的标签页都会同步主题变化
const themeSyncer = new ThemeSyncer();
themeSyncer.setTheme('dark');  // 其他标签页也会切换到 dark
```

### 3.3 storage 事件的重要细节

```javascript
// 细节 1：setItem、removeItem、clear 都会触发
window.addEventListener('storage', (e) => {
    if (!e.newValue && e.oldValue) {
        // removeItem 或 clear 导致（newValue 为 null）
        console.log(`键 "${e.key}" 被删除了`);
    } else if (e.newValue && !e.oldValue) {
        // 新增键
        console.log(`新增键: ${e.key} = ${e.newValue}`);
    } else {
        // 修改已有键
        console.log(`${e.key}: ${e.oldValue} → ${e.newValue}`);
    }
});

// 细节 2：sessionStorage 变动不会触发 storage 事件
sessionStorage.setItem('test', 'value');  // 其他标签页收不到！

// 细节 3：当前标签页自己的修改不会触发自身的事件
localStorage.setItem('self-test', '1');
// 当前标签页的 storage 监听器不会被触发
// 但其他同源标签页会收到
```

## 四、容量限制与性能考量

### 4.1 容量检测与处理

```javascript
/**
 * 安全地写入 localStorage（处理容量不足的情况）
 */
function safeLocalStorageSet(key, value) {
    try {
        localStorage.setItem(key, value);
        return true;
    } catch (e) {
        // QuotaExceededError — 存储空间已满
        if (e.name === 'QuotaExceededError') {
            console.error('本地存储空间已满');
            
            // 策略 A：清理旧数据
            cleanupOldData();
            try {
                localStorage.setItem(key, value);
                return true;
            } catch {
                return false;  // 还是存不下
            }
        }
        return false;
    }
}

function cleanupOldData() {
    // 删除过期的缓存数据
    for (let i = 0; i < localStorage.length; i++) {
        const key = localStorage.key(i);
        if (key.startsWith('cache:') || key.startsWith('tmp:')) {
            localStorage.removeItem(key);
            i--;  // 因为长度变化了
        }
    }
}

// 检测剩余可用空间
function estimateRemainingSpace() {
    let data = 'x';
    try {
        while (true) {
            localStorage.setItem('test-space', data);
            data += 'x';
        }
    } catch (e) {
        localStorage.removeItem('test-space');
        return data.length * 2;  // 粗略估算（UTF-16 编码每个字符 2 字节）
    }
}
```

### 4.2 性能注意事项

```javascript
// ⚠️ localStorage 是同步 API
// 在主线程上频繁读写可能造成卡顿

// ❌ 高频写入（如 scroll 事件中）
window.addEventListener('scroll', () => {
    localStorage.setItem('scroll-y', window.scrollY);  // 每次滚动都写！
});

// ✅ 使用防抖 + 批量写入
const debouncedSave = debounce((y) => {
    localStorage.setItem('scroll-y', y);
}, 500);

window.addEventListener('scroll', () => {
    debouncedSave(window.scrollY);
});

// ⚠️ 不要在循环中逐条读取/写入大量数据
for (let i = 0; i < 10000; i++) {
    localStorage.setItem(`item-${i}`, `value-${i}`);  // 极慢！
}

// ✅ 批量操作：合并为一个 JSON 对象
const batch = {};
for (let i = 0; i < 10000; i++) {
    batch[`item-${i}`] = `value-${i}`;
}
localStorage.setItem('batch-data', JSON.stringify(batch));  // 快得多
```

### 4.3 存储方案对比

| 方案 | 容量 | 类型支持 | API | 适用场景 |
|------|------|---------|-----|---------|
| Cookie | ~4KB | 字符串 | 同步 | 会话标识、旧式认证 |
| localStorage | ~5MB | 字符串 | 同步 | 偏好设置、轻量缓存 |
| sessionStorage | ~5MB | 字符串 | 同步 | 表单草稿、临时状态 |
| IndexedDB | 无限* | 几乎所有类型 | 异步 | 大量结构化数据、文件 |
| Cache API | 无限 | Request/Response | 异步 | PWA 离线资源 |

*实际受磁盘空间限制

对于更复杂的存储需求（大量数据、二进制文件、索引查询等），应该使用 **IndexedDB**：

```javascript
// IndexedDB 简要示例
function openDB(name, version) {
    return new Promise((resolve, reject) => {
        const request = indexedDB.open(name, version);
        request.onupgradeneeded = (e) => {
            const db = e.target.result;
            db.createObjectStore('articles', { keyPath: 'id' });
        };
        request.onsuccess = () => resolve(request.result);
        request.onerror = () => reject(request.error);
    });
}
```

## 五、实战：完整的存储管理器

```javascript
/**
 * StoreManager — 带过期时间和命名空间的存储管理器
 */
class StoreManager {
    constructor(namespace = 'app', storage = localStorage) {
        this.ns = namespace + ':';
        this.storage = storage;
    }

    _fullKey(key) {
        return this.ns + key;
    }

    set(key, value, ttlMs = null) {
        const entry = {
            value,
            expiresAt: ttlMs ? Date.now() + ttlMs : null
        };
        this.storage.setItem(this._fullKey(key), JSON.stringify(entry));
    }

    get(key, fallback = null) {
        try {
            const raw = this.storage.getItem(this._fullKey(key));
            if (!raw) return fallback;

            const entry = JSON.parse(raw);

            // 检查是否过期
            if (entry.expiresAt && Date.now() > entry.expiresAt) {
                this.remove(key);
                return fallback;
            }

            return entry.value;
        } catch {
            return fallback;
        }
    }

    remove(key) {
        this.storage.removeItem(this._fullKey(key));
    }

    clearNamespace() {
        // 只清理当前命名空间的数据
        const toRemove = [];
        for (let i = 0; i < this.storage.length; i++) {
            const k = this.storage.key(i);
            if (k.startsWith(this.ns)) toRemove.push(k);
        }
        toRemove.forEach(k => this.storage.removeItem(k));
    }

    // 清理所有已过期的数据
    cleanupExpired() {
        const now = Date.now();
        for (let i = 0; i < this.storage.length; i++) {
            const k = this.storage.key(i);
            if (!k.startsWith(this.ns)) continue;
            try {
                const entry = JSON.parse(this.storage.getItem(k));
                if (entry.expiresAt && now > entry.expiresAt) {
                    this.storage.removeItem(k);
                    i--;
                }
            } catch {}
        }
    }
}

// 使用示例
const appStore = new StoreManager('my-app');

// 设置带 1 小时过期的用户信息
appStore.set('user', { name: 'Alarik' }, 60 * 60 * 1000);

// 读取（自动检查过期）
const user = appStore.get('user');  // 有效期内返回对象，过期后返回 null

// 页面加载时清理过期数据
appStore.cleanupExpired();
```

## 六、总结：Web Storage 心智模型

### 6.1 决策树

```
需要存储什么？
│
├─ 小量字符串配置（< 50KB）
│   ├─ 需要跨会话保留 → localStorage
│   └─ 仅当前会话 → sessionStorage
│
├─ 大量结构化数据 / 文件
│   └─ IndexedDB
│
├─ 网络请求缓存 / 离线资源
│   └─ Cache API
│
└─ 需要跨标签页通信
    ├─ 数据同步 → storage 事件
    └─ 实时消息 → BroadcastChannel（参见《跨标签页通信》）
```

### 6.2 核心原则

1. **始终 JSON 序列化再存储**：避免 `[object Object]` 的陷阱。
2. **敏感数据不要放 localStorage**：XSS 攻击可轻易窃取。使用 httpOnly cookie 或内存变量。
3. **高频写入要做防抖**：同步 API 会阻塞主线程。
4. **考虑容量限制**：做 QuotaExceededError 的错误处理。
5. **善用命名空间**：避免不同功能模块间的 key 冲突。

> **最后的思考**：Web Storage 的设计哲学是**简单优先（Simplicity First）**。它没有 IndexedDB 的强大查询能力，没有 Cache API 的网络集成，没有 Cookie 的自动请求携带特性。但正因如此，它的学习成本几乎为零——`setItem` / `getItem`，两个方法走天下。在工程实践中，最好的工具往往不是功能最全的那个，而是**最适合当前问题的那个**。对于一个只需要记住用户主题偏好的场景来说，引入 IndexedDB 就像是用大炮打蚊子——能打，但没必要。关于跨标签页通信的更多方案（BroadcastChannel、postMessage 等），推荐阅读[《跨标签页通信》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/75.跨标签页通信.md)。关于音视频等多媒体 API，推荐阅读[《多媒体 API》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/80.多媒体API.md)。
