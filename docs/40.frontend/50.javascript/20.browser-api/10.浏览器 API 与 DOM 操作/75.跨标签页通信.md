# 跨标签页通信 —— BroadcastChannel、postMessage、SharedWorker

## 从"单打独斗"到"协同作战"的能力跃迁

在[《本地存储》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/70.本地存储.md)一文中，我们接触到了 `storage` 事件——一种通过 localStorage 变更实现的跨标签页通信方式。但这种方式有明显的局限：只能传递字符串数据、只能用于同源页面、语义不够清晰。现代浏览器提供了多种更强大的跨标签页通信方案，其中 **BroadcastChannel API** 是最简洁优雅的一个。

跨标签页通信是构建复杂 Web 应用的基础设施。当用户在同一网站打开了多个标签页时：在一个标签页登录后其他标签页应该同步状态；在一个标签播放音乐后切换到另一个标签页不应中断；在一个标签编辑文档后其他标签应该显示最新版本。这些需求都需要标签页之间能够高效地交换信息。

> **本文的目标**：全面对比三种主流的跨标签页通信方案（BroadcastChannel、postMessage、SharedWorker），分析各自的适用场景，并通过实战案例展示最佳实践。

---

## 一、BroadcastChannel API：最简单的广播通道

### 1.1 基本用法

`BroadcastChannel` 是专门为**同源标签页之间的广播式通信**而设计的 API：

```javascript
// ====== 发送端 ======
const channel = new BroadcastChannel('app-channel');

// 发送消息（可以是任意可序列化的数据）
channel.postMessage({
    type: 'user-login',
    user: { id: 42, name: 'Alarik' },
    timestamp: Date.now()
});

// 不再需要时关闭
channel.close();

// ====== 接收端（所有同源的标签页）======
const channel = new BroadcastChannel('app-channel');

channel.onmessage = (event) => {
    console.log(event.data);  // 接收到的完整数据
    console.log(event.origin); // 来源的源（如 'https://example.com'）
    
    switch (event.data.type) {
        case 'user-login':
            updateLoginUI(event.data.user);
            break;
        case 'logout':
            redirectToLogin();
            break;
        case 'theme-change':
            applyTheme(event.data.theme);
            break;
    }
};

// 或者用 addEventListener
channel.addEventListener('message', handler);

// 清理
channel.removeEventListener('message', handler);
channel.close();
```

### 1.2 核心特性

```javascript
const channel = new BroadcastChannel('my-channel');

// 特性 1：频道名完全自定义（字符串）
// 同名的 channel 才能互相通信
// 不同名的 channel 完全隔离

// 特性 2：自动包含当前所有同源标签页
// 新打开的标签页如果监听同一个频道名，立即加入

// 特性 3：支持所有可结构化克隆的数据类型
channel.postMessage('纯文本');           // 字符串
channel.postMessage({ a: 1 });          // 对象
channel.postMessage([1, 2, 3]);         // 数组
channel.postMessage(new Map());         // 部分内置对象
channel.postMessage(new ArrayBuffer(8)); // 二进制数据

// ❌ 不能发送的内容：
channel.postMessage(() => {});   // 函数不行！
channel.postMessage(document.body); // DOM 元素不行！

// 特性 4：自己发出的消息不会回传给自己
channel.postMessage('test');
// 只有其他标签页会收到，当前标签页不会收到自己的消息
```

### 1.3 实战：多标签页登录同步

```javascript
/**
 * 跨标签页认证状态管理器
 */
class AuthSyncManager {
    constructor() {
        this.channel = null;
        this.listeners = [];
        this._init();
    }

    _init() {
        if (!window.BroadcastChannel) return;  // 降级处理
        
        this.channel = new BroadcastChannel('auth-sync');
        
        this.channel.onmessage = (event) => {
            const { type, data } = event.data;
            
            // 通知所有本地监听者
            this.listeners.forEach(fn => fn(type, data));
            
            // 内置处理
            switch (type) {
                case 'login':
                    this._updateUI(data.user, true);
                    break;
                case 'logout':
                    this._updateUI(null, false);
                    window.location.reload();  // 或跳转登录页
                    break;
                case 'token-refresh':
                    this._saveToken(data.token);
                    break;
            }
        };
    }

    onAuthChange(callback) {
        this.listeners.push(callback);
        return () => {  // 返回取消订阅函数
            const idx = this.listeners.indexOf(callback);
            if (idx > -1) this.listeners.splice(idx, 1);
        };
    }

    notifyLogin(user, token) {
        this._saveToken(token);
        this.channel?.postMessage({ type: 'login', data: { user, token } });
    }

    notifyLogout() {
        localStorage.removeItem('auth-token');
        this.channel?.postMessage({ type: 'logout', data: {} });
    }

    notifyTokenRefresh(newToken) {
        this._saveToken(newToken);
        this.channel?.postMessage({ type: 'token-refresh', data: { token: newToken } });
    }

    _saveToken(token) { /* ... */ }
    _updateUI(user, isLoggedIn) { /* ... */ }

    destroy() {
        this.channel?.close();
        this.channel = null;
        this.listeners.length = 0;
    }
}
```

### 1.4 生活类比：BroadcastChannel 就像对讲机频道

- **BroadcastChannel 就像一组对讲机**：所有人调到同一个频道（'auth-sync'），任何一个人说话（postMessage），其他人都能听到（onmessage）。
  
- **频道名就是频率**：调频不同就听不到彼此。你在 'music' 频道说话的人，听不到 'chat' 频道的对话。
  
- **自己说的话自己听不到回声**：就像对讲机的硬件设计一样——你按下发射按钮时接收器被静音了。
  
- **同源限制**：就像对讲机的有效范围——只有在同一个"区域"内的设备才能互相通信（同源策略）。

> **哲学思考**：BroadcastChannel 的设计体现了**发布-订阅模式**的最纯粹形式——没有中央服务器，没有复杂的路由机制，只有"说"和"听"。这种去中心化的架构极其健壮：没有单点故障，每个节点都是平等的参与者。自然界中也有类似的例子——蜜蜂通过气味和舞蹈来共享蜜源位置的信息；鸟群通过简单的邻近感知规则实现协调飞行；人类社区通过口耳相传形成文化传承。这些系统的共同特点是：没有指挥官，但整体行为高度有序。

## 二、window.postMessage：跨域通信的桥梁

### 2.1 基本语法

`postMessage` 与 BroadcastChannel 的关键区别在于：**它可以在不同源的窗口/iframe 之间通信**。

```javascript
// ====== 发送方 ======
// targetWindow 可以是：
// - 通过 window.open() 打开的窗口引用
// - iframe 的 contentWindow
// - 父窗口（window.parent）
// - 当前窗口自身（window）

targetWindow.postMessage(
    message,      // 要发送的数据
    targetOrigin, // 指定目标源（安全措施）
    transfer       // 可选：要转移所有权的一组 Transferable 对象
);

// ====== 接收方 ======
window.addEventListener('message', (event) => {
    event.data;        // 消息内容
    event.origin;      // 发送方的源（如 'https://example.com'）
    event.source;      // 发送方窗口的引用（可用于回复）
});
```

### 2.2 安全模型：origin 验证至关重要

```javascript
/**
 * 安全的消息处理器模板
 * ⚠️ 绝不要省略 origin 检查！
 */
function setupSecureMessageHandler(allowedOrigins) {
    window.addEventListener('message', (event) => {
        // 第一道防线：验证来源
        if (!allowedOrigins.includes(event.origin)) {
            console.warn(`拒绝来自不可信来源的消息: ${event.origin}`);
            return;
        }
        
        // 第二道防线：验证数据结构
        if (!event.data || typeof event.data.type !== 'string') {
            console.warn('收到格式无效的消息');
            return;
        }
        
        // 处理已知类型的消息
        const handlers = {
            'resize-height': () => {
                const height = event.data.height;
                document.getElementById('iframe-wrapper').style.height = `${height}px`;
            },
            'ready': () => {
                event.source.postMessage(
                    { type: 'ack', message: '收到就绪信号' },
                    event.origin
                );
            },
            'data-request': async () => {
                const result = await fetchData(event.data.query);
                event.source.postMessage(
                    { type: 'data-response', id: event.data.id, result },
                    event.origin
                );
            }
        };
        
        const handler = handlers[event.data.type];
        if (handler) {
            handler();
        }
    });
}

// 使用：父页面嵌入子页面时的通信
setupSecureMessageHandler(['https://trusted-child.com']);
```

### 2.3 实战：自适应高度的嵌入组件

```javascript
/**
 * 子页面：通知父页面自身高度变化
 * 用于解决 iframe 高度无法自适应的问题
 */
class AutoResizeMessenger {
    constructor() {
        this.observer = null;
        this._init();
    }

    _init() {
        if (!window.parent || window.parent === window) return;

        const sendHeight = () => {
            const height = document.documentElement.scrollHeight;
            window.parent.postMessage(
                { type: 'resize', height },
                '*'  // 生产环境应替换为具体的父页面域名
            );
        };

        // 使用 ResizeObserver 监听尺寸变化
        this.observer = new ResizeObserver(sendHeight);
        this.observer.observe(document.body);

        // 也监听 DOM 变化
        new MutationObserver(sendHeight).observe(document.body, {
            childList: true,
            subtree: true,
            attributes: true
        });

        // 初始发送
        sendHeight();

        // 接收来自父页面的消息
        window.addEventListener('message', (e) => {
            if (e.data?.type === 'ping') {
                e.source?.postMessage({ type: 'pong', height: document.documentElement.scrollHeight }, e.origin);
            }
        });
    }

    destroy() {
        this.observer?.disconnect();
    }
}

new AutoResizeMessenger();
```

### 2.4 postMessage vs BroadcastChannel

| 维度 | postMessage | BroadcastChannel |
|------|------------|------------------|
| **通信范围** | 可跨源（指定 targetOrigin） | 仅限同源 |
| **目标定位** | 需要持有目标窗口引用 | 所有同名频道的标签页自动加入 |
| **使用复杂度** | 较高（需要管理窗口引用） | 极低 |
| **典型场景** | iframe 跨域通信 | 同源多标签页同步 |
| **安全性** | 需手动校验 origin | 天然同源保护 |

## 三、SharedWorker：共享的后台线程

### 3.1 什么是 SharedWorker？

普通 `Worker` 是**独占的**——每个创建它的页面都有一个独立的 Worker 实例。而 **SharedWorker** 是**共享的**——同一源的所有页面共用一个 SharedWorker 实例：

```
普通 Worker:
标签页 A → Worker-A（独立实例）
标签页 B → Worker-B（独立实例）
标签页 C → Worker-C（独立实例）

SharedWorker:
标签页 A ──┐
标签页 B ──┼──→ SharedWorker-X（唯一实例，共享状态）
标签页 C ──┘
```

这意味着 SharedWorker 可以作为**跨标签页的中央状态管理器**。

### 3.2 基本用法

```javascript
// ====== 主线程（各标签页）======
const worker = new SharedWorker('shared-worker.js');

worker.port.start();  // 必须显式启动端口连接

// 发送消息给 worker
worker.port.postMessage({ type: 'get-count' });

// 接收 worker 的消息
worker.port.onmessage = (event) => {
    console.log('Worker 回复:', event.data);
};

// worker 也可以主动推送消息给所有连接的端口
worker.port.onmessage = (event) => {
    if (event.data.broadcast) {
        handleBroadcast(event.data);
    }
};

// 断开连接
worker.port.close();
```

```javascript
// ====== shared-worker.js =====
let globalCount = 0;
const connectedPorts = new Set();

// 当新的端口（标签页）连接时
self.onconnect = (event) => {
    const port = event.ports[0];
    connectedPorts.add(port);
    console.log(`新连接！当前 ${connectedPorts.size} 个活跃端口`);

    port.onmessage = (e) => {
        switch (e.data.type) {
            case 'increment':
                globalCount++;
                broadcast({ type: 'count-updated', count: globalCount });
                break;
            case 'get-count':
                port.postMessage({ count: globalCount });
                break;
        }
    };

    port.start();
};

// 向所有连接的端口广播消息
function broadcast(message) {
    for (const port of connectedPorts) {
        try {
            port.postMessage(message);
        } catch (e) {
            connectedPorts.delete(port);  // 移除断开的端口
        }
    }
}
```

### 3.3 实战：基于 SharedWorker 的全局计数器

```javascript
/**
 * shared-worker.js — 全局共享的状态管理器
 */
const state = {
    onlineUsers: new Set(),
    notifications: [],
    version: 1
};
const ports = new Set();

self.onconnect = (e) => {
    const port = e.ports[0];
    ports.add(port);
    
    port.onmessage = ({ data }) => {
        switch (data.action) {
            case 'join':
                state.onlineUsers.add(data.userId);
                broadcast({ action: 'user-list-updated', users: Array.from(state.onlineUsers) });
                break;
                
            case 'leave':
                state.onlineUsers.delete(data.userId);
                broadcast({ action: 'user-list-updated', users: Array.from(state.onlineUsers) });
                break;
                
            case 'notify':
                state.notifications.push({ id: Date.now(), ...data.payload });
                broadcast({ action: 'new-notification', notification: data.payload });
                break;
                
            case 'get-state':
                port.postMessage({
                    action: 'state-snapshot',
                    state: { users: Array.from(state.onlineUsers), version: state.version }
                });
                break;
        }
    };
    
    port.start();
};

function broadcast(msg) {
    for (const p of ports) {
        try { p.postMessage(msg); }
        catch { ports.delete(p); }
    }
}
```

### 3.4 生活类比：三种通信方式对比

| 方案 | 类比 |
|------|------|
| **BroadcastChannel** | 社区大喇叭广播——调到一个频道就能听到所有人说话，简单直接 |
| **postMessage** | 寄快递——需要知道对方地址（窗口引用），还要核对寄件人身份（origin） |
| **SharedWorker** | 共享办公室前台——所有人都可以在前台留言或取消息，前台维护着一份共享的名册 |

## 四、方案选择指南

### 4.1 决策树

```
你的场景是什么？
│
├─ 同源标签页之间简单消息通信
│   └─ BroadcastChannel（首选，最简单）
│
├─ 需要与跨域 iframe 通信
│   └─ postMessage（唯一选择）
│
├─ 需要在后台线程中维护共享状态 + 复杂计算
│   └─ SharedWorker
│
├─ 只需简单的一次性同步（且兼容性优先）
│   └─ storage 事件 + localStorage
│
└─ 需要服务端中转的多设备同步
    └─ WebSocket / Server-Sent Events
```

### 4.2 兼容性速查

| API | Chrome | Firefox | Safari | Edge |
|-----|--------|---------|--------|------|
| BroadcastChannel | 54+ | 38+ | 15.4+ | 79+ |
| postMessage | 全部 | 全部 | 全部 | 全部 |
| SharedWorker | 未知* | 29+ | ❌ | 未知* |

\*: Chrome 支持 SharedWorker 但标记为实验性

## 五、总结

### 5.1 核心原则

1. **BroadcastChannel 是首选**：同源通信最简单、最直观。
2. **postMessage 务必验证 origin**：安全第一，永远信任经过验证的来源。
3. **SharedWorker 适合重状态**：需要在后台维护复杂共享数据时使用。
4. **始终做降级处理**：不是所有环境都支持这些 API。
5. **考虑内存泄漏**：及时清理事件监听器和关闭 Channel/Worker 连接。

> **最后的思考**：跨标签页通信技术的发展反映了 Web 应用从**单页面工具**向**多窗口平台**的演进。早期的 Web 页面像一座座孤岛——每个标签页互不相通。BroadcastChannel 和 SharedWorker 的出现让这些孤岛之间架起了桥梁。这种"从孤立到互联"的趋势在整个计算机科学史上不断重现：从单机到局域网再到互联网，从单体应用到微服务再到分布式系统。每一次连接能力的增强都催生了全新的应用形态——跨标签页通信也不例外，它让"Web 应用"真正变成了"Web 平台"。关于多媒体 API 的详细用法，推荐阅读[《多媒体 API》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/80.多媒体API.md)。关于 Canvas 2D 绘图技术，推荐阅读[《Canvas 2D 绘图》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/85.Canvas2D绘图.md)。
