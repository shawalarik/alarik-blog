# WebGL 基础 —— 着色器、缓冲区、绘制三角形

## 从"2D 绘图"到"GPU 加速渲染"的性能跃迁

在[《Canvas 2D 绘图》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/85.Canvas2D绘图.md)一文中，我们掌握了通过 JavaScript 在画布上绘制 2D 图形的能力。Canvas 2D API 的所有绘图操作都在 CPU 上完成——对于简单的图表和动画来说完全够用，但当你需要渲染数千个 3D 模型、处理复杂的粒子效果、或实现实时光照追踪时，CPU 就力不从心了。

**WebGL（Web Graphics Library）** 是浏览器中直接访问 **GPU（图形处理器）** 的接口。它基于 OpenGL ES 2.0 规范，让开发者能利用 GPU 的并行计算能力进行高性能图形渲染。虽然学习曲线陡峭，但一旦掌握，你就能在浏览器中创造出媲美原生应用的视觉体验。

> **本文的目标**：建立 WebGL 的核心认知框架——从着色器语言（GLSL）的基础语法，到缓冲区的创建与绑定，再到完整的渲染管线流程，帮助读者迈出 WebGL 编程的第一步。

## 一、WebGL 的核心概念体系

### 1.1 为什么需要 GPU？

```javascript
// Canvas 2D：CPU 串行处理每个像素
// 10000 个圆形 → CPU 需要逐一计算每个圆的每个像素的颜色
// 当数量增大时，帧率直线下降

// WebGL：GPU 并行处理数百万个像素
// GPU 有成百上千个核心，可以同时计算所有像素
// 即使是 100000 个三角形的场景也能流畅运行
```

**CPU vs GPU 的本质区别**：

| 特性 | CPU | GPU |
|------|-----|-----|
| 核心数量 | 几个（4~16） | 数千个 |
| 每个核心性能 | 强大（适合复杂逻辑） | 较弱（适合简单重复计算） |
| 适合任务 | 串行逻辑、分支判断 | 大规模并行数据运算 |
| 架构模式 | 缓存大、延迟低 | 吞吐量高、延迟高 |
| 类比 | 一位教授（能解决复杂问题） | 一千个小学生（每人做一道简单算术题） |

### 1.2 渲染管线的五个阶段

WebGL 的渲染流程分为几个关键阶段：

```
[顶点数据] → [顶点着色器] → [图元装配(光栅化)] → [片元着色器] → [帧缓冲(屏幕)]
    ↑              ↑                      ↑                ↑             ↑
  你提供        你编写(GLSL)          自动执行         你编写(GLSL)   最终输出
 (Buffer)      (Vertex Shader)                    (Fragment Shader)
```

- **顶点着色器**：接收每个顶点的坐标数据，对其进行变换（平移、旋转、投影），决定每个顶点最终在屏幕上的位置。
  
- **光栅化（Rasterization）**：将几何图形（如三角形）转换为屏幕上的像素集合（称为"片元"）。这个过程由 GPU 自动完成。
  
- **片元着色器**：为每个片元（像素）计算最终颜色——可以是纯色、渐变、纹理采样后的颜色等。
  
- **帧缓冲**：最终的像素颜色被写入帧缓冲区，然后显示到屏幕上。

### 1.3 生活类比：WebGL 渲染就像电影制作

想象你在拍摄一部 3D 动画电影：

- **顶点数据就是演员的骨架定义**——每个角色由一系列关键点（顶点）构成骨架。
  
- **顶点着色器就像摄影机的运镜师**——他决定了从什么角度、什么距离去拍这个角色（坐标变换 = 视角选择 + 投影）。
  
- **光栅化就像把角色的 3D 轮廓投影到胶片的每一格上**——确定哪些胶片格子（像素）需要被这个角色覆盖。
  
- **片元着色器就像调色师和灯光师**——为每个被覆盖的格子涂上合适的颜色（考虑材质、光照、纹理）。
  
- **帧缓冲就是最终的底片**——所有信息都记录在上面，最后冲洗出来就是观众看到的画面。

> **哲学思考**：WebGL 代表了计算机科学中一种重要的范式转移——**从通用计算到专用加速**。当一个问题足够重要且具有特定的结构时（如图形渲染的大规模并行特性），为其设计专用的硬件和编程模型比用通用硬件硬扛要高效得多。这种思想不仅体现在 GPU 上，还体现在 TPU（AI 加速芯片）、NPU（神经网络处理单元）、DSP（数字信号处理器）等各种专用硬件上。未来的计算世界将越来越异构化——不同的任务由最适合的处理器来完成，而程序员需要理解每种处理器的特点和边界。

## 二、GLSL 着色器语言基础

### 2.1 什么是着色器？

着色器（Shader）是用 **GLSL（OpenGL Shading Language）** 编写的程序片段，运行在 GPU 上：

```glsl
// ====== 顶点着色器 (Vertex Shader) ======
attribute vec4 a_position;     // 从 JavaScript 传入的顶点属性
uniform mat4 u_matrix;         // 统一变量（所有顶点共享同一个值）

void main() {
    // 将顶点坐标乘以变换矩阵
    gl_Position = u_matrix * a_position;
    // gl_Position 是内置输出变量——必须赋值
}

// ====== 片元着色器 (Fragment Shader) ======
precision mediump float;       // 浮点精度声明（必需）
uniform vec4 u_color;           // 统一变量：颜色

void main() {
    gl_FragColor = u_color;     // 内置输出变量：当前片元的颜色
}
```

### 2.2 GLSL 数据类型速查

```glsl
// 标量类型
float x = 1.0;       // 单精度浮点（没有 double！）
int count = 10;       // 整数
bool visible = true;  // 布尔值

// 向量类型（最常用！）
vec2 v2 = vec2(1.0, 2.0);       // 2D 向量
vec3 v3 = vec3(1.0, 2.0, 3.0);  // 3D 向量（常用于坐标和颜色）
vec4 v4 = vec4(1.0, 2.0, 3.0, 4.0);  // 4D 向量（齐次坐标）

// 访问向量分量
v4.x / v4.r / v4.s  // 第一个分量（三种命名方式：位置/颜色/纹理）
v4.y / v4.g / v4.t
v4.z / v4.b / v4.p
v4.w / v4.a / v4.q

// 矩阵类型
mat2 m2;   // 2×2 矩阵
mat3 m3;   // 3×3 矩阵
mat4 m4;   // 4×4 矩阵（用于变换）

// 采样器类型（用于纹理）
sampler2D tex;  // 2D 纹理采样器
```

### 2.3 变量的三种存储限定符

| 限定符 | 含义 | 谁来赋值 | 变化频率 |
|--------|------|---------|---------|
| `attribute`（WebGL2 为 `in`） | 每个顶点的输入数据 | JavaScript（Buffer） | 每个顶点不同 |
| `uniform` | 所有顶点/片元共享的数据 | JavaScript | 每次绘制调用相同 |
| `varying`（WebGL2 为 `out/in`） | 顶点→片元插值传递的数据 | 顶点着色器输出→片元着色器输入 | 自动插值 |

```glsl
// varying 示例：传递颜色并自动插值
// 顶点着色器中：
attribute vec3 a_color;
varying vec3 v_color;

void main() {
    v_color = a_color;  // 传给片元着色器
    gl_Position = u_mvp * a_position;
}

// 片元着色器中：
varying vec3 v_color;

void main() {
    // v_color 的值会根据片元在三角形中的位置自动插值！
    // 这就是渐变色的原理
    gl_FragColor = vec4(v_color, 1.0);
}
```

## 三、第一个 WebGL 程序：绘制彩色三角形

### 3.1 完整代码

```javascript
/**
 * WebGL 彩色三角形示例
 */
class WebGLDemo {
    constructor(canvasId) {
        this.canvas = document.getElementById(canvasId);
        this.gl = this.canvas.getContext('webgl');
        
        if (!this.gl) {
            alert('您的浏览器不支持 WebGL');
            return;
        }
        
        this._resize();
        this.program = this._createProgram();
        this._initBuffers();
        this._render();
    }

    _resize() {
        this.canvas.width = this.canvas.clientWidth * devicePixelRatio;
        this.canvas.height = this.canvas.clientHeight * devicePixelRatio;
        this.gl.viewport(0, 0, this.canvas.width, this.canvas.height);
    }

    // === 步骤 1：创建着色器程序 ===
    _createProgram() {
        const gl = this.gl;

        // 顶点着色器源码
        const vsSource = `
            attribute vec2 a_position;
            attribute vec3 a_color;
            varying vec3 v_color;

            void main() {
                gl_Position = vec4(a_position, 0.0, 1.0);
                v_color = a_color;
            }
        `;

        // 片元着色器源码
        const fsSource = `
            precision mediump float;
            varying vec3 v_color;

            void main() {
                gl_FragColor = vec4(v_color, 1.0);
            }
        `;

        // 编译顶点着色器
        const vs = this._compileShader(gl.VERTEX_SHADER, vsSource);
        // 编译片元着色器
        const fs = this._compileShader(gl.FRAGMENT_SHADER, fsSource);

        // 创建程序对象并链接
        const program = gl.createProgram();
        gl.attachShader(program, vs);
        gl.attachShader(program, fs);
        gl.linkProgram(program);

        if (!gl.getProgramParameter(program, gl.LINK_STATUS)) {
            console.error('链接失败:', gl.getProgramInfoLog(program));
            return null;
        }

        return program;
    }

    _compileShader(type, source) {
        const gl = this.gl;
        const shader = gl.createShader(type);
        gl.shaderSource(shader, source);
        gl.compileShader(shader);

        if (!gl.getShaderParameter(shader, gl.COMPILE_STATUS)) {
            console.error('编译错误:', gl.getShaderInfoLog(shader));
            gl.deleteShader(shader);
            return null;
        }
        return shader;
    }

    // === 步骤 2：准备顶点数据 ===
    _initBuffers() {
        const gl = this.gl;
        const program = this.program;

        // 使用程序
        gl.useProgram(program);

        // 定义三角形的三个顶点（位置 + 颜色）
        // 每个顶点：x, y, r, g, b（5 个 float）
        const vertices = new Float32Array([
            //  x,     y,     r,     g,     b
                 0.0,   0.6,   1.0,   0.0,   0.0,  // 顶部 - 红
               -0.6,  -0.4,   0.0,   1.0,   0.0,  // 左下 - 绿
                0.6,  -0.4,   0.0,   0.0,   1.0,  // 右下 - 蓝
        ]);

        // 创建缓冲区
        this.buffer = gl.createBuffer();

        // 绑定到 ARRAY_BUFFER 目标（后续操作都针对这个缓冲区）
        gl.bindBuffer(gl.ARRAY_BUFFER, this.buffer);

        // 将数据上传到 GPU
        gl.bufferData(gl.ARRAY_BUFFER, vertices, gl.STATIC_DRAW);

        // 获取 attribute 位置
        this.positionLoc = gl.getAttribLocation(program, 'a_position');
        this.colorLoc = gl.getAttribLocation(program, 'a_color');

        // 配置 position 属性
        const FSIZE = Float32Array.BYTES_PER_ELEMENT;  // = 4 字节
        
        gl.enableVertexAttribArray(this.positionLoc);
        gl.vertexAttribPointer(
            this.positionLoc,
            2,                  // 每个属性 2 个分量（x, y）
            gl.FLOAT,          // 类型
            false,             // 是否归一化
            5 * FSIZE,         // stride — 每个顶点占多少字节
            0                  // offset — 属性数据距顶点起点的偏移
        );

        // 配置 color 属性
        gl.enableVertexAttribArray(this.colorLoc);
        gl.vertexAttribPointer(
            this.colorLoc,
            3,                  // r, g, b 三个分量
            gl.FLOAT,
            false,
            5 * FSIZE,
            2 * FSIZE          // color 从第 3 个 float 开始（跳过 x, y）
        );
    }

    // === 步骤 3：渲染循环 ===
    _render() {
        const gl = this.gl;

        // 清空画布
        gl.clearColor(0.1, 0.1, 0.12, 1.0);  // 深灰背景
        gl.clear(gl.COLOR_BUFFER_BIT);

        // 绘制三角形
        gl.drawArrays(gl.TRIANGLES, 0, 3);
        // 参数：绘制模式、起始索引、顶点数量
    }
}

// 启动
new WebGLDemo('webgl-canvas');
```

### 3.2 关键步骤解读

整个 WebGL 程序的生命周期可以用以下流程概括：

```
1. 获取 WebGL 上下文
       ↓
2. 编写 GLSL 着色器源码（字符串形式）
       ↓
3. 编译着色器 → 得到 shader 对象
       ↓
4. 创建 program 对象 → attach shader → link
       ↓
5. 准备顶点数据（Float32Array） → 创建 Buffer → 上传到 GPU
       ↓
6. 获取 attribute/uniform 位置 → enable → vertexAttribPointer 配置
       ↓
7. 清空帧缓冲（clear）
       ↓
8. 调用 drawArrays 或 drawElements 触发渲染
```

## 四、Uniform 变量与动态控制

### 4.1 通过 uniform 传入动态参数

```javascript
// 在片元着色器中添加 uniform
const fsSource = `
    precision mediump float;
    uniform vec4 u_color;
    uniform float u_time;   // 时间参数
    
    void main() {
        // 使用时间做简单的脉动效果
        float pulse = sin(u_time * 3.0) * 0.15 + 0.85;
        gl_FragColor = vec4(u_color.rgb * pulse, u_color.a);
    }
`;

// 在 JavaScript 中获取 uniform 位置并设置值
const colorLoc = gl.getUniformLocation(program, 'u_color');
const timeLoc = gl.getUniformLocation(program, 'u_time');

// 设置 uniform 值（必须在 useProgram 之后）
gl.uniform4f(colorLoc, 1.0, 0.5, 0.0, 1.0);  // rgba

// 动画循环中更新 time
function animate(time) {
    gl.uniform1f(timeLoc, time * 0.001);  // 传入毫秒转秒
    gl.clear(gl.COLOR_BUFFER_BIT);
    gl.drawArrays(gl.TRIANGLES, 0, 3);
    requestAnimationFrame(animate);
}
requestAnimationFrame(animate);
```

### 4.2 uniform 的类型对应方法

```javascript
// uniform 的设置方法与 GLSL 类型一一对应：
gl.uniform1f(loc, value);        // float
gl.uniform2f(loc, x, y);         // vec2
gl.uniform3f(loc, x, y, z);      // vec3
gl.uniform4f(loc, x, y, z, w);   // vec4

gl.uniform1i(loc, value);        // int（用于纹理单元）

gl.uniformMatrix4fv(loc, false, matrixArray);  // mat4（4x4矩阵）
// 第二个参数：是否转置（WebGL 中几乎总是 false）
```

## 五、常见陷阱与调试技巧

### 5.1 初学者最容易犯的错误

```javascript
// ⚠️ 错误 1：忘记 clear
// 不 clear 的话，上一帧的内容还在

// ⚠️ 错误 2：viewport 与 canvas 尺寸不匹配
// 导致画面拉伸或压缩
canvas.width = window.innerWidth;  // 必须设！
canvas.height = window.innerHeight;
gl.viewport(0, 0, canvas.width, canvas.height);

// ⚠️ 错误 3：vertexAttribPointer 的 stride 和 offset 算错
// 这是 #1 的 bug 来源！务必仔细检查字节偏移

// ⚠️ 错误 4：在错误的时机获取 attribute 位置
// 必须在 linkProgram 成功之后才能 getAttribLocation/getUniformLocation

// ⚠️ 错误 5：忘记 enableVertexAttribArray
// 即使配置了 pointer，也必须显式启用才能生效
```

### 5.2 调试工具推荐

- **WebGL Inspector**（Chrome 扩展）：查看所有 WebGL 状态、缓冲区内容、着色器源码。
- **Spector.js**：捕获每一帧的渲染过程，逐 draw call 分析。
- **`gl.getError()`**：手动检查错误码的最基本方式。
- **console.log(gl.getExtension('debug_renderer_info').unmaskedRenderer_webgl)`**：查看实际的 GPU 型号。

## 六、总结

### 6.1 WebGL 学习路线

```
本文内容（基础）：
├── 理解渲染管线（5 个阶段）
├── GLSL 基本语法（类型、变量、函数）
├── Buffer 的创建和数据上传
└── 绘制一个三角形 ✅

进阶方向：
├── 变换矩阵（Model/View/Projection）
├── 纹理映射（Texture Mapping）
├── 光照模型（Phong/Blinn-Phong/PBR）
├── 深度测试与混合
└── 3D 场景管理（场景图、相机控制）

高级主题：
├── Framebuffer（离屏渲染）
├── Instanced Rendering（实例化渲染）
├── Compute Shader（GPGPU 通用计算）
└── WebGPU（下一代图形 API）
```

### 6.2 核心原则

1. **先理解管线再写代码**：不知道数据如何流转就动手，只会写出无法调试的一团乱麻。
2. **每一步都要验证**：编译成功？链接成功？buffer 数据正确？uniform 值对不对？
3. **从最小可行开始**：先画出单色三角形，再逐步添加功能。
4. **善用数学库**：不要自己实现矩阵运算，使用 gl-matrix 或类似库。
5. **参考权威资源**：LearnOpenGL、WebGL Fundamentals、MDN 文档都是极好的学习资料。

> **最后的思考**：WebGL 是前端开发中最接近"底层"的技术之一——它让你直接面对 GPU 这一强大的并行计算设备。这种近距离接触底层的能力既是挑战也是机遇：挑战在于你需要理解图形学的基本原理（向量、矩阵、光照、投影……）；机遇在于一旦跨越了这个门槛，你就拥有了一种在其他前端技术中无法获得的创造力。从数据可视化到 3D 游戏，从图像滤镜到物理模拟，从音乐可视化到生成艺术——WebGL 让你的想象力成为唯一的技术限制。关于网络信息 API 的使用方法，推荐阅读[《网络信息 API》](/40.frontend/50.javascript/20.browser-api/10.浏览器%20API%20与%20DOM%20操作/95.网络信息API.md)。
