# XMLHttpRequest —— open、send、onreadystatechange、responseType、上传进度

> **本文的目标**：系统讲解 XMLHttpRequest（XHR）的完整生命周期——从创建实例到配置请求，从发送数据到处理响应，从状态监听到进度追踪。XHRT 是 AJAX 技术的基石，理解它的工作原理有助于深入认识现代网络请求 API（如 Fetch）的设计渊源。

## 一、从"整页刷新"到"局部更新"的认知跃迁

在 Web 的早期岁月，每一次用户交互都意味着一次完整的页面刷新。你在表单里输入用户名和密码，点击登录按钮，浏览器会向服务器发送请求，然后**整个页面被替换为服务器返回的新页面**——即使页面上只有一小块区域需要变化（比如显示一条"登录成功"的提示），其余 95% 的内容可能完全相同，却也要重新加载一遍。

这种模式的问题显而易见：带宽浪费、用户体验割裂、等待时间长。想象一下你正在填写一份长达 30 个字段的注册表单，填到第 28 个字段时不小心点到了一个链接——回来之后所有内容清零重来，那种崩溃感不言而喻。

2005 年，Jesse James Garrett 在一篇文章中创造了 **AJAX**（Asynchronous JavaScript and XML）这个术语，描述了一种已经在 Gmail 和 Google Maps 中悄然使用的技术理念：**在不刷新整个页面的情况下，通过 JavaScript 向服务器请求数据并局部更新 DOM**。而 XMLHttpRequest 就是实现这一理念的底层引擎。

```javascript
// 最基本的 XHR 请求 —— 一窥全貌
const xhr = new XMLHttpRequest();           // ① 创建实例
xhr.open('GET', '/api/user/info');          // ② 配置请求方法与 URL
xhr.send();                                 // ③ 发送请求

xhr.onreadystatechange = function() {       // ④ 监听状态变化
    if (xhr.readyState === 4 && xhr.status === 200) {
        console.log(xhr.responseText);       // ⑤ 获取响应文本
    }
};
```

这五步构成了 XHR 的完整生命周期。看似简单，但每一步背后都有丰富的细节值得深究。

### 生活类比：邮局寄信

如果把 HTTP 请求比作**寄信**的过程：

- **`new XMLHttpRequest()` 就像去邮局买一个标准信封**：这个信封有预印好的格式区域——寄件人地址栏、收件人地址栏、邮票粘贴处。你不能随便拿一张纸就寄出去，必须用符合规格的信封。

- **`open()` 就像在信封上填写收件地址和邮寄方式**：你要告诉邮局这封信是平信还是挂号（GET 还是 POST），寄往哪里（URL）。注意——这一步只是"填写"，信还没有交出去。

- **`send()` 就是把信投入邮箱的那一刻**：一旦投递，你就失去了对它的控制权，它进入了邮政系统的处理流程。

- **`onreadystatechange` 就像给信件挂了追踪号码**：你可以随时查询它的状态——已揽收、运输中、派送中、已签收。每次状态变化，系统都会通知你。

- **`responseText` 就是收到回信后阅读的内容**：对方收到了你的信，写好了回复，你现在可以打开阅读了。

## 二、open() 方法：配置请求的蓝图

`open(method, url, async)` 是 XHR 请求的第一步配置。它有三个核心参数，每个参数都决定了请求的重要特征：

```javascript
// open 方法的完整签名
xhr.open(method, url, async, user, password);
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `method` | 字符串 | 是 | 请求方法：`GET`、`POST`、`PUT`、`DELETE` 等 |
| `url` | 字符串 | 是 | 目标 URL（同源或跨域均可） |
| `async` | 布尔值 | 否 | 是否异步，默认 `true` |

### 同步 vs 异步：一个危险的选择

第三个参数 `async` 控制请求是同步执行还是异步执行：

```javascript
// 异步请求（推荐）—— 不阻塞主线程
xhr.open('GET', '/api/data', true);    // true = 异步
xhr.send();
console.log('这条消息立即打印');         // ✅ 立即执行，不等待响应

// 同步请求（危险！）—— 阻塞主线程直到响应完成
xhr.open('GET', '/api/data', false);   // false = 同步
xhr.send();
console.log('等响应返回后才打印');      // ⚠️ 主线程在此期间完全冻结
```

同步请求会导致一个严重的后果：**在整个请求期间，JavaScript 主线程被冻结**。这意味着 UI 无法响应用户操作（点击无效、滚动卡顿），甚至浏览器的标签页标题都会出现"未响应"提示。现代浏览器已经会在主线程使用同步 XHR 时发出控制台警告，某些情况下甚至直接抛出异常。因此，除非你有非常特殊的理由（极少数遗留系统的兼容性需求），否则永远不要将 `async` 设为 `false`。

## 三、send() 方法：触发请求的扳机

`send()` 方法真正把请求发送到网络。根据请求方法的不同，它可以接收不同类型的参数：

```javascript
// GET 请求 —— 通常不传参数（数据编码在 URL 中）
xhr.open('GET', '/api/users?page=1&size=10');
xhr.send(null);   // GET 请求传 null 或不传参数

// POST 请求 —— 通过 send() 发送请求体
xhr.open('POST', '/api/login');
xhr.setRequestHeader('Content-Type', 'application/json');
xhr.send(JSON.stringify({ username: 'alarik', password: '123456' }));

// POST 表单数据 —— 使用 URL 编码格式
xhr.open('POST', '/api/submit');
xhr.setRequestHeader('Content-Type', 'application/x-www-form-urlencoded');
xhr.send('name=Alarik&age=25&city=Beijing');

// POST 上传文件 —— 直接传入 FormData 对象
const formData = new FormData();
formData.append('file', fileInput.files[0]);
formData.append('description', 'avatar image');
xhr.open('POST', '/api/upload');
xhr.send(formData);   // FormData 会自动设置正确的 Content-Type
```

`send()` 之后，请求正式进入网络层。此时 XHR 实例的 `readyState` 从 `0`（UNSENT）变为 `1`（OPENED），表示请求已打开但尚未发送。

> **哲学思考**：`open()` 和 `send()` 的分离设计体现了一种**准备-执行分离**的思维模式。这种模式在计算机科学中无处不在：数据库事务中的 BEGIN 和 COMMIT、Git 中的 git add 和 git commit、图形渲染中的构建命令列表和提交绘制指令。先准备好一切（配置），再一次性触发执行——这种两阶段模式让调用方有机会在"准备"阶段进行充分的检查和调整，避免在不可逆的"执行"阶段才发现问题。XHR 把这个过程具象化了：`open()` 是深思熟虑的规划，`send()` 是果断执行的行动。

## 四、readyState 与 onreadystatechange：状态机的舞蹈

这是 XHR 最独特也最容易被误解的部分。`readyState` 属性表示请求当前所处的生命周期阶段，共有五个取值：

| readyState | 常量名 | 含义 |
|-----------|--------|------|
| `0` | `UNSENT` | 请求尚未初始化（`open()` 尚未调用） |
| `1` | `OPENED` | 已调用 `open()`，但尚未调用 `send()` |
| `2` | `HEADERS_RECEIVED` | 已调用 `send()`，头部和状态码已可获取 |
| `3` | `LOADING` | 正在下载响应体（`responseText` 可能包含部分数据） |
| `4` | `DONE` | 请求完成（无论成功或失败） |

```javascript
// 完整的状态监听示例
const xhr = new XMLHttpRequest();

xhr.open('GET', '/api/large-data');   // readyState: 0 → 1

xhr.onreadystatechange = function() {
    console.log(`状态变化：${xhr.readyState}`);

    switch (xhr.readyState) {
        case 1: // OPENED
            console.log('请求已配置，即将发送');
            break;
        case 2: // HEADERS_RECEIVED
            console.log(`头部已接收，状态码：${xhr.status}`);
            // 此时可以读取 Content-Type 等 header 信息
            const contentType = xhr.getResponseHeader('Content-Type');
            console.log('响应类型：' + contentType);
            break;
        case 3: // LOADING
            // 正在下载数据，responseText 包含已下载的部分
            console.log(`已下载 ${xhr.responseText.length} 个字符`);
            break;
        case 4: // DONE
            if (xhr.status >= 200 && xhr.status < 300) {
                console.log('请求成功！');
                console.log(xhr.responseText);
            } else {
                console.error(`请求失败，状态码：${xhr.status}`);
            }
            break;
    }
};

xhr.send();   // 触发请求
// 输出示例：
// 状态变化：1
// 请求已配置，即将发送
// 状态变化：2
// 头部已接收，状态码：200
// 响应类型：application/json; charset=utf-8
// 状态变化：3
// 已下载 1024 个字符
// 状态变化：4
// 请求成功！
```

### 为什么需要判断 status？

`readyState === 4` 只说明**HTTP 请求/响应流程已完成**，并不代表业务层面的"成功"。HTTP 状态码 `404`（未找到）、`500`（服务器错误）、`403`（禁止访问）都会使 `readyState` 变为 `4`，但这些都不是我们期望的结果。因此必须同时检查 `status` 或 `status` 的范围：

```javascript
// 常见的成功状态判断方式
if (xhr.readyState === 4 && xhr.status === 200) { ... }        // 仅 200
if (xhr.readyState === 4 && xhr.status >= 200 && xhr.status < 300) { ... }  // 2xx 范围
if (xhr.readyState === 4 && /^(2|3)\d{2}$/.test(String(xhr.status))) { ... } // 正则匹配
```

### onreadystatechange vs onload/onerror

除了通用的 `onreadystatechange`，XHR 还提供了一些更具体的事件回调：

```javascript
const xhr = new XMLHttpRequest();
xhr.open('GET', '/api/data');

// 方式一：传统的 onreadystatechange（老式写法）
xhr.onreadystatechange = function() {
    if (xhr.readyState === 4 && xhr.status === 200) {
        handleSuccess(xhr.response);
    }
};

// 方式二：更语义化的事件回调（现代写法）
xhr.onload = function() {
    // 当 readyState 变为 4 且状态码为 2xx/3xx 时触发
    // 注意：onload 在某些非 2xx 状态下也可能触发！
    if (xhr.status >= 200 && xhr.status < 300) {
        handleSuccess(xhr.response);
    }
};

xhr.onerror = function() {
    // 网络层面失败时触发（如断网、DNS 解析失败）
    // 注意：不会在 HTTP 错误（如 404、500）时触发！
    console.error('网络连接异常');
};

xhr.ontimeout = function() {
    // 超时时触发
    console.error('请求超时');
};

xhr.timeout = 5000;  // 设置 5 秒超时

xhr.send();
```

一个关键区别：**`onerror` 只在网络级别故障时触发，HTTP 错误状态码（404、500 等）仍然会触发 `onload`**。这是一个容易踩坑的地方——不要以为 `onerror` 能捕获所有类型的失败。

## 五、responseType：解析响应数据的钥匙

默认情况下，`responseText` 以纯字符串的形式返回响应体。但在实际开发中，服务器返回的数据往往是 JSON、XML 甚至二进制格式。`responseType` 属性让你告诉 XHR 如何解析响应数据：

| responseType 值 | response 属性类型 | 说明 |
|----------------|------------------|------|
| （空/默认） | `responseText`（String） | 纯文本 |
| `""`（空字符串） | `responseText`（String） | 同上 |
| `"text"` | `responseText`（String） | 文本 |
| `"json"` | `response`（Object） | 自动 JSON.parse |
| `"document"` | `response`（Document） | 解析为 HTML/XML 文档 |
| `"arraybuffer"` | `response`（ArrayBuffer） | 二进制缓冲区 |
| `"blob"` | `response`（Blob） | 二进制大对象 |

```javascript
// 获取 JSON 数据（最常见）
const xhr = new XMLHttpRequest();
xhr.open('GET', '/api/users');
xhr.responseType = 'json';   // 告诉 XHR 自动解析 JSON
xhr.onload = function() {
    // xhr.response 已经是一个对象，无需手动 JSON.parse！
    const users = xhr.response;
    console.log(users[0].name);   // 直接访问属性
    console.log(typeof xhr.response);  // "object"
};
xhr.send();

// 下载图片为 Blob
const imgXhr = new XMLHttpRequest();
imgXhr.open('GET', '/static/photo.jpg');
imgXhr.responseType = 'blob';   // 二进制大对象
imgXhr.onload = function() {
    const blob = imgXhr.response;   // Blob 对象
    const url = URL.createObjectURL(blob);
    document.querySelector('#preview').src = url;
};
imgXhr.send();

// 下载音频为 ArrayBuffer（用于进一步处理）
const audioXhr = new XMLHttpRequest();
audioXhr.open('GET', '/audio/music.mp3');
audioXhr.responseType = 'arraybuffer';
audioXhr.onload = function() {
    const buffer = audioXhr.response;   // ArrayBuffer
    // 可以用 AudioContext 进行解码和处理
    audioContext.decodeAudioData(buffer, decoded => {
        playAudio(decoded);
    });
};
audioXhr.send();
```

`responseType` 必须在 `send()` **之前**设置，否则无效。如果在 `send()` 之后修改，浏览器会抛出异常。

## 六、上传与下载进度追踪

对于大文件传输或慢速网络环境，进度反馈是提升用户体验的关键。XHR 提供了两个专门用于进度监控的事件：`upload.onprogress`（上传进度）和 `onprogress`（下载进度）：

```javascript
const xhr = new XMLHttpRequest();
xhr.open('POST', '/api/upload-large-file');

// 监听上传进度（客户端 → 服务器）
xhr.upload.onprogress = function(event) {
    if (event.lengthComputable) {
        const percent = Math.round((event.loaded / event.total) * 100);
        updateProgressBar(percent);   // 更新 UI 进度条
        console.log(`已上传 ${formatBytes(event.loaded)} / ${formatBytes(event.total)}`);
    }
};

// 监听下载进度（服务器 → 客户端）
xhr.onprogress = function(event) {
    if (event.lengthComputable) {
        const percent = Math.round((event.loaded / event.total) * 100);
        console.log(`已下载 ${percent}%`);
    }
};

// 辅助函数：格式化字节大小
function formatBytes(bytes) {
    if (bytes === 0) return '0 B';
    const k = 1024;
    const sizes = ['B', 'KB', 'MB', 'GB'];
    const i = Math.floor(Math.log(bytes) / Math.log(k));
    return parseFloat((bytes / Math.pow(k, i)).toFixed(2)) + ' ' + sizes[i];
}

// 准备FormData并发送
const formData = new FormData();
formData.append('file', largeFileInput.files[0]);
xhr.send(formData);
```

ProgressEvent 提供三个关键属性：

| 属性 | 类型 | 说明 |
|------|------|------|
| `loaded` | 数字 | 已传输的字节数 |
| `total` | 数字 | 总字节数（如果可知） |
| `lengthComputable` | 布尔值 | `total` 是否可靠（服务器是否提供了 Content-Length） |

需要注意的是，`lengthComputable` 可能 为 `false`——当服务器没有在响应头中提供 `Content-Length` 时（比如使用了分块传输编码 chunked transfer encoding），浏览器就无法知道总大小，也就无法计算百分比。此时通常的做法是显示不确定进度的动画（旋转圈或脉冲条）而非具体的百分比数字。

## 七、完整的封装示例

下面是一个生产级的 XHR 封装函数，展示了如何将上述所有知识点整合为一个实用的工具：

```javascript
/**
 * 基于 XMLHttpRequest 的通用请求函数
 * @param {string} method - 请求方法
 * @param {string} url - 请求地址
 * @param {Object} [options] - 可选配置
 * @returns {Promise<any>}
 */
function request(method, url, options = {}) {
    return new Promise((resolve, reject) => {
        const xhr = new XMLHttpRequest();

        // 配置基本参数
        xhr.open(method, url, true);

        // 设置 responseType
        if (options.responseType) {
            xhr.responseType = options.responseType;
        }

        // 设置超时
        xhr.timeout = options.timeout || 15000;

        // 设置自定义请求头
        if (options.headers) {
            Object.entries(options.headers).forEach(([key, value]) => {
                xhr.setRequestHeader(key, value);
            });
        }

        // 上传进度回调
        if (options.onUploadProgress) {
            xhr.upload.onprogress = options.onUploadProgress;
        }

        // 下载进度回调
        if (options.onDownloadProgress) {
            xhr.onprogress = options.onDownloadProgress;
        }

        // 成功回调
        xhr.onload = function() {
            if (xhr.status >= 200 && xhr.status < 300) {
                resolve({
                    data: xhr.response,
                    status: xhr.status,
                    headers: xhr.getAllResponseHeaders()
                });
            } else {
                reject(new Error(`HTTP Error: ${xhr.status} ${xhr.statusText}`));
            }
        };

        // 网络错误回调
        xhr.onerror = function() {
            reject(new Error('Network error: 无法连接到服务器'));
        };

        // 超时回调
        xhr.ontimeout = function() {
            reject(new Error(`Timeout: 请求超过 ${xhr.timeout}ms 未响应`));
        };

        // 发送请求
        let body = options.body;
        // 如果 body 是对象且未显式设置 Content-Type，自动序列化为 JSON
        if (body && typeof body === 'object' && !(body instanceof FormData)) {
            xhr.setRequestHeader('Content-Type', 'application/json');
            body = JSON.stringify(body);
        }

        xhr.send(body || null);
    });
}

// 使用示例
request('POST', '/api/auth/login', {
    body: { username: 'alarik', password: 'secret' },
    responseType: 'json',
    timeout: 8000,
    onUploadProgress(e) {
        console.log(`上传进度: ${(e.loaded/e.total*100).toFixed(1)}%`);
    }
})
.then(res => console.log('登录成功:', res.data))
.catch(err => console.error('请求失败:', err.message));
```

> **哲学思考**：XHR 的设计反映了 Web 早期的一种工程哲学——**事件驱动 + 回调地狱**。每一个步骤都需要你显式地注册回调函数来处理，每一个状态变化都要你去关心。这种方式赋予了开发者极大的细粒度控制力（你能精确知道请求处于哪个阶段），但也带来了显著的复杂度成本（嵌套的回调、重复的状态检查）。Fetch API 用 Promise 统一了这个过程，AbortController 取代了手动的超时管理，stream API 替代了 progress 事件——每一代新 API 都是对上一代痛点的一次抽象和简化。但这并不意味着 XHR 已经过时：在某些需要精确控制请求生命周期的场景（如上传进度追踪、低级流控），XHR 仍然是不可替代的工具。技术演进从来不是简单的替代，而是工具箱的丰富——你知道的选项越多，做出的选择就越明智。
