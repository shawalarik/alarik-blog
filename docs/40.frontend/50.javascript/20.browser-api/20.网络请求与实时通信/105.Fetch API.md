# Fetch API —— fetch 返回 Promise、Request/Response 对象、Headers

> **本文的目标**：从零掌握现代 Web 网络请求的标准接口 Fetch API——理解其基于 Promise 的设计哲学、Request 与 Response 对象的结构、Headers 的操作方式，以及它与 XHR 的本质区别。

## 一、从回调地狱到 Promise 链：一次认知升级

在 [《XMLHttpRequest》](/40.frontend/50.javascript/20.browser-api/20.网络请求与实时通信/100.XMLHttpRequest.md) 中我们看到了 XHR 的完整生命周期：创建实例、调用 `open()`、配置各种事件处理器、调用 `send()`、然后在 `onreadystatechange` 里判断 `readyState` 和 `status`……这套流程虽然强大，但存在一个根本性的问题：**它基于事件驱动的回调模式，天然容易产生嵌套和状态管理的混乱**。

想象一下你需要"先获取用户信息，再根据用户 ID 获取订单列表，最后根据第一个订单的详情获取商品信息"。用 XHR 来实现这个逻辑：

```javascript
// XHR 的回调嵌套 —— 所谓的"回调地狱"
const xhr1 = new XMLHttpRequest();
xhr1.open('GET', '/api/user/info');
xhr1.onload = function() {
    const user = JSON.parse(xhr1.responseText);

    const xhr2 = new XMLHttpRequest();
    xhr2.open('GET', `/api/orders?userId=${user.id}`);
    xhr2.onload = function() {
        const orders = JSON.parse(xhr2.responseText);

        const xhr3 = new XMLHttpRequest();
        xhr3.open('GET', `/api/products/${orders[0].productId}`);
        xhr3.onload = function() {
            const product = JSON.parse(xhr3.responseText);
            console.log(product);   // 终于拿到了商品信息！
        };
        xhr3.send();
    };
    xhr2.send();
};
xhr1.send();
```

代码向右不断缩进，形成了一个倒金字塔。每一层都需要重复相同的样板代码：创建实例、设置 `onload`、调用 `send`、手动 `JSON.parse`。这还只是三层嵌套——真实项目中五到七层并不罕见。

Fetch API 用 **Promise** 彻底重构了这个问题：

```javascript
// Fetch + async/await —— 扁平、清晰、线性
async function getFirstProduct() {
    // 第一步：获取用户信息
    const userRes = await fetch('/api/user/info');
    const user = await userRes.json();

    // 第二步：获取订单列表
    const ordersRes = await fetch(`/api/orders?userId=${user.id}`);
    const orders = await ordersRes.json();

    // 第三步：获取商品详情
    const productRes = await fetch(`/api/products/${orders[0].productId}`);
    const product = await productRes.json();

    return product;
}

getFirstProduct().then(console.log);
```

代码像阅读自然语言一样流畅：先做什么，再做什么，最后做什么。这就是 Promise 带来的**控制流反转**——从"被动地等待事件触发"变为"主动地等待异步结果"，从嵌套的深度变成了链式的长度。

### 生活类比：排队办事 vs 预约服务

XHR 就像去政府窗口办事：你到了之后取号（创建 XHR 实例），坐在椅子上等着叫号（注册 `onload` 回调）。叫到你的时候你去窗口办理（执行回调逻辑）。如果你办完一件事还需要去另一个窗口，就得重新取号、重新等、重新办——每个步骤都是独立的、被动的。

Fetch 则像预约制的高端服务：你在手机上预约好所有事项，系统会自动安排顺序。你只需要按照约定的时间依次到达每个地点，完成当前的事务后自然过渡到下一个。整个过程是线性的、可预期的，你始终掌握着主动权。

## 二、fetch() 函数：一切的开端

`fetch()` 是全局函数，位于 `window` 对象上（Node.js 18+ 也已内置支持）。它接收两个参数并返回一个 Promise：

```javascript
// 基本语法
fetch(resource, options?)
// resource: URL 字符串 或 Request 对象
// options: 可选的配置对象

// 最简单的 GET 请求
fetch('/api/users')
    .then(response => response.json())
    .then(data => console.log(data))
    .catch(error => console.error('出错:', error));
```

注意这里的一个关键细节：**`fetch()` 返回的 Promise 只在网络层面失败时才会 reject（如断网、DNS 解析失败）。HTTP 错误状态码（404、500 等）不会导致 Promise reject——它们仍然会 resolve，只不过 `response.ok` 为 `false`**。这是初学者最容易踩的坑之一：

```javascript
// ⚠️ 常见错误：以为 catch 能捕获 HTTP 404
fetch('/api/not-exist')
    .then(res => res.json())   // 这里会尝试解析一个可能不是JSON的响应体
    .then(data => console.log(data))
    .catch(err => console.error(err));  // 404 不会进入这里！

// ✅ 正确做法：检查 response.ok 或 response.status
fetch('/api/not-exist')
    .then(res => {
        if (!res.ok) {
            throw new Error(`HTTP Error: ${res.status} ${res.statusText}`);
        }
        return res.json();
    })
    .then(data => console.log(data))
    .catch(err => console.error(err));  // 现在 404 也能正确捕获了
```

## 三、第二个参数：options 配置对象

`fetch()` 的第二个参数是一个可选的配置对象，让你精细控制请求的各种属性：

```javascript
const options = {
    method: 'POST',              // 请求方法：GET, POST, PUT, DELETE, PATCH...
    headers: {                   // 请求头
        'Content-Type': 'application/json',
        'Authorization': 'Bearer eyJhbGci...'
    },
    body: JSON.stringify({       // 请求体（GET 请求不传）
        name: 'Alarik',
        email: 'alarik@example.com'
    }),
    mode: 'cors',                // 请求模式：cors, no-cors, same-origin
    credentials: 'include',      // 凭证模式：omit, same-origin, include
    cache: 'default',            // 缓存策略
    redirect: 'follow',          // 重定向处理：follow, error, manual
};

fetch('/api/users', options)
    .then(res => res.json())
    .then(data => console.log(data));
```

### POST 提交表单数据

除了常见的 JSON 格式，Web 开发中还经常需要提交表单数据：

```javascript
// URL 编码格式（传统表单提交）
fetch('/api/login', {
    method: 'POST',
    headers: {
        'Content-Type': 'application/x-www-form-urlencoded'
    },
    body: 'username=alarik&password=secret123'
});

// FormData 对象（浏览器自动设置 Content-Type 和 boundary）
const formData = new FormData();
formData.append('username', 'alarik');
formData.append('password', 'secret123');
formData.append('avatar', fileInput.files[0]);  // 支持文件
fetch('/api/register', {
    method: 'POST',
    body: formData   // 不要手动设 Content-Type，让浏览器自动处理
});
```

## 四、Response 对象：响应的全部真相

`fetch()` 返回的 Promise 会 resolve 一个 **Response 对象**，它封装了 HTTP 响应的所有信息。理解 Response 的结构是用好 Fetch 的核心：

```javascript
fetch('/api/data').then(response => {
    console.log(response);   // Response 对象的完整结构
});
```

### Response 核心属性

| 属性 | 类型 | 说明 |
|------|------|------|
| `status` | 数字 | HTTP 状态码（200, 404, 500...） |
| `statusText` | 字符串 | 状态文本（'OK', 'Not Found'...） |
| `ok` | 布尔值 | `status` 是否在 200-299 范围内 |
| `redirected` | 布尔值 | 是否经过了重定向 |
| `type` | 字符串 | 响应类型：'basic', 'cors', 'opaque', 'error' |
| `url` | 字符串 | 最终的响应 URL（经过重定向后可能不同于请求 URL） |

```javascript
fetch('/api/test-status').then(res => {
    console.log(res.status);         // 200, 404, 500 ...
    console.log(res.statusText);     // 'OK', 'Not Found' ...
    console.log(res.ok);             // true/false（最常用的快速判断）
    console.log(res.url);            // 实际响应地址（可能有重定向）
});
```

### Response.body 解析方法

Response 对象提供了多个方法来读取响应体，每个方法返回一个 Promise：

```javascript
// res.text() —— 获取纯文本
fetch('/api/readme.txt')
    .then(res => res.text())
    .then(text => console.log(text));

// res.json() —— 自动 JSON.parse
fetch('/api/users')
    .then(res => res.json())
    .then(users => users.forEach(u => console.log(u.name)));

// res.blob() —— 获取二进制大对象（图片、文件等）
fetch('/static/image.png')
    .then(res => res.blob())
    .then(blob => {
        const img = document.createElement('img');
        img.src = URL.createObjectURL(blob);
        document.body.appendChild(img);
    });

// res.arrayBuffer() —— 获取原始二进制缓冲区
fetch('/audio/music.mp3')
    .then(res => res.arrayBuffer())
    .then(buffer => audioContext.decodeAudioData(buffer, play));

// res.formData() —— 获取表单数据
fetch('/api/form-response')
    .then(res => res.formData())
    .then(form => console.log(form.get('fieldName')));

// res.clone() —— 克隆 Response（因为 body 只能消费一次！）
fetch('/api/data')
    .then(res => {
        const clone1 = res.clone();   // 克隆一份
        const clone2 = res.clone();   // 再克隆一份
        return Promise.all([
            res.json(),     // 原始响应
            clone1.text(),  // 克隆1 作为文本
            clone2.blob()   // 克隆2 作为 Blob
        ]);
    });
```

> **重要提醒**：Response 的 body 是一个**只能消费一次的流**。一旦调用了 `.json()`、`.text()` 或其他任何方法，body 就会被标记为"已使用"，再次调用将返回空结果或抛出异常。如果需要多次使用同一个响应的数据，必须先用 `.clone()` 创建副本。

## 五、Request 对象：请求的可复用蓝图

除了直接传字符串 URL 给 `fetch()`，还可以先构造一个 Request 对象，然后将其传入。这种方式在某些高级场景下非常有用：

```javascript
// 构造 Request 对象
const request = new Request('/api/users', {
    method: 'GET',
    headers: {
        'Accept': 'application/json',
        'X-Requested-With': 'FetchAPI'
    },
    credentials: 'include'
});

// 使用 Request 对象发起请求
fetch(request)
    .then(res => res.json())
    .then(data => console.log(data));

// Request 对象可以被复用或修改后重用
const postRequest = new Request('/api/submit', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ title: 'Hello World' })
});

// 同一个 Request 可以发送两次（但要注意 body 也是一次性消费的！）
// fetch(postRequest);   // 第一次发送成功
// fetch(postRequest);   // 第二次会报错：body already used
```

### Request 的核心属性

| 属性 | 说明 |
|------|------|
| `method` | 请求方法 |
| `url` | 请求地址 |
| `headers` | Headers 对象 |
| `body` | 请求体 |
| `credentials` | 凭证模式 |
| `mode` | 跨域模式 |
| `cache` | 缓存策略 |
| `redirect` | 重定向策略 |
| `referrer` | 引用页地址 |
| `signal` | AbortSignal 用于取消请求 |

## 六、Headers 对象：HTTP 头部的统一管理

Headers 是 Fetch API 中用于管理 HTTP 头部信息的专用对象。它可以独立使用，也可以作为 Request 和 Response 的一部分：

```javascript
// 方式一：通过字面量对象创建
const headers = new Headers({
    'Content-Type': 'application/json',
    'Accept': 'application/json',
    'X-Custom-Header': 'custom-value'
});

// 方式二：逐步添加
const headers2 = new Headers();
headers2.append('Content-Type', 'text/plain');
headers2.append('Authorization', 'Bearer token123');

// 常用方法
headers.get('Content-Type');           // 'application/json'
headers.has('X-Custom-Header');       // true
headers.set('Accept', 'text/html');   // 覆盖已有的值
headers.delete('X-Custom-Header');    // 删除某个 header
headers.keys();                       // 返回所有 key 的迭代器
headers.values();                     // 返回所有 value 的迭代器
headers.entries();                    // 返回 [key, value] 的迭代器

// 在 fetch 中使用 Headers
fetch('/api/data', {
    method: 'POST',
    headers: headers,    // 直接传入 Headers 对象
    body: JSON.stringify({ data: 'test' })
});

// 从 Response 中读取 Headers
fetch('/api/data').then(res => {
    console.log(res.headers.get('Content-Type'));
    console.log(res.headers.get('Cache-Control'));

    // 遍历所有响应头
    for (const [key, value] of res.headers.entries()) {
        console.log(`${key}: ${value}`);
    }
});
```

### 关于安全限制的注意事项

出于安全原因，浏览器对可以通过 JavaScript 读取的**响应头**有限制。默认情况下，只有以下"安全列表"中的头部可以通过 `response.headers.get()` 访问：

- `Cache-Control`
- `Content-Language`
- `Content-Type`（值不以 `*` 开头）
- `Expires`
- `Last-Modified`
- `Pragma`

如果服务器希望暴露自定义头部给前端，需要在响应中设置 `Access-Control-Expose-Headers` 头部（详见 [《CORS 跨域资源请求》](/40.frontend/50.javascript/20.browser-api/20.网络请求与实时通信/115.CORS跨域.md)）：

```javascript
// 服务端需要这样设置：
// Access-Control-Expose-Headers: X-Request-ID, X-RateLimit-Remaining

// 这样前端才能读到这些自定义头部
fetch('/api/data').then(res => {
    console.log(res.headers.get('X-Request-ID'));           // 可以访问了
    console.log(res.headers.get('X-RateLimit-Remaining'));   // 可以访问了
});
```

## 七、错误处理的完整策略

Fetch API 的错误处理需要同时关注两类异常：网络层面的失败和 HTTP 层面的失败。下面是一个健壮的错误处理模式：

```javascript
/**
 * 封装的 fetch 工具函数 —— 包含完整的错误处理
 */
async function safeFetch(url, options = {}) {
    let response;

    try {
        // 第一层：捕获网络级别的错误（断网、DNS失败、SSL错误等）
        response = await fetch(url, options);
    } catch (networkError) {
        throw new FetchError(
            '网络连接失败，请检查网络后重试',
            'NETWORK_ERROR',
            null,
            networkError
        );
    }

    // 第二层：处理 HTTP 状态码
    if (!response.ok) {
        let errorMessage;
        try {
            // 尝试从响应体中提取服务器返回的错误信息
            const errorData = await response.json();
            errorMessage = errorData.message || errorData.error || `HTTP ${response.status}`;
        } catch {
            // 如果响应体不是有效 JSON，使用状态文本
            errorMessage = `${response.status}: ${response.statusText}`;
        }

        throw new FetchError(errorMessage, 'HTTP_ERROR', response.status);
    }

    return response;
}

/**
 * 自定义错误类 —— 携带更多上下文信息
 */
class FetchError extends Error {
    constructor(message, type, statusCode, originalError = null) {
        super(message);
        this.name = 'FetchError';
        this.type = type;              // 'NETWORK_ERROR' | 'HTTP_ERROR'
        this.statusCode = statusCode;   // HTTP 状态码（仅 HTTP_ERROR 时有值）
        this.originalError = originalError;  // 原始错误对象
    }

    isNetworkError() { return this.type === 'NETWORK_ERROR'; }
    isHttpError() { return this.type === 'HTTP_ERROR'; }
    isClientError() { return this.statusCode >= 400 && this.statusCode < 500; }
    isServerError() { return this.statusCode >= 500; }
}

// 使用示例
try {
    const res = await safeFetch('/api/sensitive-data');
    const data = await res.json();
    console.log('获取数据成功:', data);
} catch (err) {
    if (err instanceof FetchError) {
        if (err.isNetworkError()) {
            showToast('网络似乎出了问题 😢');
        } else if (err.isClientError() && err.statusCode === 401) {
            showToast('登录已过期，请重新登录');
            redirectToLogin();
        } else if (err.isServerError()) {
            showToast('服务器暂时不可用，稍后再试');
        }
    } else {
        showToast('发生了未知错误');
    }
    console.error('详细错误:', err);
}
```

> **哲学思考**：Fetch API 的设计体现了 **"分层关注点分离"** 的工程美学。XHR 把所有东西混在一起——状态变化、HTTP 状态、网络错误、超时处理都塞进了同一个回调函数里。Fetch 把这些关注点清晰地分开了：Promise 处理异步流程，Response 对象封装响应数据，Headers 对象管理头部信息，AbortController 控制生命周期（详见[《Fetch 高级用法》](/40.frontend/50.javascript/20.browser-api/20.网络请求与实时通信/110.Fetch高级用法.md)）。
这种分离不仅让代码更易读，更重要的是让**每个部分都可以独立测试、独立替换**。当你能清晰地指出"这部分代码负责什么"的时候，你就真正掌握了它。好的架构不是把事情变复杂，而是让复杂的事情变得有条理——就像图书馆里的分类系统：书越来越多，但找书反而更快了，因为每本书都有自己明确的位置。
