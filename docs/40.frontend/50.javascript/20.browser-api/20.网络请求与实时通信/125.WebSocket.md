# WebSocket —— 握手、send、onmessage、onclose、心跳保活、重连机制

> **本文的目标**：深入掌握 WebSocket 全双工实时通信协议——从 HTTP 握手升级到 TCP 长连接的建立过程，到消息的双向收发与二进制数据处理，再到生产环境必需的心跳检测与断线重连机制。WebSocket 是现代 Web 实时应用（聊天、协作编辑、实时推送、在线游戏）的核心技术支柱。

## 一、从"一问一答"到"随时对话"：通信范式的跃迁

回顾前面学习的 [《XMLHttpRequest》](/40.frontend/50.javascript/20.browser-api/20.网络请求与实时通信/100.XMLHttpRequest.md) 和 [《Fetch API》](/40.frontend/50.javascript/20.browser-api/20.网络请求与实时通信/105.Fetch%20API.md)，它们都遵循同一个基本模式：**客户端发起请求 → 服务器返回响应 → 连接结束**。这种模式就像打电话——你拨号，对方接听，说完事情，挂断。即使你每隔 5 秒就打一次电话问"有没有新消息？"（这就是[轮询](/40.frontend/50.javascript/20.browser-api/20.网络请求与实时通信/135.轮询模式.md)），本质上仍然是离散的、间歇性的对话。

但有些场景需要的是**持续的、双向的、即时的数据流动**：

- 聊天室中别人发了一条消息，你需要**立刻**看到——而不是等到下一次轮询
- 在线协作文档中同事修改了一个段落，你的屏幕需要**同步更新**
- 股票行情每秒都在波动，你希望看到**实时的**价格变化
- 多人游戏中玩家的移动需要**毫秒级**同步

WebSocket 就是为了解决这类问题而诞生的。它提供了一种**全双工（Full-Duplex）** 的通信通道：一旦连接建立，客户端和服务器可以在任何时刻向对方发送数据，不需要等待对方的请求。连接会持续存在，直到任何一方主动关闭或网络中断。

```javascript
// 最基本的 WebSocket 连接
const ws = new WebSocket('wss://chat.example.com/ws');

// 连接建立时触发
ws.onopen = function() {
    console.log('✅ 连接已建立');
    ws.send('Hello, Server!');   // 立刻发送消息
};

// 收到服务器消息时触发
ws.onmessage = function(event) {
    console.log('收到消息:', event.data);
};

// 连接关闭时触发
ws.onclose = function(event) {
    console.log('连接已关闭, code:', event.code);
};

// 发生错误时触发
ws.onerror = function(error) {
    console.error('WebSocket错误:', error);
};
```

### 生活类比：从寄信到专线电话

把各种通信方式做个对比：

- **HTTP/Fetch 就像寄信**：你想给服务器说件事，写封信（HTTP Request）投进邮筒，等几天后收到回信（HTTP Response）。每次通信都要走一遍完整的投递流程。

- **轮询就像每隔5分钟打一次电话问"有我的信吗？"**：邮局人员每次都说"暂时没有"或者"有一封"。效率低且浪费资源。

- **长轮询就像打电话过去说"有信了吗？没有的话我先不挂"**：邮局人员一直拿着电话，直到真的有信了才告诉你。比普通轮询好一些，但仍然是一问一答。

- **WebSocket 就像拉了一条专用电话线**：一旦接通，双方可以随时说话、随时倾听，不需要重新拨号，没有"谁先说话"的限制。这条线路始终保持着，随时待命。

## 二、握手升级：从 HTTP 到 WebSocket

WebSocket 并不是一种全新的传输协议——它是在 HTTP 协议基础上通过**协议升级（Protocol Upgrade）** 机制建立的。这意味着 WebSocket 连接的建立过程始于一次普通的 HTTP 请求，然后"升级"为 WebSocket 长连接。

```
客户端                                    服务器
 │                                         │
 │  ── HTTP GET /ws ──────────────────▶   │  ① 普通的HTTP请求
 │     Connection: Upgrade                │     但携带特殊头部
 │     Upgrade: websocket                 │     表明想升级协议
 │     Sec-WebSocket-Key: dGhlIHNhbXB...  │
 │     Sec-WebSocket-Version: 13          │
 │                                         │
 │  ◀── 101 Switching Protocols ───────   │  ② 服务器同意升级
 │     Connection: Upgrade                │     返回101状态码
 │     Upgrade: websocket                 │
 │     Sec-WebSocket-Accept: s3pPLMBi...  │
 │                                         │
 ════════ 升级完成！现在是 WebSocket 连接 ════════
 │                                         │
 │  ◀──────── 消息帧 (Binary) ─────────   │  ③ 双向数据传输
 │  ───────▶ 消息帧 (Text) ────────────   │     不再是HTTP格式
 │  ◀──────── 消息帧 (Text) ─────────   │     而是WebSocket帧
 │                                         │
 │  ── Close Frame ─────────────────▶    │  ④ 任一方发送关闭帧
 │  ◀── Close Frame ─────────────────    │     连接结束
```

关键的请求头部：

| 头部 | 值 | 说明 |
|------|-----|------|
| `Connection` | `Upgrade` | 告诉代理服务器这是一个协议升级请求 |
| `Upgrade` | `websocket` | 目标协议为 WebSocket |
| `Sec-WebSocket-Key` | base64编码随机值 | 用于安全验证 |
| `Sec-WebSocket-Version` | `13` | WebSocket 协议版本号 |

服务器收到这个请求后，如果支持 WebSocket，会返回 `101 Switching Protocols` 状态码，并在响应头中包含经过计算的确认值。此后，同一底层 TCP 连接就从 **HTTP 协议切换到了 WebSocket 协议**。

这个过程对开发者是完全透明的——浏览器自动处理了所有头部组装和解析工作。你只需要 `new WebSocket(url)` 一行代码，剩下的交给浏览器。

## 三、消息的发送与接收

### send() 方法

`send()` 用于向服务器发送数据，支持多种格式：

```javascript
const ws = new WebSocket('wss://example.com/ws');

ws.onopen = function() {
    // 发送文本字符串（最常用）
    ws.send('Hello World!');

    // 发送 JSON 数据
    const message = {
        type: 'chat',
        content: '大家好！',
        timestamp: Date.now(),
        userId: 'user_123'
    };
    ws.send(JSON.stringify(message));

    // 发送二进制数据（ArrayBuffer）
    const buffer = new ArrayBuffer(8);
    const view = new DataView(buffer);
    view.setFloat64(0, Math.PI);
    ws.send(buffer);

    // 发送二进制数据（Blob）
    const blob = new Blob(['binary content'], { type: 'application/octet-stream' });
    ws.send(blob);

    // 发送 TypedArray（如 Uint8Array）
    const uint8 = new Uint8Array([0x48, 0x65, 0x6c, 0x6c, 0x6f]);
    ws.send(uint8);
};
```

### onmessage 与数据类型

`onmessage` 事件回调接收一个 `MessageEvent` 对象，其中 `data` 属性包含服务器发送的数据。数据的类型取决于服务器发送时的编码方式：

```javascript
ws.onmessage = function(event) {
    // event.data 可能是以下类型之一：
    // string  — 文本数据
    // Blob    — 二进制数据（默认情况下）
    // ArrayBuffer — 二进制数据（当 binaryType = 'arraybuffer' 时）

    if (typeof event.data === 'string') {
        // 文本消息 —— 通常需要 JSON.parse
        const msg = JSON.parse(event.data);
        handleMessage(msg);
    } else if (event.data instanceof Blob) {
        // Blob 类型二进制数据
        handleBlobData(event.data);
    } else if (event.data instanceof ArrayBuffer) {
        // ArrayBuffer 类型二进制数据
        handleBufferData(event.data);
    }
};

// 控制二进制数据的接收格式
ws.binaryType = 'arraybuffer';   // 默认是 'blob'，设为 'arraybuffer' 更方便处理
```

### readyState：连接状态机

和 XHR 类似，WebSocket 也有一个 `readyState` 属性表示当前连接状态：

| 常量 | 值 | 含义 |
|------|-----|------|
| `WebSocket.CONNECTING` | `0` | 正在建立连接 |
| `WebSocket.OPEN` | `1` | 连接已开启，可以通信 |
| `WebSocket.CLOSING` | `2` | 正在关闭连接 |
| `WebSocket.CLOSING` | `3` | 连接已关闭或无法打开 |

```javascript
function getWSStatusName(ws) {
    const states = {
        [WebSocket.CONNECTING]: '连接中...',
        [WebSocket.OPEN]: '已连接 ✅',
        [WebSocket.CLOSING]: '正在关闭...',
        [WebSocket.CLOSED]: '已关闭 ❌'
    };
    return states[ws.readyState] || '未知状态';
}

console.log(getWSStatusName(ws));   // 根据当前状态输出对应文字
```

## 四、心跳保活：让沉默的连接保持活力

TCP 连接有一个棘手的问题：**它不会主动告诉你连接是否已经断开**。想象一下这种情况：用户合上了笔记本电脑盖子（进入休眠），WiFi 断开了，但服务器的 WebSocket 连接还在那里傻等着。或者更常见的情况——中间的网络设备（NAT 网关、防火墙、负载均衡器）因为长时间没有数据流过而**主动切断了这个"看起来已经死亡"的连接**。此时客户端和服务端都以为连接还活着，但实际早已不通了。

解决方案就是**心跳（Heartbeat）机制**：客户端和服务器定期交换一个极小的消息（就像医生检查病人时的心跳检测），告诉对方"我还在，连接还是通的"。如果连续多次心跳没有得到回应，就可以判定连接已死并尝试重连。

```javascript
class HeartbeatWebSocket {
    constructor(url, options = {}) {
        this.url = url;
        this.heartbeatInterval = options.heartbeatInterval || 30000;  // 心跳间隔 30s
        this.maxMissedBeats = options.maxMissedBeats || 3;             // 最大丢失心跳数
        this.reconnectInterval = options.reconnectInterval || 5000;    // 重连间隔 5s

        this.ws = null;
        this.heartbeatTimer = null;
        this.missedBeats = 0;

        this.connect();
    }

    connect() {
        this.ws = new WebSocket(this.url);

        this.ws.onopen = () => {
            console.log('🟢 WebSocket 已连接');
            this.missedBeats = 0;
            this.startHeartbeat();
            this.onOpen?.();
        };

        this.ws.onmessage = (event) => {
            if (this.isHeartbeatMessage(event.data)) {
                // 收到心跳回复 —— 重置丢失计数
                this.missedBeats = 0;
                console.log('💓 心跳回复');
            } else {
                // 普通消息交给外部处理
                this.onMessage?.(event);
            }
        };

        this.ws.onclose = (event) => {
            console.log(`🔴 连接关闭: code=${event.code}`);
            this.stopHeartbeat();
            this.onClose?.(event);
            this.scheduleReconnect();   // 自动重连
        };

        this.ws.onerror = (error) => {
            console.error('❌ WebSocket 错误:', error);
            this.onError?.(error);
        };
    }

    startHeartbeat() {
        this.stopHeartbeat();   // 先清除已有的定时器
        this.heartbeatTimer = setInterval(() => {
            if (this.ws && this.ws.readyState === WebSocket.OPEN) {
                this.ws.send(JSON.stringify({ type: 'ping', ts: Date.now() }));
                this.missedBeats++;

                if (this.missedBeats >= this.maxMissedBeats) {
                    console.warn(`⚠️ 连续 ${this.missedBeats} 次心跳无回应，判定连接死亡`);
                    this.ws.close(4001, '心跳超时');
                }
            }
        }, this.heartbeatInterval);
    }

    stopHeartbeat() {
        if (this.heartbeatTimer) {
            clearInterval(this.heartbeatTimer);
            this.heartbeatTimer = null;
        }
    }

    isHeartbeatMessage(data) {
        try {
            const parsed = JSON.parse(data);
            return parsed.type === 'pong' || parsed.type === 'ping';
        } catch { return false; }
    }

    scheduleReconnect() {
        setTimeout(() => {
            console.log('🔄 尝试重新连接...');
            this.connect();
        }, this.reconnectInterval);
    }

    send(data) {
        if (this.ws?.readyState === WebSocket.OPEN) {
            this.ws.send(typeof data === 'string' ? data : JSON.stringify(data));
        } else {
            console.warn('⚠️ WebSocket 未连接，无法发送消息');
        }
    }

    close(code = 1000, reason = '正常关闭') {
        this.stopHeartbeat();
        this.ws?.close(code, reason);
    }

    // 回调钩子（由使用者覆盖）
    onOpen = null;
    onMessage = null;
    onClose = null;
    onError = null;
}

// 使用示例
const chatWS = new HeartbeatWebSocket('wss://chat.example.com/ws', {
    heartbeatInterval: 25000,
    maxMissedBeats: 3,
    reconnectInterval: 3000
});

chatWS.onMessage = (event) => {
    const msg = JSON.parse(event.data);
    displayChatMessage(msg);   // 处理聊天消息
};
```

### 服务端配合

心跳机制需要服务端的配合——通常采用 **Ping/Pong** 模式：

```javascript
// 客户端发送 ping
// 服务端收到后立即回复 pong
// 如果使用标准 WebSocket Ping 帧（opcode 0x9）：
// 浏览器会自动回复 Pong 帧（opcode 0xA），无需手动处理！

// 但很多实现选择在应用层做心跳（如上面的例子），这样更灵活
// 因为你可以携带额外信息（时间戳、客户端状态等）
```

## 五、断线重连：构建健壮的生产级连接

现实世界的网络是不稳定的——WiFi 信号波动、手机从 WiFi 切换到 4G、用户进出电梯隧道、服务器重启部署……这些都会导致 WebSocket 连接意外断开。一个好的 WebSocket 封装必须具备**自动重连**能力。

下面实现一个完整的带指数退避重连策略的 WebSocket 类：

```javascript
/**
 * ReconnectingWebSocket —— 支持自动重连的 WebSocket 封装
 * 核心特性：
 *   - 自动重连（指数退避）
 *   - 心跳保活
 *   - 手动 close 不触发重连
 *   - 消息缓冲（离线期间的消息排队）
 */
class ReconnectingWebSocket {
    constructor(url, protocols, options = {}) {
        this.url = url;
        this.protocols = protocols;
        this.options = {
            maxRetries: Infinity,          // 最大重试次数（无限）
            reconnectInterval: 1000,       // 初始重连延迟(ms)
            maxReconnectInterval: 30000,   // 最大重连延迟(ms)
            reconnectDecay: 2,             // 重连延迟增长因子（指数退避）
            heartbeatInterval: 30000,      // 心跳间隔(ms)
            ...options
        };

        this.ws = null;
        this.retryCount = 0;
        this.shouldReconnect = true;
        this.forcedClose = false;
        this.messageBuffer = [];           // 离线消息缓冲区
        this.listeners = {};               // 事件监听器注册表

        this._bindEventHandlers = this._bindEventHandlers.bind(this);
        this.connect();
    }

    connect() {
        if (this.protocols) {
            this.ws = new WebSocket(this.url, this.protocols);
        } else {
            this.ws = new WebSocket(this.url);
        }

        this._bindEventHandlers();
    }

    _bindEventHandlers() {
        this.ws.onopen = () => {
            console.log(`🟢 已连接 (第${this.retryCount + 1}次尝试)`);
            this.retryCount = 0;           // 重置重试计数
            this.shouldReconnect = true;

            // 发送缓冲区的积压消息
            while (this.messageBuffer.length > 0) {
                const msg = this.messageBuffer.shift();
                this.ws.send(msg);
                console.log('📤 发送缓冲消息');
            }

            this.emit('open');
            this._startHeartbeat();
        };

        this.ws.onmessage = (event) => {
            this.emit('message', event.data);
            // 心跳回复处理...
        };

        this.ws.onclose = (event) => {
            this._stopHeartbeat();
            this.emit('close', event);

            if (!this.forcedClose && this.shouldReconnect) {
                this._scheduleReconnect();
            }
        };

        this.ws.onerror = (error) => {
            this.emit('error', error);
        };
    }

    _scheduleReconnect() {
        const { maxRetries, reconnectInterval,
                maxReconnectInterval, reconnectDecay } = this.options;

        if (this.retryCount >= maxRetries) {
            console.error('已达最大重连次数，放弃重连');
            this.emit('maxretriesreached');
            return;
        }

        // 指数退避计算：delay = base * decay^attempt，但不超过上限
        const delay = Math.min(
            reconnectInterval * Math.pow(reconnectDecay, this.retryCount),
            maxReconnectInterval
        );

        this.retryCount++;
        console.log(`⏳ ${delay}ms 后进行第 ${this.retryCount} 次重连尝试...`);

        setTimeout(() => this.connect(), delay);
    }

    _startHeartbeat() {
        // 心跳逻辑同上例...
    }

    _stopHeartbeat() {
        // 清除心跳定时器...
    }

    // 发送消息（支持离线缓冲）
    send(data) {
        const payload = typeof data === 'string' ? data : JSON.stringify(data);
        if (this.ws?.readyState === WebSocket.OPEN) {
            this.ws.send(payload);
        } else {
            // 连接未就绪时将消息放入缓冲队列
            this.messageBuffer.push(payload);
            console.log('💾 消息已缓冲，等待连接恢复后发送');
        }
    }

    // 事件系统
    on(event, callback) {
        if (!this.listeners[event]) this.listeners[event] = [];
        this.listeners[event].push(callback);
        return this;   // 支持链式调用
    }

    emit(event, data) {
        (this.listeners[event] || []).forEach(cb => cb(data));
    }

    // 关闭连接（不触发重连）
    close(code = 1000, reason) {
        this.forcedClose = true;
        this.shouldReconnect = false;
        this._stopHeartbeat();
        this.ws?.close(code, reason);
        console.log('🔌 主动关闭连接');
    }

    get readyState() { return this.ws?.readyState ?? WebSocket.CLOSED; }
    get isOpen() { return this.ws?.readyState === WebSocket.OPEN; }
}

// 使用示例
const ws = new ReconnectingWebSocket('wss://live.example.com/data');

ws.on('open', () => console.log('连接成功'));
ws.on('message', data => console.log('新消息:', data));
ws.on('close', e => console.log('连接断开:', e.code));
ws.on('error', err => console.error('错误:', err));

// 正常发送
ws.send({ action: 'subscribe', channel: 'news' });

// 即使当前未连接也会被缓冲
ws.send({ action: 'ping' });

// 稍后不再需要时
ws.close();   // 这不会触发重连
```

### 重连策略对比

| 策略 | 特点 | 适用场景 |
|------|------|---------|
| **固定间隔** | 每隔 N 秒重连一次 | 开发调试阶段 |
| **线性退避** | 每次增加固定的延迟 | 一般场景 |
| **指数退避** | 延迟按倍数增长 | 生产环境推荐 |
| **抖动（Jitter）** | 指数退避加随机偏移 | 高并发场景避免惊群效应 |

> **哲学思考**：WebSocket 的设计体现了**"信任但持续验证"**的工程哲学。不像 HTTP 请求那样每次交互都是独立的、短命的，WebSocket 是一种长期存在的、需要维护的关系——就像婚姻不同于约会。在这种长期关系中，你不能假设一切永远正常：连接可能会断、对方可能失联、中间链路可能出现问题。心跳机制就是对这种不确定性的应对——定期确认"我们还好吗"，而不是等到出了大事才发现问题。而重连机制则体现了一种韧性思维：失败不是终点，而是过程中的一个节点。好的系统能优雅地处理故障，从中恢复，继续运行。这不仅是技术层面的智慧，也是人生的态度。
