# TextEncoder / TextDecoder —— 字符串与二进制互转

计算机世界的底层只认识数字（0和1），但人类交流用的是字符和语言。**字符编码（Character Encoding）** 就是连接这两个世界的桥梁——它定义了"每个字符对应哪个数字"的映射规则。`TextEncoder` 和 `TextDecoder` 就是浏览器提供的这套编码转换工具，让 JavaScript 能够在字符串和二进制数据之间自由穿梭。

## 一、编码：为什么需要它？

当你写下 `const str = '你好'` 时，JavaScript 引擎内部用 UTF-16 编码来存储这些字符。但当你需要通过网络发送这些字符、写入 [ArrayBuffer](/40.frontend/50.javascript/20.browser-api/30.数据存储与二进制/175.ArrayBuffer与视图.md)、或者存入 [IndexedDB](/40.frontend/50.javascript/20.browser-api/30.数据存储与二进制/160.IndexedDB.md) 时，UTF-16 并不总是最佳选择：

- **网络传输通常使用 UTF-8**（更紧凑，ASCII 字符只占1字节）
- **某些 API 只接受 Uint8Array 或 ArrayBuffer**
- **WebSocket 发送二进制帧时需要编码后的字节数据**

这就是 `TextEncoder` 存在的意义——把 JavaScript 的内部字符串格式转换为通用的 UTF-8 字节序列。

```javascript
// 基本用法
const encoder = new TextEncoder();
const encoded = encoder.encode('Hello 你好');

console.log(encoded);              // Uint8Array(11) [72, 101, 108, 108, 111, 32, 228, 189, 160, 229, 165, 189]
console.log(encoded.byteLength);   // 11 字节

// 分析结果：
// 'H' → 72    (1字节 - ASCII)
// 'e' → 101   (1字节)
// 'l' → 108   (1字节)
// 'l' → 108   (1字节)
// 'o' → 111   (1字节)
// ' ' → 32    (空格, 1字节)
// '你' → [228, 189, 160]  (3字节 - UTF-8中文)
// '好' → [229, 165, 189]  (3字节 - UTF-8中文)

// 总计: 5×1 + 1×1 + 2×3 = 11 字节
```

### 生活类比：翻译官

TextEncoder 就像一位**从"人类语言"到"机器语言"的翻译官**：
- 你对他说一句中文（JavaScript 字符串），他把每个字翻译成机器能理解的数字编号（UTF-8 字节序列）。
- 这些数字编号可以写在任何地方——通过网络电缆传输、存进数据库、刻在光盘上。
- 接收端再用 TextDecoder（反向翻译官）把这些数字还原成人类可读的内容。

没有这位翻译官，不同系统之间的信息交换就会变成乱码——就像你给一个只懂英语的人写了一封中文信，对方只能看到一堆无法理解的天书。

## 二、TextEncoder 深入

### encode() 方法

```javascript
const encoder = new TextEncoder();

// 基础用法
const data = encoder.encode('Hello World');
// 返回值是 Uint8Array（不是纯数组，但可以迭代、slice 等）

// encode() 只有一个参数：要编码的字符串
// 它总是返回 UTF-8 编码的结果（这是不可配置的）

// 特殊情况处理
encoder.encode('');                    // Uint8Array(0) [] — 空字符串
encoder.encode('a');                   // Uint8Array(1) [97]
encoder.encode('🎉');                  // Uint8Array(4) [240, 159, 142, 141] — emoji占4字节
encoder.encode(null);                  // Uint8Array(4) [110, 117, 108, 108] — "null"
encoder.encode(undefined);             // Uint8Array(9) [117, 110, 100, ...] — "undefined"

// ⚠️ 注意：encode() 会把非字符串参数先 toString()
// 所以 encode(123) 实际上等于 encode("123")
```

### encodeInto() 方法：高性能流式编码

`encodeInto()` 是一个更底层的方法，允许你将字符串编码到一个**已有的缓冲区**中，避免每次都分配新内存：

```javascript
const encoder = new TextEncoder();

// 预分配一个大缓冲区用于多次编码
const buffer = new Uint8Array(1024);
let offset = 0;

function writeToBuffer(str) {
    const result = encoder.encodeInto(str, { buffer, written: offset });
    
    // result 结构:
    // {
    //   read: number      — 从源字符串读取了多少个码元(code unit)
    //   written: number   — 写入目标缓冲区了多少字节
    // }
    
    console.log(`编码了 ${result.read} 个字符，写入了 ${result.written} 个字节`);
    
    if (result.read < str.length) {
        throw new Error('缓冲区不足！字符串未完全编码');
    }
    
    offset = result.written;   // 更新偏移量供下次使用
}

writeToBuffer('First message');
writeToBuffer('Second message');

// buffer 前 N 个字节现在包含两条已编码的消息
const combinedData = buffer.slice(0, offset);
```

`encodeInto()` 在以下场景特别有用：
- **WebSocket 大量短消息拼接**：避免频繁 GC（垃圾回收）
- **Worker 线程中的批量处理**：复用同一个缓冲区
- **实现自定义协议的帧组装器**：精确控制内存布局

## 三、TextDecoder 深入

### decode() 方法

```javascript
const decoder = new TextDecoder();   // 默认 UTF-8

// 基础解码
const uint8 = new Uint8Array([72, 101, 108, 108, 111]);
const str = decoder.decode(uint8);   // 'Hello'

// 解码中文 (UTF-8 编码的字节)
const chineseBytes = new Uint8Array([228, 189, 160, 229, 165, 189]);
decoder.decode(chineseBytes);        // '你好'

// 解码 emoji
const emojiBytes = new Uint8Array([240, 159, 152, 141]);
decoder.decode(emojiBytes);         // '🔍'
```

### 支持多种编码格式

虽然 UTF-8 是现代 Web 的绝对主流，但 `TextDecoder` 也支持其他历史遗留编码：

```javascript
// GBK/GB2312 — 中文 Windows 系统常用
const gbkDecoder = new TextDecoder('gbk');
// ⚠️ 注意：不是所有浏览器都支持非UTF-8编码
// Chrome/Firefox 支持，Safari 支持有限

// Shift-JIS — 日文编码
const sjisDecoder = new TextDecoder('shift-jis');

// ISO-8859-1 — 西欧语言（Latin-1）
const latin1Decoder = new TextDecoder('iso-8859-1');

// 检查浏览器支持的编码
console.log(TextDecoder.supportedCodesOf('encoding'));
```

### 流式解码（stream 参数）

当一大块数据被分成多段到达时（比如 WebSocket 分片、[Fetch 流式响应](/40.frontend/50.javascript/20.browser-api/20.网络请求与实时通信/110.Fetch高级用法.md)），可以使用 `stream: true` 进行增量式解码：

```javascript
const decoder = new TextDecoder('utf-8', { fatal: false });

// 场景：一段 UTF-8 中文字符被切成了两半
// "你" 的 UTF-8 编码是 [0xE4, 0xBD, 0xA0]
// 如果第一次只收到了前两个字节...

const chunk1 = new Uint8Array([0xE4, 0xBD]);     // 不完整的"你"字
const chunk2 = new Uint8Array([0xA0, 0xE5, 0xA5, 0xBD]);  // 剩余 + "好"

// ❌ 普通解码会产生替换字符（�）
console.log(decoder.decode(chunk1));   // '�' （乱码！）

// ✅ 流式解码会缓存未完成的字节，等待后续数据
const streamDecoder = new TextDecoder('utf-8', { stream: true });

console.log(streamDecoder.decode(chunk1));   // '' （空！等待更多数据）
console.log(streamDecoder.decode(chunk2));   // '你好' （完整输出！）

// 重要：流式解码结束后要调用一次不带参数的 decode() 来刷新缓冲区
streamDecoder.decode();                     // 清空内部缓冲区
```

### 错误模式

```javascript
// 默认模式（非致命）：遇到无效字节时插入替换字符 U+FFFD (�)
const lenient = new TextDecoder('utf-8');
lenient.decode(new Uint8Array([0xFF]));   // '�' （不会抛错）

// 严格模式（fatal: true）：遇到无效字节直接抛出异常
const strict = new TextDecoder('utf-8', { fatal: true });
try {
    strict.decode(new Uint8Array([0xFF]));
} catch (err) {
    console.error('解码错误:', err.message);
    // "The encoded data was not valid for encoding utf-8"
}

// 什么时候用严格模式？
// 安全敏感场景（解析协议头、验证签名数据），
// 宁可报错也不能静默吞掉损坏的数据。
```

## 四、实战应用场景

### 场景1：WebSocket 二进制消息编解码

```javascript
class BinaryProtocol {
    constructor(ws) {
        this.ws = ws;
        this.decoder = new TextDecoder();
        this.encoder = new TextEncoder();
        this.partialBuffer = new Uint8Array(0);
    }

    // 发送结构化消息
    sendMessage(type, payload) {
        const header = this.encoder.encode(JSON.stringify({ type }));
        const body = this.encoder.encode(JSON.stringify(payload));
        
        // 自定义简单协议：[4字节长度][header][body]
        const totalLength = header.length + body.length;
        const lengthPrefix = new Uint8Array(4);
        new DataView(lengthPrefix.buffer).setUint32(0, totalLength, true);

        // 合并三个部分
        const frame = new Uint8Array(4 + totalLength);
        frame.set(lengthPrefix, 0);
        frame.set(header, 4);
        frame.set(body, 4 + header.length);

        this.ws.send(frame);
    }

    // 处理接收到的二进制数据（可能分片到达）
    onBinaryMessage(data) {
        // 将新数据追加到缓冲区
        const merged = new Uint8Array(this.partialBuffer.length + data.byteLength);
        merged.set(this.partialBuffer);
        merged.set(new Uint8Array(data), this.partialBuffer.length);
        this.partialBuffer = merged;

        // 尝试解析完整消息
        while (this.partialBuffer.length >= 4) {
            const msgLen = new DataView(
                this.partialBuffer.buffer,
                this.partialBuffer.byteOffset,
                4
            ).getUint32(0, true);

            if (this.partialBuffer.length < 4 + msgLen) break;   // 数据还不完整

            const headerStr = this.decoder.decode(
                this.partialBuffer.slice(4, 4 + msgLen)
            );
            
            const header = JSON.parse(headerStr);
            this.handleMessage(header);

            // 移除已处理的数据
            this.partialBuffer = this.partialBuffer.slice(4 + msgLen);
        }
    }

    handleMessage(header) {
        console.log('收到消息:', header.type);
        // 根据类型分发处理...
    }
}
```

### 场景2：文件哈希计算（结合 crypto.subtle）

```javascript
/**
 * 计算文件的 SHA-256 哈希值
 * @param {File} file 
 */
async function calculateFileHash(file) {
    const encoder = new TextEncoder();
    const decoder = new TextDecoder();

    // 读取文件为 ArrayBuffer
    const arrayBuffer = await file.arrayBuffer();
    
    // 使用 Web Crypto API 计算哈希
    const hashBuffer = await crypto.subtle.digest('SHA-256', arrayBuffer);
    
    // 将二进制哈希转为十六进制字符串
    const hashArray = Array.from(new Uint8Array(hashBuffer));
    const hashHex = hashArray.map(b => b.toString(16).padStart(2, '0')).join('');
    
    return hashHex;   // 类似 "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
}

// 使用示例
const hash = await calculateFileHash(selectedFile);
console.log(`文件 ${selectedFile.name} 的 SHA-256: ${hash}`);
```

### 场景3：Base64 与 ArrayBuffer 互转

```javascript
// 利用 TextEncoder 实现 Base64 编解码
function stringToBase64(str) {
    const bytes = new TextEncoder().encode(str);
    let binary = '';
    for (let i = 0; i < bytes.length; i++) {
        binary += String.fromCharCode(bytes[i]);
    }
    return btoa(binary);
}

function base64ToString(base64) {
    const binary = atob(base64);
    const bytes = new Uint8Array(binary.length);
    for (let i = 0; i < binary.length; i++) {
        bytes[i] = binary.charCodeAt(i);
    }
    return new TextDecoder().decode(bytes);
}

// 测试
const original = '你好，世界！Hello World!';
const encoded = stringToBase64(original);
console.log(encoded);           // '5L2g5aW977yM5LiW55qESGVsbG8gV29ybGQh'
const decoded = base64ToString(encoded);
console.log(decoded === original); // true
```

> **哲学思考**：编码问题是计算机科学中最古老也最容易被忽视的问题之一。1963 年 ASCII 标准定义了 128 个字符的编码方案，解决了英文字母和基本符号的问题——但它完全没有考虑世界上其他语言的数十亿使用者。后来出现的各种变长编码方案（UTF-8、GBK、Shift-JIS 等）本质上都是在做同一件事：**用有限的数字去表示无限的字符**。这是一个从有限集合映射到无限（或极大）集合的根本性挑战。TextEncoder/TextDecoder 的存在提醒我们：在这个互联互通的世界里，"正确地表达信息"和"表达正确的信息"同等重要。一条再有价值的信息，如果因为编码问题变成了乱码，它的价值就归零了。
