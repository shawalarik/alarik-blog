# localStorage/sessionStorage —— 容量、同步操作、存储事件

localStorage 和 sessionStorage 是 Web Storage API 提供的两个键值对存储接口。它们比 [Cookie](/40.frontend/50.javascript/20.browser-api/30.数据存储与二进制/190.Cookie详解.md) 容量大得多（约 5MB vs 4KB）、操作简单得多（同步 API vs 手动编码解析）、且不会随每个 HTTP 请求自动发送。对于需要在客户端持久化少量数据的场景，它们是最便捷的选择。

## 一、两个孪生兄弟的区别

localStorage 和 sessionStorage 共享完全相同的 API，唯一的区别在于**数据的生命周期和作用域范围**：

```javascript
// ===== 两者 API 完全相同 =====

// 存储
localStorage.setItem('key', 'value');
sessionStorage.setItem('key', 'value');

// 读取
const v1 = localStorage.getItem('key');
const v2 = sessionStorage.getItem('key');

// 删除单项
localStorage.removeItem('key');
sessionStorage.removeItem('key');

// 清空所有
localStorage.clear();
sessionStorage.clear();

// 获取 key 数量
console.log(localStorage.length);
console.log(sessionStorage.length);

// 按索引获取 key（遍历用）
console.log(localStorage.key(0));   // 第一个 key 的名字
```

### 生命周期的差异

| 特性 | localStorage | sessionStorage |
|------|-------------|----------------|
| **持久性** | 永久存储（除非手动或代码清除） | 仅在当前标签页会话期间有效 |
| **关闭标签页** | 数据保留 | **数据清除** |
| **关闭浏览器** | 数据保留 | 数据清除 |
| **重新打开浏览器** | 数据还在 | 数据没了 |
| **同源不同标签** | **共享同一份数据** | **各自独立的数据副本** |
| **新标签页打开同页面** | 能读取到之前存的数据 | 得到全新的空存储 |

```javascript
// 验证实验：在同源的两个标签页中进行

// 标签页 A：
localStorage.setItem('shared', '来自A');
sessionStorage.setItem('private', '来自A的私密数据');

// 标签页 B（同一 origin，新开的标签页）：
localStorage.getItem('shared');     // ✅ '来自A'  —— 共享！
sessionStorage.getItem('private'); // ❌ null      —— 读不到！B有自己的空间

// 这意味着 sessionStorage 天然具有"隔离性"——
// 不同标签页的操作互不干扰，适合存放临时状态
// 而 localStorage 是全局共享的——适合存放跨页面的用户偏好
```

### 生活类比：公共黑板 vs 便签纸

- **localStorage 就像办公室里的公共黑板**——你在上面写的字所有人（同一来源的所有标签页）都能看到，而且除非有人擦掉（clear/removeItem），否则它永远在那里。即使大家下班回家了（关闭浏览器），第二天来上班黑板上的字还在。

- **sessionStorage 就像贴在自己工位上的便签纸**——只有坐在你这个位置的人（当前标签页）能看到。一旦你下班离开（关闭标签页），保洁阿姨就会把便签纸全扔掉。隔壁同事（另一个标签页）有他自己的便签纸，你们互相看不到对方写了什么。

## 二、深入 API 细节

### 值的类型：永远是字符串

这是新手最容易踩坑的地方：

```javascript
// ⚠️ 存进去的和读出来的类型不一样！

localStorage.setItem('count', 42);
typeof localStorage.getItem('count');   // 'string' !! 不是数字

localStorage.setItem('flag', true);
typeof localStorage.getItem('flag');    // 'string' !! 不是布尔值

localStorage.setItem('obj', { a: 1 });
typeof localStorage.getItem('obj');     // 'string' !! 不是对象
localStorage.getItem('obj');           // '[object Object]'  💀

localStorage.setItem('arr', [1, 2, 3]);
localStorage.getItem('arr');            // '1,2,3'  (toString 了!)
```

### 正确的存取模式

```javascript
// ===== 封装安全的读写函数 =====

const storage = {
    // 写入：自动序列化复杂类型
    set(key, value) {
        const serialized = typeof value === 'string' 
            ? value 
            : JSON.stringify(value);
        localStorage.setItem(key, serialized);
    },

    // 读取：尝试反序列化
    get(key, fallback = null) {
        const raw = localStorage.getItem(key);
        if (raw === null) return fallback;

        try {
            return JSON.parse(raw);   // 尝试解析为对象/数组/数字/布尔
        } catch {
            return raw;               // 解析失败说明原本就是纯字符串
        }
    },

    // 删除
    remove(key) {
        localStorage.removeItem(key);
    }
};

// 使用 —— 类型安全多了
storage.set('user', { name: 'Alarik', level: 5 });
const user = storage.get('user');
console.log(user.name);   // 'Alarik'  ✓ 是对象

storage.set('score', 100);
const score = storage.get('score', 0);
console.log(score + 1);    // 101  ✓ 是数字

storage.set('token', 'eyJhbG...');
const token = storage.get('token');
console.log(token);         // 'eyJhbG...'  ✓ 是字符串（JSON.parse后仍是字符串）
```

### 容量限制与溢出处理

大多数浏览器给 localStorage 分配约 5MB 的空间（各浏览器略有差异）。超出限额时会抛出异常：

```javascript
// 检测剩余可用空间
function getRemainingSpace() {
    const testKey = '__space_test__';
    let data = 'x';
    
    try {
        // 不断加倍写入直到报错
        while (true) {
            localStorage.setItem(testKey, data);
            data += data;   // 指数增长
        }
    } catch (e) {
        localStorage.removeItem(testKey);
        // data.length / 2 ≈ 当前可用空间
        return { used: data.length / 2, unit: 'bytes' };
    }
}

// 安全写入（处理 quota exceeded 错误）
function safeLocalStorageSet(key, value) {
    try {
        localStorage.setItem(key, typeof value === 'string' ? value : JSON.stringify(value));
        return true;
    } catch (e) {
        if (e.name === 'QuotaExceededError' || 
            e.code === 22 || 
            e.message?.includes('quota')) {
            console.warn('localStorage 已满！');
            // 策略：清理旧数据后重试？
            // 或者降级到其他存储方式？
            return false;
        }
        throw e;
    }
}
```

## 三、storage 事件：跨标签通信

当 localStorage 的数据在一个标签页中被修改时，其他**同源的**标签页会收到 `storage` 事件通知。这是浏览器原生提供的跨标签页通信机制之一：

```javascript
// 标签页 A：监听变化
window.addEventListener('storage', (event) => {
    console.log('--- Storage Event ---');
    console.log('变化的 key:', event.key);          // 变化的键名
    console.log('旧值:', event.oldValue);           // 修改前的值（null表示新增）
    console.log('新值:', event.newValue);           // 修改后的值（null表示删除）
    console.log('来源:', event.storageArea === localStorage ? 'localStorage' : 'sessionStorage');
    console.log('来源页面URL:', event.url);          // 触发事件的页面地址
});

// 标签页 B：修改数据
localStorage.setItem('theme', 'dark');
// 标签页 A 会立即收到 storage 事件！
```

### 重要细节

```javascript
// ⚠️ 注意事项：

// 1. 当前页面自己的修改不会触发自身的事件！
//    只有其他标签页的修改才会被感知
localStorage.setItem('test', '1');
// 本页面绑定的 storage 监听器不会被触发

// 2. sessionStorage 的变化不会触发事件！
//    storage 事件仅对 localStorage 生效
sessionStorage.setItem('test', '1');
// 不会有任何事件

// 3. 事件只在同源（same-origin）的标签页间传播
//    不同域名/端口/协议的页面彼此隔离

// 4. oldValue/newValue 都是序列化后的字符串形式
```

### 实战：利用 storage 事件实现多标签同步

```javascript
/**
 * TabSync —— 多标签页状态同步器
 *
 * 使用场景：
 * - 用户在一个标签修改了主题设置 → 其他标签立即切换
 * - 用户在一处登出 → 所有标签显示登录页
 * - 购物车数量变化 → 各标签同步更新角标数字
 */

class TabSync {
    constructor(channel = 'default') {
        this.channel = channel;
        this.handlers = {};
        this._listen();
    }

    // 广播变更（写入 localStorage 触发其他标签的 storage 事件）
    broadcast(type, data) {
        const key = `tabsync_${this.channel}_${type}`;
        const value = JSON.stringify({ type, data, timestamp: Date.now() });

        try {
            localStorage.setItem(key, value);
            // 写完后立即清理（不需要持久化，只是借用它当信号发射器）
            setTimeout(() => localStorage.removeItem(key), 100);
        } catch (e) {
            console.warn('广播失败:', e);
        }
    }

    // 监听特定类型的广播
    on(type, handler) {
        if (!this.handlers[type]) this.handlers[type] = [];
        this.handlers[type].push(handler);
        return this;   // 支持链式调用
    }

    off(type, handler) {
        if (this.handlers[type]) {
            this.handlers[type] = this.handlers[type].filter(h => h !== handler);
        }
    }

    _listen() {
        window.addEventListener('storage', (event) => {
            // 过滤出属于本 channel 的 tabsync 消息
            if (!event.key?.startsWith(`tabsync_${this.channel}_`)) return;

            try {
                const msg = JSON.parse(event.newValue);
                const handlers = this.handlers[msg.type] || [];
                handlers.forEach(h => h(msg.data, msg.timestamp));
            } catch (e) {
                // 忽略非 tabsync 格式的 storage 变化
            }
        });
    }

    destroy() {
        this.handlers = {};
        // 注意：removeEventListener 需要引用原始函数，这里简化处理
    }
}

// ===== 使用示例 =====

// 在应用的入口文件中初始化
const sync = new TabSync('my-app');

// 场景1：主题切换同步
sync.on('theme-change', (newTheme) => {
    document.documentElement.setAttribute('data-theme', newTheme);
    console.log(`主题已同步切换为: ${newTheme}`);
});

// 某个组件中触发主题切换
function changeTheme(theme) {
    document.documentElement.setAttribute('data-theme', theme);
    sync.broadcast('theme-change', theme);   // 通知其他标签
}

// 场景2：登出同步
sync.on('logout', () => {
    window.location.href = '/login';
});

function logout() {
    clearAuthState();
    sync.broadcast('logout', {});
    window.location.href = '/login';
}
```

## 四、何时选择何者

面对具体的业务需求，如何在各种存储方案间做出选择：

```
决策流程：

需要存储数据吗？
│
├─ 需要 → 数据量多大？
│   ├─ 极小 (<4KB)，需要随请求自动发送？
│   │   └─ → Cookie（主要用于认证 Token）
│   │
│   ├─ 小 (~KB级)，纯键值对，需要跨标签共享？
│   │   └─ → localStorage（用户偏好、主题设置等）
│   │
│   ├─ 小 (~KB级)，仅在本次浏览会话中使用？
│   │   └─ → sessionStorage（表单草稿、临时状态）
│   │
│   ├─ 中~大（MB级），结构化数据？
│   │   └─ → IndexedDB（离线数据、大量记录）
│   │
│   └─ HTTP 响应/请求的缓存？
│       └─ → Cache API（PWA 禼线支持）
│
└─ 不需要 → 那就不存，用变量或闭包就好 😄
```

> **哲学思考**：Web 存储方案的发展史，就是一部**从"服务器中心"到"客户端自主"的权力转移史**。Cookie 是服务器塞给浏览器的"小抄条"——上面写着什么由服务器决定，什么时候拿出来也由服务器决定。localStorage 则把笔交给了前端开发者自己——你想写什么就写什么，想什么时候擦就什么时候擦。这种权力的下放伴随着责任的增加：你得自己管理数据的序列化、容量的监控、过期的清理。自由从来都不是免费的——你获得了灵活性，就必须承担维护成本。好的架构师知道在"方便但受限"（Cookie）和"灵活但需自理"（localStorage/IndexedDB）之间找到平衡点，而不是一味追求最新最酷的技术方案。
