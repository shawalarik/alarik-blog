# 安全头 —— Content-Security-Policy、Referrer-Policy、HSTS

## 为什么需要安全响应头

HTTP 响应头是服务器对浏览器说的"第一句话"。在页面内容到达之前，这些头部信息就已经告诉浏览器应该如何对待即将加载的内容。安全响应头，就是在这句话中注入的**安全指令**。

如果把 Web 应用比作一座建筑，那么安全响应头就像是门口的保安规则牌——在任何人进入之前，先告知哪些行为是被允许的，哪些是被禁止的。这比在建筑内部到处安装摄像头和报警器要有效得多。

**哲学思考**：安全响应头体现了"**默认拒绝（Deny by Default）**"的安全哲学。传统模式下，浏览器默认允许一切（执行任意脚本、发送 Cookie 到任何地方、被任意网站嵌入），然后开发者通过代码去限制。而安全响应头反转了这个逻辑——默认禁止一切，只明确开放必要的权限。这种思维方式的转变，比任何具体的技术细节都更有价值。

## Content Security Policy（CSP）

CSP 是最强大的安全头，它定义了一整套资源加载的白名单策略。

### CSP 指令全解

```http
Content-Security-Policy:
  default-src 'self';
  script-src 'self' https://cdn.example.com 'nonce-abc123';
  style-src 'self' 'unsafe-inline' https://fonts.googleapis.com;
  img-src 'self' data: https:;
  connect-src 'self' https://api.example.com;
  font-src 'self' https://fonts.gstatic.com;
  frame-ancestors 'none';
  base-uri 'self';
  form-action 'self';
  upgrade-insecure-requests;
  report-uri /csp-report;
```

逐条解析：

| 指令 | 控制范围 | 默认回退 | 说明 |
|------|---------|---------|------|
| `default-src` | 所有资源类型 | 无 | 其他指令未指定时的兜底 |
| `script-src` | JS 脚本 | default-src | 控制脚本来源 |
| `style-src` | CSS 样式 | default-src | 控制样式表来源 |
| `img-src` | 图片 | default-src | 控制图片来源 |
| `connect-src` | AJAX/WS/Fetch | default-src | 控制 API 请求目标 |
| `font-src` | 字体文件 | default-src | 控制字体来源 |
| `frame-src` | iframe | default-src | 控制 iframe 来源 |
| `media-src` | 音视频 | default-src | 控制多媒体来源 |
| `object-src` | 插件 | default-src | Flash/Java 等 |
| `frame-ancestors` | 嵌入者 | 无 | 谁可以嵌套当前页 |
| `base-uri` | `<base>` 标签 | 无 | 限制 URL 基准 |
| `form-action` | 表单提交目标 | 无 | 限制表单提交去向 |
| `plugin-types` | 插件类型 | 无 | 限制可加载的插件类型 |
| `report-uri` | 报告地址 | 无 | 违规时上报的 URL |

### CSP 的值语法

```javascript
// CSP 值可以是以下几种形式之一或组合：

// 1. 关键字
'default-src \'self\'';       // 仅允许同源
'default-src \'none\'';        // 禁止一切

// 2. 完整 URL
'script-src https://cdn.example.com';

// 3. 协议限定
'img-src https:';              // 允许所有 HTTPS 图片

// 4. 通配符（谨慎使用）
'img-src *.example.com';       // 所有子域名

// 5. nonce（一次性令牌）
'script-src \'nonce-aBc123XyZ\'';

// 6. hash（内容哈希）
'script-src \'sha256-B2yPHKaXnvFWtRChIbabYrUBCh7EFkYQV8UZ25dBiVE=\''

// 7. unsafe 关键字（降低安全性）
'style-src \'unsafe-inline\''; // 允许内联样式
'script-src \'unsafe-eval\'';  // 允许 eval() / Function()
```

### CSP 报告模式

在正式启用 CSP 之前，可以先使用 `Report-Only` 模式观察违规情况而不阻止：

```
Content-Security-Policy-Report-Only:
  default-src 'self';
  script-src 'self' https://untrusted-cdn.com;
  report-uri /api/csp-reports;
```

```javascript
// 服务端收集 CSP 违规报告
app.post('/api/csp-reports', (req, res) => {
  const report = req.body['csp-report'];

  console.warn('CSP 违规:', {
    blockedUri: report['blocked-uri'],
    violatedDirective: report['violated-directive'],
    documentUri: report['document-uri'],
    sourceFile: report['source-file'],
    lineNumber: report['line-number'],
  });

  // 存入数据库用于分析
  saveCspReport(report);

  res.status(204).end();
});
```

**哲学思考**：CSP 的设计体现了一种"**声明式安全**"的理念。与其用命令式代码去检查每一个操作是否安全，不如在一开始就声明什么被允许。这与函数式编程中纯函数的思想有异曲同工之妙——约束即自由，限制即保护。

## Referrer Policy

Referrer Policy 控制 HTTP 请求中 `Referer` 头部应该携带多少信息。

### 为什么重要？

Referer 头会暴露用户的浏览路径。比如从 `https://bank.com/account` 页面点击一个链接跳转到第三方站点，该站点的服务器就能从 Referer 中看到用户正在银行账户页面——这可能泄露敏感信息。

```
Referrer-Policy: strict-origin-when-cross-origin
```

### 可选策略对比

| 策略值 | 同源请求 | 跨源请求 | 降级 HTTPS → HTTP |
|--------|---------|---------|------------------|
| `no-referrer` | 不发送 | 不发送 | 不发送 |
| `no-referrer-when-downgrade` | **完整 URL** | **完整 URL** | 不发送 |
| `origin` | 仅 origin | 仅 origin | 仅 origin |
| `origin-when-cross-origin` | **完整 URL** | 仅 origin | 仅 origin |
| `same-origin` | **完整 URL** | 不发送 | 不发送 |
| `strict-origin` | 仅 origin | 仅 origin | 不发送 |
| `strict-origin-when-cross-origin` | **完整 URL** | 仅 origin | 不发送 |

```html
<!-- HTML 中设置 -->
<meta name="referrer" content="strict-origin-when-cross-origin">

<!-- 单个链接/元素级别设置 -->
<a href="https://example.com" referrerpolicy="no-referrer">隐私跳转</a>

<!-- JavaScript 中控制 -->
fetch('https://api.example.com/data', {
  referrerPolicy: 'no-referrer',
});
```

```javascript
/**
 * ReferrerPolicy 辅助类
 * 根据场景自动选择合适的策略
 */
const ReferrerConfig = {
  // 链接到外部站点时：隐藏完整路径
  externalLink: 'strict-origin-when-cross-origin',

  // 链接到支付等敏感服务时：完全不泄露
  sensitiveTarget: 'no-referrer',

  // 内部页面间导航：保留完整信息便于分析
  internalNavigation: 'no-referrer-when-downgrade',

  /**
   * 为给定 URL 自动选择最佳策略
   */
  pickStrategy(targetUrl) {
    const url = new URL(targetUrl);
    const currentOrigin = window.location.origin;

    if (url.origin === currentOrigin) {
      return this.internalNavigation;
    }

    // 已知的敏感域名
    const sensitiveDomains = ['bank.com', 'payment.', 'auth.'];
    if (sensitiveDomains.some(d => url.hostname.includes(d))) {
      return this.sensitiveTarget;
    }

    return this.externalLink;
  }
};
```

## HSTS（HTTP Strict Transport Security）

HSTS 强制浏览器只通过 HTTPS 与服务器通信，防止 SSL Stripping 攻击（中间人将 HTTPS 降级为 HTTP）。

```
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
```

### 各参数含义

| 参数 | 含义 | 示例 |
|------|------|------|
| `max-age` | 策略生效时长（秒） | `31536000` = 1 年 |
| `includeSubDomains` | 是否包含所有子域名 | 有此参数则子域名也强制 HTTPS |
| `preload` | 加入浏览器预载列表 | 提交到 hstspreload.org 后永久生效 |

```javascript
// Express 设置 HSTS
app.use(helmet.hsts({
  maxAge: 31536000,     // 365 天
  includeSubDomains: true,
  preload: true,         // 提交预载列表
}));

// 条件性启用：仅在生产环境且已配置 HTTPS 时
if (process.env.NODE_ENV === 'production' && app.get('env') === 'https') {
  app.use(helmet.hsts({ maxAge: 31536000 }));
}
```

**HSTS 的注意事项**：
- 一旦启用且设置了较长的 max-age，**回滚非常困难**
- 如果没有有效的 HTTPS 证书，用户在 max-age 期间无法访问你的网站
- `preload` 是不可逆的一旦加入浏览器预载列表，几乎无法移除

## 其他重要的安全响应头

### X-Content-Type-Options

防止浏览器 MIME 嗅探（MIME Sniffing）。某些浏览器会尝试猜测内容的实际类型，这可能被利用来执行 XSS：

```
X-Content-Type-Options: nosniff
```

```javascript
app.use(helmet.noSniff());
// 效果：浏览器严格按照 Content-Type 解析内容，
// 即使上传了 HTML 文件但声明为 text/plain，也不会当作 HTML 渲染
```

### X-XSS-Protection（已废弃）

曾经是浏览器内置的 XSS 过滤器，现代浏览器已弃用或将其设为默认行为。建议用 CSP 替代：

```
// 已废弃，不推荐使用
// X-XSS-Protection: 1; mode=block
```

### Permissions-Policy

控制浏览器功能 API 的可用性（前身是 Feature-Policy）：

```
Permissions-Policy: camera=(), microphone=(), geolocation=(self), payment=()
```

```javascript
// Express 中设置
app.use(helmet.permissionPolicy({
  features: [
    { name: 'camera', allow: [] },           // 禁用摄像头
    { name: 'microphone', allow: [] },       // 禁用麦克风
    { name: 'geolocation', allow: ['self'] },// 仅同源可用
    { name: 'payment', allow: [] },          // 禁用支付 API
    { name: 'interest-cohort', allow: [] },  // 禁用 FloC 广告追踪
  ],
}));
```

### Cross-Origin-Opener-Policy / Cross-Origin-Embedder-Policy

用于隔离跨源窗口共享组，配合 COOP/COEP 可以启用高性能特性（如 SharedArrayBuffer）：

```
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

## 综合安全头配置示例

```javascript
/**
 * 生产级安全头中间件集合
 * 使用 helmet.js 库一站式配置
 */

const express = require('express');
const helmet = require('helmet');

const app = express();

app.use(helmet({
  // Content Security Policy
  contentSecurityPolicy: {
    directives: {
      defaultSrc: ["'self'"],
      scriptSrc: ["'self'", () => `'nonce-${generateNonce()}'`],
      styleSrc: ["'self'", "'unsafe-inline'", 'fonts.googleapis.com'],
      imgSrc: ["'self'", 'data:', 'https:'],
      connectSrc: ["'self'", 'https://api.example.com'],
      fontSrc: ["'self'", 'fonts.gstatic.com'],
      objectSrc: ["'none'"],
      frameAncestors: ["'none'"],
      formAction: ["'self'"],
      upgradeInsecureRequests: [],
    },
  },

  // HSTS —— 仅在生产环境启用
  hsts: process.env.NODE_ENV === 'production'
    ? { maxAge: 31536000, includeSubDomains: true, preload: true }
    : false,

  // 其他安全头
  crossOriginResourcePolicy: { policy: 'same-site' },
  crossOriginEmbedderPolicy: false,  // 需要时手动启用
  noSniff: true,
  referrerPolicy: { policy: 'strict-origin-when-cross-origin' },
  permittedCrossDomainPolicies: false,

  // 权限策略
  permissionPolicy: {
    features: [
      { name: 'camera', allow: [] },
      { name: 'microphone', allow: [] },
      { name: 'geolocation', allow: ['self'] },
      { name: 'interest-cohort', allow: [] },
    ],
  },
}));

function generateNonce() {
  return crypto.randomBytes(16).toString('base64');
}

app.listen(3000);
```

**哲学思考**：安全响应头的存在提醒我们，Web 安全是分层的。应用层代码可以做到完美无缺，但如果传输层没有正确的头部指示，浏览器依然可能做出不安全的假设。每一层都有自己的职责，每一层的疏忽都可能成为整体安全的短板。就像一条锁链——强度取决于最薄弱的那一环。
