# 性能指标 —— FCP、LCP、FID、CLS、TTI

## 为什么性能指标重要

在 Web 开发中，性能不是一个抽象的概念，而是用户能否完成他们想做的事情的决定因素。Google 的研究表明：页面加载时间每增加 1 秒，转化率就会下降约 7%。但这不仅仅是数字的问题——**性能的本质是尊重用户的时间**。

想象你走进一家餐厅。如果等了三分钟还没人理你，你会开始烦躁。如果菜单上的图片加载了半天才显示出来，你对这道菜的食欲就已经减半了。Web 页面也是一样——每一次等待都在消耗用户的耐心和信任。性能优化的最终目的不是让数字好看，而是让**感知体验**变得流畅自然。

## Core Web Vitals 概览

Google 定义了三个核心 Web 性能指标（Core Web Vitals），它们分别衡量了用户体验的三个维度：

| 指标 | 全称 | 衡量维度 | 好的阈值 | 需要改进 |
|------|------|---------|---------|---------|
| **LCP** | Largest Contentful Paint | **加载性能** | ≤ 2.5s | > 4.0s |
| **FID** | First Input Delay | **交互性** | ≤ 100ms | > 300ms |
| **CLS** | Cumulative Layout Shift | **视觉稳定性** | ≤ 0.1 | > 0.25 |

这三个指标覆盖了用户从打开页面到完成交互的全过程——就像评价一家餐厅要从"入座速度"、"点菜响应"和"上菜稳定性"三个方面综合打分。

## LCP（最大内容绘制）

LCP 衡量的是视口内**最大的可见元素**完成渲染的时间。"最大"通常指占据面积最大的图片、视频、`<blockquote>` 或带有背景图的区块。

```javascript
/**
 * 使用 PerformanceObserver 观察 LCP
 */
function observeLCP() {
  const lcpObserver = new PerformanceObserver((list) => {
    const entries = list.getEntries();
    const lastEntry = entries[entries.length - 1];

    console.log('LCP:', lastEntry.startTime, 'ms');
    console.log('LCP 元素:', lastEntry.element);
    console.log('LCP 尺寸:', lastEntry.size, 'px');

    // 发送到监控系统
    sendToAnalytics({
      metric: 'LCP',
      value: Math.round(lastEntry.startTime),
      element: lastEntry.element?.tagName,
      url: lastEntry.url,
    });
  });

  // 观察类型为 "largest-contentful-paint" 的条目
  lcpObserver.observe({ type: 'largest-contentful-paint', buffered: true });
}

observeLCP();
```

### 影响 LCP 的常见因素

1. **服务器响应时间慢**（TTFB 过长）
2. **CSS/JS 阻塞渲染**
3. **资源加载时间过长**
4. **客户端渲染（CSR）导致内容延迟出现**

```javascript
/**
 * LCP 优化策略清单及实现示例
 */

// 策略一：预加载关键资源
// <link rel="preload" as="image" href="/hero-image.webp">

// 策略二：优化关键 CSS，减少渲染阻塞
// 将首屏必需的内联到 <style> 标签中

// 策略三：使用 content-visibility 优化离屏内容
.offscreen-content {
  content-visibility: auto;
  contain-intrinsic-size: 0 500px; /* 预估高度防止布局偏移 */
}

// 策略四：确保 LCP 元素的图片优先级最高
const heroImage = document.querySelector('.hero-image');
if (heroImage) {
  heroImage.fetchPriority = 'high';  // 浏览器原生优先级提示
  heroImage.loading = 'eager';       // 对关键图片禁用懒加载
}
```

## FID（首次输入延迟）

FID 衡量从用户**第一次交互**（点击链接、点击按钮等）到浏览器**真正开始处理**该交互的时间间隔。它反映的是主线程是否被繁忙的任务阻塞了。

```javascript
/**
 * 使用 PerformanceObserver 观察 FID
 * 注意：FID 只在用户有交互时才有值
 */
function observeFID() {
  const fidObserver = new PerformanceObserver((list) => {
    const firstEntry = list.getEntries()[0];

    console.log('FID:', firstEntry.processingStart - firstEntry.startTime, 'ms');

    sendToAnalytics({
      metric: 'FID',
      value: Math.round(firstEntry.processingStart - firstEntry.startTime),
      name: firstEntry.name,
      startTime: firstEntry.startTime,
    });
  });

  fidObserver.observe({ type: 'first-input', buffered: true });
}

observeFID();

/**
 * FID 的替代指标：INP (Interaction to Next Paint)
 * Google 计划用 INP 替代 FID，因为它衡量所有交互而非仅首次
 */
function observeINP() {
  if (!PerformanceObserver.supportedEntryTypes.includes('event')) return;

  const inpObserver = new PerformanceObserver((list) => {
    for (const entry of list.getEntries()) {
      console.log(`交互类型: ${entry.name}`);
      console.log(`持续时间: ${entry.duration.toFixed(2)} ms`);
      console.log(`处理延迟: ${(entry.processingStart - entry.startTime).toFixed(2)} ms`);
    }
  });

  inpObserver.observe({ type: 'event', buffered: true });
}
```

### 降低 FID 的方法

FID 高的根本原因是**主线程忙**。当用户点击时，JavaScript 正在执行长任务，浏览器的交互事件只能排队等待：

```javascript
// ❌ 长任务阻塞主线程 —— 导致高 FID
function processData(data) {
  // 同步处理 10 万条数据，耗时数百毫秒
  for (let i = 0; i < data.length; i++) {
    heavyCalculation(data[i]);
  }
}

// ✅ 使用 requestIdleCallback / 时间分片
function processInChunks(data, chunkSize = 1000) {
  let index = 0;

  function processChunk() {
    const chunkEnd = Math.min(index + chunkSize, data.length);
    for (; index < chunkEnd; index++) {
      heavyCalculation(data[index]);
    }

    if (index < data.length) {
      // 让出主线程，给用户交互的机会
      requestAnimationFrame(processChunk);
    }
  }

  requestAnimationFrame(processChunk);
}

// ✅ 使用 Web Worker 将重计算移出主线程
const worker = new Worker('heavy-worker.js');

worker.postMessage(largeDataSet);

worker.onmessage = (e) => {
  // 处理完成，更新 UI
  renderResults(e.data);
};

// 主线程保持空闲 → 用户交互立即响应 → FID 极低
```

## CLS（累积布局偏移）

CLS 衡量页面加载过程中**视觉稳定性**的程度。简单来说就是：页面的内容会不会突然跳动？按钮会不会在你正要点的时候突然移位？

```javascript
/**
 * 使用 PerformanceObserver 计算 CLS
 */
function observeCLS() {
  let clsValue = 0;
  let sessionValue = 0;
  let sessionEntries = [];

  const clsObserver = new PerformanceObserver((list) => {
    for (const entry of list.getEntries()) {
      // 只有用户未滚动时发生的偏移才计入 CLS
      if (!entry.hadRecentInput) {
        const firstSessionEntry = sessionEntries[0];
        const lastSessionEntry = sessionEntries[sessionEntries.length - 1];

        // 如果条目与上一个间隔超过 1 秒或超过 5 秒，
        // 则开始新的 session
        if (sessionValue &&
            entry.startTime - lastSessionEntry.startTime > 1000 &&
            entry.startTime - firstSessionEntry.startTime < 5000) {
          sessionValue += entry.value;
          clsValue += sessionValue;
          sessionValue = 0;
          sessionEntries = [];
        } else if (
          !sessionValue ||
          entry.startTime - firstSessionEntry.startTime >= 5000
        ) {
          sessionValue = entry.value;
        } else {
          sessionValue += entry.value;
        }

        sessionEntries.push(entry);
        clsValue += entry.value;

        console.log('CLS 更新:', clsValue.toFixed(4));
      }
    }
  });

  clsObserver.observe({ type: 'layout-shift', buffered: true });
}

observeCLS();
```

### 导致 CLS 的常见原因和修复

```html
<!-- ❌ 动态插入内容导致下方元素被挤走 -->
<div class="container">
  <img src="photo.jpg" onload="this.style.display='block'" style="display:none">
  <!-- 图片加载后突然显示，下面的文字向下移动 -->
  <p>这段文字会突然跳一下</p>
</div>

<!-- ✅ 为动态内容预留空间 -->
<div class="container">
  <!-- 明确设置宽高，即使图片未加载也不会发生偏移 -->
  <img src="photo.jpg" width="800" height="600"
       style="aspect-ratio: 4/3; background: #eee;">
  <p>位置稳定，不会跳动</p>
</div>

<!-- ✅ 使用 font-display: swap 时预留字体空间 -->
<style>
  .text-block {
    font-family: 'CustomFont', sans-serif;
    /* 为字体交换预留空间 */
    min-height: 1em;
  }
</style>
```

```css
/* ✅ 更多防抖动技巧 */

/* 1. 为广告位预留空间 */
.ad-slot {
  min-height: 250px;
  min-width: 300px;
}

/* 2. 使用 transform 而非改变布局属性做动画 */
.animate-element {
  /* transform 不触发布局重排 */
  transform: translateX(100px);
  transition: transform 0.3s ease;

  /* ❌ 这会触发布局变化 */
  /* left: 100px; margin-left: 100px; */
}

/* 3. 插入内容前先占位 */
.insertion-point::after {
  content: '';
  display: block;
  height: 0; /* 内容到来时只需改高度 */
}
```

## 其他重要指标

### FCP（首次内容绘制）

FCP 是用户看到**任何可见内容**的时间点，比 LCP 更早，代表"页面开始有东西了"：

```javascript
function observeFCP() {
  const observer = new PerformanceObserver((list) => {
    const entries = list.getEntriesByName('first-contentful-paint');
    if (entries.length > 0) {
      console.log('FCP:', entries[0].startTime, 'ms');
    }
  });
  observer.observe({ type: 'paint', buffered: true });
}
```

### TTI（可交互时间）

TTI 衡量页面从开始加载到**能够可靠地响应用户输入**所需的时间：

```javascript
/**
 * TTI 的计算逻辑（简化版）
 * 需要 polyfill: tti-polyfill
 */
import { getTTI } from 'tti-polyfill';

getTTI().then((tti) => {
  console.log('TTI:', tti, 'ms');

  sendToAnalytics({
    metric: 'TTI',
    value: Math.round(tti),
  });
});
```

### TBT（总阻塞时间）

TBT 衡量 FCP 到 TTI 之间**主线程被阻塞的总时长**。它是影响 FID 的直接因素：

```javascript
/**
 * 使用 Long Task API 监测长任务（>50ms）
 * 长任务是 TBT 和高 FID 的元凶
 */
function observeLongTasks() {
  if (!('PerformanceLongTaskTiming' in window)) return;

  const observer = new PerformanceObserver((list) => {
    for (const entry of list.getEntries()) {
      const duration = entry.duration;
      console.warn(`检测到长任务: ${duration.toFixed(0)}ms`, entry.name);

      // 超过 200ms 的任务需要重点关注
      if (duration > 200) {
        reportLongTask({
          duration,
          attribution: entry.attribution?.[0]?.name,
          startTime: entry.startTime,
        });
      }
    }
  });

  observer.observe({ entryTypes: ['longtask'] });
}
```

## 综合性能采集器

```javascript
/**
 * Web Vitals 统一采集工具
 * 一站式收集所有 Core Web Vitals 指标
 */
class VitalCollector {
  constructor(options = {}) {
    this.reportUrl = options.reportUrl || '/api/vitals';
    this.sampleRate = options.sampleRate || 1;  // 采样率
    this.metrics = {};
  }

  init() {
    this.observeLCP();
    this.observeFID();
    this.observeCLS();
    this.observeFCP();
    this.observeTTFB();
    this.observeINP();
  }

  observeLCP() {
    const handler = (entry) => {
      this.saveMetric('LCP', entry.startTime);
    };
    // LCP 可能在页面隐藏前发生变化
    // 所以需要在 visibilitychange 中重新取最新值
    document.addEventListener('visibilitychange', () => {
      if (document.visibilityState === 'hidden') {
        handler(performance.getEntriesByName('largest-contentful-paint').pop());
      }
    });
  }

  observeFID() {
    new PerformanceObserver((list) => {
      const entry = list.getEntries()[0];
      this.saveMetric('FID', entry.processingStart - entry.startTime);
    }).observe({ type: 'first-input', buffered: true });
  }

  observeCLS() {
    let clsValue = 0;
    new PerformanceObserver((list) => {
      for (const entry of list.getEntries()) {
        if (!entry.hadRecentInput) {
          clsValue += entry.value;
        }
      }
      this.saveMetric('CLS', clsValue);
    }).observe({ type: 'layout-shift', buffered: true });
  }

  observeFCP() {
    new PerformanceObserver((list) => {
      for (const entry of list.getEntries()) {
        if (entry.name === 'first-contentful-paint') {
          this.saveMetric('FCP', entry.startTime);
        }
      }
    }).observe({ type: 'paint', buffered: true });
  }

  observeTTFB() {
    const navEntry = performance.getEntriesByType('navigation')[0];
    if (navEntry) {
      this.saveMetric('TTFB', navEntry.responseStart - navEntry.requestStart);
    }
  }

  observeINP() {
    if (!PerformanceObserver.supportedEntryTypes.includes('event')) return;
    new PerformanceObserver((list) => {
      const entries = list.getEntries();
      // 取 p90 最差交互
      entries.sort((a, b) => b.duration - a.duration);
      this.saveMetric('INP', entries[0]?.duration ?? 0);
    }).observe({ type: 'event', buffered: true });
  }

  saveMetric(name, value) {
    this.metrics[name] = Math.round(value || 0);
  }

  /**
   * 页面卸载时发送所有收集到的指标
   * 使用 sendBeacon 确保数据不丢失
   */
  flush() {
    if (Math.random() > this.sampleRate) return;

    navigator.sendBeacon(
      this.reportUrl,
      JSON.stringify({
        url: location.href,
        ua: navigator.userAgent,
        timestamp: Date.now(),
        ...this.metrics,
      })
    );
  }
}

// 初始化
const collector = new VitalCollector({
  reportUrl: '/api/web-vitals',
  sampleRate: 0.5,  // 采样 50%
});

collector.init();

// 页面离开时上报
document.addEventListener('visibilitychange', () => {
  if (document.visibilityState === 'hidden') {
    collector.flush();
  }
});
```

**哲学思考**：性能指标的终极意义不在于数字本身，而在于它迫使我们建立一种**以用户为中心的思维模式**。我们不再问"代码跑得有多快"，而是问"用户什么时候能看到有用的内容"、"什么时候能进行操作"、"操作过程中会不会遇到干扰"。这种视角的转变，比任何具体的优化技术都更有价值。
