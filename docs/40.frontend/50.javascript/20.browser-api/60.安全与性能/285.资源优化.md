# 资源优化 —— 图片懒加载、字体优化、代码分割

## 图片懒加载

图片通常是 Web 页面中体积最大的资源。一个页面可能包含几十张图片，如果一次性全部加载，不仅浪费带宽，还会严重拖慢首屏渲染时间。

**懒加载（Lazy Loading）** 的核心思想很简单：**只加载用户当前能看到的东西，其他的等到需要时再加载**。

这就像去图书馆借书——你不会把整座图书馆的书都搬回家，而是只取你此刻要读的那一本。等读完这本，再去取下一本。懒加载就是这种"按需获取"的策略在浏览器中的实现。

### 原生 lazy 属性

现代浏览器原生支持 `loading="lazy"` 属性，使用极为简单：

```html
<!-- 立即加载 —— 关键内容（如首屏 hero 图） -->
<img src="/hero.webp" alt="首屏大图" loading="eager" width="1200" height="600">

<!-- 懒加载 —— 非关键内容 -->
<img src="/photo-1.jpg" loading="lazy" alt="照片1" width="800" height="600">
<img src="/photo-2.jpg" loading="lazy" alt="照片2" width="800" height="600">
<img src="/photo-3.jpg" loading="lazy" alt="照片3" width="800" height="600">

<!-- iframe 也支持懒加载 -->
<iframe src="https://example.com/embed"
        loading="lazy"
        title="嵌入式内容">
</iframe>
```

**重要细节**：`loading="lazy"` 需要配合 `width` 和 `height` 属性使用。没有明确尺寸的图片在加载时会导致布局偏移（CLS 升高），因为浏览器不知道该为这张图预留多大的空间。

### IntersectionObserver 实现自定义懒加载

对于更精细的控制场景（如渐进式模糊加载、骨架屏替换），可以使用 `IntersectionObserver`：

```javascript
/**
 * 高级图片懒加载器
 * 支持多种特性：
 * - 自定义根边距（提前/延后触发）
 * - 加载状态回调
 * - 占位图 / 骨架屏
 * - 渐进式显示效果
 */
class LazyImageLoader {
  constructor(options = {}) {
    this.rootMargin = options.rootMargin || '200px';   // 提前 200px 触发
    this.threshold = options.threshold || 0;            // 元素刚出现时触发
    this.placeholder = options.placeholder || null;
    this.onLoad = options.onLoad || null;
    this.onError = options.onError || null;

    this.observer = new IntersectionObserver(
      (entries) => this._handleIntersection(entries),
      {
        rootMargin: this.rootMargin,
        threshold: this.threshold,
      }
    );
  }

  /**
   * 注册需要懒加载的元素
   * @param {HTMLElement|HTMLElement[]} elements 目标元素
   */
  observe(elements) {
    const list = Array.isArray(elements) ? elements : [elements];

    list.forEach(el => {
      if (el.dataset.src) {
        // 设置占位
        if (this.placeholder) {
          el.src = this.placeholder;
          el.style.backgroundColor = '#f0f0f0';
        }
        this.observer.observe(el);
      }
    });
  }

  _handleIntersection(entries) {
    entries.forEach(entry => {
      if (!entry.isIntersecting) return;

      const img = entry.target;
      const src = img.dataset.src;

      // 停止观察——只需加载一次
      this.observer.unobserve(img);

      // 开始加载真实图片
      this._loadImage(img, src);
    });
  }

  _loadImage(img, src) {
    // 创建预加载图片对象检测加载结果
    const preloader = new Image();
    preloader.onload = () => {
      img.src = src;
      img.classList.add('loaded');
      this.onLoad?.(img, src);
    };
    preloader.onerror = () => {
      img.classList.add('error');
      img.alt = '图片加载失败';
      this.onError?.(img, src);
    };
    preloader.src = src;
  }

  /** 停止所有观察 */
  disconnect() {
    this.observer.disconnect();
  }
}

// ====== 使用示例 ======

const loader = new LazyImageLoader({
  rootMargin: '300px',         // 提前 300px 就开始加载
  placeholder: 'data:image/svg+xml,...', // 极小的占位 SVG
  onLoad: (img, src) => {
    console.log('图片加载完成:', src);
  },
});

// 自动注册页面上所有带 data-src 的图片
loader.observe(document.querySelectorAll('img[data-src]'));
```

```css
/* 配合 CSS 实现渐入效果 */
img[data-src] {
  opacity: 0;
  transition: opacity 0.4s ease-in;
}

img.loaded {
  opacity: 1;
}
```

### 渐进式图片加载

对于高质量图片，可以先用低质量占位图（LQIP），然后平滑过渡到高清版本：

```javascript
/**
 * 渐进式图片加载 —— LQIP + 模糊到清晰
 */
function progressiveLoad(imgElement, lowSrc, highSrc) {
  // 第一阶段：显示低质量模糊图
  imgElement.src = lowSrc;
  imgElement.style.filter = 'blur(20px)';
  imgElement.style.transition = 'filter 0.6s ease';

  // 第二阶段：后台加载高清图
  const hdImage = new Image();
  hdImage.onload = () => {
    // 第三阶段：切换到高清图并移除模糊
    imgElement.src = highSrc;
    requestAnimationFrame(() => {
      imgElement.style.filter = 'blur(0)';
    });
  };
  hdImage.src = highSrc;
}

// 使用
progressiveLoad(
  document.querySelector('.hero-image'),
  '/images/hero-blur-tiny.jpg',  // ~2KB 模糊缩略图
  '/images/hero-hd.webp'          // ~50KB 高清原图
);
```

## 字体优化

Web 字体是影响 FCP 和 CLS 的隐形杀手。字体文件未加载完成时，浏览器要么显示空白（FOIT），要么用系统字体临时替代再闪烁切换（FLOC）。两种情况都会损害体验。

### font-display 策略

```css
@font-face {
  font-family: 'CustomFont';
  src: url('/fonts/custom.woff2') format('woff2');
  font-weight: 400;
  font-display: swap; /* 最推荐 */
}
```

`font-display` 有四种策略：

| 策略 | 行为 | 适用场景 |
|------|------|---------|
| `auto` | 浏览器默认行为 | 不推荐，各浏览器不一致 |
| `block` | 短暂阻塞（通常 3s），然后 swap | 品牌标识必须用指定字体时 |
| **`swap`** | **立即用系统字体显示，下载完成后替换** | **大多数场景的首选** |
| `optional` | 只在极短时间内尝试加载，超时就永久放弃 | 对字体要求不严格的场景 |
| `fallback` | 约 100ms 阻塞，然后 swap，但有一个短交换期 | 折中方案 |

```javascript
/**
 * 字体加载监控与回退处理
 * 使用 Document.fonts API 监控字体加载状态
 */
class FontOptimizer {
  constructor() {
    this.fonts = document.fonts;
  }

  /**
   * 监控特定字体的加载状态
   */
  async monitorFont(fontFamily, timeout = 3000) {
    const status = await Promise.race([
      this.fonts.load(`16px "${fontFamily}"`),
      new Promise((resolve) =>
        setTimeout(() => resolve('timeout'), timeout)
      ),
    ]);

    if (status === 'timeout') {
      console.warn(`字体 ${fontFamily} 加载超时`);
      document.body.classList.add(`${fontFamily}-fallback`);
    } else {
      console.log(`字体 ${fontFamily} 加载成功`);
      document.body.classList.add(`${fontFamily}-loaded`);
    }

    return status;
  }

  /**
   * 批量预加载关键字体
   */
  preloadCriticalFonts(fontList) {
    fontList.forEach(({ family, weight, style }) => {
      const link = document.createElement('link');
      link.rel = 'preload';
      link.as = 'font';
      link.type = 'font/woff2';
      link.href = `/fonts/${family}-${weight || 'regular'}.woff2`;
      link.crossOrigin = 'anonymous';
      document.head.appendChild(link);
    });
  }
}

const fontOpt = new FontOptimizer();

// 预加载首屏所需的关键字体
fontOpt.preloadCriticalFonts([
  { family: 'HeadingFont', weight: '700' },
  { family: 'BodyFont', weight: '400' },
]);

// 监控非关键字体的加载
fontOpt.monitorFont('DecorativeFont', 5000);
```

### 减少 FOIT/FOUT 的技巧

```css
/* 为字体交换预留空间，防止布局偏移 */
.title-text {
  /* 使用近似值匹配目标字体的度量 */
  font-family: 'CustomFont', -apple-system, sans-serif;
  /* 明确的尺寸和行高 */
  font-size: clamp(1.5rem, 4vw, 3rem);
  line-height: 1.2;
  /* 最小高度防抖动 */
  min-height: 1.2em;
}

/* 字体加载中/失败时的降级样式 */
body.CustomFont-fallback .title-text {
  /* 使用系统字体时的微调 */
  letter-spacing: -0.02em;
}
```

## 代码分割

代码分割（Code Splitting）是将打包后的 JavaScript 分成多个较小的 bundle，按需加载。这是减少初始加载体积最有效的手段之一。

想象搬家：你可以把所有东西塞进一辆卡车一次性运走（慢、费力），也可以分批运送，先搬必需品入住，其余的慢慢搬过来（快、灵活）。代码分割就是后者。

### 动态 import()

ES2020 标准化的动态 `import()` 是代码分割的核心 API：

```javascript
// ❌ 静态导入 —— 全部打包进主 bundle
import { HeavyComponent } from './HeavyComponent.js';

// ✅ 动态导入 —— 独立成一个 chunk，按需加载
async function showHeavyFeature() {
  const module = await import('./HeavyComponent.js');
  const { HeavyComponent } = module;

  const instance = new HeavyComponent();
  instance.render(document.getElementById('app'));
}

// 用户点击按钮时才加载
document.getElementById('load-feature').addEventListener(
  'click',
  showHeavyFeature
);
```

### 路由级代码分割

单页应用中最常见的分割方式是按路由拆分——每个路由对应的组件独立打包：

```javascript
/**
 * 路由级懒加载封装
 * 支持自动加载指示器和错误处理
 */

class RouteLazyLoader {
  /**
   * 创建懒加载路由组件工厂
   */
  static load(importFn, options = {}) {
    const {
      loader = () => {},     // 加载中的 UI
      error = () => <div>加载失败</div>,  // 错误 UI
      delay = 200,           // 显示 loader 的延迟时间
      timeout = 10000,       // 超时时间
    } = options;

    return async (...args) => {
      let component;

      try {
        // 带超时的 import
        component = await Promise.race([
          importFn(),
          new Promise((_, reject) =>
            setTimeout(() => reject(new Error('Import timeout')), timeout)
          ),
        ]);
      } catch (err) {
        console.error('路由模块加载失败:', err);
        return error(err);
      }

      return component.default?.(...args) ?? component?.(...args);
    };
  }
}

// 使用示例：定义路由表
const routes = {
  home: () => import('./pages/HomePage.js'),
  dashboard: () => import('./pages/Dashboard.js'),
  settings: () => import('./pages/SettingsPage.js'),
  report: () => import('./pages/ReportPage.js'),
};

// 导航函数
async function navigateTo(routeName) {
  showLoadingIndicator();

  try {
    const pageFactory = routes[routeName];
    if (!pageFactory) throw new Error(`Route not found: ${routeName}`);

    const module = await pageFactory();
    const Page = module.default;
    render(new Page());
  } catch (err) {
    showErrorPage(err);
  } finally {
    hideLoadingIndicator();
  }
}
```

### 组件级细粒度分割

除了路由级别，大型组件内部也可以进一步拆分：

```javascript
/**
 * 细粒度懒加载工具
 * 用于条件性渲染的大型子组件
 */
function createLazyComponent(importFn, fallbackUI = null) {
  let cachedModule = null;

  return async function(props) {
    // 缓存已加载的模块
    if (!cachedModule) {
      cachedModule = await importFn();
    }

    const Component = cachedModule.default;
    return Component ? <Component {...props} /> : fallbackUI;
  };
}

// 在应用中使用
const LazyChart = createLazyComponent(
  () => import('./components/HeavyChart.js'),
  () => <div className="chart-skeleton" />
);

const LazyEditor = createLazyComponent(
  () => import('./components/RichEditor.js')
);

// Dashboard 页面
function Dashboard() {
  return (
    <main>
      <section>概览数据...</section>
      {/* 只有滚动到这里才加载图表 */}
      <Suspense fallback={<ChartSkeleton />}>
        <LazyChart data={chartData} />
      </Suspense>
      {/* 只有点击"编辑"才加载编辑器 */}
      {isEditing && (
        <Suspense fallback={<div>编辑器加载中...</div>}>
          <LazyEditor content={docContent} />
        </Suspense>
      )}
    </main>
  );
}
```

**哲学思考**：代码分割的本质是对**依赖图的重新审视和重组**。传统的打包思维是"把所有东西绑在一起"，而分割思维是"理解每个模块被需要的时机"。这不仅是技术上的优化决策，更是对产品功能的深度理解——哪些功能是核心路径？哪些是锦上添花？哪些是少数用户才会触及的角落？好的架构不是让所有代码都跑得快，而是让**重要的代码先跑起来**。
