# 代码分割 —— 动态导入、预加载、prefetch/preload

## 为什么需要代码分割

一个典型的现代前端应用打包后可能产生数兆字节的 JavaScript 代码。如果一次性全部加载，用户需要等待很长时间才能看到任何内容——首屏体验极差。

代码分割的核心思想很简单：**不需要立即使用的代码，推迟加载**。

想象搬家时的策略：你可以租一辆大卡车把所有东西一次性运走（慢且贵），也可以分批用小车运送，先把床铺和日用品送到新家入住，其余的家具慢慢搬过来。代码分割就是这种"分批运送"的策略——优先保证核心功能可用，次要内容按需到达。

## 入手点分割（Vendor Splitting）

最基础的分割方式是将第三方库（vendor）和应用代码分离：

```javascript
// webpack.config.js
module.exports = {
  optimization: {
    splitChunks: {
      chunks: 'all',  // 同步 + 异步代码都参与分割
      cacheGroups: {
        // React 生态系统
        react: {
          test: /[\\/]node_modules[\\/](react|react-dom|react-router)[\\/]/,
          name: 'vendor-react',
          priority: 20,
        },

        // UI 组件库
        ui: {
          test: /[\\/]node_modules[\\/](@ant-design|element-plus|mui)[\\/]/,
          name: 'vendor-ui',
          priority: 15,
        },

        // 工具库
        utils: {
          test: /[\\/]node_modules[\\/](lodash-es|dayjs|axios)[\\/]/,
          name: 'vendor-utils',
          priority: 10,
        },

        // 其余 node_modules
        vendors: {
          test: /[\\/]node_modules[\\/]/,
          name: 'vendor-others',
          priority: 5,

          // 复用已有 chunk（如果体积太小则不单独生成）
          reuseExistingChunk: true,
          minSize: 20000,           // 最小 20KB 才单独成块
          maxSize: 244000,          // 超过 240KB 尝试二次拆分
        },
      },
    },
  },
};

// 构建产物示例：
//   vendor-react.xxxx.js    (~45 KB gzipped)
//   vendor-ui.xxxx.js        (~120 KB gzipped)
//   vendor-utils.xxxx.js    (~25 KB gzipped)
//   vendor-others.xxxx.js    (~30 KB gzipped)
//   main.xxxxx.js            (应用主代码)
```

### SplitChunks 参数详解

| 参数 | 含义 | 推荐值 |
|------|------|--------|
| `chunks: 'all'` | 同步 + 异步都参与分割 | 推荐 `'all'` |
| `minSize` | chunk 最小尺寸（字节） | `20000`（约 20KB） |
| `maxSize` | 超过此值尝试进一步拆分 | `244000`（约 240KB） |
| `maxAsyncRequests` | 并行异步加载的最大数量 | `6` |
| `maxInitialRequests` | 入口点并行加载的最大数量 | `4` |
| `reuseExistingChunk` | 复用已有的 chunk | `true` |
| `priority` | cacheGroup 的优先级 | 数值越大越优先 |

## 动态导入（Dynamic Import）

动态 `import()` 是实现运行时代码分割的核心 API：

```javascript
/**
 * 路由级代码分割 —— SPA 中最常见的用法
 */

// ❌ 静态导入 —— 全部打包进主 bundle
import DashboardPage from './pages/DashboardPage';

// ✅ 动态导入 —— 独立成 chunk，按需加载
const DashboardPage = lazy(() =>
  import(/* webpackChunkName: "dashboard" */ './pages/DashboardPage')
);

function App() {
  return (
    <Routes>
      <Route path="/" element={<HomePage />} />
      <Route
        path="/dashboard"
        element={
          <Suspense fallback={<DashboardSkeleton />}>
            <DashboardPage />
          </Suspense>
        }
      />
      {/* 更多路由... */}
    </Routes>
  );
}
```

### 魔法注释（Magic Comments）

魔法注释告诉打包工具如何处理动态导入产生的 chunk：

```javascript
// webpackChunkName —— 自定义 chunk 名称
import(/* webpackChunkName: "feature-chart" */ './ChartComponent');

// webpackPrefetch —— 浏览器空闲时预获取（下一个路由可能用到）
import(
  /* webpackPrefetch: true, webpackChunkName: "next-page" */
  './NextPage'
);

// webpackPreload —— 当前导航需要的，与父 chunk 并行加载
import(
  /* webpackPreload: true, webpackChunkName: "critical-sub" */
  './CriticalSubComponent'
);

// webpackMode: lazy —— 默认行为，每个 import() 产生独立 chunk
import(/* webpackMode: "lazy" */ './Modal');

// webpackMode: eager —— 立即包含在父 chunk 中但不执行
import(/* webpackMode: "eager" */ './Polyfill');

// Vite 也支持类似的注释语法
import(
  /* @vite-ignore */  // Vite 忽略此 import 的分析
  './dynamic-module'
);
```

## Prefetch vs Preload

这两个概念容易混淆，但用途完全不同：

```html
<!--
  preload：当前导航必需的资源，高优先级并行下载
  使用场景：当前页面即将用到的关键资源

  prefetch：未来可能需要的资源，低优先级空闲时下载
  使用场景：用户下一步可能访问的页面
-->
```

```javascript
/**
 * Prefetch / Preload 决策辅助工具
 * 根据用户行为预测性加载资源
 */
class ResourcePreloader {
  constructor() {
    this.prefetchedUrls = new Set();
    this.preloadedUrls = new Set();
  }

  /**
   * 预获取（低优先级）—— 用于下一页面的资源
   * 浏览器空闲时才下载，不会影响当前页面的性能
   */
  prefetch(url) {
    if (this.prefetchedUrls.has(url)) return;

    const link = document.createElement('link');
    link.rel = 'prefetch';
    link.href = url;
    link.as = this._guessAs(url);
    document.head.appendChild(link);
    this.prefetchedUrls.add(url);
  }

  /**
   * 预加载（高优先级）—— 用于当前页面马上要用到的资源
   * 与当前页面其他重要资源竞争带宽
   */
  preload(url) {
    if (this.preloadedUrls.has(url)) return;

    const link = document.createElement('link');
    link.rel = 'preload';
    link.href = url;
    link.as = this._guessAs(url);
    document.head.appendChild(link);
    this.preloadedUrls.add(url);
  }

  /**
   * 根据用户鼠标悬停预取链接目标
   * 这是性价比最高的 prefetch 策略之一
   */
  setupLinkHoverPrefetch(thresholdMs = 150) {
    let timerId = null;

    document.querySelectorAll('a[data-prefetch]').forEach(link => {
      link.addEventListener('mouseenter', () => {
        // 延迟一小段时间，避免快速划过触发不必要的请求
        timerId = setTimeout(() => {
          this.prefetch(link.href);
        }, thresholdMs);
      });

      link.addEventListener('mouseleave', () => {
        clearTimeout(timerId);
      });
    });
  }

  _guessAs(url) {
    if (/\.(js|mjs)(\?.*)?$/i.test(url)) return 'script';
    if (/\.css(\?.*)?$/i.test(url)) return 'style';
    if (/\.(woff2?|ttf|otf)/i.test(url)) return 'font';
    if (/\.(png|jpe?g|webp|gif)/i.test(url)) return 'image';
    return undefined;  // 让浏览器自己判断
  }
}

// ====== 使用 ======
const preloader = new ResourcePreloader();

// 导航链接悬停预取
preloader.setupLinkHoverPrefetch(200);

// 首屏渲染后预取其他路由
window.requestIdleCallback?.(() => {
  preloader.prefetch('/static/js/dashboard.chunk.js');
  preloader.prefetch('/static/js/settings.chunk.js');
}, { timeout: 3000 });
```

## 实际场景中的分割策略

```javascript
/**
 * 分割策略矩阵 —— 不同类型代码的最佳实践
 */

const splittingStrategies = {
  // ====== 1. 第三方库（几乎不变，适合长期缓存）=====
  vendor: {
    target: 'node_modules',
    strategy: 'splitChunks cacheGroup',
    reason: '独立缓存，用户升级后只需重新下载变化的 app chunk',
    config: {
      test: /[\\/]node_modules[\\/]/,
      name: 'vendor',
      chunks: 'all',
    },
  },

  // ====== 2. 页面级路由（用户导航时按需加载）=====
  routes: {
    target: 'pages/*',
    strategy: 'dynamic import()',
    reason: '首屏只加载当前页面，其余延迟',
    example: `const Page = lazy(() => import('./pages/About'))`,
  },

  // ====== 3. 大型组件（条件渲染或滚动可见时加载）=====
  heavyComponents: {
    target: 'Editor, Chart, MonacoEditor 等',
    strategy: 'dynamic import() + IntersectionObserver',
    reason: '这些组件可能很大（>100KB），不应阻塞初始渲染',
    example: `
      const LazyMonaco = lazy(() => import('monaco-editor'));
      // 进入可视区域时加载
    `,
  },

  // ====== 4. Polyfill（按需注入）=====
  polyfills: {
    target: 'core-js, regenerator-runtime',
    strategy: 'import() with feature detection',
    reason: '现代浏览器不需要 polyfill，不要浪费带宽',
    example: `
      if (!IntersectionObserver) {
        await import('intersection-observer');
      }
    `,
  },

  // ====== 5. 国际化语言包（只加载当前语言）=====
  i18n: {
    target: 'locales/*.json',
    strategy: 'dynamic import based on user language',
    reason: '中文用户不需要英文语言包',
    example: `
      const messages = await import(\`./locales/${lang}.json\`);
    `,
  },

  // ====== 6. 权限相关功能（根据角色加载）=====
  roleBased: {
    target: 'admin-panel, editor-tools',
    strategy: 'conditional dynamic import',
    reason: '普通用户不需要管理后台的代码',
    example: `
      if (user.role === 'admin') {
        const AdminPanel = await import('./admin/Panel');
      }
    `,
  },
};
```

**哲学思考**：代码分割的本质是一种**时间换空间**的策略——用稍长的总加载时间换取更短的感知等待时间。这不是免费的午餐——更多的 HTTP 请求意味着更多的开销，过多的碎片 chunk 可能适得其反。好的分割策略是在"颗粒度太粗（bundle 太大）"和"颗粒度太细（请求太多）"之间找到平衡点。就像切蛋糕——每一块都应该大小适中，既能一口吃掉又不会噎着。
