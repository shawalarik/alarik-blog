# 环境变量 —— process.env、.env 文件、跨平台兼容

## 什么是环境变量

环境变量是运行程序时从外部传入的配置信息——它们不是写在代码里的硬编码值，而是由部署环境决定的动态值。同一个代码库，在开发环境连接本地数据库，在测试环境连接测试服务器，在生产环境连接生产集群。切换环境的唯一操作就是改变环境变量的值。

这就像一家连锁餐厅：菜谱（代码）完全一样，但每家店的食材供应商（API 地址）、厨师数量（并发配置）、营业时间（超时设置）都不同。这些差异不需要修改菜谱本身，只需要在开店前告诉店长今天的"环境参数"是什么。

## .env 文件

前端项目中最常见的环境变量管理方式是 `.env` 文件：

```bash
# .env —— 基础配置（所有环境共享）
VITE_APP_TITLE=My Awesome App
VITE_API_BASE_URL=/api
VITE_ENABLE_ANALYTICS=false

# .env.development —— 开发环境专用
VITE_API_BASE_URL=http://localhost:8080/api
VITE_DEBUG_MODE=true
VITE_MOCK_API=true

# .env.production —— 生产环境专用
VITE_API_BASE_URL=https://api.example.com
VITE_DEBUG_MODE=false
VITE_MOCK_API=false
VITE_SENTRY_DSN=https://xxx@sentry.io/123

# .env.local —— 本地覆盖（不提交到 git）
# .gitignore 中应包含 .env.local
VITE_API_BASE_URL=http://my-dev-server:3000/api
```

**命名约定**：大多数构建工具要求客户端可访问的环境变量必须以特定前缀开头。Vite 中是 `VITE_`，Create React App 中是 `REACT_APP_`，Next.js 中是 `NEXT_PUBLIC_`。这个设计是有意为之的——防止开发者不小心将敏感信息（如 API 密钥）暴露到客户端代码中。

### 加载优先级

当多个文件中定义了同名变量时，加载优先级为：

```
.env.local          ← 最高（本地覆盖）
.env.[mode]         ← 模式特定（如 development/production）
.env                ← 基础配置（最低）

# 具体示例（mode = development 时）：
#
# 1. .env.local 中的 VITE_API_BASE_URL → 最先采用
# 2. .env.development 中的 VITE_API_BASE_URL → 其次
# 3. .env 中的 VITE_API_BASE_URL → 兜底
```

```javascript
// ====== 使用方式 ======

// 在 Vite 项目中：
const apiUrl = import.meta.env.VITE_API_BASE_URL;
const isDev = import.meta.env.DEV;
const isProd = import.meta.env.PROD;
const appTitle = import.meta.env.VITE_APP_TITLE;

// 注意：没有 VITE_ 前缀的环境变量在客户端代码中无法访问！
// console.log(import.meta.env.SECRET_KEY);  // undefined

// 在 Node.js / Webpack 项目中：
const apiUrl = process.env.API_BASE_URL;
const nodeEnv = process.env.NODE_ENV;
```

## 跨平台兼容性

环境变量在不同操作系统上的处理方式存在细微但致命的差异：

```javascript
/**
 * 跨平台环境变量处理工具
 * 解决 Windows / Linux / macOS 的不一致问题
 */

// 问题一：路径分隔符
// Windows: C:\Users\name\project
// Linux/macOS: /home/name/project
//
// 解决：使用 path 模块或 path.posix
import path from 'path';
import pathPosix from 'path/posix';

const configPath = pathPosix.join('config', 'settings.json');
// 无论什么系统，输出都是 'config/settings.json'

// 问题二：环境变量赋值语法
// Windows (CMD): set FOO=bar
// Windows (PowerShell): $env:FOO="bar"
// Linux/macOS: export FOO=bar
//
// 解决：使用 cross-env 包
// package.json:
//   "scripts": {
//     "build": "cross-env NODE_ENV=production vite build"
//   }

// 问题三：换行符差异
// Windows: \r\n
// Others: \n
//
// 解决：读取 .env 文件时统一处理
function parseDotEnv(content) {
  const result = {};
  
  content.split('\n').forEach(line => {
    // 移除 \r 和首尾空白
    line = line.trim().replace(/\r$/, '');
    
    // 跳过注释和空行
    if (!line || line.startsWith('#')) return;

    const eqIndex = line.indexOf('=');
    if (eqIndex === -1) return;

    const key = line.slice(0, eqIndex).trim();
    let value = line.slice(eqIndex + 1).trim();

    // 处理引号包裹的值
    if ((value.startsWith('"') && value.endsWith('"')) ||
        (value.startsWith("'") && value.endsWith("'"))) {
      value = value.slice(1, -1);
    }

    // 处理转义字符和变量引用
    value = value
      .replace(/\\n/g, '\n')
      .replace(/\$\{(\w+)\}/g, (_, varName) => process.env[varName] || '');

    result[key] = value;
  });

  return result;
}
```

### dotenv 的使用

Node.js 服务端项目中，`dotenv` 是加载 `.env` 文件的标配：

```javascript
// server/index.js
import dotenv from 'dotenv';
import path from 'path';
import { fileURLToPath } from 'url';

const __dirname = path.dirname(fileURLToPath(import.meta.url));

// 按顺序加载多个 .env 文件
dotenv.config({ path: path.resolve(__dirname, '.env.local') });
dotenv.config({ path: path.resolve(__dirname, '.env') });

// 访问环境变量
console.log(process.env.PORT);        // 3000
console.log(process.env.DATABASE_URL); // postgresql://...

/**
 * 类型安全的环境变量访问器
 * 确保必需的环境变量存在且格式正确
 */
class EnvConfig {
  constructor() {
    this._cache = {};
  }

  /**
   * 获取字符串类型的环境变量（必需）
   */
  get(key) {
    const val = process.env[key];
    if (val === undefined || val === '') {
      throw new Error(`Missing required env variable: ${key}`);
    }
    return this._cache[key] ??= val; // 缓存结果
  }

  /**
   * 获取可选的环境变量
   */
  getOptional(key, defaultValue = '') {
    return this._cache[key] ??= process.env[key] ?? defaultValue;
  }

  /**
   * 获取数字类型的环境变量
   */
  getNumber(key) {
    const raw = this.get(key);
    const num = Number(raw);
    if (isNaN(num)) throw new Error(`Env ${key} must be a number, got: ${raw}`);
    return num;
  }

  /**
   * 获取布尔类型的环境变量
   */
  getBoolean(key) {
    const raw = this.get(key).toLowerCase();
    if (!['true', 'false', '1', '0'].includes(raw)) {
      throw new Error(`Env ${key} must be boolean, got: ${raw}`);
    }
    return raw === 'true' || raw === '1';
  }

  /**
   * 获取 URL 类型的环境变量并验证格式
   */
  getUrl(key) {
    const raw = this.get(key);
    try {
      new URL(raw);
      return raw;
    } catch {
      throw new Error(`Env ${key} must be a valid URL, got: ${raw}`);
    }
  }

  /** 验证所有必需的环境变量是否存在 */
  validate(requiredKeys) {
    const missing = requiredKeys.filter(k => !process.env[k]);
    if (missing.length > 0) {
      throw new Error(
        `Missing environment variables: ${missing.join(', ')}. ` +
        `Please check your .env file or environment configuration.`
      );
    }
  }
}

// 使用
const env = new EnvConfig();

try {
  env.validate(['DATABASE_URL', 'JWT_SECRET', 'PORT']);

  const dbUrl = env.getUrl('DATABASE_URL');
  const port = env.getNumber('PORT');
  const debug = env.getBoolean('DEBUG_MODE');
  const logLevel = env.getOptional('LOG_LEVEL', 'info');

  // 启动应用...
  startServer({ port, dbUrl, logLevel, debug });

} catch (err) {
  console.error('[Config Error]', err.message);
  process.exit(1);
}
```

## 安全注意事项

**最重要的原则：不要将敏感信息暴露到前端代码中。**

```javascript
// ✅ 安全：服务端使用的环境变量（不会进入浏览器 bundle）
const DB_PASSWORD = process.env.DB_PASSWORD;
const JWT_SECRET = process.env.JWT_SECRET;
const STRIPE_SECRET_KEY = process.env.STRIPE_SECRET_KEY;

// ⚠️ 危险但有前缀限制：以 VITE_ 开头的变量会注入客户端
const PUBLIC_API_URL = import.meta.env.VITE_API_BASE_URL;
const SENTRY_DSN = import.meta.env.VITE_SENTRY_DSN;
// 这些值会出现在最终的 JS 文件中！任何人都可以在 DevTools 中看到！

// ❌ 绝对禁止：将密钥放入客户端环境变量
// VITE_STRIPE_SECRET=sk_live_xxxxxx  ← 这等于把钥匙贴在门上！
```

```bash
# .env.example —— 提交给版本控制作为模板
# 不包含真实值，仅展示需要哪些变量

# 应用名称
VITE_APP_TITLE=Your App Name

# API 地址（不含密钥）
VITE_API_BASE_URL=/api

# Sentry 错误追踪（公开 DSN 可以暴露）
VITE_SENTRY_DSN=

# ====== 服务端专用（不要加 VITE_ 前缀）=====
# 数据库连接
DATABASE_URL=
REDIS_URL=

# JWT 密钥
JWT_SECRET=

# 第三方服务密钥
STRIPE_SECRET_KEY=
AWS_ACCESS_KEY_ID=
AWS_SECRET_ACCESS_KEY=
```

**哲学思考**：环境变量体现了 **12-Factor App** 方法论的核心思想之一——**配置与代码分离**。代码不应该因为部署环境的不同而改变，改变的应该只是配置。这种分离不仅让同一份代码可以无缝运行在任何环境中，更重要的是它强制开发者在编写代码时就思考"哪些东西是变化的"、"哪些东西是固定的"。好的架构设计往往源于对"变与不变"的深刻理解。
