# 开发服务器 —— 代理、热更新、Mock API

## 开发服务器的价值

开发服务器（Dev Server）是前端工程师日常工作中接触最频繁的工具。它不仅仅是一个静态文件服务器——它是连接源码和浏览器的桥梁，提供实时预览、热模块替换、API 代理等一系列让开发体验流畅的功能。

想象你在画室里画画。每画一笔，你都要走到窗边看看效果——这太慢了。如果有一面镜子能让你在作画的同时看到完整的画面呢？这就是开发服务器的意义：**消除"修改→保存→刷新→等待"这个循环中的摩擦力**。

## 热模块替换（HMR）

HMR（Hot Module Replacement）是开发服务器的核心能力——在应用运行时替换、添加或删除模块，**无需刷新整个页面**。

### HMR 的基本原理

```
1. 开发者修改了某个文件
   ↓
2. Dev Server 监听文件变化 → 编译变更的模块
   ↓
3. 通过 WebSocket 通知浏览器："模块 X 发生了变化"
   ↓
4. 浏览器中的 HMR runtime 接收通知
   ↓
5. HMR runtime 下载新的模块代码
   ↓
6. 执行模块的热替换逻辑：
   - 如果该模块有自定义 HMR 处理函数 → 调用它
   - 否则 → 尝试向上冒泡到父模块处理
   - 如果都无法处理 → 触发整页刷新
```

```javascript
// Vite 中使用 HMR 的方式

// 方式一：框架自动处理（React Fast Refresh / Vue HMR）
// 大多数情况下你不需要写任何 HMR 相关的代码
// 框架会自动处理组件级别的热更新

// 方式二：手动接受 HMR 更新
import { useState } from 'react';

let counter = 0;

export function useCounter() {
  const [count, setCount] = useState(counter);
  return { count, increment: () => setCount(c => c + 1) };
}

// HMR 边界 —— 当此模块被更新时执行
if (import.meta.hot) {
  import.meta.hot.accept((newModule) => {
    // 保留当前状态，仅替换逻辑
    counter = newModule.counter ?? counter;
    console.log('[HMR] Counter module updated, state preserved');
  });
}
```

### HMR 与整页刷新的区别

| 维度 | 整页刷新 | HMR |
|------|---------|-----|
| 状态保留 | ❌ 全部丢失 | ✅ 可选择性保留 |
| 体验 | 白屏闪烁 | 无缝过渡 |
| 速度 | 秒级（重新加载所有资源） | **毫秒级**（只替换变化的模块） |
| 适用场景 | CSS 变更、路由级变更 | 组件/函数/样式微调 |
| 复杂度 | 无 | 需要正确处理状态 |

## API 代理

开发过程中，前端和后端通常运行在不同的端口上（如前端 `localhost:3000`，后端 `localhost:8080`）。跨域问题随之而来。开发服务器通过**代理**解决这个问题：

```javascript
// vite.config.js
export default defineConfig({
  server: {
    port: 3000,
    proxy: {
      // 简单代理：将 /api 请求转发到后端
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true,
        // 重写路径：/api/users → http://localhost:8080/users
        rewrite: (path) => path.replace(/^\/api/, ''),
      },

      // 多路径代理
      '/auth': {
        target: 'http://auth-service:4000',
        changeOrigin: true,
      },

      // WebSocket 代理
      '/socket.io': {
        target: 'http://localhost:9000',
        ws: true,
      },

      // 条件性代理（通过函数控制）
      '/dynamic-api': {
        target: 'http://backend:5000',
        configure: (proxy, options) => {
          proxy.on('proxyReq', (proxyReq, req) => {
            // 动态添加请求头
            if (req.headers['x-custom-token']) {
              proxyReq.setHeader('Authorization', `Bearer ${req.headers['x-custom-token']}`);
            }
          });
        },
      },

      // 绕过代理（本地静态资源）
      '^/local-assets': false,
    },
  },
});
```

```javascript
/**
 * 高级代理配置 —— 带认证和环境感知
 */
export default defineConfig({
  server: {
    proxy: createProxyConfig(),
  },
});

function createProxyConfig() {
  const env = loadEnv(process.env.NODE_ENV, process.cwd(), '');

  return {
    '/api': {
      target: env.VITE_API_TARGET || 'http://localhost:8080',
      changeOrigin: true,
      rewrite: (path) => path.replace(/^\/api/, ''),

      // 错误处理
      onError(err, req, res) {
        console.error('Proxy error:', err.message);
        res.writeHead(502, { 'Content-Type': 'application/json' });
        res.end(JSON.stringify({ error: 'Backend unavailable', code: 'PROXY_ERROR' }));
      },

      // 自定义响应处理
      configure(proxy) {
        proxy.on('proxyRes', (proxyRes) => {
          // 记录后端响应时间
          proxyRes.headers['x-proxy-timestamp'] = Date.now();
        });
      },
    },
  };
}
```

## Mock API

在后端接口尚未就绪时，Mock API 让前端可以独立进行开发和调试：

### 方式一：简单拦截（Vite Mock 插件）

```javascript
// vite.config.js
import { viteMockServe } from 'vite-plugin-mock';

export default defineConfig({
  plugins: [
    viteMockServe({
      mockPath: './mock',
      localEnabled: true,        // 开发环境启用
      prodEnabled: false,        // 生产环境禁用
      injectCode: `
        import { mockXHR } from '../mock/_util';
        mockXHR();
      `,
    }),
  ],
});
```

```javascript
// mock/user.js
export default [
  // 获取用户列表
  {
    url: '/api/users',
    method: 'get',
    response: ({ query }) => {
      const page = Number(query.page || 1);
      const size = Number(query.size || 10);

      return {
        code: 200,
        data: {
          list: Array.from({ length: size }, (_, i) => ({
            id: (page - 1) * size + i + 1,
            name: `用户${(page - 1) * size + i + 1}`,
            email: `user${i}@example.com`,
          })),
          pagination: { page, size, total: 100 },
        },
      };
    },
  },

  // 创建用户
  {
    url: '/api/users',
    method: 'post',
    response: ({ body }) => ({
      code: 200,
      data: { id: Date.now(), ...body, createdAt: new Date().toISOString() },
    }),
  },

  // 模拟错误场景
  {
    url: '/api/users/:id',
    method: 'delete',
    statusCode: 403,  // 返回 403 状态码
    response: () => ({
      code: 403,
      message: '无权删除此用户',
    }),
  },
];
```

### 方式二：MSW（Mock Service Worker）

MSW 在 Service Worker 层面拦截请求，可以用于开发和测试两种环境：

```javascript
// mocks/browser.ts —— 客户端 mock（开发模式）
import { setupWorker, rest } from 'msw';

const worker = setupWorker(
  // 用户信息接口
  rest.get('/api/user/profile', (req, res, ctx) => {
    const authHeader = req.headers.get('authorization');

    if (!authHeader) {
      return res(ctx.status(401), ctx.json({
        error: '未授权',
        message: '请先登录',
      }));
    }

    return res(
      ctx.delay(300),           // 模拟网络延迟
      ctx.json({
        id: 1,
        name: '测试用户',
        avatar: 'https://example.com/avatar.jpg',
        role: 'admin',
      })
    );
  }),

  // 文件上传接口
  rest.post('/api/upload', async (req, res, ctx) => {
    const formData = await req.formData();
    const file = formData.get('file') as File;

    return res(ctx.json({
      url: `https://cdn.example.com/uploads/${file.name}`,
      size: file.size,
      type: file.type,
    }));
  }),

  // 动态响应（根据请求参数返回不同数据）
  rest.get('/api/products', (req, res, ctx) => {
    const category = req.url.searchParams.get('category');
    const products = generateProducts(category);

    return res(ctx.json(products));
  })
);

// 启动
worker.start({ onUnhandledRequest: 'bypass' });

function generateProducts(category?: string) {
  const base = category ? `${category}-商品` : '通用商品';
  return Array.from({ length: 20 }, (_, i) => ({
    id: i + 1,
    name: `${base}-${i + 1}`,
    price: Math.floor(Math.random() * 10000) / 100,
    stock: Math.floor(Math.random() * 100),
  }));
}
```

```javascript
// main.tsx —— 入口文件中条件性启动 MSW
async function bootstrap() {
  if (import.meta.env.DEV && import.meta.env.VITE_MOCK_API === 'true') {
    const { worker } = await import('./mocks/browser');
    await worker.start({ onUnhandledRequest: 'bypass' });
    console.log('[MSW] Mock Service Worker 已启动');
  }

  ReactDOM.createRoot(document.getElementById('root')!)
    .render(<App />);
}

bootstrap();
```

**哲学思考**：Mock API 的价值不仅在于"后端还没做好时前端可以先干活"。更深层的意义在于它实现了**前后端并行开发的可能性**——双方只需要约定好接口格式（契约），就可以各自独立推进。这种基于契约的开发模式（Contract-First Development）是提升团队效率的关键策略之一。当 Mock 足够真实时，前端甚至可以在没有后端的情况下完成全部功能开发和验收。
