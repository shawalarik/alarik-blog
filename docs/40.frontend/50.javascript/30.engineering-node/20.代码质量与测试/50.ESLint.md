# ESLint —— 规则、插件、配置、--fix

## ESLint 是什么

ESLint 是 JavaScript/TypeScript 的静态分析工具——它在代码**运行之前**就找出潜在问题。不是运行时抛出的错误，而是通过词法分析和 AST（抽象语法树）遍历来发现模式层面的问题。

想象一个严格的编辑在阅读你的文章。他不仅检查拼写和语法，还会指出"这里用词不够精确"、"那里句子结构可以优化"、"这个段落逻辑有漏洞"。他不会帮你写内容，但会确保你写的内容符合既定的风格和质量标准。ESLint 就是代码世界的这位编辑。

## 核心概念

### 规则（Rules）

规则是 ESLint 的最小检测单元。每条规则检测一种特定的代码模式：

```javascript
// .eslintrc.js
module.exports = {
  rules: {
    // 错误级别：0=off, 1=warn, 2=error
    'no-unused-vars': 'error',        // 禁止定义未使用的变量
    'no-console': 'warn',             // console 语句警告
    'prefer-const': 'error',          // 应该用 const 的地方不能用 let
    'eqeqeq': ['error', 'always'],    // 必须使用 === 而非 ==
    'no-var': 'error',                // 禁止使用 var
    'curly': 'error',                 // 所有控制语句必须使用花括号
    'no-duplicate-imports': 'error',  // 禁止重复导入

    // 带选项的规则
    'max-len': ['warn', {
      code: 100,           // 单行最大 100 字符
      tabWidth: 2,
      ignoreComments: true,
      ignoreStrings: true,
      ignoreTemplateLiterals: true,
    }],

    'complexity': ['warn', { max: 15 }],   // 函数圈复杂度不超过 15
    'max-depth': ['warn', { max: 4 }],     // 嵌套深度不超过 4 层
  },
};
```

规则的三个严重等级决定了它如何影响构建流程：

| 级别 | 关键字 | 效果 |
|------|--------|------|
| `off` | `0` | 完全关闭此规则 |
| `warn` | `1` | 输出警告，但不阻止构建 |
| `error` | `2` | 报错，可配合 `--max-warnings=0` 阻断构建 |

### 插件（Plugins）

ESLint 本身只包含基础规则。插件扩展了它的能力范围，使其能够理解框架特有语法、检测特定模式的反模式：

```javascript
// .eslintrc.js
module.exports = {
  // React 相关规则
  plugins: [
    'react',                    // eslint-plugin-react
    'react-hooks',              // eslint-plugin-react-hooks
    '@typescript-eslint',       // @typescript-eslint/eslint-plugin
    'import',                   // eslint-plugin-import
    'unicorn',                  // eslint-plugin-unicorn（更好的实践）
  ],

  extends: [
    'eslint:recommended',                        // 内置推荐规则集
    'plugin:react/recommended',                  // React 推荐配置
    'plugin:react-hooks/recommended',            // React Hooks 规则
    'plugin:@typescript-eslint/recommended',     // TypeScript 推荐
    'plugin:@typescript-eslint/recommended-requiring-type-checking',
    'plugin:import/errors',                      // import 错误级规则
    'plugin:import/warnings',                    // import 警告级规则
    'plugin:import/typescript',                  // TS 项目中的 import 规则
  ],

  rules: {
    // 覆盖继承的规则
    'react/react-in-jsx-scope': 'off',         // React 17+ 不再需要
    'react/prop-types': 'off',                  // 使用 TypeScript 后不需要 prop-types
    '@typescript-eslint/no-explicit-any': 'warn', // any 类型警告而非报错
    '@typescript-eslint/no-unused-vars': ['error', { argsIgnorePattern: '^_' }],
    
    // import 规则细化
    'import/order': ['error', {
      groups: ['builtin', 'external', 'internal', 'parent', 'sibling', 'index'],
      'newlines-between': 'never',
      alphabetize: { order: 'asc', caseInsensitive: true },
    }],
    'import/no-duplicates': 'error',
    'import/no-cycle': ['error', { maxDepth: 3 }],
  },

  settings: {
    react: { version: 'detect' },               // 自动检测 React 版本
    'import/resolver': {
      typescript: true,                          // 支持 TypeScript 路径解析
      node: true,
    },
  },
};
```

### 配置文件层级

ESLint 支持多层配置合并，优先级从低到高：

```
1. ESLint 默认规则（最低）
2. .eslintrc.* 或 package.json 的 eslintConfig 字段
3. 命令行 --rule 参数覆盖（最高）
```

```javascript
// .eslintrc.cjs (ESM 项目中推荐用 .cjs 扩展名)
const { defineConfig } = require('eslint-define-config');

module.exports = defineConfig({
  root: true,                    // 停止向上查找父目录配置
  env: {
    browser: true,               // 浏览器全局变量（window, document 等）
    node: true,                  // Node.js 全局变量（require, process 等）
    es2024: true,                // ES2024 新语法支持
  },

  parser: '@typescript-eslint/parser',  // TypeScript 解析器
  parserOptions: {
    ecmaVersion: 'latest',
    sourceType: 'module',        // 支持 ESM
    ecmaFeatures: { jsx: true },
  },

  ignorePatterns: [
    'dist/',
    'node_modules/',
    'coverage/',
    '*.config.js',
    '*.config.ts',
  ],
});
```

## 自动修复 --fix

ESLint 最强大的功能之一是可以自动修复部分违规。`--fix` 模式让 ESLint 不仅报告问题，还能直接改代码：

```bash
# 手动修复所有可修复的问题
npx eslint src/ --fix

# 只修复特定文件
npx eslint src/components/Button.tsx --fix

# 修复并输出修复了什么
npx eslint src/ --fix --format stylish
```

```javascript
/**
 * 自定义修复规则的示例
 * 禁止直接使用数字字面量作为颜色值，要求提取为 CSS 变量或常量
 */
module.exports = {
  rules: {
    'custom/no-magic-color': {
      meta: {
        type: 'problem',
        docs: { description: '禁止魔法颜色值' },
        fixable: 'code',        // 声明此规则可以自动修复
        schema: [],
      },
      create(context) {
        return {
          Literal(node) {
            // 匹配 # 开头的十六进制颜色值
            if (typeof node.value === 'string' && /^#[0-9a-fA-F]{6}$/.test(node.value)) {
              context.report({
                node,
                message: '避免直接使用颜色字面量 "{{color}}"，应使用语义化的变量名',
                data: { color: node.value },
                fix(fixer) {
                  const varName = node.value.slice(1).toUpperCase();
                  return fixer.replaceText(
                    node,
                    `CSS_VARS.COLOR_${varName}`
                  );
                },
              });
            }
          },
        };
      },
    },
  },
};
```

**注意：** 并非所有问题都可以自动修复。涉及代码意图判断的问题（如变量命名、复杂度超标）只能人工处理；而格式类问题（空格、引号、分号等）通常都能自动修复。

## 与编辑器集成

```json
// .vscode/settings.json —— VSCode 中实时 lint
{
  "editor.formatOnSave": false,
  "editor.codeActionsOnSave": {
    "source.fixAll.eslint": "explicit",
    "source.organizeImports": "never"
  },
  "eslint.validate": [
    "javascript",
    "javascriptreact",
    "typescript",
    "typescriptreact"
  ],
  "eslint.workingDirectories": [{ "mode": "auto" }]
}
```

保存文件时自动执行 `eslint --fix`，问题在写入磁盘前就被修正。这种即时反馈循环是保证代码质量的最有效手段之一——就像有一个隐形助手在你每次敲下回车后立即整理格式。

**哲学思考**：ESLint 的价值不在于它捕获了多少 bug，而在于它建立了一种**团队共识**。"什么样的代码是好的代码"不再依赖每个人的主观判断，而是由一份共享的配置来定义。这减少了 code review 中关于风格的争论时间，让讨论聚焦于更有价值的逻辑设计和架构决策上。
