# 调试技巧 —— debugger、断点、条件断点、监视、调用堆栈

## 调试的本质

调试不是在代码中到处 `console.log`——那是在黑暗中摸索。调试是一种**系统性的问题定位方法**：观察程序状态，提出假设，验证假设，缩小范围，直到找到根因。

这就像医生诊断疾病。病人说"不舒服"（报错信息），医生不会立刻开药，而是先问诊（查看日志）、做检查（设断点）、分析指标（查看变量值），然后根据证据做出判断。好的调试者和好医生的共同特质是：**不靠猜测，只凭证据**。

## console 之外的调试工具箱

### debugger 语句

```javascript
/**
 * debugger 语句 —— 最简单的断点方式
 * 当浏览器开发者工具打开时，
 * 执行到此行会自动暂停
 */

function processOrder(order) {
  const items = order.items;
  
  // 在这里暂停，检查 items 的内容
  debugger;  // ← 执行会在此处冻结
  
  const total = items.reduce((sum, item) => sum + item.price * item.quantity, 0);
  return { ...order, total };
}
```

**注意**：`debugger` 是一个语句而非函数调用。如果 DevTools 没有打开，大多数浏览器会直接忽略它。但生产环境中不应保留 `debugger` 语句——[ESLint](/frontend/javascript/engineering-node/eslint) 的 `no-debugger` 规则可以帮你拦截它。

### console 的进阶用法

```javascript
// ====== console 不仅仅是 log ======

// 基础用法
console.log('简单输出');
console.error('错误信息');    // 红色，带堆栈追踪
console.warn('警告信息');     // 黄色
console.info('信息提示');     // 带图标

// 分组输出 —— 复杂嵌套结构的利器
console.group('用户数据');
console.log('ID:', user.id);
console.log('姓名:', user.name);

console.group('地址');
console.log('省:', user.address.province);
console.log('市:', user.address.city);
console.groupEnd(); // 关闭"地址"分组

console.table(user.orders);   // 以表格形式展示数组/对象
console.groupEnd();           // 关闭"用户数据"分组

// 样式化输出
console.log(
  '%c 重要事件 %c 发生了',
  'color:red;font-weight:bold;font-size:14px',
  'color:blue'
);

// 性能计时
console.time('数据处理');
processLargeDataset(data);  // 假设耗时操作
console.timeEnd('数据处理'); // 输出: 数据处理: 1234.56ms

// 计数器 —— 统计某段代码执行次数
function renderList(items) {
  items.forEach(item => {
    console.count('渲染次数');
    render(item);
  });
}

// 断言 —— 条件不满足时才输出
const value = fetchData();
console.assert(value > 0, 'fetchData 返回了无效值:', value);
```

### DOM 元素快速获取

```javascript
// 控制台中直接使用（无需写在代码中）
// 这些是浏览器控制台提供的全局辅助方法

$()        // document.querySelector 的简写
$$()       // document.querySelectorAll 的简写

// 示例：
$('button.primary')      // 获取第一个匹配的按钮
$$('.list-item')         // 获取所有列表项（返回数组）

$0, $1, $2               // 最近在 Elements 面板中选中的 DOM 元素
inspect($0)              // 在面板中高亮显示该元素
copy($0.outerHTML)       // 复制 HTML 到剪贴板
```

## 断点系统详解

### 行断点

最基础的断点——当程序执行到指定行时暂停：

```javascript
function calculateTax(income, rate) {
  const taxable = income - 12000;
  // ↑ 在这一行左侧点击设置断点
  
  let tax = taxable * rate;
  if (taxable <= 0) tax = 0;  // ← 也可以在这里加断点
  
  return Math.round(tax * 100) / 100;
}
```

### 条件断点

只在特定条件下触发——这是最高效的断点类型：

```javascript
// 场景一：循环中只关心第 1000 次迭代
for (let i = 0; i < data.length; i++) {
  process(data[i]);
  // 右键 → Add conditional breakpoint → 输入: i === 1000
}

// 场景二：只在特定状态下暂停
function handleRequest(req) {
  if (req.method === 'POST' && req.url.includes('/api/pay')) {
    // 只对支付接口的 POST 请求中断
    // 条件：req.method === 'POST' && req.url.includes('/pay')
  }
}

// 场景三：变量异常时捕获
function validateUser(user) {
  // 条件：user.age < 0 || user.age > 150
  // 捕获不可能的年龄值
}
```

### 日志断点

不需要暂停执行，只是自动打印表达式的值：

```javascript
// 右键 → Add logpoint → 输入表达式
// 效果等同于 console.log() 但无需改代码

function fetchUserData(userId) {
  // Logpoint 表达式: `'请求用户 ID: ' + userId`
  return api.get(`/users/${userId}`);
  
  // Logpoint 表达式: `'响应数据:' + JSON.stringify(response)`
  // （放在 await 后面的那一行）
}
```

日志断点的优势：**不改代码就能添加临时调试信息**。用完即删，不会意外提交到仓库。

### DOM 断点

在 Elements 面板中对 DOM 元素设置断点：

```
右键元素 → Break on:
├── subtree modifications  → 子树被修改时触发
├── attribute modifications → 属性被修改时触发
│                           （适合排查谁在修改 class/style）
└── node removal           → 元素被移除时触发
                           （适合排查谁在删除某个节点）
```

```javascript
// 典型场景：排查某个元素为什么会突然消失
// 
// 1. 在 DevTools 中选中目标元素
// 2. 右键 → Break on → node removal
// 3. 触发消失的操作
// 4. 自动停在移除它的那行代码上
// 5. 查看调用堆栈找到罪魁祸首
```

## 调用堆栈（Call Stack）

调用堆栈是理解"代码怎么走到这里"的最重要工具：

```javascript
// 假设你的断点停在这里：
function formatPrice(amount) {
  // 当前在这里暂停
  return new Intl.NumberFormat('zh-CN', { style: 'currency', currency: 'CNY' })
    .format(amount);
}

// Call Stack 面板显示：
//
// formatPrice          ← 当前执行的函数 (当前帧)
//   calculateTotal     ← 谁调用了 formatPrice
//     renderInvoice    ← 谁调用了 calculateTotal
//       handlePrint    ← 谁调用了 renderInvoice
//         (anonymous)  ← 事件回调或顶层调用
//
// 点击任意一帧可以跳转到对应的调用位置和上下文！
// 这对于理解"这个函数是被谁以什么参数调用的"极其有用。
```

## 监视表达式（Watch）

Watch 面板可以持续跟踪你关心的表达式，每次暂停时自动更新：

```javascript
// Watch 面板中添加的表达式（示例）：

// 监视变量
user.name
order.items.length
this.state.isLoading

// 监视复杂表达式
JSON.stringify(config)
items.filter(x => x.price > 100).length
performance.now() - startTime

// 监视 DOM 状态
document.activeElement.tagName
getComputedStyle(el).display
el.getBoundingClientRect().width
```

## Source Map 与源码映射

当代码经过打包压缩后，浏览器运行的产物和源码完全不同。Source Map 将两者关联起来：

```javascript
// webpack.config.js
module.exports = {
  devtool: process.env.NODE_ENV === 'production'
    ? 'hidden-source-map'    // 生产环境：生成 map 文件但不暴露给浏览器（仅错误追踪）
    : 'eval-source-map',     // 开发环境：高质量映射，便于逐行调试
};
```

```
开发环境中的调试体验：
- 断点打在 TypeScript 源码上 ✅
- 变量名保持原名（非 a, b, c） ✅
- 可以看到原始注释 ✅
- 调用堆栈显示原始文件路径 ✅

这一切都由 Source Map 在背后默默完成。
```

**哲学思考**：调试能力是一个工程师的核心竞争力之一。很多人依赖 `console.log` 能解决大部分问题——确实如此，但它就像用手电筒找钥匙：能照亮一小片区域，但你不知道钥匙到底在哪。而断点和调用堆栈就像是打开了房间的大灯——整个程序的执行状态一览无余。花时间掌握这些工具不是奢侈的投资，而是日常工作的加速器。
