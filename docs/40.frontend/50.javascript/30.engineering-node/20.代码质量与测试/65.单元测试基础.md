# 单元测试 —— Jest/Vitest 基础、断言（expect）、匹配器

## 为什么需要测试

"它在我机器上能跑啊。"——这句话是软件开发史上最著名的谎言之一。没有测试的代码就像没有安全网的走钢丝表演——也许你能成功一千次，但第一次失败就足以造成灾难。

测试的本质不是证明代码能工作，而是**确保代码在修改后仍然能工作**。当你重构一段逻辑、升级依赖版本或修复一个 bug 时，测试套件就是你的安全网。如果改坏了什么，测试会立即告诉你。

这就像建筑物的烟雾报警器。平时你几乎意识不到它的存在，但当真正有火情时，它能救你的命。测试就是代码的烟雾报警器。

## 核心结构

一个测试由三部分组成——Arrange-Act-Assert 模式：

```javascript
// ====== Arrange（准备）=======
// 准备测试所需的数据和环境
const calculator = new Calculator();
const inputA = 10;
const inputB = 5;

// ====== Act（执行）=======
// 调用被测函数
const result = calculator.add(inputA, inputB);

// ====== Assert（断言）=======
// 验证结果是否符合预期
expect(result).toBe(15);
```

这个模式之所以重要，是因为它强制你把"准备什么"、"做什么"、"期望什么"三个阶段清晰地分开。当测试失败时，你可以快速判断是准备数据错了、执行方式不对、还是预期本身有问题。

### describe 和 it

```javascript
/**
 * Calculator 的完整测试套件
 */
import { Calculator } from './Calculator';

describe('Calculator', () => {
  // 在所有测试之前执行一次
  beforeAll(() => {
    console.log('初始化数据库连接...');
  });

  // 每个测试之前重新创建实例（隔离性！）
  let calc;
  beforeEach(() => {
    calc = new Calculator();
  });

  // 每个测试之后清理
  afterEach(() => {
    calc.reset();
  });

  // 所有测试结束后清理全局资源
  afterAll(() => {
    console.log('关闭数据库连接');
  });

  // ====== 加法测试 ======
  describe('add()', () => {
    it('应该正确计算两个正数之和', () => {
      expect(calc.add(2, 3)).toBe(5);
    });

    it('应该处理负数', () => {
      expect(calc.add(-3, -7)).toBe(-10);
    });

    it('应该处理零值', () => {
      expect(calc.add(0, 0)).toBe(0);
      expect(calc.add(0, 42)).toBe(42);
    });

    it('应该处理小数精度问题', () => {
      expect(calc.add(0.1, 0.2)).toBeCloseTo(0.3, 10);
    });
  });

  // ====== 除法测试 ======
  describe('divide()', () => {
    it('应该正确计算除法', () => {
      expect(calc.divide(10, 2)).toBe(5);
    });

    it('除以零时应该抛出错误', () => {
      expect(() => calc.divide(10, 0)).toThrow('不能除以零');
    });
  });
});
```

## expect 匹配器大全

匹配器是断言的核心词汇——它们定义了"什么样的结果是可接受的"：

### 相等性匹配

```javascript
expect(value).toBe(expected);           // 严格相等 (===)
expect(value).toEqual(expected);        // 深度递归比较（对象/数组）
expect(value).toStrictEqual(expected);  // 更严格（类型也检查）
expect(value).toMatchObject(expected);  // 部分匹配（对象子集）

// 示例
const user = { name: 'Alice', age: 25, role: 'admin' };

expect(user.name).toBe('Alice');                    // ✅ 基本类型用 toBe
expect(user).toEqual({ name: 'Alice', age: 25 });   // ✅ 对象用 toEqual
expect({ a: 1 }).toStrictEqual({ a: 1 });          // ✅ 类型严格匹配
expect(user).toMatchObject({ role: 'admin' });       // ✅ 只检查部分属性
```

### 真值和存在性

```javascript
expect(value).toBeTruthy();     // 真值（非 falsy）
expect(value).toBeFalsy();      // 假值
expect(value).toBeNull();      // === null
expect(value).toBeDefined();    // !== undefined
expect(value).toBeUndefined();  // === undefined
expect(value).toBeTruthy();

// 实际场景：API 返回值的健壮性检查
const response = fetchUser(id);

expect(response).toBeDefined();        // 不是 undefined
expect(response.data).toBeTruthy();   // 有数据（不是 null/undefined/'')
expect(response.error).toBeUndefined();// 无错误字段
```

### 数组和集合

```javascript
expect(array).toContain(item);         // 数组包含某元素
expect(array).toHaveLength(n);         // 长度为 n
expect(array).toEqual(expect.arrayContaining([...])); // 包含指定元素（忽略顺序）

const numbers = [1, 2, 3, 4, 5];

expect(numbers).toContain(3);                          // ✅ 包含 3
expect(numbers).toHaveLength(5);                        // ✅ 有 5 个元素
expect(numbers).toEqual(expect.arrayContaining([2, 4]));// ✅ 至少包含 2 和 4
```

### 字符串

```javascript
expect(str).toMatch(regex);        // 匹配正则
expect(str).toContain(substring);  // 包含子串
expect(str).toHaveLength(n);       // 长度检查

const email = 'user@example.com';
expect(email).toMatch(/^[^\s@]+@[^\s@]+\.[^\s@]+$/);  // ✅ 合法邮箱格式
expect(email).toContain('@');                           // ✅ 包含 @
```

### 异常

```javascript
// 断言函数会抛出异常
expect(fn).toThrow();                    // 抛出了任何错误
expect(fn).toThrow(ErrorType);            // 抛出了特定类型的错误
expect(fn).toThrow('message');           // 错误消息包含指定字符串
expect(fn).toThrow(/regex/);             // 错误消息匹配正则

// 示例
function validateAge(age) {
  if (typeof age !== 'number') throw new TypeError('年龄必须是数字');
  if (age < 0) throw new RangeError('年龄不能为负数');
}

expect(() => validateAge('abc')).toThrow(TypeError);   // ✅
expect(() => validateAge(-5)).toThrow(RangeError);      // ✅
expect(() => validateAge(25)).not.toThrow();            // ✅ 不抛错
```

### 否定匹配

任何匹配器都可以加 `.not()` 取反：

```javascript
expect(result).not.toBe(null);              // 不是 null
expect(error).not.toBeDefined();             // 未定义
expect(arrays).not.toContain(unwantedItem);  // 不包含
expect(fn).not.toThrow();                   // 不抛错
```

### 自定义匹配器

```javascript
// 创建项目级自定义匹配器
expect.extend({
  /**
   * 检查日期是否在最近 N 天内
   */
  toBeRecent(received, days = 7) {
    const receivedDate = new Date(received);
    const cutoff = Date.now() - days * 24 * 60 * 60 * 1000;
    const pass = receivedDate.getTime() > cutoff;

    return {
      pass,
      message: () =>
        pass
          ? `expected ${received} not to be within the last ${days} days`
          : `expected ${received} to be within the last ${days} days`,
    };
  },

  /**
   * 检查对象是否有特定方法
   */
  toImplementInterface(received, interfaceMethods) {
    const missing = interfaceMethods.filter(m => typeof received[m] !== 'function');

    return {
      pass: missing.length === 0,
      message: () =>
        missing.length === 0
          ? `object implements all required methods`
          : `object missing methods: ${missing.join(', ')}`,
    };
  },
});

// 使用自定义匹配器
it('用户最近活跃过', () => {
  expect(user.lastLoginAt).toBeRecent(30);  // 最近 30 天内
});

it('对象实现了接口', () => {
  expect(service).toImplementInterface(['fetch', 'save', 'delete']);
});
```

## Vitest 配置示例

Vitest 是面向 Vite 生态的现代测试框架，API 兼容 Jest：

```javascript
// vitest.config.ts
import { defineConfig } from 'vitest/config';
import path from 'path';

export default defineConfig({
  test: {
    globals: true,               // 全局注册 describe/it/expect
    environment: 'jsdom',        // DOM 环境（组件测试必需）
    setupFiles: ['./vitest.setup.ts'],
    
    include: ['src/**/*.{test,spec}.{ts,tsx}'],
    exclude: ['node_modules', 'dist'],

    coverage: {
      provider: 'v8',
      reporter: ['text', 'json', 'html'],
      include: ['src/**/*.ts', 'src/**/*.tsx'],
      exclude: ['src/**/*.d.ts', 'src/**/index.ts'],
      thresholds: {
        statements: 80,
        branches: 70,
        functions: 80,
        lines: 80,
      },
    },
  },
  resolve: {
    alias: {
      '@': path.resolve(__dirname, './src'),
    },
  },
});
```

```typescript
// vitest.setup.ts —— 测试环境前置设置
import '@testing-library/jest-dom';  // 扩展 DOM 匹配器（toBeInTheDocument 等）

// Mock 浏览器 API
Object.defineProperty(window, 'matchMedia', {
  writable: true,
  value: vi.fn().mockImplementation(query => ({
    matches: false,
    media: query,
    onchange: null,
    addListener: vi.fn(),
    removeListener: vi.fn(),
    addEventListener: vi.fn(),
    removeEventListener: vi.fn(),
    dispatchEvent: vi.fn(),
  })),
});

// Mock IntersectionObserver
class MockIntersectionObserver {
  observe = vi.fn();
  unobserve = vi.fn();
  disconnect = vi.fn();
}
window.IntersectionObserver = MockIntersectionObserver as any;
```

**哲学思考**：好的测试不是越多越好，而是**每条测试都应该有一个明确的失败理由**。如果一个测试永远不会失败（比如只是重复声明显而易见的事实），那它提供的是虚假的安全感。真正有价值的测试是那些能在未来某个时刻保护你不犯错误的——它们是你对系统行为做出的精确承诺。
