# Mock —— jest.fn、spyOn、模块模拟、定时器模拟

## Mock 的哲学

Mock 是测试中的"演员替身"概念。当你拍一场戏需要一个路人角色时，你不会去找真正的路人来演——你用一个群演代替。Mock 就是代码世界的群演：它长得像真的依赖（有相同的方法签名），行为可以被导演（测试者）精确控制，而且演出结束后不留痕迹。

为什么要这样做？因为单元测试的目标是验证**你的代码逻辑是否正确**，而不是验证数据库能不能连上、第三方 API 是否在线、文件系统能不能写入。这些外部依赖的状态是不可控的——今天能连明天可能断，本地能跑服务器可能挂。Mock 把这些不可控因素排除在外，让你专注于真正需要验证的逻辑。

## jest.fn() / vi.fn()

最基本的 Mock 函数——一个可以记录所有调用信息的空壳函数：

```javascript
/**
 * Mock 函数的基本能力演示
 */

// 创建一个 Mock 函数
const mockFn = vi.fn();  // 或 jest.fn()

// 可以像普通函数一样调用
mockFn('hello', 42);
mockFn('world', 99);

// ====== 断言调用情况 ======

expect(mockFn).toHaveBeenCalled();           // 至少被调用了一次
expect(mockFn).toHaveBeenCalledTimes(2);     // 被调用了 2 次
expect(mockFn).toHaveBeenCalledWith('hello', 42);  // 第一次调用参数匹配

// 访问调用历史
console.log(mockFn.mock.calls);
// [ ['hello', 42], ['world', 99] ]

console.log(mockFn.mock.results);
// [ { type: 'return', value: undefined }, ... ]

// ====== 自定义返回值 ======

const adder = vi.fn((a, b) => a + b);

expect(adder(2, 3)).toBe(5);
expect(adder(10, 20)).toBe(30);
expect(adder).toHaveBeenCalledTimes(2);

// ====== 分阶段返回不同值 ======

const mockApi = vi.fn()
  .mockReturnValueOnce({ status: 'loading' })   // 第 1 次
  .mockResolvedValueOnce({ data: 'success' })   // 第 2 次
  .mockRejectedValueOnce(new Error('fail'));   // 第 3 次

const r1 = mockApi();  // → { status: 'loading' } (同步)
const r2 = mockApi();  // → Promise<{ data: 'success'> }
const r3 = mockApi();  // → Promise<reject Error>
```

### 实际应用场景

```javascript
/**
 * 场景一：验证回调是否被正确传递
 */
function processItems(items, callback) {
  items.forEach(item => callback(item));
}

it('应该对每个元素调用一次回调', () => {
  const cb = vi.fn();
  
  processItems(['a', 'b', 'c'], cb);
  
  expect(cb).toHaveBeenCalledTimes(3);
  expect(cb).toHaveBeenNthCalledWith(1, 'a');
  expect(cb).toHaveBeenNthCalledWith(2, 'b');
  expect(cb).toHaveBeenNthCalledWith(3, 'c');
});

/**
 * 场景二：验证事件处理器注册
 */
class EventEmitter {
  handlers = {};
  on(event, handler) { this.handlers[event] = handler; }
  emit(event, data) { this.handlers[event]?.(data); }
}

it('应该在初始化时注册事件监听器', () => {
  const emitter = new EventEmitter();
  const onStart = vi.fn();
  const onComplete = vi.fn();

  setup(emitter, { onStart, onComplete });

  emitter.emit('start');
  expect(onStart).toHaveBeenCalled();

  emitter.emit('complete', { id: 1 });
  expect(onComplete).toHaveBeenCalledWith({ id: 1 });
});
```

## spyOn（间谍）

SpyOn 比 Mock 函数更精细——它在保留原始实现的同时记录调用信息：

```javascript
/**
 * spyOn vs mock 的关键区别：
 *
 * mockFn: 完全替代原函数（原函数不会被执行）
 * spyFn: 包装原函数（原函数照常执行 + 记录调用信息）
 */

const obj = {
  getValue() { return Math.random(); },
  save(data) { /* 写入数据库 */ },
};

describe('spyOn 示例', () => {
  afterEach(() => {
    vi.restoreAllMocks();  // 清除所有 spies
  });

  it('应该跟踪对 getValue 的调用', () => {
    const spy = vi.spyOn(obj, 'getValue');

    const val1 = obj.getValue();
    const val2 = obj.getValue();

    // 原始函数正常执行了（返回了随机数）
    expect(val1).not.toBe(val2);

    // 同时记录了调用
    expect(spy).toHaveBeenCalledTimes(2);
  });

  it('可以临时覆盖实现', () => {
    vi.spyOn(obj, 'save').mockImplementation((data) => {
      console.log('[MOCK SAVE]', data);  // 不真正写入数据库
    });

    obj.save({ test: true });
    // save 被 mock 了，不会触发实际的数据库写入
    expect(obj.save).toHaveBeenCalled();
  });

  it('只监听但不影响原有行为', () => {
    const spy = vi.spyOn(console, 'log');  // 监听 console.log
    // console.log 正常工作，只是多了一双眼睛在观察
  });
});
```

## 模块级 Mock

有时需要 Mock 整个模块而非单个函数：

```javascript
// __mocks__/fs.js —— 自动 Mock 文件系统模块
export const readFile = vi.fn(() => Promise.resolve('mock file content'));
export const writeFile = vi.fn(() => Promise.resolve());
export const existsSync = vi.fn(() => true);

// 或者使用 vi.mock 动态 Mock
vi.mock('./api-client', () => ({
  default: {
    get: vi.fn().mockResolvedValue({ data: [] }),
    post: vi.fn().mockResolvedValue({ success: true }),
  },
  getUser: vi.fn().mockImplementation(async (id) => ({
    id,
    name: `User-${id}`,
  })),
}));

// 使用 Mock 的模块
import api from './api-client';
import { getUser } from './api-client';

describe('使用 Mock 的 API', () => {
  it('应该返回 Mock 数据', async () => {
    const users = await api.get('/users');
    expect(users).toEqual({ data: [] });
  });

  it('可以在每个测试中修改 Mock 行为', async () => {
    (api.getUser as any)
      .mockResolvedValueOnce({ id: 1, name: 'Special User' });

    const user = await getUser(1);
    expect(user.name).toBe('Special User');
  });
});
```

### 部分 Mock（选择性保留）

```javascript
/**
 * 有时只需要 Mock 模块中的部分导出，
 * 其余导出保持原始实现
 */
vi.mock('./heavy-module', async (importOriginal) => {
  const actual = await importOriginal<typeof import('./heavy-module')>();

  return {
    ...actual,                          // 保留原始导出
    expensiveOperation: vi.fn(),         // 只 Mock 这个耗时的
    networkCall: vi.fn().mockResolvedValue({ ok: true }),  // 和这个
  };
});
```

## 定时器模拟详解

```javascript
/**
 * 完整的定时器 Mock 示例
 * 覆盖 setTimeout / setInterval / clearTimeout / clearInterval
 */

describe('轮询器（Poller）', () => {
  beforeEach(() => {
    vi.useFakeTimers();
  });

  afterEach(() => {
    vi.useRealTimers();
  });

  it('应该按间隔重复执行', () => {
    const callback = vi.fn();
    createPoller(callback, { interval: 1000 });

    // 初始立即执行一次
    expect(callback).toHaveBeenCalledTimes(1);

    // 推进 1 秒
    vi.advanceTimersByTime(1000);
    expect(callback).toHaveBeenCalledTimes(2);

    // 再推进 3 秒
    vi.advanceTimersByTime(3000);
    expect(callback).toHaveBeenCalledTimes(5);
  });

  it('应该支持停止', () => {
    const callback = vi.fn();
    const stopper = createPoller(callback, { interval: 1000 });

    vi.advanceTimersByTime(2000);
    expect(callback).toHaveBeenCalledTimes(3);

    stopper();  // 停止轮询

    vi.advanceTimersByTime(5000);
    expect(callback).toHaveBeenCalledTimes(3);  // 不再增长
  });

  it('应该处理异步回调中的定时器', async () => {
    vi.useFakeTimers({ shouldAdvanceTime: false });  // 更精细的控制

    const asyncPoller = createAsyncPoller(async () => {
      await someAsyncTask();
    }, { interval: 1000 });

    // 触发首次执行
    await vi.runOnlyPendingTimersAsync();

    // 推进时间但手动处理微任务
    vi.advanceTimersByTime(1000);
    await vi.runOnlyPendingTimersAsync();
  });
});
```

**哲学思考**：Mock 是一种必要的妥协。理想情况下我们希望测试真实的代码和真实的依赖，但在现实中这是不可能或不切实际的。Mock 不是为了欺骗测试——而是为了让测试聚焦于**真正重要的东西**。一个好的原则是：**只在跨边界处使用 Mock**（如 HTTP、数据库、文件系统），同一应用内部的对象交互应尽量使用真实实例。过度 Mock 会制造虚假的安全感，让你以为测试通过了就没问题，但实际上 Mock 的假设可能与现实不符。
