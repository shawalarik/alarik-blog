# 进程管理 —— child_process、cluster、process 信号

> **核心内容**：`child_process` 的四种派生方式（exec/execFile/spawn/fork）、`cluster` 模块的多核利用、进程间通信（IPC）机制、信号处理与优雅关闭、进程池模式实战。

## 为什么需要多进程？

JavaScript 是单线程的——一个 Node.js 进程只能利用一个 CPU 核心。但现代服务器通常有 8 核、16 核甚至更多。要让所有核心都发挥作用，有两种策略：

1. **多进程**（本文重点）：每个 CPU 核心跑一个 Node.js 进程，通过 IPC 通信
2. **Worker Threads**：同一进程内的多线程共享内存

```
单进程模型：
┌──────────────┐
│   Node.js    │ ← 只用 1 个核，其他核空闲
│  (Core 0)    │
└──────────────┘

多进程模型（Cluster）：
┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
│ Master   │ │ Worker 1 │ │ Worker 2 │ │ Worker N │
│ (调度)   │ │ (Core 0) │ │ (Core 1) │ │(Core N-1)│
└──────────┘ └──────────┘ └──────────┘ └──────────┘
     ↑            ↑           ↑           ↑
     └────────────┴───────────┴───────────┘
                  共享端口 (Port Sharing)
```

## child_process：四种派生方式

Node.js 提供了四种创建子进程的方法，各有适用场景：

### exec — 执行命令并获取完整输出

适合执行**一次性命令**，输出量较小的情况：

```js
const { exec } = require('child_process');

// 基本用法
exec('ls -la', (error, stdout, stderr) => {
  if (error) {
    console.error(`执行错误: ${error.message}`);
    return;
  }
  console.log(`输出:\n${stdout}`);
});

// 带 options
exec(
  'find /src -name "*.ts"',
  {
    cwd: '/project',
    timeout: 10000,       // 超时 10 秒自动终止
    maxBuffer: 1024 * 1024, // 输出缓冲区上限 1MB
    env: { ...process.env, DEBUG: 'true' }, // 自定义环境变量
    shell: true,          // 通过系统 shell 执行
  },
  (err, stdout, stderr) => {
    // stdout 和 stderr 是完整的字符串（等待命令结束后才回调）
  }
);

// Promise 封装版
function execPromise(command, options = {}) {
  return new Promise((resolve, reject) => {
    exec(command, options, (error, stdout, stderr) => {
      if (error) reject({ error, stderr });
      else resolve(stdout);
    });
  });
}

const gitLog = await execPromise('git log --oneline -5');
console.log(gitLog);
```

**注意**：`exec` 会将输出缓存在内存中。如果命令产生大量输出（如 `cat huge-file.log`），可能导致 `maxBuffer` 超限报错。

### execFile — 直接执行可执行文件

与 `exec` 类似，但不经过 shell，更安全高效：

```js
const { execFile } = require('child_process');

// 直接执行文件（不通过 shell）
execFile('node', ['--version'], (error, stdout, stderr) => {
  console.log(`Node 版本: ${stdout.trim()}`);
});

// 执行自定义脚本
execFile('./scripts/build.sh', ['--prod', '--clean'], {
  cwd: __dirname,
  env: { NODE_ENV: 'production' },
}, (error, stdout, stderr) => {
  if (error) {
    console.error(stderr);
    process.exit(1);
  }
  console.log(stdout);
});
```

**exec vs execFile 的选择**：

| 场景 | 推荐 | 原因 |
|------|------|------|
| 需要管道/重定向/glob | `exec` | 需要 shell 解析 |
| 执行已知程序 + 固定参数 | `execFile` | 更安全，无 shell 注入风险 |
| 参数来自用户输入 | `execFile` | 避免 shell 特殊字符注入 |

### spawn — 流式控制长生命周期进程

`spawn` 是最灵活的方式——返回一个流接口的子进程对象：

```js
const { spawn } = require('child_process');

// 启动一个长生命周期的子进程
const ffmpeg = spawn('ffmpeg', [
  '-i', 'input.mp4',
  '-c:v', 'libx264',
  '-preset', 'fast',
  '-crf', '23',
  'output.mp4'
], {
  stdio: 'pipe', // stdin/stdout/stderr 都以 pipe 形式暴露
  detached: false,
});

// 实时获取输出（流式）
ffmpeg.stdout.on('data', (chunk) => {
  // 正常输出（通常 ffmpeg 用 stderr 输出进度）
});

ffmpeg.stderr.on('data', (chunk) => {
  const text = chunk.toString();
  if (text.includes('time=')) {
    const match = text.match(/time=(\d{2}):(\d{2}):(\d{2})/);
    if (match) {
      console.log(`进度: ${match[1]}:${match[2]}:${match[3]}`);
    }
  }
});

ffmpeg.on('close', (code) => {
  console.log(`退出码: ${code === 0 ? '成功' : '失败'}`);
});

ffmpeg.on('error', (err) => {
  console.error('启动失败:', err.message); // 通常表示命令不存在
});

// 向子进程写入数据
if (ffmpeg.stdin.writable) {
  ffmpeg.stdin.write('some input data\n');
  ffmpeg.stdin.end();
}

// 手动终止
// ffmpeg.kill('SIGTERM'); // 发送 SIGTERM 信号
```

### spawn 的 stdio 选项详解

```js
const child = spawn('node', ['script.js'], {
  stdio: [
    'pipe',   // stdin: 父进程可以通过 child.stdin 写入
    'pipe',   // stdout: 父进程可以通过 child.stdout 读取
    'inherit', // stderr: 继承父进程的 stderr（直接显示在终端）
  ],
});

// 其他 stdio 选项值
// 'ignore'     → 忽略该流
// 'inherit'    → 继承父进程对应的流
// 'pipe'       → 创建 pipe，通过 child.stdio[n] 访问
// Stream 对象  → 直接传入已有的流
// null         → 等同于 'ignore'（用于数组形式时）
// [number]     → 连接到已有的 fd

// 实例：将子进程的 stdout 重定向到文件
import fs from 'fs';
const logStream = fs.createWriteStream('output.log');

const child2 = spawn('node', ['long-running.js'], {
  stdio: ['ignore', logStream, 'inherit'],
});
```

### fork — 创建 Node.js 子进程（专用 IPC）

`fork` 是 `spawn` 的特化版本，专门用于创建新的 Node.js 进程，并且自带 **IPC 通信通道**：

```js
// main.js
const { fork } from 'child_process';

const worker = fork('./worker.js');

// 向子进程发送消息
worker.send({ type: 'start', data: [1, 2, 3, 4, 5] });

// 接收子进程消息
worker.on('message', (msg) => {
  console.log('主进程收到:', msg);
  if (msg.type === 'result') {
    console.log('计算结果:', msg.result);
  }
});

worker.on('exit', (code, signal) => {
  console.log(`子进程退出: code=${code}, signal=${signal}`);
});
```

```js
// worker.js
process.on('message', (msg) => {
  if (msg.type === 'start') {
    // 执行耗时计算任务
    const result = msg.data.reduce((sum, n) => sum + n * n, 0);

    // 将结果发回主进程
    process.send({ type: 'result', result });
  }
});

// 通知主进程已就绪
process.send({ type: 'ready' });
```

### 四种方式对比总结

| 方法 | 返回类型 | 适用场景 | 缓冲机制 | IPC 支持 |
|------|---------|---------|---------|---------|
| `exec` | 回调（完整字符串） | 一次性短命令、小输出 | 全部缓存 | 无 |
| `execFile` | 回调（完整字符串） | 已知可执行文件+参数 | 全部缓存 | 无 |
| `spawn` | ChildProcess（Stream 接口） | 长生命周期进程、大输出 | 流式 | 可选 |
| `fork` | ChildProcess（IPC 通道） | Node.js 子进程间通信 | 流式 | 内置 |

## cluster：多核利用的利器

Node.js 的 `cluster` 模块简化了多进程 HTTP 服务器的创建：

```js
// server.js — 使用 cluster 利用多核
const cluster = require('cluster');
const http = require('http');
const os = require('os');
const numCPUs = os.cpus().length;

if (cluster.isPrimary) { // 主进程（旧版本中叫 isMaster）
  console.log(`主进程 ${process.pid} 正在运行`);
  console.log(`启动 ${numCPUs} 个工作进程...`);

  // fork 出 N 个 worker
  for (let i = 0; i < numCPUs; i++) {
    cluster.fork();
  }

  // 监听 worker 事件
  cluster.on('fork', (worker) => {
    console.log(`Worker #${worker.id} 已创建 (PID: ${worker.process.pid})`);
  });

  cluster.on('online', (worker) => {
    console.log(`Worker #${worker.id} 已上线`);
  });

  cluster.on('exit', (worker, code, signal) => {
    console.log(`Worker #${worker.id} 退出 (code=${code}, signal=${signal})`);
    console.log('重启一个新的 worker...');
    cluster.fork(); // 自动重启！
  });

  // 给 worker 分配任务（负载均衡）
  let taskIndex = 0;
  cluster.on('message', (worker, msg) => {
    if (msg.cmd === 'notifyReady') {
      // 可以在这里做初始化分配等操作
    }
  });

} else {
  // 每个 worker 都独立运行这个 HTTP 服务器
  http.createServer((req, res) => {
    res.writeHead(200);
    res.end(`Hello from Worker ${process.pid}\n`);
  }).listen(3000);

  console.log(`Worker ${process.pid} 已启动，监听端口 3000`);

  // 通知主进程已就绪
  process.send({ cmd: 'notifyReady', pid: process.pid });
}
```

### Cluster 的工作原理

```
                    ┌─────────────┐
                    │   Primary    │
                    │  (Master)    │
                    └──────┬───────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
        ┌──────────┐ ┌──────────┐ ┌──────────┐
        │ Worker 1 │ │ Worker 2 │ │ Worker N │
        │ PID:101  │ │ PID:102  │ │ PID:10N  │
        └────┬─────┘ └────┬─────┘ └────┬─────┘
             └────────────┼────────────┘
                          ▼
                   ┌──────────────┐
                   │ Port :3000   │  ← 所有 worker 共享同一个端口
                   └──────────────┘
                          ▲
                    OS 负载均衡
                    （Round-Robin）
```

Node.js 默认使用操作系统提供的**Round-Robin**策略分发连接请求（除 Windows 外）。每个新连接会被依次分配给下一个 worker，实现简单的负载均衡。

### 高级 Cluster 管理

```js
// cluster-manager.js — 更健壮的集群管理
const cluster = require('cluster');
const os = require('os');

class ClusterManager {
  constructor(options = {}) {
    this.workers = new Map();
    this.maxRestarts = options.maxRestarts ?? 10;
    this.restartWindow = options.restartWindow ?? 60000; // 1分钟内
    this.restarts = [];
    this.gracefulShutdownTimeout = options.gracefulShutdownTimeout || 5000;
  }

  start(workerCount = os.cpus().length) {
    for (let i = 0; i < workerCount; i++) {
      this.#forkWorker(i);
    }
    this.#setupEventHandlers();
  }

  #forkWorker(id) {
    const worker = cluster.fork({ WORKER_ID: String(id) });

    this.workers.set(worker.id, {
      instance: worker,
      id,
      startedAt: Date.now(),
      requestsServed: 0,
    });

    worker.on('message', (msg) => this.#handleWorkerMessage(worker, msg));
  }

  #handleWorkerMessage(worker, msg) {
    const info = this.workers.get(worker.id);
    switch (msg.type) {
      case 'request-count':
        info.requestsServed = msg.count;
        break;
      case 'memory-usage':
        info.memoryUsage = msg.usage;
        break;
    }
  }

  #setupEventHandlers() {
    cluster.on('exit', (worker, code, signal) => {
      this.workers.delete(worker.id);
      this.#recordRestart();

      if (this.#isRestartingTooFast()) {
        console.error('Worker 崩溃过于频繁，停止自动重启');
        process.exit(1);
      }

      const oldId = worker.env?.WORKER_ID;
      console.log(`Worker #${oldId} 崩溃，3秒后重启...`);
      setTimeout(() => this.#forkWorker(oldId), 3000);
    });

    // 优雅关闭
    process.on('SIGTERM', () => this.gracefulShutdown());
  }

  #recordRestart() {
    const now = Date.now();
    this.restarts.push(now);
    // 清理超出时间窗口的记录
    this.restarts = this.restarts.filter(t => now - t < this.restartWindow);
  }

  #isRestartingTooFast() {
    return this.restarts.length >= this.maxRestarts;
  }

  async gracefulShutdown() {
    console.log('收到关闭信号，开始优雅关闭...');

    const shutdownPromises = [];

    for (const [id, info] of this.workers) {
      shutdownPromises.push(
        new Promise((resolve) => {
          info.instance.send({ command: 'shutdown' });

          const timer = setTimeout(() => {
            console.log(`Worker #${info.id} 未响应，强制终止`);
            info.instance.kill('SIGKILL');
            resolve(false);
          }, this.gracefulShutdownTimeout);

          info.instance.once('exit', () => {
            clearTimeout(timer);
            console.log(`Worker #${info.id} 已正常退出`);
            resolve(true);
          });
        })
      );
    }

    await Promise.all(shutdownPromises);
    console.log('所有 worker 已关闭');
    process.exit(0);
  }

  getStatus() {
    return {
      totalWorkers: this.workers.size,
      recentRestarts: this.restarts.length,
      workers: Array.from(this.workers.entries()).map(([id, info]) => ({
        id: info.id,
        pid: info.instance.process.pid,
        uptime: Math.floor((Date.now() - info.startedAt) / 1000),
        requests: info.requestsServed,
        memory: info.memoryUsage,
      })),
    };
  }
}
```

## 进程间通信（IPC）

### 消息传递机制

Node.js 的 IPC 基于 JSON 序列化，底层使用 libuv 的管道实现：

```js
// 主进程
const worker = fork('./heavy-worker.js');

// 发送各种类型的消息
worker.send({ type: 'task', payload: { items: Array(10000).fill(0).map((_,i)=>i) } });
worker.send(new Int32Array([1, 2, 3])); // 可以发送 TypedArray
worker.send(Buffer.from('binary data')); // Buffer 也支持

// 接收消息
worker.on('message', (msg) => {
  // msg 自动反序列化为 JS 对象
});
```

**限制**：不能发送函数、DOM 对象、Symbol 等。能发送的数据类型包括：基本类型、Object、Array、Buffer、TypedArray、Error 对象。

### 大数据传输优化

当需要在进程间传输大量数据时，JSON 序列化的开销可能成为瓶颈：

```js
// ❌ 低效：JSON 序列化大数组
// worker.send({ data: largeArray }); // 序列化和反序列化都很慢

// ✅ 高效：使用 SharedArrayBuffer（需要 --experimental-worker）
// 或者使用端口（port）直接传递 socket/file descriptor
```

另一种方案是使用外部存储作为中间媒介：

```js
// 使用 Redis 作为进程间通信的中间层
import Redis from 'ioredis';
const redis = new Redis();

// 生产者进程
await redis.rpush('task-queue', JSON.stringify({ id: 123, type: 'compute' }));

// 消费者进程
while (true) {
  const [_, raw] = await redis.blpop('task-queue', 30);
  const task = JSON.parse(raw);
  // 处理任务...
}
```

## 进程池（Process Pool）

对于频繁创建和销毁子进程的场景，使用进程池可以显著提升性能：

```js
// process-pool.js
const { fork } = require('child_process');
const EventEmitter = require('events');

class ProcessPool extends EventEmitter {
  constructor(scriptPath, options = {}) {
    super();
    this.scriptPath = scriptPath;
    this.poolSize = options.size || require('os').cpus().length - 1;
    this.taskQueue = [];
    this.workers = [];
    this.#initPool();
  }

  #initPool() {
    for (let i = 0; i < this.poolSize; i++) {
      const worker = fork(this.scriptPath);
      worker.on('message', (result) => this.#onResult(worker, result));
      worker.on('exit', () => this.#restartWorker(i));
      this.workers.push({
        instance: worker,
        busy: false,
        currentTask: null,
      });
    }
  }

  execute(taskData) {
    return new Promise((resolve, reject) => {
      const availableWorker = this.workers.find(w => !w.busy);

      if (availableWorker) {
        this.#assignTask(availableWorker, taskData, resolve, reject);
      } else {
        this.taskQueue.push({ taskData, resolve, reject });
      }
    });
  }

  #assignTask(worker, taskData, resolve, reject) {
    worker.busy = true;
    worker.currentTask = { resolve, reject, startTime: Date.now() };

    // 设置超时
    const timeout = setTimeout(() => {
      reject(new Error(`任务超时`));
      worker.busy = false;
      worker.currentTask = null;
      this.#processQueue();
    }, 30000); // 30秒超时

    worker.instance.send({ taskId: Date.now(), ...taskData }, (err) => {
      if (err) reject(err);
      // 保存 timeout 引引用以便清理
      worker.currentTask.timeout = timeout;
    });
  }

  #onResult(worker, result) {
    const task = worker.currentTask;
    if (!task) return;

    clearTimeout(task.timeout);
    worker.busy = false;
    worker.currentTask = null;
    task.resolve(result);
    this.#processQueue();
  }

  #processQueue() {
    if (this.taskQueue.length > 0) {
      const nextTask = this.taskQueue.shift();
      const freeWorker = this.workers.find(w => !w.busy);
      if (freeWorker) {
        this.#assignTask(freeWorker, nextTask.taskData, nextTask.resolve, nextTask.reject);
      }
    }
  }

  #restartWorker(index) {
    console.warn(`Worker #${index} 意外退出，正在重启...`);
    const worker = fork(this.scriptPath);
    worker.on('message', (result) => this.#onResult(this.workers[index], result));
    worker.on('exit', () => this.#restartWorker(index));

    // 恢复状态（不处理当前正在进行的任务）
    this.workers[index] = {
      instance: worker,
      busy: false,
      currentTask: null,
    };
  }

  getStats() {
    return {
      poolSize: this.poolSize,
      busyWorkers: this.workers.filter(w => w.busy).length,
      queueLength: this.taskQueue.length,
    };
  }

  destroy() {
    for (const w of this.workers) {
      w.instance.kill();
    }
    this.workers = [];
  }
}

// 使用示例
const pool = new ProcessPool('./compute-worker.js', { size: 4 });

async function batchCompute(dataList) {
  const results = await Promise.all(
    dataList.map(item => pool.execute({ item }))
  );
  return results;
}
```

## 信号处理最佳实践

```js
class SignalHandler {
  constructor(server) {
    this.server = server;
    this.shutdownInProgress = false;
  }

  register() {
    // SIGTERM — 来自进程管理器（systemd/docker stop）
    process.on('SIGTERM', () => this.handleSignal('SIGTERM'));

    // SIGINT — 来自 Ctrl+C
    process.on('SIGINT', () => this.handleSignal('SIGINT'));

    // SIGHUP — 配置重载（某些部署环境会发送）
    process.on('SIGHUP', () => this.reloadConfig());

    // uncaughtException — 兜底
    process.on('uncaughtException', (err) => {
      console.error('未捕获异常:', err);
      this.forceExit(1);
    });

    // unhandledRejection — Promise 异常兜底
    process.on('unhandledRejection', (reason, promise) => {
      console.error('未处理的 Promise 拒绝:', reason);
    });

    return this;
  }

  async handleSignal(signal) {
    if (this.shutdownInProgress) {
      console.warn('强制关闭信号，立即退出');
      process.exit(1);
    }
    this.shutdownInProgress = true;

    console.log(`\n收到 ${signal} 信号...`);

    // 1. 停止接受新连接
    this.server.close(() => {
      console.log('HTTP 服务器已停止接受新连接');
    });

    // 2. 设置硬性超时
    const forceExit = setTimeout(() => {
      console.error('关闭超时，强制退出');
      process.exit(1);
    }, 15000);

    // 3. 等待活跃请求完成
    await this.#waitForActiveConnections(10000);

    clearTimeout(forceExit);
    console.log('优雅关闭完成');
    process.exit(0);
  }

  #waitForActiveConnections(timeoutMs) {
    return new Promise((resolve) => {
      const deadline = Date.now() + timeoutMs;

      const check = setInterval(() => {
        const connections = this.server.connections || 0;
        console.log(`剩余活跃连接: ${connections}`);

        if (connections === 0 || Date.now() > deadline) {
          clearInterval(check);
          resolve();
        }
      }, 500);
    });
  }

  reloadConfig() {
    console.log('收到 SIGHUP，重新加载配置...');
    // 重新读取配置文件、重置内部状态
  }

  forceExit(code = 1) {
    setTimeout(() => process.exit(code), 1000);
  }
}
```

## 哲学思考：分而治之的智慧

进程管理是"分而治之"哲学在计算领域的经典体现。单个 Node.js 进程像一个独奏的音乐家——技艺精湛但无法同时演奏多种乐器；Cluster 则像一个交响乐团——每位乐手负责自己的声部，指挥（Primary）统一协调节奏。

但协调本身也有代价：IPC 通信的开销、状态同步的复杂性、故障排查的难度都会随进程数量增长。这提醒我们一个永恒的原则——**复杂度的转移而非消除**。你把计算压力分散到了多个核上，但把协调压力集中到了主进程中。好的架构师知道在哪里画这条线：什么时候该拆分，什么时候该保持简单。
